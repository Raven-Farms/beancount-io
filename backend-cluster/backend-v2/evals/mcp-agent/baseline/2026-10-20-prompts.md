# MCP prompt journeys: deployed repairs, 2026-10-20

This run measures the four MCP prompt playbooks after the 2026-09-15 repairs were deployed, and adds the two `close-month` journeys with statements. Every result below is a live client session against the hosted endpoint, run with `yarn mcp:agent-eval`. The previous baseline is [2026-09-15-prompts.md](./2026-09-15-prompts.md).

## Conditions

- **Endpoint:** `https://beancount.io/api-gateway/mcp`, which reports server `beancount-mcp 1.0.0`. The endpoint does not expose a deployed revision.
- **The deployed prompts are the repaired ones.** The harness compared served prompt text with this working tree and reported no difference for any invoked prompt. In the 2026-09-15 run, `close-month` and `categorize-imports` differed.
- **Claude Code:** 2.1.289, which reported model `claude-opus-5-5[1m]`. It selected each prompt natively as a slash command.
- **Codex:** codex-cli 0.163.0, signed in with a ChatGPT plan. Every attempt was **incomplete**: the plan's Codex usage limit was reached, and Codex refused to run until 2026-11-17. No Codex result here says anything about the prompts.
- **Credentials:**
  - A QA account's read/write key, pinned to a newly created private `mcp-agent-eval` ledger, with `ledger.read` and `ledger.write`.
  - For the read-only journey, a second key with only `ledger.read` on the same ledger.
  - Both keys expire on 2026-10-27.
- **Limits:** 1 attempt per journey and client, 300 s per client turn, 40 MCP calls per attempt, run on macOS.

## Observations

- **Month-end close with every statement, confirmed:**
  - Nothing was written before "Yes".
  - After it, exactly the missing `CORNER STORE` transaction and one period-end balance assertion for each of the four active accounts were added.
  - The ledger validated, and the answer ended with `Close status: complete`.
- **Month-end close with every statement, writes refused:** the ledger stayed unchanged. The close was reported `Close status: incomplete`, with the accounts no assertion pins at period end.
- **Month-end close without statements:** no finished close was claimed. The repaired prompt's status line rules out the old "nothing left to write, so complete" reading.
- **Categorizing imports on the repaired prompt:**
  - The agent read the ledger and stated that the key lacks `ledger.admin`, so it could not list banks.
  - It noted that the ledger has no `Expenses:Uncategorized` account, so it would ask which open account to use.
  - It named three ways to continue: an `item_id`, a `ledger.admin` credential, or linking a bank. It wrote nothing.
  - No "Resource not found" or `INTERNAL_SERVER_ERROR` appeared, unlike 2026-09-15.
- **Confirmation gate:** the ledger was untouched just before "Yes" in all three journeys with a confirmation.
- **Read-only credential:** the server refused the write, the agent reported it, and the ledger stayed unchanged.

## Found by inspection, not by a run

The `categorize-imports` prompt still told agents to remove rejected rows with `operation: "discard"`. That is an argument of the retired `manageBankImport`, and no tool accepts it now. The same change that records this run makes it name `discardStagedBankTransactions`, with a test that every argument a playbook prescribes is one some tool accepts. That correction is not deployed yet.

## Not measured

- **Codex:** blocked by its plan's usage limit until 2026-11-17.
- **`categorize-imports` with staged transactions:**
  - The hosted deployment uses Plaid's production environment: a link token begins `link-production`.
  - Sandbox credentials therefore cannot link a test bank, and staging is filled only by a Plaid sync.
  - Suggestions, previews, confirmed submission, and repeat-import deduplication remain unmeasured.
- **Variance:** one attempt per pair, so a single run cannot show how often a journey fails.
- **A close on a ledger that starts red:** that needs a second fixture, and the harness runs one fixture per suite.
- **A `ledger` argument outside the credential's pin:** covered only by unit tests.
