# One non-UTF-8 `.bean` file anywhere in the repo breaks every ledger read, even when nothing includes it; the error names no file

Found by MCP QA on 2026-10-20 against `https://beancount.io` (OAuth `ledger.read` token pinned to the synthetic QA ledger). The fixture came from a concurrent mobile QA run (`w21/042`). Commit `38667f9` added a one-line `qa-20261020-latin1.bean` holding a Latin-1 `é` (`0xE9`). `main.bean` was untouched and contains no `include`. `878d17f` removed the file two minutes later.

**Observed while the file existed:**

| Call | Result |
| --- | --- |
| `checkLedger {}` | `BAD_USER_INPUT` "Included ledger files must be valid UTF-8 text" |
| `runBqlQuery {query:"SELECT count(*)"}` | same |
| `resources/read …/errors`, `…/options`, `…/attributes` | same, as JSON-RPC `-32602` |
| `resources/read …/metadata`, `listLedgerFiles` | ok (repository-level reads) |

Every hint was "Fix the named argument and call again; `tools/list` publishes each tool's input schema." No argument is wrong, the file isn't included, and the message doesn't say which file is at fault. `checkLedger` and the `errors` resource, the tools an agent uses to find a broken file, fail the same way. The dashboard, REST and GraphQL go through the same loader.

**Expected:**

- A file that no `include` reaches does not affect loading. Beancount only reads what the main file includes.
- A reachable file that isn't valid UTF-8 shows up as a ledger error naming its path, the way a syntax error does. `checkLedger` and `errors` report it, and other reads still work or fail with that path named.
- The refusal is never coded as an argument error.

**Root cause:** `backend-cluster/ledger/src/foundation/rustledger/file-map-loader.ts:450` collects every `*.bean` path in the tree (`BEAN_FILE_RE`). `fetchInto` (`:494-508`) decodes each one with `requireUtf8: true`. `decodeText` in `backend-cluster/ledger/src/features/gitea/utils/gitea-file-content.ts:41-52` throws `BadUserInputError("Included ledger files must be valid UTF-8 text")` with no path. backend-v2 maps that to `BAD_USER_INPUT` with the generic argument hint.

**Fix:**

1. In the loader, decode leniently, or record undecodable `.bean` files instead of throwing, and keep them out of the FileMap unless an `include` reaches them.
2. When an included file is undecodable, add a loader error with the file's path, so it surfaces through `checkLedger` and `errors`.
3. Name the path in any remaining refusal, and choose a code that isn't `BAD_USER_INPUT`.

Add ledger-service tests for an unreferenced Latin-1 `.bean` (loads cleanly) and an included one (reported as an error naming the file), plus a backend-v2 parity case. Owner: `backend-cluster/ledger`, with error mapping in backend-v2. Estimate: ~60m.

**Severity:** major. A single stray file, such as an exported statement saved as `.bean` in a legacy encoding, makes a hosted ledger unreadable on every surface without saying why.
