# `appendLedgerText` with `path` writes to a file the ledger never reads and reports "No new bean-check errors"

**Severity:** minor. The entry is silently invisible: no error, and no read ever shows it. **Estimate:** 20–30 minutes. **Owner:** `backend-cluster/backend-v2`, in `src/features/ledger/workflow/directive-append-workflow.ts`. The workflow is shared, so REST, GraphQL and MCP change together. **A1:** agents pass `path: "2026/03.bean"` by analogy with a layout they've seen. Unless `main.bean` includes that file, the entry is committed and lost to every report.

## Repro (production, 2026-10-21, disposable QA ledger, `dry_run: true`)

`appendLedgerText {text: <balanced transaction>, path: P, dry_run: true}`. For each of `qa-new.bean`, `qa-dir/new.bean` and `notes.txt` the result is `ok`: "Would add 1 directive to P. No new bean-check errors." with a create diff. None of these files is in `main.bean`'s include closure (`beancount://<owner>/<name>/source-files` lists only `main.bean`), so the committed entry would never be loaded.

## Fix

Before writing, compare the target with the ledger's source files (`getSourceFiles`, already used for "valid targets for a new entry"). If the target is outside the include closure, refuse with `BAD_USER_INPUT`: "`P` is not included by the ledger (`main.bean` does not reach it); add an `include` for it, or omit `path` to auto-route". Alternatively, accept the write and return `included: false` with that sentence in the summary. Either way, refuse a non-Beancount extension such as `.txt` outright. Tests: an orphan path, a `.txt` path, and an included subdirectory file, which still succeeds.

## Dedupe

Searched `.pm/**` for append, path, include closure and unreachable. w23/018 covers non-directive text, and w23/029 covers renames that break includes. Neither covers the target file.
