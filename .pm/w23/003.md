# Bad archive names report "dependency down", and an unknown commit SHA hangs for 90 seconds

Found by MCP QA on 2026-10-20 against `https://beancount.io` (OAuth token, `ledger.read`, pinned to a synthetic QA ledger; inventory matches `main` at `afbb70a15`). REST `GET /api-gateway/v1/ledgers/{owner}/{name}/archive/{archive}` streams through the same `LedgerArchiveService.download`, so it shares the defect.

**Repro** (`resources/read`, any ledger the credential can read):

| `archive` | Result | Time |
| --- | --- | --- |
| `main.zip`, `main.tar.gz` | blob (control) | <1s |
| `deadbeef.zip` | `NOT_FOUND` "Archive with ID 'deadbeef.zip' not found" (control) | 0.5s |
| `main`, `main.rar` | `SERVICE_UNAVAILABLE` "Ledger archive is temporarily unavailable"; hint "A dependency is down…" | 0.4s |
| `deadbeef00000000000000000000000000000000.zip` (well-formed, unknown 40-hex SHA) | no answer for **90.3s**, then the same `SERVICE_UNAVAILABLE` | 90s |

```sh
node .agents/skills/qa-shared/scripts/qa-mcp.mjs --credentials-file <ro.env> --timeout-ms 150000 \
  read beancount://<owner>/<name>/archive/deadbeef00000000000000000000000000000000.zip
```

**Expected:**

- A name without a `.zip` or `.tar.gz` suffix is refused up front with `BAD_USER_INPUT`, naming the two formats. The resource description and the v1 parameter already document exactly those two.
- A reference that does not resolve to a branch, tag or commit answers `NOT_FOUND` promptly, whatever its shape.
- `SERVICE_UNAVAILABLE` is reserved for an actual upstream failure. Today an agent is told to "retry with backoff" for a typo, and each retry spends the shared archive-download budget.

**Root cause:** `backend-cluster/backend-v2/src/features/ledger/service/ledger-archive-service.ts:75-93` forwards the name verbatim to the repository host's archive API and maps every non-404 status, and the 90s `ARCHIVE_HEADERS_TIMEOUT_MS` abort, to `ServiceUnavailableError`. For an unresolvable full-length SHA the host never sends headers, so the request burns the whole header timeout. `SAFE_ARCHIVE_NAME_PATTERN` only checks characters, not the format suffix.

**Fix:**

1. Validate the suffix in the service, or in the shared archive-name helper used by both REST and MCP, and refuse anything else with `BadUserInputError`.
2. Resolve the ref, for example through the host's commit/ref lookup, before requesting the archive, and return `NotFoundError` when it doesn't resolve.
3. Map the host's 4xx responses for a bad ref to `BAD_USER_INPUT` or `NOT_FOUND`, never to `SERVICE_UNAVAILABLE`.

Extend `archive-parity.test.ts` so REST and MCP agree on all three cases, including a stubbed host that never answers for an unknown SHA. Owner: backend-v2 (REST + MCP; GraphQL only issues the URL). Estimate: ~45m.
