# Deleting the ledger's entry point commits and reports "No new bean-check errors"; the dry run answers `SERVICE_UNAVAILABLE`

**Severity:** major. One call makes every read of the ledger fail, and the result claims it was verified clean. **Estimate:** 45–60 minutes including tests. **Owners:**
- `backend-cluster/backend-v2`: `backend-cluster/backend-v2/src/features/ai-agent/tools/write-validation.ts` (`readBeanCheckErrors` / `withPostWriteValidation`), plus the delete and rename paths.
- `backend-cluster/ledger`: `checkProjectedErrors` in `src/features/ledger/service/ledger-data-service.ts`.

**A1:** an agent tidying a ledger ("delete the unused files", "rename main.bean to ledger.bean") gets a green result and leaves the ledger unloadable.

## Repro (production, 2026-10-21, disposable QA ledger, OAuth `ledger.read ledger.write` token; restored byte-identical within seconds)

| Call | Result |
| --- | --- |
| `deleteLedgerFiles {files: [{path: "main.bean"}], dry_run: true}` (3 tries) | `SERVICE_UNAVAILABLE` "preview refused: Ledger API is temporarily unavailable … Retry with backoff" |
| control: same dry run for a missing file | `NOT_FOUND` (correct) |
| `deleteLedgerFiles {files: [{path: "main.bean"}]}` | `ok`, "Committed 1 change(s) to main.bean. No new bean-check errors.", `validation: {errorsBefore: 0, errorsAfter: 0}` |
| `checkLedger` immediately after | `NOT_FOUND` "Ledger resource not found". Every ledger read fails the same way until `main.bean` is recreated |

## Cause

- **Dry run:** the projection deletes the entry point from the file map and passes it to `parseLedgerFiles`, which throws instead of returning an error. backend-v2 maps that throw to `SERVICE_UNAVAILABLE`.
- **Commit:** nothing checks whether a delete or rename removes the entry point. The commit lands, then the post-write `getErrors` fails with `NOT_FOUND` (`requireEntryPoint`). `readBeanCheckErrors` is deliberately fail-open: it logs a warning and returns `[]`. `toWriteValidation` turns that into `errorsAfter: 0`, and the summary says no new errors. "Couldn't check" is reported as "checked and clean".
- `renameLedgerFile` with `oldPath: "main.bean"` takes the same route through `withPostWriteValidation`.

## Fix

1. **Ledger:** `checkProjectedErrors` returns a regular error such as "entry point main.bean does not exist" when the projection removes the entry point, so a dry run previews it as a new error rather than an outage.
2. **backend-v2:** when the post-write check can't run, say so. Add `validation.checked: false` with the reason, and a summary like "bean-check could not run after the write: …", instead of `errorsAfter: 0`. This applies to every writer using `withPostWriteValidation`.
3. **Delete and rename:** refuse removing or renaming the ledger's entry point with `BAD_USER_INPUT` naming it, on REST `DELETE …/files/{path}`, GraphQL and MCP alike. A deliberate rewrite can use `updateLedgerFiles` `replace`.

**Tests:**
- The dry run returns a new error, not `SERVICE_UNAVAILABLE`.
- The real delete and rename are refused.
- A post-write check failure yields `checked: false`, not `errorsAfter: 0`.

## Dedupe

Searched `.pm/**` for entry point together with delete/rename, fail-open validation, and "No new bean-check errors". Nothing matches.
- w23/017 (concurrent write) and w23/027 (`.git` paths) are other `SERVICE_UNAVAILABLE` misclassifications.
- w23/011 (done) concerns undecodable files, not a missing entry point.
