# Deleting an entry leaves the blank separator lines its insertion added: every add → delete cycle grows the file

**Severity:** minor (ledger hygiene; no data change). An agent that adds and then removes an entry — a common correction loop — leaves 1–2 extra blank lines each time, and `deleteEntrySource` is not the inverse of `addLedgerEntries`/`appendLedgerText`. **Estimate:** 20–30 minutes with tests. **Owner:** `backend-cluster/ledger` — `deleteSliceFromFile` in `src/foundation/rustledger/source-slice.ts` (removes exactly `[startLine, endLine)`), used by `deleteEntrySource`/`deleteEntrySources` on REST, GraphQL and MCP. **A1.**

## Repro (production, 2026-10-21, OAuth `ledger.read ledger.write` token pinned to the disposable QA ledger; restored to blob `f1a0b83` afterwards)

1. `addLedgerEntries` with two transactions → the commit adds `\n<tx one>\n\n<tx two>\n\n` (11 lines) at the end of `main.bean`.
2. `deleteEntrySources` with both hashes → the commit removes only the 6 transaction lines.
3. `main.bean` now ends `…49.75 USD\n\n\n\n` instead of `…49.75 USD\n`; its blob is `baaf123`, not the starting `f1a0b83`. One entry added and deleted leaves 2 blank lines; two leave 3.

## Fix

When removing a slice, also drop one adjacent blank line if the slice is surrounded by blank lines (or sits at end of file after one), so the neighbours keep a single separator — the same normalization the append path applies when it inserts. Tests: add → delete of one and of two entries, at end of file and between entries, restores the original bytes; deleting an entry with a comment directly above keeps the comment.
