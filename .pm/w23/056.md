# `renameLedgerFile` moves a file without rewriting its own relative includes, so they resolve under the new directory

**Severity:** major (a reported-clean move breaks the moved file's includes). **Estimate:** 30–45 minutes including tests. **Owner:** `backend-cluster/backend-v2`, `renameLedgerFile` in `src/features/ledger/workflow/ledger-workflow.ts`. The workflow is shared, so REST `POST …/rename-file`, GraphQL `renameLedgerFile` and MCP `renameLedgerFile` change together. **A1:** agents reorganize ledgers into year folders, which moves files that themselves `include` neighbours.

## Shape (found while fixing w23/029, by reading the code)

`d/inc.bean` contains `include "x.bean"`, which resolves to `d/x.bean`. `renameLedgerFile d/inc.bean → e/inc.bean` copies the file's bytes unchanged (`preservedContent`), so the include now resolves to `e/x.bean`, which does not exist. `updateIncludes` rewrites only *other* files' includes of the moved path. The rename then reports "No new bean-check errors" whenever the moved file is outside the loaded closure.

## Fix

When `oldPath` is a `.bean`/`.beancount` file and its directory changes, resolve each of its own non-URL includes from both locations (`resolveIncludeTarget` in `src/features/ledger/utils/include-target.ts`). For every literal include whose resolution changes, refuse without `updateIncludes`, or with it rewrite the line through `includeTargetFor(newPath, resolved, target)` and `formatIncludeLine`. Refuse a glob include whose base directory changes, as w23/029 does for globs elsewhere. Leave root-anchored (`/…`) and URL targets alone. The moved file is otherwise byte-preserved, so the rewrite must decode strictly (see w23/030).

Tests: a same-directory rename leaves the content byte-identical; a cross-directory rename is refused naming the moved file, then rewritten with `updateIncludes` (`include "../d/x.bean"`); a glob in the moved file is refused; on REST, GraphQL and MCP.

## Dedupe

w23/029 (done) fixed how other files' includes of the renamed path are matched and rewritten. No item covers the moved file's own includes.
