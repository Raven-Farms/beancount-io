# A `.git` path segment is reported as an outage on reads and accepted by write previews

**Severity:** minor. **Estimate:** 30–45 minutes including tests. **Owner:** `backend-cluster/backend-v2` (`src/features/ledger/utils/safe-repo-path.ts`) and `backend-cluster/ledger` (`src/shared/safe-repo-path.ts`); one rule fixes REST, GraphQL and MCP together. **A1:** an agent that lists or writes under `.git` gets either a retry-forever outage or a preview that the real commit then refuses.

## Repro (production, 2026-10-21, OAuth `ledger.read` / `ledger.read ledger.write` tokens pinned to a disposable QA ledger)

| Call | Result |
| --- | --- |
| MCP `listLedgerFiles {dir_path: ".git"}` (also `.Git`, `sub/.git`, `.git/objects`) | `isError`, `SERVICE_UNAVAILABLE` "Ledger API is temporarily unavailable", hint "A dependency is down. Retry with backoff" — every repeat |
| REST `GET /api-gateway/v1/ledgers/<owner>/<name>/files?dir=.git` | **503** `SERVICE_UNAVAILABLE` |
| GraphQL `getLedgerDirContent(ledgerId: "<owner>/<name>", dirPath: ".git")` | `SERVICE_UNAVAILABLE` |
| Control: `dir_path: ".gitx"` / `.github` | `[]` (the not-found case w23/014 already fixed on `main`) |
| MCP `createLedgerFiles {files: [{path: ".git/qa-x.bean", …}], dry_run: true}` (also `sub/.git/…`, `.Git/…`) | `ok: true`, a diff, "Dry run: 1 change(s) previewed" |
| Same call without `dry_run` | `BAD_USER_INPUT` "commit failed: path contains a malformed path component"; HEAD unchanged |
| `readLedgerFiles {path: ".git/config"}` | `NOT_FOUND` (fine) |

## Cause

`assertSafeRepoPath` in both services rejects only empty, `.` and `..` segments. Gitea refuses any `.git` component (case-insensitive, at any depth): on the contents read it answers a non-404 error that the ledger's `dirs` route rethrows (`backend-cluster/ledger/src/api/files.ts`, `getLedgerDirContent`), which maps to `SERVICE_UNAVAILABLE`; on a commit it answers "malformed path component". Dry runs never reach Gitea, so they preview a write that cannot happen. w3/486 added the same rule to the dashboard's Create File form only.

## Fix

Reject a path segment equal to `.git` ignoring case (keep `.gitignore`, `.github`, `.gitx` valid) in both `assertSafeRepoPath` copies, with `BAD_USER_INPUT` "Paths inside .git can't be read or written" on the offending field. Every read, list, dry-run and write path already calls it. Tests: the helper in both packages, plus one MCP adapter case each for `listLedgerFiles` and a `createLedgerFiles` dry run asserting `BAD_USER_INPUT`, not `SERVICE_UNAVAILABLE` or `ok: true`.

Acceptance: the six refused calls above all return `BAD_USER_INPUT` on REST (400), GraphQL and MCP; `.gitx`, `.github` and `.gitignore` paths are unaffected.

## Dedupe

Searched `.pm/**` for `.git` path, malformed path component and safe-repo-path. w3/486 (done, dashboard) refuses `.git` client-side and confirmed the server commit refusal; it did not cover reads, listings or dry runs. w3/628 (done) is the dashboard ledger-URL `.git` suffix. w23/014 (done) is the empty-listing case, not this one.
