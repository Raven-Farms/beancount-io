# The asset download URL tells any credential which numeric ledger IDs exist, unlike every path-addressed read

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** `backend-cluster/backend-v2`, `LedgerAssetService.getAssetDownloadUrl` (`src/features/ledger/service/ledger-asset-service.ts`). It is shared by MCP `beancount://assets/download-url`, REST `GET /api-gateway/v1/asset-download-url` and GraphQL `ledgerAssetDownloadUrl`. **A1:** credentials handed to agents are scoped to hide other users' ledgers, and the scoping should not depend on how a ledger is addressed.

## Repro (production, 2026-10-22, OAuth tokens on a QA account, read-only)

`beancount://assets/download-url?ledgerRepoId=<N>&filename=x.png`:

| credential | N belongs to another user's ledger (e.g. 1, 2, 5, 50) | N does not exist (999999999) |
| --- | --- | --- |
| `ledger.read ledger.write`, pinned to the QA ledger | `FORBIDDEN` "This credential is not authorized for this ledger" | `NOT_FOUND` "Ledger with ID '999999999' not found" |
| `ledger.admin`, account-wide | `NOT_FOUND` "Ledger not found" | `NOT_FOUND` "Ledger with ID '999999999' not found" |

Either credential can walk the ID space and learn which IDs are real private ledgers, and so how many exist. Control: path-addressed reads answer uniformly. A pinned credential gets `FORBIDDEN` "outside this credential's ledger restriction" for any other `owner/name`, existing or not, and an account-wide credential gets `NOT_FOUND` "Ledger not found" for a private or missing ledger alike.

## Cause

`getAssetDownloadUrl` resolves the ID with the admin client first and throws `NotFoundError("Ledger", id)` when the lookup fails. Only after a successful lookup does it run `authorizeLedger`, which produces the pin refusal or the masked "Ledger not found". The two failure paths carry different codes and messages.

## Fix

Make a missing ID indistinguishable from an existing ledger the caller can't read. Throw the same error `authorizeLedger` gives for an unreadable ledger, or map the post-lookup `FORBIDDEN`/`NOT_FOUND` and the lookup miss to a single `NOT_FOUND` "Ledger not found". Apply it once in the service so all three surfaces change together. Tests: a missing ID and another user's private ID produce byte-identical errors for a pinned and an account-wide credential; the caller's own ID still returns a URL.
