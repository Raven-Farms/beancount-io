# BQL `cost()` of a multi-currency inventory returns one amount: numbers from every currency summed under the first currency's label

Found by MCP QA on 2026-10-20 against `https://beancount.io`, reading the public `open_ledger/example` with `runBqlQueryStructured`. GraphQL `queryShell` and REST `query` run the same engine, so they return the same values.

**Hosted repro (`open_ledger/example`):**

| Query | Result | Correct (beanquery) |
| --- | --- | --- |
| `SELECT cost(sum(position)) WHERE account ~ 'ETrade:GLD'` | `{"USD": "4559.80"}` | same (control) |
| `SELECT cost(sum(position)) WHERE account ~ 'Vacation\|ETrade:GLD'` | **`{"VACHR": "4559.80"}`** | `{"USD": "4559.80"}` (VACHR nets to 0) |
| `SELECT cost(sum(position)) WHERE account ~ '^(Assets\|Liabilities):'` | `{"USD": "106813.04944"}` | `{"USD": "106826.04944", "VACHR": "-13"}` |

The balance-sheet resource (`?conversion=at_cost`) is not affected. Its `assets` equals the sum of `byAccount` and leaves VACHR out, because that path values lots itself (`lot-inventory.ts`).

**Engine repro, no network** (`@rustledger/wasm` 0.24.0, the version `backend-cluster/ledger` pins). Ledger: `-13 VACHR` on `Assets:Hours`, and `17 GLD {268.22 USD}` on `Assets:Broker` bought with cash.

```text
queryMultiFile(…, "SELECT cost(sum(position)) WHERE account ~ '^Assets:(Hours|Broker)'")
  → [[{"number":"4546.74","currency":"VACHR"}]]      (-13 + 4559.74, labelled VACHR)
queryMultiFile(…, "SELECT cost(sum(position)) WHERE account ~ '^Assets:Broker'")
  → [[{"number":"4559.74","currency":"USD"}]]        (control)
```

The engine returns a single `Amount` where beanquery returns an `Inventory`. `ledger-shell-mappers.ts:156-158` already notes that "rustledger types some Inventory columns as a bare Amount", and passes the collapsed value through. `1.0.0-rc.18` is not a drop-in fix: its API differs (`query(source, q)`), and its parser rejects this query at `cost(`.

**Expected:** `cost()` applied to an inventory returns an inventory with one entry per currency, matching beanquery. `value()` and `convert(…, 'USD')` already do: on the same hosted set they return `{"USD": "117649.48828", "VACHR": "-13"}`. Cost-less positions stay in their own units.

**Fix:**

1. Report upstream to `rustledger/rustledger` with the three-line reproducer above, and pin or bump to a release that fixes it.
2. Until then, add a guard in `backend-cluster/ledger`: when an inventory-typed BQL function yields a bare `Amount` but its argument held more than one currency, return a `BAD_USER_INPUT`/query error that says so, rather than a silently relabelled number. Don't reimplement BQL (`.pm/DO_NOT_DO.md`).
3. Add the reproducer to `verify:rustledger` so a bump proves it.

Owner: `backend-cluster/ledger`, plus an upstream report. **Severity:** major, because it returns a wrong figure under a wrong currency with no error. Estimate: ~60m for the guard and test; the upstream fix isn't in this repo's control.
