# Every ledger-service 404 reads "Ledger resource not found": a stale entry hash or an unknown branch tells the agent its ledger is missing

**Severity:** minor-to-moderate. Entry hashes change after edits, so agents routinely hold stale ones; each such call says the *ledger* is missing and the hint points at `listLedgers`/`listLedgerFiles`, never at `listLedgerEntries`. **Estimate:** 30 minutes with tests. **Owner:** `backend-cluster/backend-v2` — `favaApiErrorToDomainError` in `src/foundation/fava/error-to-domain.ts` (`case 404: return new NotFoundError("Ledger resource")`), plus the MCP not-found hint in `mcp-errors.ts`. Shared by REST, GraphQL and MCP. **A1.**

## Repro (production, 2026-10-21, OAuth `ledger.read ledger.write` token pinned to the disposable QA ledger)

| call | result |
| --- | --- |
| `getEntryContext {entryHash: "000…0"}` | `NOT_FOUND` "Ledger resource not found", hint "Confirm the target exists: `listLedgers` for ledgers, `listLedgerFiles` … for files." |
| `updateEntrySource` / `deleteEntrySource` with that hash, and `beancount://<owner>/<name>/entry-context/000…0` | same |
| two identical transactions (hashes `H` and `H:1`); `deleteEntrySource H`, then `deleteEntrySource H:1` | second call: same "Ledger resource not found" (correctly refused, wrongly worded — `H:1` no longer exists because the survivor is now `H`) |
| `beancount://<owner>/<name>/latest-commit?branchName=master` (branch is `main`) | same "Ledger resource not found" |
| control: `beancount://<owner>/<name>/commits?branch=nope` | `NOT_FOUND` "Branch with ID 'nope' not found" (`CommitsService` maps it itself) |

## Cause

`favaApiErrorToDomainError` discards the ledger service's `message` on a 404 and always builds `NotFoundError("Ledger resource")`; `LedgerRepoService.getLatestCommit` relies on the same mapping via `unwrapFavaResponse`. The MCP hint for `NOT_FOUND` lists only ledgers and files.

## Fix

- In the 404 case, keep the ledger service's message (e.g. "Entry <hash> not found") as the `NotFoundError` detail, the way the 409 case already passes `message` through.
- In `getLatestCommit`, map the host 404 to `NotFoundError("Branch", branchName)` like `CommitsService`.
- Add `listLedgerEntries` (fresh hashes) to the MCP `NOT_FOUND` hint for entry-addressed tools and the entry-context resource.
- Tests: unknown hash on `getEntryContext`/`updateEntrySource`/`deleteEntrySource` names the entry on REST, GraphQL and MCP; unknown branch names the branch; unknown ledger still says the ledger.
