# `latest-commit?branchName=<unknown>` says "Ledger resource not found" for a ledger that exists

**Severity:** minor. An agent asking for a wrong branch is told the ledger is missing and pointed at `listLedgers`, while the sibling `commits?branch=<unknown>` correctly says "Branch with ID '<name>' not found". **Estimate:** 15 minutes with tests. **Owner:** `backend-cluster/backend-v2` — `LedgerRepoService.getLatestCommit` in `src/features/ledger/service/ledger-repo-service.ts`, behind REST `GET …/latest-commit`, GraphQL `latestCommit(branchName)` and MCP `beancount://{owner}/{name}/latest-commit{?branchName}`. **A1.**

## Repro (production, 2026-10-21, account-wide OAuth `ledger.read` token, a ledger the QA account owns)

- `beancount://<owner>/<name>/latest-commit?branchName=master` (the branch is `main`) → `-32002`, `data.code: NOT_FOUND`, "Ledger resource not found", hint "Confirm the target exists: `listLedgers` for ledgers…".
- Control: `beancount://<owner>/<name>/commits?branch=nope&limit=1` → `NOT_FOUND` "Branch with ID 'nope' not found".
- `latest-commit` with no `branchName` or `branchName=main` → `200`.

## Cause

`getLatestCommit` passes the branch as `sha` to the repository-host commit list and relies on `unwrapFavaResponse`, which maps every 404 to the generic ledger-not-found error. `CommitsService` (`commits-service.ts:221`) checks the branch and throws `NotFoundError("Branch", branch)`.

## Fix

Map the host 404 in `getLatestCommit` to `NotFoundError("Branch", branchName)` once the ledger itself has resolved (the authorize step already proved it exists), or share the branch check with `CommitsService`. Tests: unknown branch → `NOT_FOUND` naming the branch on all three surfaces; unknown ledger still says the ledger.
