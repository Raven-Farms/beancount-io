# `/.well-known/mcp.json` omits the prompts and the docs misdescribe its scopes

Found by MCP QA on 2026-10-20 against `https://beancount.io` (production inventory matches `main` at `afbb70a15`: 44 tools, 63 resource templates).

**Repro (anonymous):**

```sh
curl -s https://beancount.io/.well-known/mcp.json | jq '{capabilities, prompts, scopes: .auth.scopes}'
```

**Actual:** `capabilities` is `{"tools":{},"resources":{},"streaming":true}` and the manifest has no `prompts` key. `auth.scopes` is `["ledger.read","ledger.write","ledger.admin"]`.

**Expected:**

1. The manifest declares `capabilities.prompts` and lists the four playbooks from `MCP_PROMPTS` (`src/features/ai-agent/api/mcp-prompts.ts`), with each one's name, description and declared arguments. `initialize` already advertises prompts. Today a client reading the manifest concludes they do not exist, the same defect `w3/m8` fixed for resources.
2. `backend-cluster/backend-v2/docs/mcp.md` (the `/.well-known/mcp.json` paragraph) stops saying `auth.scopes` "contains the old `read`/`write` labels"; since `API_SCOPES` it serves the `ledger.*` names.

**Root cause:** `mcpManifest()` in `backend-cluster/backend-v2/src/features/well-known/api/well-known-route.ts` maps `MCP_TOOLS` and `MCP_RESOURCES` but never `MCP_PROMPTS`. The doc sentence predates the scope rename.

**Fix scope:** backend-v2 only (a discovery document, not an API operation, so no REST/GraphQL parity change). Extend `well-known-route.test.ts` so it asserts that the manifest's prompt names equal `MCP_PROMPTS` and that `capabilities.prompts` is present. Estimate: ~30m.
