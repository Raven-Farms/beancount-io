# `runBqlQuery` has no row cap: one `JOURNAL` returns 5.2 MB of text into the model's context

Found by MCP QA on 2026-10-20 against `https://beancount.io` (OAuth `ledger.read`, reading the public `open_ledger/example`, 3,209 postings).

**Repro:**

| Call | Content text the model receives |
| --- | --- |
| `runBqlQuery {query:"JOURNAL", ledger:"open_ledger/example"}` | `3209 rows` + table, **5,179,352 bytes** |
| `runBqlQuery {query:"SELECT *", …}` | `3209 rows` + table, 488,075 bytes |
| `runBqlQuery {query:"SELECT date, narration", …}` | `3209 rows` + table, 195,853 bytes |
| `runBqlQueryStructured` with any of the above (control) | `1000 rows (truncated)`, with `truncated: true` |

`runBqlQuery` is the first BQL tool in `tools/list`, and the one the prompts and instructions name. A single unbounded `JOURNAL` on a modest ledger is about 1.3M tokens. Hosts either fail the call or silently cut it, so the agent never learns the result was partial.

**Expected:** the text tool keeps the structured tool's ceiling (`MAX_STRUCTURED_BQL_ROWS`, 1,000 rows), and probably a byte budget as well, since `JOURNAL` rows run to kilobytes. When it truncates, the lead line says so, e.g. `3209 rows (showing the first 1000; add LIMIT or a narrower WHERE)`, and `structuredContent` carries `rowCount` and `truncated` exactly as `runBqlQueryStructured` does.

**Root cause:** `backend-cluster/backend-v2/src/features/ai-agent/tools/bql-query-tool.ts:26-52` (`executeBqlQuery`) returns `queryShellText`'s full text unchanged. `w2/m28/t001` added the 1,000-row ceiling only to `executeStructuredBqlQuery` (`:65`, `:119-123`).

**Fix:** slice the rendered table to the ceiling in the MCP tool (header, separator, then the first N rows), report `rowCount` and `truncated`, and update the tool description and `docs/mcp.md`. This is an MCP context constraint: REST and GraphQL `queryShellText` keep their full results, like the structured cap, recorded as a deliberate protocol difference in `docs/api-parity.md`. Add a test with 1,001+ rows asserting the lead line and the row count. Owner: backend-v2. Estimate: ~40m.
