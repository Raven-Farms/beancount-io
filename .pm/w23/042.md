# Entry-source write tools always return `wrote: []` (documented as "files touched"), and `deleteEntrySources` echoes duplicate hashes

**Severity:** minor (a write-outcome contract gap). **Estimate:** 20–30 minutes. **Owner:** `backend-cluster/backend-v2`, in `src/features/ai-agent/api/mcp-source-slices.ts` (`validated()` hard-codes `wrote: []`). The ledger's `updateSourceSlice` and `deleteSourceSlice` results need to carry the edited file's path. **A1:** after `updateEntrySource` or `deleteEntrySource(s)`, an agent can't tell which file changed without another read, unlike every other write tool.

## Repro (production, 2026-10-21, disposable QA ledger)

`deleteEntrySources {entries: [{entryHash: H, sha256sum: S}, {entryHash: H, sha256sum: S}]}` on an entry in an included `qa-` file returns `ok`, "Deleted 1 entry", `deletedCount: 1`, `wrote: []` and `entryHashes: [H, H]`. One file was rewritten, and the duplicate was correctly deleted only once. `updateEntrySource` on an entry in a subdirectory file likewise returns `wrote: []`.

`docs/mcp.md` (write outcome) says every write result carries "`wrote` (files touched)". `appendLedgerText`, `addLedgerEntries` and the file tools fill it.

## Fix

Have the ledger's slice update and delete return the touched path(s); the slice's file is already known from the entry's `meta.filename`. Pass them through as `wrote: [{path}]`, de-duplicated. Return `entryHashes` de-duplicated in request order. Tests: `updateEntrySource` and `deleteEntrySource` report the entry's file, `deleteEntrySources` across two files reports both once, and duplicate hashes appear once.
