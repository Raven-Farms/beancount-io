# `leaveLedger` by the ledger's owner answers `NOT_FOUND` "Ledger not found" instead of the documented "owners cannot leave"

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** `backend-cluster/backend-v2`, `LedgerCollaboratorsWorkflow.leaveLedger` (`src/features/ledger/workflow/ledger-collaborators-workflow.ts`). It is shared by REST, GraphQL and MCP `leaveLedger`. **A1:** an agent that gets "Ledger not found" for a ledger it just read concludes the ledger is gone.

## Repro (production, 2026-10-22, OAuth `ledger.admin` account-wide, disposable `qa-` ledger since deleted)

`createLedger {name: "qa-…-leave"}`, then `leaveLedger {ledger: "<owner>/qa-…-leave"}` → `isError: true`, `NOT_FOUND` "Ledger not found". `checkLedger` on the same ledger still succeeds.

Control: `removeLedgerCollaborator {collaborator: <owner>}` on the same ledger returns `OPERATION_NOT_ALLOWED` "…owns this ledger; an owner's access can't be granted or removed as a collaborator" (w23/025).

Expected: `docs/mcp.md` says "Owners cannot leave their own ledger", so the response should be `OPERATION_NOT_ALLOWED` with a hint to `deleteLedger` (or transfer, when that exists).

## Cause

`leaveLedger` calls the host's delete-collaborator for the caller's username. The owner is not a collaborator, so the host answers 404, which `error-to-domain.ts` maps to "Ledger not found". w23/025 added the owner check to `addOrUpdateCollaborator` and `deleteCollaborator` only.

## Fix

Before the host call, compare the caller with the ledger owner and refuse with the 025 wording adapted for leaving. Also check how a non-collaborator reader of a public ledger is answered: it should get a clear refusal, not `NOT_FOUND`. Tests on all three surfaces: owner leave → `OPERATION_NOT_ALLOWED`; collaborator leave unchanged.

## Dedupe

w23/025 (done) covers set/remove for the owner but not leave. w23/047 (done, not yet deployed when this was filed) only changes the 404 wording for entries and branches.
