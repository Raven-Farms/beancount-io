# Archives over 8 MiB are unreachable for OAuth MCP clients: the documented fallback URL refuses the MCP token

Found by MCP QA on 2026-10-20 against `https://beancount.io` (OAuth `ledger.read` token, audience `https://beancount.io/api-gateway/mcp`, pinned to a synthetic QA ledger).

**Repro:**

```text
resources/read beancount://<owner>/<name>/archive-download-url
  → {"downloadUrl":"https://api.v3.beancount.io/api-gateway/v1/ledgers/<owner>/<name>/archive/main.zip"}
GET that URL, Authorization: Bearer <the same MCP OAuth token>
  → 401 {"code":"UNAUTHENTICATED","message":"This endpoint requires a credential: send `x-api-key: …` or `Authorization: Bearer <token>`."}
GET https://beancount.io/api-gateway/v1/ledgers/<owner>/<name>/archive/main.zip, same bearer → same 401
```

The `archive/{archive}` blob resource works under the 8 MiB cap. Above it, `OPERATION_NOT_ALLOWED` sends the client to `archive-download-url`. `docs/mcp.md` (§ Asset and archive URL discovery) says "Fetch that URL using the same session cookie, OAuth bearer token, or API key", and later "Fetch the URL that resource returns with the same credential; it streams at any size."

**Why it fails:** ADR 0007 deliberately keeps MCP tokens (`aud` `{issuer}/api-gateway/mcp`) and application-API tokens (`{issuer}/v1`) as separate OAuth resources, so a REST route refuses an MCP token. That's correct. But the fallback the MCP contract promises therefore only works for personal API keys. Every OAuth-connected host (Claude, ChatGPT, Cursor, VS Code, Claude Code with OAuth) can never download a ledger whose archive exceeds 8 MiB. The returned URL also uses the backend's `SERVER_URL` host (`api.v3.beancount.io`) rather than the issuer `https://beancount.io` that every other MCP URL names.

**Expected:** an MCP client holding an MCP-audience token can retrieve an archive of any size through something the MCP contract names. If that isn't offered, the docs and the over-cap hint say plainly that the streaming URL needs a personal API key or session, not the MCP OAuth token.

**Fix options, for the owner to choose:**

1. Serve the stream under the MCP resource, e.g. `GET /api-gateway/mcp/archive/{owner}/{name}/{archive}`, accepting the MCP audience with the same pin and authorization checks as `streamLedgerArchive`, and return that URL from `archive-download-url` for MCP callers.
2. Correct `docs/mcp.md` and the `OPERATION_NOT_ALLOWED` hint in `mcp-resources.ts:143-147` to say an API key is required.

Either way, build the URL from the public origin (`config.dashboard.url`), not `SERVER_URL`, so clients see one host. Add a test with an MCP-audience token covering an over-cap archive end to end. Owner: backend-v2. Estimate: option 1 ~60m, option 2 ~15m.
