# Listing a directory that doesn't exist returns `[]`, indistinguishable from an empty directory

Found by MCP QA on 2026-10-20 against `https://beancount.io` (OAuth `ledger.read` token pinned to a synthetic QA ledger whose repository holds only `main.bean`). All three surfaces agree:

| Call | Result |
| --- | --- |
| MCP `listLedgerFiles {dir_path:"nope"}` | `ok`, `[]` |
| GraphQL `getLedgerDirContent(dirPath:"nope")` | `[]` |
| REST `GET …/files?dir=nope` | `200 []` |
| any surface, `dir_path`/`dir` = `main.bean` (a file) | `NOT_FOUND` "Ledger resource not found" |
| any surface, `../x` | `BAD_USER_INPUT` "Invalid file path" (control) |

Git stores no empty directories, so an empty listing for a non-root path always means the path doesn't exist. An agent that misspells a directory (`Imports` for `imports`) is told it's empty and may create a duplicate tree.

**Expected:** a non-root `dir_path` that doesn't exist answers `NOT_FOUND` naming the path, e.g. "Directory `nope` not found", with a hint to list the parent. Naming a file answers "`main.bean` is a file; read it with `readLedgerFiles`". The root of an empty repository keeps returning `[]`.

**Where:** backend-v2's directory listing (`getLedgerDirContent`, shared by the MCP `listLedgerFiles` tool, GraphQL and REST `GET …/files`) maps the host's empty `contents` response to `[]`. Check how the host answers a missing path (a 404 versus an empty list) and map that to `NotFoundError`. Add one parity test covering all three surfaces. Owner: backend-v2. Estimate: ~30m.

---

**Resolved 2026-10-20** — A shared `listDirectory` (`src/features/ledger/utils/directory-listing.ts`) wraps both directory-listing paths: `LedgerRepoService.listDirContent` (REST `GET …/files?dir=`, MCP `listLedgerFiles`) and `LedgerWorkflow.getLedgerDirContent` (GraphQL). Git stores no empty directories, so below the root an empty listing now answers `NOT_FOUND` "Directory '<path>' not found", with a hint to list the parent and a reminder that names are case-sensitive. The ledger service's 404 for a path that names a file now answers `NOT_FOUND` with the hint "'<path>' is a file, not a directory: read it with readLedgerFiles …" instead of the unnamed "Ledger resource not found". The repository root still lists `[]` when empty. backend-v2 only; the ledger service's wire behavior is unchanged. The new `directory-listing-parity.test.ts` drives the real repo service and workflow through REST, the MCP tool and GraphQL. It covers the root and an existing directory (identical listings), a misspelled directory and a file (`NOT_FOUND` naming the path and hint, on all three surfaces). Reverting the two call sites fails both refusal cases. `ledger-repo-service.test.ts`'s pass-through fixture now lists a file rather than an impossible empty subdirectory. `docs/mcp.md` notes the refusal. Native gates pass: typecheck, lint/Knip, 370 suites / 6379 tests, OpenAPI generation without drift. Shipped in the commit that moved this note (`backend-cluster/backend-v2`).
