# Guided setup with a known opening balance builds a broken ledger: `Equity:OpeningBalances` opened twice in 6 of 8 presets, and nothing validates the files ADR021 says are checked

**Severity:** major. The headline guided-setup flow — the Personal preset with a bank balance you know — produces a `main.bean` that fails bean-check, and `createLedger` would commit it as the new ledger's first commit. **Estimate:** 45–60 minutes with tests. **Owner:** `backend-cluster/backend-v2` — `previewLedgerSetup` in `src/features/ledger/setup/build-ledger.ts`, used by `createLedger` (`ledger-workflow.ts:561`, `buildLedgerFiles`) and by `previewLedgerSetup` on REST, GraphQL and MCP. **A2:** a newcomer's first ledger starts with an error; an agent following ADR021 has no validation result to read.

## Repro (production, 2026-10-21, account-wide OAuth token with `ledger.admin`; preview only, nothing created)

`previewLedgerSetup` `{"setup":{"preset":"personal@1","accounts":[{"name":"Assets:Bank","openingState":"known","amount":"1250.00"}]}}` returns:

```
2026-10-20 open Assets:Bank USD
2026-10-20 open Equity:OpeningBalances USD
2026-10-20 open Assets:Cash USD
2026-10-20 open Equity:OpeningBalances USD
…
2026-10-20 * "Opening balance"
  Assets:Bank 1250.00 USD
  Equity:OpeningBalances -1250.00 USD
```

Beancount's loader on that file: `Duplicate open directive for Equity:OpeningBalances`. Every preset whose catalog lists `Equity:OpeningBalances` (personal, business, portfolio, rental, shared-expenses, community) does this for any known opening.

Two more valid-input cases that load with errors:

| setup (`blank@1`) | bean-check |
| --- | --- |
| `Assets:Bank` `currency: EUR` known 5, `Assets:Cash` known 7 | `Invalid currency USD for account 'Equity:OpeningBalances'` (opened EUR-only by the first account) |
| `Equity:OpeningBalances` known 5 | `Balance failed … expected 5 USD != accumulated 0 USD` (no opening transaction for the equity account itself, but the assertion is still written) |

The preview result has only `preset`, `operatingCurrency`, `historyStart`, `accounts` and `files` — no validation result.

## Cause

- The account loop opens the counter account on the first known opening (`if (counter && !opened.has(counter))`), then opens it again when the sorted loop reaches the preset's own `Equity:OpeningBalances`; that branch never checks `opened`.
- The counter account is opened with the first known account's currency only, and later openings in other currencies post to it.
- For `account.name === OPENING_EQUITY` the transaction is skipped but the assertion is pushed.
- ADR021 (§ "Idempotent creation", and the preview row of the surface table) requires that "files are validated before the ledger service is called" and that the preview return "the generated files, account list, and validation result". Neither exists; `build-ledger.test.ts` asserts substrings only.

## Fix

- Skip an account already in `opened`; open `Equity:OpeningBalances` without a currency constraint (or with every currency used), and refuse a known opening on the equity account itself with `VALIDATION_FAILED`.
- Run the generated files through the ledger service's check (the same projected bean-check `addLedgerEntries` uses) in `previewLedgerSetup` and before `createLedger` calls the ledger service; return `validation: { ok, errors }` in the preview on all three surfaces, and refuse create on errors.
- Tests: for every preset in `catalog.json`, each `optionalQuestions` combination plus a known opening loads with zero errors; mixed-currency known openings load clean.

---

**Resolved 2026-10-22** — Both halves of the fix landed.

**Generation:** `previewLedgerSetup` (`backend-cluster/backend-v2/src/features/ledger/setup/build-ledger.ts`), behind `createLedger` and the preview on all three surfaces, now skips an account already opened as the counter of an earlier known opening, so `Equity:OpeningBalances` is never opened twice. Whenever a known opening exists, it opens `Equity:OpeningBalances` without a currency constraint, so openings in several currencies post to it. A known opening on `Equity:OpeningBalances` itself is refused with `VALIDATION_FAILED`; it used to write an assertion no transaction backed. Verified with the real engine: a scratch run of all 49 generated ledgers (every preset × every capability combination, with and without a known asset and liability opening, plus the note's mixed EUR/USD case) found 0 with errors, against 21 of 49 with HEAD's builder.

**Validation (ADR021):** the ledger service gained a repository-free `POST /reports/check-files` (`checkLedgerFiles` in `src/features/ledger/service/ledger-data-service.ts`). It bean-checks a supplied set of base64 files from `main.bean`, with `/check`'s input caps, the entry point required, and safe paths. It is declared in `backend-cluster/idl/beancount-ledger.openapi.json` and regenerated into backend-v2's client; a live engine run reports HEAD's Personal ledger's duplicate open and nothing for the fixed one. `LedgerWorkflow.previewLedgerSetup` now returns `validation: { ok, errors: [{message, source}] }` (warnings excluded) on REST, GraphQL (a `LedgerSetupValidation` type) and MCP. `createLedger` with a `setup` runs the same check before calling the ledger service and refuses with `VALIDATION_FAILED` "the ledger this setup creates would not load: …". `docs/mcp.md` and `docs/api-parity.md` document both.

**Tests:** `build-ledger.test.ts` adds 30 cases. Every preset and capability combination with a known opening opens each account once and opens `Equity:OpeningBalances` without a currency; a mixed-currency case posts EUR and USD to the one account; a known opening on the equity account is refused. `ledger-workflow.test.ts` covers a clean preview validation, a failing check reported in the preview with the exact files sent to the ledger, and create refused with no ledger created. Ledger `check-projected-errors.test.ts` covers `checkLedgerFiles` parsing exactly the given files without loading a repository, and three refusals. Reverting the builder fails 26.

**Gates:** ledger typecheck, lint and 1618 tests; backend-v2 typecheck, lint/Knip and the full suite. The failures were the environment-only `upstream-survival.test.ts` (see w23/027) and the `archive-parity` and `batch-processor` timing flakes. OpenAPI was regenerated (the preview's `validation`), and the `tools/list` budget holds.

Shipped in the commit that moved this note (`backend-cluster/ledger`, `backend-cluster/idl`, `backend-cluster/backend-v2`).
