# File paths accept control characters, bidi overrides and Windows-invalid names: a committed `qa-…\nx.bean` or `aux.bean` makes the ledger unclonable on Windows and un-`include`-able

**Severity:** minor (portability and spoofing; nothing escapes the repository). **Estimate:** 30 minutes with tests. **Owner:** `assertSafeRepoPath` in `backend-cluster/backend-v2/src/features/ledger/utils/safe-repo-path.ts` and its ledger-service twin (the same two copies w23/027 changes), used by every file write on REST, GraphQL and MCP (`createLedgerFiles`, `updateLedgerFiles`, `renameLedgerFile`, `createPullRequest`). **A1/A2:** the CLI and desktop users sync ledgers with `git clone`; an agent's malformed path silently breaks that for every Windows collaborator.

## Repro (production, 2026-10-21, OAuth `ledger.read ledger.write` token pinned to the disposable QA ledger)

- `createLedgerFiles` `qa-20261021-\nx.bean` (a newline inside the name) → `ok`, committed; `listLedgerFiles` lists it. Deleted right after. A 315-character file name also commits.
- `dry_run: true` accepts all of these (not committed): tab, `\r`, ESC, U+202E RIGHT-TO-LEFT OVERRIDE (renders the name reversed in any file list), `:`, `*`, `?`, `<`, `>`, `|`, `"`, `CON`, `aux.bean`, `dir/NUL.bean`, a segment ending in `.` or space (`qa-x. /y.bean`).
- Refused today: NUL, `\`, empty, `.` and `..` segments.

Effects: Git for Windows refuses to check out such paths ("invalid path"), so `git clone` of the ledger fails there; a name with a newline or `"` cannot be written in a beancount `include` (see w23/029); a bidi override lets a file display under a different name than it has.

## Fix

Extend both guards to refuse, with `BAD_USER_INPUT` naming the rule: C0/C1 control characters and U+2028/2029; bidi controls (U+202A–202E, U+2066–2069); the Windows-reserved characters `<>:"|?*`; segments ending in `.` or space; Windows device names (`CON`, `PRN`, `AUX`, `NUL`, `COM1–9`, `LPT1–9`, with or without extension, case-insensitive); and segments over 255 bytes. Existing files with such names must stay readable and deletable (apply the rule to new paths: create, rename target, PR change paths). Tests: each class refused on all three surfaces; Unicode NFC/NFD names (already supported) still accepted; deleting a legacy bad name still works.

**Resolved 2026-10-22** — Both copies of the path guard (`backend-cluster/backend-v2/src/features/ledger/utils/safe-repo-path.ts` and `backend-cluster/ledger/src/shared/safe-repo-path.ts`) gained `assertPortableRepoPath`. It applies the existing safe-path rule, then refuses with `BAD_USER_INPUT` naming the rule: C0/C1 control characters and U+2028/2029 (`\p{Cc}`), bidi controls (`\p{Bidi_Control}`), the Windows-reserved `<>:"|?*`, a segment ending in `.` or a space, Windows device names (`CON`, `PRN`, `AUX`, `NUL`, `COM1–9`, `LPT1–9`, any case, with or without an extension), and segments over 255 UTF-8 bytes. As the note asks, it applies only to new paths, so existing files keep being readable and deletable. In backend-v2 it covers `create` operations in `LedgerRepoService` (MCP `createLedgerFiles` previews and commits, REST `PUT` without a sha), GraphQL `createLedgerFile`, the `renameLedgerFile` target, and pull-request change paths. In the ledger service it covers `POST …/files` and `create` operations in the change-files route. NFC and NFD Unicode names, spaces and `auxiliary.bean` are still accepted. w23/029's rename case for `c"x.bean` became a refusal test (`c"x.bean`, `aux.bean`, a newline, a bidi override, on REST, GraphQL and MCP); `my file.bean` still round-trips. Tests: 23 helper cases in each package (each class refused; accepted names; a read of `aux.bean` still allowed by the safe-path rule), and `edit-ledger-files-refusals.test.ts` checks that four bad names are refused in the preview and the commit with no write while a legacy `aux.bean` still deletes. Reverting the repo-service call site fails 4. Gates: backend-v2 typecheck, lint/Knip and 6748 tests, with OpenAPI unchanged; ledger typecheck, lint and 1642 tests. The backend-v2 failures were the environment-only `upstream-survival.test.ts` (see w23/027) and timeouts under load (`archive-parity`, `auth-service-password-budget`, `batch-processor`) that pass alone. Shipped in the commit that moved this note (`backend-cluster/backend-v2`, `backend-cluster/ledger`).
