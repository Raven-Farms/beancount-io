# `docs/mcp.md` says ledger creation has no preview; `previewLedgerSetup` and `setup`/`requestId` are undocumented

Found by MCP QA on 2026-10-20. Production's `/.well-known/mcp.json` (whose inventory matches `main` at `afbb70a15`) lists `previewLedgerSetup`, and its `createLedger` input schema has `name`, `description`, `private`, `template`, `setup` and `requestId`. Both came from `w3/m53/t003` (`45ddc33f8`).

**Repro:**

```sh
curl -s https://beancount.io/.well-known/mcp.json \
  | jq '.tools[] | select(.name=="createLedger" or .name=="previewLedgerSetup") | {name, args: (.inputSchema.properties|keys)}'
grep -n 'previewLedgerSetup\|offer no preview\|accepts `description`, `private`, and `template`' backend-cluster/backend-v2/docs/mcp.md
```

**Actual:** the MCP guide's `### Ledger lifecycle` section says `createLedger`, `updateLedger`, and `deleteLedger` "offer no preview". It also lists `createLedger`'s inputs as `name`, `description`, `private`, `template`. `previewLedgerSetup` appears nowhere in `docs/mcp.md`. `w3/m53/t006` updated `docs/api-parity.md` but not the MCP guide, which is the customer contract agents are pointed at.

**Expected:** `### Ledger lifecycle` documents:

- `previewLedgerSetup { setup }`: no side effects; it returns files, accounts and validation, per ADR021.
- `createLedger`'s `setup`, which is mutually exclusive with `template`.
- `requestId` for idempotent retries.
- The "no preview" sentence, corrected so it applies only to update and delete.

Name the REST and GraphQL counterparts the way the section already does for the other three.

**Fix scope:** `backend-cluster/backend-v2/docs/mcp.md` only. Behavior is already at parity. Estimate: ~20m.

---

**Resolved 2026-10-20** — `docs/mcp.md` `### Ledger lifecycle` now documents `previewLedgerSetup { setup }`: no side effects, under creation's account authority, returning the resolved `preset`, `operatingCurrency`, `historyStart`, `accounts` and `files`, and refusing an invalid specification with the same `setup` validation error creation would raise. The section also documents `createLedger`'s `setup` fields, which are mutually exclusive with `template`, and `requestId` idempotency: a same-input replay returns the original ledger, different inputs are a validation error, a repeat while the first call runs is a conflict, and a key lasts 24 hours. The "no preview" sentence now applies only to update and delete. The REST counterparts (`POST …/ledgers/preview`) and GraphQL counterparts (the `previewLedgerSetup` query and the three mutations) are named. Every statement was checked against `lifecycle-handler.ts`, `ledger-workflow.ts` and `build-ledger.ts`. Docs only; behavior was already at parity. `mcp-docs.test.ts` passes. Shipped in the commit that moved this note (`backend-cluster/backend-v2`).
