# `readLedgerFiles` and write previews count a phantom empty line after the final newline

Found by MCP QA on 2026-10-20 against `https://beancount.io` (OAuth token pinned to a synthetic QA ledger; inventory matches `main` at `afbb70a15`).

**Repro:** take any file that ends in a newline, here an 87-line `main.bean` (`wc -l` → 87; the `files/{+path}` resource returns 2817 bytes, 87 `\n`).

```text
readLedgerFiles {files:[{path:"main.bean"}]}                      → totalLines 88, endLine 88
readLedgerFiles {files:[{path:"main.bean",start_line:88}]}        → ok, content ""   (line 88 does not exist)
readLedgerFiles {files:[{path:"main.bean",start_line:89}]}        → BAD_USER_INPUT "past the end of the file (88 lines)"; hint "between 1 and 88"
deleteLedgerFiles {files:[{path:"one-line.bean"}], dry_run:true}  → diff "@@ -1,2 +0,0 @@\n-; text\n-\n"   (a one-line file shown as two lines)
```

**Expected:** a file's line count matches `wc -l` and every editor: a trailing newline terminates the last line, it does not start a new one.

- `totalLines` and the clamped `endLine` are 87.
- `start_line: 88` is refused, and the refusal says "(87 lines)".
- A full read's `content` is still the file byte-for-byte.
- The preview diff for deleting a one-line file is `@@ -1 +0,0 @@` with one `-` line, so `git apply` would accept it.

**Root cause:** both paths split on `"\n"` without dropping the empty string after a terminal newline:

- `backend-cluster/backend-v2/src/features/ai-agent/tools/read-ledger-files-tool.ts:101` (`raw.split("\n")`, which feeds `totalLines`, the past-the-end check from `w5/046`, and the clamp).
- `backend-cluster/backend-v2/src/shared/unified-diff.ts:21` (`splitLines`, shared by `edit-ledger-files-tool.ts` and `directive-append-workflow.ts` previews).

The existing tests in `src/features/ai-agent/tools/__tests__/mcp-tools.test.ts` only use content without a trailing newline (`"line1\nline2\nline3"`), so they never see it.

**Fix:**

- Count lines as `split("\n")` minus a final empty element when the text ends with `\n`.
- Slice ranges against that count, and add the terminator back when the slice reaches the end, so a full read stays byte-identical.
- In the diff, emit `\ No newline at end of file` for files that lack one, instead of an empty line.

Add cases with and without a trailing newline to both test files. Owner: backend-v2. `readLedgerFiles` is MCP-only per `op-class.ts`; GraphQL and REST file reads return whole files. Estimate: ~40m.

---

**Resolved 2026-10-20** — `readLedgerFiles` drops the empty element after a terminal newline before counting. On a file that ends in `\n`, `totalLines` and the clamped `endLine` match `wc -l`, and a start on the phantom line is refused with the real count. A slice that reaches the end gets its terminator back, so a whole-file read is still byte-identical; a mid-file slice is unchanged. `unifiedDiff`, shared by the `editLedgerFiles` and directive-append previews, now splits lines with their terminators. Deleting a one-line file shows one `-` line. A last line without a newline gets git's `\ No newline at end of file` marker, and adding or removing a final newline shows as a change to that line. Hunk headers keep the explicit `-1,1` count form rather than the `-1` shorthand the note suggested. Both are valid unified diff, and `git apply` accepted the one-line deletion, a no-newline edit, adding and dropping a final newline, a creation, and a mid-file change. New cases in `mcp-tools.test.ts` and `unified-diff.test.ts` cover files with and without a trailing newline. The old `+a\n+b\n+\n` creation expectation, which pinned the bug, was corrected. Reverting the two production files fails 11 cases. Native gates pass: typecheck, lint/Knip, 369 suites / 6348 tests, OpenAPI generation without drift. Shipped in the commit that moved this note (`backend-cluster/backend-v2`).
