# `updateLedgerFiles` small validation gaps: an identical `old_string`/`new_string` makes an empty commit reported as "Committed 1 change(s)"; an empty `old_string` "matches 47 times"; an unknown key reads "files.0: Invalid input"

**Severity:** minor. **Estimate:** 20 minutes with tests. **Owner:** `backend-cluster/backend-v2` — `src/features/ai-agent/tools/edit-ledger-files-tool.ts` (MCP `updateLedgerFiles`, the AI agent's `editLedgerFiles`). **A1.**

## Repro (production, 2026-10-21, OAuth `ledger.read ledger.write` token pinned to the disposable QA ledger; file `qa-20261021-edit.bean` created and deleted by the probe)

- `old_string == new_string` (one exact match) → `ok`, "Committed 1 change(s) to qa-20261021-edit.bean", `diff: []`, and `latest-commit` advances: a commit with no change lands in history and the feed.
- `old_string: ""` → `BAD_USER_INPUT` "old_string matches 47 times (must match exactly once — add more context lines)" for a 47-character file: refused, but the count and hint describe a different problem.
- An extra key on a file operation (`replace_all: true`) → `BAD_USER_INPUT` "files.0: Invalid input", naming neither the key nor the allowed fields (the discriminated-union error loses the strict-object detail).

## Fix

- Skip operations whose result equals the current content; if none remain, return `ok` with "No changes — nothing committed" and `count: 0` (no repository call).
- Refuse an empty `old_string` with "old_string must not be empty" (`.min(1)` in the schema, which also publishes it).
- Surface the inner Zod issue for union members (e.g. `files.0: Unrecognized key "replace_all"`).
- Tests for each on MCP; the empty-commit case also asserts no repository write.

---

**Resolved 2026-10-22** — All three gaps are closed in `backend-cluster/backend-v2`.

**Identical edit:** `foldOperations` (`src/features/ai-agent/tools/edit-ledger-files-tool.ts`) now drops a change that leaves its file as it was. When nothing remains, `executeEditLedgerFiles`, behind MCP `updateLedgerFiles` and the in-app agent, returns `ok` with "No changes — nothing committed", `count: 0` and empty `operations`/`diff`, and makes no repository write. It still runs the write authorization through a dry-run `changeFiles`, so a read-only caller is refused as the commit would refuse it. A retry after a lost race that finds the winner made the same change commits nothing.

**Empty `old_string`:** refused by the schema (`min(1)`, which `tools/list` now publishes) as "files.0.old_string: old_string must not be empty", instead of "matches 47 times".

**Unknown key:** a union refusal now speaks for its closest branch, the one with the fewest issues (`describeIssue` in `src/features/ai-agent/api/mcp-errors.ts`). `replace_all: true` therefore reads `files.0: Unrecognized key: "replace_all"` instead of "files.0: Invalid input"; this applies to every MCP union argument.

**Tests:** four `edit-ledger-files-refusals.test.ts` cases through the MCP client and the real repo service: the identical edit, previewed and committed, with no repository write; and the empty `old_string` and the unknown key refused with those exact messages before any read. Reverting fails 4.

**Gates:** typecheck, lint/Knip, 6721 tests, OpenAPI unchanged. The failures were the environment-only `upstream-survival.test.ts` (see w23/027) and the `archive-parity` timeout.

Shipped in the commit that moved this note (`backend-cluster/backend-v2`).
