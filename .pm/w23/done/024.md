# Bank-account tools look the account up before authorizing: a `ledger.read` token gets "Account not found" from admin tools

Found by MCP QA on 2026-10-20 against `https://beancount.io` (OAuth tokens pinned to a synthetic QA ledger with no linked banks: one `ledger.read`, one `ledger.read ledger.write`; neither holds `ledger.admin`). This is the account-level sibling of `w23/004`, which `cc57dc6dd` fixed for `banks/{itemId}` only.

**Repro (account id `nope`, which exists nowhere):**

| Call | Token | Result | Expected |
| --- | --- | --- | --- |
| `mapBankAccount {account_id, ledger_account}` (admin) | read, read+write | `BAD_USER_INPUT` "Account not found" | `FORBIDDEN` (needs `ledger.admin`) |
| `setBankAccountCurrency {account_id, currency}` (admin) | read, read+write | same | `FORBIDDEN` |
| `listStagedBankTransactions {accountId}` | read | `BAD_USER_INPUT` "Account not found" | concealed `NOT_FOUND` "Bank connection not found" |
| `…/bank-transactions/suggested-categories?accountId=nope` | read+write | same | same |
| `importStagedBankTransactions {transactions:[{transaction_id:"nope",…}], dry_run:true}` (write) | read | `BAD_USER_INPUT` "Some transactions not found in database" | `FORBIDDEN` (needs `ledger.write`) |
| `discardStagedBankTransactions {transaction_ids:["nope"], dry_run:true}` (write) | read | same | `FORBIDDEN` |

The hint on all of them, "Fix the named argument…", sends the agent to fix an argument when the real problem is a missing scope.

**Root cause:** `backend-cluster/backend-v2/src/features/plaid/service/plaid-item-service.ts` loads `plaidAccount.getById(accountId)` globally and throws `BadUserInputError("Account not found")` before `authorizeBankAction`, at `getUnsyncedTransactionsForScope` (`:388-395`), `updateAccountMapping` (`:999-1002`) and `updateAccountCurrency` (`:1040-1043`). `plaid-sync-service.ts:624-627` (`getUnsyncedTransactionsForCategorization`, "PlaidAccount not found") does the same. So does `loadAuthorizedTransactionBatch` (`plaid-sync-service.ts:184-214`): it fetches the transactions and their accounts by id and only then calls `authorizeBankAction`, which is why a read-only token is told the transactions don't exist instead of `FORBIDDEN`. When the id does exist but belongs to someone else, these paths answer with "Unauthorized access to account" or the concealed `NOT_FOUND` instead, so the answer reveals whether an account id exists. That branch was traced in code, not exercised: the QA account has no banks.

**Fix:** as in `cc57dc6dd`, authorize `BANK_*` against the route's ledger first, so a missing scope is `FORBIDDEN` before any lookup. Then answer a missing account, or one on another ledger or user, with the same concealed `NOT_FOUND` "Bank connection not found". REST (`banks-handler.ts`), GraphQL (`plaid-resolver`) and MCP share these methods. Extend the plaid parity test with a missing account id and an under-scoped token on all three surfaces. Owner: backend-v2. Estimate: ~45m.

---

**Resolved 2026-10-20** — A shared `PlaidItemService.authorizedAccount` now backs the account-scoped bank operations: `updateAccountMapping` (MCP `mapBankAccount`, REST `PUT …/bank-accounts/{id}/mapping`, GraphQL `updatePlaidAccountMapping`), `updateAccountCurrency` (`setBankAccountCurrency`), and the `accountId` branch of staged-transaction listing and category suggestion. It authorizes the action against the route's ledger before any lookup, so a credential without the scope is `FORBIDDEN` whether or not the id exists. A missing account, or one on another ledger or user, then answers the concealed `NOT_FOUND` "Bank connection not found". The item-bound PDP decision still runs once the account is found, so chain verification and the audit record are unchanged. `PlaidSyncService.loadAuthorizedTransactionBatch` (`importStagedBankTransactions`, `discardStagedBankTransactions`) likewise authorizes against the ledger first, so a read-only token is `FORBIDDEN` instead of being told the transactions don't exist. An authorized caller still gets the existing "Some transactions not found" hint about `transactionId`, and a foreign transaction is concealed as `NOT_FOUND`. `getUnsyncedTransactionsForCategorization` has no production caller, so no surface reaches it, and it was left unchanged. `bank-item-read-parity.test.ts` (from `w23/004`) adds account mapping on REST, MCP and GraphQL through the real service and PDP: the ledger's account maps on all three; a missing id is `NOT_FOUND` on all three with no write; a `ledger.read ledger.write` token is `FORBIDDEN` on all three for an existing and a missing id, with zero account lookups. Reverting fails 2. The unit tests that pinned "Account not found", "Unauthorized access to …" and the lookup-first order now assert the concealed `NOT_FOUND` and authorize-first order. Native gates pass: typecheck, lint/Knip, 370 suites / 6406 tests, OpenAPI generation without drift. Shipped in the commit that moved this note (`backend-cluster/backend-v2`).
