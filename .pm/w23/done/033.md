# Structured `addLedgerEntries` writes tag, link, flag, account, currency and meta-key values unvalidated, so one entry can smuggle extra directives

**Severity:** major. A structured write API produces directives the caller never sent and reports "Added 1 entry". **Estimate:** 45–60 minutes including tests. **Owner:** `backend-cluster/ledger`, in `src/foundation/rustledger/journal-serialize.ts` and `entry-build.ts`, behind `POST /ledgers/{o}/{r}/entries` in `src/api/entries.ts`. That route serves REST `POST …/entries`, GraphQL and MCP `addLedgerEntries`, so all three surfaces are affected. **A1:** agents fill tags, links and meta from imported bank data. This is the hosted counterpart of the CLI fix w1/046.

## Repro (production, 2026-10-21, disposable QA ledger, OAuth `ledger.read ledger.write` token; removed byte-exact right after)

`addLedgerEntries` with one transaction whose `tags` is `["qa\n2026-03-20 note Assets:Cash \"qa-injected\"\n2026-03-20 *"]` and two balanced postings.

The result is `ok`, "Added 1 entry to main.bean. No new bean-check errors." `main.bean` gained:

```
2026-03-20 * "qa-tag" "qa" #qa
2026-03-20 note Assets:Cash "qa-injected"
2026-03-20 *
  Assets:Cash                                         -0.01 USD
  Expenses:Food:Coffee                                 0.01 USD
```

BQL over that date returns three entries: a transaction with no postings, the injected `note`, and a second transaction carrying the postings.

## Cause

`renderTransaction`, `tagsLinksSuffix`, `renderMetadata` and the other `directiveToText` cases interpolate these values raw:
- tags and links
- the transaction flag and posting flags
- account names
- currencies
- meta keys
- `custom_type`
- booking

Only payee, narration and string meta values pass through `escapeString`. The schemas in backend-v2 (`entries-handler.ts` `entriesBodySchema`) and in the MCP input accept them as plain strings. The projected bean-check passes because the smuggled text is valid Beancount. An `option`/`plugin` line, the w23/018 class, can be smuggled the same way.

## Fix

Validate each token against Beancount's lexer rules before rendering, and refuse anything else with `BAD_USER_INPUT` naming the field:
- account: `^[\p{Lu}][\p{L}\p{N}-]*(:[\p{Lu}\p{N}][\p{L}\p{N}-]*)+$`
- tag and link: `[A-Za-z0-9-_/.]+`
- flag: one of `*!&#?%PSTCURM` or `'X`
- currency: the commodity grammar
- meta key: `[a-z][A-Za-z0-9_-]*`

Do this in the ledger route so every surface inherits it. Mirror the patterns in the backend-v2 Zod schema so the MCP and OpenAPI schemas advertise them. As w1/046 did for the CLI, add a defense-in-depth check that each rendered entry parses back as exactly one directive.

Tests:
- A newline or space in each field is refused.
- Valid Unicode accounts still pass.
- A rendered entry that parses as two directives is refused.

Acceptance: the repro is refused and `main.bean` is unchanged.

**Resolved 2026-10-22** — The ledger's bulk-entries route (`backend-cluster/ledger/src/api/entries.ts`, behind REST `POST …/entries`, GraphQL, MCP `addLedgerEntries` and Plaid sync) now runs a new `assertEntryTokens` (`src/features/ledger/utils/entry-tokens.ts`) before reading any file. Every token the renderer writes unquoted is checked against Beancount's lexer rules: dates, transaction and posting flags (`*!&#?%PSTCURM`, `'X`, `txn`), tags and links, accounts, currencies (posting units and prices, amounts, `open` currencies, `commodity`/`price`, custom amounts), metadata keys, and custom account values. Anything else is refused as `BAD_USER_INPUT` "entry N: `<field>` `<value>` is not a valid `<kind>`". Non-ASCII stays allowed where Beancount's lexer allows it (`Assets:Café`, `资产:现金`, `#旅行`), but whitespace and control characters never are, including U+00A0 and U+2028. As a defense behind the token rules, each rendered entry must contain exactly one top-level line outside strings and comments (`isSingleDirective`, no WASM needed), or it is refused as "renders as more than one directive". The renderer now escapes the custom directive's type and its text, tag and link values, which it used to quote raw. The repro's injected tag is refused with no read and no commit. Deviation from the note: the patterns are not mirrored into backend-v2's Zod schemas. The ledger refusal already covers every surface and names the field, and repeating the account pattern across the `addLedgerEntries` schema would spend about 1 KB of the `tools/list` budget, which has roughly 2 KB left. Tests: `entry-tokens.test.ts` (account, flag and currency acceptance and refusal, Unicode, non-string tokens, custom values; `isSingleDirective` with multi-line strings, escapes, comments and injected lines), `entries-amount-syntax.test.ts` route cases (the repro and seven other fields refused before any read; bad tokens in `open`, `note` and `commodity`; Unicode accounts, tags, links and meta still written), and an `entry-build.test.ts` escaping case. Reverting the route and renderer fails 12. Gates: ledger typecheck, lint and 1576 of 1577 tests. The one failure was `file-request-limit.test.ts` (2 MiB body), which passes alone and touches nothing here. Shipped in the commit that moved this note (`backend-cluster/ledger`).
