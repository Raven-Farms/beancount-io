# Statement summaries silently drop every balance not in the stated currency: `conversion=units` net worth 715.58 vs 117,458 at value, and `conversion=EUR` with no EUR prices still says `valuation: "latest-price"`

**Severity:** minor-to-moderate. The summary shape is the default for REST and MCP and is what an agent quotes. With `conversion=units` (documented as "positions unconverted") or a currency the ledger can't price into, holdings in other commodities vanish from `assets`, `netWorth` and `byAccount`, and nothing in the result says anything was left out. **Estimate:** 30–45 minutes with tests. **Owner:** `backend-cluster/backend-v2` — `summarizeBalanceSheet` / `summarizeIncomeStatement` / `summarizeOverview` / `summarizeIntervalTotals` in `src/features/ledger/utils/report-summaries.ts` (`amount()` reads one currency key), behind REST `…/statements/*`, `…/overview`, `…/interval-totals` and the MCP resources of the same suffix. **A1.**

## Repro (production, 2026-10-21, account-wide OAuth `ledger.read` token, a QA-owned copy of the example ledger)

`beancount://<owner>/<name>/statements/balance-sheet?shape=summary&conversion=…`:

| conversion | currency | valuation | assets | netWorth |
| --- | --- | --- | --- | --- |
| (default) / `at_value` | USD | latest-price | 125581.84 | 117458.49 |
| `at_cost` | USD | cost | 114758.40 | 106635.05 |
| `units` | USD | units | **8838.93** | **715.58** |
| `EUR` (ledger has no EUR prices) | **USD** | **latest-price** | **8838.93** | **715.58** |

`shape=fava` for the same ledger shows the dropped holdings: `IRAUSD`, `VACHR` and the fund/stock positions sit beside `USD` in every balance map. The summary has no field naming them.

## Cause

`resolveCurrency` picks one currency (the requested one if present, else the most frequent), and `amount(balance, currency)` returns 0 for any other key, so non-stated currencies are summed as zero. `requestedCurrency("EUR")` is not found in the data, so the label falls back to USD while `valuation` is still derived from `conversion` alone. `docs/mcp.md` ("in one stated `currency`") states the single currency but not that the rest is discarded.

## Fix

Keep the single stated currency, but disclose what it excludes: add `otherCurrencies: { [currency]: number }` (or `omitted: [{ account, currency, number }]`) to each summary, and set `valuation` from what actually happened (`units` when a requested conversion currency had no prices, or refuse an unpriceable `conversion` currency with `BAD_USER_INPUT`). Document both in `docs/mcp.md` and the OpenAPI summary schema. Tests: a USD+stock ledger under `units` reports the stock under `otherCurrencies`; `conversion=EUR` without EUR prices is refused or labeled honestly; REST and MCP agree.

---

**Resolved 2026-10-22** — The summaries in `backend-cluster/backend-v2/src/features/ledger/utils/report-summaries.ts`, behind REST and MCP `statements/*`, `overview` and `interval-totals` with `shape=summary`, still report in one stated currency but no longer hide the rest. When the stated currency leaves something out, each summary carries `otherCurrencies`, a map from each other currency or commodity to the amount its headline number excludes, summed exactly and with zeros dropped. That is net worth (assets plus liabilities roots) on the balance sheet and the latest overview point, `net` on the income statement (same sign), and each interval's `total`. The field is omitted when nothing is left out, so existing single-currency results are unchanged. `conversion=units` on a ledger with stocks therefore lists `ITOT`/`VACHR` there instead of losing them from net worth. The balance sheet's `valuation` now reflects what happened: a requested conversion currency the data does not carry (no prices) converted nothing, so it reads `units`, not `latest-price`. `docs/mcp.md` documents both. GraphQL returns the raw payloads and is unaffected. Tests: five `report-summaries.test.ts` cases (units balance sheet with stocks, unpriceable EUR labelled `units` with what it left out, the field omitted when USD carries everything, income-statement net signed like `net`, overview and per-interval), plus updated parity expectations. `balance-summary-parity.test.ts` now says `units` for the unpriced-EUR request and states the other currency on both mixed-currency reads; `statement-parity.test.ts` states the fixture's EUR side. Reverting fails 5. Gates: typecheck, lint/Knip, full suite (only the environment-only `upstream-survival.test.ts` failed, see w23/027), OpenAPI unchanged.
