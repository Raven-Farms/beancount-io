# Guided setup writes account names and the title raw: a `blank@1` account name injects directives, and a title ending in `\` leaves the file unparseable

**Severity:** major (same class as w23/033, on ledger creation). **Estimate:** 30–45 minutes with tests. **Owner:** `backend-cluster/backend-v2` — `previewLedgerSetup` in `src/features/ledger/setup/build-ledger.ts` (REST, GraphQL and MCP `createLedger`/`previewLedgerSetup`). **A1/A2.**

## Repro (production, 2026-10-21, OAuth token with `ledger.admin`; preview only)

- `{"preset":"blank@1","accounts":[{"name":"Assets:Bank USD\n2020-01-01 open Assets:Evil"}]}` → `main.bean` contains `2026-10-21 open Assets:Bank USD` **and** `2020-01-01 open Assets:Evil USD`; `accounts` in the result lists the injected string as one account. A newline plus `option`/`plugin`/`include` works the same way.
- `{"preset":"blank@1","accounts":[{"name":"assets:lower"}]}` and `{"name":"Foo:Bar"}` are accepted and rendered as `open assets:lower USD` / `open Foo:Bar USD`, which beancount rejects.
- `{"preset":"personal@1","title":"Books\\"}` → `option "title" "Books\"`; beancount reads the escaped quote and the string runs into the next line: `Invalid token: 'operating_currency"'`.
- `{"title":"A \"quoted\" title"}` silently becomes `A quoted title`.

## Cause

Only non-blank presets restrict account names (to the catalog's allowed set); `blank@1` skips that check and the name is interpolated into `${openDate} open ${account.name} ${currency}`. The title is rendered as `"${title.replace(/"/g, "")}"`, which drops quotes but leaves backslashes and newlines.

## Fix

Validate every selected account against the account grammar (root in Assets/Liabilities/Equity/Income/Expenses, each component `[\p{Lu}\p{N}][\p{L}\p{N}-]*`) and refuse with `VALIDATION_FAILED` naming the account; escape the title with the same `\\`/`\"` escaping the ledger serializer uses instead of stripping quotes (and refuse control characters). Tests: newline, lowercase and bad-root account names refused on all three surfaces; a title with `"` and a trailing `\` round-trips through bean-check.

---

**Resolved 2026-10-22** — `previewLedgerSetup` (`backend-cluster/backend-v2/src/features/ledger/setup/build-ledger.ts`), the one builder behind REST, GraphQL and MCP `createLedger`/`previewLedgerSetup`, now checks every selected account against the account grammar before anything is rendered. That includes `blank@1`, which used to skip the catalog check. A name must start with one of the five default roots, each further component must start with an uppercase letter, a digit or a non-ASCII letter, and it may hold no whitespace or control character. Anything else is refused with `VALIDATION_FAILED` on `setup`, naming the account. `Assets:Bank USD\n2020-01-01 open Assets:Evil`, an injected `option` line, `assets:lower`, `Foo:Bar`, `Assets`, `Assets:bank` and `Assets:Bank Account` are refused, while `Assets:Café` and `Assets:现金` still open. The title is escaped (`\\`, `\"`) instead of having its quotes stripped, and a title holding a line break or other control character is refused. A scratch run through the real engine read the titles back exactly (`Books\`, `A "quoted" title`) with no errors, and loaded the Unicode accounts clean. Tests: 15 new `build-ledger.test.ts` cases: seven refused names, four accepted names, every account the catalog offers still accepted, both titles escaped to the exact `option` line, and a title with a newline refused. Reverting fails 10. Gates: typecheck, lint/Knip (the non-ASCII class is written `\P{ASCII}`, which `no-control-regex` accepts), 6711 tests, OpenAPI unchanged. The failures were the environment-only `upstream-survival.test.ts` (see w23/027) and the `archive-parity` timeout. Shipped in the commit that moved this note (`backend-cluster/backend-v2`).
