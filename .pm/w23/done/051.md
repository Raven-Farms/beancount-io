# `updateLedgerFiles` commits `new_string` through `String.replace`, so `$&`, `$$`, `` $` `` and `$'` are expanded — the preview shows the literal text, the commit writes something else

**Severity:** major. It silently corrupts ledger text: the dry-run diff the agent (or the user approving it) sees is not what gets committed, and "No new bean-check errors" still reports success. `$` is ordinary text in narrations, comments and meta values ("$$ fee", "paid $' …"). **Estimate:** 15–20 minutes with tests. **Owner:** `backend-cluster/backend-v2` — `src/features/ai-agent/tools/edit-ledger-files-tool.ts:268` (`cached.content.replace(f.old_string, f.new_string)`), which backs MCP `updateLedgerFiles` and the in-app AI agent's `editLedgerFiles`. **A1.**

## Repro (production, 2026-10-21, OAuth `ledger.read ledger.write` token pinned to the disposable QA ledger; file created and deleted by the probe)

1. `createLedgerFiles` `qa-20261021-dollar.bean` with `; qa-20261021 head\n; qa-20261021 TARGET\n; qa-20261021 tail\n`.
2. `updateLedgerFiles` `dry_run: true`, `old_string: "; qa-20261021 TARGET\n"`, `new_string: "; price $$5 and $& and $\` and $' end\n"`. The preview diff shows `+; price $$5 and $& and $\` and $' end` — the literal text.
3. Same call without `dry_run` → `ok`, "Committed 1 change(s) … No new bean-check errors."
4. `readLedgerFiles` returns:

```
; qa-20261021 head
; price $5 and ; qa-20261021 TARGET
 and ; qa-20261021 head
 and ; qa-20261021 tail
 end
; qa-20261021 tail
```

`$$` became `$`, `$&` the matched text, `` $` `` everything before it and `$'` everything after it.

## Cause

`String.prototype.replace(string, string)` interprets replacement patterns. The preview path (`projectContents`, line 153) uses `split(old).join(new)`, which is literal, so preview and commit disagree.

## Fix

Use a function replacement (`content.replace(old, () => new)`) or slice at the single match index (`indexOf` is already implied by the exactly-once check), and share one helper between the preview projection and the commit so they cannot diverge again. Tests: `new_string` containing each of `$$`, `$&`, `` $` ``, `$'` and `$1` commits byte-identical to the dry-run projection; reverting the fix fails them. Note the overlap with w23/028 (same function, multiple edits to one file): fix both on the same code path.
