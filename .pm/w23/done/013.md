# Statement summaries add balances as JavaScript floats: `netWorth: 906.5799999999999`, `net: 103335.53000000003`

Found by MCP QA on 2026-10-20 against `https://beancount.io`, reading the public `open_ledger/example`. REST `GET /api-gateway/v1/ledgers/{owner}/{name}/statements/…` returns the same summary.

**Repro:**

```text
resources/read beancount://open_ledger/example/statements/balance-sheet?conversion=units
  → {"assets": 3609.87, "liabilities": -2703.29, …, "netWorth": 906.5799999999999}
resources/read beancount://open_ledger/example/statements/income-statement
  → {…, "net": 103335.53000000003}
```

The default and `at_cost` balance sheets, `overview` and `interval-totals` happen to come out clean on this ledger. Which figure picks up noise depends on the data, so any ledger can hit it.

**Expected:** a summary total is exact to the decimals of its inputs, here `906.58` and `103335.53`. A client reading `netWorth` should never have to round. The ledger service sends decimal strings, and the summary should keep that precision.

**Root cause:** `backend-cluster/backend-v2/src/features/ledger/utils/report-summaries.ts`:

- `amount()` (`:144-149`) turns each decimal string into a `Number`.
- `netWorth: assets + liabilities` (`:268`) and `net: -(income + expenses)` (`:302`) then add them as floats. `total()` sums the same way.

`bignumber.js` is already a backend-v2 dependency.

**Fix:** sum with `BigNumber`, and emit the result as a JSON number from `BigNumber#toNumber()` after `decimalPlaces(maxInputScale)`, or switch the summary fields to decimal strings and document it. A number keeps the published schema; strings would need a doc and schema note. Add a test with `3609.87 + -2703.29`. This is the server-side counterpart of the dashboard's `w3/627`. Owner: backend-v2 (REST + MCP summaries; GraphQL's `shape=fava` values are strings and unaffected). Estimate: ~30m.

---

**Resolved 2026-10-20** — `report-summaries.ts` sums with `bignumber.js` (already a backend-v2 dependency) through one `sum()` helper. Hierarchy `total()` (balance plus `balance_children`), balance-sheet `netWorth` and income-statement `net` are now exact decimal sums. Each amount is the ledger's decimal string read as a number, and `String(n)` returns that decimal exactly, so the sum loses nothing and is still emitted as a JSON number. The published schema is unchanged, and REST and MCP summaries share the code. Single-value fields (`byAccount`, interval totals, overview series) were never sums and are unchanged; GraphQL's `shape=fava` strings are unaffected. `report-summaries.test.ts` adds cases where float addition is noisy: `3609.77 + 0.1` with `-2703.29` gives `assets` 3609.87 and `netWorth` 906.58, and `-(-1000.10 + 500.20)` gives `net` 499.9. The test asserts the float version really is noisy. Reverting the fix fails both. Native gates pass: typecheck, lint/Knip, 369 suites / 6376 tests, OpenAPI generation without drift. Shipped in the commit that moved this note (`backend-cluster/backend-v2`).
