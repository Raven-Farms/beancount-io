# Structured amounts like `.5` pass the decimal check but are written raw, so the entry fails as "parse errors in main.bean"

**Severity:** minor. **Estimate:** 15–20 minutes. **Owner:** `backend-cluster/ledger`, in `src/foundation/rustledger/entry-build.ts` (`DECIMAL_NUMBER` versus `toBeancountNumber`), behind `POST …/entries` (REST, GraphQL, MCP `addLedgerEntries`).

## Repro (production, 2026-10-21, disposable QA ledger)

`addLedgerEntries` with a transaction whose posting has `units: {number: ".5", currency: "USD"}` and an elided counterpart → `VALIDATION_FAILED` "adding these entries would introduce 1 new bean-check error: parse errors in main.bean". Nothing is written.

Controls on the same call:
- `"1e1"` is written as `10` (the exponent is expanded).
- `"5."` and `"+5"` are written as-is and load.
- `"1,000.00"`, `"NaN"`, `"0x10"` and `" 5 "` are refused with `BAD_USER_INPUT` "entry 0: postings[0].units.number … is not a decimal number".

## Cause

`DECIMAL_NUMBER` (`/^[+-]?(?:\d+(?:\.\d*)?|\.\d+)(?:[eE][+-]?\d+)?$/`) accepts a leading-dot fraction. `toBeancountNumber` rewrites only exponent forms and copies everything else verbatim, and Beancount's lexer can't read `.5`. The input check and the renderer disagree. The caller gets an opaque ledger parse error instead of either a normalized `0.5` or a field-level refusal.

## Fix

In `toBeancountNumber`, add the leading `0` for `.5` / `-.5` / `+.5`, keeping trailing zeros byte-identical as the comment requires. Alternatively, drop `\.\d+` from `DECIMAL_NUMBER`, so the field is refused by name. Normalizing is friendlier and matches what `1e1` already gets. Tests: `.5` and `-.5` write `0.5` and `-0.5` and load, and `5.` and `+5` are unchanged.

## Dedupe

Searched `.pm/**` for "is not a decimal number" and leading-dot amounts. The decimal guard came from an earlier fix for `(12.50)` and `abc`. No item covers its disagreement with the renderer.

---

**Resolved 2026-10-22** — `toBeancountNumber` (`backend-cluster/ledger/src/foundation/rustledger/entry-build.ts`), used for every structured amount behind REST `POST …/entries`, GraphQL and MCP `addLedgerEntries`, now writes a leading-dot fraction with its zero: `.5` becomes `0.5`, `-.5` becomes `-0.5`, `+.50` becomes `+0.50`. Ordinary decimals stay byte-identical (`5.`, `+5`, trailing zeros), and exponent forms are still expanded (`.5e1` becomes `5`). The decimal check and the renderer now agree. Tests: six `entry-build.test.ts` cases (the three leading-dot forms, one exponent, and `5.` and `+5` unchanged), plus an `entries-amount-syntax.test.ts` route case where `.5`/`-.5` postings commit as `0.5`/`-0.5`. Reverting fails 4. Gates: ledger typecheck, lint and 1610 tests. Shipped in the commit that moved this note (`backend-cluster/ledger`).
