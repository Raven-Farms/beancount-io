# BQL position cells drop the lot's acquisition date and label: `5 GLD {197.06 USD}` instead of `5 GLD {197.06 USD, 2015-09-15}`

Found by MCP QA on 2026-10-20 through differential testing. I ran the same queries on the public `open_ledger/example` source with hosted `runBqlQueryStructured`, and locally with beanquery 0.2.0 / beancount 3.2.3 from `cli/.venv`. Of 31 typical queries, 24 matched exactly. The position-rendering difference is the only one that loses information:

```text
SELECT date, account, position WHERE account ~ 'ETrade:GLD' ORDER BY date, account
  beanquery: 5 GLD {197.06 USD, 2015-09-15}
  hosted:    5 GLD {197.06 USD}
SELECT date, account, position, price WHERE price IS NOT NULL ORDER BY date LIMIT 20
  beanquery: -18 VHT {112.21 USD, 2015-11-13}
  hosted:    -18 VHT {112.21 USD}
```

`runBqlQuery`'s text, GraphQL `queryShell` and REST `query` all render cells through the same function, so they show the same loss.

**Why it matters (A1):** an agent preparing a lot-specific sale, or reading which lot a reduction hit, can't see the acquisition date. Two lots at the same per-unit cost become indistinguishable, and `{cost, date}` is exactly what a Beancount reduction has to name.

**Expected:** a position cell renders as Beancount writes it, `<units> {<number> <currency>[, <date>][, "<label>"]}`, matching beanquery's `str(Position)` and Fava's `PositionColumn`.

**Root cause:** `backend-cluster/ledger/src/foundation/rustledger/mappers.ts:77-79` (`formatCellValue`) formats `cell.cost` as `{number currency}` only. The engine's `CostValue` (`@rustledger/wasm` 0.24.0) carries `date?` and `label?`. `ledger-shell-mappers.ts:159-160` routes structured and text cells through it.

**Fix:** include the date and quoted label when present, and add a `mappers` unit test with a dated, labelled lot. The other differences found are deliberate or trivial: `null` shown as `""`, `[[0]]` for an aggregate over no rows, and 29 versus 28 significant digits on division. Owner: `backend-cluster/ledger`. Estimate: ~15m.

---

**Resolved 2026-10-20** — `formatCellValue` (`backend-cluster/ledger/src/foundation/rustledger/mappers.ts`) renders a units-with-cost cell as Beancount writes a lot: `<units> {<number> <currency>[, <date>][, "<label>"]}`, quoting the label as a JSON string. That matches beanquery's `str(Position)`. The real engine was confirmed to return `cost.date` and `cost.label`: `5 GLD {197.06 USD, "lot-a"}` bought on 2015-09-15 now renders `5 GLD {197.06 USD, 2015-09-15, "lot-a"}`. REST `query`, GraphQL `queryShell` and `runBqlQuery`'s text all pick this up through the shared cell formatter. Cost-less positions and lots without a date or label are unchanged. `mappers.test.ts` adds dated, dated-and-labelled, quote-escaped-label and null-field cases; reverting fails 3. `yarn verify:rustledger` adds the real-engine check. Inventory cells still list units only, as the engine's inventory value carries no cost. Native gates pass: lint/Knip, typecheck, build, 99 suites / 1407 tests, `verify:rustledger`. Shipped in the commit that moved this note (`backend-cluster/ledger`).
