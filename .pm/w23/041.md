# `appendLedgerText` separates `pushtag`/`poptag` (and `pushmeta`/`popmeta`) from the entries they wrap: the tag is silently dropped, or a dangling `pushtag` breaks the file

**Severity:** minor/major. The tag or metadata the caller asked for is silently lost on a reported-clean write. **Estimate:** 30–45 minutes including tests. **Owner:** `backend-cluster/backend-v2`, in `src/features/ledger/utils/directive-text.ts` (`parseDirectiveText`) and `insertDirectives`, behind the append workflow shared by MCP `appendLedgerText`, REST `POST …/directives/text` and GraphQL. **A1:** `pushtag #trip` … `poptag #trip` is the idiomatic Beancount way to tag a batch, and agents copying ledger style use it.

## Repro (production, 2026-10-21, disposable QA ledger, `dry_run: true`)

1. Text `pushtag #qa-trip` / a 2026-01-03 transaction / `poptag #qa-trip` → "Would add 3 directives to main.bean. No new bean-check errors." The diff inserts the **untagged** transaction after the 2026-01-01 entry (line 25) and appends an empty `pushtag #qa-trip` / `poptag #qa-trip` pair at the end of the file. The transaction never gets the tag.
2. The same text without `poptag` → the transaction is inserted untagged at line 25, `pushtag` is appended alone at the end, and the result reports "1 new bean-check error: parse errors in main.bean". A commit would be refused, but the preview's explanation doesn't name the cause.

## Cause

w23/018 deliberately kept `pushtag`/`poptag`/`pushmeta`/`popmeta` accepted. `insertDirectives` places each dated directive at its date position, while undated statements go to the end of the file (`appendedUnsorted` is empty here, yet they still land last). The tag stack is positional in Beancount, so moving the directives out from between the push and the pop removes their tags.

## Fix

Pick one rule and apply it on all surfaces:
- **Expand:** while parsing, apply the active pushed tags and metadata to each enclosed directive, rendering `#trip` inline and adding the meta lines. Then drop the push/pop statements, so date-ordered insertion keeps the meaning. **Recommended.**
- **Refuse:** reject push/pop statements with `BAD_USER_INPUT` "tag stacks are positional and appended entries are reordered; put `#tag` on each entry instead".

Either way, an unbalanced push is refused before projection. Tests:
- A balanced pair yields a tagged transaction at its date position, with no stray statements.
- An unbalanced push is refused, naming the line.
- `pushmeta` gets the same treatment.

## Dedupe

w23/018 (done) refused `option`/`plugin`/`include` and explicitly kept the tag and meta stack statements, which is this gap. Searched `.pm/**` for pushtag and pushmeta. No other item.
