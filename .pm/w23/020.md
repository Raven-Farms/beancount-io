# Hosted BQL: `BALANCES AT value` ignores `AT value`, and `BALANCES FROM <window>` fails with "No matching lot" (rustledger 0.24.0)

Found by MCP QA on 2026-10-20 through differential testing: hosted `runBqlQueryStructured` on the public `open_ledger/example` versus local beanquery 0.2.0 / beancount 3.2.3 on the same source. `BALANCES` and `BALANCES AT cost` match beanquery account for account (only the row order differs). These two don't:

| Query | beanquery | hosted |
| --- | --- | --- |
| `BALANCES AT value` | holdings at market, e.g. `Assets:US:ETrade:ITOT {USD: 8312.72}` | **units**, `{ITOT: 104}`, for all six holding accounts (the clause is ignored) |
| `BALANCES FROM year = 2016` (also `2017`, `FROM date >= 2016-06-01`) | rows | **`BAD_USER_INPUT` "Query execution error: evaluation error: No matching lot for VHT in Assets:US:ETrade:VHT"** |
| `SELECT account, sum(position) FROM year = 2016 GROUP BY account` | rows | rows (control) |
| `SELECT account, value(sum(position)) GROUP BY account` | values | values (control) |

**Engine reproducer, no network** (`@rustledger/wasm` 0.24.0, `queryMultiFile`). The ledger validates with no errors:

```beancount
2020-01-01 open Assets:Broker
2020-01-01 open Assets:Cash USD
2020-01-01 open Income:Gains USD
2020-01-02 * "buy lot1"
  Assets:Broker  9 VHT {113.91 USD, 2020-01-02}
  Assets:Cash
2020-02-02 * "buy lot2"
  Assets:Broker  18 VHT {112.21 USD, 2020-02-02}
  Assets:Cash
2021-01-10 * "sell lot2"
  Assets:Broker  -18 VHT {112.21 USD, 2020-02-02} @ 118.03 USD
  Assets:Cash   2124.54 USD
  Income:Gains
2021-02-10 * "buy lot3"
  Assets:Broker  4 VHT {118.03 USD, 2021-02-10}
  Assets:Cash
2021-03-10 * "sell lot1"
  Assets:Broker  -9 VHT {113.91 USD, 2020-01-02} @ 120.00 USD
  Assets:Cash   1080.00 USD
  Income:Gains
```

`BALANCES FROM year = 2021` → `No matching lot for VHT in Assets:Broker`. `SELECT account, sum(position) FROM year = 2021 GROUP BY account` returns rows. On a one-lot ledger with a price, `BALANCES AT value` returns `6 GLD`, while `value(sum(position))` returns `960 USD`.

**Why it matters (A1):** "balances for last year" and "balances at market value" are the first questions an agent asks of an investment ledger. One gives a misleading unit table labelled as values; the other refuses with an internal-sounding error and no workaround. A smaller related gap: `BALANCES FROM CLOSE ON 2016-01-01` omits beanquery's `Equity:Conversions:Current` row.

**Fix:**

1. Report both upstream to `rustledger/rustledger` with this reproducer, and bump when fixed. Don't reimplement BQL (`.pm/DO_NOT_DO.md`).
2. Meanwhile, in `backend-cluster/ledger`, make `BALANCES … AT value` fail with a hint to use `SELECT account, value(sum(position)) … GROUP BY account` rather than return units.
3. Map the `No matching lot` evaluation error to a hint suggesting the equivalent `SELECT … sum(position) FROM … GROUP BY account`.
4. Add both reproducers to `verify:rustledger`.

Owner: `backend-cluster/ledger`, plus an upstream report. **Severity:** major for `AT value`, which silently returns the wrong basis. Estimate: ~45m here.
