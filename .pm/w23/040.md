# Dynamic client registration accepts a `web` client whose redirect URI is plain `http://` on a non-loopback host

**Severity:** minor. This is a spec-conformance gap: authorization codes may be delivered over cleartext to a remote host. PKCE limits the damage. **Estimate:** 20–30 minutes including tests. **Owner:** `backend-cluster/backend-v2`, in `src/features/oauth/api/oidc-route.ts` (the oidc-provider configuration, via `extraClientMetadata` or a registration validator). **A1/A3:** MCP directory reviewers check the authorization server against the MCP authorization spec, whose redirect-URI rule this breaks.

## Repro (production, 2026-10-21, anonymous `POST https://beancount.io/api-gateway/oauth/reg`)

| `redirect_uris` | `application_type` | Result |
| --- | --- | --- |
| `http://qa-evil.example/cb` | `web` | **accepted**, `client_id` issued |
| `http://qa-evil.example/cb` | `native` | `invalid_redirect_uri` "… using http as a protocol can only use loopback addresses" |
| `javascript:…`, `data:…`, `https://…#frag` | either | `invalid_redirect_uri` (correct) |

The MCP authorization specification requires every redirect URI to be either a localhost URL or HTTPS. OAuth 2.1 and the OAuth security BCP likewise forbid cleartext redirects except loopback. Native registrations already follow the rule; `web` ones fall back to oidc-provider's defaults, which allow `http`.

One probe client from this run, named `qa-20261021-dcr-probe`, remains registered. The board can't name its id publicly, and nothing can delete a DCR client.

## Fix

Validate registration (DCR and CIMD documents alike): every `redirect_uri` must be `https:`, a loopback `http:` URI (`127.0.0.1`, `[::1]`, `localhost`), or, for native clients, a private-use scheme. Refuse anything else with `invalid_redirect_uri` "redirect URIs must use https unless they are loopback". The static Discourse client is already `https`. Tests: a `web` client with a remote `http` redirect is refused; `web` with `https` and `web` with loopback `http` are accepted; native behavior is unchanged.

## Dedupe

Searched `.pm/**` for `redirect_uri` together with http, https or loopback. w1/m30 and m31 (done) added the consent page's `loopback_only` label and CIMD support. w0/018 covers malformed OAuth links. None covers registration validation of `web` redirects.
