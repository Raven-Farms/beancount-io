# Activity feed accepts negative and fractional `offset`/`limit`: `limit=-1` returns 97 of 98 items, `offset=-3` returns the oldest two

**Severity:** minor. Paging contract violated on every surface; an agent paging with a computed value gets a wrong page that looks valid. **Estimate:** 20 minutes with tests. **Owner:** `backend-cluster/backend-v2` — `src/features/gitea/feed/api/feed-route.ts` (`feedQuery`, shared by REST `GET /api-gateway/v1/account/feed` and MCP `beancount://account/feed`) and `feed-resolver.types.ts` (`GetFeedArgs`, GraphQL `Float`). **A1.**

## Repro (production, 2026-10-21, account-wide OAuth `ledger.read` token)

`beancount://account/feed?…` on an account whose feed has `total: 98`:

| query | items | hasMore |
| --- | --- | --- |
| `limit=-1` | 97 (from the newest) | true |
| `limit=-90` | 8 | true |
| `offset=-3&limit=100` | 2 (the two **oldest**) | true |
| `offset=-1` | 0 | true |
| `offset=1.5&limit=2` | 2 | true |
| `limit=Infinity` | error "expected number, received number" |

## Cause

`feedQuery` is `z.coerce.number().default(…)` with no `int()`, `min` or `max`, and `GetFeedArgs` declares both as GraphQL `Number` (Float). `FeedService.getFeed` then does `allItems.slice(offset, offset + limit)`, so JavaScript's negative-index `slice` semantics leak through, and `hasMore = offset + limit < length` is true for any negative sum.

## Fix

`offset: z.coerce.number().int().min(0).default(0)`, `limit: z.coerce.number().int().min(1).max(100).default(10)` in `feedQuery`; `@Field(() => Int)` with the same bounds (or validate in the service) for GraphQL. Tests: `limit=-1`, `offset=-1`, `offset=1.5` and `limit=101` are `BAD_USER_INPUT` on REST, GraphQL and MCP; `offset=0&limit=10` unchanged.
