# `updateEntrySource` accepts `option`, `plugin` and `include` lines (or several directives) as one entry's replacement, and reports a "new hash" for an entry that no longer exists

**Severity:** minor (the w23/018 class, on the source-slice path). **Estimate:** 30–40 minutes including tests. **Owner:** `backend-cluster/ledger`, in `updateSourceSlice` in `src/features/ledger/service/ledger-journal-service.ts`. That path serves REST, GraphQL and MCP `updateEntrySource`. **A1:** the tool's contract is "Replace one entry's source text". An agent that pastes configuration, or a block holding two entries, gets an unrelated ledger change reported as an entry update.

## Repro (production, 2026-10-21, disposable QA ledger; temporary included `qa-` file, removed afterwards)

1. Take a transaction's `entryHash` and `sha256sum` from `getEntryContext`.
2. `updateEntrySource {entryHash, sha256sum, newContent: "option \"title\" \"qa-option\""}` → `ok`, "Updated entry `<h>` (new hash `<h>`). No new bean-check errors.". The transaction is gone from the file, which now begins `option "title" "qa-option"`. The returned `newEntryHash` names no entry.
3. Control: `newContent: "include \"main.bean\""` is refused, but only because it creates an include cycle and bean-check reports an error. An `include` of any other file would have committed.

## Cause

`updateSourceSlice` splices `newContent + "\n"` over the slice and checks the projection for new bean-check errors. Nothing checks that `newContent` parses as exactly one dated directive. w23/018 added that rule to `parseDirectiveText` for the append path only.

## Fix

Before splicing, parse `newContent` with the engine. Refuse with `BAD_USER_INPUT` on field `newContent` unless it is exactly one dated directive, plus the indented postings and metadata that belong to it. Reuse 018's message for `option`/`plugin`/`include` ("configures the ledger and is not an entry; use `updateLedgerFiles`"). For more than one directive, say "`newContent` holds N entries; edit them one at a time or use `updateLedgerFiles`". Refuse an empty `newContent` too, and point to `deleteEntrySource`, unless empty is already refused.

Tests: an `option`, an `include`, two transactions and an empty string are each refused with the file unchanged, and an ordinary one-entry edit still commits.
