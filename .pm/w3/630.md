# A mistyped search value turns pages into HTTP 500: `?tab=follower`, `?editMode=1`, `?lineNumber=12a`, `/auth/login?reason=foo`, `/ask?mode=Agent`

**Severity:** minor. It's a server-error response for an ordinary typo, on public and sign-in pages. **Estimate:** 45–60 minutes for a shared tolerant-schema helper, the listed routes and SSR tests. **Owner:** `dashboard` (`routes/*.tsx` `validateSearch`, `features/user-profile/lib/search.ts`, a helper beside `common/lib/ledger-search-params/schema.ts`). **A2/A3:** these routes validate search params with strict zod schemas (`schema.parse(search)` or a bare schema). Any value of the wrong type or outside an enum throws `SearchParamError` during SSR, so the response is **HTTP 500**, served by the error boundary ("Something went wrong" / "An unexpected error occurred"). The trigger is a link someone typed or edited: `editMode=1` instead of `true`, a capitalised tab, an unknown login `reason`. w3/120, w3/131 and w3/164 already moved Accounts, Journal and the profile list's other keys to tolerant coercion, and these keys were left strict.

## Reproduction

Local HEAD (`yarn dev`, pointed at the production API), `curl` for status; production `https://beancount.io` where marked. Read-only.

| request | HEAD | production |
| --- | --- | --- |
| `/ledger/open_ledger?tab=follower` (or `Followers`) | **500** | **500** |
| `/ledger/open_ledger?tab=followers` (control) | 200 | — |
| `/auth/login?reason=foo` | **500** | **500** |
| `/auth/login?next=123` or `?next=["x"]` | **500** | **500** |
| `/auth/sign-up?next=123`, `?withDefaultLedger=1` | **500** | — |
| `/ledger/open_ledger/example/files/blob/main/README.md?editMode=1` (or `=yes`) | **500** | 500 for `editMode=123` |
| `…/README.md?lineNumber=12a` | **500** | — |
| `…/README.md?editMode=true&lineNumber=12` (control) | 200 | — |
| `/ledger/open_ledger/example/ask?mode=x` (or `Agent`) | **500** | — |
| `/ledger/open_ledger/example/files/upload/main?dirPath=123` | **500** | — |
| `/ledger/open_ledger/example/query?query=123` (or `true`, `null`, `[1]`) | client error boundary ("This section couldn't be displayed"); route is `ssr: false` | — |
| `/ledger/open_ledger/example/files/content?path=123` | client error boundary | — |

The console shows `SearchParamError` thrown from the router's search validation, then `[ErrorBoundary] React error caught`. Ledger filter keys (`time`, `account`, `filter`), Journal `offset`, Accounts `type`/`search`, report `view`/`interval`/`conversion` and the profile's `q`/`sort`/`show` all survive the same fuzzing.

## Root cause

Strict schemas without fallbacks:

- `routes/auth.login.index.tsx:7–15`: `next: z.string()`, `reason: z.enum(["expired"])`, `parse`.
- `routes/auth.sign-up.tsx`: `next`, `withDefaultLedger: z.boolean()`.
- `routes/ledger.$ledgerOwner.$ledgerName.files.blob.$branch.$.tsx:6–9`: `editMode: z.boolean()`, `lineNumber: z.number()`. The same applies in `files.content.tsx` (`type: z.enum([...])`, `editMode`, `lineNumber`, `path`).
- `routes/ledger.$ledgerOwner.$ledgerName.files.upload.$branch.$.tsx:13`: `dirPath`.
- `routes/ledger.$ledgerOwner.$ledgerName.ask.tsx:8`: `mode: z.enum(["sandbox","agent"])`.
- `routes/ledger.$ledgerOwner.$ledgerName.query.tsx:6–12`: `query: z.string()`.
- `features/user-profile/lib/search.ts:58–63`: `tab: z.enum(USER_PROFILE_TABS)`, deliberately "keeps its original strict validation".

TanStack Router's default search parsing JSON-decodes values, so `1`, `123` and `true` arrive as numbers and booleans, and the strict types reject them.

## Fix

Add one shared tolerant pattern, field by field: `.catch(undefined)` (or `z.unknown()` plus a coercer, as the profile list and ledger filters already do), so an unusable value is dropped and the page renders its default. Coerce the obvious spellings: `editMode=1|yes` → `true`, a numeric-string `lineNumber`, enum values case-insensitively, and a numeric or JSON `query`/`next`/`path` back to its string form (or drop it). Unsafe `next` values still go through `getSafeReturnPath`. Apply it to every route listed. Keep strict behavior only where a wrong value must not render (none of the above qualifies).

Acceptance: every request in the table returns 200 with the default view (`tab=follower` shows the Ledgers tab, `reason=foo` shows the normal sign-in, `editMode=1` opens edit mode for a writer and is ignored for a reader, `query=123` shows the query `123` or an empty editor). Valid values behave exactly as today. A route-level test fuzzes each key with `123`, `true`, `[1]`, `{"a":1}` and a misspelled enum and asserts no `SearchParamError` escapes. Dashboard gates pass.
