# Stop the server redirect loop for paths containing an encoded `<`, `>`, `"`, `{`, `}` or backtick

**Severity:** major. Any such URL is unopenable: the browser shows `ERR_TOO_MANY_REDIRECTS`. **Estimate:** 45–60 minutes including an SSR request test. **Owner:** `dashboard` (`src/server.ts` / `src/router.tsx`), with an upstream report to TanStack Router. **A2:** a ledger file or document whose name contains `{`, `}`, `"` or a backtick (for example `documents/{2026}-receipt.pdf`) can't be opened from Files, and a shared link to it fails with a browser error page instead of the app.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `ce83f82b`. Read-only, anonymous `curl` and the QA-owned headless Chromium.

```
GET /ledger/open_ledger/example/account/Assets:US:a%3Cb   → 307  location: /ledger/open_ledger/example/account/Assets:US:a<b
GET /ledger/open_ledger/example/files/tree/main/a%3Cb      → 307  location: …/files/tree/main/a<b
GET /ledger/open_ledger/ex%3Cample                         → 307  location: /ledger/open_ledger/ex<ample
GET /u%3Cx                                                 → 307  location: /u<x
```

The client re-encodes the raw character, sends `%3C` again, and gets another 307. Chromium stops with `net::ERR_TOO_MANY_REDIRECTS` (`page.goto('/ledger/open_ledger/example/files/blob/main/docs%7B2026%7D.pdf')`). The same happens for `%3E` `>`, `%22` `"`, `%7B` `{`, and `%60` backtick, on every route checked: account, entry, commit, files tree/blob, ledger name, and profile. Controls that work: `%20` (space), `%2F`, `%7C` `|`, `%5E` `^`, `%5C` `\`, and non-ASCII (`Caf%C3%A9`) all return 200.

## Root cause

Upstream `@tanstack/router-core` (installed 1.167.0). On the server, `router.beforeLoad` (`dist/esm/router.js:668–684`) rebuilds the location from the decoded pathname and redirects whenever `latestLocation.publicHref !== nextLocation.publicHref`. The rebuild re-encodes paths with `encodePathLikeUrl` (`dist/esm/utils.js:239–242`), which only encodes whitespace and non-ASCII. So the decoded `<` stays raw in the canonical href while the request's href has `%3C`. They never match, and the redirect points at a URL the browser must re-encode. The latest release (1.171.37) moved the check to `load-server.js:546–557` but keeps the same comparison and the same `encodePathLikeUrl`. An upgrade alone is not expected to fix it (unverified by running).

## Fix

Normalize the request before the router sees it, so the incoming and canonical hrefs agree. In the dashboard's server entry (`src/server.ts`), or as a router `rewrite.input`, re-encode only the characters `encodePathLikeUrl` leaves raw, to the form the router itself emits. The aim is that the canonical check compares like with like and issues no redirect. Never emit a `Location` containing raw `<>"{}` or a backtick. Keep the existing canonical redirects that do terminate (for example trailing-slash or search normalization). File the minimal reproduction upstream with TanStack Router and link it here, so the workaround can be removed once fixed. Don't patch or vendor `node_modules`.

Acceptance: each URL above returns 200 (or the route's honest not-found) with no `Location` header, in a single request. A file named `{2026}.pdf` in a synthetic ledger opens from Files. A server-side test drives a request with each of `%3C %3E %22 %7B %7D %60` through the router and asserts no redirect. Dashboard gates pass.
