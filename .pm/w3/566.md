# Ledger Settings rename accepts any text, silently saves a different slug (`ünï` → `n`), and turns "name already exists" into a generic error

**Severity:** minor. **Estimate:** 30–45 minutes, reusing Create Ledger's slug helpers. **Owner:** `dashboard` (`features/ledger-data/settings/general-settings-section/index.tsx`, `features/ledger-list/components/ledger-form.tsx` helpers, settings locales). **A2:** renaming a ledger changes its URL, git remote and every agent's ledger id. Create Ledger shows the slug a name will become and refuses names with no usable characters (w0/023). The rename field does neither. Typing `Mÿ Bööks` or `ünï` enables **Save**. The server then slugifies to `m-bks` / `n` and renames the ledger to that, with only "Settings updated" as feedback. A clash with another ledger's name comes back as "Some of the information provided is invalid", not the server's specific message.

## Reproduction

Local HEAD (`yarn dev`, pointed at the production API), signed-in owner of a synthetic ledger, headless Chromium 1440×1000. **Nothing was saved.** Each value was typed and the field restored.

1. `/ledger/<owner>/<ledger>/settings` → **Ledger Name**.
2. **Save** is enabled, with no inline message, for: `mcp agent eval`, `../x`, a 120-character name, `MCP-Agent-Eval`, `.git`, `ünï`, and the names of the owner's other ledgers (`example`, `my-book2`). It is disabled only for empty and unchanged values.
3. What the server would do, from source (`backend-cluster/ledger/src/api/ledgers.ts:252–290`, `shared/ledger-name.ts:12–64`): slugify (lowercase, spaces → `-`, drop everything outside `[a-z0-9_-]`), then validate. So `ünï` → `n`, `../x` → `x`, `MCP-Agent-Eval` → `mcp-agent-eval` (a no-op rename), `.git` → `git`, 120 chars → "too long" error, an existing name → `A ledger with the name 'example' already exists. Please choose a different name.` (`BAD_USER_INPUT`).
4. The dashboard catch (`general-settings-section/index.tsx:116`) shows `formatError(error)`, which maps every `BAD_USER_INPUT` to the generic "Some of the information provided is invalid. Please check and try again." The server's reason is never shown.

## Root cause

The rename form keeps a plain `useState` string and enables Save on `ledgerName.trim() !== ledger.name` (`:78–83`, `:120`, `:180`), sending the raw text. Create Ledger uses `slugifyLedgerName` with a preview (`ledger-form.tsx:30–37, 72–79, 148–156`) that mirrors the server's slugify. That helper isn't shared with Settings.

## Fix

Move `slugifyLedgerName` (and its preview) into a shared place, and use it in the rename field. Show "Will be renamed to `<slug>`" whenever the slug differs from the input. Disable Save when the slug is empty, longer than 100 characters, or equal to the current name, or when it matches another ledger the user owns (the ledger list is already cached), with inline localized messages. Map the server's duplicate-name and too-long refusals to specific localized messages instead of the generic bad-input text. Keep the server as the authority. The client check is for feedback only.

Acceptance: typing `ünï` shows the `n` preview, and typing `example` shows "already exists" with Save disabled. `My Books` previews `my-books` and saves it. A 120-character name shows the length message. Rendered tests cover the preview, the duplicate and the server-error mapping. Dashboard gates pass.
