# Give account Settings pages a page heading, and Danger Zone any heading at all

**Severity:** minor (accessibility; WCAG 1.3.1 Info and Relationships, 2.4.6 Headings and Labels). **Estimate:** 25–35 minutes including a rendered heading test. **Owner:** `dashboard` (`features/user-settings/pages/general/index.tsx`, `ssh-keys/index.tsx`, `danger-zone/index.tsx`, `general/danger-zone-section.tsx`). **A2:** screen-reader users move through pages by headings. Three of the four account Settings pages have no `<h1>`, and Danger Zone, the page that deletes an account, has no heading at all, so its title and the "Delete Account" section are announced as plain text.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `ce83f82b`. QA-owned headless Chromium, 1440×1000, en-US, signed in. Read-only: nothing was deleted or saved.

Heading inventory (`h1–h4, [role=heading]`) after each page settles:

| Route | `<h1>` | All headings |
| --- | --- | --- |
| `/settings/api-keys` (control) | "Personal access tokens" | h1 + one heading per token |
| `/settings/general` | **none** | Growth, Usage, Upgrade Your Plan, Billing |
| `/settings/ssh-keys` | **none** | … |
| `/settings/danger-zone` | **none** | **none.** The page reads "Danger Zone · Irreversible and destructive actions · Delete Account · Permanently delete your account…", all as text |

## Root cause

- The settings layout (`features/user-settings/pages/layout.tsx:52–61`) renders only a tab `<nav>` with `aria-current`. Each page must supply its own `<h1>`. Only `api-keys/index.tsx:30` does.
- Section titles use `CardTitle` (`common/components/ui/card.tsx:31–37`), which renders a `<div>`. Danger Zone (`danger-zone/index.tsx` → `general/danger-zone-section.tsx`) and parts of General therefore contribute no headings.

## Fix

Give General, SSH Keys and Danger Zone a visible `<h1>` matching the active tab's label, following the API keys page (or render the active tab's label as the `<h1>` once in the layout and drop the per-page one). Make their section titles real headings (`<h2>`), e.g. by rendering a heading element inside `CardTitle` for these sections. Don't change the shared `CardTitle` primitive globally; other cards rely on its `div`. Keep the visual design.

Acceptance: each `/settings/*` page has exactly one `<h1>` naming the page. Danger Zone exposes `h1 "Danger Zone"` and `h2 "Delete Account"`. General's and SSH Keys' sections are `h2`. A rendered test per page asserts the heading outline. Dashboard gates pass.
