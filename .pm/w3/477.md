# Stop AI file parsing from inventing transaction descriptions that aren't in the source

**Severity:** major (data integrity: invented text becomes ledger narration). **Estimate:** 50–60 minutes including a grounding test. **Owner:** `backend-cluster/backend-v2` (`src/features/llm/utils/extract-transactions-from-file/prompts.ts`, `llm-service.ts`). The service is shared, so GraphQL `parseFile`, REST, and the MCP `parseFile` tool get the fix together. **A1/A2:** Smart Import's AI fallback writes plausible but fictional narrations ("Grocery purchase", "Payroll deposit") for rows whose source has no description. It also rewrites the source's own words ("Gehalt" → "Salary payment"). A user who accepts the preview books text their bank never produced, and nothing marks it as generated.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `ce83f82b`. QA-owned headless Chromium, ledger owner, `/ledger/<owner>/<ledger>/import`. Preview only: every non-parse mutation was blocked by a route guard (0 fired), and nothing was imported.

Synthetic files (no description/memo column except where noted):

| File | Source columns | `ParseFile` `description` returned | Shown in preview |
| --- | --- | --- | --- |
| `debit-credit.csv` | `Transaction Date,Payee,Debit,Credit` (`QA Synthetic Grocer`, `QA Synthetic Payroll`) | **"Grocery purchase"**, **"Payroll deposit"** | yes. The client CSV parser found no valid rows and fell back to `ParseFile` |
| `eu-semicolon.csv` | `Date;Description;Amount` with `QA Synthetic Gehalt` | **"Salary payment"** for the Gehalt row (the Bäckerei row kept its text) | yes |
| `us-dates.csv` | `Date,Description,Amount` (`QA Synthetic Coffee`, `QA Synthetic Refund`) | **"Coffee purchase"**, **"Refund received"** | no. The client parser handled this file, so its source text won |

The `ParseFile` GraphQL response carries the invented strings directly (e.g. `{"payee":"QA Synthetic Grocer","description":"Grocery purchase","amount":-23.1}`), so this is the server's output, not a client rendering.

## Root cause

The extraction prompt asks for generated prose rather than extracted text. `prompts.ts:56–64` ("Provide useful context … Include original memo if available"), `:138–143` ("Meaningful description with context"), and the per-row rule `:24` ("Transaction details/memo (concise but informative)") never say to leave the field empty when the source has no memo, or to keep the source's wording and language. Nothing after the model call checks that `description` is grounded in the uploaded text.

## Fix

- Prompt: `description` must be the row's memo/description text **as written** (trimmed; no translation, no summarizing). It must be `""` when the row has none. `payee` may be normalized as today, but not translated. Keep the bill/receipt single-transaction mode's summary behaviour explicitly separate if it is wanted there.
- Grounding guard in `llm-service.ts`: for CSV/OFX/QIF/text inputs, drop any `description` whose normalized tokens don't appear in the source row's text (or the file text). Leave the field empty rather than keep invented text. Record a count in the parse result or logs so drift is visible.
- Dashboard (follow-on, optional): label rows produced by the AI fallback in the preview so users know to review them.

Acceptance: re-running the three files above returns `description: ""` for rows without a memo, and `"QA Synthetic Gehalt"` unchanged (not translated). Payees and amounts are unchanged. A backend test with a mocked model that returns invented and translated descriptions shows the guard blanking them, and a prompt snapshot test pins the new rules. GraphQL, REST and MCP `parseFile` parity tests still pass. Backend-v2 checks pass.
