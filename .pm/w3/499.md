# New Entry sends a transaction that doesn't balance, with no warning

**Severity:** minor. It may be major if the server writes it: the user's ledger would then fail validation. **Estimate:** 30–45 minutes including form tests. **Owner:** `dashboard` (`features/journal/components/new-directive-dialog/transaction-form.tsx`, `transaction-auto-balance.ts`). Server-side handling should be confirmed in `backend-cluster/backend-v2` / `ledger` (`BulkEntries`). **A2:** Beancount rejects a transaction whose postings don't sum to zero per currency. The form already computes that sum to show an "auto" amount, but when every amount is filled it doesn't check the result and submits 10 USD vs −9 USD as typed.

## Live reproduction

Production `https://beancount.io`, 2026-10-16, local main at the time of filing. QA-owned headless Chromium, 1440×1000, ledger owner, `/ledger/<owner>/<ledger>/journal` → New Entry → Transaction. A route guard aborted every mutation, so nothing was written.

1. Narration "qa-20261016 synthetic"; posting 1 `Expenses:Food:Groceries` **10** USD; posting 2 `Assets:US:BofA:Checking` **−9** USD (typed key by key; `input[name="postings.1.amount"]` reads `-9`).
2. **Create Transaction Entry** is enabled, there is no inline message, and pressing it sends `BulkEntries` with postings `[{Groceries 10 USD}, {Checking -9 USD}]`, a 1 USD residual.
3. Controls: leaving one amount blank auto-balances it correctly (−10). Leaving both blank shows "Amount is required" and sends nothing.

Server outcome **unverified**: the request was blocked, so whether `BulkEntries` refuses the entry or writes it and reports validation errors was not observed.

## Root cause

`transaction-form.tsx:187–240` (`onSubmit`) runs `computeAutoBalance` only to fill **empty** amounts (`applyAutoBalanceToPostings`, `transaction-auto-balance.ts:83–101`) and checks for unresolved amounts and fewer than two postings. It never checks that the fully specified postings net to zero per currency (within Beancount's tolerance), even though `computeAutoBalance` already sums each currency group (`:36–80`).

## Fix

Before submitting, when no posting is left to infer, compute each currency's residual (decimal-exact, as the auto-balance code does). If any is non-zero beyond the inferred tolerance, block submission with an inline message such as "Postings don't balance: 1 USD left over. Adjust an amount or clear one to auto-balance it", attached to the amounts. Keep postings with cost/price annotations out of this check if the form ever supports them. Separately, confirm with one authorized disposable write what `BulkEntries` does with an unbalanced transaction, and file a server issue if it writes it silently.

Acceptance: 10 / −9 USD shows the message and sends nothing. 10 / −10 and 10 / blank still submit. Mixed currencies are checked per currency. Form tests cover each case. Dashboard gates pass. The server's behaviour is recorded.
