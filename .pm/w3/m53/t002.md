## Objective

Replace the two fixed hosted file sets with a pure builder that turns a setup specification into Beancount files, called by both manual creation and signup provisioning.

## Context

- `CreateLedgerCommand` in `backend-cluster/backend-v2/src/features/ledger/workflow/ledger-workflow.types.ts` carries only `name`, `description`, `private`, and `template` today.
- The existing creation lock, tier ledger limit, and authorization in `createLedger` / the shared create operation must be preserved unchanged.
- ADR021: `setup` and `template` are mutually exclusive; an explicit invalid value fails and nothing is created; the builder never mutates a shared template or regenerates an existing ledger.

## Steps

1. Add the optional `setup` object to `CreateLedgerCommand` with ADR021's validation rules.
2. Implement the pure builder from the t001 catalog; keep Starter and Sample behavior for callers that omit `setup`.
3. Route manual creation and `createDefaultLedger` signup provisioning through the builder, keeping lock, limit, and authorization paths intact.

## Files

- `backend-cluster/backend-v2/src/features/ledger/workflow/`
- `backend-cluster/backend-v2/src/features/ledger/utils/ledger-template.ts`
- `backend-cluster/backend-v2/src/features/auth/service/auth-service.ts`

## Acceptance criteria

- [ ] A `personal@1` spec with a `known` opening balance produces the fixture's files exactly.
- [ ] Invalid specs create nothing and return the same validation error shape as other refused creates.
- [ ] Existing Starter, Sample, and signup tests still pass.

- Public API inputs (t003) and CLI consumption (t004).
