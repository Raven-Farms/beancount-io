## Objective

Expose the setup specification, idempotent creation, and preview-without-creating on all three hosted surfaces with identical inputs, results, and failures.

## Context

- Follow the required API parity workflow in `backend-cluster/backend-v2/AGENTS.md`: identify counterparts in `VERB_TABLE` / `op-class.ts` first; eligible parity gaps stay at zero.
- The MCP `manageLedgers` lifecycle input is a separately declared strict object and does not inherit new create fields automatically (ADR021).
- `setup` is creation-only: update inputs must omit it the way they omit `template`.

## Steps

1. Add `setup` and `requestId` to the REST create input, the GraphQL `CreateLedgerInput`, and the MCP lifecycle tool input, all re-parsing through one validation path.
2. Add the preview operation (generated files, account list, validation result) as a new REST route, GraphQL field, and MCP branch executing the same workflow method.
3. Make create idempotent on `requestId` per caller; a replay returns the original ledger instead of creating a second one.
