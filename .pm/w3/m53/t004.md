## Objective

Give the CLI the same preset catalog as a generated, drift-checked copy so local and hosted creation build the same books.

## Context

- `bea init` (`cli/src/cli/commands/init.py`, engine in `cli/src/bea_engine/initiating.py`) writes a fixed `Personal ledger` chart today and must keep accepting any syntactically valid currency when no preset is passed (ADR021).
- `bea cloud ledger create` (`cli/src/cli/commands/cloud/ledger/`) sends only name, description, and privacy today.
- Packages must not import each other; the CLI holds a generated copy with a drift check, per ADR021.

## Steps

1. Generate the CLI's catalog copy from the t001 source and add the drift check to the CLI's checks.
2. Add preset selection to `bea init`, building files through the same fixture expectations.
3. Send `setup` and `requestId` from `bea cloud ledger create`.

## Files

- `cli/src/cli/commands/init.py`
- `cli/src/bea_engine/initiating.py`
- `cli/src/cli/commands/cloud/ledger/app.py`
- `cli/src/cli/commands/cloud/ledger/manager.py`

## Acceptance criteria

- [ ] `bea init` with `personal@1` produces files whose accounting results match the hosted fixture.
- [ ] Editing the canonical catalog without regenerating fails the drift check.
- [ ] `bea init` without a preset behaves exactly as before, including non-ISO currency symbols.

## Out of scope

- Local-to-hosted transfer of existing ledgers (deliberately excluded; see the anti-goal on half-self-hosted seams in `.pm/DO_NOT_DO.md`).
