## Objective

Define the one canonical, versioned catalog every consumer copies: the eight presets, the currency tables, and spec-to-files conformance fixtures.

## Context

- [ADR021](../../../docs/adrs/ADR021-backend-v2-ledger-creation-experience.md) fixes the preset IDs (`personal@1`, `freelance@1`, `business@1`, `portfolio@1`, `rental@1`, `shared-expenses@1`, `community@1`, `blank@1`), the setup fields, and the rule that packages hold generated copies with a drift check rather than importing each other.
- [PRFAQ001 Appendix A](../../../docs/prfaqs/PRFAQ001-ledger-creation.md) is the delivery contract for preset contents and acceptance scenarios.
- No shared currency list exists in the repository today.

## Steps

1. Author the catalog: per preset, account groups, zero-to-two optional questions and their effect, category meanings, first-result task, teaching examples, and metadata keys for opening-balance status and demo identity.
2. Add the two currency tables: active ISO 4217 alphabetic codes, and region-to-currency rows only where CLDR lists exactly one current legal-tender currency.
3. Write conformance fixtures pairing a setup specification with expected files and report values, covering each preset, a non-USD currency, and all three opening states.

## Files

- Catalog source and fixtures (location settled in this task, beside the backend builder it feeds)
- `docs/adrs/ADR021-backend-v2-ledger-creation-experience.md` (record the frozen location)

## Acceptance criteria

- [ ] Every preset in ADR021 has a versioned catalog entry and at least one conformance fixture.
- [ ] Currency tables match the ADR021 rules; a region with zero or several currencies has no row.
- [ ] Fixtures distinguish `unknown`, `zero`, and `known` opening states.

## Out of scope

- The builder (t002), API changes (t003), and any client UI (m54).
