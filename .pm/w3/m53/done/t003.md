## Objective

Expose the setup specification, idempotent creation, and preview-without-creating on all three hosted surfaces with identical inputs, results, and failures.

## Context

- Follow the required API parity workflow in `backend-cluster/backend-v2/AGENTS.md`: identify counterparts in `VERB_TABLE` / `op-class.ts` first; eligible parity gaps stay at zero.
- The MCP `manageLedgers` lifecycle input is a separately declared strict object and does not inherit new create fields automatically (ADR021).
- `setup` is creation-only: update inputs must omit it the way they omit `template`.

## Steps

1. Add `setup` and `requestId` to the REST create input, the GraphQL `CreateLedgerInput`, and the MCP lifecycle tool input, all re-parsing through one validation path.
2. Add the preview operation (generated files, account list, validation result) as a new REST route, GraphQL field, and MCP branch executing the same workflow method.
3. Make create idempotent on `requestId` per caller; a replay returns the original ledger instead of creating a second one.

## Evidence (2026-10-20)

- REST: `setup` (preset enum enumerated in the schema) and `requestId` on `ledgerCreateInput`; new `POST /api-gateway/v1/ledgers/preview` route returning files, accounts, and validation. GraphQL: `LedgerSetupInput`/`LedgerSetupAccountInput` input types, `LedgerSetupPreset`/`LedgerOpeningState` enums, `setup` + `requestId` on `CreateLedgerInput`, and `Query.previewLedgerSetup`. MCP: `createLedger` inherits the same REST input (including setup and requestId), plus the 44th tool `previewLedgerSetup`. All three delegate to `createLedger` / `previewLedgerSetup` on the one workflow under `LEDGER_CREATE`; the preview verb is registered in `VERB_TABLE` with all three bindings.
- Idempotency: inside the existing per-user lock, `(user, requestId)` records live in the strict Redis-backed store (`CACHE_KEYS.ledger.createRequestByUserAndId`, 24h TTL) wired from the composition root's cache helper. Same id + same request returns the original ledger; same id + different request is a validation error; a repeat while the first attempt runs is a conflict. Focused regression tests for all three outcomes plus setup creation and preview live in `ledger-workflow.test.ts` ("setup and idempotent creation").
- Parity gates: `yarn test` full suite passes (6,266 tests), including `surface-parity` at zero eligible gaps, `op-class-coverage` (82 queries, 44 tools, with the count comments updated for this verb/tool), and the OpenAPI snapshot regenerated by `yarn generate-v1-openapi`. The MCP tool-list byte budget was raised to 104 KB with the measured 100,992-byte result recorded in the test, after trimming the setup schema's descriptions. `yarn typecheck` and `yarn lint:deadcode` pass.
