# Statistics "Entries Count by Type" shows directive types in English in every language, while the Journal translates the same names

**Severity:** minor (localization). **Estimate:** 25–35 minutes including locale keys for three new types and a rendered test. **Owner:** `dashboard` (`features/ledger-data/statistics/entries-count-by-type.tsx`, statistics/journal locales). **A2:** in German the Journal's filter bar reads *Eröffnen · Schließen · Transaktion · Saldo · Notiz · Dokument · Ausgleich · Preis · Benutzerdefiniert*. The Statistics table for the same ledger lists *Balance, Close, Commodity, Custom, Document, Event, Note, Open, Pad, Price, Query, Transaction*, all English and in English alphabetical order, beside a localized heading ("Anzahl der Einträge nach Typ") and German-formatted percentages (`3,4 %`). The same happens in all 14 non-English languages.

## Reproduction

Local HEAD (`yarn dev`, pointed at the production API), signed-in QA owner, synthetic ledger, headless Chromium 1440×1000. Read-only.

1. `/ledger/<owner>/<ledger>/statistics?lang=de`. Under **Anzahl der Einträge nach Typ**, the rows read `Balance 1 3,4 %`, `Close 0 0,0 %`, … `Transaction 16 55,2 %`.
2. `/ledger/<owner>/<ledger>/journal?lang=de`. The type toggles for the same directives are translated (`Saldo`, `Eröffnen`, `Transaktion`, …).

## Root cause

`entries-count-by-type.tsx:141–144` renders `{entry.type}` directly, which is the raw `EntriesByType.type` string from `GetLedgerEntriesCountPerType`. The Journal maps the same directive types to `journal.open`, `journal.close`, `journal.transaction`, `journal.balance`, `journal.note`, `journal.document`, `journal.pad`, `journal.price` and `journal.custom` (`features/journal/components/journal-filters.tsx:28–76`). Those keys exist in all 15 catalogs. `Commodity`, `Event` and `Query` have no key yet. Recent Statistics localization (w4/229 percentages in `fde7cb58`, w4/077/w4/179 counts) never touched the type column.

## Fix

Map each known directive type to a localized label: reuse the nine existing journal keys through a shared label map (in `common/`, so Statistics doesn't import a Journal private), and add `commodity`, `event` and `query` labels to every catalog with real translations. Fall back to the raw type string for an unknown future type. Sort rows by the displayed label with the active-language collator, or keep a fixed directive order, but not English alphabetical order under a translated label. Leave counts and percentages as they are.

Acceptance: `?lang=de` shows `Saldo`, `Eröffnen`, `Transaktion`, … with unchanged counts and percentages. English is unchanged. An unknown type renders its raw name. A rendered test covers German and the fallback, and `translations.test.ts` / `locale-stray-english.test.ts` pass with the new keys. Dashboard gates pass.

## Dedupe

Searched `.pm/**` (including `done/`) for Entries Count by Type, `entries-count-by-type` and untranslated directive types. w4/229, w4/077, w4/179, w3/138, w4/145 and m14 cover percentages, plural counts, NaN, section shells and filtered counts on the same page, and none covers the type labels. This is present at HEAD, not deployment lag.
