# "Show more" buttons drop keyboard focus to the page body each time they load

**Severity:** minor (accessibility; WCAG 2.4.3 Focus Order, 2.1.1). **Estimate:** 30–40 minutes for the three buttons with one shared test. **Owner:** `dashboard` (`features/ledger-list/components/activity-feed.tsx`, `features/user-profile/components/user-profile-tabs.tsx`, `features/git/commits/components/commits-list.tsx`). **A2:** paging a list from the keyboard is the only way to read past its first page. After every press, focus is thrown to `<body>`, so the user must Tab through the whole page again to reach the next "Show more", and a screen reader announces nothing about the new items.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `18ecaff5`. QA-owned headless Chromium, 1440×1000, signed in. Read-only.

1. `/ledger` (dashboard) → Activity. Focus **Show More** and press Enter. Items go 12 → 19, and `document.activeElement` is **`<body>`**. Repeating five more times (29, 39, 49, 59, 65 items) leaves focus on `<body>` every time. At 65 the button disappears and the feed ends with no "end of activity" text.
2. `/ledger/open_ledger?tab=followers`: focus **Show more**, press Enter. After loading, focus is **`<body>`**.

## Root cause

Each button disables itself while its page loads, and a focused button that becomes `disabled` loses focus in browsers:
- `activity-feed.tsx:173`: `disabled={loading || isLoadingMore}`
- `user-profile-tabs.tsx:90`: `disabled={loadingMore}`
- `commits-list.tsx:145`: `disabled={loadingMore}` (the "load older commits" control added for w3/468). Not exercised live, since it isn't deployed yet; same mechanism.

## Fix

Keep the button focusable while loading: use `aria-disabled="true"` plus an early return in the handler (or keep it enabled and ignore repeat presses), and show the spinner with an `aria-live="polite"` status ("Loaded 7 more"). After loading, keep focus on the button if more remain. Otherwise, move it to the first newly loaded item or to an end-of-list message ("No more activity"). Apply this to all three lists through one small shared pattern or hook.

Acceptance: on each list, pressing Show more from the keyboard leaves focus on the button (or the first new item) and never on `<body>`. Repeat presses during loading don't double-fetch. The end of the list is announced. A rendered test with a delayed `fetchMore` asserts focus after loading. Dashboard gates pass.
