# Tell non-admins they can't manage a ledger's bank connections instead of "Failed to Load Data — Retry", and give the Plaid pages a heading

**Severity:** minor. **Estimate:** 30–40 minutes including rendered permission tests. **Owner:** `dashboard` (`features/plaid/pages/plaid-settings/index.tsx`, `plaid-connections/index.tsx`, `components/plaid-states.tsx`). **A2:** a signed-in reader or collaborator who opens Connected Accounts is told the data failed to load and offered a Retry that can never succeed. Nothing says the page is admin-only or who can connect a bank.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `ce83f82b`. QA-owned headless Chromium, 1440×1000, en-US. The QA account reads but does not administer `open_ledger/example`. Read-only.

1. Open `/ledger/open_ledger/example/link` (document title "Connected Accounts - example"). The main area shows only an error icon, **"Failed to Load Data"**, and a **Retry** button. There is no page heading or explanation.
2. The page's `GetPlaidItems` request returns HTTP 200 with `errors[0] = { message: "Authorization denied", extensions.code: "FORBIDDEN" }`. Pressing Retry repeats the same denial.
3. `/ledger/open_ledger/example/plaid-connections` renders the identical "Failed to Load Data | Retry".
4. Anonymous control: `/link` correctly redirects to `/auth/login?next=…/link`.
5. Owner (admin) view of their own ledger's `/link`: the page works (Sync, Manage Banks, "Bank Transactions — Review and submit 4 transactions…") but exposes **no headings at all** (`h1–h3`/`role=heading` count 0). It is the only ledger route without exactly one `<h1>` in a 24-route sweep. "Bank Transactions" is plain text.

## Root cause

- Listing bank connections requires the ledger **administrator** relation: `backend-cluster/backend-v2/authz` model `define can_read_bank_connections: administrator`, enforced in `plaid-item-service.ts:258–266` (`BANK_CONNECTIONS_LIST`).
- The pages never consult the viewer's permission. `plaid-settings/index.tsx:16–29` and `plaid-connections/index.tsx:80–93` render `PlaidErrorState` for **any** `error` (`plaid-states.tsx:18–33`: `common.failedToLoadData` plus Retry). They don't distinguish FORBIDDEN from a service failure.

## Fix

Gate both routes on `useLedgerPermission().isAdmin`, the same relation the server enforces, before mounting `usePlaidItems`. For a signed-in non-admin, keep the page header and show an accessible `role="status"` notice: "Only the ledger's owner or an administrator can connect and manage banks". It needs no Retry, and links back to Journal/Import. Map a FORBIDDEN/UNAUTHENTICATED GraphQL error, if one still arrives, to that same notice. Keep Retry for genuine network or service failures. Add the new strings in all 15 locales. Leave the admin flow unchanged, except for one fix: give both Plaid pages the standard ledger `PageHeader` `<h1>` ("Connected Accounts"), make "Bank Transactions" an `<h2>`, and keep that header in the non-admin and error states too.

Acceptance: as a reader of `open_ledger/example`, `/link` and `/plaid-connections` show the admin-only notice with no Retry and send no `GetPlaidItems`. An owner sees their connections. A simulated network failure still shows Failed to Load Data + Retry. Every state has exactly one `<h1>`. Rendered tests cover admin, reader, forbidden-response, and network-error states. Dashboard gates pass.

Searched `.pm/**` (including `done/`, `blocked/`) for Connected Accounts, GetPlaidItems, plaid settings/connections, "Failed to Load Data", and forbidden-as-error. w0/011–012 pluralized Plaid counts, w0/024 gated Receipt/Import on write access, w3/m8 ported bank imports to REST/MCP, and w4/m14/t004 is a Catalan string note.
