# Return focus to the opening menu button after dismissing menu-launched dialogs (Delete File, Edit Ledger)

**Severity:** minor (accessibility; WCAG 2.4.3 Focus Order). **Estimate:** 20–30 minutes including a rendered focus test. **Owner:** `dashboard` (`features/ledger-editor/file-editor/components/non-text-file-views.tsx` `FileActionButtons`). **A2:** a keyboard user who opens a file's More actions → Delete and then backs out (Escape, Cancel or Close) loses focus to the document body. The next Tab starts again from "Skip to main content", far from where they were.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `8379b57a`. QA-owned headless Chromium, 1440×1000, ledger owner, `/ledger/<owner>/<ledger>/files/blob/main/README.md`. Every mutation and `PUT` was blocked by a route guard, and Delete was never confirmed.

1. Focus **More actions**, press Enter, select **Delete** with Enter. The dialog "Delete File — Are you sure you want to delete "README.md"? This action cannot be undone." opens with focus on Cancel (good).
2. Dismiss it with **Escape**, **Cancel**, or **Close**. In all three cases `document.activeElement` is `<body>`.
3. Control: opening More actions and pressing Escape *without* choosing Delete returns focus to the More actions button.

**Same defect on the `/ledger` dashboard.** Each ledger in the sidebar has a "Settings" menu (Edit Ledger, Delete Ledger). Choosing **Edit Ledger** with the keyboard opens "Edit Ledger Settings", and Escape leaves focus on `<body>`. **Delete Ledger** from the same menu correctly returns focus to the Settings button: `dashboard-sidebar.tsx:180` passes `settingsTriggerRef.current` to `onDelete`, while `:174` calls `onEdit(ledger.id)` with no opener, and the edit dialog (`:489`) has no `onCloseAutoFocus`.

## Root cause

`non-text-file-views.tsx:103–170`: `isDeleteDialogOpen` is set from the `DropdownMenuItem`'s `onClick` (`:155–161`), and the `Dialog` at `:168+` is controlled with no trigger. The menu unmounts when the item is chosen, so Radix has no element to restore focus to. The shared helper `common/lib/focus/restore-focus-on-dialog-close.ts` (used by w0/008 for New Entry) isn't applied here. This is the same pattern w3/m23 fixed for Journal, Budget and Account dialogs.

## Fix

Keep a ref to the persistent More actions trigger and pass it to the Delete dialog's `onCloseAutoFocus` via `restoreFocusOnDialogClose`, as w3/m23/t008 did for account-row confirmations. After a confirmed delete, the page navigates away, so focus follows the route's normal landing. Optionally give the destructive confirmation `role="alertdialog"`. Do the same for Edit Ledger: pass the Settings trigger to `onEdit` like `onDelete` already does, and restore it in the edit dialog's `onCloseAutoFocus`.

Acceptance: after Escape, Cancel or Close, focus is on More actions (file view) or on that ledger's Settings button (dashboard Edit Ledger). Rendered tests assert it for each dismissal path. Dashboard gates pass.

## Dedupe

Searched `.pm/**` for delete file + focus, file deletion dialog, and `restoreFocusOnDialogClose`. w3/m23 (done) covered Journal export, Budget, Open Account and account-row confirmations. w0/008 covered New Entry. w4/m22 noted the editor's More actions only as a focus stop. None covers the file view's Delete dialog or the dashboard's Edit Ledger dialog. A source sweep found no other `DropdownMenuItem`-launched dialog without focus restoration (Accounts row actions already restore, per w3/m23).
