# On phones the account journal and the Accounts table hide every amount and balance

**Severity:** major (the page's core numbers are absent below 640px). **Estimate:** 45–60 minutes including a narrow-viewport render test. **Owner:** `dashboard` (`features/journal/components/journal-table.tsx` account-journal columns; `features/ledger-data/accounts/index.tsx` row columns). **A2:** an account page answers "what moved this account, and what's the balance now?" On a phone it shows only date, flag, payee and posting count. To see this account's own change, the reader must expand each row and find the account among up to 16 postings, and the running balance isn't shown anywhere.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `13dbc1eb`. QA-owned headless Chromium, en-US. Public `open_ledger/example`. Read-only.

`/ledger/open_ledger/example/account/Assets:US:BofA:Checking?time=2016`, table "Account journal":

| Viewport | Exposed column headers | First row's cells |
| --- | --- | --- |
| 1440×900 (control) | Date, F, Payee/Narration, **Units, Change, Balance**, Postings | 2016-12-29 · * · Hoogle • Payroll · 2832.14 USD · 2832.14 USD · 6377.23 USD · 16 |
| **390×900** | Date, F, Payee/Narration, Postings | 2016-12-29 · * · Hoogle Payroll · 16 |

At 390px no amount appears anywhere in the row (row text: `2016-12-29 * Hoogle Payroll 16`). Expanding it lists all 16 postings (`Assets:US:BofA:Checking 2832.14 USD`, `Income:US:Hoogle:Salary -4615.38 USD`, …). The running balance (`6377.23 USD`) is not shown at any width below `sm`. The period table above it ("Changes Over Time Period data") still shows monthly totals, and those match BQL exactly (2016-01 −609.27 USD, 2016-02 −517.48 USD).

The same happens on **Accounts** (`/ledger/open_ledger/example/accounts`, table "Accounts"). At 390px the exposed headers are Account, Status and Actions. Open Date, Close Date, Postings and **Balance** are `display:none`, and 131 numeric cells are hidden. The `Assets:US:BofA:Checking` row reads just "Assets:US:BofA:Checking Open"; its 2754.06 USD balance (visible on desktop) appears nowhere. A sweep of 12 other ledger tables at 390px found no other hidden numeric column (the Journal's hidden "Postings" is a duplicate of a visible mobile variant).

## Root cause

`journal-table.tsx:156–176`: the account journal's Units, Change and Balance columns use `hidden … sm:table-cell` for both header and cells, so below 640px they are `display:none`. Nothing replaces them in the narrow layout. The main Journal hides nothing comparable because it has no amount columns.

## Fix

Keep this account's change and the running balance on narrow screens. For example, render a compact stacked cell under Payee/Narration (`+2,832.14 USD · bal 6,377.23 USD`), or keep Change and Balance as narrow numeric columns and drop only Units (which repeats Change for single-currency accounts). Keep the posting-count toggle, the desktop layout, w3/m40's Units semantics, and w3/467's narrow count width. Amounts must stay sign-correct and isolated (see w3/479).

For Accounts, keep the Balance on narrow rows (stacked under the account name or as a narrow trailing column); open/close dates and posting counts may stay desktop-only.

Acceptance: at 390px each account-journal row shows this account's change and the running balance without expanding, and each Accounts row shows its balance. No page-level horizontal overflow. The desktop table is unchanged. Narrow render tests assert these values for an account-journal row and an Accounts row. Dashboard gates pass.

## Dedupe

Searched `.pm/**` for account journal + mobile/narrow/390, running balance, and hidden columns. w3/m40 (done) fixed what Units means. w3/189 fixed account-journal rounding. w3/467 fixed the narrow posting-count clipping. w2/047, w2/053 and w2/065 concern the **native mobile app's** account journal. w4/222 (done) kept the focused account prefix visible in narrow Accounts rows, and w3/217 is the native app's Accounts table. None restores the web tables' amounts on narrow screens.
