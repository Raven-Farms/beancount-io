# Overview's Accounts card under a Time filter shows period-end balances labelled "Current", and "View all accounts" opens today's balances with `time=` silently ignored

**Severity:** minor. **Estimate:** 30–45 minutes, dashboard only. **Owner:** `dashboard` (`features/reports/overview/components/account-balances-card.tsx`, `features/ledger-data/accounts/index.tsx`, overview/accounts locales). **A2:** a user reviewing July sees Checking at 4,564.11 USD on the Overview and clicks the card's **View all accounts** to see the rest. The Accounts page shows Checking at 6,702.01 USD, which is today's balance, while the URL still carries `?time=2026-07`. The page has no Time control and no notice, so the two pages appear to disagree about the same account in the same period.

## Reproduction

Local HEAD (`yarn dev`, pointed at the production API), signed-in owner of a synthetic ledger, headless Chromium 1440×1000. Read-only.

1. `/ledger/<owner>/<ledger>?time=2026-07`. The **Accounts** card is described "Current asset and liability account balances" and lists Savings 10,500.00, Checking **4,564.11**, Cash 140.00 USD. These are correct July 31 values, verified against the ledger source.
2. Its **View all accounts** link resolves to `/accounts?time=2026-07` (the shared search-preserving navigation keeps `time`).
3. `/accounts?time=2026-07` lists Checking **6,702.01**, Cash 49.75, Visa -143.25 USD, which are current balances. There's no Time combobox in the header and no message that the period doesn't apply.
4. Control: the Overview's other drill-downs (Income Statement, Journal, Balance Sheet) honor `time=2026-07`.

## Root cause

The Accounts directory reads `GetLedgerAccountDirectives(ledgerId)` (`features/ledger-data/accounts/graphql/accounts.graphql:1`), which has no time input. The page is an all-time directory by design, with last-entry balances for asset and liability accounts (see w1/025). The Overview card (`account-balances-card.tsx:42–56`) computes period-end balances from the filtered report, yet keeps the static description `page.overview.accountsDescription` ("Current …") and links to the directory with whatever search the router preserves.

## Fix

Keep the Accounts directory all-time, and make both ends honest:

- On the Overview card, when a Time filter is active, describe the balances as of the period end ("Asset and liability balances at Jul 31, 2026"), and point the drill-down at the Balance Sheet with the same filters. That page is period-aware and lists the same accounts.
- On the Accounts page, drop `time` from the URL on arrival, or, if the route keeps it, show a short note that balances are current and the Time filter doesn't apply.

Acceptance: with `time=2026-07`, the card's description names the period end and its link opens `/balance-sheet?time=2026-07`, showing Checking 4,564.11. Without a filter, the card reads "Current …" and links to Accounts as today. Opening `/accounts?time=…` no longer implies a period. Rendered tests cover the filtered and unfiltered card and the Accounts arrival. Dashboard gates pass.

## Dedupe

Searched `.pm/**` (including `done/`) for View all accounts, `accounts?time`, and Accounts-page time/period/filter terms. w4/204, w4/221 and w4/222 touch Accounts search focus, table naming and narrow rows. w1/025 established the all-time balance semantics. m15 made filters persist across navigation, which is why `time` reaches a page that can't use it. Present at HEAD.

Unverified: account filter (`account=`) and advanced-filter combinations on the same card; 390px layout.

Its drill-down opens the Balance Sheet, named "Open the balance sheet for this period", and the ledger route's filter retention carries `time=` there (`/balance-sheet?time=2026-07`). When a Time filter arrives with it, the page shows a note that its balances are current and the filter does not apply. The URL keeps `time` so returning to a report restores the period. Four new strings in all 15 languages.
