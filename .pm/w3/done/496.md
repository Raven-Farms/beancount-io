# Allow ledger rename-back when the old name redirects to the same repository

**Severity:** major (ordinary ledger lifecycle). **Estimate:** 40–55 minutes. **Owner:** ledger service (`src/api/ledgers.ts`); shared REST/GraphQL/MCP workflow. **A2:** owners must be able to correct a ledger rename without losing their books.

Observed 2026-10-16 against an isolated current local stack with an ordinary owner's private synthetic ledger. No production data or administrative bypass. Placeholder coordinates below replace the fixture.

## Reproduction

1. Own `alice/books`; record HEAD and file SHA/content hash.
2. `PUT /api-gateway/v1/ledgers/alice/books` with `{"name":"books-temp"}` succeeds without changing financial bytes or HEAD.
3. Metadata reads of `alice/books` and `alice/books-temp` both resolve to the same canonical repository, because Gitea follows the old-name redirect.
4. Rename the canonical path back: `PUT /api-gateway/v1/ledgers/alice/books-temp` with `{"name":"books"}`.
5. Actual: HTTP 409 `CONFLICT`, “Ledger conflict: Name already exists”, reason `LEDGER_NAME_ALREADY_EXISTS`, field `name`. Expected: success when target and source are the same canonical repository; genuine collisions still fail.

Root independently recovered the fixture by addressing the original alias with the original name, which skips this faulty preflight and lets Gitea perform the rename. HEAD, blob SHA and full file hash were unchanged, and the fixture was restored. This proves the underlying repository supports rename-back.

## Cause and scope

The update handler reduces the target `repoGet` result to a boolean and discards its stable repository ID. A followed self-redirect is treated as an occupied name before `repoEdit` can run. Fix the shared internal handler by distinguishing the same repository from a different target, preserving create collisions, ownership/authorization and upstream error behavior. Never hand-edit the generated Gitea client or disable redirect compatibility.

Eligible adapters share `LedgerWorkflow.updateLedger`: REST ledger PUT, GraphQL `updateLedger`, and MCP `manageLedgers` operation `update`. The discovery exercised REST live; GraphQL/MCP were initially source-traced. Verify all eligible surfaces through the shared fix.

## Acceptance

- Ordinary owner can rename a private ledger away and back through its canonical path without changing HEAD, file bytes or privacy.
- A genuinely different target remains a duplicate-name error; missing or invalid repository identities cannot accidentally authorize self-collision bypass; upstream failures retain their behavior.
- Meaningful production-handler regressions fail on the original runtime and pass with the fix. Ledger lint, typecheck, build and unit gates pass. Record runtime parity evidence and its practical limits.
