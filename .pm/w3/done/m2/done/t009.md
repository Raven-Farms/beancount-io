## Watch the delete path especially (noted 2026-08-27)

Add and update both go through `bulkEntries`, so the `custom` fix covers them.
**Delete does not** — it is the `getLedgerEntryContext` → `deleteLedgerEntrySourceSlice`
two-step, a different code path that the fix never touched and that has never
been exercised against a budget.

One concrete reason to probe it: `hashEntry` in the ledger's `entry-hash.ts`
hashes a custom directive from **date and `custom_type` only** — it explicitly
skips `values`, because beancount's `dtype` marker is not carried on the wire.
Every budget sharing a date therefore shares a base hash regardless of account,
interval or amount, and they are told apart only by occurrence index (position
in the directive stream). Ledgers where several budgets were created on the same
day are the normal case, not the exotic one.

So the delete test that matters is: with three budgets all dated the same day,
delete the middle one and confirm the other two survive intact.
