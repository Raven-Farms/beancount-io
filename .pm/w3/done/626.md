# Files offers Delete on `main.bean`, which the server always refuses; the user confirms "cannot be undone" and then gets a generic error

**Severity:** minor. **Estimate:** 20–30 minutes including a component test. **Owner:** `dashboard` (`features/ledger-editor/file-editor/components/ledger-file-view/index.tsx` and the view that renders **More actions**). **A2:** `main.bean` is the ledger's root file. The mobile app shows it with a lock icon and no delete action (w4/051, w4/022; `mobile/src/screens/ledger-file-browser-screen/utils.ts:29–31` `canDeleteLedgerFile`). The dashboard puts **Delete** in the same file's menu, asks "Are you sure you want to delete "main.bean"? This action cannot be undone.", and on confirmation the server refuses. The user is first told they're about to destroy their ledger, then told only that "Some of the information provided is invalid."

## Reproduction

Local HEAD (`yarn dev`, pointed at the production API), signed-in owner of a synthetic ledger, headless Chromium 1440×1000. The confirmation was **cancelled**, not submitted.

1. `/ledger/<owner>/<ledger>/files/blob/main/main.bean` → **More actions**. The menu shows **Download** and **Delete**.
2. **Delete** opens "Delete File — Are you sure you want to delete "main.bean"? This action cannot be undone." with **Delete** enabled.
3. What confirming does, from source: backend-v2 `deleteLedgerFile` throws `BadUserInputError("main.bean file cannot be deleted")` before touching the repository (`backend-cluster/backend-v2/src/features/ledger/workflow/ledger-workflow.ts:758–759`, present since the backend import). The dashboard's `onError` (`ledger-file-view/index.tsx:149–151`) shows `formatError(error)`, which maps every `BAD_USER_INPUT` to the generic "Some of the information provided is invalid. Please check and try again."

## Fix

Don't offer Delete for the root `main.bean`. Match mobile and the server rule: hide or disable the action with a short reason ("main.bean is the ledger's root file and can't be deleted"), and show a lock indicator where the tree lists it if the tree has row actions. Compare on the root path, not just the filename: the server refuses only `path === "main.bean"`, so `accounts/main.bean` stays deletable. As a fallback, map this specific refusal to the same localized reason instead of the generic bad-input text.

Acceptance: `main.bean` at the root has no enabled Delete, and its reason is visible and announced. Other files, including a nested `*/main.bean`, keep Delete. A component test covers both. Dashboard gates pass.

## Dedupe

Searched `.pm/**` (including `done/`) for main.bean delete/protect terms. w4/051 and w4/022 record the **mobile** lock as correct behavior. w3/196 refuses creating names the server won't accept, and nothing covers dashboard delete. Present at HEAD.

Side observation (not filed separately): mobile's `canDeleteLedgerFile` compares only the filename, so it also locks a nested `*/main.bean` that the server would allow deleting. Fold that into this fix if mobile is touched.

---

**Resolved 2026-10-17** — Files no longer offers a confirmable Delete for the ledger's root file. `LedgerFileView` withholds its delete handler when the path is the root `main.bean`, with or without a leading slash. The rule matches the server's `path === "main.bean"`, so `accounts/main.bean` keeps Delete. Without a handler, `FileActionButtons` shows a disabled **Delete** menu item with a lock and the reason "main.bean is the ledger's root file and can't be deleted" as part of its accessible name. If the server's own refusal is ever reached, it maps to the same reason instead of the generic invalid-input text. One new string in all 15 file-editor locales, with the file name as a placeholder. Tests check that the view hands no delete handler to `main.bean`/`/main.bean` and a handler to `accounts/main.bean`/`transactions.bean`. They also check that the menu renders the disabled, reasoned item without a handler and the confirmation dialog with one. Restoring the originals fails the three root-file cases while the three controls pass. The tree has no row actions, so no lock was added there. Mobile's filename-only check was not touched. Dashboard format, lint (including dead code), tests (5,867 passed, one skipped), build and a public-tree secret scan passed, shipped in `90152e5e` (`dashboard`).
