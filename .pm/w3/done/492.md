# Let the ledger transport accept a valid 1 MiB base64 file

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** `backend-cluster/ledger` (`src/server/start-server.ts`). **A2:** prerequisite discovered while verifying [w3/490](./490.md): raising the gateway JSON allowance alone cannot make the advertised upload work because the downstream ledger parser rejects the encoded file.

## Reproduction and evidence

Real HTTP on 2026-10-15 through a separate current-source gateway container, a synthetic ordinary local account, and a disposable private local ledger. Empty-file control succeeds and is removed. The gateway accepts a valid exactly 1,048,576-byte file after its candidate fix, but the downstream ledger service refuses the forwarded request: expected/actual request length 1,398,208 bytes, parser limit 1,048,576, `entity.too.large`. The gateway translates that upstream refusal to `SERVICE_UNAVAILABLE`. No production/customer data writes.

Current ledger `src/server/start-server.ts` calls `bodyParser()` with the default 1 MiB JSON limit. The gateway's explicit decoded/UTF-8 file guard and generated-directive distinction belong to 490 and are preserved separately while this transport prerequisite ships.

## Fix and acceptance

Give the internal ledger JSON parser a bounded allowance that accommodates one normally encoded 1 MiB file and its envelope. Preserve the existing Python-compatible error envelope, credential forwarding, raw/multipart routes, and the independent form cap. Do not add a decoded upload policy to internal generated/merged writes. Meaningful real-HTTP tests prove an exactly 1 MiB base64 create/update request reaches its real file adapter unchanged, while an above-allowance request is refused before the write dependency. Revert the fix and observe the regression test fail. Run the ledger package gates, then use the two fixed local services to finish 490's actual at-limit write/readback and over-limit refusal checks.

## Dedupe

490 owns the public gateway parser, explicit file-write guards, API parity, and generated-client adoption. This note isolates its newly observed downstream transport prerequisite in the ledger package; it does not duplicate the gateway guard.
