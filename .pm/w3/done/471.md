# Answer a missing account, entry, commit, pull request or user profile with a real not-found, not an indexable 200 page

**Severity:** minor. **Estimate:** 50–60 minutes including SSR status tests. **Owner:** `dashboard` (`routes/ledger.$ledgerOwner.$ledgerName.account.$accountName.tsx`, `…entry.$entryHash.tsx`, `…commit.$commitSha.tsx`, `…pull.$prNumber.tsx`, `features/reports/account/`). **A2/A3:** a mistyped or stale account link on a public ledger renders a full "account details and transaction history" page for an account that doesn't exist. Search engines, link checkers and agents get HTTP 200, no `noindex`, and a canonical URL for it, so any made-up account name on a public ledger becomes an indexable page.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `ce83f82b`. Anonymous fetch for status and head, plus the QA-owned headless Chromium (1440×1000, en-US, signed-in reader) for the settled page. Read-only.

| --- | --- | --- | --- | --- |
| `account/Assets:US:BofA:Checking` (control, real) | 200 | none | Assets:US:BofA:Checking - example | account charts and journal |
| `account/Assets:Nope:Missing` | **200** | **none** | Assets:Nope:Missing - example | full account page; charts say "No Data Available — No account data found for this account" |

The account response's `<meta name="description">` reads "Account details and transaction history for Assets:Nope:Missing in example." Its canonical is `…/account/Assets%3ANope%3AMissing`. Working control in the same app: a missing ledger (`/ledger/nosuchowner/nosuchledger`) answers a real not-found via `notFound()`, as do unmatched sub-routes since w3/198.

## Root cause

- The entity routes have no loader that validates their parameter. `routes/ledger.$ledgerOwner.$ledgerName.account.$accountName.tsx` only sets `component`, `validateSearch` and `head: createLedgerHead(args, "ledgerAccount")`. `grep -rn "notFound()" src/routes` lists the ledger layout, catch-alls, OAuth and ledger assets, and none of the entity routes.
- `routes/ledger.$username.tsx` likewise has no loader. w3/152 (done) made the API classify a missing profile as NOT_FOUND, but the page only learns it after hydration, so the response stays 200 and indexable, and the not-found view still offers Try again.
- The account page (`features/reports/account/`) treats an unknown name as an account with no data. Entry and pull pages detect NOT_FOUND only after hydration, inside the component, too late to set the status or `noindex`.

## Fix

- **Account:** in the route's `loader`, read the ledger's account names (the query the account comboboxes already use, cache-first) and `throw notFound()` when the decoded `$accountName` is not an open or closed account of the ledger. Render a not-found view ("No account named … in this ledger", with a link to Accounts) with `noindex`.
- **Entry, commit, pull:** in each route `loader`, query the entity and map a NOT_FOUND / BAD_USER_INPUT GraphQL code to `notFound()`, following `ledger.$ledgerOwner.$ledgerName.tsx:50–62`. Keep UNAUTHENTICATED → login redirect and FORBIDDEN → not-found.
- **User profile:** in `ledger.$username.tsx`, query the profile in a `loader` and `throw notFound()` on NOT_FOUND (w3/152's classification). Drop Try again from the not-found view; keep Go to dashboard.
- Keep the existing 200 pages for real entities, and the honest in-page states for client-side navigation.

Acceptance: a direct request for each missing path in the table returns 404 with `noindex`. The real account still returns 200. Client navigation to a missing account shows the not-found view, not charts. Route tests cover real, missing, and invalid-root account names, plus missing entry/commit/pull and a missing user profile, under SSR. Dashboard gates pass.

## Dedupe

Searched `.pm/**` (including `done/`, `blocked/`) for soft 404, missing/unknown/nonexistent account, not found, and entity route status. w3/198 (done) made **unmatched** sub-routes answer 404 and explicitly scoped itself to the catch-alls. w2/m8 set `noindex` on ledger loader error states. w0/018 handled ledger assets and OAuth links. w3/152 (done) fixed the missing-profile **API** classification, not the page status. None covers matched entity routes with a missing parameter. The account-page behavior has existed since the dashboard import. It is not a regression.
