# Smart Import preview names its editable cells by placeholder: "Edit 0.00" and "Edit YYYY-MM-DD", and while editing the amount field is announced as "0.00"

**Severity:** minor. **Estimate:** 20–30 minutes including a rendered accessibility test. **Owner:** `dashboard` (`features/importer/components/steps/preview/editable-cell.tsx`, `editable-preview-row.tsx`). **A2:** a screen-reader user reviewing an import moves through the preview's cells to check and fix amounts and dates. The controls should say which field they edit ("Edit amount, row 3"). Today they say the field's placeholder, so the amount reads as "Edit 0.00. Current value: -4.50" and the date as "Edit YYYY-MM-DD…", in every language. Once a cell is opened, the text box has no label, and its name falls back to the placeholder "0.00" or "YYYY-MM-DD" (German "JJJJ-MM-TT").

## Live reproduction

Local HEAD (`yarn dev`, pointed at the production API), signed-in QA owner, headless Chromium, en, 2026-10-17. Read-only (nothing imported). `/ledger/<owner>/<ledger>/import` → Browse files → a one-row comma CSV (`2026-09-05,qa-20261017-plain,qa-20261017 plain control,-3.21`).

1. The accessibility tree for the preview row's buttons: `Edit YYYY-MM-DD. Current value: 2026-09-05`, `Edit Payee name. Current value: qa-20261017-plain`, `Edit Description. Current value: qa-20261017 plain control`, **`Edit 0.00. Current value: -3.21`**, `Delete row`.
2. Activate the amount cell. The focused element is an `<input>` with no `aria-label`, no `aria-labelledby` and no `<label>`, and its computed accessible name is **`textbox "0.00"`** (the placeholder). The date cell behaves the same way (`textbox "YYYY-MM-DD"`).
3. No name includes the row, and **Delete row** doesn't say which row, so leaving the table structure (a buttons list or the rotor) gives a column of identical controls.

## Root cause

`editable-cell.tsx:224–227` builds the collapsed button's name as `importer.preview.editCellLabel` with `field: placeholder`. `editable-preview-row.tsx:117/138/158/181` passes the placeholders `importer.preview.dateFormat` ("YYYY-MM-DD"), `payeePlaceholder`, `descriptionPlaceholder` and `amountPlaceholder` ("0.00"). The editing `<Input>`/`<Textarea>` (`editable-cell.tsx:149–186`) gets only `placeholder`, which the browser then uses as the accessible name.

## Fix

Give `EditableCell` a required `label` (the column's localized name: `importer.preview.date`, `.payee`, `.description_column`, `.amount`, the same keys as the table headers) and a `rowNumber`. Name the collapsed button "Edit {label}, row {n}. Current value: {value}". Give the editing input `aria-label="{label}, row {n}"` (or `aria-labelledby` the column header plus a row-number cell id). Keep the placeholder as a format hint only, and attach it with `aria-describedby` if it helps. Name **Delete row** "Delete row {n}". Add the strings to every importer locale.

Acceptance: in the fixture above, the buttons read "Edit Date, row 1…", "Edit Payee, row 1…", "Edit Description, row 1…", "Edit Amount, row 1…" and "Delete row 1". The open amount input's accessible name is "Amount, row 1" with the existing error association unchanged. A rendered test asserts these names via accessible queries in en plus one other locale. Dashboard gates pass.
