# Upload Files labels a file "Exceeds 1MB limit" and then uploads it anyway

**Severity:** minor. It may be major if the server accepts the file: an oversized blob would land in the ledger repository against the stated limit. **Estimate:** 25–35 minutes including a rendered upload test. **Owner:** `dashboard` (`features/ledger-editor/upload-files/index.tsx`). Server-side size enforcement belongs to `backend-cluster/backend-v2` / `ledger` if it turns out to be absent. **A2:** the page says "Maximum file size: 1MB" and flags the offending row, then still lets the user press Upload Files. It sends the file first, as a 16 MB base64 GraphQL payload.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `dc60caaf`. QA-owned headless Chromium, 1440×1000, ledger owner, `/ledger/<owner>/<ledger>/files/upload/main`. A route guard aborted every GraphQL mutation and S3 `PUT`, so nothing was uploaded.

1. Choose four synthetic files: `qa-big.bin` (12,000,000 bytes), `qa-empty.bean` (0 B), `qa name with spaces.bean` (1 B) and `qa-ok.bean` (30 B). The list shows `qa-big.bin (11718.75 KB) — Exceeds 1MB limit`. The other rows read `(0.00 KB)`, `(0.00 KB)`, `(0.03 KB)`.
2. **Upload Files** stays enabled. Press it.
3. The first request is `POST CreateLedgerFile` with `{"path":"qa-big.bin", "content": <16,000,000 characters>}`, i.e. the oversized file, base64-encoded. The guard aborted it, so whether the server refuses it is **unverified**.

## Root cause

`upload-files/index.tsx:31` defines `MAX_FILE_SIZE = 1024 * 1024`, but it is only used to style the row and show the warning (`:319–338`). `isUploadDisabled` (`:65–66`) checks only `!canWrite || selectedFiles.length === 0 || isUploading`, and `handleUpload` (`:103–114`) loops over every selected file with no size check. A 1-byte file also renders as "0.00 KB".

## Fix

Enforce the limit the page states. Disable Upload Files while any selected file exceeds `MAX_FILE_SIZE`, with an explanation tied to the button ("Remove files over 1 MB to upload"), or skip oversized files with an explicit per-file status. Never send them. Also format sizes readably (bytes under 1 KB, "11.4 MB" rather than "11718.75 KB"). With one authorized disposable attempt, confirm whether `CreateLedgerFile` refuses a payload over the limit. If it doesn't, file the matching server check so REST, GraphQL and MCP enforce the same limit.

Acceptance: with an oversized file selected, no request carries it, and the user is told why. Valid files still upload. Sizes read "0 B"/"1 B"/"30 B"/"11.4 MB". A rendered test with a >1 MB `File` asserts the disabled or skipped state and that the upload mutation is not called for it. Dashboard gates pass. The server's behaviour is recorded.

## Dedupe

Searched `.pm/**` for upload size, "Exceeds 1MB", `exceedsFileSizeLimit`, and `CreateLedgerFile` limits. w4/128 (done) gated Upload on write permission, and w3/486 (open) covers Create File path validation. None covers upload size enforcement. The importer has its own 10 MB check (`importer.upload.fileSizeError`) in a different flow; it was not re-tested here.
