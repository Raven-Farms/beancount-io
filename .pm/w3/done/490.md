# Make the advertised 1 MiB file upload reachable through the gateway request limit

**Severity:** minor. **Estimate:** 45–60 minutes including transport/parity checks. **Owner:** `backend-cluster/backend-v2` (body parser and explicit file-write boundaries). **A2:** Upload Files permits files through 1 MiB, but a valid file near that limit fails because its encoded request exceeds the gateway JSON cap.

## Reproduction and evidence

Found while resolving w3/487 on 2026-10-15. Real HTTP against the running isolated local Docker stack, using a newly created synthetic ordinary account and disposable local ledger; no production/customer data writes.

- An authenticated zero-byte `createLedgerFile` control succeeds.
- A 1,048,577-byte file returns HTTP 413 before GraphQL and leaves HEAD unchanged.
- A file **exactly 1,048,576 bytes**, which the upload UI permits, also returns HTTP 413. Its base64 field alone is **1,398,104 characters**, before the GraphQL envelope. No file is committed.
- Controls/probe files were removed. These observations concern the running local stack, not a production write.
- Current main `backend-cluster/backend-v2/src/server/middleware/body-parser-middleware.ts` explicitly sets `jsonLimit: "1mb"`; the protocol encoding therefore makes the advertised decoded-file limit unreachable. A 413 here does not prove that every API surface enforces a decoded per-file limit.

## Fix

Give file-write requests a bounded allowance that accommodates their protocol envelope, and enforce the advertised decoded/UTF-8 file size at the eligible explicit customer file-write boundaries across REST, GraphQL and MCP. Check base64 bytes for GraphQL file content and UTF-8 bytes for text-file adapters. Keep authorization and typed failures consistent. Do not apply the upload cap blindly to generated directive appends or merged ledger files, and do not block reads/downloads of existing larger files.

Acceptance: one authorized disposable file at exactly 1 MiB succeeds through `CreateLedgerFile`; the same explicit file-write contract works through eligible REST/MCP adapters. An over-limit explicit file write is refused before storage with a useful error, while the parser retains a bounded request cap. Meaningful tests exercise the actual body-parser/adapter boundary, encoded and UTF-8 byte counts, and the internal generated-write distinction. Native package gates pass.

## Dedupe

w3/487 owns the dashboard selection guard, readable sizes, and empty-file encoding. It uncovered this separate backend transport mismatch; w3/486 concerned reserved paths and did not change request limits.
