# Create File path validation: trim whitespace, explain empty segments correctly, and refuse `.git/` paths

**Severity:** minor. **Estimate:** 25–35 minutes including schema tests. **Owner:** `dashboard` (`features/ledger-editor/create-file/`, its path schema and locales). The server-side `.git` behaviour belongs to `backend-cluster/backend-v2` if it turns out to be missing. **A2:** the Create File form either refuses a path with a reason that doesn't apply, or sends a path the user didn't mean.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `ae0d73cf`. QA-owned headless Chromium, 1440×1000, ledger owner, `/ledger/<owner>/<ledger>/files/new/main`. Every GraphQL mutation was intercepted and aborted by a route guard, so nothing was written; the "Connection problem" toasts below are that guard, not production.

## Root cause

The create-file schema rejects `.`/`..` segments and empty segments with one message (`create-file/locales/en.ts:7`), and it neither trims the input nor rejects a `.git` path component. The server's own rule, `backend-cluster/backend-v2/src/features/ledger/utils/safe-repo-path.ts:8–23` (`assertSafeRepoPath`), rejects empty, `.` and `..` segments, backslashes and NUL, but not a `.git` segment, and w3/196 mirrored exactly that rule into the client. Gitea may still refuse it, but that was **not verified** because no write was made.

## Fix

- Trim leading and trailing whitespace before validating and sending (or reject it with "Remove spaces at the start or end").
- Split the messages: empty segment / trailing slash → "Remove the empty folder name (// or a trailing /)"; `.`/`..` → the existing text. Add both in all 15 locales.
- Reject any `.git` path segment client-side ("Files inside .git can't be edited"), and confirm with one authorized disposable write that the server refuses it too. If it doesn't, add the same check in backend-v2's file-write path for REST, GraphQL and MCP alike.

Acceptance: ` spaced.bean` is sent as `spaced.bean` (or refused with the whitespace message); `a//b.bean` and `dir/` show the empty-segment message; `.git/config` is refused before any request. Unit tests cover each case. Dashboard gates pass. The server-side `.git` result is recorded.

## Dedupe

Searched `.pm/**` for create file, file path validation, `..` segments, `.git` path, and whitespace in file names. w3/196 (done) added client-side validation mirroring `assertSafeRepoPath`, which is where the single `. or ..` message for every segment problem comes from. It didn't add trimming, separate messages, or a `.git` rule. w3/197 (done) fixed the false unsaved-changes prompt. w4/128 (done) gated Create/Upload on write permission.
