# Journal Balance rows never show the asserted amount: the journal payload drops `amount` for Balance directives

**Severity:** minor. **Estimate:** 40–55 minutes including serializer, type and rendered-row tests. **Owner:** `backend-cluster/ledger` (`foundation/rustledger/journal-serialize.ts`, `foundation/ledger-api-types/index.ts`), then `dashboard` (`features/journal/components/journal-description/balance-description.tsx`, `common/types/journal.ts`). The OpenAPI/backend-v2 copies of `JournalBalancePublic` move with it. **A2:** a balance assertion is how a user records "the bank says 49.75 USD on this date." In the Journal and the account journal the row reads only `2026-08-29 Balance Assets:Cash`, with empty Units, Change and Balance cells. To see what was asserted, the user has to open Entry Context or the source file. Fava's journal shows the amount on the row.

## Live reproduction

Production `https://beancount.io`, 2026-10-16, QA-owned headless Chromium, 1440×1000, English/light. The signed-in owner used a synthetic ledger whose last line is `2026-08-29 balance Assets:Cash  49.75 USD`. Read-only.

1. Open `/ledger/<owner>/<ledger>/journal`, turn **Transaction** off and **Balance** on.
2. The row reads `2026-08-29 · Balance · Assets:Cash`. The asserted amount appears nowhere on the row, and expanding it shows nothing more.
3. On `/account/Assets:Cash?time=2026-08` with Balance on, the same row has empty Units/Change/Balance cells. The transactions around it all fill those cells.
4. Clicking the row opens Entry Context, whose source line is the only place `49.75 USD` appears.
5. Network: `GetLedgerJournal` returns `{"directive_type":"Balance","date":"2026-08-29","meta":null,"account":"Assets:Cash","diff_amount":null}`. The response has no `amount` and no `tolerance`.

Confirmed at local HEAD as well: this checkout's dashboard (`yarn dev`, pointed at the production API), anonymous on public `open_ledger/example`, renders every Balance row as `date · Balance · account` with empty amount cells.

## Root cause

`journal-serialize.ts:228–236` (`case "balance"`) emits only `account` and `diff_amount: null`. `JournalBalancePublic` (`ledger-api-types/index.ts:1337`, and the copies in `backend-v2/src/foundation/fava/Api.ts:1306` and `idl/beancount-ledger.openapi.json:9969`) has no `amount` field. The same file already serializes the amount for other surfaces (`:320`, the plaintext renderer `:619`). Only the journal shape drops it. The dashboard's `JournalBalance` type (`common/types/journal.ts:62`) mirrors that, so `BalanceDescription` can only render the account. `diff_amount` is documented as always `null` under rustledger (`journal-serialize.ts:52–54`), so the row's one optional amount line never renders either.

## Fix

Add `amount` (`JournalAmountPublic`) and `tolerance` (nullable) to the Balance journal item in the ledger serializer and `JournalBalancePublic`, and regenerate/update the backend-v2 and IDL copies. The change is additive, so existing consumers keep working. In the dashboard, render the asserted amount on Balance rows: in the journal description, and in the account journal's Units/Balance cells where Fava puts it. Use the shared `Amount` formatting so precision and RTL isolation match transactions. REST/GraphQL/MCP journal reads share this producer and gain the field together. Check the parity gate and any snapshot of the journal shape.

Acceptance: the Balance row for the fixture above reads `Assets:Cash … 49.75 USD` in the Journal and the account journal, on desktop and at 390px. `GetLedgerJournal` includes `amount: {number: "49.75", currency: "USD"}`. A serializer test pins the amount and tolerance, and a rendered row test fails if the amount is dropped. Ledger and dashboard gates pass.

## Dedupe

Searched `.pm/**` (including `done/` and `blocked/`) for `diff_amount`, balance-assertion amounts in the journal, and `JournalBalance`. CLI notes w5/323 and w5/224 concern `bea` output and import dedupe, and w3/116 concerns transaction amount precision. None covers the journal Balance shape. `git log -S` shows the Balance case unchanged since the rustledger serializer landed, so this is not deployment lag.

Unverified: mobile's transactions screen (`mobile/src/screens/transactions-screen/types.ts` reads `diff_amount`) and whether it would show the new field; other locales.

---

**Resolved 2026-10-17** — Balance journal items now carry the asserted `amount` (`JournalAmountPublic`) and the explicit `tolerance` (`null` without a `~` annotation). The change spans the ledger serializer, `JournalBalancePublic`, the IDL `beancount-ledger.openapi.json` (amount required, tolerance nullable) and backend-v2's regenerated fava client. backend-v2 passes journal items through untyped, so GraphQL, REST and MCP journal reads gained the field together, and the v1 OpenAPI snapshot had no drift. The golden parity test keeps comparing every other field with the legacy Python serializer and now documents the two additive fields. A dedicated serializer test pins `amount`/`tolerance` both from the golden source and for `49.75 ~ 0.01 USD`. In the dashboard, the Balance description renders the amount beside the account through the shared `Amount` RTL isolation, in the Journal and the account journal, and the description column carries it at 390px too. It sits in the description rather than the account journal's Units/Balance cells, so the desktop row does not repeat it. Adding the field exposed a real bug: the entry's accessible name treated any directive with `amount` as a Price, which would have named the row "49.75 USD/undefined". Balance is now named first ("Open entry 2026-08-29 Balance Assets:Cash 49.75 USD (row 1)"). A payload from an older ledger service still renders the account alone. Rendered tests cover both journals, the tolerance form, the accessible name and the legacy payload. Restoring the original description fails the three amount cases; restoring the original label fails the naming case. Mobile excludes Balance directives from its lists, so it needed no change. No live browser pass was made. Ledger lint (including dead code), typecheck, build and tests (88 suites, 1,316 tests) passed. backend-v2 typecheck, lint, tests (5,527, including the parity gate) and the OpenAPI drift check passed, as did the IDL CLI codegen and typecheck. Dashboard format, lint, tests (5,789 passed, one skipped; journal suites re-run after the final label cleanup), build and a public-tree secret scan passed, shipped in `f2043317` (`ledger`, `idl`, `backend-v2`, `dashboard`). The ledger service must deploy before rows show amounts; the dashboard renders without them meanwhile.
