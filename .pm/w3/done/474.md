# Profile follow hint says "Add this profile to your following list" next to Unfollow

**Severity:** minor (copy contradicts state). **Estimate:** 15–25 minutes including a rendered test. **Owner:** `dashboard` (`features/user-profile/pages/user-profile-page.tsx`, `components/user-profile-skeleton.tsx`, user-profile locales). **A2:** on a profile you already follow, the only text under the button tells you to do the thing you've already done, right beside the button that undoes it.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `ce83f82b`. QA-owned headless Chromium, 1440×1000 (the hint is `md:block`), en-US, signed in as an account that follows `open_ledger`. Read-only.

Open `/ledger/open_ledger`. The follow control reads **Unfollow**. Directly beneath it, the visible muted hint reads **"Add this profile to your following list."** The hint isn't wired to the button (`aria-describedby` absent), so it is only visual, and visually wrong.

## Root cause

`user-profile-page.tsx:243–246` renders `t("userProfile.followDescription")` whenever `!isOwnProfile`, regardless of `isFollowing` (which `FollowButton` already receives at line 217). The loading skeleton repeats the same unconditional hint (`user-profile-skeleton.tsx:82`).

## Fix

Choose the hint from the follow state. Keep `followDescription` when not following, and add `userProfile.unfollowDescription` ("Remove this profile from your following list.") when following. Add it in all 15 locales. Update it together with the button after a follow/unfollow succeeds; on failure, keep the server's state (as w3/107 did for Star). In the skeleton, render no follow-state copy until the state is known. Optionally reference the hint from the button with `aria-describedby`.

Acceptance: following → "Remove …" beside Unfollow; not following → "Add …" beside Follow. Toggling updates both. A rendered test covers both states and a toggle. Dashboard gates pass.

## Dedupe

Searched `.pm/**` for `followDescription`, Unfollow, and "following list". w3/104 (guest Follow loses the return destination), w3/107 (Star stays selected after failure), w4/111 (translated social tabs) and w2/m15 (social authz) don't cover the hint's state.
