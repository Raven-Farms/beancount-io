# Label the New Entry form's fields: date, payee, narration and every posting's account/amount/currency are named only by placeholders

**Severity:** minor (accessibility; WCAG 1.3.1, 3.3.2 Labels or Instructions, 2.5.3). **Estimate:** 40–55 minutes across the transaction, balance and note forms, with a rendered-name test. **Owner:** `dashboard` (`features/journal/components/new-directive-dialog/transaction-form.tsx`, `balance-form.tsx`, `note-form.tsx`, journal locales). **A2:** New Entry is how a web user writes to their ledger. A screen-reader user hears "Account (e.g., Assets:Bank:Checking), combobox" twice, with nothing saying which posting it is. Once a value is typed, the placeholder, and with it the field's only name, disappears. Voice-control users have no stable label to target.

## Live reproduction

Production `https://beancount.io`, 2026-10-16, local main at the time of filing. QA-owned headless Chromium, 1440×1000, ledger owner, `/ledger/<owner>/<ledger>/journal` → **New Entry** (Transaction tab). Every mutation was blocked by a route guard, and no entry was created.

The dialog's inputs (DOM inspection):

| Field | `<label>` / `aria-label` / `aria-labelledby` | Only name |
| --- | --- | --- |
| Date | none | placeholder `MM/DD/YYYY` |
| Status (control) | `aria-label="Status"` | — |
| Payee | none | placeholder "Payee" |
| Narration | none | placeholder "Narration" |
| Posting 1 account | none | placeholder "Account (e.g., Assets:Bank:Checking)" |
| Posting 1 amount (`name="postings.0.amount"`) | none | placeholder "Amount (e.g., 100.00)" |
| Posting 1 currency | none | placeholder "Currency (e.g., USD)" |
| Posting 2 account / amount / currency | none | **the same three placeholders** |

The visible "1" / "2" posting numbers are not associated with their fields.

## Root cause

`transaction-form.tsx` renders `FormItem` → `FormControl` without a `FormLabel` for date, payee (`:383–395`), narration (`:405–412`), and each posting's account (`:447`), amount and currency (`:498`). Only Status (`:349`) and the add/remove-posting buttons (`:513`, `:526`) carry names. `balance-form.tsx` and `note-form.tsx` reuse `journal.accountPlaceholder` the same way.

## Fix

Give every field a persistent label. Use visible `FormLabel`s, or visually hidden ones where the compact layout must stay. Posting fields are indexed: "Posting 1 account", "Posting 1 amount", "Posting 1 currency". Keep the placeholders as examples only. Apply the same to the Balance and Note tabs. New strings in all 15 locales. Keep the field order, validation messages (wired to the labelled controls via `FormMessage`), and focus behaviour unchanged.

Acceptance: `getByLabel("Posting 2 amount")` (and equivalents for every field) resolves to exactly one control in each New Entry tab, and the names persist after typing. A rendered test asserts the posting-indexed names. Dashboard gates pass.
