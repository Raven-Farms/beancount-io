## Objective

Prove both engines produce equivalent accounting results for every preset before any preset is listed to customers.

## Context

- ADR021: both engines (the Python CLI and the hosted ledger service) must produce equivalent accounting results for every fixture before a preset is listed.
- Fixtures come from t001; the hosted builder from t002; the CLI path from t004.

## Steps

1. Run every fixture through the hosted builder and through `bea init`, comparing files and report values.
2. Fix divergences in the catalog or builders, never by editing a fixture to match a bug.
3. Record the conformance run (fixtures, engines, versions, date) in this task.

## Files

- t001 fixtures and both builders, as needed

## Acceptance criteria

- [ ] Every listed preset passes on both engines with equivalent accounts, opening postings, and assertions.
- [ ] Any preset that fails is unlisted, not shipped with a known divergence.

## Out of scope

- New presets beyond the ADR021 eight.

CLI side: `cli/tests/test_setup_conformance.py` runs the same canonical fixtures through `bea init --preset` and compares opened accounts, plus `bea check` on the result. Both pass.
