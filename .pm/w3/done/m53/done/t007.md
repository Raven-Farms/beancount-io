The Evidence above was written from truncated reviewer summaries and understated the full simplify review. The complete reuse, quality, and efficiency reviews returned findings, which were then fixed in the follow-up simplify commit: shared `_prepare_new_file`/`_parse_opening_balances` helpers in the CLI engine (removing drift between the two init paths), a dead `preset_ids()` deleted, the dead `kind` field removed from every setup surface, the REST preset enum derived from the catalog with a GraphQL-enum parity test, opened accounts tracked during generation instead of re-parsed from output, `TTL.HOUR_24` and a narrowed idempotency record in the workflow, and the preset set computed once in the cloud create command. Two findings were deliberately not taken: using the Redis record-store abstraction (the workflow layer receives the strict cache helper, not the raw cache it wraps) and collapsing the CLI's parallel preset options into one object (each flag is independently validated at its own layer).
