# Files: a missing file answers an indexable HTTP 200, and an invalid path (`../secret`) shows a retryable "Failed to load file content — Try Again"

**Severity:** minor. **Estimate:** 35–50 minutes including SSR status tests. **Owner:** `dashboard` (`routes/ledger.$ledgerOwner.$ledgerName.files.blob.$branch.$.tsx`, `features/ledger-editor/file-editor/components/ledger-file-view/index.tsx`). **A2/A3:** stale links into a public ledger's files (a renamed `README.md`, an `include` path quoted in a blog post) land on a page that tells crawlers and link checkers the file exists: HTTP 200 and no `noindex`. A malformed path that the server deliberately refuses is presented as a transient failure, and its **Try Again** can never succeed. w3/471 gave the account, entry, commit, pull-request and profile routes a real not-found. The file route was not in its table.

## Reproduction

Local HEAD (`yarn dev`, pointed at the production API), signed in, headless Chromium 1440×1000, public `open_ledger/example`. Read-only.

| URL (under `/ledger/open_ledger/example`) | HTTP | robots | page | API |
| --- | --- | --- | --- | --- |
| `/files/blob/main/README.md` (control) | 200 | — | file preview | `GetLedgerFile` → content |
| `/files/blob/main/nope.bean` | **200** | **none** | "File not found: nope.bean · Browse parent directory" | `GetLedgerFile` → `null`, no error |
| `/files/blob/main/..%2Fsecret` | **200** | none | "Failed to load file content · **Try Again**" (title `../secret · Files - example`) | `BAD_USER_INPUT "Invalid file path"` |
| `/files/tree/main/nope-dir` | 200 | `noindex` | "This directory is empty" | `GetLedgerDirContent` → `[]` |

The last row is acceptable, since git has no empty directories and creating a file there creates the folder. It is listed only as a control for the `noindex` treatment the blob route lacks.

## Root cause

The blob route has no loader that validates the file before SSR, so a `null` file is discovered only during client rendering (`ledger-file-view/index.tsx`, `FileErrorView`/not-found branches) after a 200 has been sent with the page's ordinary indexable head. The route file declares only `component`, `validateSearch` and `head` (`createLedgerHead(args, "ledgerFiles", { noIndex: editMode })`). The error branch at `ledger-file-view/index.tsx:162–163` treats every `GetLedgerFile` error alike: `if (error) return <FileErrorView …/>`, with its retry action, including the server's `BAD_USER_INPUT` refusal of an unsafe path (`backend-v2` `assertSafeRepoPath`).

## Fix

Follow w3/471's pattern: in a cache-first loader for the blob route, read the file and `throw notFound()` when it resolves to `null` or the server refuses the path as `BAD_USER_INPUT`, so SSR returns 404 with `noindex` and the existing not-found view (keep **Browse parent directory**). Reserve the retryable error view for real transport and service failures. Client navigation to a missing file should show the same not-found view.

Acceptance: direct requests for `nope.bean` and `..%2Fsecret` return 404 with `noindex`, and the real `README.md` stays 200. A service failure (mocked) still shows Try Again. Route tests cover all three. Dashboard gates pass.
