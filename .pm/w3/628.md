# A ledger URL with a capital letter (`/ledger/open_ledger/Example`) or a `.git` suffix answers HTTP 500 "unexpected error", not a redirect or a 404

**Severity:** minor. **Estimate:** 30–45 minutes including SSR status tests. **Owner:** `dashboard` (`routes/ledger.$ledgerOwner.$ledgerName.tsx`, `common/components/ledger-layout/ledger-route-error.tsx`). **A2/A3:** people retype ledger links from READMEs, chat and talks, and capitalizing the name (`Open_Ledger/Example`) or pasting a git remote's `…/example.git` is common. Those URLs return **HTTP 500** with "Failed to Load Ledger — An unexpected error occurred while loading the ledger" and a **Try Again** button that can never succeed. Crawlers and link checkers record a server error on the public showcase. w3/m46 already made the REST surface refuse the same malformed names with a 4xx that names the slug rule. The dashboard route still treats them as an outage.

## Reproduction

Local HEAD (`yarn dev`, pointed at the production API) and production `https://beancount.io`, 2026-10-16/17, headless Chromium, signed in. Read-only.

| URL | HEAD | production |
| --- | --- | --- |
| `/ledger/open_ledger/Example` | **500**, "Failed to Load Ledger", `noindex` | **500**, same page |
| `/ledger/<owner>/MCP-Agent-Eval/journal` | **500** | — |
| `/ledger/open_ledger/example.git` | **500** | — |
| `/ledger/open_ledger/ex%2Fample` | **500** | — |
| `/ledger/open_ledger/does-not-exist` (control) | 404 (w3/471) | — |
| `/ledger/OPEN_LEDGER/example` (owner case) | 200, but `<link rel="canonical" href="…/ledger/OPEN_LEDGER/example">` | — |

Every ledger read for those names fails with `BAD_USER_INPUT "Ledger name slug must contain 1-100 lowercase letters, digits, underscores, or hyphens"` (backend-v2 `shared/str.ts` `validateLedgerSlugs` / `shared/ledger-slug.ts:4`), before any lookup.

## Root cause

The route loader maps only `UNAUTHENTICATED` → login redirect and `FORBIDDEN`/`NOT_FOUND` → `notFound()` (`routes/ledger.$ledgerOwner.$ledgerName.tsx:47–60`). `BAD_USER_INPUT` for an impossible slug falls through to `LedgerRouteError`, which SSR serves as a 500 "unexpected error". The owner segment is case-insensitive upstream, so uppercase owners load. The page then emits the request's own casing as canonical, creating duplicate indexable URLs for the same public ledger.

## Fix

Validate the params in the route before loading, against the same slug rules as backend-v2 (`LEDGER_NAME_PATTERN`, `LEDGER_OWNER_PATTERN`):

- A name that is valid once lowercased (and/or with a trailing `.git` removed) → permanent redirect to the canonical lowercase URL, preserving the subpath and search.
- Any other impossible name → `notFound()`, so SSR returns 404 with the existing not-found page.
- Map a `BAD_USER_INPUT` slug refusal from the ledger read to `notFound()` as a backstop.
- Emit the canonical link with the owner's canonical casing (from the `GetLedger` result's `fullName`), so `/ledger/OPEN_LEDGER/example` declares `/ledger/open_ledger/example`.

Acceptance: `/ledger/open_ledger/Example` and `/…/example.git` redirect to `/ledger/open_ledger/example` (subpaths and search kept). `/…/ex%2Fample` returns 404. `/ledger/OPEN_LEDGER/example` declares the lowercase canonical. SSR status tests cover each, and existing private/missing/unauthenticated mappings are unchanged. Dashboard gates pass.

## Dedupe

Searched `.pm/**` (including `done/`) for uppercase ledger/owner URLs, `.git` routes, "Failed to Load Ledger" and `BAD_USER_INPUT` in route loaders. w3/m46 hardened **REST** path params against the same inputs. w3/471 and w3/198 return 404 for missing entities and unknown sub-routes, w3/356 is CLI create validation, and w4/200 is the activity feed. None covers malformed ledger slugs on the dashboard route. Present at HEAD and on production.
