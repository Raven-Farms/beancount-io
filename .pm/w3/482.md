# A deleted file's diff is headed "/dev/null", and its file-list link goes nowhere

**Severity:** minor. **Estimate:** 25–35 minutes including a diff-viewer test. **Owner:** `dashboard` (`common/components/diff-viewer/diff-viewer.tsx`). **A2:** Version History is where a user checks what a commit removed. For a deletion, the diff's file heading reads `/dev/null` instead of the deleted file's name. The "files changed" link for that file doesn't scroll to it, and a shared `#diff-file-…` deep link opens at the top of the page.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `906bafd3`. QA-owned headless Chromium, 1440×1000, ledger owner. Read-only.

| Commit (synthetic probe file) | File-list link | Diff section id | Diff heading |
| --- | --- | --- | --- |
| "create qaloop3-probe.bean" (control) | `#diff-file-qaloop3-probe.bean` | `diff-file-qaloop3-probe.bean` | `qaloop3-probe.bean` |
| "Add 1 entry" on `main.bean` (control) | `#diff-file-main.bean` | `diff-file-main.bean` | `main.bean` |
| **"delete qaloop3-probe.bean"** | `#diff-file-qaloop3-probe.bean` | **`diff-file-%2Fdev%2Fnull`** | **`/dev/null`** |

On the deletion commit, expanding "files changed" and activating the `qaloop3-probe.bean` link sets the hash, but no element has that id, so nothing scrolls. Loading `/commit/<sha>#diff-file-qaloop3-probe.bean` directly stays at `scrollY = 0`.

## Root cause

`diff-viewer.tsx` names a file with `file.newPath || file.oldPath` (lines 137, 140, 284, 349, and the id via `getDiffFileId`). For a deletion the parsed diff's `newPath` is the literal string `"/dev/null"`, which is truthy, so the old (real) path is never used. `commit-file-list.tsx` builds its links from the real path, so the two disagree. The same expression at line 93 (`isBeancountFile(file.newPath || file.oldPath)`) also skips Beancount highlighting for a deleted `.bean` file.

## Fix

Derive one display path per file: `newPath` unless it is `/dev/null` (deletion), else `oldPath`; and `oldPath` is ignored when it is `/dev/null` (creation). Use it for the heading, the `diff-file-` id, the tokenizer check, and filename matching. Optionally mark the section as Deleted/Added. Keep existing ids for modified and added files unchanged so current deep links keep working.

Acceptance: on a deletion commit the diff heading shows the deleted path, the file-list link scrolls to it, and `#diff-file-<path>` deep links land on it. Modified/added files are unchanged. A diff-viewer unit test covers added, modified and deleted files' headings and ids. Dashboard gates pass.
