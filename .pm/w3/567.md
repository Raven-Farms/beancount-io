# `/ledger` hydrates with a mismatch on every load: the sidebar skeleton picks a random width on the server and again in the browser

**Trivial · dashboard · 10–15m · A2.** Local HEAD (`yarn dev`, pointed at the production API), signed in, fresh headless Chromium, `/ledger`. Every load logs React's "A tree hydrated but some attributes of the server rendered HTML didn't match the client properties. This won't be patched up." The diff is only `style={{--skeleton-width:"58%"}}` versus `"60%"`, and likewise for each of the three `SidebarMenuSkeleton` rows under `SidebarLedgerSkeleton` (`features/ledger-list/pages/dashboard-page/components/dashboard-sidebar.tsx:209`).

Cause: `common/components/ui/sidebar.tsx:847–851` initializes `width` with `useState(() => \`${Math.floor(Math.random() * 40) + 50}%\`)`. The initializer runs once on the server and once on the client, producing two different values. The visible effect is cosmetic (the server's widths stay until the skeleton unmounts). The cost is a hydration error on the dashboard home in development, which hides real hydration regressions on that page and makes the console noisy for anyone debugging.

Fix: make the width deterministic. Derive it from the skeleton's index (pass `index` from the caller, for example `[60, 72, 54][index % 3]`) or use a fixed width. `dashboard-sidebar.tsx` is the only caller outside the primitive.

Acceptance: a fresh `/ledger` load logs no hydration warning, and a unit test renders the skeleton twice and gets identical widths.

Dedupe: searched `.pm/**` for hydration with skeleton/random/width; w3/110 is number-format hydration in reports, a different cause. Present at HEAD.
