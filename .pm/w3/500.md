# Balance Sheet "At Market Value" values a past period at today's prices, disagreeing with the Overview

**Severity:** major (a historical statement reports a market value that period never had). **Estimate:** 50–60 minutes including a dated-price fixture and parity checks. **Owner:** `backend-cluster/ledger` (hierarchy `at_value` valuation date) with `backend-cluster/backend-v2` projections; REST/GraphQL/MCP balance-sheet surfaces move together. **A1/A2:** with `time=2016`, the Overview says net worth was 82,450.23 USD at market value, while the Balance Sheet for the same period values Assets alone at 90,957.98 USD. The difference is entirely 2017 price moves applied to a 2016 statement.

## Live reproduction

Production `https://beancount.io`, 2026-10-16. QA-owned headless Chromium, 1440×1000, public `open_ledger/example`, conversion **At Market Value**, `time=2016`. Read-only (the conversion preference was restored to At Cost afterwards).

| Source | Assets (USD) | Liabilities (USD) | Net worth (USD) |
| --- | --- | --- | --- |
| Overview Net Worth card ("At market value · 1 not in total") | — | — | **82,450.228** |
| BQL `convert(value(sum(position), 2016-12-31), 'USD')` / `convert(sum(position),'USD')`, `date <= 2016-12-31` | **84,219.108** | −1,768.88 | **82,450.228** (matches Overview) |
| Balance Sheet → Assets Hierarchy (At Market Value) | **90,957.978** | | |
| BQL `convert(value(sum(position)), 'USD')` (latest prices), same positions | **90,957.978** (matches Balance Sheet) | | |
| BQL `convert(cost(sum(position)), 'USD')` | 80,174.807 | | |

So the Balance Sheet values the end-of-2016 positions at the **latest** available prices (2017), not at the period's end date.

## Root cause

The Balance Sheet hierarchy's `at_value` conversion uses the latest price rather than the time filter's end date. w6/009 (done, `4155e3d7`) documented the same split from the other side: the balance-sheet summary's dated chart point versus the "latest-valued hierarchy". It made the **summary** follow the hierarchy, leaving the hierarchy's valuation date as is. Fava values tree reports at the filtered end date, which is what the Overview card and the dated chart already do here.

## Fix

Value hierarchy (tree) balances `at_value` at the time filter's end date. Use the latest price on or before it, as w4/m26 defines `at_value` against a valuation date. Use today only when the filter is open-ended or runs to the present. Keep summaries derived from the same hierarchy (w6/009), so they follow automatically. Disclose the valuation date ("market value as of 2016-12-31") on the statement and in exports. Apply to Balance Sheet, Trial Balance and Income Statement trees, and to REST/GraphQL/MCP alike.

Acceptance: for `open_ledger/example`, `time=2016`, At Market Value, the Balance Sheet assets equal 84,219.108 USD, and net worth equals the Overview's 82,450.228 USD. An unfiltered or current-year view is unchanged. A ledger fixture with two dated prices (w6/009's XYZ fixture) proves the period-end valuation. Parity tests pass across surfaces.

## Dedupe

w6/009 (done) aligned the summary with the latest-valued hierarchy and did not change the hierarchy's date. w4/121 (done) fixed Holdings' current valuation date, w4/m26 introduced market valuation and its disclosure, and w1/m13/t002 Fava-style conversion. Searched `.pm/**` for valuation date, period-end price, and market value with a time filter: no item addresses historical tree valuation.
