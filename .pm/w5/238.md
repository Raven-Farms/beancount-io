# `add price --commodity HOOL --currency USD --amount '130 USD'` writes `price USD 130 USD`; repeated single-valued `add` options silently keep only the last

**Major · cli · 30–45m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
`--commodity` and `--currency` are two spellings of one option on `add
price`, so passing both (the natural reading: the thing priced, and the
quote currency) drops HOOL and records a price of 130 USD for USD itself,
with exit 0. The same last-one-wins rule silently discards input on other
`add` commands: `add open -a One -a Two` opens only `Two`. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Checking USD
2024-01-01 open Assets:Broker HOOL
2024-01-01 open Expenses:Food USD
2024-01-01 open Equity:Opening USD
2024-01-01 commodity HOOL
2024-01-02 * "Opening"
  Assets:Checking  1000.00 USD
  Equity:Opening
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`. Run each command on a pristine copy.

```sh
bea -f main.bean add price --date 2024-06-01 --commodity HOOL --currency USD --amount '130 USD'
bea -f main.bean add open --date 2024-06-01 -a Assets:One -a Assets:Two
bea -f main.bean add note --date 2024-06-01 -a Assets:Checking --comment first --message second
```

Actual: all exit 0 with `Added 1 …` and empty stderr. Appended lines:

```beancount
2024-06-01 price USD      130 USD
2024-06-01 open Assets:Two
2024-06-01 note Assets:Checking "second"
```

Control: `add price --date 2024-06-01 --commodity HOOL --amount '130 USD'`
writes `price HOOL 130 USD`. Repeating `--amount` exits 2: `Pass --amount
exactly once; a price holds one amount (2 given).` A worker saw `add
transaction Coffee --narration Tea` refused as conflicting narrations, and
`add commodity --commodity AAA --currency BBB` write only `BBB`.

Expected: `docs/USAGE.md` says `price` and `commodity` accept `--commodity`
as an alias and that "Repeated `--amount` is refused on both commands";
"Exit 0 is a promise". Two different values for one single-valued option
are a contradiction and should exit 2 naming both, writing nothing.

Cause: these are scalar options, so the option parser keeps the last
value. Alias pairs are declared at `cli/src/cli/commands/add.py:329`
(price), `:377` (commodity), `:302` (note); only `--amount` (`:55`) and
narration (`:137`) are guarded.

Fix: refuse a repeat of any single-valued `add` option, at least when the
values differ, with exit 2 naming both values; for `add price`, say that
the quote currency belongs in `--amount`. No dependency change.

Blast radius: a worker confirmed last-wins for `add close -a`, `add event
-t`, `add transaction --date/--flag/--payee`, `--into`, `add transactions
--from`, `import --csv/--account/--rules/--duplicates` and `init -c`.
Read-side repeats (list and report filters) are harmless.

Dedupe: board search for `--commodity`, `--message`, "exactly once" and
repeated options finds w3/done/367 (repeated `--amount`, fixed for that
option only); nothing covers the alias pair or other options.

Acceptance: the three commands exit 2 naming the conflicting values and
write nothing; the single-value control is unchanged. Only macOS and the
checkout were exercised.
