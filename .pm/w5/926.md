# Accept the native parser's missing-units sentinel on a balancing import posting

**Minor · cli · 20–30m · A1.** A Python importer returning the official
parser's entries for a valid payment with a bare balancing posting fails
before preview: `AttributeError: type object 'MISSING' has no attribute
'currency'`. Replacing only that sentinel with `None` imports correctly.
No product fix implemented.

Real CLI QA, 2026-10-21, HEAD `9c7878b18` (CLI unchanged from
`73ea2a66b`), checkout `bea 0.3.1`, macOS 26.5.1 arm64, frontend Python
3.13.3, existing managed Python 3.12 engine with Beancount 3.2.3; Beangulp
already enabled. Fresh subprocesses, closed stdin/no TTY, isolated absolute
`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, no inherited
`BEA_FILE`/`BEA_TOKEN`. Reproduced twice from pristine synthetic fixtures.

Create disposable `/abs/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
```

Create synthetic `bank.txt` containing a valid native transaction. Its source
account has an explicit amount; only its counterposting is omitted:

```beancount
2024-02-01 * "Coffee"
  bank_id: "coffee-1"
  Assets:Cash -4.50 USD
  Expenses:Food
```

Create and inspect `importers.py`:

```python
from pathlib import Path
from beancount.parser import parser

class Imp:
    def identify(self, file): return str(file).endswith(".txt")
    def account(self, file): return "Assets:Cash"
    def extract(self, file, existing_entries=None):
        entries, errors, _ = parser.parse_string(
            Path(file).read_text(encoding="utf-8"))
        assert not errors, errors
        return entries

CONFIG = [Imp()]
```

From `/abs/books`, with the isolated child environment above:

```sh
bea --json --no-input -f /abs/books/main.bean import /abs/books/bank.txt --config /abs/books/importers.py
bea --json --no-input -f /abs/books/main.bean import /abs/books/bank.txt --config /abs/books/importers.py --apply
bea --json -f /abs/books/main.bean check
```

Preview and apply both exit **1**, stdout empty, JSON stderr category
`validation` with the attribute error above. The ledger, source and importer
are unchanged; check exits 0. Human output fails identically, including when
the counter account is open without a currency restriction.

Expected: preview one ready transaction, apply one, then skip its unchanged
stable-ID repeat. Fresh BQL must show **Assets:Cash −4.50 USD** and
**Expenses:Food 4.50 USD**, check clean. IMPORTING requires explicit amounts on
source-account postings; the balancing counterposting is supported. Native
loading the initial ledger plus `bank.txt` succeeds and produces those exact
postings. `parser.parse_string` reports no syntax error and returns the
Beancount `MISSING` sentinel for the omitted units.

Controls, twice each:

- In ten fresh journeys, the raw parser case is the only failure. Replacing
  just `posting.units is MISSING` with `None` succeeds, as does constructing
  the same `Posting(..., units=None, ...)` directly. Both write once and
  reimport with one duplicate, zero writes and unchanged ledger bytes.
- Explicit `Expenses:Food 4.50 USD` and currency-only `Expenses:Food USD`
  parser results also work and repeat correctly; the latter leaves its **number**
  for interpolation but has an Amount object with a known currency.
- Four additional human-output journeys reproduce the raw sentinel failure on
  restricted and unrestricted open counter accounts. All corresponding native
  reference ledgers validate and balance to the expected numbers. Source and
  configuration bytes remain unchanged.

Cause: debug capture reaches `importing.py:1113`, where `_writable` checks
`_invalid_name`; that calls `_entry_accounts` (:1980), which calls
`_posting_currency`. At :1848 the helper tests only `posting.units is not
None`, then reads `.currency` from `MISSING`. Its weight-inference loop also
skips only `None`, so it needs the same sentinel handling. Formatting the bare
posting already works; this failure is the currency inspection, not invalid
source text or missing optional dependencies.

Fix: treat native `MISSING` units like `None` when inspecting a balancing
counterposting and inferring its currency from the other legs. Preserve
explicit source-account requirements, normal currency restrictions and
ambiguous/malformed-row validation. Missing/unopened counter accounts should
reach the existing blocked-row remedy instead of this attribute error. Do not
require importers to rewrite the official parser's valid directive objects.
No dependency or backend/API change needed.

Dedupe: searched all board states for this exact error, parser/MISSING units,
amountless counterpostings and `_posting_currency`, and scanned active milestone
scopes. Completed w5/074 (`023d4aa9`) introduced `_posting_currency` to handle
`None`; its fixtures construct that representation directly and leave this
native-parser case uncovered. Completed w5/855 refuses a cost without units,
which this cost-free balancing posting does not have. No overlapping open
repair or later fix found.

Acceptance: the public parser-based importer previews/applies/repeats correctly
with fresh BQL/check, matching the `None`, explicit and currency-only controls.
Human and JSON output agree; duplicate/refused runs preserve bytes. Retain
unopened-account remedies and real invalid/ambiguous transaction failures.
Only macOS/checkout tested; repaired behavior unverified.
