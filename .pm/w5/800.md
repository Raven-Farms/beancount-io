# A posting with a cost but no commodity (`3 {80}`, `3 {}`, `3 {80} @ 90 USD`) is written as `3 USD {80}` — three dollars held at 80 dollars each — with exit 0, and `check` passes (incomplete fix of w5/098)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `0f2118d8e`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/098 (done).
w5/098's fix: do not default the units commodity when the posting carries a
cost or price, and refuse naming the posting. USAGE says `3 {80 USD}` is
refused rather than written as `3 USD {80 USD}`. No product fix implemented.

The w5/098 fixture: `option "operating_currency" "USD"`, opens for
`Assets:Checking USD`, `Assets:Brokerage` and `Equity:Opening`, an opening, and
a `10 HOOL {100.00 USD}` buy.

```sh
bea --file /abs/main.bean add transaction "Buy more" --date 2026-02-01 -p 'Assets:Brokerage 3 {80}' -p 'Assets:Checking -240.00 USD'
bea --file /abs/main.bean check
```

Actual:
- The add exits 0 and writes `Assets:Brokerage         3 USD {80}`, and
  `check` exits 0.
- A query shows `3.00 USD` at cost `240.00 USD` (`cost_number 80`,
  `cost_currency USD`).
- `3 {}`, `3 {80} @ 90 USD`, `3 {2026-01-01}` and `3 {"x"}` default the same
  way, and so does `-p 'Assets:Checking 3 {80}'` (hunter's runs).

Control: `-p 'Assets:Brokerage 3 {80 USD}'` exits 2 with `--posting 1 gives a
cost or price in USD but no commodity…`.

Expected: refuse any posting whose units commodity bea would default while
it carries a cost or price, naming the posting.

Cause: `cli/src/bea_engine/ledger/adding.py` (around `:890-891`) checks
`getattr(rate, "currency", None) == choices[0]`, where `rate` is the cost if
present, otherwise the price. A cost whose currency is MISSING never equals
`USD`, and the price is not consulted when a cost exists.

Fix: refuse whenever any cost spec or price is present and the commodity is
being defaulted.

Dedupe: w5/098 (done) is the parent.

Acceptance: each form above exits 2 naming the posting. A test pins `3 {80}`
and `3 {}`.
