# `bea add transaction -p` silently drops a `;` comment in a posting, and `-p 'Expenses:Food ; 8.00 USD'` writes an inferred leg instead of the typed amount

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
Everything after a `;` in a `--posting` is parsed as a Beancount comment and
thrown away. The command still exits 0 with `written: 1`, and the result
does not mention the lost text. When the `;` comes before the amount, that
posting becomes the elided, inferred leg. The bulk path disagrees:
`add transactions` refuses a `;`-led amount. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Food USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "Open"
  Assets:Checking  100.00 USD
  Equity:Opening
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea --json -f main.bean add transaction "Lunch" --date 2026-01-05 -p 'Expenses:Food 12.50 USD ; split with Sam' -p 'Assets:Checking'
bea -f main.bean add transaction "Taxi" --date 2026-01-06 -p 'Expenses:Food ; 8.00 USD' -p 'Assets:Checking -8.00 USD'
```

Actual: both commands exit 0.

- First command: the JSON `entry` is
  `2026-01-05 * "Lunch"\n  Expenses:Food    12.50 USD\n  Assets:Checking\n`.
  The comment is gone from both the file and the response.
- Second command: it writes `Expenses:Food` with no amount, which Beancount
  infers. `check` exits 0.
- A bulk row whose `amount` is `"12.50 USD ; split"` is also written
  without its comment.

Reproduced in three fresh runs from a pristine copy.

Control: `add transactions` with `"amount": "; 8.00 USD"` exits 1 with
`Could not parse amount '; 8.00 USD' as a posting fragment: no amount
found`, and the ledger is unchanged. `--meta 'memo:a; b'` keeps the `;` as
text.

Expected: `docs/USAGE.md` lists "a memo with a `;` in it" among `--meta`
inputs that are kept as "the text typed", because "everything after `;` is
a comment" (`_is_typed_literal`, `ledger/adding.py:933-940`). `--posting`
should get the same protection: refuse with exit 2 rather than silently
discard typed input or change which leg carries the amount.

Cause: `cli/src/bea_engine/ledger/adding.py:696` builds the candidate as
`header_text + "".join(f"  {item.strip()}\n" for item in postings)` and
parses it with `parse_exact`. Beancount's lexer drops `;` and everything
after it on the line, and the transaction is re-rendered from the parsed
entry, so the comment cannot survive. The bulk `amount` path
(`ledger/models.py:204`) splices the fragment into a probe the same way,
which is why a trailing comment gets through there too.

Fix: refuse a `;` that is not inside a quoted string in a `--posting` or in
a bulk `amount`/`account`, with exit 2 naming the posting number and
suggesting `--meta` (or posting metadata in a bulk row) for a note. No
dependency change.

Blast radius: `add transaction -p` and the `amount` field of
`add transactions` rows. The other `add` kinds build directives from typed
fields, not raw posting text.

Dedupe: searched all of `.pm/**` (`done/` included) for "semicolon",
"; comment", "trailing comment" and "posting comment". The hits are BQL
comment notes (w1/026, w3/402, w4/182) and CSV delimiter notes (w3/226).
The `--meta` `;` fix in w5/128 (`379630cb`) does not cover postings.

Acceptance: on the fixture, both commands exit 2 naming `--posting 1`, and
the ledger is unchanged. A bulk row with `"amount": "12.50 USD ; split"`
is refused the same way. A real-command regression test covers `-p` and
the bulk path. Only macOS and the checkout were exercised.

Addendum (CLI QA r72, 2026-10-14, same HEAD): a `;` also silently drops
a cost or price written after it. `bea add transaction X --date
2026-01-05 -p 'Assets:Brk 1 AAPL {100 USD} ; @ 200 USD' -p Assets:Cash`
exits 0 and writes `Assets:Brk 1 AAPL {100 USD}` with no price. `-p
'Assets:Brk 1 AAPL ; {100 USD}'` writes a plain `Assets:Brk 1 AAPL`.
The `--json` echo shows `price: null` / `cost: null`. The cause is the
same: `_posting_fragment` (`cli/src/bea_engine/ledger/models.py:185-205`)
parses through Beancount's grammar, which ends the posting at `;`. The
acceptance should also cover these two inputs, each refused with exit 2
and nothing written. Reproduced twice by the hunter and once by me.
