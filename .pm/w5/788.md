# First-run and packaging polish: a failed first-use install gives no remedy (unlike `bea upgrade`), uninstall leaves a 30–60 MB engine the docs never mention, and the PyPI page's license links are relative (404)

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `46d7394e9`, `bea 0.3.1` built and installed from a fresh wheel, macOS 26.5.1.
No product fix implemented.

1. **No remedy.** Offline, the README's first command, `bea --no-input init
   books --currency USD --date 2026-08-01`, exits 1 with `Error: Could not
   install the hash-pinned engine packages (uv exited 2).` and uv's causes
   (`Connection refused`). Nothing says this is a network problem, that
   retrying a local command once online works, or not to `pip install
   beancount`, all of which README says. `bea upgrade` already appends "Retry
   with a local command such as 'bea check' once the network and uv are
   available." (`cli/src/cli/commands/upgrade.py:215`).
2. **Uninstall.** USAGE's uninstall table (`cli/docs/USAGE.md:1932-1936`) does
   not mention `$XDG_DATA_HOME/bea/engine/<version>` (53 MB, or 61 MB with
   beanprice). Engines of earlier versions are never pruned after an upgrade,
   and uv may download CPython into `$XDG_DATA_HOME/uv/python` (hunter's
   inspection).
3. **PyPI links.** README's `[GPL-2.0-only](LICENSE.engine)` and `[MIT
   notice](NOTICE.fava)` (`cli/README.md:225`) are embedded in the wheel's long
   description, where they resolve to `pypi.org/project/beancount-io/LICENSE.engine`
   (404). The rest of README uses absolute GitHub URLs.

Fix: append the retry advice to first-use failures; document removing the
engine directory and prune other versions after a successful upgrade; use
absolute license links.

Dedupe: no match for "once the network", engine cleanup or the license
links.

Acceptance: each item is fixed as above.
