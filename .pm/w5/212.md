# A bulk posting with `cost` but no `units` is written with the cost silently discarded, exit 0

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
In `add transactions`, a posting that carries a structured `cost` (number,
date, label) but omits `units` is accepted. The cost vanishes: the posting
is written as a bare balancing leg, and the brokerage account ends up
holding cash instead of a lot. The envelope reports one clean write. No
product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Broker
2024-01-01 open Assets:Cash USD
```

`/absolute/books/rows.json`:

```json
[{"date":"2024-06-01","narration":"buy, units forgotten","postings":[
  {"account":"Assets:Broker","cost":{"number":"100.00","currency":"USD","date":"2024-06-01","label":"lot1"}},
  {"account":"Assets:Cash","amount":"-1000.00 USD"}]}]
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea --json -f main.bean add transactions --from rows.json
bea -f main.bean balance -x units
```

Actual: exit 0, `"data": {"written": 1, "rejected": []}`. The ledger gains:

```beancount
2024-06-01 * "buy, units forgotten"
  Assets:Broker
  Assets:Cash  -1000.00 USD
```

`balance` shows `Broker 1,000.00 USD`. The cost, lot date and label are
nowhere.

Control: the same row with `"price_total": {"number":"1000.00",
"currency":"USD"}` in place of `cost` exits 1 with `Total price on a
posting without units: 1000.00 USD.` and writes nothing.

Expected: `docs/USAGE.md`: "Omit `units`/`amount` for a balancing posting.
Supplying both forms or unknown fields … is rejected." A balancing posting
has no cost; a supplied field must be written or refused, never dropped.
The row should be rejected naming `postings.0`.

Cause: `cli/src/bea_engine/ledger/models.py:120-128` has no rule tying
`cost` to `units`. `cli/src/bea_engine/ledger/writer.py:326-333` builds a
posting with no units and a cost, and the upstream printer renders an empty
position when units are missing, so the cost never reaches the text.

Fix: a posting-model validator: `cost` without `units`/`amount` is a
row-level validation error (exit 1, `Row N, postings.i`). No dependency or
API change.

Blast radius: the bulk structured form only.

Dedupe: board search for "without units" and `cost` with
dropped/discarded/ignored finds w1/done/108 (unknown keys dropped) and
w5/186 (single amount-less posting); neither covers a known field
discarded.

Acceptance: the batch exits 1 naming row 1 `postings.0` and leaves the
ledger byte-identical; the same posting with `units` added is written with
its cost, date and label. Only macOS and the checkout were exercised.
