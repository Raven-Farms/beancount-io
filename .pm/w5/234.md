# Closing the terminal with a half-typed line in the query shell leaves the engine spinning at 100% CPU, ignoring SIGTERM

**Major · cli · 30–45m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
If the terminal goes away (window closed, SSH dropped) while the `bea
query` shell has text on the line, the `bea` frontend exits but the engine
child keeps running as an orphan at 100% CPU. SIGTERM does not stop it;
only SIGKILL does. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
2026-01-05 * "Cafe" "Coffee"
  Expenses:Food  4.00 USD
  Assets:Cash
```

Run on a real PTY (stdin, stdout and stderr all the terminal) with the
child's HOME set to a disposable directory (the shell keeps its history
under `$HOME/.config/beanquery/`), XDG_DATA_HOME pointing at the installed
engine, isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1,
`TERM=dumb`, no inherited BEA_FILE/BEA_TOKEN/CI.

1. Start `bea -f /absolute/books/main.bean query` and wait for
   `beanquery> `.
2. Type `SELECT cou` with no newline.
3. Close the PTY master (what closing the terminal does).
4. Six seconds later list processes whose command line names the ledger.

Actual: `…/engine/0.3.1/bin/python -P -m bea_engine shell --file …` is
still running with parent 1, state `R`, 100% CPU. After `kill -TERM` and
1.5 s it is still alive; `kill -KILL` ends it.

Control: the same hangup at an empty prompt leaves no process after six
seconds. A worker saw stock `bean-query` exit on the half-typed hangup, and
the same spin for `bea query --source FILE`.

Expected: a hangup ends the session; a closed terminal must not leave a
CPU-bound process that ignores termination.

Cause: `cli/src/bea_engine/__main__.py:15` installs Python-level handlers
for SIGTERM and SIGHUP, and the shell hands back only SIGINT
(`cli/src/bea_engine/stopping.py:43-47`). With a non-empty edit buffer the
line editor treats end-of-file on the dead terminal as "no input" and
loops without returning to the interpreter, so the pending Python handlers
never run. Under the default disposition, as in stock `bean-query`, the
kernel would end the process.

Fix: for `shell` and `source-shell`, restore the default disposition for
SIGHUP and SIGTERM (a read-only session has nothing to unwind), or exit
when stdin reports hangup/EOF. No dependency or API change.

Blast radius: interactive `bea query` and `bea query --source` sessions.

Dedupe: board search for `SIGHUP`, orphan, "100% CPU" and hangup finds
w5/208 (the frontend not forwarding signals on the native path; that orphan
finishes its work and exits) and w3/done/440, w5/done/014 (staging files).
None covers an engine that receives the signal and never exits.

Acceptance: one second after the PTY closes with text on the line, no
process naming the ledger remains; SIGTERM ends a shell session at any
prompt state. Only macOS (libedit) and the checkout were exercised.
