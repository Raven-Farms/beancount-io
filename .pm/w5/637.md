# An importer row with an unopenable account name (`Expenses:food stuff`) or a malformed currency (`usd`) is "blocked: not open", with a remedy that `bea add` refuses (gap in w3/386)

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-16, HEAD `75a67e85`, checkout `bea 0.3.1`, macOS 26.5.1.
w3/386 made an unopenable account name "a usage error, not an unopened
account", with `add`'s own message, but only for `--account`,
`--default-account` and rules. Its Unverified section left the Python
importer path untested. Importer-extracted accounts and currencies are only
tested for membership in the ledger's opens. No product fix implemented.

`imp.py` extracts two rows: a lunch whose counter posting is `Expenses:food
stuff`, and a fee in currency `usd` on `Assets:Checking`.

```sh
bea --file /abs/main.bean import bank.txt --config imp.py
bea --file /abs/main.bean add open --account 'Expenses:food stuff' --date 2026-02-01 -c USD   # the printed remedy
```

Actual: the import exits 0 (with `--apply`, exit 4): `Row 1: Account
'Expenses:food stuff' is not open. Run: bea add open --account 'Expenses:food
stuff' --date 2026-02-01 -c USD.` and `Row 2: Cannot post usd to
'Assets:Checking' (open for USD only)… or add usd to its open directive.` The
remedies exit 2: `Invalid account 'Expenses:food stuff'. … The character
U+0020 (SPACE) is not allowed.` and `'usd' is not one commodity`. The preview
diff shows text that is not valid Beancount. A `balance` on `Assets:Checking
Account` behaves the same.

Control: a valid but unopened `Expenses:Dining` gets a working `add open`
remedy.

Expected: each importer row's accounts and currencies are validated with the
same rules as `add`. An invalid one blocks (or refuses) the row with that
message (`Importer base row 1: Invalid account 'Expenses:food stuff' …`) and
no `add open` remedy.

Cause: `_blocked_reason` (`cli/src/bea_engine/importing.py:1255-1330`) checks
`open_currencies` membership only; `parse_account` and the commodity check are
not applied to extracted entries.

Fix: as above.

Dedupe: w3/386 (done) is the parent; w5/530 (open) is NFD normalization only.

Acceptance: both rows report the invalid name or currency without a remedy
that fails. A test pins them.
