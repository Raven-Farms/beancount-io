# `add transactions --from /dev/stdin` (or `/dev/fd/0`, `/dev/tty`) waits on the terminal under `--json`, `--no-input` or `CI=1`, where `--from -` refuses at once (gap in w5/210)

**Minor · cli · 5–10m · A1.** Real CLI QA, 2026-10-17, HEAD `87570e643`, checkout `bea 0.3.1`, macOS 26.5.1. PTY via `script(1)`.
USAGE:160 says that under `--no-input` (implied by `--json` and `CI`)
"nothing waits for a human". w5/210 made `--from -` refuse a terminal stdin.
No product fix implemented.

```sh
sleep 8 | script -q /dev/null bash -c 'bea --file /abs/main.bean --json add transactions --from /dev/stdin'
```

Actual: bea blocks for the full 8 s until the terminal sends EOF, then exits 2
with `Invalid JSON at line 1, column 1: Expecting value.`. Nothing is
written. `CI=1 … --from /dev/fd/0` and `--from /dev/tty </dev/null` wait the
same way (hunter's runs).

Control: the same pipeline with `--from -` exits 2 in 0 s with `Transactions
are required with --no-input. Pipe the JSON array on stdin or name a file with
--from PATH.`

Expected: a named path that is a terminal is refused at once when unattended,
with the same message.

Cause: `cli/src/cli/commands/add.py:577-587` calls
`context.refuse_terminal_stdin` only for `-`. Other paths are read with
`read_bytes()`.

Fix: open the named path first; when `os.isatty(fd)` and the run is
unattended, refuse as for `-`.

Dedupe: w5/210 (done) is the parent; w5/723 covers treeify decoding.

Acceptance: the pipeline exits 2 in under a second. A PTY test pins it.
