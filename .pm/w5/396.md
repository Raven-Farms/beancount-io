# With any pre-existing semantic error in the ledger, every add is refused as "The change would leave the ledger invalid" with new-entry advice and no `--allow-errors` hint; `add balance`/`add price` instead say "Pass --allow-errors to report anyway"

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
USAGE documents `--allow-errors` for exactly this case: a semantic error
already in the books. When the write would introduce nothing new, the
refusal still reads as if the new entry broke the ledger. Two things go
wrong:

- It attaches the balance-assertion recovery advice meant for a new
  assertion.
- It never mentions the flag that fixes it.

`add balance` and `add price` use the read commands' "report anyway"
wording on a write instead. A user with one stale assertion cannot work
out how to keep adding entries. No product fix implemented.

Create disposable `/absolute/books/main.bean`. It is a USD ledger opening
`Assets:Cash`, `Assets:Bank`, `Expenses:Food` and `Equity:Opening`, with
a 100 USD seed transaction and a failing `2026-01-03 balance Assets:Cash
999 USD`. Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME,
BEA_NO_UPDATE_NOTIFIER=1, no inherited BEA_FILE/BEA_TOKEN, and closed
stdin.

```sh
bea -f /absolute/books/main.bean add transaction X --date 2026-01-05 -p 'Expenses:Food 5 USD' -p Assets:Cash
bea -f /absolute/books/main.bean add note --date 2026-01-05 -a Assets:Cash -m hi
bea -f /absolute/books/main.bean add price --date 2026-01-05 -c EUR --amount '1.1 USD'
```

Actual:

- `add transaction` (and `add note`, `add open`) exits 1 with `The
  change would leave the ledger invalid; nothing was written.`, the old
  `main.bean:9: Balance failed …`, and "Balance assertions run at the
  start of the day … record known fees as transactions before adjusting."
  There is no `--allow-errors` hint.
- `add price` (and `add balance`) exits 1 with `Ledger has 1 error(s).
  Pass --allow-errors to report anyway.`
- The ledger is unchanged.

Reproduced twice by the hunter and once by me.

Control: the same commands with `--allow-errors` exit 0 and write, with a
warning about the old assertion.

Expected: `docs/USAGE.md` says "Every add command, and `import`, accepts
`--allow-errors` for a semantic error already in the books … An error
the write itself would introduce … is refused even with the flag." When
the write introduces no error, the refusal should say: "The ledger
already has 1 error(s); nothing was written. Pass --allow-errors to write
anyway". It should list the errors without new-entry hints, and use the
same wording for balance and price.

Cause:

- `cli/src/bea_engine/ledger/write.py:1378-1384` raises the same message
  whether or not `new_records` is empty. The balance hints (about
  `:1352-1365`) run for pre-existing errors too.
- `cli/src/bea_engine/ledger/adding.py:300` and `:602` reuse the read
  refusal.

Fix:

- When `not allow_errors and not new_records`, raise the pre-existing
  error message with the flag hint and without the new-entry hints.
- Reword `adding.py:300` and `:602` to "write anyway".
- No dependency change.

Blast radius: every `add` subcommand, bulk add and `import --apply` on a
ledger that already has an error, which is common while the books are
being repaired.

Dedupe: searched `.pm/**`, including `done/`, for "leave the ledger
invalid", "report anyway" together with add, and `--allow-errors` hint.

None covers the refusal wording.

Acceptance: on the fixture, each command without the flag exits 1 and

new-assertion advice. With the flag, each writes. A test covers
