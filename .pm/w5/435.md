# An `include` that names a FIFO (or another non-regular file) makes every command that loads the ledger hang silently: `check`, `list`, `balance`, `add` and `price export`; `format` already refuses it

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
[w5/120](./done/120.md) turned unreadable includes into a one-line exit
2: a directory gives "it is a directory, not a file", and a broken
symlink gets a similar message. A FIFO is not caught. The snapshot reads
every include with `read_bytes()`, and opening a FIFO that has no writer
blocks forever. Every command that loads the ledger hangs with no output
until it is killed. A killed frontend also leaves its engine child
running (the 300 family). No product fix implemented.

Create a disposable directory with `mkfifo p.bean` and a `main.bean`:

```beancount
option "operating_currency" "USD"
include "p.bean"
2026-01-01 open Assets:Cash USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, and
closed stdin.

```sh
perl -e 'alarm 8; exec @ARGV' bea -f /absolute/books/main.bean balance
bea format -i /absolute/books        # control
```

Actual: `balance` is killed by the alarm (exit 142) with no output. The
hunter saw the same for `check`, `list transaction` and `price export`
(10–20 s alarms, two fixtures), and engine children were left behind.
Reproduced by me once. I killed the engine I started.

Control: `format -i` exits at once with `Error: Not a regular file:
…/p.bean.`. A directory include exits 2 with the w5/120 message.
`include "/dev/null"` loads as empty.

Expected: a non-regular include should be refused the same way as a
directory, for example "Included file '…/p.bean' … is not readable: it is
not a regular file", with exit 2.

Cause: `LedgerSnapshot.capture` (`cli/src/bea_engine/ledger/write.py:80-99`)
calls `path.read_bytes()` on each include. The `except OSError` branch
is never reached, because the open blocks.

Fix: check `stat.S_ISREG` before reading, and refuse with the existing
`UsageError` wording. Character devices such as `/dev/null` may be
allowed explicitly. No dependency change.

Blast radius: any ledger whose include resolves to a FIFO or socket, for
example through a glob over a directory that holds one. Every command
hangs.

Dedupe: searched `.pm/**`, including `done/`, for FIFO and named pipe
together with include. w5/120 handles OSErrors only, and w5/277 covers
FIFO `-o` destinations. None covers this.

Acceptance: with the fixture, `check`, `balance`, `list` and `price
export` exit 2 at once naming `p.bean`, and no engine process remains. A
test covers a FIFO include.

Addendum (CLI QA r80, 2026-10-14): `include "/dev/zero"` goes through the
same unchecked `read_bytes()` and never returns. The engine's memory grew
to about 22–26 GB within 7–15 s in two runs, and the engine survived its
killed frontend. The `S_ISREG` check fixes this too. Allow `/dev/null`
explicitly, or allow only character devices that read empty. Because of
the unbounded memory, an unattended run can exhaust the machine. Treat
the fix as more urgent than "Minor" suggests.
