# A `credentials.json` that is a FIFO (or a link to `/dev/zero`) silently hangs every local command, and deeply nested JSON there fails every local read with a raw recursion error (gap in w5/297)

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `595daa2f`, checkout `bea 0.3.1`, macOS 26.5.1.
The engine launch reads the stored credential on every helper start so that
managed price fetches can authenticate. The comment there says
"Missing/invalid login must not break local books". The read blocks on a
non-regular file, and only `ValueError` counts as invalid JSON. No product
fix implemented.

Any valid ledger; isolated `BEA_CONFIG_DIR`.

```sh
mkfifo "$BEA_CONFIG_DIR/credentials.json"
bea -f /abs/main.bean balance            # also check, list, --json balance, ask
python3 -c "print('['*100000 + ']'*100000)" > "$BEA_CONFIG_DIR/credentials.json"
bea -f /abs/main.bean balance
bea cloud logout
```

Actual: with the FIFO, `balance`, `check`, `list` and `--json balance` hang
with no output (killed by a 10 s alarm); a link to `/dev/zero` hangs while
memory grows. With the nested JSON, `check` and `balance` exit 1 with `Error:
maximum recursion depth exceeded while decoding a JSON array from a unicode
string.` (`validation`), and `cloud logout` exits 1 with the same text and
leaves the file.

Related messages on the same path: when the credential is a directory, or
its directory is read-only, `cloud logout` says `… Run 'bea cloud login' to
replace it, or 'bea cloud logout' to remove it. It could not be removed
either: Operation not permitted.`, advising the command that just failed.
With `BEA_CONFIG_DIR=/dev/null`, `cloud status` says the stored credential
`/dev/null/credentials.json` is unusable (`NotADirectoryError`) instead of
saying `BEA_CONFIG_DIR` is not a directory.

Control: `--offline balance` with the FIFO exits 0; `[]` or `{not json` makes
local reads work and cloud commands exit 3 naming the file.

Expected: local commands never wait on or fail because of the credential
file. A non-regular or unparseable file is "unusable" (cloud commands exit 3
naming it; logout removes it, exit 1). Remedies never name the command that
just failed.

Cause: `_helper_env` (`cli/src/cli/engine/launch.py:732-740`) calls
`load_credentials()` and catches only `AuthError`; `load_credentials`
(`cli/src/cli/auth/credentials.py:99`) reads with `read_text()` and no
regular-file check, and `:107-109` catch only `ValueError`; logout
(`cli/src/cli/commands/cloud/app.py:49-60`) catches only
`UnusableCredentials`.

Fix: check `S_ISREG` (open with `O_NONBLOCK`) and cap the size; treat
`RecursionError` as invalid JSON; in `_helper_env`, swallow any credential
failure for local commands; word the logout and directory cases correctly.

Dedupe: searched `credentials.json` with FIFO and recursion; w5/297 (done)
covers bad JSON and a missing token; w5/435 is a FIFO include.

Acceptance: with the FIFO or nested JSON, local reads answer normally; cloud
commands exit 3 naming the file. Tests pin both.
