# `bea check books.bean` (the `bean-check FILE` habit) ignores the path: "No ledger file at 'main.bean'", or upstream's "Got unexpected extra argument", never `bea --file books.bean check`

**Trivial · cli · 10–15m · A1/A2.** Real CLI QA, 2026-10-16, HEAD `3f2372e1`, checkout `bea 0.3.1`, macOS 26.5.1.
A newcomer or agent coming from `bean-check FILE` types the ledger as an
argument. Each refusal sends them somewhere other than the fix. No product
fix implemented.

```sh
# in a directory without main.bean
bea check books.bean
# in a directory with main.bean
bea check books.bean
bea --json check books.bean
```

Actual (all exit 2): (1) `No ledger file at 'main.bean' (from the working
directory). Name one with --file PATH, …`, without mentioning
`books.bean`; (2) upstream's `Usage: bean-check [OPTIONS] FILENAME …
Error: Got unexpected extra argument (books.bean)`; (3) `bea --json check
does not accept bean-check options (books.bean). Drop --json to use native
bean-check flags…`, and dropping `--json` then fails as in (2).

Expected: when the extra argument names an existing file, exit 2 with `bea
check takes the ledger from --file: run bea --file books.bean check`, as the
misplaced-global hint does (w5/416).

Cause: `cli/src/cli/commands/check.py:39`, `:56-62` never recognize a
positional ledger path.

Fix: detect a lone existing-file argument before forwarding and refuse with
that hint.

Dedupe: w5/416 and 443 are sibling hints; `unexpected extra argument`
matches only w5/195 (unrelated).

Acceptance: the three commands print the `--file` hint. A test pins it.
