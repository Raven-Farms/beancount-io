# `bea ask`'s BQL tool returns errors to the model without the engine's details (no column list), and reports an engine crash, such as an empty query, as "Ledger is invalid"

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-16, HEAD `0c12f2dc`, checkout `bea 0.3.1`, macOS 26.5.1. Simulation: local stub of the AI proxy issuing `run_bql_query` calls.
The system prompt tells the model to "read the error carefully, fix the
syntax". The tool result drops the details that make that possible. An
engine traceback is reported as an invalid ledger, which can push the model
toward "fixing" a valid ledger. No product fix implemented.

The stub's first reply calls `run_bql_query` with `SELECT foo`, then with `""`.

```sh
bea -f /abs/main.bean ask q --print </dev/null
```

Actual (tool results sent back to the model, from the stub's request log):

- `SELECT foo` gives `BQL error: Cannot run this BQL query: column "foo" not
  found in table "postings".. Fix the query and retry.` There is no column
  list and no caret, and the full stop is doubled.
- `""` gives `Ledger is invalid: IndexError: list index out of range Pass
  --debug before the command for a traceback.`; the ledger is valid.

Control: `bea query "SELECT foo"` prints the caret and `Columns in postings:
account, …`; `bea query ""` exits 2 with `A query is required…`.

Expected: the tool result carries the engine's details (without CLI-only
hints such as `--debug` or `.tables`); a blank query is refused in the tool;
an engine failure is reported as a tool failure, not an invalid ledger.

Cause: `cli/src/cli/ask/agent.py:405` formats `{exc}` without `exc.details`;
`agent.py:403` treats every `LedgerError` as an invalid ledger, but
`helper_json` maps any engine failure to `validation` (`LedgerError`) and
appends the `--debug` advice (`cli/src/cli/engine/launch.py:423-441`).

Fix: as above.

Dedupe: searched `BQL error`, `Columns in postings`, `Ledger is invalid`;
w3/157, w5/198 and 250 are different.

Acceptance: the stub's log shows the column list for `SELECT foo` and a
blank-query refusal for `""`. A test pins both.
