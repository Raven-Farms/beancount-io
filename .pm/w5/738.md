# Four input-refusal messages say the wrong thing: decode offsets skip a leading BOM, a stray NUL "looks like UTF-16", `--from ''` advises omitting a required option, and a non-string tagged metadata value gets raw `TypeError` text

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-17, HEAD `87570e643`, checkout `bea 0.3.1`, macOS 26.5.1.
No product fix implemented. Each case refuses correctly, writes nothing, and
exits with the right code; only the message is wrong.

1. **BOM offset.** `bombad.json` is `EF BB BF` followed by
   `[{"date":"2026-02-01","narration":"caf\xe9"}]`; the bad byte is at raw
   offset 41. `add transactions --from bombad.json` says `invalid continuation
   byte at byte 38`. `query` from stdin and `format -` are off by 3 as well
   (hunter's runs). USAGE:779 promises "the offending byte offset". Cause:
   the input is decoded with `utf-8-sig`, and `cli/src/cli/utils.py:95` prints
   `exc.start` unchanged.
2. **NUL.** A UTF-8 row file with one trailing `\x00` gets `'…/nul.json'
   (from --from) looks like UTF-16 text; re-save it as UTF-8 and retry.`, and
   so does a UTF-32 file. The file is already UTF-8. Cause:
   `cli/src/cli/commands/add.py:599` treats any NUL as UTF-16. Control:
   `import` says the file "contains NUL bytes".
3. **Empty required path.** `add transactions --from ''` gets `--from '' is
   empty; name a path, or omit --from.` Omitting it gives `Missing option
   '--from'`. Cause: `cli/src/cli/utils.py:218` ignores `param.required`.
   `--into ''` gets the same text, which is right there.
4. **Tagged metadata.** `"meta": {"td": {"kind": "date", "value": 20260201}}`
   gets `Row 1, meta.td: Invalid 'date' metadata for 'td': expected string or
   bytes-like object, got 'int'`. A `{"kind": "number", "value": null}` gets
   `conversion from NoneType to Decimal is not supported`. USAGE:1436-1439 says
   tagged dates are `YYYY-MM-DD` strings. Cause: the `TypeError` text is
   copied into the message (`cli/src/bea_engine/ledger/write.py`, around
   `:2924`).

Fix: add the BOM length to the offset; name UTF-16 only when NULs alternate,
otherwise name the NUL and its offset; drop "or omit" for a required option;
say that a tagged value must be a string.

Dedupe: w5/155 (done) introduced the offset; w5/386, 387 and 389 (done)
introduced the empty-path wording; nothing covers these four.

Acceptance: each message matches the corrected wording above.
