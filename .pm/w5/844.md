# Hosted ledger: since w5/625, a price below an org heading or `#` line that holds a `"` is shadowed against the managed feed, but the hosted engine (rustledger) never sees it, so that date's price disappears entirely; and the feed validator splits on a lone CR, which rustledger does not (regression of w5/625; gap in w5/629)

**Minor · ledger · 20–30m · A1.** CLI QA, 2026-10-17, HEAD `94c872026`. Offline only: the ledger package's own functions and the pinned `@rustledger/wasm` 0.24.0 were run locally, and no hosted service was contacted. Regression of w5/625 (done); gap in w5/629 (done).
No product fix implemented.

1. **Vanishing price.** The ledger is `include "feed.bean"`, `* Prices for the
   12" binder`, `2026-09-10 price BTC 70000 USD`, `* Transactions` and a 2026-09-12
   transaction. The feed has `2026-09-10 price BTC 69000 USD` and `2026-09-11
   price BTC 69500 USD`.
   - The collector now records the authored 2026-09-10 pair, and the overlay
     drops the feed's 09-10 point.
   - Rustledger 0.24.0 treats the heading's `"` as opening a string, so it
     never sees the authored 70000 price, or the later transaction, and
     reports no error.
   - Parsing the result with rustledger leaves only `2026-09-11 BTC 69500
     USD`. Before the fix, the feed's 69000 point survived.
   - Rustledger swallows the quote the same way on `#` lines, with a parse
     error on `:`, `!`, `&` and `?` lines. Only `%` lines behave like Python
     Beancount.
2. **Lone CR (trivial).** Feed bodies `2026-09-10 price BTC 70000 USD\r
   observed-at: "…"\n` and `…USD\r2026-09-11 price BTC 71000 USD\r` pass the
   hosted validator. Rustledger reports `parse error: unexpected input` and
   keeps only the first price, and Python Beancount errors too. The CLI's
   validator refuses both. w5/629's aim is that a body which validates also
   parses.

Expected: the precedence pass shadows a feed point only when the hosted
engine sees the authored price, and the validator agrees with rustledger on
line breaks.

Cause: `STRING_OR_COMMENT_RE`
(`backend-cluster/ledger/src/foundation/managed-prices/managed-price-overlay.ts:84`)
copies the CLI's Python-Beancount rule (w5/476), which differs from
rustledger's lexer. The feed and overlay split on `/\r\n|\r|\n/`
(`managed-price-feed.ts:202`, `managed-price-overlay.ts:126`).

Fix: collect authored price pairs from rustledger's own parse of the
committed files, not a regex, and split on `\n` only, refusing bare CRs.
Report rustledger's silent drop of directives after a quoted heading
upstream.

Dedupe: w5/625 and 629 (done) are the parents; w5/476 is the CLI rule.

Acceptance: fixture 1 keeps a 2026-09-10 price in the hosted parse; the
lone-CR bodies are refused. Tests pin both.
