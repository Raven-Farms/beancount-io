# The "no ledger found" error suggests `bea init books --currency USD` even when `./books/main.bean` already exists

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A new user who runs the README quick start but skips `cd books` gets a
no-ledger error whose only copy-pasteable command is `bea init books
--currency USD`. Following it exits 4, because the books they just made are
in `./books`. No data is affected; the guidance points away from the one
thing that would work. The owner may judge this pedantic. No product fix
implemented.

Fixture: an empty directory `/absolute/g1`.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/g1`
throughout.

```sh
bea --no-input init books --currency USD --date 2026-08-01 --opening-balance "Assets:Checking 1000"
bea add transaction "Coffee" --date 2026-08-02 --posting "Expenses:Dining 12.50" --posting "Assets:Checking"
bea --no-input init books --currency USD
```

Actual: the first command exits 0. The second exits 2:

```text
Error: No ledger file at 'main.bean' (from the working directory). Name one with --file PATH, set BEA_FILE, or run from a directory containing main.bean or main.beancount. To start new books, run bea init books --currency USD.
```

The third, the printed suggestion verbatim, exits 4:

```text
Error: Already exists: /absolute/g1/books/main.bean. Choose a new path; init never overwrites a ledger.
```

Control: in an empty directory the same error appears and the suggested
`bea --no-input init books --currency USD` exits 0.

Expected: `cli/README.md` has the user run `init books`, `cd books`, then
`add transaction`; standing one directory up is the likeliest first slip.
When an immediate child directory holds `main.bean` or `main.beancount`,
the message should name it (`cd books`, or `--file books/main.bean`)
instead of suggesting an `init` that cannot succeed.

Cause: `cli/src/cli/context.py:104-108` appends the fixed sentence `To
start new books, run bea init books --currency USD.` without looking for an
existing child ledger.

Fix: when discovery from the working directory fails, probe immediate child
directories for a root ledger; if one exists, replace the init sentence with
a pointer to it, shell-quoted. Keep the init suggestion otherwise. No
dependency or API change.

Blast radius: every local command that resolves the ledger from the
working directory, text and JSON.

Dedupe: board search for "To start new books", "No ledger file at" and
"init never overwrites" finds w3/done/307 (`main.beancount` discovery),
w3/done/340 (stale `BEA_FILE` message), w5/done/055 and w5/114 (init's
"Next:" line); none covers this suggestion colliding with existing books.

Acceptance: the second command's error names `books/main.bean` and how to
use it, and does not suggest `bea init books`; the empty-directory control
is unchanged. Only macOS and the checkout were exercised.
