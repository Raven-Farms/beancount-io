# `add balance` with a `~` tolerance leaves a formatted ledger failing `format --check`

**Minor · cli · 30–40m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Same promise as [231](./done/231.md), different cause.
Cosmetic, but it breaks "a formatted file stays formatted after an add"
and any CI gate on formatting. A balance assertion with a tolerance is
appended as `1538 ~        1 USD`, and the formatter then wants to move the
currency column of every older line. Neither the account nor the amount is
wider than what the file already has. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Equity:Opening

2026-01-02 * "Opening"
  Assets:Checking  1538.00 USD
  Equity:Opening

2026-01-03 balance Assets:Checking 1538.00 USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea format -i main.bean
bea format --check main.bean
bea -f main.bean add balance --date 2026-02-01 --account Assets:Checking --amount "1538 ~ 1 USD"
bea format --check main.bean
```

Actual: the first `format --check` exits 0. The add exits 0 and appends
`2026-02-01 balance Assets:Checking 1538 ~        1 USD`. The second
`format --check` exits 1 (`would format: /absolute/books/main.bean`). A
worker saw a following `bea format` leave the new line alone and shift
every older amount seven columns right.

Control: the same sequence with `--amount "1538 USD"` appends
`2026-02-01 balance Assets:Checking     1538 USD` and `format --check`
stays 0.

Expected: `docs/USAGE.md`: "Appended lines are written where `bea format`
would put them given the file's current contents, so a formatted file
stays formatted after an add; when a new amount or account is wider than
any before it, a later `bea format` realigns only the older lines." The
tolerance form is documented syntax.

Cause: `cli/src/bea_engine/ledger/formatting.py:235-246` (width
discovery): the prefix pattern takes `2026-02-01 balance Assets:Checking
1538 ~` as the line's prefix, because the number before `~` is not
followed by a currency, and that becomes the widest prefix in the file.
`cli/src/bea_engine/ledger/write.py:993-1000` aligns the draft with that
width but keeps only the appended tail.

Fix: a tolerance assertion must not widen the prefix column: measure only
up to the account on `balance … N ~ T CUR` lines, or keep such lines out
of the aligner. No dependency or API change.

Blast radius: `add balance` with `~`, with and without `--pad-from`; any
hand-written tolerance assertion already makes `bea format` widen the
file.

Dedupe: board search for tolerance with `format --check`/realign and
"stays formatted" finds w5/231 (posting-metadata indent, a different
trigger and function) and w3/done/293 (`list balance` omitting the
tolerance).

Acceptance: `format --check` stays 0 after `add balance` with a tolerance;
the plain-amount control is unchanged. Only macOS and the checkout were
exercised.
