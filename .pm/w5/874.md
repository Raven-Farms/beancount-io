# CSV currency advice tells an already-open unrestricted account to open again, producing a duplicate-open refusal (follow-up to w5/841)

**Minor · cli · 15–20m · A1/A2.** Real CLI QA, 2026-10-20, checkout
`bea 0.3.1`, HEAD `c306dcbad`, Darwin 25.5.0 arm64; frontend Python 3.13.3.
No product fix implemented.

Create synthetic `/abs/case/books/main.bean`:

```beancount
2024-01-01 open Assets:Cash
2024-01-01 open Expenses:Uncategorized
```

Create `/abs/case/bank.csv`:

```csv
Date,Description,Amount
2024-02-01,Coffee,-3.50
```

Use cwd `/abs/case`, closed stdin/no TTY, isolated absolute
`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, and no inherited
`BEA_FILE`/`BEA_TOKEN`:

```sh
bea --file /abs/case/books/main.bean import /abs/case/bank.csv --csv date=Date,narration=Description,amount=Amount --account Assets:Cash
```

Actual: exit 2, `no currency column, and the ledger knows no commodity yet.
Open Assets:Cash for one currency first: bea add open --account Assets:Cash
--currency CODE --date YYYY-MM-DD.` JSON gives the same advice. The account
is already open for any currency. Even restoring the omitted ledger path
and replacing the placeholders cannot make the remedy work:

```sh
bea --file /abs/case/books/main.bean add open --account Assets:Cash --currency USD --date 2024-01-01
```

That exits 1: `Duplicate open directive for Assets:Cash` and
`Assets:Cash is already opened at …/books/main.bean:1 for any currency; an
account opens once.` Both refusals leave the ledger byte-identical.

Working control, exercised from the same fixture:

```sh
bea --file /abs/case/books/main.bean add commodity --date 2024-01-01 --currency USD
bea --file /abs/case/books/main.bean import /abs/case/bank.csv --csv date=Date,narration=Description,amount=Amount,currency=USD --account Assets:Cash --apply
bea --file /abs/case/books/main.bean check
```

All three exit 0; import writes one payment. The complete failure and control
sequence was repeated in two fresh directories. This is a valid ledger with
currency-neutral accounts, not a malformed fixture.

Expected: when the source account is already open without a currency list,
offer a remedy it can use: declare a commodity and select it with
`--csv currency=CODE`, or explain how to edit the existing open to restrict
it. Preserve the source-opening remedy for a genuinely missing account.
Printed commands must retain the ledger path, especially from a working
directory with no `main.bean`.

Cause: the empty-known-commodity branch in
`cli/src/bea_engine/csv_mapper.py` (`CsvImporter.extract`, around :1720)
unconditionally tells the user to `add open`; it does not distinguish an
existing unrestricted source account. It also hard-codes `bea` rather than
the instance's existing `self._bea` ledger command. The branch is shared by
human/JSON CSV preview and apply; it fails before any row can be prepared.

Dedupe: whole-board searches for no-commodity/currency-advice and duplicate
opens, plus all open/blocked milestone scopes, found the completed parent
w5/841. Its `2fd060ad3` fix exercises empty/comment/BOM ledgers with no
existing open. This valid already-open case remains; w5/838 covers other
missing-ledger remedies. Targeted history finds the branch's introduction
and no later repair.

Acceptance: the new fixture receives a usable remedy and following it
reaches one import and a clean check; the empty-ledger control still gets
valid account-opening advice; both modes retain byte-preserving refusals.
Windows/Linux and repaired behavior unverified. Sanitized evidence and
fixtures: `.tmp/qa-2026-10-20-cli-loop-d3c5ebec/captures/currency-*.json`
and `currency-advice-{1,2}/`; the public reproducer is self-contained.
