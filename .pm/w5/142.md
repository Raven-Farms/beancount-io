# Any `ImportError` in an importer config is reported as a missing engine package

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A typo in an import from the user's own sibling module is reported as
"Importer dependency is unavailable … the package has to be installed" in
the managed engine. Nothing is missing; the message sends the user to
install a package. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Uncategorized USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "Open" "Opening balance"
  Assets:Checking  5000.00 USD
  Equity:Opening
```

`/absolute/books/c/helper.py`:

```python
ACCOUNT = "Assets:Checking"
```

`/absolute/books/c/badname.py`:

```python
from helper import ACCOUNTS
CONFIG = []
```

`/absolute/books/x.txt`: one line.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean import x.txt --config c/badname.py
```

Actual: exit 2.

```text
Error: Importer dependency is unavailable: cannot import name 'ACCOUNTS' from 'helper' (/absolute/books/c/helper.py). Importer configurations are executed by the managed engine, not the environment you run bea from, so the package has to be installed there; 'bea engine status' prints which engine serves and where it lives. See docs/IMPORTING.md.
```

A worker saw the same text for `from . import helper` ("attempted relative
import with no known parent package").

Control: a config that says `import helper` loads; the run proceeds to
`No configured importer recognizes x.txt`.

Expected: `docs/IMPORTING.md` says "The configuration can import sibling
modules." A wrong name or a relative import is a mistake in the config and
should read as `Importer failed (ImportError): …`, ideally noting that the
config runs as a script so siblings are imported absolutely. The
dependency message is right only for a module that cannot be found.

Cause: `cli/src/bea_engine/importing.py:216-226` catches every
`ImportError`.

Fix: reserve the dependency message for `ModuleNotFoundError` whose name is
not a module beside the config; route other `ImportError`s to the generic
branch at `:227-231`. No dependency or API change.

Blast radius: every Python importer config, text and JSON.

Dedupe: board search for "cannot import name", relative import and sibling
module finds w5/done/013 (reworded this message for the real
missing-package case) and w5/blocked/015 (dependency policy); neither
covers the misclassification.

Acceptance: the command reports an importer failure naming the
`ImportError` without telling the user to install a package; a config
importing a truly absent package keeps today's message. Only macOS and the
checkout were exercised.
