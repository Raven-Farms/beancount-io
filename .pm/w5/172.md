# `list custom --allow-errors` dies with a raw `TypeError` on a `custom` directive that has no values

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A `custom "marker"` line with no values already makes the ledger fail
`check` (an upstream plugin error), but `--allow-errors` is the documented
way to read such a ledger. `list custom --allow-errors` instead exits 1
with a Python `TypeError`. A hardening gap. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
2024-01-01 open Assets:Cash
2024-01-02 custom "marker"
2024-01-03 custom "budget" "x"
2024-01-04 event "location" "Paris"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean list custom --allow-errors
bea -f main.bean list event --allow-errors
```

Actual: the first exits 1: `Error: TypeError: 'NoneType' object is not
iterable Pass --debug before the command for a traceback.`

Control: the second exits 0 with the event row and the upstream error on
stderr.

Expected: `docs/USAGE.md` says `--allow-errors` returns "data even though
the ledger has loader errors (they still print on stderr)": two custom
rows, the first with no values.

Cause: Beancount parses a value-less custom with `values=None`;
`cli/src/bea_engine/ledger/reader.py:560` iterates it unguarded.

Fix: iterate `entry.values or []`. No dependency or API change.

Blast radius: `list custom` on ledgers containing a value-less custom.

Dedupe: w3/done/232 stopped `add custom` from writing such a line; the
read side is not covered.

Acceptance: the first command exits 0 with two rows and the loader error
on stderr. Only macOS and the checkout were exercised.
