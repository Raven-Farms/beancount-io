# `docs/agent-skills.md`'s "from a CLI checkout `uv run python` works too" fails from the directory you run `bea ask` from, and names no interpreter for a Homebrew install

**Trivial · cli (docs) · 10–15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
The "Check discovery without a model call" section says to "Run it from
the directory you run `bea ask` from", and that "from a CLI checkout `uv
run python` works too". Plain `uv run python` finds its project by looking
upward from the current directory. So from any ledger directory outside
`cli/`, the snippet fails with `ModuleNotFoundError: No module named
'cli'`. From inside `cli/` it imports, but then it inspects
`cli/.agents/skills/`, which is not the directory the doc asks about. The
doc also names no interpreter for Homebrew, the install channel the README
lists first. No product fix implemented.

Setup: a CLI checkout at `/absolute/checkout/cli`, a project directory
`/absolute/proj` outside it, and the doc's own step-1 fixture at
`.agents/skills/test-skill/SKILL.md`. Use an isolated `BEA_CONFIG_DIR` and
no inherited BEA_FILE/BEA_TOKEN.

```sh
cd /absolute/proj
uv run python -c "
from cli.ask.skills import load_skills
for s in load_skills():
    print(f'{s.name}\t{s.path}')
"
```

Actual: exit 1 with `ModuleNotFoundError: No module named 'cli'`.
Reproduced from three directories outside `cli/`.

Control: `uv run --project /absolute/checkout/cli python -c "…"`, run from
`/absolute/proj`, prints
`test-skill	/absolute/proj/.agents/skills/test-skill/SKILL.md`. The
remaining walkthrough steps (fixture, move out, restore, user-level copy,
`.bak` rename) behave as documented.

Expected: every interpreter the doc names runs from the ledger directory,
and the Homebrew channel (`brew install bex-co/tap/bea`) is covered.

Cause: `cli/docs/agent-skills.md:68`. Without `--project`, `uv run`
searches for `pyproject.toml` from the current directory upward. The
Homebrew keg's frontend interpreter is
`$(brew --prefix bea)/libexec/venv/bin/python`, and the doc does not
mention it.

Fix: write the checkout form as `uv run --project /path/to/cli python`,
and add the Homebrew interpreter. Docs only.

Blast radius: this one paragraph, which is the doc's only way to check
discovery without credentials.

Dedupe: a board search for `load_skills`, `agent-skills.md` and
`uv run python` finds w5/021 (`23b60209`), which rewrote this section and
verified it with a `uv tool` interpreter only, and w5/287 (BOM discovery).
Neither covers the checkout or Homebrew interpreters.

Acceptance: from a directory outside `cli/`, each interpreter line in the
doc (uv tool, checkout, Homebrew) lists the project-level fixture with its
path. Only macOS and the checkout were exercised. The Homebrew path was
read from the keg layout, not run.
