# Forwarded `doctor` commands print Python's "Exception ignored … BrokenPipeError" on a closed pipe

**Minor · cli · 20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
`bea doctor print-options … | head` exits 141 as documented, but prints
two lines of interpreter noise on stderr. Other commands are silent. No
product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD

2026-01-05 * "Café" "Lunch"
  Expenses:Food  12.00 USD
  Assets:Cash
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, no TTY, cwd `/absolute/books`. Run under bash.

```sh
bea doctor print-options main.bean | true; echo "rc=${PIPESTATUS[0]}"
```

Actual: `rc=141`, with stderr:

```text
Exception ignored in: <_io.TextIOWrapper name='<stdout>' mode='w' encoding='utf-8'>
BrokenPipeError: [Errno 32] Broken pipe
```

Control: `bea -f main.bean list transaction | true` gives `rc=141` and an
empty stderr. A worker saw the noise from `doctor list-options` and
`doctor lex` too, and silence from `query`, `balance`, `report`, `format`,
`example` and `treeify`.

Expected: `docs/USAGE.md` says "a closed downstream pipe still exits 141,
both without a message."

Cause: `cli/src/cli/engine/launch.py:565-572` (`_spawn`) lets the native
child inherit stderr and only rewrites the exit code; the upstream Python
child ignores SIGPIPE and prints its own flush failure.

Fix: start native children with SIGPIPE at its default action, or drop
that epilogue when the downstream pipe is closed. No dependency or API
change.

Blast radius: commands forwarded through `run_native` with inherited
streams; seen on three `doctor` subcommands.

Dedupe: board search for "Exception ignored" and BrokenPipe finds
w3/done/378 and w5/122 (the frontend's own flush message and exit 120);
neither covers the native child.

Acceptance: the command exits 141 with an empty stderr; the `list`
control is unchanged. Only macOS and the checkout were exercised.
