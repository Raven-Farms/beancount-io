# Import rules are matched against the raw multi-line CSV cell, not the one-line text the preview and ledger show

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A quoted CSV field with a line break is shown and written with the break
replaced by a space, but rules still see the break. Two rows that display the
same text get different categories, and a salary deposit lands in
`Expenses:Uncategorized`. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Income:Salary
2026-01-01 open Expenses:Groceries
2026-01-01 open Expenses:Uncategorized
2026-01-01 open Equity:Opening
2026-01-02 * "Opening balance"
  Assets:Checking  1000.00 USD
  Equity:Opening
```

`/absolute/books/s.csv` (row 1 has LF inside the quoted cell; row 3 has
CRLF):

```csv
Date,Description,Amount
2026-08-02,"CARD PURCHASE
WHOLE FOODS MKT",-20.00
2026-08-03,CARD PURCHASE WHOLE FOODS MKT,-21.00
2026-08-04,"ACME
PAYROLL",1000.00
```

`/absolute/books/r.toml`:

```toml
[[rule]]
match = "purchase whole foods"
account = "Expenses:Groceries"

[[rule]]
match = "^acme payroll$"
account = "Income:Salary"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea --file main.bean import s.csv --account Assets:Checking --rules r.toml --apply
```

Actual: exit 0.

```text
1  new  2026-08-02  CARD PURCHASE WHOLE FOODS MKT  -20.00 USD   hash  unmatched
2  new  2026-08-03  CARD PURCHASE WHOLE FOODS MKT  -21.00 USD   hash  purchase whole foods
3  new  2026-08-04  ACME PAYROLL                   1000.00 USD  hash  unmatched
```

Rows 1 and 3 are written flagged `!` against `Expenses:Uncategorized`
(row 3 as `Expenses:Uncategorized -1000.00 USD`).

Control: row 2, the same text on one line, matches and posts to
`Expenses:Groceries`.

Expected: `docs/IMPORTING.md` says imported payees and narrations "replace
CR/LF line breaks with spaces before preview, duplicate matching, and
writing." A user can only write rules against the text `bea` shows, so rule
matching should see the same flattened text and rows 1 and 3 should match.

Cause: `cli/src/bea_engine/csv_mapper.py:1068-1070` passes the stripped raw
cells to `_categorize`, which only NFC-normalizes them (`:1101`) before
`rule.expression.search` (`:1103`). Line breaks are flattened later by
`normalize_entry_strings` in `cli/src/bea_engine/importing.py`.

Fix: apply the same CR/LF-to-space flattening to payee, narration and
category text before rule matching. No dependency or API change.

Blast radius: every CSV import with `--rules` whose export has multi-line
quoted cells; preview and apply.

Dedupe: board search for rules with multi-line, line break and newline finds
w4/done/140 and w4/done/032 (unrelated to rules) and w1/063 (NFC before rule
matching); none covers line breaks.

Acceptance: all three rows show a rule and post to the rule's account; the
one-line control is unchanged. A real-command regression test covers LF and
CRLF cells. Only macOS and the checkout were exercised.
