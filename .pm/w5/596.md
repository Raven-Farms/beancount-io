# `bea doctor missing-open` on a ledger with a syntax error exits 0 with a partial list and never mentions the error (gap in w1/068 and w5/440)

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `56b3a3ad`, checkout `bea 0.3.1`, macOS 26.5.1.
w5/440 made `missing-open` refuse a ledger with undecodable text for exactly
this reason: an empty or partial list reads as "nothing else is missing".
A syntax error that hides directives from the parser gets no such check.
`print-options` and `roundtrip` already run the closure syntax check. No
product fix implemented.

`main.bean`: `option "operating_currency" "USD"`, `include "sub/jan.bean"`,
`2026-01-01 open Assets:Bank USD`. `sub/jan.bean`:

```text
2026-01-10 * "Ok"
  Expenses:Rent 9.00 USD
  Assets:Bank
2026-01-11 * "Cafe" "Broken
  Expenses:Food 4.50 USD
  Assets:Bank
2026-01-12 * "X" "Y"
  Expenses:Coffee 1.00 USD
  Assets:Bank
```

```sh
bea doctor missing-open /abs/main.bean
bea -f /abs/main.bean check
```

Actual: `missing-open` exits 0 with only `2026-01-10 open Expenses:Rent` and
nothing on stderr; `check` exits 1 with `sub/jan.bean:7: Invalid token: 'X"'`.

Control: with the quote closed, `missing-open` lists Rent, Food and Coffee.

Expected: exit 1 naming the syntax error, as `print-options` and `roundtrip`
do.

Cause: `_forward_missing_open` (`cli/src/cli/commands/doctor.py:593-619`)
keeps only the "inactive account" lines from the helper check;
`_closure_syntax_errors_of` runs only for `print-options` (`:393`) and
`roundtrip` (`:509`).

Fix: run the closure syntax check for `missing-open` (and the other location
ops if they share the risk).

Dedupe: w3/364, w5/139, 439 and 440 (done) cover other causes; open w5/567
and 568 cover stdout and symlinks.

Acceptance: the command exits 1 naming `sub/jan.bean:7`. A test pins it.
