# `bea format --check`/`-i` report an include that names a directory as a "missing include", while every read names it correctly as "a directory, not a file"

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
The format closure walk counts any include that does not resolve to a
regular file as missing. For an include that names an existing
directory, "missing" sends the user looking for a file that is in fact
there. [w5/120](./done/120.md) gave reads the precise reason. No product
fix implemented.

Create `main.bean` with `option "operating_currency" "USD"`, `include
"sub"` and one open, plus an existing directory `sub/`. Use isolated
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, and closed stdin.

```sh
bea format --check /absolute/books/main.bean
bea -f /absolute/books/main.bean balance        # control
```

Actual: `format --check` exits 1 with `missing include: "sub" (included
by …/main.bean)` and `1 include(s) are missing.`. `format -i` says the
same. Reproduced twice by the hunter and once by me.

Control: `balance` (and `check`, `list`, `add`) exit 2 with `Included
file '…/sub' … is not readable: it is a directory, not a file.`

Expected: give the actual reason, "is a directory, not a file".

Cause: `_walk_closure` (`cli/src/cli/output.py:395-399`) appends
`MissingInclude` whenever `_include_matches` finds no regular file.
`cli/src/cli/commands/format.py:290` prints it as "missing".

Fix: classify an include that exists but is not a regular file with its
reason (directory, FIFO, other) and print that. No dependency change.

Dedupe: w5/120 fixed reads only. The "missing include" notes (w1/083,
w1/102, w1/159, w3/370, w5/069-071) concern absent files. 438 is the
doctor counterpart.

Acceptance: `format --check` names `sub` as a directory. A truly absent
include still says "missing". A test pins both.
