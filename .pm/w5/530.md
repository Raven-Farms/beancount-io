# Import skips Unicode normalization for importer-extracted accounts and CSV category cells: an NFD `Expenses:Café` is "not open" (and the printed remedy is a duplicate open), or "not an account name" and sent to Uncategorized

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `5d08dc41`, checkout `bea 0.3.1`, macOS 26.5.1. Gap in w3/386.
USAGE (around line 940) says an account typed in another Unicode
normalization "resolves to the same account instead of a false
unknown-account error … for every add, bulk row, and import". w3/386 applied
NFC to `--account`, `--default-account` and rule accounts only. Text from
macOS file names, PDFs and some bank exports arrives NFD. No product fix
implemented.

Ledger: `option "operating_currency" "EUR"`, opens `Assets:Checking EUR`,
`Expenses:Café`, `Expenses:Uncategorized`.

1. **Python importer.** Its `extract` returns one transaction:
   `Assets:Checking -4.50 EUR` and
   `unicodedata.normalize("NFD", "Expenses:Café") 4.50 EUR`.
   `bea --file /abs/main.bean import stmt.txt --config importers.py` shows `1
   blocked`: `Row 1: Account 'Expenses:Café' is not open. Run: bea add open
   --account 'Expenses:Café' --date 2026-03-01 -c EUR.` The diff below it
   prints the NFC name. `--apply` exits 4, and the remedy exits 1 with
   `Duplicate open directive`. Balance and Note rows behave the same.
2. **CSV category column.** `bank.csv` is
   `Date,Description,Amount,Category` / `2026-03-01,Coffee,-4.50,<NFD
   Expenses:Café>`, imported with `--account Assets:Checking`. It exits 0,
   and the row is written `!` to `Expenses:Uncategorized`. stderr says `1
   row(s) carry a category that is not an account name ('Expenses:Café')`,
   a name identical on screen to the open account.

Control: the same cell in NFC posts to `Expenses:Café`; NFD in `--account`,
`--default-account`, rules and bulk `add transactions` resolves.

Expected: both resolve to the open `Expenses:Café`, with the usual NFC/NFD
note.

Cause: the blocked check (`cli/src/bea_engine/importing.py:1182-1183`) tests
the importer's raw names from `_entry_accounts` (`:1124-1125`), and the writer
applies NFC only when printing (`cli/src/bea_engine/ledger/writer.py:258-288`).
`_categorize` (`cli/src/bea_engine/csv_mapper.py:1269-1275`) runs `is_valid`
on the raw cell, where a combining mark fails `\p{L}`.

Fix: NFC-normalize extracted entries' accounts before the blocked check
(reuse `_nfc_entry_accounts`), and the category cell before `is_valid`.

Dedupe: w3/386 (done) explicitly left the category column out; no note
covers importer accounts.

Acceptance: both fixtures write to `Expenses:Café` (`*` for the category
row). Tests pin each.
