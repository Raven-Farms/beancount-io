# `bea doctor roundtrip` in a read-only directory prints a 34-line double traceback (`PermissionError`, then `TypeError: stat: path should be string … not NoneType`) and exits 1

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `04c94595`, checkout `bea 0.3.1`, macOS 26.5.1.
`roundtrip` writes scratch files beside the ledger. bea leaves an unwritable
directory to upstream (`# Upstream reports an unwritable directory itself.`).
Upstream raises, and its `finally` crashes on `os.path.exists(None)`.
w5/438 converted the sibling doctor tracebacks. The exit table gives
permission failures exit 3. No product fix implemented.

```sh
mkdir -p books && printf '2024-01-01 open Assets:Cash USD\n' > books/main.bean && chmod 555 books
bea doctor roundtrip books/main.bean
```

Actual: exit 1, 34 lines on stderr: `PermissionError: … main.roundtrip1.bean`
and `TypeError: stat: path should be string, bytes, os.PathLike or integer,
not NoneType`. Nothing is left behind.

Expected: exit 3 with one line: `doctor roundtrip writes scratch copies beside
the ledger, and …/books is not writable.`

Cause: `cli/src/cli/commands/doctor.py:497` skips the check for an
unwritable directory.

Fix: test the directory (or try creating the scratch name) before running
upstream, and refuse on EACCES or EROFS.

Dedupe: searched roundtrip with read-only and PermissionError. No match.

Acceptance: the command exits 3 with the one-line message. A test pins it.
