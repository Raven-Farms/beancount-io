# A dot command at the start of a one-shot query swallows the lines after it and exits 0, emptying the `-o` export

**Minor · cli · 40–50m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
In a one-shot `bea query`, text that begins with a dot command is exempt
from the one-statement rule and is handed whole to the shell, which treats
the following lines as the dot command's argument. The query never runs,
the failed dot command prints `error:` and exits 0, and an existing `-o`
destination is replaced with an empty file. `bea query ".bogus"` exits 0,
and under `--json` returns a success envelope with empty text. No product
fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
2026-01-05 * "Cafe" "Coffee"
  Expenses:Food  4.00 USD
  Assets:Cash
2026-01-01 query "b-good" "SELECT count(*) AS n"
```

and `/absolute/books/keep.csv` containing `LAST GOOD EXPORT`.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, no TTY, cwd `/absolute/books`.

```sh
printf '.format csv\nSELECT count(*) AS n;\n' | bea -f main.bean query -o keep.csv
bea --json -f main.bean query ".bogus"
printf '.tables\n.run b-good\n' | bea -f main.bean query
```

Actual: the first exits 0 with stderr `error: invalid number of arguments`
and `keep.csv` is now 0 bytes. The second exits 0 with
`{"bea": "0.3.1", …, "data": {"text": ""}, "truncated": false}`. The third
exits 0, prints the table list, and never runs `b-good`.

Control: `printf 'SELEC;\n' | bea -f main.bean query -o keep.csv` exits 2
and leaves `LAST GOOD EXPORT`. `printf 'SELECT count(*) AS n;\n.tables\n' |
bea -f main.bean query` exits 2: `One BQL statement per invocation; got 2.`
`bea -f main.bean query ".run nope"` exits 2.

Expected: `docs/USAGE.md`: one-shot queries carry exactly one statement;
exports "replace the destination only after a successful query"; "Exit 0
is a promise".

Cause: `cli/src/cli/commands/query.py:150-151` (`_refuse_multi_statement`)
returns early for text starting with `.`; the whole string goes to one
`onecmd` (`cli/src/bea_engine/query.py:220`). Upstream's dot-command
`error(...)` prints and returns, so the helper reports success and the
export is written (`query.py:224`).

Fix: refuse a one-shot whose text starts with a dot command and has further
non-blank lines (exit 2); in the non-interactive path turn upstream
dot-command errors into a usage error so the exit is 2, the JSON error
envelope is emitted and no export is written. No dependency change.

Blast radius: `bea query` argument and stdin forms, text and `--json`,
with and without `-o`.

Dedupe: board search for "unknown command", "invalid number of arguments"
and one-statement finds w3/done/277 (`.output` one-shot), w3/done/236
(`.run` missing name), w1/done/042 (statements after `;`) and w3/done/380
(failed query truncating an export); none covers dot-command lines.

Acceptance: the first command exits 2 and leaves `keep.csv` intact;
`bea query ".bogus"` exits 2 with a usage error in text and JSON; a single
valid dot command still works. Only macOS and the checkout were exercised.
