# An importer's `dict` or `Inventory` metadata value is silently dropped on `import --apply` (exit 0), though IMPORTING.md says a value Beancount cannot print stops the import

**Minor · cli · 5–10m · A1.** Real CLI QA, 2026-10-17, HEAD `9e727c0e7`, checkout `bea 0.3.1`, macOS 26.5.1.
IMPORTING.md:565-570 says "a value Beancount cannot print, such as a `float`
or an arbitrary object, stops the import with `Importer NAME row N cannot be
written as a ledger entry` and writes nothing". Beancount's printer skips
`dict` and `Inventory` metadata values without raising, so bea never notices
them. No product fix implemented.

`main.bean` opens `Assets:Checking USD` and `Expenses:Food USD`. `s1.qa` is
`2026-01-10|-12.50|Coffee`. `imps.py` is a minimal `beangulp.Importer` that
identifies `.qa` files on `Assets:Checking`. It builds one transaction
(`Assets:Checking -12.50 USD`, `Expenses:Food 12.50 USD`) whose metadata is
`data.new_metadata(...)` plus `meta["ok"] = {"a": 1}`, `meta["inv"] =
inventory.Inventory()` and `meta["keep"] = "x"`.

```sh
bea --json --file /abs/main.bean import /abs/s1.qa --config /abs/imps.py --apply
```

Actual: exit 0 with `written: 1` and no note or warning. The entry is written
with `keep: "x"` and `import-id`, but no `ok` or `inv` key. The preview diff
omits them too, so nothing tells the user they went missing.

Control: a `set` or `float` value exits 1 with `Importer … row 1 cannot be
written as a ledger entry (ValueError)` (hunter's runs). Bulk `add
transactions` refuses a `dict` metadata value (USAGE).

Expected: exit 1 with the documented message, and nothing written.

Cause: `_writable` (`cli/src/bea_engine/importing.py:726`) checks only that
`format_entry` does not raise. `printer.write_metadata` passes over `dict` and
`Inventory` values.

Fix: in `_writable`, refuse `dict` and `Inventory` values in entry and posting
metadata with the documented message.

Dedupe: w5/319 and 639 cover a dict as the row itself; w5/227 covers `int`
metadata. None covers a dict metadata value.

Acceptance: the fixture exits 1 and writes nothing. A test pins the dict
case.
