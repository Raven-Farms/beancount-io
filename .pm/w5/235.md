# Quitting the query shell without typing anything leaves a history file that makes every later shell session crash at startup

**Major · cli · 30–45m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
Open `bea query`, press Ctrl-D, and the shell writes a history file that
holds only its header. The next `bea query` cannot load it and dies with a
traceback ending `PermissionError: [Errno 1] Operation not permitted`,
exit 1, before any prompt. It stays broken until the user finds and
deletes `~/.config/beanquery/history`. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
2026-01-05 * "Cafe" "Coffee"
  Expenses:Food  4.00 USD
  Assets:Cash
```

Run on a real PTY (stdin, stdout and stderr all the terminal) with the
child's HOME set to a disposable directory (the shell keeps its history
under `$HOME/.config/beanquery/`), XDG_DATA_HOME pointing at the installed
engine, isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1,
`TERM=dumb`, no inherited BEA_FILE/BEA_TOKEN/CI. Start with an empty HOME.

1. Start `bea -f /absolute/books/main.bean query`, wait for the prompt,
   press Ctrl-D.
2. Start `bea -f /absolute/books/main.bean query` again.

Actual: session 1 exits 0 and leaves `$HOME/.config/beanquery/history`
containing only `_HiStOrY_V2_`. Session 2 never reaches a prompt: a boxed
traceback through `beanquery/shell.py`, ending `PermissionError: [Errno 1]
Operation not permitted`, exit 1.

Control: a first session in which one query was typed before Ctrl-D writes
a history with an entry; the second session opens and answers normally. A
worker saw one-shot `bea query "…"` unaffected by the broken history, the
same crash for a 0-byte, unreadable, or directory history, and stock
`bean-query` failing the same way on the header-only file.

Expected: `docs/USAGE.md`: "`.exit` (or `Ctrl-D`) ends the session with
exit 0 and saves its history". A saved history must be loadable; a history
problem should cost the history, not the session, and print one line.

Cause: `beanquery/shell.py:184-189`, reached from
`cli/src/bea_engine/query.py:750` (`build_shell`), guards the history load
only against a missing file. The line editor reports failure for a history
with no entries, and the exit-time write produces exactly that file when
nothing was typed.

Fix: have `bea` own history setup in `build_shell`, as it already does for
the init file: treat any `OSError` from creating the directory or reading
the history as "start with empty history" with a one-line note naming the
path, and make the exit-time write tolerate `OSError`. No dependency
change.

Blast radius: every interactive `bea query` and `bea query --source`
session after one empty session.

Dedupe: board search for `history`, `HiStOrY`, `read_history_file` and
"Operation not permitted" finds only w1/done/066 (history lost when Ctrl-C
killed the shell); nothing covers an unloadable history.

Acceptance: after an empty session the next session opens normally; with
the history file empty, unreadable or a directory the shell opens with a
one-line note and no traceback. Only macOS (libedit) and the checkout were
exercised.
