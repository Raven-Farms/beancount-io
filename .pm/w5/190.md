# The 17th managed price include fails with a misleading "File glob" error, and `price export` exits 0 with the URL left in the snapshot

**Minor · cli · 45m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A ledger may load at most 16 managed price feeds. The 17th is not
reported as over a limit: `check` says `File glob "http://…" does not
match any files` with no file or line, reads and writes are refused, and
`price export` exits 0 while leaving the URL include in the exported
ledger, which stock tools then reject. The limit is not documented. No
product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Assets:Coin BTC
2024-01-01 open Equity:Opening
2024-01-01 commodity BTC
2024-01-01 commodity USD

2024-01-02 * "Open"
  Assets:Cash  10000.00 USD
  Equity:Opening

2024-01-03 * "Buy"
  Assets:Coin  2 BTC {1000.00 USD}
  Assets:Cash  -2000.00 USD
```

followed by 17 lines `include "http://127.0.0.1:PORT/prices/C1"` …
`C17`.

The feed is a **simulation**: a loopback server on `127.0.0.1` allowed
through `MANAGED_PRICE_ORIGINS`, which proves local handling only, not the
real service's behaviour. Use isolated BEA_CONFIG_DIR and a fresh
XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no inherited BEA_FILE/BEA_TOKEN,
closed stdin, no TTY, cwd `/absolute/books`. Each simulated feed returns one line, `2024-01-05 price BTC 1100.00
USD`.

```sh
bea -f main.bean check
bea -f main.bean price export
grep -c 'include "http' main-export/main.bean
```

Actual: `check` exits 1: `<load>:0: File glob
"http://127.0.0.1:PORT/prices/C17" does not match any files`. `price
export` exits 0 with `Exported 17 files`, and the exported `main.bean`
still contains one `include "http…` line.

Control: with 16 includes `check` exits 0, the export exits 0 and no URL
include is left. A worker saw `price status` list 16 sources with the
17th absent, and stock `bean-check` reject the 17-feed export.

Expected: an over-limit include reported as such — naming the include,
its file and line and the limit — and `docs/USAGE.md`: "An unavailable
source refuses the export unless `--allow-errors` carries its marker
alone", for a copy meant "for stock tools".

Cause: `cli/src/bea_engine/managed_load.py:288-289` drops sources past
the budget silently; the include is then left verbatim for Beancount to
treat as a file glob, and `export_portable` judges availability only
from the sources that were loaded.

Fix: treat an over-limit include as an unavailable source with a clear
message, list it in `price status`, refuse it in export like any
unavailable source, and document the limit. No dependency change.

Blast radius: ledgers tracking more than 16 pairs.

Dedupe: board search for the cap finds only the milestone text that
defines it; nothing covers how it surfaces.

Acceptance: `check` names `main.bean` and the line of the 17th include
and states the 16-source limit; `price export` exits nonzero without
`--allow-errors`; the 16-feed control is unchanged. Only macOS, the
checkout and a loopback simulation were exercised.
