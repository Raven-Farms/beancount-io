# The query regex pre-check refuses valid queries: it checks the right-hand literal of `?~` (whose pattern is the left operand), and only the first literal of a concatenated `~` pattern (adjacent to w5/558)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `a513b1113`, checkout `bea 0.3.1`, macOS 26.5.1. Adjacent to w5/558 (done); the operand regex dates from w5/103.
No product fix implemented.

1. **`?~`.** beanquery defines `x ?~ y` as `re.search(x, y)`
   (`beanquery/query_compile.py:303-305` in the managed engine), so the
   pattern is on the left. On `qm.bean` (two `Expenses:Books` transactions,
   narrations "Primer" and "Cookbook"):

   ```sh
   bea --file /abs/qm.bean query "SELECT date, narration WHERE account = 'Expenses:Books' AND narration ?~ 'POS 1234 Primer (Bookshop'"
   ```

   This exits 2 with `'POS 1234 Primer (Bookshop' is not a valid regular
   expression: missing ), unterminated subpattern at position 16.` The
   literal is the subject, and `bean-query` answers `2026-01-05 Primer`
   (hunter's run). `--json` and `--source` refuse the same way.
2. **Concatenation.** `bea --file /abs/rx.bean query "SELECT DISTINCT account
   WHERE account ~ '^(' + 'Assets|Expenses' + '):'"` exits 2 with `'^(' is not
   a valid regular expression…`. `bean-query` answers both accounts (hunter's
   run). The function branch of the same pre-check already notes that "a
   concatenated pattern is first known when it runs".

Control: `'(' ?~ narration` is still refused at compile time, and `account ~
'^(Assets|Expenses):'` answers.

Expected: both queries run.

Cause: `_PATTERN_LITERAL` (`cli/src/bea_engine/query.py:1901`) matches the
`~ '…'` inside `?~`, and its `~` branch has no lookahead for a following `+`.

Fix: exclude `?~` from the right-operand branch (and check a literal just
before `?~` instead), and pre-check a `~`/`!~` literal only when no `+`
follows it.

Dedupe: w5/558, 509, 429 and 103 (done) assumed the right side; w5/683 (open)
covers run-time operator warnings.

Acceptance: both queries answer; `'(' ?~ narration` is still refused.
