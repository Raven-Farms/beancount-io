# Without `--time`, report series end on a date after the report's own `as_of`, and the date moves with `--interval`

**Minor · cli · 45–60m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
The CLI twin of the dashboard finding w1/done/022. A report run without a
time filter states its period and `as_of` correctly, but the last point of
each interval series is dated at the end of the surrounding interval: with
`-i yearly` a ledger whose last entry is 2026-02-10 gets a net-worth point
dated 2026-12-31, after `as_of` and in the future. The amounts are right;
the date is wrong and changes with the interval. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Equity:Opening USD
2026-01-01 open Expenses:Food USD
2026-01-02 * "Opening"
  Assets:Cash        1000.00 USD
  Equity:Opening    -1000.00 USD
2026-02-10 * "Lunch"
  Expenses:Food        10.00 USD
  Assets:Cash         -10.00 USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea --json -f main.bean report balance-sheet -i yearly
bea -f main.bean report income-statement -i quarterly
```

Actual (exit 0): the JSON has `"period": {"start": "2026-01-02",
"end_exclusive": "2026-02-11"}`, `"as_of": "2026-02-10"`, and
`"net_worth_series": [{"date": "2026-12-31", "balance": {"USD":
"990.00"}}]`. The text report is headed `Income Statement — 2026-01-02
through 2026-02-10` and its only row is `PERIOD END 2026-03-31`.

Control: `bea --json -f main.bean report balance-sheet -i yearly -t
"2026-01-02 - 2026-02-10"` gives the same `period` and `as_of` and
`"net_worth_series": [{"date": "2026-02-10", …}]`. A worker saw the last
date move across daily, weekly, monthly, quarterly and yearly intervals in
`overview`, `income-statement` and `balance-sheet` alike.

Expected: `docs/USAGE.md`: "asset/liability series are balances as of each
date", and balance series "must still reach the as-of date"; a point dated
after `as_of` is a balance the ledger cannot know. The last bucket should
be dated at `as_of`, as it is under `--time`.

Cause: `cli/src/fava/ledger.py:224-229` (`interval_ranges`) passes
`complete = not self.date_range`, so without a time filter the vendored
`interval_ends` (`cli/src/fava/util/date.py:258-274`) extends the last
range to the next interval boundary, while
`cli/src/bea_engine/report.py:432` publishes `period` and `as_of` from the
last entry date.

Fix: when no time filter is set, clip the final interval at the last entry
date so its date equals `as_of`; keep full-width earlier buckets and the
existing `--time` behaviour. No dependency change; series dates change.

Blast radius: the three interval reports (`overview`, `income-statement`,
`balance-sheet`), text and JSON, for every run without `--time`.

Dedupe: board search for `as_of`, `end_exclusive`, "future" and "interval
end" finds w3/done/349 and w1/done/051 (series stopping before `as_of`,
the opposite direction), w3/done/375 and 384 (fragments under `-t`),
w5/193 (placeholder-dated directives) and w1/done/022 (the dashboard
original); none covers the CLI's unfiltered case.

Acceptance: both commands date their last series point 2026-02-10; no
series date exceeds `as_of` for any interval; the `--time` control is
unchanged. Only macOS and the checkout were exercised.
