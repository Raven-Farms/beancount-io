# Reused bank references after w5/599: a native-ID hit a month away hides the same-day hand-entered twin, so the documented `--duplicates include` double-books; and re-importing a month is a "conflict" when the latest entry under the reused ID has a different amount (incomplete fix of w5/599)

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-17, HEAD `5b305b485`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/599 (done).
IMPORTING (w5/599) says a re-import "is matched to the entry under that ID
dated nearest the row", and that for a reused reference you should "choose
`--duplicates include` to keep both". No product fix implemented.

The ledger opens `Assets:Checking`, `Expenses:Rent` and `Expenses:Uncategorized`.
CSV rows carry a `Reference Number` mapped to `id`.

1. **Hidden twin.**
   - The ledger has `2026-01-01 * "Rent January"` with `import-id:
     "bank:RENT-AUTOPAY"` (−1200.00), and a hand-entered `2026-02-01 * "Rent
     February"` (−1200.00, no IDs).
   - Importing `2026-02-01,Rent February,-1200.00,RENT-AUTOPAY` exits 4: `Stable
     ID bank:RENT-AUTOPAY is already in the ledger on 2026-01-01, 31 days from
     this row; a reference reused on other dates … is not a unique ID.`. The
     February twin is never mentioned.
   - Following the docs with `--duplicates include` writes a second "Rent
     February" (two −1200.00 rows on 2026-02-01).
   - Without the January entry, the same row is matched to February.
2. **Latest entry wins.** The ledger has January −1200.00 and February −1210.00,
   both under `RENT-AUTOPAY`. Importing `jan.csv` (January's −1200.00 row plus
   a new `2026-01-05,Coffee,-4.00,COFFEE-1`) exits 4: `Row 1 (conflict): Stable
   ID matches an entry with different transaction data.`, with the match on
   February (line 12). Coffee is not written, and the file is unchanged.
   January (0 days away, same amount) is an exact duplicate.

Expected: (1) name the same-day twin as the match (or both). (2) Choose the
nearest agreeing entry under the ID before judging a conflict; Coffee is
written.

Cause: the w5/599 branch (around `cli/src/bea_engine/importing.py:498-510`)
sits inside `if hits:`, and the twin and counterpart checks are `elif`s. The
hit and conflict test uses `identities[key]`, which holds only the latest
entry under the ID (around `:438-457`).

Fix: run the twin check even after a distant native-ID hit, and match the
nearest agreeing entry first.

Dedupe: w5/599 (done) is the parent; w3/420, w3/326 and w1/168 cover other
conflict causes.

Acceptance: case 1 names February; case 2 writes Coffee with exit 0.
