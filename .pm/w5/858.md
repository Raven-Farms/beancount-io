# Applying an import with both blocked and invalid rows hides the invalid rows behind the blocked refusal (incomplete fix of w5/638)

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-17, HEAD `8e35a3636`, checkout `bea 0.3.1`, macOS 26.5.1. Twice from pristine fixtures, isolated config/cache, stdin closed, no TTY. No product fix implemented.

Open `Assets:Checking USD` and `Expenses:Food USD` on 2026-01-01. A Python importer named `bank` files under `Assets:Checking` and returns three February transactions, using the class and Beancount constructors in [855](./855.md):

| Row | Checking | Counter posting |
|---|---|---|
| 1, Feb 1 | −2 USD | Expenses:Food +2 USD |
| 2, Feb 2 | −4 USD | Expenses:Unopened +4 USD |
| 3, Feb 3 | −3 USD | Expenses:Food +3.5 USD |

```sh
bea --file /abs/main.bean import /abs/bank.txt --config /abs/imp.py
bea --file /abs/main.bean import /abs/bank.txt --config /abs/imp.py --apply
```

Actual: preview exits 0, counts `1 ready, ... 1 blocked, 1 invalid`, and stderr names `Row 3: Transaction does not balance: (0.5 USD)`. Apply exits 4, says one row is blocked, and lists only row 2 with an `add open` remedy. Row 3 and its imbalance disappear from both human streams. The ledger is byte-identical after both commands.

Expected: the apply refusal includes both row 2's blocked reason and row 3's accounting error, so fixing the listed problems allows the next apply to succeed. Preserve the existing conflict exit category; the issue is missing diagnostics. IMPORTING and w5/638 promise invalid rows are named on apply.

Cause: the review branch in `cli/src/bea_engine/importing.py:757` builds details from conflict, possible_duplicate and blocked rows only. It raises before the validation-error refusal below it can name invalid rows. This affects the shared import/apply path for CSV and Python importers when statuses mix.

Fix: retain row-numbered validation errors in the review refusal and make its guidance acknowledge them. Avoid printing the same error twice when no review statuses exist.

Dedupe: whole-board searches for blocked/invalid mixed refusals found no open coverage. Parent w5/638 (done, `8c1d18ce7`) tested invalid rows without this competing refusal.

Acceptance: human and JSON apply refusals carry both actionable errors; an invalid-only batch keeps its existing exit 1, and every rejected run preserves ledger bytes.
