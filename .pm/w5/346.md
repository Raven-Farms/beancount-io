# A write aimed at an included leaf with `--file` succeeds (exit 0) after validating only that leaf, and silently leaves the root ledger invalid (failed balance, reference after a close) or double-booked (import dedupe misses root rows)

**Minor · cli · 30–45m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
When `--file` names an included file that is valid on its own, `add` and
`import --apply` validate and deduplicate against that file alone. When
the write succeeds, nothing says the root was not checked:

- A balance assertion or a `close` can contradict transactions in the
  root.
- Import dedupe cannot see rows already booked in the root.

The failure path already knows the file is a leaf ("on its own it lacks
the accounts and options that root provides"). The success path never
asks. [343](./343.md) covers one instance, a duplicate `open` written
after following a wrong remedy. This note covers the general silent
success. No product fix implemented.

Create disposable `/absolute/my books/main.bean`:

```beancount
option "operating_currency" "USD"
include "sub dir/extra.bean"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
2026-01-01 open Equity:Opening
2026-01-04 * "Dep" "dep"
  Assets:Bank  100 USD
  Equity:Opening
2026-02-01 * "Spend" "x"
  Expenses:Food 3 USD
  Assets:Bank
```

Create `/absolute/my books/sub dir/extra.bean`, containing `include
"nested/deep.bean"`, and `/absolute/my books/sub dir/nested/deep.bean`,
containing `2026-01-01 open Assets:Bank USD`. The root passes `bea check`.
(Line numbers below refer to this fixture.)
Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, and closed stdin. Start each case from a
pristine copy.

```sh
bea -f '/absolute/my books/sub dir/nested/deep.bean' add balance --date 2026-03-01 --account Assets:Bank --amount '0 USD'
bea -f '/absolute/my books/main.bean' check
bea -f '/absolute/my books/sub dir/nested/deep.bean' add close --account Assets:Bank --date 2026-01-20
bea -f '/absolute/my books/main.bean' check
```

Actual:

- The balance write exits 0 with `Added 1 balance to …/deep.bean.`. The
  root `check` then exits 1 with `deep.bean:3: Balance failed for
  'Assets:Bank': expected 0 USD != accumulated 97 USD`.
- The close write exits 0. The root `check` then exits 1 with
  `main.bean:9: Invalid reference to inactive account 'Assets:Bank'`.
- Import, found by the hunter:
  1. Add `open Expenses:Uncategorized USD` to `deep.bean`.
  2. Import a CSV with a `2026-02-01,Spend,x,-3.00` row plus one new row
     via `bea -f …/deep.bean import s.csv --csv … --account
     Assets:Bank`. The preview shows both rows as `new`.
  3. Run the same import against the root. It flags the first row as
     `possible_duplicate` of `main.bean:9`.
  4. Run the leaf `--apply`. It exits 0 with `written: 2`, and Bank is
     double-booked.

The balance and close cases were reproduced twice each by me and twice by
the hunter.

Control: `bea -f '/absolute/my books/main.bean' add close --account
Assets:Bank --date 2026-01-20 --into 'sub dir/nested/deep.bean'` is
refused with exit 1. The message names the reference at `main.bean:9`.

Expected: `docs/USAGE.md` says "For split ledgers, keep `--file` pointed
at the root and choose the included destination with `--into` … Validation
includes the entire root ledger". When `bea` can tell that the target is
an included leaf, which it already does for error hints, the write should
either:

- validate and deduplicate against the including root, refusing as the
  `--into` control does; or
- at minimum, refuse or warn that the root was not checked, and print the
  `--into` recipe.

It should not report a plain success.

Cause:

- Validation (`cli/src/bea_engine/ledger/write.py`, the loop around
  `:1191-1250`) and import dedupe use the invoked file's own load.
- `including_root` (`write.py:982-1004`) is consulted only when building
  error hints (`write.py:1248-1250`, `ledger/adding.py:742`).

Fix: on a write whose target has an including root (found with the climb
from [347](./347.md)), either validate against that root with the target
as the `--into` destination, or refuse with exit 2 and the `--into`
recipe. The first matches the documented guarantee. The second is
cheaper and keeps the rule "point `--file` at the root". It should cover
every `add` subcommand, bulk add and `import --apply`. No dependency
change.

Blast radius: every write run with `--file` on an included leaf that
loads cleanly by itself, a common layout (`accounts.bean`, per-year
files). The result is a broken or double-booked root, discovered only on
the next whole-ledger command.

Dedupe: searched `.pm/**`, including `done/`, for "lacks the accounts",
`including_root`, "included by" and "Run against the root". Related notes:

- w3/438, w5/112 and w5/124: hint wording and cost.
- 343: the duplicate-open instance. Its fix sentence suggests root
  validation, but its acceptance tests only that case.

Acceptance: on the fixture, the leaf balance and close writes, and the
leaf import `--apply`, either fail like the `--into` control with the
ledger unchanged, or refuse with the `--into` recipe. A real-command
regression test covers balance, close and import against a self-valid
leaf. Only macOS and the checkout were exercised.
