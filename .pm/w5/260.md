# A list-valued column next to an aggregate with no `GROUP BY` fails with `TypeError: unhashable type`

**Minor · cli · 20m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
`SELECT other_accounts, count(*)` (implicit grouping) exits 1 with a bare
Python `TypeError`, while the explicit `GROUP BY other_accounts` form gets
a clear usage error. No product fix implemented.

Create disposable `/absolute/books/m.bean`:

```beancount
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
2024-01-02 * "Shop" "x" #trip
  Expenses:Food 5 USD
  Assets:Cash
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea --file m.bean query "SELECT other_accounts, count(*)"
```

Actual: exit 1.

```text
Error: TypeError: unhashable type: 'list' Pass --debug before the command for a traceback.
```

A worker saw the same for `SELECT balance, sum(number)` (`'Inventory'`)
and `SELECT meta, count(*)` (`'dict'`), category `validation` under
`--json`.

Control: `bea --file m.bean query "SELECT other_accounts, count(*) GROUP BY
other_accounts"` exits 2: `Cannot run this BQL query: GROUP-BY a
non-hashable type is not supported: "Column(name='other_accounts')".`

Expected: the same exit 2 and explanation for the implicit form; a query
mistake is a usage error, not a ledger validation failure.

Cause: the explanation at `cli/src/bea_engine/query.py:1141` fires only on
Beanquery's compile-time message. With implicit grouping the failure is a
run-time `TypeError` during aggregation, which reaches the generic
handler.

Fix: detect an unhashable non-aggregate column beside an aggregate before
execution, or map this `TypeError` to the usage error with the
`joinstr(...)` advice. No dependency or API change.

Blast radius: one-shot and stored queries; `--source` shows a traceback
(a worker's observation).

Dedupe: board search for "unhashable" finds nothing; w3/done/353 and
w1/done/161 cover the explicit `GROUP BY`/`DISTINCT` forms, w5/105 covers
set-cell ordering.

Acceptance: the command exits 2 with a one-line explanation naming the
column; the explicit control is unchanged. Only macOS and the checkout
were exercised.
