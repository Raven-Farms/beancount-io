# The `bea ingest` `CONFIG` preflight refuses a working ingest script and lets an annotated `CONFIG` module through as a silent no-op

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, Beangulp 0.2.0, macOS.
`bea ingest` decides from the script's source text whether it is a real
ingest script or a `bea import --config` module. The text test is wrong in
both directions: a working script that keeps its importers in `CONFIG` and
calls `beangulp.Ingest` through a helper is refused with exit 2 and no
override, while a config-only module written `CONFIG: list = […]` passes
and does nothing with exit 0. No product fix implemented.

`bank.py` (the importer):

```python
import csv, datetime
from decimal import Decimal
import beangulp
from beancount.core import data, amount

class Bank(beangulp.Importer):
    @property
    def name(self): return "bank"
    def identify(self, filepath): return filepath.endswith(".csv")
    def account(self, filepath): return "Assets:Checking"
    def date(self, filepath): return datetime.date(2026, 8, 31)
    def filename(self, filepath): return "bank.csv"
    def extract(self, filepath, existing):
        out = []
        with open(filepath, newline="", encoding="utf-8") as fh:
            for i, row in enumerate(csv.DictReader(fh), 2):
                meta = data.new_metadata(filepath, i)
                units = amount.Amount(Decimal(row["Amount"]), "USD")
                out.append(data.Transaction(meta, datetime.date.fromisoformat(row["Date"]), "*", row["Payee"], row["Narration"], frozenset(), frozenset(), [
                    data.Posting("Assets:Checking", units, None, None, None, None),
                    data.Posting("Expenses:Misc", -units, None, None, None, None)]))
        return out
```

Case (a), in `/absolute/h1`: `bank.py`, `dl/a.csv`:

```csv
Date,Payee,Narration,Amount
2026-08-02,Cafe,Coffee,-5.25
```

`runner.py`:

```python
import beangulp
def run(importers, hooks=None):
    beangulp.Ingest(importers, hooks)()
```

and `ingest.py`:

```python
from bank import Bank
from runner import run

CONFIG = [Bank()]

if __name__ == "__main__":
    run(CONFIG)
```

Case (b), in `/absolute/c1`: `dl/a.csv` as above and `annot.py`, which is
`bank.py` followed by `CONFIG: list = [Bank()]`.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY.

```sh
cd /absolute/h1 && bea ingest identify dl
cd /absolute/c1 && bea ingest identify --config annot.py dl
```

Actual: (a) exits 2: `/absolute/h1/ingest.py looks like a `bea import
--config` module (CONFIG = [...]). `bea ingest` needs a script that calls
beangulp.Ingest(...)(); run `bea import --config` for this file instead.`
(b) exits 0 with empty stdout and stderr.

Controls: (a) with the variable renamed `IMPORTERS` exits 0 and prints
`dl/a.csv ... OK / bank`. (b) written `CONFIG = [Bank()]` is refused with
exit 2 as documented.

Expected: `docs/USAGE.md` — "`bea ingest` needs a script that calls
`beangulp.Ingest(...)()`; a `CONFIG = [...]` import module is refused with
exit 2". Script (a) does call it and should run; module (b) is that import
shape and should be refused, not exit 0 having done nothing.

Cause: `cli/src/cli/commands/ingest.py:108-110` searches the text for
`Ingest\s*\(` and then `^CONFIG\s*=`. A call in an imported module is
invisible to the first; an annotated assignment does not match the
second.

Fix: decide from behaviour — treat exit 0 with empty output as the
config-only no-op — or at minimum widen the pattern to annotated
assignments and stop refusing a script that has a `__main__` block. No
dependency or API change.

Blast radius: `ingest identify`, `extract` and `archive`.

Dedupe: w3/done/317 (the original silent exit 0) and w1/done/m23/t006
cover only the plain `CONFIG = [...]` form.

Acceptance: (a) runs and lists the file; (b) exits 2 with the existing
message; the two controls are unchanged. Only macOS and the checkout were
exercised.
