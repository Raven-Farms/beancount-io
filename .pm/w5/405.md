# Under a non-UTF-8 locale, `list`/`balance`/`report` tables and `list --details` "Beancount syntax" are written in the locale codec with `İ` escapes, so redirected output mixes Latin-1 bytes with literal escapes, while `query` and `format` stay UTF-8

**Trivial · cli · 15–20m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
[w5/121](./done/121.md) routed `format` and `query` data through
`write_data`, which always writes UTF-8. Its resolution says: "Not fixed
here: `bea list` tables under cp1252 still escape". Other data-printing
commands go through stdout, which is set up with `errors="backslashreplace"`
in the locale's codec. Two problems follow:

- Redirected tables become Latin-1, with `İ`-style escapes for
  characters outside it.
- `list --details`, which renders entries "in Beancount syntax", prints
  `"İPEK"` and `Expenses:İstanbul`. Saved and reloaded, that
  names a different payee and account. This is the failure w5/121 fixed
  for `format`.

No product fix implemented.

Use the ledger from [404](./404.md) plus `2026-01-02 * "Zoë" "x"`, with the
same environment.

```sh
LC_ALL=en_US.ISO8859-1 bea -f /absolute/books/main.bean list transaction > t.txt; file t.txt
LC_ALL=en_US.ISO8859-1 bea -f /absolute/books/main.bean list transaction --details
LC_ALL=en_US.ISO8859-1 bea -f /absolute/books/main.bean balance
```

Actual:

- `t.txt` is ISO-8859 text (`Zoë` as byte `eb`).
- `--details` prints `2026-01-03 * "İPEK" "istanbul"`.
- `balance` and `report balance-sheet` show `İstanbul`.
- JSON is correct.

Reproduced by the hunter under two locales and two
`PYTHONIOENCODING` values, and by me once (`--details`).

Control: `bea query "SELECT payee"` under the same locale writes UTF-8.

Expected: `docs/USAGE.md` says ledger text on stdout is UTF-8 whatever the
locale, and that only messages are escaped. Table rows and `--details`
text are ledger data, so they should be UTF-8 too. At the very least,
`--details` should be. If tables are meant to stay in the locale codec,
USAGE should say so.

Cause: tables and `--details` print through the default stdout, which
`cli/src/cli/main.py:51` reconfigures with `backslashreplace`. Only
`format` and `query` call `output.write_data` (`cli/src/cli/output.py:63-82`).

Fix: route `list`, `balance`, `report` and `--details` data through
`write_data`, or make stdout UTF-8 for data-producing commands while
keeping `backslashreplace` for stderr. No dependency change.

Blast radius: text output of `list`, `balance` and `report` under
non-UTF-8 locales or `PYTHONIOENCODING`.

Dedupe: w5/121 (done) names this as not fixed, and no open note covers
it. 404 covers the forwarded commands.

Acceptance: under `LC_ALL=en_US.ISO8859-1`, `list --details` prints
UTF-8 `İPEK`, and redirected tables are UTF-8. A test pins
`--details`.
