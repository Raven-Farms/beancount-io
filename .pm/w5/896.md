The two fills sell 10 of 20 shares. FIFO books the first fill from the
100/110 USD lots and the second from the 120 USD lot. Holdings are **10
HOOL**; realized gains are **−360 USD** in Beancount's income sign.

`importers.py` extracts that same trade from any synthetic `statement.txt`:

```python
from datetime import date
from decimal import Decimal
from beancount.core import data, amount, position
from beancount.core.number import MISSING

class Broker:
    def identify(self, path): return str(path).endswith('.txt')
    def account(self, path): return 'Assets:Broker:HOOL'
    def extract(self, path, existing_entries=None):
        meta = data.new_metadata(path, 1)
        posts = [data.Posting(
            'Assets:Broker:HOOL', amount.Amount(Decimal(q), 'HOOL'),
            position.CostSpec(MISSING, None, None, None, None, False),
            amount.Amount(Decimal('150'), 'USD'), None, None)
            for q in ('-4', '-6')]
        posts += [
            data.Posting('Assets:Cash', amount.Amount(Decimal('1500'), 'USD'), None, None, None, None),
            data.Posting('Income:CapitalGains', None, None, None, None, None)]
        return [data.Transaction(meta, date(2024, 2, 1), '*', None,
                                 'Sold HOOL fills', data.EMPTY_SET, data.EMPTY_SET, posts)]
CONFIG = [Broker()]
```

Actual: preview reports **1 ready, 0 possible duplicates**. Apply exits
**0**, writes the sale **again**, and holdings become **0 HOOL** instead
of 10. The file contains two `Sold HOOL fills` entries, with the sale cash
posted twice. A fresh check still exits **0**: the empty gain leg books
against the remaining lot, leaving a valid ledger with the wrong activity.
`--duplicates skip` cannot prevent it because the row was called new.

Native-ID variant, also twice: remove the hand-entered sale and set
`meta['bank_id'] = 'QA-SALE-001'` in the importer. First apply writes one
valid sale, leaving 10 shares. Re-importing the identical statement previews
a **conflict** and apply exits **4**: `Stable ID matches an entry with
different transaction data.` It preserves the ledger, but rejects its own
unchanged write. This also reproduces when the first sale drains an initial
10 shares completely and the gain posting is supplied explicitly.

Controls, each twice: hand-entered controls retain 10 shares; corresponding
native-ID fixtures also re-import exactly.

- Combine the two same-price fills into one `-10 HOOL {}` posting:
  hand-entered twin is skipped and native-ID re-import is exact.
- Keep the two fills but buy 4 at 100 and 16 at 120, so the first fill
  does not split across lots: same successful duplicate behavior.
- Keep the original lots and price the second fill at 160 USD: same
  successful matching, with correct initial gains of −420 USD.

Expected: the booked representation and the importer's open-cost fills
describe the same source movement. Recognize a hand-entered twin as a
possible duplicate, so `skip` preserves 10 shares; recognize a shared
native ID as exact. `cli/docs/IMPORTING.md:579–584` and completed w5/603
explicitly require matching open-cost sales to their split booked lots.

Cause: `_legs_agree` in `cli/src/bea_engine/importing.py:1400–1418` tries
each incoming fill separately. `_split_booking` (:1428–1449) selects **all**
remaining compatible booked legs and requires their total to equal that
one fill. For incoming `−4` then `−6` at the same price, the first fill sees
booked `−2 @100`, `−2 @110`, `−6 @120` totaling −10, so it fails instead
of matching the first two and leaving the third for the second fill.
That predicate feeds native-ID content checks, hand-entered twin lookup
and generated/legacy-ID matching in the same module.

Fix: compare the combined compatible source quantities, preserving stated
cost, currency, label and price constraints and accounting for each booked
quantity once. Do not require every compatible lot to belong to one fill,
ignore cost differences, or weaken stable-ID conflict checks. Preserve
the existing single-fill and differing-lot/price controls. No dependency
or API change is needed.
