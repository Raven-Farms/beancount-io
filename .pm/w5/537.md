# `add transactions --partial` is still quadratic when a row breaks a balance assertion already in the ledger: 400 rows take ~9 s, 800 ~34 s, 10k an estimated hour and a half (gap in w5/123)

**Major · cli · 30–45m · A1.** Real CLI QA, 2026-10-16, HEAD `c3c42a48`, checkout `bea 0.3.1`, macOS 26.5.1.
w5/123 made `--partial` cost three loads at any size, by dropping the rows the
refused batch's errors name. Its resolution keeps row-by-row trials "only
when an error cannot be placed on an appended row". A balance assertion
already in the ledger is exactly such an error: it sits on an existing line,
not on an appended row. The fallback then does one full load per row over a
growing batch. The atomic refusal itself tells the user to "Pass --partial",
and a monthly statement assertion is an ordinary ledger line. No product fix
implemented.

`bal.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Assets:Cash
2026-01-01 open Expenses:Food
2026-12-31 balance Assets:Checking 0 USD
```

`balN.json`: N rows of `{"date": "2026-02-01", "narration": "rI",
"postings": [{"account": "Expenses:Food", "amount": "1 USD"}, {"account":
"Assets:Cash"}]}`, with row N/2 posting to `Assets:Checking` instead of
`Assets:Cash` (it breaks the assertion).

```sh
bea -f /abs/bal.bean add transactions --from bal400.json            # 0.5 s, exit 1, "Pass --partial…"
bea -f /abs/bal.bean add transactions --partial --from bal400.json
```

Actual: `Added 399 of 400 transactions; 1 row was rejected.` (correct rows);
time 2 s at 100 rows, about 9 s at 400, about 34 s at 800.

Control: the same 800 rows with the bad row posting to an unknown account
finish in under 1 s.

Expected: a bounded number of loads (w5/123's acceptance), or at worst
O(k log n) for k bad rows.

Cause: `_rows_with_errors` (`cli/src/bea_engine/ledger/adding.py`, about
`:1448`) returns `None` when an error's location is an existing line; the
caller (`:1393-1401`) then falls back to `write.validate_append(file,
[*texts, text])` per row.

Fix: replace the per-row fallback with bisection (group testing), or
attribute balance and booking errors to the rows that touch the asserted
account and currency before the assertion date.

Dedupe: w5/123 (done) is the fix this extends; its test counts loads only for
attributable errors.

Acceptance: 800 rows with one assertion-breaking row finish with a bounded
number of loads (a test counts them at two sizes) and the same rows written.
