# `add open -c USD -c ''` silently drops the blank currency; a lone `-c ''`, `--tag ''` and `-v ''` are all refused

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `7334a32b`, checkout `bea 0.3.1`, macOS 26.5.1.
The w5/239 and w5/382 rule is that an empty value is not an omitted one:
`-c "$UNSET"` usually means a script lost a variable. Here the blank is
refused only when every value is blank. No product fix implemented.

```sh
bea -f /abs/main.bean add open --date 2026-01-05 -a Assets:Wallet -c USD -c ''
```

Actual: exit 0, writes `2026-01-05 open Assets:Wallet USD`.

Control: `-c ''` alone exits 2 with `Every --currency value is blank after
trimming…`; `--tag a --tag ''` exits 2.

Expected: exit 2, naming the blank `-c` value, nothing written.

Cause: `cli/src/bea_engine/ledger/adding.py:173-177` filters blanks out and
refuses only when nothing is left.

Fix: refuse when any value is blank, with the existing wording adjusted.

Dedupe: searched `blank after trimming`; only w4/007 (unrelated) matches.
w5/239 and 382 set the rule for other options.

Acceptance: the command exits 2 and writes nothing. A test pins it.
