# A lone carriage return in the ledger marks every later directive "generated": `--on-disk` hides them and `add price` loses its conflict guard

**Major · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
One raw CR byte inside a string (pasted text, or `\r\r\n` endings from a
double conversion) shifts `bea`'s own line table by one. Every directive
after it is then judged plugin-generated: `list --on-disk` omits written
transactions and notes, and `add price` accepts a conflicting quote for a
date that already has one, exit 0. `bea check` passes. This is the residual
of w1/done/049 (rated major), whose fix covered U+2028, U+0085 and form
feed but not `\r`. No product fix implemented.

Create disposable `/absolute/books/main.bean` with a raw CR between
`pasted` and `text`:

```sh
python3 -c "open('main.bean','wb').write(b'2024-01-01 open Assets:Cash USD\n2024-01-01 open Equity:Open USD\n\n2024-01-02 * \"Shop\" \"pasted\rtext\"\n  Assets:Cash   10.00 USD\n  Equity:Open\n\n2024-01-03 * \"Cafe\" \"coffee\"\n  Assets:Cash   5.00 USD\n  Equity:Open\n2024-01-04 note Assets:Cash \"hello\"\n2024-01-05 price USD 1.0 EUR\n')"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean check
bea -f main.bean list transaction --on-disk
bea -f main.bean list note --on-disk
bea --json -f main.bean add price --date 2024-01-05 --currency USD --amount "1.2 EUR"
```

Actual: `check` exits 0. `list transaction --on-disk` shows only the
2024-01-02 row; the 2024-01-03 transaction is missing. `list note
--on-disk` prints `No notes found.` `add price` exits 0 with `"written":
1, "duplicate": false`; the file now has two different USD prices for
2024-01-05.

Control: the same file with a space in place of the CR lists both
transactions and the note, and `add price` exits 2: `USD already has a
2024-01-05 price of 1.0 EUR (at /absolute/books/main.bean:12); refusing
1.2 EUR. Pass --force to record another quote.` A worker saw the same with
`\r\r\n` line endings, where `list transaction --on-disk` returned
nothing at all, and an exact-duplicate price written twice.

Expected: `docs/USAGE.md` — "`--on-disk` drops the synthesized rows,
answering exactly what `grep` would find in the file", and `add price`
refuses a different amount for the same date. Stock Beancount numbers
lines by `\n` alone, and every directive here is on disk.

Cause: `cli/src/bea_engine/ledger/reader.py:107` reads the file with
`Path.read_text`, whose universal-newline handling turns a lone `\r`
into `\n` before the `split("\n")` at `:111` — defeating the comment
just above it. `entry_generated` then inspects the wrong line and reports
the entry as generated.

Fix: build the line table from bytes (decode without newline
translation, or open with `newline=""`), and add `\r` and `\r\r\n` to
the foreign-line-break regression tests. No dependency or API change.

Blast radius: every `generated` judgement in the reader and listing, and
the price duplicate guard in `adding.py`. The same read-then-split
pattern appears in `bea_engine/main.py` (`_written_document_path`) and
`bea_engine/query.py` (`_plugin_directive`), not exercised.

Dedupe: w1/done/049 is the same symptom for other break characters;
w5/108 is a CR reaching the terminal in query tables; w3/done/394 is
slash dates. Board search for lone CR, carriage and universal newline
finds nothing else.

Acceptance: on the CR fixture both `--on-disk` listings match the
control's rows and `add price` exits 2 naming line 12. Real-command
regression tests cover `\r` in a string and `\r\r\n` endings. Only
macOS and the checkout were exercised.
