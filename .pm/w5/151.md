# CSV import on a ledger with a renamed expenses root fails unless `--default-account` is passed, blaming a flag the user never typed

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
On a ledger that sets `name_expenses`, every `--csv` import is refused
with exit 2 because the built-in fallback account `Expenses:Uncategorized`
has a root the ledger does not use — even when a rule matches every row.
The error names `--default-account`, which was not on the command line.
Nothing is written; passing the flag works. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "EUR"
option "name_assets" "Aktiva"
option "name_expenses" "Aufwand"
2024-01-01 open Aktiva:Bank EUR
2024-01-01 open Aufwand:Essen EUR
2024-01-01 open Equity:Anfang EUR
2024-01-02 * "Opening"
  Aktiva:Bank  1000.00 EUR
  Equity:Anfang
```

`/absolute/books/bank.csv`:

```csv
Date,Amount,Description
2024-03-06,-40.00,Markt Einkauf
```

`/absolute/books/rules.toml`:

```toml
[[rule]]
match = "Markt"
account = "Aufwand:Essen"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean import bank.csv --csv date=Date,amount=Amount,narration=Description --account Aktiva:Bank --rules rules.toml --apply
```

Actual: exit 2, ledger unchanged.

```text
Error: --default-account: Account 'Expenses:Uncategorized' has root 'Expenses', which this ledger does not use; its roots are Aktiva, Liabilities, Equity, Income, Aufwand (set by the name_* options). Use one of those roots.
```

Control: adding `--default-account Aufwand:Essen` exits 0 and previews the
row with rule `Markt`. A worker saw the same refusal with `--csv auto`,
without `--rules` and under `--json`, and that a default-root ledger
accepts the command without the flag.

Expected: `docs/USAGE.md` says "configured root names are supported", and
`docs/IMPORTING.md` documents the default as `Expenses:Uncategorized`. The
default should follow the ledger's expenses root
(`Aufwand:Uncategorized`), and an error should not name an option the user
did not pass.

Cause: `cli/src/bea_engine/importing.py:160` validates the literal
`"Expenses:Uncategorized"` against the ledger's roots; the frontend
(`cli/src/cli/commands/import_.py`) and `csv_mapper.py` carry the same
literal default.

Fix: derive the default from the ledger's `name_expenses` option
engine-side, and update the help text and `IMPORTING.md`. No dependency or
API change.

Blast radius: every `--csv` import (explicit, `auto`, remembered mapping)
on a ledger that sets `name_expenses`. Python importers were not
exercised.

Dedupe: board search for `name_expenses`, `default-account`,
Uncategorized and renamed root finds w1/done/157 (added the root check
that now trips on `bea`'s own default) and w5/080 (renamed roots in `add
custom`); neither covers the import default.

Acceptance: the command succeeds without `--default-account` and an
unmatched row posts to `Aufwand:Uncategorized` (blocked as unopened if the
account is not open); the explicit-flag control is unchanged. A
real-command regression test covers a renamed root. Only macOS and the
checkout were exercised.
