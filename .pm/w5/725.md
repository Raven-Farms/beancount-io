# A ledger with its own error is told "Pass --partial to append the rows that validate", and `--partial` then rejects every row, blaming each one for the existing failure

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `cc6b52ed`, checkout `bea 0.3.1`, macOS 26.5.1. Next to the w5/537 per-row guard and w5/607.
No product fix implemented.

`err.bean`:

```
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Assets:Cash
2026-01-01 open Expenses:Food
2026-12-31 balance Assets:Checking 5 USD
```

`ok5.json` holds 5 valid rows (`Expenses:Food 1 USD` / `Assets:Cash`). None
touches `Assets:Checking`.

```sh
bea -f /abs/err.bean add transactions --from ok5.json
bea -f /abs/err.bean add transactions --partial --from ok5.json
```

Actual:
- The first exits 1 with `The ledger already has 1 error(s); nothing was
  written. Pass --allow-errors to write anyway. Pass --partial to append the
  rows that validate.`
- The second exits 1 with `Added 0 of 5 transactions; 5 rows were rejected.`
  Every `Row N:` repeats the existing `Balance failed for 'Assets:Checking'`
  error. The same happens before `e22bd04d`.

Expected: no `--partial` advice when the ledger itself refuses every write,
and no row named as the cause of an error it does not cause. `--allow-errors`
is the only remedy offered.

Cause: the hint at `cli/src/bea_engine/ledger/adding.py:1451-1453` is offered
whenever more than one row parses. The per-row guard in `_refused_in_order`
records a pre-existing error against each row.

Fix: offer `--partial` only when some row would validate, and under
`--partial` report a pre-existing error once, as the ledger's.

Dedupe: w5/607 (open) has the same advice under a full disk; w5/537 (done) is
next to it.

Acceptance: the first command does not suggest `--partial`; the second says
the ledger already fails and blames no row.
