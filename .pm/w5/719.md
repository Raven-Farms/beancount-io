# Staging copies left by a killed engine (`.bea-*.tmp`, including full copies of the root) are not cleared by the next write, contrary to USAGE; the sweep waits an hour and covers only the target's directory

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-17, HEAD `5ac35014`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/014 (done).
USAGE:984-986 says "a later write in the same directory clears any copy left
by a kill that could not be caught". No product fix implemented.

`books/main.bean` holds 50,000 generated transactions (3.1 MB) and `include
"sub/a.bean"`; `sub/a.bean` holds one transaction.

```sh
bea -f /abs/books/main.bean add transaction k1 --date 2024-03-01 -p "Expenses:Food 1.00 USD" -p Assets:Cash --into sub/a.bean &
P=$!; sleep 1.6; kill -KILL $(pgrep -P $P); wait $P
bea -f /abs/books/main.bean add transaction k2 --date 2024-03-02 -p "Expenses:Food 1.00 USD" -p Assets:Cash --into sub/a.bean
```

Actual:
- Each killed write exits 4 (`The Beancount engine was killed by SIGKILL…`),
  which is fine.
- Each kill leaves two `books/sub/.bea-*.tmp` files (199 bytes) and one
  `books/.bea-*.tmp` (3,139,106 bytes, a full copy of the root).
- After three kills, the next `--into sub/a.bean` write exits 0 and all
  nine copies remain.
- The hunter also aged the copies past an hour: further `--into` writes then
  cleared `sub/` but never the root-directory copies, which only a write to
  the root itself removes.

Control: killing `bea` itself (SIGINT, SIGTERM or SIGKILL) left no copies in
the hunter's 50 trials.

Expected: the next write clears the copies, as USAGE says, or USAGE states
the age limit and which directories are swept.

Cause:
- `sweep_abandoned_candidates` (`cli/src/bea_engine/ledger/write.py:643`)
  removes only files older than `_ABANDONED_CANDIDATE_SECONDS = 3600`
  (`:453`, cutoff at `:660`).
- `append` sweeps only `target.parent` (`:2848`), while `LedgerSnapshot.staged`
  (`:316`) also stages a copy beside each includer.

Fix: sweep every directory a write stages into. Hold a lock on each staging
copy for its lifetime, so the sweep can remove abandoned ones at once
instead of after an hour (or document the hour).

Dedupe: w5/014 (done) introduced the hour-based sweep; w5/606 (open) covers a
stop right after the replace.

Acceptance: after an engine kill, the next `--into` write leaves no
`.bea-*.tmp` in either directory. A test pins it.
