# `--cache-filename` (or `BEANCOUNT_LOAD_CACHE_FILENAME`) inside an include glob writes a pickle that the ledger then includes: the read exits 0, and every later command fails on it

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `3f2372e1`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE's "Output destinations" rule refuses a path that "would become part of
the ledger once written", meaning one an include pattern matches. The load
cache check compares only against existing closure members. So a cache
path under `include "txns/*.bean"` is accepted, the read that writes it
exits 0, and the books are broken from then on. The resulting advice is
"Re-save the file as UTF-8". No product fix implemented.

`main.bean`: `include "txns/*.bean"`. `txns/big.bean`: an `open` pair plus
~60,000 small transactions, so a load takes over a second and the cache is
written.

```sh
bea -f /abs/main.bean check --cache-filename txns/zcache.bean
bea -f /abs/main.bean check
```

Actual: the first exits 0 and writes an 11 MB pickle at `txns/zcache.bean`;
the second (and `balance`, `list`, every load) exits 1 with `Cannot decode
'…/txns/zcache.bean' as UTF-8: invalid start byte at byte 0. Re-save the
file as UTF-8 and retry.` `BEANCOUNT_LOAD_CACHE_FILENAME=txns/envcache.bean`
does the same.

Control: a cache path outside the glob works; an existing member named as
the cache is refused (w5/065, 067).

Expected: the cache path is refused (exit 2) when an include glob would claim
it, as other output destinations are.

Cause: `refuse_cache_over_ledger` (`cli/src/cli/output.py:539-572`) checks
`same_file` against existing closure members and never calls the
include-claim check (`_refuse_include_claim`, `output.py:604`).

Fix: run the include-claim check for both the option and the environment
variable.

Dedupe: w5/065, 067, 175, 411, 417 and 418 cover other cache-path cases; none
covers a glob claim.

Acceptance: both spellings are refused with exit 2 and nothing is written. A
test pins it (it can force the cache write instead of timing a big ledger).
