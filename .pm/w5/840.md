# The "ledger already has N error(s)" refusal describes the ledger as if the refused write had landed: "Did you mean <the account being added>?" and "Account opened … at <a line that was never written>"

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-17, HEAD `473bce6af`, checkout `bea 0.3.1`, macOS 26.5.1. Related to w5/666 (open) and 772 (open).
The refusal says nothing was written, so its hints should describe the
ledger on disk. No product fix implemented.

`closes.bean` is the single line `2026-01-01 close Assets:Cash`, an error ledger
(closing an unopened account).

```sh
bea -f /abs/closes.bean add open --date 2026-01-01 --account Assets:Bank --currency USD
```

Actual: exit 1, `The ledger already has 1 error(s); nothing was written.`, with
the detail `closes.bean:1: Unopened account Assets:Cash is being closed. Did you
mean Assets:Bank?`. `Assets:Bank` exists only in the refused write, and the
file is unchanged. Two more cases (hunter's runs):
- `add open --date 2026-02-01 --account Assets:Cash …` says `Account opened
  2026-02-01 at …/closes.bean:3`, but the file has one line.
- On `bal.bean` (`2026-01-31 balance Assets:Cash 0 USD` only), `add open --account
  Assets:Bank` suggests `Did you mean Assets:Bank?` for `Assets:Cash`.

Control: with no lookalike (`--account Liabilities:Card`) it says `The ledger
never opens Assets:Cash; check the account name.`, which is right.

Expected: suggestions and "opened at" facts come from the ledger as it is.

Cause: the hint builder (`cli/src/bea_engine/ledger/write.py`, around
`:1897`) collects accounts from the candidate entries, refused append
included. The close and unknown-account branches use them, and the
pre-existing-error path reuses those records.

Fix: build pre-existing-error hints from the before-load only.

Dedupe: w5/666 (open, items 4–5) and 772 (open) cover unwritten lines in
other paths; the "Did you mean <refused account>" symptom is new.

Acceptance: the refusal suggests nothing from the refused write.
