# Under `check_drained`, closing a parent whose subaccount holds money is told the parent "still holds" it; following the hint word for word posts −100 to the parent, and `check` then passes with wrong books (gap in w5/399)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `955c0274e`, checkout `bea 0.3.1`, macOS 26.5.1. Gap in w5/399 (done).
No product fix implemented.

```
option "operating_currency" "USD"
plugin "beancount.plugins.check_drained"

2026-01-01 open Assets:Bank USD
2026-01-01 open Assets:Bank:Sub USD
2026-01-01 open Equity:Opening

2026-01-02 * "Fund"
  Assets:Bank:Sub  100 USD
  Equity:Opening
```

```sh
bea -f /abs/main.bean add close --date 2026-03-01 -a Assets:Bank
bea -f /abs/main.bean add transaction Drain --date 2026-03-01 -p "Assets:Bank -100 USD" -p Equity:Opening
bea -f /abs/main.bean add close --date 2026-03-01 -a Assets:Bank
bea -f /abs/main.bean check
```

Actual:
- The first close exits 1 with `This zero assertion is added by check_drained
  for the close of Assets:Bank on 2026-03-01: the account still holds 100 USD
  then. Move that balance out of Assets:Bank with a transaction dated on or
  before 2026-03-01, then close it.`
- Following that, the drain, the second close and `check` all exit 0.
- `query "SELECT account, sum(position) GROUP BY account"` then shows
  `Assets:Bank -100 USD` and `Assets:Bank:Sub 100 USD`: a closed parent with a
  negative balance, and an open child still holding the money.

Expected: the hint says the 100 USD is in `Assets:Bank:Sub` (Beancount balance
assertions include subaccounts), and that `Assets:Bank:Sub` must be drained or
closed before `Assets:Bank`.

Control: for a leaf account, the hint is correct (w5/399's case).

Cause: `_drained_close_hint` (`cli/src/bea_engine/ledger/write.py:2164`) copies
upstream's accumulated amount, which includes the subtree, and attributes all
of it to the closed account.

Fix: when descendants hold the amount, name them and their amounts, and
advise draining or closing them first.

Dedupe: w5/399 (done) is the parent; w5/666 (open) item 3 names the wrong
plugin in a `close_tree` + `check_drained` case, which is a different text.

Acceptance: the first close names `Assets:Bank:Sub 100 USD`. A test pins it.
