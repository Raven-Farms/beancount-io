# The `add open` remedy for blocked import rows is dated per row, so the first one dead-ends a newest-first export

**Minor · cli · 20–30m · A2.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, macOS. Each blocked row suggests opening the
missing account on that row's own date. Bank exports usually list the newest
row first, so running the first suggestion opens the account after the older
rows, and the retry fails with an inactive-account error that only a hand edit
of the ledger can clear. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"

2026-01-01 open Assets:Checking USD
2026-01-01 open Liabilities:Card USD
2026-01-01 open Expenses:Food
2026-01-01 open Expenses:Uncategorized
2026-01-01 open Equity:Opening

2026-01-02 * "Opening balance"
  Assets:Checking  1000.00 USD
  Equity:Opening
```

`/absolute/books/a.csv`:

```csv
Date,Description,Amount
2026-03-20,Shell gas,-40.00
2026-02-10,Shell gas,-35.00
2026-01-15,Shell gas,-30.00
```

and `/absolute/books/rules.toml`:

```toml
[[rule]]
match = "shell"
account = "Expenses:Fuel"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`, and
a fresh configuration directory so no mapping is remembered.

```sh
bea -f /absolute/books/main.bean import a.csv --account Assets:Checking --rules rules.toml --apply
bea -f /absolute/books/main.bean add open --account Expenses:Fuel --date 2026-03-20 -c USD
bea -f /absolute/books/main.bean import a.csv --account Assets:Checking --rules rules.toml --apply
```

Actual: the first import exits 4; row 1 says `Account 'Expenses:Fuel' is not
open. Run: bea add open --account Expenses:Fuel --date 2026-03-20 -c USD.`
and rows 2 and 3 give the same command dated `2026-02-10` and `2026-01-15`.
Running row 1's command exits 0. The retry exits 1:

```text
Error: Import would leave the ledger invalid; nothing was written.
  Proposed append (not written): Invalid reference to inactive account 'Expenses:Fuel' Account opened 2026-03-20 at /absolute/books/main.bean:<line>. Correct the transaction date or edit that directive; …
```

The other two suggested commands now fail too, because the account is already
open. Repeated twice.

Control: opening with `--date 2026-01-15`, the earliest row, then the same
import writes three entries with exit 0 and `bea check` passes.

Expected: `docs/IMPORTING.md` says a blocked row "names the missing account
and the `bea add open` line that fixes it". A suggested command should fix
the import it was printed for; one command per account, dated early enough for
every row of this import that posts to it, does.

Cause: `cli/src/bea_engine/importing.py:698` formats the remedy with
`entry.date.isoformat()` for the row in hand; `_blocked_reason` sees one
entry at a time and has no view of the other rows posting to the same account.

Fix: date each account's remedy with the earliest date among all rows of the
import that post to it, and print that one command for every affected row, in
the JSON `reason` and the human review lines alike. No dependency or API
change.

Dedupe: board search for inactive accounts, blocked rows and remedy dates
finds w3/276, w3/386 and w1/157 (remedy validity and quoting — w1/157's
acceptance was that the suggested remedy must succeed); none considers the
date across rows.

Acceptance: on the fixture every blocked row prints the `2026-01-15` command,
running it once lets the import apply with exit 0, and an oldest-first export
is unchanged. Regression tests run the three-step journey through the real
commands for CSV and for a Python importer. Only macOS and the checkout were
exercised.
