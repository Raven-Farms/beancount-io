# Prompts go to stdout, so a redirected stdout hides the question while `bea` waits

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
`bea init books > log` (or `| tee log`, or `out=$(bea init books)`) typed
in a terminal shows nothing and appears to hang: the "Operating currency
[USD]:" question was written into the redirect. The captured stdout then
holds the prompt text glued to the result. A worker observed the same for
the `cloud ledger delete` confirmation, where the hidden question guards a
destructive action — the owner may raise severity for that case. No
product fix implemented.

No fixture is needed. Run in an empty directory with stdin and stderr on a
pseudo-terminal and stdout on a pipe, isolated HOME, BEA_CONFIG_DIR and
XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no inherited
BEA_FILE/BEA_TOKEN/CI:

```sh
bea init b1 > captured.txt
```

then type `EUR`, `2026-01-01`, `5`, each followed by Enter.

Actual: three seconds after launch, before any keystroke, the terminal
shows nothing and the process is still waiting. After the answers it exits
0 and stdout holds:

```text
Operating currency [USD]: Earliest date you will record (opening balances must be as of this date) [2026-10-11]: Checking opening balance on 2026-01-01 (negative for an overdraft) [0]: Created /absolute/b1/main.bean …
```

Control: with stdout on the terminal the prompts are visible. A worker saw
`bea --no-input init` with piped stdout exit 2 naming `--currency`, the
delete confirmation (`Permanently delete ledger 'alice/books'? [y/N]:`,
fake token against a closed loopback port) land in the pipe the same way,
and `bea query` refuse to open its shell when stdout is not a terminal.

Expected: a question is shown to the person who must answer it, and stdout
carries only results. `docs/USAGE.md` says "`--no-input` is implied
whenever stdin is not a terminal … In that mode nothing waits for a
human"; the CLI already treats a piped stdout as a script for strict
reads.

Cause: `cli/src/cli/commands/init.py:129,142,161` call `typer.prompt(...)`
and `cli/src/cli/context.py:136` calls `typer.confirm(...)` with the
default `err=False`; `RunContext.no_input` looks at stdin only.

Fix: pass `err=True` so questions and re-prompt errors go to stderr; when
stderr is not a terminal either, treat the run as `--no-input` and exit 2
naming the missing option or `--yes`. No dependency or API change.

Blast radius: `init`, every confirmation through `RunContext.confirm`
(the `cloud … delete` gates), and by the worker's observation the `ask`
REPL.

Dedupe: board search for `typer.prompt`, `typer.confirm`, prompt text and
redirected stdout with init finds w3/388 (Ctrl-C at prompts, done) and
w2/024 (currency warning timing, done); neither covers the stream.

Acceptance: with stdout redirected and stdin/stderr on a terminal, the
three questions appear on the terminal and `captured.txt` holds only the
`Created …` result; with stdout and stderr both redirected the command
exits 2 without waiting. Only macOS and the checkout were exercised.
