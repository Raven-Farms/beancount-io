# Three trivial gaps in the w5/487, 488 and 490 fixes: the `--force` balance hint still loops, the filled-in-leg hint names a nonexistent GBP leg (or a cost leg), and a no-break space in `add balance --amount` is shown as a plain space

**Trivial · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `06e9ca0f`, checkout `bea 0.3.1`, macOS 26.5.1.
No product fix implemented.

1. **w5/487: recovery loop.** With an existing `2026-01-25 balance
   Assets:Cash 0 USD`: `add balance --date 2026-01-25 -a Assets:Cash --amount
   '7 USD' --force` exits 1 and prints `Opening adjustment command: …
   --amount '7 USD' --pad-from SOURCE_ACCOUNT`. Running that exits 2 (`Pass
   --force`), and adding `--force` exits 1 with `remove one of the two` plus
   the same command again. The note's Fix asked to suppress the recovery
   command when the conflict is the cause; `_balance_recovery_hints`
   (`cli/src/bea_engine/ledger/write.py`) does not know the conflict.
2. **w5/488: filled-in leg.** `-p 'Expenses:Dining 45 EUR @ 1.1 GBP' -p
   'Liabilities:CreditCard'` hints `price the GBP leg at the rate paid:
   'NUMBER GBP @ RATE USD'` (there is no GBP leg; the useful hint is
   `'Expenses:Dining 45 EUR @ RATE USD'`). `-p 'Assets:Broker 2 HOOL {10
   EUR}'` hints `'NUMBER EUR @ RATE USD'` (the useful hint is the cost in USD).
   With two EUR legs only the first is named. Cause: the hint (around
   `write.py:2125`) matches legs by units currency only.
3. **w5/490: NBSP in `--amount`.** `add balance --date 2026-01-02 -a
   Assets:Cash --amount $'0 USD'` exits 2 with `--amount: Invalid token:
   ' USD'`, neither naming nor escaping the NBSP. `add price --amount
   $'10 USD'` and bulk `"amount": "5 USD"` accept it, normalizing to a
   space; `add balance` should do the same (or name U+00A0 as `-p` does).
