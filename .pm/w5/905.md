# Keep missing-price route explanations within the selected accounts

**Trivial · cli · 20–30m · A1.** A filtered report borrows an unrelated
held lot's cost currency to explain missing prices. It names a future route
that can never value the selected holding. Follow-up to completed
[557](./done/557.md) and [748](./done/748.md). The holdings, missing pair and
refusal category are correct; this finding concerns the explanation. No
product fix implemented.

Real CLI QA 2026-10-20, checkout `e85a7b165` (`cli` unchanged through
`32fe8a5cb`), `bea 0.3.1`, Darwin 25.5.0 arm64, frontend Python 3.13.3,
managed engine Python 3.12. Reproduced twice through balance and balance-sheet,
JSON partial output and strict refusal, plus human balance output. Fresh
synthetic fixtures/processes, closed stdin/no TTY, isolated absolute
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no inherited
BEA_FILE/BEA_TOKEN.

Create `/absolute/qa/main.bean`:

```beancount
option "operating_currency" "EUR"
2024-01-01 open Assets:Cash USD,EUR
2024-01-01 open Assets:HoldUSD HOOL
2024-01-01 open Assets:HoldEUR HOOL
2024-01-02 * "USD-cost lot"
  Assets:HoldUSD 10 HOOL {100 USD}
  Assets:Cash -1000 USD
2024-01-03 * "EUR-cost lot"
  Assets:HoldEUR 10 HOOL {90 EUR}
  Assets:Cash -900 EUR
2024-03-10 price HOOL 120 USD
2024-03-10 price USD 0.90 EUR
```

With the isolated environment:

```sh
bea --json -f /absolute/qa/main.bean check
bea --json -f /absolute/qa/main.bean balance Assets:HoldEUR --time 2024-02 --conversion EUR --allow-errors
bea -f /absolute/qa/main.bean balance Assets:HoldEUR --time 2024-02 --conversion EUR --allow-errors
bea --json -f /absolute/qa/main.bean report balance-sheet --account Assets:HoldEUR --time 2024-02 --conversion EUR --allow-errors
bea --json -f /absolute/qa/main.bean balance Assets:HoldEUR --time 2024-02 --conversion EUR
```

Check and partial reads exit 0. Human stderr and JSON
`missing_price_summary` say:

```text
HOOL → EUR has no price before 2024-03-10; earlier rows shown in HOOL
```

The strict read exits 1 with the same sentence in `error.details` and the
correct missing-price date `2024-02-29`. But the selected lot is at **EUR**
cost, so HOOL→USD→EUR is not its eligible cost-currency route. That route
belongs to the unselected Assets:HoldUSD lot.

Repeat both filtered report commands for `--time 2024-04`: the holding is
still unvalued, and the summary changes to
`HOOL has no EUR price at any date; shown in units`.
A fresh BQL control confirms the distinction after the prices are available:

```sh
bea --json -f /absolute/qa/main.bean query "SELECT convert(sum(position),'EUR',2024-04-30) WHERE account='Assets:HoldEUR'"
bea --json -f /absolute/qa/main.bean query "SELECT convert(sum(position),'EUR',2024-04-30) WHERE account='Assets:HoldUSD'"
```

They return **10 HOOL** and **1080.00 EUR**, respectively, twice. There is
no conversion-engine defect here; 557 explicitly requires distinguishing
lots whose stated cost makes an indirect route eligible.

Controls, each twice through both report commands and both periods:

- Remove only the unselected USD-cost purchase: the selected 10 HOOL and
  all prices are unchanged, but February now gets the correct undated
  wording, matching April.
- Select Assets:HoldUSD instead: February's March 10 wording is correct,
  and April values the holding completely at 1080 EUR.
- Add `2024-03-10 price HOOL 110 EUR`: the selected EUR-cost holding has
  a real direct-price start, so February's dated wording is correct and
  April values it completely at 1100 EUR.

All fixture checks pass; every read preserves ledger bytes. Partial and
strict exit categories remain as documented.

Cause: `_price_summary_lines` in `cli/src/bea_engine/report.py:804` calls
`_held_cost_currencies(ledger.all_entries, ...)`. That helper (:764–786)
nets by currency and date, but never by selected account or actual unvalued
positions. The extra USD lot therefore gives `_routed_since` a false route
for the filtered view while all unvalued dates precede March 10. Its date
guard hides that route in April, explaining the contradictory wording.
Caller search finds the shared `_valuation` path from balance and all four
report kinds. Only balance and balance-sheet were exercised for this case.

Fix: derive candidate route currencies from the positions actually left
unvalued in the report's selected accounts and row date. Preserve the
existing cost-currency eligibility and quote-date rules; do not add a new
conversion path or alter totals. Keep strict details, human notes and JSON
summaries consistent.

Dedupe: all-board search for missing-price cost routes, account filters and
unrelated held lots, plus active milestone review. 557 fixes the eligibility
distinction; 748 (`4bbfc1600`) stops sold or not-yet-bought lots influencing
the message, but still scans all accounts. Its original cause explicitly
included account scope; the current resolution implements only as-of
holdings. Open 903 concerns successful price-write advisories, not report
route explanations. No overlapping open repair or later fix was found.

Acceptance: the selected EUR-cost account gets the undated wording in both
months regardless of the unrelated USD lot; balances, missing dates and exit
categories stay correct. Retain the selected-USD/direct-price controls and
748's as-of holdings behavior. Evidence: ignored pass6
`repro_filtered_cost_route_notice.py`, `filtered-route-results.json`, eight
fixtures, strict/partial/human captures and separate BQL controls. Other
report kinds, arbitrary filter combinations and platforms remain unverified.
