# A bulk row's `amount` shorthand silently overwrites an explicit `cost`, `price` or `price_total` on the same posting, exit 0

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `c3c42a48`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE: "Supplying both forms … is rejected" (`amount` with `units`, `price`
with `price_total`). When the `amount` fragment carries its own cost or
price, it replaces the explicit field without a word. That changes the cost
basis, the lot label and therefore lot selection. No product fix implemented.

Ledger with `Assets:Brokerage` and `Assets:Checking` open. Row:

```json
[{"date": "2026-02-01", "narration": "A",
  "postings": [{"account": "Assets:Brokerage", "amount": "5 HOOL {10 USD}",
                "cost": {"number": "99", "currency": "USD", "label": "lot-x"}},
               {"account": "Assets:Checking"}]}]
```

```sh
bea -f /abs/w.bean add transactions --from j.json
```

Actual: exit 0; writes `Assets:Brokerage  5 HOOL {10 USD}`. The explicit `{99
USD, "lot-x"}` is gone. `"amount": "… @ 12 USD"` with `"price"` (99), and
`"… @@ 60 USD"` with `"price_total"` (75), keep the fragment's price the
same way.

Control: a fragment price plus an explicit `price_total` is refused (`Use
either price or price_total`); `"amount": "5 HOOL"` plus `cost` keeps the
cost.

Expected: the row is refused (exit 2 atomic, rejected under `--partial`),
naming the posting and both sources of the cost or price.

Cause: `cli/src/bea_engine/ledger/models.py:172`: `value |=
_posting_fragment(amount)` replaces keys the caller supplied.

Fix: in the shorthand expansion, refuse when the fragment yields a key that
is already present and not null.

Dedupe: searched `shorthand`; w3/272, w5/057, 063, 211 and 213 are different.

Acceptance: the three rows are refused naming the conflict. A test pins
them.
