# `bea query > out.txt` (or `| tee`) opens the interactive shell with no visible prompt, and the `beanquery>` prompts end up in the results file

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `f29eb957`, checkout `bea 0.3.1`, macOS 26.5.1. PTY for stdin and stderr, stdout to a file.
USAGE: "Questions are written to stderr, so a redirected or piped stdout
carries only results." The shell opens based on stdin alone, and upstream's
`input()` writes the prompt to stdout. The terminal stays blank, so the
command looks hung, and the file is no longer clean output. The w5/163
resolution says `bea query` refuses to open when stdout is not a terminal;
that does not hold at HEAD. No product fix implemented.

```sh
bea -f /abs/main.bean query > out.txt
# type: SELECT count(*)   then   .exit
```

Actual: nothing appears on the terminal for the whole session; exit 0;
`out.txt` holds `beanquery> count(*)\n--------\n      10\nbeanquery> `. A pipe
behaves the same, and line editing is off.

Control: with stdout on the terminal the prompt is visible; `init`'s prompts
go to stderr in the same setup.

Expected: refuse with exit 2 when stdout is not a terminal (`the query shell
needs a terminal on stdout; pass a query, or use -o FILE`). Alternatively,
draw the prompt on stderr so the file holds only results.

Cause: `cli/src/cli/commands/query.py:397-410` checks stdin and `ctx.no_input`
only.

Fix: as above; reuse `context.can_prompt` or check `sys.stdout.isatty()`.

Dedupe: w5/163 (done) left the query shell out; no open note.

Acceptance: the command exits 2 (or the file holds no prompt). A PTY test pins
it.
