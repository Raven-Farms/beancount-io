# `bea import` keeps only the last of a repeated `--account`, `--csv` or `--rules`, and `init` keeps only the last `-c`: a second `--account` books the rows to that account with exit 0 and remembers it

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
[238](./done/238.md) made every `bea add` refuse two different values for
a single-valued option. Its resolution says "The `import` and `init`
repeats listed in the note's blast radius are outside `add` and were not
changed", and no open note tracks that gap.

- `bea import … --account Assets:Checking --account Assets:Wallet --apply`
  exits 0 with no warning and books the rows against `Assets:Wallet`, in
  that account's currency. It also remembers `Assets:Wallet` for the CSV
  layout, so a later run without flags repeats the mistake.
- A repeated `--csv` silently drops the first mapping, then reports a
  missing column that the user did pass.

No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Assets:Wallet BTC
2026-01-01 open Equity:Opening
2026-01-01 open Expenses:Uncategorized
2026-01-02 * "Open"
  Assets:Checking  100.00 USD
  Equity:Opening
```

`/absolute/books/s.csv`:

```text
Date,Amount,Payee
2026-01-05,-3.00,Cafe
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean import s.csv --csv date=Date,amount=Amount,payee=Payee --account Assets:Checking --account Assets:Wallet --apply
bea -f main.bean import s.csv --csv date=Date,amount=Amount --csv payee=Payee --account Assets:Checking
bea --no-input init i2 -c USD -c EUR --date 2026-01-01
```

Actual:

- The first command exits 0 with `csv → Assets:Wallet: 1 ready` and
  writes `Assets:Wallet -3.00 BTC` / `Expenses:Uncategorized 3.00 BTC`.
  Import memory stores `"account": "Assets:Wallet"`.
- The second exits 2 with `--csv needs date=Column; got 'payee=Payee'.`
- The third exits 0 and writes only `option "operating_currency" "EUR"`.
- With `--rules r1.toml --rules r2.toml`, only `r2.toml` is used: a row
  that `r1.toml` matches stays `unmatched`.

Reproduced in three fresh runs, each with a fresh config directory.

Control: `bea add note -a Assets:Checking -a Assets:Wallet …` exits 2 with
`Conflicting values for one option: --account 'Assets:Checking' and
--account 'Assets:Wallet'. Pass it once; …`, and writes nothing.

Expected: `docs/USAGE.md` states the 238 rule for `add`. Import is the
riskier surface, since `--apply` writes rows and remembers the mapping, so
it should refuse the same way. `init -c` should either refuse or write
every currency.

Cause: `cli/src/cli/commands/import_.py` and `cli/src/cli/commands/init.py`
declare plain single-valued Typer options, so Click keeps the last
occurrence. The refusal exists only in the parser subclass in
`cli/src/cli/commands/add.py:40-70` (the check at `:59`).

Fix: lift the `add.py` parser subclass into a shared helper and apply it to:

- `import`: `--account`, `--csv`, `--rules`, `--duplicates`,
  `--date-format`, `--into`, `--importer` and `--config`.
- `init`: `-c`/`--currency` and `--date`.

Two different values then exit 2 naming both, and nothing is written or
remembered. Repeating the same value is still accepted. Alternatively,
`init` could accept several currencies by design. No dependency or API
change.

Blast radius:

- `import`, preview and `--apply`, for CSV and Python importers. The wrong
  account also persists in import memory.
- `init`.
- Read commands behave the same way but write nothing: `report -t 2026
  -t 2025` reports 2025, `list --limit 1 --limit 5`, `report -x USD -x
  EUR`, and `format -o a -o b` writes only `b`.

Dedupe:

- w5/238 (`aead15fb`): `add` only; its resolution leaves `import` and
  `init` out.
- w3/367: `add balance --amount` only.

Board searches for "repeated", "last one", "--account" with "twice", and
"Conflicting values" found nothing open.

Acceptance:

- On the fixture, the first command exits 2 naming both `--account`
  values, and `main.bean` and import memory are unchanged.
- The repeated `--csv` and `--rules` refusals name both values.
- `init -c USD -c EUR` exits 2, or writes both currencies by documented
  design.
- Repeating the same value still works.
- A real-command regression test covers import preview and apply, and
  init.

Only macOS and the checkout were exercised.
