# Three option-handling gaps: `add price` under `pedantic` still advises a `--force` that then fails, `option "plugin_processing_mode" "raw"` is dropped from `query PRINT -f beancount` exports (and `--pad-from` silently does nothing there), and an invalid `name_*` value blocks every simple `add` on that root

**Trivial · cli · 15m · A1.** Real CLI QA, 2026-10-17, HEAD `227d5a25b`, checkout `bea 0.3.1`, macOS 26.5.1.
No product fix implemented.

1. **`pedantic` prices (gap in w5/397).** On a ledger with `plugin
   "beancount.plugins.pedantic"`, commodities USD and EUR, and `2026-01-05
   price EUR 1.10 USD`:
   - `add price --date 2026-01-05 --currency EUR --amount "1.12 USD"` exits 2
     with `… refusing 1.12 USD. Pass --force to record another quote.`
   - With `--force` it exits 1: `p.bean:5: Disagreeing price entries`.
   - Under `unique_prices` itself, the first refusal names the plugin and says
     to edit the existing line.

   Cause: `cli/src/bea_engine/ledger/adding.py:714` tests
   `name.endswith("unique_prices")`, but `pedantic` bundles `unique_prices`.
2. **Raw processing mode (gap in w5/474).** A ledger with `option
   "plugin_processing_mode" "raw"`, a 1000.00 USD funding and `2026-01-03
   balance Assets:Cash 999.00 USD` passes `check`, because raw mode skips the
   balance check.
   - `query PRINT -f beancount -o exp.bean` writes no option preamble, and
     `bea -f exp.bean check` fails with `exp.bean:9: Balance failed for
     'Assets:Cash': expected 999.00 USD != accumulated 1000.00 USD`. USAGE:705-711
     says the export carries the options its validity rests on.
   - In raw mode, `add balance … --pad-from Equity:Opening` writes the pad and
     balance (exit 0), but balances never change because pads are not
     processed (hunter's run).

   Cause: `_EXPORTED_OPTIONS` (`cli/src/bea_engine/query.py:1335`) omits the
   option.
3. **Invalid `name_*` value.** With `option "name_assets" "assets"`, Beancount
   rejects the value (`Invalid root account name: 'assets'`) and keeps `Assets`.
   - `add note --date 2026-01-06 --account Assets:Cash --comment hi
     --allow-errors` exits 2: `Account 'Assets:Cash' has root 'Assets', which
     this ledger does not use; its roots are assets, Liabilities, …`.
   - Following that advice is refused as an invalid account.
   - Open, close, pad, note, document and custom are all blocked.

   Cause: `root_names_of` (`cli/src/bea_engine/ledger/text.py`, around
   `:326-344`) regex-reads option values without Beancount's validation.

Fix: count `pedantic` as loading `unique_prices`; export
`plugin_processing_mode` and warn on `--pad-from` in raw mode; keep a `name_*`
value only when it is a valid root.

Dedupe: w5/397 and 474 (done) are the parents of 1 and 2; w5/402, 462 and 710
cover other root cases.

Acceptance: each case behaves as above.
