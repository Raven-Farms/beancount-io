# On an include cycle (`main.bean` → `a.bean` → `main.bean`), reads tell the user "main.bean is included by …/main.bean … Run with --file …/main.bean", the command they just ran

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `fe8ed158`, checkout `bea 0.3.1`, macOS 26.5.1.
The w5/348 root hint climbs from the given file to its including root. On a
cycle the climb returns to the starting file and treats it as a leaf of
itself. No product fix implemented.

`main.bean`: `option "operating_currency" "USD"`, `2020-01-01 open Assets:Cash
USD`, `include "a.bean"`. `a.bean`: `include "main.bean"`.

```sh
bea --file /abs/main.bean check
```

Actual: exit 1, upstream's `<load>:0: Duplicate filename parsed:
"…/main.bean"`, then `main.bean is included by …/main.bean; on its own it lacks
the accounts and options that root provides. Run with --file …/main.bean to
read the whole ledger.` `--json` details and `list open` carry the same line
(and `list` counts it, see w5/514).

Control: `include "main.bean"` directly in `main.bean` gives no hint.

Expected: no root hint when the climb comes back to the file itself.

Cause: `top_root` (`cli/src/bea_engine/ledger/write.py:1320-1330`) returns the
starting file when the cycle closes, instead of `None`.

Fix: return `None` when the climb revisits `file`.

Dedupe: searched `is included by`, `top_root`; w5/346 and 348 (done)
introduced the hint.

Acceptance: the command shows upstream's error without the hint. A test pins
it.

Addendum (CLI QA 2026-10-16, automation sweep): writes print the same
self-referential line. On the cycle fixture, `bea add note --date 2026-01-03
-a Assets:Checking -m hi --allow-errors` says `main.bean is included by
…/main.bean; the write goes to main.bean and is checked against that whole
ledger.`, and `bea -f a.bean check` says the same about `a.bean`. The
`top_root` fix covers both.
