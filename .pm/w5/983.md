# Preserve staged short-lot selectors in batch writes

**Major · cli · 45–60m · A1.** A chronological batch opening two short
lots and then covering the first rewrites its label selector to the other
lot's label. It books a **120 USD** lot instead of **100 USD**, reports
**30 USD profit instead of 10**, exits 0 and passes a fresh check. The
recent completed [925](./done/925.md) repair recognizes short lots already
on disk; it does not recognize lots introduced by the current batch.
No product fix implemented.

Real CLI QA, 2026-10-22, checkout-selected `bea 0.3.1`, macOS 26.5.1 arm64,
frontend Python 3.13.3, existing managed Python 3.12.10 / Beancount 3.2.3.
Exploratory reproduction on `75cff6325`, which includes 925's `4021d33a7`
and the parser-counterposting repair. Public recipe replay uses `b972a8082`;
CLI source is unchanged between those heads. All subprocesses are bounded,
closed-stdin/no TTY, with isolated child config/cache, notifier disabled and
inherited ledger/token/engine overrides removed. Only synthetic local books.

With `bea` on PATH, select a fresh absolute directory and run this recipe.
Its first label contains a genuine native multiline string; the second
contains one space, so they are distinct labels. Dates are January 2,
January 3 and February 1: this is not a same-day ordering case.
`bulk-alias` reproduces the wrong lot. `bulk-seeded` writes the opening
positions to the initial ledger instead and covers correctly. `import-native`
and `import-hash` exercise an inspected Python importer of the same native
statements; the source files remain unchanged during every command.

```python
from pathlib import Path
import json, os, subprocess

case = Path('/abs/staged-short-case')
mode = 'bulk-alias'
human_apply = False
profiles = {
    'bulk-alias': ('bulk', True, False, False, True),
    'bulk-seeded': ('bulk', True, True, False, True),
    'bulk-noalias': ('bulk', False, False, False, True),
    'bulk-plain': ('bulk', False, False, True, True),
    'import-native': ('import', True, False, False, True),
    'import-hash': ('import', True, False, False, False),
    'import-seeded': ('import', True, True, False, True),
}
pipeline, alias, seeded, plain, native_ids = profiles[mode]
case.mkdir(parents=True, exist_ok=False)
ledger, reference = case/'main.bean', case/'reference.bean'
label = 'First Lot' if plain else 'First\nLot'
base = '''option "operating_currency" "USD"
2024-01-01 open Assets:Stock HOOL "FIFO"
2024-01-01 open Assets:Cash USD
2024-01-01 open Income:Gains USD
'''
first = f'''2024-01-02 * "First short lot"
  Assets:Stock -2 HOOL {{100 USD, "{label}"}}
  Assets:Cash 200.00 USD
'''
second = '''2024-01-03 * "Second short lot"
  Assets:Stock -2 HOOL {120 USD, "First Lot"}
  Assets:Cash 240.00 USD
'''
cover = f'''2024-02-01 * "Cover first short lot"
  Assets:Stock 1 HOOL {{"{label}"}}
  Assets:Cash -90.00 USD
  Income:Gains
'''
ledger.write_text(base + (first+second if seeded else ''), encoding='utf-8')
reference.write_text(base+first+(second if alias else '')+cover, encoding='utf-8')
def opening(name, day, price, lot):
    return dict(date=day, narration=name, postings=[
        dict(account='Assets:Stock', units=dict(number='-2', currency='HOOL'),
             cost=dict(number=str(price), currency='USD', label=lot)),
        dict(account='Assets:Cash', units=dict(number=str(price*2), currency='USD'))])
cover_row = dict(date='2024-02-01', narration='Cover first short lot', postings=[
    dict(account='Assets:Stock', units=dict(number='1', currency='HOOL'), cost=dict(label=label)),
    dict(account='Assets:Cash', units=dict(number='-90.00', currency='USD')),
    dict(account='Income:Gains')])
rows = [] if seeded else [opening('First short lot', '2024-01-02', 100, label)]
if alias and not seeded: rows.append(opening('Second short lot', '2024-01-03', 120, 'First Lot'))
rows.append(cover_row)
payload = case/'trades.json'
payload.write_text(json.dumps(rows), encoding='utf-8')
source, config = case/'broker.statement', case/'importer.py'
statements = [cover] if seeded else [first]+([second] if alias else [])+[cover]
if native_ids:
    statements = [text.replace('\n', f'\n  bank_id: "row-{i}"\n', 1)
                  for i, text in enumerate(statements)]
source.write_text('\n'.join(statements), encoding='utf-8')
config.write_text('''from beancount.parser import parser
class Broker:
    name = 'broker'
    def identify(self, file): return str(file).endswith('.statement')
    def account(self, file): return 'Assets:Stock'
    def extract(self, file, existing_entries=None):
        entries, errors, _ = parser.parse_file(str(file))
        assert not errors, errors
        return entries
CONFIG = [Broker()]
''', encoding='utf-8')
inputs = {p:p.read_bytes() for p in (payload, source, config, reference)}
env = os.environ.copy()
for key in ('BEA_FILE', 'BEA_TOKEN', 'BEANCOUNT_LOAD_CACHE_FILENAME',
            'BEA_ENGINE_PYTHON', 'BEA_ENGINE_DIR'):
    env.pop(key, None)
env.update(BEA_CONFIG_DIR=str(case/'config'), XDG_CACHE_HOME=str(case/'cache'),
           BEA_NO_UPDATE_NOTIFIER='1')
def run(tag, args, file=ledger, human=False):
    argv = ['bea', *([] if human else ['--json']), '--no-input', '-f', str(file), *map(str,args)]
    before = ledger.read_bytes()
    result = subprocess.run(argv, cwd=case, env=env, stdin=subprocess.DEVNULL,
                            capture_output=True, text=True, timeout=25)
    assert all(p.read_bytes()==data for p,data in inputs.items())
    print(json.dumps(dict(tag=tag, args=argv, exit=result.returncode,
                         stdout=result.stdout, stderr=result.stderr,
                         ledger_changed=ledger.read_bytes()!=before)), flush=True)
args = (['add','transactions','--from',payload] if pipeline=='bulk'
        else ['import',source,'--config',config,'--apply'])
positions = ['query', "SELECT date,number,cost_number,cost_date,cost_label WHERE account='Assets:Stock' ORDER BY date,cost_date"]
profit = ['query', "SELECT sum(number) WHERE account='Income:Gains'"]
run('baseline', ['check'])
run('first-apply', args, human=human_apply)
run('first-positions', positions)
run('first-profit', profit)
run('first-sheet', ['report','balance-sheet','--time','2024-01-01 to 2024-02-29','--conversion','at_cost'])
run('first-income', ['report','income-statement','--time','2024-01-01 to 2024-02-29','--conversion','at_cost'])
if pipeline=='import':
    run('unchanged-repeat', args)
    run('repeat-profit', profit)
    run('third-import', args)
run('reference-check', ['check'], reference)
run('reference-positions', positions, reference)
run('reference-profit', profit, reference)
run('reference-sheet', ['report','balance-sheet','--time','2024-01-01 to 2024-02-29','--conversion','at_cost'], reference)
run('final-check', ['check'])
```

Actual and expected, twice from pristine books:

- `bulk-alias` writes all three rows, exit 0. The February cover reloads as
  **1 HOOL / 120 USD / 2024-01-03 / `First Lot`**. Income:Gains is −30 USD,
  and at-cost income statement profit and balance sheet net worth are 30.
  The independently bookable reference selects **100 USD / 2024-01-02 /
  `First\nLot`**, gains −10 and profit/net worth 10. Cash 350 and net
  quantity −3 are identical, so those totals alone miss the error.
- `bulk-seeded` succeeds, writes only the cover and selects the first lot
  correctly, profit 10. The current fix's existing-lot case therefore works.
  A staged plain-label control also succeeds with profit 10. Removing only
  the space-labelled alias makes the valid staged cover falsely refuse at
  exit 1 with every ledger byte unchanged; its native reference succeeds.
- `import-native` previews three ready rows and writes all three, exit 0,
  with the same wrong 120 USD cover and 30 profit. Repeating the identical
  native-ID source now conflicts at exit **4**, writing nothing: the
  post-import ledger holds the multiline short lot, so the next analysis
  preserves the original selector and disagrees with the first write.
- `import-hash` first writes the same wrong three rows. Repeating the
  **unchanged** source writes one more cover, exit **0**. Cash falls from
  **350 to 260 USD**, net shares change −3 to −2 and profit becomes **40**,
  while the source describes only one cover and the reference remains
  Cash 350 / shares −3 / profit 10. A third identical import finally skips.
  The state-dependent selector normalization changed the generated identity.
- Seeding the native import's opening positions before extraction, or using
  a plain label, preserves the correct cover and repeat writes 0. Without
  an alias, native import apply refuses with exit 1 and leaves the valid
  source ledger untouched. Human bulk output reproduces the wrong-lot write.

Cause: `ledger.writer.normalize_entry_strings.posting_strings` preserves a
positive label only when `(account, label)` is in `_SHORT_LOT_LABELS`.
`writer.short_lot_labels` memoizes `held_short_lot_labels` over the existing
ledger, installed by `ledger.adding.answer`; import's `_with_short_lots` /
`importing.answer` similarly supplies only its initial loaded entries.
Neither includes the earlier staged short openings before normalizing the
later cover. Thus `single_line` changes its selector to `First Lot`, and
native booking correctly chooses that **different** 120 USD lot. Once the
first write exists, the provider sees the remaining multiline short lot,
explaining the changed identity on import repeat. The root is the writer's
inventory context, before the ordinary import matching path runs.

Fix: decide whether a positive labelled posting reduces a short lot using
the inventory relevant to that posting, including the earlier staged rows
in the batch/import's actual booking context. Preserve the original native
selector when it is a reduction; retain documented new-acquisition label
normalization. Use the native booking evidence rather than inferring that
every positive posting is a purchase or every label mentioned anywhere is
a short lot. Keep valid native statement semantics, input/source bytes,
atomic failures, existing-lot controls and repeat identity stable. Do not
change unrelated same-day trade ordering or make import append exact
repeats. One CLI writer/import context repair; no API or dependency change.
