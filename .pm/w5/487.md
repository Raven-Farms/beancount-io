# `add balance --pad-from` on a date that already has a different assertion gives contradictory advice ("Date the pad after 2026-01-25") and suggests re-running the same command, instead of the duplicate-assertion refusal

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `7334a32b`, checkout `bea 0.3.1`, macOS 26.5.1. Sibling of w3/224.
Without `--pad-from`, a second, different assertion for the same date,
account and currency is refused with exit 2 and `--force` advice, as USAGE
documents. With `--pad-from`, the conflict check is skipped. The write
then fails validation and prints three hints: one that cannot be
satisfied, one that loops back to the same command, and Beancount's
duplicate error last. No product fix implemented.

`main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Equity:Opening USD

2026-01-25 balance Assets:Cash 0 USD
```

Isolated config/cache, closed stdin.

```sh
bea -f /abs/main.bean add balance --date 2026-01-25 -a Assets:Cash --amount '7 USD' --pad-from Equity:Opening
```

Actual: exit 1 (validation), nothing written. Details include: `…the
2026-01-25 assertion at main.bean:5 already holds and consumes it, so the
2026-01-25 assertion stays unpadded. Date the pad after 2026-01-25.`; an
`Opening adjustment command: bea --file … add balance --date 2026-01-25
--account Assets:Cash --amount '7 USD' --pad-from SOURCE_ACCOUNT` (the
command just run); and last, `Duplicate balance assertion with different
amounts`.

Control: without `--pad-from`, exit 2 with `Assets:Cash already has a
2026-01-25 balance of 0 USD (at …:5); refusing 7 USD. Pass --force to record
another assertion.`

Expected: the same exit-2 conflict refusal with or without `--pad-from`. The
pad hint never says "Date the pad after D" when D is the asserted date
itself.

Cause: the `--pad-from` path of `_balance` in
`cli/src/bea_engine/ledger/adding.py` writes without `_balance_conflict`;
`_unused_pad_hint` (`cli/src/bea_engine/ledger/write.py:1951-1956`) does not
handle `first.date == balance.date`; `_balance_recovery_hints` repeats the
command.

Fix: run the same-date conflict check before the pad path; suppress the
unused-pad hint and the recovery command when the conflict is the cause.

Dedupe: searched `Date the pad after`, `pad-from`. w3/224 (circular
`--pad-from` hint) and w1/116 are done; this case is not covered.

Acceptance: the command exits 2 with the conflict refusal; `--force` keeps
its documented meaning. A test pins it.
