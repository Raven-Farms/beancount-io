# `bea example` over an allowed 96-year span runs ~11 s, then fails with "start --date-begin on January 1, with --date-birth before it", advice the user already followed

**Trivial · cli · 10m · A2.** Real CLI QA, 2026-10-16, HEAD `04c94595`, checkout `bea 0.3.1`, macOS 26.5.1.
w5/390 limited spans to 100 years. Inside that limit, some long spans still
fail upstream's own validation, with errors such as `Amount is zero: "0.000
RGAGX"`. bea's refusal always appends the whole-calendar-year advice, which
fits only the mid-year-start failures it was written for (w5/136). No
product fix implemented.

```sh
bea example --seed 1 --date-begin 2000-01-01 --date-end 2095-12-31
```

Actual: after ~11 s, exit 1: `bean-example generated a ledger that fails
validation (194 errors), so nothing was printed. Its rules assume whole
calendar years: start --date-begin on January 1, with --date-birth before
it.`, then `Amount is zero: "0.000 RGAGX"` lines.

Control: `--date-end 2090-12-31` succeeds.

Expected: the calendar-year advice only for the inactive-account and balance
errors that a mid-year start produces. Other failures say the span is
too long for upstream to generate cleanly and suggest a shorter one.

Cause: `_refuse_invalid` (`cli/src/cli/commands/example.py:87-104`) appends
the advice unconditionally.

Fix: choose the advice by the error kinds found.

Dedupe: searched `Amount is zero`, `whole calendar years`; w5/136 and 390
(done) are the related fixes.

Acceptance: the command's refusal does not give the calendar-year advice. A
test with a stubbed validation output pins it.
