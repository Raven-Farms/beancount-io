# A refused or partial write through an included file never says it was checked against the root: the "txns.bean is included by …" note appears only on success (incomplete fix of w5/613)

**Trivial · cli · 5–10m · A1.** Real CLI QA, 2026-10-17, HEAD `2f69b1461`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/613 (done, `1c38897bd`).
Commit `1c38897bd` says "On a refusal the note still goes to stderr". USAGE says
a note says so, in `warnings` under `--json`. No product fix implemented.

`main.bean` opens `Assets:Cash USD`, `Expenses:Food` and
`Expenses:Uncategorized`, then `include "txns.bean"`.

```sh
bea --no-input --file txns.bean add transaction --date 2026-01-03 b -p "Expenses:Nope 2 USD" -p Assets:Cash
```

Actual: exit 1, and neither stream contains "included by". A `--json
--partial` bulk add with one bad row writes the good row and exits 1, with
`"result": {"written": 1, …}` but no note and no file named (hunter's run).

Control: a successful leaf add prints `txns.bean is included by …`.

Expected: the note on refusals and partial writes too, in text and JSON.

Cause: `_redirect_on_failure` (`cli/src/bea_engine/main.py:298`) writes the note
to the engine's stderr. The frontend shows that stderr only on success.

Fix: carry the note in the failure envelope and render it.

Dedupe: w5/613 (done) is the parent; w5/514, 578, 774 and 775 concern when the
redirect applies.

Acceptance: the refused add prints the note.
