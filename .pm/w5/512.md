# `bea format -o a.bean -o b.bean` and `-c 40 -c 70` keep the last value with exit 0; every other local command refuses two different values (sibling of w5/381)

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `bea189ec`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE's rule for add, import, init, list, report, balance and query is exit
2 with `Conflicting values for one option`. `format` was not given the
shared command class. No product fix implemented.

```sh
bea format -o a.bean -o b.bean main.bean
bea format -c 40 -c 70 main.bean
```

Actual: exit 0; only `b.bean` is written; the currency column is 70. `-w`
and `-W` behave the same.

Control: `bea list transaction -a Food -a Pay` exits 2 with `Conflicting
values for one option`.

Expected: exit 2 naming both values, nothing written; the same value
repeated is accepted.

Cause: `format` is registered without `cls=SingleValueCommand`
(`cli/src/cli/main.py:452`).

Fix: register it with `SingleValueCommand`, as w5/381 did for the read
commands. Check the other commands (`treeify`, `example`, `doctor`, `ingest`)
for the same gap while there.

Dedupe: w5/381 (done) covered read commands; w5/483 covers `price export`
and w5/485 the global `-f`.

Acceptance: both commands exit 2 and write nothing. A test pins it.
