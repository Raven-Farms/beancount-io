# MCP dry runs say a write would succeed when the plan's directive limit will refuse it (`RESOURCE_LIMIT_REACHED` only on the real call)

**Minor · backend-v2 · 30–45m · A1.** Found 2026-10-21 while exercising the `categorize-imports` prompt for [w5/m5/t004](./blocked/m5/README.md). The client was Claude Code, using the hosted MCP endpoint with real staged bank transactions on a free-tier ledger that was already over its 1,000-directive allowance.

- `importStagedBankTransactions` with `dry_run: true` answered `wouldAddCount: 1` with no new validation errors. The agent showed that preview and the user confirmed.
- The real call was then refused with `RESOURCE_LIMIT_REACHED`: the server projected about 2,062 directives against the allowance. Nothing was written, and the agent reported it honestly.
- The playbook tells agents to dry-run first precisely so the user approves what will happen. A preview that cannot see the refusal makes the confirmation meaningless on any over-limit ledger.

Cause, read from code (only the import path was observed live):

- The directive limit is enforced only where the ledger service commits.
- `PlaidSyncService.submitTransactionsToLedger` returns its dry-run preview before calling `addBulkEntries`.
- `DirectiveAppendWorkflow` (`appendLedgerText`) skips the commit on `dryRun` in the same way, so its preview can make the same promise.
- `evaluateDirectiveLimit` and `evaluateMergeDirectiveLimit` (`src/features/gitea/policy/directive-limit-gate.ts`) already compute "would the ledger end over the limit and bigger than now" for pushes and merges.

Fix: have each dry-run path ask the same question with the projected count, and refuse in the preview exactly as the commit would. Projected count is the current count plus the directives the write adds. Keep fail-open (`unknown`) behavior as the gate does, and keep the mobile bypass. REST and GraphQL take `dryRun` through the same services, so the fix lands for all three surfaces; check parity in the surface-parity suite.

Acceptance: on a ledger over its owner's allowance, a dry-run bank import and a dry-run `appendLedgerText` both return `RESOURCE_LIMIT_REACHED` with the same message as the real call, and a ledger under it still previews normally. Tests pin both.
