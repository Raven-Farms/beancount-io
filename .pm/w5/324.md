# The JSON `target` gains an undocumented `into` key on every `add` and on `price export`, while `import`, `format -o` and `query -o` report their destination elsewhere

**Trivial · cli (docs) · 10–15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
The `target` table in USAGE lists exactly six shapes: `file`, `files`,
`directory`, `stdin`, `server` and `null`. Two writers add a shape that is
not in the table:

- Every successful `bea --json add …` returns `{"file": <root>, "into":
  <destination>}`. This happens even without `--into`, when `into` equals
  `file`.
- `price export` returns `{"file": <root>, "into": <output directory>}`
  and repeats that directory as `data.output`.

Other writers report the same fact, where the write landed, in three other
ways:

- `import` uses `data.into`.
- `format -o` uses `data.output`.
- `query -o` does not report it at all.

[w3/442](../w3/done/442.md) introduced the table to stop undocumented
target keys, and `into` slipped past it. No product fix implemented.

Use any valid ledger at `/absolute/books/main.bean`, with the same
environment as [323](./323.md).

```sh
bea --json -f /absolute/books/main.bean add note --date 2026-02-01 -a Assets:Checking -m hi
bea --json -f /absolute/books/main.bean price export -o /absolute/exp
```

Actual:

- `add` returns `"target": {"file": "/absolute/books/main.bean", "into":
  "/absolute/books/main.bean"}`.
- `price export` returns `"target": {"file": …, "into": "/absolute/exp"}`
  together with `"data": {"output": "/absolute/exp", …}`.
- `import` returns `"target": {"file": …}` and `"data": {"into": …}`.

All three exit 0. Reproduced in three fresh runs.

Control: `check`, `balance`, `list`, `query`, `report` and `price status`
return exactly `{"file": …}`.

Expected: `docs/USAGE.md` › JSON output says "`target` identifies the
operation's scope" and gives the table. Either document `{"file", "into"}`
as a seventh shape and use it consistently, including for `import`, or
keep `target` to the table and report the destination in `data` for every
writer.

Cause:

- `cli/src/cli/commands/add.py:140`, `:293`, `:314`, `:406` and `:623`
  emit `target={**output.file_target(file), "into": target}`.
- `cli/src/cli/commands/price.py:165` does the same for `price export`.
- `import` reports `into` inside `data`.

Fix: choose one place for the write destination, apply it to `add`,
`price export` and `import`, and add that shape to the table. Docs plus a
small change to how these commands emit `target`. No dependency change.

Blast radius: JSON consumers of `add`, `price export` and `import`.

Dedupe: w3/442 (the comma-joined `files` key) is the predecessor that
documented the table. w3/438 and w3/452 cover `--into` text. No other note
covers target keys.

Acceptance: every `target` shape a local command emits appears in USAGE's
table, and `add`, `price export` and `import` report their destination
under the same key. A test asserts the target key set for each writer.
Only macOS and the checkout were exercised.
