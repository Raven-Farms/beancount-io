# `bea --json format --check` (and `-i`, `--dry-run`) skip an encrypted include silently: the envelope never names it, so it reads as a ledger with no includes (incomplete fix of w5/495)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `306653d5`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/495 (done, `bf573f9b`).
w5/495's acceptance asked that the encrypted file be named as skipped. Text
mode prints `Skipped …secret.bean.gpg: it is encrypted…`, but that note is
dropped under `--json`. USAGE (around lines 836-844) says a named file stands
for its whole include closure and that `-i` exits nonzero when anything was
skipped; it carves out only URL includes. No product fix implemented.

`main.bean`: `include "secret.bean.gpg"` and one open; `secret.bean.gpg` holds
encrypted (or random) bytes.

```sh
bea --json format --check /abs/main.bean       # also -i and --dry-run
bea format --check /abs/main.bean
```

Actual: JSON exits 0 with `{"data": {"scanned": 1, "formatted": [], "failed": [],
"missing": [], …}}` and nothing on stderr; text prints the `Skipped …` line.

Expected: a `skipped` list in the envelope (and in `error.result`) naming the
encrypted file and why; USAGE documents the encrypted carve-out (and whether
`-i` exits nonzero for it).

Cause: `cli/src/cli/commands/format.py:469-471` uses `output.note`, which JSON
mode drops (`cli/src/cli/output.py:111-114`).

Fix: as above.
