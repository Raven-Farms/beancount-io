# Loading doctor operations bypass the booking-arithmetic diagnostic and print a raw DivisionByZero traceback where check names the transaction

**Minor · cli · 15–25m · A1.** Real CLI QA, 2026-10-17, HEAD `8e35a3636`, checkout `bea 0.3.1`, macOS 26.5.1. Each command twice from fresh synthetic fixtures, isolated config/cache, stdin closed, no TTY. No product fix implemented.

Create `main.bean`:

```beancount
2026-01-01 open Assets:Checking USD
2026-01-01 open Assets:Brokerage

2026-02-01 * "Zero total cost"
  Assets:Brokerage  0 HOOL {{310 USD}}
  Assets:Checking  -310 USD
```

```sh
bea --file /abs/main.bean check
bea doctor print-options /abs/main.bean
bea doctor missing-open /abs/main.bean
bea doctor display-context /abs/main.bean
bea doctor linked /abs/main.bean 4
```

Actual: check exits 1 with `FILE:4: Beancount cannot book this transaction: Assets:Brokerage holds zero units at a total cost ... Give the posting its units, or write its cost per unit in single braces.` Each doctor command exits 1 with an unrequested traceback ending `decimal.DivisionByZero: [<class 'decimal.DivisionByZero'>]`; linked uses a long Rich traceback. No files change. The repeated harness fixtures had extra opens/options and located the same error at line 7.

Expected: doctor reports the same located booking failure without an unrequested Python traceback. The ledger is invalid; this finding concerns its diagnostic, not accepting the posting. USAGE promises every read reports this arithmetic failure at its transaction line.

Cause: `cli/src/cli/commands/doctor.py:205,232,716` prechecks decoding and plugin failures, not booking failures. `managed_load`'s booking guard applies to bea's loader, while ordinary doctor loads use upstream's own path. `cli/src/bea_engine/scoped.py:105` also re-raises exceptions with no EngineError behind them. The shared doctor dispatcher exposes other loading operations to the same omission; only the four above were rerun here. Lex, parse and list-options do not load/book the ledger.

Fix: route attributable booking failures through the located diagnostic before invoking a loading doctor operation, or normalize them at its existing loader boundary. Keep lex/parse useful for inspecting the invalid source and preserve explicit `--debug` behavior.

Dedupe: whole-board DivisionByZero/cannot-book/doctor searches found w5/538 (done) and w5/732 (open, other exception types in bea's own booking guard). This is the doctor bypass. w5/643 (done, `48b24ef26`) fixes a different strict-price error masked by upstream cleanup.

Acceptance: the four commands above name the transaction and reason with exit 1 and no traceback. Cover a wide inferred amount as another booking-arithmetic case, while a valid-ledger doctor control remains unchanged.
