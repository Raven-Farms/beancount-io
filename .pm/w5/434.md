# `--into` case handling: the case-mismatch refusal tells the user to use "the name as it is on disk" but shows the include line's spelling, and a new file under a glob include with the folder in another case is refused as "not included"

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1 (case-insensitive APFS), engine Python 3.12.
w5/097 made `--into` refuse a destination that names a ledger file in
another letter case. Two rough edges remain. No product fix implemented.

1. When the include line's case differs from the file on disk
   (`include "Sub/X.bean"`, while the file is `sub/x.bean`), `--into
   sub/x.bean` is refused with "Pass --into with the name as it is on
   disk (X.bean)". The user did pass the on-disk name. Only the include
   line's spelling, `Sub/X.bean`, is accepted.
2. Under a glob include `months/*.bean`, `--into MONTHS/feb.bean` (a new
   file, folder in another case) is refused as `not included … Create it
   and add an include directive`. `--into months/feb.bean` creates the
   file.

Use a ledger whose `main.bean` has `include "Sub/X.bean"` (file
`sub/x.bean`) and `include "months/*.bean"`. Use isolated
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, and closed
stdin.

```sh
bea -f /absolute/books/main.bean add transaction T --date 2026-01-05 -p 'Expenses:Food 1 USD' -p Assets:Cash --into sub/x.bean
bea -f /absolute/books/main.bean add transaction T --date 2026-02-05 -p 'Expenses:Food 1 USD' -p Assets:Cash --into MONTHS/feb.bean
```

Actual: both exit 2, with the messages above. Nothing is written.
Reproduced twice by the hunter.

Expected:

1. Name the spelling bea will accept: "as the include line spells it
   (Sub/X.bean)", with the full relative path.
2. Give the same case-mismatch hint for a new glob-covered file, or accept
   it.

Cause: `cli/src/bea_engine/ledger/write.py:134-140` prints `path.name`
(the include's spelling) and folds case only for existing contents.
`_included_new_file` compares the text path against the glob pattern
without folding.

Fix: reword with the include's relative spelling, and apply the
case-fold comparison to glob matching for new files. No dependency
change.

Dedupe: w5/097 introduced the check and covered existing files only. 433
covers duplicate includes. None covers these messages.

Acceptance: case 1's message names `Sub/X.bean`, and case 2 gives the
case hint or creates `months/feb.bean`. A test covers both on a
case-insensitive volume.

Addendum (CLI QA r77, 2026-10-14): the NFC/NFD form shows the same
wording problem, and there it cannot be acted on. Take a file stored NFD
(`sub/re\xcc\x81el.bean`) under an include line written NFC. `--into`
with the NFD on-disk bytes is refused with "Pass --into with the name as
it is on disk (réel.bean)". The suggested name is the include's NFC
form, which looks identical in the terminal. Prefer accepting a spelling
that `samefile`-matches an included file when only the Unicode form
differs. Otherwise, name the include line's form and show the code
points.
