# `query PRINT -f beancount` rewrites a relative document path as absolute, so the export fails `bea check` when moved

**Minor · cli · 30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A `document` directive written with a relative path is exported with the
absolute path of the machine it ran on. Saved outside the ledger directory,
the export of a valid ledger fails `bea check` with the portable-document
warning; it also puts an absolute home path into a file meant to be shared.
No product fix implemented.

Create disposable `/absolute/books/main.bean`, with any bytes at
`/absolute/books/receipts/r.pdf` and an empty directory
`/absolute/elsewhere`:

```beancount
2026-01-01 open Assets:Cash
2026-01-05 document Assets:Cash "receipts/r.pdf"
2026-01-06 note Assets:Cash "control"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean check
bea -f main.bean query PRINT -f beancount -o /absolute/elsewhere/out.bean
bea -f /absolute/elsewhere/out.bean check
```

Actual: the first two exit 0. `out.bean` contains
`2026-01-05 document Assets:Cash "/absolute/books/receipts/r.pdf"`, and the
third command exits 1:

```text
Error: /absolute/elsewhere/out.bean: 1 portable-document warning(s).
  /absolute/elsewhere/out.bean:3: Document path '/absolute/books/receipts/r.pdf' resolves to '/absolute/books/receipts/r.pdf', outside the ledger directory /absolute/elsewhere. Move the file under the ledger directory and use a relative path so copies stay portable.
```

Control: `bea -f main.bean query "PRINT FROM type != 'document'" -f
beancount -o /absolute/elsewhere/ctl.bean` produces a file that passes
`bea check`. A worker saw `--json list document` return the relative
`receipts/r.pdf`, and an export saved beside the ledger pass `check` but be
refused by `price export` ("document attachments would not travel with the
export").

Expected: the export keeps the value the ledger wrote; `bea`'s own exporter
should not produce what its own `check` reports. `list document` already
prints the relative path.

Cause: `cli/src/bea_engine/query.py:804-820` (`_render_beancount`) prints
loaded entries, in which the loader has already made the document path
absolute; `cli/src/bea_engine/ledger/reader.py:513-538` holds the
relativising logic that `list` uses.

Fix: in the beancount and CSV entry renderers, print a document path that
lies inside the root ledger's directory relative to its source file, as
`list document` does; leave out-of-tree paths alone. Native `--source`
output stays upstream's. No dependency or API change.

Blast radius: `PRINT` and `SELECT entry` in beancount, text and CSV
formats, to stdout and `-o`. Stock `bean-query` prints the same absolute
path.

Dedupe: board search for `portable-document`, and document with
PRINT/absolute/relative, finds w5/170 (`list document` on a symlinked
root), w5/216 (documents option), w3/done/351 and w1/done/165 (`check` and
`add`); none covers the export. Same family as w5/085 and w5/225.

Acceptance: `out.bean` contains `"receipts/r.pdf"`; exported beside the
ledger it passes `bea check` and `price export`. Only macOS and the
checkout were exercised.
