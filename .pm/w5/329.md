# `--time FY2027-Q2` on a ledger whose fiscal year ends mid-month (`"04-05"`) is refused as "Failed to parse date", while `fiscal_quarter` on the same ledger gives the real reason

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
A fiscal year that does not start on the first of a month, such as the UK
tax year (`"04-05"`), has no fiscal quarters. That is Fava's rule. On such
a ledger, `--time fiscal_quarter` exits 2 and explains the rule. The
documented explicit spelling `--time FY2027-Q2` also exits 2, but its
message is `Failed to parse date: FY2027-Q2` after a list of accepted
formats, which suggests the spelling itself is wrong. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Checking USD
2024-01-01 open Equity:Opening
2024-01-01 custom "fava-option" "fiscal-year-end" "04-05"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY.

```sh
bea -f /absolute/books/main.bean report income-statement -t FY2027-Q2
bea -f /absolute/books/main.bean balance -t FY2027-Q2
bea -f /absolute/books/main.bean report income-statement -t fiscal_quarter
```

Actual: the first two commands exit 2 with `Error: Invalid time filter
'FY2027-Q2'. Use month, year, YYYY, YYYY-MM, or a date range such as
'2026-01 - 2026-06'. Failed to parse date: FY2027-Q2`. The third exits 2
with `… Cannot use fiscal quarter if fiscal year does not start on first
of the month`. Reproduced in three fresh runs.

Control: on the same ledger, `-t FY2027` reports `2026-04-06 through
2027-04-05`. With a fiscal-year-end of `"03-31"`, `FY2028-Q1` works.

Expected: `docs/USAGE.md` lists `FY2026-Q1` among the fiscal spellings
without saying that quarters need a fiscal year that starts on the first
of a month. Every spelling of the same undefined period should get the
same refusal, naming the option, its value and the rule, and USAGE should
state the rule.

Cause: upstream `get_fiscal_period` (`cli/src/fava/util/date.py:535-536`)
returns `(None, None)` when `has_quarters()` is false, and `parse_date`
then fails with its generic message. Only the relative path (`:363-364`)
raises `FyeHasNoQuartersError`. `cli/src/bea_engine/report.py:401-405`
wraps whichever message reaches it.

Fix: in `report.py`, when the filter contains an explicit `FY…-Q` and the
fiscal-year-end has no quarters, refuse with exit 2 using the relative
path's text, naming the option and its line. Add one sentence to USAGE.
Leave the vendored Fava unchanged. No dependency change.

Blast radius: `balance` and all four `report` subcommands with an explicit
`FY…-Q…` (alone or in a range), on ledgers whose fiscal year starts
mid-month.

Dedupe: searched `.pm/**`, including `done/`, for `has_quarters`, "fiscal
quarter", `FY20..-Q` and "Failed to parse date". w5/147 covers an invalid
fiscal-year-end only. w3/133, w3/185 and w4/134 cover other clients. None
of them is open.

Acceptance: on the fixture, `-t FY2027-Q2` exits 2 naming the option, its
value `04-05` and the first-of-month rule, without `Failed to parse
date`. USAGE states the rule. A real-command test covers the explicit and
relative spellings. Only macOS and the checkout were exercised.
