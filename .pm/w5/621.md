# A literal tab is refused as an import delimiter (`--delimiter $'\t'`, `--csv …,delimiter=<TAB>`), and the refusal recommends "a literal tab"

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `e2565f3b`, checkout `bea 0.3.1`, macOS 26.5.1.
`parse_delimiter` explicitly accepts `"\t"`, but its input is `.strip()`ped
first, which deletes the tab. The `--csv` spelling becomes empty and lands in
the "bare comma" message, which then lists "a literal tab" as accepted.
Scripts that pass `$'\t'` (the usual shell idiom for TSV) cannot import. No
product fix implemented.

Ledger opening `Assets:Checking` and `Expenses:Uncategorized`; `t.csv`
tab-separated: `Date<TAB>Description<TAB>Amount` /
`2026-04-01<TAB>Coffee shop<TAB>-4.50`.

```sh
TAB=$'\t'
bea -f /abs/main.bean import t.csv --csv date=Date,amount=Amount,narration=Description --account Assets:Checking --delimiter "$TAB"
bea -f /abs/main.bean import t.csv --csv "date=Date,amount=Amount,narration=Description,delimiter=$TAB" --account Assets:Checking
```

Actual: exit 2, `Bad --delimiter '\t': use ',', ';', '|', or 'tab'.`; and `Bad
--csv delimiter '': a bare comma separates fields, so write delimiter=comma
(or semicolon, tab, pipe — or ';', '|', a literal tab).` The quoted
`delimiter='<TAB>'` forms fail the same way.

Control: `--delimiter tab` and `delimiter=tab` import.

Expected: a literal tab is accepted in both spellings, as the message says.

Cause: `parse_delimiter` (`cli/src/cli/csv_mapper.py:614-626`; engine copy
`cli/src/bea_engine/csv_mapper.py:782-794`) strips before comparing;
`spec_value` (`cli/src/cli/csv_mapper.py:137-142`) and
`_parse_delimiter_value` (`:251-268`) strip too.

Fix: compare the unstripped value (strip spaces only), in both copies.

Dedupe: searched `literal tab`, `delimiter` with tab; w3/226, w1/151 and
w1/m24/t001 (done) cover other delimiter cases.

Acceptance: both commands import the row. A test pins them.
