# `bea example -o DIR` says "Already exists: DIR. Pass --force to overwrite it" (exit 4), but following that advice exits 2 with "--output must be a file path, not a directory"

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
`example` checks whether `--output` exists before it checks whether the
path is a directory. A directory therefore gets the overwrite conflict
(exit 4) and the advice to pass `--force`. With `--force`, the directory
check finally runs and refuses with exit 2. The advice can never work.
The w5/136 resolution says "a directory destination now exits 2 before
generating, matching `treeify -o`", but that holds only with `--force`.
No product fix implemented.

Use an empty directory with a subdirectory `d2`, with the environment
from [352](./352.md).

```sh
bea example --seed 3 -o d2
bea example --seed 3 -o d2 --force
```

Actual:

- The first command exits 4 with `Already exists: d2. Pass --force to
  overwrite it with a generated example; without it, example never
  overwrites.`
- The second exits 2 with `--output must be a file path, not a directory
  (d2).`

Reproduced twice by the hunter and once by me.

Control: `treeify -o d2`, `format main.bean -o d2` and `query … -o d2`
each exit 2 at once with the directory message.

Expected: a directory destination should get the directory refusal (exit
2) with or without `--force`, as w5/136 describes. `--force` only gets
past the case where a file is replaced.

Cause: `cli/src/cli/commands/example.py:105-114` raises `ConflictError`
for any existing path, directories included, before
`check_output_destination` runs at `:132`.

Fix: run `check_output_destination` first, or exclude directories from
the conflict branch. The w5/277 behaviour for existing files stays the
same. No dependency change.

Blast radius: `bea example -o` with a directory path.

Dedupe: searched `.pm/**`, including `done/`, for `example -o` and "not a
directory". w5/136 claimed the exit-2 behaviour. w5/277 kept the
existing-file conflict and noted the directory case without testing
`--force`. None covers the advice that cannot work.

Acceptance: both commands exit 2 with the directory message. An existing
file still exits 4, and `--force` still replaces it. A test pins both.
Only macOS and the checkout were exercised.
