# `--id-key fitId` (a legal camelCase key) is now silently folded to `fitid`, which turns native-ID dedupe off for ledgers that use it, and the `--id-key` refusal runs only after the importer (regression from the w5/469 fix)

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `b2de72a3`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/469 (done, `ac237bd5`).
w5/469 folds a key whose lowercase form is a default key to that default, so
that `FITID` works. Beancount metadata keys must start lowercase, but may
contain capitals afterwards. `fitId`, `bank_ID` and `transaction_ID` are
therefore legal keys, and the fold rewrites the one the user typed and the
ledger uses. No product fix implemented.

Ledger with an entry carrying `fitId: "F1"` (`bea check` passes); a beangulp
importer setting `meta["fitId"] = row["Ref"]`; `s.csv` row
`2026-02-01,COFFEE,-9.99,F1`.

```sh
bea -f /abs/main.bean import s.csv --apply --id-key fitId
```

Actual: exit 0; the row is `new` (`hash`), and the ledger now holds two
`fitId: "F1"` entries with different amounts. An identical re-import, which
the parent commit reports as `1 exact duplicates`, now exits 4 as a possible
duplicate.

Before the fix: exit 4 conflict (correct for a reused ID with changed data).

Expected: a legal key is used verbatim; only spellings that cannot be keys
(capitalized first letter, such as `FITID`) are folded or refused.
IMPORTING.md: "`--id-key` never silently disables bank-ID dedupe".

Also: the refusal of an illegal key (`--id-key Ref`, exit 2) happens after the
ledger load and after the importer's `extract()` has run (`_effective_id_keys`
is called at `cli/src/bea_engine/importing.py:317`, after `_extracted` at
`:245`/`:283`), though the w5/469 resolution says "before anything is read or
written". An importer with side effects in `extract()` leaves them behind.

Cause: `cli/src/bea_engine/importing.py:118` folds by `key.lower()`.

Fix: fold only keys whose first character is uppercase; validate `--id-key`
values at the start of `answer()` (or in the frontend).

Dedupe: searched `fitId`, `camelCase`; w5/469 (done) is the parent.

Acceptance: `--id-key fitId` gives the exit-4 conflict (and an identical
re-import an exact duplicate); `--id-key Ref` exits 2 before the importer
runs. Tests pin both.
