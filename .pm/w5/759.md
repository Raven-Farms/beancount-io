# `format` after w5/565: a valid ledger whose tag or link contains `/0` (`#proj/0`, `^inv/0`) is refused as "Division by zero", and a parenthesised zero divisor (`100/(0)`) still kills the whole `format -i DIR` batch with SIGSEGV (regression and incomplete fix of w5/565)

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-17, HEAD `1d0fe90f3`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/565 (done, `8c1078d8e`).
USAGE says `--check` fails only on "a file the parser rejects", and that `-i`
"formats every reachable file". No product fix implemented.

1. **Tags and links (new with the fix).** This ledger passes `check`:

   ```
   option "operating_currency" "USD"
   2020-01-01 open Assets:Cash USD
   2020-01-01 open Income:Gains

   2020-01-05 * "a" #proj/0 ^inv/0
       Assets:Cash     1 USD
     Income:Gains   -1 USD
   ```

   `query "SELECT tags, links"` returns `proj/0 inv/0`. `bea format --check
   /abs/main.bean` exits 1 with `cannot parse: …/main.bean:5: Division by zero
   in an amount expression…`. `format -i` reports `1 file(s) cannot be parsed`
   and leaves the file unformatted. `#proj/1 ^inv/1` formats normally.
2. **Parenthesised zero.** `books/main.bean` includes `jan.bean` (misaligned)
   and `feb.bean` with `Assets:Cash  100/(0) USD`. `bea format -i /abs/books`
   exits 1 with `The Beancount engine was killed by SIGSEGV answering
   'bea-engine syntax …/feb.bean …/jan.bean …/main.bean'`. `jan.bean` is left
   unchanged, and `feb.bean` is not named. `100/(2-2)` and `--check` /
   `--dry-run` behave the same (hunter's runs). Control: with `100/0`, `jan.bean`
   is formatted and `feb.bean:2` is named.

Expected: (1) the file is formatted, because a tag or link is not
arithmetic. (2) The other files are formatted and the crashing file is named,
as for `100/0`.

Cause:
- `_NOT_ARITHMETIC` (`cli/src/cli/amounts.py:48`) blanks strings, comments and
  line-start directives, but not `#tag`/`^link` tokens. `_ZERO_DIVISOR` (`:43`)
  then matches `/0` inside them.
- Every unflagged file still goes to one batched `bea-engine syntax` call
  (`cli/src/cli/commands/format.py`, around `:496-503`), so one crash
  kills the batch.

Fix: skip tag and link tokens in the scan, and when the batched syntax run
dies on a signal, re-run it per file to name the crashing one.

Dedupe: w5/565 (done) is the parent; w5/010 and 057 accepted computed
divisors as uncatchable for `check` and `add`, but per-file isolation needs
no static analysis.

Acceptance: fixture 1 formats; fixture 2 formats `jan.bean` and names
`feb.bean`. Tests pin both.
