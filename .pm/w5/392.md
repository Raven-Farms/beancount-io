# The `bea query` shell writes its history to the fixed upstream path `~/.config/beanquery/history`, ignoring `BEA_CONFIG_DIR` and `XDG_CONFIG_HOME`, and USAGE never says where it goes

**Trivial · cli · 10–20m · A2.** CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1. **Confirmed from the code and docs only.** No interactive session was run, because it would have written to the real home directory.

USAGE says per-user state lives under `BEA_CONFIG_DIR`, which defaults to
`$XDG_CONFIG_HOME/bea`. The interactive query shell saves its line
history to upstream's hard-coded `~/.config/beanquery/history`, and only
`HOME` changes that path. A user or CI job that isolates bea with
`BEA_CONFIG_DIR`/`XDG_CONFIG_HOME` still gets queries written into the
real home directory. The shell section says only that `.exit` "saves its
history", without saying where.

Earlier QA runs recorded this as a coverage limit and filed nothing
(w4/173, w3/406: "hardcoded upstream history cannot be isolated through
BEA_CONFIG_DIR"). No product fix implemented.

Evidence:

- `cli/src/bea_engine/query.py:450` builds `history =
  Path(upstream.HISTORY_FILENAME).expanduser()`, which is upstream
  `beanquery/shell.py:44`.
- The history is saved at exit (`query.py:469`, `:473-484`).
- `docs/USAGE.md:1858` says `BEA_CONFIG_DIR` holds "Per-user state:
  credentials, `ask` history, user skills".
- `docs/USAGE.md:704` says "`.exit` (or `Ctrl-D`) ends the session with
  exit 0 and saves its history."

Control: `ask` history lands in `$BEA_CONFIG_DIR/ask_history`, as
documented. Piped one-shot `bea query` runs do not touch the history
file; the hunter compared its mtime and size before and after.

Expected: per-user state honours `BEA_CONFIG_DIR` (or XDG), or the docs
name the exception.

Fix: one of these.

- Keep bean-query compatibility and document `~/.config/beanquery/history`
  in the shell section and the environment table.
- Store the history under `BEA_CONFIG_DIR`, optionally importing the
  upstream file once.

The init file (`~/.config/beanquery/init`) is already documented, and
the same choice applies to it. No dependency change.

Blast radius: interactive `bea query` sessions, and isolated or CI
setups that rely on `BEA_CONFIG_DIR`.

Dedupe: w5/233, w5/234 and w5/235 fixed shell crashes using a disposable
`HOME`. w4/173 and w3/406 note the gap as a QA limit only. No note covers
it.

Acceptance: either `BEA_CONFIG_DIR=/x bea query` (interactive) writes its
history under `/x` and nothing under `~/.config/beanquery`, or USAGE
names the history path in both places. A test pins the chosen path.
