# `import --csv` compares column names byte for byte across Unicode normalizations, with no hint

**Minor · cli · 20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, Beancount 3.2.3, macOS (APFS).
A mapping typed as `narration=Descripción` in one Unicode form is
refused against a CSV whose header has the same text in the other form:
"The mapping names column 'Descripción' …, which nfc.csv lacks". The two
names print identically, and the look-alike hint that fires for case
differences does not fire here. The rest of import already compares
NFC. No product fix implemented.

Create `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Bank USD
2024-01-01 open Expenses:Uncategorized USD
```

and `nfc.csv` with a composed `ó` in the header:

```sh
printf 'Fecha,Descripci\xc3\xb3n,Importe\n2024-01-02,abc,-5.00\n' > nfc.csv
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY. cwd `/absolute/books`.

```sh
bea -f main.bean import nfc.csv --csv "$(printf 'date=Fecha,narration=Descripcio\xcc\x81n,amount=Importe')" --account Assets:Bank
```

Actual: exit 2: `The mapping names column 'Descripción' for narration,
which nfc.csv lacks.`

Control: the same command with the composed spelling in `--csv` exits 0
and previews the row. A worker saw the reverse direction fail too, a
case-only difference get `Did you mean 'Descripción'? Column names are
case-sensitive.`, and the remembered mapping not recalled when
`--account` or the header row is in the other form.

Expected: resolve the column, as rules and duplicate ids already do
under NFC, or at least give the look-alike hint.

Cause: `cli/src/bea_engine/csv_mapper.py:896` (also `:754`, `:863`)
tests `column not in headers` on raw strings; the look-alike helper
(`:801-805`) folds case only. The remembered record compares `--account`
raw in `cli/src/cli/commands/import_.py`.

Fix: NFC both sides in header lookup, in the header signature used for
memory, and in the account comparison. No dependency or API change.

Blast radius: `import --csv` with non-ASCII headers; remembered
mappings.

Dedupe: w1/063 (rules NFC) and w3/377 (ids NFC) cover other parts of
import; board search for "lacks" and look-alike with normalization finds
nothing.

Acceptance: the command exits 0 and previews the row in both directions;
an absent column is still refused. Only macOS and the checkout were
exercised.
