# `add balance --pad-from` blames a pad an earlier assertion already used ("already fills this assertion") and hides the real cause, and the remedy it prints then fails (gap in w1/116)

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-17, HEAD `116cf55c0`, checkout `bea 0.3.1`, macOS 26.5.1. Gap in w1/116 (done).
USAGE says the refusal names "the real reason a pad goes unused". No product
fix implemented.

```
option "operating_currency" "USD"

2026-01-01 open Assets:Checking USD
2026-01-01 open Equity:OpeningBalances
2026-01-01 open Equity:Adjust

2026-01-09 pad Assets:Checking Equity:OpeningBalances

2026-01-10 balance Assets:Checking   600.00 USD

2026-01-19 pad Assets:Checking Equity:OpeningBalances

2026-01-20 balance Assets:Checking   650.00 USD
```

```sh
bea --file /abs/chain.bean add balance --date 2026-01-15 -a Assets:Checking --amount "650.00 USD" --pad-from Equity:Adjust
```

Actual:
- Exit 1: `The existing pad at …:7 (2026-01-09 from Equity:OpeningBalances)
  already fills this assertion, so a pad from Equity:Adjust would go unused`
  and `Add the balance without --pad-from to let that pad insert 50.00 USD
  from Equity:OpeningBalances`.
- Following that (`add balance … --amount "650.00 USD"` with no `--pad-from`)
  exits 1 with `Balance failed … expected 650.00 USD != accumulated 600.00 USD`.
- With `--pad-from Equity:OpeningBalances`, it gives only the generic
  "Balance failed" advice (hunter's run).

The 2026-01-09 pad was consumed by the 2026-01-10 assertion. The real
problem is that the *existing* 2026-01-19 pad would go unused (`check` on the
written candidate reports only `:11: Unused Pad entry`, per the hunter).

Expected: name the existing 2026-01-19 pad that would go unused ("the book
balance already matches the 2026-01-20 assertion; remove that pad first").
Never offer a consumed pad as the cover.

Cause: `_unused_pad_only` (`cli/src/bea_engine/ledger/adding.py:610`) treats any
`Unused Pad` as the new pad going unused. `_covering_pad` (`:596`) picks the
latest earlier pad without checking whether that currency was already
padded.

Fix: tell an existing unused pad from the new one, and count a pad as
covering only if it is unconsumed for that currency.

Dedupe: w1/116 (done) introduced this logic.

Acceptance: the command names the 2026-01-19 pad, and its remedy works. A
test pins it.
