# When one file is included under two names (letter case, Unicode form, symlink or hard link; for example `include "Sub/X.bean"` and `include "SUB/x.bean"`), it is loaded twice and its entries double-counted, while `bea check` exits 0

**Major · cli · 20m · A2.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1 (case-insensitive APFS), engine Python 3.12.
Beancount detects a repeated include by comparing path strings. On macOS
the default filesystem ignores case, so two spellings of one file load
twice and every entry in it is counted twice. No error is reported. The
same happens when a glob include and an explicit include in another case
both reach one file. bea already treats case-variant paths as the same
file for `--into` (w5/097), but its loads and checks do not. This is A2
because stock `bean-check` has the same gap, but bea could detect it,
since it already has the include closure. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
include "Sub/X.bean"
include "SUB/x.bean"
include "months/*.bean"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "seed"
  Assets:Cash 100 USD
  Equity:Opening
```

`sub/x.bean` holds one 1 USD Food transaction, and `months/jan.bean`
holds one 2 USD Food transaction. Use isolated
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, and closed
stdin, on a case-insensitive volume.

```sh
bea -f /absolute/books/main.bean check
bea -f /absolute/books/main.bean list transaction
bea -f /absolute/books/main.bean balance Food
```

Actual: `check` exits 0. `list` shows the `x` transaction twice, and
`balance Food` is 4 USD instead of 3. The hunter also saw `include
"months/*.bean"` plus `include "MONTHS/jan.bean"` double-count, and
`price export` carry the duplicate into the snapshot. Reproduced by the
hunter on two variants and by me on the first.

Control: the same include repeated in the same case gives `Duplicate
filename parsed …` with exit 1.

Expected: a file included twice is an error however its path is
spelled, on the filesystem it lives on.

Cause: upstream `beancount/loader.py` compares path strings. bea's
include closure (the snapshot contents) does not fold case or compare by
`same_file`, although `require_target`
(`cli/src/bea_engine/ledger/write.py:134-140`) already does.

Fix: after a load, group the included files by `os.path.samefile`, or by
inode, and report a duplicate-include error naming both spellings. Apply
this in `check` and in reads. No dependency change.

Blast radius: macOS (and Windows) users whose includes vary in case,
which is common after renaming folders. Every report silently
double-counts.

Dedupe: w5/097 covers `--into` in another case, w5/087 covers `format
-o` through a symlinked root (not duplicate includes), and w5/247 covers
glob characters in names.
None covers a duplicate include in another case.

Acceptance: on the fixture, `check` exits 1 naming both spellings, and
reads refuse or warn. A same-case single include is unaffected. A test
runs on a case-insensitive temp volume or skips elsewhere.

Addendum (CLI QA r77, 2026-10-14): the Unicode-form twin has the same
cause. Take a directory `café/` stored NFC, with `include "café/x.bean"`
written once NFC (`c3 a9`) and once NFD (`65 cc 81`). `check` exits 0
and `balance Food` doubles to 2 USD (reproduced in two directories by
the hunter, once by me). A glob written NFC over an NFD directory, plus
an explicit NFD include of a file in it, also doubles. Two identical NFC
spellings give `Duplicate filename parsed`. Widen this note to "letter
case or Unicode form". A `samefile` grouping covers both.

Addendum (my own repro, 2026-10-14, same HEAD): the problem is not
specific to case-insensitive volumes. Any two names for one file
double-count:

- a hard link: `ln x.bean y.bean` with `include "x.bean"` and `include
  "y.bean"`;
- a symlink: `ln -s x.bean z.bean` with `include "x.bean"` and `include
  "z.bean"`.

In both cases `check` exits 0 and `balance Food` reports 2 USD for a
single 1 USD transaction. The `samefile` fix covers every variant. Any
test can use a hard link or symlink, so it does not need a
case-insensitive volume. (The "w5/087 covers a duplicate through a
symlink" dedupe line above is wrong: w5/087 is about `format -o` through
a symlinked root, not duplicate includes.)
