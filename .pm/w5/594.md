# Previewing a second file with the same header drops the first file's remembered `sign=ledger`, so a flag-free `--apply` writes the opposite sign with exit 0 and no note (gap in w1/150)

**Major · cli · 20–30m · A1.** Real CLI QA, 2026-10-16, HEAD `56b3a3ad`, checkout `bea 0.3.1`, macOS 26.5.1.
IMPORTING.md: a flag-free `--apply` writes the rows the last preview showed,
and dropped settings are named. w1/150 kept a `sign=ledger` preview for the
file it was chosen for. The record holds one `sign_ledger_sha256` per header,
and any explicit `--csv` run on another file with that header replaces it.
The first file's apply then reads it bank-signed, flipping every amount,
with no note. Card exports from consecutive months share a header, so this
is the normal monthly flow. No product fix implemented.

`main.bean`: `option "operating_currency" "USD"`, opens for `Liabilities:Card
USD` and `Expenses:Uncategorized USD`. `aug.csv`: `Date,Description,Amount` /
`2026-08-02,GROCERY,25.00`. `sep.csv`: same header, `2026-09-02,REFUND,-12.00`.

```sh
bea -f /abs/main.bean import /abs/aug.csv --account Liabilities:Card --csv date=Date,amount=Amount,narration=Description,sign=ledger
bea -f /abs/main.bean import /abs/sep.csv --account Liabilities:Card --csv date=Date,amount=Amount,narration=Description
bea -f /abs/main.bean import /abs/aug.csv --apply
```

Actual: the first preview shows `Liabilities:Card -25.00 USD`; the third
exits 0, says `Using settings remembered from sep.csv for aug.csv: --csv
date=Date,amount=Amount,narration=Description …`, and writes `Liabilities:Card
25.00 USD`, with no sign note. If the second run also passes `sign=ledger`, the
apply still writes +25.00, with a note claiming aug.csv "is read bank-signed".

Control: without the `sep.csv` preview, the apply prints `Re-applied
sign=ledger: aug.csv is the file it was chosen for.` and writes -25.00.

Expected: `sign=ledger` stays with each file it was previewed for (aug.csv
writes -25.00), or the apply refuses or names the dropped setting before
writing.

Cause: every explicit `--csv` run overwrites the header's single
`sign_ledger_sha256` (`cli/src/cli/commands/import_.py:956`); the replay
(`:710-746`) matches only the latest file and never names the eviction.

Fix: remember `sign=ledger` per file hash (a set per header), or name the
dropped sign when another file's run replaces it.

Dedupe: searched `sign=ledger`, `never carried`; w1/150, w3/279, w5/073, 078 and
426 (done) cover other sign-memory cases.

Acceptance: the three commands write -25.00 (or the apply refuses naming the
sign). A test pins it.
