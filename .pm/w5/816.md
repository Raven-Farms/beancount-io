# Resource-limit messages: when the engine or a native tool cannot be spawned, every engine-backed command prints only a bare `[Errno 24]`/`[Errno 35]`, and an engine killed by SIGXCPU gets "an out-of-memory killer, a timeout, or a kill" instead of the CPU-time limit

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `e68430c47`, checkout `bea 0.3.1`, macOS 26.5.1. Limits set only in the child.
No product fix implemented. Nothing is written or corrupted in any case.

1. **Spawn failure.** `bash -c 'ulimit -n 8; exec bea -f /abs/main.bean balance'`
   exits 1 with `Error: [Errno 24] Too many open files. Pass --debug before the
   command for a traceback.`. Under `ulimit -u 100`, `check`, `format`, `doctor`,
   `example` and `add note` give `[Errno 35] Resource temporarily
   unavailable.`, with JSON category `validation` (hunter's runs). Neither
   names the engine or the limit. Other spawn failures already say what failed
   (w5/372: `could not start git (…)`). Cause: `_run_helper`
   (`cli/src/cli/engine/launch.py:499`) and the native spawns do not catch
   `OSError` from `Popen`.
2. **SIGXCPU.** `bash -c 'ulimit -t 2; exec bea -f /abs/big.bean balance'` on a
   slow ledger exits 1 with `The Beancount engine was killed by SIGXCPU …` and
   `Nothing in bea sends this signal, so it came from outside: an
   out-of-memory killer, a timeout, or a kill.` (hunter's runs, nine
   commands). SIGXCPU means the CPU-time limit was exceeded, and none of
   those three sends it. Cause: `_signal_hint` (`launch.py:1242`, fallback at
   `:1168`).

Expected: (1) `Could not start the Beancount engine (Too many open files — the
open-file limit is reached); nothing was run.` (2) A SIGXCPU (and SIGXFSZ)
branch naming the resource limit (`ulimit -t` / RLIMIT_CPU).

Dedupe: w5/207 (done) covers lock exhaustion inside the engine; nothing
covers these.

Acceptance: both messages name the cause.
