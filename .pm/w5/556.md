# With a same-day price in each direction, `balance`/`report` value a holding differently from `bea query` and the answer depends on line order; `add price` writes that state without a conflict

**Minor · cli · 30–45m · A1.** Real CLI QA, 2026-10-16, HEAD `be9ef4f2`, checkout `bea 0.3.1`, macOS 26.5.1.
An FX purchase recorded with `@` (with `implicit_prices`) and a quote typed
for the same day in the other direction give two rates for one date. The
reports (Fava's price map) and BQL (Beancount's) pick different ones.
Within the reports, the winner depends on which line comes later in the
day. Beancount sorts by date, type and line number without the file name, so
with a separate `prices.bean` it depends on line numbers across files.
ADR015 already treats a same-date reciprocal pair as one collision whose
precedence "never depends on include order". No product fix implemented.

`a1.bean`:

```beancount
option "operating_currency" "USD"
plugin "beancount.plugins.implicit_prices"

2026-01-01 open Assets:EUR EUR
2026-01-01 open Assets:USD USD
2026-01-01 open Equity:Opening

2026-01-01 price EUR 1.10 USD

2026-01-02 * "Open"
  Assets:EUR  1000.00 EUR
  Equity:Opening

2026-01-05 * "Buy USD with EUR"
  Assets:USD  100.00 USD @ 0.80 EUR
  Assets:EUR  -80.00 EUR

2026-01-05 price EUR 1.20 USD
```

```sh
bea -f /abs/a1.bean balance Assets:EUR
bea --json -f /abs/a1.bean report balance-sheet
bea -f /abs/a1.bean query "SELECT convert(sum(position),'USD') AS v WHERE account = 'Assets:EUR'"
```

Actual (all exit 0): `balance` shows `1,104.00 USD` (920 × 1.20); the
balance sheet's `net_worth` is `1204.0000` USD; `query` says `1150.0000 USD`
(920 × 1.25, the inverse of the implicit `USD 0.80 EUR`), as does
`getprice('EUR','USD')`. Moving the `price EUR 1.20 USD` line above the
transaction makes `balance` say 1,150.00.

Also: starting from a ledger with `2026-01-05 price USD 0.80 EUR`, `bea add
price --date 2026-01-05 --currency EUR --amount "1.20 USD"` prints `Added 1
price` (exit 0), producing this state; USAGE says a different amount for the
same date is refused.

Control: same-direction duplicates on one day agree between report and
query (last line wins in both); a 210-ledger differential fuzz without
same-day reciprocals found no mismatch.

Expected: one valuation per ledger and date, independent of line order, the
same in reports and BQL. Upstream's rule (the inverted minority direction
wins) is the one bean-query users see. `add price` treats a local reciprocal
same-day quote as a conflict needing `--force`, as it already does for
managed points.

Cause: `FavaPriceMap` (`cli/src/fava/beans/prices.py:86-95`) appends each rate
and its inverse in entry order, and `_keep_last_per_day` (`:42-56`) keeps
whichever sorts last; upstream `build_price_map`
(`beancount/core/prices.py:104-119`) settles the pair first. `add price`
counts a local conflict only when `entry_pair == pair`
(`cli/src/bea_engine/ledger/adding.py:649`), while the managed check
(`:638`) includes the reciprocal.

Fix: settle same-day reciprocal precedence once, the way upstream does,
before Fava's per-day dedupe (keep `NOTICE.fava`); extend the `add price`
conflict check to the reciprocal pair.

Dedupe: searched `keep_last_per_day`, `FavaPriceMap`, `reciprocal`. w1/050,
w3/432 and w1/m29/t003 cover other price cases.

Acceptance: the three commands agree (1,150 USD) in both line orders; `add
price` refuses the reciprocal quote without `--force`. Tests pin both.
