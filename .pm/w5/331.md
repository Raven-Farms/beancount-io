# `bea balance` and `bea report` print a bidirectional override in an account name raw, while `list` escapes it: the w5/148 fix did not reach the report tree

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
[148](./done/148.md) made human output escape Unicode bidi overrides
(U+202A–202E, U+2066–2069) as a visible `\uNNNN`, and its blast radius
named "report breakdowns". The account tree printed by `balance` and by
every `report` subcommand does not go through that sanitizer.

Beancount and `bea check` accept an account component that contains
U+202E. In the report tree it reaches the terminal raw, just before the
amount column, so on a bidi-aware terminal the rest of the row can read
reversed. `list open` shows the same account as `Pay‮emoc`. The raw
bytes were confirmed in output captured from a pipe and from a PTY; the
visual effect itself was not observed. No product fix implemented.

Create disposable `/absolute/books/main.bean` (`<RLO>` stands for a raw
U+202E):

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Pay<RLO>emoc USD
2026-01-01 open Equity:Opening
2026-01-02 * "Open"
  Assets:Pay<RLO>emoc  5 USD
  Equity:Opening
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin.

```sh
bea -f /absolute/books/main.bean balance
bea -f /absolute/books/main.bean report balance-sheet
bea -f /absolute/books/main.bean list open
```

Actual:

- `check` exits 0.
- `balance`, `report balance-sheet` and `report trial-balance` exit 0. The
  tree row contains the raw bytes `e2 80 ae`, both on a pipe and on a
  100-column PTY.
- `list open` shows `Assets:Pay‮emoc`.

Reproduced in three fresh copies, one of them an independent rerun.

Control: `list open` and `list transaction` escape the character. An
ordinary Hebrew or Arabic account component is left untouched everywhere.

Expected: per 148, human-facing output writes bidi overrides as a visible
`\uNNNN`. The report tree is human-facing output, and 148 listed it.

Cause: `_print_tree` (`cli/src/cli/commands/report.py:115-128`) builds
`label` from `node["account"]` and echoes it without calling `single_line`
(`cli/src/cli/utils.py:24`), which `output.table` applies to every cell.
`_heading` (`report.py:135`) also echoes `account_filter` raw.

Fix: render `single_line(label)` in `_print_tree` and `single_line` the
filter in `_heading`, so padding is computed from the escaped text's
width. `--json` keeps the exact name. No dependency or API change.

Blast radius: `bea balance` and every `report` subcommand that prints an
account tree, in human output on a pipe or a terminal, for any ledger
(hand-edited or received) whose account names contain these characters.
`add` already refuses such names in new writes (w5/203).

Dedupe: searched `.pm/**`, including `done/`, for `202e`, bidi,
right-to-left override and `_print_tree`. w5/148 is the predecessor; it
covered the sanitizers and `table`. w5/246 and w1/106 cover widths, and
w5/203 covers the add side. None of them covers the report tree.

Acceptance: on the fixture, `balance` and `report balance-sheet` print
`Pay‮emoc` with no raw U+202E byte, on both a pipe and a PTY. The
amount column stays aligned, and `--json` still carries the exact name. A
real-command regression test covers `balance` and one `report`
subcommand. Only macOS and the checkout were exercised.
