# `init DIR` and `format -o` leak raw OS errors as exit 1 when the destination cannot be created

**Minor · cli · 25–35m · A2.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, Beancount 3.2.3, macOS. When the destination's directory is not
writable, or a path component is a regular file, these commands print a Python
exception name and exit 1 (category `validation`), where the same tool
elsewhere gives a clear message and exit 3 or 2. `init` is the first command
a newcomer runs. No product fix implemented.

In a disposable directory create a regular file `notes`, a directory
`lock` with mode `555`, and `a.bean` holding `2026-01-01 open Assets:A`.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY. Cwd that directory:

```sh
bea --no-input init notes --currency USD
bea --no-input init lock/books --currency USD
bea format a.bean -o lock/out.txt
```

Actual: each exits 1 — `Error: FileExistsError: [Errno 17] File exists:
'…/notes' Pass --debug before the command for a traceback.`,
`Error: PermissionError: [Errno 13] Permission denied: '…/lock/books' …`, and
`Error: [Errno 13] Permission denied: 'lock/out.txt'`. Repeated twice.

Controls on the same `lock` directory: `bea --no-input init lock/x.bean
--currency USD` exits 3 with `Cannot stage a copy of x.bean in …/lock: the
directory is not writable… Nothing was written.`; `bea -f a.bean query
"SELECT account" -o lock/out.txt` exits 3 with the same message; `bea format
a.bean -o nodir/out.txt` exits 2.

Expected: `docs/USAGE.md` Exit codes — 3 is a permission failure, 2 is bad
arguments or a missing target — and the messages the controls already print.
No Python exception name in user output.

Cause: `cli/src/bea_engine/initiating.py:103` calls
`file.parent.mkdir(parents=True, exist_ok=True)` with no `OSError`
handling; `cli/src/cli/commands/format.py:521` writes the destination with a
bare `write_text`.

Fix: map these failures onto the existing "directory is not writable" (exit 3)
and "is not a directory" (exit 2) errors; for `format -o`, check the
destination before the engine runs, as `query -o` does. `treeify -o` into
an unwritable directory names its hidden staging file in the same way and
should share the fix. No dependency or API change.

Dedupe: board search for `FileExistsError`, `PermissionError` and errno
text finds w1/073 (a read-only include directory on add), w5/004 (`format
-i` on an unwritable file) and w5/056 (price export through a blocked
directory); none covers `init DIR` or `format -o`.

Acceptance: the three commands exit 2, 3 and 3 with messages naming the path
and saying nothing was written, in text and `--json`; the controls are
unchanged. Only macOS and the checkout were exercised.
