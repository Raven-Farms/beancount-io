# `cloud ledger clone --dir target` into a non-empty directory asks the server first, then exits 1 with git's message; `create --clone --dir target` refuses the same target with exit 2 before any request (gap in w5/371)

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `d16aea3e`, checkout `bea 0.3.1`, macOS 26.5.1. Simulation: local stub API.
USAGE: "A clone target git would refuse (`./<name>` or `--dir` naming a file
or a non-empty directory) is refused with exit **2**." w5/371 added the
pre-check to `create --clone` only; w5/372 moved `clone`'s git check ahead of
the request for the same reason. No product fix implemented.

Working directory with `target/notes.txt` (any content).

```sh
bea --json cloud ledger clone qa/books --dir target
bea --json cloud ledger create fresh --clone --dir target
```

Actual: `clone` sends `GET /api-gateway/v1/ledgers/qa/books`, then exits 1
(`validation`): `Clone failed for ssh://…/qa/books.git (fatal: destination
path 'target' already exists and is not an empty directory.).` `create
--clone` exits 2 (`usage`) with `Clone target 'target' already exists and is
not an empty directory; nothing was created.` Nothing changes on disk.

Expected: `clone` refuses an occupied `--dir` with exit 2 before credentials
and the request. For the default `./<name>`, it refuses right after the
lookup, before git.

Cause: `ledger_clone` (`cli/src/cli/commands/cloud/ledger/app.py:121-150`)
never calls `manager.refuse_occupied_clone_target`.

Fix: call it as described above.

Dedupe: w5/371 and 372 (done) are the sibling fixes.

Acceptance: the `clone` command exits 2 with the target message and no
request. A test pins it.
