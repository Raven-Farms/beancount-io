# `bea doctor` prints a raw upstream traceback (41–213 lines, exit 1) when an included file is unreadable or a directory, on every operation that loads includes; w5/120's one-line exit-2 refusal does not reach doctor

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
[w5/120](./done/120.md) made an unreadable include a one-line exit 2
"so every read and write exits 2", and routed `check` around native
bean-check. `doctor` was neither tested nor routed. It forwards to native
`bean-doctor`, whose traceback is passed through. [w5/256](./done/256.md)
notes "`doctor` operations were not probed". No product fix implemented.

Create a disposable `main.bean` that includes `inc.bean`, a USD ledger.
Make `inc.bean` a directory (or `chmod 000` it). Use isolated
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, and closed
stdin.

```sh
bea doctor print-options /absolute/books/main.bean
bea doctor context /absolute/books/main.bean 5
bea doctor roundtrip /absolute/books/main.bean
bea -f /absolute/books/main.bean balance          # control
```

Actual:

- `print-options`, `missing-open`, `directories`, `display-context` and
  `context` exit 1 with an upstream traceback of about 41 lines, ending
  in `IsADirectoryError: [Errno 21] …/inc.bean` (or `PermissionError`).
- `linked` and `region` print about 210 boxed lines.
- `roundtrip` ends in `TypeError: stat: path should be string … not
  NoneType`.

The hunter reproduced these on both fixtures, and I reproduced
`print-options`.

Control: `balance`, `list`, `report`, `price`, `import` and `check` exit
2 with `Included file '…/inc.bean' (included from '…/main.bean') is not
readable: it is a directory, not a file. …`

Expected: w5/120's claim that every read gives the one-line exit 2 should
hold for `doctor` too. There should be no traceback (w3/298, w5/089).

Cause: `_needs_compat` (`cli/src/cli/commands/doctor.py:207-242`) sends
an unreadable closure to native `bean-doctor` (`except OSError:
continue` / `return False`). `_run`/`_capture` (`:245-256`) pass the
traceback through. `check` avoids this with
`output.has_unreadable_include` (`cli/src/cli/commands/check.py:66`,
`cli/src/cli/output.py:347`).

Fix: for operations outside `_SINGLE_FILE_OPS`, call
`output.has_unreadable_include(root)`. If it is true, route to the helper
or raise w5/120's `UsageError`. No dependency change.

Blast radius: every `bea doctor` operation that loads includes, on
ledgers with an unreadable or directory include.

Dedupe: w5/120 is the parent and claims full coverage. w3/382 (malformed
location), w5/256 (unprobed doctor) and w5/312 (load-cache permissions)
cover other cases. None covers this.

Acceptance: each doctor operation above exits 2 with w5/120's one line
and no traceback. A test covers `print-options` and `roundtrip` with a
directory include.

Addendum (CLI QA r84, 2026-10-14): `bea ingest extract -e LEDGER` has the
same gap. With an `-e` ledger whose include is a directory (or `chmod
000`), it exits 1 with a 46-line beangulp/beancount traceback ending in
`IsADirectoryError` (or `PermissionError`). Reproduced twice by the
hunter. `_forward` (`cli/src/cli/commands/ingest.py:70-81`) does not
check the `-e` ledger's closure. Calling `output.has_unreadable_include`
on the `-e` path (found by `_extract_ledgers`) before forwarding fixes
it.
