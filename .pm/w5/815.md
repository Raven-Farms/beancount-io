# `bea engine status` calls a healthy managed engine "damaged — Remove … and rerun" when its probe cannot be spawned (process or descriptor limit), though every command works; feature presence reads "absent" the same way (sibling of w5/724)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `e68430c47`, checkout `bea 0.3.1`, macOS 26.5.1. Limits set only in the child (`bash -c 'ulimit …; exec bea …'`).
w5/724's stated rule is that bea never advises deleting an engine that loads.
Following this advice deletes a working engine, and rebuilding it needs the
network. No product fix implemented.

```sh
bash -c 'ulimit -n 9; exec bea engine status'
bash -c 'ulimit -n 9; exec bea -f /abs/main.bean check'
```

Actual:
- `engine status` exits 0 with `Provisioned: damaged — the engine cannot load
  ([Errno 24] Too many open files). Remove ~/.local/share/bea/engine/0.3.1 and
  rerun; bea provisions a fresh engine.`
- Under `ulimit -u 100` it says the same with `[Errno 35] Resource temporarily
  unavailable`, reports `beangulp: enabled, absent`, and JSON gives `"usable":
  false` with `"damaged": "[Errno 35] …"` (hunter's runs).
- Under the same `ulimit -n 9`, `check` exits 0.

Expected: when the probe itself cannot start, say the engine could not be
checked (with the reason), give no removal advice, report `usable` as unknown,
and do the same for feature presence.

Cause: `engine_load_failure` (`cli/src/cli/engine/launch.py:747`) returns
`str(exc)` when `subprocess.run` raises `OSError` (the probe never ran).
`engine_status` (`cli/src/cli/commands/engine.py:32`) treats any reason as
damaged. `_packages_importable` (`cli/src/cli/engine/provision.py:301`) turns
the same `OSError` into "absent". The probe needs one more descriptor than a
real command, which is why `-n 9` breaks status but not `check`.
`_refuse_unusable_engine` (`:775`) shares the probe.

Fix: distinguish "could not probe" from "probed and failed" in both
functions.

Dedupe: w5/724 (open) is the `PYTHONIOENCODING` trigger; w5/320, 481 and 785
cover engines that really are damaged.

Acceptance: under `ulimit -n 9`, `engine status` gives no removal advice.
