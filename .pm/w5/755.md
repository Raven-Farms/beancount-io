# A DEBIT/CREDIT "Type" column (ING-NL "Af Bij", "Dr / Cr") cannot be mapped, and header inference ignores it, so every debit is booked as money in with exit 0

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-17, HEAD `0e9729be5`, checkout `bea 0.3.1`, macOS 26.5.1.
No product fix implemented.

`type.csv`:

```
Date,Description,Amount,Type,Balance
2026-01-02,Coffee shop,4.50,DEBIT,995.50
2026-01-03,Payroll,2000.00,CREDIT,2995.50
2026-01-04,Rent,1200.00,DEBIT,1795.50
```

```sh
bea --file /abs/main.bean import type.csv --account Assets:Checking --apply
```

Actual: exit 0 after `Read the column mapping from the header row: --csv
date=Date,amount=Amount,narration=Description`. It writes +4.50, +2000.00 and
+1200.00 to `Assets:Checking`, so the account rises by 3204.50. The preview
showed the same signs, and nothing mentions the Type column.

Expected: the change is −4.50 + 2000 − 1200 = +795.50, which matches the
export's own Balance column (1000 → 1795.50). A `4.50 DR` suffix is refused
cleanly. The column form should either be mappable or at least be flagged.

Cause: the mapping fields (`_MAPPING_FIELDS`, `cli/src/bea_engine/csv_mapper.py:27`)
have no direction or indicator field, and inference reads only its listed
synonyms.

Fix: add a `direction=Column` field (DEBIT/CREDIT, D/C, Dr/Cr, Af/Bij). At
minimum, have inference refuse (or note) an unmapped column whose values are
only those words.

Dedupe: w5/614 (open, pending/status rows) is the closest sibling; nothing
covers direction columns.

Acceptance: the fixture imports +795.50 with `direction=Type`, and without it
the run names the Type column. Tests pin both.
