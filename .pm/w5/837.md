# From a deleted working directory, every refusal that prints a remedy built by `bea_command` dies with a bare `FileNotFoundError` (exit 1) and loses the real reason: add with an unknown account (regression from w5/619), import with blocked rows, the empty BQL window

**Minor · cli · 5m · A1.** Real CLI QA, 2026-10-17, HEAD `8a64f3768`, checkout `bea 0.3.1`, macOS 26.5.1. Regression from w5/619 (done, `3cf4f4e43`) for `add`.
w5/248 (done) established that commands given absolute paths must not depend
on the working directory. A shell left in a removed directory (after `git
checkout` or a cleanup) is a common state. No product fix implemented.

`books/main.bean` opens `Assets:Checking`, `Expenses:Food USD` and
`Expenses:Uncategorized`. From a working directory that has been removed:

```sh
bea --file /abs/books/main.bean add transaction Latte --date 2026-04-01 -p 'Expenses:Coffee 4 USD' -p Assets:Checking
```

Actual: exit 1, `Error: FileNotFoundError: [Errno 2] No such file or
directory. Pass --debug before the command for a traceback.`. The real reason
(unknown account) is lost, and `--json` reports category `validation`. An
import preview with blocked rows prints no preview, and an empty `FROM OPEN …
CLOSE ON …` query exits 1 instead of 2, the same way (hunter's runs).

Control: a valid add from the same removed directory exits 0. Before
`3cf4f4e43`, the refused add gave its normal validation error (hunter's run
on the pre-fix engine).

Expected: the normal refusal, with the remedy naming the absolute ledger.

Cause: `bea_command` (`cli/src/bea_engine/ledger/text.py:79`, around `:91`)
calls `Path.cwd()`, which raises. It is called from `write.py` (the w5/619
remedies), `importing.py` and `query.py`.

Fix: when the cwd is unavailable, fall back to `bea --file <absolute target>`.

Dedupe: w5/619 and 248 (done) are related.

Acceptance: the refused add prints its unknown-account refusal from a removed
directory. A test pins it.
