# `--conversion AT_COST`/`AT_VALUE`/`UNITS` is accepted as a made-up currency, and `-x cost`/`value`/`market` suggests "Did you mean 'COST'?", which leads straight there

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
[w3/427](../w3/done/427.md) made malformed `--conversion` values exit 2
so that a typo would not become a fake currency. An upper-cased keyword
still gets through, because `AT_COST` is a valid Beancount currency
name. The report is then valued in a currency with no prices:

- under a terminal it exits 0, prints `Valuation: AT_COST`, and shows
  units;
- piped or with `--json` it exits 1, `validation`, with `Missing prices
  for USD → AT_COST`.

Near-miss words are worse. The hint for `-x cost` is `Did you mean
'COST'?`, and following it gives the case above. No product fix
implemented.

Use any ledger, for example `option "operating_currency" "USD"`, with
`Assets:Bank` and `Equity:Opening` open and one 100 USD transaction. Use
isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, and closed stdin.

```sh
bea --json -f /absolute/books/main.bean balance -x AT_COST
bea --json -f /absolute/books/main.bean balance -x UNITS
bea -f /absolute/books/main.bean balance -x cost
bea -f /absolute/books/main.bean balance -x value
```

Actual:

- `AT_COST` and `UNITS` exit 1 with `Missing prices for USD → AT_COST`
  (or `→ UNITS`) and `USD has no AT_COST price at any date; shown in
  units`.
- Under a PTY, `report balance-sheet -x AT_COST` exits 0 with `Valuation:
  AT_COST` and a partial-valuation note.
- `-x cost` exits 2 with `Invalid --conversion 'cost'. … Did you mean
  'COST'?`. `-x value` suggests `'VALUE'`, and the hunter saw `market` and
  `at_market` suggest `'MARKET'` and `'AT_MARKET'`.

Reproduced by the hunter on two fixtures and by me.

Control: `-x at_cost` works. `-x Units` exits 2 with `Did you mean
'units'?`.

Expected: `docs/USAGE.md` says malformed values exit **2** before loading
the ledger, and w3/427 aimed to keep typos from becoming currencies.
Therefore:

- a value whose lowercase form is a keyword (`AT_COST`, `UNITS`) should
  exit 2 suggesting the keyword;
- the suggestion for a near miss should be the closest keyword (`cost` →
  `at_cost`, `value` or `market` → `at_value`) before falling back to
  upper case.

Cause: `answer` in `cli/src/bea_engine/report.py:63-71`.
`_valid_conversion` (`:36-48`) accepts `AT_COST` because the lexer reads
it as a currency. The hint tries `.lower()` only for an exact keyword
match, then `.upper()`. This dates from `a6c0231b` (w3/427).

Fix:

- Before the lexer check, refuse a value whose `.lower()` is a keyword
  but which is not that exact keyword.
- Choose suggestions with `difflib.get_close_matches` over the keywords,
  or with an explicit `cost`/`value`/`market` map, before the upper-case
  fallback.
- No dependency change.

Blast radius: `--conversion`/`-x` on `balance` and `report *`, in text,
piped and JSON modes.

Dedupe: searched `.pm/**`, including `done/`, for `AT_COST`, `at_market`
and "Invalid --conversion". w3/427 covers lowercase and malformed values
only. w5/328 covers a misspelled `operating_currency`. None covers this.

Acceptance: `-x AT_COST`, `AT_VALUE` and `UNITS` exit 2 suggesting the
lowercase keyword. `-x cost` and `-x value` suggest `at_cost` and
`at_value`. `-x USD` and an unpriced real currency are unchanged. A test
pins all of these.
