# `add open -c USD -c EUR -c USD` writes a repeated currency list (`open Assets:Z USD,EUR,USD`), while repeated `--tag`/`--link` values are collapsed

**Trivial · cli · 5–10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
`-c/--currency` on `add open` is repeatable. Each value is appended
as-is, so a repeat produces a duplicated constraint list. Beancount
tolerates it, so `check` passes, but the written text is untidy and
inconsistent with how bea treats repeated tags and links. No product fix
implemented.

Use any ledger. Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME,
BEA_NO_UPDATE_NOTIFIER=1, and closed stdin.

```sh
bea -f /absolute/books/main.bean add open --account Assets:Z --date 2026-01-01 -c USD -c EUR -c USD
```

Actual: exit 0, and the ledger gets `2026-01-01 open Assets:Z
USD,EUR,USD`. `-c USD -c USD` gives `USD,USD`. Reproduced twice by the
hunter and once by me.

Control: `add transaction … --tag a --tag '#a' --link x --link '^x'`
writes `#a ^x` once each.

Expected: collapse repeats in first-seen order (`USD,EUR`), or refuse
them with exit 2 naming `--currency`, in line with w5/238's rule against
silently mishandling repeated options.

Cause: `cli/src/bea_engine/ledger/adding.py:155-165` builds `currencies`
straight from the request.

Fix: de-duplicate while keeping order. No dependency change.

Dedupe: w5/238 covers conflicting single-valued options and price
`-c`/`--commodity`. No `.pm` hit for `USD,USD` or "duplicate currency".

Acceptance: the command writes `open Assets:Z USD,EUR`. A test pins it.
