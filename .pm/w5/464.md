# Under `--allow-errors`, an append into a file that ends inside an unbalanced `pushtag`/`pushmeta` silently inherits that tag and metadata, while the `--json` echo reports none

**Trivial · cli · 15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
[w5/200](./done/200.md) made an unbalanced `pushtag`/`pushmeta` an error
that `--allow-errors` tolerates as pre-existing. It did not consider that
text appended after an open push inherits it. A transaction added with
`--into` such a file gets a tag and metadata the user never gave, and the
echo shows the entry without them. No product fix implemented.

Use a `main.bean` that includes `inc.bean` and opens `Assets:Cash` and
`Equity:O` (USD). `inc.bean` starts with `pushmeta source: "bank-a"` and
`pushtag #trip`, holds one transaction, and never pops either. Use
isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, and
closed stdin.

```sh
bea --json -f /absolute/books/main.bean add transaction B --date 2026-01-03 -p 'Assets:Cash 2 USD' -p Equity:O --into inc.bean --allow-errors
bea --json -f /absolute/books/main.bean list transaction --allow-errors
```

Actual: `add` exits 0, and its echo shows `"tags": [], "meta": {}`.
`list` shows `B ['trip'] {'source': 'bank-a'}`. Without
`--allow-errors`, the write is refused (`Unbalanced pushed tag`).
Reproduced by the hunter on three fixtures and by me once.

Expected: the written entry means what the echo says. Either refuse the
append, even under `--allow-errors`, naming the open push and its line,
or warn that the new entry will inherit it. Silently writing an entry
with extra tags or metadata is not acceptable.

Cause: the append path in `cli/src/bea_engine/ledger/write.py` treats
the `Unbalanced pushed tag`/`metadata` diagnostics as pre-existing, and
never compares the appended entry's loaded tags and metadata with those
requested.

Fix: when the destination ends inside a push, refuse with exit 2 naming
the line. Alternatively, compare the loaded entry with the request and
refuse on any difference. No dependency change.

Blast radius: `add *`, bulk add and `import --apply` with
`--allow-errors` into files with an open push.

Dedupe: w5/200 (done) introduced the tolerance. No other `.pm` note
covers inheritance.

Acceptance: on the fixture, the write is refused (or warned) naming
`pushtag #trip` at line 2, and no entry with inherited tags is written. A
test pins it.
