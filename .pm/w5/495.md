# A ledger with an encrypted include (`include "secret.bean.gpg"`) fails `format --check`/`-i` and `doctor print-options`/`roundtrip`, and `format` advises re-saving the encrypted file as UTF-8

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-16, HEAD `3f2372e1`, checkout `bea 0.3.1`, macOS 26.5.1. Isolated `GNUPGHOME` with a no-passphrase test key.
Beancount decrypts `.gpg` and armored `.asc` includes when it loads them
(`beancount.utils.encryption.is_encrypted_file`), so `bea check`, `list` and
`query` work. `format` and some doctor operations walk the include closure
as text and read the ciphertext. The `format` refusal tells the user to
"Re-save the file as UTF-8", which would store the secrets in plaintext. No
product fix implemented.

`secret.bean.gpg`: an encrypted transaction (`gpg -e -r <test key>` of a
one-transaction file). `main.bean`:

```beancount
include "secret.bean.gpg"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
```

With that `GNUPGHOME`:

```sh
bea -f /abs/main.bean check                   # exit 0
bea format --check /abs/main.bean
bea doctor print-options /abs/main.bean
```

Actual: `format` exits 1 with `Cannot decode '…/secret.bean.gpg' as UTF-8:
invalid start byte at byte 0. Re-save the file as UTF-8 and retry.` (`-i`
and `--dry-run` the same; nothing written). `doctor print-options` and
`roundtrip` exit 1 with `cannot load main.bean: secret.bean.gpg:1: Invalid
token: '\x85\x01…'`. `bea list transaction` labels the decrypted entries
SOURCE `generated`.

Control: upstream `bean-doctor print-options` and `roundtrip` exit 0.

Expected: encrypted members are treated like URL includes: skipped by
`format` (named as skipped), not syntax-checked as text by doctor, and never
reported as undecodable. `list` shows their file as the source.

Cause: `_walk_closure` (`cli/src/cli/output.py:423-480`) adds encrypted
members as ordinary text; `format`'s `_syntax_failures` → `_text`
(`cli/src/cli/commands/format.py:472-490`) decodes them;
`_closure_syntax_errors_of` (`cli/src/cli/commands/doctor.py:245-259`) and
the engine's `syntax` command parse the ciphertext.

Fix: recognize encrypted members with upstream's rule and exclude them from
text walks; keep loading them through the loader.

Dedupe: searched `gpg`, `encrypted`. No match.

Acceptance: `format --check` exits 0 or 1 based only on the plaintext files
and names the encrypted one as skipped; both doctor operations exit 0. A
test with a fake `is_encrypted` fixture pins it.
