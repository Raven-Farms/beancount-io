# `report -a Expenses:Travel` also matches `Assets:Reimbursable:Expenses:Travel`, and `-a Income` pulls `Expenses:Taxes:Income` into net profit: an account-name filter matches the components anywhere in a name

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `0c520fd1`, checkout `bea 0.3.1`, macOS 26.5.1. Gap in w5/292.
USAGE (Reports): "A value spelled as an account name matches that account and
its children only". w5/292 switched to Beancount's `has_component`, which is
`re.search("(^|:){value}(:|$)")`. It matches that run of components anywhere
in a name, not only at the start, so totals, net worth and net profit
include unrelated accounts. Reimbursable-expense and tax-on-income accounts
are common shapes. No product fix implemented.

`reimb.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Bank USD
2026-01-01 open Assets:Reimbursable:Expenses:Travel USD
2026-01-01 open Expenses:Travel USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "fund"
  Assets:Bank  1000.00 USD
  Equity:Opening
2026-01-10 * "own trip"
  Expenses:Travel  100.00 USD
  Assets:Bank
2026-01-12 * "work trip"
  Assets:Reimbursable:Expenses:Travel  400.00 USD
  Assets:Bank
```

`inc.bean`: income of 1000.00 USD split into `Assets:Bank 700.00` and
`Expenses:Taxes:Income 300.00`, plus a 50.00 food expense.

```sh
bea -f /abs/reimb.bean report balance-sheet -a Expenses:Travel
bea --json -f /abs/inc.bean report income-statement -a Income
```

Actual: the balance sheet lists `Reimbursable` › `Expenses` › `Travel 400.00
USD` and `Net Worth: 400.00 USD` (also in `trial-balance` and `overview`); the
income statement's `net_profit` is `{"USD": "700.00"}`, with
`Expenses:Taxes:Income` in the expenses tree.

Control: `-a '^Expenses:Travel(:|$)'` shows no assets and net worth 0;
`-a '^Income(:|$)'` gives net profit 1000.00.

Expected: an account-name (or bare root) value matches `name == value or
name.startswith(value + ":")` only: net worth 0 / "—" for the first, net
profit 1000.00 for the second.

Cause: `cli/src/fava/core/filters.py:462-465` uses `account.has_component` for
valid names and roots (the comment at `:457` states the intended rule); every
report shares this predicate.

Fix: anchor account-name and root values at the start, as above; keep regex
search for real patterns (coordinate with open w5/502, which reworks invalid
patterns in the same predicate).

Dedupe: searched `has_component`, `Reimbursable`; w5/292 (done) introduced
it; w5/502 (open) and w3/379 are different.

Acceptance: the two commands give net worth 0 and net profit 1000.00. Tests
pin both.
