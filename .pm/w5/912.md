# Keep child source accounts in parent-importer transaction identity

**Major · cli · 45–60m · A1.** An importer filing under a parent account can
silently omit a real payment to a different child account. The two rows get
one generated ID, and even `--duplicates include` cannot keep the second.
Agents importing separate brokerage statements need each cash posting to
survive. No product fix implemented.

Real CLI QA 2026-10-21, checkout `169bb4fb0` (`cli` unchanged since the
`bcd564706` reproduction), `bea 0.3.1`, Darwin 25.5.0 arm64, frontend Python
3.13.3, managed engine Python 3.12 with existing Beangulp. Reproduced twice
from pristine fixtures, bounded separate processes, closed stdin/no TTY,
isolated absolute BEA_CONFIG_DIR/XDG_CACHE_HOME, updater disabled, and no
inherited BEA_FILE/BEA_TOKEN.

Create `/absolute/qa/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Broker:One USD
2024-01-01 open Assets:Broker:Two USD
2024-01-01 open Income:Interest USD
```

Create `one.txt` containing `One` and `two.txt` containing `Two`, each with a
trailing newline. Put this inspected synthetic importer in `importers.py`:

```python
from pathlib import Path
from beancount.parser import parser

class Imp:
    def identify(self, file):
        return str(file).endswith(".txt")
    def account(self, file):
        return "Assets:Broker"
    def extract(self, file, existing_entries=None):
        child = Path(file).read_text().strip()
        entries, errors, _ = parser.parse_string(
            '2024-02-01 * "Broker" "Interest"\n'
            f'  Assets:Broker:{child} 1.00 USD\n'
            '  Income:Interest -1.00 USD\n'
        )
        assert not errors, errors
        return entries

CONFIG = [Imp()]
```

Run with absolute paths:

```sh
bea --json -f /absolute/qa/main.bean import /absolute/qa/one.txt --config /absolute/qa/importers.py --apply
bea --json -f /absolute/qa/main.bean import /absolute/qa/two.txt --config /absolute/qa/importers.py
bea --json -f /absolute/qa/main.bean import /absolute/qa/two.txt --config /absolute/qa/importers.py --apply --duplicates include
bea --json -f /absolute/qa/main.bean query "SELECT account, sum(number) GROUP BY account ORDER BY account"
bea --json -f /absolute/qa/main.bean check
```

Actual, both repetitions: the first writes 1. The second preview leaves the
ledger unchanged and calls Two's payment an exact duplicate of One's:
`import-id csv:sha256:bfb41b5c36505377 is already in the ledger.` Its proposed
entry posts to `Assets:Broker:Two`, while `match.entry` posts to
`Assets:Broker:One`. Apply exits **0**, writes **0**, and leaves the ledger
byte-identical. BQL shows only One `1.00 USD` and Income `-1.00 USD`; Two's
payment is missing. `check` exits 0. Human apply and reversed child order
reproduce the same omission twice each.

Expected: both payments import once, One and Two each hold `1.00 USD`, and
Income is `-2.00 USD`. Different source child accounts are different cash
postings, even when an importer files their documents under one root.

Controls, twice each: return the exact child from `account()` and both rows
are new and write. Different descriptions or distinct native bank IDs also
let `--duplicates include` write both, although their preview still falsely
flags a possible duplicate across children. A manually written One entry
likewise makes Two a possible duplicate; include keeps it. Reimporting the
same child correctly writes 0. Returning both child rows in one initial file
writes 2 because occurrence numbering distinguishes them; splitting that
file into one-row exports exposes the collision. All fresh checks pass.

Cause: `cli/src/bea_engine/importing.py:1281–1296` correctly selects child
source postings when no exact root posting exists, but `_hash_import_ids`
at 2417–2435 retains only their amounts, commodities and lots. It omits each
posting's account, then hashes the parent `account()` value. `_same_row`
at 1754–1775 trusts a canonical generated-ID hit without content checking.
The adjacent `_legs` at 1386–1391 also drops child names, explaining false
possible duplicates and why a migration cannot merely rename the new hash.
The shared callers cover Python importer row hashing, legacy claims, native
ID content checks and twin matching. Ordinary exact-account CSV imports
cannot select two different source children this way.

Fix: include the actual source-account distribution when identifying rows
selected through a filing parent, in both generated IDs and relevant content
matching. Keep exact-account IDs and counter-account edit behavior stable
where possible. Treat old child-blind IDs as lossy: only match a known child
distribution, or surface ambiguity for review; do not silently consume
another child's payment through a legacy lookup. Preserve normal same-child
reimports, parent brokerage extraction, and valid transfer matching. Owning
package is CLI; no API or dependency change is required.
