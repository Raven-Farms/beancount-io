# `bea --file DIR init` on an existing empty directory exits 4 "init never overwrites a ledger" instead of the usual "is a directory" usage error

**Trivial · cli · 5–10m · A1.** Real CLI QA, 2026-10-17, HEAD `101b89e3`, checkout `bea 0.3.1`, macOS 26.5.1.
No product fix implemented.

```sh
mkdir books
bea --no-input --file books init --currency USD --date 2026-08-01
```

Actual: exit 4, category `conflict`: `Already exists: …/books. Choose a new
path; init never overwrites a ledger.` The directory is empty, so nothing
would be overwritten.

Control: `bea --file books check` exits 2 with `Ledger path 'books' (from
--file) is a directory; expected a ledger file. Point --file to its root
ledger, for example --file books/main.bean.` Positional `bea init books`
creates `books/main.bean`.

Expected: exit 2 explaining that `--file` names a file, and suggesting `bea
init books` or `--file books/main.bean`.

Cause: `cli/src/cli/commands/init.py:117-125` uses `ctx.file` as the target
file without checking whether it is a directory, then raises `ConflictError`.

Fix: when `--file` names a directory, raise a `UsageError` with both
alternatives.

Dedupe: w3/346, w5/219 and w5/295 cover other init target cases; none covers
`--file DIR`.

Acceptance: the command exits 2 with the hint; an existing file still exits 4.
