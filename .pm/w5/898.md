# Preserve the evaluated digits of a wide arithmetic `@@` total

**Minor · cli · 15–25m · A1.** The arithmetic-total probe bypasses the
existing exact parser, changing a terminating total beyond 28 significant
digits before writing it. Follow-up to completed [059](./done/059.md),
[802](./done/802.md) and [263](./done/263.md). No product fix implemented.

Real CLI QA 2026-10-20, checkout `e029d663b`, `bea 0.3.1`, Darwin 25.5.0
arm64, frontend Python 3.13.3, managed engine Python 3.12. Reproduced twice
per path in fresh synthetic ledgers, closed stdin/no TTY, isolated absolute
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1 and no inherited
BEA_FILE/BEA_TOKEN.

Create `/absolute/qa/main.bean`:

```beancount
2024-01-01 open Assets:HOOL HOOL
2024-01-01 open Assets:Cash USD
```

Run:

```sh
bea --json -f /absolute/qa/main.bean add transaction 'QA total' --date 2024-02-01 -p 'Assets:HOOL 3 HOOL @@ (123456789012345.123456789012345+1) USD' -p Assets:Cash
bea --json -f /absolute/qa/main.bean check
```

Both exit 0, stderr empty. The first writes:

```beancount
2024-02-01 * "QA total"
  Assets:HOOL  3 HOOL @@ 123456789012346.1234567890123 USD
  Assets:Cash
```

The JSON answer repeats that truncated value in
`data.directive.postings[0].price_total.number`. Independent 80-digit
Decimal addition gives **123456789012346.123456789012345**. Changing only the
expression to that plain literal preserves all digits in the file and JSON.
A grouped literal `123,456,789,012,346.123456789012345` also preserves them.
The normal-sized expression `(40+60)` correctly writes `@@ 100 USD`.
All three controls were repeated twice through both entry paths.

Bulk reproducer, on the pristine ledger, using this `input.json`:

```json
[{"date":"2024-02-01","narration":"QA total","postings":[
  {"account":"Assets:HOOL","amount":"3 HOOL @@ (123456789012345.123456789012345+1) USD"},
  {"account":"Assets:Cash"}]}]
```

`bea --json -f /absolute/qa/main.bean add transactions --from input.json`
exits 0 and writes the same shortened total. A fresh query and check both
succeed. Booked per-unit division/inferred-cash rounding is upstream behavior
and is excluded; this finding concerns the changed total annotation and the
single-add JSON answer. USAGE's Investment postings section promises an exact
`@@` total, and 263/w1/m27 require preserving input digits on disk.

Cause: `cli/src/bea_engine/amounts.py:174–196`, `_probed_amount`, calls raw
`beancount_parser.parse_string` at line 186 under its default 28-digit
context. That re-evaluation replaces the result of `parse_exact`, already
used by the main single/bulk posting parsers. The literal fast path in
`split_total_price` (:166–168) returns source digits unchanged, while the
grouped positive literal reaches the probe without an arithmetic operation
that rounds it. Callers are `_total_price` in `ledger/adding.py` and
`_posting_fragment` in `ledger/models.py`; both were exercised.

Fix: evaluate the probe through the existing exact parser, retaining its
documented upstream precision for non-terminating quotients. Preserve
plain/glued/grouped totals, malformed-input handling, quoted labels and the
zero-divisor refusal. Do not create a separate arithmetic evaluator or
reconstruct a total from a divided price.

Dedupe: searched all board states for `_probed_amount`, arithmetic totals,
wide/28-digit `@@` values and exact-price annotations; reviewed active
milestone scopes. Completed 059 first added the probe, 802's
`f5b460db8` made the whole non-literal tail reach it, and 263 fixed other
parsers with `parse_exact`. No open item covers this remaining raw-parser
call, and current main has no later repair. Small and literal controls pass.

Acceptance: both reproduced commands write the full independently evaluated
total and the single-add JSON agrees; keep literal/grouped/small controls and
the existing non-terminating-quotient behavior. Evidence retained in ignored
pass5 `repro_total_price_precision_v2.py`, `total-precision-v2-results.json`,
fixtures and per-command captures. Initial exploratory code indexed an empty
query after an invalid negative-price control; that harness failure was
excluded and the accepted-input matrix rerun completely. No hosted state,
new dependencies or other platforms were exercised.
