# With a deleted working directory, `bea init /abs/dir` creates the ledger and then exits 2 with a bare `[Errno 2]`; `format` and `query -o` on a split ledger fail the same way

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Fix the include half with [071](./done/071.md).
When the shell's working directory has been removed (a deleted temporary
directory, a moved checkout), commands given absolute paths still consult
the working directory. `init` writes the ledger, prints its success line,
then fails with exit 2 and a bare errno; `format` and `query -o` on a
ledger with an include fail before doing anything. No product fix
implemented.

Fixture: a child process whose working directory is removed before `bea`
starts (in Python: `os.chdir(tmp); os.rmdir(tmp)` in a pre-exec hook), and
a split ledger `/absolute/split/main.bean`:

```beancount
include "inc/jan.bean"
2026-01-01 open Assets:Cash USD
```

with `/absolute/split/inc/jan.bean` containing `2026-01-02 open
Expenses:Food USD`.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY.

```sh
bea --no-input init /absolute/nb --currency USD --date 2026-01-01
bea format --check /absolute/split/main.bean
bea -f /absolute/split/main.bean query 'select count(*) as c' -f csv -o /absolute/out.csv
```

Actual: `init` prints `Created /absolute/nb/main.bean with 14 accounts in
USD.`, then `Error: [Errno 2] No such file or directory`, and exits 2; the
ledger exists and no "Next:" line is printed. The other two exit 2 with
only `Error: [Errno 2] No such file or directory`; `out.csv` is not
written.

Control: from an existing working directory all three exit 0. With the
deleted working directory, `bea -f /absolute/split/main.bean check` still
exits 0; a worker saw `list`, `balance`, `add`, `import --apply` and
`--json init` unaffected, and a raw `Error in sys.excepthook` traceback
when the working directory is unreadable rather than deleted.

Expected: a completed `init` exits 0, and exit 2 is the usage category.
Commands given absolute paths should not depend on the working directory,
and an error should name what is missing.

Cause: `cli/src/cli/commands/init.py:184` evaluates `Path.cwd()` after the
success line, only to choose the hint. `cli/src/cli/output.py:237` builds
`(source.parent, Path.cwd())` eagerly for every include, the same line
w5/071 wants changed.

Fix: in `init`, treat an unavailable working directory as "not the cwd
ledger" and still print the hint; in the include walker, do not consult
the working directory for file sources (per 071), or evaluate it lazily
and tolerate `OSError`. No dependency or API change.

Blast radius: `init`; every caller of the include walker (`format`,
`query -o`, `format -o`, `treeify -o`).

Dedupe: board search for `getcwd`, `Path.cwd` and "deleted" working
directory finds only w5/071 (same line, different symptom); the `init`
half is unfiled.

Acceptance: with a deleted working directory, `init /absolute/nb` exits 0
with its hint, and `format --check` and `query -o` on the split ledger
behave as from a normal directory. Only macOS and the checkout were
exercised.
