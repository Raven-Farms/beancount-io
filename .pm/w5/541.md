# A `--partial` bulk write that wrote rows drops their NFC/NFD account notes in text mode (JSON keeps them as `ledger_warnings`)

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `c3c42a48`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE promises the cross-normalization note "for every `add`, bulk row, and
import". It prints when no row is rejected. When one row is rejected, text
mode suppresses the warnings of the rows that were written: w5/461's rule
for refused writes is applied to a partial one. No product fix implemented.

Ledger with `Expenses:Food` and `Assets:Café` opened in NFD (`Café`).
Rows: one food purchase from `Assets:Café` (NFC), and one to the
unknown `Expenses:Nope`.

```sh
bea -f /abs/nfdp.bean add transactions --from nfd_mix.json --partial
```

Actual: exit 1; stderr has `Added 1 of 2 transactions; 1 row was rejected.`
and the Row 2 detail, with no normalization note for the written row. With
`--json`, the note is present as `error.ledger_warnings`.

Control: the same ledger with only the valid row prints the note.

Expected: the note prints for the written row in text mode too.

Cause: the engine returns the written rows' warnings in `ledger_errors` of
the partial-result error (`cli/src/bea_engine/ledger/adding.py:1414`). The
frontend suppresses tolerated errors in text for any write
(`cli/src/cli/engine/launch.py:428`, `if tolerated and (not writes or
json_output)`).

Fix: render the warnings when the error carries written rows.

Dedupe: w5/461 (done) chose silence for refused writes only.

Acceptance: the partial run prints the note. A test pins it.
