# `add balance --pad-from` with a positive amount on a credit-normal account with no history (a loan, equity, income) pads silently with no warning, while the same assertion without `--pad-from` flags the sign (incomplete fix of w5/611)

**Minor · cli · 5–10m · A1.** Real CLI QA, 2026-10-17, HEAD `2f69b1461`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/611 (done), whose addendum raised this case.
No product fix implemented.

`z.bean`: `option "operating_currency" "USD"`, `open Liabilities:Loan USD`, `open
Equity:OpeningBalances`.

```sh
bea --json -f /abs/z.bean add balance --date 2026-07-10 --account Liabilities:Loan --amount '5000 USD' --pad-from Equity:OpeningBalances
```

Actual: exit 0 with `"warnings": []`. In text it says `the pad inserts 5000 USD
into Liabilities:Loan from Equity:OpeningBalances`, and `report balance-sheet`
then counts the loan as adding to net worth (hunter's run).

Control: without `--pad-from`, the same assertion exits 1 with `Liabilities
balances are negative in Beancount, so an amount owed of 5000 USD is asserted
as -5000 USD…`. An exactly-negated existing balance is refused without
`--force`.

Expected: at least the same sign note in `warnings` when a credit-normal
account with no balance is padded to a positive amount.

Cause: `negated_credit_hint` (`cli/src/bea_engine/ledger/write.py:1300`) returns
None when the held balance is 0. The zero-history note exists only in the
refusal's recovery steps, which a successful pad never reaches.

Also (trivial): `--force` help (`cli/src/cli/commands/add.py`, around `:279`, and
`docs/REFERENCE.md`) still describes only a second assertion on the date,
though it now also overrides the sign refusal.

Fix: emit the sign note as a warning on this path, and update the `--force`
help.

Dedupe: w5/611 (done) is the parent; w5/359 and 361 (done) are the skill
side.

Acceptance: the command warns about the sign. A test pins it.
