# Cost labels are written to the ledger with raw control characters and bidi overrides (bulk rows and `-p`), though payees and narrations are escaped

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `c3c42a48`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE escapes ESC, other C0 controls and bidi controls (as `\xNN` / `\uNNNN`)
in written strings. It calls out that an RLO "ahead of an amount could
otherwise reorder how the rest of a row reads". A lot label sits right
before `@ price`. Labels from broker exports or an agent's JSON are written
byte for byte. No product fix implemented.

Ledger with `Assets:Brokerage` and `Assets:Checking` open. Row:

```json
[{"date": "2026-02-01", "payee": "\u001b[2JP", "narration": "buy",
  "postings": [{"account": "Assets:Brokerage", "units": {"number": "1", "currency": "HOOL"},
                "cost": {"number": "5", "currency": "USD", "label": "\u001b[2J‮L"}},
               {"account": "Assets:Checking"}]}]
```

```sh
bea -f /abs/w.bean add transactions --from j.json
bea -f /abs/w.bean add transaction x --date 2026-02-01 -p $'Assets:Brokerage 1 HOOL {5 USD, "\e[31mL‮X"}' -p Assets:Checking
```

Actual: exit 0. `od -c` shows the payee written as the visible text
`\x1b[2JP`, but the label as raw bytes `033 [ 2 J 342 200 256 L`. A newline in
a label is also written raw. `bea list` tables escape it; the file does not.

Expected: labels get the same escaping as other strings.

Cause: `normalize_entry_strings` (`cli/src/bea_engine/ledger/writer.py:216`)
skips cost labels; `_escape_cost_label` (`writer.py:252`) escapes only quotes
and backslashes; the `-p` path writes the typed text unchanged.

Fix: apply the shared control/bidi escaping to labels on write, for both
paths.

Dedupe: w1/011 and w5/060 (done) cover backslashes and quotes in labels.

Acceptance: both commands write the label with `\x1b` and `‮` escapes.
A test pins it.
