# `add custom --value account:…` refuses an account name typed in a decomposed Unicode form

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`),
checkout `bea 0.3.1`, macOS.
Every other `add` command accepts an account typed in NFD (as a macOS file
name or paste yields) and writes it NFC. `add custom` refuses it with "would
reload as different values", and in a terminal the "requested" and "reloads
as" lines look identical. No product fix implemented.

Create disposable `/absolute/books/main.bean`, with `É` as the single
code point U+00C9:

```beancount
option "operating_currency" "USD"
2020-01-01 open Assets:Élan USD
2020-01-01 open Equity:Opening
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY. In the command, type the account with `E` followed by U+0301:

```sh
bea --json -f /absolute/books/main.bean add custom --date 2021-01-05 --type budget \
  --value "account:Assets:Élan" --value "amount:5 USD"
```

Actual: exit 2 with `The custom directive would reload as different values;
nothing was written.`, details `requested: account:Assets:E\u0301lan,
amount:5 USD` and `reloads as: account:Assets:\u00c9lan, amount:5 USD`.
The file is unchanged.

Control: `bea -f … add note --account <the same NFD spelling> --comment hi
--date 2021-01-05` exits 0. A worker confirmed `add custom` with the NFC
spelling exits 0 and that open, close, balance, transaction and document
accept NFD.

Expected: `docs/USAGE.md` says "An account name written in a different
Unicode normalization than the ledger uses … resolves to the same account
instead of a false unknown-account error, and the new directive is written
NFC."

Cause: `cli/src/bea_engine/ledger/writer.py:482` compares the requested
values with the rendered text's reload, but the text was rendered through
`_nfc_entry_accounts` (`:275-282`) while `_custom_value_key`
(`:488-489`) compares the raw request. `adding.py:214` calls
`parse_account` for the value and discards its normalised result.

Fix: normalise account-typed custom values to NFC before the comparison —
keep `parse_account`'s result at `adding.py:214`, or normalise in
`_custom_value_key`. No dependency or API change.

Dedupe: board search for NFD with custom and the message text finds w5/080
(the same command on renamed roots, a different cause) and w1/m26/t004,
w3/278 (the NFC work that left this comparison out).

Acceptance: the fixture command exits 0 and writes
`custom "budget" Assets:Élan 5 USD` in NFC; the NFC spelling and other
value kinds are unchanged. Only macOS and the checkout were exercised.
