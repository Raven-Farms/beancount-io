# Managed-price shadowing detects ledger-authored prices by regex: an arithmetic amount (`price BTC 90000 * 1 USD`) is missed, so the feed beats the user's own price, and a price-shaped line inside a multi-line string shadows the feed, so the ledger is left with no price

**Minor · cli + ledger · 20–30m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1. **Simulation:** the feed comes from a localhost origin through `MANAGED_PRICE_ORIGINS`. The defect is in the CLI and hosted engine logic.

USAGE promises that "a ledger-authored price for the same date and pair
shadows the managed point". The authored pairs are found with a
line-anchored regex over the raw ledger text, and it is wrong in both
directions:

- **Missed:** the amount is matched with `\S+`, so any amount expression
  with spaces is not seen. Examples are `90000 * 1` and `(90000 + 0)`.
  Both prices then load, and which one Beancount uses depends on line
  numbers across files. That contradicts ADR018's "never depends on
  include order".
- **False match:** a price-shaped line inside a multi-line string, such
  as a note or narration holding pasted text, matches and shadows the
  managed point, although nobody authored a price. The ledger then has
  no price for that date.

No product fix implemented.

Setup (by the hunter):

- `main.bean` includes `http://127.0.0.1:<port>/prices/BTC-USD` and
  holds 1 BTC at a cost of 100 USD.
- The feed body is `; alias: BTC-USD`, 17 blank lines, then `2026-01-10
  price BTC 100000 USD`. That puts the feed point at a later line than the
  ledger's.
- Each case appends one line (or one multi-line note) to `main.bean`, then
  runs `bea price refresh`.
- Isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
  inherited BEA_FILE/BEA_TOKEN, and closed stdin.

```sh
bea -f /absolute/L/main.bean query "SELECT getprice('BTC','USD',2026-01-10) AS p"
bea --json -f /absolute/L/main.bean price status
```

Actual:

| Appended ledger text | `getprice` | `shadowed_count` | What follows |
|---|---|---|---|
| `2026-01-10 price BTC 90000 * 1 USD` (or `(90000 + 0) USD`) | **100000** | **0** | `list price` shows both prices, and `balance -x USD -t 2026-01-10` values Crypto at 100,000 USD |
| A multi-line note whose second line is `2026-01-10 price BTC 1 USD` | none | **1** | `effective_dates: []`, `list price` shows "No prices found", and `balance -x USD` exits 1 with `Missing prices for BTC → USD` |

Each case was reproduced twice by the hunter in fresh caches. I
confirmed the regex.

Control:

- `2026-01-10 price BTC 90000 USD` gives `getprice` 90000 and
  `shadowed_count` 1.
- The same note text on one line leaves the managed price in place.

Expected: `docs/USAGE.md` (Managed price includes) says "A price you
declare yourself wins: a ledger-authored price for the same date and pair
shadows the managed point". Any price directive the user wrote should
shadow, whatever its amount syntax. Text inside a string is not a price
directive.

Cause:

- `_LEDGER_PRICE_RE` (`cli/src/bea_engine/managed_load.py:80-84`) uses
  `\S+` for the amount and is anchored only at line start, so it matches
  continuation lines of strings. `collect_ledger_price_pairs` (`:137-152`)
  applies it to raw text.
- The hosted engine has the same regex:
  `backend-cluster/ledger/src/foundation/managed-prices/managed-price-overlay.ts:73-74`.

Fix:

- Collect `(date, base, quote)` from the parsed `Price` entries of the
  ledger's own files, which the load already has before it overlays
  feeds.
- Or tokenize with Beancount's lexer, which skips string contents and
  accepts any number expression.
- Apply the same change to the hosted overlay so both engines shadow the
  same points.
- No dependency change.

Blast radius: ledgers with managed price includes and either arithmetic
price amounts or multi-line strings containing price-like text. The
result is a silently wrong valuation or a missing price.

Dedupe: searched `.pm/**`, including `done/`, for shadow,
`collect_ledger_price_pairs`, "ledger-authored", arithmetic and
precedence. 377 is about the feed-side grammar, and w3/413, w3/433,
w3/436 and w3/387 cover other problems. None covers how authored prices
are detected.

Acceptance:

- An arithmetic authored price shadows the feed point (`shadowed_count`
  1, `getprice` 90000).
- A price-shaped line inside a multi-line string does not shadow.
- The CLI and hosted engine give the same result on a shared fixture.
- Tests cover both cases in both engines.
