# An unreadable `--into` include, `--rules` file or `price export -o` directory is reported as "The Beancount engine did not answer", and on writes as exit 4 "the outcome is unknown", though nothing ran (gap in w5/120)

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-17, HEAD `6d74be10`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE: "An include that reaches a file without read permission … exits **2** on
every command" (w5/120), and an unwritable destination is a permission
failure (exit 3). The engine's own Typer `Path` options default to
`readable=True`, so Click rejects the value before the command body runs and
no answer envelope is written. The frontend reads a missing envelope as an
engine death, and for writes as an unknown outcome. No product fix
implemented.

`main.bean` with `include "inc.bean"`; `inc.bean` at mode `200` (or `000`).

```sh
bea --json -f /abs/main.bean add open --date 2026-02-03 --account Assets:New2 --into inc.bean
bea -f /abs/main.bean import s.csv --account Assets:Checking --rules r.csv          # r.csv mode 000
bea -f /abs/main.bean price export -o exp                                            # exp/ mode 0300
```

Actual: the `add` exits 4 (`conflict`): `The Beancount engine did not answer
'bea-engine add --file … --into inc.bean' (exit 2); the outcome is unknown.
Inspect the file before retrying.`, with the engine's Rich usage box and
`Invalid value for '--into': Path 'inc.bean' is not readable.` in the details.
Files are unchanged. `add transactions --into` and `import --into` behave the
same; the `--rules` preview exits 1 (`--apply` 4); the `price export` exits 1.

Control: the same ledger without `--into` exits 2 with w5/120's one-line
`Included file … is not readable: Permission denied …`.

Expected: exit 2 with the w5/120 message for the unreadable include and rules
file, and exit 3 for the unwritable export directory; never "outcome unknown".

Cause: `readable=True` defaults on the engine options
(`cli/src/bea_engine/main.py:257`, `:300`, `:478` `--into`; `:463` `--rules`;
`:762` `--output`); `_parse` (`cli/src/cli/engine/launch.py:578-620`) maps a missing
envelope to an engine failure, and with `writes=True` to `ConflictError` (`:607`).

Fix: pass `readable=False` on those engine options and let the engine's checks
report the problem; separately, treat an engine exit 2 without an envelope or
traceback as an argv usage error, not an unknown outcome.

Dedupe: searched `did not answer` with into and rules, `not readable`; w5/120
(done) fixed the snapshot path; w5/523 is format-only.

Acceptance: the three commands exit 2, 2 and 3 with bea's own messages. Tests
pin them.
