# Under `--json`, a successful `import` does not say that it could not save the import memory

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Same mechanism as [270](./done/270.md) and [282](./282.md).
When the config directory is read-only (a container, a sandbox that allows
writes only in the project), a text-mode import warns `Could not remember
the column mapping … Pass --csv on the next import.` Under `--json` the
same run exits 0 with nothing about memory, so an agent's next flag-free
import fails, or silently uses older remembered settings. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Food
2026-01-01 open Expenses:Uncategorized
```

`/absolute/books/apr.csv`:

```csv
Date,Description,Amount
2026-04-02,Grocer,-20.00
```

`/absolute/books/may.csv`:

```csv
Date,Description,Amount
2026-05-02,Grocer,-4.50
```

`/absolute/books/rules.toml`:

```toml
[[rule]]
match = "grocer"
account = "Expenses:Food"
```

Use a fresh BEA_CONFIG_DIR made read-only (`chmod 555`) before the first
run, an isolated XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no inherited
BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea --json -f main.bean import apr.csv --csv date=Date,amount=Amount,narration=Description --account Assets:Checking --rules rules.toml --apply
bea --json -f main.bean import may.csv --apply
```

Actual: the first exits 0 with `written: 1`, `notes: ["Using column
mapping (--csv)."]` and empty stderr. The second exits 2: `Read a column
mapping from the header row of may.csv (…), but not which account the
export belongs to.`

Control: the first command in text mode on the same read-only config
prints `Could not remember the column mapping: [Errno 13] Permission
denied: '…/importers'. Pass --csv on the next import.` With a writable
config directory, the JSON pair exits 0 and 0. A worker saw the same
silence for a Python importer (`Could not remember the importer path`) and,
with older memory present, the next flag-free import use the stale rules.

Expected: `docs/IMPORTING.md`: "the mapping is remembered", and "settings
it drops are named, never silently discarded"; `docs/USAGE.md` says
`import` emits an envelope so a script can confirm what happened. The
envelope should carry the statement text mode makes.

Cause: `cli/src/cli/commands/import_.py:283` (`_remember_csv`) and `:130`
(`_remember_config`) report the failure only through a note that is a
no-op under `--json` (`cli/src/cli/output.py:53-56`); the envelope built
at `:671-689` has no field for whether memory was saved.

Fix: have both helpers return the failure text, append it to the `notes`
in the envelope, and optionally add a stable boolean such as
`memory_saved`. No dependency change; fields are added only.

Blast radius: `bea --json import`, preview and apply, CSV and Python
importer modes, whenever the `importers/` directory cannot be written.

Dedupe: board search for "Could not remember" and `_remember_csv` finds
w5/215 (an unreadable directory fails with a raw errno; it uses this note
as its text-mode control), w5/282 (failure envelope lacks notes), w5/214
(concurrent memory writes) and w5/073; none covers the JSON success
envelope omitting a failed save.

Acceptance: the first command's envelope states that memory was not saved
and what to pass next time; the writable control is unchanged. Only macOS
and the checkout were exercised.
