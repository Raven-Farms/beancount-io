# A cached ledger export omits a sibling helper imported inside the plugin function, reporting success for a snapshot that fails check (follow-up to w5/327)

**Minor · cli · 30–50m · A1.** Real CLI QA, 2026-10-20, checkout
`bea 0.3.1`, HEAD `866d1e78a`, Darwin 25.5.0 arm64; frontend Python 3.13.3.
No product fix implemented.

Create disposable `/abs/case/books/main.bean`:

```beancount
option "operating_currency" "USD"
option "insert_pythonpath" "TRUE"
plugin "myplug"
2024-01-01 open Assets:Cash USD
```

Create `books/helper.py` containing `TEXT = "Synthetic"`, and this
inspected local `books/myplug.py`:

```python
import time
__plugins__ = ["run"]
def run(entries, options):
    time.sleep(1.1)
    import helper
    assert helper.TEXT == "Synthetic"
    return entries, []
```

The sleep makes the tiny fixture reach the normal load-cache threshold;
a naturally slow ledger/plugin has the same state. With isolated absolute
`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, no inherited
`BEA_FILE`/`BEA_TOKEN`, closed stdin/no TTY, cwd `/abs/case`:

```sh
bea --json --file /abs/case/books/main.bean check
bea --json --file /abs/case/books/main.bean check
bea --json --file /abs/case/books/main.bean price export --output /abs/case/snapshot
bea --json --file /abs/case/snapshot/main.bean check
```

Actual: both source checks exit 0. The second serves the cache. Export exits
0 and lists only `snapshot/main.bean` and `snapshot/myplug.py`;
`helper.py` is missing. A fresh snapshot check exits 1 with
`Plugin "myplug" failed while running: ModuleNotFoundError: No module named
'helper'.` Reproduced twice in fresh directories.

In the captured fixture, an additional local `.runs` marker appended by the
plugin confirms it ran once for the first check, then zero times for the
cached check/export. First check takes ~1.4 s; cached check/export ~0.2–0.3 s.
The marker is optional instrumentation; the public plugin above suffices.

Working control: export the unchanged source using a fresh **isolated**
cache directory in the child environment and a new output directory. The
plugin executes, `helper.py` is included, and the fresh snapshot check exits
0. An import at module scope is the existing w5/327 control. This failure
uses ordinary readable files, independently of w5/879's permissions case.

Expected: dependency completeness must not depend on whether this ledger
was checked recently. USAGE promises a self-contained snapshot including
local helper modules the plugin imports. Either carry the helper or refuse
the incomplete export before publishing success.

Cause: `_sibling_imports` in
`cli/src/bea_engine/managed_load.py:2193–2237` calls
`importlib.import_module` for each plugin then scans `sys.modules`. On a
cached load the plugin function did not run, and importing its module does
not execute the function's `import helper`. The helper is absent from the
module inventory and `_export_plugin_modules` omits it. Cold loads happen
to populate that inventory. Local helpers and helper packages imported
during plugin execution share the gap.

Fix: ensure export's dependency inventory includes imports made while
plugins execute even when ordinary reads can reuse a cached load, or
validate/refuse an incomplete staged snapshot before reporting success.
Keep unrelated root-directory files excluded and preserve containment,
collision, atomicity and permission checks. Avoid a repair that merely
copies every nearby file. No dependency or backend/API change is needed.

Dedupe: whole-board searches for cached/lazy plugin helper exports and all
open/blocked milestone scopes found completed w5/327 (`32638d15`). That fix
explicitly imports plugin modules to account for caching, but its tests use
module-scope imports only. w5/220 concerns cached normalization, and
w5/868/879 concern package resources/traversal. Targeted source history
contains no repair for function-scope dependency discovery.

Acceptance: warm and cold exports of the fixture both produce fresh-loadable
snapshots, or an incomplete export refuses without destination residue;
module-scope and no-helper controls continue working. Pin the actual warm
cache transition with subprocesses. Windows/Linux and repaired behavior
remain unverified. Sanitized evidence and fixtures are retained under
`.tmp/qa-2026-10-20-cli-loop-d3c5ebec/`: `export-cached-plugin-{1,2}/`
and matching `captures/cached-plugin-*.json`. The public setup is sufficient
without ignored evidence.
