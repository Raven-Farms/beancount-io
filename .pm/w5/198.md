# BQL errors send `--json` and non-terminal callers to the interactive shell, which refuses them

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
Every BQL usage error ends "Run bea query with no argument for the
interactive shell, where .tables lists what you can query." Under
`--json` or without a terminal, `bea query` with no argument is itself an
error. `bea query .tables` works in every mode and is what the hint
should say. No product fix implemented.

Create any valid `/absolute/books/main.bean`, for example:

```beancount
2020-01-01 open Assets:Checking USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea --json -f main.bean query "SELECT acount"
bea --json -f main.bean query
bea --json -f main.bean query .tables
```

Actual: the first exits 2 (correct) and its `details` end with the shell
advice. The second exits 2: `A query is required as an argument or on
stdin.` The third exits 0 and lists the tables.

Control: the third command.

Expected: advice that works where it is printed: `Run bea query .tables
to list what you can query`, mentioning the shell only on a terminal.

Cause: `cli/src/bea_engine/query.py:1143` appends the line to every usage
error unconditionally.

Fix: change the wording as above. No dependency or API change.

Blast radius: every unknown-column, unknown-table and syntax error.

Dedupe: w3/done/234 made `--json query .tables` work and quoted this
hint as a symptom; the hint text was left unchanged.

Acceptance: the error's last detail names `bea query .tables`; following
it exits 0 in text and JSON. Only macOS and the checkout were exercised.
