# A ledger with a deny-delete ACL fails every write with a raw `PermissionError` and leaves a staged copy behind each time (regression of w1/done/073)

**Minor · cli · 30m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
w1/done/073 made a refused replace exit 3 with a clear message and no
staging file. The w1/done/099 fix, which copies the ledger's ACL onto the
staged candidate, landed afterwards: when the ledger carries a deny-delete
ACL, the candidate inherits it, the cleanup `unlink` is refused, and that
error replaces the intended one. Each attempt leaves a `.bea-<hex>.tmp`
copy of the ledger that the user cannot delete without removing the ACL.
Rare, but a regression. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"

2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Food USD
```

then `chmod +a "everyone deny delete" /absolute/books/main.bean` (macOS).

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea --file main.bean add transaction --date 2026-01-05 --narration Lunch --posting "Expenses:Food 10 USD" --posting Assets:Checking
bea --json --file main.bean add note --date 2026-01-05 -a Assets:Checking -m hi
```

Actual: both exit 1; the ledger is unchanged and two `.bea-<hex>.tmp`
files remain beside it.

```text
Error: PermissionError: [Errno 13] Permission denied: '/absolute/books/.bea-a85b1060fa997e69.tmp' Pass --debug before the command for a traceback.
```

JSON reports category `validation`.

Control: the same ledger without the ACL accepts both commands (exit 0)
and leaves no staging file. A worker saw the same failure for `format -i`,
`import --apply` and `add transactions`, and w1/done/073's first trigger
(a read-only include directory) still holding.

Expected: w1/done/073: a refused replace "exits 3 naming the path instead
of a raw `Errno 13` reported as validation", with "no staging file left
behind". The code already has the message: "The filesystem refused to
replace … nothing was written."

Cause: `cli/src/bea_engine/ledger/write.py:1186` (`keep_file_metadata`,
from the 099 fix) copies the ACL to the candidate before `os.replace`;
the replace is refused and the intended error raised (`:1190-1192`); then
`candidate.unlink` in the cleanup (`:386`) hits the copied ACL and its
`PermissionError` masks the first. The 073 test replaces `os.replace` with
a stub, so a real ACL is never exercised.

Fix: when the replace is refused, strip the copied ACL and flags from the
candidate before unlinking, and never let a cleanup error mask the
original. Add a real-ACL regression test on macOS. No dependency change.

Blast radius: every staged writer (`add`, `add transactions`,
`import --apply`, `format -i`).

Dedupe: board search for "deny delete" and "refused to replace" finds only
w1/done/073; the open notes about ACLs or `.bea-*.tmp` (w5/096, 099, 119,
144, 173, 181) are different problems.

Acceptance: both commands exit 3 with the "refused to replace" message and
leave no `.bea-*.tmp`; the no-ACL control is unchanged. Linux was not
checked; only macOS and the checkout were exercised.
