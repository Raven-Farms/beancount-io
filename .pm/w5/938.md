# Exclude calculated prices from quote duplicate and conflict checks

**Major · cli · 30–45m · A1.** A calculated price that inherits another
price directive's source location is correctly marked generated by listing,
but `add price` and native import count it as an authored quote. A forced
correction from 1.20 to 1.30 USD exits successfully without writing, leaving
a 100 GBP holding valued at 120 USD instead of the requested 130 USD.
No product fix implemented.

Real CLI QA, 2026-10-21, HEAD `7790292dd`, checkout `bea 0.3.1`, macOS
26.5.1 arm64, frontend Python 3.13.3, existing managed Python 3.12.10.
Separate subprocesses, closed stdin/no TTY, isolated absolute
`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, no inherited
`BEA_FILE`/`BEA_TOKEN`. The synthetic calculation plugin uses the real native
loader; no mocked CLI result or external service.

Create disposable `/abs/books/qa_cross.py`:

```python
from decimal import Decimal
from beancount.core.amount import Amount
from beancount.core.data import Price

__plugins__ = ("derive",)

def derive(entries, options):
    out = []
    for entry in entries:
        out.append(entry)
        if isinstance(entry, Price) and entry.currency == "EUR":
            out.append(entry._replace(
                meta=entry.meta.copy(),
                currency="GBP",
                amount=Amount(entry.amount.number * Decimal(13) / Decimal(11), "USD"),
            ))
    return out, []
```

Actual: all eight exit 0. Full listing has three prices and correctly marks
the calculated GBP 1.30 as `generated: true`; `--on-disk` returns only EUR 1.10
and GBP 1.20. The forced add nevertheless reports `written: 0`,
`duplicate: true`, citing the **EUR** source line. Every source byte remains
unchanged. Net worth stays 120 USD, and the authored quote stays 1.20.

Expected: the calculated point is not authored duplicate evidence. `--force`
appends the requested GBP 1.30 quote (`written: 1`), the next load values
the holding at 130 USD, and the ledger remains valid. Without force, the
real authored 1.20 must cause the ordinary exit-4 conflict. Removing only
the plugin line in a pristine copy is a working control: force writes one,
check passes and net worth becomes 130 USD.

Native import has the same gap. With the already-enabled Beangulp feature,
create `/abs/books/importer.py`:

```python
import datetime
import json
from decimal import Decimal
from beancount.core.amount import Amount
from beancount.core.data import Price, new_metadata

class Quotes:
    def identify(self, file):
        return str(file).endswith("quote.json")
    def account(self, file):
        return "Assets:Cash"
    def extract(self, file, existing=None):
        value = json.loads(open(file).read())
        return [Price(new_metadata(str(file), 1), datetime.date(2024, 2, 1),
                      "GBP", Amount(Decimal(value["amount"]), "USD"))]

CONFIG = [Quotes()]
```

Cause: `cli/src/bea_engine/ledger/adding.py:_price` calls
`entry_generated(entry, "price")` at :918 without the loaded entries'
`shared_locations` context. The default test sees a real price line/date/type

returns before force/conflict handling. Its reciprocal generated-price
classification at :988 has the same omitted context.
`cli/src/bea_engine/importing.py:_written_quotes` (:1471–1490) independently
omits that context at :1484. Although import's transaction/on-disk filtering
already supplies it, quote guards receive the full loaded sequence at :466
and readmit this generated price. The price declaration comparison in
`reader._declares` already distinguishes EUR from the derived GBP when given
shared context, explaining the correct listing result.
