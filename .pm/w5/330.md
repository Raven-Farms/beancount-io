# A well-formed but nonexistent date (`2027-02-29`, `2026-04-31`) is refused with "Use YYYY-MM-DD format", although it is already in that format

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
When a date option is in the right format but names a day that does not
exist, every frontend date option still tells the user to fix the format.
February 29 in a non-leap year and April 31 are common slips. The bulk
path and `report -t` both name the real problem. No product fix
implemented.

Use any valid ledger, with isolated BEA_CONFIG_DIR/XDG_CACHE_HOME,
BEA_NO_UPDATE_NOTIFIER=1, no inherited BEA_FILE/BEA_TOKEN, closed stdin, no
TTY.

```sh
bea -f /absolute/books/main.bean add transaction X --date 2027-02-29 -p 'Expenses:Food 1 USD' -p Assets:Checking
bea --no-input init ib --currency USD --date 2026-02-30
bea -f /absolute/books/main.bean list transaction --from-date 2027-02-29
```

Actual: each command exits 2 with `Invalid value: Invalid date
'2027-02-29'. Use YYYY-MM-DD format.` (with its own date), and the ledger
is unchanged. Reproduced in three fresh runs.

Controls:

- An `add transactions --from` row with `"date": "2027-02-29"` is refused
  with `date '2027-02-29' must be a calendar date in YYYY-MM-DD form`.
- `report -t 2026-02-30` says `day is out of range for month`.
- A badly shaped date such as `2027-2-28` correctly gets the format
  message.

Expected: a correctly formatted date that is not a real day is reported as
such, for example `Invalid date '2027-02-29': 2027 has no February 29.`
or `… is not a calendar date`. The format message stays for badly shaped
input.

Cause: `parse_date` (`cli/src/cli/utils.py:180-193`) raises the same
`BadParameter` for a regex miss and for a `fromisoformat` range error.

Fix: keep the format message for a regex miss. When a well-shaped string
fails `fromisoformat` with a `ValueError`, raise `Invalid date '{s}': not a
calendar date ({err}).` instead. No dependency change.

Blast radius: every frontend date option that goes through `parse_date` or
`parse_opt_date`, about 30 call sites. This includes `add` (`--date`,
`--pad-date`), `init --date`, and `list --from-date`/`--to-date`.

Dedupe: searched `.pm/**`, including `done/`, for "Use YYYY-MM-DD format"
and "Invalid date '". w1/111 added the format regex, w5/239 covers empty
dates, and w2/024 covers a currency in a date option. None of them covers
a well-shaped date that does not exist.

Acceptance: the three commands exit 2 with a message that the date does
not exist, and without "Use YYYY-MM-DD format". Badly shaped input keeps
the format message. A test covers both cases. Only macOS and the checkout
were exercised.
