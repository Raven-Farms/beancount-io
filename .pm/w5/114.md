# With `BEA_FILE` set, `init`'s "Next:" command checks a different ledger than the one just created

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-11, HEAD `0227141a` (CLI unchanged since `97600b74`),
checkout `bea 0.3.1`, macOS.
`bea init DIR` ends by telling the user to run `cd DIR && bea check` and
to record purchases with `bea add transaction`. When `BEA_FILE` is set,
both of those operate on the ledger `BEA_FILE` names, not the new one, so
the advertised first step reports on — and the suggested add writes to —
somebody else's books. No product fix implemented.

Create disposable `/absolute/main/main.bean`:

```beancount
2024-01-01 open Assets:Checking USD
2024-01-01 open Expenses:Groceries USD
2024-01-05 * "bad"
  Expenses:Nope  1 USD
  Assets:Checking
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1,
`BEA_FILE=/absolute/main/main.bean`, closed stdin, no TTY, cwd
`/absolute`:

```sh
bea init books --currency USD --date 2026-08-01
cd books && bea check
```

Actual: `init` exits 0 with `Created /absolute/books/main.bean with 14
accounts in USD.`, `Next: cd /absolute/books && bea check` and `Record
purchases with bea add transaction …`. The printed `bea check` exits 1
with `/absolute/main/main.bean:3: Invalid reference to unknown account
'Expenses:Nope'`. A worker also ran the suggested `bea add transaction`
(with `--allow-errors`) and saw it report `Added 1 transaction to
/absolute/main/main.bean`, leaving the new ledger untouched; I did not
re-run that step.

Control (worker-observed): without `BEA_FILE`, the same hint exits 0 on the
new ledger.

Expected: w5/055 set the bar that "the advertised next command checks the
file just created". `docs/USAGE.md` documents that `BEA_FILE` outranks
working-directory discovery and does not redirect `init`; the precedence is
right, the hint is wrong for this environment.

Cause: `cli/src/cli/commands/init.py:184-189` chooses the
working-directory form of the hint without checking whether `BEA_FILE` is
set and would override it.

Fix: when `BEA_FILE` is non-empty, print `bea --file <new> check` (and
the same form for the add hint), or add a line saying `BEA_FILE` points
elsewhere. No dependency or API change.

Blast radius: human `init` output only; JSON carries no hint.

Dedupe: board search for `BEA_FILE` with `init` and `Next:` finds
w5/055 (a quoted-tilde hint, done) and w3/340 (`BEA_FILE` versus discovery);
neither covers the hint under `BEA_FILE`.

Acceptance: with `BEA_FILE` set to another ledger, the printed next command
run verbatim exits 0 on the new file; without it the hint is unchanged. A
real-command regression test runs the printed line. Only macOS and the
checkout were exercised.
