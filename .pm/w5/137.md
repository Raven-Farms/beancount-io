# `bea treeify` exits 0 with a scrambled half-tree when any account has a non-ASCII letter

**Minor · cli · 30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
Rows whose account contains an accented or CJK character are left flat in
the middle of the tree, sometimes above their own parent, and the command
exits 0. No product fix implemented.

Create disposable `/absolute/books/bal.txt`:

```text
account               sum
Assets:Bank:Checking  500.00 CNY
Assets:Bank:Épargne    50.00 CNY
Expenses:Food:Café      5.00 CNY
Expenses:Food:Lunch    30.00 CNY
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea treeify bal.txt
```

Actual: exit 0, stdout:

```text
account               sum
|-- Assets
|   `-- Bank
|       `-- Checking  500.00 CNY
Assets:Bank:Épargne    50.00 CNY
Expenses:Food:Café      5.00 CNY
`-- Expenses
    `-- Food
        `-- Lunch      30.00 CNY
```

Control: the same file with `Epargne` and `Cafe` renders a complete tree.
A worker saw the same partial output from real `bea query … GROUP BY
account` output with CJK accounts, no change with `-A`, exit 2 "found no
hierarchical column" when every account is non-ASCII, and a correct tree
with `-r '[^ :]+(:[^ :]+)+'`.

Expected: `docs/USAGE.md` documents `bea query … > balances.txt; bea
treeify < balances.txt` as "the account column drawn as a tree", and
already makes "not a tree" a failure. Accounts `bea check` accepts should
be drawn, or the run should exit nonzero.

Cause: `cli/src/cli/commands/treeify.py:130` forwards with upstream's
default patterns, which accept only `[A-Za-z0-9-_']` in account components.

Fix: when no `-r`/`-F`/`-A` is given, pass a Unicode-aware default pattern
matching Beancount's account grammar; at minimum exit nonzero when
account-shaped rows in the detected column were left unrendered. No
dependency or API change.

Blast radius: stdin, file and `-o` paths for any ledger with accented or
CJK account components.

Dedupe: board search for treeify with non-ASCII, Unicode, CJK and accent
finds w3/338 (no-column exit 0, done) and w5/061 (bad regex); neither
covers partial rendering.

Acceptance: the command draws all four accounts under `Assets` and
`Expenses`; the ASCII control is byte-identical to today. A real-command
regression test covers accented and CJK components. Only macOS and the
checkout were exercised.
