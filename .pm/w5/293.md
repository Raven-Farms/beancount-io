# `bea query --source` still prints a Python traceback for a bad `csv:` parameter, `-m` on a CSV source, `-f beancount` on a column result, and `.describe` with an unclosed quote

**Minor · cli · 30–40m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
Four input mistakes in a `--source` one-shot still exit 1 with a boxed
traceback, about 98 lines on stderr, raised through `bea_engine/main.py`
and `bea_engine/query.py`. [250](./done/250.md) fixed the I/O cases; its
resolution says the non-I/O triggers "still print a traceback, because a
blanket catch-all was left to the neighbouring notes", but no open note
tracks them. The `--file` path refuses or answers the same mistakes. No
product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
2026-01-01 open Assets:Wallet
2026-01-01 open Equity:Opening
2026-01-02 * "Dust"
  Assets:Wallet  0.00000001 BTC
  Equity:Opening
```

and `/absolute/books/t.csv`:

```text
name,amount
alpha,1.5
beta,2
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea query --source "csv:/absolute/books/t.csv?header=true" "SELECT * FROM t"
bea query --source csv:/absolute/books/t.csv -m "SELECT * FROM t"
bea query --source /absolute/books/main.bean -f beancount "SELECT account"
bea query --source /absolute/books/main.bean ".describe 'x"
```

Actual: each command exits 1 with empty stdout. Stderr ends in a boxed
traceback; in order, the last lines are:

- `TypeError: beanquery.sources.csv.Table() got multiple values for keyword argument 'header'`
- `AttributeError: 'NoneType' object has no attribute 'build'`
- `AttributeError: 'str' object has no attribute 'meta'`
- `ValueError: No closing quotation`

These `csv:` parameters crash the same way:

- `?header=false`
- `?encoding=bogus`, ending in `LookupError: unknown encoding: bogus`
- `?foo=bar`, ending in `TypeError: 'foo' is an invalid keyword argument …`
- `?dialect=nope`, ending in `Error: unknown dialect`

Reproduced in a fresh process.

Controls:

- `bea -f main.bean query -f beancount "SELECT account"` exits 2 with
  `--format beancount prints directives, so the query must return entries; …`.
- An invalid regex under `--source` exits 2 with one line.
- `.run 'x` under `--source` exits 2 (w5/237).
- `bea -f main.bean query ".describe 'x"` prints no traceback, but still
  exits 1 with `Error: ValueError: No closing quotation`. That leaks a
  Python class name into a usage error.

Expected: `docs/USAGE.md` says native `--source` one-shots "keep upstream's
rendering but not its exit status", and that BQL which does not parse or
compile exits 2 "with the reason on stderr". 250's expectation was "no
traceback without `--debug`". A malformed source URI parameter or a
mistyped dot command is a usage error: exit 2 with one line.

Cause:

- `source_query` (`cli/src/bea_engine/main.py:616-640`) catches only
  `protocol.EngineError` and `OSError`.
- The `TypeError` and `LookupError` from upstream
  `beanquery/sources/csv.py:108` escape to the helper's exception printer.
  That function passes `header=True` together with the URI's `**params`.
- numberify's `None` display context on a CSV source escapes the same way.
- So does upstream's beancount renderer unpacking a column row.
  `GuardedShell` (`cli/src/bea_engine/query.py:365-419`) lacks the
  `_require_entries` guard that the `--file` shell applies at
  `query.py:1009`.
- `.describe`'s `shlex` `ValueError` is not mapped to a usage error on
  either path.

Fix:

- Map source-attach `TypeError`, `LookupError` and `csv.Error` to a
  one-line usage error (exit 2) that names the `--source` parameter.
- Apply `_require_entries` in the native shell.
- Refuse `-m` with a `csv:` source, or give it a display context.
- Map `shlex` `ValueError` in dot commands to exit 2 with the reason, as
  w5/237 did for `.run`.
- Keep the tracebacks under `--debug`.

No dependency change.

Blast radius: `query --source` one-shots and `source-shell`, which uses the
same dispatch, plus `.describe` on `--file`.

Dedupe: searched the board for `header=`, `invalid keyword`,
`unknown encoding`, `No closing quotation`, `attribute 'build'` and
`.describe`.

- w5/250: its resolution leaves these triggers open.
- w5/237: covers `.run` only.
- w5/249 and w5/259: other inputs.

None of them is open.

Acceptance: each of the four commands and each listed `csv:` parameter
exits 2 with one line and no traceback, and leaves an existing `-o`
intact. `.describe 'x` on `--file` exits 2. A real-command regression test
covers them. Only macOS and the checkout were exercised.
