# `bea engine status` reports a `BEA_ENGINE_PYTHON` override as usable when it loads the engine but has no `bean-check` beside it, while `check` and `example` fail on exactly that (incomplete fix of w5/481)

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `604894f6`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/481 (done).
w5/481's fix probes whether the override can load `bea_engine`. The note
asked for "bean-check present, `bea_engine` importable, the sentinel", and
the same reason `check` gives. Native tools are resolved beside the
interpreter, which status does not check. A Homebrew or system Python with
Beancount installed `--user` puts its scripts elsewhere, which is exactly
this case. No product fix implemented.

`wrap/python`: `#!/bin/sh` / `exec ~/.local/share/bea/engine/0.3.1/bin/python "$@"`
(an interpreter that can load the engine, with no `bean-check` in its
directory). `bad.bean` has an unknown-account error.

```sh
BEA_ENGINE_PYTHON=/abs/wrap/python bea --json engine status
BEA_ENGINE_PYTHON=/abs/wrap/python bea -f /abs/bad.bean check
```

Actual: status exits 0 with `"usable": true` and features present; `check`
exits 1 with `BEA_ENGINE_PYTHON=…/wrap/python names an environment with no
'bean-check' (…/wrap). Correct or unset BEA_ENGINE_PYTHON, or run 'bea engine
status' to see which engine would serve.` `bea example` fails the same way
naming `bean-example`.

Control: `/usr/bin/true`, a Python without Beancount and a venv without it are
reported unusable with the right reason.

Expected: status reports `usable: false` with "no bean-check beside
…/wrap/python" (and the other native tools), the same reason `check` gives.

Cause: `cli/src/cli/commands/engine.py:44` probes only
`launch.engine_load_failure`; natives come from `paths.bin_dir_for(override)`
(`cli/src/cli/engine/launch.py:356-374`).

Fix: for an override, also require `bin_dir_for(python)/bean-check` (and its
siblings) to exist.

Dedupe: w5/481 (done) is the parent.

Acceptance: the status for the wrapper reports unusable with that reason. A
test pins it.
