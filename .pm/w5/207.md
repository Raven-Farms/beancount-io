# `bea format -i DIR` fails with "Too many open files" once the directory holds more files than the descriptor limit

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
In-place formatting takes a lock on every target before it formats the
first one, and each lock is an open descriptor. Under the default macOS soft
limit of 256 a directory of 260 files cannot be formatted at all; the error
names an internal lock path and is followed by one line per file. Nothing is
changed on failure. No product fix implemented.

Create disposable `/absolute/books/` with 260 files `f0000.bean` …
`f0259.bean`, each:

```beancount
2020-01-01 open Assets:Bank USD
2020-01-02 * "t"
  Assets:Bank      1 USD
  Assets:Bank  -1 USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, and a soft descriptor
limit of 256 in the child (`launchctl limit maxfiles` reports 256 here; a
shell with a raised `ulimit -n` hides the problem).

```sh
bea format -i /absolute/books
bea --json format -i /absolute/books
```

Actual: exit 1, tree byte-identical, stdout empty, 26.7 KB of stderr:

```text
Error: Could not finish in-place formatting: [Errno 24] Too many open files: '/absolute/cache/bea/locks/f36a…3505.lock'.
  failed: /absolute/books/f0075.bean: …
  not attempted: /absolute/books/f0000.bean
  … (259 "not attempted" lines)
```

`--json` gives category `validation`, exit 1, and the same 260 lines as
`details` (50 KB).

Control: 250 files under the same limit exit 0 with `250/250 file(s)
formatted.`; the 260 files with the limit raised to 4096 exit 0 with
`260/260 file(s) formatted.` A worker saw `format --check` and every other
command (check, balance, list, query, reports, `add`, `price status`) work
on 5,000 files under the 256 limit, and the same failure at 300 and 5,000
files.

Expected: `docs/USAGE.md` documents "`bea format -i .`" as "rewrite every
.bean/.beancount file under a directory", with no size bound; the number of
files should not be limited by the descriptor limit, and the failure is not
a validation error in the ledger.

Cause: `cli/src/bea_engine/ledger/formatting.py:77-78` enters
`write.lock_file` for every target in one `ExitStack` before the formatting
loop, so the run holds one descriptor per file until the end.

Fix: lock, format and replace one file at a time; or raise `RLIMIT_NOFILE`
toward the hard limit first. Either way, report "N files not attempted" as a
count rather than one line each. No dependency or API change.

Blast radius: `format -i` with many targets only; other writers lock at
most two files.

Dedupe: board search for `Too many open files`, `Errno 24`, `EMFILE`,
`ulimit` and `file descriptor` finds nothing. Nearest is w5/125 (per-file
directory sweep in the same loop).

Acceptance: with a soft limit of 256, `bea format -i` on the 260-file
directory exits 0 and formats all 260; a real-command regression test lowers
`RLIMIT_NOFILE` in the child. Linux (default 1024) should show the same at
about 1,000 files; only macOS and the checkout were exercised.
