# `bea format` refuses a ledger not named `.bean`/`.beancount` ("Expected a .bean or .beancount file, or a directory."), yet formats the same file when it is reached through an include

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `3f2372e1`, checkout `bea 0.3.1`, macOS 26.5.1.
Ledgers named `books.ledger`, `journal.txt` or `main.bc` are common. Every
other command and upstream `bean-format` accept them, and USAGE says a
named file stands for its closure "whatever its suffix". The refusal does
not name the path either. No product fix implemented.

`books.ledger` (a valid ledger with one unaligned posting); `main.bean` =
`include "books.ledger"`.

```sh
bea --file books.ledger check          # exit 0
bea format --check books.ledger
bea --file books.ledger format --check
bea format --check main.bean
```

Actual: both direct forms exit 2 with `Error: Expected a .bean or .beancount
file, or a directory.`; through `main.bean` it exits 1 with `would format:
…/books.ledger`.

Expected: an explicitly named regular file is formatted whatever its suffix;
the suffix filter applies only when walking a directory.

Cause: `cli/src/cli/commands/format.py:446`, a check from the original
command (`ff47e5c6`) with no test pinning it.

Fix: accept any regular file named explicitly (or via `--file`); keep
`.bean`/`.beancount` for directory walks; name the path in any refusal.

Dedupe: no match for the message, `.ledger` or suffix.

Acceptance: both direct forms report `would format: …/books.ledger`. A test
pins it.
