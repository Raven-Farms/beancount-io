# `add price` and `add balance` tell the user to pass `--allow-errors` for a pre-existing syntax error, which that flag can never get past (gap in w5/396)

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `bea189ec`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE says syntax errors are always rejected, and w5/396 kept `--allow-errors`
out of the advice when one is present, but only in the shared validation.
The strict pre-checks of `add price` and `add balance` still advise the
flag. With it, the add fails again with a different message, so the user
goes round in a loop. No product fix implemented.

Any valid ledger with `Assets:Bank:Checking`, plus the line `2024-03-01
bogus line here`.

```sh
bea -f /abs/main.bean add price -c EUR --amount "1.10 USD" --date 2024-03-02
bea -f /abs/main.bean add price -c EUR --amount "1.10 USD" --date 2024-03-02 --allow-errors
bea -f /abs/main.bean add balance -a Assets:Bank:Checking --amount "3487.50 USD" --date 2024-03-02
```

Actual: the first and third exit 1 with `The ledger already has 3 error(s);
nothing was written. Pass --allow-errors to write anyway.` and the `Invalid
token` errors; the second exits 1 with `The change would leave the ledger
invalid; nothing was written.` The ledger is unchanged.

Control: `add transaction` and `add note` on the same ledger name the
syntax error without suggesting the flag.

Expected: with a syntax error present, the message says it must be fixed
first and does not mention `--allow-errors`.

Cause: `_balance` (`cli/src/bea_engine/ledger/adding.py:316-320`) and
`_price` (`:631-635`) use the wording unconditionally; only `write.py`'s
headline (around `:1840`) checks `syntax_errors`.

Fix: apply the same condition in both pre-checks (share the helper).

Dedupe: searched `write anyway`, `already has`. w5/396 and 200 (done).

Acceptance: both adds name the syntax error and omit the flag. A test pins
it.
