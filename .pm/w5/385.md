# `import --date-format ''` is treated as "not given" and saved to import memory as `""`, so the next plain `bea import s.csv` fails with "Remembered --date-format '' does not match"

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
In the engine, an empty `--date-format` falls back to the default, so
the import works. The frontend still saves the empty string as the
remembered format for the file. On the next plain run, the saved `''`
is compared with the detected format and refused with exit 2. From then
on, every repeat of the same import fails until the user re-passes
`--csv` or `--date-format`. This is the w5/239 pattern (an empty value
read as omitted) in the import family, and here it also poisons the
saved settings. No product fix implemented.

Use any USD ledger with `Assets:Cash` and `Expenses:Uncategorized` open,
and `s.csv`:

```text
Date,Payee,Narration,Amount
2026-01-07,Shop,stuff,-3.00
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, and closed stdin.

```sh
bea -f /absolute/books/main.bean import s.csv --csv date=Date,payee=Payee,narration=Narration,amount=Amount --account Assets:Cash --date-format ''
bea -f /absolute/books/main.bean import s.csv
```

Actual:

- The first run exits 0 with a normal preview.
- `$BEA_CONFIG_DIR/importers/csv-….json` now holds `"date_format": ""`.
- The second run exits 2 with `Remembered --date-format '' does not
  match s.csv, whose dates look like %Y-%m-%d. Pass --date-format
  %Y-%m-%d (or --csv) for this file.`

Reproduced twice by the hunter and once by me.

Control: leaving out `--date-format` detects `%Y-%m-%d` and saves it.
`--date-format ' '`, `--delimiter ''` and `--duplicates ''` all exit 2.

Expected: w5/239's rule is that an empty value is refused rather than
read as "option omitted". `docs/USAGE.md` refuses empty `--account`,
`--time` and `--conversion` instead of "silently falling back to the …
default". `--date-format ''` should exit 2 naming the option and save
nothing.

Cause:

- The frontend (`cli/src/cli/commands/import_.py:863`) forwards `''` and
  stores it as `chosen_date_format` (`:545`, `:889`, `:922`).
- The engine (`cli/src/bea_engine/importing.py:189`) treats it as unset:
  `resolved_date_format = date_format or "%Y-%m-%d"`.
- The recall check (`import_.py:802-812`) then refuses the saved `''`.

Fix: refuse an empty or blank `--date-format` with `UsageError` before
anything else runs, and test `is None` in the engine. When reading memory,
treat a saved `""` as unset so existing poisoned files heal. No
dependency change.

Blast radius: `bea import` runs that pass `--date-format ''`, for
example from a template with an unset variable, and every later plain
import of that file.

Dedupe: searched `.pm/**`, including `done/`, for `--date-format ''`,
`date_format": ""` and "Remembered --date-format". Related notes:

- w5/239: its resolution left other option families alone.
- 382: `--flag`/`--booking`.
- 311: repeated import options.
- w3/311: sticky rules.

None covers this.

Acceptance: `--date-format ''` exits 2 and saves nothing. A memory file
that already holds `""` no longer blocks a plain import. A real-command
test covers both.
