# Four `bea doctor` operations exit 245 with no message when the engine crashes on the ledger (regression of w5/done/010)

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
w5/done/010 made a signal-killed engine a documented exit 1 that names the
signal. `doctor missing-open`, `roundtrip`, `linked` and `region` (a
worker also saw `directories`) were moved to a capturing launcher the day
after that fix and lost it: on a ledger that crashes the upstream parser
they exit 245 with empty output. No product fix implemented.

Create disposable `/absolute/books/dz.bean` (the crashing input from 010):

```beancount
option "operating_currency" "EUR"
2026-01-01 open Assets:Cash EUR
2026-01-01 open Expenses:X EUR

2026-02-01 * "dz" ^lk
  Expenses:X   100/0 EUR
  Assets:Cash
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea doctor missing-open dz.bean
bea doctor roundtrip dz.bean
bea doctor linked dz.bean dz.bean:6
bea doctor region dz.bean dz.bean:5:7
```

Actual: all four exit 245; stdout and stderr are empty (`roundtrip` prints
only `INFO    : Read the entries`).

Control: `bea doctor context dz.bean 6` on the same file exits 1 with
`Error: The Beancount engine (bean-doctor) was killed by SIGSEGV and
produced no result.` With `100/2` in place of `100/0`, `doctor
missing-open` exits 0.

Expected: `docs/USAGE.md`: "These five codes are the whole table. If the
engine process dies on a signal … `bea` reports it as exit 1 with a message
naming the signal, rather than passing the shell's `128+N` convention
through as an undocumented status."

Cause: `cli/src/cli/commands/doctor.py:174-179` (`_replayed`) raises
`typer.Exit(completed.returncode)`; for a signal-killed child that is -11,
which the OS reports as 245. These operations use `capture_native` /
`capture_engine` (`doctor.py:275`, `:312`, `:332`, `:351`), which bypass
the signal handling in `_spawn` (`cli/src/cli/engine/launch.py:573-574`).
The existing regression test for 010 does not cover captured operations.

Fix: treat a negative return code in `_replayed` (or inside the capture
helpers) as `_spawn` does, exit 1 naming the signal with the same hint;
keep the Ctrl-C exception; add stub-engine regressions for each operation.
No dependency or API change.

Blast radius: the captured `doctor` operations. `treeify` and `example`
also capture but report a failure line at exit 1 (not reproduced).

Dedupe: board search for `245`, `_replayed`, `capture_native`, SIGSEGV and
"killed by" finds w5/done/010 (the original fix), w5/135 and w5/139 (other
`doctor` items) and w5/208 (SIGTERM to the frontend); none covers this
regression.

Acceptance: each of the four commands exits 1 with a message naming
SIGSEGV; the `context` control and the `100/2` control are unchanged. Only
macOS and the checkout were exercised.
