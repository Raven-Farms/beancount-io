# `doctor linked` / `region` round the balance tree when the scope mixes whole and fractional amounts

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-10, HEAD `97600b74`,
checkout `bea 0.3.1`, macOS. The balance tree under a scoped `doctor` listing
rounds every amount to the precision most postings in scope use. When most are
whole numbers and one has cents, the tree drops the cents and disagrees with
the `Net Income` line printed directly beneath it. This is the remaining half
of w3/352. Owner call: stock `bean-doctor` prints the same tree. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Income:Salary USD
2026-01-01 open Expenses:Food USD
2026-01-01 open Expenses:Rent USD

2026-01-15 * "Acme" "Salary" ^jan
  Assets:Checking  3000 USD
  Income:Salary

2026-01-20 * "Grocer" "Food" ^jan
  Expenses:Food  45.25 USD
  Assets:Checking

2026-02-01 * "Landlord" "Rent" ^jan
  Expenses:Rent  1200 USD
  Assets:Checking
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, closed
stdin, no TTY:

```sh
bea doctor linked /absolute/books/main.bean ^jan
```

Actual: exit 0. The three transactions print with exact amounts, then

```text
|-- Assets
|   `-- Checking          1755 USD
|-- Expenses
|   |-- Food                45 USD
|   `-- Rent              1200 USD
`-- Income
    `-- Salary           -3000 USD

Net Income: (1754.75 USD)
```

A worker saw the same tree from `bea doctor region main.bean 7:17`.

Controls (worker-observed, not re-run by me): `doctor region main.bean 11:13`,
the 45.25 transaction alone, prints `45.25`; the same ledger written with
`3000.00` and `1200.00` prints `1754.75` and `45.25`.

Expected: 3000 − 45.25 − 1200 = 1754.75, so `Checking 1754.75 USD` and
`Food 45.25 USD`. `docs/USAGE.md` says of these listings that "The tree and
`Net Income` now agree in both directions", and w3/352 asked that "balance
trees match the scoped postings (and Net Income)".

Cause: `cli/src/bea_engine/scoped.py:71-89` (`_context_of`) builds a display
context from the scoped entries, but upstream renders the tree with that
context's default `build()`, which picks each currency's most common
precision. Four in-scope USD numbers are whole and two have cents, so the
tree renders at zero decimals.

Fix: hand upstream a context whose default build uses each currency's maximum
in-scope precision, so no scoped amount is rounded. Keep column alignment.
If the owner prefers upstream parity, correct the USAGE sentence instead and
close this. No dependency or API change.

Dedupe: board search for `doctor linked`, `doctor region`, `_context_of` and
most-common precision finds only w3/352 (done), whose test covers an all-cents
scope against whole-number neighbours.

Acceptance: on the fixture the tree prints `1754.75 USD` and `45.25 USD` for
both `linked` and `region`, matching `Net Income`; an all-whole scope still
prints whole numbers. A regression test covers a scope where the fractional
postings are the minority. Only macOS and the checkout were exercised.
