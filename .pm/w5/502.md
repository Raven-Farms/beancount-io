# `report -a '*Food*'` (an invalid regex) is accepted and silently drops `Expenses:FoodTruck`; other invalid patterns match nothing with exit 0, and refusals quote positions in a pattern the user never typed

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-16, HEAD `e03cf71e`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE: "malformed account filters exit **2**". A shell-glob habit (`*Food*`)
is not a valid Python regex, but the filter falls back to two other
matchers. One of them wraps the raw value in `(^|:)…(:|$)`, where `*Food*`
compiles to "component `Foo` followed by `d*`". The report then omits a real
account with exit 0, and the net profit is wrong. No product fix
implemented.

`food.bean`: USD ledger with `Assets:Bank`, `Expenses:Food`,
`Expenses:FoodTruck`, `Equity:Opening-Balances`; an opening of 100 USD, then
10.00 to Food and 7.00 to FoodTruck.

```sh
bea -f /abs/food.bean report income-statement -a '*Food*'
bea -f /abs/food.bean report income-statement -a '\1'
bea -f /abs/food.bean report income-statement -a 'Fo)(od'
```

Actual:

- `*Food*` (and `*Food`): exit 0, only `Food 10.00 USD`, `Net Profit:
  -10.00 USD`;
- `\1`: exit 0, `No accounts match \1.`;
- `Fo)(od`: exit 2, `unbalanced parenthesis at position 7`; the user's
  error is at position 2. `\` says `unbalanced parenthesis at position 10`,
  though the user typed no parenthesis.

Control: `-a '.*Food.*'` shows Food and FoodTruck, `Net Profit: -17.00 USD`.

Expected: a value that is not a valid regex (and not a plain account name)
exits 2 with Python's message for the user's own pattern and position.

Cause: `Match` (`cli/src/fava/core/filters.py:187-192`) swallows `re.error`
and falls back to equality; the predicate (`filters.py:464-465`) ORs that
with `account.has_component(name, value)`, which formats the raw value
unescaped into `(^|:){}(:|$)`. When that wrapper fails, the error and position
reported (`cli/src/bea_engine/report.py:408-413`) are the wrapper's.

Fix: compile the user's value on its own first and refuse on `re.error` with
its position; call `has_component` only for values that are valid account
names (or escape them).

Dedupe: w1/018 (exit code), w5/292 (prefix siblings) and w5/429 (POSIX
classes) are done; none covers invalid patterns being accepted.

Acceptance: the three values exit 2 naming the user's pattern and position;
`.*Food.*` and `Expenses:Food` are unchanged. A test pins them.
