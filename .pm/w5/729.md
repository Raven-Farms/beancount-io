# `add custom --value 'amount:-0.00 USD'` (or `number:-0`) is refused with "would reload as different values", though every metadata path accepts a negative zero

**Trivial · cli · 5m · A1.** Real CLI QA, 2026-10-17, HEAD `9e727c0e7`, checkout `bea 0.3.1`, macOS 26.5.1.
No product fix implemented.

```sh
bea --file /abs/main.bean add custom --date 2026-01-05 -t budget --value 'account:Expenses:Food' --value 'amount:-0.00 USD'
```

Actual: exit 2 with the file unchanged:

```
Error: The custom directive would reload as different values; nothing was written. Rendered: '2026-01-05 custom "budget" Expenses:Food (-0.00) USD'
  requested: account:Expenses:Food, amount:-0.00 USD
  reloads as: account:Expenses:Food, amount:0.00 USD
```

`number:-0`, `number:-0.00` and `amount:-0 USD` fail the same way (hunter's
runs). The message offers no remedy.

Control:
- `amount:0.00 USD` is written.
- `--meta 'adj:-0.00 USD'` writes `0.00 USD`.
- A bulk tagged amount with `"-0.00"` writes `-0.00 USD`.

Expected: write the zero (as `0.00 USD`, matching `--meta`).

Cause: `_CustomValueDecimal` (`cli/src/bea_engine/ledger/writer.py:150`)
renders a negative zero in parentheses. Beancount reads it back as positive
zero, so `_require_custom_roundtrip` (`:536`) sees a different value.

Fix: render a negative zero as zero (`copy_abs()`) before the round-trip
check.

Dedupe: w5/217 and 697 cover other `-0` renderings.

Acceptance: the command writes `0.00 USD`. A test pins it.
