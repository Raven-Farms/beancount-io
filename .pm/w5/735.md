# A refused JSON float's hint quotes `repr(float)`, not the number typed: `1.10` is told to send `'1.1'`, and following that hint writes a transaction 3 cents out of balance at exit 0; long decimals lose digits (incomplete fix of w5/335 and w5/420)

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-17, HEAD `87570e643`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/335 and 420 (done).
USAGE:969-972 says a JSON float "is refused naming the field, the row, and
the string form to send". The frontend parses the JSON into a `float` before
the engine sees it, so the literal the user typed is gone, and the hint
reports Python's shortest repr instead. No product fix implemented.

`main.bean` opens `Assets:Checking USD` and `Expenses:Food USD`. `b1.json`:

```
[{"date":"2026-02-01","narration":"n","postings":[{"account":"Expenses:Food","units":{"number":1.10,"currency":"USD"}},{"account":"Assets:Checking","units":{"number":"-1.13","currency":"USD"}}]}]
```

```sh
bea --file /abs/main.bean add transactions --from b1.json
```

Actual:
- Exit 1: `JSON number 1.1 is not supported in Beancount amounts… Send the
  amount as a decimal string, such as '1.1'.`
- Sending `"1.1"` as told exits 0 and writes `Expenses:Food 1.1 USD` against
  `Assets:Checking -1.13 USD`, 3 cents out. `check` passes because `1.1`
  carries a 0.05 tolerance.
- Sending `"1.10"`, which was typed, exits 1 with `Transaction does not
  balance: (-0.03 USD)`.
- `1.234567890123456789` is told `'1.2345678901234567'`, and
  `12345678901234567890.123456789` is told `'12345678901234567000'` (also
  for a `meta` number). `1E400` is called `inf` (hunter's runs).

Control: `0.1` is told `'0.1'`.

Expected: the hint quotes the literal as typed (`"1.10"`,
`"12345678901234567890.123456789"`, `"1E400"`), so following it never
changes the amount, its precision or the tolerance.

Cause: `json.loads` at `cli/src/cli/commands/add.py:614` has no
`parse_float`. The hints come from `repr(float)` in
`cli/src/bea_engine/amounts.py` (around `:149-158`),
`cli/src/bea_engine/ledger/adding.py` and `cli/src/bea_engine/ledger/write.py`.

Fix: parse with `parse_float` that keeps the source text (for example a
`str` subclass marked as a JSON float), and refuse it quoting that text.

Dedupe: w5/335 (done) fixed the hint's notation, and w5/420 (done) shipped
the lossy `12345678901234567000` hint; w3/558 is the dashboard analogue.

Acceptance: `b1.json` is told `'1.10'`; the long decimal keeps every digit. A
test pins both.
