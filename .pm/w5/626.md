# A padded `--account` filter (`-a " Assets:Cash"`) passes validation and then matches nothing with exit 0, in `list` and `balance` (incomplete fix of w5/473)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `83bba7bb`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/473 (done).
w5/473 made `-c " HOOL"` match by stripping the currency before forwarding.
`--account` has the same split: the blank check tests the stripped value, but
the raw value is forwarded and compared as a substring. Account names cannot
contain spaces, so the padded value never matches, and the empty answer
reads as "nothing there". No product fix implemented.

`l.bean`:

```beancount
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
2026-01-05 * "Shop" "food"
  Expenses:Food  10.00 USD
  Assets:Cash
2026-01-08 balance Assets:Cash -10.00 USD
```

```sh
bea -f /abs/l.bean list balance -a " Assets:Cash"
bea --json -f /abs/l.bean list transaction -a "Assets:Cash "
bea -f /abs/l.bean balance " Assets:Cash"
```

Actual: exit 0 with `No balance assertions found.`; `"data": []`; and `No
accounts match  Assets:Cash.`

Control: `-a Assets:Cash` and `-a assets:cash` match; `--tag " trip"`,
`--link "inv-1 "` and `--flag " !"` exit 2.

Expected: the stripped value is matched (as w5/473 did for `-c`), or a padded
value is refused with exit 2 like tags and flags.

Cause: `refuse_blank_filter` (`cli/src/cli/utils.py:107`) tests
`value.strip()`; `cli/src/cli/commands/list.py` forwards the raw `--account`
(only `--currency` is stripped, `:349-352`); the engine compares the raw
substring (`cli/src/bea_engine/ledger/reader.py:329`, `:358`, `:418`).

Fix: strip `--account` and `balance` terms before forwarding (or in the
engine); check `--search` for the same split.

Dedupe: w5/473 (done, currency only), w3/341 (`add open`).

Acceptance: the three commands match `Assets:Cash`. A test pins them.

Addendum (CLI QA 2026-10-17, HEAD `d6c32f470`): `-a=Food` (short option with `=`) is
read by Click as the value `=Food`. `list transaction -a=Food`, `list open
-a=Assets` and `report income-statement -a=Expenses` (header `account: =Expenses`)
match nothing with exit 0. No account can contain `=`, so the same
can-never-match refusal (whitespace, `=`) would close this and the padded
case.
