# When an `add balance --pad-from` write validates, it skips the same-day conflict and duplicate checks: a second, different assertion is written without `--force`, and an identical one is written twice (incomplete fix of w5/487)

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-16, HEAD `06e9ca0f`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/487 (done).
w5/487's Expected: "the same exit-2 conflict refusal with or without
`--pad-from`". The `--force` help says it records "another assertion when the
date/account already has one", and USAGE says identical re-runs write
nothing. The fix runs the conflict and match checks only when the pad write
fails validation. A pad that makes the pair valid skips them. No product fix
implemented.

`main.bean`: `option "operating_currency" "USD"`, opens for `Assets:Cash USD`
and `Equity:Opening USD`, and `2026-01-25 balance Assets:Cash 7.00 USD` (failing:
the book holds 0).

```sh
bea -f /abs/main.bean add balance --date 2026-01-25 -a Assets:Cash --amount '7 ~ 0.5 USD' --pad-from Equity:Opening
```

Actual: exit 0, `Added 1 pad and 1 balance`; the file now has two 2026-01-25
assertions for `Assets:Cash`, without `--force`. `--amount '7 USD'` (identical to
the existing one) writes the pad and a duplicate assertion (`written: 2,
duplicate: false`).

Control: plain `add balance --amount '7 ~ 0.5 USD' --allow-errors` exits 2 with
`already has a 2026-01-25 balance of 7.00 USD …; refusing 7 ~ 0.5 USD. Pass
--force`.

Expected: a different amount is refused with exit 2 (as without `--pad-from`).
An identical amount writes only the pad that makes the existing assertion
hold (or reports the duplicate).

Cause: in `_balance` (`cli/src/bea_engine/ledger/adding.py`, around `:371`),
`_balance_conflict` and `_balance_match` run only in the `except
protocol.LedgerError` branch.

Fix: run both checks before the pad write.

Dedupe: w3/297 and w5/115 (done) cover the plain and race paths; open w5/513
and 611 are different `--pad-from` issues.

Acceptance: the different amount exits 2; the identical one writes no second
assertion. Tests pin both.
