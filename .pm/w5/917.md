# Skip an imported document on repeat when its attachment path is relative

**Minor · cli · 25–40m · A1.** Real CLI QA, 2026-10-21, checkout
`bea 0.3.1`, HEAD `032af595c` (CLI unchanged from reproduction at
`e80968380`), macOS 26.5.1 arm64, frontend Python 3.13.3, managed engine
Python 3.12 / Beancount 3.2.3. Three unchanged imports write three identical
document references when the importer supplies a relative attachment path.
Supplying its absolute spelling writes once. No product fix implemented.

Create `/abs/case/books/main.bean`:

```beancount
2024-01-01 open Assets:Cash USD
```

Create `/abs/case/books/receipts/statement.txt` with any synthetic text,
`/abs/case/statement.json` containing:

```json
{"filename":"receipts/statement.txt"}
```

and `/abs/case/importers.py`:

```python
import datetime
import json
from pathlib import Path
from beancount.core import data

class Statement:
    name = "relative-document"
    def identify(self, path): return path.endswith(".json")
    def account(self, path): return "Assets:Cash"
    def extract(self, path, existing):
        filename = json.loads(Path(path).read_text())["filename"]
        return [data.Document(data.new_metadata(path, 1),
                              datetime.date(2024, 2, 1), "Assets:Cash",
                              filename, frozenset({"statement"}),
                              frozenset({"jan2024"}))]

CONFIG = [Statement()]
```

With cwd `/abs/case`, isolated absolute `BEA_CONFIG_DIR` and
`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, inherited `BEA_FILE` and
`BEA_TOKEN` removed, closed stdin and no TTY, run three times:

```sh
bea --json --no-input -f /abs/case/books/main.bean import /abs/case/statement.json --config /abs/case/importers.py --apply
```

Actual: every run exits 0, `written: 1`, `duplicates: 0`, row status `new`.
A separate preview before each apply leaves the ledger unchanged but also
reports one new/ready document. The ledger ends with this line three times:

```beancount
2024-02-01 document Assets:Cash "receipts/statement.txt" #statement ^jan2024
```

Fresh `list document` returns three equal date/account/filename/tag/link
records at different source lines. Fresh `check` exits 0; the statement
input, importer and attachment bytes stay unchanged. Human output reproduces
the false `1 ready, 0 exact duplicates` and `Wrote 1 entry` on repeat.

Reproduced twice each with a relative path, a `./` spelling and an absolute
path, writing into the root or an included file: 12 fresh journeys. Relative
and dot-relative paths write `[1,1,1]`; absolute paths write `[1,0,0]`.
The included-file fixture has `include "entries/statements.bean"` in
`books/main.bean`, uses `--into /abs/case/books/entries/statements.bean`,
and supplies `../receipts/statement.txt`. It remains valid but duplicates on
every unchanged repeat too. The importer/input live outside `books/`, so the
case also distinguishes the destination's directory from the importer's cwd
or source-document directory.

Expected: `cli/docs/IMPORTING.md` promises identical nontransaction
directives are skipped. The unchanged, valid document resolves to the same
attachment on every load. Its relative spelling is an ordinary supported
ledger value and should remain usable for portable imports.

Cause: native `beancount.parser.grammar.Builder.document` (installed
`grammar.py:815–820`) resolves a relative document filename to an absolute
path using the file containing the directive. Existing loaded documents
therefore hold absolute names. `cli/src/bea_engine/importing.py:465` indexes
their `_directive_text`; `:649,692–695` compares the importer's text with it.
`_directive_text` (`:1504–1514`) handles NFC and computed balance differences,
but not the filename transformation. `format_entry`
(`ledger/writer.py:317–334`) prints the filename supplied to it. Thus an
existing absolute filename never matches the unchanged relative input.
Same-batch identical relative documents already write once because neither
side has yet passed through the loader's filename resolution.

Fix: compare document filenames in the form they will have after loading
the **chosen destination file**. For a new relative filename, use that
destination's parent, including `--into`; an existing loaded filename is
already absolute. Use the loader's lexical normalization. Preserve the
importer's relative spelling in appended text and the preview, and keep the
remaining directive fields significant. Do not move/copy the attachment or
rewrite existing ledger lines. Coordinate the comparison helper with
[916](./916.md); filename resolution is separate from its metadata and
allowed-currency ordering rules. No dependency or API change is needed.

Controls, twice each: absolute-path reimports skip; identical relative
documents within one batch write once; genuinely different attachment
paths (including the same basename in two directories), accounts, dates or
tags remain new. All resulting ledgers pass fresh checks. Four additional
human journeys reproduce the root and included-file repeat failure.

Dedupe: searched every `.pm` state for document import/reimport/dedup and
