# `--json query -o` to an unwritable destination exits 1 "validation" with a raw errno, while text mode exits 3 or 0

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`),
checkout `bea 0.3.1`, macOS.
The same export to the same unwritable place ends differently depending on
`--json`: text mode reports a permission failure with exit 3, JSON mode
reports a ledger validation failure with exit 1 and a bare
`[Errno 13]` naming an internal staging file. For a read-only existing
file the two modes disagree outright — JSON refuses, text replaces the file
and exits 0. No product fix implemented.

Create disposable `/absolute/books/a.bean` containing
`2026-01-01 open Assets:A`, a directory `/absolute/books/lock` with mode
555, and `/absolute/books/keep.txt` containing `old` with mode 444.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY.

```sh
bea        -f /absolute/books/a.bean query "SELECT account" -o /absolute/books/lock/out.txt
bea --json -f /absolute/books/a.bean query "SELECT account" -o /absolute/books/lock/out.json
bea --json -f /absolute/books/a.bean query "SELECT account" -o /absolute/books/keep.txt
bea        -f /absolute/books/a.bean query "SELECT account" -o /absolute/books/keep.txt
```

Actual, in order: exit 3 with `Cannot stage a copy of out.txt in
/absolute/books/lock: the directory is not writable … Nothing was written.`;
exit 1 with `{"error": {"category": "validation", "message": "[Errno 13]
Permission denied: '/absolute/books/lock/.bea-<random>.tmp'", "exit_code":
1}}`; exit 1 `validation` with `Output file is read-only:
/absolute/books/keep.txt` and the file unchanged; exit 0 with the file's
content replaced (mode still 444).

Control (worker-observed): `--json … -o /absolute/books/ok.json` exits 0
and writes the envelope.

Expected: `docs/USAGE.md` Exit codes gives 3 to "Authentication or
permission failure" and 1 to "Ledger or validation error". One input should
not change exit code or outcome with the output mode: both locked-directory
runs exit 3 with the staged-copy message, and the read-only file is either
refused in both modes (exit 3) or replaced in both.

Cause: under `--json` the frontend writes the envelope itself through
`cli/src/cli/output.py:481` → `atomic_write`. `cli/src/cli/utils.py:221`
opens the staging file with no `PermissionError` handling and `:216`
raises a bare `PermissionError` for a read-only target; both fall to the
generic error mapping. The engine's text path maps the same failures at
`cli/src/bea_engine/ledger/write.py:367-374` and does not test the target's
mode.

Fix: map `PermissionError` from `atomic_write(export=True)` to the
permission error with the path and "nothing was written", and choose one rule
for a read-only existing export, applied by both writers. No dependency or
API change.

Blast radius: every frontend-side export through `atomic_write`; the
callers beyond `--json query -o` were not enumerated.

Dedupe: board search for read-only exports and `query -o` finds w5/090
(`init DIR` and `format -o`), w3/270 (directory or missing parent) and
w2/021, w1/146 (other `--json -o` issues); none covers the JSON-mode
permission path or the mode disagreement.

Acceptance: the two locked-directory commands exit 3 with category
`permission` and no `.bea-` path in the message; the two read-only-file
commands agree on exit code and on whether the file changes. Real-command
regression tests cover both modes. Only macOS and the checkout were
exercised.
