# Turkish `İ`/`ı` are not folded by `list event|custom --type` or by the CSV column "Did you mean" hint: `-t ikamet` finds nothing for `event "İkamet"`

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `5d08dc41`, checkout `bea 0.3.1`, macOS 26.5.1. Gap in w1/132.
USAGE says `--type` is case-insensitive, and that `--search`, `--account` and
`balance` fold Turkish `İ`/`ı`; w1/132 required the same term to match
everywhere. `--type` (added later, w3/350) and the CSV header lookalike use a
plain `casefold()`, under which `İ` becomes `i̇` (with a combining dot). No product fix implemented.

`main.bean`:

```beancount
2026-01-01 open Expenses:İstanbul
2026-01-09 event "İkamet" "x"
2026-01-09 custom "İzin" "x"
```

```sh
bea --file /abs/main.bean --json list event -t ikamet
bea --file /abs/main.bean --json list custom -t izin
bea --file /abs/main.bean import tr.csv --csv 'date=işlem tarihi,narration=Açıklama,amount=Tutar' --account Expenses:İstanbul
```

(`tr.csv` header: `İşlem Tarihi,Açıklama,Tutar`.)

Actual: both lists return `"data": []` (`-t İKAMET` matches). The import exits
2 with `…'işlem tarihi' for date, which tr.csv lacks.` and no hint.

Control: `list note -a istanbul` matches `Expenses:İstanbul`; `amount=TUTAR`
gets `Did you mean 'Tutar'?`.

Expected: `-t ikamet` lists the event, and the import hint offers `İşlem
Tarihi`.

Cause: `cli/src/bea_engine/ledger/reader.py:530`, `:537`, `:624`, `:631` and
`_lookalike_header` (`cli/src/bea_engine/csv_mapper.py:951`) use `casefold()`
instead of `text.fold_account`.

Fix: use `fold_account` (or the shared fold) in both.

Dedupe: w1/132 (done) predates `--type`.

Acceptance: the three commands match or hint as above. A test pins them.
