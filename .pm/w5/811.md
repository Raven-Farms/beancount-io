# A stored credential whose token is empty, contains whitespace or is non-ASCII is reported as "Not logged in" or "Fix the environment value", and `cloud logout` exits 3 and leaves the file; a `BEA_CONFIG_DIR` symlink loop is blamed on the credential (incomplete fix of w5/297 and w5/589)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `46a722c5c`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/297 and 589 (done).
USAGE:1871 says a credential file that exists but cannot be used "is never
read as 'not logged in': cloud commands exit 3 naming the file and the
reason, and `cloud logout` deletes it and exits 1". No product fix
implemented.

1. **Bad token in the file.** With `credentials.json` =
   `{"token":"qa fake","expireAt":"2099-01-01T00:00:00+00:00"}` and `BEA_TOKEN`
   unset:
   - `bea cloud status` and `bea cloud logout` both exit 3 with `Invalid BEA_TOKEN
     or stored credential (contains whitespace, control or non-ASCII
     characters). Fix the environment value or run 'bea cloud login'.`
   - With `"token": ""`, both exit 3 with `Not logged in. Run 'bea cloud login',
     or set BEA_TOKEN.`
   - The file is left on disk in every case, and no request is made. Tab and
     non-ASCII tokens behave the same (hunter's runs).
2. **Config directory loop (trivial).** With `BEA_CONFIG_DIR` a self-referential
   symlink, `cloud status` says `The stored credential …/cfgloop/credentials.json
   is unusable: it cannot be read (OSError).`. Logout says it could not remove
   the file (`Too many levels of symbolic links`). A file, FIFO or `/dev/null`
   there gets "The bea configuration directory … is not a directory".

Control: `{"token": 5, …}` and `{not json` get the unusable-file message naming
the file, and logout deletes them (exit 1).

Expected: the documented unusable-credential path, naming the file and the
reason ("its token is empty" / "contains whitespace…"). For (2), the
configuration-directory message.

Cause: `load_credentials` (`cli/src/cli/auth/credentials.py:129`) calls
`_validate_token` (`:25`), which raises a plain `AuthError`. Logout catches only
`UnusableCredentials` (`cli/src/cli/commands/cloud/app.py:79`). `_read_stored`
(`:91`) maps only `NotADirectoryError` to the directory message.

Fix: raise `UnusableCredentials` for an invalid stored token, and map ELOOP
(and EACCES on a parent) to the directory message.

Dedupe: w5/297 and 589 (done) are the parents; w5/703 (open) covers the
`BEA_TOKEN` wording.

Acceptance: case 1 names the file and logout deletes it (exit 1); case 2
names `BEA_CONFIG_DIR`.
