# A closed pipe on stderr (`2>&1 | head -1`) exits 120, outside the documented table, and turns a usage exit 2 into 1

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-16, HEAD `d16aea3e`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE (exit codes) says the five codes are the whole table and that a closed
downstream pipe "still exits 141, … without a message". Agents commonly run
`cmd 2>&1 | head`. When the broken pipe is stderr's, bea redirects only fd 1,
so CPython's final flush of the unwritten stderr line fails and replaces the
status with 120. No product fix implemented.

`m.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food
2026-01-02 * "lunch"
  Expenses:Food 2.50 USD
  Assets:Cash -5.00 USD
```

bash, isolated config/cache, closed stdin:

```sh
bea -f m.bean list transaction --allow-errors 2>&1 >/dev/null | true; echo ${PIPESTATUS[0]}
bea -f m.bean list transaction --limit 0 2>&1 | true; echo ${PIPESTATUS[0]}
```

Actual: the first exits **120** (0 with `2>/dev/null`); the second, a usage
error that exits 2 with stderr open, exits **1**. `bea -f
txns/jan.bean check 2>&1 | head -1` on an included leaf exits 120 every time,
where a root ledger's error run exits 141.

Expected: 141 for the broken pipe, and a usage error keeps exit 2 even when
its message cannot be written.

Cause: `_exit_on_broken_pipe` (`cli/src/cli/main.py:99-115`) points only fd 1
at `/dev/null`; when the `BrokenPipeError` came from a stderr write,
`sys.stderr` still holds the unwritten text and the interpreter's shutdown
flush fails (exit 120). The leaf case writes the w5/348 root hint
(`cli/src/cli/commands/check.py:124-127`) after native bean-check already hit
the closed pipe. The 2→1 path is not traced.

Fix: also point fd 2 at `/dev/null` (and drop `sys.stderr`'s buffer) on a
broken pipe; preserve the intended exit code when only the message failed.

Dedupe: w3/378, w5/122, 160 and 407 (done) cover stdout; w5/308 covers a
closed fd 2 (`2>&-`), not a broken pipe.

Acceptance: the commands above exit 141 and 2 respectively. A test with a
closed-reader pipe on stderr pins it (do not wrap the child in a `perl
alarm`, which itself disturbs fd 2).
