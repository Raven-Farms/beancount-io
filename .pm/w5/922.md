# Keep CSV preamble skipping and delimiter detection on the same records

**Minor · cli · 35–50m · A1/A2.** `skip=N` skips logical CSV records during
extraction but physical lines during delimiter detection. A valid quoted
multiline preamble therefore makes detection choose a separator from inside
the preamble. Forcing the right separator imports correctly, but the saved
header fingerprint uses detection again and makes the flag-free repeat fail.
No product fix implemented.

Real CLI QA, 2026-10-21, HEAD `3504fd3cf` (CLI unchanged from
`1ae0f8791`), checkout `bea 0.3.1`, macOS 26.5.1 arm64, frontend Python
3.13.3, existing managed Python 3.12 engine. Fresh subprocesses, closed
stdin/no TTY, isolated absolute `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`,
`BEA_NO_UPDATE_NOTIFIER=1`, no inherited `BEA_FILE`/`BEA_TOKEN`.


Create `bank.csv` exactly as this semicolon-separated CSV. Its three-line

```csv
"Statement for synthetic account

Date;Description;Amount;Reference
2024-02-01;Coffee;-4.50;qa-1
```

From `/abs/books`, with the isolated child environment above:

```sh
bea --json --no-input -f /abs/books/main.bean import /abs/books/bank.csv --csv date=Date,narration=Description,amount=Amount,id=Reference,skip=1 --account Assets:Cash --default-account Expenses:Food
bea --json --no-input -f /abs/books/main.bean import /abs/books/bank.csv --csv date=Date,narration=Description,amount=Amount,id=Reference,skip=1 --account Assets:Cash --default-account Expenses:Food --delimiter ';' --apply
bea --json --no-input -f /abs/books/main.bean import /abs/books/bank.csv --account Assets:Cash --apply
bea --json --no-input -f /abs/books/main.bean import /abs/books/bank.csv --csv date=Date,narration=Description,amount=Amount,id=Reference,skip=1 --account Assets:Cash --default-account Expenses:Food --delimiter ';' --apply
bea --json -f /abs/books/main.bean query "SELECT sum(number) WHERE account='Assets:Cash'"
```

Actual: first exits **2** with stdout empty and says the real header was read
as one column using comma, then suggests `--delimiter ';'` **or omitting the
delimiter**. No delimiter was supplied. The second command exits 0 and writes
both rows correctly. The third exits **2**, preserving the ledger, with a
note that the remembered `';'` does not read this file and was replaced by
detection. The file has not changed. The fourth, retyping the correct settings,
exits 0 with two duplicates and zero writes. BQL returns **−10.75 USD**;
fresh `check` passes. Human output has the same refusal and misleading omission
advice. Preview/refused/duplicate calls preserve ledger bytes and the CSV stays
unchanged.

Expected: skip one CSV record, detect the actual header's semicolon, and read
two payments. A successful explicitly delimited import must also remember the
header it actually read, so an unchanged flag-free repeat skips both payments.
IMPORTING describes `skip=N` as leading **records**, automatic separator
detection, and remembered mappings; Python's CSV reader already reads the
quoted preamble correctly when given the right separator.

Controls and scope:

- Sixteen fresh journeys: two repetitions × comma/semicolon/tab/pipe ×
  single-line/multiline preamble. All eight single-line cases detect/import
  correctly; all eight multiline cases fail only under detection. Forcing the
  real separator previews two ready rows, applies two, repeats with two exact
  duplicates, gives Cash −10.75 USD and passes check. File bytes are preserved
  on preview/repeat; these repetitions keep the explicit separator.
- Eight additional journeys cover explicit versus inferred mappings and
  `skip=1`/`skip=3`, twice each. Human detection refuses, forced apply succeeds,
  and flag-free repeat fails on the unchanged file. Adding one new Tea payment
  for −1.25 also fails flag-free; explicitly repeating the correct settings
  writes only that row, skips the old two and gives Cash −12.00 USD.

Cause: both `cli/src/cli/csv_mapper.py:637–665` and its engine twin
`cli/src/bea_engine/csv_mapper.py:982–1010` implement `detect_delimiter` by
calling `next(stream)` N times, then sampling physical lines. In contrast,
`open_records` (:753 / :1153 onward) skips via `next(csv.reader)` N times.
Detection starts on the address line inside the quoted record and mistakes
its commas for the header's delimiter. Frontend discovery, date inference,
explicit mapping setup and engine extraction call these helpers.

The remembered-header path also ignores the chosen delimiter:
`cli/src/cli/commands/import_.py:1389` calls `read_header` with encoding/skip
but no delimiter. It stores the falsely detected one-column header beside the
correct chosen `';'`. Recall (:562 onward) redetects the same wrong fingerprint;
`_reads_header` (:647–655) then correctly reads four cells under `';'`, sees
that they differ from the bad saved fingerprint, and wrongly discards the
working separator (:1130 onward). This is why forcing it once is insufficient.

Fix: make separator sampling honor complete quoted CSV records and the same
skip count as extraction; keep the frontend/engine copies consistent. Persist
and validate the header parsed with the effective chosen settings rather than
redetecting a different header. Preserve explicit-override precedence,
revalidation for genuinely changed separators, ordinary preamble/`sep=` cases,
malformed-quote diagnostics and physical error line numbers. Do not reinterpret
`skip` as a different number of lines in different phases.

(`212f68a14`) introduced `skip`, but its fixtures skip single-line records.
