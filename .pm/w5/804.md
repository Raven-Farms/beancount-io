# When bea defaults a posting's currency to the operating currency, the resulting refusal gives FX advice for an exchange the user never made, and never says the currency was defaulted

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `0f2118d8e`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE documents the default: a bare number takes the ledger's sole operating
currency. No product fix implemented.

The ledger has `option "operating_currency" "USD"` and opens `Assets:Checking
USD`, `Assets:Euro EUR` and `Expenses:Food`.

```sh
bea --file /abs/fx.bean add transaction "Lunch in Paris" --date 2026-02-01 -p 'Expenses:Food 10' -p 'Assets:Euro -10 EUR'
```

Actual: exit 1 with `Transaction does not balance: (10 USD, -10 EUR)` and
`For a currency exchange, use a price annotation with the actual exchange
rate: for example, '100 EUR @ 1.08 USD'…`. With `-p 'Assets:Euro'` (no amount),
it says `Invalid currency USD for account 'Assets:Euro'` and advises `price
the USD leg at the rate paid: 'Expenses:Food 10 USD @ RATE EUR'`. The user
never typed USD (hunter's run).

Control: `-p 'Expenses:Food 10 EUR' -p 'Assets:Euro'` writes.

Expected: say that `Expenses:Food 10` was read as `10 USD` (the operating
currency), and suggest `10 EUR` rather than a price.

Cause: the default is applied silently in `cli/src/bea_engine/ledger/adding.py`
(around `:877-897`). The balance and interpolation hints in
`cli/src/bea_engine/ledger/write.py` do not know a currency was defaulted.

Fix: carry the defaulted postings into the validation hints, and name them
when they are involved.

Dedupe: w3/303 and w5/488 (done) cover other FX-hint cases.

Acceptance: both commands name the defaulted `10 USD` and suggest `10 EUR`.
