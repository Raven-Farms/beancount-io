# `check_commodity` refusals on `add` show `<check_commodity>:0: Missing Commodity directive for 'EUR' …` with no `Proposed append` label and no `bea add commodity` remedy, which CSV import already gives

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
A write that uses an undeclared commodity under
`beancount.plugins.check_commodity` is refused with the plugin's raw line
and a pseudo-location. The error comes from the proposed entry, but it
is not labelled as such, and no fix is offered. No product fix
implemented.

Use a USD ledger with `plugin "beancount.plugins.check_commodity"` and
`2026-01-01 commodity USD`, with the environment from [396](./396.md).

```sh
bea -f /absolute/books/main.bean add price --date 2026-01-05 -c EUR --amount '1.1 USD'
bea -f /absolute/books/main.bean add transaction X --date 2026-01-05 -p 'Expenses:Food 5 EUR' -p 'Assets:Cash -5 EUR'
```

Actual: exit 1 with `The change would leave the ledger invalid …` and
`<check_commodity>:0: Missing Commodity directive for 'EUR' in 'Price
Directive Context'` (or `… in 'Assets:Cash'`). With `--allow-errors` it
is correctly classified as new, but the line is equally bare.
Reproduced twice by the hunter and once by me (price).

Control: a CSV import with an undeclared currency gets `… bea add
commodity --date YYYY-MM-DD --currency EUR`.

Expected: label the error `Proposed append (not written)`, drop or
explain `<check_commodity>:0`, and add the `bea add commodity` remedy.

Cause: the write error loop in `cli/src/bea_engine/ledger/write.py`
(about `:1225-1300`) has no case for `Missing Commodity directive for`.
The remedy exists only in `cli/src/bea_engine/csv_mapper.py:925`.

Fix: handle that message in the write loop, with the label and the
remedy. No dependency change.

Dedupe: w5/153 (done) covers the `--allow-errors` classification of these
errors only. No note covers the message or remedy.

Acceptance: both commands show the label and the `bea add commodity
--currency EUR` remedy, with no `<check_commodity>:0`. A test pins the
price case.
