# `list --tag`/`--link` repeated are ANDed (undocumented), and the refusal for `--tag trip,work` advises "Repeat --tag for several tags", which then finds nothing with exit 0; tag matching is also case-sensitive, unlike every other list filter

**Minor · cli docs · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `d6c32f470`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE (around :898-900) spells out AND for repeated `--search` (fixed in w3/334
for this exact agent trap), but says only "repeatable" for `--tag` and
`--link`. No product fix implemented.

The ledger has one `#trip` and one `#work` transaction.

```sh
bea -f /abs/main.bean list transaction --tag trip,work
bea -f /abs/main.bean list transaction --tag trip --tag work
```

Actual: the first exits 2 with `… Repeat --tag for several tags.`. Following
that, the second exits 0 with `No transactions found.` (JSON `"data": []`).
`--link a,b` gives the same advice.

Expected: help and USAGE say repeated `--tag`/`--link` require every value
(and that tags match case-sensitively), and the refusal says the same.
Alternatively, switch to OR.

Cause: `issubset` in `cli/src/bea_engine/ledger/reader.py:363-365`; the advice
and help in `cli/src/cli/commands/list.py`.

Fix: document AND and case-sensitivity, and reword the advice.

Dedupe: w3/334 (done) covers `--search`; w3/333, w5/340 (done) and 722 (open)
cover other tag messages.

Acceptance: help, USAGE and the refusal describe AND.
