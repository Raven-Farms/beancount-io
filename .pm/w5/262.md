# A comment after the closing `;` makes a one-statement query fail with "One BQL statement per invocation; got 2"

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
`SELECT …; /* note */` is one statement to Beanquery and to stock
`bean-query`, but `bea`'s statement counter treats the trailing comment as
a second statement and refuses with exit 2. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Equity:Opening USD
2026-01-01 open Expenses:Food USD
2026-01-02 * "Opening"
  Assets:Cash        1000.00 USD
  Equity:Opening    -1000.00 USD
2026-02-10 * "Lunch"
  Expenses:Food        10.00 USD
  Assets:Cash         -10.00 USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean query "SELECT account FROM accounts ORDER BY account LIMIT 2; /* c */"
```

Actual: exit 2.

```text
Error: One BQL statement per invocation; got 2. Run each query in its own `bea query` call.
```

Control: with the comment before the semicolon, `… LIMIT 2 /* c */;`, the
query prints its two rows and exits 0. A worker saw the same refusal on
stdin and with `--source`, stock `bean-query` accept the text, and a
genuine `SELECT …; SELECT …` still refused.

Expected: the query runs; the guard's own stated intent (w4/done/182) is
that comment content must not affect the statement count.

Cause: `cli/src/cli/commands/query.py:92-137` (`_split_statements`)
appends comment text to the current fragment, so a comment-only tail
survives the empty-fragment filter. The engine twin
(`_refuse_statement_tail` in `cli/src/bea_engine/query.py`) tests raw
rather than masked text and would refuse the same input.

Fix: a fragment that is only whitespace and comments is not a statement,
in both guards. No dependency or API change.

Blast radius: one-shot queries by argument, stdin and `--source`; stored
`query` directives and `.run` through the engine twin.

Dedupe: board search for "trailing comment" and "One BQL statement" finds
w4/done/182 and w3/done/402 (punctuation inside a comment), w1/done/042
(dropped tail statements) and w5/236 (dot commands); none covers a comment
after the terminator.

Acceptance: the command prints its two rows and exits 0; two real
statements are still refused. Only macOS and the checkout were exercised.
