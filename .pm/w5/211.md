# A bulk row whose lot label contains ` @ ` and that has a `price_total` is refused, aborts the batch, and breaks the JSON round trip

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A lot label such as `"AAPL @ Schwab"` combined with a total price makes
`add transactions` refuse the whole batch with exit 2 and a message about
line breaks. `--partial` does not save the valid rows. The same posting
through `add transaction --posting` is written correctly, so its JSON
answer cannot be fed back as the docs promise. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Broker
2024-01-01 open Assets:Cash USD
```

`/absolute/books/rows.json`:

```json
[{"date":"2024-06-01","narration":"plain","postings":[{"account":"Assets:Broker","amount":"1 ABC {10 USD}"},{"account":"Assets:Cash"}]},
 {"date":"2024-06-02","narration":"labelled, total price","postings":[
   {"account":"Assets:Broker","units":{"number":"10","currency":"ABC"},
    "cost":{"number":"10","currency":"USD","label":"AAPL @ Schwab"},
    "price_total":{"number":"121","currency":"USD"}},
   {"account":"Assets:Cash"}]}]
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean add transactions --from rows.json
bea --json -f main.bean add transactions --from rows.json --partial
```

Actual: both exit 2, ledger byte-identical, row 1 not written even with
`--partial`:

```text
Error: Directive 2 of 2 would be written as 0 directive(s); a field holds a line break or a value that is not one token. Nothing was written.
```

Control: the same file with the label `"AAPL at Schwab"` exits 0 and writes
`Assets:Broker  10 ABC {10 USD, "AAPL at Schwab"} @@ 121 USD`. The flag
form `bea -f main.bean add transaction single --date 2024-06-02 -p
'Assets:Broker 10 ABC {10 USD, "AAPL @ Schwab"} @@ 121 USD' -p Assets:Cash`
exits 0 and writes the ` @ ` label correctly. A worker saw the row accepted
with `price` instead of `price_total`, and the flag form's `data.directive`
refused when piped back into `add transactions`.

Expected: `docs/USAGE.md`: "Round-trip guarantee: the `units`, `cost`,
`price`, and `price_total` shapes in `add transaction --json` output are
valid `add transactions` input, so a returned posting pipes back into
`--from -` unedited." The row is valid and should be written as the flag
form writes it.

Cause: `cli/src/bea_engine/ledger/writer.py:124` does
`position_str.rpartition(" @ ")` to strip a unit price before appending
`@@ total`. On the bulk path the price is already absent
(`writer.py:315-317` stashes the total and sets `price = None`), so the
split lands inside the quoted label and produces `{10 USD, "AAPL @@ 121
USD`, an unterminated string that the read-back guard counts as zero
directives.

Fix: strip a unit-price suffix only when the posting has a price, and only
the trailing one; otherwise append ` @@ total` to the untouched text. The
pre-render check should also report such a row per row (exit 1, `Row N`,
`--partial` honoured). No dependency or API change.

Blast radius: bulk structured and bulk shorthand postings with
`price_total`/`@@`; the outcome is always a refusal, never altered text. A
worker noted a further trigger of the same batch-abort guard: a bulk `cost`
with `number_total` and no `currency`.

Dedupe: board search for `rpartition`, `@ Schwab` and "would be written
as" finds w5/129 and w5/184 (same guard, but invalid input: bad metadata
key, malformed account); w5/done/059, w5/done/060, w1/done/011 and
w1/done/093 cover other `@@` and label cases. None covers a valid label
mangled by the renderer.

Acceptance: the batch exits 0 and writes both rows, row 2 as `10 ABC {10
USD, "AAPL @ Schwab"} @@ 121 USD`; the flag form's JSON answer round-trips
through `add transactions --from -`. Only macOS and the checkout were
exercised.
