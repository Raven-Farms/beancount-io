# `bea query PRINT` exports of a valid ledger with renamed roots or a tolerance option fail `bea check`; USAGE says the export passes it

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-16, HEAD `8195088f`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE says the Beancount export "of a valid ledger passes `bea check`". The
export prints result directives only. Options are not entries, so any
option that decides validity is dropped. This affects `name_*` root renames,
used by non-English ledgers that rename `Assets` to `Activos` or `Aktiva`,
and tolerance options. No product fix implemented.

Disposable `main.bean`:

```beancount
option "name_assets" "Activos"
option "name_equity" "Patrimonio"
option "operating_currency" "EUR"
2026-01-01 open Activos:Banco EUR
2026-01-01 open Patrimonio:Apertura EUR
2026-01-02 * "Apertura"
  Activos:Banco  100.00 EUR
  Patrimonio:Apertura
```

Isolated config/cache, closed stdin.

```sh
bea -f /abs/main.bean check                # exit 0
bea -f /abs/main.bean query -o export.bean PRINT   # exit 0
bea -f /abs/export.bean check
```

Actual: the last exits 1 with `export.bean:1: Invalid account name:
Activos:Banco` and three more like it. A ledger that balances only through
`option "inferred_tolerance_default" "USD:0.05"` re-checks as `Transaction
does not balance: (0.02 USD)`.

Control: a ledger with default root names exports and re-checks cleanly.

Expected: the export carries the validity-affecting options at the top
(`name_*`, `inferred_tolerance_*`, `tolerance_multiplier`, `booking_method`,
`operating_currency`), so it re-checks. Alternatively, USAGE states the
limit and the export notes which options were left out.

Cause: `_render_beancount` (`cli/src/bea_engine/query.py:1263`) writes the
result rows only; the loaded `options_map` is not consulted.

Fix: emit `option` lines for the non-default validity options from the
options map before the entries, for `-f beancount` and `-o x.bean`.

Blast radius: `query -f beancount`, `-o *.bean`, the shell's `.format
beancount`.

Dedupe: w5/085's control mentions an export reloading "once its option lines
are restored", so this was seen but never filed against USAGE's promise.
w5/462 and 463 are other renamed-root issues, both done.

Acceptance: both fixtures export and re-check with exit 0. A test pins it.
