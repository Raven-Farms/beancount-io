# With `--file` on an included leaf, the unknown-account error tells the user to `bea add open` accounts the root already opens, and following it writes a duplicate `open` (exit 0) that breaks the whole ledger

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
A write aimed at an included file is validated against that file alone.
Every account the root opens therefore looks unknown, and each one gets
"To create it, use bea add open …". The same error also prints the
correct root `--into` recipe, so the two remedies contradict each other.

If the user takes the first remedy and runs it against the same leaf,
`add open` succeeds with exit 0. The root then fails `check` with
`Duplicate open directive`. The leaf write validated only the leaf, so
nothing caught the break. No product fix implemented.

Create disposable `/absolute/my books/main.bean` (the space is
deliberate):

```beancount
option "operating_currency" "USD"
include "sub dir/extra.bean"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
2026-01-01 open Equity:Opening
```

and `/absolute/my books/sub dir/extra.bean`:

```beancount
2026-01-01 open Expenses:Rent USD
2026-01-03 close Expenses:Rent
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, and an unrelated cwd.

```sh
bea -f '/absolute/my books/sub dir/extra.bean' add transaction X --date 2026-01-02 -p 'Expenses:Food 5 USD' -p Assets:Cash
bea -f '/absolute/my books/sub dir/extra.bean' add open --account Assets:Cash --date 2026-01-01
bea -f '/absolute/my books/main.bean' check
```

Actual:

- The first command exits 1. For both `Expenses:Food` and `Assets:Cash`
  it prints `Invalid reference to unknown account '…' … To create it, use
  bea add open --account … --date YYYY-MM-DD.`
- After each of those it prints `extra.bean is included by …/main.bean;
  … Run against the root and pick the destination with --into: bea
  --file '…/main.bean' <command> --into 'sub dir/extra.bean'.`
- The second command exits 0 with `Added 1 open to …/sub dir/extra.bean.`
  and no warning.
- `check` on the root then exits 1 with `extra.bean:4: Duplicate open
  directive for Assets:Cash`.

Reproduced by the hunter with `Assets:Cash` and, on a fresh copy, with
`Expenses:Food`, and again by me.

Control: the same transaction against the root succeeds. The `--into`
recipe, pasted from an unrelated cwd, writes correctly.

Expected: `docs/USAGE.md` says "For split ledgers, keep `--file` pointed
at the root and choose the included destination with `--into`." When the
target is an included leaf:

- Accounts the root opens should get only the root `--into` recipe.
- "To create it" should appear only for an account the root also lacks.
- A leaf write that would make the root invalid, such as a duplicate
  open, should at least warn that the root was not checked. Better, it
  should be validated against the root that includes the leaf.

Cause:

- The unknown-account remedy (`cli/src/bea_engine/ledger/write.py:1225-1245`)
  is built from the leaf-only load.
- `root_ledger_hints` (`write.py:1007-1017`) is appended separately, and
  nothing compares the account against the including root's opens.
- A successful leaf write validates only the leaf.

Fix: when `including_root(file)` is found, load the root's account set
once. Drop the `add open` remedy for accounts the root opens and keep the
`--into` recipe. For a leaf write that succeeds, validate the including
root as well (or warn that it was not validated). See 346: one root-validation change closes both notes. No dependency
change.

Blast radius: every `add` subcommand and bulk add run with `--file` on an
included file of a split ledger. Users and agents often aim `--file` at
the file they mean to append to.

Dedupe: searched `.pm/**`, including `done/`, for "To create it",
`root_ledger_hints`, "included by" and "Duplicate open". Related notes
cover other cases:

- w3/438: the `--into` hint repeating itself.
- w5/154 and w5/009: other changes to "To create it".
- w5/303: import's remedy dropping `--file`.

None covers a remedy that names accounts the root opens, or a leaf write
that leaves the root invalid.

Acceptance: on the fixture, the first command prints only the root
`--into` recipe for `Assets:Cash` and `Expenses:Food`. The leaf `add open
--account Assets:Cash` is refused or warned about, and the root still
passes `check`. A never-opened account still gets the `add open` remedy.
A real-command regression test covers both. Only macOS and the checkout
were exercised.
