# importer-author's `identify()` template opens files as UTF-8 without a guard, so any Latin-1 export meant for another importer crashes the whole runner; `bea import --config` then names neither the importer nor the phase

**Minor · skills + cli · 10–15m · A1.** Real CLI QA, 2026-10-17, HEAD `0a4036ed5`, checkout `bea 0.3.1`, macOS 26.5.1.
No product fix implemented.

`skills/.claude/skills/beancount-importer-author/references/beangulp-api.md:34-37`
gives `with open(filepath) as f: return f.readline().strip() == …`, though
`beangulp-api.md:128` warns that Latin-1 and BOM files are routine.

A runner with the template's "chase" importer and a Latin-1 "giro" importer
(`giro.csv`: `Buchungstag;Verwendungszweck;Betrag` / `05.05.2026;M\xdcLLER
B\xc4CKEREI;-4,80`):

- `bea --file /abs/main.bean ingest identify --config import.py giro.csv`
  exits 1 with `giro.csv ERROR` / `UnicodeDecodeError: 'utf-8' codec can't
  decode byte 0xdc in position 48`.
- `bea --file /abs/main.bean --no-input import giro.csv --config config.py`
  exits 1 with `Importer failed (UnicodeDecodeError): 'utf-8' codec can't
  decode byte 0xdc…`. Nothing says the *chase* importer's `identify()` raised.

Control: without the template importer, the runner exits 0 and giro claims
the file.

Also (trivial): `eval3_importer.py` and its golden output carry no
`import-id`, though `SKILL.md:60` requires one on every transaction, and the
repair rules say to keep old golden files passing (hunter's read).

Expected: the template's `identify()` catches `(OSError, UnicodeError)` and
reads with the importer's encoding, as `eval3_importer.py` does. bea's message
names the importer and the phase (`identify`).

Cause: the template text, and `cli/src/bea_engine/importing.py` (around
`:311-313`), which wraps any importer exception without naming the importer
or phase.

Fix: correct the template, and include the importer name and phase in
`Importer failed (…)`.

Dedupe: w5/639 (open) is related on the CLI side.

Acceptance: the two-importer runner claims `giro.csv`, and a raising
`identify()` is named in the error.
