# `add price` and `add balance` messages print tiny amounts in scientific notation, which `bea` refuses as input

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, Beancount 3.2.3, macOS.
A price conflict for a very small quote reads "already has a 2026-02-10
price of 1E-8 BTC …; refusing 2E-8 BTC". `bea` rejects scientific
notation on input and documents that results use fixed-point "so tiny
values can be fed back into input"; these messages do not, and the
"refusing" value is not what the user typed. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
2026-01-01 open Assets:Wallet
2026-01-01 open Equity:Opening

2026-01-02 * "Open"
  Assets:Wallet  0.00000001 BTC
  Equity:Opening

2026-02-10 price SHIB 0.00000001 BTC
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean add price --date 2026-02-10 -c SHIB --amount '0.00000002 BTC'
bea -f main.bean add price --date 2026-02-11 -c SHIB --amount '1e-8 BTC'
```

Actual: the first exits 2 (correct): `SHIB already has a 2026-02-10
price of 1E-8 BTC (at /absolute/books/main.bean:8); refusing 2E-8 BTC.
Pass --force to record another quote.` The second exits 2: `Scientific
notation '1e-8' is not supported in Beancount amounts.`

Control: the second command — the notation the message uses is refused
as input. A worker saw `1E-8`/`0E-8` in `add balance` conflict and
`--pad-from` messages and in JSON `error.message`, while the `directive`
echo and `list` print `0.00000001`.

Expected: `docs/USAGE.md` — amounts are spelled "in fixed-point decimal
notation (`0.00000001`, never `1E-8`) so tiny values can be fed back into
input".

Cause: `str(Decimal)` interpolation in the conflict and pad messages in
`cli/src/bea_engine/ledger/adding.py` (the balance helpers near
`:294-297`, `:339-376`, `:440-442` and the price conflict near
`:590-592`).

Fix: format with `format(value, "f")`, as the opening-adjustment hint in
`write.py` already does. No dependency or API change.

Blast radius: `add price` and `add balance` diagnostics, text and JSON.

Dedupe: w1/done/053 fixed scientific notation in query, balance and
report JSON fields; w5/done/007 is related; neither covers `add`
diagnostics.

Acceptance: the first command's message reads `price of 0.00000001 BTC
…; refusing 0.00000002 BTC`. Only macOS and the checkout were exercised.
