# The forced-string form `--meta 'key:"…"'` drops backslashes and turns `\t`, `\n`, `\f` into control characters

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Fix with [082](./done/082.md) and [128](./128.md).
The documented way to force a string metadata value, inner quotes, reads
the value as a Beancount string literal with C-style escapes. A quoted
Windows path or regular expression is stored corrupted with exit 0:
`"C:\Users\tian\receipts\feb\new.pdf"` becomes `C:Users<TAB>ian
eceipts<FF>eb ew.pdf` and `"INV-\d+"` becomes `INV-d+`. Uncommon (it needs
a backslash inside a deliberately quoted value), but agents that quote
every string defensively will hit it. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Food
2026-01-01 open Equity:Opening

2026-01-02 * "Open"
  Assets:Checking  5000.00 USD
  Equity:Opening
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean add transaction "Scan" --date 2026-02-01 -p "Expenses:Food 5" -p Assets:Checking \
  --meta 'receipt:"C:\Users\tian\receipts\feb\new.pdf"' \
  --meta 'pattern:"INV-\d+"' \
  --meta 'bare:C:\Users\tian\receipts\feb\new.pdf'
```

Actual: exit 0. The ledger gains:

```beancount
2026-02-01 * "Scan"
  receipt: "C:Users\\x09ian eceipts\\x0ceb ew.pdf"
  pattern: "INV-d+"
  bare: "C:\\Users\\tian\\receipts\\feb\\new.pdf"
  Expenses:Food          5 USD
  Assets:Checking
```

Control: the bare form in the same command keeps every backslash. Bulk
JSON `"meta": {"receipt": "C:\\Users\\tian\\receipts\\feb\\new.pdf"}`
through `add transactions` writes `receipt:
"C:\\Users\\tian\\receipts\\feb\\new.pdf"`. A worker saw `add commodity
--meta` corrupt a quoted path the same way.

Expected: `docs/USAGE.md`: "Inner quotes force a string, e.g. `--meta
'code:"1234"'`", and, of string metadata on single adds, bulk JSON and
imports, "Quotes and backslashes retain their contents." The quoted value
should be stored as typed.

Cause: `cli/src/bea_engine/ledger/adding.py:900` parses `key: <raw>` with
Beancount's parser and stores the parsed value (`:902`). For a quoted value
the lexer applies C-style escapes: `\t`, `\n`, `\f`, `\r` become control
characters and any other backslash is dropped. The writer then flattens or
spells out the control characters.

Fix: when the raw value is one complete `"…"` literal, store the text
between the quotes with only `\"` and `\\` unescaped; or document that the
quoted form takes Beancount escapes and refuse an unrecognised escape
rather than dropping it. No dependency or API change.

Blast radius: `--meta` on `add transaction` and `add commodity` (the two
callers of `_parse_metadata`). Bulk JSON, CSV import and Python importers
do not use it.

Dedupe: board search for backslash, `x0c`, "Inner quotes" and `--meta`
quoting finds w5/082 and w5/128 in the same function; both cover bare
values and both name the quoted form as the working control. This is the
quoted form itself failing.

Acceptance: the command stores `receipt` and `pattern` with every
backslash, as the bare and bulk controls do; `--meta 'code:"1234"'` still
stores the string `1234`. Only macOS and the checkout were exercised.
