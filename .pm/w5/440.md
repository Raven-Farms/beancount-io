# On a ledger with a non-UTF-8 byte in a string, `bea doctor print-options`/`roundtrip` show a raw `UnicodeDecodeError`, and `missing-open`, `context`, `directories` and `display-context` exit 0 with no output

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
w5/278 made "Cannot decode '…' as UTF-8 … Re-save the file as UTF-8 and
retry" the rule on the ledger read path, and `bea check` follows it.
`doctor` does not:

- Operations that pre-check syntax pass the helper's raw decode error
  through, class name included.
- Operations that forward to native `bean-doctor` exit 0 with nothing
  printed. For `missing-open`, that reads as a false "nothing missing".

No product fix implemented.

Use a valid ledger plus `2026-01-09 * "caf\xe9"`, a single Latin-1 byte
written with `printf`. Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME,
BEA_NO_UPDATE_NOTIFIER=1, and closed stdin.

```sh
bea doctor print-options /absolute/books/main.bean
bea doctor missing-open /absolute/books/main.bean
bea -f /absolute/books/main.bean check          # control
```

Actual:

- `print-options` exits 1 with `doctor print-options cannot load …:
  …main.bean:3: UnicodeDecodeError: 'utf-8' codec can't decode byte 0xe9
  …`. `roundtrip` does the same.
- `missing-open` exits 0 with no output, and so do `context`,
  `directories` and `display-context`.

Reproduced by the hunter in the matrix and by hand, and by me
(`print-options`, `missing-open`).

Control: `check` exits 1 with `Cannot decode '…/main.bean' as UTF-8:
invalid continuation byte at byte 275. Re-save the file as UTF-8 and
retry.`

Expected: every doctor operation that loads the ledger, all but `lex` and
`parse`, gives w5/278's message with exit 1 and no class name, and none
exits 0 on a ledger it could not decode.

Cause: `_syntax_errors_of`/`_closure_syntax_errors_of`
(`cli/src/cli/commands/doctor.py:159-194`) relay the raw string. The
forwarding paths (`_forward_scoped` and similar, `doctor.py:474+`) let
native bean-doctor log the error and exit 0.

Fix: detect a decode error in the helper load and raise w5/278's error
for those operations. No dependency change.

Dedupe: w5/278 (done) lists its commands without doctor. 438
(unreadable includes) and 439 (plugin failures) are related doctor gaps.
None covers decode errors.

Acceptance: on the fixture, each doctor operation except `lex`/`parse`
exits 1 with w5/278's message, and none exits 0 silently. A test pins
`missing-open` and `print-options`.
