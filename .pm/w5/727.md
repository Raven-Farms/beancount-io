# A quoted `--meta` value followed by `; comment` exits 0 but silently drops the comment, and C-style escapes rewrite the quoted text: `"C:\Users\tian\new.pdf" ; scanned` is stored as `C:Users\x09ian ew.pdf` (incomplete fix of w5/128 and w5/232)

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-17, HEAD `9e727c0e7`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/128 and w5/232 (done).
USAGE:1229-1236 says "a memo with a `;` in it" is stored as the text typed.
It also says "The quoted text is stored as typed: only `\"` and `\\` are
escapes". w5/128 fixed `;` for bare values, and w5/232 fixed escapes for a
value that is exactly one quoted literal. A quoted literal followed by more
text falls between the two fixes. No product fix implemented.

```sh
bea --file /abs/main.bean add transaction "Scan" --date 2026-01-05 -p 'Expenses:Food 10 USD' -p Assets:Checking \
  --meta 'receipt:"C:\Users\tian\new.pdf" ; scanned copy' --meta 'memo:"lunch" ; split with Sam'
```

Actual: exit 0, `Added 1 transaction`, and the file gains:

```
  receipt: "C:Users\\x09ian ew.pdf"
  memo: "lunch"
```

The text after `;` is gone. `\U` lost its backslash, `\t` became a tab
(written `\x09`), and `\n` became a newline, then a space. `check` exits 0,
and the `--json` echo shows the same values. `add commodity --meta
'name:"Hooli\Inc" ; ticker HOOL'` writes `name: "HooliInc"` (hunter's run).

Control: `--meta 'receipt:"C:\Users\tian\new.pdf"'` is stored exactly as
`"C:\\Users\\tian\\new.pdf"`. `--meta 'memo:12 ; split'` is stored as the text
`"12 ; split"`.

Expected: either refuse with exit 2 naming the text after the closing quote,
or store the whole typed text. Never store the lexer's reading.

Cause: `cli/src/bea_engine/ledger/adding.py:1147-1154`. `_may_be_typed`
(`:1081`) lets Beancount parse any value starting with `"`, and the parser
treats `; …` as a comment. The whole-literal regex then fails on the trailing
text, and `:1154` keeps the parser's value because `raw.startswith('"')`.

Fix: for a value starting with `"`, accept only one whole literal (with `\"`
and `\\` as the only escapes). Refuse anything after the closing quote. The
"close the quoted string" message for `"a" "b"` should also say the string is
closed and name the extra text.

Dedupe: w5/128 and 232 (done) are the parents; w5/669 (open) covers wide
negative numbers.

Acceptance: both `--meta` values above exit 2 (or store the whole text),
with nothing written by the lexer. A test pins the Windows-path case.
