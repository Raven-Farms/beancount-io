# price export copies a local plugin package's Python files but drops its required package resources, reporting success for a snapshot that cannot load

**Trivial · cli · 15–25m · A1.** Real CLI QA, 2026-10-18, HEAD `4ef6ab16f`, checkout `bea 0.3.1`, macOS 26.5.1, managed engine Python 3.12. Twice from pristine synthetic books with isolated config/cache, stdin closed and no TTY. The plugin is controlled local code; no network, credentials or installation changes. No product fix implemented.

Create `books/main.bean`:

```beancount
option "operating_currency" "USD"
option "insert_pythonpath" "TRUE"
plugin "pkgplug"
2026-01-01 open Assets:Cash USD
```

Create `books/pkgplug/settings.json` containing `{"label":"Synthetic"}`, and `books/pkgplug/__init__.py`:

```python
import json
from importlib.resources import files

CONFIG = json.loads(files(__package__).joinpath("settings.json").read_text())
__plugins__ = ["run"]

def run(entries, options):
    return entries, []
```

```sh
bea --file /abs/books/main.bean check
bea --json --file /abs/books/main.bean price export -o /abs/snapshot
bea --file /abs/snapshot/main.bean check
```

Actual: the source check exits 0. Export exits 0 and lists exactly `snapshot/main.bean` and `snapshot/pkgplug/__init__.py`. It omits `pkgplug/settings.json`. A fresh check of the snapshot exits 1 with `FileNotFoundError ... snapshot/pkgplug/settings.json`. The original settings file retains its bytes. This is a required resource inside the selected package, not an unrelated file beside the ledger.

Control: inline `CONFIG = {"label":"Synthetic"}` in the same package, leaving the unrelated JSON beside it. Source check, export and fresh snapshot check all exit 0.

Expected: the copied package remains loadable, including its required ordinary package resources, or the export refuses to promise a portable copy. USAGE around `:1907` says a local plugin module or package is copied so the snapshot's plugin lines still resolve. The current Python-only copy leaves a partial package while reporting success.

Cause: `_export_plugin_modules` (`cli/src/bea_engine/managed_load.py:1891`) enumerates a selected package with `package.rglob("*.py")` at `:1911`. Resource files never enter the export plan, so its collision, containment and missing-file checks cannot see them. `_sibling_imports` discovers Python modules, not non-module files read through the package resource API. The same omission affects local helper packages imported by the plugin.

Fix: carry ordinary resources belonging to the selected local package through the existing export plan, preserving containment, collision and permission safeguards and excluding bytecode caches. Reject resources that cannot travel safely instead of silently dropping required package contents. Avoid indiscriminately copying unrelated root-ledger files.

Dedupe: searched all board states for plugin/package resources, data files, `settings.json`, non-Python files and `importlib.resources`; no open coverage. Completed w5/094 added local plugin copies and w5/327 added sibling-module discovery, both Python-module cases. The latter's statement that a package is copied whole is overbroad for resources. This is independent of the planned-name collision in w5/867.

Acceptance: the fixture exports a loadable package with its JSON resource and passes a fresh check; the inlined control stays valid. Include a helper-package resource case and preserve rejection of paths outside the permitted export tree.
