# A lone `\uD83D` escape in a bulk JSON text field aborts the batch with a raw `UnicodeEncodeError`

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A JSON string cut in the middle of an emoji — which other tools emit as
a lone surrogate escape such as `\ud83d` — makes `add transactions` fail
with a Python `UnicodeEncodeError`, exit 1 `validation`, no row number,
and nothing written even with `--partial`. The same defect as raw bytes
gets a clear exit-2 message. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food
```

`/absolute/books/rows.json`, with a literal backslash-u sequence in row 2:

```json
[{"date":"2026-02-01","narration":"r1","postings":[{"account":"Expenses:Food","amount":"10 USD"},{"account":"Assets:Cash"}]},
 {"date":"2026-02-02","narration":"Coffee \ud83d","postings":[{"account":"Expenses:Food","amount":"11 USD"},{"account":"Assets:Cash"}]},
 {"date":"2026-02-03","narration":"r3","postings":[{"account":"Expenses:Food","amount":"12 USD"},{"account":"Assets:Cash"}]}]
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea --json -f main.bean add transactions --from rows.json --partial
```

Actual: exit 1, ledger unchanged:

```text
{"error": {"category": "validation", "message": "UnicodeEncodeError: 'utf-8' codec can't encode character '\\ud83d' in position 21: surrogates not allowed Pass --debug before the command for a traceback.", "exit_code": 1}}
```

Control: the same file with `\u001b` in place of `\ud83d` exits 0 and
writes all three rows. A worker saw the same error for payee and
metadata values and for a low surrogate, and the raw-byte form of the
defect exit 2 with `Cannot decode … as UTF-8 … Re-save the file as UTF-8
and retry.`

Expected: a per-row rejection (`Row 2, narration: …`) with rows 1 and 3
written under `--partial`, or an exit-2 input error naming the row and
field, as `docs/USAGE.md` describes for undecodable input.

Cause: `json.loads` in `cli/src/cli/commands/add.py` accepts lone
surrogates; the string reaches the engine, where the first UTF-8 encode
raises inside the bulk validation in
`cli/src/bea_engine/ledger/adding.py`.

Fix: reject unpaired surrogates when loading the JSON, naming row and
field, or refuse them per row in the model's string fields so `--partial`
still works. No dependency or API change.

Blast radius: every free-text field of a bulk row.

Dedupe: board search for surrogate finds w1/done/112 and w1/done/166
(raw non-UTF-8 bytes on stdin) and w5/155 (`query` stdin); none covers a
JSON escape.

Acceptance: the command exits nonzero with a message naming row 2 and
`narration`, no Python exception name, and under `--partial` rows 1 and
3 are written. Only macOS and the checkout were exercised.
