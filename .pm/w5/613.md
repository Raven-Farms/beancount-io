# A write through an included file (`--file txns.bean`) reports that file as `target.file`, keeps the "checked against the root" note out of the JSON, and stores import memory under the included file instead of the root

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-16, HEAD `be46147e`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE's target table defines `file` as the resolved ledger and `into` as the
appended file. IMPORTING says "The mapping is remembered per root ledger".
Since w5/343/346, a write through an included file runs through its root, but
only the engine knows that. The frontend reports and remembers by the file
the user named, so two equivalent writes describe themselves differently. A
mapping remembered through the leaf is invisible to the root, and the other
way round. No product fix implemented.

`main.bean`: `option "operating_currency" "USD"`, opens for `Assets:Cash USD`,
`Expenses:Food`, `Expenses:Uncategorized`, and `include "txns.bean"`;
`txns.bean`: one transaction.

```sh
bea --json --no-input --file txns.bean add transaction --date 2026-01-03 b -p "Expenses:Food 2 USD" -p Assets:Cash
bea --json --no-input --file main.bean add transaction --into txns.bean --date 2026-01-04 c -p "Expenses:Food 2 USD" -p Assets:Cash
bea --json --no-input --file txns.bean import x.csv --csv date=Date,narration=Description,amount=Amount --account Assets:Cash --apply
bea --json --no-input --file main.bean import y.csv --into txns.bean       # same header, no flags
```

Actual: (1) `target {"file": ".../txns.bean", "into": ".../txns.bean"}`,
`warnings: []`, with `txns.bean is included by …/main.bean; the write goes to
txns.bean and is checked against that whole ledger.` as plain text on stderr;
(2) `target {"file": ".../main.bean", "into": ".../txns.bean"}`; (3) the
mapping is saved under the hash of `txns.bean`, and its `notes` omit the
redirect; (4) exits 2 asking for `--account`.

Expected: both writes report `file` = `main.bean`; the redirect note appears
in `warnings`/`notes` under `--json` (as the NFC notes do); memory is keyed by
the root ledger.

Cause: the frontend uses the invoked file for the target
(`cli/src/cli/commands/add.py:114`, `:320`, `:344`, `:436`, `:681`;
`cli/src/cli/commands/import_.py:1115`) and for memory (`_csv_record`,
`_config_record`, `import_.py:72-90`, from `:560`); the redirect happens in
the engine (`write_through_root`, `cli/src/bea_engine/ledger/write.py:1350-1370`),
which reports through `protocol.note` (stderr, `cli/src/bea_engine/protocol.py:183`).

Fix: have the engine return the resolved root (or resolve it in the
frontend) and use it for `target.file` and the memory key; route the note
into the JSON warnings. Coordinate with w5/578 (open), which narrows when the
redirect applies.

Dedupe: w5/343, 346, 347, 348 (done) and w5/514, 578 (open) concern
validation and hints, not the target or memory.

Acceptance: the four commands report `main.bean` as `file`, carry the note in
JSON, and share one remembered mapping. Tests pin them.
