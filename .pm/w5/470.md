# `bea import`'s "no importer" refusal suggests `--account Assets:Checking` and placeholder columns, whatever account was typed and whatever the file's header says

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `8195088f`, checkout `bea 0.3.1`, macOS 26.5.1.
An agent or user that copies the suggested command imports savings rows
into checking. The command also fails on the column names, which come from
no file. The `--csv auto` refusal already lists the file's real columns. No
product fix implemented.

Disposable `main.bean` opening `Assets:Checking` and `Assets:Savings`;
`sav.csv`:

```csv
When,What,HowMuch
2026-02-01,A,-1.00
```

```sh
bea -f /abs/main.bean import sav.csv --account Assets:Savings
```

Actual: exit 2, `Error: Choose a Python importer with --config FILE, or
place importers.py beside the root ledger. … map the columns directly with
--csv date=Date,amount=Amount,narration=Description --account
Assets:Checking.`

Expected: the hint keeps the typed `--account Assets:Savings` (or a
placeholder when none was typed) and lists the file's columns (`When`,
`What`, `HowMuch`), as the `--csv auto` error does ("Its columns are: …").

Cause: hard-coded string in `_config_path`
(`cli/src/cli/commands/import_.py:146-151`).

Fix: build the hint from the typed account and the header bea read, when
there is one.

Dedupe: the string appears only as command text in w5/003, 215, 265, 267
and 284. No note covers the hint itself.

Acceptance: the refusal above names `Assets:Savings` and the three real
columns. A test pins it.
