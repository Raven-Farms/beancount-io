# A one-description CSV row is never a possible duplicate of a ledger entry that has a payee, even with identical date, narration and amount

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `5e09bcc4`, checkout `bea 0.3.1`, macOS 26.5.1.
IMPORTING.md: a row with no payee "is compared by its normalized narration".
The existing entry is keyed by its payee when it has one, so the two never
meet. The beancount-migrate skill writes exactly this shape for Monarch
(`payee` = Merchant, narration = original statement text,
`references/monarch.md`). A later bank export of the same rows then
double-books them. No product fix implemented.

`main.bean`:

```beancount
option "operating_currency" "USD"

2026-09-01 open Assets:Checking USD
2026-09-01 open Expenses:Dining USD
2026-09-01 open Expenses:Uncategorized USD

2026-09-28 * "Starbucks" "CARD PURCHASE 1234"
  Assets:Checking  -4.50 USD
  Expenses:Dining   4.50 USD
```

`bank.csv`: `Date,Description,Amount` / `2026-09-28,CARD PURCHASE 1234,-4.50`.

```sh
bea --file /abs/main.bean import bank.csv --csv date=Date,narration=Description,amount=Amount --account Assets:Checking --duplicates skip --apply
```

Actual: exit 0, `1 ready, 0 exact duplicates, 0 possible duplicates`; the row
is written and Checking is `-9.00 USD`.

Control: the same entry without the payee (`2026-09-28 * "CARD PURCHASE
1234"`) gives `1 possible duplicates`, and nothing is written.

Expected: a `possible_duplicate`, skipped under `--duplicates skip`
(Checking −4.50).

Cause: `_candidate_key` (`cli/src/bea_engine/importing.py:1636`) keys the
existing entry by `payee or narration` and the row by its narration.

Fix: when either side lacks a payee, compare narration with narration (or
match on either field).

Dedupe: searched `one-description`, `no payee`; w5/140 (done) is about ID
claims.

Acceptance: the fixture reports the possible duplicate and writes nothing. A
test pins it.
