# A reconciled zero valuation adjustment, and a zero total equity, print as "—" / `{}` under a currency conversion, beside `0.00 USD` net worth (also in the README quick start)

**Trivial · cli · 10m · A2.** Real CLI QA, 2026-10-16, HEAD `e03cf71e`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE uses "—" / `{}` for an account with no balance. Under a currency
conversion, the headline values `net_profit` and `current_earnings` name the
currency (`"0"`). Two derived lines next to them do not, so a newcomer's
first balance sheet reads "Total equity (credit): —" above "Net Worth: 0.00
USD". No product fix implemented.

`opens.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Bank USD
2024-01-01 open Equity:Opening-Balances
```

```sh
bea -f /abs/opens.bean report balance-sheet
bea -f /abs/opens.bean --json report balance-sheet
```

Actual: `Valuation/translation adjustment (credit): —` and `Total equity
(credit): —` above `Net Worth: 0.00 USD`; JSON `valuation_adjustment: {}` and
`equity_total: {}` beside `equity_reconciled: true`. A ledger with income in
the period still prints the adjustment as `—`. The README quick-start ledger
shows the same.

Expected: `0.00 USD` in text and `{"USD": "0"}` in JSON for both lines, as
the headline values do.

Cause: `cli/src/bea_engine/report.py:343-344` returns the raw inventories
instead of passing them through `_headline(…, conversion)`.

Fix: wrap both values in `_headline`.

Dedupe: searched `Total equity`, `valuation_adjustment`; only w5/127 (done,
different).

Acceptance: both lines read `0.00 USD` / `{"USD": "0"}`. A test pins it.
