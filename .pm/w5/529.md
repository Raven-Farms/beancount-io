# A CSV in Windows-1250/1251, Latin-9 or EUC-JP is told "it decodes as cp1252 — pass --csv encoding=cp1252"; following the advice writes mojibake (`Wp³ata £ódŸ`) with exit 0

**Minor · cli · 20–30m · A1/A2.** Real CLI QA, 2026-10-16, HEAD `5d08dc41`, checkout `bea 0.3.1`, macOS 26.5.1.
The decoding probe asks only whether every byte decodes under cp1252, which
almost any 8-bit file does. Polish, Czech, Russian and other Central or
Eastern European bank exports therefore get advice that garbles every payee.
The advice is also the only encoding hint shown. `--csv encoding=cp1251` is
refused (`write utf-8, cp1252, or latin-1`), so the working path is to
re-save as UTF-8, and nothing says so. w5/406 treated advice that leads to
mojibake as a bug. No product fix implemented.

Ledger with `Assets:Checking EUR` open; `pl.csv` encoded cp1250:

```csv
Date,Description,Amount
2026-03-01,Wpłata Łódź,-4.50
```

```sh
bea --file /abs/main.bean import pl.csv --account Assets:Checking
bea --file /abs/main.bean import pl.csv --csv encoding=cp1252 --account Assets:Checking --apply
```

Actual: the first exits 2 with `pl.csv is not valid UTF-8 (invalid start byte
at byte 37); it decodes as cp1252 — pass --csv encoding=cp1252.`; the second
writes `2026-03-01 ! "Wp³ata £ódŸ"`, exit 0. A cp1251 `Пятёрочка` becomes
`Ïÿò¸ðî÷êà`; Latin-9 `€` becomes `¤`.

Control: a real cp1252 or Latin-1 export imports correctly with
`encoding=cp1252` (IMPORTING.md presents that case).

Expected: when the cp1252 reading looks like mojibake (upper-Latin-1 letters
that would not occur in Western text, such as `³ £ Ÿ ¸`, or runs of them),
the refusal says the export is probably in another code page and to re-save
it as UTF-8. Otherwise it makes the cp1252 advice conditional ("if the
export is Western European"). Accepting more encodings is the alternative
(`cp1250`, `cp1251`, `iso-8859-15`).

Cause: `probe_decoding` (`cli/src/cli/csv_mapper.py:533-537`; engine twin
`cli/src/bea_engine/csv_mapper.py` near `:700`).

Fix: as above; keep the frontend and engine copies in step.

Dedupe: searched `cp1251`, `decodes as cp1252`. w5/332 (latin-1 hint for
Shift_JIS) and w5/406 (mixed files) are done and do not cover this.

Acceptance: the cp1250 and cp1251 fixtures get the re-save advice (or import
correctly); a cp1252 file still gets the cp1252 hint. A test pins all three.
