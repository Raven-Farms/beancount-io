# The BOM remedy "Run bea format -i" is refused when the ledger came from the current directory or `BEA_FILE`

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
For a ledger that starts with a UTF-8 BOM, `bea check --auto` (run in
the ledger's directory) says "Run bea format -i to strip the mark, then
retry." That exact command is refused — bare `bea format` reads stdin —
so the BOM stays and the original command fails again. No product fix
implemented.

Create `/absolute/books/main.bean` as the three bytes `EF BB BF`
followed by `2020-01-01 open Assets:Cash USD`.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea check --auto
bea format -i
```

Actual: the first exits 2: `bea check cannot pass bean-check options
(--auto) for this ledger: a file in its include closure starts with a
UTF-8 BOM bean-check cannot parse. Run bea format -i to strip the mark,
then retry.` The second exits 2: `Name the files to format: reading stdin
has nothing to compare or rewrite.` The file still starts with `efbbbf`.

Control: `bea format -i main.bean` exits 0 and removes the mark. A worker
saw the same dead end with `BEA_FILE` set and under `--json`.

Expected: a remedy that works for the ledger in effect; `bea format`
needs the file named.

Cause: `cli/src/cli/commands/check.py:125` is a constant string, though
the function holds the resolved ledger path.

Fix: include the shell-quoted path: `Run bea format -i <file> to strip
the mark, then retry.` No dependency or API change.

Blast radius: this one message.

Dedupe: board search for "strip the mark" finds nothing; w5/135 (doctor
on BOM ledgers) is unrelated.

Acceptance: the message names the ledger file, and running the printed
command removes the BOM so the original command proceeds. Only macOS and
the checkout were exercised.
