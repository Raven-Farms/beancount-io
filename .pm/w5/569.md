# `bea doctor` counts a file included under two spellings twice (`Net Income: (-6.00 USD)` for one 3.00 lunch), and `doctor roundtrip` crashes with a long `CompareError` traceback (gap in w5/433)

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `04c94595`, checkout `bea 0.3.1`, macOS 26.5.1. Case-insensitive APFS.
USAGE says such a file "is loaded once, from its first include", with a
`Duplicate include` error. `check` and the reads enforce this (w5/433).
Doctor refuses ledgers that `check` rejects for undecodable text or plugin
failures, because otherwise "its answer would describe a ledger other than
yours", but it does not run the duplicate-member check. No product fix
implemented.

`books/main.bean`:

```beancount
include "Sub/X.bean"
include "SUB/x.bean"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
```

`books/Sub/X.bean`: `2026-01-05 * "lunch" ^l`, `Expenses:Food 3.00 USD`, `Assets:Cash`.

```sh
bea doctor linked books/main.bean ^l
bea doctor roundtrip books/main.bean
```

Actual: `linked` exits 0 with `Food 6.00 USD` and `Net Income: (-6.00 USD)`;
`context SUB/x.bean:1` shows the balance already holding 3.00; `roundtrip`
exits 1 with a traceback ending `ValueError: CompareError(… Duplicate entry
…)`.

Control: `bea check` exits 1 with `Duplicate include: …SUB/x.bean is
…Sub/X.bean…`; `bea --allow-errors balance` shows 3.00.

Expected: doctor refuses with check's `Duplicate include` line, exit 1.

Cause: doctor's pre-checks (`cli/src/cli/commands/doctor.py:657-665`) cover
unreadable includes, undecodable text and plugins, not
`output.has_duplicate_member`.

Fix: add the duplicate-member refusal to the pre-checks.

Dedupe: w5/433 (done) fixed load and check only.

Acceptance: both commands exit 1 with the `Duplicate include` line. A test
pins it (skip where the filesystem is case-sensitive, or use a hard link).
