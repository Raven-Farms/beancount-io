# Warn when a recorded quote loses to another price

**Minor · cli · 45–60m · A1.** Some price writes report success without
warning that subsequent reads use a different price. Import misses
the reciprocal warning that `add price` already supplies; both writers also
miss a same-direction winner when the new quote goes into a short included
file. A forced correction can also lose to an older written quote. These
gaps belong to the same effective-price advisory repair after
completed [741](./done/741.md). No price-selection change or product fix
implemented.

Real CLI QA 2026-10-20, checkout `6d7693000`, `bea 0.3.1`, Darwin 25.5.0
arm64, frontend Python 3.13.3, managed engine Python 3.12 with Beangulp already
available. Human and JSON imports each reproduced twice in pristine fixtures,
separate bounded processes, closed stdin/no TTY, isolated absolute
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no inherited
BEA_FILE/BEA_TOKEN.

Create `/absolute/qa/main.bean`:

```beancount
plugin "beancount.plugins.implicit_prices"
option "operating_currency" "USD"
2024-01-01 open Assets:EUR EUR
2024-01-01 open Assets:USD USD
2024-01-01 open Equity:Opening
2024-01-02 * "Opening"
  Assets:EUR 1000 EUR
  Equity:Opening -1000 EUR
2024-01-05 * "Exchange"
  Assets:USD 100 USD @ 0.80 EUR
  Assets:EUR -80 EUR
```

Create a synthetic `quotes.txt` and `importers.py`:

```python
from datetime import date
from decimal import Decimal
from beancount.core.data import Price, new_metadata
from beancount.core.amount import Amount

class Quotes:
    def identify(self, file): return str(file).endswith('.txt')
    def account(self, file): return 'Assets:EUR'
    def extract(self, file, existing_entries=None):
        return [Price(new_metadata(file, 1), date(2024, 1, 5), 'EUR',
                      Amount(Decimal('1.20'), 'USD'))]

CONFIG = [Quotes()]
```

From `/absolute/qa` with the environment above:

```sh
bea --json -f /absolute/qa/main.bean check
bea --json --no-input -f /absolute/qa/main.bean import quotes.txt --config importers.py --apply
bea --json -f /absolute/qa/main.bean query "SELECT getprice('EUR','USD',2024-01-05) LIMIT 1"
bea --json -f /absolute/qa/main.bean query "SELECT convert(sum(position),'USD',2024-01-05) WHERE account ~ '^Assets:'"
bea --json -f /absolute/qa/main.bean check
```

All exit 0. Import calls the row `new`, writes 1, and reports
`validation_warnings: []`; its only note identifies the importer config.
The file contains `2024-01-05 price EUR 1.20 USD`. Fresh queries nevertheless
return rate **1.25** and asset value **1250.00 USD**, because the implied
USD→EUR 0.80 still determines the reverse direction. An operator expecting
the imported rate would calculate `920 EUR × 1.20 + 100 USD = 1204 USD`.
The issue is the absent explanation of the existing settlement rule.

Human import, in a separate pristine fixture, likewise writes the visible
1.20 quote and says `Wrote 1 entry`; stderr only identifies the config.
There is no unused-quote warning in either stream.

Controls, twice each:

- On the original ledger, use `bea --json -f /absolute/qa/main.bean add price
  --date 2024-01-05 --currency EUR --amount '1.20 USD'`. It writes 1 and
  warns that the USD 0.80 EUR price is implied at `main.bean:9`, that every
  read keeps using it, and that the new quote is never used. Queries agree
  with the warning: 1.25 and 1250 USD.
- Remove only the implicit-prices plugin and perform the import: it writes
  1, the rate becomes 1.20 and assets value at 1204 USD. No warning is needed.

Cause: `cli/src/bea_engine/importing.py:650–693` checks only recorded quotes
from `_own_quotes` (:1471–1490), deliberately excluding generated ones, and
adds an accepted price without evaluating the generated winner. That is
correct for deciding whether to write, but no advisory check follows.
`ledger/adding.py:978–1037` already simulates quote settlement with
`settle_price_days` and appends the relevant generated-winner warning.
The import frontend renders `validation_warnings` at
`cli/src/cli/commands/import_.py:1650`, but receives none for this case.

Fix: surface the same effective-price advisory for accepted imported quotes,
including the generated winner's location and rate. Judge the complete
candidate quote set, because several rows can change which direction wins;
do not blindly evaluate each row against the pre-import set. Keep writing
valid source quotes, preserve recorded-price conflicts and exact duplicates,
and avoid warnings when the incoming rate is actually effective. Do not
turn the generated quote into an exact duplicate or change price settlement.

Dedupe: searched all board states for import/implied or implicit prices,
unused quotes and generated-winner warnings; reviewed active milestones.
741 (`95e492811`) added the warning to add-price while repairing import's
recorded reciprocal conflicts, leaving this caller. 302 (`e06e6500`) requires
that a plugin-generated quote not suppress an import. Open [902](./902.md)
is incorrect conflict-remedy text under a one-price policy; this is successful
write feedback and a different branch. No overlapping open repair or newer
implementation was found. IMPORTING's price rules explicitly follow
add-price, and 741 requires explaining a quote no read will use.

Acceptance: both import output modes explain the 1.25/1.20 mismatch while
retaining the written quote; fresh BQL and check agree with the explanation.
Keep add-price, no-plugin and multi-price controls. Evidence retained in
ignored pass6 `repro_import_generated_price_warning.py`,
`generated-price-import-results.json`, eight fixtures and captures. Only
macOS/checkout exercised; repaired behavior remains unverified.

Additional batch controls, each twice from pristine fixtures: keep the

This exercises 740's existing per-day count rule in

## Additional reproduction: same-direction quote in an included file

Reproduced twice per writer and control at HEAD `3e514739e`. This extends
the warning repair to `add price` itself: reusing its current reverse-only
advisory unchanged would leave this case broken.

Create `prices.bean` containing just `; quote file` and this `main.bean`:

```beancount
include "prices.bean"
plugin "beancount.plugins.implicit_prices"
option "operating_currency" "USD"
2024-01-01 open Assets:EUR EUR
2024-01-01 open Assets:USD USD
2024-01-01 open Equity:Opening USD
2024-01-02 * "Opening"
  Assets:USD 1000 USD
  Equity:Opening -1000 USD
2024-01-05 * "Exchange"
  Assets:EUR 100 EUR @ 1.25 USD
  Assets:USD -125 USD
```

Run either writer on a fresh fixture:

```sh
bea --json -f /absolute/qa/main.bean add price --date 2024-01-05 --currency EUR --amount '1.20 USD' --into prices.bean
bea --json --no-input -f /absolute/qa/main.bean import quotes.txt --config importers.py --apply --into prices.bean
```

The importer is the same complete `Quotes` class above. Each command exits
0, writes 1 and returns empty warning arrays. The explicit 1.20 quote lands
on **prices.bean:3**. The generated price borrows **main.bean:10** from the
exchange, so it comes later in the loaded entry order. Fresh queries from
the original repro return **1.25** and **1000 USD**, rather than the
**995 USD** the recorded 1.20 rate would give (`100 × 1.20 + 875`). Every
fresh check passes. This is the same missing-advisory outcome, with another
gap in the existing helper's prediction of the effective quote.

Controls, each twice through both writers:

- Omit `--into`: the quote is appended at main.bean:14, takes effect at
  1.20 and values assets at 995 USD. No warning is appropriate.
- Start the included file with 30 comment lines: its new quote is on line
  32, takes effect at 1.20 and values assets at 995 USD.
- Omit the plugin but retain the short included file: the quote is the
  effective 1.20 rate, assets 995 USD, no warning needed.

All sixteen final values and persisted price lines were checked. Upstream
`beancount.core.data.entry_sortkey` orders equal-day/equal-kind entries by
line number; the CLI's `settle_price_days` retains the last same-direction
quote in that order. The existing `adding.py:978–1008` advisory considers
only generated **reciprocals** and appends its simulated quote last, which
does not model this included-file placement. Import supplies no such check.

Extend the repair and acceptance: evaluate generated winners in either
direction against the actual candidate ordering and locations, including
`--into`. Warn on both short-file writes above, retain the root/long-file/
no-plugin controls, and preserve the original reciprocal and batch cases.
The price-settlement rule remains unchanged. All-board search for
same-direction implied prices and split-file warning gaps found no other
open repair; this extends 903 to avoid overlapping advice work. Evidence:
ignored pass6 `repro_same_direction_implied_quote.py`,
`same-direction-price-results.json`, sixteen fixtures and captures. JSON
was exercised for this added matrix; human output shares the warning fields
but was not rerun here.

**Written-price extension, 2026-10-21.** The same placement gap occurs with
no plugin: a forced correction written into a short included file can lose
to an older **written** quote, with no warning in either output mode.
Checkout `bea 0.3.1`, macOS 26.5.1 arm64, frontend Python 3.13.3, managed
Python 3.12.10 / Beancount 3.2.3. Same isolated, closed-stdin environment as
above; two pristine reproductions and fresh working controls. No product fix.

Create this disposable fixture:

```python
from pathlib import Path
books = Path('/abs/books')
books.mkdir(parents=True, exist_ok=True)
(books / 'prices.bean').write_text(
    '; old quote\n' * 39 + '2024-01-03 price HOOL 20 USD\n')
(books / 'corrections.bean').write_text('; corrections\n')
(books / 'main.bean').write_text('''option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Assets:Stock HOOL
2024-01-01 open Equity:Opening USD
2024-01-01 * "Capital"
  Assets:Cash 100 USD
  Equity:Opening -100 USD
2024-01-02 * "Buy"
  Assets:Stock 1 HOOL {10 USD}
  Assets:Cash -10 USD
include "prices.bean"
include "corrections.bean"
''')
```

From `/abs/books`:

```sh
bea --json -f /abs/books/main.bean check
bea --json --no-input -f /abs/books/main.bean add price --date 2024-01-03 --currency HOOL --amount '22 USD' --force --into corrections.bean
bea --json -f /abs/books/main.bean query "SELECT getprice('HOOL','USD',2024-01-03) LIMIT 1"
bea --json -f /abs/books/main.bean query "SELECT convert(sum(position),'USD',2024-01-03) WHERE account ~ '^Assets:'"
bea --json -f /abs/books/main.bean report overview --time 2024-01 --conversion at_value
bea --json -f /abs/books/main.bean check
```

All exit **0**. The force call returns `written: 1`, `warnings: []`, and
the 22 USD directive. It appends the correction at **corrections.bean:3**.
Fresh BQL still returns **20 USD**, asset value **110 USD**, and overview
agrees. The old written quote at **prices.bean:40** wins; the new 22 rate
would give 112 USD. Both checks remain valid. Root and old-price bytes are
unchanged. A fresh human run likewise says `Added 1 price`, with empty
stderr and no unused-quote advisory.

Controls, twice each: put the old quote on line 1, prefill corrections with
60 comment lines, or append the correction to `prices.bean` itself. Each
force call writes one effective quote, and fresh BQL/report return **22 /
112 USD**, so no warning is appropriate. Omitting `--force` exits **4** and
preserves every file. Twelve fresh human/JSON/placement/control books all
pass native check. Twelve unwrapped upstream loader/price-map references
independently reproduce the exact effective rates; this is feedback about
native ordering, not a request to replace it.

Root-cause scope: `adding._price`'s advisory (:976–1022) only considers
generated reciprocal candidates, and its simulation always appends the
proposed quote last. The existing same-direction extension already requires
actual candidate locations/order, but restricting its winners to generated
entries would leave this plugin-free `--force` case unfixed. The `_price`
dispatcher is the single add-price backend; import cannot use this force
option. `settle_price_days` intentionally keeps the last quote within one
direction/day, and upstream `entry_sortkey` sorts equal-day prices by their
source line number. Preserve both rules.

Extend the same repair/acceptance to a forced write whose winning quote is
already written: explain that the newly recorded rate is ineffective and
name the winning file, line and amount. Keep the successful write, ordinary
conflict refusal, same-file/long-target controls and all earlier generated
and reciprocal cases. No automatic edits/reordering of other source files,
dependency or API change. Estimate remains 45–60m for this shared advisory
