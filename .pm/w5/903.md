# Warn when an imported quote loses to a generated reciprocal

**Minor · cli · 30–45m · A1.** Importing a price reports a successful write
without warning that every subsequent read uses a different implied price.
The same `add price` operation correctly warns. Missed import caller after
completed [741](./done/741.md); no price-selection change or product fix
implemented.

Real CLI QA 2026-10-20, checkout `6d7693000`, `bea 0.3.1`, Darwin 25.5.0
arm64, frontend Python 3.13.3, managed engine Python 3.12 with Beangulp already
available. Human and JSON imports each reproduced twice in pristine fixtures,
separate bounded processes, closed stdin/no TTY, isolated absolute
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no inherited
BEA_FILE/BEA_TOKEN.

Create `/absolute/qa/main.bean`:

```beancount
plugin "beancount.plugins.implicit_prices"
option "operating_currency" "USD"
2024-01-01 open Assets:EUR EUR
2024-01-01 open Assets:USD USD
2024-01-01 open Equity:Opening
2024-01-02 * "Opening"
  Assets:EUR 1000 EUR
  Equity:Opening -1000 EUR
2024-01-05 * "Exchange"
  Assets:USD 100 USD @ 0.80 EUR
  Assets:EUR -80 EUR
```

Create a synthetic `quotes.txt` and `importers.py`:

```python
from datetime import date
from decimal import Decimal
from beancount.core.data import Price, new_metadata
from beancount.core.amount import Amount

class Quotes:
    def identify(self, file): return str(file).endswith('.txt')
    def account(self, file): return 'Assets:EUR'
    def extract(self, file, existing_entries=None):
        return [Price(new_metadata(file, 1), date(2024, 1, 5), 'EUR',
                      Amount(Decimal('1.20'), 'USD'))]

CONFIG = [Quotes()]
```

From `/absolute/qa` with the environment above:

```sh
bea --json -f /absolute/qa/main.bean check
bea --json --no-input -f /absolute/qa/main.bean import quotes.txt --config importers.py --apply
bea --json -f /absolute/qa/main.bean query "SELECT getprice('EUR','USD',2024-01-05) LIMIT 1"
bea --json -f /absolute/qa/main.bean query "SELECT convert(sum(position),'USD',2024-01-05) WHERE account ~ '^Assets:'"
bea --json -f /absolute/qa/main.bean check
```

All exit 0. Import calls the row `new`, writes 1, and reports
`validation_warnings: []`; its only note identifies the importer config.
The file contains `2024-01-05 price EUR 1.20 USD`. Fresh queries nevertheless
return rate **1.25** and asset value **1250.00 USD**, because the implied
USD→EUR 0.80 still determines the reverse direction. An operator expecting
the imported rate would calculate `920 EUR × 1.20 + 100 USD = 1204 USD`.
The issue is the absent explanation of the existing settlement rule.

Human import, in a separate pristine fixture, likewise writes the visible
1.20 quote and says `Wrote 1 entry`; stderr only identifies the config.
There is no unused-quote warning in either stream.

Controls, twice each:

- On the original ledger, use `bea --json -f /absolute/qa/main.bean add price
  --date 2024-01-05 --currency EUR --amount '1.20 USD'`. It writes 1 and
  warns that the USD 0.80 EUR price is implied at `main.bean:9`, that every
  read keeps using it, and that the new quote is never used. Queries agree
  with the warning: 1.25 and 1250 USD.
- Remove only the implicit-prices plugin and perform the import: it writes
  1, the rate becomes 1.20 and assets value at 1204 USD. No warning is needed.

Cause: `cli/src/bea_engine/importing.py:650–693` checks only recorded quotes
from `_own_quotes` (:1471–1490), deliberately excluding generated ones, and
adds an accepted price without evaluating the generated winner. That is
correct for deciding whether to write, but no advisory check follows.
`ledger/adding.py:978–1037` already simulates quote settlement with
`settle_price_days` and appends the relevant generated-winner warning.
The import frontend renders `validation_warnings` at
`cli/src/cli/commands/import_.py:1650`, but receives none for this case.

Fix: surface the same effective-price advisory for accepted imported quotes,
including the generated winner's location and rate. Judge the complete
candidate quote set, because several rows can change which direction wins;
do not blindly evaluate each row against the pre-import set. Keep writing
valid source quotes, preserve recorded-price conflicts and exact duplicates,
and avoid warnings when the incoming rate is actually effective. Do not
turn the generated quote into an exact duplicate or change price settlement.
