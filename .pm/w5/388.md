# `bea treeify --filler ''` crashes with `ZeroDivisionError` (exit 1)

**Trivial · cli · 5m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
`--filler` is passed to upstream unchanged, and upstream divides by its
length. No product fix implemented.

Use any ledger with postings, and isolated BEA_CONFIG_DIR/XDG_CACHE_HOME
with closed stdin.

```sh
bea -f /absolute/books/main.bean query "SELECT account, sum(position) GROUP BY account" > bal.txt
bea treeify bal.txt --filler ''
```

Actual: exit 1 with `Error: treeify failed (exit 1): ZeroDivisionError:
integer division or modulo by zero`. Reproduced three times by the
hunter and once by me.

Control: `--filler .` exits 0.

Expected: exit 2 naming `--filler` (it needs at least one character),
with no exception class, per w5/239's rule for empty values.

Cause: `cli/src/cli/commands/treeify.py:56` and `:67` forward the value.
Upstream `beancount/tools/treeify.py:387` computes `args.filler * (left
// len(args.filler) + 1)`.

Fix: refuse an empty `--filler` with `UsageError` in `treeify()`. No
dependency change.

Dedupe: searched `.pm/**`, including `done/`, for `filler` and
`ZeroDivisionError`. There are no hits. 352 covers treeify path errors.

Acceptance: `--filler ''` exits 2 naming the option. A test pins it.
