# `{100 # USD}` or `{# USD}` beside an omitted amount crashes `add transaction` with a raw `AttributeError: type object 'MISSING' has no attribute 'copy_sign'`

**Minor · cli · 5m · A1.** Real CLI QA, 2026-10-17, HEAD `0f2118d8e`, checkout `bea 0.3.1`, macOS 26.5.1.
No product fix implemented.

```sh
bea --file /abs/main.bean add transaction Buy --date 2026-02-01 -p 'Assets:Brokerage 2 HOOL {100 # USD}' -p 'Assets:Cash'
```

Actual: exit 1, `Error: AttributeError: type object 'MISSING' has no attribute
'copy_sign'. Pass --debug before the command for a traceback.`. `--json` gives
category `validation` with the same text, and the file is unchanged. `{#
USD}`, `{100 # USD, 2026-01-01}`, and the same with `@ 120 USD` crash the same
way (hunter's runs).

Control: with an explicit `Assets:Cash -200 USD`, `{# USD}` gets the clean
"Too many missing numbers for currency group 'USD'" refusal, which is what
Beancount and `bea check` say for the hand-written equivalent.

Expected: that same readable refusal, naming the posting.

Cause: `_inferred_leg_is_zero` (`cli/src/bea_engine/ledger/adding.py:970`, around
`:994-999`) checks `cost.number_total is None`. MISSING is not None, so it
calls `.copy_sign` on the sentinel.

Fix: treat MISSING per-unit and total numbers as unknowable, and let
validation report Beancount's reason.

Dedupe: w5/732 (open) is a raw error from upstream booking, a different
cause.

Acceptance: the command exits 1 with "Too many missing numbers…". A test pins
it.
