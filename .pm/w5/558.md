# `bea query`'s regex pre-check reads `~ '…'` inside comments and string literals, so valid queries are refused (exit 2) in `--file`, `--json` and `--source`

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `7898f69d`, checkout `bea 0.3.1`, macOS 26.5.1. Differential run against upstream `bean-query`.
The pre-check that refuses invalid patterns and POSIX classes in `~`/`!~`
operands scans the raw query text. A commented-out condition, or a string
literal containing ` ~ '`, is treated as a pattern. USAGE already treats
comments and quotes as non-code for the one-statement rule ("semicolons
inside quotes or comments are not second statements"). No product fix
implemented.

`rx.bean`:

```beancount
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Rent USD
2026-01-05 * "Landlord" "Rent (January)"
  Expenses:Rent  1500.00 USD
  Assets:Cash
```

```sh
bea --file /abs/rx.bean query "SELECT date, narration /* was: narration ~ 'Rent (' */ WHERE account ~ 'Rent'"
bea --file /abs/rx.bean --json query "SELECT date, narration WHERE narration != \"a ~ '[\" AND account ~ 'Rent'"
bea query --source /abs/rx.bean "SELECT date, narration WHERE account ~ 'Rent' /* ~ '[[:alpha:]]' */"
```

Actual: all exit 2: `'Rent (' is not a valid regular expression: missing ),
unterminated subpattern at position 5.`; `'[\" AND account ~ ' is not a valid
regular expression` (a "pattern" spliced across two literals); and the
POSIX-class refusal for text in a comment.

Control: `bean-query` runs all three (exit 0, `2026-01-05  Rent
(January)`); the first query without the comment runs in bea.

Expected: comments and string literals are ignored when finding regex
operands.

Cause: `_PATTERN_LITERAL` (`cli/src/bea_engine/query.py:1732`) is matched
against the raw statement (`:1570`); `_code_mask` (`:54`) already blanks
comments and literals for other checks.

Fix: locate `~`/`!~` operators in the code mask, then read the literal that
follows from the original text at that offset.

Dedupe: searched `PATTERN_LITERAL`, `not a valid regular expression`. w5/509
(open) is about regex functions, a different gap.

Acceptance: the three queries answer like `bean-query`. A test pins them.
