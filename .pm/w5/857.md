# Importer-shape guidance still proposes an Adapter that crashes, and malformed CONFIG/extract results escape as bare AttributeError or TypeError (gaps in w5/639)

**Trivial · cli · 20–30m · A1.** Real CLI QA, 2026-10-17, HEAD `8e35a3636`, checkout `bea 0.3.1`, macOS 26.5.1. Each case reproduced twice with isolated config/cache and fresh synthetic ledgers, stdin closed, no TTY. No product fix implemented.

Use [855](./855.md)'s importer setup with a valid transaction: Checking −5 USD, an opened `Expenses:Food` +5 USD. Preview with:

```sh
bea --file /abs/main.bean import /abs/bank.txt --config /abs/imp.py
```

1. Remove `@property` from the modern `Bank(beangulp.Importer)` class's `name` method. Exit 2 says `CONFIG entry Bank is a Beancount v2 importer ... wrap it as beangulp.Adapter(Bank(...))`. Following that advice with `CONFIG = [beangulp.Adapter(Bank())]` exits 1: `Importer failed (AssertionError): .` The class is a modern importer with one incorrectly declared property; the working remedy is to add `@property`.
2. Keep the valid importer and change `CONFIG` to `[Bank(), None]`, `[lambda: Bank()]` or `["bank"]`. All exit 1 with `Importer failed (AttributeError): 'NoneType'/'function'/'str' object has no attribute 'identify'`, naming no CONFIG position or useful remedy. A bad unused entry blocks the working importer beside it.
3. Keep the valid CONFIG but have `extract()` return `0`. Exit 1 says `Importer failed (TypeError): 'int' object is not iterable`, rather than naming the importer, returned type and list requirement.

Control: `CONFIG = [Bank()]`, a name property and a list containing the valid transaction previews one ready row at exit 0. All failing and control previews preserve the ledger's hash.

Expected: each refusal names the CONFIG entry or importer and an actionable remedy. For (1), suggest a name property for a modern importer; suggest Adapter only for an actual legacy ImporterProtocol it accepts. For (2), refuse the malformed entry with exit 2 before calling importer methods; identify missing callable identify/account/extract methods and call a listed factory if that was intended. For (3), use `_extracted`'s existing exit-1 `extract() returned a ... instead of a list of Beancount directives` wording.

Cause: `_name` (`cli/src/bea_engine/importing.py:1003`) equates every callable name with a legacy importer and otherwise does not validate the instance's interface. `_importer` calls `identify` after `_selectors` accepts the entry. `_extracted` (`:842`, used by both extraction paths) excludes selected wrong shapes but lets `list(0)` raise. Beangulp's Adapter checks for ImporterProtocol, so it cannot repair case 1.

Dedupe: whole-board searches for Adapter, CONFIG entry, missing identify and not-iterable found the completed w5/639 and w5/319 parents, not these shapes. History: `b969c471c` and `0e202213`.

Acceptance: a modern method-name importer gets a remedy that works; malformed CONFIG entries name their position/type and missing interface; an integer result names the importer and return requirement. Valid modern and Adapter-wrapped legacy importers still work, including a valid importer next to an unrelated valid importer.
