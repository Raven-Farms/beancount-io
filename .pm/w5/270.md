# Under `--json`, plugin output is discarded, although the docs say it goes to stderr

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Owner call: may be deliberate.
A ledger plugin that prints (to stdout or to stderr) is shown on stderr in
text mode. Under `--json` the same output appears nowhere. The JSON on
stdout is clean, which is the important half; but the documented
destination for plugin text is stderr, and a failing plugin's diagnostics
vanish from automated runs. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
option "insert_pythonpath" "TRUE"
plugin "noisy"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
2026-01-02 * "x"
  Expenses:Food  1.00 USD
  Assets:Cash
```

and `/absolute/books/noisy.py`:

```python
import sys
__plugins__ = ["noisy"]
def noisy(entries, options_map, config=None):
    print("PLUGIN-PRINT"); sys.stdout.flush()
    sys.stderr.write("PLUGIN-STDERR\n")
    return entries, []
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea --json -f main.bean balance
bea -f main.bean balance
```

Actual: the `--json` run exits 0 with a clean envelope on stdout and empty
stderr; neither marker appears. The text run prints both markers on
stderr.

Expected: `docs/USAGE.md`: "What they print … never reaches bea's machine
output: plugin output goes to stderr". w1/done/061's acceptance says
"parseable JSON, plugin text on stderr".

Cause: `cli/src/cli/engine/launch.py:353-354` forwards helper stderr
through `output.note`, which does nothing in JSON mode
(`cli/src/cli/output.py:53-56`).

Fix: print captured helper stderr in JSON mode when the command succeeds,
or say in the docs that `--json` suppresses plugin text (JSON-mode stderr
may be meant to carry only the error object). No dependency change.

Blast radius: every helper-path command under `--json` on ledgers with
plugins that print.

Dedupe: board search for "plugin output" and "descriptor 1" finds
w1/done/061 (envelope corruption) and w5/143 (importer output lost on
raise); nothing covers discarded plugin text.

Related cases (a worker's observations, 2026-10-12, not re-run): the same
dropped-stderr mechanism makes `bea --json query ".set nosuch 1"` exit 0
with `{"text": ""}` and nothing on stderr (text mode prints `error:
variable "nosuch" does not exist`; see also 236), and `bea --json query
--allow-errors ".errors"` return empty text on a broken ledger.

Acceptance: the `--json` run shows both markers on stderr with stdout
unchanged, or the docs state the suppression. Only macOS and the checkout
were exercised.
