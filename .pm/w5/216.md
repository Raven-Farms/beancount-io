# `bea check` fails a valid ledger whose `option "documents"` folder is outside the ledger directory, once per file, at line 0, with a remedy that does not apply

**Minor · cli · 30–40m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A ledger that keeps statements in a sibling folder
(`option "documents" "../statements"`) passes stock `bean-check` and works
with every other `bea` command, but can never pass `bea check`. The
diagnostic is the one written for `document` directives: it blames
`main.bean:0`, prints the absolute path twice, tells the user to "use a
relative path" when the only path they wrote is relative, and repeats for
every file found. No product fix implemented.

Create disposable `/absolute/f1/books/main.bean`:

```beancount
option "operating_currency" "USD"
option "documents" "../statements"
2026-01-01 open Assets:Checking USD
2026-01-01 open Equity:Opening
2026-01-01 * "open"
  Assets:Checking  100.00 USD
  Equity:Opening
```

Add any bytes as
`/absolute/f1/statements/Assets/Checking/2026-01-31.statement.pdf` and
`…/2026-02-28.statement.pdf`. Control: `/absolute/f1/books/control.bean`,
the same text with `option "documents" "docs"`, and
`/absolute/f1/books/docs/Assets/Checking/2026-01-31.statement.pdf`.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/f1`.

```sh
bea -f /absolute/f1/books/main.bean check
bea -f /absolute/f1/books/main.bean balance
```

Actual: `check` exits 1; `balance` exits 0.

```text
Error: /absolute/f1/books/main.bean: 2 portable-document warning(s).
  /absolute/f1/books/main.bean:0: Document path '/absolute/f1/statements/Assets/Checking/2026-01-31.statement.pdf' resolves to '/absolute/f1/statements/Assets/Checking/2026-01-31.statement.pdf', outside the ledger directory /absolute/f1/books. Move the file under the ledger directory and use a relative path so copies stay portable.
  (the same for 2026-02-28)
```

Stock `bean-check main.bean` exits 0 silently. A worker saw `add note`
succeed on the same ledger and `--json check` report category
`validation`.

Control: `control.bean` (folder inside the ledger directory) passes
`bea check`.

Expected: `docs/USAGE.md`: "`add document` takes a relative path that stays
inside the root ledger's directory … and `bea check` reports any document
that resolves outside that directory, quoting the path as written." That
rule is about `document` directives. Here there is no directive and no
written path: Beancount discovered the files from the option. Whether an
out-of-tree documents folder should fail `check` is the owner's call; if it
does, it should be one diagnostic that names the `option "documents"` line
and its value, with a remedy that fits an option.

Cause: `cli/src/bea_engine/main.py:811-828` (`_validate`) applies the
out-of-tree test to every `Document` entry. Entries Beancount generates
from the option carry line 0 of the ledger file, so
`_written_document_path` (`main.py:778-792`) finds nothing and the message
falls back to the absolute file name and `file:0`.

Fix: treat option-discovered documents separately: exempt them, or emit one
diagnostic naming the option line and the resolved folder. Directive-level
behaviour is unchanged. No dependency or API change.

Blast radius: `bea check` only, text and JSON. An absolute documents folder
outside the tree takes the same path (not run).

Dedupe: board search for `portable-document`, "outside the ledger
directory" and `option "documents"` finds w3/done/351 (introduced the check
for directive paths) and w1/done/165 (`add document ../`); neither covers
the option or generated documents.

Acceptance: on the fixture `bea check` either exits 0, or exits 1 with a
single line that names `option "documents" "../statements"` at its real
line; no `:0` location and no per-file repetition. A `document` directive
with an out-of-tree path is still reported as today. Only macOS and the
checkout were exercised.
