# A proxy that refuses the CONNECT tunnel (407) makes `cloud ledger create`/`delete` exit 4 "outcome unknown", though nothing reached the API (gap in w5/368)

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `d16aea3e`, checkout `bea 0.3.1`, macOS 26.5.1. Simulation: a local proxy stub answers every CONNECT with 407.
USAGE: "A write that never connected (a refused connection, a failed DNS
lookup, a connect timeout) sent nothing, so it exits **1** with `Could not
reach the server (…)`." A refused HTTPS tunnel is the same case: the request
never left the proxy. w5/368 exempts only `ConnectError` and
`ConnectTimeout`. `httpx.ProxyError` is a `TransportError` sibling, so it
falls into the unknown-outcome branch, which tells the user to check state
they cannot reach. No product fix implemented.

```sh
HTTPS_PROXY=http://127.0.0.1:<proxy> NO_PROXY= BEA_API_URL=https://api.qa.invalid bea --json cloud ledger create newbook
HTTPS_PROXY=http://127.0.0.1:<proxy> NO_PROXY= BEA_API_URL=https://api.qa.invalid bea -y cloud ledger delete qa/books
```

Actual: both exit 4, `Creating ledger 'newbook' did not complete cleanly
(ProxyError). The outcome is unknown — check the current state before
retrying.` The proxy log shows only `CONNECT api.qa.invalid:443`. `cloud
ledger show` through the same proxy exits 1 with `Could not reach the server
(ProxyError).`

Expected: exit 1 with `Could not reach the server (ProxyError).`, like the
read.

Cause: the never-connected tuple `(httpx.ConnectError, httpx.ConnectTimeout)`
at `cli/src/cli/commands/cloud/ledger/app.py:78` and
`cli/scripts/gen_cloud_commands.py:209` (→ `generated/ledger.py:97`).

Fix: add `httpx.ProxyError` to the tuple in both places and regenerate.
Check `cloud logout`'s classification (w5/521).

Dedupe: no `.pm` match for `ProxyError`; w5/368 (done) is the fix this
extends.

Acceptance: both writes exit 1 under a refusing proxy. A test pins it.
