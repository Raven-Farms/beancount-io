# Import crashes on an importer row whose counter-posting has no amount

**Major · cli · 20–30m · A1.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, macOS. A Python importer may leave the
categorized leg of a transaction without an amount, as Beancount allows. When
that leg's account is unopened or its `open` restricts currencies, `bea
import` stops with a raw `AttributeError` instead of the blocked-row remedy or
a normal preview. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"

2026-01-01 open Assets:Checking USD
2026-01-01 open Liabilities:Card USD
2026-01-01 open Expenses:Food
2026-01-01 open Expenses:Uncategorized
2026-01-01 open Equity:Opening

2026-01-02 * "Opening balance"
  Assets:Checking  1000.00 USD
  Equity:Opening
```

`/absolute/books/imp.py`, a configuration you wrote and inspected:

```python
import csv, datetime
from decimal import Decimal
from beancount.core.amount import Amount
from beancount.core.data import Posting, Transaction, new_metadata

class Elided:
    name = "elided"
    def identify(self, filepath): return filepath.endswith(".csv")
    def account(self, filepath): return "Assets:Checking"
    def extract(self, filepath, existing):
        out = []
        with open(filepath, newline="") as s:
            for line, row in enumerate(csv.DictReader(s), start=2):
                out.append(Transaction(
                    new_metadata(filepath, line), datetime.date.fromisoformat(row["Date"]),
                    "*", None, row["Desc"], frozenset(), frozenset(), [
                        Posting("Assets:Checking", Amount(Decimal(row["Amount"]), "USD"), None, None, None, None),
                        Posting(row["Cat"], None, None, None, None, None),
                    ]))
        return out
CONFIG = [Elided()]
```

and three one-row exports with the header `Date,Desc,Amount,Cat`:
`restricted.csv` (`2026-01-05,Pay card,-12.00,Liabilities:Card`),
`unopened.csv` (the same row with `Expenses:Dining`) and `ok.csv` (with
`Expenses:Food`).

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`, and
a fresh configuration directory so no mapping is remembered.

```sh
bea -f /absolute/books/main.bean import restricted.csv --config imp.py
bea -f /absolute/books/main.bean import unopened.csv --config imp.py
```

Actual: both exit 1 with

```text
Error: AttributeError: 'NoneType' object has no attribute 'currency' Pass --debug before the command for a traceback.
```

`--json` reports category `validation`. The ledger is unchanged. Repeated
twice.

Control: `ok.csv`, whose counter account is open with no currency list,
previews `1 ready`, applies, and `bea check` exits 0.

Expected: `docs/IMPORTING.md` requires explicit amounts only "on
source-account postings". The restricted row is a valid transaction — the
missing leg interpolates to 12.00 USD, a currency `Liabilities:Card` allows —
and should preview as `new`. The unopened row should be `blocked`, naming
the account and the `bea add open` line that fixes it, as the guide describes
for every row "that would post to an account the ledger never opened".

Cause: `cli/src/bea_engine/importing.py:693` builds the remedy with
`next(p.units.currency for p in entry.postings if p.account == name)` and
`:705` tests `posting.units.currency not in allowed`; both dereference
`units` on a posting whose amount the importer left for Beancount to infer.

Fix: for a posting with no units, judge the currency Beancount will infer —
the transaction's single other currency — or skip the restriction test when
that cannot be determined before booking and let validation report it. For an
unopened account reached only through such a posting, emit the remedy with
that inferred currency, or without `-c` when it is ambiguous. The CSV mapper
always writes explicit amounts and is unaffected. No dependency or API change.

Dedupe: board search for elided postings, `units.currency`, `AttributeError`
and blocked rows finds w1/012 (zero versus missing source amounts) and
w1/m24/t008 (which introduced blocked rows); neither covers an amountless
counter-posting.

Acceptance: `restricted.csv` previews and applies with `bea check` at exit
0; `unopened.csv` is `blocked` with a remedy that, once run, lets the import
apply; `ok.csv` is unchanged; a two-currency transaction with an amountless
leg reports a normal validation error. Real-command regression tests use an
inspected local importer. Only macOS and the checkout were exercised.
