# Decimal-comma and tag messages after w5/534: `1.234,56` and bulk `amount` strings still get raw parser text, and the tag/link refusal says "after an optional leading # or ^" while refusing `--tag '^x'`, and quotes `##c` as `'#c'` (incomplete fix of w5/534)

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-17, HEAD `cc6b52ed`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/534 (done, `6eacc6f0`).
No product fix implemented.

`main.bean` opens `Assets:Checking EUR` and `Expenses:Food EUR`.

1. **`1.234,56`, the most common European spelling.**
   - `bea -f /abs/main.bean add transaction y --date 2026-02-01 -p
     'Expenses:Food 1.234,56 EUR' -p Assets:Checking` exits 2 with
     `--posting 1: syntax error, unexpected COMMA, expecting end of file or EOL
     or ATAT or AT`.
   - `add balance --amount '1.234,56 EUR'` gives `--amount: syntax error,
     unexpected COMMA` (hunter's run).
2. **Bulk rows.** `add transactions --from b.json` with `"amount": "4,50 EUR"`
   exits 1 with `Row 1, postings.0: Value error, Could not parse amount '4,50
   EUR' as a posting fragment: ValueError: Invalid number format: '4,50'.`
3. **Tags and links.**
   - `--tag '^a2'` and `--link '#x'` (and bulk `"links": ["#x"]`) are refused
     with `'^a2' is not one tag or link; use only ASCII letters, digits and -
     _ / . after an optional leading # or ^ …`.
   - `--tag '##c'` is quoted back as `'#c'`.
   - Control: `list transaction --tag '^a2'` names only its own sigil and
     quotes the input verbatim.

Control: `-p 'Expenses:Food 4,50 EUR'`, `add price --amount '1.234,56 EUR'` and
`add custom --value 'amount:1.234,56 EUR'` get the shared `Invalid amount
'4,50'. A comma is read only as a thousands separator…` sentence.

Expected: the shared decimal-comma sentence for every amount input, and a tag
(or link) message that names only that option's sigil and quotes the typed
value.

Cause:
- `readable_parser_message` (`cli/src/bea_engine/query.py:2146`) matches only
  `Invalid number format: '…,…'`. The lexer reports `1.234,56` as
  `unexpected COMMA`.
- `_posting_fragment` (`cli/src/bea_engine/ledger/models.py:235`) relays the
  raw message.
- `require_tag_or_link` (`cli/src/bea_engine/ledger/text.py:195`) has one
  message for both kinds and runs after the sigil is stripped.

Fix:
- Route the fragment refusal through `readable_parser_message`, and map
  `unexpected COMMA` after a number to the comma help.
- Word the tag and link messages separately, quoting the original input.

Dedupe: w5/534 (done) is the parent; w3/226 and w5/265 cover CSV import.

Acceptance: the three amount inputs get the shared sentence; the tag cases
name the right sigil and the typed text.
