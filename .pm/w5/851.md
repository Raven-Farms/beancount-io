# Two more `CONFIG = [...]` modules get past `bea ingest`'s refusal and exit 0 having written nothing: one saved with a UTF-8 BOM, and one binding `CONFIG` by `from myimps import *` (incomplete fix of w5/635)

**Minor · cli · 5–10m · A1.** Real CLI QA, 2026-10-17, HEAD `3295e9a3d`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/635 (done), whose addendum case (a commented `Ingest(`) is now fixed.
USAGE says a `CONFIG = [...]` import module is refused with exit 2 and pointed
at `bea import --config`. No product fix implemented.

`myimps.py` binds `CONFIG = [Base([...])]` from a small `base.py` importer.
`bom.py` is the same bytes with a UTF-8 BOM, and `star.py` is `from myimps
import *`.

```sh
bea -f /abs/main.bean ingest extract --config /abs/bom.py /abs/dl -o /abs/out_bom.bean
bea -f /abs/main.bean ingest extract --config /abs/star.py /abs/dl -o /abs/out_star.bean
```

Actual: both exit 0 with empty output, and no `out_*.bean` is created. `bea
import dl/bank.txt --config star.py` reads the star module fine (`1 ready`).

Control: `myimps.py` itself is refused with exit 2 and the pointer.

Expected: exit 2 with the pointer for both.

Cause: `cli/src/cli/commands/ingest.py` (around `:180-183`) reads the module as
`utf-8`, keeping U+FEFF, so `ast.parse` raises `SyntaxError` and the check
gives up. `_binds_config` (around `:222`) matches only the alias name `CONFIG`,
not `*`.

Fix: parse with `ast.parse(script.read_bytes())` (or decode `utf-8-sig`), and
treat `from X import *` as binding `CONFIG` when sibling `X.py` binds it.

Dedupe: w5/635 and 167 (done) are the parents; w5/704 and 710 cover BOMs
elsewhere.

Acceptance: both commands exit 2 with the pointer.
