# Every write fails with a raw `PermissionError` reported as validation when the lock directory cannot be created

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `0227141a` (CLI unchanged since `97600b74`),
checkout `bea 0.3.1`, macOS.
Writers take a lock under `XDG_CACHE_HOME`. When that directory is
read-only — a locked-down home, a sandboxed agent — `add`, `import
--apply` and `format -i` all fail with a Python exception name, exit 1 and
JSON category `validation`, the code that means the ledger is broken. No
product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
```

and an empty directory `/absolute/ro` with mode 555. Use isolated
BEA_CONFIG_DIR, BEA_NO_UPDATE_NOTIFIER=1, `XDG_CACHE_HOME=/absolute/ro`,
closed stdin, no TTY:

```sh
bea -f /absolute/books/main.bean add transaction N --date 2024-02-01 -p 'Expenses:Food 5.00 USD' -p Assets:Cash
bea --json -f /absolute/books/main.bean add open --account Assets:New --date 2024-01-01
```

Actual: the first exits 1 with `Error: PermissionError: [Errno 13]
Permission denied: '/absolute/ro/bea' Pass --debug before the command for a
traceback.` The second exits 1 with `{"error": {"category": "validation",
"message": "PermissionError: [Errno 13] …", "exit_code": 1}}`. The ledger is
unchanged. A worker saw `format -i` fail the same way, and
`NotADirectoryError` / `FileExistsError` when the cache path or
`bea/locks` is a regular file.

Control: `bea -f … check` with the read-only cache exits 0. The same
`add transaction` with a writable `XDG_CACHE_HOME` exits 0.

Expected: `docs/USAGE.md` assigns exit 3 to "Authentication or permission
failure", and w1/073 moved staging and replace refusals to exit 3 "instead of
a raw `Errno 13` reported as validation". This is the same class: exit 3,
category `permission`, a message naming the lock directory and the remedy
(make it writable or set `XDG_CACHE_HOME`), and no exception name.

Cause: `cli/src/bea_engine/ledger/write.py:323-326` (`lock_file`) creates
the directory and opens the lock file with no `OSError` handling, so the
exception reaches the generic wrapper.

Fix: map an `OSError` from lock-directory creation or lock-file open onto
the existing exit-3 "not writable … Nothing was written" error. No dependency
or API change.

Blast radius: every writer through `lock_files` — `add`, `import
--apply`, `format -i`.

Dedupe: board search for `bea/locks`, `XDG_CACHE_HOME` and `Errno 13`
finds w5/090 (`init DIR` and `format -o` destinations), w1/073 (read-only
include directory) and w5/095 (reads needing a writable ledger directory);
none names the lock directory.

Acceptance: both commands exit 3 with category `permission` and a message
naming the lock directory, in text and JSON, for a read-only cache root, a
cache root that is a file, and `bea/locks` being a file; the ledger stays
byte-identical. Only macOS and the checkout were exercised.
