# `price export` of a feed included from two files writes a snapshot that fails `bean-check`

**Minor · cli · 30–40m · A1.** Real CLI QA, 2026-10-10, HEAD `97600b74`,
checkout `bea 0.3.1`, macOS. A ledger may include the same managed price feed
from more than one file; loading keeps the first and ignores repeats. The
exported snapshot rewrites every occurrence to the same local feed file, and
Beancount refuses a file included twice, so the "self-contained copy for stock
tools" does not load. The export itself exits 0. No product fix implemented.

The feed was a **simulation**: a loopback HTTP server allowlisted through the
documented `MANAGED_PRICE_ORIGINS` variable served two synthetic BTC/USD price
lines; no Beancount.io endpoint was contacted and no credential was used. The
rewrite under test is local and does not depend on the origin.

Disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Wallet BTC
2026-01-01 open Equity:Opening
include "http://127.0.0.1:18765/prices/BTC-USD"
include "y/2026.bean"
```

and `/absolute/books/y/2026.bean`:

```beancount
include "http://127.0.0.1:18765/prices/BTC-USD"
2026-01-02 * "Open"
  Assets:Wallet  2 BTC {50000 USD}
  Equity:Opening
```

With isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1,
`MANAGED_PRICE_ORIGINS=http://127.0.0.1:18765`, closed stdin, no TTY:

```sh
bea -f /absolute/books/main.bean check
bea -f /absolute/books/main.bean price export --output /absolute/books/out
bea -f /absolute/books/out/main.bean check
```

Actual: `check` exits 0. The export exits 0 with `Exported 3 files to
/absolute/books/out.` `out/main.bean` carries
`include "prices/BTC-USD.beancount"` and `out/y/2026.bean` carries
`include "../prices/BTC-USD.beancount"`. Checking the snapshot exits 1 with
`<load>:0: Duplicate filename parsed:
"/absolute/books/out/prices/BTC-USD.beancount"`. A worker saw stock
`bean-check` fail the same way.

Control: with the include line removed from `y/2026.bean`, the same three
commands exit 0, 0, 0.

Expected: `docs/USAGE.md` says "`price export` snapshots a self-contained copy
for stock tools", and the loader promises that the same URL included twice
never multiplies entries (`managed_load.py` `_rewrite_includes`). A source
ledger that passes `bea check` should export to a snapshot that passes too.

Cause: `cli/src/bea_engine/managed_load.py:783-785` maps every include of a
URL to the one feed file, and `_rewrite_export_includes` (`:983-988`) rewrites
each occurrence to it. The load path (`:555-562`) keeps the first occurrence
and swaps repeats for a placeholder comment.

Fix: in the export rewrite, keep the first include per URL across the whole
closure and replace later ones with a comment line, preserving line counts as
the load path does. No dependency or API change.

Blast radius: any export where one URL appears more than once, including
twice in the root. The marker-only export under `--allow-errors` shares the
rewrite and was not run.

Dedupe: board search for duplicate filename, included twice and repeated feed
include finds w3/413 (a local file colliding with the generated feed name),
w5/058 (symlink aliases) and w5/094 (local plugin on export); none covers a
repeated feed include.

Acceptance: the fixture's snapshot passes `bea check` and stock `bean-check`,
lists each feed price once, and keeps every non-include line at its original
line number; the single-include control is byte-identical to today. A
real-command regression test exports from a seeded offline cache with the URL
in the root twice and in a child. Only macOS and the checkout were exercised,
against a simulated feed.
