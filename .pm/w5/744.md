# `bea ask`'s BQL tool: a query containing a NUL kills the whole question with "embedded null byte" (exit 1), losing the "already wrote" note in a session; and a query starting with `-` is parsed as an engine option, so the model gets the engine's usage text (gap in w5/549)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `15b5e52f4`, checkout `bea 0.3.1`, macOS 26.5.1. Simulation: a local AI-proxy stub with a fake token. Follow-up to w5/549 (done, `383ded4fe`).
w5/549 made tool failures go back to the model with the engine's details.
USAGE:1807-1809 says a turn that fails after an approved write names what it
wrote. No product fix implemented.

1. **NUL.**
   - The stub's first reply calls `run_bql_query` with `SELECT account WHERE
     payee = "a\u0000b"`.
   - `bea -f /abs/main.bean ask q --print` exits 1 with `Error: embedded null
     byte. Pass --debug before the command for a traceback.` after one
     request, so the model never sees a tool result.
   - In a session after an approved `write_directive`, the same failure
     prints with no `Note: This question had already written 1 directive(s)`,
     though the write landed (hunter's run).
2. **Leading dash.**
   - A `run_bql_query` of `-- Food total\nSELECT account` returns this tool
     result to the model: `BQL error: The Beancount engine did not answer
     'bea-engine query --file … -- Food total …' (exit 2)`, followed by the
     engine's usage box and internal argv.
   - `--help` and `--version` behave the same (hunter's runs).
   - Control: the same query with a leading space gets the normal BQL syntax
     error and caret.

Expected: (1) a tool error returned to the model, and the session names the
earlier write. (2) The BQL error, as `bea query` gives.

Cause: `cli/src/cli/ask/agent.py:427` builds `["query", "--file", file, query,
"--format", "json"]`. A NUL makes `Popen` raise `ValueError`, and only
`BeaError` is caught. A dash-leading query is read as an option;
`cli/src/cli/commands/query.py` adds `--` for exactly this. The session's
generic failure path skips `_naming_writes` (`cli/src/cli/ask/repl.py`,
around `:341-347`).

Fix: put the query after `--`, refuse a NUL with `ModelRetry` (or pass the
query on stdin), and name earlier writes in every failure path.

Dedupe: w5/549 and 547 (done) are the parents; w5/503 and w1/155 fixed the
`--` case for `balance` and `query --source`.

Acceptance: both stub cases return a BQL error to the model, and the session
case names the earlier write. Tests pin both.
