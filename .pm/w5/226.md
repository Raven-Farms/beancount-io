# `--importer NAME` cannot choose between two instances of one importer class; the error lists the same name twice

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A config with `[Bank("Assets:Checking"), Bank("Assets:Savings")]`, the
ordinary way to reuse one importer for two accounts, cannot be used: both
instances have Beangulp's default name, shown as `<run_path>.Bank`, and
passing that name to `--importer` returns the same error. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"

2026-01-01 open Assets:Checking USD
2026-01-01 open Assets:Savings USD
2026-01-01 open Expenses:Food
2026-01-01 open Equity:Opening

2026-01-02 * "Opening balance"
  Assets:Checking  1000.00 USD
  Equity:Opening
```

`/absolute/books/imp.py`:

```python
import datetime
from decimal import Decimal as D
import beangulp
from beancount.core import data
from beancount.core.amount import Amount

class Bank(beangulp.Importer):
    def __init__(self, acct): self.acct = acct
    def identify(self, filepath): return filepath.endswith(".txt")
    def account(self, filepath): return self.acct
    def extract(self, filepath, existing):
        return [data.Transaction(data.new_metadata(filepath, 1), datetime.date(2026, 1, 5), "*", "Cafe", "Coffee", frozenset(), frozenset(), [
            data.Posting(self.acct, Amount(D("-5.25"), "USD"), None, None, None, None),
            data.Posting("Expenses:Food", Amount(D("5.25"), "USD"), None, None, None, None)])]

CONFIG = [Bank("Assets:Checking"), Bank("Assets:Savings")]
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.
`/absolute/books/stmt.txt` holds the single line `statement`.

```sh
bea -f main.bean import stmt.txt --config imp.py
bea -f main.bean import stmt.txt --config imp.py --importer '<run_path>.Bank' --apply
```

Actual: both exit 2, nothing written:

```text
Error: Multiple importers match; choose one with --importer.
  <run_path>.Bank
  <run_path>.Bank
```

Control: adding a `name` property returning `"bank-" +
self.acct.rsplit(":", 1)[1].lower()` lets `--importer bank-savings --apply`
exit 0 and post to `Assets:Savings`.

Expected: `docs/IMPORTING.md`: "If multiple importers recognize the export,
select one with `--importer NAME`." The advice must be followable, or the
message must say the names collide and how to make them distinct.

Cause: `cli/src/bea_engine/importing.py:511-521` filters by name, keeps
both matches, and raises the same error with the same advice.

Fix: when names collide, list each candidate with its `account()` and
accept a selector that distinguishes them (an index such as `NAME#2`, or
the account); at minimum say the names are identical and that each importer
needs a distinct `name`. No dependency change.

Blast radius: any config that instantiates one importer class more than
once for files both instances identify.

Dedupe: board search for "Multiple importers match", `run_path` and
`--importer` finds only w5/done/013 (a dependency error); nothing covers
identical names.

Acceptance: on the fixture the error distinguishes the two importers and
names a selector that works when used; the named control is unchanged.
Only macOS and the checkout were exercised.
