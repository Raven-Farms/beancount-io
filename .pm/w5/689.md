# `--offline` still lets forwarded `bea price` (bean-price) fetch quotes and `engine enable` download packages, and `-h`/`--help` given as an option value turns the cloud refusal off (incomplete fix of w5/515)

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-17, HEAD `b8d871d0`, checkout `bea 0.3.1`, macOS 26.5.1. Simulations: a fake engine with a logging `bean-price` shim; a `uv` shim; a local cloud stub. Follow-up to w5/515 (done).
`--offline` means "Never fetch" (help, USAGE:96). The w5/515 fix refuses it for
`bea cloud` and `bea ask`, and USAGE:96 now lists `price refresh`, `bea cloud`
and `bea ask` as refusing. Three paths still use the network, and the cloud
check can be bypassed. No product fix implemented.

1. **Forwarded `bea price`.** With `BEA_ENGINE_PYTHON` pointing at a fake engine
   whose `bin/bean-price` logs its argv, `bea --offline price -e
   USD:yahoo/AAPL` and `bea --offline price /abs/main.bean` exit 0, and the
   shim was called (with `MANAGED_PRICE_OFFLINE` unset). Real bean-price
   fetches quotes from the internet.
2. **`engine enable`.** `BEA_UV=<shim> BEA_ENGINE_DIR=<dir> bea --offline engine
   enable beanprice` runs `uv venv …` and `uv pip install --require-hashes
   --only-binary :all: -r …/engine-requirements.lock` without `--offline`. By
   code reading, `bea --offline upgrade` (`cli/src/cli/commands/upgrade.py:91`)
   would also run `brew upgrade bea` or `uv tool upgrade beancount-io`.
3. **Help token as a value.** With a local stub, `bea --offline cloud ledger
   create newbook -d -h` (also `-d --help`, and `-- -h` as the name) sends
   `POST /api-gateway/v1/ledgers {"name": "newbook", "description": "-h", …}`.
   `-d x` exits 2 with nothing sent.

Expected: each exits 2 before any network use (`… requires network access;
remove --offline.`), or USAGE names the exceptions; the help check
recognizes only a real help request.

Cause: no offline check in `cli/src/cli/commands/price.py:42-73` (forwarding),
`engine_enable` (`cli/src/cli/commands/engine.py:97`) or `upgrade`; the cloud
check (`cli/src/cli/commands/cloud/app.py:36`) is skipped when raw `sys.argv`
contains `-h`/`--help` anywhere.

Fix: add the refusal to the three commands (or pass `--offline` to `uv` for
`engine enable` where it can work from cache); detect help through Click's
parsing, or refuse inside `authenticated_client()`.

Dedupe: w5/515 (done) is the parent; w5/458 (update check) is related.

Acceptance: the five commands exit 2 with no network use. Tests (with shims
and a stub) pin them.

Addendum (CLI QA 2026-10-17, HEAD `46d7394e9`): first-use provisioning ignores
`--offline` too. On an installed wheel with no managed engine yet, `bea
--offline -f /abs/main.bean check` starts `Installing the Beancount engine
0.3.1 (one time)…`. With network access it downloads about 30 MB from PyPI
(hunter's run). Offline it attempts the install twice (w5/784). Help says
"`--offline` Never fetch". Fix: under `--offline`, refuse an unprovisioned
engine ("not installed; rerun without --offline with network access"), or
pass `UV_OFFLINE`. Otherwise narrow the help text.
