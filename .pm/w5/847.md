# `bea ask`'s approval panel shows a zero-width character in an AI-written account name invisibly, so approving it creates a lookalike `Assets:Cash` that splits the balance (security-relevant: hidden content in an approval)

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-17, HEAD `4bd8c6ec7`, checkout `bea 0.3.1`, macOS 26.5.1. Simulation: a local AI-proxy stub on 127.0.0.1 with a fake token, driven on a PTY.
The panel is the only gate between AI-proposed text and the user's books.
USAGE's ask section says what is on screen is what will be written, and the
repl docstring says nothing shown may hide content. No product fix
implemented.

The ledger opens `Assets:Cash`, `Expenses:Food` and `Equity:Opening`, with an
opening. The stub's reply calls `write_directive` with:

```
2024-01-01 open Assets:Ca<U+200B>sh USD
2024-01-20 * "Cafe" "Latte"
  Expenses:Food  5.00 USD
  Assets:Ca<U+200B>sh
```

Actual:
- In `bea -f /abs/main.bean ask`, the "Confirm AI write" panel shows
  `Assets:Ca​sh` with the U+200B written raw (invisible), with no escape and no
  "new account" note.
- Approving with `y` writes the bytes `Assets:Ca\xe2\x80\x8bsh`, and `check`
  passes.
- A balance query then lists `Assets:Cash 95.00 USD` and `Assets:Ca​sh -5.00 USD`
  as two identical-looking rows (hunter's run).
- U+200F, U+2060 and U+00AD are accepted the same way.

Control: ESC and U+202E in the same text are refused (`Write rejected: the
directive text contains the control character …`).

Expected: format characters are shown escaped (`\u200b`) on the panel, and
refused in account names the text opens or posts to unless the account
already exists. Ideally the panel also notes each new account the text opens.

Cause: `CONTROL_CHARACTERS` (`cli/src/bea_engine/ledger/text.py:28` and
`cli/src/cli/utils.py:23`) omits U+200B–U+200F, U+2060–U+2064, U+FEFF and
U+00AD. The panel's escaping and the ask append both use it, and the raw
append path never runs `parse_account`'s name checks.

Fix: extend the escape set for display, and check opened and posted account
names in the ask append.

Dedupe: w5/657 (open) covers the same characters on `bea add`; its fix does
not reach ask. w5/148 (done) left directional marks alone deliberately.

Acceptance: the panel shows `\u200b`, and the write is refused (or flagged)
before approval. A PTY test pins it.
