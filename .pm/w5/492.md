# `add --into` a new file whose directory does not exist exits 1 "validation" with staging-mechanism wording, instead of a usage refusal saying the directory must exist

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `7334a32b`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE says an absent `--into` destination "is created only when a validated
write succeeds; its parent directory must already exist". Breaking that
rule is a usage error: exit 2 with the rule stated. bea instead reports a
filesystem failure of its internal staged copy, as exit 1 `validation`. An
agent reading the category retries or reports a ledger problem. No product
fix implemented.

`main.bean` with `include "y/*/*.bean"` and an existing `y/a/a.bean`; no `y/b/`.

```sh
bea --json -f /abs/main.bean add event --date 2026-01-05 -t a -d b --into y/b/new.bean
```

Actual: exit 1, `{"error": {"category": "validation", "message": "Cannot
write a staged copy of new.bean in …/y/b (No such file or directory);
nothing was written.", "exit_code": 1}}`.

Expected: exit 2, `usage`, e.g. `--into y/b/new.bean: directory y/b does not
exist; create it first (bea creates only the file).` Nothing written.

Cause: the missing directory is first noticed when staging
(`_stage_failed`, `cli/src/bea_engine/ledger/write.py:970-979`); the `--into`
resolution never checks the parent.

Fix: check the destination's parent when resolving `--into` (frontend or
engine), before any staging, for every write that takes `--into`.

Dedupe: searched `staged copy`; w5/134, 257, 312 and 410 concern other
staging failures. Compare w3/270 for `query -o`.

Acceptance: the command exits 2 with the rule stated. A test pins it.
