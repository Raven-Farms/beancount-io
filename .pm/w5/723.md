# `bea treeify` input decoding gaps: a UTF-8 BOM splits the tree into a `﻿Assets` root and glues the amount to the name, and a pipe given by path (`/dev/stdin`, `<(…)`, a FIFO) still fails with the raw `UnicodeDecodeError` (incomplete fix of w5/535)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `cc6b52ed`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/535 (done, `0a8d0c43`).
No product fix implemented.

1. **BOM.** `bom.txt` is `EF BB BF` followed by `Assets:Cafe 10 EUR` and
   `Assets:Bank 5 EUR`. `bea treeify bom.txt` (and `bea treeify < bom.txt`)
   exits 0 with:

   ```
   |-- ﻿Assets
   |   `-- Cafe 10 EUR
   `-- Assets
       `-- Bank5 EUR
   ```

   That is an invisible second root, with the second row's amount joined to
   its name. Without the BOM, there is one `Assets` root with `Cafe 10 EUR`
   and `Bank 5 EUR`. This predates w5/535. `format -` reads with `utf-8-sig`.
2. **Pipe by path.** `t1.txt` is Latin-1 `Assets:Caf\xe9 10 EUR`. `cat t1.txt
   | bea treeify /dev/stdin` exits 1 with `Error: treeify failed (exit 1):
   UnicodeDecodeError: 'utf-8' codec can't decode byte 0xe9 in position 10…`.
   `<(cat t1.txt)` and a named FIFO do the same (hunter's runs). Control:
   `bea treeify t1.txt` exits 2 with `Cannot decode '…/t1.txt' as UTF-8:
   invalid continuation byte at byte 10. Re-save the file as UTF-8 and retry.`

Expected: a BOM is skipped as everywhere else in bea, and every non-UTF-8
input gets the exit-2 refusal.

Cause: `_check_input` (`cli/src/cli/commands/treeify.py:119-135`) decodes only
when `path.is_file()`, and `_require_utf8` (`:139`) uses plain `utf-8`. For a
regular file, upstream reads the raw bytes.

Fix: decode with `utf-8-sig` and pass the text to upstream for files, FIFOs
and held descriptors alike.

Dedupe: w5/535 (done) is the parent; w5/705 (open) covers `-`; w5/582 (open)
covers FIFOs for `import --rules`/`--config`.

Acceptance: the BOM fixture renders one root; `/dev/stdin` gets the exit-2
refusal.
