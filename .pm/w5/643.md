# `bea --strict-prices doctor roundtrip FILE` with a stale or unavailable managed source prints a 184-line traceback ending in `TypeError: stat: path should be string … not NoneType` instead of the strict-mode error

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `c0267f61`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE (doctor): for roundtrip an unavailable source is only printed, so "pass
`--strict-prices` to fail on one instead". Doing that raises bea's strict
error inside upstream's roundtrip. Upstream's `finally` then calls
`os.path.exists(None)`, and the `TypeError` replaces it. This is the same
upstream crash as open w5/572 (read-only directory), but w5/572's fix (a
writability pre-check) does not cover this path. No product fix implemented.

A ledger with one managed include and no cached revision.

```sh
bea --offline --strict-prices doctor roundtrip /abs/main.bean
bea --offline --strict-prices doctor missing-open /abs/main.bean
```

Actual: `roundtrip` exits 1 with 184 lines: `LedgerError: managed price source
… is unavailable in strict mode …`, "During handling of the above exception",
then `TypeError: stat: path should be string, bytes, os.PathLike or integer,
not NoneType`. A stale cached source gives the same. `missing-open` (and
print-options, display-context, context, linked, region) prints `error:
managed price source … is unavailable in strict mode: no cached revision.`,
exit 1.

Expected: roundtrip prints the same one-line strict error, exit 1.

Cause: `_invoke` (`cli/src/bea_engine/scoped.py:77-89`) catches only
`SystemExit` and `EngineError`; upstream roundtrip's `finally` turns the
error into a `TypeError`.

Fix: run the managed load with its strict and staging checks before invoking
upstream's roundtrip (or catch a `TypeError` whose `__context__` is an
`EngineError` and report that error). Fixing this together with w5/572 is
natural.

Dedupe: w5/572 (open) is the sibling.

Acceptance: both strict cases give the one-line error. A test pins it.
