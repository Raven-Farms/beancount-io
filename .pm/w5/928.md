# Recognize opened accounts from included files in CSV account validation

**Minor · cli · 45–60m · A1.** A valid split ledger can retain English-root
accounts in an include while its main file renames a root. CSV import refuses
those already-open accounts in `--account`, `--default-account` and rules;
a category naming one is treated as a label and posted to the fallback with
`!`. Manual transaction adds and Python imports into that same include work.
No product fix implemented.

Real CLI QA, 2026-10-21, HEAD `98751d3cd`, CLI sources unchanged after pulling
`f5e4d1cb2`. Checkout `bea 0.3.1`, macOS 26.5.1 arm64, frontend Python
3.13.3, existing managed Python 3.12 engine. Closed stdin/no TTY, fresh
processes, isolated absolute `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`,
`BEA_NO_UPDATE_NOTIFIER=1`, no inherited `BEA_FILE`/`BEA_TOKEN`.

Create disposable `/abs/books/main.bean`:

```beancount
option "name_expenses" "Aufwand"
option "operating_currency" "USD"
include "legacy.bean"
```

Create `/abs/books/legacy.bean`:

```beancount
2024-01-01 open Assets:Cash USD
2024-01-01 open Assets:Suspense USD
2024-01-01 open Expenses:Food USD
```

Create `/abs/books/bank.csv`:

```csv
Date,Description,Amount,Reference,Category
2024-02-01,Coffee,-4.50,coffee-1,Expenses:Food
```

From `/abs/books`, with the isolated child environment above:

```sh
bea --json -f /abs/books/main.bean check
bea --json --no-input -f /abs/books/main.bean import /abs/books/bank.csv --csv date=Date,narration=Description,amount=Amount,id=Reference,category=Category --account Assets:Cash --default-account Expenses:Food --into legacy.bean
bea --json --no-input -f /abs/books/main.bean import /abs/books/bank.csv --csv date=Date,narration=Description,amount=Amount,id=Reference,category=Category --account Assets:Cash --default-account Expenses:Food --into legacy.bean --apply
bea --json --no-input -f /abs/books/main.bean import /abs/books/bank.csv --csv date=Date,narration=Description,amount=Amount,id=Reference,category=Category --account Assets:Cash --default-account Assets:Suspense --into legacy.bean
bea --json --no-input -f /abs/books/main.bean import /abs/books/bank.csv --csv date=Date,narration=Description,amount=Amount,id=Reference,category=Category --account Assets:Cash --default-account Assets:Suspense --into legacy.bean --apply
bea --json -f /abs/books/main.bean query "SELECT account,number,currency WHERE narration='Coffee'"
bea --json -f /abs/books/main.bean add transaction "Manual control" --date 2024-02-02 -p "Assets:Cash -1.25 USD" -p "Expenses:Food 1.25 USD" --into legacy.bean
bea --json -f /abs/books/main.bean check
```

Actual: exits `0, 2, 2, 0, 0, 0, 0, 0`. The first two imports refuse:
`--default-account: Account 'Expenses:Food' has root 'Expenses', which this
ledger does not use; its roots are Assets, Liabilities, Equity, Income, Aufwand
(set by the name_* options). Use one of those roots.` Both preserve all ledger
bytes. With the valid fallback, preview/apply instead say the category is
not an account name, assign rule `unmatched`, and write one `!` transaction
against `Assets:Suspense`. BQL returns:

```json
[["Assets:Cash", "-4.50", "USD"], ["Assets:Suspense", "4.50", "USD"]]
```

The manual control then posts to `Expenses:Food` in `legacy.bean` at exit 0,
and the combined ledger still passes check. Preview preserves ledger bytes,
all refused runs preserve both ledger files, and the source CSV stays unchanged.

Expected: an account this ledger already opens, and which the selected existing
include can parse, remains usable in CSV import. The category is the full
opened account name, so the row should carry `*` and post to `Expenses:Food`.
Beancount applies root-name options per parsed file, as USAGE's `--into` and
query-export sections document; the main file's five names are not the entire
set of accounts the loaded ledger accepts. Keep the per-file parsing rule.

Reproduction and controls:

- Sixteen fresh journeys: two repetitions × source account / fallback / rule /
  category × renamed-main/default-main profiles. Renaming `name_assets` to
  `Aktiva` makes `--account Assets:Cash` refuse despite its included open.
  Renaming `name_expenses` to `Aufwand` refuses the fallback and
  `account="Expenses:Food"` rule; category mode silently routes to suspense
  with `!`. All eight default-main controls correctly categorize as
  `Expenses:Food` with `*`. Every fixture passes before and after check; all
  16 manual adds into the same include succeed. Successful CSV repeats write
  zero, preserving the original classification rather than repairing it.
- Eight Python-importer controls, twice each for a renamed assets/expenses
  root and open/closed legacy cash account. Explicit −4.50/+4.50 USD postings
  to the legacy accounts preview/apply successfully while active; exact repeats
  skip. Closing the cash account before the import date correctly blocks
  preview and refuses apply at exit 4 without writes. No plugin or feature was
  enabled to obtain these controls.
- Two unknown-root controls retain the intended policy: an unopened
  `Foo:Food` fallback refuses at exit 2; that value as a category queues for
  review. Do not replace root validation with unrestricted root acceptance.

Cause: `cli/src/bea_engine/importing.py:216–245` obtains `ledger_roots(options)`
from the main file and validates the two CSV account options through
`_valid_account` (:1778), then loads rules with only those roots.
`CsvRule.parse` (`csv_mapper.py:507`) and `CsvImporter._names_account`
(:1504–1516) likewise call `parse_account` with that root list.
`ledger/text.py:558–559` rejects any other root without considering the already
loaded opens. These CSV checks run before ordinary posting validation can
recognize the existing account and destination. Native importer extraction
bypasses these CSV-only option/rule/category checks, explaining its working
control. The frontend rule reader has no loaded-root list; the rejecting
rule check is in the engine.

Fix: let these CSV paths recognize the loaded ledger's already-opened,
syntactically valid account names, including their normalized spelling, while
retaining strict root validation for names the ledger never opens. Pass that
context consistently to source/fallback, rule and category validation; do not
accept every unknown account under a newly unioned root. Keep later date,
currency, self-counterposting and per-destination parse checks. Do not rewrite
existing include options or disable the unknown-root protections. No dependency
or backend/API change needed.

Acceptance: the four CSV paths use the already-open legacy accounts when
writing to their compatible include; the public category chooses `Expenses:Food`

Unknown foreign-root names still refuse/review; closed, future-opened,

An incompatible destination still refuses with the per-file option guidance.
