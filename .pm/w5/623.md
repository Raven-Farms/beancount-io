# `bea cloud ledger create x --private --public` creates a public ledger (the last flag wins), `-d a -d b` keeps the last, and `--dir` without `--clone` is silently ignored

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-16, HEAD `e2565f3b`, checkout `bea 0.3.1`, macOS 26.5.1. Simulation: local stub API.
The command's help says a mistyped flag "cannot put someone's finances on the
open internet". USAGE's rule is that single-value options refuse two
different values (w5/238, 381), and `add balance` refuses `--pad-date`
without `--pad-from`. `cloud ledger create` does neither, and the request
goes out. No product fix implemented.

Against a local stub (`BEA_API_URL=http://127.0.0.1:<stub>`, test token):

```sh
bea cloud ledger create qa-x --private --public
bea cloud ledger create qa-y --dir books
```

Actual: both exit 0. The stub receives `POST /api-gateway/v1/ledgers`
`{"name":"qa-x","description":null,"private":false}`; text prints `private:
no`. The second creates the ledger and clones nothing, with no word about
`--dir`. A parse probe shows `-d a -d b` keeps `b`.

Expected: exit 2 before credentials or any request, for `--private` with
`--public`, for two different `-d` values, and for `--dir` without
`--clone`.

Cause: `cli/src/cli/commands/cloud/ledger/app.py:44-113` is not a
`SingleValueCommand`, and reads `directory` only `if clone:` (`:69-73`, `:93`).

Fix: register with `SingleValueCommand` (refusing the `--private/--public`
pair explicitly) and refuse `--dir` without `--clone`, alongside the existing
name check.

Dedupe: w5/483, 485 and 512 cover other commands.

Acceptance: the three cases exit 2 with no request (a stub test counts
requests).
