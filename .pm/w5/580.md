# `bea init books` through a dangling symlink (an unmounted drive) says the working directory "is a file, not a directory"

**Trivial · cli · 10m · A2.** Real CLI QA, 2026-10-16, HEAD `3514cc17`, checkout `bea 0.3.1`, macOS 26.5.1.
The blocker search uses `.exists()`, which follows symlinks, so it skips the
broken link and blames its parent. No product fix implemented.

```sh
ln -s /Volumes/NoSuchDrive/books books
bea init books --currency USD --date 2026-01-01
```

Actual: exit 2, `Cannot create a ledger in …/books: … is a file, not a
directory. Choose another directory. Nothing was written.`, naming the
current directory.

Expected: `…/books is a broken symbolic link to /Volumes/NoSuchDrive/books`
(as `entry_file` already says for `--file`).

Cause: `cli/src/bea_engine/initiating.py:146-150` picks the first path where
`.exists()` is true.

Fix: test with `os.path.lexists`/`is_symlink` and name the broken link.

Dedupe: searched `is a file, not a directory`; w5/295 (cwd discovery) is
different.

Acceptance: the command names the broken link. A test pins it.
