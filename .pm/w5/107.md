# The query shell's error banner prints ledger text raw, so a ledger can erase the notice that it is invalid

**Minor · cli · 30m · A1.** Real CLI QA, 2026-10-11, HEAD `0227141a` (CLI unchanged since `97600b74`),
checkout `bea 0.3.1`, macOS, driven through a real pseudo-terminal.
When the interactive query shell loads a ledger with errors, it prints each
offending entry verbatim, control bytes included. A payee carrying a
clear-screen sequence wipes the "does not balance" line from the terminal —
the only sign in a lenient session that answers are partial. Every other
diagnostic path escapes such bytes. No product fix implemented.

Create disposable `/absolute/books/main.bean`, where `␛` stands for the
single byte 0x1b:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Food USD
2026-01-05 * "Cafe" "Coffee"
  Expenses:Food  4.00 USD
  Assets:Checking
2026-01-06 * "Bank␛[2J␛[1;1HFAKE" "imported row"
  Expenses:Food  9.00 USD
  Assets:Checking  -8.00 USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN/CI, `TERM=dumb`, and stdin, stdout and stderr all
attached to a pseudo-terminal.

```sh
bea -f /absolute/books/main.bean query
```

then `.errors` and `.exit`.

Actual: at startup and again on `.errors` the terminal receives
`main.bean:7: Transaction does not balance: (1.00 USD)` followed by the
entry with the two raw escape sequences (bytes `1b 5b 32 4a 1b 5b 31 3b 31
48` captured from the PTY). A real terminal clears the screen and homes the
cursor at that point. Exit 0. Repeated twice; a worker saw the same on
`.reload`.

Control: on the same terminal, the one-shot `bea -f … query "SELECT count(*)
AS n"` prints only the one-line error with no entry text and no escape byte.
A worker confirmed `list transaction` shows the payee as
`Bank\x1b[2J\x1b[1;1HFAKE`.

Expected: `docs/USAGE.md` says "Diagnostics get the same treatment in text
mode: loader errors and warnings … show … control characters as `\xNN`",
excepting only native `bea check` output. The shell banner is bea's own
diagnostic, so control characters in it should be escaped.

Cause: `cli/src/bea_engine/query.py:624`, the startup load, and upstream's
`.errors` command all call Beancount's `printer.print_errors`, which
renders the offending entry verbatim. The frontend's inert-text filter never
sees it because the shell child owns the terminal.

Fix: print shell load errors through an inert path at startup, `.reload`
and `.errors` — the one-line form the one-shot uses, or the upstream block
with control characters escaped. `PRINT` output keeps exact bytes, per
w4/173. No dependency or API change.

Blast radius: the interactive `--file` shell only.

Dedupe: board search for `print_errors`, inert text and shell banner finds
w1/134 (frontend diagnostics, done), w4/173 (query table cells, done; it
records that the interactive shell was not separately exercised) and w3/392
(import); none covers the shell banner.

Acceptance: on the fixture the PTY stream contains no 0x1b byte at startup,
on `.errors` or on `.reload`, and the balance error stays visible; a
ledger without control bytes prints as today. A PTY regression test asserts
the bytes. Only macOS and the checkout were exercised.
