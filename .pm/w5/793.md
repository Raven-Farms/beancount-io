# A ledger inside a directory without search permission fails every command with a raw `[Errno 13] Permission denied`, exit 1 "validation", instead of the documented exit 2; `init` there gives the same instead of exit 3

**Minor · cli · 5–10m · A1.** Real CLI QA, 2026-10-17, HEAD `9b822564b`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE:129 says "An unreadable ledger exits **2**, naming the path and the
source that selected it". No product fix implemented.

`locked/main.bean` is a valid two-line ledger; then run `chmod 000 locked`.

```sh
bea -f locked/main.bean check
```

Actual: exit 1, `Error: [Errno 13] Permission denied: 'locked/main.bean'. Pass
--debug before the command for a traceback.`. `--json balance` (category
`validation`), `add note`, and `bea init locked/books …` fail the same way
(hunter's runs).

Control: with `chmod 000 locked/main.bean` and the directory searchable, exit
2 with `Path 'locked/main.bean' is not readable.`

Expected: exit 2 with the same "not readable" wording naming the directory,
and exit 3 for `init` (as for a read-only parent, w5/090).

Cause: `candidate.is_symlink()`/`exists()` in `cli/src/cli/context.py` (around
`:148`) and `file.exists()` in `cli/src/cli/commands/init.py` (around `:127`)
raise `PermissionError` on Python 3.13 for EACCES.

Fix: catch `PermissionError` around those checks and use the existing
messages.

Dedupe: w3/417, w5/090, 673, 708 and 787 cover other permission paths.

Acceptance: `check` exits 2 and `init` exits 3, each naming `locked`.
