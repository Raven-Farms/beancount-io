# A `../` include reached through a symlinked directory resolves physically in bea's frontend walker but lexically in Beancount's loader: `format -o` overwrites the included file the ledger loads (exit 0, data lost), `format -i` formats the wrong file, and `--into` gives an unclearable "ledger changed; retry"

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
Beancount's loader globs an include, then `normpath`s the match:
`root/link/../other.bean` opens `root/other.bean`. bea's frontend closure
walker keeps the unnormalised glob result and resolves it through the
symlink, physically, to `real/other.bean`. The frontend guards and
`format` therefore protect and format a file the ledger does not load,
and miss the one it does. [w5/087](./done/087.md) fixed the same kind of
mismatch for a symlinked *root* only. No product fix implemented.

Create a disposable directory:

```text
link -> real/sub                       (ln -s real/sub link)
main.bean        option "operating_currency" "USD"; include "link/f.bean";
                 open Assets:Cash USD; open Equity:O USD
real/sub/f.bean  include "../other.bean"
real/other.bean  2026-01-03 * "PHYSICAL real/other"   (1 USD Cash/Equity:O)
other.bean       2026-01-04 * "LEXICAL root/other"    (5 USD Cash/Equity:O)
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1,
closed stdin, and a fresh copy for each command.

```sh
bea -f /absolute/s/main.bean list transaction
bea format /absolute/s/main.bean -o /absolute/s/other.bean
bea format -i /absolute/s/main.bean
bea -f /absolute/s/main.bean add note --date 2026-01-05 -a Assets:Cash -m x --into real/other.bean
```

Actual:

- `list` shows only "LEXICAL root/other": the loader opens `other.bean`.
- `format -o other.bean` exits 0 and replaces the loaded `other.bean` with
  the root's text. Its transaction is lost, and the ledger then reports
  `Duplicate open directive`.
- `format -i` reports `formatted: …/real/other.bean`, a file not loaded,
  and leaves the loaded `other.bean` untouched.
- `--into real/other.bean` exits 4 with `The ledger changed during the
  operation: …/real/other.bean. Nothing was written; retry.` every time.
  `--into other.bean` works.

Reproduced by the hunter on several fresh copies. I reproduced the
`format -o` overwrite (the loaded `other.bean` became the root's text,
exit 0).

Control: `format -o` onto a plain included file exits 2 with "would
overwrite the ledger it reads". `query -o other.bean`,
`BEANCOUNT_LOAD_CACHE_FILENAME=other.bean` and `price export` behave
correctly, because they use the engine's lexically normalised closure.

Expected: the frontend walker names the files the loader opens, so the
`-o` guard refuses (exit 2), `format -i` formats `other.bean`, and
`--into real/other.bean` is refused as not included (or accepted as the
same file).

Cause:

- `_include_matches` (`cli/src/cli/output.py:336-339`) keeps glob's
  unnormalised `…/link/../other.bean`. Later `is_file`, reads and
  `same_file` resolve it physically.
- `_included_new_file` (`cli/src/bea_engine/ledger/write.py:266-275`)
  compares the physical `Path(directory).resolve()` against the target,
  so `require_target` raises the conflict (`write.py:141-144`).

Fix: `os.path.normpath` each glob match before testing or reading it, as
`_glob_members` already does (`write.py:230-232`), and compare lexically
normalised paths in `_included_new_file`. No dependency change.

Blast radius: ledgers that reach includes through symlinked directories
with `../` paths, common when shared account files are symlinked in.
`format -o` can silently destroy an included file.

Dedupe: w5/087 (symlinked root), w5/096 (`..` staging names), w5/285
(`../` with managed includes), w5/058 (export symlink collapse) and 433
(duplicate includes) cover other cases. None covers a symlinked
directory partway through the closure.

Acceptance: on the fixture, `format -o other.bean` exits 2 and changes
nothing, `format -i` formats `other.bean`, and `--into real/other.bean`
does not loop on "changed". A test pins all three.
