# `add balance --amount "3487.50 USD ; per statement 3480"` silently drops everything after the `;`, exit 0 (sibling of w5/298)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `bea189ec`, checkout `bea 0.3.1`, macOS 26.5.1.
The w5/298 rule (USAGE "a `;` in posting text…") refuses a comment in amount
text because Beancount drops the rest of the line. `add price --amount`
refuses it, and so does `add custom -v`. `add balance --amount` passes the
text to the parser unchecked, so the user's note is lost and the assertion
is written. No product fix implemented.

Any ledger with `Assets:Bank:Checking` open.

```sh
bea -f /abs/main.bean add balance -a Assets:Bank:Checking --amount "3487.50 USD ; per statement 3480" --date 2024-03-02
```

Actual: exit 0, appends `2024-03-02 balance Assets:Bank:Checking  3487.50
USD`.

Control: `add price -c EUR --amount "1.10 USD ; ecb"` exits 2.

Expected: exit 2 naming `--amount` and the `;`, nothing written (or, if notes
are wanted, a documented `--meta`/comment path).

Cause: `_parse_balance_amount` (`cli/src/bea_engine/ledger/adding.py:576-584`)
hands the text to `parse_exact` without the `comment_start` check the
posting path uses.

Fix: apply the same check (refuse `;` outside quotes) before parsing.

Dedupe: searched `comment_start`, `';'`. Only w5/298 (done; postings and
bulk).

Acceptance: the command exits 2 and writes nothing. A test pins it.
