# `bea price refresh` loads the whole ledger twice, plugins included, even when the ledger has no managed price includes

**Trivial · cli · 15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
`price refresh` first does a full offline load only to record each
managed source's previous revision, then resets the cache windows and
loads again. On a ledger with no managed includes, both loads are
unnecessary. Each runs every plugin. No product fix implemented.

The hunter used a counter plugin and a 10k-transaction ledger with no
managed includes, a fresh `XDG_CACHE_HOME`, and closed stdin.

```sh
bea -f /absolute/big.bean price refresh
```

Actual: the plugin runs twice, and the command takes 0.72 s against 0.58
s for `balance`. Reproduced on two fixtures by the hunter. I confirmed
the first load at `main.bean:715`.

Expected: at most one load, and none when there is nothing to refresh.

Cause: `price_refresh` in `cli/src/bea_engine/main.py` (about `:712-715`,
`managed_load.load_with_sources(root, offline=True, strict=False)`) runs
before the refresh load.

Fix: read previous revisions from the cache `head.json` per include URL
without a full load. If a cheap scan finds no managed include, skip both
loads. No dependency change.

Blast radius: `price refresh` on large or plugin-heavy ledgers.

Dedupe: 354 and 379 cover `price` message text, and 430 and 431 cover
other double loads. None covers this.

Acceptance: with the counter plugin, `price refresh` on a ledger without
managed includes runs the plugin at most once. On a ledger with includes,
revisions are still reported correctly. A test counts invocations.
