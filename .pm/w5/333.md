# Lot-booking errors still show Python reprs: `No position matches "Posting(… CostSpec(number_per=Decimal('999') … meta={'filename': …, 'lineno': 11})"` and `Cost is negative: "Cost(number=Decimal('-5') … datetime.date(2026, 3, 1) …)"`

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
`format_error` (w3/302, `0f7fac5f`) turns loader messages that arrive as
Python artifacts into one readable line. It does not cover two common
booking errors, so they reach users and agents as raw namedtuple reprs:

- a sell that matches no lot;
- a negative per-unit cost.

These are the errors an agent hits while writing investment transactions.
The repr includes `Decimal(...)`, `datetime.date(...)`, a full `CostSpec`,
and the posting's `meta`. For an `add` refusal, that meta gives a line
number in the proposed append, which was never written. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Assets:Broker HOOL
2026-01-01 open Income:Gains USD
2026-01-01 open Equity:Opening
2026-01-03 * "Buy"
  Assets:Broker  10 HOOL {100.00 USD}
  Assets:Cash
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin.

```sh
bea --json -f /absolute/books/main.bean add transaction Sell --date 2026-03-01 -p 'Assets:Broker -5 HOOL {999 USD}' -p 'Assets:Cash 600 USD' -p Income:Gains
bea -f /absolute/books/main.bean add transaction Neg --date 2026-03-01 -p 'Assets:Broker 3 HOOL {-5 USD}' -p Assets:Cash
```

Actual: both commands exit 1 and leave the ledger unchanged.

- The JSON details read: `Proposed append (not written): No position
  matches "Posting(account='Assets:Broker', units=-5 HOOL,
  cost=CostSpec(number_per=Decimal('999'), …), …,
  meta={'filename': '/absolute/books/main.bean', 'lineno': 11})" against
  balance (10 HOOL {100.00 USD, 2026-01-03})`. The file has 8 lines.
- The second command prints `Cost is negative: "Cost(number=Decimal('-5'),
  currency='USD', date=datetime.date(2026, 3, 1), label=None)"`.

The same reprs appear in `bea --json check` details, and in the strict-read
refusals of `balance`, `list`, `report` and `query` when such entries are
already in the ledger. Reproduced in four fresh directories, one of them an
independent rerun.

Control: neighbouring booking errors are readable, for example `Not enough
lots to reduce "-15 HOOL {100.00 USD}": 10 HOOL {100.00 USD, 2026-01-03}`
and `Ambiguous matches for "-5 HOOL {}": …`. A `noduplicates` hit is
rewritten as one line (w3/302). Native `bea check` text output passes
through upstream's own wording, as USAGE documents.

Expected: w3/302 set the rule that these messages should not show raw
reprs, and `format_error`'s docstring calls it "the one boundary where
error objects become display strings". w5/104, w5/230 and w5/294 keep
`Decimal(` and `datetime.` out of output cells. A lot error should read
like its siblings, for example `No lot matches -5 HOOL {999 USD} in
Assets:Broker; it holds 10 HOOL {100.00 USD, 2026-01-03}` or `Cost is
negative: -5 USD`, with no meta dict and no line number for an unwritten
append.

Cause: `format_error` (`cli/src/bea_engine/query.py:1721-1739`) recognises
only plugin-failure and `noduplicates` messages. Upstream
`beancount/parser/booking_full.py` formats these two errors with `%s` over
the `Posting` and `Cost` namedtuples. `Not enough lots` and `Ambiguous
matches` use `position.to_string`, which is why those two read well.

Fix: in `format_error`, rewrite `No position matches "Posting(...)"` from
the error's posting (units plus the cost spec, rendered as
`writer._cost_spec_text` does) and `Cost is negative: "Cost(...)"` from
the number and currency. Keep the held-lot list. Leave unrecognised
messages unchanged. No dependency or API change.

Blast radius:

- every writer's refusal: all `add` kinds, `add transactions`, and
  `import --apply`;
- JSON `check` details;
- strict-read refusals and `--allow-errors` warnings.

Dedupe: searched `.pm/**`, including `done/`, for `No position matches`,
`Cost is negative`, `CostSpec(` and `Decimal('`.

- w1/135 and w3/416 quote the repr as a fixture or as the expected
  refusal.
- w3/302 fixed `noduplicates` only.
- w5/294 covers the query table.

None of them tracks the wording of booking errors.

Acceptance: on the fixture, both `add` refusals, and the `--json check`
details for the same entries written by hand, contain no `Posting(`,
`CostSpec(`, `Cost(`, `Decimal(`, `datetime.` or `meta=`. Each still names
the units, the requested cost and the held lots. A real-command regression
test covers the add path and `--json check`. Only macOS and the checkout
were exercised.
