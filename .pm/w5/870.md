# A leaf write misses an including root spelled main.BEAN or main.Beancount and fails on unknown accounts (sibling of w5/865)

**Minor · cli · 15–20m · A1.** Found while closing w5/865, 2026-10-20, checkout HEAD `b5d95edfc`, macOS (case-insensitive APFS). Isolated config/cache, synthetic books. No product fix implemented.

`books/main.BEAN` opens `Assets:Checking USD` and `Expenses:Food USD` and has `include "txns/*.bean"`; `books/txns/2026.bean` holds only a comment.

```sh
bea --file /abs/books/txns/2026.bean add transaction Lunch --date 2026-02-01 -p 'Expenses:Food 5 USD' -p Assets:Checking
```

Actual: exit 1, `Invalid reference to unknown account 'Assets:Checking'` and `'Expenses:Food'`, each with an `add open` remedy against the leaf. Nothing is written.

Control: the same books with the root renamed `main.bean` print `2026.bean is included by …/books/main.bean; the write goes to 2026.bean and is checked against that whole ledger.` and add the transaction.

Cause: `_scan_includers` (`cli/src/bea_engine/ledger/write.py`, behind `including_root`/`including_roots`) lists candidates with `directory.glob("*.bean") + directory.glob("*.beancount")`, which match case-sensitively on POSIX even on a case-insensitive volume — the same pattern w5/865 fixed in the frontend's output guard (`cli/src/cli/output.py` `_ledger_candidates`). Every write that finds its root this way (`add`, `import`, `ask`) is affected.

Fix: match candidate suffixes case-insensitively there too, keeping the level, candidate and size limits and on-disk spellings. The engine cannot import the frontend helper, so it needs its own.

Acceptance: the command above runs through `main.BEAN` and `main.Beancount` roots as it does through `main.bean`; a regression test covers both suffix families.
