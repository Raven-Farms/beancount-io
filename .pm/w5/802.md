# A `@@` total with the currency glued to the number (`@@ 100USD`) loses `@@` and is written as a repeating unit price (`@ 33.33333333333333333333333333 USD`), in single and bulk adds (gap in w5/059)

**Minor · cli · 5–10m · A1.** Real CLI QA, 2026-10-17, HEAD `0f2118d8e`, checkout `bea 0.3.1`, macOS 26.5.1. Gap in w5/059 (done).
USAGE says "A `@@` total is written back with `@@` and its exact total, never
divided into a repeating unit price". Beancount's lexer reads `100USD` as
`100 USD`. No product fix implemented.

```sh
bea --file /abs/at.bean add transaction Total --date 2026-02-01 -p 'Assets:Stock 3 HOOL @@ 100USD' -p 'Assets:Cash -100.00 USD'
```

Actual: exit 0. The file gains `Assets:Stock        3 HOOL @
33.33333333333333333333333333 USD`, and the JSON answer has that price with
`price_total: null`. The bulk shorthand `"amount": "3 HOOL @@ 100USD"` does the
same, as does `@@ (40+60)USD` (hunter's runs).

Control: `@@ 100 USD` writes `@@ 100 USD` and answers `price_total`.

Expected: `@@ 100 USD` written, with `price_total` in the answer.

Cause: `split_total_price` (`cli/src/bea_engine/amounts.py:93`) splits the tail
on whitespace and needs two tokens, so `100USD` falls through to the
parser's divided unit price.

Fix: lex the tail with Beancount's tokens instead of splitting on
whitespace.

Dedupe: w5/059 (done) fixed arithmetic totals only.

Acceptance: both paths write `@@ 100 USD`. A test pins it.
