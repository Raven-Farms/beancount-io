# Read commands need a writable ledger directory once the ledger has a managed price include

**Minor (design-adjacent; owner call) · cli · 30–45m · A1.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, macOS. A ledger
kept in a read-only directory can be checked, listed and reported on — until
it gains a managed price include. Then every read exits 3 with a message
about validating a write the user did not ask for. No product fix
implemented.

The feed was a **simulation**: a loopback HTTP server allowlisted through the
documented `MANAGED_PRICE_ORIGINS` variable served one synthetic feed; no
Beancount.io endpoint was contacted and no credential was used. It served, at
`/prices/BTC-USD`:

```beancount
; alias: BTC-USD
; commodity: BTC
; quote: USD
2026-01-04 price BTC 53000.50 USD
  observed-at: "2026-10-10T00:00:00Z"
```

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
include "http://127.0.0.1:18765/prices/BTC-USD"

2026-01-01 open Assets:Checking USD
```

then remove write permission from the file and its directory.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, and an absolute `--file`. Set `MANAGED_PRICE_ORIGINS` to the loopback origin.

```sh
bea -f /absolute/books/main.bean list open
```

Actual: exit 3 with `Error: Cannot stage a copy of main.bean in
/absolute/books: the directory is not writable. bea validates a write on a
staged copy beside each changed file; make the directory writable before
retrying. Nothing was written.` `check` and `balance` fail the same way.
Repeated twice.

Control: the same read-only directory without the URL include reads
normally.

Expected: `docs/USAGE.md` documents the staging-copy exit 3 for writes and
says `check`, `list`, `query` and `report` "all see the same resolved
prices", with no writable-directory requirement. A read should not need
write access to the books; at the least its error should describe a read.

Cause: `cli/src/bea_engine/managed_load.py:346` shadows every file in the
closure beside its source so relative paths keep their meaning, reusing the
write path's staging helper and its message. Beside-source staging is a
deliberate design choice; read-only trees are not among its recorded
consequences.

Fix: owner's call. At minimum give reads their own message naming the managed
include as the reason. Better, fall back to a shadow outside the ledger
directory when it is not writable, translating paths back, so reads work on
read-only mounts and shared directories. No dependency or API change.

Dedupe: board search for "Cannot stage", read-only directories and managed
includes finds w1/079 (a read-only price cache) and w5/090 (init and format
destinations); neither covers reads.

Acceptance: on the fixture `list`, `check`, `balance` and `price
status` either succeed or exit with a read-specific message; no staging file
is left behind; writes keep exit 3. Only macOS and the checkout were
exercised, against a simulated feed; a read-only included directory was not
run.
