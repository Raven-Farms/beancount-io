# `--meta 'check:1045/0'` crashes the engine: exit 4 "the outcome is unknown"

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Fix with [128](./done/128.md).
A slash-separated reference such as a cheque or invoice number ending in
`/0` is ordinary metadata. Because `--meta` values go through Beancount's
expression parser (128), this one is a division by zero that kills the
engine. The user is told the write's outcome is unknown; the ledger is in
fact untouched. The posting path refuses the same expression cleanly. No
product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Equity:Opening
2026-01-01 open Expenses:Food
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean add transaction Dinner --date 2026-02-01 -p "Expenses:Food 40 USD" -p Assets:Checking --meta 'check:1045/0'
```

Actual: exit 4, ledger byte-identical:

```text
Error: The Beancount engine did not answer 'bea-engine add --file /absolute/books/main.bean --type transaction --request -' (exit -11); the outcome is unknown. Inspect the file before retrying.
```

Control: `-p "Expenses:Food 40/0 USD"` exits 2 with `Division by zero in
'Expenses:Food 40/0 USD'. …`. `--meta 'check:"1045/0"'` writes `check:
"1045/0"`. A worker saw `add commodity --meta 'ratio:1/0'` crash the same
way.

Expected: `docs/USAGE.md`: "A literal zero divisor (`100/0`) is refused as
a usage error before it reaches the engine", and bare metadata text
becomes a string. Store the text or refuse with exit 2.

Cause: `cli/src/bea_engine/ledger/adding.py:899-900` (`_parse_metadata`)
hands the raw value to Beancount's parser; the frontend's zero-divisor
guard (`cli/src/cli/amounts.py:46-55`) is called for postings and balance
amounts only (`cli/src/cli/commands/add.py:144`, `:227`).

Fix: the fix proposed in 128 (keep a typed value only when the raw text is
one plain literal, otherwise store the text) removes this too; until then
apply the literal-zero-divisor refusal to `--meta` values. No dependency
change.

Blast radius: `--meta` on `add transaction` and `add commodity`.

Dedupe: w5/128 covers silent arithmetic in the same function but lists no
crash; w5/done/010 and w5/done/057 fixed literal divisors in postings and
bulk amounts; w5/252 is the wording of `(exit -11)`.

Acceptance: the command stores `check: "1045/0"` or exits 2 naming the
value; no engine crash and no exit 4. Only macOS and the checkout were
exercised.
