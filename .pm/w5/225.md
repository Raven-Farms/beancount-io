# `query` directive strings are written unescaped: `query PRINT -f beancount` output fails to reload, and an importer returning one is refused

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A `query` directive whose BQL contains a double quote is printed without
escaping it. The beancount-format export of a valid ledger is then invalid,
with exit 0; and a Python importer that returns such a directive has its
whole batch refused with a message about line breaks. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-03 query "cafe" "SELECT account WHERE payee = \"Cafe\""
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.
The fixture passes stock `bean-check`.

```sh
bea -f main.bean query PRINT -f beancount -o out.bean
bea -f out.bean check
```

Actual: the export exits 0 and `out.bean` contains

```beancount
2026-01-03 query "cafe" "SELECT account WHERE payee = "Cafe""
```

which fails to load: `out.bean:3: Invalid token: 'Cafe""'`.

Importer side: an importer that returns a coffee transaction plus
`data.Query(meta, date, "cafe", 'SELECT account WHERE payee = "Cafe"')`
exits 2 on preview and apply, writing nothing, the valid transaction
included:

```text
Error: Directive 2 of 2 would be written as 0 directive(s); a field holds a line break or a value that is not one token. Nothing was written.
```

Control: the same importer with the single-quoted spelling `payee = 'Cafe'`
applies with exit 0.

Expected: an export in beancount format reloads with the original values
(the contract w3/done/457 set for `custom` values), and the printer already
escapes note, document, event and custom strings.

Cause: the string-field table in `cli/src/bea_engine/ledger/writer.py:87-92`
lists `Note`, `Document`, `Event` and `Custom` but not `Query`, so the
upstream printer's raw formatting of `name` and `query_string` is used.

Fix: add `Query: ("name", "query_string")` to that table. No dependency or
API change.

Blast radius: the beancount-format `PRINT` export and Python-importer
output. There is no `add query` command.

Dedupe: board search for "query directive", `query_string`, and `PRINT`
with escape/quote finds w3/done/457 (custom values) and w5/085 (pad in
PRINT); neither covers `query`.

Acceptance: `out.bean` passes `bea check` and stock `bean-check` and holds
the escaped string; the importer batch applies both entries. Only macOS and
the checkout were exercised.
