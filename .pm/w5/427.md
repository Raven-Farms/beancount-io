# A `--rules` pattern using a POSIX class (`[[:alpha:]]`) leaks Python's raw `FutureWarning: Possible nested set` with a source path to stderr, and silently means something else, so the rule matches nothing

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
Python's `re` does not support POSIX bracket classes. It reads
`[[:alpha:]]` as a literal character set and emits a `FutureWarning`.
bea compiles rule patterns with no warning filter, so the warning, with
bea's own source path and line, reaches the user. The rule then matches
nothing, and its rows fall to `Expenses:Uncategorized` with exit 0. No
product fix implemented.

Use the ledger and `s.csv` from [426](./426.md), and `r.toml`:

```toml
[[rule]]
match = "[[:alpha:]]"
account = "Expenses:Food"
```

```sh
bea -f /absolute/books/main.bean import s.csv --account Assets:Cash --csv date=Date,payee=Payee,amount=Amount --rules r.toml
```

Actual: exit 0. stderr starts with `…/cli/src/bea_engine/csv_mapper.py:325:
FutureWarning: Possible nested set at position 1`. The row is
uncategorized. Reproduced twice by the hunter and once by me.

Control: `\w+` and `[a-z]` match. An invalid regex such as `[` exits 2
with "Rule 1 has an invalid regex".

Expected: no Python warnings or source paths on stderr. A pattern that
Python reads differently from what the user wrote should be refused, or
warned about in bea's words, for example "Rule 1 uses `[[:alpha:]]`, a
POSIX class Python regex does not support; use `[^\W\d_]`".

Cause: `re.compile` at `cli/src/bea_engine/csv_mapper.py:325`, with no
warnings handling.

Fix: compile under `warnings.catch_warnings(record=True)` and turn
`FutureWarning`/`DeprecationWarning` into a `UsageError` (exit 2) naming
the rule. No dependency change.

Dedupe: searched `.pm/**`, including `done/`, for FutureWarning, "nested
set" and POSIX class. 338 covers unknown rule keys only. None covers
this.

Acceptance: the command exits 2 naming rule 1 and the POSIX class, with
no `FutureWarning` text. Ordinary patterns are unchanged. A test pins it.
