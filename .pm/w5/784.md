# On first use, text `bea check` and `bea doctor` try to install the engine twice after a failed install (double the wait, offline), and when the retry succeeds they still exit 1 with the stale failure

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-17, HEAD `46d7394e9`, `bea 0.3.1` installed from a freshly built wheel into a throwaway Python 3.12 venv, with isolated `XDG_*`/uv directories, macOS 26.5.1. Offline means `HTTP(S)_PROXY=http://127.0.0.1:9`.
README says that when a first-use provision fails, you retry a local command
such as `bea check`. That retry is where this happens. No product fix
implemented.

1. **Offline.** `bea -f /abs/main.bean check` exits 1 after 10 s, with stderr
   showing `Installing the Beancount engine 0.3.1 (one time) in …` twice.
   `bea --json -f /abs/main.bean check` takes 5 s with one attempt. `bea doctor
   print-options /abs/main.bean` makes two attempts. `bea --no-input init
   books …` makes one.
2. **Unanswered proxy.** Text `check` takes 89 s against 44 s for `--json`. Two
   such commands started together queue behind each other's four attempts,
   finishing after 133 s and 177 s (hunter's run).
3. **Transient failure.** With a uv shim that fails only the first `uv pip
   install`, `bea check` prints `Installing…` twice, then `Beancount engine
   0.3.1 ready.`, then `Error: Could not install the hash-pinned engine
   packages (uv exited 2).` and exits 1. The engine is provisioned, and the
   next `bea check` exits 0 (hunter's run, twice).

Expected: one attempt per command, and never a stale failure after `ready`.
USAGE: "Exit 0 is a promise", and conversely a passing check must not exit 1.

Cause:
- `cli/src/cli/commands/check.py` (around `:97-104`) catches every `BeaError`
  from the `--documents-only` helper call, including the provisioning failure
  from `ensure_engine()`, and keeps it as `portable`. `run_native` then
  provisions again, and `portable` is raised after bean-check passes.
- `doctor` fails open the same way (`cli/src/cli/commands/doctor.py`, around
  `:183`, `:239`, `:260`).

Fix: raise provisioning and engine-resolution failures as an error those
fail-open handlers do not catch, or resolve the engine once up front.

Dedupe: searched "Installing the Beancount engine", "documents-only",
"provision twice"; nothing open.

Acceptance: offline text `check` makes one attempt; the transient case exits
0. Tests pin both.
