# Native `bea check --json` still prints nothing on stdout for a duplicate include (exit 1) or an unreadable include (exit 2) (incomplete fix of w5/496)

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-17, HEAD `93520860`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/496 (done).
w5/496 made bea's own findings appear in bean-check's JSON shape when
`--json` is forwarded. The duplicate-include and unreadable-include
refusals run earlier, in a branch that raises text before the JSON
handling. A script reading stdout gets nothing. No product fix
implemented.

`main.bean`: `include "a.bean"`, `include "b.bean"`, `2024-01-01 open
Assets:Cash USD`; `a.bean`: `2024-01-02 open Expenses:Food USD`; `b.bean` is a
symlink to `a.bean`. Variant: the include is `chmod 000`.

```sh
bea -f /abs/main.bean check --json
```

Actual: duplicate: exit 1, empty stdout, text stderr `Error: …: 1 error(s).` /
`…:2: Duplicate include: …/b.bean is …/a.bean under another name…`;
unreadable: exit 2, empty stdout.

Expected: `{"errors": [{"message": "Duplicate include: …", "filename":
"…/main.bean", "lineno": 2}]}` (or the unreadable reason), with the same exit
code. Upstream `bean-check --json` prints a JSON list here.

Also: for an undecodable include, the JSON `filename` names the root rather
than the include (`_json_error` falls back to the root file).

Cause: the `has_unreadable_include`/`has_duplicate_member` branch
(`cli/src/cli/commands/check.py:79`) raises text before the `as_json` handling.

Fix: route those findings through the same JSON rendering.

Dedupe: w5/496 (done) is the parent.

Acceptance: both cases print a JSON error list naming the right file. A test
pins them.
