# Plugin-triggered write refusals are unattributed or misattributed: `leafonly`/`coherent_cost`/`onecommodity` errors appear at existing lines with no plugin named, an import blocked by a `close_tree` close cites `<beancount.plugins.close_tree>:0`, a `close_tree`+`check_drained` hint names the wrong plugin, and an `auto_accounts` open hint cites a line past the end of the file

**Trivial · cli · 20–30m · A1.** Real CLI QA, 2026-10-16, HEAD `5a0cdcb4`, checkout `bea 0.3.1`, macOS 26.5.1.
w5/398 (check_commodity), w5/399 (check_drained) and w5/222 (close_tree on
`add`) set the precedent: a write refused because of a plugin says the
proposed entry triggered it and names the plugin. Four more cases do not.
No product fix implemented.

1. **Errors at existing lines.** With `leafonly` and `coherent_cost`:
   `add open --date 2026-01-07 --account Expenses:Food:Coffee` exits 1 with
   `main.bean:6: Non-leaf account 'Expenses:Food' has postings on it` (line 6
   is the existing open), and `add transaction buy … -p "Assets:Broker 1 HOOL
   {50 USD}"` exits 1 with `main.bean:18: Currency 'HOOL' is used both with and
   without cost`. A backdated `onecommodity` violation is reported at existing
   lines too. Fix: when an error is new relative to the before-load but
   anchored at an existing line, say the proposed entry triggered it and name
   the plugin (`cli/src/bea_engine/ledger/write.py:1555-1572` labels by line
   only).
2. **Import after a `close_tree` close.** A CSV row for `Assets:Bank:Sub` after
   `2026-01-10 close Assets:Bank` reports `Row 1: Account 'Assets:Bank:Sub' was
   closed 2026-01-10 (at <beancount.plugins.close_tree>:0) … Re-date the
   close…`. `add transaction` on the same ledger already says "closed … by
   plugin beancount.plugins.close_tree, not by a line in the ledger;
   Assets:Bank is closed that day at main.bean:7". Fix: reuse that wording in
   `_inactive_reason` (`cli/src/bea_engine/importing.py:1349-1364`).
3. **Wrong plugin named.** With `close_tree` then `check_drained`, `add close
   --date 2026-01-10 --account Assets:Bank` (with 100 USD in `Assets:Bank:Sub`)
   says the failing assertion "is generated by plugin
   beancount.plugins.close_tree"; `check_drained` generated it for the close
   `close_tree` generated. Fix: check `_drained_close` before `_plugin_origin`
   (`write.py:1822`, `:2055`).
4. **`auto_accounts` open after first use.** On a 6-line ledger where
   `Assets:Cash` is first used 2026-01-02, `add open --date 2026-01-03
   --account Assets:Cash --currency USD` says `Account opened 2026-01-03 at
   …/main.bean:8. Correct the transaction date or edit that directive`. Line 8
   does not exist; the fix is the proposed `--date`. Fix: recognize this write's
   own open and say "date it on or before 2026-01-02" (`write.py:1674-1681`).

Dedupe: searched `leafonly`, `coherent_cost`, `Non-leaf`, `close_tree`;
w5/153, 222, 339, 398 and 399 (done) are the precedents.

Acceptance: each case names the plugin or the right remedy. Tests pin them.
