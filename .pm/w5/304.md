# USAGE's JSON-output transcript fails on the README quick-start ledger: its first command posts to `Expenses:Food`, which `bea init` never opens

**Minor · cli (docs) · 15–20m · A2.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
The fix for w1/127 (`ac5d39f1`) made the USAGE "JSON output" transcript
record its own expense first. The prose says the transcript runs against
"a ledger with a 1000 USD opening balance in `Assets:Checking` and one
12.50 USD expense recorded first", which is the README quick-start ledger.
But the added command posts to `Expenses:Food`, and `bea init`'s personal
template does not open that account. A reader who does the README quick
start and then copies the transcript gets exit 1 on the first line. If
they open the account to get past it, `net_profit` comes out as
`{"USD":"-25.00"}` instead of the documented `{"USD":"-12.50"}`. The docs
test passes only because its hidden `USAGE_SETUP` opens `Expenses:Food`.
No product fix implemented.

Run the README quick start verbatim, with isolated
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no inherited
BEA_FILE/BEA_TOKEN, and closed stdin:

```sh
bea --no-input init books --currency USD --date 2026-08-01 --opening-balance "Assets:Checking 1000"
cd books
bea add transaction "Coffee" --date 2026-08-02 --posting "Expenses:Dining 12.50" --posting "Assets:Checking"
# then the USAGE "JSON output" fence (cli/docs/USAGE.md:1808-1825), verbatim:
bea add transaction Coffee --date 2026-08-02 --posting "Expenses:Food 12.50" --posting Assets:Checking
```

Actual: exit 1, and the ledger is unchanged:

```text
Error: The change would leave the ledger invalid; nothing was written.
  Proposed append (not written): Invalid reference to unknown account 'Expenses:Food' Did you mean Expenses:Fees, Expenses:Rent, Expenses:Transport? To create it, use bea add open --account Expenses:Food --date YYYY-MM-DD.
```

After `bea add open --date 2026-08-01 --account Expenses:Food -c USD`, the
add succeeds, and `bea --json report income-statement | jq -c
'.data.net_profit'` prints `{"USD":"-25.00"}`. Reproduced in three fresh
directories. A fresh `init` without the quick-start Coffee fails the same
way on the first line.

Control: `cli/tests/test_docs_examples.py` passes. Its `USAGE_SETUP` opens
`Expenses:Food` and records no quick-start Coffee, so it tests a ledger the
prose never describes.

Expected: the fence runs as written on the ledger its prose describes and
prints the values it shows. The README promises "Every command below runs
as written". The docs test's docstring claims "Every documented `bea`
invocation runs in CI with its expected outcome".

Cause: the `add` line in `cli/docs/USAGE.md:1808-1825` came from
`ac5d39f1`. `bea init`'s template (`cli/src/cli/commands/init.py:26`,
`_ACCOUNTS`) opens `Expenses:Dining` and `Expenses:Groceries`, not
`Expenses:Food`. The docs test hides the gap by opening the account in a
shared setup. The fence also still shows `"bea": "0.1.0"`.

Fix (choose one):

- Drop the fence's `add` line, so the transcript reads the quick-start
  ledger as described; its Coffee is the 12.50 USD expense.
- Post to `Expenses:Dining` and say the ledger is a fresh `init` without
  the quick-start Coffee.

Either way, have the docs test build exactly the ledger the prose
describes for this fence, instead of the shared `USAGE_SETUP`. Optionally,
render the version as `<version>`. Docs and test only.

Blast radius: this one fence. Other USAGE fences state that their accounts
were opened first. Agents copy this transcript's JSON paths, which was
w1/127's stated reason for fixing it.

Dedupe: w1/127 (done, `ac5d39f1`) is the predecessor. Its reproducer, the
README quick-start ledger, now fails at the new first line.
`git log -S 'These run against a ledger with a 1000 USD'` returns only
`ac5d39f1`. A board search for `Expenses:Food` with "transcript" or
"quick-start" finds nothing open.

Acceptance: on a ledger built by the README quick start verbatim, every
line of the USAGE JSON fence exits 0 and prints exactly the values shown,
and the docs test builds that ledger for this fence. Only macOS and the
checkout were exercised.
