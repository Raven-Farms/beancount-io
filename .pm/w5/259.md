# `bea query --source` with an impossible date literal prints a long traceback instead of the usage error the `--file` path gives

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Fix with [250](./250.md).
w1/done/085 turned a bad BQL date literal into a one-line usage error.
The mapping was added on the `--file` path only; the same query through
`--source` exits 1 with a boxed traceback (a worker counted 1,132 lines).
No product fix implemented.

Create disposable `/absolute/books/m.bean`:

```beancount
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
2024-01-02 * "Shop" "x"
  Expenses:Food 5 USD
  Assets:Cash
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea query --source /absolute/books/m.bean "SELECT date WHERE date > 2020-99-01"
```

Actual: exit 1 and a traceback through `bea_engine/main.py` and
`bea_engine/query.py`, ending `ValueError: month must be in 1..12`.

Control: `bea --file m.bean query "SELECT date WHERE date > 2020-99-01"`
exits 2: `Error: Cannot run this BQL query: invalid date literal: month
must be in 1..12.`

Expected: w1/done/085: the query exits 2 with "Cannot run this BQL query:
invalid date literal…", on both paths.

Cause: `native_one_shot` (`cli/src/bea_engine/query.py:426-430`) catches
only Beanquery's own error type, and `source_query`
(`cli/src/bea_engine/main.py:582-591`) only engine errors; a parse-time
`ValueError` escapes.

Fix: route the `--source` one-shot through the same `ValueError` to
usage-error mapping (the `OSError` mapping proposed in 250 belongs in the
same place). No dependency or API change.

Blast radius: `query --source` one-shots. The shells are covered by
w5/109.

Dedupe: w5/109 covers a mistyped date in the interactive and `--source`
shells; w5/250 covers `--source DIR`; neither covers the one-shot.

Acceptance: the command exits 2 with the one-line message and no
traceback. Only macOS and the checkout were exercised.
