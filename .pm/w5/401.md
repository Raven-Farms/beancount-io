# `list --on-disk` keeps a plugin-generated transaction when the plugin stamps it with a real source line on the same date, so the "on disk" answer shows a row `grep` cannot find, and `--details` labels it with another entry's line

**Trivial · cli · 20–30m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
`entry_generated` decides whether an entry was written in the ledger from
four things only: `(filename, lineno, date, leading token)`. A
third-party plugin may build a new entry with `new_metadata(src.filename,
src.lineno)` on the source's own date, which is a common pattern. That
entry passes every check. It is treated as written: `--on-disk` keeps
it, the SOURCE column is blank, and `--details` heads it with the source
transaction's line. When two loaded entries of one kind share a location,
at most one of them can be the written one. No product fix implemented.

Create a disposable directory holding `myplug.py`:

```python
from decimal import Decimal
from beancount.core import data
__plugins__ = ["run"]
def run(entries, options_map, config=None):
    out = []
    for e in entries:
        out.append(e)
        if isinstance(e, data.Transaction) and "inv" in e.tags:
            meta = data.new_metadata(e.meta["filename"], e.meta["lineno"])
            out.append(data.Transaction(meta, e.date, "*", "Broker", "fee (generated)", frozenset({"gen"}), frozenset(),
                [data.Posting("Expenses:Fees", data.Amount(Decimal("1"), "USD"), None, None, None, None),
                 data.Posting("Assets:Cash", data.Amount(Decimal("-1"), "USD"), None, None, None, None)]))
    return out, []
```

The directory also holds `main.bean`:

```beancount
plugin "myplug"
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Fees USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "seed"
  Assets:Cash 1000 USD
  Equity:Opening
2026-01-05 * "Broker" "buy" #inv
  Expenses:Fees 10 USD
  Assets:Cash
```

Run with `PYTHONPATH` set to that directory, isolated
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no inherited
BEA_FILE/BEA_TOKEN, and closed stdin.

```sh
bea -f /absolute/books/main.bean list transaction --on-disk
bea -f /absolute/books/main.bean list transaction --tag gen --on-disk
bea -f /absolute/books/main.bean list transaction --details --limit 2
```

Actual:

- `--on-disk` lists 3 transactions, including `fee (generated)`. The file
  holds 2.
- `--tag gen --on-disk` returns the generated row.
- `--details` heads the fee with the `buy` transaction's line, with no
  `(generated)` marker.

Reproduced by the hunter in two fresh copies and by me once.

Control: with the generated copy dated one day later, the row is marked
`generated` and `--on-disk` drops it.

Expected: `docs/USAGE.md` says "`--on-disk` drops the synthesized rows,
answering exactly what `grep` would find in the file". Its date rule
covers *copies* of a declared entry. A different entry that borrows
another's line is not declared by that line.

Cause: `entry_generated` (`cli/src/bea_engine/ledger/reader.py:131-169`)
compares only location, date and leading token. `listing.answer`
(`cli/src/bea_engine/ledger/listing.py:103-107`) and the `--details`
label rely on it.

Fix: base the on-disk status on the plugin-free parse. A loaded entry is
on disk only if it matches the parsed entry at that location: same type,
date and payee/narration, or an equal content hash. At minimum, when
several loaded entries of a kind share one location, mark only the one
matching the parsed text as on disk. No dependency change.

Blast radius: `list *` with `--on-disk`, the SOURCE column and
`--details` labels on ledgers whose plugins synthesize same-date entries
stamped with real lines.

Dedupe: searched `.pm/**`, including `done/`, for `--on-disk`,
`entry_generated`, "grep would find" and stamped. Related notes:

- w3/301: introduced the marking.
- w3/394: date spellings.
- w5/070 and w5/285: feeds and `..` includes.
- w5/325: forecast copies in import dedupe.

None covers a same-date entry stamped with a real line.

Acceptance: on the fixture, `--on-disk` lists 2 transactions, the fee row
is marked `generated`, and `--details` labels it `(generated)`. A test
covers the plugin.
