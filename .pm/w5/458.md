# `bea --offline …` still runs the passive update check: an interactive offline command asks PyPI (or the Homebrew tap) for the latest release

**Trivial · cli · 5–10m · A2.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1. **Simulation:** the update index was a localhost logging mock reached through `BEA_UPDATE_API_URL`.

`--offline` is documented narrowly: "Resolve managed price includes from
the local cache only; never fetch". The passive update check ignores it.
A user who passes `--offline` on a plane, in a sandbox, or to avoid
egress will reasonably expect no network traffic. They still get a
request to the release index and, if it answers, an update notice. A2,
because the documentation scopes `--offline` to price includes. No
product fix implemented.

Setup by the hunter: r40's pipx-layout venv, so that the notifier is
active, run under a PTY with `BEA_UPDATE_API_URL=http://127.0.0.1:<port>`,
a fresh `BEA_CONFIG_DIR`, and `HTTP(S)_PROXY` pointed at a blocking
logger.

```sh
bea --offline engine status
```

Actual: exit 0. The mock logged `GET /pypi/beancount-io/json` with
`User-Agent: bea/0.3.1`, and stderr showed `bea 9.9.9 is available …`.
Reproduced twice by the hunter. I confirmed the call site does not pass
`offline`.

Control: every `--offline` read and `price` command made no request.

Expected: either `--offline` also suppresses the passive update check,
or `--help` and USAGE say plainly that it covers price feeds only and
list `BEA_NO_UPDATE_NOTIFIER` for the notice.

Cause: `cli/src/cli/main.py:324` calls `update.start(json_output=…,
no_input=…, channel=…)` without `ctx.offline`. `update.start`
(`cli/src/cli/update.py:186`) has no offline gate.

Fix: pass `offline` into `update.start` and skip the check when it is
set. Otherwise, reword the `--offline` help. No dependency change.

Blast radius: interactive `--offline` runs from installed channels
(brew, pipx, uv tool).

Dedupe: no `.pm` hit for offline together with the update notice. 375
and 376 cover the update check's timeout and escaping, and w5/322 covers
`--check`.

Acceptance: `bea --offline <command>` makes no request to the release
index and prints no notice. A test with a fake index pins it.
