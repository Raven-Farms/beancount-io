# Normalize repeated CSV page headers like the initial header

**Minor · cli · 20–30m · A1/A2.** A bank export whose header repeats
byte-for-byte on each page is refused as containing a non-data row when the
header uses a supported normalized spelling, such as decomposed accents.
The same header maps successfully when it appears only once. No product fix
implemented.

Real CLI QA, 2026-10-21, HEAD `85c7707f8`, checkout `bea 0.3.1`, macOS
26.5.1 arm64, frontend Python 3.13.3, existing managed Python 3.12 engine.
Fresh subprocesses, closed stdin/no TTY, isolated absolute
`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, no inherited
`BEA_FILE`/`BEA_TOKEN`. All cases reproduced twice from pristine synthetic
fixtures; refused writes preserve ledger bytes and every fresh check passes.

Create disposable `/abs/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
```

Save `make_csv.py` beside it. This explicitly writes the decomposed header
twice rather than relying on how a text editor stores the accent:

```python
import csv
import unicodedata

header = ["Date", unicodedata.normalize("NFD", "Descripción"),
          "Amount", "Reference"]
with open("bank.csv", "w", encoding="utf-8", newline="") as stream:
    writer = csv.writer(stream)
    writer.writerow(header)
    writer.writerow(["2024-02-01", "Coffee", "-4.50", "qa-1"])
    writer.writerow(header)
    writer.writerow(["2024-02-02", "Lunch", "-6.25", "qa-2"])
```

From `/abs/books`, with the isolated child environment above:

```sh
python3 make_csv.py
bea --json --no-input -f /abs/books/main.bean import /abs/books/bank.csv --csv date=Date,narration=Descripción,amount=Amount,id=Reference --account Assets:Cash --default-account Expenses:Food
bea --json --no-input -f /abs/books/main.bean import /abs/books/bank.csv --csv date=Date,narration=Descripción,amount=Amount,id=Reference --account Assets:Cash --default-account Expenses:Food --date-format %Y-%m-%d --apply
bea --json -f /abs/books/main.bean check
```

Preview exits **2**, stdout empty, with `Row 2 (line 3): 'Date' in column
'Date' is not a data row. Remove the line and import again.` Explicitly
supplying the valid date format reaches engine extraction, but apply still
exits **2**, naming the repeated header's date as invalid. The ledger is
unchanged and check exits 0.

Expected: skip the repeated header with the existing page-break note, preview
two ready payments, and apply both: Cash **−10.75 USD**, two transactions,
check clean. IMPORTING promises that repeated headers are skipped and header
comparison is NFC-normalized, strips format characters and folds Unicode
spaces. Here the first and second source headers are also byte-identical;
no case-insensitive matching or new footer policy is needed.

Controls and scope:

- Twenty-four fresh journeys: two repetitions × six header styles × with/
  without a page header. Plain ASCII and composed-accent repeats skip
  correctly. Decomposed accents, an inner format character, an inner no-break
  space and an inner BOM all map/import correctly without a repeat, but their
  eight repeated-header cases refuse preview/apply. Removing only the repeated
  header on a disposable copy imports both unchanged payments; fresh BQL gives
  two rows and −10.75 USD, and check passes. Original CSV bytes stay unchanged.
- Eight additional journeys cover human output and explicit-date engine
  extraction. An initial decomposed header followed by a composed repeat works;
  the reverse fails. Even a normalized header in an **unmapped extra column**
  makes a byte-identical repeated record fail. A genuinely different non-data
  row beginning with `Date` remains correctly refused; retain that control.

Cause: `open_records` normalizes the initial header cells and uses those
strings as dictionary keys. Both `_is_header_repeat` implementations
(`cli/src/cli/csv_mapper.py:733–735` and
`cli/src/bea_engine/csv_mapper.py:1133–1135`) then compare raw repeated cell
values, only stripped, to those normalized header names. The decomposed
`Descripción` value cannot equal its composed header key. The frontend date
inspector calls it at :906, and engine date inference/extraction at
:1232/:1652; skipping the frontend inspector with `--date-format` therefore
does not repair the import. Extraction also uses it when inspecting an unmapped
pending column, so keep the two implementations consistent.

Fix: compare every repeated-header cell with the same header normalizer used
for the initial header and mapping names. Keep the whole-record equality
requirement, ordinary data text/amounts, physical line numbers and the genuine
non-data refusal; do not silently drop any row merely because its date fails.
No dependency or backend/API change needed.
