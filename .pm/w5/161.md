# Non-transaction listings are oldest-first, so the default `--limit` keeps the oldest rows and drops the current ones

**Minor · cli · 30–60m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
`bea list transaction` shows newest first, and `docs/USAGE.md` says
"Listings are newest first". Every other list type walks oldest first and
stops at the default limit of 50, so `bea list price` on a ledger with
more than 50 quotes returns the stalest 50 and omits the current price.
There is no `--sort` to reverse it. No product fix implemented.

Create disposable `/absolute/books/main.bean` with two opens, then one
price and one transaction per day for 60 days:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Equity:Open USD
2026-01-01 price BTC 60000 USD
2026-01-01 * "t0"
  Assets:Cash  1 USD
  Equity:Open
; … one `price BTC` (60001, 60002, …) and one transaction per day
; through 2026-03-01 price BTC 60059 USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea list price --currency BTC
bea list price --sort newest
bea list transaction
```

Actual: the first exits 0 with 50 rows from `2026-01-01 BTC 60000 USD` to
`2026-02-19 BTC 60049 USD`, then `Showing the first 50; pass --limit for
more.` The ten newest quotes are missing. The second exits 2: `No such
option: --sort`.

Control: `bea list transaction` on the same ledger starts at `2026-03-01`
and descends. A worker saw the same oldest-first order with `--limit 2`
for open, close, balance, pad, note, event, commodity, document and
custom, and identical ordering in JSON.

Expected: `docs/USAGE.md` — "Listings are newest first". For dated types
such as `price` and `balance`, the rows a truncated default listing keeps
should be the most recent, or the order should be selectable and
documented per type.

Cause: `cli/src/bea_engine/ledger/reader.py:250` reverses entries only in
`list_transactions`; the other listers walk in date order and stop at the
limit. `--sort` exists only on `list transaction`
(`cli/src/cli/commands/list.py`).

Fix: offer `--sort` on every type, or default dated types to newest
first; at minimum correct the USAGE sentence and document per-type order.
Changing the default order is a visible behaviour change — owner call. No
dependency change.

Blast radius: ten list types, text and JSON.

Dedupe: board search for "newest first", "oldest first" and `--sort` with
list types finds w1/done/127 (added the sentence for the transaction
example); nothing covers the other types.

Acceptance: `bea list price --currency BTC` on the fixture includes
`2026-03-01 BTC 60059 USD` in its first 50 rows, or `--sort newest` is
accepted and the doc states each type's default order. Only macOS and the
checkout were exercised.
