# `bea import` flags real bank rows as possible duplicates of the bundled forecast plugin's projected copies, and `--duplicates skip` then drops every real payment

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
Import's duplicate detection compares new rows against every loaded
transaction, including entries a plugin generated. Forecast plugins exist to
project recurring payments, so every real bank row that matches a
projection becomes a `possible_duplicate`. The "Existing entry" it cites is
the projected copy, located at the template's file and line, with a date
and narration that line does not contain.

If the user resolves this with `--duplicates skip` (the documented choice
for unattended re-imports), `--apply` exits 0 and writes nothing. The real
payments never reach the books, and `balance` keeps reporting the forecast
as if it had happened. The plugin here is the bundled
`fava.plugins.forecast` (w1/113, w5/084). No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
plugin "fava.plugins.forecast"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Rent USD
2026-01-01 open Expenses:Uncategorized USD
2026-01-01 open Equity:Opening
2026-01-02 * "Open"
  Assets:Checking  5000.00 USD
  Equity:Opening
2026-01-05 # "Landlord" "Rent [MONTHLY UNTIL 2026-04-01]"
  Expenses:Rent  1000.00 USD
  Assets:Checking
```

and `/absolute/books/s.csv`:

```text
Date,Payee,Amount
2026-02-05,Landlord,-1000.00
2026-03-05,Landlord,-1000.00
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, and cwd
`/absolute/books`.

```sh
bea -f main.bean import s.csv --csv date=Date,payee=Payee,amount=Amount --account Assets:Checking
bea -f main.bean import s.csv --csv date=Date,payee=Payee,amount=Amount --account Assets:Checking --apply --duplicates skip
```

Actual:

- The preview exits 0 with `0 ready, 0 exact duplicates, 2 possible
  duplicates`. Each row cites `Existing entry at /absolute/books/main.bean:10:
  2026-02-05 # "Landlord" "Rent"`, but line 10 is the
  `2026-01-05 … [MONTHLY UNTIL …]` template.
- `--apply --duplicates skip` exits 0 with `Wrote 0 entries`, and the file
  is unchanged.

Reproduced in three fresh runs, one of them an independent rerun.

Control: the same ledger without the `plugin` line previews `2 ready`.

Expected: `docs/USAGE.md` already applies this rule to prices: "Only
written price directives count: a price a plugin such as `implicit_prices`
generates is neither a duplicate nor a conflict". `docs/IMPORTING.md` says
duplicate candidates "show the existing entry and its source location". A
generated projection is not an existing entry. A row that matches only
plugin-generated transactions should be `new`. At minimum it should be
labelled as matching a generated entry; it should never be cited as a
written line or silently skipped.

Cause: `cli/src/bea_engine/importing.py:278-283` builds `identities` and
`fingerprints` from every loaded `Transaction`, without the
`entry_generated` filter (`ledger/reader.py`). That filter is already used
by `list --on-disk` and by the `add price`/`add balance` guards
(`ledger/adding.py:443`, `:466`, `:618`).

Fix:

- Skip generated entries when building `identities` and `fingerprints`.
- Optionally, report a match against a generated entry as a note (for
  example, "matches a forecast copy generated from main.bean:10").
- Apply the same rule to the non-transaction set (`:288`), which shares a
  root cause with [302](./302.md).

No dependency or API change.

Blast radius: `import` preview and `--apply`, for both CSV and Python
importers, on any ledger with a cloning plugin (forecast, amortize,
recurring). With `--duplicates skip` the result is silent data loss.

Dedupe: searched `.pm/**`, including `done/`, for "forecast", "generated"
together with import or duplicate, `entry_generated`, and "Existing entry
at".

- w1/113: fixed `list --on-disk` only.
- w5/084: `check` on bundled plugins.
- w5/302: importer prices.

None covers transactions.

Acceptance: on the fixture, the preview reports `2 ready` and `--apply`
writes both rows. A real-command regression test uses
`fava.plugins.forecast` and covers the preview, `--apply --duplicates
skip`, and a control in which the real payment is already written and must
still be detected as a duplicate. Only macOS and the checkout were
exercised.
