# Any write, even a refused one, deletes the user's own files named `.bea-*` beside the ledger

**Major · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
Before each write `bea` sweeps the ledger directory for abandoned staging
copies. The sweep matches any regular file whose name starts with `.bea-`
or `..bea-` and is more than an hour old, so a user's `.bea-rules.yaml` or
`.bea-backup.bean` is deleted silently — also when the write itself is
refused with "nothing was written". The naming trigger is narrow; the
loss is silent and permanent. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Equity:Open USD
2026-01-02 * "o"
  Assets:Checking  1 USD
  Equity:Open
```

and beside it `.bea-rules.yaml`, `..bea-thing` and `.beanotes.txt` with
any content and an old modification time (`touch -t 202609010000 …`), plus
a freshly created `.bea-recent.txt`.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY. cwd `/absolute/books`.

```sh
bea -f main.bean add note -a Assets:Checking --date 2026-05-02 -m n
```

and, on a pristine copy,

```sh
bea -f main.bean add note -a Assets:Nope --date 2026-05-02 -m n
```

Actual: the first exits 0; the second exits 1 with "The change would
leave the ledger invalid; nothing was written." After either,
`.bea-rules.yaml` and `..bea-thing` are gone. `.bea-recent.txt` (under an
hour old) and `.beanotes.txt` (no hyphen) remain.

Control: on a third copy, `bea check` and `bea list open` delete nothing.
A worker saw `bea format -i` delete the files while reporting "0 file(s)
formatted", a `.bea-dir/` directory survive, and — with `--into` a file
that is a symlink to another directory — a `.bea-*` file in that other
directory deleted.

Expected: `docs/USAGE.md` says "a later write in the same directory
clears any copy left by a kill" — `bea`'s own staging copies, which are
named `.bea-<16 hex>.tmp`. A refusal that says nothing was written should
leave the directory's file list intact.

Cause: `cli/src/bea_engine/ledger/write.py:215` sets `_CANDIDATE_GLOBS =
(".bea-*", "..bea-*")` and the sweep unlinks every matching regular file
older than an hour. A strict name pattern exists in the same module but
the sweep does not use it. The sweep runs in `append()` before validation
and once per file in `formatting.py`.

Fix: sweep only names matching the staging pattern and that candidate's
own cache sidecar; add a regression test with an aged `.bea-notes.md`.
No dependency or API change.

Blast radius: every `add`, `add transactions`, `import --apply` and
`format -i`, in the destination file's resolved directory.

Dedupe: board search for the sweep, abandoned candidates and `.bea-*`
finds w5/125 (sweep cost in `format`), w5/done/014 and w3/done/390, 435
and 440; none covers deleting files `bea` did not create.

Acceptance: after both commands the three old dotfiles are still
present; a genuine aged `.bea-0123456789abcdef.tmp` is still removed.
Only macOS and the checkout were exercised.
