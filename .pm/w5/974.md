# Keep cash IDs when only the counterposting has an open lot

**Major · cli · 20–30m · A1.** The exact same investment-sale statement
is imported again when a display plugin hides the original and only its
Stock counterposting uses an open cost selector. The importer's Cash leg
is explicit, costless and unchanged. Three applies of one native bank
reference produce three sales: Cash **890 USD**, Stock **14**, gains **30**,
instead of **830 / 18 / 10** after one sale. Explicit counter-cost/no-filter
controls correctly deduplicate. Follow-up to completed
[881](./done/881.md); no product fix implemented.

Environment: 2026-10-22 QA, clean main `28541f4e4` (initial reproduction on
`0bda87737`; implicated source unchanged), checkout `bea 0.3.1`, frontend
Python 3.13.3, managed Python 3.12.10 / Beancount 3.2.3 / Beanquery 0.2.0,
macOS 26.5.1 arm64. Fresh subprocesses, closed stdin/no TTY, isolated absolute
config/cache paths, notifier disabled and inherited file/token overrides
removed. Inspected local importer/filter and synthetic files only.

Run with the checkout's `bea` on PATH, replacing `/abs/case` with a fresh
absolute disposable directory. The stock has one 20-unit lot costing
10 USD each. `{USD}` selects that existing lot without restating its unit
cost; Beancount books the sale correctly. The importer's source is explicitly
`Assets:Cash`, and Cash is the first balance-sheet posting, so the native
bank reference belongs to Cash rather than Stock.

```python
import json, os, subprocess
from pathlib import Path
case = Path('/abs/case')
books = case / 'books'
books.mkdir(parents=True)
ledger = books / 'main.bean'
sales = books / 'sales.bean'
use_filter = True
counter_cost = '{USD}'
header = 'option "insert_pythonpath" "TRUE"\noption "operating_currency" "USD"\n'
header += 'plugin "cleared_only"\n' if use_filter else ''
header += '''2024-01-01 open Assets:Cash USD
2024-01-01 open Assets:Stock HOOL
2024-01-01 open Equity:Opening USD
2024-01-01 open Income:Gains USD
2024-01-01 * "Capital"
  Assets:Cash 1000.00 USD
  Equity:Opening -1000.00 USD
2024-01-01 * "Buy"
  Assets:Stock 20 HOOL {10 USD}
  Assets:Cash -200.00 USD
include "sales.bean"
'''
ledger.write_text(header)
sales.write_bytes(b'')
(books / 'cleared_only.py').write_text('''from beancount.core.data import Transaction
__plugins__ = ['run']
def run(entries, options):
    return [e for e in entries if not isinstance(e, Transaction) or e.flag != '!'], []
''')
statement = case / 'sale.statement'
statement.write_text('2024-01-03 ! "Sale"\n  bank_id: "sale-1"\n'
    '  Assets:Cash 30.00 USD\n  Assets:Stock -2 HOOL ' + counter_cost + ' @ 15 USD\n'
    '  Income:Gains -10.00 USD\n')
config = case / 'importer.py'
config.write_text('''from beancount.parser import parser
class Broker:
    name = 'cash-sale'
    def identify(self, file): return str(file).endswith('.statement')
    def account(self, file): return 'Assets:Cash'
    def extract(self, file, existing_entries=None):
        entries, errors, _ = parser.parse_file(str(file))
        assert not errors, errors
        return entries
CONFIG = [Broker()]
''')
fixed = {p: p.read_bytes() for p in (statement, config, books / 'cleared_only.py')}
env = os.environ.copy()
for key in ('BEA_FILE', 'BEA_TOKEN', 'BEANCOUNT_LOAD_CACHE_FILENAME',
            'BEA_ENGINE_PYTHON', 'BEA_ENGINE_DIR'):
    env.pop(key, None)
env.update(BEA_CONFIG_DIR=str(case / 'config'), XDG_CACHE_HOME=str(case / 'cache'),
           BEA_NO_UPDATE_NOTIFIER='1')
def run(tag, args, json_mode=True, overrides=None):
    argv = ['bea', *(['--json'] if json_mode else []), '--no-input', '-f', str(ledger), *map(str, args)]
    result = subprocess.run(argv, cwd=case, env=env | (overrides or {}),
                            stdin=subprocess.DEVNULL, capture_output=True,
                            text=True, timeout=25)
    print(json.dumps(dict(tag=tag, args=argv, exit=result.returncode,
                         stdout=result.stdout, stderr=result.stderr)), flush=True)
run('baseline-check', ['check'])
run('original-apply', ['import', statement, '--config', config, '--into', sales, '--apply'])
authored = sales.read_bytes()
run('source-check', ['check'])
repeat = ['import', statement, '--config', config, '--into', sales]
run('human-preview', repeat, json_mode=False)
run('preview', repeat)
run('second-apply', [*repeat, '--apply'])
run('third-apply', [*repeat, '--apply'])
ledger.write_text(header.replace('plugin "cleared_only"\n', ''))
try:
    override = {'XDG_CACHE_HOME': str(case / 'unfiltered-cache')}
    run('unfiltered-facts', ['query', 'SELECT account,sum(number) GROUP BY account ORDER BY account'], overrides=override)
    run('unfiltered-profit', ['report', 'income-statement', '--time', '2024-01', '--conversion', 'at_cost'], overrides=override)
    run('unfiltered-check', ['check'], overrides=override)
finally:
    ledger.write_text(header)
assert sales.read_bytes().startswith(authored)
assert all(p.read_bytes() == content for p, content in fixed.items())
```

All ten commands exit **0**. Original apply correctly writes **1** sale,
preserving its `{USD}` selector and native bank ID. The unchanged statement
then previews **ready 1 / duplicates 0**, human preview calls it new, and
both the second and third applies wrongly write **1** each. Unfiltered
positions are:

```text
Assets:Cash       890.00 USD
Assets:Stock       14 HOOL
Equity:Opening  -1000.00 USD
Income:Gains      -30.00 USD
```

Unfiltered income reports profit **30 USD**, and `check` passes. The
original sale stays an unchanged prefix; two copies were appended under
that same native identity. Statement/config/filter bytes stay unchanged and
the root filter is restored. Three bounded applies are enough to prove this;
no oversold-inventory limit was exercised.

Working control: change only `counter_cost = '{10 USD}'` in a fresh fixture.
It books exactly the same original sale, but preview reports duplicate 1 /
ready 0 and all repeated applies write zero. Cash stays **830 USD**, Stock
**18**, gains **10**. Keeping `{USD}` but omitting the display filter also
works. Both controls preserve the same original financial facts.

Expected: a cash-source native-ID duplicate must still be recognized when
its irrelevant counterposting leaves a booking selector open. IMPORTING's
identity contract (`cli/docs/IMPORTING.md:538–567`) scopes the ID and amount
to the importer's source account and permits counter-account edits without
changing that identity. The old sale's Cash leg has no cost or price at all;
its stable ID and 30 USD source are fully known. This is not an attempt to
change or prove a booked Stock lot.

Reproduction and financial controls:

- Eight pristine same-statement producer/re-import cases, twice each of
  filter on/off × open `{USD}`/explicit `{10 USD}` counter cost:
  **56 CLI calls**. Only filter+open counter writes the same sale on both
  retries. It leaves Cash 890 / Stock 14 / gains 30; every control stays
  830 / 18 / 10. Original statement/config/filter bytes are unchanged and
  every root is restored.
- **24 further cost-basis reports** and **eight unwrapped native Beancount
  inventory references** agree: the bad native-repeat case has cost-basis
  net worth 1030 / profit 30 versus 1010 / 10 in controls. The stock basis is
  140 versus 180 USD respectively. Sheets reconcile with no valuation
  adjustment; these are duplicate real sale entries.
- Eight other fresh cases (**56 CLI calls**) first import the same Python
  sale, then import a cash CSV carrying its same 30 USD/reference. Here the
  filtered open-counter case writes one cash-only duplicate, reaching
  Cash 860 / Stock 18 / gains 40. Another 24 reports/eight native references
  confirm cost-basis net worth 1040 versus controls' 1010. Explicit-cost
  and no-filter controls deduplicate this cash CSV too. This additional
  exposure confirms that the Cash leg's own identity is fully comparable,
  independently of the counterposting shape.
- The exact final public recipe was replayed twice with the explicit-cost
  control and JSON/human apply variants. Both output surfaces agree on
  repeat writes, preserved prefixes, final positions and profit.

Cause: `_written_identities` in
`cli/src/bea_engine/importing.py:1839–1848` skips a transaction if **any**
posting has a cost with neither stated per-unit nor total number. Its loop
walks `raw.postings`, including the unrelated Stock counterposting.
For this source, `_source_legs(raw, 'Assets:Cash')` contains only the
costless 30 USD Cash posting. The guard therefore discards an identity that
can be compared exactly under the source-account policy.

Direct raw-index controls on the actual original-sale graphs confirm:
both source legs are `30.00 USD` with cost None; the explicit Stock-counter
case has one native-ID owner, while the open Stock-counter case has zero.
The loaded view cannot rescue it after the filter, so `_under_id` sees no
owner and the unchanged imported row is called new. With no filter, the booked loaded sale
supplies that owner, explaining the passing open-cost control.

Fix in `cli/`: apply source-lot comparability safeguards only to postings
in the declared source set (including applicable source children), not to
counterpostings that native-ID source comparison ignores. Retain the guard
when the actual source lot is open; do not vouch for a changed booked lot.
Preserve native-ID issuing-account scoping, source amounts/prices and
counter-account edit behavior. No dependency or API change indicated.

Caller scope: lazy `written_source` at `importing.py:480–485` feeds
`_under_id:1780–1812` from `answer:558`. Python repeat and Python-to-CSV
journeys were exercised. `_fingerprint` (`:1473`) already compares only
`_source_legs`; the raw-index eligibility guard should use that same source
scope. The original slot was an included leaf; other layouts are regression
scope rather than separately reproduced failures.
