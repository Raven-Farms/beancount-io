# Keep native-ID conflicts when a plugin filters the original row

**Major · cli · 20–30m · A1.** A corrected amount under an existing bank
reference is imported as a new transaction when a plugin filters the
original from the loaded view. A real CSV import first writes 100 USD;
changing only the amount to 110 under the same native reference then
writes another transaction, leaving actual Cash **210 USD**. There is no
BOM or malformed text. Pass-through/no-plugin controls correctly report a
conflict and refuse the same change. Follow-up to completed
[881](./done/881.md); no product fix implemented.

Environment: 2026-10-22 QA, clean main `3aa30d607` (initial reproduction on
`8aa0577d2`; implicated source unchanged), checkout `bea 0.3.1`, frontend
Python 3.13.3, managed Python 3.12.10 / Beancount 3.2.3 / Beanquery 0.2.0,
macOS 26.5.1 arm64. Fresh subprocesses, closed stdin/no TTY, isolated absolute
config/cache paths, notifier disabled and inherited file/token overrides
removed. Inspected local filter and synthetic files only.

Run with the checkout's `bea` on PATH, replacing `/abs/case` with a fresh
absolute disposable directory. The display plugin hides uncleared `!`
transactions; it does not modify their written source facts. Both the
original transaction and its native ID are produced by the real CLI. The
script changes the synthetic bank export after the first import, then
briefly removes/restores the display filter to inspect actual accounting.

```python
import json, os, subprocess
from pathlib import Path
case = Path('/abs/case')
books = case / 'books'
books.mkdir(parents=True)
ledger = books / 'main.bean'
transactions = books / 'transactions.bean'
header = '''option "insert_pythonpath" "TRUE"
option "operating_currency" "USD"
plugin "cleared_only"
2024-01-01 open Assets:Cash USD
2024-01-01 open Income:Salary USD
include "transactions.bean"
'''
ledger.write_text(header)
transactions.write_bytes(b'')
use_filter = True
body = "[e for e in entries if not isinstance(e, Transaction) or e.flag != '!']" if use_filter else 'entries'
(books / 'cleared_only.py').write_text('from beancount.core.data import Transaction\n'
    '__plugins__ = ["run"]\ndef run(entries, options):\n    return ' + body + ', []\n')
source = case / 'salary.csv'
original_csv = 'Date,Memo,Amount,Reference\n2024-01-02,Salary,100.00,salary-1\n'
source.write_text(original_csv)
env = os.environ.copy()
for key in ('BEA_FILE', 'BEA_TOKEN', 'BEANCOUNT_LOAD_CACHE_FILENAME',
            'BEA_ENGINE_PYTHON', 'BEA_ENGINE_DIR'):
    env.pop(key, None)
env.update(BEA_CONFIG_DIR=str(case / 'config'), XDG_CACHE_HOME=str(case / 'cache'),
           BEA_NO_UPDATE_NOTIFIER='1')
def run(tag, args, json_mode=True, overrides=None):
    argv = ['bea', *(['--json'] if json_mode else []), '--no-input', '-f', str(ledger), *map(str, args)]
    result = subprocess.run(argv, cwd=case, env=env | (overrides or {}),
                            stdin=subprocess.DEVNULL, capture_output=True,
                            text=True, timeout=25)
    print(json.dumps(dict(tag=tag, args=argv, exit=result.returncode,
                         stdout=result.stdout, stderr=result.stderr)), flush=True)
run('empty-check', ['check'])
run('first-apply', ['import', source, '--csv', 'date=Date,narration=Memo,amount=Amount,id=Reference',
                   '--account', 'Assets:Cash', '--default-account', 'Income:Salary',
                   '--into', transactions, '--apply'])
authored = transactions.read_bytes()
# The bank corrects the amount, retaining its transaction reference.
source.write_text(original_csv.replace('100.00', '110.00'))
corrected_csv = source.read_bytes()
run('source-check', ['check'])
repeat = ['import', source, '--into', transactions]
run('human-preview', repeat, json_mode=False)
run('preview', repeat)
run('second-apply', [*repeat, '--apply'])
run('third-apply', [*repeat, '--apply'])
ledger.write_text(header.replace('plugin "cleared_only"\n', ''))
try:
    run('unfiltered-facts', ['query', "SELECT count(*),sum(number) WHERE account='Assets:Cash'"],
        overrides={'XDG_CACHE_HOME': str(case / 'unfiltered-cache')})
    run('unfiltered-check', ['check'], overrides={'XDG_CACHE_HOME': str(case / 'unfiltered-cache')})
finally:
    ledger.write_text(header)
assert transactions.read_bytes().startswith(authored)
assert not transactions.read_bytes().startswith(b'\xef\xbb\xbf')
assert source.read_bytes() == corrected_csv
```

All nine commands exit **0**. First apply correctly writes **1**. After the
bank export changes to 110 USD under the same `salary-1` reference, preview
says **ready 1 / conflicts 0 / duplicates 0**, human preview also calls it
new, and second apply writes **1**. Third apply writes zero by matching the
newly appended 110 USD copy. Unfiltered facts are **[[2, "210.00"]]** and
unfiltered `check` passes: the balanced source now holds both 100 and 110
under one bank identity. Original entry bytes remain as a prefix, the
corrected CSV stays unchanged by the CLI, and the root filter is restored.

Working control: set only `use_filter = False` in a fresh fixture, making
the same plugin return entries unchanged. The second preview instead says
**ready 0 / conflicts 1**, both attempted applies exit **4** and preserve the
ledger, and unfiltered facts remain **[[1, "100.00"]]**. Omitting the plugin
entirely has the same correct refusal. An identical repeat, or changing only
narration under that ID while filtering, correctly deduplicates without writes.

Expected: a previewed conflict and byte-preserving apply refusal (exit 4),
independent of the display filter. `cli/docs/IMPORTING.md:548–567` says reused
native IDs with changed source amounts/commodities are conflicts requiring
review; payee/narration edits do not change the identity. The transaction's
old 100 USD source is still present and parseable, and its same-account bank
reference is known. This should not be treated as a different bank event or
an automatic in-place correction.

Reproduction and controls: ten pristine real-CSV producer cases, twice each
of filter+amount change, pass-through+change, no plugin+change,
filter+description edit and filter+identical input: **60 CLI calls**.
Only the filtered amount correction appends another row and reaches
210 USD / count 2. Both unfiltered controls preview conflict 1 and apply 4
twice with no writes; description/identical controls deduplicate correctly
at 100 USD / count 1. All roots are restored and original entries preserved.
The exact public recipe above was also replayed twice with the pass-through
control and JSON/human apply variants; all agree on status, write effects
and the actual source balance.

Cause: `_under_id` in `cli/src/bea_engine/importing.py:1796–1812` initially
gets `found = identities.get(key)` from loaded entries. That is None after
the filter. Its raw-source fallback keeps only `_same_row`-agreeing source
entries. The written 100 USD owner correctly disagrees with incoming 110,
so `agreeing` is empty; the final return falls back to loaded `found`
(None), discarding the known raw owner. The caller sees no hit and labels
the correction new.

A direct managed-helper control confirms the distinction: the real snapshot's
`_written_identities` contains exactly one owner under
`(Assets:Cash, bank, bank:salary-1)`, with source units `100.00 USD`; incoming
units are `110.00 USD`, but `_under_id` returns None. This is not failure to
parse or discover the source. With a pass-through/no plugin, loaded `found`
still points at the old row, which supplies the correct conflict.

Fix in `cli/`: when the loaded owner is absent, retain an appropriate known
raw native-ID owner even if no source amount agrees, so normal conflict
classification still runs. Continue preferring the nearest agreeing owner
for reused references, then use the documented non-agreement fallback for
a conflict. Do not weaken amount/lot comparison or treat all raw owners as
exact duplicates. Keep source-account scoping, generated-ID semantics and
booked-open-lot safeguards. No dependency or API change indicated.

Caller scope: lazy `written_source` (`importing.py:480–485`) builds the
raw index and is passed to `_under_id` at `:558`; its result controls ID-hit
classification in `answer`. CSV was exercised end to end. Python importers
share the answer path but this exact corrected-amount/filter combination
was not separately driven through one.

Dedupe: searched every board state for filtered native corrections,
changed-source conflicts and `_under_id`, plus targeted history. `8b7827c6f`
closed 881 and added the source fallback; its filtered-source test covers
unchanged repeats, while changed-source tests retain a loaded owner.
Completed [822](./done/822.md), `53de922d3`, defines the nearest-agreeing/
latest-nonagreeing policy with visible entries. Open [972](./972.md) is BOM
normalization causing an empty raw index; this plain-text fixture has a
proven raw owner but discards it. [937](./937.md) concerns a synthesized
plugin copy being mistaken for a written match; no such copy exists here.
No overlapping open task or already-shipped missing-owner conflict fix found.

Acceptance: filtered native correction previews conflict 1 / ready 0 and
both JSON/human applies exit 4 with no source write; actual Cash remains
100 USD / one transaction. Keep a legitimate first import, identical and
narration-only duplicate controls, pass-through/no-plugin refusals, reused

`cli/` on implementation. Windows/Linux and interactive TTY were not exercised.
