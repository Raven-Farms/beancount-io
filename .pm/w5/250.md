# `bea query --source DIR` (or `csv:<missing>`) prints a long traceback of engine source instead of a usage error

**Minor · cli · 20m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Fix with [249](./done/249.md).
Pointing `--source` at a directory, or at a `csv:` path that does not
exist, exits 1 with a boxed Python traceback through `bea`'s own engine
files, without `--debug`. `--file` with the same directory gives a
one-line usage error. No product fix implemented.

Create disposable `/absolute/books/main.beancount`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
2024-01-01 open Equity:Opening USD
2024-01-02 * "Open"
  Assets:Cash  100.00 USD
  Equity:Opening
2024-01-03 * "Lunch"
  Expenses:Food  12.50 USD
  Assets:Cash
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea query --source /absolute/books "SELECT 1"
```

Actual: exit 1 and a boxed traceback (a worker counted 184 lines) through
`bea_engine/compat.py`, `bea_engine/main.py` and `bea_engine/query.py`,
ending `IsADirectoryError: [Errno 21] Is a directory`. A worker saw 87
lines ending `FileNotFoundError` for `--source csv:/absolute/books/nope.csv`,
and an existing `-o` file left intact in both cases.

Control: `bea -f /absolute/books query "SELECT 1"` exits 2: `Ledger path
'/absolute/books' (from --file) is a directory; expected a ledger file.`

Expected: a one-line usage error, exit 2, and no traceback without
`--debug` (the launch code states that a Python traceback reaches only the
`--debug` field); w3/done/274 already did this for a bad source scheme.

Cause: `source_query` (`cli/src/bea_engine/main.py:582-591`) catches only
engine errors, so an `OSError` from attaching the source escapes into the
helper's exception printer; `source_shell` (`:563-567`) has the same gap.

Fix: the existence and regular-file preflight proposed in 249 should cover
directories and `csv:` paths with exit 2 and the `--file` wording; also
map `OSError` in both functions to a one-line error. No dependency change.

Blast radius: `query --source` one-shot and shell.

Dedupe: board search for `IsADirectoryError`, `FileNotFoundError` and
`--source` with directory finds w3/done/274 (scheme only), w5/138 (`doctor`
on a directory) and w1/done/067 (shell tracebacks for BQL errors).

Further triggers of the same uncaught-exception gap (2026-10-12): `--source
""` (an unset shell variable; re-run by me) prints a traceback of about
100 lines, where `-f ""` gives a one-line exit 2. A worker also saw
tracebacks for an unreadable source, `-f beancount` on a column query,
`csv:` sources with `-m`, an invalid regex, and `.describe` with an
unclosed quote. A single catch-all in `source_query` would make all of
them one-line errors (see also 259, 288).

Acceptance: both commands exit 2 with one line naming the path and no
traceback. Only macOS and the checkout were exercised.
