# Ingest extract replaces the source document or its own script when `-o` names it

**Minor (source-file loss) · cli · 25–40m · A1.** Real CLI QA, 2026-10-10,
HEAD `97600b74`, checkout `bea 0.3.1`, Beangulp enabled in the managed engine,
macOS. `bea ingest extract` guards `-o` against the ledger it reads, but not
against the other files the same run reads: a bank export named as both source
and destination is replaced by the extracted entries, and so is the ingest
script, each with exit 0. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Food USD
```

`/absolute/books/dl/apr.csv`:

```csv
Date,Payee,Memo,Amount
2026-04-21,Deli,lunch,-12.00
```

and `/absolute/books/ingest.py`, a script you wrote and inspected:

```python
import csv, datetime
from decimal import Decimal
import beangulp
from beancount.core import data, amount

class Bank(beangulp.Importer):
    def identify(self, filepath):
        return filepath.endswith(".csv")
    def account(self, filepath):
        return "Assets:Checking"
    def extract(self, filepath, existing):
        out = []
        with open(filepath) as fh:
            for i, row in enumerate(csv.DictReader(fh), 2):
                units = amount.Amount(Decimal(row["Amount"]), "USD")
                out.append(data.Transaction(
                    data.new_metadata(filepath, i), datetime.date.fromisoformat(row["Date"]),
                    "*", row["Payee"], row["Memo"], frozenset(), frozenset(),
                    [data.Posting("Assets:Checking", units, None, None, None, None),
                     data.Posting("Expenses:Food", -units, None, None, None, None)]))
        return out

if __name__ == "__main__":
    beangulp.Ingest([Bank()])()
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`:

```sh
bea --file /absolute/books/main.bean ingest extract dl/apr.csv -o dl/apr.csv
```

Actual: exit 0, empty stdout, stderr `* /absolute/books/dl/apr.csv ... OK`.
`dl/apr.csv` no longer holds the bank export; its hash changed and it now reads

```text
;; -*- mode: beancount -*-

**** /absolute/books/dl/apr.csv

2026-04-21 * "Deli" "lunch"
  Assets:Checking  -12.00 USD
  Expenses:Food     12.00 USD
```

Repeated twice from a restored export with before/after hashes. Further
real-command cases on restored fixtures, each exit 0:

- `ingest extract dl -o dl/apr.csv` (the source named as a directory) replaces
  the export the same way.
- `-o link.csv`, a symlink to `dl/apr.csv`, replaces the export through the link.
- `--output=ingest.py` replaces the ingest script with the extracted entries.

Controls: `-o out.bean` writes the same entries and leaves the export and the
script byte-identical. `-o main.bean` exits 2 with `would overwrite the ledger
it reads`. `bea treeify t.txt -o t.txt` exits 2 with `would overwrite the file
it reads (t.txt)`.

Expected: `docs/USAGE.md` Output destinations opens with "a `bea` command never
replaces a file it was not given", and its treeify paragraph states "a
destination that is the input file is refused". An extract's inputs are its
source documents and its script; a destination that is one of them should exit
2 before Beangulp starts, naming the colliding path and leaving it
byte-identical. The original export is the only evidence for the extracted
entries and for a later `ingest archive`, so losing it silently is worse than
losing a regenerable output.

Cause: `cli/src/cli/commands/ingest.py:71` calls
`output.guard_forwarded_output` with only the ledgers from `_extract_ledgers`
(`:78-92` — `bea --file` and Beangulp's `-e`). The positional sources in
`ctx.args` and the resolved script from `_ingest_script` are never compared
with the destination, and Beangulp opens `-o` for writing once extraction is
done. The single-input refusal already exists as `output.refuse_input_alias`
(`cli/src/cli/output.py:330`), used by treeify (`treeify.py:127`) and
`query --source` (`query.py:72`).

Fix: before launching the script, resolve the forwarded `-o` in every spelling
the existing guard already accepts and refuse, by file identity, when it is the
ingest script, a positional source file, or a file inside a positional source
directory that Beangulp would walk. Keep the ledger and `-e` refusals, keep an
ordinary existing export overwritable, and leave `archive -o DIR` to upstream's
own collision handling as documented. Extend the Output destinations paragraph
to name source documents and the script. No dependency or API change.

Dedupe: board search for `ingest extract`, source document, input file and
output aliases finds w3/431 (the ledger and its includes, done), w1/141
(abbreviated and clustered spellings, done) and w3/317 (config-only scripts);
none compares the destination with the documents or the script.
`git log -S refuse_input_alias -- cli` shows the helper wired to treeify and
`query --source` only.

Acceptance: a destination equal to a source file, a file under a source
directory, a symlink or hard link to either, or the ingest script exits 2
before extraction with the path named and every file byte-identical;
`-o out.bean`, a pre-existing unrelated export, and `-o -` keep working. Real
`bea ingest extract` regression tests cover each spelling. Only macOS and the
checkout were exercised; `ingest archive` was run once as a control and is not
part of this finding.
