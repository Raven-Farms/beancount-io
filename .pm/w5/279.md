# `price export` and `example -o` into an unwritable directory exit 1 with a raw OS error instead of the documented exit 3

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Fix with [090](./done/090.md) and [119](./119.md).
090 covers `init` and `format -o`, and 119 `--json query -o`. Two more
commands under the same destination rule report an unwritable directory
as a raw `PermissionError` or an upstream failure line, exit 1, category
`validation`. Nothing is written. No product fix implemented.

Create `/absolute/books/a.bean` containing `2026-01-01 open Assets:A`, a
directory `/absolute/books/lock` with mode 555, and
`/absolute/books/okdir` with mode 755.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f a.bean price export --output lock/exp
bea example -s 1 -o lock/ex.beancount
```

Actual: both exit 1; `lock/` stays empty.

```text
Error: PermissionError: [Errno 13] Permission denied: 'lock/exp' Pass --debug before the command for a traceback.
Error: bean-example failed (exit 1): Error: Could not open file 'lock/ex.beancount': Permission denied
```

`--json price export` reports category `validation`, exit 1.

Control: `bea -f a.bean query "SELECT account" -o lock/out.txt` exits 3:
`Cannot stage a copy of out.txt in /absolute/books/lock: the directory is
not writable … Nothing was written.` `price export --output okdir/exp`
exits 0. A worker saw `treeify -o lock/tree.txt` exit 1 with a raw
`[Errno 13]` naming a staging file (noted as an aside in 090).

Expected: `cli/README.md`: "3 | Authentication or permission failure,
including a read-only destination"; `docs/USAGE.md`: "One rule covers
every command that takes an output destination — `query -o`, `format -o`,
`ingest extract -o`, `treeify -o`, `price export --output`, `example -o`".

Cause: `cli/src/bea_engine/managed_load.py:834-845` creates the directory
and copies files with no `OSError` handling;
`cli/src/cli/commands/example.py:42` hands the destination to the upstream
tool and only wraps its failure.

Fix: check that the destination directory is writable before any write
and raise the existing "directory is not writable" error (exit 3) in text
and JSON; for `price export`, also catch `OSError` in the copy loop so a
mid-export failure names what was already written. No dependency change.

Blast radius: `price export --output`, `example -o`, `treeify -o`
(`ingest extract -o` fails with upstream's own message).

Dedupe: w5/090 (`init`, `format -o`), w5/119 (`--json query -o`),
w5/done/056 (a blocking file in `price export`); none covers these two
commands.

Acceptance: both commands exit 3 naming the directory and saying nothing
was written, in text and JSON; the writable control is unchanged. Only
macOS and the checkout were exercised.
