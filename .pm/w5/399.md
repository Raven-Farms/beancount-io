# Under `check_drained`, `add close` on an account that still holds a balance gets generic statement-assertion advice ("use the following day's date … record known fees") instead of "drain the account before closing it"

**Trivial · cli · 15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
[w5/222](./done/222.md) made plugin-generated balances say they are not
balances written in the ledger, and dropped the date advice. That rule
excludes appended text. `check_drained` stamps its zero-balance assertion
with the line of the close being appended, so the failure is treated as a
balance the user typed. The user is then advised about statement dates
and fees, although they wrote a `close`. No product fix implemented.

Use a USD ledger with `plugin "beancount.plugins.check_drained"` and
`Assets:Cash` holding 100 USD, with the environment from [396](./396.md).

```sh
bea -f /absolute/books/main.bean add close --account Assets:Cash --date 2026-01-10
```

Actual: exit 1 with `Proposed append (not written): Balance failed for
'Assets:Cash': expected 0 USD != accumulated 100 USD (100 too much)`,
followed by "Balance assertions run at the start of the day … For a
statement closing balance, use the following day's date. Review missing
or duplicate transactions and record known fees …". Reproduced twice by
the hunter (text and JSON) and once by me.

Control: after a transaction that drains the account, the close writes.

Expected: name the plugin and the remedy, for example "check_drained
requires Assets:Cash to be 0 USD before its close; move the remaining 100
USD first".

Cause: `_plugin_origin` (`cli/src/bea_engine/ledger/write.py:1483-1510`)
returns `None` for appended lines ("Text this write appends … is never a
plugin's"). The balance then falls through to `_balance_recovery_hints`
(about `:1352-1365`).

Fix: when a Balance error points into the appended range at a directive
that is not a `balance` (here, a `close`), treat it as plugin-generated
and give a drained-close hint. No dependency change.

Dedupe: w5/222 (done) handles closes already in the ledger only, and
w5/152 covers "already recorded". Nothing covers an appended close.

Acceptance: the command names `check_drained` and the 100 USD remaining,
with no statement-date or fees advice. A test pins it.
