# `bea price export` time grows quadratically with the number of ledger files: the w5/072 include-glob guard resolves every planned path once per include pattern

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
`price export` slows down with the square of the number of files the
ledger includes. On the same ledgers, `check`, `balance`, `list`, `query`,
`add` and `format --check` stay under about a second. The extra time is
spent in the include-glob guard added by w5/072, not in copying files. No
product fix implemented.

| included files | `price export` | `check` on the same ledger |
| --- | --- | --- |
| 300 | 2 s | under 1 s |
| 375 | 2.7 s | |
| 600 | 6 s | under 1 s |
| 750 | 9.5 s | |
| 1500 | 37 s | 0.7 s |

Generate `/absolute/books/main.bean` with this header followed by
`include "f1.bean"` through `include "fN.bean"`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Equity:Opening
```

Each `fN.bean` holds one line: `2026-01-02 note Assets:Checking "nN"`.
Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean price export -o exp
```

Actual: exit 0 with `Exported N+1 files to exp.`, taking the times in the
table. A chain of includes (`f1` includes `f2`, and so on) gives the same
numbers. A profile of the engine's `price-export` at 750 files shows
`pathlib.Path.resolve` called 567,005 times (751 planned files × 755
patterns), accounting for 14.9 s of 17.6 s. Reproduced independently in a
fresh run.

Expected: w1/087 and w5/125 fixed per-file rescans in `format` so that a
split ledger with thousands of files stays usable. An export should cost
about one load plus the copy.

Cause: `cli/src/bea_engine/managed_load.py:1035-1036` evaluates
`next((p for p in snapshot.patterns if _included_new_file(dest.resolve(), p)), None)`
for every planned destination, so `dest.resolve()` is recomputed for each
pattern. `_included_new_file` (`cli/src/bea_engine/ledger/write.py:266-275`)
then runs `glob.glob(parent)` and `Path(directory).resolve()` for each
pair. The total work is O(files × patterns). The guard arrived with
`bddbd867`.

Fix: keep the guard's behaviour, and make it cheap:

- Resolve each destination once.
- Pre-filter patterns by `fnmatch` on the leaf name before running any
  glob.
- Cache each pattern's expanded and resolved parent directory.
- Check literal include paths with a single set lookup.

Coordinate with [296](./296.md), which changes how the same guard matches
directories. No dependency or API change.

Blast radius: `price export`, with the default destination or `-o`, on
ledgers that have hundreds of includes or more. About 120 files (ten years
of monthly files) costs well under a second. Other `-o` writers check a
single destination and are linear.

Dedupe: searched the board, including `done/`, for "quadratic", "slow",
seconds together with includes, and `price export` together with time.

- w1/087 and w5/125: `format` rescans.
- w5/112 and w5/124: write-validation rescans.

None covers `price export`.

Acceptance: on a 1,500-file fixture, `price export -o exp` finishes within
a small multiple of `bea check` and exports the same files. A test pins
the guard's refusals and asserts that the number of resolve or glob calls
stays linear in the file count. Only macOS and the checkout were
exercised.
