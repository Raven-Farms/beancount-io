# A refused JSON float in `add transactions` suggests a replacement that is also refused: "Send the amount as a decimal string, such as '1e+20'" (similarly `'nan'`, `'-inf'`, `'1e-08'`)

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
Bulk input refuses a JSON float in an amount, a cost or tagged metadata, as
intended by w3/260 and w1/045. The suggested fix is the float's Python
`str()` in quotes. For large, tiny or non-finite numbers that string is in
scientific notation or is `nan`/`inf`, and the next run refuses it with a
different message. An agent that follows the hint literally loops between
the two errors. No product fix implemented.

Use any valid ledger that opens `Expenses:Food` and `Assets:Cash` in USD,
with isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, and closed stdin. Create `in.json`:

```json
[{"date":"2026-01-05","narration":"B","postings":[
  {"account":"Expenses:Food","units":{"number":1e20,"currency":"USD"}},
  {"account":"Assets:Cash"}]}]
```

```sh
bea -f /absolute/books/main.bean add transactions --from in.json
# follow the hint: "number": "1e+20"
```

Actual:

- The first run exits 1 with `… JSON number 1e+20 is not supported in
  Beancount amounts; … Send the amount as a decimal string, such as
  '1e+20'.`
- Following the hint, the second run exits 1 with `Scientific notation
  '1e+20' is not supported in Beancount amounts.`
- Other inputs give similar hints:
  - `0.00000001` suggests `'1e-08'`.
  - `NaN` suggests `'nan'`, which is then refused as invalid.
  - `-Infinity` suggests `'-inf'`.
  - A cost number or tagged metadata number gives the same kind of hint.

The ledger is unchanged. Reproduced in three fresh directories.

Control: `0.1` suggests `'0.1'`, and that string is accepted.

Expected: a suggested replacement is one the same command accepts. For a
finite float that is the fixed-point spelling (`'100000000000000000000'`,
`'0.00000001'`). For NaN and Infinity, the message should say the value
has no decimal form.

Cause: `require_decimal_notation` (`cli/src/bea_engine/amounts.py:153-156`)
and `_exact_metadata_number` (`cli/src/bea_engine/ledger/write.py:2090-2093`)
interpolate `str(float)`. Both came from `2ee00f4d`.

Fix: for a finite value, suggest `format(Decimal(repr(value)), "f")`. For
NaN or Infinity, say "is not a finite number; send a decimal string". No
dependency change.

Blast radius: `add transactions` fields `units`, `cost`, `price` and tagged
metadata numbers, and any other model field validated through these
helpers.

Dedupe: searched `.pm/**`, including `done/`, for "decimal string, such
as", "JSON float" and "JSON number … not supported". w3/260 and w1/045
introduced the refusal. w3/259 and w3/265 cover other inputs. None covers
the wording of the hint.

Acceptance: for `1e20`, `1e-8`, `NaN` and `-Infinity` in units, cost and
tagged metadata, the suggested string is either accepted on rerun or, for
non-finite values, not offered. A test pins each case. Only macOS and the
checkout were exercised.
