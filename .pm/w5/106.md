# A `.reload` that cannot read the ledger prints a traceback and the shell then answers from stale data

**Minor · cli · 30–40m · A1.** Real CLI QA, 2026-10-11, HEAD `0227141a` (CLI unchanged since `97600b74`),
checkout `bea 0.3.1`, macOS, driven through a real pseudo-terminal.
In the interactive query shell, a `.reload` whose load raises (file
unreadable or gone) dumps a Python traceback, clears the session's error
state, and keeps the old entries. Even a `--strict` session then answers
queries from the data it loaded before, and `.errors` reports
`(no errors)`. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Food USD
2026-01-05 * "Cafe" "Coffee"
  Expenses:Food  4.00 USD
  Assets:Checking
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN/CI, `TERM=dumb`, and stdin, stdout and stderr all
attached to a pseudo-terminal.

```sh
bea --strict -f /absolute/books/main.bean query
```

At the prompt type `SELECT count(*) AS n;` (prints `2`). From another
terminal run `chmod 000 /absolute/books/main.bean`. Back at the prompt type
`.reload`, `SELECT count(*) AS n;`, `.errors`, `.exit`.

Actual: `.reload` prints `error:` and a multi-screen traceback through
`managed_load.py` and `ledger/write.py` ending in `PermissionError: [Errno
13] Permission denied: '/absolute/books/main.bean'`. The following `SELECT`
prints `2`. `.errors` prints `(no errors)`. Exit 0. Repeated twice; a
worker saw the same with the file moved away and with an unreadable include,
including after an earlier failed reload had correctly closed the strict gate.

Control: a one-shot `bea -f /absolute/books/main.bean query "SELECT
count(*)"` on the unreadable file exits 2 with one line saying the path is
not readable. A worker confirmed a `.reload` that returns loader errors
(rather than raising) is gated correctly.

Expected: `docs/USAGE.md` says of the strict shell that "after a
`.reload` that introduces errors, typed and stored (`.run`) queries are
refused until a clean `.reload`", and w1/039 asked that a reload "never
silently reuse an old valid answer" with no traceback. A reload that cannot
read the ledger should print one line naming the cause, leave the session
marked unloaded so queries are refused until a clean reload, and show the
failure under `.errors`.

Cause: `cli/src/bea_engine/query.py:613-631` (`do_reload`) clears
`context.errors` and `context.options` (`:619-620`) before calling the
loader (`:621`). When the load raises, the old entries remain with an empty
error list, so the gate in `execute` (`:675-676`) passes. `_recovering`
(`:482-490`) catches only the engine's own error type, so the `OSError`
reaches upstream's command loop, which prints the traceback.

Fix: load first and swap entries, errors and options only on success. On an
exception print a single-line error, drop the entries (or mark the session
failed) and record the failure for `.errors`. No dependency or API change.

Blast radius: the interactive `--file` shell only. Clearing `options`
also empties the include list the `.output` ledger guard reads; a worker
found the guard's fallback still held.

Dedupe: board search for `.reload` with traceback, stale and unreadable
finds w1/039 (reloads that return loader errors, done) and w5/006 (`.output`
traceback, done); neither covers a reload that raises.

Acceptance: on the fixture, `.reload` after `chmod 000` prints one line
and no `Traceback`; the next typed query and `.run` are refused in strict
and lenient sessions; `.errors` names the failure; restoring the mode and
reloading recovers. A PTY regression test covers an unreadable root, a missing
root and an unreadable include. Only macOS and the checkout were exercised.
