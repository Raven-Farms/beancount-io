# On a ledger with renamed roots, every `--into` write to an included file is refused as `Invalid account name: Aufwand:Food` for accounts the root opens, with no hint that Beancount applies `name_*` options per file

**Minor · cli · 15m · A2.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
Beancount checks account names against the `name_*` options of the file
being parsed, so an included file parses with the default roots. A user
who renames roots in `main.bean` and splits the ledger therefore cannot
add anything to an include. Every `--into` write is refused with
upstream's bare "Invalid account name", naming accounts that are valid
and open, with no hint. A2, because the parsing rule is upstream's: stock
`bean-check` also rejects the same text written by hand. bea could still
explain it, or seed new include files with the options. No product fix
implemented.

Create disposable `main.bean`:

```beancount
option "name_assets" "Aktiva"
option "name_expenses" "Aufwand"
option "name_equity" "Eigenkapital"
option "operating_currency" "USD"
include "sub.bean"
2026-01-01 open Aktiva:Cash USD
2026-01-01 open Aufwand:Food USD
```

and an empty `sub.bean`. Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME,
BEA_NO_UPDATE_NOTIFIER=1, and closed stdin.

```sh
bea -f /absolute/books/main.bean add transaction X --date 2026-01-05 -p 'Aufwand:Food 5 USD' -p Aktiva:Cash --into sub.bean
```

Actual: exit 1 with `Proposed append (not written): Invalid account
name: Aufwand:Food` and `… Aktiva:Cash`. A new glob member (`--into
glob/new.bean`) is refused the same way. Reproduced twice per case by the
hunter, and in every renamed-root random seed before the harness added
option headers, and once by me.

Control: with `option "name_assets" "Aktiva"` and `option
"name_expenses" "Aufwand"` at the top of `sub.bean`, the same write
succeeds and `check` passes. Default-root ledgers accept `--into` writes.

Expected: either write successfully (when bea creates a new include via
`--into`, start it with the root's `name_*` option lines), or refuse with
a hint such as: "Beancount applies `name_*` options per file; repeat
`option "name_assets" "Aktiva"` (and the others) at the top of sub.bean".
The renamed-roots and `--into` sections of USAGE should mention it.

Cause: upstream's per-file option scope. bea's write-error enrichment
(`cli/src/bea_engine/ledger/write.py`, about `:1225-1300`) adds hints
only to `Invalid reference to unknown account`, and passes `Invalid
account name` through.

Fix: when the error is `Invalid account name: X` and X's root is one of
the ledger's renamed roots, add the hint. Seed new `--into` files with
the root's `name_*` options. No dependency change.

Blast radius: split ledgers with renamed roots. No `--into` write can
succeed until the user discovers the per-file rule.

Dedupe: 402 (foreign roots on `add open`/`close`/`custom`), w5/151,
w5/154, w5/080, 403 and 414 cover other renamed-root issues. None covers
includes.

Acceptance: on the fixture, the command either writes, or refuses with
the per-file hint. A new glob member created by `--into` carries the
`name_*` options and the write succeeds. A test pins both.
