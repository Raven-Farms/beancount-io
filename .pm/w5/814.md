# `price export -o txns/p.bean` under `include "txns/*.bean"` exports into a directory the glob then loads as an include, and every later load fails with "is a directory"

**Minor · cli · 15m · A1.** Found while fixing w5/595, 2026-10-17, checkout `bea 0.3.1`, macOS 26.5.1.
`price export -o` takes a directory. The include guards (w5/072, w5/296,
w5/595) check every *file* the export plans, but not the output directory
itself. A directory whose name an include glob matches becomes an include
once it exists. This happens in any letter case.

`books/main.bean`: `option "operating_currency" "USD"`, opens for
`Assets:Cash` and `Equity:Opening`, `include "txns/*.bean"`; `books/txns/a.bean`
holds one transaction. From `books/`:

```sh
bea -f /abs/books/main.bean price export -o txns/p.bean
bea -f /abs/books/main.bean balance
```

Actual: the export exits 0 (`Exported 2 files to txns/p.bean.`). Every later
load exits 2 with `Included file '…/txns/p.bean' … is not readable: it is a
directory, not a file.`

Expected: refused before anything is written, like a planned file the glob
claims (`would become part of the ledger being exported`).

Fix: run the export directory itself through `include_claims`
(`cli/src/bea_engine/ledger/write.py`) next to the planned files.

Acceptance: the export exits 2 naming the include, and `txns/` is unchanged.
A test pins it.
