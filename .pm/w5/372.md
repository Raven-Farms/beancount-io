# `cloud ledger clone` with git missing exits 1 with `could not start git ([Errno 2] No such file or directory: 'git')` after querying the server; `create --clone` exits 2 with a clean message before any request

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1. **Simulation:** the API came from a localhost mock.

`ledger create --clone` calls `manager.ensure_git_available()` first and
refuses with exit 2: `git executable not found on PATH; install Git
before using --clone`. `ledger clone` skips that check. It fetches the
ledger from the server, then fails to start git, and reports the
`OSError` text with exit 1 (`validation`). No product fix implemented.

Use the mock and environment from [370](./370.md), with `PATH` set to a
directory that holds no `git`.

```sh
bea cloud ledger clone qa/book
bea cloud ledger create qa-z --clone
```

Actual:

- `clone` exits 1 with `Clone failed for git@127.0.0.1:book.git (could
  not start git ([Errno 2] No such file or directory: 'git')).` The mock
  was queried first.
- `create --clone` exits 2 with `git executable not found on PATH;
  install Git before using --clone`, and sends no request.

Reproduced twice by the hunter. I confirmed the missing check in the
code.

Expected: the `docs/USAGE.md` exit table maps a missing dependency to 2
(`usage`). `clone` should run the same check before credentials or the
network.

Cause: `ledger_clone` (`cli/src/cli/commands/cloud/ledger/app.py:106-135`)
never calls `manager.ensure_git_available()`. The `OSError` becomes a
`CloneError` in `manager.py:158-162`.

Fix: call `manager.ensure_git_available()` at the top of `ledger_clone`.
No dependency change.

Blast radius: `bea cloud ledger clone` on a machine without git.

Dedupe: searched `.pm/**`, including `done/`, for "could not start git"
and "git executable not found". The only hits are the original `--clone`
precheck work.

Acceptance: with no git on `PATH`, `clone` exits 2 with the
`git executable not found` message and sends no request. A test pins it.
