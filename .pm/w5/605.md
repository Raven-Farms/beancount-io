# `bea init`, and any write `--into` a new file, always fail on exFAT or FAT volumes (USB sticks, SD cards) with a raw `OSError: [Errno 45] Operation not supported` naming a hidden staging file

**Major · cli · 20–30m · A2.** Real CLI QA, 2026-10-16, HEAD `c210da9b`, checkout `bea 0.3.1`, macOS 26.5.1. exFAT RAM disk (`hdiutil attach -nomount ram://32768`, `newfs_exfat`), detached afterwards; FAT16 behaves the same.
A new file is claimed with `os.link(candidate, target)`, which refuses to
replace an existing file. FAT and exFAT have no hard links, so every
creation fails. Writes to files that already exist on the same volume work.
A user who keeps books on a USB stick or SD card cannot run `bea init` at
all. No product fix implemented.

```sh
cd /Volumes/<exFAT>/books
bea init main.bean --currency USD
# with main.bean holding include "txns/*.bean" and an existing txns/2025.bean:
bea -f main.bean add note -a Assets:Checking -m hi --date 2026-02-02 --into txns/2026.bean
```

Actual: both exit 1 (`validation`): `Error: OSError: [Errno 45] Operation not
supported: '…/.bea-<hex>.tmp' -> '…/main.bean' Pass --debug before the command
for a traceback.` Nothing is created, and no staging file is left. `add
transactions --into` a new file and `bea --json init` fail the same way.

Control: `--into txns/2025.bean` (existing) succeeds; `format -i` and `import
--apply` into existing files succeed; the same commands on APFS succeed.

Expected: `init` and new `--into` destinations work on removable
filesystems; any remaining refusal is in bea's words (w5/410's rule), without
the class name or staging path.

Cause: `cli/src/bea_engine/initiating.py:122` and
`cli/src/bea_engine/ledger/write.py:2744` use `os.link` and catch only
`FileExistsError` (and `PermissionError`).

Fix: on `ENOTSUP`/`EPERM`/`EXDEV` from `os.link`, claim the name with
`O_CREAT|O_EXCL` and `os.replace` the candidate over the empty placeholder
(or use `renamex_np(RENAME_EXCL)` / `renameat2(RENAME_NOREPLACE)` where
available).

Dedupe: searched `os.link`, `exFAT`, `FAT32`, `Operation not supported`,
`Errno 45`. No match.

Acceptance: on an exFAT volume, `init` and `add --into` a new file succeed. A
test that makes `os.link` raise `ENOTSUP` pins the fallback.
