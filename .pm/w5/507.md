# `list --on-disk` drops real transactions and labels them "(generated)" when a plugin adds an entry at their location and their header has a quoted word in a comment or a multi-line narration (regression from w5/401)

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-16, HEAD `bea189ec`, checkout `bea 0.3.1`, macOS 26.5.1.
w5/401 decides which of two entries sharing one source location is the one
on disk. It compares the header line's payee and narration with each entry.
The check takes the first two quoted strings anywhere on the line,
including inside a `;` comment, and reads only one line, so a multi-line
narration never matches. Neither entry then counts as on disk: `--on-disk`
omits the user's real transaction and `--details` calls it generated. Before
the fix both were kept. No product fix implemented.

`myplug.py` (on `PYTHONPATH`): for each transaction tagged `#inv`, it appends
a generated fee transaction stamped with the original's `filename` and
`lineno`.

```python
from decimal import Decimal
from beancount.core import data
__plugins__ = ["run"]
def run(entries, options_map, config=None):
    out = []
    for e in entries:
        out.append(e)
        if isinstance(e, data.Transaction) and "inv" in e.tags:
            meta = data.new_metadata(e.meta["filename"], e.meta["lineno"])
            out.append(data.Transaction(meta, e.date, "*", "Broker", "fee (generated)", frozenset({"gen"}), frozenset(),
                [data.Posting("Expenses:Fees", data.Amount(Decimal("1"), "USD"), None, None, None, None),
                 data.Posting("Assets:Cash", data.Amount(Decimal("-1"), "USD"), None, None, None, None)]))
    return out, []
```

```sh
bea -f /abs/main.bean list transaction --on-disk
bea -f /abs/main.bean list transaction
```

Actual: `--on-disk` lists only `seed` (exit 0); the full listing shows `buy`
and `Shop` with SOURCE `generated`, next to the plugin's fees.

Control: remove ` ; see "receipt" folder` and `buy` is listed as on disk.

Expected: USAGE says `--on-disk` answers "exactly what grep would find", so
`buy` and `Shop` are on disk and the fees are generated.

Cause: `_declares` (`cli/src/bea_engine/ledger/reader.py:170-176`) takes the
first two quoted strings of `lines[lineno - 1]`, including ones after `;`,
and never reads continuation lines. `shared_locations`
(`cli/src/bea_engine/ledger/listing.py:104`) applies only to transactions;
other directive types still use the bare test at `reader.py:220` (a
plugin's inverse `price` at a price's location is still listed as on disk).

Fix: compare against a plugin-free parse of the file at that location (the
entry the file spells), or use the lexer to read the header's strings. Apply
the shared-location rule to every directive type.

Dedupe: searched `--on-disk`, `_declares`, `shared_locations`. Only w5/401
(done) matches.

Acceptance: `--on-disk` lists `seed`, `buy` and `Shop`, and no generated fee;
a plugin price at a price line's location is excluded. Tests pin each.
