# "Pass --debug before the command for a traceback" is shown only for engine-side errors; unexpected frontend errors and forwarded-native crashes print a bare class name with no hint, although `--debug` does add a traceback for them

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
When an unexpected error comes from the engine subprocess, bea appends
"Pass --debug before the command for a traceback". Unexpected errors from
the frontend itself, and crashes of forwarded natives, print only the
class name or raw message. `--debug` produces a traceback in all three
cases, but the user is told how to get it only in the first. Several
open notes are fixing the wording of such errors (352, 366, 388, 407,
410). This note covers the inconsistent hint, which would remain for any
errors those fixes miss. No product fix implemented.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1,
and closed stdin. `bal.txt` is `bea query "SELECT account,
sum(position) GROUP BY account"` output.

```sh
bea treeify bal.txt --filler ''
bea --debug treeify bal.txt --filler ''
bea -f /absolute/books/main.bean query "SELECT account LIMIT 9223372036854775808"   # control
```

Actual:

- `treeify` prints `Error: treeify failed (exit 1): ZeroDivisionError:
  …` with no hint. With `--debug`, the upstream traceback follows.
- A stdout write error under a file-size limit (407) and `cloud status`'s
  `'dict' object has no attribute 'username'` (366) also lack the hint.
- The engine-side control prints `ValueError: … Pass --debug before the
  command for a traceback.`

Reproduced twice by the hunter, and once by me (treeify).

Expected: `docs/USAGE.md` says `--debug` includes exception tracebacks.
Whenever a hidden traceback exists, the hint should appear, whatever the
error's source.

Cause: the hint is added only in `helper_json`
(`cli/src/cli/engine/launch.py:418-422`). `output.error`
(`cli/src/cli/output.py:118-129`) and `check_native`
(`launch.py:283-305`) build or keep a traceback for `--debug` but never
add the hint otherwise.

Fix: in `output.error`, when not in debug mode, append the hint for
non-`BeaError` exceptions and for errors carrying a native traceback. No
dependency change.

Dedupe: the class-name notes listed above cover message wording only, and
w3/298 and w5/089 set the no-class-name rule. Nothing covers where the
hint appears.

Acceptance: `bea treeify bal.txt --filler ''` (until 388 is fixed) and any
other unexpected frontend or native error show the hint, and `--debug`
adds the traceback. A test pins one frontend and one native case.
