# `bea add pad` before an assertion that already holds is refused with "omit --pad-from", an option `add pad` does not have

**Minor · cli · 15–25m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
When a later balance assertion already holds, `bea add pad` dated before it
is refused with `Book balance already matches the assertion; omit
--pad-from and add the balance alone.`

- `add pad` has no `--pad-from` option.
- The balance already exists.
- The hint names neither the assertion nor where it is.
- Every Unused Pad refusal is also glued to its hint with no punctuation
  between them (`Unused Pad entry Book balance…`).

No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "Open"
  Assets:Checking  100.00 USD
  Equity:Opening

2026-01-10 balance Assets:Checking  100.00 USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean add pad --date 2026-01-05 -a Assets:Checking --source Equity:Opening
```

Actual: exit 1, and the ledger is unchanged:

```text
Error: The change would leave the ledger invalid; nothing was written.
  Proposed append (not written): Unused Pad entry Book balance already matches the assertion; omit --pad-from and add the balance alone.
```

`--json` puts the same text in `details`. `bea add pad --help` lists no
`--pad-from`. Reproduced in three fresh runs.

Controls:

- `add balance --pad-from Equity:Opening` with a matching amount no longer
  reaches this hint. It exits 0 with `Book balance already matches 100.00
  USD; omitted the pad from --pad-from and wrote the assertion alone.` So
  the "omit --pad-from" text now fires only for `add pad`, where it is
  wrong.
- A lone `add pad` with no later assertion gets the correct atomic hint,
  but with the same missing separator (`Unused Pad entry Add both
  directives…`).
- An existing pad orphaned by another write gets the accurate
  `appended=False` message, which names the assertion's location
  (`write.py:1471-1478`).

Expected: w3/224, which added this hint for the `--pad-from` path, says
"Keep the existing hint for a lone `bea add pad`". For `add pad`, the
refusal should say that the `2026-01-10` assertion at `main.bean:8`
already holds, so the pad would have nothing to fill and need not be
added. A sentence break should separate Beancount's message from the hint.

Cause: `_unused_pad_hint` (`cli/src/bea_engine/ledger/write.py:1416-1480`)
falls through to the `--pad-from` text at `:1480` for any appended pad
whose reached assertions all hold. Its `appended` flag does not say which
command appended the pad. The caller at `:1344-1346` concatenates the hint
onto Beancount's `Unused Pad entry`, and every hint begins with a bare
space.

Fix: give `add pad` its own "already holds" text that names the first
reached assertion and its location, as the `appended=False` branch does.
Drop or retarget the `--pad-from` wording, which nothing reaches correctly
any more. Join the two parts with `". "`. No dependency change.

Blast radius: `add pad` in text and JSON output, plus the separator on
every Unused Pad refusal.

Dedupe: searched `.pm/**` for "omit --pad-from", "Unused Pad" and "already
matches", and ran `git log -S` on the hint string. Related notes:

- w3/224: the `--pad-from` circular hint (fixed).
- w5/081: the `--allow-errors` Unused Pad exemption.
- w5/085, w5/221 and w1/116: other pad paths.

None covers the `add pad` wording.

Acceptance: on the fixture, `add pad` exits 1 with a message that names the
`2026-01-10` assertion at `main.bean:8`, does not mention `--pad-from`, and
has a sentence break after `Unused Pad entry`. The ledger is unchanged. A
real-command test pins the text and JSON output. Only macOS and the
checkout were exercised.
