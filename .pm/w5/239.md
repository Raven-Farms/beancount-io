# `add transaction --date ""` books the entry on today's date with exit 0

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
An empty `--date`, which is what an unset shell variable produces
(`--date "$D"`), is treated as "not given": the transaction is written
with the run date and exit 0. Sibling commands refuse the same empty
value. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Checking USD
2024-01-01 open Assets:Broker HOOL
2024-01-01 open Expenses:Food USD
2024-01-01 open Equity:Opening USD
2024-01-01 commodity HOOL
2024-01-02 * "Opening"
  Assets:Checking  1000.00 USD
  Equity:Opening
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean add transaction Coffee --date '' -p 'Expenses:Food 5.00 USD' -p Assets:Checking
```

Actual: exit 0, `Added 1 transaction`, and the ledger gains `2026-10-11 *
"Coffee"` (the day of the run).

Control: `bea -f main.bean add open --date '' -a Assets:New` exits 2:
`Invalid date ''. Use YYYY-MM-DD format.` `add transaction --date ' '`
(one space) exits 2 the same way. A worker saw `init --date ''` date the
opens today and `add balance … --pad-date ''` use the default pad date,
both with exit 0.

Expected: the help says "Transaction date YYYY-MM-DD; defaults to today",
a default for an omitted option. `docs/USAGE.md` states the policy for
list filters: an empty value "is almost always a template hole or an unset
shell variable" and is refused. The command should exit 2 and write
nothing.

Cause: truthiness tests instead of `is not None`:
`cli/src/cli/commands/add.py:146` and `:262`, and
`cli/src/cli/commands/init.py:148`.

Fix: test `is None`, so `""` reaches the date parser and is refused. No
dependency or API change.

Blast radius: `add transaction --date`, `add balance --pad-date`,
`init --date`. A worker saw the same pattern default `--flag ''` and
`--booking ''` silently.

Dedupe: board search for empty `--date`, unset variable and `pad-date`
finds w3/done/255 (empty strings for required text fields); it does not
cover dates falling back to a default.

Acceptance: each of the three commands with an empty date exits 2 with
`Invalid date ''` and writes nothing; omitting the option still defaults
as documented. Only macOS and the checkout were exercised.
