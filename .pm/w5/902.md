# Import price-conflict advice must respect `unique_prices`

**Trivial · cli · 10–20m · A1.** A price import recommends recording a
second same-day quote with `bea add price --force` even when the ledger's
`unique_prices` plugin prohibits it. Following the advice gives another
conflict, whose add-price message correctly says to edit the existing quote.
Follow-up to completed [397](./done/397.md). Refused commands preserve the
ledger; no data loss or product fix is claimed.

Real CLI QA 2026-10-20, checkout `f5137652f`, `bea 0.3.1`, Darwin 25.5.0
arm64, frontend Python 3.13.3, managed engine Python 3.12 with Beangulp
already available. Reproduced twice with fresh synthetic fixtures, separate
processes, closed stdin/no TTY, isolated absolute BEA_CONFIG_DIR/XDG_CACHE_HOME,
BEA_NO_UPDATE_NOTIFIER=1 and no inherited BEA_FILE/BEA_TOKEN.

Create `/absolute/qa/main.bean`:

```beancount
plugin "beancount.plugins.unique_prices"
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Equity:Opening USD
2024-01-02 * "Opening"
  Assets:Cash 100 USD
  Equity:Opening -100 USD
2024-02-01 price HOOL 100 USD
```

Create a synthetic `quotes.txt` and `importers.py`:

```python
from datetime import date
from decimal import Decimal
from beancount.core.data import Price, new_metadata
from beancount.core.amount import Amount

class Quotes:
    def identify(self, file): return str(file).endswith('.txt')
    def account(self, file): return 'Assets:Cash'
    def extract(self, file, existing_entries=None):
        return [Price(new_metadata(file, 1), date(2024, 2, 1), 'HOOL',
                      Amount(Decimal('120'), 'USD'))]

CONFIG = [Quotes()]
```

From `/absolute/qa`, with the isolated environment:

```sh
bea --json -f /absolute/qa/main.bean check
bea --json --no-input -f /absolute/qa/main.bean import quotes.txt --config importers.py
bea --json --no-input -f /absolute/qa/main.bean import quotes.txt --config importers.py --apply
bea --json -f /absolute/qa/main.bean add price --currency HOOL --amount '120 USD' --date 2024-02-01 --force
```

Initial check exits 0. Preview exits 0 with one price conflict and no write.
Apply exits **4**, stdout empty, with this advice in the JSON error message:
`drop the row, or record a second quote deliberately with bea add price --force`.
The last command follows that alternative but exits **4** too, naming the
plugin and saying to `edit the existing price` instead. Both refusals leave
the ledger byte-identical.

Controls, twice each: remove only the plugin declaration, and the import
still offers the same advice but the forced add succeeds, leaving two prices
and a clean check. With the plugin, correct the existing price line from
100 to 120 in the owned fixture instead: re-import exits 0, writes 0, leaves
one price and passes check. A fresh `list price` verifies each final count.

Cause: `cli/src/bea_engine/importing.py:888–892` builds one unconditional
force remedy for every `price_conflicts` refusal. `ledger/adding.py:937–962`
already checks loaded `unique_prices`/`pedantic` plugins and gives the edit
remedy. Import does not reuse that policy when composing its advice.
The common import helper supplies both human and JSON refusal messages;
only JSON was exercised here. Reciprocal conflicts can reach the same string,
but this reproduction uses a direct same-pair quote.

Fix: when the loaded price policy disallows a second quote, tell the user to
edit the recorded quote at its reported location, preserving the option to
drop an unwanted row. Retain the force alternative where it works. Keep
plugin recognition consistent with add-price, including bundled
`unique_prices`; do not bypass the plugin or weaken validation.

Dedupe: all-board search for import/unique_prices/pedantic and forced-price
remedies, plus active milestone review. 397 (`abc16946`) fixes add-price
only; 766 extends its bundled-plugin recognition; 677 aligns conflict exit
codes. Import's force text dates to `98f70f792` (302) and has no newer
policy-aware change. No overlapping open repair found. Existing add-price
behavior is the working control, not a regression of 397 itself.

Acceptance: this import refusal names a usable existing-quote edit and does
not recommend an impossible forced second quote. Keep the no-plugin force
control, exact re-import after correction, exit categories and unchanged
files on refusal. Evidence retained in ignored pass6
`repro_unique_price_import_hint.py`, `unique-price-import-results.json`, four
fixtures and per-command captures. Other platforms, human output and bundled
plugins remain unverified.
