# Four parser diagnostics still show Python reprs on every bea error surface (`CompoundAmount(number_per=Decimal(…))`, `KeyValue(…, datetime.date(…))`, `TagsLinks(tags={…}, links=set())`), including the `add` refusal for a mistyped posting

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12. Companion to [333](./333.md); the two could ship as one "readable ledger diagnostics" change.
`format_error` (w3/302) rewrites only plugin failures and `noduplicates`
reprs. Upstream's parser (`beancount/parser/grammar.py`) builds four more
messages with `"{}".format(...)` over grammar namedtuples, and bea passes
them through verbatim on these surfaces:

- `--json check` details;
- the strict-read refusals of `balance`, `list`, `report` and `query`;
- `--allow-errors` warnings;
- the `add transaction` posting refusal.

The four messages, plus one cosmetic one, all come from common hand-editing
slips:

| Message | Ledger slip | Rendered as |
| --- | --- | --- |
| `Duplicate cost` (`grammar.py:536`) | `Assets:Broker 10 HOOL {100.00 USD, 101.00 USD}` | `Duplicate cost: 'CompoundAmount(number_per=Decimal('101.00'), number_total=None, currency='USD')'.` |
| `Duplicate metadata field on entry` (`:1083`) | `amt: 5.00` then `amt: 6.00` on a transaction | `… KeyValue(key='amt', value=Decimal('6.00'))` |
| `Duplicate posting metadata field` (`:1101`) | `dt: 2026-01-01` then `dt: 2026-01-02` under a posting | `… KeyValue(key='dt', value=datetime.date(2026, 1, 2))` |
| `Tags or links not allowed after first Posting` (`:1068`) | a `#trip` line between postings | `… TagsLinks(tags={'trip'}, links=set())` |
| (cosmetic) `Too many strings on transaction description` (`:1003`) | `2026-01-03 * "a" "b" "c"` | `… ['a', 'b', 'c']` |

No product fix implemented.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin.

```sh

bea -f /absolute/books/main.bean balance
# on the header alone (no transaction):
bea -f /absolute/books/main.bean add transaction Buy --date 2026-01-03 -p 'Assets:Broker 10 HOOL {100.00 USD, 101.00 USD}' -p Assets:Cash
```

Actual:

- `--json check` exits 1, with the repr lines from the table in `details`.
- `balance` and `report balance-sheet` exit 1 with `Ledger has 1 error(s).
  …` followed by the same lines.
- `add` exits 2 with `--posting 1: Duplicate cost:
  'CompoundAmount(number_per=Decimal('101.00'), number_total=None,
  currency='USD')'.`, and the ledger is unchanged.

All five messages reproduced in fresh directories. The `add` case was
independently rerun.

Control: a balance-assertion failure, `Transaction does not balance`, the
`sellgains` message and `Not enough lots to reduce …` all print readable
amounts. Native `bea check` text is upstream passthrough, as documented,
and is out of scope.

Expected: per w3/302, w5/104, w5/230, w5/294 and w5/333, bea's ledger
diagnostics carry no raw Python reprs. Each message should name the
offending value as Beancount text, for example `Duplicate cost: '101.00
USD'.`, `Duplicate metadata field on entry: amt: 6.00`, or `Tags or links
not allowed after first Posting: #trip`.

Cause: `format_error` (`cli/src/bea_engine/query.py:1721-1739`) passes every
unrecognised message through verbatim. Upstream formats its namedtuples,
sets and lists with `str()`, and for these types that is their repr. The
`add` posting refusal (`cli/src/bea_engine/ledger/adding.py:711`) reports
the parser's message the same way.

Fix: extend `format_error` with a small table of message prefixes, and
re-render the value from the source line the error points at (or from the
repr). Use the same helper for the `add` posting refusal. Unrecognised
messages keep their current rendering. No dependency or API change.

Blast radius: every surface that shows loader errors (JSON `check`,
strict-read refusals, `--allow-errors` warnings, and writer refusals) for
these parser slips. On the `add` path, only the duplicate-cost case is
reachable.

Dedupe: searched `.pm/**`, including `done/`, for `CompoundAmount`,
`TagsLinks`, `KeyValue(`, "Too many strings", "Duplicate metadata field"
and "Tags or links not allowed". w5/200 uses "Duplicate metadata field"
only as a fixture for write gating. w3/302, w5/333 and w5/294 cover other
messages. None of them covers these parser messages.

Acceptance: on the five fixtures, `--json check` details, the `balance`
refusal and the `add` posting refusal contain no `CompoundAmount(`,
`KeyValue(`, `TagsLinks(`, `Decimal(`, `datetime.` or `set()`, and each one
still names the duplicated value or the stray tag. A real-command
regression test covers each message and the `add` refusal. Only macOS and
the checkout were exercised.
