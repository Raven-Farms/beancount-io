# `bea ask` answered with a redirect (HTTP 307/302) says "Could not reach the server (ModelAPIError)" instead of the redirect sentence the cloud commands give

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `6d74be10`, checkout `bea 0.3.1`, macOS 26.5.1. Simulation: local stub answers every request with a redirect.
USAGE's 3xx rule (w5/367): bea does not follow redirects and says so, naming
the target. The cloud commands do. `ask` maps the AI SDK's status error to
"could not reach", which is false (the server answered) and hides the
captive portal or wrong URL behind it. No product fix implemented.

Stub: every request gets `307` with `Location: http://127.0.0.1:18790/x` (and,
separately, 302).

```sh
BEA_TOKEN=<test> BEA_API_URL=http://127.0.0.1:<stub> bea -f /abs/main.bean ask hi --print
BEA_TOKEN=<test> BEA_API_URL=http://127.0.0.1:<stub> bea cloud status
```

Actual: `ask` exits 1 with `Error: Could not reach the server (ModelAPIError).`
`cloud status` exits 1 with `Unexpected redirect (HTTP 307) to
http://127.0.0.1:18790/x; bea does not follow redirects. Check that
BEA_API_URL, if set, names the API with https:// and the right host…`.

Expected: `ask` gives the same redirect sentence (exit 1).

Cause: the OpenAI client raises `APIStatusError` (307), which pydantic-ai wraps
as `ModelAPIError`; `translated_failures` (`cli/src/cli/ask/agent.py:203-210`)
sends it to `_unreachable`.

Fix: route a status-bearing `ModelAPIError` through `_redirect_error` /
`error_from_status`.

Dedupe: searched redirect with ask, `ModelAPIError`; w5/367 (done) fixed the
cloud commands.

Acceptance: the `ask` command prints the redirect sentence. A test pins it.
