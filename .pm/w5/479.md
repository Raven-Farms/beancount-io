# `bea price export` exits 0 when a URL include was refused (not allowlisted), leaving the URL in the "self-contained" snapshot

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `0864aeed`, checkout `bea 0.3.1`, macOS 26.5.1.
The export promises a snapshot that stock tools load. An unavailable source
already refuses it, and w5/190 refused an over-limit one. A refused include
(origin not allowlisted, malformed alias) is never a source, so the
export's check never sees it. The snapshot keeps the URL and `bean-check`
fails on it. No product fix implemented.

`main.bean`:

```beancount
option "operating_currency" "USD"
include "https://www.beancount.io/prices/BTC-USD"
2026-01-01 open Assets:Cash USD
```

Default `MANAGED_PRICE_ORIGINS` (unset), isolated config/cache, closed stdin.

```sh
bea --offline -f /abs/main.bean price export -o exp
```

Actual: the refusal is printed (`origin https://www.beancount.io is not
allowlisted`), then `Exported 1 file to exp.` with exit 0. `--json` gives
`"sources": []`. `exp/main.bean` still holds the URL include, and stock
`bean-check exp/main.bean` exits 1 with `File glob … does not match any
files`.

Control: an allowlisted but unavailable source refuses the export with
`Cannot export: managed price source … is unavailable`.

Expected: the export refuses (or requires `--allow-errors`) and names the
refused include and why.

Cause: the gate at `cli/src/bea_engine/managed_load.py:1121-1126` checks only
`loaded.sources`; refused includes are recorded as load errors, not sources.

Fix: include refused managed includes in the gate, with the same
`--allow-errors` escape and marker as unavailable ones.

Dedupe: w5/450 (refusals in loads) and w5/190 (over-limit sources) are done
and do not cover the export.

Acceptance: the command above exits nonzero, names the include and leaves no
snapshot; with `--allow-errors` the snapshot marks it. A test pins it.
