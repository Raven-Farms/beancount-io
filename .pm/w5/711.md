# When the target file ends inside an unterminated string, `add` blames the new entry ("Proposed append (not written): Invalid token: 'Lunch\"'") and never names the broken line

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `a7c2762d`, checkout `bea 0.3.1`, macOS 26.5.1.
No product fix implemented.

```
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
2026-01-02 note Assets:Cash "Called the bank about
```

```sh
bea --file /abs/main.bean add transaction Lunch --date 2026-01-05 -p "Expenses:Food 10 USD" -p Assets:Cash
bea --file /abs/main.bean add note -a Assets:Cash --comment done --date 2026-01-05 --allow-errors
```

Actual:
- The add exits 1 with `The change would leave the ledger invalid; nothing
  was written.` and `Proposed append (not written): Invalid token: 'Lunch"'`.
- The note with `--allow-errors` exits 1 with `The change would introduce 1
  new ledger error(s)… Invalid token: 'done"'`.
- The file is unchanged. Nothing mentions line 3, so the user is led to
  suspect their own narration.

Control:
- `bea check` reports `main.bean:3: Invalid token: '"Called'`.
- `add balance` on the same file exits 1 with `The ledger already has 4
  error(s), including a syntax error… Fix the syntax error first` and lists
  line 3.

Expected: every add refuses as `add balance` does, naming the existing syntax
error at line 3.

Cause: the quote in the appended text closes the dangling string, so line 3's
lexer error disappears and the new error falls past the old end of file. The
errors are labeled "Proposed append" by line number alone (`cli/src/bea_engine/
ledger/write.py`, around `:1597-1615`). The balance path runs the strict
pre-existing-error check (`_preexisting_refusal`,
`cli/src/bea_engine/ledger/adding.py:298`) first.

Fix: run the syntax pre-check before every append, or refuse when the target
ends inside an unterminated string, naming that line.

Dedupe: searched `unterminated`, `unclosed string`, `Proposed append (not
written): Invalid token`; no hits.

Acceptance: both commands exit 1 naming `main.bean:3`. A test pins one.
