# Pad hints and checks: the Unused Pad warning for a staged pad says to use `add balance --pad-from`, which that same pad then blocks; a `--pad-from` currency refusal says to "record this posting in EUR" for a synthesized pad leg; and a pad whose source is its own account is accepted

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-17, HEAD `116cf55c0`, checkout `bea 0.3.1`, macOS 26.5.1.

---

**Resolved 2026-10-20** — staged pads say to complete with plain `add balance` or remove the pad; pad-leg currency refusals name a `--pad-from` source that allows the currency (or the existing pad); self-pads are exit-2 usage errors. Shipped in `384a89138` (`cli`). Gate note: one full run flaked on two `uv`-shelling distribution/release tests that pass alone and together; clean re-run green (9626 passed).

1. **Staged pad hint.** `st.bean` opens `Assets:Savings USD` and
   `Equity:OpeningBalances`.
   - USAGE's own two-step, `bea --file /abs/st.bean add pad --date 2026-01-01
     -a Assets:Savings -s Equity:OpeningBalances --allow-errors`, exits 0 with
     `Unused Pad entry. Add both directives atomically with bea add balance
     --pad-from ACCOUNT …`.
   - Following that hint exits 1: `The ledger has a staged pad still waiting
     for its balance assertion; nothing was written. Complete that pair …`.
   - The same atomic hint appears on unrelated refusals while a pad's balance
     is missing (hunter's run).
   - USAGE says to complete a staged pad with a plain `add balance`, as the
     staged nounused open does (w5/221).
2. **Pad currency hint.** With `open Equity:EurOnly EUR`, `add balance --date
   2026-01-10 -a Assets:Checking --amount "100.00 USD" --pad-from
   Equity:EurOnly` exits 1 with `… for EUR only. To post USD there, edit that
   open … otherwise record this posting in EUR, converted at the rate paid.`.
   A pad's leg cannot be written in another currency. The plain balance
   hint already says to choose a source that allows USD.
3. **Self-pad.** `add pad --date 2026-01-09 -a Assets:Checking -s
   Assets:Checking --allow-errors` exits 0 and stages a pad no balance can
   complete. `add balance … --pad-from Assets:Checking` gets only "Balance
   failed … review missing transactions" (hunter's run).

Expected:
1. "Staged: add its balance with `bea add balance` (without `--pad-from`), or
   remove the pad."
2. "Choose a `--pad-from` account that allows USD, or edit that open."
3. Exit 2: the pad source must be another account.

Cause: `_unused_pad_hint` (`cli/src/bea_engine/ledger/write.py:2054`) returns
the atomic text for any pad without a following assertion.
`_currency_widen_hint` (`:2213`) treats the padding transaction like a user
posting. Neither `add pad` nor `add balance` checks that the source differs
from the account.

Fix: word the staged case and the pad-leg case separately, and refuse
source == account.

Dedupe: w3/224 (done) covers the hint after a matching `--pad-from`; w5/488
(done) and 660 (open) cover other currency legs.

Acceptance: each case gives the expected message; following case 1's hint
writes.
