# An import preview with 0 ready rows still ends "Review the entries, then repeat with --apply to write.", whether every row is a duplicate or every row is blocked

**Trivial · cli · 5–10m · A1.** Real CLI QA, 2026-10-17, HEAD `101b89e3`, checkout `bea 0.3.1`, macOS 26.5.1.
No product fix implemented.

```sh
printf 'Date,Description,Amount\n2026-03-02,Coffee,-4.50\n' > a.csv
bea --file /abs/main.bean import a.csv --account Assets:Checking --apply
bea --file /abs/main.bean import a.csv --account Assets:Checking
```

Actual: the second command exits 0 with `0 ready, 1 exact duplicates…`, `Row 1:
import-id … is already in the ledger.`, then `Preview only. Review the
entries, then repeat with --apply to write.` Following that advice prints
`Wrote 0 entries`. When every row is blocked (w5/692's fixture), the same
footer appears and `--apply` exits 4. Rerunning the tutorial import after
applying it gives the same footer.

Expected: no offer to write when nothing can be written. For example,
`Nothing new to import.` when every row is a duplicate, and `Resolve the
blocked rows, then preview again.` when rows are blocked.

Cause: `cli/src/cli/commands/import_.py:1176` prints the footer whatever the
counts.

Fix: choose the footer from `ready`, `blocked` and `conflicts`.

Dedupe: w5/638 and 684 (open) cover previews that wrongly report rows ready;
this is the 0-ready case.

Acceptance: an all-duplicate preview and an all-blocked preview print
footers that don't suggest `--apply`. A test pins both.
