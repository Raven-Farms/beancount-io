# `doctor missing-open` calls a posting dated before its account's `open` a "closed account" and counts error lines as accounts

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
When a posting predates its account's `open`, `doctor missing-open` says
the ledger "still references 1 closed account(s); reopen them". Nothing is
closed, and the number counts error lines, not accounts. The exit code is
right; the remedy is wrong. No product fix implemented.

Create disposable `/absolute/books/pre.bean`:

```beancount
2026-02-01 open Assets:Cash
2026-01-01 open Equity:Opening
2026-01-15 * "early"
  Assets:Cash  1.00 USD
  Equity:Opening
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea doctor missing-open pre.bean
```

Actual: exit 1. stdout: `pre.bean:3: Invalid reference to inactive account
'Assets:Cash'`. stderr: `Error: doctor missing-open still references 1
closed account(s); reopen them or fix the postings.` A worker saw "3 closed
account(s)" for a ledger with one early two-posting transaction and one
posting to a single closed account.

Control: a ledger that opens, closes, then posts to the account gets the
same message, which is accurate there (worker observation).

Expected: the message should describe what Beancount reported — an
inactive account, used before its open date or after its close — and count
distinct accounts, so the reader moves the `open` earlier instead of
looking for a `close` to undo.

Cause: `cli/src/cli/commands/doctor.py:361-366` filters check details on
the substring `inactive account`, uses `len(inactive)` and hard-codes
"closed account(s); reopen them".

Fix: report "N reference(s) to M inactive account(s) (posted before the
open date or after the close)" with M deduplicated. No dependency or API
change.

Blast radius: `doctor missing-open` only.

Dedupe: w3/364 (done) introduced this path and considers only closed
accounts; board search for "closed account(s)" finds nothing else.

Acceptance: the command still exits 1, and its message says "inactive"
with distinct-account count 1 and mentions the open date; the closed-account
case still reads correctly. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — `doctor missing-open` now reports "N reference(s) to M inactive account(s) (posted before the open date or after the close)" with M counted as distinct accounts, and its remedy mentions moving the open earlier as well as reopening (`cli/src/cli/commands/doctor.py`). The exit code and the forwarded Beancount lines are unchanged; the exit-status table in `docs/USAGE.md` uses the same wording. The regression test covers a posting before the open date and two postings to one closed account (both fail with the fix reverted), and an active ledger that exits 0. Only macOS was exercised. `make check-all` passed. Shipped in `0ac80cef` (`cli`).
