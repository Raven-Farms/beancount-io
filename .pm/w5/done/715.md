# Import's settings notes are still missing from three flag-free refusals (a remembered date format, a remembered encoding, an unreadable settings directory) and are now added to a typed `--csv` refusal, where they are documented not to appear (incomplete fix of w5/525)

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-17, HEAD `8cd20be7`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/525 (done, `3d6b3b6f`).
IMPORTING.md:584-586 says "A failure with no preview, on a run whose column
mapping was remembered or read from the header row, lists those settings
notes first in the error details". The w5/282 resolution limits this to
recalled or inferred mappings, "never typed". No product fix implemented.

`main.bean` opens `Assets:Checking EUR`. Every CSV has the header
`Date,Description,Amount`.

1. **Remembered date format.**
   - Apply `a.csv` (`13/03/2026,COFFEE,-3.00`) with `--account Assets:Checking
     --date-format %d/%m/%Y`.
   - Then `bea --json --file /abs/main.bean import b.csv` (`2026-03-14,…`)
     exits 2 with `Remembered --date-format %d/%m/%Y does not match b.csv…`
     and no `details`.
2. **Remembered encoding.**
   - Apply a cp1252 `a2.csv` with `--csv encoding=cp1252`.
   - A flag-free `import d.csv` (byte `\x81`) exits 2 with `d.csv is not valid
     cp1252 (character maps to <undefined> at byte 36).` It has no `details`,
     and nothing says the user never typed cp1252.
3. **Unreadable settings directory.** With `chmod 000 <config>/importers`, a
   flag-free `import e.csv` of a cp1252 file gets the plain decode refusal.
   It lacks the documented `Cannot read remembered import settings…` note
   (IMPORTING.md:321-326), although that unreadable directory is why the
   remembered cp1252 was not applied (hunter's run).
4. **Typed run (new).** `bea --json --file /abs/main.bean import bad.csv
   --account Assets:Checking --csv date=Date,amount=Amount,narration=Description`
   (`2026-03-99`) exits 2 with `"details": ["Using column mapping (--csv)."]`.
   Before the fix, details were empty here. A bad amount on the same run
   still has none.

Control: a bad date on a remembered run lists `Using settings remembered from
a.csv for c.csv: …`.

Expected: cases 1–3 carry the settings notes; case 4 carries none.

Cause (`cli/src/cli/commands/import_.py`):
- `settings_notes` (`:843`) is not used by the date-format mismatch
  (`details=recall_notes` around `:916`), the delimiter or decode refusals
  raised before it exists (around `:778-786`), or the `--importer` refusal
  (`details=config_notes`, around `:815`).
- Its typed branch now feeds the bad-date refusal.

Fix: use `settings_notes` in those refusals, but only for a remembered or
inferred origin.

Dedupe: w5/525 and 282 (done) are the parents.

Acceptance: cases 1–3 list the notes in text and JSON; case 4 has no
details. Tests pin cases 2 and 4.
