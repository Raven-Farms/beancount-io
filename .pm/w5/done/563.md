# `SELECT DISTINCT other_accounts` leaks Python's "cannot use starred expression here (<string>, line 4)" and gives advice about `tags` and `links`

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `7898f69d`, checkout `bea 0.3.1`, macOS 26.5.1. Gap in w3/353 and w5/260.
`other_accounts` is a list column, like `tags` and `links`, and cannot be
hashed. bea explains this for `GROUP BY` (`BQL cannot group by
other_accounts (list)…`), but `DISTINCT` falls to the generic compile error,
whose advice names the wrong columns. No product fix implemented.

```sh
bea --file /abs/main.bean query "SELECT DISTINCT other_accounts"
```

Actual: exit 2, `Error: Beanquery could not compile this BQL query: cannot use
starred expression here (<string>, line 4).`, then four lines about `tags`
and `links` holding a set per entry.

Control: `SELECT other_accounts, count(*)` gets the specific `other_accounts`
message with a `joinstr(other_accounts)` recipe.

Expected: the same `other_accounts` message and recipe for `DISTINCT`, with
no Python syntax text.

Cause: `_SET_COLUMNS = ("tags", "links")` (`cli/src/bea_engine/query.py:1769`),
so the SyntaxError branch (`:1625-1632`) uses the generic tags/links advice.

Fix: include `other_accounts` with its own recipe.

Dedupe: w3/353 and w5/260 (done) cover tags/links and implicit grouping.

Acceptance: the command names `other_accounts` and the `joinstr` recipe. A
test pins it.

---

**Resolved 2026-10-17** — Shipped in `2ec640a8` (`cli`). In `cli/src/bea_engine/query.py`, `other_accounts` joins `_SET_COLUMNS`, and `_set_column_advice` gives it its own recipes (`joinstr(other_accounts)` for distinct combinations and counts) instead of the tags/links lines; a query naming both gets both. `SELECT DISTINCT other_accounts` now exits 2 with `BQL cannot use DISTINCT or GROUP BY on other_accounts: a list is not a value it can compare.` and no Python syntax text. The non-hashable path uses the same advice. `tests/test_query_set_columns.py::test_distinct_on_other_accounts_names_it_and_its_own_recipe` pins the message, the advice and that the recipe runs; it fails without the fix.
