# `add open --booking` advertises AVERAGE, which the engine cannot book

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
`bea add open --help` lists AVERAGE as a lot booking method and accepts
it. An account opened that way takes purchases but can never sell: every
reduction is refused with "AVERAGE method is not supported". `bea check`
stays clean throughout. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Income:Gains USD
2026-01-02 * "seed"
  Assets:Checking  1000.00 USD
  Income:Gains
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea add open --date 2026-01-01 --account Assets:Avg --booking AVERAGE
bea add transaction buy --date 2026-02-01 -p "Assets:Avg 1 HOOL {10 USD}" -p Assets:Checking
bea add transaction buy --date 2026-02-02 -p "Assets:Avg 1 HOOL {20 USD}" -p Assets:Checking
bea add transaction sell --date 2026-02-03 -p "Assets:Avg -1 HOOL {}" -p "Assets:Checking 15 USD" -p Income:Gains
```

Actual: the first three exit 0. The fourth exits 1: `Error: The change
would leave the ledger invalid; nothing was written. Proposed append (not
written): AVERAGE method is not supported`.

Control: the same four commands with `--booking FIFO` all exit 0.

Expected: help should list only methods that work, or `add open` should
refuse or warn for AVERAGE, and the refusal on the sale should say what to
do. The limitation is upstream (Beancount 3.2.3 rejects every AVERAGE
reduction); advertising it as a choice is `bea`'s own text.

Cause: the option help in `cli/src/cli/commands/add.py`, the generated
`docs/REFERENCE.md`, and the unknown-value message in
`cli/src/bea_engine/ledger/writer.py` all name AVERAGE.

Fix: drop AVERAGE from help and the reference (regenerate with `make
docs`); optionally refuse it in `add open` with exit 2 and add a remedy to
the "not supported" message. No dependency or API change.

Blast radius: `add open --booking` and its documentation.

Dedupe: board search for AVERAGE and booking finds w3/done/306 (introduced
`--booking`, listing AVERAGE as expected) and w3/done/290 (`list open`);
neither notes that it is unusable.

Acceptance: `bea add open --help` no longer offers AVERAGE (or `add open
--booking AVERAGE` exits 2 explaining why); the FIFO control is unchanged.
Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — `bea add open --booking` no longer offers AVERAGE: the option help in `cli/src/cli/commands/add.py` and the regenerated `cli/docs/REFERENCE.md` list STRICT, STRICT_WITH_SIZE, NONE, FIFO, LIFO and HIFO, and `write_open` in `cli/src/bea_engine/ledger/writer.py` refuses AVERAGE (any case, text or `--json`) with exit 2 before anything is written, explaining that Beancount cannot reduce a position booked that way; the unknown-method message drops it from its choices too. For ledgers that already carry a hand-written AVERAGE account, the rejected sale in `cli/src/bea_engine/ledger/write.py` now appends the remedy (edit that account's open directive to another method) to the upstream "AVERAGE method is not supported". The regression test `cli/tests/test_add_open_booking_average_refused.py` covers the help text, the text and JSON refusals with the ledger left byte-identical, the unknown-method choices, the remedy on a sale, and the four-command FIFO control; six of its seven cases fail with the fix reverted and the FIFO control passes either way. The refusal is unconditional, so `--allow-errors` does not let `add open` write AVERAGE; such an account can still be written by hand. Only macOS was exercised. `make check-all` passed. Shipped in `6e08dba5` (`cli`).
