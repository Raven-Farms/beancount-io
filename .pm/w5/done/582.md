# Process substitution for `import --rules <(…)` and `--config <(…)` gives misleading errors ("Bad file descriptor", "Importer configuration not found") (gap in w5/436)

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `3514cc17`, checkout `bea 0.3.1`, macOS 26.5.1.
w5/436 made a pipe passed as the import source say "is a pipe, not a file.
Save it to a file…". The `--rules` and `--config` files are read in the
engine child, which does not inherit the descriptor. No product fix
implemented.

bash, with a valid `r.toml` and `cfg.py`:

```sh
bea -f /abs/main.bean import s.csv --csv date=Date,amount=Amount,payee=Payee --account Assets:Checking --rules <(cat r.toml)
bea -f /abs/main.bean import s.csv --config <(cat cfg.py)
```

Actual: `Cannot read rules file /dev/fd/63: [Errno 9] Bad file descriptor:
'/dev/fd/63'.`; and `Using importers from /dev/fd/63` followed by `Importer
configuration not found: /dev/fd/63` (exit 2).

Control: `import <(cat s.csv)` gives the pipe message; `--rules r.toml`
works.

Expected: either the frontend reads the file and passes its content (so it
works), or the refusal says `--rules /dev/fd/63 is a pipe, not a file; save
it to a file`.

Cause: the engine child runs with `close_fds`; `cli/src/bea_engine/csv_mapper.py:451-453`
reads the rules there and `cli/src/bea_engine/importing.py:753-754` checks
`is_file()`.

Fix: apply the w5/436 pipe check (`output.not_a_file`) to `--rules` and
`--config` in the frontend.

Dedupe: w5/436 (done) covered the source, treeify and doctor.

Acceptance: both commands give the pipe message (or work). A test pins it.

---

**Resolved 2026-10-17** — Shipped in `95e5d653` (`cli`). `bea import` (`cli/src/cli/commands/import_.py`) now applies w5/436's check to `--rules` and `--config` in the frontend, before the engine child starts. The child does not inherit a `<(…)` descriptor. An existing path that is not a regular file is refused with exit 2, for example `--rules /dev/fd/63 is a pipe, not a file. Save it to a file and pass that file.`, replacing `Bad file descriptor` and the config `not found`. `tests/test_process_substitution_inputs.py::test_a_piped_import_option_file_is_named` pins both flags with a held pipe; both fail without the fix.
