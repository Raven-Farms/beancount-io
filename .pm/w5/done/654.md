# `--into` written relative to the working directory from a subdirectory gets advice to create a new include (or a doubled `ledger/ledger/` directory) instead of "--into is relative to the root's directory; did you mean txns/2026.bean?"

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `87ad7af8`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE: `--into` "is relative to the root ledger's directory". Users and agents
working in a subdirectory naturally type the path relative to where they
are. The refusal does not say which base it used, and it advises creating
a new include for a file that is already included. No product fix
implemented.

`ledger/main.bean` with `include "txns/*.bean"` and an existing
`ledger/txns/2026.bean`.

```sh
cd ledger/txns
bea --file ../main.bean add transaction X --into 2026.bean --date 2026-02-01 -p "Expenses:Food 5 USD" -p Assets:Checking
cd ../..
bea --file ledger/main.bean add transaction X --into ledger/txns/2026.bean --date 2026-02-01 -p "Expenses:Food 5 USD" -p Assets:Checking
```

Actual: (1) exit 2, `Write destination …/ledger/2026.bean is not included by
…/main.bean. Create it and add an include directive to the root first.`, never
mentioning the included `txns/2026.bean`; (2) exit 2, `Write destination
directory …/ledger/ledger/txns does not exist. Create the directory first.`
`import --apply --into` gives the same messages.

Expected: both refusals state the rule (relative to `…/ledger`), and when the
working-directory reading names an included file, suggest it (`did you mean
--into txns/2026.bean?`).

Cause: the last two refusals in `require_target`
(`cli/src/bea_engine/ledger/write.py:196-201`).

Fix: as above.

Dedupe: searched `Create the directory first`, `add an include directive to the
root first`; w3/228, w5/386 and 449 are different; w5/492 (open) covers the
staging wording for a missing directory under a glob.

Acceptance: both commands name the rule and the intended file. A test pins
them.

---

**Resolved 2026-10-18** — Shipped in `818c608d2` (`cli`). Shared write-destination refusals now state that relative `--into` paths use the root ledger's directory. The raw spelling is preserved across add, import and append checks so symlink components identify the right member; absolute paths receive no cwd-relative guess.
