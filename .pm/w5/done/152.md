# `add balance` treats a plugin-generated assertion as "already recorded" and writes nothing

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
On a ledger using `beancount.plugins.check_drained`, the plugin
synthesizes a zero balance assertion after each `close`. `bea add balance`
for that account and date reports the assertion as already recorded —
pointing at the `close` line — and exits 0 without writing, though no
`balance` directive exists in any file. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
plugin "beancount.plugins.check_drained"
option "operating_currency" "USD"
2023-01-01 open Assets:Bank USD
2023-01-01 open Assets:Old USD
2023-01-01 open Equity:Opening
2023-01-02 * "Opening"
  Assets:Bank  1000.00 USD
  Equity:Opening
2023-02-01 close Assets:Old
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean add balance -a Assets:Old --amount '0 USD' --date 2023-02-02
bea -f main.bean list balance --on-disk
```

Actual: the first exits 0 with `Balance already recorded at
/absolute/books/main.bean:9; nothing was written.` Line 9 is the `close`.
The second prints `No balance assertions found.`

Control: the same ledger without the `plugin` line exits 0 with `Added 1
balance`. A worker saw `--amount '0.00 USD'` on the plugin ledger exit 2
("already has a 2023-02-02 balance of 0 USD … refusing 0.00 USD"), and
`add price` on an `implicit_prices` ledger correctly ignore the generated
price.

Expected: `docs/USAGE.md` says "Only written price directives count: a
price a plugin such as `implicit_prices` generates is neither a duplicate
nor a conflict. `add balance` is idempotent the same way". The assertion
should be written.

Cause: `cli/src/bea_engine/ledger/adding.py:388-426` (`_balance_match`,
`_balance_conflict`) scan every loaded `Balance` without the
`entry_generated(entry, …)` filter the price path applies at `:568`.

Fix: skip generated balances in both helpers, including the `--pad-from`
retry path. No dependency or API change.

Blast radius: `add balance` on ledgers with a plugin that synthesizes
`Balance` entries; `check_drained` confirmed, `check_closing` uses the
same mechanism and was not run.

Dedupe: board search for `check_drained`, `check_closing`, "already
recorded" and generated finds w3/done/318–320 (generated rows in `list`)
and w5/070; none covers `add balance`.

Acceptance: the first command writes `2023-02-02 balance Assets:Old 0
USD` and `list balance --on-disk` shows it; re-running is then an
idempotent no-op citing the written line. Only macOS and the checkout
were exercised.

---

**Resolved 2026-10-13** — `add balance` now ignores balance assertions a plugin synthesizes: the `_balance_match` and `_balance_conflict` helpers in `cli/src/bea_engine/ledger/adding.py` skip entries `entry_generated` reports as not on disk, the same filter `add price` already applied, so both the plain path and the `--pad-from` retry see only written assertions. On a `check_drained` ledger the command writes `2023-02-02 balance Assets:Old 0 USD`, `list balance --on-disk` shows it, and a re-run is an idempotent no-op citing the written line; a different precision is no longer refused as a conflict with the `close` line. The regression test `cli/tests/test_add_balance_generated_assertion.py` runs the real command over `check_drained` and `check_closing` ledgers, the conflict and `--pad-from` paths, and a no-plugin control; four of its five cases fail with the fix reverted (the control passes either way). `docs/USAGE.md` already stated this contract, so no prose changed. Only macOS was exercised. `make check-all` passed. Shipped in `2978156c` (`cli`).
