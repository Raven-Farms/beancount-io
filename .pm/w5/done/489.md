# A futures commodity such as `/0J` is refused as "Division by zero" in `add` postings, balances and bulk amounts

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `7334a32b`, checkout `bea 0.3.1`, macOS 26.5.1.
Beancount 3 accepts currencies that begin with `/` (futures contracts such
as `/6J`, `/0J`, `/ESZ26`). bea's zero-divisor pre-check reads `/0` as a
division by zero whenever a letter follows. No product fix implemented.

Any ledger with `Assets:Brokerage` (no currency constraint) and `Assets:Cash` open.

```sh
bea -f /abs/main.bean add transaction F --date 2026-01-05 -p 'Assets:Brokerage 1 /0J {100 USD}' -p 'Assets:Cash'
bea -f /abs/main.bean add balance --date 2026-01-06 -a Assets:Brokerage --amount '1 /0J'
```

Actual: exit 2, `Division by zero in 'Assets:Brokerage 1 /0J {100 USD}'.
Beancount evaluates amount arithmetic while parsing…`. A bulk row `"amount":
"1 /0J {100 USD}"` is rejected the same way.

Control: `-p 'Assets:Brokerage 1 /6J {100 USD}'`, `add commodity -c /0J`,
`add price -c /0J` and bulk `"currency": "/0J"` are accepted, and `bea check`
passes on the result.

Expected: `/0J` is a currency, and the posting is written.

Cause: the regex `/\s*[-+]?(?:0+(?:\.0*)?|\.0+)(?![\d.])` at
`cli/src/cli/amounts.py:61` and `cli/src/bea_engine/amounts.py:139`. Its
lookahead does not exclude a following letter or currency character.

Fix: extend the negative lookahead to `[\d.A-Z'_-]` (or require the divisor
to end at whitespace, `)` or end of text).

Dedupe: searched `/0J`, `futures`. w5/010 and 057 concern real zero divisors.

Acceptance: both commands succeed; `1 / 0 USD` is still refused. A test pins
both.

---

**Resolved 2026-10-16** — Shipped in `277ffac7` (`cli`). The zero-divisor pre-check in `check_decimal_notation` (`cli/src/cli/amounts.py`) and in the engine's `refuse_zero_divisor` (`cli/src/bea_engine/amounts.py`, used for bulk rows) now stops at a currency character after the zero (`(?![\d.A-Z'_-])`). `1 /0J {100 USD}` and `add balance … '1 /0J'` are written and check clean, while `1 / 0 USD`, `1/0 USD`, `(1/0.0) USD` and `10 / -0` are still refused. `tests/test_futures_commodity_not_zero_divisor.py` pins both functions and the end-to-end add; the slash-currency cases fail without the fix.
