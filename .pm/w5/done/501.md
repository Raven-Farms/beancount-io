# `report -a Equity -t 2025` drops the period's previous earnings: equity shows -1,000 where `bea balance Equity -t 2025` and the unfiltered report show -4,000, and `-a Equity:Earnings` says "No accounts match"

**Major · cli · 30–45m · A1.** Real CLI QA, 2026-10-16, HEAD `e03cf71e`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE (Reports): with `--account`, "totals, trees, and the interval
breakdown all describe the accounts you asked for". When a time filter
opens a period, Beancount's clamp moves prior income into
`Equity:Earnings:Previous` and builds the opening and conversion summaries.
The report runs that clamp after the account filter, so it sees only the
transactions that touch the filtered accounts. The synthesized equity
entries are missing or wrong, with exit 0. No product fix implemented.

`eq.bean`:

```beancount
option "operating_currency" "USD"

2024-01-01 open Assets:Bank USD
2024-01-01 open Equity:Opening-Balances
2024-01-01 open Income:Salary USD

2024-01-01 * "Opening"
  Assets:Bank 1000.00 USD
  Equity:Opening-Balances

2024-06-30 * "Salary"
  Assets:Bank 3000.00 USD
  Income:Salary

2025-03-01 * "Salary"
  Assets:Bank 100.00 USD
  Income:Salary
```

Isolated config/cache, closed stdin.

```sh
bea -f /abs/eq.bean report trial-balance -t 2025
bea -f /abs/eq.bean report trial-balance -t 2025 -a Equity
bea -f /abs/eq.bean balance Equity -t 2025
bea -f /abs/eq.bean report trial-balance -t 2025 -a Equity:Earnings
```

Actual:

- unfiltered: `Equity -4,000.00 USD`, with `Earnings:Previous -3,000.00`
  and `Opening-Balances -1,000.00`;
- `-a Equity`: `Equity -1,000.00 USD`, only `Opening-Balances`. The
  balance sheet does the same, as does `--json` (`account_filter_empty:
  false`);
- `bea balance Equity -t 2025`: -4,000.00, including `Previous`;
- `-a Equity:Earnings`: `No accounts match Equity:Earnings.`, exit 0.

In a multi-currency ledger `-a Equity -t 2024-02` also loses
`Equity:Conversions:Current` and values `Opening-Balances` differently.

Control: Assets, Income and Expenses filters with `-t` match the unfiltered
balances exactly. BQL `SELECT account, sum(position) FROM OPEN ON 2025-01-01
CLOSE ON 2026-01-01 WHERE account ~ '^Equity' GROUP BY account` gives -3000
and -1000.

Expected: the filtered report equals the unfiltered report's Equity
subtree, and `bea balance Equity -t 2025`.

Cause: `FilteredLedger` (`cli/src/fava/ledger.py:181-187`) applies the
`AccountFilter` before the `TimeFilter` clamp, so `clamp_opt` summarizes
only filtered transactions. This is inherited Fava ordering.
`account_filter_empty` (`cli/src/bea_engine/report.py:578`) then judges
from those entries.

Fix: clamp over all entries first, then apply the account filter to the
clamped entries (in bea's report layer, or in the vendored `FilteredLedger`
keeping `NOTICE.fava`). Pin `-a Equity`, `-a Equity:Earnings` and an FX
conversion case.

Blast radius: every `report` subcommand with `-a` and `-t` on equity (and any
account the clamp synthesizes into).

Dedupe: searched `Earnings:Previous`, `retained earnings`, `clamp`. w3/288
(phantom opening balances) is different; the hosted w6/m5 milestone is
backend-only.

Acceptance: the four commands agree on -4,000 / -3,000. A test pins it.

---

**Resolved 2026-10-17** — Shipped in `14143aae` (`cli`). `FilteredLedger` (`cli/src/fava/ledger.py`, marked as a Beancount.io change) now applies the account filter after the time filter's clamp. The clamp summarizes every entry, and `--account` then narrows the clamped entries. The advanced filter still runs before the clamp, as in Fava. `report trial-balance -t 2025 -a Equity` shows -4,000 (`Earnings:Previous` -3,000, `Opening-Balances` -1,000), matching the whole report and `bea balance Equity -t 2025`. `-a Equity:Earnings` finds `Previous` at -3,000, and the FX case keeps `Equity:Conversions:Current`. `tests/test_report_account_filter_after_clamp.py` compares the filtered and whole equity trees for both ledgers and pins `-a Equity:Earnings`; all fail without the fix.
