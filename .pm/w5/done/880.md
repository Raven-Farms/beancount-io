# Portable plugin exports omit runtime helpers on cached loads and namespace-package resources, reporting success for snapshots that fail check (follow-up to w5/327)

**Minor · cli · 45–60m · A1.** Real CLI QA, 2026-10-20, checkout
`bea 0.3.1`, HEAD `866d1e78a`, Darwin 25.5.0 arm64; frontend Python 3.13.3.
No product fix implemented.

Create disposable `/abs/case/books/main.bean`:

```beancount
option "operating_currency" "USD"
option "insert_pythonpath" "TRUE"
plugin "myplug"
2024-01-01 open Assets:Cash USD
```

Create `books/helper.py` containing `TEXT = "Synthetic"`, and this
inspected local `books/myplug.py`:

```python
import time
__plugins__ = ["run"]
def run(entries, options):
    time.sleep(1.1)
    import helper
    assert helper.TEXT == "Synthetic"
    return entries, []
```

The sleep makes the tiny fixture reach the normal load-cache threshold;
a naturally slow ledger/plugin has the same state. With isolated absolute
`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, no inherited
`BEA_FILE`/`BEA_TOKEN`, closed stdin/no TTY, cwd `/abs/case`:

```sh
bea --json --file /abs/case/books/main.bean check
bea --json --file /abs/case/books/main.bean check
bea --json --file /abs/case/books/main.bean price export --output /abs/case/snapshot
bea --json --file /abs/case/snapshot/main.bean check
```

Actual: both source checks exit 0. The second serves the cache. Export exits
0 and lists only `snapshot/main.bean` and `snapshot/myplug.py`;
`helper.py` is missing. A fresh snapshot check exits 1 with
`Plugin "myplug" failed while running: ModuleNotFoundError: No module named
'helper'.` Reproduced twice in fresh directories.

In the captured fixture, an additional local `.runs` marker appended by the
plugin confirms it ran once for the first check, then zero times for the
cached check/export. First check takes ~1.4 s; cached check/export ~0.2–0.3 s.
The marker is optional instrumentation; the public plugin above suffices.

Working control: export the unchanged source using a fresh **isolated**
cache directory in the child environment and a new output directory. The
plugin executes, `helper.py` is included, and the fresh snapshot check exits
0. An import at module scope is the existing w5/327 control. This failure
uses ordinary readable files, independently of w5/879's permissions case.

Expected: dependency completeness must not depend on whether this ledger
was checked recently. USAGE promises a self-contained snapshot including
local helper modules the plugin imports. Either carry the helper or refuse
the incomplete export before publishing success.

Cause: `_sibling_imports` in
`cli/src/bea_engine/managed_load.py:2193–2237` calls
`importlib.import_module` for each plugin then scans `sys.modules`. On a
cached load the plugin function did not run, and importing its module does
not execute the function's `import helper`. The helper is absent from the
module inventory and `_export_plugin_modules` omits it. Cold loads happen
to populate that inventory. Local helpers and helper packages imported
during plugin execution share the gap.

Fix: ensure export's dependency inventory includes imports made while
plugins execute even when ordinary reads can reuse a cached load, or
validate/refuse an incomplete staged snapshot before reporting success.
Keep unrelated root-directory files excluded and preserve containment,
collision, atomicity and permission checks. Avoid a repair that merely
copies every nearby file. No dependency or backend/API change is needed.

Dedupe: whole-board searches for cached/lazy plugin helper exports and all
open/blocked milestone scopes found completed w5/327 (`32638d15`). That fix
explicitly imports plugin modules to account for caching, but its tests use
module-scope imports only. w5/220 concerns cached normalization, and
w5/868/879 concern package resources/traversal. Targeted source history
contains no repair for function-scope dependency discovery.

Acceptance: warm and cold exports of the fixture both produce fresh-loadable
snapshots, or an incomplete export refuses without destination residue;
module-scope and no-helper controls continue working. Pin the actual warm
cache transition with subprocesses. Windows/Linux and repaired behavior
remain unverified. Sanitized evidence and fixtures are retained under
`.tmp/qa-2026-10-20-cli-loop-d3c5ebec/`: `export-cached-plugin-{1,2}/`
and matching `captures/cached-plugin-*.json`. The public setup is sufficient
without ignored evidence.

## Additional dependency-inventory gap: namespace-package resources

Reproduced twice at HEAD `1417b263f`, independently of caching. Use the
same root ledger above, remove `helper.py`, create
`books/bankdata/settings.json` containing `{"ok": true}`, and deliberately
leave `bankdata` without `__init__.py`: it is a Python namespace package.
Replace `myplug.py` with:

```python
from importlib.resources import files
__plugins__ = ["run"]
def run(entries, options):
    assert files("bankdata").joinpath("settings.json").read_text().strip() == '{"ok": true}'
    return entries, []
```

Run the source check, export and snapshot check commands above in a fresh
case/cache directory. The source check exits 0; export exits 0, copies
`myplug.py` but omits the entire `bankdata/` directory. The snapshot check
exits 1 with `Plugin "myplug" failed while running: ModuleNotFoundError:
No module named 'bankdata'.` The captured plugin appends a local call marker:
it executes once on source check and again on export, proving the omission
also occurs on a cold load. The original source directory was temporarily
renamed inside the disposable case before checking the snapshot, then
restored in `finally`, so the portability check had no original-module
fallback.

Working control, repeated twice: add only an empty
`books/bankdata/__init__.py` to an otherwise identical pristine fixture.
Export includes the resource, and the snapshot checks successfully while
the original source is hidden. All source directories have been restored.

The additional cause is distinct from cache reuse but lives in the same
dependency inventory: `_sibling_imports` at `managed_load.py:2219–2221`
unconditionally skips a module whose `__file__` is absent/None. Namespace
packages identify their locations with `__path__`, so this local helper is
never added to `wanted`; `_package_files` is never asked to carry its
resource. Executing the plugin again alone does not fix this variant.
Conversely, recognizing namespace locations alone does not fix the original
cached function-scope helper case. The two real failures need both controls.

Extend the fix to recognize local namespace-package search locations under
the allowed ledger module paths, retaining containment, collision and
permission checks; do not copy arbitrary directories from `sys.path`.
USAGE's promise that imported local packages travel with their data applies
to this working standard-library resource loader too. This is one shared
dependency-inventory repair, kept with the overlapping open item rather
than filed twice. All-board searches for namespace packages, `__path__`
and missing `__file__` found no other coverage; w5/868's helper-package
resource control uses a regular package. Targeted history traces this
discovery code to w5/327's `97ee41737`.

Additional acceptance: both namespace and regular-package fixtures produce
fresh-loadable snapshots with `bankdata/settings.json`, or an incomplete
export refuses before publishing files. Keep the original warm/cold helper
controls. Multi-location namespace packages and Windows/Linux remain
unverified. Sanitized captures/fixtures are
`.tmp/qa-2026-10-20-cli-loop-pass2-2afc4ed1/namespace-export-{1,2}-{namespace,regular}/`
and matching `captures/namespace-export-*.json`. No product fix implemented.

---

**Resolved 2026-10-22** — portable export now runs each local plugin function once more on a copy of the entries list while inventorying imports, so a helper imported inside the function travels even when the load was served from cache, and it reads `__path__` for packages without `__file__`, so a namespace package and its resources travel. `cli/tests/test_price_export_plugin_runtime_imports.py` (warm-cache and namespace fixtures, snapshot checked with the source hidden) fails without the fix; shipped in the commit that moves this note (`cli`).
