# `add balance` in a currency the account's `open` does not allow prints upstream's dangling `Invalid currency 'USD' for Balance directive: `, then the generic missing-transactions advice and a `--pad-from` command that cannot work

**Trivial · cli · 15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
A balance assertion in a currency that the account's `open` excludes gets
upstream's message, which ends in `: ` because upstream expects the entry
to be printed after it. bea then adds the normal recovery block:

- "Review missing or duplicate transactions and record known fees …";
- an "Opening adjustment command" with `--pad-from SOURCE_ACCOUNT`.

No transaction or pad can put USD in an account restricted to AAPL. The
message never says that the account does not accept the currency. The
same mistake in `add transaction` gets a clear `Invalid currency USD for
account …`. No product fix implemented.

Use the ledger from [349](./349.md) plus `2026-01-01 open Assets:Stock
AAPL`, with the same environment.

```sh
bea -f /absolute/books/main.bean add balance --date 2026-03-04 --account Assets:Stock --amount '1950 USD'
```

Actual: exit 1 with

```text
Error: The change would leave the ledger invalid; nothing was written.
  Proposed append (not written): Invalid currency 'USD' for Balance directive: 
  Proposed append (not written): Balance failed for 'Assets:Stock': expected 1950 USD != accumulated 0 USD (1950 too little)
  Balance assertions run at the start of the day, … Review missing or duplicate transactions and record known fees as transactions before adjusting.
  Review missing transactions first. The following command creates an intentional opening adjustment.
  Opening adjustment command: bea --file …/main.bean add balance --date 2026-03-04 --account Assets:Stock --amount '1950 USD' --pad-from SOURCE_ACCOUNT
```

`bea check` on a ledger that already holds such a line, and the `--json`
details, show the same dangling colon. Reproduced twice by the hunter and
once by me.

Control: `bea add transaction X -p 'Assets:Stock 5 USD' -p Assets:Cash`
exits 1 with `Invalid currency USD for account 'Assets:Stock'`.

Expected:

- The detail should read like the transaction case: `Invalid currency USD
  for account 'Assets:Stock' (its open allows AAPL)`.
- The missing-transactions advice and the `--pad-from` command should not
  appear when the asserted currency is outside the account's allowed
  currencies, because neither can fix it.

Cause:

- Upstream `beancount/ops/balance.py:129` formats `"Invalid currency '{}'
  for Balance directive: "`.
- bea's `format_error` (`cli/src/bea_engine/query.py:1721-1739`) passes it
  through unchanged.
- `_balance_recovery_hints` (`cli/src/bea_engine/ledger/write.py:800-816`)
  attaches the generic block to any failing Balance without checking
  `open.currencies`.

Fix:

- In `format_error`, rewrite that message to name the account and its
  allowed currencies.
- In `_balance_recovery_hints`, skip the date, fees and pad advice when
  the asserted currency is outside a non-empty `open.currencies`.
- No dependency change.

Blast radius: `add balance` (including `--pad-from` and bulk rows),
`check`, and reads that print ledger errors, whenever a Balance names a
currency the account excludes.

Dedupe: searched `.pm/**`, including `done/`, for "Invalid currency",
"for Balance directive" and dangling colon. Related notes:

- w5/074, w3/276 and w3/323: currency restrictions for transactions and
  import.
- 345: the never-opened balance hint.

None covers the Balance currency message or its recovery block.

Acceptance: on the fixture, the error names `Assets:Stock` and its
allowed `AAPL`, has no trailing `: `, and prints no fees or `--pad-from`
advice. A balance that fails only on its amount keeps the current hints.
A test covers both. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-15** — `format_error` (`cli/src/bea_engine/query.py`) rewrites upstream's `Invalid currency 'USD' for Balance directive: ` as `Invalid currency USD for account 'Assets:Stock': its open does not allow it.`, using the error's balance entry. `_balance_recovery_hints` (`ledger/write.py`) checks the account's `open` first. When the asserted currency is outside a non-empty currency list, it returns only "Assets:Stock's open allows AAPL only, so a USD balance cannot hold there; assert it in AAPL, or add USD to that open." The date, fees and `--pad-from` advice is dropped. A balance that fails only on its amount keeps the current hints. `--json check` details get the rewritten message; native `bea check` text stays upstream's, as documented. `cli/tests/test_balance_currency_not_allowed.py` covers the `add` refusal, the amount-only control and `--json check`; the 2 currency cases fail with the fix reverted. Only macOS was exercised. `make check-all` passed. Shipped in `61afee9c` (`cli`).
