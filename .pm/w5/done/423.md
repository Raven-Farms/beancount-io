# A managed-price blob cached by released bea 0.3.0/0.3.1 (no `sha256` in its sidecar) is trusted without a check, so a truncated download from those versions is pinned by 304s: every read fails and `price refresh` reports "unchanged"

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1. **Simulation:** the feed comes from a localhost origin. The old cache state was crafted by hand to match what the released versions wrote.

[w1/077](../w1/done/077.md) (`3afb458a`) added a digest to each cached
revision so that "a corrupted blob is refetched in full instead of being
pinned by 304s". That fix came after the `cli-v0.3.0` and `cli-v0.3.1`
tags, which already shipped managed includes (`4e265882`). Their cached
sidecars have no `sha256`. They were also the versions that could cache
a truncated download, the bug w1/077 fixed. `_read_blob` checks the
digest only when one is present. A digest-less truncated blob is
therefore trusted, and its ETag is replayed. The server answers 304, and
the broken revision is never replaced. No product fix implemented.

Setup by the hunter:

- `pf/main.bean` includes `http://127.0.0.1:<port>/prices/BTC-USD`,
  served by a mock with `ETag "v1"` that honours `If-None-Match` with 304.
- `bea price refresh` primes the cache. Then, to recreate the 0.3.x
  state, `"sha256"` is removed from `managed-prices/<hash>/v1.json` and
  `v1.beancount` is truncated mid-line.
- Isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, `MANAGED_PRICE_ORIGINS` set to
  the mock, and closed stdin.

```sh
bea -f /absolute/pf/main.bean list price
bea -f /absolute/pf/main.bean price refresh
bea -f /absolute/pf/main.bean list price
```

Actual:

- `list price` exits 1 with `…/v1.effective….beancount:3: syntax error,
  unexpected end of file`.
- `price refresh` sends `If-None-Match: "v1"`, gets 304, and prints
  `BTC-USD: unchanged at v1` with exit 0.
- Every later read fails. Only deleting the cache recovers.

Reproduced twice by the hunter. I confirmed the code path, and confirmed
with `git merge-base` that `3afb458a` is not in `cli-v0.3.1`.

Control: the same truncation with `sha256` kept makes refresh drop the
ETag and fetch in full, and `list price` works.

Expected: w1/077's promise should cover blobs written before the digest
existed, because those are exactly the ones that could be truncated.

Cause: `_read_blob` (`cli/src/bea_engine/managed_price_cache.py:123-132`)
compares only when `digest is not None`.

Fix: for a sidecar without `sha256`, validate the text before trusting it
(the feed validator or a parse), or drop its ETag so the next online
resolve fetches in full and records a digest. Optionally, `price
refresh` should not report "unchanged" while the served revision fails
to load. No dependency change.

Blast radius: users upgrading from bea 0.3.0/0.3.1 whose cache holds a
truncated revision. Every read of the ledger fails until they delete the
cache by hand.

Dedupe: searched `.pm/**`, including `done/`, for pre-digest, 304
together with truncated, and sidecar. w1/077 assumes a digest. 377-379,
408 and 409 cover other cache problems. None covers digest-less blobs.

Acceptance: with the crafted 0.3.x cache, the next `price refresh` (or
online read) fetches in full and `list price` works. A blob with a digest
behaves as today. A test pins a digest-less truncated blob.

---

**Resolved 2026-10-15** — `_read_blob`
(`cli/src/bea_engine/managed_price_cache.py`) now re-validates a cached
revision whose sidecar has no `sha256`, the 0.3.0/0.3.1 format, with the
feed validator. Its prices must equal the ones the sidecar recorded.
Otherwise the blob reads as missing, as a digest mismatch already did, so
the next online resolve sends no `If-None-Match`, fetches in full, and
writes a new sidecar with a digest. That covers a truncation mid-line and
one at a line boundary, which still parses but has fewer prices. An
intact digest-less blob is still served, and a blob with a digest
behaves as before. Pinned by
`cli/tests/test_price_cache_predigest_blob.py`, which fails without the
fix.
