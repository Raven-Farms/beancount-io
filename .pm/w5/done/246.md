# Tables count zero-width marks as one column: Thai, Devanagari and emoji rows are padded short, and truncation cuts inside emoji sequences

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
Cosmetic. The table width measure treats many zero-width characters
(Thai and Devanagari vowel marks, the emoji variation selector, the
zero-width joiner) as one column each, so rows containing them are padded
1–3 cells short and later columns shift left. Truncation can stop between
an emoji and its joiner. Numbers stay correct. No product fix implemented.

Generate `/absolute/books/main.bean`:

```python
P = ["Plain Cafe",
     "\u0e23\u0e49\u0e32\u0e19\u0e01\u0e4b\u0e27\u0e22\u0e40\u0e15\u0e35\u0e4b\u0e22\u0e27\u0e1b\u0e49\u0e32\u0e28\u0e23\u0e35",
     "\u0915\u093f\u0930\u093e\u0928\u093e \u0926\u0941\u0915\u093e\u0928",
     "\u2615\ufe0f\u2764\ufe0f\u2708\ufe0f Trip",
     "\U0001f468\u200d\U0001f469\u200d\U0001f467\u200d\U0001f466 Family dinner out"]
s = 'option "operating_currency" "USD"\n2026-01-01 open Assets:Checking USD\n2026-01-01 open Expenses:Food USD\n'
for i, p in enumerate(P):
    s += f'2026-01-0{i+2} * "{p}" "lunch"\n  Expenses:Food  {i+1}.00 USD\n  Assets:Checking\n'
open("main.bean", "w").write(s)
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN/CI/COLUMNS, `TERM=xterm-256color`, closed
stdin unless a PTY is stated, cwd `/absolute/books`. Run on a real PTY at 120 and at 62 columns. Width measure used
for checking: East Asian wide = 2; categories Mn, Me, Cf and skin-tone
modifiers = 0; everything else = 1.

```sh
bea -f main.bean list transaction -a Food
```

Actual at 120 columns: the NARRATION cell starts at display column 50 for
`Plain Cafe`, 48 for the Thai row, 49 for the Hindi row, and 47 for both
emoji rows. At 62 columns the payee is truncated to the code points
`U+1F468 U+200D ...` (a dangling joiner; the four-person family becomes one
man) and `U+2615 U+FE0F U+2764 ...` (the heart cut from its variation
selector).

Control: the ASCII row. A worker saw rows with a combining acute accent and
CJK text align exactly, and the same shift in the import preview table.

Expected: the measure's own docstring (`cli/src/cli/output.py:128-140`)
says a combining mark takes no column because it renders onto the
character before it; w3/done/391 and w1/done/106 accepted "every table
sizes and pads by display width".

Cause: `cli/src/cli/output.py:141` uses `unicodedata.combining(c)`, the
canonical combining class, which is 0 for many nonspacing marks (Thai
U+0E31, U+0E34–0E37, U+0E47–0E4E; Devanagari U+0941–0948), for U+FE0F and
for U+200D. `truncate` (`:149-158`) iterates code points with that
measure.

Fix: treat general categories Mn, Me and Cf, and U+1F3FB–1F3FF, as width
0; in `truncate`, never break before a width-0 code point or directly
after U+200D. No dependency change.

Blast radius: every table (`list`, import preview, `price status`, report
interval tables) and the narrow `list transaction` layout.

Dedupe: board search for `display_width`, combining, ZWJ, VS16, Thai and
grapheme finds w3/done/391 and w1/done/106 (East Asian width only), w5/149
(tree padding) and w5/148 (bidi controls, which mentions format characters
in passing); none covers nonspacing marks or truncation splitting.

Acceptance: all five rows start the NARRATION cell at the same display
column at 120 columns; at 62 columns no truncated cell ends in U+200D or
separates a base from its variation selector. Emoji widths vary by
terminal; only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — The table width measure in `cli/src/cli/output.py` now gives no column to general categories Mn, Me and Cf (the soft hyphen keeps its cell) or to the emoji skin-tone modifiers U+1F3FB–1F3FF, instead of relying on the canonical combining class, which is 0 for Thai and Devanagari vowel signs and the emoji variation selector. `truncate` now cuts only between clusters: a base stays with the zero-width marks after it, and a zero-width joiner stays with both emoji it joins, so a joined family is kept whole or dropped whole. Because every table, the import preview and the narrow `list transaction` layout share this measure, no other file changed. The regression test `cli/tests/test_table_zero_width_marks.py` checks the measure against an independently written rule, checks `truncate` across widths, and runs `bea list transaction -a Food` on a real pseudo-terminal at 120 and 62 columns with the note's five payees, asserting one narration start column and no cut that ends in a joiner or parts a base from its mark; 21 of its 33 cases fail with the fix reverted, and the ASCII, combining-acute and spacing-mark controls pass either way. Emoji widths still vary by terminal, so the alignment holds under the note's stated measure rather than for every emulator's rendering of joined sequences. Only macOS was exercised. `make check-all` passed. Shipped in `a42c196c` (`cli`).
