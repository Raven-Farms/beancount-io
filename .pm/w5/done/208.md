# SIGTERM or SIGHUP to `bea check`, `bea doctor` or `bea query --source` kills the frontend but leaves the engine child running

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A supervisor that stops `bea check` with SIGTERM (a CI timeout, an editor
cancelling a save hook, `timeout(1)`) gets the frontend's exit at once, but
the Beancount child keeps running to completion as an orphan with the
inherited stdout and stderr still open. Commands on the JSON-helper path
clean up correctly. No product fix implemented.

Generate a disposable slow ledger `/absolute/books/main.bean` (9,000 cost
lots in one account; about 8 s to load):

```sh
python3 -c "
import datetime as d
o=['option \"operating_currency\" \"USD\"','2000-01-01 open Assets:Inv','2000-01-01 open Assets:Bank USD']
for i in range(9000):
  o.append(f'{d.date(2000,1,2)+d.timedelta(days=i%6000)} * \"buy\"\n  Assets:Inv  1 ABC {{{10+i%97}.{i%100:02d} USD}}\n  Assets:Bank\n')
open('main.bean','w').write('\n'.join(o)+'\n')"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`,
load cache removed before each run. Start the command, wait 2.5 s, send
SIGTERM to the `bea` pid only, then list processes whose command line names
the ledger 0.5 s later.

```sh
bea -f /absolute/books/main.bean check
bea query --source /absolute/books/main.bean "SELECT count(*)"
bea -f /absolute/books/main.bean balance -x units
```

Actual:

| command | frontend | 0.5 s after the signal |
| --- | --- | --- |
| `check` | exits −15 at once | `…/engine/0.3.1/bin/bean-check` still running; gone 5.8 s after the signal |
| `query --source` | exits −15 at once | `…/bin/python -P -m bea_engine source-query` still running; gone 5.8 s after |
| `balance -x units` (control) | exits −15 at once | no child |

A worker saw the same for SIGHUP and for `doctor context`, with orphans
living 13–15 s on a larger fixture, and a reader of the inherited pipe
blocked until the orphan ended. SIGINT cleaned up on both paths.

Expected: terminating `bea` terminates the work it started, as the helper
path already does; a cancelled command should not keep the pipe open or the
CPU busy.

Cause: `cli/src/cli/engine/launch.py:546-565` (`_spawn`, used by
`run_native` and `run_engine_argv`) calls plain `subprocess.run`. Only
`_run_helper` wraps its child in `_forwarding_teardown`.

Fix: run `_spawn`'s child under the same forwarding teardown. No dependency
or API change.

Blast radius: every native-path command: `check` in text mode, `doctor`,
`query --source`, and by the same code path `example`, `treeify`, `price`
and `ingest` (not signal-tested).

Dedupe: board search for `SIGTERM`, `SIGHUP`, `orphan`, `run_native` and
`_spawn` finds w3/done/440, w1/done/074 and w5/done/014, all about the
helper write path and staging files; none covers the native path.

Acceptance: 0.5 s after SIGTERM or SIGHUP to `bea check` on the slow
fixture, no process naming the ledger remains; the `balance` control is
unchanged. A real-command regression test covers `check` and
`query --source`. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — The inherited-streams launcher in `cli/src/cli/engine/launch.py` (`_spawn`, behind `run_native` and `run_engine_argv`) now runs its child through a new `_run_inherited`, which passes a SIGTERM or SIGHUP aimed at `bea` on to the child, kills the child if it has not gone within the existing five-second cleanup grace, and then dies of the same signal so the caller still sees the usual status. It is a sibling of the helper path's forwarding teardown rather than a reuse of it, because that handler waits for the child itself and would stall for the whole grace period while the main thread is already blocked in the child's wait; the child also stays in the frontend's process group so an interactive shell keeps its terminal, and Ctrl-C handling is unchanged. `cli/tests/test_native_termination_reaches_child.py` runs the real command against a ledger whose plugin parks the load, signals only the frontend, and asserts the exit status, that the loading process is gone the moment the frontend exits, and that the inherited pipes are released; it covers `check`, `query --source` and `doctor print-options` under SIGTERM and SIGHUP, with `balance -x units` as the control. Six of the eight cases fail with the fix reverted, and the two control cases pass either way. The in-process branch used when stdout or stderr is not a real file descriptor is unchanged, and `example`, `treeify`, `price` and `ingest` share the fixed code path but were not signal-tested. Only macOS was exercised. `make check-all` passed. Shipped in `af656847` (`cli`).
