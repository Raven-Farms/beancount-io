# `bea doctor` does not resolve managed price includes: `region --conversion value` leaves the holding unvalued and `roundtrip` reports success over a "File glob" error

**Minor · cli · 30–45m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
`balance` values a holding from a managed price include; `doctor region
… --conversion value` on the same ledger shows it unvalued, with exit 0
and no warning, because the `doctor` operations load the ledger without
the managed loader. A worker saw `roundtrip` print a "File glob … does not
match any files" error for the include and still congratulate. No product
fix implemented.

Create `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Wallet BTC
2026-01-01 open Assets:Bank USD
2026-01-01 open Equity:Opening
include "http://127.0.0.1:18765/prices/BTC-USD"

2026-01-02 * "Buy"
  Assets:Wallet  2 BTC {30000.00 USD}
  Assets:Bank   -60000.00 USD
```

Simulation only: no network and no server. Run with `--offline`, isolated
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1,
`MANAGED_PRICE_ORIGINS=http://127.0.0.1:18765` (the documented test
override), no inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY. cwd `/absolute/books`. The cache was seeded by hand with one
revision of the feed holding `2026-01-05 price BTC 41000.00 USD` and a
current `observed-at`.

```sh
bea --offline -f main.bean balance
bea --offline doctor region main.bean main.bean:7:9 --conversion value
bea --offline doctor roundtrip main.bean
```

Actual: `balance` shows `Wallet 82,000.00 USD`. `doctor region` exits 0
showing `Wallet 2 BTC` and `Net Income: (-60000.00 USD, 2 BTC)`. `doctor
roundtrip` exits 0 ending `Entries are the same. Congratulations.`

Control: `balance` in the same run. A worker exported the ledger with
`price export` and saw `doctor region … --conversion value` on the
snapshot print `82000.00 USD`.

Expected: `docs/adrs/ADR018-cli-managed-price-includes.md`: "Every load
path calls one of the two … No command can see a different ledger than
another." `docs/USAGE.md`: "One line values a holding at market in every
command".

Cause: `cli/src/bea_engine/scoped.py:42` runs upstream `doctor` in
process, which calls Beancount's loader directly, and
`cli/src/cli/commands/doctor.py` forwards the other operations to stock
`bean-doctor`; neither goes through the managed loader.

Fix: have the loading `doctor` operations read through the managed loader
(or hand upstream the staged root); at minimum warn or fail on a managed
include instead of answering silently. No dependency change.

Blast radius: every loading `doctor` operation on a ledger with a managed
include (`lex` and `parse` are unaffected).

Dedupe: board search for `doctor` with managed, "File glob" and
`--conversion` finds w5/135 (BOM/NFD ledgers) and w5/101 (region
rounding); neither concerns managed includes.

Acceptance: `doctor region … --conversion value` shows `82000.00 USD` for
the wallet, and `roundtrip` reports no glob error. Only macOS and the
checkout were exercised; managed-price behaviour was simulated offline.

---

**Resolved 2026-10-13** — `bea doctor` now loads a ledger with a managed price include the way every other command does: `cli/src/cli/commands/doctor.py` routes every loading operation on such a ledger to the helper, and `cli/src/bea_engine/scoped.py` hands upstream's doctor a loader that resolves the include through the managed loader (`names_managed_source` in `cli/src/bea_engine/managed_load.py` decides), while a ledger without one keeps upstream's own load unchanged. `doctor region --conversion value` values the holding from the feed as `balance` does, online and from the cache under `--offline`, and `doctor roundtrip` no longer prints a "File glob" error; `--strict-prices` fails the operation with one line, and `cli/docs/USAGE.md` states the behaviour. The regression test `cli/tests/test_doctor_managed_price_include.py` runs the real commands against a loopback feed, covering region, roundtrip, print-options, context, linked, display-context, missing-open and the include-free control; 8 of its 11 cases fail with the fix reverted. One deviation worth knowing: when a source is unavailable without `--strict-prices`, the operations that upstream never prints load errors for (such as `region`) still answer without a warning, exactly as they do for any other load error; `roundtrip` names the unavailable source. Only macOS was exercised. `make check-all` passed. Shipped in `286ccb69` (`cli`).
