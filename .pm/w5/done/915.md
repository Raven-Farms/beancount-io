# Preserve empty labels when printing booked costs for exports and imports

**Minor · cli · 20–30m · A1.** `query PRINT` erases an empty cost label in
the saved ledger, merging lots that JSON kept separate. A native importer
returning a booked `Cost` loses it too. The existing fix handles `CostSpec`
inputs, so direct adds and that importer control still work. No product fix
implemented.

Real CLI QA 2026-10-21, checkout `2eb7f8c4d`, `bea 0.3.1`, Darwin 25.5.0
arm64, frontend Python 3.13.3, managed Python 3.12 engine with existing
Beangulp. Two pristine repetitions, bounded separate processes, closed
stdin/no TTY, isolated absolute BEA_CONFIG_DIR/XDG_CACHE_HOME, updater
disabled, no inherited BEA_FILE/BEA_TOKEN. No hosted data.

Create `/absolute/qa/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Assets:Stock HOOL
2024-01-01 open Equity:Opening USD
2024-01-01 * "Capital"
  Assets:Cash 1000 USD
  Equity:Opening -1000 USD
2024-02-01 * "Existing unlabelled"
  Assets:Stock 1 HOOL {100 USD}
  Assets:Cash -100 USD
```

```sh
bea --json -f /absolute/qa/main.bean add transaction Empty --date 2024-02-01 -p 'Assets:Stock 1 HOOL {100 USD, ""}' -p 'Assets:Cash -100 USD'
bea --json -f /absolute/qa/main.bean add transaction Named --date 2024-02-01 -p 'Assets:Stock 1 HOOL {100 USD, "lot-a"}' -p 'Assets:Cash -100 USD'
bea --json -f /absolute/qa/main.bean query "SELECT sum(position) WHERE account = 'Assets:Stock'"
bea -f /absolute/qa/main.bean query PRINT --format beancount -o /absolute/qa/flat.bean
bea --json -f /absolute/qa/flat.bean query "SELECT sum(position) WHERE account = 'Assets:Stock'"
bea --json -f /absolute/qa/flat.bean check
```

Actual, twice: the adds correctly retain the empty label. Source JSON has
three `1 HOOL` positions, cost 100 USD and acquisition date February 1, with
labels `null`, `""`, and `"lot-a"`. Export exits **0**, but the empty-label
posting is printed as `{100 USD, 2024-02-01}`. Reloading the saved file has
only two positions: `2 HOOL` with label `null`, and `1 HOOL` with `"lot-a"`.
`check` still exits 0. Default `query PRINT -o …` reproduces the same loss
twice. The source ledger stays byte-identical during export; cash and total
cost remain unchanged. This is persistent lot-metadata loss in the copy.

The native-import path has the same cause. On a fresh copy of the initial
fixture, create a synthetic `bank.txt` and `importers.py`:

```python
from beancount.core.data import Transaction, Posting
from beancount.core.amount import Amount
from beancount.core.position import Cost
from datetime import date
from decimal import Decimal

class Imp:
    def identify(self, file):
        return str(file).endswith(".txt")
    def account(self, file):
        return "Assets:Stock"
    def extract(self, file, existing_entries=None):
        day = date(2024, 2, 1)
        return [Transaction({}, day, "*", None, "Imported trade",
            frozenset(), frozenset(), [
                Posting("Assets:Stock", Amount(Decimal("1"), "HOOL"),
                    Cost(Decimal("100"), "USD", day, ""), None, None, None),
                Posting("Assets:Cash", Amount(Decimal("-100"), "USD"),
                    None, None, None, None),
            ])]

CONFIG = [Imp()]
```

Preview then apply with `bea --json -f /absolute/qa/main.bean import
/absolute/qa/bank.txt --config /absolute/qa/importers.py [--apply]`. Both
exit 0; apply writes 1 and check passes. The preview already omits `""`, and
the new position merges into the existing unlabelled `2 HOOL` lot. Repeated
twice. Returning `CostSpec(Decimal("100"), None, "USD", day, "", False)`
instead preserves two positions with labels `null` and `""`. Both types with
`None` or a nonempty `"lot-a"` label work as controls, twice each.

Expected: full Beancount exports and native imports preserve the label they
receive, including a present empty string. USAGE's query export contract
promises complete cost specifications. Keep upstream's existing lot-matching
rules; this note does not ask for a new interpretation of empty selectors.

Cause: `cli/src/bea_engine/ledger/writer.py:116–122` calls upstream's posting
printer, which drops a falsy label, then repairs it only when the cost is a
`CostSpec`. A loaded ledger contains booked `Cost` objects, so the query's
`_render_beancount` (`cli/src/bea_engine/query.py:1762–1810`) bypasses that
repair. `format_entry` at writer.py:317–321 uses the same printer for native
importer rows (`importing.py:649`, 1101 and 1118). Escaping a label first
does not help: an escaped empty string remains falsy. The typed `CostSpec`
helper already tests `label is not None`.

Fix: make the shared printer faithfully render both booked `Cost` and
unbooked `CostSpec`, retaining an empty label, acquisition date and exact
number without changing total/partial-cost handling. Cover the actual booked
type in regression cases, plus None/nonempty and CostSpec controls. Preserve
default PRINT and explicit Beancount export, and the native import's preview
and persisted entry. No backend or dependency change; explicit native
`--source` rendering keeps its documented upstream contract.

Dedupe: whole-board empty-label searches and current milestone review found
completed [805](./done/805.md), `6f9181fa1`, whose CostSpec write fix still
passes. The type-limited repair came from `78217b30d` (w3/m49); query exports
adopted the shared printer in `505211928`. Open [872](./872.md) covers two
different truthiness checks in the transaction table and position/bare-cost
CSV renderer. Those fixes do not enter this printer branch or preserve a
saved ledger/native Cost import. No later repair or overlapping open task
was found. Keep this shared booked-cost issue separate from 872's displays.

Acceptance: the exported copy retains all three one-unit positions and
labels; the native Cost import retains its empty-labelled one-unit position
beside the existing unlabelled one. All source/export ledgers pass check,
normal controls retain their current meaning, and read-only export leaves
source bytes unchanged. Cash and cost totals stay the same.
