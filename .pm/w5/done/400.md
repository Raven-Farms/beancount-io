# USAGE says a plugin that raises while running is reported as `Cannot import plugin "NAME": CAUSE`, but the CLI prints `Plugin "NAME" failed while running: CAUSE`, and a plugin missing its config string gets no hint

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
The CLI distinguishes import failures from runtime failures, which is
sensible. The doc describes one wording for both. The most common runtime
failure is a bundled plugin that needs a configuration string
(`currency_accounts`, `commodity_attr`). It surfaces as a raw `TypeError
… missing 1 required positional argument: 'config'`, with no hint about
the `plugin "NAME" "CONFIG"` form. No product fix implemented.

Use a USD ledger whose first line is `plugin
"beancount.plugins.currency_accounts"`, with the environment from
[396](./396.md).

```sh
bea -f /absolute/books/main.bean check
```

Actual: exit 1 with `main.bean:1: Plugin
"beancount.plugins.currency_accounts" failed while running: TypeError:
insert_currency_trading_postings() missing 1 required positional
argument: 'config'.`. Reproduced by the hunter in text and JSON, and by
me.

Expected: `cli/docs/USAGE.md:426-428` reads "a `plugin` line that cannot
be imported, or whose plugin raises while running, as `FILE:LINE: Cannot
import plugin "NAME": CAUSE`". The doc should name both forms. A missing
`config` argument should add: "this plugin needs a configuration string:
plugin \"NAME\" \"CONFIG\"".

Cause: `cli/src/bea_engine/query.py:1758-1761` uses "Cannot import" only
for import failures (`0f7fac5f`, w1/m25/t004).

Fix: update the USAGE sentence to cover both forms. When the cause is a
`TypeError` about a missing `config` argument, add the hint. No
dependency change.

Dedupe: w1/101 and w5/256 (done) cover the location and traceback of
plugin failures, not this wording or hint.

Acceptance: USAGE matches the two printed forms, and the
`currency_accounts` case shows the config hint. A test pins the hint.

---

**Resolved 2026-10-15** — `_plugin_message` (`cli/src/bea_engine/query.py`)
now adds `This plugin needs a configuration string: plugin
"beancount.plugins.currency_accounts" "CONFIG".` when a plugin's run
fails because its `config` argument is missing. That applies in text and
JSON, and on `check` and every other read. USAGE's sentence now names
both printed forms, `Cannot import plugin "NAME": CAUSE` for an import
failure and `Plugin "NAME" failed while running: CAUSE` for a runtime
one, and mentions the configuration hint. An import failure carries no
config hint. Pinned by `cli/tests/test_plugin_config_hint.py`, which
fails without the fix.
