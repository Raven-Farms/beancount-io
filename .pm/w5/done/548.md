# `bea ask` answers silently lose any text in angle brackets and any HTML block: `--account <ACCOUNT>` prints as `--account `, and a `<div>…99.00 USD…</div>` vanishes

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `0c12f2dc`, checkout `bea 0.3.1`, macOS 26.5.1. Simulation: local stub of the AI proxy.
Models write `<PLACEHOLDER>` in suggested commands routinely, and payees can
contain `<…>`. Rich's Markdown renderer drops inline and block HTML tokens.
Text the model sent disappears without a trace, which w1/097 and w3/392 ruled
out for links: nothing the model sends may hide what the user reads. No
product fix implemented.

Stub reply:

```text
To open it run: bea add open --account <ACCOUNT> --date <DATE>

The payee was <Amazon Marketplace> and the memo <b>bold</b> x.

<div>
hidden block 99.00 USD
</div>
```

```sh
bea -f /abs/main.bean ask q --print </dev/null
```

Actual: exit 0; stdout is `To open it run: bea add open --account  --date` and
`The payee was  and the memo bold x.`; the `<div>` block, with its amount, is
gone. The REPL renders the same.

Control: the same placeholders in backticks survive; `1 < 2` survives.

Expected: angle-bracket text and HTML blocks are shown literally.

Cause: `cli/src/cli/commands/ask.py:94` and `cli/src/cli/ask/repl.py:332`
render with `rich.markdown.Markdown`, which skips `html_inline` and
`html_block` tokens.

Fix: escape `<` before rendering, or render HTML tokens as literal text
(alongside the existing `inert_text` and `hyperlinks=False` handling).

Dedupe: searched `angle bracket`, `html block`, `Markdown(`. Only w1/097
(links).

Acceptance: the reply above prints every word, including `<ACCOUNT>` and
`99.00 USD`. A test pins it.

---

**Resolved 2026-10-17** — Shipped in `0706393f` (`cli`). The new `answer_markdown` (`cli/src/cli/ask/render.py`) renders an answer with Rich's Markdown but re-parses it with HTML off (`MarkdownIt("commonmark", {"html": False})`, plus strikethrough and tables as before). Inline and block HTML then render as the literal text they are. It keeps `inert_text` and `hyperlinks=False`, and both `--print` and the session use it. The note's reply prints `--account <ACCOUNT> --date <DATE>`, `<Amazon Marketplace>`, `<b>bold</b>` and the `<div>` block with `99.00 USD`; bold, code spans and links still render. `tests/test_ask_answer_keeps_html_text.py` pins the rendering, the Markdown control and the `--print` end to end; the end-to-end case fails without the fix. `make check-all` passed.
