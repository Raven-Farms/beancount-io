# `import --id-key ID` silently turns off bank-ID matching; only the lowercase spelling `id` is aliased

**Minor · cli · 15–25m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
w3/done/237 made `--id-key id` an alias for the `bank_id` key so that it
"never silently disables bank-ID dedupe". The alias is an exact,
case-sensitive match. With `--id-key ID`, the header name from that note's
own example, imports fall back to content hashes: a second statement row
reusing the same bank id with different data is written with exit 0
instead of being stopped as a conflict. A byte-identical re-import is still
caught by its hash. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2020-01-01 open Assets:Bank:Checking USD
2020-01-01 open Expenses:Uncategorized
2020-01-01 open Equity:Opening-Balances

2020-01-01 * "seed"
  Assets:Bank:Checking      100 USD
  Equity:Opening-Balances  -100 USD
```

`/absolute/books/a.csv`:

```csv
Date,Description,Amount,ID
2024-03-10,Cafe,-4.50,id1
```

`/absolute/books/b.csv`:

```csv
Date,Description,Amount,ID
2024-03-11,Other,-9.99,id1
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea --no-input -f main.bean import a.csv --csv date=Date,amount=Amount,narration=Description,id=ID --account Assets:Bank:Checking --id-key ID --apply
bea --no-input -f main.bean import b.csv --csv date=Date,amount=Amount,narration=Description,id=ID --account Assets:Bank:Checking --id-key ID --apply
```

Actual: both exit 0 and write one entry. The ledger holds two transactions
with `bank_id: "id1"`, carrying `import-id: "csv:sha256:c92c735b314faa80"`
and `"csv:sha256:f3c4aca941e8d9db"` rather than `bank:id1`. `bea check`
passes; no warning.

Control: the same two commands with `--id-key id` write `import-id:
"bank:id1"` and then exit 4: `Row 1 (conflict): Stable ID matches an entry
with different transaction data.`

Expected: `docs/IMPORTING.md`: "`--id-key id` is accepted as an alias for
`bank_id`, the canonical key the `--csv` path writes, so it never silently
disables bank-ID dedupe." `ID` can never be a metadata key (keys start
lowercase), so it should be aliased or refused.

Cause: `cli/src/bea_engine/importing.py:87`: `mapped = "bank_id" if key ==
"id" else key`.

Fix: on the CSV path alias case-insensitively (and alias the header mapped
to `id=`); otherwise refuse an `--id-key` that is not a legal metadata key,
or keep `bank_id` in the list whenever the mapping has `id=`. No dependency
change.

Blast radius: any `--id-key` other than `id`/`bank_id` combined with
`--csv … id=`; a worker saw `--id-key other` fall back the same way.

Dedupe: board search for `id-key` finds w3/done/237 (the lowercase alias),
w3/done/326 (conflict wording), w3/done/184 and 210; nothing in the open
notes.

Acceptance: the two commands with `--id-key ID` behave as the lowercase
control (second import exits 4), or the option value is refused with exit
2 naming a valid spelling. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — `_effective_id_keys` in `cli/src/bea_engine/importing.py` now aliases `--id-key id` to `bank_id` in any case (`ID`, `Id`), and a `--csv` mapping that has `id=` keeps `bank_id` in the native-ID list whatever keys were named, since that is the only key its rows carry; `cli/docs/IMPORTING.md` states both. With the note's fixture, `--id-key ID` now writes `import-id: "bank:id1"` and the second import exits 4 as a conflict, exactly like the lowercase control, and `--id-key other` from the blast radius behaves the same. The regression test `cli/tests/test_id_key_keeps_bank_id.py` runs the real command for `id`, `ID`, `Id` and `other`, plus a control that a mapping without `id=` still imports both rows by content hash; three of its five cases fail with the fix reverted. The note's alternative of refusing an `--id-key` that is not a legal metadata key was not taken: such a key stays in the list, where it matches nothing. Only macOS was exercised. `make check-all` passed. Shipped in `aa39ec62` (`cli`).
