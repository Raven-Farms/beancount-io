# On a ledger that uses the `nounused` plugin, no `bea` command can create an account, and the printed remedies point at one that cannot succeed

**Minor · cli · 30–45m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
`beancount.plugins.nounused` (also part of `pedantic`) reports an account
that is opened but not yet used. `bea add open` is therefore refused, since
the open alone is "unused"; and a transaction to the new account is
refused, since the account is not open, with a remedy that says to run
`bea add open`. `--allow-errors` does not help. The only way to add an
account is to edit the file by hand. Each refusal follows the documented
rule; the gap is that there is no route to a valid state. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
plugin "beancount.plugins.nounused"
2024-01-01 open Assets:Bank USD
2024-01-01 open Equity:Opening
2024-01-01 open Expenses:Food USD

2024-01-02 * "Opening"
  Assets:Bank  1000.00 USD
  Equity:Opening

2024-02-01 * "Lunch"
  Expenses:Food  12.50 USD
  Assets:Bank
```

`/absolute/books/s.csv`:

```csv
Date,Payee,Narration,Amount
2024-03-01,Shell,gas,-40.00
```

`/absolute/books/r.toml`:

```toml
[[rule]]
match = "shell"
account = "Expenses:Fuel"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.
The fixture passes `bea check`. Run each command on a pristine copy.

```sh
bea -f main.bean add transaction --date 2024-03-01 gas -p 'Expenses:Fuel 40.00 USD' -p Assets:Bank
bea -f main.bean add open --account Expenses:Fuel --date 2024-03-01 -c USD
bea -f main.bean add open --account Expenses:Fuel --date 2024-03-01 -c USD --allow-errors
bea -f main.bean import s.csv --account Assets:Bank --rules r.toml --apply
```

Actual: nothing is written by any of them.

```text
1. exit 1  Invalid reference to unknown account 'Expenses:Fuel' … To create it, use bea add open --account Expenses:Fuel --date YYYY-MM-DD.
2. exit 1  The change would leave the ledger invalid; nothing was written. Proposed append (not written): Unused account 'Expenses:Fuel'
3. exit 1  The change would introduce 1 new ledger error(s); nothing was written. … Unused account 'Expenses:Fuel'
4. exit 4  Row 1 (blocked): Account 'Expenses:Fuel' is not open. Run: bea add open --account Expenses:Fuel --date 2024-03-01 -c USD.
```

Control: the same ledger without the `plugin` line accepts command 2
(`Added 1 open`). The plugin ledger with `2024-03-01 open Expenses:Fuel
USD` and the gas transaction appended by hand passes `bea check`, so the
end state is valid. A worker saw the same dead end on a `pedantic` ledger
and for `add transactions`.

Expected: `docs/USAGE.md` documents refusing a write that introduces an
error and names the staged pad as the one exception. An opened-but-unused
account is the same transient first half of a two-step. Either that step is
allowed, or a single command writes the open with its first use; and the
remedies name a command that works.

Cause: `cli/src/bea_engine/ledger/write.py:771` refuses any candidate with
errors; under `--allow-errors`, `write.py:680` exempts only `Unused Pad`
from "newly introduced". The remedies at `write.py:698` and
`cli/src/bea_engine/importing.py:698` are printed regardless.

Fix: tolerate a newly introduced `Unused account '<X>'` for the account
that `add open --allow-errors` is opening (mirroring the staged pad), or
let `add transaction`/`import` write the missing `open` atomically with
its first use; make both remedies say whichever applies. No dependency or
API change.

Blast radius: `add open`, and through their remedies `add transaction`,
`add transactions` and `import`, on ledgers loading `nounused` or
`pedantic`.

Dedupe: board search for `nounused`, "Unused account" and `pedantic`
finds no plugin note. w5/134 is the mirror case (`auto_accounts`, where
the open is unnecessary); w5/154 is a dead-end `add open` hint for a
different reason; w5/076 is the date in the import remedy.

Acceptance: on the fixture there is a documented command sequence (or one
command) that ends with `Expenses:Fuel` opened and the gas transaction
written, `bea check` passing; every printed remedy, run as printed, makes
progress. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — `bea add open --allow-errors` now stages an account on a ledger that loads `beancount.plugins.nounused` (alone or through `pedantic`): `validate_candidate` in `cli/src/bea_engine/ledger/write.py` exempts a newly appended open's `Unused account` the same way it exempts a staged pad's `Unused Pad`, and only when the request appends nothing but opens. On such ledgers the unknown-account refusal from `add transaction`/`add transactions` and the blocked-row remedy from `import` (`cli/src/bea_engine/importing.py`) now print the `add open` line with `--allow-errors`, the plain `add open` refusal names the flag, and an import no longer stops on an existing error that is only an account staged this way. `docs/USAGE.md` and `docs/IMPORTING.md` describe the two-step. `cli/tests/test_nounused_staged_open.py` runs each printed remedy as printed on the note's fixture under both plugins, ends with the account opened, the transaction written and `bea check` passing, checks that the flag still refuses other introduced errors, and keeps a no-plugin control; seven of its eight cases fail with the fix reverted. The note's alternative of writing the open atomically with its first use was not implemented, and the plugin is recognised by its two upstream module names, so a third-party plugin raising the same error gets the staging but not the adjusted remedy text. Only macOS was exercised. `make check-all` passed. Shipped in `300509a9` (`cli`).
