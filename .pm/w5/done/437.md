# SIGTERM or SIGHUP to `bea` leaves `example`, `treeify`, `doctor roundtrip|directories|missing-open` and cloud `git clone` children running; an orphaned clone finishes in the background, so a supervisor's retry fails on the existing directory

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12. **Simulation** for the clone: a localhost mock API, and a fake ssh that serves a local bare repo after an 8 s delay.

[w5/208](./done/208.md) made native commands forward SIGTERM and SIGHUP to
their child. Its resolution says "`example`, `treeify`, `price` and
`ingest` share the fixed code path". That is true only for `_spawn`.
`capture_native`, used by `example`, `treeify` and doctor's captured
operations, is a bare `subprocess.run` with no forwarding, and so is
cloud `git clone`. When a supervisor or a `timeout` signals only bea's
PID, these children keep running after bea exits 143 or 129. Ctrl-C at a
terminal is fine, because it signals the whole process group. No product
fix implemented.

The hunter started bea with stdin closed and sent the signal to the
frontend PID only. Isolated BEA_CONFIG_DIR, a fresh XDG_CACHE_HOME per
run.

| Command | Signal | Frontend exit | Still running 2 s later |
|---|---|---|---|
| `bea example --seed 1 --date-begin 1970-01-01 -o out.bean` | TERM or HUP at 1.5 s | -15 / -1 | bean-example (2 runs) |
| `bea doctor roundtrip big.bean` (150k txns) | TERM or HUP at 3 s | -15 / -1 | bean-doctor (3 runs); ran ~14 s more |
| `bea doctor directories big.bean` | TERM at 3 s | -15 | bean-doctor |
| `bea treeify fifo.txt` | TERM or HUP at 2 s | -15 / -1 | treeify |
| `bea cloud ledger clone qa/book` | TERM (×2) or HUP at 2 s | -15 / -1 | `git clone`, sh, ssh |

What the orphans do afterwards:

- The orphaned `doctor roundtrip` left a scratch `…roundtrip1.bean.picklecache`
  that bea normally deletes (`doctor.py:422-425`).
- The orphaned `git clone` completed `book/` about 8 s after bea died. A
  retry then fails with `destination path '…/book' already exists and is
  not an empty directory` (exit 1).

Control: under a PTY, Ctrl-C exits 130 with no survivors. `check`
(`run_native`) and helper commands (`balance`, `add` on 150k) forward
TERM and HUP, leaving no survivors, no `.bea-*` files and no locks.

I confirmed that `capture_native` (`cli/src/cli/engine/launch.py:265-277`)
is a bare `subprocess.run`. I did not re-run the signal matrix.

Expected: w5/208's stated behaviour, "is passed on to the child", should
hold for every child bea starts.

Cause:

- `capture_native` (`launch.py:265-277`), used by `example.py:135`,
  `treeify.py:146` and `doctor.py:256` (`_capture`).
- `clone_ledger` (`cli/src/cli/commands/cloud/ledger/manager.py:151`).
- The same shape exists in `upgrade.py:141` and `:203`, read but not run.

Fix: run these through the same `Popen` plus forwarding used by
`_run_helper`/`_run_inherited`: forward TERM or HUP, kill the child after
the grace period, then re-raise. For the clone, consider removing a
partly created target when stopped. No dependency change.

Blast radius: `example`, `treeify`, doctor captures and cloud clone under
supervisors, CI timeouts and `kill <pid>`.

Dedupe: w5/208 (done) fixed `_spawn` only, and its claim about the other
commands was untested. w5/300 and its addendum cover SIGKILL and the
treeify FIFO. w3/440 and w5/014 cover writes. None covers these paths.

Acceptance: for each row above, no child survives 2 s after the
frontend exits, and the clone target is absent (or reported) after a
stopped clone. A test signals the frontend PID for `example` and a
captured `doctor`.

---

**Resolved 2026-10-15** — `cli/src/cli/engine/launch.py` gained
`run_captured`, a captured `subprocess.run` that shares `_run_inherited`'s
forwarding. Both now use `_stop_passed_on`. The child stays in bea's
process group, so it can still prompt on the terminal and hear Ctrl-C.
A SIGTERM or SIGHUP aimed at bea alone is passed on to the child, which
is killed after the grace period, and bea then dies of the same signal.
`capture_native` (`example`, `treeify`, doctor's captured `roundtrip`,
`directories` and `missing-open`) and the cloud `git clone`
(`cli/src/cli/commands/cloud/ledger/manager.py`) run through it. A stopped
clone's git removes its own half-made directory, rather than finishing it
in the background. `cli/tests/test_captured_termination_reaches_child.py`
signals the frontend PID alone for `example` and for captured doctor
`missing-open`/`roundtrip` under TERM and HUP, and asserts no child
survives 2 s later. All 5 cases fail without the fix. The clone path is
covered through the same function, not by a signal test of its own. The
`subprocess.run` calls in `upgrade.py` (`:146`, `:208`), which the note
read but did not run, are unchanged.
