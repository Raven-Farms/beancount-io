# Process-substitution inputs (`<(…)`) fail with misleading errors: `bea treeify <(…)` exits 1 with `OSError: [Errno 9] Bad file descriptor: '/dev/fd/11'`, and `bea import <(…)` says "Export file not found" for a path that exists

**Trivial · cli · 15–20m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
Shells pass `<(cmd)` as a `/dev/fd/N` path. `treeify` forwards the path
to a child process started with the default `close_fds=True`. The child
cannot open the parent's descriptor and fails with a class name.
`import` checks `is_file()`, which is False for a pipe, and reports the
existing path as "not found". `doctor` says the path "does not exist".
No product fix implemented.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, and
closed stdin for bea itself.

```sh
bea treeify <(printf 'Assets:Cash  5\n')
bea -f /absolute/books/main.bean import <(cat s.csv) --account Assets:Cash --csv date=Date,payee=Payee,amount=Amount
bea doctor lex <(cat /absolute/books/main.bean)
```

Actual:

- `treeify` exits 1 with `treeify failed (exit 1): OSError: [Errno 9] Bad
  file descriptor: '/dev/fd/11'`.
- `import` exits 2 with `Export file not found: /dev/fd/11`.
- `doctor lex` says `Path '/dev/fd/11' does not exist`.

Reproduced twice by the hunter, and by me for `treeify`.

Control: `bea treeify < bal.txt` works. `-f <(…)`, `query --source
<(…)` and `format <(…)` refuse with accurate "not a regular file"
messages.

Expected: either read the data (pass the descriptor through, or read it
in the frontend and pipe it to the child), or refuse with an accurate
message such as "is not a regular file (a pipe); save it to a file
first". There should be no class name, and no "not found" for a path
that exists.

Cause:

- `capture_native` (`cli/src/cli/engine/launch.py:265-277`) runs the
  child with `close_fds=True`.
- The import frontend uses `if not source.is_file(): raise
  UsageError("Export file not found: …")`
  (`cli/src/cli/commands/import_.py:522-523`).

Fix: for `/dev/fd/N` arguments, use `pass_fds`, or read the data in the
frontend. Word the import refusal by file type: missing, directory or
not regular. No dependency change.

Dedupe: w2/025 covers the "Export file not found" wording for missing
paths, and 352 covers treeify's own input pre-check (it could absorb the
treeify half). Nothing covers process substitution.

Acceptance: `treeify <(…)` renders the tree, or refuses accurately
without `OSError`. `import <(…)` and `doctor lex <(…)` give accurate
messages. A test covers a pipe argument.

---

**Resolved 2026-10-15** — `treeify <(…)` now renders the tree.
`capture_native` and `run_captured` take `pass_fds`, and `treeify` passes
a `/dev/fd/N` input that the process holds open through to the child
(`cli/src/cli/commands/treeify.py`, `cli/src/cli/engine/launch.py`). This
works with and without `-o`. `output.not_a_file` (formerly private)
names a pipe as "is a pipe, not a file". `import <(…)` exits 2 with
`Export /dev/fd/N is a pipe, not a file. Save it to a file and import
that file.` A directory gets "Name the export file inside it", and a
missing path still says "Export file not found"
(`cli/src/cli/commands/import_.py`). `doctor lex <(…)`, and any doctor
operation, exits 2 with `Ledger path /dev/fd/N is a pipe, not a file.
Save it to a file and pass that file.` instead of upstream's "does not
exist" (`cli/src/cli/commands/doctor.py`). Pinned by
`cli/tests/test_process_substitution_inputs.py`, which passes a held
pipe the way a shell does and fails without the fix.
