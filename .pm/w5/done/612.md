# Two more import refusals still suggest `--account Assets:Checking` when no account was typed (gap in w5/470)

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `be46147e`, checkout `bea 0.3.1`, macOS 26.5.1.
w5/470's fix made the no-importer refusal keep the typed account (or an
`ACCOUNT` placeholder) and list the file's columns. Two other refusals still
hard-code `Assets:Checking`. An agent that follows them imports a savings or
card export into checking. On a ledger with no `Assets:Checking`, they name an
account that does not exist. No product fix implemented.

Ledger opening `Assets:Checking`, `Assets:Savings`, `Income:Interest`,
`Expenses:Uncategorized`; `savings.csv`:

```csv
Posted Date,Memo,Debit,Credit
07/31/2026,INTEREST PAYMENT,,8.25
```

```sh
bea --no-input --file /abs/main.bean import savings.csv
bea --no-input --file /abs/main.bean import savings.csv --csv 'date=Posted Date,debit=Debit,credit=Credit,narration=Memo'
```

Actual (both exit 2): `…but not which account the export belongs to. Add
--account Assets:Checking, or choose a Python importer with --config FILE.`
and `--csv needs --account ACCOUNT for the source account, for example
--account Assets:Checking.`

Expected: the w5/470 rule: an `ACCOUNT` placeholder (or the ledger's open
Assets/Liabilities accounts as candidates).

Cause: hard-coded strings in `cli/src/cli/commands/import_.py:819-827`; the
w5/470 fix (`9e9040b4`) changed only `_config_path`.

Fix: use the placeholder (or list candidates) in both.

Dedupe: w5/470 (done) is the parent.

Acceptance: neither refusal names `Assets:Checking` unless the user typed it.
A test pins both.

Addendum (CLI QA 2026-10-16, re-check of the w5/470 fix): a third refusal
has the same hard-coded advice. For a header bea reads only partly
(`partial.csv` = `Date,What,HowMuch` / `2026-02-01,A,-1.00`), `bea -f
/abs/main.bean import partial.csv --account Assets:Savings` (and `--csv
auto`) exits 2 with `Cannot read a column mapping from the header row of
partial.csv. Its columns are: Date, What, HowMuch. Name them with --csv
date=Date,amount=Amount,narration=Description.` Pasting it fails with `The
mapping names column 'Amount' for amount, which partial.csv lacks.` Cause:
the fixed string at `cli/src/cli/commands/import_.py:253`. Use the same
`date=COLUMN,…` placeholder form (and keep the typed `--account`) as the
w5/470 fix.

---

**Resolved 2026-10-17** — Shipped in `04d4c612` (`cli`).
- In `cli/src/cli/commands/import_.py`, the inferred-mapping refusal now reads "Add --account ACCOUNT, naming the account it belongs to, or choose a Python importer with --config FILE."
- The typed-mapping refusal reads "--csv needs --account ACCOUNT, naming the account the export belongs to." The engine's copy in `cli/src/bea_engine/importing.py` says the same.
- Addendum: the unread-header refusal reads "Its columns are: Date, What, HowMuch. Name them with --csv date=COLUMN,amount=COLUMN,narration=COLUMN --account Assets:Savings.". It keeps a typed `--account` (`ACCOUNT` otherwise) and never names columns the file lacks.
- `tests/test_import_refusals_name_no_account.py` pins both account refusals and the unread header with and without a typed account. All 4 fail without the fix. `make check-all` passed.
