# `bea example` skips its date-range check for non-ISO dates and fails with `IndexError`

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
w1/done/086 added a guard so an inverted or too-short range exits 2 before
generating. The guard parses ISO dates only; a date the upstream tool also
accepts, such as `2026/03/01`, slips past it and the generator crashes.
No product fix implemented.

No fixture. Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY.

```sh
bea example --seed 1 --date-begin 2026/03/01 --date-end 2026/01/01
```

Actual: exit 1, `Error: bean-example failed (exit 1): IndexError: list
index out of range`.

Control: `bea example --seed 1 --date-begin 2026-03-01 --date-end
2026-01-01` exits 2: `--date-begin 2026-03-01 is after --date-end
2026-01-01; begin must be on or before end.` A worker saw `StopIteration`
for a short slash-dated range and the same crash for `"March 1 2026"`.

Expected: `docs/USAGE.md`: "`bea example` exits 2 before generating when
its date range is inverted or shorter than 31 days".

Cause: `cli/src/cli/commands/example.py:83-86` parses with
`date.fromisoformat` and returns on `ValueError`, so other spellings reach
the generator unchecked.

Fix: parse the dates as upstream does before applying the guard, or refuse
non-ISO dates with exit 2. No dependency change.

Blast radius: `bea example` only.

Dedupe: board search for `StopIteration`, `bean-example` and non-ISO finds
w1/done/086 (the ISO case); w5/089 and w5/136 are other `example` items.

Acceptance: the slash-dated command exits 2 with the begin/end message (or
a message that dates must be ISO). Only macOS and the checkout were
exercised.

---

**Resolved 2026-10-13** — The date-range guard in `cli/src/cli/commands/example.py` no longer returns silently when a date is not ISO: `--date-begin` and `--date-end` must now be written `YYYY-MM-DD`, and any other spelling (`2026/03/01`, `March 1 2026`, `20010601`) exits 2 naming the option and the value before `bean-example` runs. Of the note's two fixes this is the refusal, because upstream's liberal parser (python-dateutil) is an engine-side dependency the frontend does not carry; the consequence is that a valid slash-dated range, which used to generate, is now refused too, and `docs/USAGE.md` states the rule. `tests/test_example_non_iso_dates.py` runs the real command for slash, worded and compact dates on either side of the range, plus the ISO inverted-range and valid-range controls; five of its seven cases fail with the fix reverted. `--date-birth` is not part of the range guard and still passes through to upstream unchanged. Only macOS was exercised. `make check-all` passed. Shipped in `046fe998` (`cli`).
