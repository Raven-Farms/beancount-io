# A blocked import through a symlink cites a nonexistent ledger line instead of the open's row in this import (incomplete fix of w5/636)

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-17, HEAD `8e35a3636`, checkout `bea 0.3.1`, macOS 26.5.1. Twice from fresh synthetic fixtures; isolated config/cache, stdin closed, no TTY. No product fix implemented.

In `/abs/books/main.bean`, open `Assets:Checking USD` on 2026-01-01. Put synthetic text in `bank.txt`. `imp.py` exports a `beangulp.Importer` instance named `bank`, whose `identify` returns True, `account` returns `Assets:Checking`, and `extract` returns these directives:

```python

Transaction({}, datetime.date(2026, 2, 1), "*", None, "Lunch", frozenset(), frozenset(), [
    Posting("Assets:Checking", Amount(D("-5"), "USD"), None, None, None, None),
    Posting("Expenses:Dining", Amount(D("5"), "USD"), None, None, None, None)])
```

Use the ordinary Beancount imports and importer class shown in [855](./855.md), with the two directives above as the returned list. Create `/abs/books-link` as a symlink to `/abs/books`.

```sh
bea --file /abs/books-link/main.bean import /abs/books-link/bank.txt --config /abs/books-link/imp.py
bea --json --file /abs/books-link/main.bean import /abs/books-link/bank.txt --config /abs/books-link/imp.py --apply
```

Actual: preview exits 0 with one blocked row and says the account opens at `/abs/books-link/main.bean:<proposed-append line>`. That line does not exist in the original file. JSON apply exits 4 and repeats the nonexistent location. Both preserve every ledger byte.

Control: the same preview using `/abs/books/main.bean` correctly says `(row 1 of this import)`. The repeated fixtures used a five-line initial ledger and likewise cited its nonexistent line 7 through the symlink, versus import row 1 through the real path.

Expected: name row 1 of this import through either spelling, as w5/636's acceptance requires. The advice must identify the proposed open the user can actually edit.

Cause: `_entries_after` in `cli/src/bea_engine/importing.py:1538` compares `os.path.normpath(meta["filename"])` with `os.path.normpath(target)`. Staging remaps the former to the unresolved spelling while `ledger_write.destination` resolves the latter. The equality fails, so `_IMPORT_ROW` is never attached and `_where` prints the append's temporary line number. `_entries_after` has one caller in import preparation; the same comparison also covers `--into` destinations.

Fix: compare file identity through the snapshot's path-identity mechanism or resolve both spellings before assigning import-row metadata. Preserve the displayed spelling for actual existing ledger locations.

Dedupe: whole-board searches for symlink/import-row attribution found only w5/636 (done). Its fix is `d2d2a8834`; this is a missed spelling, not a new locator policy.

Acceptance: real and symlinked roots identify the imported open as row 1 in preview and apply refusal; add a symlinked include/`--into` regression too. No rejected run changes files.

---

**Resolved 2026-10-20** — `_entries_after` attaches the import row to an appended entry when its file is any name the snapshot knows the destination by (`_stands_for`: resolved path or captured device/inode), not only the resolved spelling, so a blocked row's reason says `(row 1 of this import)` through `books-link/main.bean` in the preview and in the `--apply` refusal, and through a linked root into an `--into` include. Existing ledger locations keep their displayed spelling. `tests/test_import_blocked_reason_real_location.py` adds the linked-root preview/apply and linked-include cases; no refused run changes files.
