# `upgrade --check` still accepts unreadable index answers with exit 0: `info.version: null` reports `"latest": "None"` (and caches it), an empty version reads "unknown", and on Homebrew an HTML page from the tap URL reads "Latest release: unknown" (incomplete fix of w5/484)

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `604894f6`, checkout `bea 0.3.1`, macOS 26.5.1. Synthetic local release index. Follow-up to w5/484 (done).
w5/484 mapped HTML and shape errors to "the index sent an unreadable answer"
(exit 1). `str(payload["info"]["version"])` still turns any JSON value into
a string. The Homebrew branch returns `""` when its patterns do not match, so
an HTML error page from the tap URL is a "success". Homebrew is the main
install channel. No product fix implemented.

```sh
# index answers {"info":{"version":null}}
BEA_UPDATE_API_URL=http://127.0.0.1:<stub> bea --json upgrade --check
# index answers {"info":{"version":""}}, ["0.9.0"], or 9
# Homebrew channel: BEA_TAP_FORMULA_URL serving a 200 text/html 502 page
```

Actual: `null` → exit 0, `"latest": "None"` (text: `Latest release: unknown
(the index answered 'None')`), and the cache stores `"None"`; `""` → exit 0,
`Latest release: unknown` (the shape w5/322 fixed); `["0.9.0"]` reads back as
`'['0.9.0']'`. On the Homebrew channel (simulated by patching
`current_channel`), the HTML page gives exit 0, `Latest release: unknown`,
`Would run: brew upgrade bea`, and caches `""`.

Control: `{"info":{"version":"0.9.0"}}` → `Latest release: 0.9.0`; `{"info":{}}`
and `[1]` → the unreadable-answer error.

Expected: exit 1 with `Could not check … for a newer release: the index sent
an unreadable answer.` for each, and nothing cached.

Cause: `_fetch_latest` (`cli/src/cli/update.py:232-244`): `str(...)` on the JSON
value; `return match.group(1) if match else ""` on Homebrew.

Fix: require a non-empty version string that parses as a version; raise the
unreadable-answer error when the Homebrew patterns do not match.

Dedupe: w5/322 and w5/484 (done) are the parents.

Acceptance: the five answers above exit 1 with the sentence. Tests pin them.

---

**Resolved 2026-10-17** — Shipped in `0f6b26925` (`cli`). `_fetch_latest` in `cli/src/cli/update.py` requires `info.version` to be a string that looks like a version (`_VERSION`). On the Homebrew channel, a formula with no version raises instead of returning `""`. `null`, `""`, `["0.9.0"]`, `9` and an HTML page from the tap URL each exit 1 with `the index sent an unreadable answer`, and nothing is cached. Tests are in `cli/tests/test_message_full_stops_and_index_answers.py`. The w5/376 hostile-answer test now expects the unreadable refusal, still with no escape sequence or forged line on the terminal.
