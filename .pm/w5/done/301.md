# An `include` whose file name contains a newline makes every root-ledger `bea add` fail with "Cannot locate an include path in the ledger."

**Trivial · cli · 15–20m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
Beancount loads `include "a\nb.bean"` (an escaped newline), and
`bea check` and `bea list` read it. But every write that stages the root
ledger fails: `bea add note` without `--into` exits 2 with a message that
names neither the file nor the cause. A `--into` write into the
newline-named file succeeds. `price export` writes a copy whose root then
fails `bea check` with the same error. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Equity:Opening USD
include "a\nb.bean"
```

and a file named `a`, newline, `b.bean`:

```beancount
2026-01-03 note Assets:Checking "inc"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY.

```sh
bea -f /absolute/books/main.bean check
bea -f /absolute/books/main.bean add note --date 2026-01-05 -a Assets:Checking -m root
bea --json -f /absolute/books/main.bean add note --date 2026-01-05 -a Assets:Checking -m root
```

Actual: `check` exits 0, and `list note` shows the included note. Both
`add` runs exit 2 with `Cannot locate an include path in the ledger.`
(JSON category `usage`) and leave the ledger unchanged.
`price export -o exp` exits 0, but then `bea -f exp/main.bean check` exits
2 with the same message, because the exported root contains a literal
newline inside the include string. Reproduced twice from pristine copies.

Control: the same ledger with `include "ab.bean"` adds the note and exits 0.

Expected: a write to a ledger that Beancount loads and `bea check` accepts
should succeed once validated. An include that `bea` cannot rewrite should
at least be named in the error.

Cause: `iter_includes` (`cli/src/bea_engine/ledger/text.py:367-371`)
searches for the STRING token starting at the token's reported line.
Beancount's lexer reports a string that spans lines at its last line, so
`content.find(text, starts[line - 1])` returns -1 and raises. The staged
twin and the export spell the include with a literal newline because
`_include_literal` (`write.py:255-263`) uses `escape_string`, which leaves
`\n` unescaped.

Fix: search from `starts[line - 1 - text.count(b"\n")]`, or locate the
token by a running offset. If newline names stay unsupported, refuse the
include by name instead. No dependency change.

Blast radius: every caller of `iter_includes`: write staging
(`write.py:53`), the managed and export rewrites
(`managed_load.py:655/727/1337`) and `compat.py:93`. So every
root-staged write and `price export` of such a ledger is affected. File
names with newlines are rare.

Dedupe: searched for `Cannot locate an include path`, newline and
multi-line include, and multiline string, and ran `git log -S` (finds
`790791ac`, `b1846ef4`). Related notes:

- w5/247: glob characters in include names.
- w3/252, w3/415 and w1/048: newlines in directive strings.
- w1/060: CSV injection.

None covers an include name that contains a newline.

Acceptance: on the fixture, `add note` without `--into` either exits 0 and
writes, or exits 2 naming the include. `price export` produces a root that
`bea check` accepts. A regression test covers both. Only macOS was
exercised.

---

**Resolved 2026-10-14** — `literal_include` (`cli/src/bea_engine/ledger/write.py`) now escapes `\n`, `\r` and `\t`, which `escape_string` left raw, so staged copies and exported roots keep `include "a\nb.bean"` on one line. `iter_includes` (`cli/src/bea_engine/ledger/text.py`) starts its search at the first line of a string token that spans lines, since the lexer reports it at its last line. A hand-written include with a raw newline is therefore located too. On the fixture, `add note` without `--into` writes and exits 0, and `price export -o exp` gives a root that `check` and `list note` accept. `cli/tests/test_include_name_with_newline.py` covers the escaped and raw spellings; both fail with the fix reverted. Only macOS was exercised. `make check-all` passed. Shipped in `d711c5ed` (`cli`).
