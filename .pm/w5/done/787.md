# First-use provisioning locks: an unwritable data directory gives a raw `[Errno 13] Permission denied` with exit 1 (not 3) from every engine command including `bea init`, and a command waiting on another's install waits forever with no output

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-17, HEAD `46d7394e9`, `bea 0.3.1` installed from a freshly built wheel with isolated data directories, macOS 26.5.1.
No product fix implemented.

1. **Unwritable data directory** (a sandboxed agent, for example).
   - With `XDG_DATA_HOME` pointing at a mode-555 directory, `bea -f
     /abs/main.bean check` exits 1 with `Error: [Errno 13] Permission denied:
     '…/rodata/bea'. Pass --debug before the command for a traceback.`
   - `--json check` (category `validation`), `engine enable`, `--no-input
     init`, and `BEA_ENGINE_DIR` under a read-only parent fail the same way
     (hunter's runs).
   - `engine status` meanwhile says it "provisions on first use".
   - USAGE's exit table makes permission failures exit 3, and the sibling
     write-lock rule names the directory and the variable to set.
2. **Silent wait.** While another process holds `flock(LOCK_EX)` on
   `<data>/bea/engine/0.3.1.lock` (a stalled or Ctrl-Z'd first install), `bea
   -f /abs/main.bean check` prints nothing on stdout or stderr until killed
   (8 s here, more than 15 s in the hunter's run). `--json check` and `engine
   enable` behave the same. The write lock (w5/182) prints `Waiting up to 60
   seconds for another bea write…` and gives up after 60 s.

Expected:
1. Exit 3 naming the directory, with "make it writable or set XDG_DATA_HOME
   / BEA_ENGINE_DIR".
2. A "Waiting for another bea to finish installing the engine at <root>…"
   notice after about a second (silent under `--json`), and a bounded wait.

Cause: `provisioning_lock` (`cli/src/cli/engine/provision.py:65`) creates the
directory and takes a blocking `flock` via `exclusive_lock`
(`cli/src/cli/utils.py:363`), with no `OSError` handling, notice or timeout.

Fix: catch `OSError` around the mkdir and lock (exit 3 with the remedy), and
poll the lock with a notice and a timeout, as the write lock does.

Dedupe: w1/120 (done) added the lock and w5/182 (done) the write-lock notice;
w5/279, 090 and 309 cover other permission paths.

Acceptance: case 1 exits 3 naming the directory; case 2 prints the notice
within about a second.
