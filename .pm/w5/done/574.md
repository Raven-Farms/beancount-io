# A write `--into` a file the ledger also reaches under a second name (a symlink the include glob matches, or a case variant) validates against a load that counts the file twice: a wrong balance assertion is written with exit 0, a correct one is refused, and the existing-error gate is skipped

**Major · cli · 30–45m · A1.** Real CLI QA, 2026-10-16, HEAD `3514cc17`, checkout `bea 0.3.1`, macOS 26.5.1. Write-path sibling of w5/433.
Reads load such a file once and report `Duplicate include` (w5/433). For a
write, the staged candidate replaces only the target's own path. The
second name still points at the original, and the candidate has a new inode,
so the duplicate check finds nothing. The original's entries are loaded
beside the candidate's, and the existing `Duplicate include` error
disappears from that load. A "current year" symlink matched by the include
glob is a plausible layout. No product fix implemented.

`main.bean`:

```beancount
option "operating_currency" "USD"
2020-01-01 open Assets:Bank USD
2020-01-01 open Expenses:Food USD
include "txns/*.bean"
```

`txns/2020.bean`: `2020-01-03 * "Shop" "food"`, `Expenses:Food 10.00 USD`,
`Assets:Bank`. `txns/current.bean` is a symlink to `2020.bean`.

```sh
bea -f /abs/main.bean add balance --date 2020-03-01 --account Assets:Bank --amount "-20.00 USD" --into txns/2020.bean --allow-errors
bea -f /abs/main.bean check
bea -f /abs/main.bean add balance --date 2020-03-01 --account Assets:Bank --amount "-10.00 USD" --into txns/2020.bean --allow-errors   # fresh copy
bea -f /abs/main.bean add transaction X --date 2020-02-02 -p "Expenses:Food 1.00 USD" -p Assets:Bank --into txns/2020.bean          # fresh copy
```

Actual:

- the -20.00 assertion (twice the real balance) is written with exit 0
  (`Added 1 balance`); `check` then reports `txns/2020.bean:5: Balance failed
  for 'Assets:Bank': expected -20.00 USD != accumulated -10.00 USD`;
- the true -10.00 assertion is refused: `The change would introduce 2 new
  ledger error(s)…`, `expected -10.00 USD != accumulated -20.00 USD (10.00
  too little)`;
- the transaction `--into` is written without `--allow-errors`, though the
  ledger already has the `Duplicate include` error;
- a write to the root names the staging file: `.bea-….tmp:2: Duplicate
  include: …`.

The case-variant twin (`include "sub/x.bean"` plus `include "SUB/X.bean"` on
case-insensitive APFS) behaves the same.

Control: `bea balance` refuses with `main.bean:4: Duplicate include:
txns/current.bean is txns/2020.bean under another name …`; with
`--allow-errors` Bank is -10.00. A ledger with one name per file is
validated correctly.

Expected: the candidate load reads the target once (as reads do), keeps the
existing `Duplicate include` error (so the gate applies), and judges the
assertion against -10.00. USAGE: "a write that exits 0 introduces no new `bea
check` error".

Cause: `LedgerSnapshot.staged` (`cli/src/bea_engine/ledger/write.py`, around
`:288-310`) swaps in the candidate only for the path equal to the target;
`_duplicate_members` (`cli/src/bea_engine/managed_load.py:803-822`) groups by
`(st_dev, st_ino)`, which the new inode escapes. Errors in the staged include
listing file (`write.py` around `:313-330`) are not mapped back to the
includer.

Fix: while staging, treat every closure path in the target's dev/inode group
as the target (or carry the original snapshot's duplicate map into the
candidate load); map listing-file errors to the include line.

Dedupe: searched `Duplicate include`, `validate_append`, `.bea-*.tmp`. w5/433
(done) covered reads; w5/144 and 391 are different.

Acceptance: the -20.00 assertion is refused, the -10.00 one is accepted (with
`--allow-errors`), the plain `--into` write is refused for the existing error,
and messages name `main.bean:4`. Tests pin each (symlink and case variant).

---

**Resolved 2026-10-17** — Shipped in `311985b9` (`cli`). Changes in `LedgerSnapshot` (`cli/src/bea_engine/ledger/write.py`):
- **Staging:** every closure name with the target's captured device and inode is treated as the target, so a case variant or a link stands for it too.
- **Include lines:** `staged` leaves names reached a second time out of staged include lines, as reads do, so the candidate is loaded once.
- **Errors:** `duplicate_include_errors` restores the read's `Duplicate include` error at the original include line. `validate_candidate` appends it to the staged load's errors, and its wording is now shared through `managed_load.duplicate_include_message`.

On the note's symlink fixture:
- the `-20.00` assertion is refused (`expected -20.00 USD != accumulated -10.00 USD`);
- the true `-10.00` one is written with `--allow-errors`, and `check` then shows only the duplicate include;
- the plain transaction `--into` is refused by the existing-error gate;
- a root write names `main.bean:4`, not a `.bea-….tmp` staging file.

`tests/test_write_duplicate_member.py` pins all four cases, which fail without the fix. Not exercised: the case-variant twin on a case-insensitive volume, which takes the same inode path. `make check-all` passed.
