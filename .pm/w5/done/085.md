# A `PRINT` export of a ledger with a pad does not pass `bea check`

**Minor · cli · 30m · A1.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, macOS. `bea query PRINT -f beancount` is the
documented way to export parseable directives. For a ledger containing a
`pad`, the export carries both the `pad` directive and the padding
transaction Beancount synthesized from it, so the exported file fails
validation. No product fix implemented.

Create disposable `/absolute/books/pad.bean`:

```beancount
2024-01-01 open Assets:Cash USD
2024-01-01 open Equity:Open
2024-01-09 pad Assets:Cash Equity:Open
2024-01-10 balance Assets:Cash  42.00 USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, and an absolute `--file`.

```sh
bea -f /absolute/books/pad.bean check
bea -f /absolute/books/pad.bean query PRINT -f beancount -o /absolute/books/out.bean
bea -f /absolute/books/out.bean check
```

Actual: exits 0, 0, then 1 with `out.bean:4: Unused Pad entry`. The export
holds the `pad` line and a `2024-01-09 P "(Padding inserted for Balance of
42.00 USD …)"` transaction. Repeated twice.

Control: a ledger without a pad — cost lots, sales, labels, typed metadata,
multi-line strings — exports and reloads to the same entries once its option
lines are restored.

Expected: `docs/USAGE.md` calls `PRINT` output "parseable directives" and
says the Beancount format "preserves" values so an export can be reloaded. An
export of a valid ledger should itself pass `bea check`.

Cause: `cli/src/bea_engine/query.py:804-820` (`_render_beancount`) prints
every result row, including flag-`P` transactions whose source location is a
`pad` line. Upstream `bean-query` prints the same pair, but this renderer is
`bea`'s own and already departs from upstream to keep exports reloadable.

Fix: under `-f beancount`, omit a padding transaction when the `pad` that
generated it is in the same result, so the reloaded ledger derives it again.
Native `--source` rendering stays upstream's. No dependency or API change.

Dedupe: board search for Unused Pad, "Padding inserted" and `PRINT`
round-trips finds w3/224 and w1/116 (`add balance --pad-from`) and w3/457
(custom values in exports); none covers pads in exports.

Acceptance: the fixture's export passes `bea check` and holds one `pad` and
one `balance`; a filtered `PRINT` that selects the padding transaction
without its `pad` still prints it; the pad-free control is unchanged. Only
macOS and the checkout were exercised.

---

**Resolved 2026-10-12** — Under `-f beancount`, the `PRINT` renderer omits a padding (`P`) transaction when the `pad` at the same source location is in the same result, so the reloaded export derives it again. The fixture's export holds one `pad` and one `balance` and passes `bea check`; a filtered `PRINT` that selects the padding transaction without its `pad` still prints it. Native `--source` rendering is untouched, and `docs/USAGE.md` states the rule. Shipped in `14189e29` (`cli`).

Real-command regression tests cover the padded export (reloads, passes `check`, and still sums to `42.00 USD`), the padding transaction selected alone, and a pad-free ledger exporting as before. The first fails with the fix reverted; the other two pass either way. `make check-all` passed. Only macOS was exercised.
