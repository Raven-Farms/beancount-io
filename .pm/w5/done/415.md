# `bea example -o FILE --version` exits 0 and writes `Beancount 3.2.3` as FILE; with `--force` it replaces an existing ledger with that 16-byte string

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
`example` removes `-o`, captures bean-example's stdout, and writes it
atomically to the destination whenever the child exits 0. `--version` is
not a bea option, so it is forwarded. The child prints its version and
exits 0, and bea writes that banner as the "generated ledger". With
`--force`, the overwrite guard is bypassed, so an existing ledger can be
replaced. That includes the cwd-discovered `main.bean`. No product fix
implemented.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, and
closed stdin. Run the second command only on a disposable copy.

```sh
bea example --seed 1 -o /absolute/ex.bean --version
cat /absolute/ex.bean
cd /absolute/copy && bea example -o main.bean --force --version
```

Actual:

- The first command exits 0 with no message. `ex.bean` holds `Beancount
  3.2.3`.
- The second exits 0, and the copied `main.bean` becomes 16 bytes.

Reproduced three times by the hunter and once by me (first command).

Control:

- `bea example --version` without `-o` prints the version.
- `bea example -o x --help` writes nothing.
- `bea example --seed 1 -o main.bean --force` writes a full example.

Expected: `-o` writes the generated example ledger. bea "writes it only
once the run and its validation have succeeded" (`example.py:125-127`).
A version banner is not a ledger. `--version` should print to stdout and
leave `-o` alone, or the combination should exit 2.

Cause: `cli/src/cli/commands/example.py:133-139` writes whatever stdout
the child produced on exit 0. `_refuse_invalid` inspects only stderr.

Fix: when the forwarded arguments contain `--version`, skip the output
split and print. As a backstop, refuse to write stdout that holds no
directives. No dependency change.

Blast radius: `bea example -o … --version`, and with `--force` the loss
of an existing ledger file's contents.

Dedupe: searched `.pm/**`, including `done/`, for `example` together
with `--version`. w5/089, w5/136, w5/277, 353 and 389 cover other `-o`
cases, and w3/314 covers `--json --version`. None covers this.

Acceptance: `bea example -o ex.bean --version` prints the version and does
not create `ex.bean`, or exits 2. The `--force` variant leaves
`main.bean` unchanged. A test pins it.

---

**Resolved 2026-10-15** — `bea example` (`cli/src/cli/commands/example.py`)
now treats `--version` as informational: it prints bean-example's version
and, when `-o` was given, notes `--version prints bean-example's version;
ex.bean was not written.` The destination is never touched, so `-o
ex.bean --version` creates nothing and `-o main.bean --force --version`
leaves `main.bean` as it was. As a backstop, `-o` is never written with
output that holds no Beancount directive (`bean-example printed no
ledger, so … was not written.`, exit 1). Plain `--version` and real
examples are unchanged. Pinned by
`cli/tests/test_example_version_with_output.py`, which fails without the
fix; one mocked test of glued `-o` now returns a directive-shaped output.
