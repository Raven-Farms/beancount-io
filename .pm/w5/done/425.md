# `add price -c ''` and `add commodity -c ''` say "Request field 'currency' must be a non-empty string.", naming an internal request field instead of the `-c/--currency` option

**Trivial · cli · 5–10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
The exit code (2) is right, but the message comes from the engine's
generic request validator, so it names a field the user never typed.
`add open -c ''` has a frontend check that names the option. No product
fix implemented.

Use any USD ledger, isolated BEA_CONFIG_DIR/XDG_CACHE_HOME,
BEA_NO_UPDATE_NOTIFIER=1, and closed stdin.

```sh
bea -f /absolute/books/main.bean add price --date 2026-01-05 -c '' --amount '1 USD'
bea -f /absolute/books/main.bean add commodity --date 2026-01-05 -c ''
bea -f /absolute/books/main.bean add open --account Assets:X --date 2026-01-01 -c ''   # control
```

Actual: the first two exit 2 with `Request field 'currency' must be a
non-empty string.`. The control says `Every --currency value is blank
after trimming; supply a currency symbol or omit -c.`. Reproduced twice
by the hunter and once by me (price).

Expected: name `-c/--currency`, following w5/239's empty-value rule.

Cause: `cli/src/bea_engine/ledger/adding.py:1433` uses the generic
`Request field {field!r} must be a non-empty string.`

Fix: add the `add open` style frontend check for price and commodity,
or map request field names to option names in that helper. No dependency
change.

Dedupe: `Request field` appears only in a w3/m24 test list. The r46
empty-value sweep tried `-c -`, not `-c ''` on price. None covers it.

Acceptance: both commands name `-c/--currency`. A test pins one.

---

**Resolved 2026-10-15** — the engine's request helper `_text`
(`cli/src/bea_engine/ledger/adding.py`) maps each `bea add` request field
to the option it comes from. A blank value now names that option:
`add price -c ''` and `add commodity -c ''` exit 2 with `-c/--currency
must not be empty; give it a value.`. The same goes for `-a/--account`,
`-m/--comment`, `-d/--description`, `-t/--type`, `-s/--source`,
`--filename` and `--amount` on every single `add` that reads them. An
unmapped field keeps the old generic message. Pinned by
`cli/tests/test_add_blank_option_named.py`, which fails without the fix;
w3/255's empty-value test still passes.
