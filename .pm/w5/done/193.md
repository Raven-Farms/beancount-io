# A placeholder-dated `custom` or `query` directive stretches the report period and floods interval series with zero rows

**Minor · cli · 30–45m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
Configuration directives are conventionally dated long before any
activity (`1970-01-01 custom "fava-option" …`). Reports take that date as
the start of the ledger: the heading reads "1970-01-01 through
2024-05-17", and the monthly series carries 652 zero rows before the one
real month. Totals are correct. `commodity`, `open` and `close` are
already exempt for exactly this reason. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
1970-01-01 custom "fava-option" "language" "en"
2024-01-01 open Assets:Bank
2024-01-01 open Income:Job
2024-05-17 * "pay"
  Assets:Bank  10.00 USD
  Income:Job
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean report balance-sheet
bea --json -f main.bean report income-statement
bea -f main.bean report overview
```

Actual: all exit 0. The heading is `Balance Sheet — 1970-01-01 through
2024-05-17`; the JSON has `"period": {"start": "1970-01-01", …}` and 653
`periods`; `report overview` prints 667 lines.

Control: with `1970-01-01 commodity USD` in place of the `custom` line,
the heading is `2024-05-17 through 2024-05-17`, JSON has 1 period and
the overview is 15 lines. A worker saw the same stretch from an
early-dated `query`, `event` and `custom "budget"`, a future-dated
`custom` push `as_of` to 2099, and `-i daily` print 19,875 lines.

Expected: the period runs over dated activity. The report code states
the rule itself: "Opens, closes and commodities are declarations — a
commodity conventionally carries a placeholder date decades before any
activity." A `custom "fava-option"` or a stored `query` is the same kind
of declaration.

Cause: `cli/src/fava/ledger.py:202-209` skips only `Open`, `Close` and
`Commodity` when deriving the first and last dates;
`cli/src/bea_engine/report.py` inherits that and repeats the same triple
in its boundary check.

Fix: treat `Custom` and `Query` as declarations for period bounds in
both places; keep notes, balances, documents, prices and pads as dated
facts (w3/349). Whether `event` belongs in the exemption is an owner
call. No dependency change.

Blast radius: heading, `period` and `as_of` in all four reports and
`balance`, and every interval series.

Dedupe: w3/349 (done) extended the period to notes on purpose; w3/407
(done) is the 9999 boundary; w5/147 is `fiscal-year-end`. None covers
configuration directives setting the period.

Acceptance: on the fixture the period is 2024-05-17 through 2024-05-17
with one interval row; a ledger whose earliest entry is a note keeps
today's behaviour. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — The report period no longer takes its first or last day from a `custom` or `query` directive: `cli/src/fava/ledger.py` now names one declaration set (Open, Close, Commodity, Custom, Query) that the period bounds skip, and the 9999 boundary check in `cli/src/bea_engine/report.py` reuses that set instead of repeating its own triple. On the note's fixture all four reports and `bea balance` read 2024-05-17 through 2024-05-17 with a single monthly row, and a future-dated `custom` or `query` no longer pushes `as_of` forward. `cli/tests/test_report_period_skips_config_directives.py` covers the four report kinds in JSON, the human headings of balance-sheet, overview and `balance`, the monthly and daily series, a 2099-dated declaration, the boundary helper, and the controls (an early `commodity`, and an early note or event that still starts the period); 16 of its 22 cases fail with the fix reverted. `event` was left as a dated fact, as the note called it an owner decision and the existing code comment lists events among the facts; every `custom` type, including `custom "budget"`, is treated as a declaration as the note prescribes. Only macOS was exercised. `make check-all` passed. Shipped in `0b09d625` (`cli`).
