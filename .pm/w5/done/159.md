# `treeify -o LINK` overwrites an existing `.bean` ledger without `--force` when the symlink's own name lacks the suffix

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
`treeify -o` refuses to replace an existing `.bean` file without
`--force`. The check looks at the name as typed, so a symlink called
`latest` pointing at `books.bean` gets past it and the ledger is replaced
by an ASCII tree, exit 0. The layout is uncommon; the result is a
destroyed ledger. No product fix implemented.

In `/absolute/books`, create `books.bean`:

```beancount
2026-01-01 open Assets:Cash USD
2026-01-01 open Assets:Bank:Checking USD
```

a symlink `latest` → `books.bean`, and `bal.txt`:

```text
account               sum
Assets:Bank:Checking  500.00 USD
Assets:Bank:Savings    50.00 USD
Assets:Cash             5.00 USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, no TTY, cwd `/absolute/books`. Closed stdin.

```sh
bea treeify bal.txt -o books.bean
bea treeify bal.txt -o latest
```

Actual: the first exits 2: `Already exists: /absolute/books/books.bean.
Pass --force to overwrite it; without it, an existing ledger file is never
replaced.` The second exits 0 with no output; `books.bean` now contains
the tree (`` `-- Assets `` …) and `latest` is still a symlink.

Control: the first command.

Expected: `docs/USAGE.md` says a destination is refused when it "would
replace a file that did not come from this command: an existing
`.bean`/`.beancount` file for `treeify -o`", and "`--force` is the only
way past". A link to such a file replaces it just the same.

Cause: `cli/src/cli/output.py:425` tests the suffix of the unresolved
name, while `cli/src/cli/utils.py` (`atomic_write(export=True)`) resolves
the link and replaces its target.

Fix: evaluate the suffix on the resolved destination as well. No
dependency or API change.

Blast radius: `treeify -o`; the same guard serves `ingest extract -o`,
which was not run.

Dedupe: board search for treeify with symlink finds w3/done/431 and m48
(aliasing the ledger being read) and w5/068 and 087 (different
mechanisms); none covers the suffix check through a link.

Acceptance: the second command exits 2 naming the resolved file and
leaves `books.bean` byte-identical; `--force` still overwrites. Only
macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — The existing-ledger guard in `cli/src/cli/output.py` (`guard_output_destination`) judged a `treeify -o` destination by the suffix of the name as typed, so a symlink named without `.bean`/`.beancount` that pointed at a ledger was written through and the ledger replaced. The guard now judges such a link by the file it resolves to, exits 2 naming the resolved file, and leaves the ledger byte-identical; `--force` still overwrites, and `docs/USAGE.md` says the refusal applies to a ledger named directly or reached through a symlink. The new `cli/tests/test_treeify_output_symlink_to_ledger.py` runs the real command over direct and chained links with `-o` and `--output`, the direct-name control, `--force`, and a link to a non-ledger file that is still written; the four link cases fail with the fix reverted. The note's blast radius names `ingest extract -o`, but at this commit only `treeify` opts into this guard, so nothing else changed. Only macOS was exercised. `make check-all` passed. Shipped in `bea71691` (`cli`).
