# A ledger with both a `../` include and a managed price include treats the included file's entries as generated: `--on-disk` hides them and `add price` writes a conflicting quote

**Major · cli · 30–45m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
The common layout of a per-year root that includes a shared folder
(`include "../shared/prices.bean"`) breaks once the ledger also has a
managed price include. Entries from the shared file are labelled
`generated`, `list --on-disk` reports none, and the `add price` conflict
guard no longer sees them: a second, different quote for the same day and
pair is written with exit 0. A worker also saw diagnostics name vanished
`.bea-*.tmp` files. The managed source need not even be available. No
product fix implemented.

Create `/absolute/books/2026/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Bank USD
include "../shared/prices.bean"
include "http://127.0.0.1:18765/prices/BTC-USD"
```

and `/absolute/books/shared/prices.bean`:

```beancount
2026-01-03 price EUR 1.10 USD
```

Simulation only: no network and no server. Run with `--offline`, isolated
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1,
`MANAGED_PRICE_ORIGINS=http://127.0.0.1:18765` (the documented test
override), no inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY. cwd `/absolute/books/2026`. (My run had a hand-seeded
cached revision for the feed; a worker saw the same with an empty cache.)

```sh
bea --offline -f main.bean list price
bea --offline -f main.bean list price --on-disk
bea --offline -f main.bean add price --commodity EUR --amount '1.25 USD' --date 2026-01-03
```

Actual: the listing shows `2026-01-03  EUR  1.10 USD  generated`;
`--on-disk` prints `No prices found.`; the add exits 0 with `Added 1
price`, and the ledger now holds 1.10 and 1.25 for the same day and pair.

Control: the same books without the managed include line: `--on-disk`
lists the price, and the add exits 2: `EUR already has a 2026-01-03 price
of 1.10 USD (at /absolute/books/shared/prices.bean:1); refusing 1.25 USD.
Pass --force to record another quote.` A worker saw the same correct
refusal with the managed include and a sibling (no `..`) include.

Expected: `docs/adrs/ADR018-cli-managed-price-includes.md`: "Entry and
error filenames are mapped back to the originals before anything leaves
the loader … so every diagnostic names the file the customer wrote."
`docs/USAGE.md`: "Duplicate detection and the `--force` conflict rule apply
to prices already authored in the ledger, including its local included
files."

Cause: `cli/src/bea_engine/ledger/write.py:83` builds closure paths with
`Path(p).absolute()`, which keeps the `..` segment;
`cli/src/bea_engine/managed_load.py:346` stages each twin beside that
spelling and keys the map back to originals by it (`:363`). Beancount's
loader normalises include paths, so entries carry the normalised staged
path, which is not in the map and is left unmapped; the staging file is
gone after the load, so the generated test
(`cli/src/bea_engine/ledger/reader.py:116`) cannot read it and answers
"generated".

Fix: normalise closure paths at capture, or key the map by the normalised
staged path. No dependency or API change.

Blast radius: every read through the managed loader on a ledger with a
managed include and a `..` include: `list --on-disk`, the `generated`
field, `add price` guards, BQL `filename`, and all diagnostics.

Dedupe: w5/096 (write-path `..` staging name, no managed include), w5/092
(same symptoms from a multi-file glob), w5/099 (BQL `filename` on managed
ledgers) and w5/145 (guard lost on an absent `--into` file); none covers
`..` plus a managed include on reads.

Acceptance: on the fixture the EUR row is listed as written on disk,
`--on-disk` shows it, and the 1.25 add is refused as in the control. Only
macOS and the checkout were exercised; managed-price behaviour was
simulated offline.

---

**Resolved 2026-10-13** — The behaviour was already cured by the w5/096 fix, which landed after this note was filed: the ledger snapshot in cli/src/bea_engine/ledger/write.py now names every include member by its normalized path, as Beancount's loader does, so the staged-twin map back to the originals no longer misses a file reached through `..`. No test pinned this note's case, so the change here is test-only: cli/tests/test_dotdot_include_staged_reads.py runs real commands against a loopback price feed and asserts that, beside a managed price include, the shared file's price lists as written, appears under `list --on-disk`, is named by a BQL query, and makes `add price` refuse a second quote naming the real file and line, online and offline, with a sibling-include control. The same file covers w5/291 with no managed include: a different quote into an absent `--into` file is refused, the same quote is reported as a duplicate, and `--allow-errors` tolerates the old assertion. With the normalization reverted, 8 of the 16 cases fail (every `..` case) and the 8 controls pass. One deviation from the note: with an empty cache and `--offline` the unavailable source is now a ledger error that stops these commands, so the test loads the feed once from loopback first. Only macOS was exercised. `make check-all` passed. Shipped in `3c2cb479` (`cli`).
