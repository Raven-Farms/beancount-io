# `init --currency X_` (any symbol ending in `_`) passes init's check, then fails with exit 1 "Invalid token: '_'" and leaves an empty directory (incomplete fix of w3/411)

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `101b89e3`, checkout `bea 0.3.1`, macOS 26.5.1. Follows w3/411 (done).
w3/411 widened init's currency check to "every symbol the loader accepts",
using upstream's `CURRENCY_RE`, which allows a trailing `_`. The lexer does not
accept that symbol on an `open` line. No product fix implemented.

```sh
bea --json init xb --currency AB_ --date 2026-08-01
bea --no-input init xc/books.bean --currency X_ --date 2026-08-01
```

Actual: both exit 1, category `validation`, `The change would leave the ledger
invalid; nothing was written.`, details `…/main.bean:6: Invalid token: '_'
Same problem on 3 more lines: 7, 8, 9.` Empty `xb/` and `xc/` directories are
left behind.

Control: `add open -c X_` exits 2 with `'X_' is not one commodity; use capital
letters and digits, optionally with ' . _ - inside…`.

Expected: exit 2 with init's `Invalid operating currency` message before
anything is created.

Cause: `_CURRENCY_SYMBOL` (`cli/src/cli/commands/init.py:53`) ends in
`[A-Z0-9_]`. `tests/test_init_currency_symbols.py` asserts `X_` is valid but
never loads a ledger built with it.

Fix: match the rule `add open` uses (a trailing `_` is not allowed), and add an
init-then-check test for the edge symbols. The leftover directory belongs to
w5/610.

Dedupe: w3/411 (done) explicitly accepted `X_`; w5/610 (open) covers
directories left behind on other failures.

Acceptance: `init --currency X_` exits 2 with nothing created; `F` and `NT.TO`
still work.

The outdated public-`CURRENCY_RE` comparison was replaced by 819 actual loader samples; that regex accepts trailing underscores the lexer rejects. Documentation now states the boundary. An initial six test-only failures used a whitespace-sensitive posting assertion, corrected to compare tokens.
