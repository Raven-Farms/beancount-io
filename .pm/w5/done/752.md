# Help text: `bea import --help` splits the `--csv` example mid-word (`narr` / `ation=Description`) at every width, and 13 sub-command help rows still end in `...` (gap in w5/264)

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `a00da14e3`, checkout `bea 0.3.1`, macOS 26.5.1.
No product fix implemented.

1. **Mid-word split.** `bea import --help` prints `Column mapping
   (date=Date,amount=Amount,narr` and then `ation=Description,...;
   delimiter=';'` on the next line, at any width from 20 to 300 columns.
   Copying the mapping gives a broken `--csv` value. Cause: the 52-character
   token in `cli/src/cli/commands/import_.py:482` is longer than click's
   description column, and click breaks long words.
2. **Truncated rows.** These rows end in `...` at 80 columns and wider,
   because click caps help at 80:
   - `bea list --help`: `transaction` (`--details adds...`)
   - `bea report --help`: `income-statement`, `balance-sheet`, `trial-balance`
   - `bea add --help`: `balance` (`pad from...`), `price` (`ledger-authored...`)
   - `bea engine --help`: `status`, `enable`
   - `bea cloud --help`: `login`, `status`
   - `cloud ledger`: `list` (hunter's run)
   - `bea ingest --help`: `identify`, `extract` (`not bea...`)

   w5/264 fixed only the root help, and its resolution says sub-group rows
   were unchanged.

Expected: copyable tokens are never split, and every help row shows its
whole summary.

Fix: add break points after the commas in the `--csv` help, shorten those
first docstring lines (or reuse the root's row formatter), and extend
`tests/test_root_help_rows_untruncated.py` to sub-groups.

Dedupe: w5/264 (done) is the parent.

Acceptance: `import --help` keeps `narration=Description` whole, and no
sub-group help row ends in `...`.
