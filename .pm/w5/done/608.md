# SIGTERM or SIGHUP during a frontend export (`format -o`, `treeify -o`, `example -o`, `--json query -o`) leaves a hidden `.bea-*.tmp` copy, up to full size, that nothing removes

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-16, HEAD `c210da9b`, checkout `bea 0.3.1`, macOS 26.5.1. Sibling of w3/440.
USAGE: "`-o` replaces its destination only once the whole formatted text is
written: a write that fails part-way … leaves no partial file". w3/440 made
the engine's exports clean up on signals. The frontend's `atomic_write`
relies on `finally`. SIGTERM and SIGHUP have default handlers at that point,
so the `finally` never runs. No product fix implemented.

A 3.4 MB misaligned ledger `mis.bean`. A watcher sends SIGTERM to bea as soon
as a `.bea-*` file appears in the directory:

```sh
python3 onstage.py <dir> <dir> TERM 0 -- format mis.bean -o out.bean
ls -a <dir> | grep '^\.bea-'
```

Actual: bea dies by SIGTERM and leaves `.bea-<hex>.tmp` (a full 3.4 MB copy
for `format -o`; a full 26 MB for a large `treeify -o`). Re-running the command,
or an `add` in the same directory, leaves it. `example -o` and `--json query
-o` behave the same; SIGHUP too.

Control: SIGINT cleans up (exit 130); text-mode `query -o` (engine-written)
cleans up on SIGTERM.

Expected: no staging file survives a stop; an existing destination is kept.

Cause: `atomic_write` (`cli/src/cli/utils.py:303-357`) has no SIGTERM/SIGHUP
handling; `_forwarding_teardown` has restored the default handlers by then.
Import's remembered-settings write (`cli/src/cli/commands/import_.py:437`)
uses the same path.

Fix: install SIGTERM/SIGHUP handlers that raise `SystemExit` around
`atomic_write` (so `finally` runs), or register the candidate for cleanup as
the engine's `stopping.staged` does; let a later write sweep stale
`.bea-*.tmp` files in the destination directory.

Dedupe: w3/440 and w5/014 (done) are engine-side.

Acceptance: the commands above leave no `.bea-*` file after SIGTERM or
SIGHUP. A test pins `format -o`.

---

**Resolved 2026-10-17** — Shipped in `22b58dff` (`cli`).
- `atomic_write` (`cli/src/cli/utils.py`, `_unwinding_on_stop`) turns SIGTERM and SIGHUP into an exception while a copy is staged. It does so only where their disposition is still the default and only on the main thread; the update check's background write is untouched.
- The copy is removed, including one created a moment before its `finally` was armed, and bea then ends by that signal, so the shell sees the same status. An existing destination is kept.
- This covers every frontend `-o` export (`format`, `treeify`, `example`, `--json query`) and the import-memory writes.
- Deviation: the "sweep stale copies on a later write" half was not added. A SIGKILL can still leave a copy beside an export destination, as USAGE already says for uncatchable kills.
- USAGE documents the stop case.
- `tests/test_export_stop_removes_staged_copy.py` holds the frontend at the staged copy's `fsync` (a `sitecustomize` shim) and sends SIGTERM or SIGHUP to `format -o`. It asserts death by the signal, no `.bea-*` file, and a new destination absent or an existing one unchanged. All 4 fail without the fix. `make check-all` passed.
