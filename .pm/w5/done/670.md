# `BEANCOUNT_LOAD_CACHE_FILENAME=main.bean bea query --source main.bean …` deletes the root ledger and exits 0; a cache path inside an include glob writes a pickle into the books (incomplete fix of w5/497, gap in w5/067)

**Major · cli · 15–20m · A1.** Real CLI QA, 2026-10-17, HEAD `93520860`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/497 (done).
USAGE (around line 206): this variable is refused "on every local command that
loads the ledger — list, query, …". Beancount deletes a cache file it cannot
read. `--file` reads guard against that (w5/067, 418, 497), but `query
--source` loads through upstream beanquery's `beancount:` source, and
neither the frontend nor the engine guard runs on that path. A
`BEANCOUNT_LOAD_CACHE_FILENAME` left in a shell profile, or set by a tool,
deletes the ledger. No product fix implemented.

`main.bean`: `include "txns/*.bean"` and `2024-01-01 open Assets:Cash USD`;
`txns/a.bean`: `2024-01-01 open Expenses:Food USD`.

```sh
BEANCOUNT_LOAD_CACHE_FILENAME=main.bean bea query --source main.bean "SELECT 1"
ls main.bean
```

Actual: exit 0, empty stdout; stderr `ERROR:root:Cache file is corrupted: could
not find MARK; recomputing.` and `<load>:0: File "…/main.bean" does not exist`.
**`main.bean` is gone.** With `BEANCOUNT_LOAD_CACHE_FILENAME=txns/q.bean` on a
60k-transaction ledger, `query --source` exits 0 and writes a 10 MB pickle
inside the include glob, breaking every later load. `beancount:main.bean` as
the source behaves the same.

Control: `bea -f main.bean query "SELECT 1"` with the same variable exits 2 with
`… names …/main.bean, a file of the ledger being read. Beancount deletes a
cache file it cannot read, so this would delete the ledger. … Nothing was
changed.`

Expected: the same exit-2 refusal on the `--source` path (and the interactive
`--source` shell), for both a ledger file and an include-glob claim.

Cause: the `--source` branch (`cli/src/cli/commands/query.py:361-390`) never
calls `output.refuse_cache_over_ledger`; the engine's `_native_shell`
(`cli/src/bea_engine/query.py:334`) loads via beanquery, bypassing
`managed_load`'s guard.

Fix: run the frontend guard (member check and include claim) on the
`--source` ledger path, and guard the engine's native-source load too (or
unset the variable for native-source loads after checking it).

Dedupe: searched `BEANCOUNT_LOAD_CACHE_FILENAME` with `--source`; w5/067, 418 and
497 (done) cover `--file` reads.

Acceptance: both commands exit 2 and leave every file in place. Tests pin
them.
