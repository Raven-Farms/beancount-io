# `bea ask` cuts digits and account names in answer tables with `…` at the default 80 columns, including the documented `--print > FILE` save, with exit 0; and `COLUMNS=0` prints nothing at all

**Major · cli · 15–20m · A1.** Real CLI QA, 2026-10-17, HEAD `a00da14e3`, checkout `bea 0.3.1`, macOS 26.5.1. Simulation: a local AI-proxy stub on 127.0.0.1 with a fake token.
`cli/src/cli/ask/render.py:11-19` says every character of an answer is shown
("Nor may text vanish", w1/097). USAGE:1801 offers `bea ask QUESTION --print >
FILE` to save an answer. A financial answer in a Markdown table is common.
No product fix implemented.

The stub answers with this table:

```
| Account | Jan | Feb | Mar |
|---|---|---|---|
| Assets:Investments:Brokerage:Retirement:Roth-IRA:Vanguard-Total-Stock | 123,456,789,012.35 USD | 123,456,790,112.35 USD | 123,456,791,212.35 USD |
| Expenses:Misc | -27.17 USD | -1,027.17 USD | -2,027.17 USD |
```

1. **Truncation.** `bea -f /abs/main.bean ask q --print > out.txt` (with
   `COLUMNS` unset) exits 0 with empty stderr, and `out.txt` holds:

   ```
    Account             Jan                 Feb                Mar
    Assets:Investment…  123,456,789,012.35  123,456,790,112.…  123,456,791,212.35
                        USD                 USD                USD
   ```

   Feb has lost its cents, and the account name is cut. In a 40-column PTY,
   a two-column table shows `123,456,789,012.3…`. At 132 columns the account
   still ends `…Roth-IRA:Vanguard…`, and the session shows the same cuts
   (hunter's runs). Piped answers are also hard-wrapped at 80 columns, so a
   suggested `bea add transaction … --posting "…"` command is split across
   lines.
2. **`COLUMNS=0`.** With `COLUMNS=0`, the same command (with a one-sentence
   answer) exits 0 and writes 0 bytes to stdout and stderr. In the session the
   answer never appears. Every other bea surface treats `COLUMNS=0` as unset.

Control: `COLUMNS=200` prints every digit and the full account.

Expected: an answer table never drops characters (cells fold, or the raw
Markdown table is printed when it cannot fit). Non-terminal output is not
hard-wrapped. `COLUMNS` of 0 or less is ignored.

Cause: Rich's Markdown table adds columns with the default `overflow="ellipsis"`.
bea renders through `answer_markdown` (`cli/src/cli/ask/render.py:24-27`) on a
bare `Console()` (`cli/src/cli/commands/ask.py:108`, `cli/src/cli/ask/repl.py:51`),
which is 80 columns wide off a terminal and takes `COLUMNS=0` literally.

Fix: render table cells with `overflow="fold"` (or fall back to the source
table), use an unbounded width when stdout is not a terminal, and ignore
non-positive `COLUMNS`.

Dedupe: w5/548 (done), w1/097 (done), w3/452 and open w5/739/745 cover other
ask rendering; none covers tables or width.

Acceptance: the stub table prints every digit and the full account in
`--print > FILE` and at 40 columns; `COLUMNS=0` prints the answer. Tests pin
both.

---
**Resolved 2026-10-19** — answer tables fold cells instead of cutting with `…`, piped answers size to their content instead of hard-wrapping, and non-positive `COLUMNS` is ignored, shipped in `edee27ed9` (`cli`)
