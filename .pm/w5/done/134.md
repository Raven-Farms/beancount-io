# On an `auto_accounts` ledger, import blocks every row that posts to an account not yet used

**Minor · cli · 30–45m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A ledger that relies on `beancount.plugins.auto_accounts` has no `open`
directives to write. `bea import` nevertheless refuses rows whose counter
account has never appeared, with exit 4 and a remedy (`bea add open`) the
ledger's own convention does not need, while `bea add transaction` to the
same account succeeds. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
plugin "beancount.plugins.auto_accounts"

2026-01-02 * "Opening balance"
  Assets:Checking  1000.00 USD
  Equity:Opening

2026-08-02 * "Lunch" "elided"
  Expenses:Food  5.00 USD
  Assets:Checking
```

`/absolute/books/s.csv`:

```csv
Date,Payee,Narration,Amount
2026-08-02,Lunch,deli,-5.00
2026-08-03,Shell,gas,-40.00
2026-08-04,Other,x,-1.00
```

`/absolute/books/r.toml`:

```toml
[[rule]]
match = "shell"
account = "Expenses:Fuel"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.
The fixture passes `bea check`.

```sh
bea --file main.bean import s.csv --account Assets:Checking --rules r.toml --apply --duplicates skip
```

Actual: exit 4, ledger byte-identical.

```text
Error: Import needs review; nothing was written. 2 rows are blocked by unopened accounts or currency mismatches; resolve them first.
  Row 2 (blocked): Account 'Expenses:Fuel' is not open. Run: bea add open --account Expenses:Fuel --date 2026-08-03 -c USD.
  Row 3 (blocked): Account 'Expenses:Uncategorized' is not open. Run: bea add open --account Expenses:Uncategorized --date 2026-08-04 -c USD.
```

A first import on such a ledger blocks every unmatched row, because
`Expenses:Uncategorized` has never been used.

Control: on a copy of the same ledger, `bea add transaction --date 2026-08-03
--payee Shell --narration gas --posting 'Assets:Checking -40.00 USD'
--posting 'Expenses:Fuel 40.00 USD'` exits 0 and `bea check` then exits 0. A
worker ran the same import on a ledger with explicit opens and no plugin; it
wrote all three entries.

Expected: the ledger with those rows appended is valid, because the plugin
opens the accounts; `docs/USAGE.md` acknowledges that "`auto_accounts` opens"
are plugin-added directives. The rows should be ready, and `import` should
agree with `add` about what the ledger accepts.

Cause: `cli/src/bea_engine/importing.py:238-247` builds `open_currencies`
from `Open` entries of the pre-append ledger, and `_blocked_reason` (`:678`,
called at `:363`) blocks any account missing from that map before, and
regardless of, `validate_append` (`:398`), which would pass.

Fix: decide "unopened" by validating the candidate, or skip the
unopened-account block when the candidate validates; keep the
currency-restriction check. No dependency or API change.

Blast radius: every CSV and Python-importer import on ledgers that use
`auto_accounts`; preview and apply. A worker saw the same block when a
Python importer returns an `Open` and a transaction to that account in one
batch — worth a second acceptance case.

Dedupe: board search for `auto_accounts` finds w3/done/301 and w3/done/359
(listing plugin opens) and w5/084, none import-related; w3/276 introduced the
blocked status and w5/076 covers the remedy's date.

Acceptance: the import exits 0 and writes rows 2 and 3 (row 1 skipped as a
duplicate), and `bea check` passes; on a ledger without the plugin the same
rows are still blocked. A real-command regression test covers both. Only
macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — Import used to decide "unopened" only from the ledger before the append. In `cli/src/bea_engine/importing.py`, when a row is blocked on a missing account, the open accounts are now re-read from a staged copy of the ledger with the proposal appended, so accounts opened by a plugin such as `auto_accounts`, or by an `open` the importer returns in the same batch, no longer block their rows. Currency restrictions still block, and a ledger without the plugin blocks exactly as before. The real-command test covers the note's CSV case in preview and apply followed by `bea check`, the importer open-plus-transaction batch and a currency-restricted open in the batch (three cases fail with the fix reverted), plus the no-plugin control. `docs/IMPORTING.md` gained a sentence. Only macOS was exercised. `make check-all` passed. Shipped in `e1e2a088` (`cli`).
