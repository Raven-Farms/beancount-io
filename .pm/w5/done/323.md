# `bea --json add balance --pad-from` returns a raw-Beancount `directives` array instead of the `directive` object every other `add` returns, and the balance in it carries an internal `diff_amount` field

**Minor · cli · 15–25m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
When `add balance --pad-from` writes both the pad and the assertion, it
returns `{"written": 2, "directives": [...]}`. That array is serialized
straight from Beancount's namedtuples:

- `meta` comes first.
- The balance carries Beancount's internal `diff_amount: null`.
- The `duplicate` and `source` keys are missing.

Every other branch of the same command, and plain `add balance`, returns
`data.directive` in the model shape that `bea list balance` and
`bea list pad` use. A script reading `data.directive` therefore finds the
key missing exactly when the pad was written. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Equity:Opening
2026-01-02 * "Open"
  Assets:Checking  100.00 USD
  Equity:Opening
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, and a pristine copy for
each command.

```sh
bea --json -f /absolute/books/main.bean add balance --date 2026-03-07 -a Assets:Checking --amount '800 ~ 0.01 USD' --pad-from Equity:Opening
bea --json -f /absolute/books/main.bean add balance --date 2026-03-08 -a Assets:Checking --amount '800 ~ 0.01 USD'
bea --json -f /absolute/books/main.bean list balance
```

Actual: the first command exits 0 with:

```json
"data": {"written": 2, "directives": [
  {"meta": {}, "date": "2026-03-06", "account": "Assets:Checking", "source_account": "Equity:Opening"},
  {"meta": {}, "date": "2026-03-07", "account": "Assets:Checking", "amount": {"number": "800", "currency": "USD"}, "tolerance": "0.01", "diff_amount": null}],
  "warnings": []}
```

Plain `add balance` returns `"directive": {…}, "duplicate": false,
"source": null`. `list balance` shows the same row with no `diff_amount`.
Reproduced in three fresh runs.

Controls:

- When the book already matches, `--pad-from` writes the assertion alone
  and returns the model `directive`.
- `add pad --json` returns `directive` in the `list pad` shape.

Expected: one command returns one shape, built from the reader models.
`docs/USAGE.md` says the directive models "define the exact object fields
for directive listings and bulk input", and w5/104 removed
interpreter-shaped values from directive JSON. The `directives` answer
appears in the engine README but not in USAGE.

Cause: `cli/src/bea_engine/ledger/adding.py:333-334` builds raw `Pad` and
`Balance` namedtuples. The two-directive return at `:414-419` hands them
directly to `protocol.jsonable`. The single-directive branches return
`directive.model_dump(mode="json")`.

Fix: serialize both directives through the same model dump. Pick one
documented key layout and use it in every branch, for example `directive`
for the assertion plus `pad` for the inserted pad, or `directives`
everywhere. State the layout in USAGE's add section. No dependency change.

Blast radius: `add balance --pad-from` under `--json`, which the docs
recommend for opening adjustments. The `ask` write tool consumes the same
engine answer and was not examined.

Dedupe: searched the board (including `done/`) for `diff_amount`,
`"directives"`, `--pad-from` with json, and `"written": 2`.

- w3/224 and w5/299: `--pad-from` hint text.
- w5/224: mentions `diff_amount` only in import duplicate text.

None covers the envelope shape.

Acceptance: on the fixture, the `--pad-from` answer contains no
`diff_amount`. Its balance object equals the `list balance` row and its pad
object equals the `list pad` row. The key layout is the same across the
written-2, already-matches and existing-pad branches. A real-command test
pins all three branches. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-15** — The written-2 branch of `_balance` (`cli/src/bea_engine/ledger/adding.py`) now answers `directive` (the `BalanceDirective` dump) plus `pad` (a `PadDirective` dump), with `duplicate: false` and `source: null`. Every other balance branch carries `"pad": null`, and the frontend's `--pad-from` path (`cli/src/cli/commands/add.py`) defaults `duplicate`/`source` as the plain path does. One key layout (`written`, `directive`, `pad`, `duplicate`, `source`, `warnings`) covers the written-2, already-matches and existing-pad branches. There is no `diff_amount`, and the objects equal the `list balance`/`list pad` rows. USAGE's `--pad-from` paragraph and the engine README state the layout. `cli/tests/test_pad_from_json_shape.py` pins all three branches; all fail with the fix reverted. The `ask` write tool consumes the same answer and was not separately examined. Only macOS was exercised. `make check-all` passed. Shipped in `639f5ebf` (`cli`).
