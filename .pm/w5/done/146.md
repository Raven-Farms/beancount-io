# "Same problem on N more lines" lists bare line numbers that belong to different files

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS (APFS).
When a refused write repeats one problem across several included files, the
collapsed message ends `Same problem on 2 more lines: 1, 1.` The numbers
are lines in other files, and nothing says which. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
include "y/mar.bean"
include "y/apr.bean"
include "y/may.bean"
```

`y/mar.bean`, `y/apr.bean` and `y/may.bean` each hold one transaction,
dated 2024-03-10, 2024-04-10 and 2024-05-10:

```beancount
2024-03-10 * "x"
  Expenses:Food  1 USD
  Assets:Cash
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY. cwd `/absolute/books`.

```sh
bea -f main.bean add close --account Expenses:Food --date 2024-03-01
```

Actual: exit 1 (correct), one detail line: `/absolute/books/y/mar.bean:1:
Invalid reference to inactive account 'Expenses:Food' … Same problem on 2
more lines: 1, 1.` The other two locations are `y/apr.bean:1` and
`y/may.bean:1`. A worker saw `8 more lines: 1, 1, 1, 1, 1, 1, 2, 2`
spanning eight files.

Control: the same three transactions in a single `main.bean` end `Same
problem on 2 more lines: 6, 9.`, which is correct and usable.

Expected: each collapsed occurrence should be locatable; loader diagnostics
elsewhere carry a file path and line.

Cause: `cli/src/bea_engine/ledger/write.py:533-538` (`_collapse_repeats`)
groups records across files and prints only `record.lineno`; the error
record carries no file.

Fix: carry the source file in the record and print `file:line` for
occurrences outside the first message's file, or group per file. No
dependency or API change.

Blast radius: every refused write or import on a split ledger where one
problem repeats across files; text and JSON `details`.

Dedupe: board search for "Same problem on" and "more line" finds
w1/done/118 (duplicate records for one line) and w4/done/058 (unrelated);
neither covers multi-file locations.

Acceptance: the message names `y/apr.bean:1` and `y/may.bean:1`; the
single-file control is unchanged. A real-command regression test covers
three files. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — The loader error record in `cli/src/bea_engine/ledger/write.py` now carries its source file, and `_collapse_repeats` prints an occurrence that sits outside the first message's file as `file:line` (the same absolute path form the message itself uses), while repeats inside the named file stay bare line numbers. The note's refusal therefore ends `Same problem on 2 more lines: …/y/apr.bean:1, …/y/may.bean:1.` in both text and JSON `details`, and the single-file control still ends `7, 10.` style bare numbers. `cli/tests/test_collapsed_repeats_name_their_file.py` runs the real `bea add close` command against a three-file split ledger in JSON and text modes, a mixed case with one repeat in the named file and two elsewhere, and the single-file control; three of its four cases fail with the fix reverted and the control passes either way. Mixed lists interleave bare numbers and `file:line` entries rather than grouping per file. Only macOS was exercised. `make check-all` passed. Shipped in `863d4f1d` (`cli`).
