# What an importer printed is discarded when it then raises, even with `--debug`

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
An importer's `print` output is shown when it succeeds, but if `extract`
raises, everything it printed beforehand is dropped — from stderr, from
`--debug`, and from JSON. That is the moment an importer author most needs
it. Partly an owner call on where to surface it. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Uncategorized USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "Open" "Opening balance"
  Assets:Checking  5000.00 USD
  Equity:Opening
```

`/absolute/books/importers.py`:

```python
import sys
class I:
    name = "noisy"
    def identify(self, f): return True
    def account(self, f): return "Assets:Checking"
    def extract(self, f, existing):
        print("DEBUG row 7 date cell = '31/02/2026'")
        print("WARN: skipping malformed row", file=sys.stderr)
        if str(f).endswith("bad.txt"):
            raise ValueError("day is out of range for month")
        return []
CONFIG = [I()]
```

`bad.txt` and `ok.txt`: one line each.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean import bad.txt
bea --debug -f main.bean import bad.txt
bea -f main.bean import ok.txt
```

Actual: the first two exit 1 with `Error: Importer failed (ValueError): day
is out of range for month.`; neither `DEBUG row 7` nor `WARN: skipping`
appears anywhere, with or without `--debug`.

Control: the third exits 0 and both lines appear on stderr. A worker
confirmed the lines are also absent from `--json --debug` on failure and
present in `data.importer_output` on success.

Expected: `docs/IMPORTING.md` says importer output "is captured in the
preview's `importer_output` field so it does not corrupt JSON". Captured
output should survive the failing path: on stderr in text mode and in the
error envelope in JSON.

Cause: `cli/src/bea_engine/importing.py:209-231` collects output under
`_capturing(logs)`, but the `UsageError`/`LedgerError` raised on failure
never carries `logs.getvalue()`.

Fix: attach the captured text to the error (for example
`error.result.importer_output`) and print it to stderr in text mode. No
dependency change; the JSON error gains one optional field.

Blast radius: every Python importer and child process it runs.

Dedupe: board search for `importer_output` with fail, raise and discard
finds w1/done/061 (prints corrupting the envelope); nothing covers loss on
failure.

Acceptance: the first command still exits 1 and its stderr includes both
printed lines before the error; `--json` carries them in the error
envelope with stdout empty; the success control is unchanged. Only macOS
and the checkout were exercised.

---

**Resolved 2026-10-13** — The engine's import command (`cli/src/bea_engine/importing.py`) now attaches whatever a Python importer printed before it raised to the failure as `result.importer_output`, on the generic "Importer failed", missing-dependency and engine-error paths alike, and `bea import` (`cli/src/cli/commands/import_.py`) prints that text on stderr ahead of the `Error:` line in human mode, while `--json` carries it as `error.result.importer_output` with stdout empty. `cli/docs/IMPORTING.md` and the engine README describe the new field. The regression test `cli/tests/test_import_failed_importer_output.py` runs the real command against a noisy importer that prints to stdout, stderr and from a child process, covering text mode with and without `--debug`, the JSON error, a missing importer dependency, a silent failure that adds no `result`, and the unchanged success control; four of its six cases fail with the fix reverted. One side effect beyond the note: a rejected `--apply`, whose error already carried the preview, now also shows that preview's importer output on stderr in human mode. Only macOS was exercised. `make check-all` passed. Shipped in `d367fec0` (`cli`).
