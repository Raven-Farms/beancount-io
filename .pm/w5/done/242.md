# `bea format --currency-column N` silently ignores `--prefix-width` and `--num-width`

**Minor · cli · 10–20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Owner call: inherited from stock `bean-format`.
With `-c`, the `-w` and `-W` options are accepted, validated, even echoed
back in the `--check` hint, and have no effect. Nothing in help or the
docs says so. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Checking USD
2024-01-01 open Assets:Broker HOOL
2024-01-01 open Expenses:Food USD
2024-01-01 open Equity:Opening USD
2024-01-01 commodity HOOL
2024-01-02 * "Opening"
  Assets:Checking  1000.00 USD
  Equity:Opening
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea format -c 60 main.bean
bea format -c 60 -w 40 -W 20 main.bean
bea format -w 40 main.bean
```

Actual: all exit 0. The first two outputs are byte-identical; the third
differs (so `-w` does work on its own).

Expected: the help says "`-w` Force fixed prefix width", "`-W` Force fixed
numbers width", "`-c` Align currencies to this column", with no stated
interaction. Either honour the widths or refuse or document the
combination.

Cause: `cli/src/bea_engine/ledger/formatting.py:252` passes all three to
the upstream aligner, which takes a separate path when a currency column
is set and never reads the widths; `cli/src/cli/commands/format.py:488-507`
validates each value in isolation.

Fix: exit 2 for `--currency-column` combined with either width, or add
"ignored with `--currency-column`" to the two help strings and the
reference. No dependency change.

Blast radius: `bea format` in every mode.

Dedupe: board search for `currency-column` and `prefix-width` finds
w3/done/331 and 348 (bounds), w2/done/023 (hint dropping flags) and w5/165
(no-break space); none covers the interaction.

Acceptance: the combination is refused with exit 2, or the help for `-w`
and `-W` states that `-c` overrides them. Only macOS and the checkout were
exercised.

---

**Resolved 2026-10-13** — Took the note's documentation branch rather than the exit-2 refusal: `bea format` still accepts `--prefix-width`/`--num-width` beside `--currency-column`, as stock `bean-format` does and as an existing `--check` remedy test already pins, but the interaction is now stated. In `cli/src/cli/commands/format.py` the `-w` and `-W` help strings end "ignored with -c" and `-c` says it "overrides -w and -W"; `cli/docs/USAGE.md` states that a nonzero `--currency-column` makes the two widths have no effect, and `cli/docs/REFERENCE.md` was regenerated. The new `cli/tests/test_format_currency_column_overrides_widths.py` asserts the three help rows, the USAGE sentence, and the behaviour they describe (`-c 60 -w 40 -W 20` equals `-c 60`, while the widths alone and beside `-c 0` do change the layout); four of its five cases fail with the change reverted, the fifth being the behaviour control that held before. The internal `bea-engine format` helper's own help strings were left as they are. Only macOS was exercised. `make check-all` passed. Shipped in `897002c8` (`cli`).
