# A failed `bea price export -o DIR` says "Nothing was written." but leaves a truncated `main.bean` behind, and the retry is then refused as an overwrite

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
`price export` writes each file in place with `write_bytes`. When a write
fails partway, the `except OSError` branch reports only files it had
already finished, so the half-written file is neither removed nor
counted. The user sees "Nothing was written". The leftover then blocks a
plain retry (`pass --force`). If the cut falls inside a number, the
leftover could carry a changed amount. [w5/156](./done/156.md) made
`format -o`, `query -o` and `treeify -o` atomic, but not `price export`.
No product fix implemented.

Use any ledger larger than 512 bytes. Use isolated
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, and closed
stdin. A file-size limit stands in for a full disk.

```sh
( trap "" XFSZ; ulimit -f 1; bea -f /absolute/L/main.bean price export -o /absolute/o/exp )
ls -l /absolute/o/exp
bea -f /absolute/L/main.bean price export -o /absolute/o/exp
bea -f /absolute/o/exp/main.bean check
```

Actual:

- The first command exits 1 with `Cannot export into …/o/exp: writing
  …/o/exp/main.bean failed (File too large). Nothing was written.`
- `o/exp/main.bean` exists at 512 bytes, cut off mid-posting.
- The unlimited retry exits 2 with `… already holds …/main.bean, which the
  export would overwrite … pass --force`.
- `check` on the leftover exits 1 with `Transaction does not balance`.

Reproduced three times by the hunter and once by me.

Control: without the limit, the export writes the whole ledger and exits
0.

Expected: after "Nothing was written", no file remains. Either stage each
file and swap it in, or remove the partial destination. Otherwise the
message must say the file is incomplete.

Cause: `cli/src/bea_engine/managed_load.py:1102-1129` writes `dest`
directly, and its `except OSError` branch counts only completed files.

Fix: write each file through the atomic staging used for `format -o`
(`atomic_write(..., export=True)`), or unlink `dest` on failure. No
dependency change.

Blast radius: `bea price export` on a full disk, a quota or an I/O
error. A truncated ledger copy is left behind under a message saying
nothing was written.

Dedupe: w5/156 and w3/404 (done) made the other `-o` writers atomic. No
note covers `price export`.

Acceptance: under the limit, no `main.bean` (or any partial file) remains
in `o/exp`, and the retry succeeds without `--force`. A test simulates a
failing write.

---

**Resolved 2026-10-15** — `_write_export`
(`cli/src/bea_engine/managed_load.py`) now writes each exported file to a
hidden `.bea-*.tmp` sibling. The sibling gets the source's mode, is
fsynced, and is renamed onto the destination. A destination link is
still followed, as USAGE says, and the sibling is registered for
signal cleanup. A write that fails partway removes the sibling and
leaves the destination as it was. Under the size limit, `price export -o
…/exp` still exits 1 with `… failed (File too large). Nothing was
written.`, and now nothing is there. The plain retry succeeds without
`--force`, and its `main.bean` passes `check`. Files completed before
the failure are still listed in the "already written" message as
before. Pinned by `cli/tests/test_price_export_partial_write.py`, which
uses `RLIMIT_FSIZE` and fails without the fix.
