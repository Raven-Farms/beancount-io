# `check` and the read commands on an included leaf report unknown-account errors with no hint that the file is a leaf of another ledger, and suggest only `--allow-errors`, while writes print the root hint

**Trivial · cli · 15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
Point `--file` at an included file that uses accounts opened in the
root, for example a per-year or per-month file:

- `check` lists `Invalid reference to unknown account` errors.
- Reads (`list`, `balance`, `report`, `query`) refuse with `Ledger has N
  error(s). Pass --allow-errors to report anyway.`

Neither says that the file is included by a nearby root. The only remedy
offered, `--allow-errors`, gives numbers for part of the ledger. A
failing write on the same file prints `X is included by ROOT … Run
against the root`. No product fix implemented.

Use the fixture from [346](./346.md). Its `sub dir/extra.bean` also holds
`2026-01-01 open Expenses:Rent USD` and a 2026-01-05 transaction posting
`Expenses:Rent 40 USD` against `Assets:Cash`, an account opened in the
root. Use the same environment.

```sh
bea -f '/absolute/my books/sub dir/extra.bean' check
bea -f '/absolute/my books/sub dir/extra.bean' balance
bea -f '/absolute/my books/sub dir/extra.bean' list transaction
bea -f '/absolute/my books/sub dir/extra.bean' query 'SELECT count(*)'
```

Actual:

- `check` exits 1 with `extra.bean:3: Invalid reference to unknown
  account 'Assets:Cash'`.
- The three reads exit 1 with `Ledger has 1 error(s). Pass --allow-errors
  to report anyway.` and the same detail.
- No output mentions `main.bean`.

Reproduced by me and twice by the hunter. A glob-included `months/jan.bean`
behaves the same way.

Control: a failing `add` on the same file prints `extra.bean is included
by /absolute/my books/main.bean; … Run against the root …`.

Expected: `docs/USAGE.md` gives a directory passed as the ledger "a hint
to select its root ledger file". A file that a nearby root includes is
the same mistake. It should get the same kind of hint, for example
`extra.bean is included by /absolute/my books/main.bean; run with --file
'/absolute/my books/main.bean'`. It should come before, or instead of,
the `--allow-errors` suggestion.

Cause: the read refusal (`cli/src/bea_engine/query.py:780`,
`cli/src/cli/output.py:830`) and `check` never call
`including_root`/`root_ledger_hints`. Those helpers are used only on the
write path (`cli/src/bea_engine/ledger/write.py:1249`,
`ledger/adding.py:742`).

Fix: when a read or `check` load has errors, append the root hint once,
using the lookup fixed in [347](./347.md), if an includer is found. Keep
the cost bounded as w5/112 and w5/124 require. No dependency change.

Blast radius: `check`, `list`, `balance`, `report *` and `query` run with
`--file` on an included leaf that is invalid on its own, in text and JSON.

Dedupe: searched `.pm/**`, including `done/`, for "included by", "Run
against the root" and `--allow-errors` together with include. Related
notes:

- w3/438, w5/112, w5/124 and 343: hints on the write path only.
- w5/138: directory targets.

None covers reads or `check`.

Acceptance: on the fixture, `check` and each read print the root hint
naming `main.bean`. Exit codes are unchanged. A root ledger with real
errors gets no hint. A real-command test covers `check` and one read.
Only macOS and the checkout were exercised.

---

**Resolved 2026-10-15** — A new `write.root_read_hint(file)` uses `top_root`, the climb from w5/346 factored out, with the wider w5/347 search. For an included file it reads: "X is included by ROOT; on its own it lacks the accounts and options that root provides. Run with --file ROOT to read the whole ledger." It runs only when a load has errors, so clean reads pay nothing. It is appended to the engine's read refusals (`query._gate` for `query`, `report._load` for `report`/`balance`) and to `--json check`'s details. It is also carried as `root_hint` in the `list` answer and in `check`'s documents-only answer, which the frontend shows through `render_ledger_errors(hint=…)` and after a failing native `bean-check`. Exit codes are unchanged, and a root ledger with real errors gets no hint. `cli/tests/test_leaf_read_root_hint.py` covers `check`, `balance`, `list`, `query`, `--json check` and the root control; the 5 hint cases fail with the change reverted. Only macOS was exercised. `make check-all` passed. Shipped in `6140d417` (`cli`).
