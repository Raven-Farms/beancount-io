# Leaf-output protection skips roots with uppercase or mixed-case suffixes: format still overwrites main.BEAN or doubles its included transactions, exit 0 (incomplete fix of w5/651)

**Major · cli · 20–30m · A1.** Real CLI QA, 2026-10-18, HEAD `5767e70f8` (includes the w5/651 fix `9ccdca1f9`), checkout `bea 0.3.1`, macOS 26.5.1. Every destination/suffix combination reproduced twice from pristine synthetic fixtures with isolated config/cache, stdin closed and no TTY. No product fix implemented.

Create `main.BEAN`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Equity:Opening USD
include "txns/*.bean"
```

Create `txns/2026.bean`:

```beancount
2026-01-02 * "Opening"
  Assets:Checking  100 USD
  Equity:Opening
```

From that directory, on separate pristine copies for each output:

```sh
bea --file main.BEAN query "SELECT sum(position) WHERE account = 'Assets:Checking'"
bea format txns/2026.bean -o txns/copy.bean
bea --file main.BEAN query "SELECT sum(position) WHERE account = 'Assets:Checking'"
bea --file main.BEAN check

# On a fresh copy:
bea format txns/2026.bean -o main.BEAN
bea --file main.BEAN check
```

Actual:

- The glob destination exits 0 and creates `txns/copy.bean`. The query changes from 100 USD to 200 USD, and check still exits 0: the same opening transaction is read twice.
- The root destination exits 0 and replaces `main.BEAN` with the leaf's transaction. The operating currency, account opens and include disappear. The following check exits 1 for unknown accounts.
- A root named `main.Beancount` behaves identically for both destinations.

Controls: a root physically named `main.bean` makes both format commands exit 2 and leaves every ledger byte unchanged, as the w5/651 fix intends. All six initial ledgers load cleanly at 100 USD. The recorded before/after hashes include suffixes case-insensitively, so the overwritten uppercase root itself is part of the file evidence.

Expected: both destinations are refused with exit 2 for every supported spelling of a ledger suffix. USAGE's Output destinations contract says a leaf's nearby including root and include globs are protected. Query and check already accept these roots; uppercase suffixes do not make their contents disposable.

Cause: `_output_ledger_members` (`cli/src/cli/output.py:564`) finds candidate roots through `directory.glob("*.bean")` and `glob("*.beancount")`. pathlib's POSIX glob matching is case-sensitive even on the tested case-insensitive APFS volume, so neither root is examined. The protection is then computed from the leaf alone. The same shared helper serves `refuse_ledger_alias` and `refuse_include_claim`; callers include format, query and example directly, and forwarded-output guards for treeify/ingest. Only format's wrong writes were exercised for this new spelling.

Fix: enumerate candidate ledger files with a case-insensitive suffix check while retaining the existing regular-file, size, search-depth and candidate-budget safeguards. Keep the filename as it exists on disk when reporting and reading it. Check both `.bean` and `.beancount` families, including intermediate includers.

Dedupe: whole-board searches for uppercase/mixed-case ledger suffixes, `.BEAN`/`.BEANCOUNT`, and including-root output guards found no open coverage. w5/651 is the completed parent; w5/595 (done) covers case-variant destination/include-directory paths, and w5/459 (done) already treats query output ledger suffixes case-insensitively. This is discovery of the including root's filename, not a request to remove its safety guard.

Acceptance: the commands above refuse before writing for `main.BEAN` and `main.Beancount`, preserving root/leaf hashes and the 100 USD balance. Lowercase roots remain protected and a safe output outside the include tree still succeeds. Add regression coverage for both suffix families through the shared guard.

---

**Resolved 2026-10-20** — `_output_ledger_members` lists each nearby directory once and keeps files whose suffix case-folds to `.bean` or `.beancount` (`.bean` first, as before), under the unchanged 64-candidate budget, size and regular-file checks, keeping on-disk spellings; `main.BEAN`, `main.Beancount` and `main.BeAn` roots are now found, so `format -o` into the include glob or onto the root, and `query -o` onto the root, refuse with exit 2 and change no bytes. `tests/test_output_included_leaf.py` covers the three spellings through the shared guard; lowercase roots and the outside-the-tree output still behave as before.
