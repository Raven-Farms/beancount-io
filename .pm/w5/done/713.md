# The w5/529 code-page check misses Czech, Turkish, Shift-JIS and other exports, which still get "pass --csv encoding=cp1252" and are written as mojibake; a remembered cp1252 skips the check entirely; and Western files with `12m³` or `McDonald´s` are told they are another code page (incomplete fix of w5/529)

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-17, HEAD `8cd20be7`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/529 (done, `2d8610a3`).
w5/529's Expected says the cp1252 advice becomes conditional when no foreign
code page is detected. The fix added a detector that recognizes only Polish,
Cyrillic, Latin-9 and Greek signals, and left the fallback advice
unconditional. No product fix implemented.

`main.bean` opens `Assets:Checking EUR` and `Expenses:Uncategorized`. Each CSV
has the header `Date,Description,Amount`.

   účtu,-4.50` saved as cp1250.
   - `bea --file /abs/main.bean import cz.csv --account Assets:Checking`
     exits 2 with `…is not valid UTF-8 (invalid continuation byte at byte 52);
     it decodes as cp1252 — pass --csv encoding=cp1252.`
   - Following that with `--apply` exits 0 and writes `2026-03-01 !
     "Poplatek za vedení úètu"`.
   - Shift-JIS `東京電力` gets the same advice and would be written as
     `“Œ‹ž“d—Í`. The hunter's Hungarian, Croatian, Romanian, Slovak (cp1250),
     Turkish (cp1254), Lithuanian (cp1257) and Hebrew (cp1255) fixtures got
     the same plain advice.
2. **Remembered encoding.**
   - Import a Western cp1252 `w.csv` (`Café Crème`) with `--csv
     encoding=cp1252 --apply`.
   - A flag-free `import pl.csv --apply` of a Polish cp1250 file with the same
     header then exits 0 and writes `"Wp³ata £ódŸ"`.
   - This is the path for anyone who followed the old advice once. Run

3. **False alarm (introduced by the fix).** `de.csv` is cp1252 with
   `2026-03-01,Wasser 12m³ Stadtwerke,-4.50` and `2026-03-02,McDonald´s
   Köln,-9.00`. It exits 2: `Read as cp1252 it shows '12m³', which looks like
   another code page (Central or Eastern European, Cyrillic or Asian).
   Re-save the export as UTF-8…`. w5/529's acceptance says "a cp1252 file
   still gets the cp1252 hint". `UK£20` and Icelandic `Þýðing` also trigger it
   (hunter's fixtures).

Control: `Café Crème` gets the cp1252 hint; Polish, Russian, Latin-9 `€` and
Greek get the re-save advice.

Expected:
- When the export's code page is uncertain, the advice is conditional
  ("re-save as UTF-8, or pass `encoding=cp1252` only if it is Western
  European").
- A remembered 8-bit encoding is re-checked before it writes.
- Western-only text never triggers the foreign-code-page message.

Cause:
- `_foreign_code_page_sample` (`cli/src/cli/csv_mapper.py:515` and engine
  `cli/src/bea_engine/csv_mapper.py:683`) knows a few letter signals. The
  unconditional advice is at `:571`/`:739`.
- A remembered encoding is re-checked only by `_is_multibyte_utf8`
  (`cli/src/cli/commands/import_.py:421`, used at `:685`).

Fix: word the fallback conditionally (or always), run the code-page check
on a remembered cp1252/latin-1, and loosen the letter-adjacency signals
(`m²`/`m³`, `´` between letters, `£` after letters).

Dedupe: w5/529 (done) is the parent; w5/332 and 281 (done) are earlier
encoding notes.

Acceptance: `cz.csv` and Shift-JIS get conditional advice, the remembered
`pl.csv` run is refused or warned, and `de.csv` gets the cp1252 hint. Tests
pin each.

This is the acceptance's warning policy: a warned apply still uses the remembered decoding and may write mojibake; it does not infer the true encoding or silently replace the saved codec.
