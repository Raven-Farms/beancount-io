# A CSV mixing UTF-8 and cp1252 rows is told "it decodes as cp1252 — pass --csv encoding=cp1252", and following that advice silently writes mojibake (`CafÃ©`) for the UTF-8 rows

**Trivial · cli · 10m · A2.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
The decode check sees invalid UTF-8 and suggests cp1252, because every
byte decodes under cp1252. It does not notice that the same file also
holds valid multi-byte UTF-8 sequences. This happens when an export has
been concatenated or partly re-saved. Following the hint turns `é`
written as UTF-8 into `Ã©`. Mixed files are uncommon, hence A2. No
product fix implemented.

Use any USD ledger with `Assets:Cash` and `Expenses:Uncategorized` open.
Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1,
and closed stdin.

```sh
printf 'Date,Payee,Narration,Amount\n2026-01-07,Caf\xc3\xa9,a,-3.00\n2026-01-08,Caf\xe9,b,-4.00\n' > mix.csv
bea -f /absolute/books/main.bean import mix.csv --csv date=Date,payee=Payee,narration=Narration,amount=Amount --account Assets:Cash
bea -f /absolute/books/main.bean import mix.csv --csv date=Date,payee=Payee,narration=Narration,amount=Amount,encoding=cp1252 --account Assets:Cash
```

Actual:

- The first run exits 2 with `mix.csv is not valid UTF-8 (… byte 67); it
  decodes as cp1252 — pass --csv encoding=cp1252.`
- The second run previews `2 ready`, with `"CafÃ©"` for row 1.

Reproduced twice by the hunter in fresh config directories.

Expected: when the file also has valid multi-byte UTF-8, say that it mixes
encodings, name the first row of each kind, and do not recommend cp1252.

Cause: the cp1252 suggestion in the import decode check
(`cli/src/cli/commands/import_.py`, near `_is_multibyte_utf8` at `:382`).
That helper is used only to re-validate remembered encodings (`:626`).

Fix: before suggesting cp1252, check for valid multi-byte UTF-8
sequences. If any are present, report a mixed file instead. No
dependency change.

Dedupe: w5/281 (remembered cp1252 on a UTF-8 file) and w1/065 (UTF-16
misdiagnosed) cover other cases. Nothing covers mixed files.

Acceptance: on `mix.csv`, the first command names both encodings and the
rows, and does not suggest cp1252. A pure cp1252 file still gets the
cp1252 hint.

---

**Resolved 2026-10-15** — both `_decode_usage_error` twins
(`cli/src/cli/csv_mapper.py`, `cli/src/bea_engine/csv_mapper.py`) now
scan the file line by line (`_mixed_lines`) before suggesting cp1252.
When it holds a valid multi-byte UTF-8 line and a line that is not
UTF-8, the import exits 2 with `mix.csv mixes encodings: line 2 is UTF-8
with accented characters, while line 3 is not UTF-8 (… at byte 67). No
single --csv encoding reads both correctly; re-save the export in one
encoding (UTF-8) and import it again.`, and suggests no cp1252. A pure
cp1252 file still gets the cp1252 hint. Pinned by
`cli/tests/test_csv_mixed_encodings.py`, which fails without the fix.
