# `add open`, `add close` and `add custom --value account:` with a root the ledger does not use get only Beancount's bare `Invalid account name: X`; the w5/154 root message reaches only postings and references

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
[w5/154](./done/154.md) made an account under a root the ledger does not
use, whether renamed roots or a typo, say so and list the roots. That
message is attached only to "Invalid reference to unknown account"
errors. `add open`, `add close` and a custom `account:` value never
produce that error. They fail as Beancount's bare `Invalid account
name`. `bea import` already refuses a foreign root up front, with exit 2
and the root list. No product fix implemented.

Use a ledger with `option "name_assets" "Aktiva"`, plus `name_liabilities
"Passiva"`, `name_equity "Eigenkapital"`, `name_income "Ertrag"` and
`name_expenses "Aufwand"`, opening `Aktiva:Bank` and
`Aufwand:Essen`. Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME,
BEA_NO_UPDATE_NOTIFIER=1, no inherited BEA_FILE/BEA_TOKEN, and closed
stdin.

```sh
bea -f /absolute/books/main.bean add open --account Expenses:X --date 2026-01-01
bea -f /absolute/books/main.bean add close --account Expenses:Essen --date 2026-02-01
bea -f /absolute/books/main.bean add custom --date 2026-01-05 --type budget --value account:Expenses:Essen
bea -f /absolute/books/main.bean add note --date 2026-01-05 -a Expenses:X -m hi
```

Actual:

- The first three exit 1 with `Proposed append (not written): Invalid
  account name: Expenses:X` (or `…:Essen`). The close adds
  `Unopened account … is being closed`.
- The `add note` control prints `Account 'Expenses:X' has root
  'Expenses', which this ledger does not use; its roots are Aktiva,
  Passiva, Eigenkapital, Ertrag, Aufwand (set by the name_* options). Use
  one of those roots.`
- A default-root ledger behaves the same for `add open --account Foo:Bar`.

Reproduced twice by the hunter (open) and once each (close, custom), and
by me once (open, note).

Expected: `parse_account`'s docstring (`cli/src/bea_engine/ledger/text.py:309-312`)
says that with the ledger's roots "the root is checked too, so a caller
can refuse the name instead of suggesting an `add open` that can never
succeed". Every account field of an added directive should get that
check. The result should be exit 2 with the root message, as `import`
already does.

Cause: `_directive` in `cli/src/bea_engine/ledger/adding.py` calls
`parse_account(...)` without `roots` for open (`:164`), close (`:171`),
the custom account value (`:228`), and pad and document. The root check
(`text.py:325-326`) is skipped.

Fix: pass `ledger_roots(options)` to every `parse_account` call in
`_directive`. No dependency change.

Blast radius: `add open`, `add close`, `add custom`, `add pad` and `add
document` with a foreign root, which is common on renamed-root ledgers
when users or agents type English roots.

Dedupe: w5/154 (done) covers postings and references only. w5/080 (done)
made custom values accept renamed roots, w1/157 is import only, and 394
covers the bare close wording in general. None covers foreign roots on
these directives.

Acceptance: each command above exits 2 with the root message, and the
ledger is unchanged. A valid renamed-root open still writes. A test
covers open and custom.

---

**Resolved 2026-10-15** — `answer` (`cli/src/bea_engine/ledger/adding.py`)
now reads the root file's five roots as text, without loading the ledger
(`root_names_of` in `cli/src/bea_engine/ledger/text.py`, the last
`option "name_*"` winning). For a write to the root ledger it passes them
to every account `_simple` parses: `open`, `close`, `pad` (both
accounts), `note`, `document` and custom `account:` values. On the
fixture, `add open --account Expenses:X`, `add close --account
Expenses:Essen` and `add custom … --value account:Expenses:Essen` exit 2
with w5/154's `Account '…' has root 'Expenses', which this ledger does
not use; its roots are Aktiva, Passiva, Eigenkapital, Ertrag, Aufwand
(set by the name_* options). Use one of those roots.`, and nothing is
written. `add note` gives the same message, now at exit 2. A
renamed-root `open` still writes. A write `--into` an include is left to
the load, because Beancount applies `name_*` per file (w5/462). Pinned
by `cli/tests/test_add_foreign_root_directives.py`, which fails without
the fix.
