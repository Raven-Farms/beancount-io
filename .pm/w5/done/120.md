# An unreadable included file fails every command with a raw Python exception, and `bea check` prints a traceback

**Minor · cli · 30–40m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`),
checkout `bea 0.3.1`, macOS.
When the root ledger is unreadable, bea exits 2 with a sentence naming the
path. When an *included* file is unreadable, every read and write exits 1
"validation" with `PermissionError: [Errno 13] …`, `--allow-errors` makes
no difference, and plain `bea check` dumps a multi-frame Python traceback.
No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
2026-01-01 open Assets:Checking USD
include "sub/apr.bean"
```

and `/absolute/books/sub/apr.bean` containing
`2026-04-01 note Assets:Checking "x"`, then `chmod 000` the include.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY.

```sh
bea -f /absolute/books/main.bean list note
bea --json -f /absolute/books/main.bean balance --allow-errors
bea -f /absolute/books/main.bean check
```

Actual: `list note` exits 1 with `Error: PermissionError: [Errno 13]
Permission denied: '/absolute/books/sub/apr.bean' Pass --debug before the
command for a traceback.` `balance` exits 1 with the same text under
`"category": "validation"`. `check` exits 1 with a Python traceback from
`bean-check`. A worker saw the same from `query`, the reports, every
`list` type, `add note` and `price status`, and `IsADirectoryError` /
`FileNotFoundError` for an include that is a directory or a dangling
symlink.

Control: with the include readable and the root `chmod 000`,
`list note` exits 2 with `Path '/absolute/books/main.bean' is not
readable.` A worker confirmed a missing include gives the clean
`File glob … does not match any files`, which `--allow-errors` tolerates,
and that `format -i` says `Could not read …/sub/apr.bean: Permission
denied.`

Expected: `docs/USAGE.md` says "An unreadable ledger exits 2, naming the
path and the source that selected it", and w3/417 set that standard for the
root. An include is part of the ledger: one line naming the include and the
file that includes it, the permission exit code, no exception class, and no
traceback from `check`.

Cause: `cli/src/bea_engine/ledger/write.py:78-79`
(`LedgerSnapshot.capture`) stats and reads every closure member with no
`OSError` handling, so the exception reaches the generic handler at
`cli/src/bea_engine/protocol.py:114`. Native `bean-check` is started
without a readability check on the closure
(`cli/src/cli/commands/check.py:65`).

Fix: catch `OSError` in `capture` and raise a named error ("Included
file X, from Y, is not readable"), or pre-check the closure in the frontend
as is done for the root; either should also cover text `check`. No
dependency or API change.

Blast radius: every caller of `managed_load.load_file` — all reads and all
writes — plus native `check`.

Dedupe: board search for unreadable includes and these exception names finds
w3/417 (root only), w5/106 (the interactive `.reload`), w1/073 (read-only
include directory on writes), w3/362 (`format` and broken symlinks) and
w5/117 (missing document on export); none covers an unreadable include on
ordinary commands.

Acceptance: the three commands exit with the permission code and a single
line naming `sub/apr.bean` and `main.bean`, in text and JSON, with no
`Error:` class name and no `Traceback`; a directory or dangling symlink
in the include's place is reported as clearly. Only macOS and the checkout
were exercised.

---

**Resolved 2026-10-13** — The engine's include-graph snapshot (`LedgerSnapshot.capture` in `cli/src/bea_engine/ledger/write.py`) now turns an unreadable include into a usage error naming the include and the file that includes it, so every read and write exits 2 with one line in text and JSON and no exception name. Text `bea check` detects such a closure in the frontend and asks the helper instead of native bean-check, so there is no traceback. A directory or a broken symlink in the include's place is reported the same way with its own reason. `docs/USAGE.md` states the contract; the regression test covers the three shapes across list, balance, check, query and add (all 30 cases fail with the fix reverted) plus readable, missing-include and unreadable-root controls. The exit code is 2, matching the unreadable-root rule the docs state, not 3. `make check-all` passed. Only macOS was exercised. Shipped in `929f39c8` (`cli`).
