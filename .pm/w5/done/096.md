# A write into a file reached through a `..` include names a nonexistent staging file and `--allow-errors` refuses it

**Major · cli · 30–45m · A1.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, macOS. When the destination of a write is
included through a path containing `..` — a shared file beside a per-year
root — validation messages name a hidden `.bea-*.tmp` file that no longer
exists, and an error already in that file is counted as newly introduced, so
`--allow-errors` cannot write there. No product fix implemented.

Create disposable `/absolute/books/2026/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Food
2026-01-01 open Equity:Opening
include "../shared/tx.bean"
```

and `/absolute/books/shared/tx.bean`:

```beancount
2026-01-02 * "Opening"
  Assets:Checking  1000.00 USD
  Equity:Opening
2026-01-10 balance Assets:Checking  5.00 USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY.

```sh
bea -f /absolute/books/2026/main.bean add transaction Lunch --date 2026-02-01 -p "Expenses:Food 5 USD" -p "Assets:Checking" --into ../shared/tx.bean --allow-errors
```

Actual: exit 1, files unchanged, no staging file left:

```text
Error: The change would introduce 1 new ledger error(s); nothing was written.
  /absolute/books/shared/.bea-<hex>.tmp:4: Balance failed for 'Assets:Checking': expected 5.00 USD != accumulated 1000.00 USD (995.00 too much)
```

The "new" error is the assertion already at `shared/tx.bean:4`. Without
`--allow-errors`, a genuinely bad write is refused correctly but also names
the `.tmp` path and loses the `Proposed append (not written)` label.
Repeated twice.

Controls: the same command without `--into` (writing the root) exits 0 and
warns naming `shared/tx.bean:4`. The same layout with `include
"shared/tx.bean"` and `--into shared/tx.bean` exits 0 under
`--allow-errors`.

Expected: `docs/USAGE.md` Adding directives — every add command and
`import` "accepts `--allow-errors` for a semantic error already in the
books". Messages name the user's files, never a staging copy.

Cause: `cli/src/bea_engine/ledger/write.py:82` keys the snapshot by
`Path(p).absolute()`, which keeps `..`; staging (`:182`) builds the copy
at `path.parent/.bea-*.tmp`, also with `..`. Beancount's loader normalizes
include names with `normpath`, so errors come back under the normalized
staging path and every lookup that should map it to the original misses —
the display mapping, the before/after error key (so the error reads as new)
and the assertion hint.

Fix: normalize snapshot and staged-path keys the way the loader does
(`normpath` of the absolute path, without resolving symlinks), so a
`..`-reached destination behaves exactly like the control. No dependency or
API change.

Blast radius: every writer that validates a candidate — all `add` types,
`add transactions`, `import --apply` and `ask` writes — when the
destination or a file that includes it is reached through `..`. Reads and
output guards on the same fixture were correct. The fault only refuses and
misnames; no wrong write was accepted.

Dedupe: board search for staging paths in messages, `..` includes and
`normpath` finds w1/135 (staged paths embedded in message text), w5/079 and
w5/092 (glob line shifts) and w4/171 (`price export` with `..`); none
covers staged-path normalization.

Acceptance: the fixture command exits 0 and warns at `shared/tx.bean:4`; a
bad write there is refused naming `shared/tx.bean` and the proposed append;
import and bulk row errors name real paths. Only macOS and the checkout were
exercised.

---

**Resolved 2026-10-12** — The write snapshot names each included file the way Beancount's loader does — the `normpath` of its absolute path, links unresolved — so a destination reached through `..` maps back to the user's file like any other. On the fixture the add exits 0 under `--allow-errors` and warns at `shared/tx.bean:4`; a bad write there is refused naming `shared/tx.bean` and the proposed append. Capture and the pre-commit change check share one helper, since naming them differently made every such write report "The included files changed". Shipped in `f6fdb889` (`cli`).

Real-command regression tests run each case on the `..` layout and on a plain-include control: an add over an existing error under `--allow-errors`, a bad add with and without the flag, a bulk row error, and an import applied over the existing error, each asserting no staging name or `/../` path appears and no staging file is left. Five fail on the `..` layout with the fix reverted; the plain-include controls pass either way. `make check-all` passed. Only macOS was exercised.
