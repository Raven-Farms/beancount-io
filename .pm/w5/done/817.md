# A path component longer than 255 bytes given to `-f`, `-o` (query, format, example, price export) or `--into` exits 1 with a raw `[Errno 63] File name too long` (`--into` and `price export` prefix `OSError:`) instead of a usage error naming the flag (gap in w5/410)

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `e68430c47`, checkout `bea 0.3.1`, macOS 26.5.1.
The `check_output_destination` docstring promises "usage errors naming the
flag … never a downstream errno", and w5/410's resolution says there is no
`OSError:` or `Errno` text. No product fix implemented.

With `Q256` = 256 `Q` characters, and existing parent directories:

```sh
bea -f /abs/main.bean query "SELECT date" -o /abs/Q256
bea -f /abs/main.bean add note -a Assets:Bank -m x --date 2020-03-01 --into inc/Q256
bea -f /abs/LN/Q256 check
```

Actual: each exits 1. The first and third print `Error: [Errno 63] File name too
long: '…'`; the `--into` one prints `Error: OSError: [Errno 63] File name too
long: …`. `example -o`, `format -o` and `price export -o` behave the same
(hunter's runs). Nothing is written.

Control: `-f /abs/nonexist/zz.bean` and `-o /abs/nodir/q.csv` exit 2 with bea's
own messages. 255-byte and 755-byte multibyte names work.

Expected: exit 2 naming the flag and the over-long component.

Cause: on Python 3.12+, `Path.exists()`/`is_symlink()` raise on
ENAMETOOLONG. The unguarded calls are in `cli/src/cli/context.py` (around
`:148`), `cli/src/cli/output.py` (`check_output_destination`), `example.py`,
`cli/src/bea_engine/ledger/write.py` (`destination`), and `price export`
planning.

Fix: catch `OSError` at those checks and raise a usage error naming the flag.

Dedupe: w5/795 (open) covers `bea init` (with its addendum); w5/770 covers
doctor's scratch name.

Acceptance: each command exits 2 naming the flag.

---

**Resolved 2026-10-20** — a new `cli.paths.refuse_too_long_name` looks the path up with `os.lstat` and turns ENAMETOOLONG into a usage error. It runs for `-f`/`$BEA_FILE` (`Ledger path (from --file) … has a name too long for the filesystem; choose a shorter one.`), at the top of `check_output_destination` and `guard_output_destination` (`query`, `format`, `treeify`, `ingest extract -o`), for `example -o`, and for `price export -o`; the engine's `--into` destination does the same check (`--into inc/QQQ….bean has a name too long …`). Each exits 2 with no `Errno`/`OSError` text and writes nothing; a 255-byte name still writes. USAGE's output-destination section says so. `tests/test_too_long_path_names_the_flag.py` covers all eight flags plus the 255-byte control (the eight fail at HEAD). Gate note: gated as one stack with w5/819 and 818 (one `make check-all`, 9758 passed; each item shipped as its own commit); its only failures were the known load-induced managed-price timeouts, which pass in isolation. Shipped in `44688fc46` (`cli`)
