# Every read of a ledger with a local plugin creates `__pycache__/<plugin>.cpython-312.pyc` beside the ledger, though USAGE says no read adds a file beside a ledger

**Trivial · cli · 5–10m · A1.** Real CLI QA, 2026-10-16, HEAD `87ad7af8`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE: "no read — list, query, balance, report, check, doctor — adds a file
beside a ledger". The engine and native children run without `-B` or
`PYTHONDONTWRITEBYTECODE`, so importing a plugin module next to the ledger
writes Python bytecode there. That is a stray directory in a git-tracked
books folder. Upstream `bean-check` does the same, so the alternative is to
narrow the USAGE sentence. No product fix implemented.

`main.bean`: `option "insert_pythonpath" "TRUE"`, `plugin "myplug"`, an open;
`myplug.py` beside it: `__plugins__ = ["p"]` / `def p(e, o): return e, []`.

```sh
bea --file /abs/main.bean check     # also list, balance, report, query
ls /abs/__pycache__
```

Actual: exit 0, and `__pycache__/myplug.cpython-312.pyc` (0644) appears beside
the ledger, even when `myplug.py` is a symlink to a module elsewhere.

Expected: no file beside the ledger after a read.

Cause: the engine is started as `python -P -m bea_engine`
(`cli/src/cli/engine/launch.py:707`) without `-B`; native children likewise.

Fix: pass `-B` (or set `PYTHONDONTWRITEBYTECODE=1`) for the engine and native
children, or narrow the USAGE sentence to bea's own files.

Dedupe: searched `pycache`, `bytecode`; w5/094 (done) concerns export.

Acceptance: a read leaves no `__pycache__` beside the ledger. A test pins it.

---

**Resolved 2026-10-18** — Shipped in `3bcdaee26` (`cli`). Helper and native child environments set `PYTHONDONTWRITEBYTECODE=1`, so importing a local ledger plugin does not create or update Python bytecode beside the books. Existing plugins still execute; no existing user cache is removed. Sixteen command regressions cover local and symlinked plugin modules across text/JSON/native-option check, list, query, balance, report and doctor, verify absence of bytecode in both source locations, and verify plugin-generated events still load. All sixteen fail with the production fix reverted. Ninety-one focused tests and `make check-all` passed (7,379 tests, 2 skipped).
