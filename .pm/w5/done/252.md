# A write whose engine dies on a signal still reports the raw `(exit -11)` instead of naming the signal

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Fix with [251](./251.md).
Message only: the exit code (4, outcome unknown) and the untouched ledger
are correct. w5/done/010 promised that the helper path "names the signal
too, replacing the raw `exit -11`"; the read path does, the write path
does not. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "EUR"
2026-01-01 open Assets:Cash EUR
2026-01-01 open Expenses:X EUR
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea --file main.bean add transaction dz --date 2026-02-01 -p "Expenses:X 100/(2-2) EUR" -p "Assets:Cash"
```

Actual: exit 4, ledger byte-identical:

```text
Error: The Beancount engine did not answer 'bea-engine add --file /absolute/books/main.bean --type transaction --request -' (exit -11); the outcome is unknown. Inspect the file before retrying.
```

Control: a read on a ledger containing the same expression, `bea --file
dz.bean list transaction`, exits 1 with `The Beancount engine was killed by
SIGSEGV answering 'bea-engine list …' and produced no result.`

Expected: the same wording for a write: keep exit 4 and "the outcome is
unknown", but name the signal and add the hint. A writer killed from
outside (out of memory, a supervisor) would presumably print `(exit -9)`
the same way; not tested.

Cause: `cli/src/cli/engine/launch.py:455-463`: in `_parse`, the write
branch raises its conflict error with the raw return code before control
reaches the signal-naming branch (`:464-476`).

Fix: when the return code is negative on a write, keep the conflict error
but name the signal and append the signal hint. No dependency or API
change.

Blast radius: every writing helper call: `add`, `add transactions`,
`import --apply`, `format -i`.

Dedupe: board search for `exit -11`, `exit -9` and "outcome is unknown"
finds w5/done/010 and w5/done/057 (which fixed literal zero divisors, not
computed ones); no open item.

Acceptance: the command exits 4 with a message naming SIGSEGV and no
`(exit -11)`; the ledger is unchanged. Only macOS and the checkout were
exercised.

---

**Resolved 2026-10-13** — The write branch of `_parse` in `cli/src/cli/engine/launch.py` raised its "outcome is unknown" conflict with the raw return code before reaching the signal-naming code, so a writer killed by a signal printed `(exit -11)`. It now names the signal for a write too ("was killed by SIGSEGV answering 'bea-engine add ...'; the outcome is unknown. Inspect the file before retrying.") and appends the same signal hint the read path gives, while keeping exit 4, the `conflict` category and the untouched ledger; a writer that exits nonzero without a signal still reports its exit code. `tests/test_write_signal_death_names_signal.py` covers the note's `bea add transaction` command with a computed zero divisor in text and `--json` form, a stub writer killed by SIGKILL (named, with the outside-kill hint rather than the zero-divisor one), and controls for an ordinary nonzero writer exit and a signal-killed reader; three of its five cases fail with the fix reverted. The change sits in the shared helper launcher, so it covers every write that goes through `helper_json`; `format -i` and `import --apply` were not exercised separately. Only macOS was exercised. `make check-all` passed. Shipped in `cafa2457` (`cli`).
