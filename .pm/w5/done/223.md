# A Python importer whose `account()` returns a parent account is refused outright: "has no posting to its source account"

**Minor · cli · 45–90m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Owner call on scope.
A brokerage importer written the usual Beangulp way returns one root from
`account()` (`Assets:Broker`) and posts to sub-accounts (`Assets:Broker:Cash`,
`Assets:Broker:HOOL`). `bea import` refuses the whole batch because no
posting names the root exactly. The error gives no remedy, and the docs do
not state the rule. Nothing is written. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"

2026-01-01 open Assets:Checking USD
2026-01-01 open Assets:Broker:Cash USD
2026-01-01 open Assets:Broker:HOOL HOOL
2026-01-01 open Income:Broker:Dividends USD
2026-01-01 open Equity:Opening

2026-01-02 * "Opening balance"
  Assets:Broker:Cash  5000.00 USD
  Equity:Opening
```

`/absolute/books/imp.py`:

```python
import datetime
from decimal import Decimal as D
import beangulp
from beancount.core import data
from beancount.core.amount import Amount
from beancount.core.position import Cost

class Broker(beangulp.Importer):
    def __init__(self, root): self.root = root
    def identify(self, filepath): return filepath.endswith(".txt")
    def account(self, filepath): return self.root
    def extract(self, filepath, existing):
        return [
            data.Transaction(data.new_metadata(filepath, 1), datetime.date(2026, 1, 5), "*", "Broker", "Buy 10 HOOL", frozenset(), frozenset(), [
                data.Posting(f"{self.root}:HOOL", Amount(D("10"), "HOOL"), Cost(D("100.00"), "USD", datetime.date(2026, 1, 5), None), None, None, None),
                data.Posting(f"{self.root}:Cash", Amount(D("-1000.00"), "USD"), None, None, None, None)]),
            data.Transaction(data.new_metadata(filepath, 2), datetime.date(2026, 1, 20), "*", "Broker", "Dividend HOOL", frozenset(), frozenset(), [
                data.Posting(f"{self.root}:Cash", Amount(D("12.50"), "USD"), None, None, None, None),
                data.Posting("Income:Broker:Dividends", Amount(D("-12.50"), "USD"), None, None, None, None)]),
        ]

CONFIG = [Broker("Assets:Broker")]
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.
`/absolute/books/stmt.txt` holds the single line `statement`.

```sh
bea -f main.bean import stmt.txt --config imp.py
bea -f main.bean import stmt.txt --config imp.py --apply
```

Actual: both exit 1, ledger unchanged:

```text
Error: Importer row 1 has no posting to its source account Assets:Broker.
```

Control: appending `Broker.account = lambda self, filepath:
"Assets:Broker:Cash"` to `imp.py` makes `--apply` exit 0, write both rows,
and pass stock `bean-check`. A worker saw the re-import then report two
exact duplicates.

Expected: `docs/IMPORTING.md` says import "calls configured importers using
the modern Beangulp interface" and asks only for "explicit amounts on
source-account postings". Beangulp defines `account()` as the account used
to file the document, so returning a root is conforming. Either postings
under the root count as source postings, or the docs state that `account()`
must be the exact posting account and the error says so.

Cause: `cli/src/bea_engine/importing.py:271-272` requires
`posting.account == account` exactly and raises for the whole batch; the
same exact match scopes existing-entry identities (`:248`) and row hashing
(`:814`).

Fix: treat `account()` as a prefix (equal, or starts with `account + ":"`)
at those sites; or keep the rule, document it, and make the error name the
accounts the row does post to and what `account()` should return. No
dependency change.

Blast radius: importers for brokerages and multi-currency accounts that
follow the filing-root pattern. Even with the workaround, a row that does
not touch the one chosen account (a share transfer, a reinvested dividend)
meets the same guard.

Dedupe: board search for "has no posting", "source account", "filing" and
sub-account finds no importer note; w1/157 and w1/117 are unrelated
account-root items.

Acceptance: the fixture previews and applies both rows and a re-import
reports two exact duplicates; or the documented rule and an error with a
remedy exist. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — `cli/src/bea_engine/importing.py` now treats an importer's `account()` as the source account or a parent of it: a row's source postings are the ones to that exact account when it has any, otherwise every posting under it, and the same rule scopes existing-entry identities and row hashing. Rows with an exact source posting keep the source amounts and generated ids they always had. A row that posts neither to the account nor under it is still refused, and the error now lists the accounts the row posts to and says what `account()` should return; `cli/docs/IMPORTING.md` states the rule. `cli/tests/test_import_filing_root_account.py` runs the note's brokerage fixture through preview, apply, `bea check` and a re-import that reports two exact duplicates, plus the exact-account control and the refusal for an unrelated account and for a name that is only a string prefix; three of its four cases fail with the fix reverted. Both of the note's acceptance alternatives hold. Only macOS was exercised. `make check-all` passed. Shipped in `99c8145b` (`cli`).
