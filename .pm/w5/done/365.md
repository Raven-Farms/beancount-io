# A `--time` filter that starts partway through an interval keeps the empty leading fragment as a full quiet period (`-t 2026-03 -i weekly` opens with a one-day "2026-03-01" week of 0); w3/375 drops only the trailing fragment

**Trivial · cli · 15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
[w3/375](../w3/done/375.md) and [w5/086](./done/086.md) made flow series
drop an empty trailing fragment when `--time` ends partway through an
interval. A period that starts partway through an interval has the same
problem at the other end, and that fragment is still shown as a whole
quiet period. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
2026-01-01 open Income:Salary USD
2026-02-27 * "feb"
  Expenses:Food 5 USD
  Assets:Cash
2026-03-05 * "groceries"
  Expenses:Food 40 USD
  Assets:Cash
2026-03-20 * "pay"
  Assets:Cash 1000 USD
  Income:Salary
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, and closed stdin.

```sh
bea -f /absolute/books/main.bean report income-statement -t 2026-03 -i weekly
bea --json -f /absolute/books/main.bean report income-statement -t 2026-03 -i weekly
```

Actual: exit 0. The weekly breakdown starts with `2026-03-01  0 USD  0
USD  0 USD`. 2026-03-01 is a Sunday, so that "week" is one day long and
empty. The JSON has the same first period. The trailing Mon–Tue fragment
is correctly dropped, so the rows end at 2026-03-29.

The hunter saw the same leading row with other intervals:

- `-i monthly -t "2020-01-31 - 2020-03-31"` adds `2020-01-31`.
- `-i yearly -t "2019-12-31 - 2020-12-31"` adds a one-day year,
  `2019-12-31`.
- `-i quarterly -t "2020-09-30 - 2020-12-31"` adds `2020-09-30`.

Reproduced by the hunter in two fresh copies and on a second fixture,
and once by me.

Control: `-t "2026-03-02 - 2026-03-31" -i weekly` starts at `2026-03-08`.
A leading fragment that holds entries keeps its row, with the correct
total.

Expected: `docs/USAGE.md` says flow series drop an empty fragment "so a
clipped boundary does not read as one more quiet week". The text
describes only the ending boundary, but the reason applies equally to a
clipped start. Balance series keep every bucket, as documented.

Cause: `_flow_ranges` (`cli/src/fava/modules/chart.py:35-66`) examines
only `ranges[-1]` (`:57`) and returns `ranges[:-1]` (`:66`). It never
checks `ranges[0]`. This is a Beancount.io addition to the vendored Fava
code (`a721703e`, `51c748ec`).

Fix: apply the same rule to the first range. Keep it only if it is a
whole interval, holds an entry, or is the only range. Update the USAGE
paragraph to say "first or last bucket". No dependency change.

Blast radius: `report income-statement -i …` and the overview's income
and expense series whenever `--time` starts partway through an interval,
in text and JSON.

Dedupe: searched `.pm/**`, including `done/`, for fragment, leading and
"first bucket". w3/375 and w5/086 cover the trailing fragment, w3/384
covers quarterly `get_prev`, and w6/005 covers another surface. None
covers a leading fragment.

Acceptance: on the fixture, the weekly series starts at `2026-03-08`. The
monthly, yearly and quarterly cases lose their empty leading row. A
leading fragment with entries, and a single-range filter, still show.
Balance series are unchanged. A test pins both ends.

**Resolved.** `_flow_ranges` (`src/fava/modules/chart.py`) now uses one `quiet_fragment` test for both ends. A range counts as a quiet fragment when it is not a whole interval and no declared entry falls in it. The trailing range is dropped first, as before. The leading range is then dropped too, unless it is the only range left. `docs/USAGE.md` and the `interval_totals` docstring now describe both ends.

`tests/test_report_leading_fragment.py` uses the note's fixture:

- the weekly series starts at `2026-03-08`;
- the monthly (`2026-01-31 - 2026-03-31`), yearly (`2025-12-31 - 2026-12-31`) and quarterly (`2025-09-30 - 2026-03-31`) series lose their empty leading row;
- a leading fragment holding the 2026-02-27 lunch keeps its 5 USD row;
- a two-fragment filter keeps one row;
- the balance-sheet series still starts at `2026-03-01`.

With the fix stashed, the four series cases fail. The existing trailing-fragment, quarterly and clamp tests still pass.
