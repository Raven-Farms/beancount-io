# Ctrl-C during `bea check` prints `Aborted!`, though the docs say an interrupt exits 130 without a message

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Cosmetic.
On a ledger large enough to interrupt, Ctrl-C during plain `bea check`
exits 130 but the terminal shows `Aborted!`, printed by the forwarded
`bean-check` child. Commands on the helper path are silent. No product fix
implemented.

Fixture: `/absolute/books/main.bean` generated with `bea example --seed 3
--date-begin 2000-01-01 --date-end 2026-01-01 -o main.bean` (59,064
lines).

Run on a real PTY with isolated BEA_CONFIG_DIR/XDG_CACHE_HOME,
BEA_NO_UPDATE_NOTIFIER=1, no inherited BEA_FILE/BEA_TOKEN, the load cache
disabled, cwd `/absolute/books`. Start `bea check` and send Ctrl-C after
0.3 s (and again after 0.5 s).

Actual: exit 130; the terminal shows `^C` then `Aborted!` at both delays.

Control: `bea query "SELECT account LIMIT 1"` interrupted at 0.5 s ends on
the signal with nothing after `^C`. A worker saw `doctor lex` print
`Aborted!` too, and `doctor roundtrip`, `example` and the `init` prompt
stay silent.

Expected: `docs/USAGE.md`: "`Ctrl-C` still exits 130 and a closed
downstream pipe still exits 141, both without a message."

Cause: `cli/src/cli/commands/check.py:64` and `doctor.py:185/207` call
`run_native`, which runs the child with inherited stderr
(`cli/src/cli/engine/launch.py:565`); the child is a Click program and
prints Click's `Aborted!` when the terminal's SIGINT reaches it.

Fix: an interrupt on a forwarded command exits 130 with nothing on stderr
from either process (suppress or filter the child's abort line). No
dependency change.

Blast radius: `check` in text mode, forwarded `doctor` operations,
probably `query --source`.

Dedupe: board search for `Aborted!` and `KeyboardInterrupt` finds
w3/done/388 (the prompt case, fixed; its table recorded `check` as
silent), w5/233 (shell load) and w5/208 (SIGTERM orphan).

Acceptance: Ctrl-C at any point during `bea check` on the fixture exits
130 with no text after `^C`. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — `run_native` in `cli/src/cli/engine/launch.py` now starts the forwarded upstream program (`bean-check`, `bean-doctor`, `bean-price`) with SIGINT blocked, so the Click child no longer answers the terminal's Ctrl-C with `Aborted!`; the frontend alone hears the interrupt, kills the child and exits 130 with nothing printed, and a Ctrl-C pressed while the child is being started is recorded and delivered once the child can be stopped rather than lost. The helper path (`run_engine_argv`) and ingest scripts are unchanged and still hear Ctrl-C themselves. `tests/test_native_interrupt_is_silent.py` interrupts `bea check`, `bea check --verbose` and `bea doctor context` on a real PTY while a plugin holds the upstream program inside its load, asserting exit 130, no text after `^C` and no surviving child, with controls that an uninterrupted check still passes upstream's streams and status through, that only upstream programs are started deaf, and that the frontend's own interrupt still ends the child; four of its six cases fail with the fix reverted. One deviation: a SIGINT sent to the upstream child alone, not through the terminal, is now ignored by it, so the stub in `tests/test_engine_signal_death.py` unblocks the signal before dying of it. `query --source` already ran on the helper path and was silent. Only macOS was exercised. `make check-all` passed. Shipped in `802003a4` (`cli`).
