# An explicit `--pad-date` before the account's open now gets "Date the balance after the open, for example --date 2024-06-02", which fails the same way when followed (regression from w5/513)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `b8d871d0`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/513 (done, `aa5125ec`).
w5/513 gave the derived-pad-date case a useful hint: the default pad date is
the day before the balance, so date the balance after the open. The branch
also fires when the user typed `--pad-date` explicitly. Moving the balance
date cannot help then, and the advice loops. Before the fix the message was
`Pad accounts must be open on the pad date, 2024-05-20.`, which was correct.
No product fix implemented.

A ledger whose last line is `2024-06-01 open Expenses:Travel USD`, with
`Equity:Opening-Balances` opened earlier.

```sh
bea -f /abs/main.bean add balance -a Expenses:Travel --amount "25 USD" --date 2024-06-10 --pad-date 2024-05-20 --pad-from Equity:Opening-Balances
bea -f /abs/main.bean add balance -a Expenses:Travel --amount "25 USD" --date 2024-06-02 --pad-date 2024-05-20 --pad-from Equity:Opening-Balances
```

Actual: both exit 1 with `Expenses:Travel opens 2024-06-01, after the pad date
2024-05-20: --pad-from pads the day before the balance. Date the balance after
the open, for example --date 2024-06-02.` (also in `--json` details).

Control: `--pad-date 2024-06-01` writes; the note's own case (derived pad date)
gets the right hint.

Expected: for an explicit `--pad-date`, `the pad date 2024-05-20 is before
Expenses:Travel opens (2024-06-01); pass --pad-date 2024-06-01 or later.`

Cause: `cli/src/bea_engine/ledger/write.py:1770` branches on `pad_from and
_opened_after(...)`; `validate_candidate` receives only `pad_from: bool` and
cannot tell a derived pad date from an explicit one.

Fix: pass whether the pad date was explicit and word the remedy accordingly.

Dedupe: w5/299 and 513 (done) are related.

Acceptance: the first command advises `--pad-date 2024-06-01`; the derived case
is unchanged. A test pins both.
