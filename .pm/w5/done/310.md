# `bea init --opening-balance` writes the equity leg rounded to 28 significant digits, so a wide opening balance is not negated exactly

**Trivial · cli · 10–15m · A2.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
[263](./done/263.md) made `add` write numbers wider than 28 significant
digits exactly. `init` still computes its `Equity:OpeningBalances` leg in
the default decimal context, so for a balance that wide the written leg is
not the exact negation of the typed balance. This happens for both signs.
No product fix implemented.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, and closed stdin.

```sh
bea --no-input init ib --currency USD --date 2026-01-01 --opening-balance "Assets:Checking -1234567890123456789012345.678901"
tail -2 ib/main.bean
```

Actual: exit 0, and the ledger ends with:

```text
  Assets:Checking         -1234567890123456789012345.678901 USD
  Equity:OpeningBalances      1234567890123456789012345.679 USD
```

With a positive balance, the equity leg is
`-1234567890123456789012345.679 USD`. `bea check` accepts both, because
Beancount balances in the same 28-digit context. Reproduced in three fresh
runs.

Control: the `Assets:Checking` leg keeps every digit, and a balance of 28
digits gets an exact equity leg.

Expected: the equity leg is the exact negation of the typed balances,
matching how `add` now writes typed numbers.

Cause: `cli/src/bea_engine/initiating.py:91` writes
`{-sum(nonzero.values()):f}`. Both `sum` and unary minus round to the
default 28-digit context.

Fix: compute the sum under a `localcontext()` wide enough for the inputs,
and negate with `copy_negate()`. No dependency change.

Blast radius: `init` with opening balances wider than 28 significant
digits, which is contrived in practice.

Dedupe: w5/263 covers the `add` paths only. A board search for
`OpeningBalances` together with "round" finds nothing.

Acceptance: on the fixture, the equity leg reads
`1234567890123456789012345.678901 USD`. A test covers one balance and a
sum of two. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-15** — `cli/src/bea_engine/initiating.py` sums the opening balances under a `localcontext` at `MAX_PREC` and writes the equity leg with `copy_negate()`. On the fixture, the leg reads `1234567890123456789012345.678901 USD`, and a sum with `Assets:Cash 0.000001` gives `-1234567890123456789012345.678902 USD`, which `check` accepts. `cli/tests/test_init_wide_opening_balance.py` covers both signs and a sum of two; all 3 cases fail with the fix reverted. Only macOS was exercised. `make check-all` passed. Shipped in `dd8e4a53` (`cli`).
