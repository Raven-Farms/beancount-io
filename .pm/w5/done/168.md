# Docs and `engine status` say Beangulp needs the system libmagic library; `bea ingest` runs without it

**Minor · cli docs · 10m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, Beangulp 0.2.0, macOS.
`docs/USAGE.md`, `docs/IMPORTING.md` and `bea engine status` state that
Beangulp needs system libmagic. On a machine without it, `import magic`
fails in the managed engine and `bea ingest identify`, `extract` and
`archive` all work. The stated requirement can send users to install a
system library they do not need. Owner call on wording. No product fix
implemented.

Evidence on this machine: the managed engine's Python reports
`ImportError: failed to find libmagic. Check your installation` for
`import magic`; `bea engine status` shows `beangulp: enabled, present`
with the note "Needs the system libmagic library (python-magic)"; and the
`ingest` commands in w5/166 and w5/167 ran successfully in the same
environment. A worker found no libmagic under the usual Homebrew and
local library directories and traced the only use to an optional import
in Beangulp's deprecated file-type helper, which falls back to guessing
by extension.

Expected: the requirement described as optional — only importers that
call python-magic themselves need libmagic.

Where: `cli/docs/USAGE.md:66-68` ("Beangulp also needs the system
libmagic library"), the matching paragraph in `cli/docs/IMPORTING.md`,
and the feature note in `cli/src/cli/engine/manifest.json` that `engine
status` prints.

Fix: reword the three places. No code change.

Dedupe: board search for libmagic finds only w1/done/m16, which recorded
the requirement as an assumption.

Acceptance: the docs and `engine status` describe libmagic as optional.
No control is possible — there is no failing case. Only macOS and the
checkout were exercised.

---

**Resolved 2026-10-13** — The Beangulp feature note in `cli/src/cli/engine/manifest.json`, which `bea engine status` prints, and the matching passages in `cli/docs/USAGE.md`, `cli/docs/IMPORTING.md` and `cli/README.md` now say the system libmagic library is optional: only importers that call python-magic themselves need it. This matches Beangulp 0.2.0, whose only use of python-magic is a guarded optional import in its deprecated file-type helper that falls back to guessing by extension. No code path changed. The new `cli/tests/test_engine_libmagic_optional.py` runs `bea engine status` and reads the three documents, asserting each libmagic mention says optional and none states it as a requirement; all 4 cases fail with the wording reverted. The same "needs system libmagic" wording in the customer skills tree (`skills/`) and the historical rationale in ADR012 were left untouched as outside this note. Only macOS was exercised. `make check-all` passed. Shipped in `f3daa112` (`cli`).
