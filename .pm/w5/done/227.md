# An integer metadata value from a Python importer fails the import with a bare `ValueError: Unexpected value`

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
An importer that sets `check_number=1042` (a Python `int`) on a
transaction makes preview and apply fail with a generic exception line
that names neither the importer, the row nor the key. The bulk-add path
already coerces integers. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"

2026-01-01 open Assets:Checking USD
2026-01-01 open Assets:Savings USD
2026-01-01 open Expenses:Food
2026-01-01 open Equity:Opening

2026-01-02 * "Opening balance"
  Assets:Checking  1000.00 USD
  Equity:Opening
```

`/absolute/books/imp.py`:

```python
import datetime, unicodedata
from decimal import Decimal as D
from beancount.core import data
from beancount.core.amount import Amount

class Imp:
    name = "demo"
    def identify(self, filepath): return filepath.endswith(".txt")
    def account(self, filepath): return "Assets:Checking"
    def txn(self, filepath, **meta):
        return data.Transaction(dict(data.new_metadata(filepath, 1), **meta), datetime.date(2026, 1, 5), "*", "Cafe", "Coffee", frozenset(), frozenset(), [
            data.Posting("Assets:Checking", Amount(D("-5.25"), "USD"), None, None, None, None),
            data.Posting("Expenses:Food", Amount(D("5.25"), "USD"), None, None, None, None)])
    CHECK = 1042   # control: D("1042")
    def extract(self, filepath, existing):
        return [self.txn(filepath, check_number=self.CHECK)]
CONFIG = [Imp()]
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.
`/absolute/books/stmt.txt` holds the single line `statement`.

```sh
bea -f main.bean import stmt.txt --config imp.py --apply
```

Actual: exit 1, nothing written:

```text
Error: ValueError: Unexpected value: '1042' Pass --debug before the command for a traceback.
```

Control: with `CHECK = D("1042")` the import exits 0 and writes
`check_number: 1042`. A worker saw a similar bare `AttributeError` for a
`custom` directive whose values are plain tuples.

Expected: w3/done/230 fixed this exact message for `bea add transactions`
by treating a bare integer as a number. Importer problems are otherwise
reported as `Importer failed (…)`. The integer should be written as a
number, or the error should name the importer, row and metadata key.

Cause: `cli/src/bea_engine/importing.py:356` renders each entry outside the
`try` that wraps importer calls (`:209-233`), so the upstream printer's
error reaches the generic handler.

Fix: coerce non-boolean `int` metadata to `Decimal` as the bulk path does,
and wrap per-row rendering so any failure reads `Importer NAME row N: …`.
No dependency or API change.

Blast radius: Python importers only.

Dedupe: board search for "Unexpected value" finds w3/done/230 and
w1/done/109 (bulk add); w5/074 is another uncaught importer-output
exception with a different trigger.

Acceptance: the fixture imports and writes `check_number: 1042`; an
unrenderable value produces an error naming the importer and row. Only
macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — `cli/src/bea_engine/importing.py` now passes every extracted importer row through one step before deduplication: non-boolean Python `int` metadata on the entry and on its postings becomes a `Decimal`, and the row is printed once to prove it can be written. The note's fixture therefore imports and writes `check_number: 1042`, exactly as its `Decimal` control does, and an integer `bank_id` still deduplicates on a second import. A row that still cannot be printed (a `float`, an arbitrary object, a `custom` directive whose values are plain tuples) fails with `Importer NAME row N cannot be written as a ledger entry (ExceptionType): ...`, keeps the importer's captured output in the JSON error, and writes nothing; the message names the importer and row but not the metadata key, which the note offered as an alternative to coercion. `cli/docs/IMPORTING.md` states both behaviours. The regression test `cli/tests/test_import_integer_metadata.py` runs the real command over those cases, and six of its seven cases fail with the fix reverted (the `Decimal` control passes either way). Only macOS was exercised. `make check-all` passed. Shipped in `138e18a2` (`cli`).
