# `add balance --pad-from` with a default pad date before the account's open cites a line that does not exist as an assertion that "already holds" and says the pad "need not be added"

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `bea189ec`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/299.
The w5/299 unused-pad hint assumes only `add pad` reaches it. Through
`--pad-from`, the pad and the assertion are proposed together. When the pad
also fails for another reason (the account opens on the assertion date, so
the default pad date the day before is too early), the hint runs and
describes the proposed append as an existing assertion at a line past the
end of the file. No product fix implemented.

A 17-line ledger that opens `Expenses:Travel` on 2024-06-01 and
`Equity:Opening-Balances` earlier.

```sh
bea -f /abs/main.bean add balance -a Expenses:Travel --amount "0 USD" --date 2024-06-01 --pad-from Equity:Opening-Balances
```

Actual: exit 1, nothing written:
`Unused Pad entry. The 2024-06-01 assertion at …/main.bean:21 already holds,
so this pad would have nothing to fill; it need not be added.`, then `Invalid
reference to inactive account 'Expenses:Travel' … Correct the pad date or
edit that directive…` and `Pad accounts must be open on the pad date,
2024-05-31.`

Expected: one refusal that names the real problem and the remedy: the pad
date 2024-05-31 is before `Expenses:Travel` opens, so pass `--pad-date
2024-06-01` (or a later balance date). It should not cite line 21 or say the
assertion already holds.

Cause: `_unused_pad_hint` (`cli/src/bea_engine/ledger/write.py:1966-1973`)
runs when `_unused_pad_only` declines the retry because of the second error.

Fix: skip the unused-pad hint for a `--pad-from` pair, and add a `--pad-date`
remedy to the inactive-account error on that path.

Dedupe: `need not be added` appears only in w5/299 (done); w5/487 is a
different `--pad-from` case.

Acceptance: the command prints the pad-date remedy without the unused-pad
text. A test pins it.

---

**Resolved 2026-10-17** — Shipped in `aa5125ec` (`cli`). In `validate_candidate` (`cli/src/bea_engine/ledger/write.py`), a `--pad-from` pad that is itself invalid no longer gets the w5/299 unused-pad hint, which cited the proposed assertion past the end of the file as one that "already holds". When its account opens after the derived pad date, the pad hint reads `Expenses:Travel opens 2024-06-01, after the pad date 2024-05-31: --pad-from pads the day before the balance. Date the balance after the open, for example --date 2024-06-02.` `--pad-date` cannot help, because it must be earlier than the balance date. Other `--pad-from` unused-pad hints (w5/487's forced case, intermediate assertions) are unchanged. `tests/test_add_balance_pad_from_before_open.py` pins the refusal, which fails without the fix, and that the suggested date writes the pair.
