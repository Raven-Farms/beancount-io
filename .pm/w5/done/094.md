# `price export` exits 0 for a ledger with a local plugin, and the snapshot fails stock `bean-check`

**Minor · cli · 30–40m · A1.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, macOS. `bea price export` is documented to
produce a self-contained copy for stock tools and to refuse, before writing,
anything that cannot travel. A plugin module that lives beside the ledger is
neither copied nor refused, so the export reports success and the snapshot
does not load. No product fix implemented.

Create disposable `/absolute/books/myplug.py`:

```python
__plugins__ = ["noop"]


def noop(entries, options_map, config=None):
    return entries, []
```

and `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
option "insert_pythonpath" "TRUE"
plugin "myplug"

2026-01-01 open Assets:Checking USD
2026-01-01 open Equity:Opening
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, and an absolute `--file`.

```sh
bea --offline -f /absolute/books/main.bean price export
bean-check /absolute/books/main-export/main.bean
```

Actual: the export exits 0 with `Exported 1 file to
/absolute/books/main-export.`; the directory holds only `main.bean`.
Upstream `bean-check` on the snapshot exits 1 (`Error importing "myplug"`),
while the source ledger passes it. Repeated twice.

Control: the same ledger without the two plugin lines exports and passes
`bean-check`; `document` attachments are copied as documented.

Expected: `docs/USAGE.md` — "`price export` snapshots a self-contained
copy for stock tools", and attachments that cannot travel refuse "the export
before anything is written". A plugin resolved from the ledger's own
directory is the same kind of dependency: copy it or refuse naming it.

Cause: `cli/src/bea_engine/managed_load.py:871-945` plans only `document`
attachments; nothing considers `insert_pythonpath` or plugin modules
resolved from the root's directory.

Fix: when a plugin resolves from the root's directory through
`insert_pythonpath`, copy that module or package to the same relative place
under the existing collision rules, or refuse the export naming it; choose
one and document it. No dependency or API change.

Dedupe: w4/180 is the document analogue and does not mention plugins; board
search for `insert_pythonpath` and plugins with price export finds nothing.

Acceptance: the fixture's snapshot passes upstream `bean-check`, or the
export exits 2 naming `myplug` with nothing written; the plugin-free
control is unchanged. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-12** — Chose "copy" over "refuse": when the ledger sets `option "insert_pythonpath"`, `bea price export` copies each plugin module (`myplug.py`) or package (`myplug/`, its `.py` files, not `__pycache__`) that sits beside the root ledger to the same relative place in the export. The modules join the existing attachment plan, so a file already at a destination refuses the export without `--force` and nothing is written. The fixture's snapshot passes stock `bean-check`. A plugin that does not resolve beside the root is left alone. `docs/USAGE.md` states the rule. Shipped in `7f0a7b39` (`cli`).

Real-command regression tests cover a single module, a package named directly and a package submodule (each snapshot checked with stock `beancount.scripts.check`), a pre-existing module at the destination (refused, untouched, no ledger written), a plugin installed elsewhere, and a plugin-free ledger exported byte-identical. Four fail with the fix reverted. Limit: only the plugin's own module or package travels; a sibling module it imports from the same directory is not discovered. `make check-all` passed. Only macOS was exercised.
