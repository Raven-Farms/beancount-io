# `bea format --check DIR` silently skips a subdirectory it cannot read and reports the tree formatted

**Minor · cli · 30m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
The formatting gate walks a directory. A subdirectory the user cannot list
is skipped without a word, so `--check` exits 0 for a tree it never looked
at; `-i` likewise leaves those files alone. The docs say an unreadable
walked entry stops the run with exit 2. No product fix implemented.

Create `/absolute/books/t/a.bean`:

```beancount
2026-01-01 open Assets:A USD
```

and `/absolute/books/t/locked/z.bean` (unformatted):

```beancount
2026-01-01 open Assets:B USD
2026-01-02 * "x"
  Assets:B     1 USD
  Assets:B  -1 USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea format --check /absolute/books/t
chmod 000 /absolute/books/t/locked
bea format --check /absolute/books/t
```

Actual: the first run exits 1 (`would format: …/t/locked/z.bean`). After
the `chmod`, the second exits 0: `checked: /absolute/books/t/a.bean` /
`All 1 file(s) are formatted.` The locked directory is not mentioned.

Control: the readable tree (first run). A worker saw `--json` report
`scanned: 1`, `-i` print `0/1 file(s) formatted.`, a broken symlink in the
walk exit 2 as documented, and an unreadable file (rather than directory)
exit 1 with category `validation` instead of the documented 2.

Expected: `docs/USAGE.md`: "a walked entry it cannot read stops the run
(exit **2**) naming the path… Silently dropping it would let `--check`
report a tree it never looked at".

Cause: `cli/src/cli/commands/format.py:399` uses `root.rglob(pattern)`,
which swallows `PermissionError` on directories it cannot list; an
unreadable regular file fails later as a ledger error (`:351`).

Fix: a directory the walk cannot list, or a file it cannot read, stops
`--check`, `--dry-run` and `-i` with exit 2 naming the path. No dependency
change.

Blast radius: the three walking modes of `format` on a directory.

Dedupe: board search for unreadable, `chmod 000` and `rglob` finds
w3/done/362 (broken symlinks omitted, fixed), w3/done/329 (outbound
symlinks) and w5/120 (unreadable include on load); none covers an
unlistable directory.

Acceptance: the second command exits 2 naming `t/locked`; the readable
control is unchanged. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — The directory walk in `cli/src/cli/commands/format.py` no longer uses `Path.rglob`, which swallowed the error from a subdirectory it could not list; it now walks with `os.walk` and an error hook, and checks read access on each walked ledger file, so `bea format --check`, `--dry-run` and `-i` on a directory stop with exit 2 and `Could not read <path>: Permission denied` naming the unlistable directory or unreadable file. Like the walk it replaces, it does not descend through directory symlinks, and outbound file symlinks are still skipped. `cli/docs/USAGE.md` now names both shapes beside the broken-symlink case. The regression test `cli/tests/test_format_directory_unlistable.py` covers an unlistable subdirectory and an unreadable walked file in all three modes, the `--json` usage envelope, the readable control and a directory symlink; 7 of its 9 cases fail with the fix reverted. An unreadable file named explicitly on the command line (not reached by a directory walk) is unchanged and still exits 1 as a ledger error. Only macOS was exercised. `make check-all` passed. Shipped in `fee1395a` (`cli`).
