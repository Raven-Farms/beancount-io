# A zero-width space (U+200B) after an account in `add -p` still produces an invisible duplicate account through the printed `add open` suggestion (incomplete fix of w5/490)

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `06e9ca0f`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/490 (done).
w5/490's acceptance: "the suggested `add open` never contains an invisible
character", and diagnostics show invisible characters escaped. The fix
refuses Unicode spaces (`str.isspace()`). Format characters such as U+200B,
U+2060, U+FEFF and U+00AD are not spaces, so they pass. They also come in
with pasted text. No product fix implemented.

```sh
bea -f /abs/main.bean add transaction X --date 2026-01-05 -p $'Expenses:Food​ 5 USD' -p 'Assets:Cash -5 USD'
bea -f /abs/main.bean add open --account $'Expenses:Food​' --date 2026-01-01     # the printed suggestion
bea -f /abs/main.bean add transaction X --date 2026-01-05 -p $'Expenses:Food​ 5 USD' -p 'Assets:Cash -5 USD'
```

Actual: the first exits 1 with `Invalid reference to unknown account
'Expenses:Food​' Did you mean Expenses:Food? To create it, use bea add open
--account 'Expenses:Food​' …`; the U+200B is printed raw. The suggested `add
open` exits 0, the retry exits 0, and `balance` then shows two `Food` rows with
the 5 USD on the invisible one. U+2060, U+FEFF, U+00AD, bulk rows and `add
balance -a` behave the same.

Control: U+00A0, U+2009 and U+3000 are refused with exit 2 naming the
character.

Expected: the unknown-account message and its suggestion escape format
characters (`Expenses:Food​`). A new `add open` name containing one is
refused with exit 2 naming it.

Cause: `_refuse_unicode_space` and `parse_account`
(`cli/src/bea_engine/ledger/text.py`) test only `str.isspace()`.

Fix: as above. Constraints: w5/203 deliberately allows posting to an account
that already exists with a zero-width character, and ZWJ/ZWNJ (U+200C/D) are
legitimate in some scripts; refuse them only in new names, and escape them
everywhere in diagnostics.

Dedupe: searched `zero-width`, `200B`, `invisible`; w5/531 (CSV headers) and
w5/203 (done, existing names) are related.

Acceptance: the suggestion shows the escape and the `add open` is refused. A
test pins both.
