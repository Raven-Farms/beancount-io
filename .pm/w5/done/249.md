# `bea query --source <missing file>` exits 0 and replaces an existing `-o` export with a header-only file

**Major · cli · 30–40m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A typo in the `--source` path makes the query run over nothing. The
command exits 0, and an existing export named by `-o` is replaced with
just the header row. With `-q` there is no message at all. The same typo
with `--file` exits 2 and leaves the export alone. No product fix
implemented.

Create disposable `/absolute/books/main.beancount`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
2024-01-01 open Equity:Opening USD
2024-01-02 * "Open"
  Assets:Cash  100.00 USD
  Equity:Opening
2024-01-03 * "Lunch"
  Expenses:Food  12.50 USD
  Assets:Cash
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea query --source /absolute/books/main.beancount "SELECT account, sum(position) GROUP BY account ORDER BY account" -f csv -o report.csv
bea query --source /absolute/books/mian.beancount "SELECT account, sum(position) GROUP BY account ORDER BY account" -f csv -o report.csv
```

Actual: the first exits 0 and writes a 103-byte `report.csv`. The second
(source misspelled) exits 0 with stderr `<load>:0: File
"/absolute/books/mian.beancount" does not exist`, and `report.csv` is now
23 bytes: `account,sum(position)`. A worker saw both streams empty with
`-q`.

Control: `bea -f /absolute/books/mian.beancount query "…" -f csv -o
report.csv` exits 2 (`No ledger file at …`) and leaves the file intact.
`bea query --source /absolute/books/main.beancount "SELEC bad" -o
report.csv` exits 2 and leaves it intact. Stock `bean-query` also exits 0
on a missing file, so the status is inherited; replacing the export is
`bea`'s own step.

Expected: `docs/USAGE.md`: "Native `--source` one-shots keep upstream's
rendering but not its exit status … an existing `--output` export is
replaced only after the query succeeds", and "If the resolved file does not
exist, the command exits **2**."

Cause: `cli/src/cli/commands/query.py:251-274` never checks that the
`--source` path exists. In the engine, `native_one_shot`
(`cli/src/bea_engine/query.py:398-432`) builds the shell; Beanquery records
the "does not exist" load error and attaches empty tables, and nothing
inspects that before the export is written (`:431-432`).

Fix: for a bare path or `beancount:` source, refuse a path that is not an
existing regular file with exit 2 before the engine starts; as a backstop,
treat a missing-root load error as failure before writing the export.
Ordinary loader errors in an existing source keep upstream's behaviour. No
dependency or API change.

Blast radius: `query --source` one-shots, and by the same code the
interactive `--source` shell (opens on an empty database; not run).

Dedupe: board search for `--source` with "does not exist", missing, typo
and header-only finds w1/done/043 (missing stored query exits 0),
w1/done/040 (missing query text), w4/done/181 and w1/done/154 (output
aliasing the source) and w3/done/274 (bad scheme); none covers a missing
source file.

Further triggers (2026-10-12): `--source Beancount:main.bean -o out.csv …`
(mixed-case scheme; re-run by me) exits 0 with `File "…/Beancount:main.bean"
does not exist` and leaves a 23-byte header-only export: the frontend
case-folds the scheme, the engine does not. A worker saw the same for a
file name containing `#`. Both would pass a frontend "is it an existing
file" check, so the engine-side backstop is required.

Acceptance: the misspelled command exits 2 naming the path and leaves
`report.csv` byte-identical; the correct command is unchanged. Only macOS
and the checkout were exercised.

---

**Resolved 2026-10-13** — `bea query --source` now refuses a Beancount source (a bare path or `beancount:<path>`) whose ledger file does not exist or is a directory: `cli/src/cli/commands/query.py` exits 2 naming the path before the engine starts, and `_native_shell` in `cli/src/bea_engine/query.py` repeats the check on the path it would really hand the loader, so the one-shot and the interactive shell both stop before an existing `--output` export is touched. The engine-side check is what covers spellings the two sides read differently, such as a mixed-case `Beancount:` scheme or a file name containing `#`; load errors inside a ledger that exists keep upstream's behaviour, and `docs/USAGE.md` states the rule. `cli/tests/test_query_source_missing_file.py` runs the real command for absolute, relative, URI and mixed-case spellings with and without `-q`, a directory, a `#` name, the helper invoked directly, and the PTY shell, asserting exit 2, the named path and a byte-identical export, alongside controls for an existing source, a source with ordinary load errors and a `csv:` source; 16 of its 21 cases fail with the fix reverted. A missing `csv:` file and an empty `beancount:` URI still end in an upstream traceback with exit 1 and were left out of scope. Only macOS was exercised. `make check-all` passed. Shipped in `5218c233` (`cli`).
