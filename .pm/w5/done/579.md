# `bea init 'books$HOME.bean'` creates a ledger every later command refuses, and `init '$HOME/books'` fails with a leaked staging path and leaves `./$HOME/books/` behind (gap in w5/315)

**Minor · cli · 10m · A2.** Real CLI QA, 2026-10-16, HEAD `3514cc17`, checkout `bea 0.3.1`, macOS 26.5.1.
w5/315 refuses a ledger path containing an environment variable that
Beancount's loader would expand. It applies to reads and writes, but not to
`init`. No product fix implemented.

In an empty directory:

```sh
bea init 'books$HOME.bean' --currency USD --date 2026-01-01
bea -f 'books$HOME.bean' check
bea --json init '$HOME/books' --currency USD --date 2026-01-01
```

Actual: the first exits 0 and prints a `Next: bea --file …/books$HOME.bean
check` hint; that command exits 2 with `contains an environment variable that
Beancount would expand … Rename the file`. The third exits 1 (`validation`):
`The change would leave the ledger invalid; nothing was written.` with
`<load>:0: File "…/Users/…/books/.bea-….tmp" does not exist`, and an empty
`./$HOME/books/` is left behind.

Control: `bea -f 'x$HOME.bean' check` gives the clean exit-2 refusal.

Expected: `init` refuses such a path with the same exit-2 message before
creating anything.

Cause: `cli/src/cli/commands/init.py:116-122` builds the target without
`context.refuse_expanding_ledger_path`.

Fix: call it before `_make_parent` and the helper.

Dedupe: w5/315 (done) is the fix this extends.

Acceptance: both `init` commands exit 2 and create nothing. A test pins them.

---

**Resolved 2026-10-17** — Shipped in `6bce1e4e` (`cli`). `bea init` (`cli/src/cli/commands/init.py`) now calls `context.refuse_expanding_ledger_path` on the resolved ledger path before checking or creating anything. That is the same exit-2 refusal reads and writes give (w5/315). `init 'books$HOME.bean'` and `--json init '$HOME/books'` both exit 2 with `contains an environment variable that Beancount would expand …`, and nothing is left in the directory. `tests/test_ledger_path_env_expansion.py::test_init_refuses_an_expanding_path_and_creates_nothing` pins the file name, the directory and the global `--file` form; all three fail without the fix.

Gate: `test_release`'s cold-cache `uv sync` timed out at 120 s three times in a row while PyPI was slow (about 1.2 s per request). This is the known network flake, which passed on earlier reruns; the change cannot affect packaging, and the rest of `make check-all` passed (7032).
