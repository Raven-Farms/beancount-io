# `bea doctor missing-open` writes its inactive-account diagnostics to stdout, so the documented `missing-open main.bean >> main.bean` corrupts the ledger

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `04c94595`, checkout `bea 0.3.1`, macOS 26.5.1. Differential run against upstream `bean-doctor`.
Upstream's `missing-open` prints only the generated `open` directives, so its
output can be appended to the ledger. w3/364 and w5/139 added
inactive-account lines to bea's output, and they go to stdout. USAGE (non-
interactive behavior): a redirected stdout "carries only results", and
warnings and errors never go to stdout. No product fix implemented.

`main.bean`:

```beancount
2024-02-01 open Assets:Cash USD

2024-01-15 * "early"
  Assets:Cash  5 USD
  Income:Gift
```

```sh
bea doctor missing-open main.bean 2>/dev/null
bea doctor missing-open main.bean >> main.bean
bea --file main.bean check
```

Actual: exit 1; stdout is `2024-01-15 open Income:Gift` and
`/abs/main.bean:3: Invalid reference to inactive account 'Assets:Cash'`. After
the append, `check` fails with `main.bean:7: syntax error … Invalid token:
'sers/…'`.

Control: `bean-doctor missing-open` prints only the `open` line.

Expected: the inactive-account lines (and any other diagnostics) go to
stderr; stdout holds only directives.

Cause: `cli/src/cli/commands/doctor.py:610` uses `typer.echo(line)`;
`tests/test_doctor_missing_open_inactive_wording.py:76` pins stdout.

Fix: echo the lines with `err=True` and update the test.

Dedupe: w3/364 and w5/139 (done) added the lines; neither discussed the
stream.

Acceptance: the append leaves a ledger that checks (or fails only on the
inactive reference). A test pins the streams.

---

**Resolved 2026-10-17** — Shipped in `e05e725b` (`cli`). `_forward_missing_open` (`cli/src/cli/commands/doctor.py`) no longer echoes the inactive-account lines; they are the details of its `LedgerError`, so they print on stderr. Stdout holds only upstream's `open` lines, and the note's fixture gives exactly `2024-01-15 open Income:Gift` there, ready for `missing-open main.bean >> main.bean`. USAGE's doctor table names the streams.

`tests/test_doctor_missing_open_inactive_wording.py` pins the streams, including the note's fixture; it fails without the fix. Two tests that pinned the old stream were updated to stderr: `test_cli_parity_qa.py::test_doctor_missing_open_names_pre_closed_accounts` and the `w3/364` entry of the exit-contract matrix. `make check-all` passed.
