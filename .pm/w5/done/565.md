# `format -i DIR` (and `-i ROOT`, `--check`, `--dry-run`) aborts the whole run when any one file holds a zero divisor (`100/0 USD`): nothing is formatted and the file is not named

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `fe8ed158`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE: "`--in-place` formats every reachable file and skips the unparseable
ones, exiting nonzero when anything was skipped", and `--check` fails
"naming" the bad file. The pre-format syntax pass parses every file in one
engine process, and upstream's parser segfaults on a zero divisor. One bad
file therefore kills the batch, and the message lists every file. No
product fix implemented.

`books/main.bean`:

```beancount
option "operating_currency" "USD"
2020-01-01 open Assets:Cash USD
2020-01-01 open Income:Gains
include "jan.bean"
include "feb.bean"
```

`books/jan.bean` (misaligned): `2020-01-05 * "a"` / `    Assets:Cash     1 USD`
/ `  Income:Gains   -1 USD`. `books/feb.bean`: `2020-02-01 * "b"` /
`  Assets:Cash  100/0 USD` / `  Income:Gains`.

```sh
bea format -i books
bea format --check books
```

Actual: exit 1, `Error: The Beancount engine was killed by SIGSEGV answering
'bea-engine syntax …/feb.bean …/jan.bean …/main.bean' and produced no
result.` with the `/0` hint; `jan.bean` is unchanged.

Control: with a syntax error (`1 USD x`) in `feb.bean` instead, `jan.bean` is
formatted and the run reports `cannot parse: …/feb.bean:2: Invalid token:
'x'`.

Expected: `jan.bean` is formatted, `feb.bean` is reported as cannot-parse
(division by zero), exit 1.

Cause: `_syntax_failures` (`cli/src/cli/commands/format.py:472-482`, called at
`:111`) runs one `bea-engine syntax` for all files; `parser.parse_file`
(`cli/src/bea_engine/ledger/text.py:314`) crashes on the divisor.

Fix: pre-scan each file for a literal zero divisor with the guard `add`
already uses (`cli/src/bea_engine/amounts.py:132`) and report it as
cannot-parse, or isolate the syntax pass per file when the batch process
dies.

Dedupe: searched `SIGSEGV`, `zero divisor`, `bea-engine syntax`. w5/010, 057,
251 and 252 (done) cover check, add and doctor.

Acceptance: the commands format `jan.bean` and name `feb.bean`. A test pins
it.

---

**Resolved 2026-10-17** — Shipped in `8c1078d8` (`cli`). `format`'s `_syntax_failures` (`cli/src/cli/commands/format.py`) first scans each file for a literal zero divisor outside strings, `;` comments and the line starts Beancount skips (`zero_divisor_line` in `cli/src/cli/amounts.py`, sharing the pattern `check_decimal_notation` uses). That file is reported as cannot-parse at its line (`…/feb.bean:2: Division by zero in an amount expression; …`), and only the others go to the engine's syntax pass. `format -i DIR`, `-i ROOT` and `--check` now format or report `jan.bean`, name `feb.bean` and exit 1.

The scan sits in the frontend rather than in the engine's `syntax` command. Placed in the engine, it made `doctor lex`, which never evaluates the expression, report a syntax error. Doctor's own probes are unchanged.

`tests/test_format_zero_divisor_file.py` pins `-i` on the directory and on the root, plus `--check`. Its controls are a slash date, and `/0` inside a string and a comment. All three cases fail without the fix. `make check-all` passed.
