# `add transaction --flag ''` writes `*` with exit 0, and `add open --booking ' '` writes an open with no booking method; bulk add refuses `"flag": ""`

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
[w5/239](./done/239.md) set the rule that an empty option value is
refused, not read as "omitted", so that only an omitted option gets the
default. Its resolution left `--flag` and `--booking` alone as "a
different option family". Both still treat an empty value as absent. A
template with an unset `$FLAG` therefore silently writes a cleared
transaction where the user meant `!`. The bulk path refuses the same
empty flag, so single and bulk add disagree. No product fix implemented.

Use any USD ledger with `Expenses:Food` and `Assets:Cash` open, with the
environment from [381](./381.md).

```sh
bea -f /absolute/books/main.bean add transaction X --date 2026-01-02 -p 'Expenses:Food 1 USD' -p Assets:Cash --flag ''
bea -f /absolute/books/main.bean add open --account Assets:Bank --date 2026-01-01 --booking ' '
bea -f /absolute/books/main.bean add transactions --from f.json     # a row with "flag": ""
```

Actual:

- `--flag ''` exits 0 and writes `2026-01-02 * "X"`. `--json` reports
  `"flag": "*"`.
- `--booking ' '` exits 0 and writes `open Assets:Bank` with no booking
  method.
- The bulk row is refused: `Row 1, flag: Value error, '' is not a flag`.
- `--flag ' '` and `--booking bogus` exit 2.

Reproduced by the hunter in two fresh ledgers and by me once.

Expected: w5/239's rule, and USAGE's refusals of empty `--account`,
`--time` and `--conversion` instead of "silently falling back to the …
default", mean that an empty `--flag` or `--booking` should exit 2
naming the option, matching bulk add.

Cause:

- `cli/src/bea_engine/ledger/adding.py:685` uses
  `str(request.get("flag") or "*")`.
- `adding.py:152-154` uses `str(booking).strip().upper() or None`.

Fix: apply the default only when the value is absent or `None`, and pass
`""` through the flag and booking validators. No dependency change.

Blast radius: `add transaction --flag` and `add open --booking` with an
empty or blank value.

Dedupe: searched `.pm/**`, including `done/`, for `--flag ''`, empty
flag and `--booking`. w5/239 explicitly left these out of scope, and no
open note covers them.

Acceptance: `--flag ''` and `--booking ' '` exit 2 naming the option, and
the ledger is unchanged. An omitted `--flag` still writes `*`. A test
pins both.

**Resolved.** `cli/src/bea_engine/ledger/adding.py` now defaults the transaction flag to `*` only when it is omitted (`None`). `--flag ''` therefore reaches the header validator and exits 2 with `--flag: '' is not a flag; use one of * ! & # ? % or a single capital letter.`, matching bulk add. A blank `--booking` (`''` or `' '`) now exits 2 with `--booking ' ' is blank; omit --booking for the default, or choose one of: STRICT, STRICT_WITH_SIZE, NONE, FIFO, LIFO, HIFO.` In both cases nothing is written.

`tests/test_add_empty_flag_booking.py` covers the empty flag, blank booking and empty booking in text and JSON. Each exits 2 naming the option, with the ledger unchanged. The control checks that an omitted `--flag` still writes `*`. With the fix stashed, the six refusal cases fail.
