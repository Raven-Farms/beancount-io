# An import preview with a mistyped or wrong `--account` (even one never opened, with every row blocked) is remembered, so every later flag-free import of that header is refused as "matches multiple source accounts", and there is no documented way to forget the stale entry

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
Import memory is keyed by root ledger, header row and source account. A
successful preview saves its (header, account) entry. When the preview
used a typo such as `Assets:Savngs` (never opened, every row blocked),
that entry is saved anyway, next to the correct one the user saves a
moment later. From then on, the flag-free imports that IMPORTING.md
promises ("When only one account uses those headers, the next import
needs no flags") are refused permanently. No command or documented step
removes the stale entry. No product fix implemented.

Use a USD ledger opening `Assets:Bank` and `Expenses:Uncategorized`, and
two CSVs `s.csv` and `t.csv` sharing the header `Date,Description,Amount`.
Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME (fresh),
BEA_NO_UPDATE_NOTIFIER=1, and closed stdin.

```sh
bea -f /absolute/books/main.bean import s.csv --csv date=Date,narration=Description,amount=Amount --account Assets:Savngs
bea -f /absolute/books/main.bean import s.csv --csv date=Date,narration=Description,amount=Amount --account Assets:Bank --apply
bea -f /absolute/books/main.bean import t.csv
```

Actual: the typo preview exits 0 with every row blocked, and the
corrected `--apply` exits 0. The flag-free `import t.csv` then exits 2
with `This CSV header matches multiple source accounts: Assets:Bank,
Assets:Savngs. Pass --account ACCOUNT …`, and does so on every later
run. The hunter saw the same when the mistaken account was a real open
one. Reproduced in three directories by the hunter and once by me.

Control: without the mistaken preview, `import t.csv` reuses
`Assets:Bank` with no flags.

Expected: a preview that only explores, especially with an unopened
account or with no ready rows, should not register a second account for
the header. There should also be a documented way to forget an entry.
IMPORTING.md says only that settings live in `importers/`.

Cause: `cli/src/cli/commands/import_.py:1005-1015` saves after any
successful preview. `_remember_csv` (`:397-431`) appends a (header,
account) entry and never prunes one.

Fix: do not remember an account that the ledger does not open, nor a
preview with zero ready rows. Let a successful `--apply` for a header
supersede entries that never applied, or add a `--forget` option, and
document it. No dependency change.

Blast radius: users and agents who try a wrong `--account` once, which is
common while learning. Flag-free imports for that bank's exports break
for good.

Dedupe: w5/214 (lost entries under concurrent writers), 311, 385,
w5/281-284 and w3/311 cover other memory issues. None covers stale
mistaken entries or forgetting.

Acceptance: on the fixture, `import t.csv` reuses `Assets:Bank` with no
flags. A preview with an unopened account saves nothing. A documented way
removes an entry. A test pins it.

Addendum (CLI QA r97, 2026-10-14): a mistyped `--default-account` is
saved the same way. `import s.csv --csv … --account Assets:Bank
--default-account Expenses:Nope` previews with every row blocked and
exits 0, and the memory then holds `"default_account": "Expenses:Nope"`.
Every later flag-free import recalls it ("Using settings remembered …
--default-account Expenses:Nope"), blocks every row, and advises `Run:
bea add open --account Expenses:Nope …`. Following that advice would
make the typo a real account. Typing a correct `--default-account`
replaces it, with a note. Reproduced twice by the hunter and once by me.
The fix should cover both fields: never save a source or default account
that the ledger does not open.

---

**Resolved 2026-10-15** — The engine's import preview (`cli/src/bea_engine/importing.py`) reports `unopened_accounts`: every account its rows post to that the ledger still does not open after the import. That includes duplicate rows, so an already-imported file cannot hide a typo, and an `auto_accounts` ledger's opens still count. When the run's `--account` or `--default-account` is among them, `import` (`cli/src/cli/commands/import_.py`) keeps no settings and notes `Not remembering these settings: Assets:Savngs is not open in this ledger.`. On the fixture, the flag-free `import t.csv` then reuses `Assets:Bank`, and both of the note's typos are covered. For entries remembered before this fix, the "matches multiple source accounts" refusal names the ledger's memory record to delete. IMPORTING.md documents both behaviors; there is no per-entry `--forget`. `cli/tests/test_import_memory_unopened_account.py` covers the fixture sequence, the default-account typo saving nothing, and the refusal's forget path; all 3 fail with the fix reverted. Only macOS was exercised. `make check-all` passed (6055 tests). Shipped in `66f9dac2` (`cli`).
