# Read-only commands leave a world-readable full copy beside a private ledger once a load takes a second

**Major · cli · 45–60m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
When loading the ledger takes about a second or more, any read command
(`check`, `list`, `report`) leaves `.main.bean.picklecache` beside it — a
complete copy of the ledger's contents, created with the process umask.
For a ledger kept at mode 0600, the copy is 0644 under the common umask
022. The documentation promises private ledger files and never mentions
this file. Severity rests on that privacy promise; small ledgers are
unaffected. No product fix implemented.

Create `/absolute/books/main.bean` with mode 0600 containing two `open`
directives and 60,000 two-posting transactions (about 4 MB; a short
generator script suffices).

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY. cwd `/absolute/books`, umask 022.

```sh
bea -f main.bean list note
ls -la
```

Actual: exit 0 (`No notes found.`). The directory now holds
`-rw-r--r-- .main.bean.picklecache` (about 12 MB) beside `-rw-------
main.bean`.

Control: a worker ran the same on an 18,000-transaction ledger and on
`add note` for the large one; neither leaves a cache. The worker also
observed: mode 0666 under umask 000; the cache written through a
pre-existing dangling symlink at that name, creating the copy at the
link's target outside the ledger directory; and that a cache file already
present beside a ledger is loaded by read commands before any freshness
check — so a ledger folder obtained from elsewhere can carry one that
supplies the answers (upstream Beancount behaviour that `bea`'s own
helper inherits).

Expected: `docs/USAGE.md` says "New ledger files are private by default
(`0600` …: readable and writable only by their owner)" and that writes
"preserve the file's permissions". Reads should not create a more widely
readable copy of the same data, or any file, in the ledger directory.

Cause: upstream Beancount's loader writes its load cache next to the
ledger at the process umask, following links, when a load exceeds one
second; `cli/src/bea_engine/managed_load.py:474-480` loads through it,
as does the native `bean-check` behind `bea check`.

Fix: disable the load cache for `bea`-driven loads, or point Beancount's
cache-filename setting at a 0700 directory under the `bea` cache home for
both helper and native children. Either removes the file from ledger
directories and closes the symlink and planted-cache observations.

Blast radius: every load-bearing read on a slow ledger.

Dedupe: board search for picklecache, umask and 0644 finds w5/111 and
w5/116 (staleness), w5/118 (roundtrip leftover), w5/067 (cache setting
aliasing the ledger) and w3/done/390 (staged sidecar); none covers the
cache's mode, location or link-following.

Acceptance: after the command the ledger directory contains only
`main.bean`, under umask 022 and 000; a second read is still served
correctly. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — Beancount's default load cache no longer lands beside the ledger: the helper (`cli/src/bea_engine/ledger/write.py`, installed from `managed_load.py` and `scoped.py`) resolves it under `$XDG_CACHE_HOME/bea/load-cache`, a 0700 directory with one file per ledger file keyed by the ledger's directory, and `cli/src/cli/engine/launch.py` hands `bean-check` and `bean-doctor` the same path as a `BEANCOUNT_LOAD_CACHE_FILENAME` pattern, so the cache is still shared and large ledgers stay fast. A pattern the user set, or `bea check --cache-filename`, keeps upstream's meaning, and `docs/USAGE.md` now describes where the cache lives. The new `tests/test_load_cache_outside_ledger_directory.py` runs real `list`, `check`, `balance` and `doctor` reads on a slow ledger under umask 022 and 000 and asserts the ledger directory holds only `main.bean`, that a second read is a cache hit and a changed ledger is re-read, that two same-named ledgers do not share a cache, that a dangling link at the old name is not written through, and that a cache file planted beside the ledger no longer supplies the answer; 12 of its 15 cases fail with the fix reverted, the other three being controls. Deviations from the note: a `.<name>.picklecache` left by an earlier version is neither read nor removed, and the optional `bea price` (bean-price) and `bea ingest` forwarders still run upstream with its own cache placement. Only macOS was exercised. `make check-all` passed. Shipped in `f48c48fd` (`cli`).
