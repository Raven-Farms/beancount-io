# `report -t "year - year+1"` (also `month - month+2`, `day - day+7`, `quarter - quarter+1`) is refused with exit 2, while `(year) - (year+1)` works

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `0c520fd1`, checkout `bea 0.3.1`, macOS 26.5.1. Upstream Fava bug in the vendored date parser.
The vendored time-filter grammar supports `year`, `month`, `day`, `week`,
`quarter` and their fiscal forms with `±N` offsets and ranges. Substitution
replaces every occurrence of the matched text. So the bare `year` also
rewrites the start of `year+1` into `2026+1`, and the second term no longer
parses. No product fix implemented.

```sh
bea -f /abs/main.bean report income-statement -t "year - year+1"
bea -f /abs/main.bean report income-statement -t "(year) - (year+1)"
```

Actual: the first exits 2 with `Invalid time filter 'year - year+1'. … Failed
to parse date: year - year+1`; the second prints `Income Statement —
2026-01-01 through 2027-12-31`. `year-1 - year` works because the longer match
is substituted first.

Expected: both give 2026-01-01 through 2027-12-31.

Cause: `substitute()` in `cli/src/fava/util/date.py:352-388` uses
`string.replace(complete_match, …)` (all occurrences).

Fix: substitute by match span (`VARIABLE_RE.sub` with a function), keeping
`NOTICE.fava` attribution; consider reporting it upstream.

Dedupe: searched `Failed to parse date`, `year+1`; only dashboard
invalid-date notes.

Acceptance: the six spellings above parse. A test pins them.

---

**Resolved 2026-10-17** — Shipped in `79505f17` (`cli`).
- `substitute()` (`cli/src/fava/util/date.py`, marked as a Beancount.io change) now replaces each matched variable where it stands, using `VARIABLE_RE.sub` with a function, instead of `str.replace` on every occurrence.
- `year - year+1`, `month - month+2`, `day - day+7`, `quarter - quarter+1` and `week - week+1` now parse exactly like their parenthesized forms; `report income-statement -t "year - year+1"` exits 0 with the same period as `(year) - (year+1)`.
- Not reported upstream from here.
- `tests/test_time_filter_variable_ranges.py` pins the five spellings against their parenthesized forms (independent of today's date) and the report; all 6 fail without the fix. `make check-all` passed.
