# `list transaction --details` ("Beancount syntax") spells a different string than the ledger holds: a TAB in a narration or metadata becomes `\\x09` and a line break becomes a space

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `d6c32f470`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE:896 says `--details` renders Beancount syntax. No product fix
implemented.

A ledger with `2026-01-08 * "Tab<TAB>here" "Rent<LF>for January"` and `memo:
"a<TAB>b"` (real control bytes):

```sh
bea -f /abs/main.bean list transaction --details
```

Actual: `2026-01-08 * "Tab\\x09here" "Rent for January"` and `memo: "a\\x09b"`.
Parsed as Beancount, that is a literal backslash, and the narration's line
break is gone. `--json` and `query PRINT` keep the real values. A lot label
with a tab shows `"lot\x09A"` in the table but `"lot\\x09A"` in `--details`
(hunter's run).

Expected: the ledger's own string, as valid Beancount (`\t` and `\n` escapes,
or the raw characters, with the terminal-safety escaping applied by the
frontend as usual).

Cause: `--details` renders through `writer.format_entry`, which runs the
write-path sanitizer `normalize_entry_strings`
(`cli/src/bea_engine/ledger/writer.py:216`). `single_line`
(`cli/src/bea_engine/ledger/text.py`, around `:37-56`) turns line breaks into a
space and TAB into `\x09`, which the printer then escapes. The frontend
already makes control characters inert.

Fix: render loaded entries without write normalization.

Dedupe: w5/148, 542 and w4/173 (done) are about the sanitizer; w5/733 and 756
(open) are other side effects of it; w5/631 (open) is `--search`.

Acceptance: the `--details` output parses back to the ledger's strings.

---

**Resolved 2026-10-20** — `format_transaction(…, loaded=True)` prints a loaded entry with the plain directive printer, skipping the write sanitizer, and `list --details` uses it, so a TAB or line break inside a string is written as the ledger holds it; the frontend makes control characters inert (`\\xNN`) only when stdout is a terminal, so redirected output parses back to the same payee, narration and metadata. `tests/test_list_details_keeps_strings.py` parses the rendering back; USAGE says so.
