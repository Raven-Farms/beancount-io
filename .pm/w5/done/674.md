# A plugin that calls `sys.exit` (argparse rejecting a mistyped plugin config) leaks its status: text `check` exits 2 or 7, `--json check` exits 1 "engine did not answer", `add` exits 4 "outcome unknown", and `sys.exit(0)` gives silent false successes

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-17, HEAD `6d74be10`, checkout `bea 0.3.1`, macOS 26.5.1. Sibling of w5/634 (importers).
Plugins that parse their config string with `argparse` exit the process on a
typo. Upstream's loader deliberately lets exits through. bea catches only
`Exception`, so the plugin's exit status becomes bea's: outside the
exit-code table, different in text and JSON, and on writes a false "outcome
unknown". No product fix implemented.

`argplug.py` beside the ledger:

```python
import argparse, shlex
__plugins__ = ["argplug"]
def argplug(entries, options_map, config=""):
    p = argparse.ArgumentParser(prog="argplug"); p.add_argument("--threshold", type=int, default=0)
    p.parse_args(shlex.split(config)); return entries, []
```

`main.bean`: `option "insert_pythonpath" "TRUE"`, `plugin "argplug"
"--treshold=5"`, and some entries.

```sh
bea -f /abs/main.bean check
bea --json -f /abs/main.bean check
bea -f /abs/main.bean add open --date 2026-02-01 --account Assets:New
```

Actual: text `check` (and `doctor missing-open`, `query --source`) exits **2**
with only argparse's two lines, reading as a bea usage error; `--json check`
and `list` exit 1 with `The Beancount engine did not answer … (exit 2).`; `add`
exits **4** ("the outcome is unknown") with the ledger unchanged. With
`sys.exit(7)`, text `check` exits 7 silently; with `sys.exit(0)`, `query
--source` and `doctor missing-open` exit 0 with no output.

Control: a plugin raising `ValueError` gives exit 1 with `Plugin "argplug"
failed while running: ValueError: …` everywhere, and `add` exits 1.

Expected: exit 1 with `Plugin "argplug" failed while running: SystemExit: 2`
plus its output, the same in text and JSON, for every command.

Cause: upstream `beancount/loader.py` lets exits through ("Catch all
exceptions … except exits"); `cli/src/bea_engine/protocol.py:118` catches only
`Exception`; the native paths (`cli/src/cli/commands/check.py:137` `run_native`,
`run_engine_argv`) pass the status through.

Fix: catch `SystemExit` around plugin execution in the engine (and wrap the
native runs) and report it as a plugin failure.

Dedupe: searched `sys.exit`, `SystemExit`, `failed while running`; w5/634 (open)
is the importer sibling.

Acceptance: the commands exit 1 with the plugin-failure message, including
for `sys.exit(0)` and `sys.exit(7)`. Tests pin them.
