# Under a currency conversion, quiet interval rows give `{}` / `—` for income and expenses instead of the documented `{"USD": "0"}` / `0.00 USD`

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
The docs promise that a currency conversion "names that currency in every
row". That holds for net profit and net worth, but the income and expense
cells of a month with no activity are an empty object in JSON and a dash in
text. A consumer reading `periods[i]["expenses"]["USD"]` hits a missing key
on quiet months. No numbers are wrong. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Income:Salary USD
2026-01-01 open Expenses:Food USD

2026-01-15 * "Pay"
  Assets:Checking  1000.00 USD
  Income:Salary

2026-03-10 * "Lunch"
  Expenses:Food  10.00 USD
  Assets:Checking
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea --json -f main.bean report income-statement
bea -f main.bean report overview
```

Actual (exit 0): the February period is `{"date": "2026-02-28", "income":
{}, "expenses": {}, "net_profit": {"USD": "0"}}`; January has `"expenses":
{}` and March `"income": {}`. The text overview row for February reads
`2026-02-28  1,000.00 USD  —  —  —`.

Control: in the same output `net_profit` is `{"USD": "0"}`. A worker saw
`net_worth_series` zero-filled as documented, and `-x units` reading `{}`
(the documented per-unit behaviour).

Expected: `docs/USAGE.md`: "A currency conversion names that currency in
every row, so a month with no activity reads `0.00 USD` / `{"USD": "0"}`".

Cause: `cli/src/bea_engine/report.py:212-213` emits the income and expense
balances raw, and `:182-185` sends the overview series through
`_series_json` (`:522-523`); only net profit (`_summary`, `:573-576`) and
net worth (`_summary_series_json`, `:538-554`) zero-fill. The test from
w3/done/373 asserts only `net_profit`.

Fix: under a currency conversion, spell every empty flow and balance cell
`{CUR: "0"}` (text `0.00 CUR`); keep `{}` for `units`, `at_cost` and
`at_value`. Or narrow the doc sentence to net profit and net worth. No
dependency change; JSON cell shape changes.

Blast radius: income-statement `periods[].income/expenses`, the four
overview series, and both text tables.

Dedupe: board search for "names that currency", quiet row/month and
zero-fill finds w3/done/373 (which wrote the rule and fixed net worth) and
w1/done/072 (tree parents); nothing open.

Acceptance: every period in the fixture's income statement has
`"income"` and `"expenses"` keyed by `USD`, and the February overview row
reads `0.00 USD` in the flow columns; `-x units` is unchanged. Only macOS
and the checkout were exercised.

---

**Resolved 2026-10-13** — Under a currency conversion, `cli/src/bea_engine/report.py` now spells an empty interval cell as zero in that currency, so income-statement `periods[].income` / `periods[].expenses` and all four overview series read `{"USD": "0"}` and both text tables read `0.00 USD` for a quiet row, matching the net profit and net worth beside them and the rule in `docs/USAGE.md`. A cell that holds anything keeps exactly what it holds, so an amount the report could not value stays in its source commodity, and `units`, `at_cost` and `at_value` still read `{}` / `—`. The new `cli/tests/test_quiet_flow_cells_name_conversion_currency.py` runs the note's fixture through both reports in JSON and text, plus the per-unit control and an unvalued row; four of its five cases fail with the fix reverted (the per-unit control passes either way). One existing assertion in `tests/test_report_account_filter_series.py` that pinned `{}` for a filtered-out overview expense series was updated to the new spelling. The as-of `totals` of the overview and the report trees are not interval rows and were left as they were. Only macOS was exercised. `make check-all` passed. Shipped in `586315d1` (`cli`).
