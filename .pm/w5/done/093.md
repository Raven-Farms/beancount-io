# A purchase with an omitted cash leg makes every report amount in that currency print the cost's decimals

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, macOS. Human report tables are documented to
round each currency to the precision the ledger uses for it, explicitly not
to the precision of costs or price quotes. One purchase whose balancing leg is
left for Beancount to infer breaks that: the inferred amount carries the
cost's digits, and every figure in that currency is then printed with them.
No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"

2026-01-01 open Assets:Checking USD
2026-01-01 open Assets:Brokerage
2026-01-01 open Expenses:Food
2026-01-01 open Equity:Opening

2026-01-02 * "Opening balance"
  Assets:Checking  5000.00 USD
  Equity:Opening  -5000.00 USD

2026-01-20 * "Grocer"
  Expenses:Food  45.25 USD
  Assets:Checking  -45.25 USD

2026-02-03 * "Buy AAPL"
  Assets:Brokerage  1.5 AAPL {191.559998 USD}
  Assets:Checking

2026-02-10 price AAPL 200.00 USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, and an absolute `--file`.

```sh
bea -f /absolute/books/main.bean balance
```

Actual: exit 0 with `Assets 4,967.4100030 USD`, `Equity -5,000.0000000
USD`, `Expenses 45.2500000 USD`; the balance sheet and income statement
print the same seven decimals on every USD figure. A total-cost purchase with
an omitted leg printed 26 decimals. Repeated twice.

Control: the same ledger with the last leg written out as `Assets:Checking
-287.34 USD` prints `4,967.41 USD` and `45.25 USD`.

Expected: `docs/USAGE.md` Reports — the precision "comes from posting
amounts and balance assertions … not from price quotes or cost numbers, so a
`price AAPL 191.559998 USD` does not make a cents ledger print six
decimals." Every amount written in this ledger is in cents.

Cause: `cli/src/bea_engine/report.py:592-623` (`_display_precision`)
learns from the units of every posting, including the one Beancount
interpolated (marked `__automatic__` in its metadata). That number is units
times cost and carries the cost's digits.

Fix: skip interpolated postings when learning display precision. JSON is
exact already and stays unchanged. No dependency or API change.

Dedupe: w1/052 fixed the same symptom for price directives, with tests that
use an explicit cash leg; w3/304 is the unknown-currency fallback. Board
search for display precision with interpolated or omitted postings finds
nothing else.

Acceptance: the fixture prints the control's figures; `{{total}}` and
`@ price` variants with an omitted leg do the same; a ledger whose written
amounts really use more decimals keeps them. Only macOS and the checkout were
exercised.

---

**Resolved 2026-10-12** — Display precision is no longer learned from an interpolated posting in a currency the ledger itself writes with decimals. The fixture prints the control's figures (`4,967.41 USD`, `-5,000.00 USD`, `45.25 USD`) for `balance`, the balance sheet and the income statement, and the `{{total}}` and `@ price` variants with an omitted leg do the same. `--json` is exact and unchanged. `docs/USAGE.md` Reports states the rule. Shipped in `1b51b7b8` (`cli`).

Deviation from the note's fix, which said to skip interpolated postings outright: the full suite showed that would round real cash. A shipped test from w3/241 (`test_at_value_prices_costless_lots`) expects an inferred `21.0 USD` leg to print in a ledger that otherwise writes whole dollars, and the same rule would turn an inferred 31.5 USD into `32 USD`. So an interpolated leg still counts where the ledger writes that currency only in whole numbers, or not at all. The remaining gap is narrow and unchanged from before: a whole-number ledger with a many-decimal cost and an omitted leg still prints that cost's digits.

Regression tests cover the three lot spellings across three commands, the omitted leg against the written one, a ledger whose written amounts really use four decimals (kept), and the whole-number control (`68.5 USD`). Eleven fail with the fix reverted. `make check-all` passed. Only macOS was exercised.
