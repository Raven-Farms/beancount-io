# `add document --into` a symlinked include judges the document path against the link's target directory, but Beancount resolves it beside the link: a valid receipt next to the include is refused as "outside the ledger directory" (gap in w1/165)

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `87ad7af8`, checkout `bea 0.3.1`, macOS 26.5.1.
A document path in an included file resolves beside that file as named.
Beancount uses the lexical path, and bea's own message says so ("resolve
from …/txns, the directory containing link.bean"). The containment check
computes the holder through `.resolve()`, which follows the include's
symlink to its target directory. No product fix implemented.

`books/main.bean`: `option "operating_currency" "USD"`, `2026-01-01 open
Assets:Checking USD`, `include "txns/*.bean"`. `books/txns/link.bean` is a
symlink to `../../shared/a/b/link.bean` (which opens `Equity:Opening`).
`books/txns/receipt.pdf` exists.

```sh
bea --file main.bean add document --into txns/link.bean --date 2026-02-01 -a Assets:Checking --filename receipt.pdf
```

Actual: exit 2, `Document path 'receipt.pdf' resolves outside the ledger
directory …/books, which bea check refuses…`. Appending the same directive to
the linked file by hand gives `bea check` exit 0.

Also observed by the QA hunter (not reproduced in my layout, where staging
validation refused it): with a different arrangement, a `--filename` that
climbs out of the ledger tree was written with exit 0 and `bea check` then
failed.

Control: `--into txns/2026.bean` (a regular file) with `receipt.pdf` is
accepted.

Expected: add judges the path exactly as `bea check` will, beside the link:
the receipt is accepted, and any path `check` would refuse is refused.

Cause: `cli/src/bea_engine/ledger/adding.py:113` uses `holder =
write.destination(file, into).parent`, and `destination()`
(`cli/src/bea_engine/ledger/write.py:46-48`) calls `.resolve()`.

Fix: compute the holder lexically (`normpath(root.parent / into)`).

Dedupe: w1/165 (done) fixed plain `../`.

Acceptance: the receipt is accepted; a climbing path is refused. A test with
a symlinked include pins both.

---

**Resolved 2026-10-18** — Shipped in `2be5abebe` (`cli`). The document containment precheck computes the destination file's parent lexically, matching Beancount's resolution beside a symlinked include instead of beside the link target. A receipt beside the named include now writes and passes check; climbing paths and receipt symlinks outside the ledger tree are refused before mutation. Six command regressions cover relative and absolute `--into` spellings, accepted receipts, refused paths, preserved source bytes, and preserved include links. Reverting the fix makes both positive cases fail. Twelve focused document tests and `make check-all` passed (7,353 tests, 2 skipped); tracked-content gitleaks passed, while the full-directory scan retained 72 ignored local runtime/build/cache findings.
