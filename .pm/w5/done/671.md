# With a realistic-size encrypted include, doctor still says "Re-save the file as UTF-8" and native `check -v/--json/--auto` says "re-save the file in Unicode NFC"; include globs inside an encrypted file escape the destination guards; `doctor context` at a location in it prints a traceback (incomplete fix of w5/495)

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-17, HEAD `93520860`, checkout `bea 0.3.1`, macOS 26.5.1. Isolated `GNUPGHOME` with a no-passphrase test key. Follow-up to w5/495 (done).
w5/495's fix keeps encrypted members out of `format` and doctor's main text
walks. Other scans still read the ciphertext as text. Random bytes then trip
them depending on the file's size and content: the note's single-transaction
file passes, but a 7.7 KB plaintext encrypted fails 4 times out of 5. No
product fix implemented.

`main.bean`: `include "secret.bean.gpg"` and two opens; `secret.bean.gpg` is
`gpg -e -r <test key>` of a plaintext with about 1,000–3,000 transactions.

```sh
bea doctor print-options /abs/main.bean        # also roundtrip, missing-open, display-context, directories, context
bea -f /abs/main.bean check --json             # also -v, --auto
```

Actual: doctor exits 1 with `Cannot decode '…/secret.bean.gpg' as UTF-8:
invalid start byte at byte 0. Re-save the file as UTF-8 and retry.`; native
check exits 2 with `bea check cannot pass bean-check options (--json) for this
ledger: …/secret.bean.gpg names an account or tag outside Unicode NFC … re-save
the file in Unicode NFC`. Plain `check`, `balance`, `format --check` and `add`
work.

Two related gaps:

- **Globs inside the encrypted file.** When `secret.bean.gpg` itself holds
  `include "more/*.bean"`, `check --cache-filename more/zcache.bean`,
  `BEANCOUNT_LOAD_CACHE_FILENAME=more/envcache.bean bea balance` and `query PRINT
  -o more/backup.bean` all exit 0 and write into the books, breaking the next
  load. The closure walk skips encrypted members' include patterns, and the
  engine snapshot misses them too.
- **Location inside the encrypted file.** `bea doctor context /abs/main.bean
  secret.bean.gpg:2` exits 1 with a Python traceback ending `RuntimeError:
  Parsed entry corresponding to real entry not found in original filename.`
  (upstream re-reads the ciphertext). Refuse with one sentence instead.

Expected: no scan treats ciphertext as text. Encrypted members contribute
their (decrypted) include patterns to the guards, or destinations under
their directories are refused. Doctor operations exit 0 (the note's
acceptance), for any ciphertext.

Cause: `_refuse_undecodable` (`cli/src/cli/commands/doctor.py:196-215`) sends
the ciphertext to the engine `syntax` command; `_closure_needs_compat`
(`cli/src/cli/commands/check.py:301-314`) and doctor's `_needs_compat` /
`_refuse_plugin_failures` decode it; `_walk_closure`
(`cli/src/cli/output.py:485`) skips its include patterns.

Fix: skip `output.is_encrypted(member)` in each text scan; take include
patterns of encrypted members from the loader's decrypted parse (or refuse
destinations below them); refuse doctor locations inside encrypted members.
Test with a large ciphertext.

Dedupe: `encrypt`/`.gpg` match only w5/495 and 499 (done).

Acceptance: the commands above exit 0 on a large encrypted include, the
destination guards refuse paths matched by its globs, and the location case
is a one-line refusal. Tests pin them.

**Resolved 2026-10-18** — Shipped in `373c83e4f11a517123d5c7e3f628318a38183663` (`cli`). Doctor's text/plugin/compatibility scans and native check's BOM/NFC scan skip encrypted members; the engine snapshot retains ciphertext without treating it as include text. Doctor context refuses encrypted locations with one sentence. This implements the note's conservative destination alternative: configured load-cache and output paths beneath an encrypted member's directory are refused because its include patterns cannot be inspected, rather than decrypting them during preflight. Both lexical and resolved ancestry are checked, with query spelling carried alongside the approved resolved target to protect directory symlinks and link retargeting during load. Paths outside that directory remain usable, and CSV sources retain their ordinary input rules. USAGE documents the boundary. Twenty-nine regression/control cases pass, including seven directory-symlink cases that failed on the first implementation; reverting all six production files gives 25 failures and four passing controls. All 84 focused checks passed. A separate real-GPG check of a 108 KB encrypted include passed all 12 doctor/native-check/refusal cases and preserved original bytes; isolated synthetic keys and scratch were removed. `make check-all` passed (7,736 passed, 2 skipped). Tracked-content gitleaks is clean; the required full-directory scan reports the same 72 pre-existing ignored runtime/cache/build matches.
