# `bea query --source 'x$HOME/m.bean'` silently queries the environment-expanded file (another ledger) with exit 0, and `-o` replaces an existing export with a bare header (gap in w5/315 and w5/579)

**Major · cli · 5–10m · A1.** Real CLI QA, 2026-10-17, HEAD `9b822564b`, checkout `bea 0.3.1`, macOS 26.5.1. Gap in w5/315 and 579 (done).
w5/315 and w5/579 refuse a ledger path containing an environment variable
that Beancount would expand, but only for `--file`, `BEA_FILE`, cwd discovery,
`doctor` and `init`. `query --source` goes straight to the native loader.

---

**Resolved 2026-10-20** — the frontend refuses an expanding `beancount:`/plain `--source` with exit 2 before the engine starts, and the engine refuses the path it would really hand the loader; `csv:` sources keep loading literally. Both commands exit 2 naming the variable with the export untouched, shipped in `cc2672dd4` (`cli`).

The directory holds two ledgers:
- `x$HOME/m.bean` (a directory literally named `x$HOME`): one transaction,
  "real".
- `x/Users/<user>/m.bean` (what `x$HOME` expands to): one transaction, "OTHER
  LEDGER".

```sh
bea query --source 'x$HOME/m.bean' 'SELECT narration'
```

Actual: exit 0, printing `OTHER LEDGER`, the other file. `--source
'beancount:x$HOME/m.bean'` does the same. With only the literal file present,
`query --source 'b$HOME.bean' 'SELECT narration' -f csv -o out.csv` exits 0
after `<load>:0: File "…/b/Users/<user>.bean" does not exist`, and replaces
`out.csv` with just `narration` (hunter's run).

Control: `bea -f 'x$HOME/m.bean' query 'SELECT narration'` exits 2 with
`contains an environment variable that Beancount would expand…`.

Expected: the same exit-2 refusal for `--source`, with nothing written. w5/249
also says a `--source` load failure must not exit 0 and replace an export.

Cause: `_require_source_ledger` (`cli/src/cli/commands/query.py:96`) checks
existence and type only. It never calls `refuse_expanding_ledger_path`
(`cli/src/cli/context.py:261`).

Fix: call `refuse_expanding_ledger_path` on `beancount:`/plain `--source` paths.

Dedupe: w5/315 and 579 (done) are the parents; w5/249 (done) covers `-o`
after a failed `--source`.

Acceptance: both commands exit 2 naming the variable, and `out.csv` is
unchanged. A test pins it.
