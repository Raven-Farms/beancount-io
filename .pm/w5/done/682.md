# `add price` / `add balance` still advise `--allow-errors` when the existing error is a `pad` from an unopened account, which the flag cannot write past either (incomplete fix of w5/508)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `db21f706`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/508 (done).
w5/508 stopped the strict pre-checks from advising `--allow-errors` for a
syntax error, which the flag cannot pass. The shared validation also blocks
on pads whose accounts are not active, "even with --allow-errors". The
pre-checks still advise the flag for that error, so the user loops. No
product fix implemented.

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Bank:Checking USD
2024-01-01 open Equity:Opening-Balances
2024-01-01 * "Opening"
  Assets:Bank:Checking 100.00 USD
  Equity:Opening-Balances
2024-02-01 pad Assets:Bank:Checking Equity:Nope
```

```sh
bea -f /abs/pad.bean add price -c EUR --amount "1.10 USD" --date 2024-03-02
bea -f /abs/pad.bean add price -c EUR --amount "1.10 USD" --date 2024-03-02 --allow-errors
```

Actual: the first exits 1 with `The ledger already has 2 error(s); nothing was
written. Pass --allow-errors to write anyway.`; the second exits 1 with `The
change would leave the ledger invalid; nothing was written. … Pad accounts must
be active, even with --allow-errors.` `add balance` behaves the same.

Control: `add note` on the same ledger does not suggest the flag; the
syntax-error case is fixed.

Expected: the refusal names the pad and its unopened account
(`Equity:Nope`), says to open it or fix the pad first, and does not suggest
`--allow-errors`.

Cause: `_preexisting_refusal` (`cli/src/bea_engine/ledger/adding.py:298-308`)
checks only `ParserSyntaxError`/`LexerError`; the shared validation also blocks on
`invalid_pad_accounts` (`cli/src/bea_engine/ledger/write.py:1757-1758`).

Fix: treat an invalid-pad-account error like a syntax error there (share the
helper with `write.py`).

Dedupe: searched `write anyway`, `Pad accounts must be active`; w5/395, 396 and
508 (done) are related.

Acceptance: both commands refuse without suggesting the flag, naming the pad.
A test pins it.
