# Write validation rescans the whole ledger for each "inactive account", unbalanced-conversion and failed-assertion error

**Major for the first case, minor for the others · cli · 30–45m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`),
checkout `bea 0.3.1`, macOS arm64.
Three more per-error hint computations sit in the same validation loop as
w5/112, and unlike it they need no include or sibling ledger. One mis-dated
`open` in a 40,000-transaction ledger makes every `bea add` take 18
seconds to refuse, where `check` reports the same errors in 1.4 seconds.
No product fix implemented.

Generate `/absolute/books/main.bean`: `Assets:Wallet` is opened in 2030
by mistake and used by every fifth transaction.

```sh
python3 -c "
import datetime as d,sys;N=int(sys.argv[1]);f=open('main.bean','w');f.write('2000-01-01 open Assets:Bank USD\n2000-01-01 open Expenses:Food USD\n2030-01-01 open Assets:Wallet USD\n')
f.writelines(f'{d.date(2000,1,1)+d.timedelta(days=i%9000)} * \"t{i}\"\n  Expenses:Food  1 USD\n  Assets:{\"Wallet\" if i%5==0 else \"Bank\"}\n\n' for i in range(N))" 40000
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY.

```sh
bea -f /absolute/books/main.bean add note --account Assets:Bank --comment hi --date 2021-03-01
bea --json -f /absolute/books/main.bean check
```

Actual: `add note` exits 1 with `The change would leave the ledger
invalid; nothing was written.` after 18.4 s at 40,000 transactions and
5.2 s at 20,000 (8,000 and 4,000 errors). `check` exits 1 in 1.4 s.

Control: the same 40,000-transaction file with the open dated 2000 accepts
the note in 2.6 s.

Worker-measured siblings in the same loop (20k / 40k transactions, each
twice; I did not re-run these two):

- Multi-currency "does not balance" errors (every fifth transaction an
  unpriced EUR/USD conversion): 6.5 s / 23.2 s.
- Failed balance assertions (one every tenth transaction): 4.4 s / 15.6 s;
  with `--allow-errors`, which skips that hint, 2.5–3.9 s.

The worker also measured a 50-row CSV import on the 40,000-transaction
fixture at 23.9 s to preview and 44.6 s to apply with `--allow-errors`.

Expected: validation time close to load time, growing linearly with the
error count. A mis-dated `open` or `close` in a migrated ledger is a
realistic source of thousands of these errors; the other two need thousands
of unpriced conversions or failing assertions and are marginal.

Cause: inside the per-error loop of `validate_candidate`
(`cli/src/bea_engine/ledger/write.py:662`): `:705-712` scans every entry
for the account's open and close on each inactive-account error;
`:723-729` rebuilds the held-at-cost set over all postings on each
multi-currency imbalance; `_balance_recovery_hints` (`:404`) re-splits
the source file on each failed assertion. Worker profiles at 20,000
transactions attribute 12.5 of 14.1 s and 13.6 of 15.2 s to the first two.
The close-match suggestion at `:700` also runs per unknown-account error
and is worth memoising per account name.

Fix: before the loop, build the account → open/close index and the
held-at-cost set once, cache split lines per source file, and memoise the
close-match lookup. Do it with w5/112, which is the same loop. No dependency
or API change.

Blast radius: every `add` subcommand, and `import` preview and apply.

Dedupe: board search for `validate_candidate`, inactive account and
quadratic finds w5/112 (`root_ledger_hints` only), w1/135 and w3/323
(message content); none covers these three hints.

Acceptance: the 40,000-transaction fixture is refused in under 4 seconds
with the same message, and each of the three error kinds scales linearly from
10k to 40k transactions. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — Write validation in `cli/src/bea_engine/ledger/write.py` now builds the account open/close index and the held-at-cost index once on first use, counts each source file's lines once, and remembers the close-match suggestion per account name, instead of redoing each for every error. Refusal messages are byte-identical to before. The regression test counts passes over the ledger at 3 and 60 errors for each error kind and requires them to be equal (four cases fail with the fix reverted), and pins the hint wording. On the 40,000-transaction fixture the refusal fell from 44 s to 4–12 s on a heavily loaded machine; the note's "under 4 seconds" clause was not shown reliably. Only macOS was exercised. `make check-all` passed. Shipped in `105fa92b` (`cli`).
