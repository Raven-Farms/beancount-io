# A possible-duplicate reason says "different bank IDs do not rule out a duplicate" for rows that have no bank IDs

**Trivial · cli · 5–10m · A1.** Real CLI QA, 2026-10-16, HEAD `be46147e`, checkout `bea 0.3.1`, macOS 26.5.1.
Two identical rows in one export (two same-day Netflix charges) are correctly
flagged. The stated reason talks about bank IDs that neither row has, which
misleads an agent deciding whether to skip. No product fix implemented.

Ledger opening `Liabilities:CreditCard USD` and `Expenses:Uncategorized USD`;
`n.csv`:

```csv
Date,Description,Amount
10/04/2026,NETFLIX.COM,-15.49
10/04/2026,NETFLIX.COM,-15.49
```

```sh
bea --json --no-input --file /abs/main.bean import n.csv --csv date=Date,narration=Description,amount=Amount --account Liabilities:CreditCard
```

Actual: row 2 is `possible_duplicate` with reason `Date, narration and source
amount match; different bank IDs do not rule out a duplicate.` (`match.row`
is 1).

Expected: a reason that fits, e.g. `Repeats row 1 of this import; neither row
has a bank ID.`

Cause: fixed strings in `cli/src/bea_engine/importing.py:456-461`.

Fix: choose the wording by whether either side has a native ID and whether
the twin is in the batch or the ledger.

Dedupe: none found.

Acceptance: the fixture's reason names the repeated row without mentioning
bank IDs. A test pins it.

---

**Resolved 2026-10-17** — Shipped in `e5ea5a00` (`cli`).
- `_twin_reason` (`cli/src/bea_engine/importing.py`) words a possible duplicate by where its twin is and which bank IDs exist.
- The note's fixture now reads "Date, narration and source amount match row 1 of this import; neither row has a bank ID.". A ledger twin without IDs reads "…match; neither has a bank ID.". Differing IDs read "their bank IDs differ, which does not rule out a duplicate", and one-sided IDs "only one of them carries a bank ID".
- Deviation: the reason keeps the existing "Date, payee/narration and source amount match" opening, which `tests/test_import_possible_duplicate_without_payee.py` pins, rather than the suggested "Repeats row 1 …"; it names the row after it.
- `tests/test_import_twin_reason_ids.py` pins the three cases; all fail without the fix. `make check-all` passed.
