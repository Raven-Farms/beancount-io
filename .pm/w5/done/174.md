# The optional-feature probe imports Python modules from the current directory

**Major · cli · 15–20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
`bea engine status` — and, per a worker, the `price` and `ingest`
commands that check whether an optional engine feature is installed —
run a probe that imports the feature's package by name with the current
directory on Python's import path. A file named `beanprice.py` in the
directory `bea` is run from is therefore executed, and an innocent folder
of that name makes the feature look installed. This is the residual of
w1/done/098, which closed the same hole for the engine helper itself. No
product fix implemented.

In an otherwise empty directory `/absolute/untrusted`, create
`beanprice.py` that appends a line to a marker file in a scratch
directory. Create an empty directory `/absolute/clean`.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY.

```sh
cd /absolute/untrusted && bea --json engine status
cd /absolute/clean && bea --json engine status
```

Actual: from `untrusted`, the command exits 0, the marker file gains a
line, and the JSON reports `"beanprice": {"enabled": false, "present":
true`. From `clean` it reports `"present": false` and no marker is
written.

Control: the `clean` run. A worker saw `bea check` from the same
directory not import the file (the earlier fix holds for the helper),
and — with only an empty `beanprice/` folder in the cwd — `bea price
list` exit 1 advising the user to remove the engine directory, where the
clean directory gives the correct "not enabled; run `bea engine enable
beanprice`".

Expected: w1/done/098's acceptance — a module in the current directory
"is never imported by any engine command"; the code comment in
`cli/src/cli/engine/launch.py` states the same intent.

Cause: `cli/src/cli/engine/provision.py:321-322` runs the engine Python
with `-c "import …"` and no `-P`, so the current directory is first on
the import path. It is reached from the feature availability and status
checks and from `launch.require_feature`.

Fix: pass `-P` (or `-I`) to the probe. A worker noted the same
`[python, "-c", …]` shape in `cli/src/cli/commands/upgrade.py`, by
reading only. No dependency or API change.

Blast radius: `engine status`, the `price` passthroughs, `ingest`, and
`engine enable` verification, whenever run from a directory containing a
file or folder named after an optional package.

Dedupe: w1/done/098 fixed the helper launch only; board search for the
probe function and safe-path finds nothing else.

Acceptance: from a directory containing `beanprice.py`, `bea engine
status` reports `present: false` (when the feature is not installed) and
the file is not executed; the clean-directory output is unchanged. A
real-command regression test covers a file and an empty folder. Only
macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — The optional-feature probe in `cli/src/cli/engine/provision.py` now runs the engine interpreter with `-P`, as the helper launch already does, so the working directory is no longer on its import path: a `beanprice.py` beside the ledger is not executed and an empty `beanprice/` folder no longer makes the feature look installed to `bea engine status`, the `price` passthroughs, `ingest` or `engine enable` verification. The new `cli/tests/test_engine_feature_probe_ignores_cwd.py` runs the real `bea --json engine status` and `bea price list` from a clean directory, a directory holding a marker-writing `beanprice.py` and a directory holding an empty `beanprice/` folder, and asserts the shadowed runs match the clean control (`present: false`, the same exit 2 refusal) and that the marker is never written; all four cases fail with the fix reverted. The test drives the probe through an explicit engine interpreter rather than a managed engine, which shares the same probe function. The similar `-c` child in `cli/src/cli/commands/upgrade.py` that the note mentioned by reading only was left unchanged, since `bea upgrade` could not be exercised. Only macOS was exercised. `make check-all` passed. Shipped in `255d01c3` (`cli`).
