# Import preview prints small amounts in scientific notation (`-5.0E-7 BTC`) in the table and in JSON `amount`

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
An imported amount below one millionth is shown as `-5.0E-7 BTC` in the
preview table's SOURCE AMOUNT column and in the JSON row's `amount` field,
while the diff directly below shows `-0.00000050 BTC`. The written entry is
correct; the displayed value is one `bea` refuses as input. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "BTC"
2026-01-01 open Assets:Wallet BTC
2026-01-01 open Expenses:Uncategorized
```

`/absolute/books/w.csv`:

```csv
Date,Description,Amount
2026-02-01,Network fee,-0.00000050
2026-02-02,Dust sweep,0.00000546
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean import w.csv --csv 'date=Date,narration=Description,amount=Amount' --account Assets:Wallet
bea --json -f main.bean import w.csv --csv 'date=Date,narration=Description,amount=Amount' --account Assets:Wallet
```

Actual: exit 0.

```text
ROW  STATUS  DATE        PAYEE / NARRATION  SOURCE AMOUNT   ID    RULE
1    new     2026-02-01  Network fee        -5.0E-7 BTC     hash  unmatched
2    new     2026-02-02  Dust sweep         0.00000546 BTC  hash  unmatched
```

JSON row 1 has `"amount": "-5.0E-7 BTC"`.

Control: row 2 in the same output prints `0.00000546 BTC`; the diff and the
JSON `entry` text for row 1 print `-0.00000050 BTC`.

Expected: `docs/USAGE.md`: JSON output "spells amounts in fixed-point
decimal notation (`0.00000001`, never `1E-8`) so tiny values can be fed
back into input without losing precision."

Cause: `cli/src/bea_engine/importing.py:964` (`_source_amounts`)
interpolates the number with `str(Decimal)`; the sibling `_exact_amount`
(`:726-742`) already formats fixed-point.

Fix: format with `format(number, "f")`. No dependency or API change.

Blast radius: import preview and apply output, text and JSON, for CSV and
Python importers. A worker noted the same pattern at
`cli/src/bea_engine/query.py:1328`, not triggered.

Dedupe: board search for "scientific", `1E-` and "SOURCE AMOUNT" finds
w1/done/053 (query, balance and report JSON), w5/201 (`add price` and
`add balance` messages) and w3/done/259 (import refusing scientific
input); none covers the preview's amount field.

Acceptance: row 1 shows `-0.00000050 BTC` in the table and in JSON
`amount`. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — The import row's source amount is now formatted fixed-point in `_source_amounts` (`cli/src/bea_engine/importing.py`), so a `-0.00000050 BTC` row reads that way in the preview table's SOURCE AMOUNT column and in the JSON row's `amount` field instead of `-5.0E-7 BTC`, keeping the digits as the source wrote them and matching the diff below. `cli/docs/USAGE.md` now names import row amounts among the JSON output that is spelled in fixed-point notation. The regression test `cli/tests/test_import_source_amount_fixed_point.py` runs the note's CSV import for the text preview, the JSON preview and the JSON `--apply` result, with the `0.00000546 BTC` row as the control; all three cases fail with the fix reverted. The same `str(Decimal)` interpolation in the duplicate-entry summary in `cli/src/bea_engine/query.py` was left alone, as the note did not trigger it. Only macOS was exercised. `make check-all` passed. Shipped in `9d027c8d` (`cli`).
