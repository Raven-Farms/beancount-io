# The shared `add open` recipe fails on any ledger that loads `nounused` (or `pedantic`), and the CLI's documented two-step needs the `--allow-errors` that `bea-cli.md` forbids

**Minor · skills · 15m · A1.** Real CLI QA, 2026-10-16, HEAD `66aeb02e`, checkout `bea 0.3.1`, macOS 26.5.1. Sibling of w5/221.
w5/221 documented the CLI's two-step for these plugins in USAGE and
IMPORTING.md: stage the open with `--allow-errors`, then add the first
transaction. `beancount-init/references/bea-cli.md` still says "Do not use
`--partial` or `--allow-errors` to get an ordinary confirmed batch through a
failed check", with no exception. Every write workflow (import, reconcile,
migrate, options) opens accounts first, so on such a ledger all of them
stop, or an agent breaks the rule without guidance.

```beancount
option "operating_currency" "USD"
plugin "beancount.plugins.nounused"
2026-01-01 open Assets:Bank:Checking USD
2026-01-01 open Expenses:Food USD
2026-01-01 open Equity:OpeningBalances
2026-01-02 * "Opening"
  Assets:Bank:Checking  100.00 USD
  Equity:OpeningBalances
2026-01-03 * "Lunch"
  Assets:Bank:Checking  -10.00 USD
  Expenses:Food
```

```sh
bea --file /abs/main.bean --json --no-input add open --date 2026-01-01 --account Expenses:Uncategorized --into main.bean
```

Actual: exit 1, `Unused account 'Expenses:Uncategorized'` and `This ledger's
nounused plugin reports an account until something uses it. Stage the open
with --allow-errors, then add the account's first transaction.`

Control: `add open … --allow-errors`, then the batch, then `check` → valid.

Expected: `bea-cli.md` documents the carve-out: when it is allowed (an open
refused only for being unused), that the ledger is red until the first
posting lands, and that the workflow must write that posting before stopping
(and how to resume).

Files: `skills/.claude/skills/beancount-init/references/bea-cli.md` (`:53-56`,
`:84-90`); an eval with `nounused`.

Dedupe: `nounused` matches only w5/221 (done, CLI side).

Acceptance: the skill text states the two-step, and a recipe test runs it on
the fixture.

**Resolved 2026-10-17** — Shipped in `07fb2ad9` (`skills`). `beancount-init/references/bea-cli.md` documents the `nounused`/`pedantic` two-step right after the `open` recipe. When a new open is refused only as an unused account, the agent stages it with the new `open-staged` recipe (`--allow-errors`); any other error in the refusal means fix the proposal. In the same workflow it writes the confirmed batch that first posts to the account, without the flag, and runs `check`. The text says the ledger is red for that account alone in between, so the workflow must not stop or report done there, and how to resume if interrupted. The batch paragraph names the staged open as the one exception to "no `--allow-errors`", for the open only.

Tests: beancount-import eval 13 (`nounused-ledger-staged-open`, fixtures `eval13_ledger.beancount`/`eval13_export.csv`) adds the case. `skills/scripts/test_beancount_skills.py::test_a_nounused_ledger_stages_the_open_then_writes_its_first_posting` runs it on a nounused fixture: the refused plain open, the staged open, the red check, the batch, then a passing check. It fails without the recipe.

`ci-check.py`, `test_ci_check.py` and `check-agent-guidance.py` pass, and `test_beancount_skills.py` passes against the checkout's `bea`.
