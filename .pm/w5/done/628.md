# The w5/472 decimal-failure message blames the 12-digit rendering limit for any decimal error and tells `--file` users to use `--file` (incomplete fix of w5/472)

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `83bba7bb`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/472 (done).
w5/472 replaced the `--source` traceback with one line about upstream's
12-integer-digit rendering and advises `--file`. Every `DecimalException`
now gets that line, including ones unrelated to the limit. The `--file`
shell also routes through it, so it suggests the mode it is already in. No
product fix implemented.

`n.bean`:

```beancount
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Fx USD
2026-01-06 * "Bank" "a"
  rate: "nan"
  Expenses:Fx  1.00 USD
  Assets:Cash
2026-01-07 * "Bank" "b"
  rate: "1.25"
  Expenses:Fx  2.00 USD
  Assets:Cash
```

Query Q: `SELECT narration, decimal(entry_meta('rate')) AS rate WHERE account =
'Expenses:Fx' ORDER BY rate`.

```sh
bea query --source /abs/n.bean "Q"
bea -f /abs/n.bean query "Q"
bea -f /abs/n.bean query          # interactive, then type Q
```

Actual: (1) exit 1, `error: Decimal arithmetic failed while running or
printing this query (InvalidOperation). Upstream's rendering holds an amount
to twelve integer digits; query the ledger with --file to print larger ones.`;
(2) the recommended `--file` path exits 1 with `Error: InvalidOperation:
[<class 'decimal.InvalidOperation'>]. Pass --debug…`; (3) the `--file` shell
prints the "query the ledger with --file" line. `max(decimal(…))` behaves the
same.

Expected: the 12-digit advice only for the quantize overflow it describes;
other decimal failures get a neutral sentence (`a NaN or infinite value cannot
be compared or summed; filter it out with WHERE …`); the `--file` path and
shell never suggest `--file`, and the one-shot `--file` path does not print a
bare class name.

Cause: `unexpected_failure` (`cli/src/bea_engine/query.py:813-828`) maps every
`DecimalException` to the overflow text; `_recovering` (`:766`) routes the
`--file` shell through it.

Fix: distinguish the quantize overflow (precision exceeded on render) from
other decimal errors, and word by mode.

Dedupe: searched `InvalidOperation`, `twelve integer`; w5/472 (done) is the
parent.

Acceptance: the three commands give an accurate one-line message. Tests pin
them.

**Resolved 2026-10-17** — Shipped in `0122c05e3` (`cli`). `decimal_failure` in `cli/src/bea_engine/query.py` gives the twelve-digit rendering advice only for a finite amount that `quantize` could not hold, and only on the `--source` path. A NaN or an infinity gets `a NaN or infinite value cannot be ordered, compared or used in arithmetic. Filter it out with WHERE, for example WHERE str(<value>) NOT IN ('NaN', 'Infinity', '-Infinity').` `_compiled` turns the signal into that sentence for the `--file` one-shot, JSON and prompt paths, so none of them prints a bare class name or suggests `--file`. `--source` keeps the raw exception so its `--debug` stack still shows. Tests: `cli/tests/test_query_decimal_failure_wording.py`; `test_query_source_unexpected_failure.py` now expects the narrower "while printing" wording.
