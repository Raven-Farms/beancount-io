# Native `bea check --json` (bean-check's "Output errors as JSON") prints `{"errors": []}` while exiting 1, or nothing at all, when the failure is one of bea's own checks

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-16, HEAD `3f2372e1`, checkout `bea 0.3.1`, macOS 26.5.1.
`bea check --help` lists `--json  Output errors as JSON`, forwarded to
bean-check. bea adds its own findings around bean-check: plugin import
failures before it, portable-document warnings after it, and UTF-8
decoding. These are printed as text on stderr. A script that reads stdout
sees either "no errors" or invalid JSON, while the exit status says the
check failed. No product fix implemented.

(a) `books/main.bean`, with `outside/r.pdf` existing:

```beancount
2024-01-01 open Assets:Cash USD
2024-01-02 document Assets:Cash "../outside/r.pdf"
```

(b) `plug.bean`: `plugin "no_such_plugin_xyz"` and `2024-01-01 open
Assets:Cash USD`.

```sh
bea -f /abs/books/main.bean check --json
bea -f /abs/plug.bean check --json
```

Actual: (a) exit 1, stdout `{"errors": []}`, stderr `Error: …: 1
portable-document warning(s).` plus the detail. (b) exit 1, empty stdout,
stderr `Error: …: 1 plugin(s) failed to load.` A non-UTF-8 byte in a note
string gives (b)'s shape.

Control: upstream `bean-check --json` prints a JSON `errors` list in (b), and
its exit status agrees with it. `bea --json check` (bea's envelope) reports
all three.

Expected: when the forwarded arguments include `--json`, bea's own findings
are emitted in bean-check's JSON shape on stdout (`message`, `filename`,
`lineno`), merged into its list, so stdout and the exit status agree.

Cause: `cli/src/cli/commands/check.py:114` raises plugin failures as text
before bean-check runs; `:131` raises the portable-document warnings after
bean-check printed its clean JSON; `:99-104` re-raises decoding failures as
text.

Fix: in the forwarded path, detect `--json` and render bea's findings in
that shape.

Dedupe: w5/256 (done) covers the text form of plugin failures; w5/005 and
416 cover other forwarders.

Acceptance: both commands print a JSON `errors` list naming the problem and
exit 1. A test pins each.

---

**Resolved 2026-10-16** — Shipped in `c1ed2eff` (`cli`). When bean-check's `--json` is forwarded, `cli/src/cli/commands/check.py` now prints bea's own findings in bean-check's JSON shape (`{"errors": [{"message", "filename", "lineno"}]}`) on stdout and exits 1. That covers a plugin import failure, an undecodable file (`lineno` 0), and a portable-document warning. For the warning, bean-check runs captured and the finding is appended to bean-check's own list, with its stderr passed through. Without `--json` the text forms are unchanged. `tests/test_native_check_json_bea_findings.py` pins the three findings, which fail without the fix, and an ordinary bean-check error.
