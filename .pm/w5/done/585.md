# Ctrl-C in the query shell's pager (`PAGER=less`) leaves `less` running, and it and the shell then split every keystroke; quitting the pager early prints Python `ResourceWarning`s

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-16, HEAD `f29eb957`, checkout `bea 0.3.1`, macOS 26.5.1. Interactive shell on a PTY.
USAGE: Ctrl-C "cancels the current line and returns to `beanquery>`, as under
`bean-query`". bea hands the shell `sys.stdout` itself, so upstream's
conditional pager turns on. Upstream `bean-query` passes Click's stdout
wrapper and never pages. Ctrl-C interrupts the wait on the pager without
ending it, and a broken pipe from `q` is swallowed without closing or
reaping the pager. No product fix implemented.

A ledger with a dozen postings; terminal 6 rows high.

```sh
PAGER=less bea -f /abs/main.bean query
# beanquery> SELECT date, account, position     (result pages)
# Ctrl-C, then type: SELECT count(*)
```

Actual: after Ctrl-C the terminal shows `(interrupted)`, `warning: subprocess
NNNN is still running`, `beanquery> `, with `less` still a live child. Typing
`SELECT count(*)` opens less's `Examine:` prompt and the shell receives
fragments (`error: syntax error`). On a 60,000-transaction ledger, pressing `q`
before the result finishes prints `warning: unclosed file
<_io.TextIOWrapper name=4 …>` and `warning: subprocess NNNN is still running`.

Control: the default `more` exits cleanly on Ctrl-C; `bean-query` in the same
terminal prints all rows without a pager.

Expected: Ctrl-C (and `q`) end the pager and return to a clean prompt, with no
warnings.

Cause: `cli/src/bea_engine/query.py:908` passes `sys.stdout` to the shell;
upstream's `output` property (`beanquery/shell.py`) and
`beancount/utils/pager.py` handle the pager; `query.py:907`'s
`filterwarnings("always")` surfaces the ResourceWarnings.

Fix: on interrupt or broken pipe, terminate and wait for the pager before
returning to the prompt (wrap the pager context), or pass a non-paging
stream as `bean-query` does and document paging as off.

Dedupe: searched `pager`, `PAGER`, `ResourceWarning`, `unclosed file`. No CLI
note.

Acceptance: after Ctrl-C in `less`, no child remains and the next query runs;
`q` mid-result prints no warning. A PTY test pins both.

---

**Resolved 2026-10-17** — Shipped in `e5f626b7` (`cli`). The note's second option: both bea query shells now start with Beanquery's `pager` setting off (`_unpaged` in `cli/src/bea_engine/query.py`), as `bean-query` runs. That covers the ledger shell and the `--source` shell. Upstream turned its conditional pager on only because bea handed it `sys.stdout` itself. With `PAGER=less` on a six-row terminal, a long result now prints whole, the prompt returns, the next command runs and `.exit` ends with 0, with no surviving `less` and no warnings. `.set pager on` still turns the pager on, without this fix's Ctrl-C handling. USAGE says the shell does not page.

`tests/test_query_shell_unpaged.py` drives the session on a PTY. It fails without the fix, hanging in `less` until killed. `make check-all` passed.
