# The inactive-account error tells the user to "Correct the transaction date" when the directive being added is a `note`, `document` or other non-transaction

**Trivial · cli · 5–10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
The inactive-account remedy built by the write path always says
"transaction", whatever directive failed. It also offers `bea init
--date`, which fits only a new ledger. No product fix implemented.

Use a ledger that opens `Assets:Cash USD` on 2026-01-01. Use isolated
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no inherited
BEA_FILE/BEA_TOKEN, and closed stdin.

```sh
bea -f /absolute/books/main.bean add note --date 2025-12-01 -a Assets:Cash -m early
bea --json -f /absolute/books/main.bean add document --date 2025-12-01 -a Assets:Cash --filename docs/r.pdf
```

Actual: exit 1 with `Invalid reference to inactive account 'Assets:Cash'
Account opened 2026-01-01 at …/main.bean:2. Correct the transaction date
or edit that directive; for new books use bea init --date YYYY-MM-DD.`.
Reproduced twice by the hunter (note in text and JSON, document in
JSON) and once by me.

Control: for `add transaction` the same sentence is accurate.

Expected: the remedy names the directive being added ("Correct the note
date"), or says "the date".

Cause: `cli/src/bea_engine/ledger/write.py:1291` (`" Correct the
transaction date or {remedy}; …"`).

Fix: derive the noun from `error.entry`'s type, or say "the date". No
dependency change.

Blast radius: `add note`, `add document`, `add balance`, `add pad` and
`add close` (and bulk rows of those kinds) dated outside the account's
open range.

Dedupe: w5/076 and w5/222 (done) changed this sentence's remedy for
transactions and plugin closes. Neither covers the noun for other kinds.

Acceptance: the note and document cases say "note" and "document" (or
"the date"). The transaction wording is unchanged. A test pins one
non-transaction kind.

---

**Resolved 2026-10-15** — Shipped in `670acb0c`. The inactive-account remedy in `validate_candidate` (`cli/src/bea_engine/ledger/write.py`) now names the directive that failed, from the error entry's type: "Correct the note date …", "Correct the document date …", "Correct the pad date …". It falls back to "directive" when there is no entry. A pad's own padding transaction (flag `P`, at the pad's line) is named "pad" too, so w1/118's one-paragraph refusal for an inactive `--pad-from` source still collapses. Transactions still read "Correct the transaction date …", so the existing pins for w5/076 and w5/222 are unchanged.

`tests/test_inactive_account_names_the_directive.py` pins:
- the note in text and the document in JSON, the note's two commands;
- the transaction control.

The note and document cases fail at the prior HEAD. The `bea init --date` clause is unchanged, since it is still the remedy for new books.
