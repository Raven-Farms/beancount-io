# An overlay is still taken for the ledger's root in its common real forms: a forecast overlay with `plugin "fava.plugins.forecast"`, a Fava overlay that repeats `option "operating_currency"`, any overlay above a per-year leaf, and the unknown-account hint; the wrong balance is written with exit 0 and the true one refused (incomplete fix of w5/578)

**Major · cli · 30–45m · A1.** Real CLI QA, 2026-10-17, HEAD `3fe1ca1ff`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/578 (done, `18c62aa9d`).
USAGE:1015-1017 now says "a Fava or forecast overlay that includes a working
ledger and only adds entries is" not its root. w5/578's acceptance: the 5000
assertion accepted, the 4000 one refused, the rent row new, and no root hint.
The fix handles only a bare overlay. No product fix implemented.

`main.bean`: `option "operating_currency" "USD"`, opens for `Assets:Checking`,
`Expenses:Rent`, `Expenses:Food` and `Equity:Opening`, and a 5000.00 USD
opening.

1. **Forecast plugin.** `forecast.bean` beside it is `plugin
   "fava.plugins.forecast"`, `include "main.bean"`, and `2026-02-01 #
   "Landlord" "Rent [MONTHLY REPEAT 1 TIMES]"` (`Expenses:Rent 1000.00 USD` /
   `Assets:Checking`). The forecast plugin is exactly what a forecast overlay
   needs.
   - From that directory, `bea add balance -a Assets:Checking --amount
     '5000.00 USD' --date 2026-03-01` exits 1 (`… != accumulated 4000.00
     USD`).
   - The same with `'4000.00 USD'` exits 0, `Added 1 balance to
     …/main.bean.`
2. **Fava options.** `books/main.bean` as above, with `fava.bean` in the parent:
   `option "title" "Household"`, `option "operating_currency" "USD"`, `include
   "books/main.bean"` and the `#` rent entry. `bea --file /abs/books/main.bean
   add balance … '4000.00 USD' …` exits 0 after `main.bean is included by
   …/fava.bean; the write goes to …`. Import dedupe against the overlay's
   forecast entry and a failing `--file books/main.bean check` both point at
   `fava.bean` (hunter's runs).
3. **Leaf below the root.** `main.bean` ends `include "2026.bean"`; `2026.bean`
   is `; 2026`; `forecast.bean` is the bare overlay (no plugin, no option).
   - `bea --file /abs/2026.bean add balance … '5000.00 USD' …` exits 1, and
     `'4000.00 USD'` exits 0, written to `2026.bean`.
   - A rent import from `--file 2026.bean` is a `possible_duplicate` of
     `forecast.bean`'s entry, with `written: 0` (hunter's run).
4. **Hint.** With the bare overlay, `bea add transaction Cafe … -p
   'Expenses:Fodo 5.00 USD' -p Assets:Checking` advises `Run against the root
   and pick the destination with --into: bea --file …/forecast.bean <command>
   --into main.bean.` Following that re-creates the original w5/578 failure.

Control: the original w5/578 fixture (bare overlay beside the root) now
refuses 4000 and accepts 5000.

Expected: in every case `main.bean` (or the leaf under it) is validated and
deduplicated against `main.bean`'s own closure, and no hint names the overlay.

Cause (`cli/src/bea_engine/ledger/write.py`):
- `_DEFINITION`/`defines_for` (`:1414-1435`) count any `plugin` line, and any
  option except `title`/`render_commas`, in the includer, even one the
  included file already sets.
- `top_root` (`:1392`) climbs past the nearest includer to the topmost one,
  so `defines_for(leaf, top)` sees `main.bean`'s opens in the overlay's
  closure.
- `root_ledger_hints` (`:1479`) uses `including_root` with no `defines_for`
  check.

Fix: count an includer as root only when the file needs it, ignoring
plugins and options the file already sets. Check at each step of the climb
and stop below an overlay. Apply the same test in `root_ledger_hints`.

Dedupe: w5/578 (done) is the parent; w5/662 (open) is a different forecast
dedupe issue.

Acceptance: all four fixtures behave like the bare-overlay control. Tests pin
the plugin, option and leaf shapes.
