# A split ledger under a directory with a decomposed (NFD) name: `--allow-errors` refuses every write and errors name vanished staging files

**Major · cli · 45–60m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS (APFS).
When any directory on a split ledger's path is spelled in decomposed
Unicode, a pre-existing error in an included file is treated as newly
introduced by every write. `--allow-errors` cannot get past it, and the
diagnostic names a `.bea-*.tmp` file that no longer exists. The same ledger
under the composed spelling works. No product fix implemented.

Create a directory `/absolute/Buchführung` whose `ü` is `u` followed by
U+0308 (bytes `75 cc 88`). In it, `main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Equity:Open USD
2024-01-01 open Expenses:Food USD
include "y2024.bean"
```

`y2024.bean`:

```beancount
2024-01-05 * "open"
  Assets:Cash  100 USD
  Equity:Open
2024-03-01 balance Assets:Cash  999 USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY.

```sh
bea -f /absolute/Buchführung/main.bean add transaction --into y2024.bean --date 2024-02-07 --narration lunch -p "Expenses:Food 3 USD" -p "Assets:Cash" --allow-errors
```

Actual: exit 1, file unchanged.

```text
Error: The change would introduce 1 new ledger error(s); nothing was written.
  /absolute/Buchführung/.bea-a13f5c94cce58189.tmp:4: Balance failed for 'Assets:Cash': expected 999 USD != accumulated 97 USD (902 too little)
```

Control: the identical fixture in a directory spelled with precomposed
U+00FC exits 0, adds the transaction and prints the assertion as a warning
at `y2024.bean:4`.

A worker additionally observed, on the NFD directory only: the same refusal
when writing to the root file; `add price --into` a not-yet-existing file
accepting `12 USD` for a date that already has `10 USD` in another include
(exit 0, where the NFC control exits 2 "already has … refusing"); and an
ASCII root with an NFD-named subdirectory naming `.bea-….tmp` in errors.

Expected: `docs/USAGE.md` offers `--allow-errors` for "a semantic error
already in the books, such as a balance assertion that still fails", and
diagnostics should name the user's files. The spelling of a parent
directory must not change whether a write is accepted.

Cause: `cli/src/bea_engine/compat.py` NFC-normalizes the whole text of
every parsed file, including the absolute include paths `bea` itself writes
into staged copies (`ledger/write.py`, `managed_load.py`). Beancount then
reports included files under NFC-spelled paths, while the map-back tables
(`filenames`, `_error_key`, `_remap_entry`/`_remap_error`) are keyed by the
on-disk NFD spelling and miss, so before/after error keys differ and the
staging name leaks.

Fix: keep normalization away from the paths `bea` injects, or compare and
map paths by a normalization-insensitive key (NFC of the normalized path,
or file identity). No dependency or API change.

Blast radius: every validating writer (`add *`, `add transactions`,
`import --apply`) on a split ledger with a decomposed path component —
plausible on macOS with older volumes and some sync tools. Single-file
ledgers and NFC paths are unaffected. Behaviour on normalization-sensitive
filesystems was not tested.

Dedupe: board search for NFD, decomposed and normalization with include,
directory and staging finds w5/097 (the `--into` argument spelled in
another form), w5/096 (`..` in include paths — same symptom family,
different trigger), w1/135 (staged paths in messages, done) and
w5/done/009 (NFD account names); none covers NFD path components.

Acceptance: the NFD fixture behaves exactly like the NFC control for the
command above, for a root write, and for `add price` conflict detection; no
message contains `.bea-`. Real-command regression tests create the
directory with an explicit NFD name. Only macOS and the checkout were
exercised.

---

**Resolved 2026-10-13** — The engine's parser shim in `cli/src/bea_engine/compat.py` still reads ledger text as NFC, but now puts every parsed include target back in the spelling the file has it in, so the loader opens and reports included files under their on-disk names and the absolute paths `bea` writes into staged copies survive a decomposed directory component. That is the note's first suggested fix, applied to all include targets rather than only the injected ones, which also covers an ASCII root with an NFD-named subdirectory reached by a literal or glob include; the map-back tables in `ledger/write.py` and `managed_load.py` are unchanged. The new `cli/tests/test_write_under_decomposed_directory.py` runs real commands against directories created with an explicit NFD name and an NFC control: `add transaction --allow-errors` into the included file and into the root, a refused write without the flag, and `add price --into` a new file conflicting with a quote in another include, each asserting the user's `y2024.bean:4` is named and no message or leftover file contains `.bea-`. With the source change reverted 10 of its 16 cases fail, and the 6 that pass are the NFC controls and the price case under the subdirectory layouts. `import --apply` shares the same validation path but was not exercised separately, and a normalization-sensitive filesystem was not tested. Only macOS was exercised. `make check-all` passed. Shipped in `0cb456dc` (`cli`).
