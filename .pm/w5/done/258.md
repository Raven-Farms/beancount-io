# With stdout closed, `format`, `doctor` and `query --source` exit 1 with `'NoneType' object has no attribute 'write'`

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
w1/done/107 made commands survive a closed standard output (`>&-`, as some
schedulers and service managers start jobs). The fix guarded one shared
function; several commands write to stdout directly and still fail with a
raw attribute error. No write is involved. No product fix implemented.

Create disposable `/absolute/books/m.bean`:

```beancount
2024-01-01 open Assets:Bank USD
2024-01-01 open Expenses:Food USD
2024-01-02 * "x"
  Expenses:Food 1 USD
  Assets:Bank
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`. Run each command with file descriptor 1 closed in the child.

```sh
bea format /absolute/books/m.bean >&-
bea doctor lex /absolute/books/m.bean >&-
bea query --source /absolute/books/m.bean "SELECT account" >&-
```

Actual: each exits 1 with `Error: 'NoneType' object has no attribute
'write'`.

Control: the same commands with `>/dev/null` exit 0, and `bea --file
m.bean list open >&-` exits 0. A worker saw `doctor context`, `treeify`
and `example` fail the same way.

Expected: w1/done/107: "no raw `AttributeError` reaches the user"; the
commands should behave as `list`, `query` and `report` do.

Cause: unguarded `sys.stdout.write` at
`cli/src/cli/commands/format.py:519`, `doctor.py:192` and `:302`,
`treeify.py:143`, `example.py:45` and `cli/src/cli/engine/launch.py:560`;
the 107 fix guarded only `_settle_stdout` (`cli/src/cli/main.py:69-71`).

Fix: one shared "write to stdout if it exists" helper used at these
sites. No dependency or API change.

Blast radius: `format` to stdout, the `doctor` operations, `treeify`,
`example`, `query --source`. The closed-stderr twins were not run.

Dedupe: board search for "has no attribute 'write'" and `>&-` finds only
w1/done/107 and w3/done/378 (closed pipe).

Related (a worker's observation, 2026-10-12, not re-run): the closed-stderr
twin. `bea query --source main.bean "SELEC" 2>&-` exits 1 instead of 2
with the same `'NoneType' … 'write'` message, and a query on a ledger with
errors prints its answer and then exits 1; cause
`cli/src/cli/engine/launch.py:562`.

Acceptance: the three commands exit 0 (or fail with a clear message) with
stdout closed; the `/dev/null` control is unchanged. Only macOS and the
checkout were exercised.

---

**Resolved 2026-10-13** — A new `replay` helper in `cli/src/cli/output.py` writes a child's captured output only when the target stream exists, and `doctor` (both replay paths and its flush), `treeify`, `example` and the captured branch of `_spawn` in `cli/src/cli/engine/launch.py` (behind `query --source`) now use it instead of calling `sys.stdout.write` / `sys.stderr.write` directly. `bea format` to stdout had already been fixed through `write_data` and is pinned here as well. Because the same lines wrote stderr, the closed-stderr twin on that path is fixed too: `bea query --source m.bean "SELEC" 2>&-` exits 2 again; other closed-stderr behaviour was not examined. `cli/tests/test_closed_stdout_replayed_output.py` runs `format`, four `doctor` operations, `query --source`, `treeify` and `example` with stdout closed and with stdout open as the control, plus a roundtrip of unparseable books and two closed-stderr queries; 9 of its 19 cases fail with the fix reverted. Only macOS was exercised. `make check-all` passed. Shipped in `773ac93e` (`cli`).
