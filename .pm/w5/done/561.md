# `query -f csv` drops a lot's date and label from a `position.cost` column, so two lots print as identical `100 USD` cells (gap in w5/465)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `7898f69d`, checkout `bea 0.3.1`, macOS 26.5.1. Differential run against upstream `bean-query`.
w5/465 made CSV positions keep the cost date and label. A bare `Cost` value
(`position.cost`, `cost(position)` via attribute access) goes through the
generic number-and-currency branch instead. No product fix implemented.

`cost.bean`:

```beancount
2026-01-01 open Assets:Brk HOOL
2026-01-01 open Assets:Cash USD
2026-01-03 * "Buy A"
  Assets:Brk  10 HOOL {100 USD, 2026-01-03, "lotA"}
  Assets:Cash  -1000 USD
2026-01-06 * "Buy B"
  Assets:Brk  10 HOOL {100 USD, 2026-01-06, "lotB"}
  Assets:Cash  -1000 USD
```

```sh
bea --file /abs/cost.bean query -f csv "SELECT date, position.cost WHERE account = 'Assets:Brk'"
```

Actual: exit 0, rows `2026-01-03,100 USD` and `2026-01-06,100 USD`.

Control: `bean-query -f csv` gives `" 100 USD, 2026-01-03, ""lotA"""`; bea's
text and `--json` keep date and label; `SELECT date, position` in CSV gives
`10 HOOL {100 USD, 2026-01-03, "lotA"}`.

Expected: CSV renders the cost with its date and label, as USAGE says CSV
cells hold values "as bean-query writes them".

Cause: `_csv_from_jsonable` (`cli/src/bea_engine/query.py:1500-1501`) renders
a dict with number and currency as `number currency`; `_csv_cost` is used only
inside the `"units"` branch (`:1494-1498`).

Fix: render a dict that carries `date`/`label` through `_csv_cost`.

Dedupe: w5/465 (done) fixed positions only.

Acceptance: the command prints both lots' dates and labels. A test pins it.

---

**Resolved 2026-10-17** — Shipped in `687e1b19` (`cli`). In `cli/src/bea_engine/query.py`, `_csv_from_jsonable` renders a number-and-currency dict that carries a `date` or `label` (a bare `Cost`, as `position.cost` gives) through `_csv_cost`. `_csv_cost` now writes the amount itself rather than recursing. The note's query prints `"100 USD, 2026-01-03, ""lotA"""` and `"100 USD, 2026-01-06, ""lotB"""`, and plain amounts and cost-less cells are unchanged. `tests/test_query_csv_lot_cost.py::test_a_bare_cost_column_keeps_each_lots_date_and_label` pins the three lots (one with an escaped label) and the cost-less control; it fails without the fix. `make check-all` passed.
