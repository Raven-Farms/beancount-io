# `add price` and `init --opening-balance` refuse comma-grouped numbers (`65,432.10 USD`) that `add balance`, `--posting` and stock Beancount accept

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Same class as [213](./213.md), different code path.
A price pasted from a quote page, `65,432.10 USD`, is refused by `add
price` as an invalid amount, while `add balance` and `add transaction
--posting` accept the same grouping and write it ungrouped. The frontend's
own number check has no grouping form; the other commands hand the text to
Beancount's parser. Clear error, nothing written. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Assets:Coin BTC
2026-01-01 open Equity:Opening
2026-01-01 commodity BTC
2026-01-02 * "Opening"
  Assets:Cash        70000.00 USD
  Equity:Opening
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean add price --date 2026-03-01 -c BTC --amount '65,432.10 USD'
bea --no-input init ./nb --currency USD --date 2026-01-01 --opening-balance 'Assets:Checking 1,000.00'
```

Actual: both exit 2 and write nothing.

```text
Error: Invalid amount '65,432.10'. Use finite decimal notation with ASCII digits, such as '1538.25'.
Error: Invalid value: Invalid amount '1,000.00'. Use finite decimal notation with ASCII digits, such as '1538.25'.
```

Control: `bea -f main.bean add balance --date 2026-03-01 -a Assets:Cash
--amount '70,000.00 USD'` exits 0 and writes `balance Assets:Cash
70000.00 USD`. `add price … --amount '65432.10 USD'` exits 0. A file
containing `2026-03-01 price BTC 65,432.10 USD` passes stock `bean-check`.
A worker saw `add custom --value 'number:1,500'` refused the same way and
`--posting '… @ 65,432.10 USD'` accepted.

Expected: `docs/USAGE.md` lists the refused number spellings as exponents,
underscores and non-ASCII digits; comma grouping is not among them, and
sibling commands accept it. Either accept it everywhere or say "remove the
thousands separators".

Cause: `cli/src/cli/amounts.py:16-29` (`parse_decimal_number`) has no
grouping alternative; it is reached from `add price`
(`cli/src/cli/commands/add.py:339`), `add custom` (`:463-467`) and
`init --opening-balance` (`cli/src/cli/commands/init.py:63-68`), while
`add balance` and postings go through Beancount's grammar
(`cli/src/bea_engine/ledger/adding.py:495-513`, `:647-649`).

Fix: accept well-formed grouping in `parse_decimal_number` and strip the
commas, keeping the other refusals; mirror the change in
`cli/src/bea_engine/amounts.py:16-22`. Or document the restriction and
make the error name the separators. No dependency change.

Blast radius: `add price`, `add custom` (`number:`, `amount:`),
`init --opening-balance` and its interactive prompt.

Dedupe: w5/213 is the bulk two-token shorthand (a different function);
w3/done/256, w5/255 and w5/265 are CSV import cells. None names these
commands.

Acceptance: the two commands write `price BTC 65432.10 USD` and an opening
balance of `1000.00`, or exit 2 with a message that names the thousands
separators; the controls are unchanged. Only macOS and the checkout were
exercised.

---

**Resolved 2026-10-13** — `parse_decimal_number` in `cli/src/cli/amounts.py`, and its engine twin in `cli/src/bea_engine/amounts.py`, now read comma grouping exactly as Beancount's grammar does for `add balance` and `--posting` (groups of three digits, dropped from the result), so `add price --amount '65,432.10 USD'` writes `price BTC 65432.10 USD`, `init --opening-balance 'Assets:Checking 1,000.00'` and its interactive prompt record `1000.00`, and `add custom` reads `number:1,500` and `amount:-2,000,000.50 USD`. Any other comma (`65,43`, `12,34,567`) still exits 2 and writes nothing, now with a message that names the thousands separators and the decimal point. Structured bulk JSON fields (`units.number`, tagged `number`/`amount` metadata) keep their documented no-grouping rule through an explicit `grouping=False`, and `cli/docs/USAGE.md` states the new flag behaviour. The regression test `cli/tests/test_flag_numbers_read_comma_grouping.py` covers the three commands, the prompt retry, the direct engine init path, both parsers' agreement, and the controls (plain price, grouped `add balance`, the other refused spellings, structured bulk numbers); 22 of its 30 cases fail with the source change reverted. As in Beancount, a zero-led group such as `0,125` reads as `125`, matching the sibling commands rather than the stricter CSV import rule. Only macOS was exercised. `make check-all` passed. Shipped in `38dafbec` (`cli`).
