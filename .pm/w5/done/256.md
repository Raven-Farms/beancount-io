# Plain `bea check` still prints a Python traceback for a broken `plugin` line (w3/done/359's own reproduction)

**Minor · cli · 30–40m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Owner call: text-mode `check` forwards stock `bean-check`.
w3/done/359 was closed with "a broken `plugin` directive reports the plugin
name, file, line, and cause with no traceback". That holds for `--json
check`, `list`, `balance` and writes, but not for the note's own command,
plain `bea check`, which forwards to stock `bean-check` and shows its
traceback at `<load>:0`. No product fix implemented.

Create disposable `/absolute/books/missing.bean`:

```beancount
option "operating_currency" "USD"
plugin "nonexistent_plugin_xyz"
2026-01-01 open Assets:Cash USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea --file missing.bean check
```

Actual: exit 1, eleven stderr lines:

```text
<load>:0: Error importing "nonexistent_plugin_xyz": Traceback (most recent call last):
    File ".../beancount/loader.py", line 688, in run_transformations
    …
  ModuleNotFoundError: No module named 'nonexistent_plugin_xyz'
```

Neither the ledger file nor the line is named.

Control: `bea --json --file missing.bean check` reports
`/absolute/books/missing.bean:2: Cannot import plugin
"nonexistent_plugin_xyz": ModuleNotFoundError: No module named
'nonexistent_plugin_xyz'. Check the name is spelled right and the plugin is
installed.` `bea --file missing.bean list open` prints the same one-line
form. A worker saw a plugin with a bad config string do the same in both
modes.

Expected: w3/done/359: "One/two-line plugin failure (name + terminal
exception); full traceback only under `--debug`", for the command the note
itself reproduces with.

Cause: `cli/src/cli/commands/check.py:64` runs stock `bean-check` for
text-mode check; only closures flagged by `_closure_needs_compat` (`:115`)
go to the helper that formats plugin failures. The fix commit changed only
helper paths, and its test covers `--json check` only.

Fix: have text-mode `check` report a failed plugin as `FILE:LINE: Cannot
import plugin "X": <cause>` (for example by routing a closure whose load
reports a plugin failure through the helper), with the traceback only
under `--debug`; add a text-mode case to the plugin-failure tests. If
upstream formatting is accepted for plain `check`, record that on the
closed note instead.

Blast radius: plain `bea check` on a ledger with a missing or failing
plugin. `doctor` operations were not probed.

Dedupe: board search for "Error importing", plugin with traceback, and
`w3/359` finds w3/done/359 (closed) and w5/084 (bundled `fava.plugins.*`
missing from the native path, a module-path gap whose acceptance does not
ask for traceback removal).

Acceptance: the command prints one or two lines naming `missing.bean:2`,
the plugin and the cause, with no traceback; `--json check` is unchanged.
Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — Plain `bea check` now reports a `plugin` line that cannot be imported, or whose plugin raises while running, as `FILE:LINE: Cannot import plugin "NAME": CAUSE` under one `Error:` line and exits 1, instead of forwarding bean-check's traceback at `<load>:0`. The helper pass that already loads the ledger before bean-check (`check --documents-only` in `cli/src/bea_engine/main.py`) now answers the plugin failures, and `cli/src/cli/commands/check.py` raises them before bean-check runs; `bea --debug check` still runs bean-check as is and keeps its traceback, and `--json check` is unchanged. With no bean-check options the ledger's other load errors are listed beside the plugin line, as `--json check` lists them; with options such as `-v` or `--auto`, which can change those errors, only the plugin failures are listed, a choice the note left open. `cli/tests/test_check_text_plugin_failure.py` covers the note's command, a second load error, `-v` and `--auto`, a plugin that raises, `--debug`, `--json`, and ledgers without a failed plugin keeping bean-check's own output; five of its eight cases fail with the fix reverted. `cli/docs/USAGE.md` and the helper README describe the behaviour. Only macOS was exercised. `make check-all` passed. Shipped in `5ed166fd` (`cli`).
