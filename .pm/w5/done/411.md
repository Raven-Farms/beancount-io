# A failed load-cache write leaks Beancount's raw `WARNING:root:Could not write to picklecache file …` line to stderr

**Trivial · cli · 5–10m · A2.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
On ledgers slow enough to be cached, upstream's loader logs a cache-save
failure through the root logger. bea installs no handler for it, so a
read on a full disk prints Python logging output. The read itself
correctly succeeds, and a read-only cache directory prints nothing. No
product fix implemented.

The hunter used a 40k-transaction ledger, large enough to load in more
than a second so the pickle cache is written. Isolated
BEA_CONFIG_DIR/XDG_CACHE_HOME and closed stdin. A file-size limit stands
in for a full disk.

```sh
( trap "" XFSZ; ulimit -f 1; bea -f /absolute/B/main.bean balance )
```

Actual: exit 0 with correct output. stderr carries
`WARNING:root:Could not write to picklecache file
…/cache/bea/load-cache/<hash>.main.bean.picklecache: [Errno 27] File too
large`. A 512-byte partial pickle is left behind, and it is rebuilt
correctly on the next run. Reproduced twice by the hunter. I did not
re-run it, because it needs the large fixture.

Control: a read-only `load-cache` directory gives exit 0 with no warning.

Expected: silence, as in the read-only case, or bea's own warning
format. Never a `WARNING:root:` line.

Cause: upstream `beancount/loader.py` logs the cache-save failure through
the root logger. bea's cache setup (`cli/src/bea_engine/ledger/write.py:340-364`,
`keep_load_cache_private`) does not configure that logger.

Fix: silence or translate the `beancount.loader` warning, or check
writability before the load. No dependency change.

Dedupe: w3/390, w5/111, w5/175, w5/312 and w5/326 cover cache location,
poisoning, permissions and invalidation. None covers this log line.

Acceptance: under the limit, `balance` prints no `WARNING:root:` line.
A test simulates a failing cache write.

Addendum (CLI QA r70, 2026-10-14, same HEAD): this has a read-side twin.
When a load-cache pickle that bea marked as its own is corrupt, upstream
prints `ERROR:root:Cache file is corrupted: invalid literal …;
recomputing.` to stderr, then exits 0 and heals. It was reproduced twice
via `BEANCOUNT_LOAD_CACHE_FILENAME` inside the run directory. The same
logger configuration should silence or translate it. 417 has the
`check --cache-filename` variant.

---

**Resolved 2026-10-15** — the engine now adds `_quiet_cache_logs` to the
root logger once, alongside its private-cache setup
(`keep_load_cache_private` in `cli/src/bea_engine/ledger/write.py`). It
drops the four messages Beancount's loader logs about its cache: a
corrupted cache, a cache it could not remove, a cache it could not
write, and an ignored cache filename. That matches the silence of the
read-only-directory case. Every other log record, a plugin's
`logging.warning` included, still reaches stderr. A read whose cache
write fails (simulated by a cache path in a missing directory, standing
in for a full disk) exits 0 with no `picklecache` line. Pinned by
`cli/tests/test_load_cache_logs_quiet.py`, which fails without the fix.
This covers engine loads; native bean-check runs keep upstream's own
lines (see 417).
