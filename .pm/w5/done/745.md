# `bea ask` reply handling: a partial answer ending in `finish_reason: "content_filter"` prints as complete with exit 0; a 200 labelled gzip but not gzipped is sent three times, then reported as "Could not reach the server"; and a wrong-typed field prints a raw Pydantic warning (incomplete fix of w5/546 and w5/547)

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-17, HEAD `15b5e52f4`, checkout `bea 0.3.1`, macOS 26.5.1. Simulation: a local AI-proxy stub with a fake token. Follow-up to w5/546 and 547 (done).
No product fix implemented.

All cases use `bea -f /abs/main.bean ask q --print </dev/null`.

1. **Content filter.** The stub answers `Your January spending was 1` with
   `finish_reason: "content_filter"`. The command exits 0, prints the partial
   text, and leaves stderr empty. USAGE:1815-1817 and w5/546 say that part of
   an answer must not print as the whole answer. Control: `length` gets the
   cut-off notice and exit 1. Cause: `cut_off` (`cli/src/cli/ask/agent.py:129-133`)
   checks only `"length"`.
2. **False gzip.** A valid completion body with `Content-Encoding: gzip` but no
   compression exits 1 with `Error: Could not reach the server
   (ModelAPIError).`. The stub logged three POSTs, so a real proxy would bill
   the question three times. USAGE:324-327 says an unreadable 2xx gives
   `Unexpected server response (HTTP 200).` Cause: the SDK retries
   `httpx.DecodingError` as a connection error, and `_unreachable` (`:261`)
   looks only for `TransportError`.
3. **Pydantic warning.** A completion with `"created": 1700000000.5` exits 1,
   and stderr begins
   `…/site-packages/pydantic/main.py:475: UserWarning: Pydantic serializer
   warnings: …` before the CLI's sentence. w5/427 treated a leaked Python
   warning as a bug.

Expected:
1. The cut-off notice (with its own wording) and a non-zero exit.
2. One request, and the unexpected-response sentence.
3. Only bea's sentence.

Fix:
1. Treat `content_filter` with partial text as cut off.
2. Map a `DecodingError` in the cause chain to the unreadable-reply error,
   without retrying.
3. Capture warnings around the model call.

Dedupe: w5/546 and 547 (done) are the parents; w5/679 (open) covers 3xx
redirects.

Acceptance: the three stub cases behave as expected. Tests pin each.
