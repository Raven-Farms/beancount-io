# A relative `BEA_CONFIG_DIR` resolves against each working directory, scattering state

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
`BEA_CONFIG_DIR=relstate` is taken relative to wherever `bea` is run, so
each working directory gets its own `relstate/` and remembered importer
settings are found only from the directory that wrote them. Relative
`XDG_*` values are documented as ignored for exactly this reason. No
product fix implemented.

Create disposable `/absolute/rel/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Equity:Open USD
```

`/absolute/rel/bank.csv`:

```csv
Date,Description,Amount
2026-02-02,Grocer,-2.00
```

and empty directories `/absolute/cwdA` and `/absolute/cwdB`. Use
`BEA_CONFIG_DIR=relstate`, isolated XDG_CACHE_HOME,
BEA_NO_UPDATE_NOTIFIER=1, no inherited BEA_FILE/BEA_TOKEN, closed stdin.

```sh
cd /absolute/cwdA && bea -f /absolute/rel/main.bean import /absolute/rel/bank.csv --account Assets:Checking
cd /absolute/cwdB && bea -f /absolute/rel/main.bean import /absolute/rel/bank.csv --account Assets:Checking
cd /absolute/cwdA && bea -f /absolute/rel/main.bean import /absolute/rel/bank.csv --account Assets:Checking
```

Actual: all exit 0. The first two print `Read the column mapping from the
header row`; the third prints `Using remembered settings for bank.csv`.
Both `/absolute/cwdA/relstate` and `/absolute/cwdB/relstate` now exist.

Control: a worker confirmed an absolute `BEA_CONFIG_DIR` shares state
across directories and a relative `XDG_CONFIG_HOME` is ignored.

Expected: `docs/USAGE.md` says a relative XDG value "is ignored", and the
code comment gives the reason: state would scatter across working
directories. `BEA_CONFIG_DIR` should be refused (exit 2 naming the
variable) or ignored the same way, and the choice documented.

Cause: `cli/src/cli/config.py:30-32` returns `Path(override).expanduser()`
with no absolute-path check.

Fix: require an absolute value. No dependency or API change.

Blast radius: importer memory here; by reading, credentials, history and
the update-check cache follow the same directory, so a relative value
could place them inside a project tree.

Dedupe: board search for `BEA_CONFIG_DIR` with relative finds nothing.

Acceptance: a relative `BEA_CONFIG_DIR` exits 2 naming the variable, or
is ignored with a note, and no `relstate/` directory is created. Only
macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — A relative `BEA_CONFIG_DIR` is now a usage error: `config_dir()` in `cli/src/cli/config.py` refuses a value that is not absolute after `~` expansion, exiting 2 with a message naming the variable, and the root callback in `cli/src/cli/main.py` checks it for every command so the result does not depend on whether a command happens to touch per-user state. Refusal was chosen over ignoring the value as the XDG variables do, because the variable is bea's own and a silent fallback would put credentials somewhere other than where the user pointed; `cli/docs/USAGE.md` records the rule. `bea --help` and `bea --version` still answer, the latter because the update-cache read in `cli/src/cli/update.py` treats the refusal as "no cache"; a subcommand's own `--help` is refused like the command itself. The regression test `cli/tests/test_config_dir_relative_refused.py` runs the note's import from two working directories and asserts exit 2, the variable named in text and `--json` errors, no `relstate/` directory created, and the absolute-path control sharing remembered importer settings across directories; four of its six cases fail with the fix reverted. Only macOS was exercised. `make check-all` passed. Shipped in `da244950` (`cli`).
