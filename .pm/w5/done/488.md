# The w5/363 currency-widen hint drops the account's booking method from the open it suggests, and suggests widening a card account for a leg the user never priced

**Minor · cli · 20–30m · A1/A2.** Real CLI QA, 2026-10-16, HEAD `7334a32b`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/363.
w5/363 added a hint for a posting in a currency its account does not allow:
"edit that open to '…'". It has two problems. No product fix implemented.

1. **The suggested line drops the booking method.** `main.bean`:

   ```beancount
   option "operating_currency" "USD"

   2026-01-01 open Assets:Broker USD "FIFO"
     institution: "Acme"
   2026-01-01 open Assets:Cash USD
   ```

   `bea -f /abs/main.bean add transaction Buy --date 2026-01-05 -p
   'Assets:Broker 2 HOOL {10 USD}' -p 'Assets:Cash'` exits 1 with `edit that
   open to '2026-01-01 open Assets:Broker USD,HOOL'`. Pasting it silently
   changes lot matching from FIFO to the default; `list open` then shows
   `booking: None`.

2. **The hint fires for an amount-less leg.** On a ledger from `bea
   --no-input init books -c USD --date 2026-01-01 --opening-balance
   'Assets:Checking 500'`, `bea -f books/main.bean add transaction Dinner
   --date 2026-01-05 -p 'Expenses:Dining 45 EUR' -p 'Liabilities:CreditCard'`
   exits 1 with `Liabilities:CreditCard is opened … for USD only. To post EUR
   there, edit that open to '2026-01-01 open Liabilities:CreditCard USD,EUR'…`.
   The user never wrote EUR for the card: Beancount inferred it. This is the
   foreign card charge w5/363 was about, and the useful advice is a price,
   `-p 'Expenses:Dining 45 EUR @ RATE USD'`, which the explicit-amount case
   already gives (`For a currency exchange, use a price annotation…`).

Expected: (1) the suggested line keeps the booking string (`USD,HOOL
"FIFO"`); (2) for an interpolated leg, the hint names the price annotation
on the priced leg instead of widening the account.

Cause: `cli/src/bea_engine/ledger/write.py:2059` builds the line from
`opened.currencies` only; `write.py:1728-1733` attaches the widen hint to any
`Invalid currency` error, including legs Beancount filled in.

Fix: render the open with its booking (and keep metadata out of the
one-line suggestion). Detect an interpolated posting (no units in the
request) and give the price-annotation hint instead.

Dedupe: `edit that open` and `widen` match only w5/363 (done).

Acceptance: both commands give the corrected hints. Tests pin each.

Addendum (CLI QA 2026-10-16, docs sweep): a third case of the same hint.
On a ledger from `bea --no-input init books --currency USD --date 2026-08-01
--opening-balance "Assets:Checking 1000"`, `bea --file books/main.bean add
open --date 2026-08-01 --account Assets:Checking -c EUR` exits 1. The
details are `Duplicate open directive for Assets:Checking`, then a side-effect
`Invalid currency USD for account 'Assets:Checking'`, with the hint `edit that
open to '2026-08-01 open Assets:Checking USD,USD'`. Beancount's currency
check keeps the last (proposed, EUR-only) open, so the existing USD posting
fails against it. The useful line is `open Assets:Checking USD,EUR`. Fix
alongside: for a duplicate open, drop the side-effect errors and give one
hint naming the existing open with the merged currency list. Cause:
`cli/src/bea_engine/ledger/write.py:1728-1733` and `_currency_widen_hint`
(`:2054-2066`).

---

**Resolved 2026-10-16** — Shipped in `63757415` (`cli`). In `validate_candidate` (`cli/src/bea_engine/ledger/write.py`) the three cases now read:
- **Booking method.** The suggested open line is rendered by `_open_line` and keeps it: `'2026-01-01 open Assets:Broker USD,HOOL "FIFO"'`.
- **Filled-in leg.** A leg Beancount filled in (`__automatic__`) in a currency its account refuses gets `_interpolated_leg_hint`: `Liabilities:CreditCard was given no amount, so Beancount filled in EUR from the other legs. If it was charged in USD, price the EUR leg at the rate paid: 'Expenses:Dining 45 EUR @ RATE USD'.` An explicitly written leg still gets the widen hint.
- **Duplicate open (addendum).** A duplicate open names the existing open with the merged list: `To allow EUR too, edit that open to '2026-01-01 open Assets:Checking USD,EUR'`. The existing postings' side-effect currency error says `This follows from the duplicate open of Assets:Checking above.` instead of suggesting `USD,USD`. The side-effect error line itself stays, because each error keeps its detail line.

`tests/test_currency_widen_hint_cases.py` pins all three and the explicit-leg control; the three cases fail without the fix. `tests/test_ledger_safety.py::test_distinct_problems_are_still_reported_separately` now counts problem lines, since the duplicate open carries a hint line.
