# `bea query ".describe Accounts"` (or any unknown or wrong-case name) exits 0 with no output, now that `FROM ACCOUNTS` works case-insensitively (sibling of w5/560)

**Trivial · cli · 5m · A1.** Real CLI QA, 2026-10-17, HEAD `a513b1113`, checkout `bea 0.3.1`, macOS 26.5.1. Sibling of w5/560 (done, `5773855b7`); upstream `bean-query` is silent too.
No product fix implemented.

```sh
bea --file /abs/main.bean query ".describe Accounts"
```

Actual: exit 0 and no output. `--json` with `.describe Postings` gives
`"data": {"text": ""}`, and `-o` says "Nothing was written" with exit 0
(hunter's runs).

Control: `.describe accounts` lists the columns (`table accounts:`,
`account (str)`, …). Since w5/560, `FROM ACCOUNTS` and `FROM Balances` reach
the real tables.

Expected: the same case folding as `FROM`, and an exit-2 refusal for a name
that matches no table or type. bea already refuses other upstream silences,
such as `.run` with a missing name. An agent can read an empty describe as
"no columns".

Cause: upstream `do_describe` skips a name that the case-sensitive
`tables.get` does not find. bea's `do_describe` (`cli/src/bea_engine/query.py`,
around `:409`) only adds shlex checking.

Fix: fold the name for table lookup, and refuse an unknown name.

Dedupe: w3/246, 247 and w5/293 (done) cover other `.describe` issues.

Acceptance: `.describe Accounts` lists the columns; `.describe nope` exits 2.

---
**Resolved 2026-10-19** — `.describe` matches tables and structured types case-insensitively like `FROM`, and a name matching neither is a usage error naming it with the tables and types listed, shipped in `bae43228d` (`cli`)
