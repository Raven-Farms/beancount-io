# A Python importer's `balance`, `note` or `document` on a never-opened account is shown `new` and counted as ready, then `--apply` fails the whole batch with exit 1; a transaction to the same account is `blocked` and exits 4

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12 with beangulp.
w3/276 made rows that post to a never-opened account show as `blocked`,
with the `bea add open` remedy. Such rows are left out of `ready`, and
`--apply` exits 4. That check runs only for transactions. A `Balance`,
`Note` or `Document` that an importer returns for an unopened account is
treated differently:

- the preview calls it `new`, counts it as ready, and exits 0;
- `--apply` fails ledger validation with exit 1 and writes nothing, not
  even the valid rows in the same batch;
- the JSON row reports `"accounts": []`, although the directive names an
  account.

Importers that emit the statement's closing balance are common, so the
first import into a new account hits this. [339](./339.md) is the sibling
gap for inactive accounts on transactions. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Bank
2026-01-01 open Expenses:Food USD
2026-01-01 open Equity:Opening
2026-01-02 * "Seed"
  Assets:Bank  100 USD
  Equity:Opening
```

Create `imp.py`:

```python
import datetime, os
from decimal import Decimal as D
from beancount.core import data, amount
from beangulp import importer

class Imp(importer.Importer):
    def identify(self, filepath):
        return os.path.basename(filepath).startswith("k-")
    def account(self, filepath):
        return "Assets:Bank"
    def extract(self, filepath, existing):
        return [data.Balance(data.new_metadata("x", 1), datetime.date(2026, 1, 10),
                             "Assets:Nope", amount.Amount(D("0"), "USD"), None, None)]

CONFIG = [Imp()]
```

`k-balnope.txt` can hold any content. Use isolated

BEA_FILE/BEA_TOKEN, and closed stdin.

```sh

bea --json -f /absolute/books/main.bean import k-balnope.txt --config imp.py
bea -f /absolute/books/main.bean import k-balnope.txt --config imp.py --apply
```

Actual:

- The preview exits 0 with `1 ready, 0 exact duplicates, 0 possible
  duplicates` and `+2026-01-10 balance Assets:Nope 0 USD`. Below it,
  `Proposed append (not written): Invalid reference to unknown account
  'Assets:Nope' … To create it, use bea add open …`.
- The JSON row is `"status": "new"` with `"accounts": []`, and `ready` is
  1.
- `--apply` exits **1**, and the ledger is unchanged.
- A `Note` on `Assets:Nope` behaves the same way.

Reproduced twice by the hunter and once by me.

Control: an importer transaction posting to `Assets:Nope` gives `0 ready
… 1 blocked` with `Row 1: Account 'Assets:Nope' is not open. Run: bea add
open --account Assets:Nope --date 2026-01-05 -c USD.`, and `--apply`
exits **4**.

Expected: `docs/IMPORTING.md` says "Rows that would post to an account
the ledger never opened … are shown `blocked`, not ready: the row names
the missing account and the `bea add open` line that fixes it … and
`--apply` refuses with exit **4** while any row is blocked." A balance,
note, document or pad on an unopened account cannot be written either.
It should be blocked the same way, with the same remedy, and `accounts`
should list the account.

Cause:

- In `cli/src/bea_engine/importing.py:425`, `if include and
  isinstance(entry, Transaction):` limits `_blocked_reason` (`:948`) to
  transactions.
- The row's `accounts` (`importing.py:436`) is `[p.account for p in
  entry.postings] if isinstance(entry, Transaction) else []`.
- The w5/134 recheck in the same function also iterates only
  `entry.postings`.

Fix:

- Derive the referenced accounts for every directive kind:
  `entry.account` for Balance, Note, Document and Close, plus
  `source_account` for Pad.
- Run the open check (and, for Balance, the currency check) on those
  accounts.
- Fill `accounts` from the same list.
- Keep the w5/134 rule that an `open` returned by the importer in the
  same batch unblocks the row.
- No dependency change.

Blast radius: `import` with Python importers (beangulp or `--config`)
that return Balance, Note, Document or Pad directives, in preview and
`--apply`, text and JSON. CSV imports produce only transactions and are
unaffected.

Dedupe: searched `.pm/**`, including `done/`, for blocked together with
balance, note, document or non-transaction, and for `isinstance(entry,
Transaction)`. Related notes:

- w3/276: transactions.
- 339: inactive accounts, transactions only.
- w5/134: the auto_accounts recheck.
- w5/224: re-import text of non-transaction directives.

None covers non-transaction directives on unopened accounts.

Acceptance:

- On the fixture, row 1 is `blocked` with the `bea add open --account
  Assets:Nope …` line, the preview reports `0 ready`, and the JSON shows
  `accounts: ["Assets:Nope"]`.
- `--apply` exits 4 and writes nothing.
- An `open` returned in the same batch unblocks the row.
- A real-command test covers Balance and Note.
- Only macOS and the checkout were exercised.

---

**Resolved 2026-10-15** — A new `_entry_accounts` (`cli/src/bea_engine/importing.py`) lists the accounts each directive needs open, with the currency it puts there when known. A transaction contributes its postings, a balance its account and currency, a pad both accounts, and a close, note or document its account; notes and documents are left out of the inactive check, as Beancount allows them after a close. `_blocked_reason`, `_inactive_reason`, `_first_uses`, the row's `accounts` and the w5/134 re-check all use that list, so any row kind runs the open, inactive and currency checks. On the fixture, an importer's balance and note on `Assets:Nope` are `blocked` with the `bea add open --account Assets:Nope …` line and `accounts: ["Assets:Nope"]`, the preview counts `0 ready`, and `--apply` exits 4 with nothing written. An `open` returned in the same batch unblocks the balance. IMPORTING.md's blocked-rows paragraph says so. `cli/tests/test_import_non_transaction_blocked.py` covers the balance, the note and the same-batch open; the 2 blocked cases fail with the fix reverted. Only macOS was exercised. `make check-all` passed. Shipped in `09d5300d` (`cli`).
