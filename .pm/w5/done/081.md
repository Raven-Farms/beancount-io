# `--allow-errors` lets a write introduce an Unused Pad error and still exit 0

**Major · cli · 30–45m · A1.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, macOS. `--allow-errors` is documented to
tolerate errors already in the books and to refuse an error the write itself
introduces, with one exception for the staged half of the two-step pad flow.
The exception is applied to every "Unused Pad" error from any command, so a
clean ledger can be left failing `bea check` by a write that exits 0. No
product fix implemented.

Create disposable `/absolute/books/main.bean` (`bea check` exits 0):

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Assets:Cash
2026-01-01 open Expenses:Food
2026-01-01 open Equity:Opening

2026-01-02 * "Open"
  Assets:Checking  5000.00 USD
  Equity:Opening
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f /absolute/books/main.bean add balance --date 2026-02-01 -a Assets:Checking --amount "5000.00 USD" --pad-from Equity:Opening --allow-errors
bea -f /absolute/books/main.bean check
```

Actual: the add exits 0 (`"written": 2` under `--json`) and appends
`2026-01-31 pad Assets:Checking Equity:Opening` and the balance. `check`
then exits 1 with `main.bean:<line>: Unused Pad entry`. Repeated twice.

Second shape, on the fixture plus

```beancount
2026-01-09 pad Assets:Cash Equity:Opening
2026-01-10 balance Assets:Cash  50.00 USD
```

(`check` exits 0): `bea -f … add transaction "found it" --date 2026-01-05
-p "Assets:Cash 50.00 USD" -p Equity:Opening --allow-errors` exits 0, adds
the transaction, and prints `Unused Pad entry Book balance already matches
the assertion; omit --pad-from and add the balance alone.` — advice about an
option that was not used. `check` then exits 1 on the pad that was valid
before the write.

Controls: without `--allow-errors`, the first command writes the assertion
alone with `Book balance already matches 5000.00 USD; omitted the pad` and
`check` stays at exit 0; the second exits 1 and writes nothing.

Expected: `docs/USAGE.md` Exit codes — "a write that exits 0 introduces no
new `bea check` error" — and Adding directives — an error the write itself
would introduce "is refused even with the flag; the staged-pad half of the
two-step pad flow below is the one exception", and "When the book already
holds the asserted amount, `--pad-from` writes the assertion alone and says
so." The first command should write the assertion alone, as it does without
the flag; the second should be refused. Only `add pad --allow-errors`, whose
own pad is the one left waiting, may stage an unused pad.

Cause: `cli/src/bea_engine/ledger/write.py:680` sets
`is_new = "Unused Pad" not in message` for any error not present before, so
every Unused Pad is exempt whatever the directive type and whichever pad it
names. `cli/src/bea_engine/ledger/adding.py:314` re-raises when
`allow_errors` is set instead of taking the already-matches path, and with
the exemption nothing is raised at all.

Fix: narrow the exemption to an Unused Pad whose pad directive is in the text
this request appends, and only for an `add pad` request. Under
`--pad-from --allow-errors`, run the same already-matches and covering-pad
logic as without the flag. The orphaned-pad warning must not suggest
`--pad-from` to a command that did not use it. No dependency or API change.

Blast radius: all `add` types, `add transactions` and
`import --apply --allow-errors` share the validation.

Dedupe: board search for Unused Pad, staged pads and `--pad-from` with
`--allow-errors` finds w3/224 and w1/116 (`--pad-from` matching without the
flag) and w1/m23/t002, which introduced the exemption; its breadth is not
filed.

Acceptance: the first command writes one balance with the omitted-pad message
and `check` exits 0; the second exits 1 with files unchanged; `add pad
--allow-errors` followed by its balance still completes the documented
two-step flow. Real-command regression tests cover both shapes and an import.
Only macOS and the checkout were exercised.

---

**Resolved 2026-10-12** — The `Unused Pad` exemption under `--allow-errors` now covers only a pad inside the text a pad-only request appends — the first half of the documented two-step flow. `add balance --pad-from --allow-errors` on a book that already matches writes the assertion alone with the omitted-pad message, as it does without the flag, and `check` stays at exit 0. A write that would orphan a pad already in the books exits 1 with files unchanged, and its hint names the assertion that now holds instead of advising `--pad-from`. Shipped in `a081ded8` (`cli`).

Real-command regression tests cover both shapes with and without the flag, an `import --apply --allow-errors` that would orphan an existing pad, `add pad --allow-errors` followed by its balance (still completes, `check` ends at 0), and an `add pad` that would orphan a pad that was valid before. Five fail with the fix reverted. One of them — the plain `add transaction` case — failed before only on the hint text; that write was already refused. The existing pad suites pass unchanged. `make check-all` passed. Only macOS was exercised.
