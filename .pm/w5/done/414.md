# `bea treeify`'s default pattern hard-codes `Assets|Liabilities|Equity|Income|Expenses`, so the documented `bea query … > balances.txt; bea treeify < balances.txt` pipeline fails on a ledger with renamed roots

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
[w5/137](./done/137.md) gave `treeify` its own account pattern so that
non-ASCII components work, but kept upstream's English root alternation.
On a ledger that sets `name_assets "Aktiva"` and similar, the documented
pipeline finds "no hierarchical column". The error then tells the user
to pipe colon-separated names, which is exactly what the input holds. No
product fix implemented.

Use a ledger with `option "name_assets" "Aktiva"` and `option
"name_equity" "Eigenkapital"`, opening `Aktiva:Bank:Giro` and
`Eigenkapital:Start`, with one transaction between them. Use isolated
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, and closed stdin.

```sh
bea -f /absolute/books/de.bean query "SELECT account, sum(position) GROUP BY account" > de.txt
bea treeify de.txt
bea treeify -A de.txt
```

Actual:

- `bea treeify de.txt` exits 2 with `WARNING: Could not find any valid
  column in input` and `Error: treeify found no hierarchical column to
  render (colon-separated names like Assets:Cash). Pipe balances or an
  account listing, not plain text.`
- `-A` draws the tree.

Reproduced twice by the hunter and once by me.

Control: the same pipeline on an English-root ledger exits 0.

Expected: the pipeline `docs/USAGE.md` documents should work with any
root names Beancount accepts. Failing that, the error should suggest
`-A` or `-r`.

Cause: `_ACCOUNT_PATTERN` (`cli/src/cli/commands/treeify.py:22-26`),
forwarded at `:139-140`.

Fix: use Beancount's generic root grammar (a capital or non-ASCII
letter, then account characters) instead of the five English names, and
mention `-A` in the no-column message. No dependency change.

Blast radius: `bea treeify` on ledgers with renamed roots, which are
common for non-English users.

Dedupe: w5/137 added the pattern, w5/061 covers bad user patterns, and
402 and 403 cover other renamed-root gaps. None covers treeify.

Acceptance: `bea treeify de.txt` draws `Aktiva` → `Bank` → `Giro` with
exit 0. English-root output is unchanged. A test pins both.

---

**Resolved 2026-10-15** — `_ACCOUNT_PATTERN`
(`cli/src/cli/commands/treeify.py`) now takes any root Beancount's
grammar allows: a capital or non-ASCII letter, then account characters.
The root must be followed by at least one component, so a capitalized
word or a currency is not mistaken for an account; the five English
roots still match on their own. The documented pipeline on a ledger with
`name_assets "Aktiva"`/`name_equity "Eigenkapital"` draws `Aktiva` →
`Bank` → `Giro` with exit 0. English output is byte-identical to before,
bare roots included. The no-column message now suggests `-A` or `-r`.
Pinned by `cli/tests/test_treeify_renamed_roots.py`, which fails without
the fix.
