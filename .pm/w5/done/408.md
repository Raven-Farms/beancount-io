# On a full disk, every read of a ledger with a managed price include fails with a raw `OSError: [Errno 27]` and exit 1, even with a valid cached revision; only a read-only directory gets the clean degrade

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1. **Simulation:** the feed comes from a localhost origin through `MANAGED_PRICE_ORIGINS`, and a file-size limit stands in for a full disk.

A ledger with a managed price include is read through a temporary
"effective" copy written beside each ledger file. `candidate_file` maps
only `PermissionError` (w5/095 gives that case a clean exit-3 message).
Any other write failure escapes, so on a full disk or quota every
`balance`, `list` and `report` dies with the raw error. That includes
reads where the price cache already holds a valid revision, and it
contradicts the documented "degrades to serving from memory". No product
fix implemented.

Setup by the hunter: `feed/main.bean` includes
`http://127.0.0.1:<port>/prices/BTC-USD`, a mock serves a 1.8 KB feed,
and `MANAGED_PRICE_ORIGINS` names it. Isolated BEA_CONFIG_DIR/XDG_CACHE_HOME,
BEA_NO_UPDATE_NOTIFIER=1, and closed stdin.

```sh
bea -f /absolute/feed/main.bean price refresh            # primes the cache, unlimited
( trap "" XFSZ; ulimit -f 1; bea -f /absolute/feed/main.bean balance )
( trap "" XFSZ; ulimit -f 1; bea --json -f /absolute/feed/main.bean list price )
```

Actual: exit 1 with `Error: OSError: [Errno 27] File too large Pass
--debug before the command for a traceback.` `--debug` shows
`cli/src/bea_engine/ledger/write.py:756` (`candidate_file`) reached from
`managed_load.py:686`. Reproduced four times by the hunter. I confirmed
the same `candidate_file` path, which also gives the class-name message
in 410.

Control: without the limit, both exit 0. A read-only ledger directory
gives w5/095's clean exit-3 message.

Expected: `docs/USAGE.md` says "A cache that cannot be written still
loads its prices, with a `price cache not writable` warning", and
`_try_write` documents that "a read-only or full cache degrades to
serving from memory". A full disk on the staged copy should either
degrade the same way (load without the overlay and report the source
unavailable) or exit with a bea sentence naming the directory, as the
permission branch does.

Cause: `managed_load.py:684-697` catches only `AuthError`.
`candidate_file` (`write.py:735-760`) maps only `PermissionError`.

Fix: map any `OSError` during the stage write in `candidate_file` to a
bea error. In `managed_load`, give it read-specific wording or fall back
to an overlay-free load. No dependency change.

Blast radius: every read of a ledger with managed price includes when
its directory's disk is full or over quota.

Dedupe: w5/095 (done) covers a read-only directory, w5/312 covers an
untraversable load-cache directory, and w5/321 covers the notifier cache.
None covers a full disk on this staged copy.

Acceptance: under the limit, `balance` either succeeds with a source
warning or exits with a bea sentence naming the directory, with no
`OSError:` prefix. A test simulates `EFBIG` in `candidate_file`.

---

**Resolved 2026-10-15** — the read path's staging
(`cli/src/bea_engine/managed_load.py`) now handles a full disk as it
handled a read-only directory. A read's temporary copy can fail in
`_shadow` (the candidate, mapped by w5/410's `candidate_file` change) or
when the closure file's bytes are written into it. Either way the read
exits 1 with `Cannot read …/main.bean: its managed price include (…) is
resolved on a temporary copy beside each ledger file, and the directory …
could not take it (File too large). Free space there, or read a snapshot
made with bea price export, which needs no temporary copy. Nothing was
changed.`. No `OSError:` appears and no `.bea-*` file is left. The
read-only case keeps w5/095's exit-3 wording, now through the shared
`_staging_refused`. A load that validates a write keeps the write path's
"nothing was written" sentence. The simpler outcome of the two the note
allowed (a bea sentence, not an overlay-free load) was chosen. Pinned by
`cli/tests/test_managed_read_disk_full.py`, which primes a real cached
revision and then reads under `RLIMIT_FSIZE`; it fails without the fix.
