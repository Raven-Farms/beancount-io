# A blocked import row's "opens … after this row" reason names a vanished staging file (`.bea-<hex>.tmp:9`) whenever the second-look reload decides it

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `75a67e85`, checkout `bea 0.3.1`, macOS 26.5.1.
w5/096 and w5/144 removed staging names from error messages. Import's
second look at blocked rows loads the staged candidate but discards its
staged-to-original filename map. The open it cites then carries the
temporary name and a line number in the candidate. When the open is a row of
the same import, it should cite that row instead. No product fix implemented.

A (Python importer): `extract()` returns `Open(2026-03-01, Expenses:Dining,
["USD"])` and a 2026-02-01 lunch posting to `Expenses:Dining`.

B (CSV): `main.bean` = `option "operating_currency" "USD"`, `plugin
"beancount.plugins.auto_accounts"`, `2026-03-01 open Assets:Checking USD`;
`s.csv` = `Date,Payee,Narration,Amount` / `2026-02-02,Cafe,Coffee,-5.00`.

```sh
bea --file /abs/main.bean import bank.txt --config imp.py
bea --file /abs/main.bean import s.csv --csv date=Date,amount=Amount,payee=Payee,narration=Narration --account Assets:Checking --default-account Expenses:Misc
```

Actual: exit 0 with `Row 2: Account 'Expenses:Dining' opens 2026-03-01 (at
…/.bea-cfe84d178467050c.tmp:9), after this row's 2026-02-01. Re-date that
open…`; the CSV case cites `(at …/.bea-200ed30a890c9e24.tmp:4)`. The same text
is in JSON `rows[].reason` and the `--apply` refusal; the file no longer
exists.

Control: without `auto_accounts`, the first pass names `…/main.bean:4`.

Expected: `(at …/main.bean:4)` for a ledger open, and `(row 1 of this import)`
for an open the batch itself carries.

Cause: `_entries_after` (`cli/src/bea_engine/importing.py:1203`) loads the
staged candidate and drops the map (`as (root, _)`); the reloaded directives
reach `_where()` (`:1368`) via `_inactive_reason` (`:1352`, `:1362`) on the
second look (`:549-551`).

Fix: map filenames back with the dict `staged()` yields, and recognize batch
rows.

Dedupe: w5/096, 134 and 144 (done) are siblings.

Acceptance: both commands name the real location (or the batch row). Tests
pin both.

---

**Resolved 2026-10-17** — Shipped in `d2d2a8834` (`cli`). `_entries_after` in `cli/src/bea_engine/importing.py` now maps every reloaded entry back from its staged copy to the real file. A directive that the import's own appended rows wrote carries its row number, located with `appended_spans` in `ledger/write.py`. `_where` then cites `(at …/main.bean:4)` for a ledger open and `(row 1 of this import)` for an open the batch carries. Test: `cli/tests/test_import_blocked_reason_real_location.py` covers the Python importer case and the `auto_accounts` CSV case.
