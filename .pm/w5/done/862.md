# ETag "HEAD" or "Head" still overwrites the managed-price revision record on a case-insensitive filesystem, so a successful check cannot be repeated offline (incomplete fix of w5/645)

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-18, HEAD `b7dfbe1bf`, checkout `bea 0.3.1`, macOS 26.5.1 on case-insensitive APFS. Two pristine, independent config/cache directories per ETag; stdin closed, no TTY. Synthetic loopback HTTP server only, no credentials. No product fix implemented.

A local server answers `/prices/BTC-USD` with HTTP 200, `ETag: "HEAD"`, and:

```beancount
; alias: BTC-USD
; commodity: BTC
; quote: USD
2026-10-01 price BTC 100 USD
  observed-at: "2026-10-18T07:00:00Z"
```

In `main.bean`, include `http://127.0.0.1:PORT/prices/BTC-USD` and open `Assets:Cash USD` on 2026-01-01. Set `MANAGED_PRICE_ORIGINS=http://127.0.0.1:PORT` and an empty isolated `XDG_CACHE_HOME`/`BEA_CONFIG_DIR` for all three commands:

```sh
bea --file /abs/main.bean check
bea --offline --file /abs/main.bean check
bea --json --offline --file /abs/main.bean price status
```

Actual: online check exits 0. The immediate offline check exits 1, `managed price source unavailable ... no cached revision`. JSON status exits 0 but reports `revision: null`, `freshness: "unavailable"`, `error: "no cached revision"`. The feed's sidecar record is aliased to `head.json`, whose remaining keys are only `revision`, `next_refresh_at`, `last_error`, so it cannot validate as a blob record. The ledger stays byte-identical.

`ETag: "Head"` behaves identically. Controls with lowercase `"head"` (now falling back to a body hash) and ordinary `"r1"` both pass online and offline, and status has a revision and no error. Test directories and evidence filenames differed numerically so the filesystem did not merge case-variant fixtures.

Expected: a successful fetch remains usable offline regardless of the ETag's casing; the fix must preserve the distinction between a cache head and a revision sidecar.

Cause: `feed_revision_id` in `cli/src/bea_engine/managed_prices.py:648` excludes only `safe == "head"`. `"HEAD"` passes, then its `HEAD.json` record and `head.json` refer to the same file on APFS. All managed-price reads and exports share this revision/cache mechanism. Case-sensitive filesystems were not exercised.

Fix: reserve the cache metadata name case-insensitively before using an ETag as a filename (or use a revision namespace that cannot alias metadata). Do not change the original ETag used for conditional HTTP requests.

Dedupe: whole-board searches for ETag/HEAD, casing and revision/head collisions found only the completed w5/645 parent (`c78bd7e91`), whose tests cover lowercase head and hidden names. This is its remaining filesystem spelling.

Acceptance: HEAD, Head and weak uppercase-head ETags cache safely; immediate offline loads succeed on case-insensitive storage. Preserve lowercase-head fallback and normal revision controls. A portable test can require the reserved-name check to case-fold, with the real APFS journey as evidence.

---

**Resolved 2026-10-20** — `feed_revision_id` compares the reserved cache name case-folded, so an ETag of `"HEAD"`, `"Head"` or `W/"HEAD"` falls back to the body SHA-256 like `"head"` and never writes a revision record over `head.json` on a case-insensitive volume; an immediate offline load then serves the cached revision. The ETag sent on conditional requests is unchanged, and ordinary ETags (`"r1.2"`) still name their revision. `tests/test_price.py` (`TestCacheAndUrlEdges`) adds the three spellings to the reserved-ETag unit and an online-then-offline journey for each. Gate note: gated as one stack with w5/858–863 (one `make check-all` over the six changes, each shipped as its own commit); its only failures were four load-induced managed-price fetch timeouts in `test_price_source_limit.py` (load average ~100), and the price suites pass in isolation (276 tests) on the stack's exact state. Shipped in `eb49423a5` (`cli`)
