# On a full disk, frontend exports say only "Could not write output: No space left on device", and `bea init` prints a raw `OSError` or says "nothing was written" while leaving the directories it created (gap in w5/410)

**Trivial · cli · 10–15m · A1/A2.** Real CLI QA, 2026-10-16, HEAD `c210da9b`, checkout `bea 0.3.1`, macOS 26.5.1. A full 8 MB RAM disk; `ulimit -f 0`.
w5/410 gave failed writes one sentence: "Cannot write a staged copy of X in
DIR (…); nothing was written". The frontend's export writer and `init`'s
directory creation do not use it. No product fix implemented.

```sh
# on a full volume
bea format main.bean -o out.bean          # also treeify -o, example -o, --json query -o
bea init n1/books/main.bean --currency USD
# elsewhere
bash -c 'ulimit -f 0; bea init deep/er/main.bean --currency USD'
```

Actual: the exports exit 1 with `Error: Could not write output: No space left
on device.` (the stdout-failure sentence: no path, no "nothing was written",
category `validation`); `init` on the full disk prints `Error: OSError:
[Errno 28] No space left on device: '…/n1' Pass --debug…`; under `ulimit -f
0`, `init` says nothing was written but leaves `deep/er/` behind.

Control: text `query -o` on the full disk prints `Cannot write a staged copy
of q.csv in … (No space left on device); nothing was written.`

Expected: the w5/410 sentence for every creation failure, and `init` removes
the directories it created when it writes nothing.

Cause: the candidate `os.open` in `atomic_write` (`cli/src/cli/utils.py:332`)
catches only `PermissionError`; `_make_parent`
(`cli/src/bea_engine/initiating.py:134-160`) maps only some `OSError`s and never
removes what it made.

Fix: as above.

Dedupe: w5/407 and 410 (done) cover stdout and writes after creation.

Acceptance: the commands print the staging sentence, and `deep/` does not
exist afterwards. Tests pin both.

---

**Resolved 2026-10-17** — Shipped in `823af82c` (`cli`).
- `atomic_write` (`cli/src/cli/utils.py`) reports an export's refused staged copy as "Cannot write <file> (No space left on device); nothing was written.", as it already did a failed write. This covers `format -o`, `treeify -o`, `example -o` and `--json query -o`, which no longer say "Could not write output".
- `init`'s `_make_parent` (`cli/src/bea_engine/initiating.py`) says any other `mkdir` failure as "Cannot create <dir> (<reason>); nothing was written." and returns the directories it made. `init` removes them, innermost first and only while empty, whenever it writes nothing.
- Under `RLIMIT_FSIZE` 0, `bea init deep/er/main.bean` prints "Cannot write a staged copy of main.bean in …/deep/er (File too large); nothing was written." and `deep/` is gone.
- Deviation: the exports keep the frontend's "Cannot write <file> (…)" form that w5/410's `test_write_size_limit_message.py` pins, rather than "a staged copy of … in …".
- `tests/test_full_disk_creation_messages.py` pins the `init` size limit, an `init` `mkdir` that hits `ENOSPC` after creating `n1/`, and `format -o` whose copy the disk refuses. All 3 fail without the fix. `make check-all` passed.
