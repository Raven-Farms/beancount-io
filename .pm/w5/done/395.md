# "Pad accounts must be active, even with --allow-errors." is printed when `--allow-errors` was not passed, once per error, including for `add balance --pad-from`

**Trivial · cli · 5–10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
w3/243 added this hint for the `add pad … --allow-errors` path. It is
appended for every `Pad` entry with an invalid-account error:

- whether or not `--allow-errors` was passed;
- once per error, so it can print twice;
- even when the pad came from `add balance --pad-from`, where the user
  never wrote a pad directive.

No product fix implemented.

Use the ledger from [394](./394.md) and the same environment.

```sh
bea -f /absolute/books/main.bean add balance --date 2026-02-05 --account Assets:Cash --amount '150 USD' --pad-from Equity:Nope
bea -f /absolute/books/main.bean add pad --date 2025-12-01 --account Assets:Cash --source Equity:Opening
```

Actual: both exit 1. After the invalid-account line, `Pad accounts must
be active, even with --allow-errors.` is printed, and it appears twice in
the second case. Neither command used `--allow-errors`. Reproduced twice
by the hunter and once by me (first command).

Control: `add pad … --source Equity:Nope --allow-errors` prints the hint
once, where it fits.

Expected: mention `--allow-errors` only when it was passed, and print the
hint once. For `--pad-from`, say "the --pad-from account must be open on
the pad date".

Cause: `cli/src/bea_engine/ledger/write.py:1292-1294` appends the hint
for every `Pad` with an `Invalid reference to` error, without checking
`allow_errors` or deduplicating.

Fix: guard the hint with `allow_errors`, add it once, and choose the
wording by how the pad arrived. No dependency change.

Blast radius: `add pad` and `add balance --pad-from` failures.

Dedupe: w3/243 introduced the hint. Nothing else matches.

Acceptance: neither command mentions `--allow-errors`, and the explicit
`--allow-errors` case prints the hint once. A test pins all three.

---

**Resolved 2026-10-15** — Shipped in `95c4b9da`. The inactive-pad hint in `validate_candidate` (`cli/src/bea_engine/ledger/write.py`) is now added once per distinct wording. Its wording depends on how the pad arrived:
- For `add balance --pad-from`, when the error names the pad's source account: "The --pad-from account must be open on the pad date, <date>." With `--allow-errors`, it adds ", even with --allow-errors". `write.append` takes `pad_from`, and the `--pad-from` path in `adding.py` passes it.
- With `--allow-errors`: "Pad accounts must be active, even with --allow-errors."
- Otherwise: "Pad accounts must be open on the pad date, <date>."

`tests/test_add_pad_inactive_hint.py` pins:
- the `--pad-from Equity:Nope` refusal (option named, no flag);
- the pad before both opens (one hint, no flag);
- the `--allow-errors` control (the flag hint once);
- `--pad-from` together with the flag.

The first three fail at the prior HEAD.

Deliberate change: `tests/test_ledger_safety.py`'s w1/118 `--pad-from` case pinned the old flag wording without the flag. It now expects the `--pad-from` hint and no `--allow-errors`.
