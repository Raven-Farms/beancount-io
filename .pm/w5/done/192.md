# Text `bea check` fails on a managed include written `HTTP://…`, which `--json check` and every other command accept

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
`bea check` decides with its own text pattern whether a ledger has a
managed price include. The pattern is case-sensitive and requires a
space, so `include "HTTP://…"` (and, per a worker, `include"http://…"`)
is sent to stock `bean-check`, which reports the URL as a missing file.
`--json check` on the same file says valid. Unusual spellings; low
priority. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Assets:Coin BTC
2024-01-01 open Equity:Opening
2024-01-01 commodity BTC
2024-01-01 commodity USD

2024-01-02 * "Open"
  Assets:Cash  10000.00 USD
  Equity:Opening

2024-01-03 * "Buy"
  Assets:Coin  2 BTC {1000.00 USD}
  Assets:Cash  -2000.00 USD
```

followed by `include "HTTP://127.0.0.1:PORT/prices/X"`.

The feed is a **simulation**: a loopback server on `127.0.0.1` allowed
through `MANAGED_PRICE_ORIGINS`, which proves local handling only, not the
real service's behaviour. Use isolated BEA_CONFIG_DIR and a fresh
XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no inherited BEA_FILE/BEA_TOKEN,
closed stdin, no TTY, cwd `/absolute/books`. The simulated feed returns `2024-01-05 price BTC 1100.00 USD`.

```sh
bea -f main.bean check
bea --json -f main.bean check
```

Actual: the first exits 1: `<load>:0: File glob
"HTTP://127.0.0.1:PORT/prices/X" does not match any files`. The second
exits 0 with `"valid": true, "errors": []`.

Control: the second command. A worker saw lowercase `http://` pass text
`check`, and `list price` show the feed price for the uppercase form.

Expected: `docs/USAGE.md` — "`check`, `list`, `query`, `report`,
`import`, and write validation all see the same resolved prices."

Cause: `cli/src/cli/commands/check.py:16` matches
`^\s*include\s+"https?://` case-sensitively; the engine's own URL
pattern is case-insensitive and the include scanner elsewhere allows no
space.

Fix: make the pattern case-insensitive and allow zero spaces. No
dependency or API change.

Blast radius: text-mode `check` only.

Dedupe: board search for the pattern name and uppercase scheme finds
nothing.

Acceptance: text `check` exits 0 for both spellings and agrees with
`--json check`. Only macOS, the checkout and a loopback simulation were
exercised.

---

**Resolved 2026-10-13** — The pattern text `bea check` uses to decide whether a ledger names a URL include native bean-check cannot fetch, in `cli/src/cli/commands/check.py`, now matches the scheme in any letter case and lets the `include` keyword touch its string, as the loader and the include scanner already read it. Ledgers written `include "HTTP://…"` or `include"http://…"` therefore go to the helper check and exit 0 in agreement with `--json check`, instead of failing in bean-check as a file glob that matches nothing. The new `cli/tests/test_check_managed_include_spellings.py` runs both modes against a loopback feed for five spellings (lowercase, uppercase, mixed case, no space, no space with uppercase), checks that bean-check options are refused with the URL-include reason for an uppercase scheme, and keeps a local `include"HTTP/extra.bean"` on native bean-check as the control; five of its seven cases fail with the fix reverted. The feed is a loopback simulation allowed through `MANAGED_PRICE_ORIGINS`, so only local handling is proven. Only macOS was exercised. `make check-all` passed. Shipped in `6a5373db` (`cli`).
