# Any nearby file that includes the root (a Fava or forecast overlay) takes over validation and dedupe for every write on that root: a wrong balance is written with exit 0, a correct one refused, and a real bank row skipped as a duplicate of a forecast entry (regression from w5/343/346)

**Major · cli · 30–45m · A1.** Real CLI QA, 2026-10-16, HEAD `3514cc17`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE says writes are redirected through an including root only "When
`--file` names an included file … in the same or the parent directory". The
w5/343/346 change applies the redirect to every write, including cwd
discovery and a `--file` that is itself a working root. It also searches
several levels up and sibling folders. A common pattern is a
`forecast.bean` or `fava.bean` that includes `main.bean` and adds
projections. That file then becomes the "root". Its forecast entries count
in validation and dedupe, while the write lands in `main.bean`. No product
fix implemented.

`main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Rent USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "Opening"
  Assets:Checking  5000.00 USD
  Equity:Opening
```

`forecast.bean` beside it:

```beancount
include "main.bean"
2026-02-01 # "Landlord" "Rent (forecast)"
  Expenses:Rent  1000.00 USD
  Assets:Checking
```

From that directory, no `--file`:

```sh
bea add balance -a Assets:Checking --amount '5000.00 USD' --date 2026-03-01
bea add balance -a Assets:Checking --amount '4000.00 USD' --date 2026-03-01
bea check
bea --json import bank.csv --csv date=Date,amount=Amount,payee=Payee --account Assets:Checking --rules rules.toml --apply --duplicates skip
```

(`bank.csv`: `2026-02-01,-1000.00,Landlord`; a rule maps `Landlord` to
`Expenses:Rent`.)

Actual: the true 5000 assertion is refused (`expected 5000.00 USD !=
accumulated 4000.00 USD`); the wrong 4000 one is written with exit 0 after
`main.bean is included by …/forecast.bean; the write goes to main.bean and is
checked against that whole ledger.`; `check` then fails (`main.bean:9: Balance
failed … expected 4000.00 USD != accumulated 5000.00 USD`) and advises `Run
with --file …/forecast.bean`. The import writes 0 rows; the real rent payment
is `possible_duplicate` of the forecast entry, while `target.file` says
`main.bean`. An overlay in the parent directory (`fava.bean` with `include
"books/main.bean"`) does the same.

Control: with `forecast.bean` moved away, the 5000 assertion is valid and the
rent row is new.

Expected: a file that loads cleanly on its own (or was named by `--file` or
found by cwd discovery as a root) is validated and deduplicated against
itself. Redirect only when the named file fails alone in a way an includer
fixes, as USAGE describes. When it is ambiguous, ask for `--file`/`--into`
rather than guess.

Cause: `write_through_root` is called for every add, append and import
(`cli/src/bea_engine/main.py:282`, `:326`, `:498`); `top_root` /
`including_root` (`cli/src/bea_engine/ledger/write.py:1249-1360`) treat any
nearby includer as the root; `root_read_hint` (`write.py:1333`) misdirects
reads the same way.

Fix: as above; keep w5/343/346's case (a leaf that fails alone) working.

Dedupe: searched `overlay`, `forecast`, `fava.bean`, `including_root`. Only
w5/343, 346, 347 and 348 (done), which assume "the file nothing includes is
the root".

Acceptance: with the overlay present, the 5000 assertion is accepted, the
4000 one refused, the rent row imported as new, and no root hint printed; the
w5/343 leaf fixtures still redirect. Tests pin both.

Addendum (CLI QA 2026-10-17, HEAD `a7c2762d`): a second shape with the same
outcome. This one is the w5/343 case the fix must keep (a leaf that fails on
its own), but **two** roots include the leaf. `main.bean` opens `Assets:Cash`,
books a 100 USD opening, then `include "2026.bean"`, then a 30 USD dinner.
`main-backup.bean` beside it holds the same lines without the dinner.
`2026.bean` is `; 2026`. With `bea --file 2026.bean add balance -a Assets:Cash
--amount '70 USD' --date 2026-02-01`, the true balance exits 1 (`expected 70
USD != accumulated 100 USD`). The false `'100 USD'` exits 0 after
`2026.bean is included by …/main-backup.bean; the write goes to 2026.bean and
is checked against that whole ledger.` `bea --file main.bean check` then
fails on it. `including_root` takes the first includer in sorted
`*.bean` order, and `-` sorts before `.`, so `main-backup.bean` wins. The
refusal also drops the "is included by" note:
`cli/src/cli/engine/launch.py:449-450` relays the engine's stderr note only
on success, so the user never learns which root judged the write. Extra
acceptance: with two includers, the write exits 2 listing both and asking for
`--file ROOT --into LEAF`, and the reroute note appears on refusals too.

**Resolved 2026-10-17** — Shipped in `18c62aa9` (`cli`). `defines_for` (`cli/src/bea_engine/ledger/write.py`) decides whether a nearby includer is a file's root: the includer's own files (its closure minus the file's) must define what the file reads, meaning an `open`, a `plugin`, or an `option` other than `title` or `render_commas`. `write_through_root` and `root_read_hint` now require it. A per-year leaf whose root opens its accounts is still redirected (w5/343, 346, 347, 348; their 86 tests pass). A `forecast.bean` or `fava.bean` that includes a working ledger and only adds entries is not its root.
- The wrong 4000 assertion is refused and the true 5000 one is written, with no "is included by" note; `check` then passes.
- The bank row imports as `new` instead of a duplicate of the forecast entry.
- A failing `check` no longer points to the overlay.
- A title-only `fava.bean` in the parent folder is no root.

A first attempt that loaded the file alone and redirected only on unknown-account errors broke the w5/343 case, where the leaf loads cleanly and only the write uses the root's accounts. It was replaced by the definitions rule. USAGE states the rule. `tests/test_overlay_includer_not_root.py` pins the four cases, which all fail without the fix. Not implemented: the note's "ask when ambiguous". `make check-all` passed.
