# `import --apply --allow-errors` writes a pad-only batch that leaves a clean ledger failing `bea check` ("Unused Pad entry"), exit 0, and every later write is refused (incomplete fix of w5/081)

**Minor · cli · 5–10m · A1.** Real CLI QA, 2026-10-17, HEAD `116cf55c0`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/081 (done).
USAGE says an error a write itself would introduce "is refused even with the
flag", except for the staged `add pad` and the nounused open. w5/081's Fix
said the exemption is "only for an `add pad` request".

---

**Resolved 2026-10-20** — `stages_pad` is now an explicit flag passed only by `add pad`; a pad-only import is refused even with `--allow-errors`, exit 1, nothing written. Shipped in `8a599157f` (`cli`).

`ipad.bean` opens `Assets:Checking USD` and `Equity:OpeningBalances`. A minimal
beangulp importer turns `p.stmt` into one `Pad(2026-03-14, Assets:Checking,
Equity:OpeningBalances)`.

```sh
bea --json --file /abs/ipad.bean import /abs/p.stmt --config /abs/padimp.py --apply --allow-errors
bea --file /abs/ipad.bean check
```

Actual: the import exits 0 with `"written": 1` and a validation warning
`…:6: Unused Pad entry`. `check` then exits 1 (`ipad.bean:6: Unused Pad entry`),
and every later write is refused with `The ledger already has 1 error(s)`
(hunter's run).

Control: without `--allow-errors`, the import exits 1 and writes nothing.

Expected: the import is refused even with `--allow-errors`, as the flag
covers only errors already in the ledger.

Cause: `validate_append` and `append` are called from import with
`stages_pad=_only_pads(texts)` (`cli/src/bea_engine/ledger/write.py:2745`,
`:2959`), so a pad-only import gets `add pad`'s exemption.

Fix: pass `stages_pad` only from `add pad`.

Dedupe: w5/081 (done) is the parent.

Acceptance: the command exits 1 and writes nothing. A test pins it.
