# `bea query` text tables pad cells by character count, so a CJK payee or account pushes that row's numbers out from under their headers

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `a00da14e3`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE:674 says text-table numbers are aligned on the decimal point. Other bea
tables pad by display width (w3/391, w1/106, w5/149, w5/246). No product fix
implemented.

`q.bean`: `Assets:Cash` and `Expenses:Food`, with a 2026-01-04 "Cafe Bistro
Paris" 100.00 USD and a 2026-01-05 "東京ラーメン屋さん" 12.34 USD.

```sh
bea -f /abs/q.bean query "SELECT date, payee, position, balance WHERE account = 'Expenses:Food'"
```

Actual: exit 0.

```
   date           payee          position     balance
----------  -----------------  -----------  -----------
2026-01-04  Cafe Bistro Paris   100.00 USD   100.00 USD
2026-01-05  東京ラーメン屋さん            12.34 USD   112.34 USD
```

Both rows have 55 characters, but on screen the CJK row is 64 columns wide.
Its position `12.34 USD` sits under `balance`, and the balance runs past the
table. CJK account names do the same (hunter's run).

Control: ASCII payees align; `--json` has the right values.

Expected: columns padded by display width.

Cause: bea swaps in its own text renderers (`_text_renderers`,
`cli/src/bea_engine/query.py:1563`; `PlainObjectRenderer` at `:1596`), but
measures and pads with `len()`, like upstream's `query_render`. The display
width helper exists in `cli/src/cli/output.py`.

Fix: measure and pad cells by display width in the text renderers.

Dedupe: w3/391 scoped out beanquery's interactive tables; w5/726 (open)
covers the error caret. Nothing covers the one-shot table.

Acceptance: the CJK row's columns line up with the headers. A test pins it.

---
**Resolved 2026-10-19** — the `--file` text table measures cells and pads rows by display width, keeping upstream's exact output where widths agree, shipped in `dec6c4c73` (`cli`)
