# A plugin error whose `source` is `None` makes every write fail with an internal `AttributeError: 'NoneType' object has no attribute 'get'`, while reads cope

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `5a0cdcb4`, checkout `bea 0.3.1`, macOS 26.5.1.
Third-party plugins sometimes return errors with `source=None` when they have
no single entry to blame. `list` shows such an error as `<ledger>:0: …`. The
write gate's error keying assumes a dict. Once such an error exists, every
write crashes, `--allow-errors` included. No product fix implemented.

`nosrc.py` beside the ledger:

```python
import collections
from beancount.core import data
__plugins__ = ["nosrc"]
E = collections.namedtuple("E", "source message entry")
def nosrc(entries, options_map):
    return entries, [E(None, "flagged entry", e) for e in entries
                     if isinstance(e, data.Transaction) and "bad" in e.tags]
```

`main.bean`: `option "insert_pythonpath" "TRUE"`, `plugin "nosrc"`, two opens.

```sh
bea --file /abs/main.bean add transaction x --date 2026-01-05 -p "Assets:Cash 1 USD" -p Equity:Opening --tag bad
```

Actual: exit 1 (`validation`), `Error: AttributeError: 'NoneType' object has no
attribute 'get'. Pass --debug before the command for a traceback.` After a
`#bad` entry exists, every write (`add note … --allow-errors` too) fails the
same way.

Expected: a `None` source is treated as unanchored (as `format_error` does):
the write is refused as introducing `flagged entry` (or tolerated under
`--allow-errors` when it already existed).

Cause: `_error_key` (`cli/src/bea_engine/ledger/write.py:2178`) and `:1575` call
`error.source.get` without a guard.

Fix: treat `None` as `{}` at both sites.

Dedupe: no match for `source=None` or the AttributeError text.

Acceptance: the add is refused with the plugin's message; writes under
`--allow-errors` work afterwards. A test pins both.

---

**Resolved 2026-10-18** — Shipped in `9e6721431b3955bfb89f11f384cebd28e0eb3c09` (`cli`). Write validation, error keying and unanchored matching treat a missing source as empty metadata, preserving the plugin's message rather than raising AttributeError. An existing source-less error is tolerated under --allow-errors; additional errors and a different replacement message are refused. Twelve text/JSON regression and control cases pass; reverting the fix gives 10 failures and two passing clean-ledger controls, and reverting only the message identity gives two failures. All 54 focused checks passed, and `make check-all` passed (7,650 passed, 2 skipped). Tracked-content gitleaks is clean; the required full-directory scan reports the same 72 pre-existing ignored runtime/cache/build matches.
