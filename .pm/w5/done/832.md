# Rows from a Python importer that carry generated `csv:sha256:` import-ids are told "only one of them carries a bank ID" when neither has one (incomplete fix of w5/615)

**Trivial · cli · 5m · A1.** Real CLI QA, 2026-10-17, HEAD `d6c32f470`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/615 (done).
The w5/615 resolution says the reason names only the bank IDs that exist. No
product fix implemented.

A minimal beangulp importer that sets `import-id = "csv:sha256:" +
sha256(date|amount|DESC|account[|n])[:16]` per row, as the importer-author
skill describes, reads `n.csv`: two identical `2026-10-04,NETFLIX.COM,-15.49`
rows.

```sh
bea --json --no-input -f /abs/main.bean import n.csv --config imp615.py
```

Actual: row 2 is `possible_duplicate` with `Date, narration and source amount
match row 1 of this import; only one of them carries a bank ID.`. Neither
carries one; both have generated digests.

Control: the same rows through `--csv … id=Id` with empty Id cells get "neither
row has a bank ID".

Expected: "neither row has a bank ID".

Cause: `cli/src/bea_engine/importing.py:523` passes `ours=id_source != "hash"`,
counting any importer-supplied `import-id` as a bank ID. `theirs` already
tests `_GENERATED_ID`.

Fix: compute `ours` like `theirs`.

Dedupe: w5/615 (done) is the parent; w5/823 (open) affects the same regex.

Acceptance: the reason says "neither".

---

**Resolved 2026-10-20** — `_twin_reason` judges both rows with one test (`_carries_bank_id`: a native ID, or an `import-id` that is not a generated `…:sha256:…` digest), so two identical rows from an importer that sets generated `csv:sha256:` ids read `neither row has a bank ID.`. `tests/test_import_twin_reason_ids.py` adds the Python-importer case beside the w5/615 ones.
