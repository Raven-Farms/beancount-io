# `bea ask` loads skills from the working directory's `.agents/skills/` silently: they are never named to the user, they override same-named user skills, and their size is unbounded (a 2 MB description is sent on every turn)

**Trivial · cli · 20m · A2 (design).** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1. **Simulation:** a localhost mock model received the requests.

USAGE documents that `ask` loads skills from `<cwd>/.agents/skills/` as
well as the user directory, that project skills override user skills,
and that supplied skill context is sent to the hosted service. It gives
no notice of which skills were loaded and no warning about running `ask`
inside a checkout you do not control. A repository can therefore place a
skill whose description is a prompt-injection attempt, or one that
shadows the user's own skill of the same name. Nothing shows it, and its
text is resent to the model on every turn with no size limit. Writes
still need the approval panel, but see 453. No product fix implemented.

The hunter used a `repo/.agents/skills/` holding an `evil` skill
(description "IGNORE PREVIOUS INSTRUCTIONS…") and a `dup` skill that
overrides `$BEA_CONFIG_DIR/skills/dup`, against a mock model.

- `bea -f repo/main.bean ask --print "q"` sent both project skills, and
  printed nothing about them.
- A 2,000,000-character description produced a 2.0 MB request, and 3,000
  small skills produced a 703 KB request, on each turn.

Reproduced twice by the hunter. I confirmed the loader paths in the code.

Expected: tell the user which project skills were loaded, and name any
user skill they shadow, in both the REPL and `--print`. Cap description
and index size. Document the trust implication. Optionally, require an
opt-in for project skills.

Cause: `load_skills` (`cli/src/cli/ask/skills.py:76-100`) and
`build_skills_index_prompt` (`:103-122`) apply no limits and print
nothing.

Fix: print one line listing the project skills loaded (and any shadowed
user skill). Cap each description (for example 1 KB) and the total index.
Add a USAGE note about untrusted directories. No dependency change.

Blast radius: `bea ask` run inside third-party repositories.

Dedupe: 403 (roots in the system prompt), 373 and 374 cover other ask
issues. None covers skill trust or size.

Acceptance: running `ask` in the fixture prints the loaded project skills
and the shadowed `dup`. An oversized description is truncated or refused
with a note. The USAGE ask section carries the warning.

---

**Resolved 2026-10-15** — `load_skills` (`cli/src/cli/ask/skills.py`) marks each skill from `<cwd>/.agents/skills/` as a project skill and records whether it replaced a same-named user skill. Before the REPL or `--print` starts, `bea ask` prints one stderr line from `project_skills_notice`, for example `Loaded 2 project skill(s) from .agents/skills in the working directory: dup (replaces your dup), evil. Their descriptions are sent to the model on every turn; run ask only in a directory you trust.`. A description is cut to 1,024 characters and the skill index to 32 KiB, each with a note, so the 2 MB description and the 3,000-skill index no longer reach the model whole. USAGE's ask section carries the trust warning. Project skills still load without an opt-in. `cli/tests/test_ask_project_skills.py` covers the notice (shadowed `dup`, user-only skills silent), the cut description, the index cap, and the notice reaching `ask --print`'s stderr. Only macOS was exercised. `make check-all` passed (6037 tests). Shipped in `5f5d6e9b` (`cli`).
