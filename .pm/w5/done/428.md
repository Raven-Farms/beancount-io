# A CSV column whose header contains a comma (`"Amount (USD, net)"`) cannot be named in `--csv`: the spec is split on every comma, quoting does not help, and the error points at a fragment (`Bad --csv mapping ' net)'`)

**Trivial · cli · 15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
Bank exports sometimes use headers like `Amount (USD, net)`. The
`--csv` spec has no escape for commas. It is split on every `,`, quotes
are not honoured, and `--csv auto` cannot infer the mapping either. Such
a file cannot be imported through `--csv` at all. No product fix
implemented.

Use the ledger from [426](./426.md) and `c.csv`:

```text
Date,Payee,"Amount (USD, net)"
2026-01-05,Shop,-5.00
```

```sh
bea -f /absolute/books/main.bean import c.csv --account Assets:Cash --csv 'date=Date,payee=Payee,amount=Amount (USD, net)'
bea -f /absolute/books/main.bean import c.csv --account Assets:Cash --csv 'date=Date,payee=Payee,amount="Amount (USD, net)"'
```

Actual: both exit 2 with `Bad --csv mapping ' net)': use field=Column
pairs …` (the quoted form gives `' net)"'`). `--csv auto` exits 2 with
"Cannot read a column mapping from the header row". Reproduced twice by
the hunter and once by me (first form).

Expected: `docs/IMPORTING.md` documents `field=Column` pairs and header
matching after stripping, with no exception for commas. There should be
a way to name such a column, for example by honouring CSV-style quotes
in the spec. Otherwise the error should say that commas in column names
are unsupported and suggest a Python importer.

Cause: `parse_mapping` splits on `,` (`cli/src/bea_engine/csv_mapper.py:356`).
The frontend copy in `cli/src/cli/commands/import_.py` does the same.

Fix: parse the spec with `csv.reader` (quote-aware) in both places, and
document the quoting. No dependency change.

Blast radius: imports of exports whose header cells contain commas.

Dedupe: searched `.pm/**`, including `done/`, for comma together with
column name and "Bad --csv mapping". None covers this.

Acceptance: the quoted form maps the column and imports the row. The
first form gives a message about commas in column names. A test pins
both.

---

**Resolved 2026-10-15** — the `--csv` spec is now split by `split_spec`
(`cli/src/bea_engine/csv_mapper.py`, with a frontend twin in
`cli/src/cli/csv_mapper.py`). It keeps a double-quoted stretch whole, and
`spec_value` takes the quotes off. Every frontend reader of the spec uses
it: `parse_mapping`, `validate_reading_keys`, the key stripping, the
shell echo, and the remembered-settings path. `--csv
'date=Date,payee=Payee,amount="Amount (USD, net)"'` maps the column and
imports the row, and a remembered mapping replays it. The unquoted form
still exits 2, now saying `A column name with a comma in it must be
double-quoted, as in amount="Amount (USD, net)".` An unclosed quote is
named, and an inferred spec quotes such a header. `docs/IMPORTING.md`
documents the quoting. Pinned by
`cli/tests/test_csv_spec_quoted_column.py`, which fails without the fix.
