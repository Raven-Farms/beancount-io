# A whole-number ledger with one `@@` total (or `{{total}}` cost) and an omitted leg prints every figure in that currency with 25 decimals (`Net Profit: -1,200.0000000000000000000000000 JPY`)

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `60ea00ea`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE (Reports): "a whole-dollar ledger prints `10 USD` rather than `10.00`".
The report's display precision learns from interpolated legs. Beancount
fills an omitted leg against a total that does not divide evenly (`3 HOOL @@
1000 JPY` → `-999.9999999999999999999999999 JPY`), and that division noise
becomes the precision of every JPY figure. The user wrote only whole
numbers. Writing the leg out is refused by upstream, so the omitted leg is
the normal way to record this. No product fix implemented.

```beancount
option "operating_currency" "JPY"
2026-01-01 open Assets:Cash JPY
2026-01-01 open Assets:Broker
2026-01-01 open Expenses:Food JPY
2026-01-01 open Equity:Opening
2026-01-02 * "Open"
  Assets:Cash      100000 JPY
  Equity:Opening
2026-01-03 * "Lunch"
  Expenses:Food    1200 JPY
  Assets:Cash
2026-01-04 * "Buy"
  Assets:Broker    3 HOOL @@ 1000 JPY
  Assets:Cash
```

```sh
bea -f /abs/main.bean report income-statement -x units
bea -f /abs/main.bean balance -x units
```

Actual: exit 0; `Food 1,200.0000000000000000000000000 JPY`, `Net Profit:
-1,200.0000000000000000000000000 JPY`; the balance sheet shows `Net Worth: 3
HOOL 97,800.0000000000000000000000000 JPY`. `{{1000 JPY}}` behaves the same,
and a whole-dollar USD copy (`@@ 100 USD`) prints 26 decimals. JSON stays
exact.

Control: `@@ 900 JPY` (divides evenly) prints `1,200 JPY`; upstream
`bean-query` prints `97800 JPY`.

Expected: `1,200 JPY` and `97,800 JPY`. An interpolated leg contributes no
more digits than the transaction's written numbers carry (a written `31.5`
still counts).

Cause: `cli/src/bea_engine/report.py:840` records the interpolated leg's
exponent, and `:843-845` adopt it when the currency's written precision is 0.

Fix: as above.

Dedupe: searched `_display_precision`, whole-dollar, JPY; w5/093 (done) noted
the many-decimal-cost case only. Sibling of open w5/571 (doctor trees).

Acceptance: the fixture prints whole yen in every report. A test pins it.
