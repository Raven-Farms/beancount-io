# `bea list document` gives each path relative to the include file that wrote it, but never says which file, so two different attachments list identically and neither resolves from the root

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `d6c32f470`, checkout `bea 0.3.1`, macOS 26.5.1.
No product fix implemented.

`main.bean` opens `Assets:Cash` and includes `2025/books.bean` and `2026/books.bean`.
Each include holds `… document Assets:Cash "receipt.pdf"`, and `2025/receipt.pdf`
and `2026/receipt.pdf` exist. There is no `receipt.pdf` beside the root.

```sh
bea --json -f /abs/main.bean list document
```

Actual: both rows have `"filename": "receipt.pdf"` and no `source`; the text
table shows the same. `query "PRINT FROM type = 'document'"` prints
`"2025/receipt.pdf"` and `"2026/receipt.pdf"` (hunter's run). Transaction rows
carry `source`; document rows do not.

Expected: each row identifies its attachment, either through a `source`
(filename, lineno) or a path relative to the root. USAGE (around :725) gives
query output's document paths relative to the root; the list section does
not say which base it uses.

Cause: `cli/src/bea_engine/ledger/reader.py` (around `:639`) relativizes
against the directive's own directory, deliberately since w5/066, so `add
document --into` accepts the value back. `DocumentDirective`
(`cli/src/bea_engine/ledger/models.py`, around `:415`) has no source.

Fix: add `source` to document rows (and a column or note in text), and
document the base.

Dedupe: w3/244, w5/066 and 170 (done) set the base; w5/681 (open) covers
`--on-disk`.

Acceptance: the two rows are distinguishable and resolvable.

---

**Resolved 2026-10-20** — document rows now carry `source` (`filename`, `lineno` of the directive) in JSON, and the text table gains a `WRITTEN IN` column (`2025/books.bean:1`, relative to the root's folder as the ledger spells it), so two includes' `receipt.pdf` are distinguishable and each resolves as `source.filename`'s folder plus `filename`; the filename itself keeps w5/066's base so `add document --into` still takes it back. `tests/test_list_document_names_its_file.py` pins both forms; the `list note` table test now compares against the document table's tag and link cells; USAGE documents the base.
