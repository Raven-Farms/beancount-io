# Report and balance account trees pad by character count, so a wide-character account name shifts its amount

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
In `report` and `balance` trees, an account component containing CJK
characters pushes its amount to the right of the column the other rows
use. Cosmetic; the numbers are correct. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Bank:Checking USD
2026-01-01 open Assets:Bank:Épargne USD
2026-01-01 open Assets:Bank:X現金口座 USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "open"
  Assets:Bank:Checking  3000.00 USD
  Assets:Bank:Épargne  2000.00 USD
  Assets:Bank:X現金口座  1000.00 USD
  Equity:Opening
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`. The fixture passes `bea check`.

```sh
bea -f main.bean report balance-sheet
```

Actual: exit 0.

```text
      Checking                                    3,000.00 USD
      X現金口座                                       1,000.00 USD
      Épargne                                     2,000.00 USD
```

The CJK row's amount starts four display columns to the right.

Control: the `Checking` and `Épargne` rows align. A worker saw the same in
`balance`, trial balance and overview, piped and on a PTY.

Expected: one amount column for every row; `cli/src/cli/output.py`
already states that an East Asian wide character takes two columns and
`output.table` honours it.

Cause: `cli/src/cli/commands/report.py:118` pads with
`f"{... label:<46}"`, which counts characters, not display columns.

Fix: use `output.pad` for the label. No dependency or API change.

Blast radius: the account tree in all four reports and `balance`.

Dedupe: w3/done/391 and w1/done/106 fixed tables and `list`; 391 scoped
trees out on the premise that CJK account names cannot occur, but
`Assets:Bank:X現金口座` passes `bea check`. w5/137 (`treeify`) is a
different command.

Acceptance: all three amounts start in the same display column; ASCII
output is byte-identical to today. Only macOS and the checkout were
exercised.

---

**Resolved 2026-10-13** — The account tree shared by `bea report balance-sheet`, `trial-balance`, `income-statement` and `bea balance` padded each label with `str.format`, which counts code points, so a CJK account component pushed its amount four columns right of the other rows. `_print_tree` in `cli/src/cli/commands/report.py` now pads the label with `output.pad`, which measures terminal display columns, so every row starts its amount in the same column while ASCII and accented-Latin rows keep their exact bytes. `cli/tests/test_report_tree_wide_account_alignment.py` runs the real balance-sheet, trial-balance and balance commands on the note's fixture, asserting that the Checking, Épargne and X現金口座 amounts all start at the same display column and that the narrow rows are byte-identical to before; the three alignment cases fail with the fix reverted and the three byte-identity controls pass either way. `report overview` prints no account tree, so it was not affected, and the fixed-ASCII summary lines under the balance sheet were left as they are. Only macOS was exercised. `make check-all` passed. Shipped in `56833bd1` (`cli`).
