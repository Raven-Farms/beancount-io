# Editing the previewed CSV before a flag-free `--apply` drops its `sign=ledger`, flipping every amount with exit 0, and the note calls the same file "another file" (sibling of w5/594)

**Major · cli · 10–15m · A1.** Real CLI QA, 2026-10-17, HEAD `0e9729be5`, checkout `bea 0.3.1`, macOS 26.5.1. Sibling of open w5/594.
IMPORTING.md:304-305 says a flag-free `--apply` writes "the rows the last
preview showed". The obvious remedy for a pending row (w5/614) is deleting it
from the CSV, which changes the file's hash. No product fix implemented.

`main.bean` opens `Assets:Checking USD`, `Liabilities:Card USD`,
`Expenses:Uncategorized` and `Income:Uncategorized`. `card.csv`:

```
Date,Description,Amount
2026-01-02,Grocery,54.20
2026-01-03,PENDING Hotel hold,200.00
2026-01-04,Gas,40.00
```

```sh
bea --file /abs/main.bean import /abs/card.csv --account Liabilities:Card --csv date=Date,narration=Description,amount=Amount,sign=ledger
# delete the PENDING line from card.csv
bea --json --file /abs/main.bean import /abs/card.csv --apply
```

Actual: the preview shows −54.20, −200.00 and −40.00. The apply exits 0 with
`written: 2` and amounts `54.20 USD` and `40.00 USD`, both posted to
`Liabilities:Card` with the wrong sign. Its note says `card.csv was imported
with sign=ledger, but sign is never carried to another file: card.csv is read
bank-signed.`, though it is the same path and was never imported.

Control: without the edit, the apply says `Re-applied sign=ledger: card.csv is
the file it was chosen for.` and writes −54.20.

Expected: keep `sign=ledger` for the same path and account (after
re-checking the header), or refuse the apply until `sign=` is passed. Never
describe the same file as another.

Cause: `cli/src/cli/commands/import_.py` (around `:739-777`) re-applies sign
only when `_source_sha256(source)` equals `sign_ledger_sha256` (stored at
`:995`). w5/594's proposed fix, a set of hashes per header, would not cover
an edited file.

Fix: key the remembered sign on the source path plus account, or refuse a
flag-free `--apply` whose remembered run used `sign=ledger` when the file
changed.

Dedupe: w5/594 (open) has another trigger (another file previewed in
between); w1/150, w5/078 and 073 (done) are earlier sign fixes.

Acceptance: the edited apply writes −54.20 and −40.00 (or exits 2 asking for
`sign=`). A test pins it.

---
**Resolved 2026-10-19** — a flag-free run on the same name with changed bytes refuses until `sign=` is passed again (no more silent flip, no more "another file" mislabel); shipped in `1390b57e6` (`cli`)
