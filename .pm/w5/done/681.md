# `list --on-disk` now drops a real `document` (relative path, depending on the working directory) or a `note` under `pushtag` when a plugin stamps a copy at its location; the full `list <type>` never marks such copies `generated` (incomplete fix of w5/507)

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-17, HEAD `db21f706`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/507 (done, `92f0bd62`).
w5/507 extended the shared-location rule to every directive type: when two
entries share a location, the one the line spells is on disk. The spelled
entry comes from parsing that line's fragment with no filename and no tag
stack. A relative document path in the fragment therefore resolves against
the process's working directory, and `pushtag` tags are missing. The real
entry then no longer matches its own line. Before the fix, non-transaction
types never used this rule, so these rows were listed. No product fix
implemented.

`mirror.py` (on `PYTHONPATH`) copies every `note` and `document` on
`Assets:Cash` to `Assets:Mirror`. `books/main.bean` (with `books/docs/r.pdf`
present):

```beancount
plugin "mirror"
2026-01-01 open Assets:Cash USD
2026-01-01 open Assets:Mirror USD
2026-01-03 document Assets:Cash "docs/r.pdf"
pushtag #trip
2026-01-04 note Assets:Cash "tagged by pushtag"
poptag #trip
2026-01-05 note Assets:Cash "plain"
```

```sh
bea -f /abs/books/main.bean list document --on-disk           # from the run dir
cd books && bea -f /abs/books/main.bean list document --on-disk
bea -f /abs/books/main.bean list note --on-disk
```

Actual: from the run dir, `No documents found.`; from `books/`, the document is
listed. `list note --on-disk` lists only `plain`, dropping the real `tagged by
pushtag` note.

Also (the w5/507 resolution left this out): the full `list price` (and open,
close, balance, note, commodity, event, custom) shows a plugin copy at a real
line with no `generated` mark, while `--on-disk` drops it. The two views
disagree.

Control: a note outside `pushtag` and a document with an absolute path work from
any directory.

Expected: the real entries are listed by `--on-disk` regardless of cwd and
tags; copies are dropped there and marked `generated` in the full listing.

Cause: `cli/src/bea_engine/ledger/reader.py:181` parses the fragment with
`parser.parse_string(...)` (no filename, no tag stack); the comparison at
`:202-203` includes tags. `cli/src/bea_engine/ledger/listing.py:105-106` passes
`shared` only for transactions.

Fix: compare against a plugin-free parse of the whole file (matched by line),
or at least parse the fragment with `report_filename` and leave tags out;
pass `shared` to every lister.

Dedupe: searched `_spelled_at`, `shared location`, `pushtag` with on-disk;
w5/401 and 507 (done) are the parents.

Acceptance: the commands above list the real entries from any directory, and
the full listing marks the copies. Tests pin them.
