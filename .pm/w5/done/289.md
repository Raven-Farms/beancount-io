# `bea query --source F -o FILE ".help"` prints to stdout and replaces the export with an empty file

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Fix with [236](./236.md).
Low value (a dot command combined with `-o`), but it destroys an existing
export with exit 0. On the `--source` path `.help` and `.parse` write to
the process's stdout instead of the output buffer, and the empty buffer
then replaces the `-o` file. The `--file` path was fixed for this in
w3/done/233. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
2024-01-01 open Equity:Opening USD
2024-01-02 * "Open"
  Assets:Cash  100.00 USD
  Equity:Opening
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`. Create `out.txt` containing `MARKER old export` (18 bytes)
before each command.

```sh
bea query --source main.bean -o out.txt ".help"
```

Actual: exit 0; the help text goes to stdout; `out.txt` is now 0 bytes.

Control: `bea -f main.bean query -o out.txt ".help"` writes 309 bytes of
help into `out.txt`. `bea query --source main.bean -o out.txt ".tables"`
writes 90 bytes. A worker saw `.parse SELECT 1` behave like `.help`, and
stock `bean-query -o` leave the file untouched.

Expected: `docs/USAGE.md`: "an existing `--output` export is replaced only
after the query succeeds"; a result that never reached the buffer should
not replace the export with nothing.

Cause: `GuardedShell` (`cli/src/bea_engine/query.py:318-347`) lacks the
`do_help`/`do_parse` overrides that `PreciseShell` has (`:633-647`);
upstream writes those to process stdout, and `native_one_shot` writes the
empty buffer unconditionally (`:431-432`).

Fix: share the two overrides with `GuardedShell`, and do not replace an
export with an empty result from a dot command. No dependency change.

Blast radius: `query --source … -o` with `.help` or `.parse`. A worker saw
failing dot commands (`.tabels`, `.set bogus 1`) empty the export on
`--source` exactly as 236 describes for `--file`, and `.errors -o` empty
it on both paths.

Dedupe: w3/done/233 fixed only the `--file` shell; w5/236 covers failing
dot commands, not successful ones that bypass the buffer.

Acceptance: the command writes the help text to `out.txt` (or refuses and
leaves it intact); `.tables` is unchanged. Only macOS and the checkout
were exercised.

---

**Resolved 2026-10-13** — The native `--source` shell in `cli/src/bea_engine/query.py` now shares the `--file` shell's `.help` and `.parse` overrides, so both write to the output buffer and reach an `-o` export instead of the terminal. On both paths a one-shot shell command that printed nothing to the buffer (`.history`, `.reload`, `.clear`, a bare `.run` with no stored queries, `.errors` over a ledger with errors, which upstream prints elsewhere) no longer replaces the destination with a zero-byte file: it exits 0, says "Nothing was written to ..." on stderr and neither empties nor creates the file, while a query with no rows still writes its empty result. `tests/test_query_dot_command_export.py` runs the real command on `--file` and `--source` for `.help`, `.parse`, the `.tables` and `.errors` controls, the silent commands, the broken-ledger `.errors` case and the empty-query control; 12 of its 22 cases fail with the fix reverted. One choice beyond the note's main case: the silent commands keep exit 0 with a stderr line rather than becoming a refusal, and `.errors` over a ledger with errors is left intact rather than redirected into the export. `docs/USAGE.md` states the rule. Only macOS was exercised. `make check-all` passed. Shipped in `9a1057ea` (`cli`).
