# `add`, bulk add and `import --apply` that fail after `--allow-errors` drop the tolerated ledger errors: the `--json` error object has no `ledger_warnings`, although USAGE promises it and `query` provides it

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
USAGE:289 says "`ledger_warnings` carries loader errors a `--json`
command tolerated before failing anyway". That holds for `query`, which
routes its tolerated errors through `output.render_ledger_errors`. The
write commands receive theirs inside the engine response. On success they
surface in `data.warnings`. On failure the response is never read, so the
pre-existing errors appear nowhere in the output. An agent is told only
about the new failure, not that the ledger was already broken. No product
fix implemented.

Use a USD ledger opening `Assets:Cash` with a failing `2026-01-20 balance
Assets:Cash 999 USD`. Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME,
BEA_NO_UPDATE_NOTIFIER=1, and closed stdin.

```sh
bea --json -f /absolute/books/main.bean add transaction X --date 2026-03-01 -p 'Expenses:Nope 1 USD' -p Assets:Cash --allow-errors
bea --json -f /absolute/books/main.bean query --allow-errors "SELECT nosuchcol"     # control
```

Actual: the `add` error object has only `category`, `details`,
`exit_code` and `message`. The `query` error object adds
`ledger_warnings: ["…main.bean:3: Balance failed …"]`. The hunter saw
the same omission for bulk `add transactions` (exit 1) and `import
--apply` (exit 4), in two rounds each. I reproduced `add` and the
control.

Expected: per USAGE:289 and :746, every `--json` failure that tolerated
loader errors carries them as `error.ledger_warnings`.

Cause: `add.py:284-286` pops the engine's `ledger_errors` and renders
them only without `--allow-errors`. `output.error()`
(`cli/src/cli/output.py:143-145`) folds in only
`_pending_warnings` (`:834`), which `add` and `import` never populate.

Fix: when an `add` or `import` engine call fails under `--allow-errors`,
pass the tolerated errors into the error envelope as `ledger_warnings`,
for example by registering them before the call or attaching them to the
`LedgerError` result. No dependency change.

Blast radius: agents and scripts using `--json --allow-errors` writes.

Dedupe: 460 covers `list`/`query` success envelopes, and 396 covers
refusal wording without the flag. No `.pm` hit for `ledger_warnings` on
writes.

Acceptance: on the fixture, the failing `add`, bulk add and `import
--apply` include `error.ledger_warnings` naming the failed assertion. A
test pins `add`.

---

**Resolved 2026-10-15** — A refused `--allow-errors` write (`CandidateRejected` in `cli/src/bea_engine/ledger/write.py`) now carries the pre-existing errors the flag tolerated as `ledger_errors`. Bulk `add transactions` (`ledger/adding.py`) forwards them from its batch refusal and its partial-rejection result, and `import` (`importing.py`) forwards them into its needs-review conflict and validation failures. The frontend (`cli/src/cli/engine/launch.py`) puts them in the `--json` error envelope as `ledger_warnings`, as USAGE promises. In text mode a refused write still names only what forced the refusal, which the w5 `allow_errors_*` tests pin. `cli/tests/test_write_failure_ledger_warnings.py` covers `add` (exit 1), bulk add (exit 1), and `import --apply` (exit 4) on the failing-assertion fixture, each listing `main.bean:3: Balance failed` with the ledger untouched. All 3 fail with the fix reverted. Only macOS was exercised. `make check-all` passed (5996 tests). Shipped in `25e43038` (`cli`).
