# A CSV category cell naming an opened account Beancount loads (Thai, a CJK leaf, a leading combining mark) is called "not an account name" and the row goes to Uncategorized, while a rule naming the same account works (gap in w5/203)

**Minor · cli · 5–10m · A1.** Real CLI QA, 2026-10-17, HEAD `701764c5a`, checkout `bea 0.3.1`, macOS 26.5.1. Gap in w5/203 (done).
IMPORTING says a category value that is a full account name categorizes the
row. w5/203 made every other surface accept names the loader accepts. No
product fix implemented.

`main.bean` opens `Assets:Bank USD`, `Expenses:Uncategorized USD` and
`Expenses:Kค่า USD`. `bank.csv` is `Date,Description,Amount,Category` /
`2024-02-05,Market,-3.00,Expenses:Kค่า`.

```sh
bea -f /abs/main.bean import bank.csv --csv date=Date,narration=Description,amount=Amount,category=Category --account Assets:Bank --apply
```

Actual:
- Exit 0, with `1 row(s) carry a category that is not an account name
  ('Expenses:Kค่า'); they post to Expenses:Uncategorized with flag '!'. … or
  map a column of full account names with --csv category=Column.`
- The row is written to `Expenses:Uncategorized`, and the advice tells the
  user to do what they already did.
- `Assets:Cash:中文` and a leading combining mark behave the same (hunter's
  runs).

Control: a rule `account = "Expenses:Kค่า"` writes the row to that account.

Expected: the row posts to `Expenses:Kค่า`.

Cause: `cli/src/bea_engine/csv_mapper.py` (around `:1338`, `:1366`) tests
`is_valid(category)` instead of the loader rule `parse_account`
(`cli/src/bea_engine/ledger/text.py:438`) uses.

Fix: accept a category that `parse_account(category, roots)` accepts, keeping
the review flag for real labels.

Dedupe: w5/203 (done) is the parent; w5/530 (done) covered NFD; w5/637 (open)
covers genuinely invalid importer names.

Acceptance: the fixture posts to `Expenses:Kค่า` with `*`.

---

**Resolved 2026-10-20** — the importer's category check now parses a cell the way Beancount's loader reads account names (`parse_account` against the ledger's root names, cached per importer) instead of `is_valid`, so an opened `Expenses:Kค่า`, `Assets:Cash:中文` or a leaf with a leading combining mark categorizes the row, as a rule naming it already did; a cell that is no account name still goes to Uncategorized with its warning. `tests/test_import_category_loader_valid_accounts.py` covers the three leaves and the control. Gate note: gated as one stack with w5/829 and 828 (one `make check-all`, 9694 passed; each item shipped as its own commit). Shipped in `4760797cb` (`cli`)
