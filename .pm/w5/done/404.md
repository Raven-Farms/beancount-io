# Under a non-UTF-8 locale, `bea treeify` and `bea doctor context` crash on non-Latin-1 text: `treeify` exits 1 with a `UnicodeEncodeError` class name, and `doctor` prints an upstream traceback

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
Forwarded upstream programs run with the locale's codec in strict mode.
Under `LC_ALL=en_US.ISO8859-1` (or `PYTHONIOENCODING=latin-1`/`cp1252`),
any account or payee outside Latin-1 crashes their output: `İstanbul`,
CJK and emoji all do. [w5/121](./done/121.md) made `format` and `query`
write UTF-8 "whatever the locale". Its resolution says "`treeify`,
`example` and `doctor` were not checked". No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:İstanbul USD
2026-01-03 * "İPEK" "istanbul"
  Expenses:İstanbul 5 USD
  Assets:Cash
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, and closed stdin.

```sh
bea -f /absolute/books/main.bean query "SELECT account, sum(position) GROUP BY account" > bal.txt
LC_ALL=en_US.ISO8859-1 bea treeify bal.txt
LC_ALL=en_US.ISO8859-1 bea doctor context /absolute/books/main.bean 4
```

Actual:

- `treeify` exits 1 with `Error: treeify failed (exit 1):
  UnicodeEncodeError: 'latin-1' codec can't encode character 'İ' in
  position 8`.
- `doctor context` exits 1 with a multi-line Click/beancount traceback
  ending in `UnicodeEncodeError`.

Reproduced twice each by the hunter and once each by me.

Control: under a UTF-8 locale, both print `İstanbul` and exit 0. `bea
query` under the Latin-1 locale writes UTF-8 bytes.

Expected: `docs/USAGE.md` says "Ledger text and query results on stdout
are UTF-8 whatever the locale … Only messages are escaped (`\xfc`) when
the locale cannot show them". No class name or traceback should reach
the user (w3/298, w5/089).

Cause: `_native_env` (`cli/src/cli/engine/launch.py:164`, used by
`run_native` at `:113-132`) does not set `PYTHONIOENCODING=utf-8` or
`PYTHONUTF8=1`. The frontend's UTF-8 rule (`output.write_data`,
`cli/src/cli/output.py:63-82`) covers only `format` and `query`.

Fix: set `PYTHONIOENCODING=utf-8` (or `PYTHONUTF8=1`) in `_native_env`
for forwarded natives (`treeify`, `doctor`, `example`, `price`, `ingest`).
No dependency change.

Blast radius: forwarded commands under non-UTF-8 locales or
`PYTHONIOENCODING`, which are common on older systems, in CI images with
`LANG=C` set to a non-UTF-8 codec, and on Windows code pages.

Dedupe: w5/121 (done) names the unchecked commands. w1/104 and w1/057 are
other encode cases. None covers forwarded natives.

Acceptance: under `LC_ALL=en_US.ISO8859-1`, both commands exit 0 and
write UTF-8 `İstanbul`. A test runs `treeify` under a Latin-1
`PYTHONIOENCODING`.

---

**Resolved 2026-10-15** — `_native_env`
(`cli/src/cli/engine/launch.py`) now sets `PYTHONIOENCODING=utf-8` for
every forwarded upstream program. Captured native output (`run_captured`
and `_spawn`'s captured branch) is decoded as UTF-8 rather than in the
locale's codec. `treeify`, `example` and doctor's captured operations
switch stdout to UTF-8 (`output.utf8_stdout`, w5/405) before replaying
it. Under `PYTHONIOENCODING=latin-1`, `bea treeify bal.txt` exits 0 and
writes UTF-8 `İstanbul`, and `bea doctor context main.bean 4` exits 0
with UTF-8 `"İPEK" "istanbul"`. There is no `UnicodeEncodeError` and no
traceback. Pinned by `cli/tests/test_native_utf8_output.py`, which fails
without the fix.
