# A typed `--delimiter` is refused after a header-inferred import of a semicolon file has been remembered

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Fix with [077](./077.md).
After one flag-free import of a `;`-delimited file, the remembered mapping
contains `delimiter=';'` as if the user had typed it. A later comma-
delimited file with the same header cannot be imported: flag-free it fails
on the stale delimiter (077), and the documented remedy, typing
`--delimiter ','`, is refused as conflicting with a `--csv delimiter=` the
user never passed. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Assets:Euro EUR
2026-01-01 open Expenses:Uncategorized
```

`/absolute/books/aug.csv`:

```csv
Date;Description;Amount
2026-08-02;Coffee;-4,50
```

`/absolute/books/sep.csv`:

```csv
Date,Description,Amount
2026-09-02,Lunch,-9.00
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME (fresh), BEA_NO_UPDATE_NOTIFIER=1,
no inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean import aug.csv --account Assets:Checking --apply
bea -f main.bean import sep.csv --delimiter ','
```

Actual: the first exits 0 and writes one entry. The second exits 2:

```text
Error: --delimiter ',' disagrees with --csv delimiter=';'; pass only one.
```

Control: with a fresh config directory, `bea -f main.bean import sep.csv
--delimiter ',' --account Assets:Checking` previews one ready row. A
worker saw the reverse order (comma file first, then `--delimiter ';'`)
work, and a mapping remembered from an explicit `--csv … --delimiter ';'`
accept a later typed delimiter.

Expected: `docs/IMPORTING.md`: "An option you type always wins over one bea
read or remembered."

Cause: `cli/src/cli/commands/import_.py:469-472` appends `delimiter=…` to
an inferred spec so the echoed command pastes back; `:597` stores that
string; on recall (`:426`) it becomes the request, and
`_check_delimiter_conflict` (`:498-500`) treats the remembered key as
typed.

Fix: do not persist the echoed `delimiter=`/`encoding=` keys in the stored
mapping (the record already has a delimiter field), or skip the conflict
check when the spec came from memory so the flag wins. No dependency
change.

Blast radius: every header-inferred import of a non-comma file followed by
a differently delimited file with the same header; today the only way out
is retyping the full `--csv` mapping.

Dedupe: w5/077 is the stale replay of a detected delimiter and names a
typed `--delimiter` as its working control (the comma-first case); w5/073
is typed options not being saved. Neither covers the typed flag being
refused.

Acceptance: the second command previews one ready row; the fresh-config
control is unchanged. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — The refusal no longer reproduces: the w5/077 change to cli/src/cli/commands/import_.py already stopped storing the echoed delimiter= key in the remembered mapping and strips it from older records on recall, so a typed --delimiter ',' now previews one ready row after a header-inferred import of a semicolon file and is saved as the remembered separator. No source change was needed; this adds cli/tests/test_import_typed_delimiter_beats_remembered.py, which pins the note's two commands, the stored record carrying no separator, a record written before that change that still holds delimiter=';' in its mapping, the fresh-config control, and that a --csv delimiter= key and a --delimiter flag typed together and disagreeing are still refused. Three of the five cases fail with the note's exact error when the import command is put back to its state before the w5/077 change; the two controls pass either way. The whole acceptance holds. Only macOS was exercised. `make check-all` passed. Shipped in `7fe30bb6` (`cli`).
