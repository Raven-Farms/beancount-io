# `bea balance -- <term>` forwards the term into the engine's argv without `--`: `-- -f other.bean` reports another ledger's balances under the original target, and `-- -Balances` fails the engine call

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `e03cf71e`, checkout `bea 0.3.1`, macOS 26.5.1. Sibling of w1/155.
`--` is how a user passes a term that starts with a dash (`-Balances` from
`Opening-Balances`, `-Card`). The frontend accepts it, but builds the engine
call as `balance --file F <terms> --conversion …`, so the engine parses the
terms as its own options. No product fix implemented.

`eq.bean`: any ledger with `Equity:Opening-Balances`. `other.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Other USD
2024-01-01 open Equity:Opening-Balances
2024-01-01 * "Other"
  Assets:Other 777.00 USD
  Equity:Opening-Balances
```

```sh
bea -f /abs/eq.bean balance -- -Balances
bea -f /abs/eq.bean --json balance -- -f /abs/other.bean
bea -f /abs/eq.bean balance -- -x EUR
```

Actual:

- `-- -Balances`: exit 1, `Error: The Beancount engine did not answer
  'bea-engine balance --file …/eq.bean -Balances' (exit 2).` with the
  engine's `No such option: -B` box;
- `-- -f other.bean`: exit 0, `target.file` is `eq.bean`,
  `account_filters` null, and the data is other.bean's (`Assets:Other
  777.00 USD`);
- `-- -x EUR`: treated as a conversion, not a filter.

Control: `balance -- Opening-Balances` works; `report -a '-Card'` works,
since option values are passed as `--account VALUE`.

Expected: each term after `--` is an account filter.

Cause: `cli/src/cli/commands/report.py:207-209` builds `["balance", "--file",
file, *terms]` and appends options after the terms, with no `--`.

Fix: options first, then `"--", *terms`.

Dedupe: w1/155 (done) fixed the same class for `query --source`. No note
covers `balance`.

Acceptance: the three commands treat the term as a filter; the second
reports eq.bean's balances. A test pins it.

---

**Resolved 2026-10-17** — Shipped in `89c2d7c6` (`cli`). The engine call for `bea balance` (`cli/src/cli/commands/report.py`) now puts every option first, then `--` and the account terms. `-- -Balances` filters to Opening-Balances, and `-- -f other.bean` is two filter terms against eq.bean (target unchanged, no other ledger read). `-- -x EUR` is two filter terms, not a conversion. `tests/test_balance_terms_after_double_dash.py` pins all three, and all fail without the fix.
