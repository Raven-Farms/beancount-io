# Descriptor paths after w5/582: `--rules /dev/stdin < rules.toml` works once but remembers `/dev/fd/0`, so later plain imports drop and forget the rules (or wait on the terminal); and a `/dev/fd/N` that is a regular file gets the old misleading errors (incomplete fix of w5/582)

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-17, HEAD `9b822564b`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/582 (done, `95e5d6537`).

---

**Resolved 2026-10-20** — a held `--rules` descriptor passes through to the engine child and applies to that run only (prior memory carries forward); `--config`, the import source, `-f`, `--source`, format targets and doctor operands are refused by name; remembered descriptor paths are dropped without opening. Case 1 never stores `/dev/fd/0`, shipped in `deb0d289c` (`cli`).

`main.bean` opens `Assets:Checking`, `Expenses:Food` and
`Expenses:Uncategorized`. `s.csv` is `Date,Payee,Amount` /
`2026-01-07,Cafe Nero,-3.00`. `r.toml` has one `[[rule]]`: `match = "cafe"`,
`account = "Expenses:Food"`.

1. **Remembered descriptor.**
   - `bea -f /abs/main.bean import s.csv --csv date=Date,payee=Payee,amount=Amount
     --account Assets:Checking --rules /dev/stdin < r.toml` exits 0 with rule
     `cafe` applied. The importer record stores `"rules": "/dev/fd/0"`.
   - A later `bea -f /abs/main.bean import s.csv </dev/null` exits 0 with
     `Remembered --rules /dev/fd/0 cannot be used (Rules file /dev/fd/0 must
     hold a [[rule]] list…); importing without rules.`. The row is
     `unmatched`, and the record is rewritten to `"rules": null`.
   - At a terminal, the plain import prints nothing and blocks until EOF
     (hunter's PTY run). USAGE:160 says nothing waits for a human.
2. **`/dev/fd/N` regular file.** `--rules /dev/fd/3 3<r.toml` exits 2 with
   `Cannot read rules file /dev/fd/3: [Errno 13] Permission denied:
   '/dev/fd/3'.`. In the hunter's runs:
   - `--config /dev/fd/3 3<cfg.py` says `Importer configuration not found`.
   - `import /dev/fd/3 3<s.csv` says `Export file not found`.
   - `import /dev/stdin < s.csv` says `The mapping names column 'Date' …,
     which 0 lacks.`
   - `-f /dev/fd/3 check`, `query --source /dev/fd/3`, `format --check
     /dev/fd/3` and `doctor lex /dev/fd/3` give "does not exist" or
     "Permission denied".

Control: `--rules <(cat r.toml)` exits 2 with `--rules /dev/fd/63 is a pipe,
not a file…`. `treeify /dev/fd/4 4<bal.txt` works, because it passes the fd
through.

Expected: a descriptor path either works (passed through) or is refused with
the pipe wording, and is never remembered.

Cause: the w5/582 check (`cli/src/cli/commands/import_.py`, around `:574-593`)
refuses only when `not is_file()`, and stores the resolved `/dev/fd/0`. Engine
children run with `close_fds`, so they cannot open the frontend's
descriptor.

Fix: treat `/dev/stdin`, `/dev/fd/*` and `/proc/self/fd/*` as descriptors: pass
them through with `pass_fds`, or refuse them, and never remember them.

Dedupe: w5/582 and 436 (done) cover FIFOs; w5/737 (open) is `--from`.

Acceptance: case 1 never stores `/dev/fd/0`; case 2 works or is refused by
name. Tests pin both.
