# The query text table prints Python `frozenset({...})` for tags and links of notes and documents, in unstable order

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, Beanquery 0.2.0, macOS.
`SELECT tags, links FROM #notes` (and `#documents`) prints the Python
repr `frozenset({'work', 'tax', 'trip'})` in the text table, with the
element order changing between runs. The same columns from
`#transactions` print cleanly, and CSV and JSON are fine. Stock
`bean-query` prints the same repr; `bea` already fixed the other paths.
No product fix implemented.

Create disposable `/absolute/books/main.bean` (with an empty
`docs/a.pdf`):

```beancount
2024-01-01 open Assets:Cash
2024-01-02 note Assets:Cash "plain note"
2024-01-03 note Assets:Cash "tagged note" #trip #tax #work ^inv-1
2024-01-05 document Assets:Cash "docs/a.pdf" #trip #tax #work ^inv-1
2024-01-06 * "Txn" #trip #tax #work ^inv-1
  Assets:Cash  1 USD
  Assets:Cash  -1 USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean query "SELECT date, tags, links FROM #notes"
bea -f main.bean query "SELECT date, tags, links FROM #transactions"
```

Actual: the first exits 0 with

```text
2024-01-02  frozenset()                         frozenset()
2024-01-03  frozenset({'work', 'tax', 'trip'})  frozenset({'inv-1'})
```

Control: the second prints `tax  trip  work` and `inv-1`. A worker saw a
different element order on a repeat run, the same for `#documents`, and
sorted values in `-f csv` and `--json`.

Expected: the same rendering as the transaction columns — sorted,
space-separated, empty when there are none.

Cause: `cli/src/bea_engine/query.py:728-731` hands rows to the upstream
text renderer, which knows `set` but not `frozenset` and falls back to
`str()`; `_inert_cell` (`:770`) deliberately keeps the `frozenset` type.

Fix: in the text branch, convert `frozenset` cells to sorted sets and
type the column as a set. No dependency or API change.

Blast radius: four columns (`tags`, `links` on notes and documents) in
one-shot text, `.run` and the shell.

Dedupe: w5/105 covers JSON and CSV ordering of set cells; w5/104 covers
`--json PRINT` reprs; w5/171 is `bea list note`. Board search for
frozenset finds nothing else.

Acceptance: the first command prints `tax  trip  work` and `inv-1`, and
blank cells for the plain note, identically across runs. Only macOS and
the checkout were exercised.

---

**Resolved 2026-10-13** — The query text table now prints `tags` and `links` from `#notes` and `#documents` the way it prints a transaction's: sorted, space-separated, and blank when there are none. Those columns are typed `frozenset[str]`, which the upstream text renderer does not recognise, so `cli/src/bea_engine/query.py` retypes any frozenset column as `set` in the text branch of the shell's SELECT handler, covering one-shot queries, `.run` and the interactive shell through the one code path. The regression test `cli/tests/test_query_text_frozenset_cells.py` runs the note's fixture against `#notes`, `#documents` and the `#transactions` control under five hash seeds, asserting identical output and the exact cells, plus a statement piped to the shell on stdin; three of its four cases fail with the fix reverted, the control passing either way. CSV and JSON output are unchanged. Only macOS was exercised. `make check-all` passed. Shipped in `23381826` (`cli`).
