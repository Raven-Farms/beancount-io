# Three paths still miss w5/522's pipe statuses: a `--json --allow-errors` read exits 1, bare `bea` exits 120, and a native command that fails on its own exits 141 whenever stdout's reader is gone (incomplete fix of w5/522)

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-17, HEAD `9eece8ad`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/522 (done, `f197b6a0`).
USAGE:289-294 lists five exit codes plus 130 and 141, where "a closed
downstream pipe still exits 141 … without a message". No product fix
implemented.

`m.bean` is the w5/522 fixture (one unbalanced transaction):

```
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food
2026-01-02 * "lunch"
  Expenses:Food 2.50 USD
  Assets:Cash -5.00 USD
```

In bash:

1. **JSON deferred warnings.** `bea --json -f m.bean list transaction
   --allow-errors 2>&1 >/dev/null | true; echo ${PIPESTATUS[0]}` prints `1`.
   `balance`, `query` and `report balance-sheet` with `--allow-errors` do the
   same. The text-mode command prints `141`. Cause: JSON mode defers the
   tolerated warnings to `output.flush_warnings()`, which
   `cli/src/cli/main.py:286,298` calls after the `BrokenPipeError` guard. The
   error then reaches typer's handler, which exits 1.
2. **No-arguments help.** `bea </dev/null 2>&1 | true` prints `120`, outside
   the table. With a live stream it exits 2, and `bea report` with no
   subcommand keeps 2 under the same pipe. Cause: `main.py:257` re-raises so
   typer can show the help, and typer's `e.show()` raises `BrokenPipeError`
   outside any guard.
3. **Native failures.** `bad.bean` posts to an unopened `Expenses:Nope`.
   - `bea -f bad.bean check 2>/dev/null | true` prints `141`; with a live
     stdout it exits 1.
   - `bea query --source m.bean 'selec x' | true` also prints `141`; its live
     status is 2.

   Their diagnostics were printed in full on stderr, and nothing was written
   to stdout. Control: `bea -f bad.bean list transaction | true` exits 1.
   Cause: `_spawn` (`cli/src/cli/engine/launch.py:770`) maps any child status
   above 0 to 141 when `_downstream_pipe_closed()` reports the reader gone. It
   cannot tell an EPIPE from the child's own failure.

Expected: 141 for 1, 2 (or 141) for 2, and the child's own status for 3.

Fix:
1. Run `flush_warnings`/`print_notice` inside the guard.
2. Handle `BrokenPipeError` around typer's no-args help.
3. Translate to 141 only when the child actually hit EPIPE, for example its
   flush-failure status or the relayed `BrokenPipeError` epilogue.

Dedupe: w5/522 (done) is the parent; w3/378 and w5/160 (done) introduced and
refined the heuristic in item 3.

Acceptance: the commands above give 141, 2, and 1/2. Tests pin each.

**Resolved 2026-10-18** — Shipped in `36a47421aa7744e39b5454435adbed51c7538fcf` (`cli`). Deferred warnings and update notices now run inside the frontend's pipe/output/interrupt guards on normal returns and native `Exit` paths. Bare no-argument help is rendered and flushed inside its parse guard, preserving usage exit 2 when its diagnostic pipe is closed. Native launch no longer infers EPIPE from a nonzero child status plus a closed reader: only FIFO/socket stdout on supported POSIX hosts is relayed, and an actual failed relay write establishes exit 141. No-output native failures retain their original status; terminals and regular files keep direct inheritance. Unrenamed merged stdout/stderr share one relay writer to preserve byte order; renamed diagnostics retain their existing separate relay. USAGE explains attempted-write versus independent-failure statuses.
