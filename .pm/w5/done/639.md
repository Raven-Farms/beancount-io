# Importer-shape refusals name neither the importer nor the fix: a legacy importer listed beside a working one blocks the whole config with "Use the current Beangulp Importer interface", and `extract()` returning one directive is "row 1 is a dict" (gap in w5/319)

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `75a67e85`, checkout `bea 0.3.1`, macOS 26.5.1.
No product fix implemented.

1. **Legacy or class entries.** `CONFIG = [Base([...]), OnlyOfx()]`, where
   `OnlyOfx` is a legacy `ImporterProtocol` that does not identify the file,
   exits 2 with `Use the current Beangulp Importer interface (name property
   and file paths).` A modern importer listed as a class (`CONFIG = [Bank]`)
   gets the same sentence. It names no importer and no fix. The same list
   wrapped in `beangulp.Ingest(CONFIG)()` works under `bea ingest identify`,
   because Beangulp adapts it. Expected: name the entry and its remedy
   (`OnlyOfx: wrap it as beangulp.Adapter(OnlyOfx())`, as IMPORTING.md
   describes; `Bank is a class; list an instance, Bank(...)`). Arguably,
   importers that do not identify the file should not block it. Cause:
   `_name()` (`cli/src/bea_engine/importing.py:838-842`) runs for every entry in
   `_selectors` before `identify`.
2. **`extract()` returns one directive.** `def extract(self, f, e): return
   txn(...)` exits 1 with `Importer base row 1 is a dict, not a Beancount
   directive; extract() must return a list of directives.` (`list()` iterated
   the namedtuple's fields). Expected: `extract() returned a Transaction
   instead of a list of directives`, like w5/319's message for str/None/dict.
   Cause: `_extracted` (`importing.py:712`) does not test
   `isinstance(result, ALL_DIRECTIVES)`.

Dedupe: searched `Adapter`, `ImporterProtocol`, `name property`; w5/319 (done)
covered str/None/bytes/dict.

Acceptance: both refusals name the importer and its fix. Tests pin them.
