# `bea doctor roundtrip` writes its scratch file `main.roundtrip1.bean`, a full printed copy of the ledger, beside a 0600 ledger as 0644

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, umask 022.
Upstream `bean-doctor roundtrip` writes `<ledger>.roundtrip1.bean`
(and `…2`) beside the ledger using the process umask. bea forwards it
unchanged, so a private ledger is briefly copied in world-readable form.
The file exists for the length of the run, a few seconds on large
ledgers, and longer when the run is stopped, since 437 shows bean-doctor
can survive a SIGTERM to bea. No product fix implemented.

Use a 0600 ledger large enough to take a few seconds (the hunter used
60k transactions). Poll the directory every 50 ms during:

```sh
bea doctor roundtrip /absolute/books/main.bean
```

Actual: `-rw-r--r-- main.roundtrip1.bean` (hundreds of KB to several MB)
is visible for about 2–3 s, then removed. Reproduced twice by the
hunter.

Expected: the w5/175 rule. No world-readable copy of private ledger
data, even a transient one.

Cause: `_forward_roundtrip` (`cli/src/cli/commands/doctor.py:412-438`)
runs upstream with the inherited umask.

Fix: run the native child with umask `0o077`, or pre-create both scratch
names at 0600 after the existing collision check (`doctor.py:343+`). No
dependency change.

Dedupe: w5/118, w1/156, w3/409 and w3/410 cover roundtrip's cache,
symlinks, deletion and exit code, not modes. 456 is the ingest
equivalent.

Acceptance: during the run, the scratch files are 0600. A test checks
the mode of the scratch file.

---

**Resolved 2026-10-15** — `_private_roundtrip_artifacts` (`cli/src/cli/commands/doctor.py`) creates both of upstream's scratch names, `<ledger>.roundtrip1/2`, exclusively at mode 0600 right after the existing collision refusal. Upstream's `open(..., "w")` truncates them and keeps that mode, so the printed copies of a private ledger are never world-readable, on the native and compat paths alike. A `finally` removes any scratch file upstream did not get as far as removing. The umask route was not used because the compat path runs inside the engine. `cli/tests/test_doctor_roundtrip_scratch_mode.py` runs a 0600 ledger under umask 022 with a plugin that records the scratch file's mode as upstream starts. It asserts `0o600`, the congratulation, and that neither scratch file remains; it fails with the fix reverted (the file is absent until upstream creates it at 0644). Only macOS was exercised. `make check-all` passed (6018 tests). Shipped in `b06ccbc8` (`cli`).
