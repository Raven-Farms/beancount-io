# `bea doctor linked ROOT txns/jan.bean:1:7` (the region form) no longer resolves an include-relative path: "matched no entries", exit 1

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `3f2372e1`, checkout `bea 0.3.1`, macOS 26.5.1. Regression of w3/355, introduced by the w5/062 fix (`16648894`).
Upstream `linked` accepts a LOCATION (`file:line`) or a REGION
(`file:start:end`). The w5/062 fix splits the filename from one trailing
field for `linked`. So `txns/jan.bean:1:7` is read as file `txns/jan.bean:1`,
which does not exist, and the argument is forwarded unresolved. No product
fix implemented.

`books/main.bean`:

```beancount
include "txns/jan.bean"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
```

`books/txns/jan.bean`:

```beancount
2024-01-05 * "a" ^grp
  Expenses:Food  10 USD
  Assets:Cash

2024-01-06 * "b" ^grp
  Expenses:Food  5 USD
  Assets:Cash
```

From the parent of `books`:

```sh
bea doctor linked books/main.bean txns/jan.bean:1:7
```

Actual: exit 1, stdout `Net Income: ()`, stderr `Error: doctor linked
matched no entries for 'txns/jan.bean:1:7' in books/main.bean.`

Control: `bea doctor linked books/main.bean txns/jan.bean:1` and `bea doctor
region books/main.bean txns/jan.bean:1:7` print the tree and `Net Income:
(-15 USD)`, as does the region form run from inside `books/`.

Expected: the region form resolves like the line form (USAGE: `context`,
`linked` and `region` resolve an include-relative location against the root's
directory).

Cause: `cli/src/cli/commands/doctor.py:157`: `lines = r"\d+:\d+" if op ==
"region" else r"\d+"`. `tests/test_doctor_relative_location.py` covers
`linked` with `file:line` only.

Fix: for `linked`, accept `\d+(?::\d+)?`.

Dedupe: w3/355 (done, covers `linked`) and w5/062 (done, the change that
introduced this).

Acceptance: the command above prints the tree and `Net Income: (-15 USD)`. A
test pins it.

---

**Resolved 2026-10-16** — Shipped in `60dd3911` (`cli`). The include-relative location rewrite in `cli/src/cli/commands/doctor.py` now gives `linked` both of upstream's forms: it tries `file:start:end` first, then `file:line`, each checked against an existing file. `bea doctor linked books/main.bean txns/jan.bean:1:7` prints the tree and `Net Income: (-15 USD)` again, as the line form and `region` do. `tests/test_doctor_linked_region_location.py` pins both forms from outside `books/`; the region form fails without the fix.
