# An NFD-typed `--account`/`--default-account` the ledger does not open is remembered anyway, and every later flag-free import of that header refuses with "matches multiple source accounts" (gap in w5/452 and w5/530)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `8cd20be7`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/530 (done, `4e4b7545`).
IMPORTING.md:285-287 says "A run whose --account or --default-account the
ledger does not open is not remembered — it says so". w5/452 added that guard;
w5/530 normalized importer accounts to NFC. The guard still compares the raw
typed name. No product fix implemented.

`main.bean` opens `Assets:Checking EUR`; `plain.csv` is
`Date,Description,Amount` / `2026-03-01,Shop,-4.50`.

```sh
bea --file /abs/main.bean import plain.csv --account "$(python3 -c 'import unicodedata;print(unicodedata.normalize("NFD","Assets:Crédit"))')"
bea --file /abs/main.bean import plain.csv --account Assets:Checking
bea --file /abs/main.bean import plain.csv
```

Actual:
- Run 1 exits 0 with the row `blocked` and no "Not remembering…" note. The
  record stores `"account": "Assets:Crédit"`.
- Run 3 exits 2: `This CSV header matches multiple source accounts:
  Assets:Checking, Assets:Crédit.`
- `--default-account` with an NFD `Expenses:Thé` is stored the same way
  (hunter's run).

Control: the NFC spelling prints `Not remembering these settings: Assets:Crédit
is not open in this ledger.`, and run 3 then uses `Assets:Checking`.

Expected: the NFD run says it is not remembering, as the NFC run does.

Cause: `cli/src/cli/commands/import_.py:1086-1091` checks the raw names from
`csv_to_remember` against the engine's `unopened_accounts`, which are NFC.

Fix: NFC-normalize both sides, and store remembered accounts in NFC.

Dedupe: w5/452 and 530 (done) are the parents; open w5/536, 541, 637 and 704
cover other NFD surfaces.

Acceptance: run 1 with NFD prints the note and stores nothing; run 3 uses
`Assets:Checking`.
