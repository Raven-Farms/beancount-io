# When the file read is an included leaf (or stdin), the output-destination guard ignores the root that includes it: `bea format txns/2026.bean -o main.bean` replaces the root ledger, and `-o txns/x.bean` joins the include glob and doubles balances, both with exit 0 (gap in w5/072)

**Major · cli · 30–45m · A1.** Real CLI QA, 2026-10-16, HEAD `87ad7af8`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE ("Output destinations") says a bea command refuses a path that "would
become part of the ledger once written", and "never replaces a file it was
not given". Each `-o` guard builds the ledger's closure downward from the
file it was handed. When that file is a leaf of a split ledger, the root
that includes it, and the root's include globs, are outside the closure.
Reads and writes already treat a leaf as part of its root (w5/343/346/348);
the output guards do not. No product fix implemented.

`main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Food USD
2026-01-01 open Equity:Opening USD
include "txns/*.bean"
```

`txns/2026.bean`: an opening transaction of 100.00 USD into `Assets:Checking`.

```sh
bea format txns/2026.bean -o txns/2026-fmt.bean
bea --file main.bean query "SELECT sum(position) WHERE account='Assets:Checking'"
bea format txns/2026.bean -o main.bean
bea --file main.bean check
```

Actual: the first exits 0 and the sum doubles to `200.00 USD` (`check`
passes); `cat txns/2026.bean | bea format -o txns/stdin-fmt.bean` does the
same. The third exits 0 and **replaces `main.bean` with the leaf's text**,
losing its options, opens and include; `check` then fails with unknown
accounts. The same gap: `bea --file txns/2026.bean example --seed 1 -o
txns/ex.bean`, `treeify … -o txns/t.bean`, `ingest extract … -o
txns/extracted.bean`, and `query PRINT -o` from a self-contained leaf all
write into the books with exit 0.

Control: `bea format main.bean -o txns/x.bean` exits 2 with `would become part
of the ledger it reads: include "txns/*.bean" … matches that path.`

Expected: the guard also considers the including root's closure and its
include globs (found the way `write.top_root` does), so all of the above
exit 2 and nothing is written. For stdin `format`, guard against the working
ledger, as `example` and `treeify` already do.

Cause: `output.ledger_closure` (`cli/src/cli/output.py:488`) walks only
downward; `format.py:151` checks only the named paths and the stdin path
(`format.py:102`) checks nothing; `query.py:396`, `example.py:141-145`,
`treeify.py:223-228` and `ingest.py:95-110` use `ctx.entry_file()`.

Fix: as above. Coordinate with w5/578 (open), which narrows when a nearby
includer counts as the root: for this guard, more candidate roots only make
it refuse more.

Dedupe: searched `become part of the ledger`, `included leaf`, `-o main.bean`;
w5/072 (done), 595, 497 and 613 cover other cases.

Acceptance: every command above exits 2 and leaves the files byte-identical.
Tests pin the leaf→glob, leaf→root and stdin cases.

**Resolved 2026-10-17** — Shipped in `9ccdca1f9` (`cli`). Output-destination guards now include nearby ledgers that include the input, climbing through intermediate includers and checking both a named symlink and its resolved target. Leaf-to-root overwrites and leaf-to-include-glob copies are refused before output is written across format, query, example, treeify and ingest. Stdin format checks the working ledger. The existing example `--force` overwrite policy is preserved. Fifteen command-level regression cases cover root/glob destinations, stdin, symlinked leaves, nested includers and a safe output outside the ledger; reverting the fix makes the stdin regression fail. `make check-all` passed (7,341 tests, 2 skipped); the current canonical OpenAPI description was synced and regenerated to clear pre-existing spec drift. Tracked-content gitleaks scan passed; the full-directory scan reported unrelated ignored build/cache matches.
