# `bea price export` copies a local plugin but not the sibling module it imports, then reports success for a snapshot that cannot load

**Trivial · cli · 15–20m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
[094](./done/094.md) made `price export` copy a plugin module that sits
beside the root, so that "the snapshot's `plugin` lines still resolve".
Its resolution notes that "a sibling module it imports from the same
directory is not discovered", but no note tracks that gap. A plugin that
imports a sibling module therefore exports with exit 0, and the snapshot
then fails `bea check` with `ModuleNotFoundError`. No product fix
implemented.

Create `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
option "insert_pythonpath" "TRUE"
plugin "myplug"
2026-01-01 open Assets:Checking USD
```

with `/absolute/books/helper.py` (`TEXT = "x"`) and
`/absolute/books/myplug.py`:

```python
import helper
__plugins__ = ["run"]
def run(entries, options_map, config=None):
    return entries, []
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, and closed stdin.

```sh
bea -f /absolute/books/main.bean price export -o /absolute/exp
bea -f /absolute/exp/main.bean check
```

Actual: the export exits 0 with `Exported 2 files`, copying `main.bean` and
`myplug.py` but not `helper.py`. The snapshot's `check` exits 1 with
`/absolute/exp/main.bean:3: Cannot import plugin "myplug":
ModuleNotFoundError: No module named 'helper'.` Reproduced in three fresh
runs, one of them an independent rerun.

Control: when the helper's code is inlined into the plugin, the exported
snapshot checks clean. A package plugin (`pkgplug/`) is copied whole and
resolves.

Expected: `docs/USAGE.md` says `price export` "snapshots a self-contained
copy for stock tools", and that a plugin beside the root "is copied … so
the snapshot's `plugin` lines still resolve". An export that cannot keep
that promise should say so instead of exiting 0.

Cause: `_export_plugin_modules` (`cli/src/bea_engine/managed_load.py:1247-1274`)
copies `<top>.py` or the `<top>/` package for each `plugin` name and does
not follow the plugin's own imports.

Fix (choose one):

- (a) Also copy the local modules the plugin actually loaded: every
  `sys.modules` entry whose `__file__` is directly under the root's
  directory, or inside a package there.
- (b) Load the written snapshot once, and refuse (or exit nonzero) when its
  plugins fail to import, naming the missing module.

No dependency or API change.

Blast radius: `price export`, with the default destination and with `-o`,
for any ledger whose local plugin imports a sibling module or a helper
package that is not itself named in a `plugin` line.

Dedupe: w5/094 (done) scoped this case out. A board search for "sibling
module", helper together with plugin or export, and
`_export_plugin_modules` finds nothing else.

Acceptance: on the fixture, either `helper.py` is exported and the
snapshot's `check` exits 0, or the export exits nonzero naming `helper` and
writes nothing. A real-command regression test covers both the
plugin-plus-helper case and the single-module case. Only macOS and the
checkout were exercised.

---

**Resolved 2026-10-15** — Option (a). A new `_sibling_imports` (`cli/src/bea_engine/managed_load.py`) imports each local plugin with the root's directory on `sys.path`, because a cached load runs none of them. It then collects every top-level module in `sys.modules` whose file is `<root dir>/<top>.py` or inside `<root dir>/<top>/`. `_export_plugin_modules` copies those beside the plugins themselves. On the fixture, the export writes `main.bean`, `myplug.py` and `helper.py`, and the snapshot's `check` exits 0. An unrelated `.py` beside the ledger that nothing imports is not copied. USAGE's plugin-export sentence says so. `cli/tests/test_price_export_plugin_siblings.py` covers the plugin-plus-helper and single-module cases; the helper case fails with the fix reverted. Only macOS was exercised. `make check-all` passed. Shipped in `32638d15` (`cli`).
