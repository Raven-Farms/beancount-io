# `bea doctor roundtrip` on a ledger whose plugin cannot be imported (or crashes) prints Beancount's raw traceback, then "Entries are the same. Congratulations.", and exits 0

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
w3/371 made `roundtrip` "drop its congratulations and exit 1 on input
`bea check` rejects", but only syntax errors are checked. A plugin import
or runtime failure is a load error. The captured upstream output, a full
traceback followed by the congratulations, is replayed with exit 0. The
same ledger fails `bea check` with a one-line message. `missing-open`,
`print-options` and `display-context` also exit 0 silently on such a
ledger, although the plugin never ran. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
plugin "no.such.plugin"
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, and
closed stdin.

```sh
bea doctor roundtrip /absolute/books/main.bean
bea -f /absolute/books/main.bean check          # control
```

Actual: `roundtrip` prints `<load>:0: Error importing "no.such.plugin":
Traceback (most recent call last): …` (17 frames, ending in
`ModuleNotFoundError`), then `Entries are the same. Congratulations.`,
and exits 0. `plugin "beancount.plugins.currency_accounts"` without its
config behaves the same way, with a `TypeError` traceback. Reproduced by
the hunter in the matrix and by hand, and once by me (the
congratulations line).

Control: `bea check` exits 1 with `main.bean:1: Cannot import plugin
"no.such.plugin": …`.

Expected: `roundtrip` should exit 1 on any input `bea check` rejects,
with no congratulations. It should show the plugin failure in check's
one-line form, with no traceback (w3/298).

Cause: `_forward_roundtrip` (`cli/src/cli/commands/doctor.py:412-438`)
refuses only on `_closure_syntax_errors_of` (`:175-194`).

Fix: also refuse on load errors that are plugin import or run failures,
using the same helper result `check` uses, and print the one-line
message. Apply the same refusal to `missing-open`, `print-options` and
`display-context`. No dependency change.

Blast radius: `bea doctor roundtrip` (and the silent operations) on
ledgers with broken or misconfigured plugins.

Dedupe: w3/371 (done) covers syntax errors only. w5/256 covers `check`
and says doctor was not probed. 400 covers USAGE wording, and 438 covers
unreadable includes. None covers this.

Acceptance: on the fixture, `roundtrip` exits 1 with the one-line plugin
message and no congratulations. The other operations named either refuse
the same way or document that they ignore plugins. A test pins
`roundtrip`.

---

**Resolved 2026-10-15** — when the ledger's closure declares a `plugin`,
every doctor operation that loads the ledger (all but `lex`, `parse` and
`list-options`) now runs the engine's check first
(`_refuse_plugin_failures` in `cli/src/cli/commands/doctor.py`). If that
reports a plugin that cannot be imported or fails while running, the
operation exits 1 before upstream runs, with check's one-line form:
`doctor roundtrip cannot load …/main.bean: …/main.bean:1: Cannot import
plugin "no.such.plugin": ModuleNotFoundError: …`. There is no traceback
and no congratulations. `missing-open`, `print-options` and
`display-context` refuse the same way, as does the `currency_accounts`
run failure. A working plugin still round-trips with exit 0, and ledgers
without plugins pay nothing extra. USAGE's doctor exit contract documents
this. Pinned by `cli/tests/test_doctor_plugin_failure.py`, which fails
without the fix.
