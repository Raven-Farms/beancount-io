# Re-running a Python-importer import writes notes, events and balances again when their text differs from the reloaded ledger

**Minor · cli · 30–45m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
Non-transaction directives from an importer are deduplicated by comparing
printed text. When the importer's strings are in decomposed Unicode (as
macOS file names and some bank exports are), or when an identical balance
assertion already exists but currently fails, the texts differ and every
re-run appends the same directives again with exit 0. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"

2026-01-01 open Assets:Checking USD
2026-01-01 open Assets:Savings USD
2026-01-01 open Expenses:Food
2026-01-01 open Equity:Opening

2026-01-02 * "Opening balance"
  Assets:Checking  1000.00 USD
  Equity:Opening
```

`/absolute/books/imp.py`:

```python
import datetime, unicodedata
from decimal import Decimal as D
from beancount.core import data
from beancount.core.amount import Amount

class Imp:
    name = "demo"
    def identify(self, filepath): return filepath.endswith(".txt")
    def account(self, filepath): return "Assets:Checking"
    def txn(self, filepath, **meta):
        return data.Transaction(dict(data.new_metadata(filepath, 1), **meta), datetime.date(2026, 1, 5), "*", "Cafe", "Coffee", frozenset(), frozenset(), [
            data.Posting("Assets:Checking", Amount(D("-5.25"), "USD"), None, None, None, None),
            data.Posting("Expenses:Food", Amount(D("5.25"), "USD"), None, None, None, None)])
    FORM = "NFD"   # control: "NFC"
    def extract(self, filepath, existing):
        n = lambda s: unicodedata.normalize(self.FORM, s)
        m = lambda i: data.new_metadata(filepath, i)
        return [self.txn(filepath),
                data.Note(m(2), datetime.date(2026, 1, 6), "Assets:Checking", n("relev\u00e9 de janvier"), None, None),
                data.Event(m(3), datetime.date(2026, 1, 6), "location", n("Z\u00fcrich")),
                data.Balance(dict(m(4), source=n("relev\u00e9")), datetime.date(2026, 1, 6), "Assets:Checking", Amount(D("994.75"), "USD"), None, None)]
CONFIG = [Imp()]
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.
`/absolute/books/stmt.txt` holds the single line `statement`.
Run the command three times.

```sh
bea -f main.bean import stmt.txt --config imp.py --apply
```

Actual: all three exit 0. Afterwards the ledger holds the note, the event
and the balance three times each (the transaction once); stock
`bean-check` still passes.

Second trigger: with `2026-01-06 balance Assets:Checking 994.75 USD`
already in the ledger (failing, because the coffee is missing) and an
importer returning the transaction plus that same balance, `--apply
--allow-errors` exits 0 and the ledger holds the balance line twice.

Control: with `FORM = "NFC"` three runs leave one note, one event and one
balance. Without the pre-existing balance, apply then re-apply leaves one
balance line.

Expected: `docs/IMPORTING.md`: "Identical nontransaction directives are
skipped."

Cause: `cli/src/bea_engine/importing.py:255` builds the identity set from
the printed text of loaded entries and `:356-359` compares the importer
entry's own printed text. The loader normalises ledger text to NFC
(`cli/src/bea_engine/compat.py:54-69`) while the printer normalises only
account names; and a failing balance loads with a difference attached, which
the printer appends as a `; Diff:` comment.

Fix: compare a canonical form on both sides (NFC text; balance without the
computed difference), and write the NFC form as is already done for account
names. No dependency or API change.

Blast radius: Python importers only (the CSV mapper emits transactions,
which match by id and were skipped correctly here).

Dedupe: board search for "Identical directive", `diff_amount`, `; Diff`
and NFD finds w3/done/377 (transaction id hashing across normalisations)
and w5/199 (NFD account names on `add`); neither covers the non-transaction
text comparison.

Acceptance: three runs of the NFD fixture leave one note, one event and one
balance; the failing-balance fixture is reported as an identical directive
and not written again. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — Import now compares and writes non-transaction directives in the form the ledger reads them back: `cli/src/bea_engine/importing.py` gained `_directive_text`, which prints a note, event, balance or other non-transaction entry as Unicode NFC text and drops the computed difference a currently failing balance loads with, and both the existing-ledger set and the importer's own entries go through it. `cli/docs/IMPORTING.md` states that rule beside "Identical nontransaction directives are skipped". The regression test `cli/tests/test_import_identical_directive_reloaded.py` runs a real Python importer three times with NFD and with NFC strings (one note, one event and one balance remain, later runs report "Identical directive already exists."), applies over a pre-existing failing balance with `--allow-errors` (reported identical, not written again), and keeps two controls: a balance the importer wrote is skipped on the next run, and a failing balance on another date is still new. Two of the five cases fail with the source change reverted (the NFD run and the failing-balance fixture). Transactions are unchanged; they still match by id and keep the importer's own text. Only macOS was exercised. `make check-all` passed. Shipped in `7d2490c0` (`cli`).
