# `bea query ""` on a terminal opens the interactive shell instead of exiting 2

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-11, HEAD `0227141a` (CLI unchanged since `97600b74`),
checkout `bea 0.3.1`, macOS, driven through a real pseudo-terminal.
An explicitly empty query argument is treated like no argument at all, so on a
terminal it drops into the interactive prompt and waits. A script line such as
`bea query "$Q"` with `Q` unset, or an agent running commands under a
pseudo-terminal, stalls instead of getting the documented usage error. No
product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Food USD
2026-01-05 * "Cafe" "Coffee"
  Expenses:Food  4.00 USD
  Assets:Checking
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN/CI, `TERM=dumb`, and stdin, stdout and stderr all
attached to a pseudo-terminal.

```sh
bea -f /absolute/books/main.bean query ""
```

Actual: the `beanquery>` prompt appears and the process waits for input;
after `.exit` it exits 0. Repeated twice. A worker observed that
`query "" -o out.txt` also truncates `out.txt` before opening the shell;
I did not re-run that variant.

Control: `bea -f /absolute/books/main.bean query " "` on the same terminal
exits 2 with `Error: A query is required as an argument or on stdin.`

Expected: `docs/USAGE.md` says "One-shot queries carry exactly one
statement: an empty or whitespace-only query … [is] refused with exit 2", and
w1/m23/t005 required a blank query to be rejected in every mode.

Cause: `cli/src/cli/commands/query.py:281` (and `:257` for `--source`)
test `if not query_string:`, which is true for `""` as well as for an
omitted argument.

Fix: open the shell or read stdin only when the argument is absent
(`query_string is None`); an explicit empty string takes the same usage
error as whitespace. No dependency or API change.

Dedupe: board search for empty and whitespace-only queries finds w3/262 and
w1/m23/t005 (the whitespace form, done); the empty string on a terminal
remained.

Acceptance: `query ""` exits 2 with the usage message on a terminal, with
piped stdin and with `--source`, and with `-o` leaves an existing output
file untouched; `query` with no argument still opens the shell. A PTY
regression test covers it. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — `bea query` now opens the interactive shell or reads stdin only when the query argument is omitted; an explicit empty string takes the same exit-2 usage error as a whitespace-only query, in the `--file` and `--source` branches of `cli/src/cli/commands/query.py`. A PTY regression test covers the empty argument on a terminal, with piped stdin, with `--source`, and with `-o` against an existing file (six cases fail with the fix reverted), plus the whitespace and omitted-argument controls. `make check-all` passed. Only macOS was exercised. Shipped in `8e577049` (`cli`).
