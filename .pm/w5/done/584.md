# With stdin closed (`<&-`), commands that read stdin exit 1 with a raw `'NoneType' object has no attribute 'isatty'` / `'read'`, instead of their exit-2 refusals

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `f29eb957`, checkout `bea 0.3.1`, macOS 26.5.1. Sibling of w5/258 (closed stdout) and w5/308 (closed stderr).
CI runners and daemons sometimes start a process with fd 0 closed. Python
then sets `sys.stdin` to `None`. `context._stdin_is_a_terminal` handles that,
but several commands call `sys.stdin` methods directly. No product fix
implemented.

Any valid ledger. For each ARGS below:

```sh
sh -c "exec bea -f /abs/main.bean ARGS <&-"
```

with ARGS = `query`, `query --source main.bean`, `format -`, `add transactions
--from -`, `treeify`.

Actual: exit 1 each time: `Error: 'NoneType' object has no attribute 'isatty'.
Pass --debug before the command for a traceback.` (both query forms), `…
'read'.` (`format -`, `add transactions --from -`), and `Error: treeify failed
(exit 1): TypeError: 'NoneType' object is not iterable.`

Control: with `</dev/null`, query exits 2 (`A query is required as an
argument or on stdin.`), `add transactions` exits 2 (`Invalid JSON…`),
`format -` exits 0, and treeify exits 2.

Expected: a closed stdin behaves like an empty one: the same exit-2
refusals (or empty input), with no Python attribute text.

Cause: `cli/src/cli/commands/query.py:373` and `:397` call
`sys.stdin.isatty()`; `cli/src/cli/commands/format.py:594-596` and
`cli/src/cli/commands/add.py:583-584` call `sys.stdin.read()`; treeify starts
upstream without fd 0.

Fix: treat `sys.stdin is None` as empty input (and give natives
`stdin=DEVNULL`), perhaps by reopening fd 0 on `/dev/null` at startup the way
`_discard_diagnostics` does for fd 2.

Dedupe: searched `<&-`, `'isatty'`, `stdin closed`. w5/258 and 308 (done) are
the siblings.

Acceptance: the five commands give the `</dev/null` results. A test pins
them.

---

**Resolved 2026-10-17** — Shipped in `558ae1a7` (`cli`). `_empty_stdin_when_closed` (`cli/src/cli/main.py`) runs at startup beside the stderr guard. When fd 0 is closed, it reopens it on `/dev/null`, inheritable, and gives `sys.stdin` a reader on it. The note's five commands now answer as with `</dev/null`:
- `query` and `query --source` exit 2 with `A query is required …`;
- `format -` exits 0;
- `add transactions --from -` exits 2 with `Invalid JSON …`;
- `treeify` exits 2 with its no-column refusal.

`tests/test_closed_stdin_reads_empty.py` pins all five with fd 0 closed; all fail without the fix.

Gate: `test_release`'s cold-cache `uv sync` timed out again (the known network flake; wheels at about 450 KB/s). The rest of `make check-all` passed (7046).
