# `ingest --config FIFO` hangs in AST preflight before its existing regular-file refusal, even with `--no-input`

**Minor · cli · 15–30m · A1.** Real CLI QA, 2026-10-20, checkout
`bea 0.3.1`, HEAD `c83638602`, Darwin 25.5.0 arm64, frontend Python 3.13.3.
The existing managed engine has Beangulp enabled/present; no installation
changed. Reproduced twice for each of `identify`, `extract` and
`archive --dry-run`. No product fix implemented.

Create a disposable empty `downloads/` directory and a named pipe
`ingest.py`, with no writer attached. Use isolated absolute
`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, no inherited
`BEA_FILE`/`BEA_TOKEN`, cwd `/abs/case`, closed stdin and no TTY. A bounded
reproducer avoids leaving the affected command running:

```python
import os, subprocess
from pathlib import Path
case = Path('/abs/case')
case.mkdir(parents=True, exist_ok=True)
source = case / 'downloads'
source.mkdir(exist_ok=True)
fifo = case / 'ingest.py'
os.mkfifo(fifo)
env = os.environ.copy()
for key in ('BEA_FILE', 'BEA_TOKEN'):
    env.pop(key, None)
env.update(BEA_CONFIG_DIR=str(case / 'config'),
           XDG_CACHE_HOME=str(case / 'cache'), BEA_NO_UPDATE_NOTIFIER='1')
p = subprocess.Popen(
    ['/abs/checkout/cli/.venv/bin/bea', '--no-input', 'ingest', 'identify',
     '--config', str(fifo), str(source)], cwd=case, env=env,
    stdin=subprocess.DEVNULL, stdout=subprocess.PIPE, stderr=subprocess.PIPE,
    text=True, start_new_session=True)
try:
    try:
        out, err = p.communicate(timeout=3)
        print('returned:', p.returncode, repr(out), repr(err))
    except subprocess.TimeoutExpired:
        p.terminate()
        out, err = p.communicate(timeout=2)
        print('timed out:', p.returncode, repr(out), repr(err))
finally:
    fifo.unlink()
```

Repeat from a fresh case using `extract` instead of `identify`, or
`archive` with `--dry-run` appended. Actual: all six runs time out after
about 3 seconds, stdout/stderr both empty. Only the frontend is live; no
engine/script child has started. SIGTERM ends it with subprocess return
code −15. That signal status is harness cleanup, not a CLI error category.
All test processes exited and all named pipes were removed. No documents
were extracted or moved.

Passing controls, twice each: a regular script containing
`from beangulp import Ingest` and
`if __name__ == "__main__": Ingest([])()` exits 0 promptly over the empty
source. The full regular-script extract/archive lifecycle also passed
independently. `--json ingest identify --config FIFO ...` promptly exits 2
with the documented unsupported-JSON refusal, and global `--file FIFO`
check/query promptly exit 2 naming a non-regular ledger. Feed the ingest
pipe exactly one valid script and the CLI consumes it, then exits 2 with
`Ingest script not found: ...`: its regular-file guard exists, but runs
after reading. Bulk `add transactions --from` deliberately accepts streams;
its wait for a FIFO writer is not this finding.

Expected: refuse a non-regular ingest script with usage exit 2 before
opening/parsing it, naming `--config` and telling the caller to save a
regular Python script. This does not request FIFO-script support. The CLI
already enforces a regular script in `run_optional_script`; preflight must
not block before that requirement. There is no prompt to answer.

Cause: `cli/src/cli/commands/ingest.py:99` calls
`_refuse_config_only_script` (:222), whose `_parsed` (:259–264) calls
`script.read_bytes()` unconditionally. Opening an unfed FIFO waits for a
writer. The `script.is_file()` refusal in
`cli/src/cli/engine/launch.py:324–325` runs afterward, through the call at
`ingest.py:106`. All three ingest operations share `_forward`.

Fix: check the script's file type before AST preflight, reusing the existing
non-regular-input diagnostic where appropriate. Preserve CONFIG-only and
aliased-entrypoint detection, regular script forwarding and the Beangulp
feature gate. No dependency or backend/API change is needed.

Dedupe: searched all board states for ingest hangs, config FIFOs, script
preflight and named pipes, and reviewed open milestone scopes. Completed
w5/582 (`95e5d653`) adds the early pipe check to import `--config`/`--rules`,
not ingest; w5/706 guards ingest's existing-ledger input. w5/851
(`7a8278c5b`) changes this AST preflight without moving the script type
check ahead of it. No overlapping open item or later repair found.

Acceptance: all three operations with an unfed config FIFO return the usage
refusal promptly under closed stdin/`--no-input`, with no script execution
or file changes; regular-script controls continue working. Pin bounded real
subprocess coverage so a reintroduced hang cannot stall tests. Windows
named pipes, symlink-to-FIFO configs and repaired behavior are unverified.
Sanitized captures are
`.tmp/qa-2026-10-20-cli-loop-pass2-2afc4ed1/captures/fifo-config-*.json`;
case directories retain empty sources and regular controls, with every
named pipe removed. The public reproduction is self-contained.

**Resolved 2026-10-22** — `ingest --config` now refuses an existing non-regular path (a named pipe) with usage exit 2 naming `--config`, before the CONFIG preflight opens it; a missing path and regular scripts behave as before. `cli/tests/test_ingest_config_fifo.py` runs identify, extract and archive --dry-run against an unfed pipe under a timeout and fails (hangs) without the fix; shipped in the commit that moves this note (`cli`).
