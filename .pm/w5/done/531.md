# A doubled BOM or a zero-width character in a CSV header is invisible in `bea import`'s refusal, and following its own `--csv date=Date,…` advice fails with "which bank.csv lacks"

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-16, HEAD `5d08dc41`, checkout `bea 0.3.1`, macOS 26.5.1.
Some export tools write a BOM twice, and spreadsheet round trips can leave a
U+200B in a header cell. IMPORTING.md says the file may start with a BOM and
that header cells are stripped before matching. Amount cells already drop
U+200B, U+2060 and U+FEFF; header cells do not. The refusal prints the
invisible character raw, so the user copies a mapping that cannot match.
No product fix implemented.

`bank.csv`, as bytes: `EF BB BF EF BB BF` then
`Date,Description,Amount\n2026-03-01,Coffee,-4.50\n`. Ledger with
`Assets:Checking` open.

```sh
bea --file /abs/main.bean import bank.csv --account Assets:Checking
bea --file /abs/main.bean import bank.csv --csv date=Date,amount=Amount,narration=Description --account Assets:Checking
```

Actual: the first exits 2 with `Its columns are: Date, Description, Amount.
Name them with --csv date=Date,amount=Amount,narration=Description.` (a U+FEFF
is hidden before `Date`); the second exits 2 with `The mapping names column
'Date' for date, which bank.csv lacks.` and no "did you mean". A U+200B after
`Description` behaves the same.

Control: a single-BOM file imports.

Expected: header cells drop zero-width characters and BOMs (U+200B, U+2060,
U+FEFF), as amount cells do, so the file imports. At minimum, the column
list shows them escaped and the lookalike hint offers the header.

Cause: header cells get only `.strip()` and NFC
(`cli/src/cli/csv_mapper.py:663`, `cli/src/bea_engine/csv_mapper.py:860`);
`_lookalike_header` (`cli/src/bea_engine/csv_mapper.py:949-953`) compares by
casefold only; the listing (`cli/src/cli/commands/import_.py:223`) prints
cells raw.

Fix: strip `_ZERO_WIDTH` from header cells in both copies; escape
invisible characters in the listing.

Dedupe: searched `double bom`, `ufeff`, `zero-width`, `lacks`. Nothing for
headers.

Acceptance: both fixtures import with the inferred mapping. A test pins
them.

---

**Resolved 2026-10-17** — Shipped in `6a66e16a` (`cli`). `open_records`, the one CSV reader every path shares (in both `cli/src/cli/csv_mapper.py` and `cli/src/bea_engine/csv_mapper.py`), now drops U+200B, U+2060 and U+FEFF from header cells before strip and NFC, as amount cells already did. A doubled BOM before `Date`, a U+200B after `Description` or a word joiner after `Date` no longer leaves a column unmatchable. Each file imports with the inferred mapping and with an explicit `--csv date=Date,…`. The column listing needs no escaping now, since the characters are gone. `tests/test_csv_header_zero_width.py` pins the three headers both ways; all six fail without the fix.
