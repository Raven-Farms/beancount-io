# `add transaction` pins an unclosed `{` on the next posting, or blames the "transaction header" when it is in the last posting

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `7334a32b`, checkout `bea 0.3.1`, macOS 26.5.1.
Beancount reports an "unexpected EOL" error on the line after the one that
is missing the token. bea maps the error's line back to a `--posting N`, so
the blame moves one posting down. For the last posting it falls outside the
range and lands on the header options, which the user did not touch. U+2028
or U+2029 in the narration, payee or a meta value shifts it the same way,
because the header's lines are counted with `str.splitlines`. No product
fix implemented.

Any ledger with `Assets:Cash` and `Assets:Brokerage` open. Isolated config/cache, closed stdin.

```sh
bea -f /abs/main.bean add transaction ab --date 2026-01-05 -p 'Assets:Cash -20 USD' -p 'Assets:Brokerage 2 HOOL {10 USD'
bea -f /abs/main.bean add transaction ab --date 2026-01-05 -p 'Assets:Brokerage 2 HOOL {10 USD' -p 'Assets:Cash -20 USD'
bea -f /abs/main.bean add transaction $'a b' --date 2026-01-05 -p 'Assets:Cash 1 USD }' -p 'Assets:Brokerage'
```

Actual:

- the first exits 2 with `Error: Invalid transaction header (--tag, --link,
  --flag, --payee, --narration, or --meta). Nothing was written.` and the
  detail `Transaction options: syntax error, unexpected EOL, expecting RCURL
  or COMMA`;
- the second blames `--posting 2`, and with three postings an error in
  posting 2 is blamed on `--posting 3`;
- the third blames the header too.

Control: narration `ab` with `-p 'Assets:Cash 1 USD }'` first reports
`--posting 1: syntax error, unexpected RCURL…`.

Expected: the posting that holds the error is named (`--posting 2` for the
first command, `--posting 1` for the second and third), and the header is
blamed only for header errors.

Cause: `cli/src/bea_engine/ledger/adding.py:753` computes `lineno -
len(header_text.splitlines())`. There is no adjustment for EOL errors
reported on the next line, and `splitlines` counts U+2028/U+2029 (sibling of
the w5/380 `lexer_lines` fix). Out-of-range numbers fall to `_HEADER_ERROR`.

Fix: count header lines on `\n` only. Map an `unexpected EOL` error back one
line, or parse each posting on its own line to attribute errors.

Dedupe: searched `unexpected EOL`, `Invalid transaction header`. w3/268 used
a brace error in posting 1 as a control; nothing covers the shift.

Acceptance: the three commands name the right posting. A test pins each.

---

**Resolved 2026-10-16** — Shipped in `4cc3c597` (`cli`). The posting attribution in `add transaction` (`cli/src/bea_engine/ledger/adding.py`) now counts the header's lines on `\n` alone, as the lexer does. It attributes an `unexpected EOL` error to the line before the one Beancount reports it on, where the missing token is. An unclosed `{` in the last, first or middle posting is blamed on that posting, and a U+2028 in the narration no longer moves an error onto the header. `tests/test_add_transaction_posting_blame.py` pins five cases; four fail without the fix. In the U+2029 case the two old off-by-ones happened to cancel.
