# An export written into a directory an include glob matches silently joins the ledger

**Major (wrong balances, exit 0) · cli · 45–60m · A1.** Real CLI QA,
2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, macOS. The
output-destination guard refuses a destination that is already one of the
ledger's files. It does not notice a destination that does not exist yet but
will be matched by one of the ledger's `include` globs the moment it is
written. A `PRINT` backup saved there is loaded as part of the books on the
next command: every exported transaction counts twice, `bea check` still exits
0, and nothing says so. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Equity:Opening USD
include "txns/*.bean"
```

and `/absolute/books/txns/jan.bean`:

```beancount
2026-01-02 * "a"
  Assets:Cash  5 USD
  Equity:Opening
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`:

```sh
bea -f /absolute/books/main.bean query "SELECT sum(position) WHERE account = 'Assets:Cash'"
bea -f /absolute/books/main.bean query "PRINT FROM date >= 2026-01-02" -o txns/backup.bean
bea -f /absolute/books/main.bean check
bea -f /absolute/books/main.bean query "SELECT sum(position) WHERE account = 'Assets:Cash'"
```

Actual: the first query prints `5 USD`. The export exits 0 with empty output
and writes the one transaction to `txns/backup.bean`. `check` exits 0 with no
output. The last query prints `10 USD`. Repeated twice from a pristine
fixture. Independent arithmetic: the ledger holds one 5 USD posting to
`Assets:Cash`.

Louder variants of the same gap, each exit 0 on a fresh fixture, leave
`bea check` failing instead of silently wrong: a text table or `-f csv` export
to `txns/out.bean` (`Invalid token: 'date'`), an unfiltered `PRINT -o
txns/copy.bean` (`Duplicate open directive`), `bea format main.bean -o
txns/fmt.bean`, and `bea treeify t.txt -o txns/t.bean`. `bea example -o
txns/ex.bean` exits 0 and merges a whole generated history into the books with
`check` still passing.

Controls: `-o txns/jan.bean`, an existing member, exits 2 with `would
overwrite the ledger it reads`. `-o backup.bean` beside the root, which no
include matches, exits 0 and leaves `check` and the balance at `5 USD`.
`-o txns/out.txt`, inside the directory but outside the glob, is harmless.

Expected: `docs/USAGE.md` Output destinations refuses a destination that "is
the ledger under read — the root file or anything it includes", and Exit codes
promises that an exit-0 run "left the ledger no worse than it found it". A
path one of the closure's include globs matches is a file the ledger includes
as soon as the write lands, so it should be refused with exit 2 before
anything is written, naming the path and the include directive that would
claim it. Backing up or archiving entries next to the files they came from is
an ordinary thing to try, and the silent form misstates every balance.

Cause: `cli/src/cli/output.py:314-327` (`refuse_ledger_alias`) compares the
destination with `ledger_closure(ledger)` by file identity
(`same_file`, `:301`). The closure is built by `walk_closure` (`:249-286`)
from files that exist now, so an absent destination has no identity to match
and no include pattern is tested against it. `guard_output_destination`
(`:412-431`) adds only the existing-`.bean` rule for treeify and example.

Fix: in the shared guard, also refuse a destination whose resolved path is
matched by any `include` pattern in the closure, evaluated relative to the
including file's directory exactly as the walk resolves it (literal names and
globs, `**` included). This covers every caller at once — `query -o`,
`format -o`, `treeify -o`, `example -o`, `ingest extract -o`, the interactive
`.output`, and each file `price export` plans to write. `--force` must not
bypass it, as with the existing first case. Destinations outside every
pattern keep working, including other suffixes in the same directory. Extend
the Output destinations paragraph. No dependency or API change.

Dedupe: board search for include globs with output destinations finds
w3/431, w1/141 and w1/159 (existing members and their spellings), w3/436,
w4/171, w4/172 and w3/412 (`price export` collisions and escapes) and w3/437
(`--into` creating its destination); none covers an absent destination that
an include glob would claim. `git log -S refuse_ledger_alias -- cli` shows
identity comparison only.

Acceptance: on the fixture, each listed command with a destination under
`txns/*.bean` exits 2 naming the path and the include, creates nothing, and
leaves `check` at exit 0 and the balance at `5 USD`; the three controls
behave as today. Real-command regression tests cover a literal absent include
target, a single-level glob, a recursive glob and a glob declared in an
included child file. Only macOS and the checkout were exercised; the
interactive `.output` and `price export` paths are source-inferred, not run.

---

**Resolved 2026-10-12** — An output destination that does not exist yet but that an `include` pattern in the ledger's closure would match is refused with exit 2 before anything is written, naming the path and the include. The check lives in the shared frontend guard, so `query -o`, `format -o`, `treeify -o` and `ingest extract -o` inherit it; `bea example -o` applies it against the working ledger and `--force` does not bypass it; the engine's interactive `.output` redirect and each file `price export` plans to write are checked the same way. `docs/USAGE.md` Output destinations lists the case. Shipped in `bddbd867` (`cli`).

Real-command regression tests cover six command shapes against a single-level glob (each asserting exit 2, no file created, `check` still 0 and the balance still `5 USD`), five include shapes — a literal absent target, `**/*.bean`, a bare `**`, a glob declared in an included child, an absolute pattern — four destinations no include matches that are still written (beside the root, another suffix, a deeper directory, a hidden name), the existing-member refusal, and `price export` into an included directory. Twelve fail with the fix reverted. `make check-all` passed.

Limits: the directory part of a pattern is expanded as it exists when the command runs, so a recursive glob does not claim a path whose parent directories the same command would have to create — reachable only through `price export`, which creates its tree. The interactive `.output` refusal was not run under a terminal; it is covered by the shared helper only. Only macOS was exercised.
