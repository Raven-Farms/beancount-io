# `bea treeify` on a missing, directory or unreadable input exits 1 (`validation`) with a Python class name, where other commands exit 2 or 3 with a plain message

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
w3/298, fixed in `4ce341a6` under w1/m25/t001, turned the `treeify`
traceback for a bad input path into one line. The exit category was left
alone. A missing file or a directory is still exit 1 (`validation`), and
an unreadable file is not exit 3. All three messages show upstream's
exception class. No product fix implemented.

Use an empty directory with a subdirectory `d` and an unreadable file
(`echo x > ro.txt; chmod 000 ro.txt`). Use isolated
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no inherited
BEA_FILE/BEA_TOKEN, and closed stdin.

```sh
bea treeify nope.txt
bea treeify d
bea treeify ro.txt
```

Actual: each command exits 1.

- `treeify failed (exit 1): FileNotFoundError: [Errno 2] No such file or
  directory: 'nope.txt'`
- `… IsADirectoryError: [Errno 21] Is a directory: 'd'`
- `… PermissionError: [Errno 13] Permission denied: 'ro.txt'`

Reproduced twice by the hunter and once by me.

Control: these commands exit 2 with plain messages:

- `bea doctor lex nope.bean` gives `Path 'nope.bean' does not exist`.
- `bea format nope.bean` gives `Formatting target does not exist`.
- `bea query --source nope.bean …` gives `No ledger file at 'nope.bean'
  (from --source)`.

Expected: the `docs/USAGE.md` exit table gives 2 (`usage`) for "Bad
arguments, missing target…" and 3 for "Authentication or permission
failure". A missing or directory input should exit 2, naming the path,
and an unreadable one should exit 3. Neither message should show an
exception class.

Cause: `cli/src/cli/commands/treeify.py:106-155` forwards `parsed.input`
without checking it. `launch.check_native`
(`cli/src/cli/engine/launch.py:299-305`) maps any non-2 upstream exit to
`BeaError` (exit 1).

Fix: after parsing, refuse a missing or directory input with `UsageError`
and an unreadable one with the permission error, as `format` does. Update
the w1/m25 unit test that pins `exit 1 … FileNotFoundError`. No dependency
change.

Blast radius: `bea treeify FILE` with a wrong path, in scripts that branch
on the exit category.

Dedupe: searched `.pm/**`, including `done/`, for treeify together with
FileNotFoundError, IsADirectoryError and PermissionError. w3/298 and
w1/m25/t001 changed the message only. Nothing else covers it.

Acceptance: the three commands exit 2, 2 and 3 with plain messages naming
the path and no class name. A valid input and stdin still work. A test
pins all three. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-15** — `treeify` (`cli/src/cli/commands/treeify.py`) checks its input with a new `_check_input` after parsing, before anything is forwarded. A missing path or a directory exits 2 with "treeify input '…' does not exist" or "is a directory", and an unreadable file exits 3 with "Cannot read treeify input '…': permission denied." None of them shows a class name. stdin (`-` or none) and a held `/dev/fd/N` pass through as before, and a valid file and stdin still render. `cli/tests/test_treeify_input_paths.py` pins the three refusals and the two controls; the 3 refusal cases fail with the fix reverted. `test_forwarded_short_options.py`'s output-spelling test fed a mocked engine an `input.txt` that did not exist, and now creates it. The first gate run also hit the known ACL-principal flake in `test_write_keeps_file_metadata.py`, which passes alone. Only macOS was exercised. `make check-all` passed. Shipped in `508ba42a` (`cli`).
