# On a ledger with a managed price include, `BEANCOUNT_DISABLE_LOAD_CACHE` no longer forces a fresh load and `check --no-cache` is refused, so a stale `.managed` load cache cannot be bypassed short of deleting it (new with w5/576)

**Minor · cli · 5–10m · A1.** Real CLI QA, 2026-10-17, HEAD `3fe1ca1ff`, checkout `bea 0.3.1`, macOS 26.5.1. Simulation: a local price feed on 127.0.0.1 allowed by `MANAGED_PRICE_ORIGINS`. New with w5/576 (done, `523a46f44`).
Before w5/576, every load with a managed include was fresh. bea honours
`BEANCOUNT_DISABLE_LOAD_CACHE` for Beancount's own cache, and w1/083 and
w5/116 use it as the way to force a fresh load. No product fix implemented.

`main.bean`: `option "operating_currency" "USD"`, `include
"http://127.0.0.1:<port>/prices/BTC-USD"`, opens for `Assets:Cash` and
`Expenses:Food`, `commodity BTC`, and `include "txns.bean"`. `txns.bean` holds
40,000 food transactions, so the load passes the caching threshold.

1. `bea -f /abs/main.bean check` twice; the second run is served from
   `…/cache/bea/load-cache/….main.bean.picklecache.managed`.
2. Edit the last `Expenses:Food` in `txns.bean` to `Expenses:Fodo`, keeping
   its size and mtime.
3. `bea -f /abs/main.bean check` exits 0. Upstream's own cache behaves the
   same under this edit, so this alone is not the bug.
4. `BEANCOUNT_DISABLE_LOAD_CACHE=1 bea -f /abs/main.bean check` also exits 0.
5. `bea -f /abs/main.bean check --no-cache` exits 2: `bea check cannot pass
   bean-check options (--no-cache) for this ledger…`.

Only after moving the `.managed` file away does `check` exit 1 with
`txns.bean:159997: Invalid reference to unknown account 'Expenses:Fodo'`.

Control: without the URL include, both `check --no-cache` and the
environment variable report the error (hunter's run).

Expected: `BEANCOUNT_DISABLE_LOAD_CACHE` (and a `--no-cache` that bea can
honour itself) forces a fresh load on managed ledgers too.

Cause: `_managed_cache_file` (`cli/src/bea_engine/managed_load.py:509`) checks
only `loader.PICKLE_CACHE_FILENAME`, never the disable variable.

Fix: return None (and remove a stale `.managed` file) when
`BEANCOUNT_DISABLE_LOAD_CACHE` is set, and let `check --no-cache` map to it for
managed ledgers.

Dedupe: w5/576 (done) is the parent; w1/083, w5/116 and 118 (done) cover
other caches.

Acceptance: step 4 (and step 5) exits 1 naming `Expenses:Fodo`. A test pins the
variable.

---

**Resolved 2026-10-19** — `BEANCOUNT_DISABLE_LOAD_CACHE` bypasses and removes the `.managed` cache, and `check --no-cache` runs the helper check cacheless instead of refusing, shipped in `356e65066` (`cli`)
