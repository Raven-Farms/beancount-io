# `bea treeify` on non-UTF-8 input exits 1 with a raw `UnicodeDecodeError` class message, where `format -` and `query` stdin name the input and say to re-save it as UTF-8

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `5d08dc41`, checkout `bea 0.3.1`, macOS 26.5.1.
Since w5/404 the native child runs with `PYTHONIOENCODING=utf-8`, so upstream
treeify decodes its input strictly and crashes on Latin-1 text. bea reports
the crash generically. No product fix implemented.

`t1.txt` as Latin-1 bytes: `Assets:Caf\xe9 10 EUR\nAssets:Bank 5 EUR\n`.

```sh
bea treeify t1.txt
bea treeify < t1.txt
```

Actual: exit 1, `Error: treeify failed (exit 1): UnicodeDecodeError:
'utf-8' codec can't decode byte 0xe9 in position 10: invalid continuation
byte. Pass --debug before the command for a traceback.`

Control: `printf 'x\xe9\n' | bea format -` gives `Cannot decode 'stdin' as
UTF-8: invalid continuation byte at byte 1. Re-save the file as UTF-8 and
retry.`

Expected: the same refusal for treeify (exit 2, naming the file or stdin and
the byte offset), checked by bea before upstream runs.

Cause: the frontend hands the input to upstream without a decode check
(`cli/src/cli/commands/treeify.py`); where the failure is wrapped is
unverified.

Fix: validate the input as UTF-8 in the frontend (file, or stdin captured)
with the shared message.

Note: `cli/tests/test_debug_hint_everywhere.py::test_a_crashed_upstream_program_carries_the_hint`
uses exactly this crash as its upstream-crash example (since w5/388), so a
fix must give that test another way to crash upstream (for example a
monkeypatched native).

Dedupe: w5/404 (done) covered output encoding only.

Acceptance: both commands exit 2 with the UTF-8 message. A test pins it.

---

**Resolved 2026-10-17** — Shipped in `0a8d0c43` (`cli`). `bea treeify` (`cli/src/cli/commands/treeify.py`) now checks a named input file as UTF-8 before upstream runs. It reads stdin itself and hands the text to upstream through a new `input_text` parameter on `launch.capture_native`/`run_captured`. A held `/dev/fd/N` still passes through untouched. Both forms exit 2 with the shared `Cannot decode 't1.txt' as UTF-8: invalid continuation byte at byte 10. Re-save the file as UTF-8 and retry.` (`'stdin'` for a pipe). `tests/test_treeify_non_utf8_input.py` pins file and stdin, which fail without the fix, and UTF-8 stdin still renders. `test_debug_hint_everywhere.py`'s upstream-crash test used this crash, so it now simulates one at the `capture_native` boundary, as the note anticipated.
