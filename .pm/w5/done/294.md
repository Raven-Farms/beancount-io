# The `bea query` text table still prints Python internals: `1E-8` for small decimals and `Transaction(meta={'fee': Decimal('1E-8')}, date=datetime.date(…))` for a directive cell

**Minor · cli · 30–45m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
In the default text table:

- A `Decimal` column prints a sub-micro amount in scientific notation:
  `1E-8`, also under `-m`.
- A whole-directive cell (`SELECT entry`, or `open`/`close` from
  `#accounts`) prints Python's repr, including `Decimal('1E-8')` and
  `datetime.date(2026, 1, 2)`.

The position column in the same row prints `0.00000001`, as do the CSV and
JSON outputs. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
2026-01-01 open Assets:Wallet
2026-01-01 open Equity:Opening
2026-01-02 * "Dust"
  fee: 0.00000001
  Assets:Wallet  0.00000001 BTC
  Equity:Opening
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean query "SELECT number, entry_meta('fee'), position WHERE account = 'Assets:Wallet'"
bea -f main.bean query -m "SELECT account, sum(position) GROUP BY account"
bea -f main.bean query "SELECT entry WHERE account = 'Assets:Wallet'"
bea -f main.bean query "SELECT open FROM #accounts WHERE account = 'Assets:Wallet'"
```

Actual: every command exits 0.

```text
  number    entry_meta('fee')      position
----------  -----------------  ---------------
1E-8        1E-8                0.00000001 BTC
```

`-m` prints `Assets:Wallet    1E-8` and `Equity:Opening  -1E-8`.
`SELECT entry` prints `Transaction(meta={'fee': Decimal('1E-8')},
date=datetime.date(2026, 1, 2), flag='*', payee=None, narration='Dust', …)`.
The `#accounts` cell prints `Open(meta={}, date=datetime.date(2026, 1, 1),
account='Assets:Wallet', currencies=None, booking=None)`. The same bytes
reach a pipe and an `-o` text file. Reproduced in a fresh process.

Controls:

- `-f csv` for the same queries gives `0.00000001`, and the directive as
  Beancount text.
- `--json` gives `"0.00000001"`.
- `bea list transaction --details` renders Beancount syntax.

Expected: `docs/USAGE.md` says a text or CSV metadata cell, including "the
metadata inside a directive", "never shows a Python `Decimal('1E-8')` or
`datetime.date(...)`". w5/201 and w5/228 set the fixed-point rule for tiny
amounts elsewhere in the CLI.

Cause: the text branch of `on_Select` (`cli/src/bea_engine/query.py:1022-1040`)
rewrites only metadata-dict cells (`_text_cell`, `:1283`) and `frozenset`
columns. Every other cell goes to upstream's renderers:

- `DecimalRenderer` formats with an f-string, which gives `1E-8` for that
  exponent.
- `ObjectRenderer.format` is `str(value)`, so a directive cell, or a scalar
  `object` cell such as `entry_meta('fee')`, prints its repr.

Fix: in the text branch:

- Render `Decimal` cells, and decimals inside `object` cells, in fixed
  point (`format(v, "f")`), keeping the decimal-point alignment.
- Render directive cells as Beancount text, as the CSV path already does
  (`_csv_cell`), or as the one-line JSON object.

Native `--source` keeps upstream's rendering, as documented. No dependency
change.

Blast radius: the local `--file` text table, meaning one-shots, `-o` text
exports, `--numberify` and the interactive shell (same `on_Select`). It
affects `Decimal` and `object` columns, `SELECT entry`, and `open`/`close`
from `#accounts`. CSV and JSON are unaffected.

Dedupe: searched the board for `1E-8`, `scientific`, `Transaction(meta`,
`Open(meta` and `SELECT entry`.

- w5/230: covers metadata dict cells only.
- w1/145: the CSV directive cell became Beancount text; the text cell
  stayed a repr.
- w5/104: JSON only.
- w5/228 and w5/201: the import preview and `add` messages.

None of them covers the text table.

Acceptance: on the fixture, the text table shows `0.00000001` in the
number, metadata and `-m` columns. The `SELECT entry` cell and the
`#accounts` `open` cell contain no `Decimal(`, `datetime.`, `Transaction(`
or `Open(`. A real-command regression test covers the text table and an
`-o` export. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-14** — The `--file` text render now swaps in fixed-point `Decimal` and object renderers for one render (`_fixed_point_text` in `cli/src/bea_engine/query.py`), so number columns, `-m` sums and `entry_meta()` cells print `0.00000001`, aligned on the decimal point. A directive cell (`SELECT entry`, `#accounts` `open`/`close`) is its Beancount text, laid out one line per table row. Native `--source` keeps upstream's table. USAGE's query output section says so. `cli/tests/test_query_text_fixed_point.py` covers the four columns and an `-o` text export; all 4 cases fail with the fix reverted. Only macOS was exercised. `make check-all` passed. Shipped in `cb1ab7ea` (`cli`).
