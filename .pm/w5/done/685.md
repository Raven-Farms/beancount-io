# `query PRINT -f beancount` of a valid ledger fails `bea check` when an include uses the default roots: the export puts the root's `option "name_assets"` ahead of every entry (incomplete fix of w5/474)

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-17, HEAD `306653d5`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/474 (done, `83bba7bb`).
w5/474 made the export start with the option lines its validity rests on.
Beancount applies `name_*` options per file as parsed, and USAGE documents
that an include reads the default roots. The export writes one option
preamble ahead of all rows, so the include's `Assets:` entries become
invalid there. No product fix implemented.

`main.bean`:

```beancount
option "name_assets" "Activos"
include "inc.bean"
2026-01-01 open Activos:Cash USD
2026-01-01 open Expenses:Food USD
```

`inc.bean`: `2026-01-01 open Assets:Bank USD`.

```sh
bea -f /abs/main.bean check                              # exit 0
bea -f /abs/main.bean query PRINT -f beancount > out.bean
bea --file out.bean check
```

Actual: the re-check exits 1 with `out.bean:3: Invalid account name:
Assets:Bank`.

Control: in a single file, entries using the default roots placed before the
`option` line check clean.

Expected: USAGE: the export of a valid ledger passes `bea check`. Write
default-root (unrooted) entries before the option preamble, or refuse the
export naming them; failing that, document the exception (w5/463's unrooted
accounts).

Cause: `_render_beancount` (`cli/src/bea_engine/query.py:1339-1348`) writes a
single preamble before all rows.

Fix: as above.

Dedupe: w5/154, 402, 463 and 474 (done) cover other renamed-root issues.

Acceptance: the fixture's export re-checks with exit 0. A test pins it.
