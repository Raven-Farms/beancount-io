# `--into` naming a glob-included file in another letter case or Unicode form is reported as a concurrent edit

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, macOS. On a case- and
normalization-insensitive volume (the macOS default), `--into` spelled
differently from the on-disk name of a file an include glob matches exits 4
with "The ledger changed during the operation … retry". Nothing changed and
retrying can never succeed. The Unicode form needs no typing mistake: a file
name macOS stores decomposed, typed composed, hits it. No product fix
implemented.

Create disposable `/absolute/b/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Food
include "txns/*.bean"
```

and `/absolute/b/txns/jan.bean`:

```beancount
2026-01-02 * "Lunch"
  Expenses:Food  5.00 USD
  Assets:Checking
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY.

```sh
bea -f /absolute/b/main.bean add transaction Dinner --date 2026-01-03 -p "Expenses:Food 9 USD" -p "Assets:Checking" --into txns/Jan.bean
```

Actual: exit 4, `Error: The ledger changed during the operation:
/absolute/b/txns/Jan.bean. Nothing was written; retry.`; `--json` reports
category `conflict`. The file is unchanged. Repeated twice. A file stored as
decomposed `café.bean` with `--into txns/café.bean` typed composed fails
the same way.

Controls: `--into txns/jan.bean` exits 0. With a literal `include
"txns/jan.bean"`, `--into txns/Jan.bean` exits 2 with "is not included by".

Expected: `docs/USAGE.md` reserves exit 4 for a conflict or unknown
outcome — "An external edit detected before replacement produces exit 4".
There was no edit. Either write to the existing file, or exit 2 naming the
on-disk spelling; the guide already treats composed and decomposed account
spellings as one name.

Cause: `cli/src/bea_engine/ledger/write.py:98-104` (`require_target`)
compares resolved paths as strings, which misses on case or normalization.
The glob then matches the typed name as a new file, and because that path
exists on the insensitive volume the code concludes it appeared mid-operation.

Fix: identify an existing destination by file identity against the
snapshot's files and use the snapshot's spelling; never raise the
concurrent-edit conflict for a path that existed when the snapshot was taken.
No dependency or API change.

Dedupe: board search for case-insensitive paths, "changed during the
operation" and `--into` spellings finds w1/075 (lock keys) and w3/389 (a
real concurrent edit misreported); neither covers `--into`.

Acceptance: on the fixture the command writes to `txns/jan.bean` or exits 2
naming it, in both the case and the Unicode variants; a real concurrent edit
still exits 4. Only macOS and the checkout were exercised; a case-sensitive
volume was not.

---

**Resolved 2026-10-12** — Chose "exit 2 naming the on-disk spelling" over silently redirecting the write. `--into` naming an included file in another letter case or Unicode normalization form is identified by file identity and refused as a usage error that names the file as stored (`Pass --into with the name as it is on disk (jan.bean)`), in text and `--json` (category `usage`). Nothing is written and no second file is created. A file that genuinely appears after the snapshot still raises the conflict. Shipped in `002b951b` (`cli`).

Real-command regression tests cover the letter-case variant and both directions of the composed/decomposed variant (each skipped on a volume that keeps the spellings apart), the exact spelling still writing, a new glob-matched file still being created, and a file appearing after the snapshot still raising the conflict. The three spelling cases fail with the fix reverted. `make check-all` passed. Exercised on macOS's default case-insensitive volume only; a case-sensitive volume was not run, where the spelling tests skip by design.
