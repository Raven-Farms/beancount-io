# `price export` silently drops a local price file whose name differs from the feed's file name only by case

**Major · cli · 40m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
On a case-insensitive volume (the macOS default), `price export` of a
ledger that has both a managed feed `…/prices/BTC-USD` and a local
`prices/btc-usd.beancount` writes the feed's text over the local file's
copy. The export exits 0 and reports three files; two exist, the manual
prices are gone, and the exported ledger values holdings differently from
the source. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Assets:Coin BTC
2024-01-01 open Equity:Opening
2024-01-01 commodity BTC
2024-01-01 commodity USD

2024-01-02 * "Open"
  Assets:Cash  10000.00 USD
  Equity:Opening

2024-01-03 * "Buy"
  Assets:Coin  2 BTC {1000.00 USD}
  Assets:Cash  -2000.00 USD
```

followed by `include "http://127.0.0.1:PORT/prices/BTC-USD"` and
`include "prices/btc-usd.beancount"`, and
`/absolute/books/prices/btc-usd.beancount`:

```beancount
2023-12-31 price BTC 900.00 USD
2024-03-01 price BTC 1700.00 USD
```

The feed is a **simulation**: a loopback server on `127.0.0.1` allowed
through `MANAGED_PRICE_ORIGINS`, which proves local handling only, not the
real service's behaviour. Use isolated BEA_CONFIG_DIR and a fresh
XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no inherited BEA_FILE/BEA_TOKEN,
closed stdin, no TTY, cwd `/absolute/books`. The simulated feed returns `2024-01-05 price BTC 1100.00 USD` and
`2024-02-05 price BTC 1500.00 USD`.

```sh
bea -f main.bean price export
ls main-export/prices
```

Actual: exit 0, `Exported 3 files`. `main-export/prices/` holds one
file, `btc-usd.beancount`, and the `1700.00` price is in no exported
file.

Control: the same fixture with the local file named
`prices/BTC-USD.beancount` (exact case) exports `BTC-USD.beancount` and
`BTC-USD-managed.beancount`, and the manual prices survive. A worker saw
the damaged export still pass stock `bean-check`, include the feed text
twice, and value the coin at 3,000 USD where the source shows 3,400 USD.

Expected: `docs/USAGE.md` describes the export as a "self-contained copy"
holding "the exact effective text the load parsed". w3/413 (done) fixed
this overwrite for an identical name.

Cause: `cli/src/bea_engine/managed_load.py:778-782,948-960`
(`_free_feed_path`) compares planned paths case-sensitively, and the
pre-write collision checks look only at files already on disk, so two
planned paths that name one file on this volume are not noticed.

Fix: compare planned destinations by a filesystem-aware key (case-folded
and Unicode-normalized, or probe the volume) so the feed takes the
`-managed` name; apply it to the shared-feed naming too. No dependency or
API change.

Blast radius: `price export` on case-insensitive volumes; by the
worker's observation also two feed aliases differing only in case.

Dedupe: w3/413 (exact-name overwrite, done), w5/058 (symlink aliases,
done) and w5/100 (one feed from two files); none covers case-only
collisions.

Acceptance: the export contains both the manual prices and the feed
prices in separate files, and its valuation equals the source ledger's;
the exact-case control is unchanged. Only macOS (case-insensitive
volume), the checkout and a loopback simulation were exercised.

---

**Resolved 2026-10-13** — `price export` now compares planned file names case-folded and Unicode-normalized when it places a managed feed (`_free_feed_path` in `cli/src/bea_engine/managed_load.py`), so a `BTC-USD` feed beside the ledger's own `prices/btc-usd.beancount` lands at `prices/BTC-USD-managed.beancount` instead of being written over the copy, and two feeds whose aliases differ only by case get separate files the same way. The comparison is applied on every platform rather than by probing the volume, so on a case-sensitive volume a feed with a case-only twin also takes the `-managed` name; `cli/docs/USAGE.md` states the rule. `cli/tests/test_price_export_case_only_collision.py` exports through a loopback feed and checks that both files exist with the manual prices intact, that the snapshot passes stock `bean-check`, lists the same prices and values the holding the same as its source, plus the exact-case and unrelated-name controls; 7 of its 10 cases fail with the fix reverted. The `_shared` naming for symlink aliases was left alone, because a case-only clash there needs two files that cannot coexist on a case-insensitive volume. Only macOS was exercised. `make check-all` passed. Shipped in `300cb5e5` (`cli`).
