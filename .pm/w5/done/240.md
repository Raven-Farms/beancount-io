# `import --importer NAME` is accepted and ignored when the CSV mapping runs

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Fix with [131](./131.md).
The mirror image of 131: when an import resolves to the built-in CSV
mapping, `--importer NoSuchImporter` is silently ignored and the row is
written with exit 0. With a Python config the same unknown name is refused.
No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Checking USD
2024-01-01 open Expenses:Uncategorized USD
2024-01-01 open Equity:Opening USD
2024-01-02 * "Opening"
  Assets:Checking  1000.00 USD
  Equity:Opening
```

`/absolute/books/bank.csv`:

```csv
Date,Payee,Narration,Amount
2024-06-02,Cafe,Coffee,-5.25
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean import bank.csv --csv date=Date,amount=Amount,payee=Payee,narration=Narration --account Assets:Checking --importer NoSuchImporter --apply
```

Actual: exit 0; the Cafe row is written. stderr says only `Using column
mapping (--csv).`

Control: `bea -f main.bean import bank.csv --config
cli/docs/examples/csv_importers.py --importer NoSuchImporter` exits 2; a
worker quoted the message `No importer named 'NoSuchImporter'; available:
categorized-checking.`

Expected: the help describes `--importer` as the importer name when
several match, and `docs/IMPORTING.md` says "An unknown name lists the
available importer names". An option that cannot apply should be refused,
as `--csv` with `--config` already is.

Cause: `cli/src/cli/commands/import_.py:647-648` forwards the importer
name only in the Python-config branch; the CSV branch (from `:485`) never
looks at it.

Fix: in CSV mode refuse `--importer` with exit 2, saying it selects a
Python importer and this import uses the CSV mapping. No dependency
change.

Blast radius: `bea import` with `--csv`, header inference, or a remembered
CSV mapping.

Dedupe: board search for `--importer` finds w5/131 (CSV options dropped
when `importers.py` exists) and w5/226 (identical importer names); neither
covers the option ignored in CSV mode.

Acceptance: the command exits 2 naming `--importer` and writes nothing;
the Python-config control is unchanged. Only macOS and the checkout were
exercised.

---

**Resolved 2026-10-13** — `bea import` now refuses `--importer NAME` with exit 2 whenever the run resolves to the built-in column mapping, instead of accepting the name, dropping it and writing the rows; the check sits at the top of the CSV branch in `cli/src/cli/commands/import_.py`, before anything is read, written or remembered, and the message says whether the mapping came from `--csv`, the header row or a remembered mapping and points at `--config FILE`. `cli/docs/IMPORTING.md` now states that `--importer` names a Python importer only. The regression test `cli/tests/test_import_importer_refused_by_csv_mapping.py` runs the real command for an explicit `--csv` mapping with `--apply`, an inferred header mapping under `--json`, and a remembered mapping, asserting exit 2, the `--importer` message and an untouched ledger, plus two controls: the mapping still imports without the option, and a Python config still reports an unknown name with the available importers and still runs a known one. Three of the five cases fail with the fix reverted; the two controls pass either way. No deviation from the note. Only macOS was exercised. `make check-all` passed. Shipped in `06b31134` (`cli`).
