# Since w5/542, a sale's lot label is escaped too, so it no longer selects an existing lot whose label holds a tab or other control character; and the `--json` answer of `add transaction -p` reports the raw label, not the escaped one written (incomplete fix of w5/542)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `eea79d702`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/542 (done, `05f3c4af2`).
No product fix implemented.

1. **Reduction selector.** The ledger opens `Assets:Checking USD`,
   `Assets:Brokerage` and `Income:Gains USD`, and holds a purchase of `10 HOOL
   {40 USD, "lot<TAB>A"}` (a literal tab byte). `check` passes, and `list
   --json` reports the label as `"lot\tA"`.
   - `bea -f /abs/t.bean add transaction "Sell tab lot" --date 2026-02-01
     -p $'Assets:Brokerage -10 HOOL {"lot\tA"} @ 50 USD' -p 'Assets:Checking
     500 USD' -p Income:Gains` exits 1:
     `No position matches -10 HOOL {"lot\x09A"} in Assets:Brokerage; it holds
     (10 HOOL {40 USD, 2026-01-10, "lot\x09A"})`.
   - The two labels print identically, so the refusal cannot be understood.
   - A bulk row with `"cost": {"label": "lot\tA"}` fails the same way (hunter's
     run).
   - Before `05f3c4af2` the sale was written.
2. **JSON echo.** `bea --json -f /abs/pj.bean add transaction buy --date
   2026-02-01 -p $'Assets:Brokerage 1 HOOL {5 USD, "e\e[2JL‮X"}' -p
   Assets:Checking` reports `data.directive.postings[0].cost.label` as the raw
   `e\x1b[2JL‮X`, with a real ESC and RLO. `data.entry` and the file have
   the escaped `"e\\x1b[2JL\\u202eX"`, so the answer cannot "be fed straight
   back" (USAGE) as written.

Expected:
- A label taken from `list --json` selects its lot.
- The JSON answer matches what was written, as it does for payees and
  narrations.

Cause:
- `posting_strings` (`cli/src/bea_engine/ledger/writer.py:231`, inside
  `normalize_entry_strings` at `:216`) escapes reduction selectors as well as
  new lot labels.
- The add answer is built from the entry before normalization
  (`cli/src/bea_engine/ledger/adding.py`, around `:896-904`).

Fix: escape only augmenting lot labels. For a reduction, match the raw label,
and if it contains control characters, refuse with a message that names them
and suggests selecting by cost or date. Build the JSON answer from the
normalized entry.

Dedupe: w5/542 (done) is the parent; w5/333, 060 and w1/011 cover other
lot-matching messages.

Acceptance: the tab-label sale is written; the JSON label equals the written
one. Tests pin both.
