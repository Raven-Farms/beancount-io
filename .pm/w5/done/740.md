# After w5/556, a same-day reciprocal price pair is settled by counting quotes over the whole ledger, so a later quote changes an earlier period's valuation; a tie is settled by line number, even across include files; and the double inversion leaves 1e-26 residue in JSON (incomplete fix of w5/556)

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-17, HEAD `15b5e52f4`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/556 (done, `a67268e6a`).
USAGE:1560 says "Prices after the report date do not affect its valuation".
USAGE:1574 says "a later quote cannot value an earlier interval".
USAGE:1261 says the pair is valued by the inverse of the direction "quoted less
often … whatever their line order". No product fix implemented.

`later0.bean`: a USD ledger, `Assets:EUR` opened with 1000.00 EUR on
2026-01-02, `2026-01-05 price EUR 1.20 USD` and `2026-01-05 price USD 0.80
EUR`. `later1.bean` is the same plus `2026-03-01 price USD 0.70 EUR`.

1. **Later quote.** `bea -f /abs/later0.bean balance Assets:EUR --time
   2026-01` shows 1,250.00 USD. The same command on `later1.bean` shows
   1,200.00 USD. The March quote changed January's value. Before the fix,
   both showed 1.25 (hunter's run). With the note's a1 fixture plus two March
   `@`-priced trades, January's `net_worth` moves from 1250 to
   `1204.000000000000000000000000` (hunter's run).
2. **Ties.**
   - Swapping the two 2026-01-05 lines in `later0.bean` changes January from
     1,250.00 to 1,200.00 USD.
   - With the two quotes in two include files, adding blank lines to one
     file flips the result (hunter's run).
   - A three-currency EUR→USD→JPY chain gives 171,875 or 165,000 JPY
     depending on line order.
3. **Residue.** `dust.bean` has EUR as operating currency, `EUR 1.10 USD`
   quoted twice, `100.00 USD @ 0.90 EUR` and `price USD 0.90 EUR`. `bea --json
   … report balance-sheet` gives `net_worth` `{"EUR":
   "90.00000000000000000000000001"}` and `valuation_adjustment`
   `-0.00000000000000000000000001`. The text output shows 0.00.

Expected: a valuation at a date depends only on quotes up to that date. A tie
gives one documented result whatever the line or file order. Values from an
original quote stay exact.

Cause: `cli/src/fava/beans/prices.py` (around `:95-110`) counts each
direction's quotes across the whole ledger and inverts the one "quoted fewer
times (on a tie, the one seen second)". It then inverts again for the reverse
map. BQL's `build_price_map` follows the same rule.

Fix: settle each same-day collision using only quotes up to that day, use a
tie-break that does not depend on line numbers (or document one), and keep
the original rate for the reverse map. Apply the same rule to the map BQL
reads.

Dedupe: w5/556 (done) is the parent; w5/665 (open) covers `unique_prices`.

Acceptance: `later0` and `later1` both value January at 1,250.00 USD,
swapped lines give the same value, and `dust` gives exactly 90.00. Tests pin
each.
