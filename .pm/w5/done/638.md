# Importer rows that cannot be written are not attributed to their row: an unbalanced row previews as `new` ("5 ready … repeat with --apply") and `--apply` fails naming no row; an unwritable metadata key stops even the preview with "Directive 2 of 3"; a string date or a unit-less source posting gives a bare Python error

**Minor · cli · 30–45m · A1.** Real CLI QA, 2026-10-16, HEAD `75a67e85`, checkout `bea 0.3.1`, macOS 26.5.1.
IMPORTING.md promises row numbers in review refusals, and says a value that
cannot be written "stops the import with `Importer NAME row N cannot be
written as a ledger entry`". w5/337 (bulk) and w5/129/184 (bulk writes) made
the same failures name their row. On the Python-importer path, three kinds
of row failure are reported without the row. No product fix implemented.

1. **Validation failures are unattributed.** Five extracted rows; row 3's
   counter posting is `3.50 USD` against `-3.00 USD`. The preview exits 0 with
   `5 ready`, every row `new` / `include: true`, the footer `Preview only. …
   repeat with --apply to write.`, and a stderr note `Proposed append (not
   written): Transaction does not balance: (0.50 USD)`. `--apply` exits 1 with
   `Import would leave the ledger invalid; nothing was written.`; neither the
   details nor `error.result` name row 3. A csvbase importer without
   `finalize` fails the same way for every row.
2. **One-directive check aborts the preview.** Four rows; row 1 is blocked
   (unopened account) and row 3 carries `meta["BankRef"] = "abc"` (an
   uppercase key Beancount cannot read back). `bea --file /abs/main.bean
   import bank.txt --config imp.py` exits 2 (`usage`) with `Directive 2 of 3
   would be written as 0 directive(s); … (Beancount: Invalid token:
   'BankRef:')`, returns no preview, and counts only ready rows. `D("NaN")` or
   `D("-Infinity")` amounts, a tag `"travel 2026"`, and `flag=None` do the
   same.
3. **Type errors are bare.** A transaction dated `"2026-02-02"` gives `Error:
   AttributeError: 'str' object has no attribute 'isoformat'.`; a
   `datetime.datetime` date gives `TypeError: can't compare datetime.datetime
   to datetime.date.`; a source posting with `units=None` (row 3 of four)
   gives `The importer must supply explicit source amounts for Assets:Checking
   before duplicate matching.` with no row.

Control: a `float` metadata value gives `Importer base row 1 cannot be written
as a ledger entry (…)`, exit 1; blocked and conflict rows are listed per row.

Expected: each failure names its importer row (`Importer base row 3: …`). A
row that fails validation is marked invalid in the preview, is not counted as
ready, and the footer does not say "repeat with --apply" while such rows
exist. Unwritable rows give exit 1 with the documented sentence. Bad dates
and missing units name the field.

Cause: `_writable` (`cli/src/bea_engine/importing.py:724-775`) checks only that
`format_entry` does not raise — not `one_entry_problem(text)`, the date type, or
explicit units. Validation errors are stored verbatim (`:574-586`), with no
per-row attribution like `adding.py`'s `_named_rows`/`_rows_with_errors`. The
batch one-entry check (`cli/src/bea_engine/ledger/write.py:2448-2461`) numbers
by position in the ready texts and raises `UsageError`, which escapes `except
LedgerError` (`importing.py:578`). Bad dates fail in `_hash_import_ids`
(`:1571`) and `_first_uses`.

Fix: extend `_writable` with the one-entry check, `type(entry.date) is
datetime.date`, and explicit source units, naming the row; attribute candidate
validation errors to rows by line (as bulk add does).

Dedupe: w5/129, 184, 337, 339 and 351 (done) cover bulk add.

Acceptance: each fixture names its row with the documented message and exit
code, and the unbalanced row is shown as invalid in the preview. Tests pin
each.

**Resolved 2026-10-17** — Shipped in `8c1d18ce7` (`cli`). Changes in `cli/src/bea_engine/importing.py`:
1. Candidate validation errors are attributed to rows through bulk add's `_named_rows`. Such a row is `invalid` with Beancount's reason and `include: false`, it is not counted in `ready`, and the preview gains an `invalid` count. `--apply` refuses with exit 1 and `Row N: …` details, and the human footer says to fix the errors before `--apply`.
2. `_writable` checks with `one_entry_problem` that each row reads back as one directive.
3. `_writable` requires a `datetime.date`, and a units check requires an amount on each source posting. Each failure stops the import with `Importer NAME row N cannot be written as a ledger entry: …` and names the field, exit 1.

An invalid account or commodity is still blocked with `add`'s message (w5/637). IMPORTING documents both. Test: `cli/tests/test_import_unwritable_rows_named.py`.
