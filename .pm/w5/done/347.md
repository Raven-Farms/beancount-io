# The included-leaf hint names the nearest includer as "the root", not the top-level ledger, and searches only two directories up, so a nested leaf gets a recipe that writes to the wrong file and deeper or `../` leaves get no hint

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
A failing write aimed at an included leaf prints `X is included by ROOT
… Run against the root and pick the destination with --into: bea --file
ROOT <command> --into REL`. `including_root` returns the first file it
finds that includes the target, and it looks only in the target's
directory and that directory's parent.

For a leaf included through an intermediate file:

- The "root" in the hint is the intermediate file, and the recipe fails
  again.
- The second hint then names the top-level root, but its `--into` points
  at the intermediate file, not the leaf. Following it writes the entry
  to the wrong file.

Leaves three or more directories below the root, or reached through
`../`, get no hint at all. No product fix implemented.

Use the fixture from [346](./346.md): `main.bean` includes `sub
dir/extra.bean`, and that file includes `nested/deep.bean`. Use the same
environment.

```sh
bea -f '/absolute/my books/sub dir/nested/deep.bean' add transaction X --date 2026-01-03 -p 'Assets:Bank 5 USD' -p Assets:Cash
```

Actual:

- Exit 1 with `deep.bean is included by /absolute/my books/sub
  dir/extra.bean; on its own it lacks the accounts and options that root
  provides. Run against the root … bea --file '/absolute/my books/sub
  dir/extra.bean' <command> --into nested/deep.bean.`
- Pasting that recipe exits 1 again with `extra.bean is included by
  /absolute/my books/main.bean; … bea --file '/absolute/my
  books/main.bean' <command> --into 'sub dir/extra.bean'`. This names the
  intermediate file, not `deep.bean`.
- A second fixture had `main.bean` including `years/2026/q1/jan.bean` and
  `../shared/common.bean`. The same failing add against either leaf
  printed no "included by" hint.

Reproduced by the hunter twice. I reproduced the nested-leaf hint once.

Control: `bea -f '/absolute/my books/main.bean' add transaction … --into
'sub dir/nested/deep.bean'` writes to `deep.bean` correctly.

Expected: the hint is meant to send the user to the root with the right
`--into`. It should name the top-level root (a file nothing else includes)
and the leaf's path relative to that root, here `--into 'sub
dir/nested/deep.bean'`. If no root can be found, it should say so rather
than stay silent.

Cause: `including_root` (`cli/src/bea_engine/ledger/write.py:982-1004`):

- It scans only `target.parent` and `target.parent.parent` for
  `*.bean`/`*.beancount`.
- It returns the first candidate whose include closure contains the
  target, without climbing to that candidate's own includer.

`root_ledger_hints` (`:1007-1017`) then computes `relpath` against that
intermediate file.

Fix:

- Climb the includers: once an includer is found, look for its own
  includer, and stop at a file that nothing includes.
- Widen the search to the ancestor directories up to a sane bound (for
  example, stopping at a directory holding `main.bean`/`main.beancount`
  or at the filesystem or VCS root).
- Compute `--into` relative to the final root.
- Keep the w5/112 and w5/124 cost limits. No dependency change.

Blast radius: the leaf hint on every failing `add` and `import` run with
`--file` on a nested or deeply placed included file. [346](./346.md) and
[348](./348.md) would reuse the same lookup.

Dedupe: searched `.pm/**`, including `done/`, for `including_root`,
"included by" and "Run against the root". Related notes:

- w3/438: the hint repeating itself.
- w5/112 and w5/124: hint cost.
- 343: wrong remedy for root accounts.

None covers which root is chosen or the depth limit.

Acceptance: on the fixture, the hint names `/absolute/my
books/main.bean` with `--into 'sub dir/nested/deep.bean'`, and pasting it
writes to `deep.bean`. A leaf three directories down and a `../` include
both get a hint. A test covers the nested, deep and `../` layouts. Only
macOS and the checkout were exercised.

Addendum (CLI QA r76, 2026-10-14): on macOS's case-insensitive
filesystem, a leaf given with a case-variant path (`-f L/SUB/X.BEAN`)
gets no "included by …" hint at all, while `-f L/sub/x.bean` does.
`including_root` (`write.py:982-1004`) compares `resolve()` paths, which
do not canonicalise case on macOS. The climb fix should compare with
`os.path.samefile`.

---

**Resolved 2026-10-15** — `including_root` (`cli/src/bea_engine/ledger/write.py`) now searches more widely. It scans the leaf's directory and up to three ancestors (stopping after a directory holding `.git`) plus each ancestor's immediate subdirectories, which covers `../shared/x.bean`. It opens only regular `.bean`/`.beancount` files under 16 MB whose text mentions `include` and either the leaf's case-folded name or a glob, at most 64 of them, and matches with `os.path.samefile`. A `.bean` FIFO in a QA directory nearby had hung the first version of this search, so non-regular files are skipped. With w5/343 and w5/346's climb, writes to these leaves run through the top root, so the "included by" recipe is now applied rather than printed and names the top root with the leaf's full `--into`. On the fixtures, a leaf three directories down (`years/2026/q1/jan.bean`) and a `../shared/common.bean` include are written through `main.bean`. A case-variant path now finds the root and is refused naming the include's own spelling (`Pass --into years/2026/q1/jan.bean`). The note's "say so when no root is found" was not added, because a real root is never included by anything and would get that message on every failure. `cli/tests/test_including_root_search.py` covers the deep, `../` and case-variant layouts and a nearby FIFO; all 4 fail with the change reverted. Only macOS was exercised. `make check-all` passed. Shipped in `e6b57f0e` (`cli`).
