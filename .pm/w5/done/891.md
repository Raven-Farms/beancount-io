# A leading UTF-8 BOM hides the first renamed account root from Ask's model context

**Trivial · cli · 10–20m · A1/A2.** Real CLI QA, 2026-10-20, checkout
`bea 0.3.1`, HEAD `af8c099f0`, Darwin 25.5.0 arm64, frontend Python 3.13.3.
Reproduced twice with the installed SDK and an owned loopback simulator;
three nearby controls repeated twice. No product fix made. This finding is
the observed outgoing context omission; live model answer quality was not tested.

Create `/abs/case/main.bean` as UTF-8 with a leading BOM (`EF BB BF`), with
the following `option` as the very first text after it:

```beancount
option "name_expenses" "Aufwand"
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Aufwand:Food USD
2024-01-02 * "Lunch"
  Assets:Cash -10 USD
  Aufwand:Food 10 USD
```

Use cwd `/abs/case`, closed stdin/no TTY, isolated absolute
`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, and no inherited
`BEA_FILE`. Point `BEA_API_URL` at an owned loopback OpenAI-compatible stub
and supply only a synthetic `BEA_TOKEN` to this child. Inspect the request's
JSON `messages` with `role: system`, without capturing headers. The stub
accepts POST `/api-gateway/ai/openai/chat/completions`, returning a standard
chat completion: assistant text, `finish_reason: stop`, model `gpt-4o`, a
completion ID and usage. No hosted service or AI quota is needed.

```sh
bea --json --file /abs/case/main.bean check
bea --file /abs/case/main.bean ask 'Synthetic QA question' --print
```

Actual: check and Ask exit **0**; the outgoing system context has the static
`^Expenses` recipes and **no** correction naming `Aufwand (for Expenses)`.
The simulation additionally requests the real `run_bql_query` tool with
`SELECT sum(number) WHERE account ~ '^Aufwand'`: its result is **10**,
showing that the local reader does recognize the valid renamed root. The
ledger remains byte-identical. A fixed simulated answer says nothing about
how an actual model would answer; no false spending answer is claimed.

Controls: remove only the BOM, or retain it but put a comment or a title
option before the `name_expenses` option. In all three cases, check and Ask
exit 0, the real tool still returns 10, and the outgoing context includes
`This ledger renames its account roots: Aufwand (for Expenses). Use those
names wherever the examples above say Expenses…`. All cases passed twice.

Expected: the same valid ledger with or without a leading BOM gives Ask the
same root-name context. Completed w5/403 requires that context so the
model's built-in recipes address the user's configured accounts. BOM
acceptance is established in `cli/docs/USAGE.md` and completed w3/257.

Cause: `cli/src/cli/ask/agent.py:369–383` reads text with `encoding="utf-8"`
and matches `_ROOT_OPTION` anchored to `^option`. The first line instead
begins with U+FEFF, so that one option is skipped; later lines still match.
The engine's ordinary loader strips the BOM. The only caller is the
dynamic system-prompt hook in `make_agent` at :580.

Fix: strip exactly the leading UTF-8 BOM for this text inspection, preserving
last-option-wins behavior and the frontend's no-Beancount boundary. Do not
rewrite the ledger or strip embedded characters. No dependency is needed.

Dedupe: searched all board states and active milestone scopes for Ask/root
names/BOM, and reviewed targeted source history. This is an unhandled input
in completed w5/403; w3/257 and w5/220 concern engine loading/cache support.
Neither has an open overlapping repair, and no later Ask fix handles it.

Acceptance: capture the real outgoing prompt for BOM-first and plain
variants and require the same renamed-root sentence; keep both BOM-prefix
controls, last-option-wins and default-root behavior. Fresh checks and tool
queries still pass without modifying the source. Evidence:
`.tmp/qa-2026-10-20-cli-loop-pass3-69d827bc/repro_ask_bom_root.py`,
`ask-bom-root-simulation.json`, `ask-bom-root-{1,2}-*/` and matching
`captures/ask-bom-root-*.json`. All owned servers stopped; no credentials
captured. Hosted model behavior, Windows/Linux and repaired behavior are
unverified.

---

**Resolved 2026-10-22** — `ledger_root_names` reads the root file as `utf-8-sig`, so a leading UTF-8 BOM no longer hides the first `name_*` option from Ask's system prompt; the ledger is not rewritten and last-option-wins is unchanged. `cli/tests/test_ask_prompt_bom_roots.py` captures the real system prompt for BOM-first, plain and both BOM-prefix controls and fails (BOM-first) without the fix; shipped in the commit that moves this note (`cli`).
