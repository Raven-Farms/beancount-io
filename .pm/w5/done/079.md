# A multi-file include glob shifts line numbers during write validation, so `--allow-errors` refuses every write

**Major · cli · 45–60m · A1.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, macOS. `--allow-errors` exists to let a write
proceed over an error already in the books. In a ledger whose root has an
include glob matching two or more files, followed by any later line that
carries an error, the pre-existing error is reported as newly introduced and
every `add` is refused. The same shift misnumbers other diagnostics. No
product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Food
2026-01-01 open Equity:Opening
include "sub/*.bean"
2026-01-02 * "Open"
  Assets:Checking  100.00 USD
  Equity:Opening
2026-01-05 balance Assets:Checking  999.00 USD
```

and three files `sub/a.bean`, `sub/b.bean`, `sub/c.bean`, each one
transaction of this shape (dates `2026-02-01`..`03`, amounts `1.00`..`3.00`):

```beancount
2026-02-01 * "a"
  Expenses:Food  1.00 USD
  Assets:Checking
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f /absolute/books/main.bean add transaction x --date 2026-03-01 -p "Expenses:Food 5 USD" -p "Assets:Checking" --allow-errors
```

Actual: exit 1, every file byte-identical:

```text
Error: The change would introduce 1 new ledger error(s); nothing was written.
  Proposed append (not written): Balance failed for 'Assets:Checking': expected 999.00 USD != accumulated 100.00 USD (899.00 too little)
```

The "new" error is the assertion already at `main.bean:9`, and it is labelled
as the proposed append. Adding `--into sub/a.bean` fails identically. Repeated
twice. The shift shows in other messages too: with the assertion corrected and
a `close` appended as line 10, a later-dated add reports the account "closed
… at main.bean:12".

Control: delete `sub/b.bean` and `sub/c.bean` so the glob matches one file;
the same command exits 0, appends the entry, and prints the tolerated error as
a warning naming `main.bean:9`. Moving the `include` line below the
assertion also exits 0 with three files present.

Expected: `docs/USAGE.md` Adding directives says every add command and
`import` "accepts `--allow-errors` for a semantic error already in the
books, such as a balance assertion that still fails". The fixture is that
case: exit 0, the entry appended, the existing error shown as a warning at
line 9. Diagnostics should name the lines the user's file has.

Cause: `cli/src/bea_engine/ledger/write.py:184-188`
(`LedgerSnapshot.staged`) rewrites each include directive in a staged
includer to point at staged paths, and for a glob joins the matches with
`"\ninclude "` — N matches turn one line into N, so every later line of the
staged includer moves down N−1. The "before" load reads the real files, so the
line-keyed comparison (`_error_key`, then `:676-680`) never pairs the
pre-existing error with its staged twin and counts it as introduced. The same
shifted numbers feed the "Proposed append" labelling and the opened/closed
locations quoted in messages.

Fix: staging must not change an includer's line numbering — keep the expanded
includes on one physical line if the grammar allows, or append the extra
include lines after the original content and keep a map, or translate staged
line numbers back before keying and reporting. Whichever is chosen, messages
must quote real line numbers. No dependency or API change.

Blast radius: every writer that validates a candidate — all `bea add` types,
`add transactions`, `import --apply`, and `ask` writes — whenever an
includer has a multi-match glob with content after it, whether the destination
is the root or an included file.

Dedupe: board search for include globs with `--allow-errors`, "introduce …
new", line shifts and staged paths finds w1/135 (the same symptom caused by
staged paths inside messages, fixed in the key) and w1/083 (cache misses on
new glob files); neither covers line numbering.
`git log -S'"\ninclude ".join' -- cli` shows only the introducing commits.

Acceptance: the fixture writes with exit 0 and warns at `main.bean:9`, with
and without `--into`; the closed-account message names line 10; an add that
really breaks the line-9 assertion is still refused and labelled as an
existing assertion; a one-match glob and a literal include are unchanged.
Real-command regression tests cover two and three matches. Only macOS and the
checkout were exercised.

---

**Resolved 2026-10-12** — A staged includer now keeps the line numbering of the file it stands for. Instead of writing a glob's N matches as N include lines, write validation points the one include line at a staged file beside the includer that lists the matches in order, so nothing below the include moves and include order is unchanged. On the fixture the add writes with exit 0 and warns at `main.bean:9`, with and without `--into`; the closed-account message names line 10. Shipped in `c3c5a85b` (`cli`).

Real-command regression tests cover one, two and three matches for a root write and an `--into` write (exit 0, the tolerated error named at line 9, no staging files left behind), a literal include, the closed-account location, and a write that really breaks the line-9 assertion — still refused with and without `--allow-errors`, reported at line 9 rather than as the proposed append. Six fail with the fix reverted; the one-match and literal cases pass either way. `make check-all` passed.

Not covered here: the managed-price loader has its own copy of the same join (`managed_load.py`), which is w5/092 and still open; the helper added here is written to be shared with it. Only macOS was exercised.
