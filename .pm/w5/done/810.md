# `bea ask` follows a symlinked `ask_history`: it chmods the link's target to 0600 and appends every question to that file outside the config directory; a FIFO there leaves the session with no prompt (sibling of w5/590)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `46a722c5c`, checkout `bea 0.3.1`, macOS 26.5.1. PTY; no question was sent, and `BEA_API_URL` pointed at a closed local port. Sibling of w5/590 (done).
w5/590 settled that state files are replaced, never written through a link.
The ask history holds private financial questions (w5/455). No product fix
implemented.

With a fake stored credential in `BEA_CONFIG_DIR`:

1. **Symlink.** `precious.txt` (mode 0644, `precious\n`) sits outside the config
   directory, and `<config>/ask_history` links to it. Opening `bea -f
   /abs/main.bean ask` on a PTY and pressing Ctrl-D changes `precious.txt` to
   mode 0600. The link stays. In the hunter's run, a typed question was
   appended to the target (`# 2026-10-17 … +second qa question`).
2. **FIFO.** With `mkfifo <config>/ask_history`, the banner prints but no prompt
   appears within 6 s. Ctrl-D is ignored, and only Ctrl-C ends it (exit 130).

Control: a regular `ask_history` (or none) opens the prompt at once and is
created 0600 inside the config directory.

Expected: never follow a link or open a non-regular file there. Fall back to
in-memory history with a one-line note (or replace the link), as
update-check.json now does.

Cause: `cli/src/cli/ask/repl.py:90-92` uses `os.open(history_file, O_WRONLY |
O_CREAT | O_APPEND)`, which follows links and blocks on a FIFO with no reader.
`history_file.chmod()` follows the link, and `FileHistory` appends through it.

Fix: open with `O_NOFOLLOW | O_NONBLOCK` and require `S_ISREG`; otherwise use
`InMemoryHistory` and say so.

Dedupe: w5/590 (done) is the update-check sibling; w5/455 and 392 (done)
cover mode and the beanquery path.

Acceptance: neither fixture changes anything outside the config directory,
and both open the prompt. Tests pin both.

---

**Resolved 2026-10-20** — `_history()` now opens `ask_history` with `O_NOFOLLOW | O_NONBLOCK`, requires a regular file (`fstat`), and sets its mode through the descriptor. A symbolic link (the open fails with ELOOP) or a FIFO (ENXIO with no reader; not a regular file otherwise) falls back to in-memory history with a note: `… is not a regular file bea can keep, so this session's questions are kept in memory only. Remove it to keep history again.` In the fixture, `precious.txt` keeps mode 0644 and its contents, and the link stays. The prompt opens at once with a FIFO there. A regular history is still kept at 0600. `tests/test_ask_history_not_followed.py` covers the link, the FIFO (guarded against blocking) and the regular-file control; the first two fail at HEAD.
