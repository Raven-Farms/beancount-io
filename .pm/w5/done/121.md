# `bea format FILE > out.bean` exits 0 with non-ASCII text rewritten as literal escapes when stdout is not UTF-8

**Minor (narrow trigger) · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`),
checkout `bea 0.3.1`, macOS.
When standard output's encoding cannot represent a character, the formatter
writes it as a literal backslash escape and exits 0. The redirected file then
contains a different payee and narration from the ledger and still passes
`bea check`. On macOS and Linux this needs a non-UTF-8 `PYTHONIOENCODING`;
the realistic trigger is redirected output on Windows, which was not
exercised. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Bank USD
2026-01-01 open Expenses:Food USD
2026-01-02 * "Müller" "Kaffee ☕"
  Expenses:Food  4.50 USD
  Assets:Bank
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY.

```sh
PYTHONIOENCODING=ascii bea format /absolute/books/main.bean > out.bean
```

Actual: exit 0, and `out.bean` holds
`2026-01-02 * "M\xfcller" "Kaffee \u2615"` as literal backslash text. A
worker confirmed `bea check` on that file exits 0, and that under
`PYTHONIOENCODING=cp1252` both `format` and `query PRINT` write
`Kaffee \u2615` in a cp1252-encoded file; my own cp1252 run produced a
non-UTF-8 byte 0xfc on stdout.

Control: with default UTF-8 output the same command prints
`"Müller" "Kaffee ☕"`. A worker confirmed `format -o out.bean` under the
ascii setting writes correct UTF-8.

Expected: `docs/USAGE.md` says "Stdout, `-o`, and `-i` produce the same
text" and "Exit 0 is a promise". Ledger text on stdout should be UTF-8
whatever the locale, or the command should fail; it must not be silently
rewritten into different strings.

Cause: `cli/src/cli/main.py:50` reconfigures stdout with
`errors="backslashreplace"`, added for w1/104 so confirmation lines cannot
crash. `cli/src/cli/commands/format.py:519` writes the ledger text through
that same stream.

Fix: write data-bearing stdout — `format`, and `query` Beancount and CSV
output — as UTF-8 bytes regardless of locale, keeping the lenient error
handler for human confirmation lines only. No dependency or API change.

Dedupe: board search for backslashreplace, `PYTHONIOENCODING` and cp1252
finds w1/104 (the fix that introduced this, done) and w1/065, w4/168, w5/078
(CSV input encoding); none covers ledger text on stdout.

Acceptance: under `PYTHONIOENCODING=ascii` and `cp1252`, `format FILE`
and `query PRINT` write bytes identical to the UTF-8 run, or exit non-zero
writing nothing; confirmation lines still never crash. Only macOS and the
checkout were exercised; Windows behaviour is inferred.

---

**Resolved 2026-10-13** — `bea format FILE` and `bea query` now write their result to stdout through a new `output.write_data` in `cli/src/cli/output.py`, which switches stdout to UTF-8 before writing ledger text or a query result; confirmation lines printed without data keep the lenient escaping from w1/104. The regression test compares `format` and `query` (PRINT, beancount, CSV, text) bytes under ascii and cp1252 stdout against the UTF-8 run and against `-o` (six cases fail with the fix reverted), and checks a confirmation naming a non-ASCII path is still escaped with exit 0. `docs/USAGE.md` states the rule. Not fixed here: `bea list` tables under cp1252 still escape, and `treeify`, `example` and `doctor` were not checked. `make check-all` passed. Only macOS was exercised; Windows behaviour is inferred. Shipped in `bab497b6` (`cli`).
