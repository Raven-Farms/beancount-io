# A `--rules` file silently ignores unknown keys and tables: a misspelled `[[rules]]` block drops its rules, and keys like `field = "narration"` are accepted but do nothing

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
`load_rules` reads only the top-level `rule` array, and from each rule only
`match` and `account`. Everything else in the file is dropped silently:

- A misspelled table header (`[[rules]]`, `[[Rule]]`) loses every rule
  under it. Those rows fall through to `unmatched`, and `--apply` books
  them to `Expenses:Uncategorized` with exit 0.
- Extra keys inside a rule (`field`, `flag`, `narration`, `tags`) read like
  restrictions or actions but do nothing. The rule still matches all three
  fields and writes `*`.

Agents that generate rules files are the likely authors of such keys. Bulk
input already refuses unknown keys for the same reason (w3/225, w1/108). No
product fix implemented.

Use any valid ledger that opens `Assets:Checking`, `Expenses:Groceries`,
`Expenses:Dining` and `Expenses:Uncategorized` in USD. Create `s.csv`:

```text
Date,Payee,Narration,Amount
2026-01-05,Whole Foods,lunch at cafe,-20.00
2026-01-06,Joe Diner,groceries run,-10.00
```

Create `r2.toml`:

```toml
[[rule]]
match = "whole foods"
account = "Expenses:Groceries"

[[rules]]
match = "diner"
account = "Expenses:Dining"
```

Create `r3.toml`, a single `[[rule]]` with `match = "diner"`,
`account = "Expenses:Dining"` and `field = "narration"`. Use isolated
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no inherited
BEA_FILE/BEA_TOKEN, and closed stdin.

```sh
bea --json -f main.bean import s.csv --csv date=Date,payee=Payee,narration=Narration,amount=Amount --account Assets:Checking --rules r2.toml --apply
bea --json -f main.bean import s.csv --csv date=Date,payee=Payee,narration=Narration,amount=Amount --account Assets:Checking --rules r3.toml
```

Actual:

- `r2.toml`: exit 0, `written: 2`, and the rules applied are
  `["whole foods", "unmatched"]`. The Joe Diner row is booked to
  `Expenses:Uncategorized`, and the `[[rules]]` block is never mentioned.
- `r3.toml`: exit 0. The rule matches row 2 through its payee, although
  `field = "narration"` was written to restrict it to the narration
  (`groceries run`).
- `flag = "!"` and `narration = "Groceries"` are accepted and ignored the
  same way.

Reproduced in three fresh directories.

Control: a misspelled required key (`acount`) exits 2 with `Rule 1 must be
{ match = "<regex>", account = "..." }`. A file with no `rule` array exits
2 with `must hold a [[rule]] list`.

Expected: `docs/IMPORTING.md` says "Each entry needs `match` and `account`"
and documents no other key or table. A key or table the loader does not
understand should be refused with exit 2, naming the rule (or table) and
the key, as a bad regex already is.

Cause: `load_rules` (`cli/src/bea_engine/csv_mapper.py:394-415`) ignores
every top-level key except `rule`. `CsvRule.compile`
(`csv_mapper.py:306-310`) reads only `match` and `account`.

Fix:

- Refuse any other top-level key, with a near-miss hint such as `unknown
  table [[rules]]; did you mean [[rule]]?`.
- Refuse any rule key other than `match` and `account`, naming it.

In both cases exit 2, write nothing and remember nothing. No dependency
change.

Blast radius: every `import` that uses `--rules`, passed directly or
remembered, in preview and `--apply`, plus the skill workflows that
generate rules files.

Dedupe: searched `.pm/**`, including `done/`, for `[[rules]]`, "unknown
key", "ignored key", and rules together with silently or ignored. Related
notes cover other inputs:

- w3/225 and w1/108: bulk input.
- w3/311: sticky rules.
- w5/131: rules dropped by `importers.py`.
- w5/311: a repeated `--rules` flag.

Acceptance: on the fixtures, both commands exit 2 naming `[[rules]]` and
`field` respectively, and the ledger and import memory are unchanged. The
bundled `examples/rules.toml` still loads. A real-command test covers an
unknown table, an unknown rule key and the near-miss hint. Only macOS and
the checkout were exercised.

---

**Resolved 2026-10-15** — `load_rules` in both `csv_mapper` twins (`cli/src/bea_engine/csv_mapper.py`, `cli/src/cli/csv_mapper.py`) runs a new `_refuse_unknown_rule_keys` first. Any top-level table or key other than `rule` exits 2: "unknown table [[rules]]; a rules file holds only [[rule]] entries — did you mean [[rule]]?", with the hint for `rules`/`Rule` spellings. Any rule key other than `match` and `account` exits 2 too: "rule 1 has unknown key 'field'; each rule holds only match and account." On the fixtures, both imports exit 2 with the ledger and import memory unchanged, and the bundled `examples/rules.toml` still loads. IMPORTING.md's rules paragraph says so. `cli/tests/test_rules_unknown_keys.py` covers `[[rules]]` beside a valid rule, `[[Rule]]`, a `field` key and the bundled example; the 3 refusal cases fail with the fix reverted. Only macOS was exercised. `make check-all` passed. Shipped in `591f5a97` (`cli`).
