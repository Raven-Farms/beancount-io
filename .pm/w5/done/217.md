# Text reports print a negative zero (`Net Profit: -0 USD`) when an amount rounds to zero

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
Cosmetic. When a small negative amount rounds to zero at the ledger's
display precision, text reports show `-0 USD`. The balance sheet shows the
same quantity as `0 USD` and `-0 USD` four lines apart. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
option "display_precision" "USD:1"
2026-01-01 open Assets:Checking USD
2026-01-01 open Income:Interest
2026-01-01 open Expenses:Fees

2026-01-05 * "wire fee"
  Expenses:Fees     25.40 USD
  Assets:Checking

2026-01-31 * "interest"
  Assets:Checking   25.00 USD
  Income:Interest
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean report income-statement -i yearly
bea -f main.bean report balance-sheet -i yearly
```

Actual (exit 0):

```text
Net Profit: -0 USD
2026-12-31  -25 USD  25 USD    -0 USD
```

and on the balance sheet `Current-period earnings (credit): 0 USD`
followed by `…the same period's Net Profit is -0 USD.`

Control: the same ledger without the `display_precision` line prints
`Net Profit: -0.40 USD` and `-25.00 USD  25.40 USD  -0.40 USD`. A worker
saw `Assets: -0 USD` / `Net Worth: -0 USD` in `report overview`, exact
`-0.40` in JSON, and `-0.00 USD` without the option when a 5 KRW expense
is converted at 0.00072 USD.

Expected: net profit is 25.00 − 25.40 = −0.40, which at whole-dollar
precision is zero. `docs/USAGE.md` says text amounts are "rounded to the
display precision the ledger uses for each currency"; a rounded zero has no
sign.

Cause: `cli/src/cli/commands/report.py:65-82` (`_quantize`) returns
`Decimal('-0')` because `quantize` keeps the sign, and `:105` formats it
with `:,.Nf`, which prints the minus.

Fix: after quantizing, drop the sign of a zero result before formatting.
JSON unchanged. No dependency or API change.

Blast radius: every amount in the four text reports and `bea balance`:
trees, headlines and interval tables.

Dedupe: board search for `-0 USD`, `-0.00`, "negative zero" and "signed
zero" finds dashboard items (w4/done/024, 130, 217) and CSV rounding
(w3/done/408); w3/done/365 and w1/done/052 are about which precision is
chosen. Nothing covers the sign of a rounded zero in CLI reports.

Acceptance: the fixture prints `Net Profit: 0 USD` and `0 USD` in the
interval row; the control still prints `-0.40 USD`. Only macOS and the
checkout were exercised.

---

**Resolved 2026-10-13** — The text amount renderer in `cli/src/cli/commands/report.py` now drops the sign of an amount that rounds to zero at the currency's display precision, so the fixture prints `Net Profit: 0 USD` and `0 USD` in the interval row instead of `-0 USD`; this one renderer serves the trees, headlines and interval tables of all four reports and `bea balance`. JSON is unchanged and still carries the exact `-0.40`, and `cli/docs/USAGE.md` now states that a rounded zero prints unsigned. The regression test `cli/tests/test_report_rounded_zero_is_unsigned.py` runs the real command for the income statement, balance sheet, overview, trial balance and `bea balance`, plus a 5 KRW expense converted to USD that used to read `-0.00 USD`, and pins the control (`-0.40 USD` without the `display_precision` option) and the JSON value. Six of its eight cases fail with the fix reverted; the two that pass are the control and the JSON check. Only macOS was exercised. `make check-all` passed. Shipped in `d9798924` (`cli`).
