# `bea price export -o first -o second` silently exports to `second`; every other command refuses two different values for one option

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `0864aeed`, checkout `bea 0.3.1`, macOS 26.5.1. Sibling of w5/381.
USAGE's rule, applied to `add`, `import`, `init` and the read commands
(w5/238, 311, 381), is that a repeated single-value option with two
different values exits 2, naming both. `price export` parses its own
arguments and keeps the last value. No product fix implemented.

`main.bean` with an allowlisted managed include.

```sh
bea -f /abs/main.bean price export -o first -o second
```

Actual: `Exported 2 files to second.`, exit 0; `first` is never created.

Expected: exit 2, `Conflicting values for one option: -o first, -o second`,
and nothing written. The same value repeated is accepted.

Cause: `_export` (`cli/src/cli/commands/price.py:165-189`) assigns
`output_dir` on each `-o`/`--output`/`--output=`.

Fix: refuse a second, different value in the loop with the shared wording.

Dedupe: w5/381 (done) covered the Typer commands; `price export` parses by
hand.

Acceptance: the command above exits 2 and writes nothing. A test pins it.

---

**Resolved 2026-10-16** — Shipped in `caa7eef7` (`cli`). `_export` (`cli/src/cli/commands/price.py`) now refuses a second, different `-o`/`--output`/`--output=` value with exit 2 and the shared wording (`Conflicting values for one option: -o 'first' and -o 'second'. Pass it once.`), before anything is written. The same value repeated is accepted. `tests/test_price_export_repeated_output.py` pins three spelling mixes, which fail without the fix, and the repeated-same case.
