# `bea treeify` picks a narration such as `NYSE:IBM dividend` as the account column, garbles it, and leaves the real accounts flat (regression from w5/414)

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `04c94595`, checkout `bea 0.3.1`, macOS 26.5.1. Differential run against upstream `treeify`.
w5/414 let treeify recognize accounts under any capitalized root (renamed
roots), and its resolution says "English output is byte-identical to
before". Upstream picks the leftmost column that looks like an account, and
the wider pattern now matches text such as `NYSE:IBM` or `POS
PURCHASE:WALMART` in a narration column first. No product fix implemented.

`main.bean`:

```beancount
2024-01-01 open Assets:Broker:Cash USD
2024-01-01 open Income:Dividends USD

2024-01-05 * "NYSE:IBM dividend"
  Assets:Broker:Cash  10.00 USD
  Income:Dividends
```

```sh
bea --file main.bean query "SELECT narration, account, position" > q.txt
bea treeify q.txt
```

Actual: exit 0:

```text
`-- NYSE
    `-- IBM dividend  Assets:Broker:Cash   10.00 USD
             dividend  Income:Dividends    -10.00 USD
```

The second row loses `NYSE:IBM`, and the accounts stay flat. `Ref:A12
Assets:Bank:Checking 5 USD` input behaves the same.

Control: upstream `treeify` on `q.txt` draws the Assets/Broker/Cash and
Income/Dividends tree beside the narration.

Expected: the English-root pattern is tried first; the any-root pattern is a
fallback when no column matches it.

Cause: `_ACCOUNT_PATTERN` (`cli/src/cli/commands/treeify.py:26-36`), injected at
`:194`.

Fix: as above (or prefer the column that matches the ledger's root names).

Dedupe: w5/414 (done) introduced the pattern.

Acceptance: the command draws the account tree; a renamed-root input still
works. A test pins both.

---

**Resolved 2026-10-17** — Shipped in `f8d3149e` (`cli`). `_ACCOUNT_PATTERN` (`cli/src/cli/commands/treeify.py`) now tries the any-root alternative only where no English-root account (`Assets:`, … with a colon) follows on the line. The English alternative matches full accounts, with the same non-ASCII components. Upstream still takes the leftmost matching column, but a narration such as `NYSE:IBM dividend` or `Ref:A12 transfer` beside `Assets:Broker:Cash` no longer wins it. The note's query output draws the Assets/Broker/Cash and Income/Dividends tree beside the narration, and renamed-root ledgers (w5/414) are unchanged. `tests/test_treeify_renamed_roots.py::test_a_colon_in_a_narration_does_not_take_the_account_column` pins both narrations and fails without the fix; the existing treeify tests pass. `make check-all` passed.
