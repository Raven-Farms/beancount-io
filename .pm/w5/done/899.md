# Include partial lot constraints in generated import IDs

**Major · cli · 25–40m · A1.** Same-day sales selecting different lots by
label alone hash identically. A later statement's second sale is silently
skipped, even with `--duplicates include`; holdings, proceeds and gains are
missing while `check` passes. Full cost-plus-label selectors work. Follow-up
to completed [349](./done/349.md) and [467](./done/467.md); distinct from
[897](./897.md)'s entirely omitted acquisition-date field. No fix implemented.

Create `sale-a.txt` containing `X`, `sale-b.txt` containing `Y`, and
`importers.py`:

```python
from datetime import date
from decimal import Decimal as D
from beancount.core import data, amount, position
from beancount.core.number import MISSING

class Imp:
    def identify(self, file): return str(file).endswith('.txt')
    def account(self, file): return 'Assets:Stock'
    def extract(self, file, existing_entries=None):
        label = open(file).read().strip()
        cost = position.CostSpec(MISSING, None, None, None, label, False)
        posts = [
            data.Posting('Assets:Stock', amount.Amount(D('-1'), 'HOOL'),
                cost, amount.Amount(D('150'), 'USD'), None, None),
            data.Posting('Assets:Cash', amount.Amount(D('150'), 'USD'),
                None, None, None, None),
            data.Posting('Income:Gains', None, None, None, None, None),
        ]
        return [data.Transaction(data.new_metadata(file, 1), date(2024, 2, 1),
            '*', 'Broker', 'Sale', frozenset(), frozenset(), posts)]

CONFIG = [Imp()]
```

nonempty label, but `_lot_text` (:1367–1380) emits **no cost constraint at
all** unless both cost number and currency are present. `_hash_import_ids`

uses `_lot_text` (:2588). `_legs_agree` can compare the stated labels, but a
canonical generated-ID hit takes precedence over that content comparison.

including a label even when its cost number/currency are open. Keep genuinely
open `{}` compatible with booked lots, and preserve older lossy IDs as
lookup-only spellings with an appropriate stated-lot content check; an old
label-less key must not silently consume a different label. Preserve exact
re-imports and the full-lot/same-label controls. No new dependency or API work.

**Resolved 2026-10-22** — `_lot_text` now writes whatever a cost states — number, currency, acquisition date, label, alone or together (`{"X"}`, `{100}`, `{USD}`) — into the generated import ID and the preview source amount, so same-day sales selecting different lots by label or number are two rows; a bare `{}` stays open, and the earlier spellings (units only, full cost only, no date) remain lookup-only legacy keys that the content check keeps from consuming a different lot. `cli/tests/test_import_partial_lot_identity.py` runs the label and number journeys, the same-selector duplicate and a label-less legacy ID, and fails without the fix; `cli/docs/IMPORTING.md` states the contract; shipped in the commit that moves this note (`cli`). Currency-only and compound partial costs were not exercised.
