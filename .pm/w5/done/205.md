# Remembered import settings are keyed by the typed spelling of the ledger path

**Minor · cli · 20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, Beancount 3.2.3, macOS (APFS).
Import settings are "remembered per root ledger", but the key is the
path as typed. On a case-insensitive volume, `-f Books/main.bean` and `-f
books/main.bean` are the same file with two memories: after a successful
import through one spelling, a flag-free import through the other fails
as if nothing were remembered. Write locks already treat every spelling
as one file. No product fix implemented.

In `/absolute/m`:

```sh
mkdir Books
printf 'option "operating_currency" "USD"\n2024-01-01 open Assets:Bank USD\n2024-01-01 open Expenses:Uncategorized USD\n' > Books/main.bean
printf 'When,What,Howmuch\n2024-01-02,abc,-5.00\n' > b.csv
printf 'When,What,Howmuch\n2024-02-02,def,-7.00\n' > b2.csv
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY. cwd `/absolute/m`.

```sh
bea -f /absolute/m/Books/main.bean import b.csv --csv date=When,narration=What,amount=Howmuch --account Assets:Bank --apply
bea -f /absolute/m/books/main.bean import b2.csv
bea -f /absolute/m/Books/main.bean import b2.csv
```

Actual: the first exits 0. The second (lower-case `books`) exits 2:
`Choose a Python importer with --config FILE, or place importers.py
beside the root ledger…`. The third exits 0: `Using settings remembered
from b.csv for b2.csv: …`.

Control: the third command. A worker saw the same split between an NFD
directory name on disk and its NFC spelling on the command line.

Expected: `docs/IMPORTING.md` — "The mapping is remembered per root
ledger"; `docs/USAGE.md` says of locks that "every spelling of one path
… takes the same lock".

Cause: `cli/src/cli/commands/import_.py:30-32,133-135` hash
`str(file.resolve())`, and `resolve()` does not canonicalize case or
normalization on macOS.

Fix: key the memory by the same identity the write lock uses (parent
directory identity plus the case-folded, normalized name). No dependency
change; existing records would need a fallback lookup.

Blast radius: remembered CSV mappings and the remembered `--config`
importer path, on case-insensitive volumes.

Dedupe: w5/141 (remembered path that no longer exists) and w5/077
(remembered delimiter); board search for remembered with spelling or
case finds nothing else.

Acceptance: the second command recalls the settings and previews
`b2.csv`. Only macOS (case-insensitive volume) and the checkout were
exercised.

---

**Resolved 2026-10-13** — Remembered import settings in `cli/src/cli/commands/import_.py` are now keyed by the ledger path spelled the way each directory stores it, so `Books/main.bean` and `books/main.bean` (or an NFC spelling of an NFD directory) share one remembered CSV mapping and one remembered `--config` path; a record saved earlier under the typed spelling is still read until the next successful import rewrites it. This deviates from the note's suggested key: the write lock's directory device and inode were not reused, because a persistent memory has to survive a remount or a restored directory, whereas the stored spelling is stable and on a case-sensitive volume still keeps two differently-cased ledgers apart. `cli/docs/IMPORTING.md` states the per-file contract. `cli/tests/test_import_memory_any_ledger_spelling.py` covers lower-case, upper-case and NFC respellings for the CSV mapping, saving through the other spelling, the remembered Python importer, a legacy record, and a sibling ledger that must recall nothing; six of its eight cases fail with the fix reverted. A legacy record written through a non-stored spelling is found only through that same spelling, and the case-sensitive-volume separation was reasoned, not exercised. Only macOS was exercised. `make check-all` passed. Shipped in `0d296810` (`cli`).
