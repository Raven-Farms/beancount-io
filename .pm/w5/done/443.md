# A date passed as `add transaction`'s positional argument becomes the narration and the entry is silently dated today: `bea add transaction 2026-01-05 -p …` writes `2026-10-14 * "2026-01-05"` with exit 0

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
`add transaction` takes the narration as its positional argument and
defaults the date to today. A user or agent who writes the date where
the narration goes, a natural guess after `bea add transaction --help`,
gets a transaction on the wrong day whose narration is the intended date.
An unquoted posting does the same thing with an amount. Nothing warns.
No product fix implemented.

Use a USD ledger with `Assets:Cash` and `Expenses:Food` open. Use
isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, and
closed stdin.

```sh
bea -f /absolute/books/main.bean add transaction 2026-01-05 -p 'Expenses:Food 5 USD' -p Assets:Cash
bea --json -f /absolute/books/main.bean add transaction 01/05/2026 -p 'Expenses:Food 5 USD' -p Assets:Cash
bea -f /absolute/books/main.bean add transaction -p Expenses:Food 5 -p 'Assets:Cash -5 USD'
```

Actual:

- The first command exits 0 and writes `2026-10-14 * "2026-01-05"`, dated
  today.
- The second writes narration `"01/05/2026"` (JSON `"date":
  "2026-10-14"`).
- The third (unquoted posting) writes narration `"5"` with the amount
  interpolated.

Reproduced twice by the hunter and once by me (the first).

Control: `add transaction Lunch 2026-01-05 …` exits 2 with "unexpected
extra argument(s) (2026-01-05)". `--date 2026-01-05` writes the right
date.

Expected: a narration that is exactly a date (ISO or a common slash
form), given without `--date`, is almost certainly a misplaced date. It
should be refused with exit 2 and a hint, for example "'2026-01-05' looks
like a date; pass --date 2026-01-05 (the positional argument is the
narration)". A bare-number narration next to a posting with no amount
deserves a similar hint.

Cause: `cli/src/cli/commands/add.py:153` (`narration_arg`) and `:177-181`
accept any text.

Fix: when the narration parses as a date and `--date` is absent, raise
`UsageError` with the hint. Optionally do the same for a bare-number
narration. No dependency change.

Blast radius: `bea add transaction` from users and agents. The result is
silently mis-dated entries, which then distort period reports.

Dedupe: searched `.pm/**`, including `done/`, for narration together
with date, positional date and `narration_arg`. No hits.

Acceptance: the first two commands exit 2 with the hint, and nothing is
written. `add transaction "Lunch 2026-01-05"` with `--date` still works.
A test pins it.

Addendum (CLI QA r87, 2026-10-14): an account or an amount in the
positional slot is written the same way. `add transaction Expenses:Food
-p 'Expenses:Food 5 USD' -p Assets:Cash` writes `2026-10-14 *
"Expenses:Food"`, and `add transaction '5 USD' -p Expenses:Food -p
'Assets:Cash -5 USD'` writes `"5 USD"`. Both exit 0 and were run twice
by the hunter. A narration that parses exactly as an account or an
amount, given without `--date`, deserves at least a warning ("looks like
an account; postings go in -p"). That case can stay a warning rather
than a refusal, because such text is a legal narration.

---

**Resolved 2026-10-15** — when `--date` is absent, `add transaction` now
refuses a positional narration that is a date (ISO, year-first with `/`
or `.`, or a day-month-year slash form). It exits 2, writes nothing, and
says `'2026-01-05' looks like a date, but the positional argument is the
narration, and without --date the entry is dated today. Pass --date
2026-01-05, or add --date to keep it as the narration.` An ambiguous
`01/05/2026` gets `--date YYYY-MM-DD`. Per the addendum, a narration that
is an account (`Expenses:Food`) or an amount (`5`, `5 USD`) is still
written, with a warning in text and JSON that postings go in `-p`. With
`--date`, any narration is written as before (`cli/src/cli/commands/add.py`).
USAGE notes both behaviors. Pinned by
`cli/tests/test_add_transaction_narration_shape.py`, which fails without
the fix.
