# `ask_history` is created world-readable (`0644`, in a `0755` config directory) and stores every `bea ask` question verbatim with no opt-out, while bea keeps credentials and import memory owner-only

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, umask 022. **Simulation:** a localhost mock model answered.

Questions asked in `bea ask` are about the user's finances and may
include pasted account numbers or secrets. They are appended to
`$BEA_CONFIG_DIR/ask_history`, which prompt_toolkit creates with the
default `0666 & ~umask`, inside a directory created with the default
mode. Any local user can read them. bea already keeps
`credentials.json` and import memory owner-only (`0600`), and w5/175 and
w5/316 set the rule that private data is not left world-readable.
History cannot be turned off, and its size is unbounded. No product fix
implemented.

Point `BEA_CONFIG_DIR` at a directory that does not exist yet. Use an
isolated XDG_CACHE_HOME, a fake `BEA_TOKEN`, the API URL on 127.0.0.1 (a
mock model), and a PTY. Start `bea -f /absolute/books/main.bean ask`,
type `my card number is 4111 1111 1111 1111`, press Enter, and exit with
Ctrl-D.

Actual: in both runs the config directory was created `drwxr-xr-x` and
`ask_history` `-rw-r--r--`, holding `+my card number is 4111 1111 1111
1111` in plain text. A 100 KB question produced a 100 KB history.
Reproduced twice by the hunter. I checked the resulting modes on disk.

Control: an import preview under the same fresh config writes
`importers/csv-….json` and `importers.lock` as `-rw-------`.
`save_credentials` uses a `0700` directory and a `0600` file
(`cli/src/cli/auth/credentials.py:63-75`).

Expected: `ask_history` at `0600`, in a `0700` directory, an opt-out
(for example `BEA_ASK_HISTORY=0`), and documentation in USAGE next to the
existing list of configuration files.

Cause: `_make_session` (`cli/src/cli/ask/repl.py:71-82`) runs
`history_file.parent.mkdir(parents=True, exist_ok=True)` and then
`FileHistory(str(history_file))`. `history_path()`
(`cli/src/cli/config.py:67-68`) cannot be disabled.

Fix: create the directory `0700`, pre-create or `chmod` the history file
to `0600` before `FileHistory` opens it, add the opt-out, and optionally
cap the size. No dependency change.

Blast radius: every `bea ask` user on a multi-user machine, or with a
shared or synced config directory.

Dedupe: 392 covers the query shell's history location. w5/175 and w5/316
set the private-file rule for caches and exports. No `.pm` hit for
`ask_history` permissions.

Acceptance: after a session under umask 022, `ask_history` is `0600` and
the config directory `0700`. The opt-out prevents any history file. A
test pins the modes.

---

**Resolved 2026-10-15** — `_history` (`cli/src/cli/ask/repl.py`) tightens the config directory to `0700` and creates `ask_history` at `0600` (or tightens an existing one) before prompt_toolkit opens it, as `save_credentials` does for `credentials.json`; existing history is kept. `BEA_NO_ASK_HISTORY=1` uses in-memory history, so no file is written. This follows the repo's truthy-switch convention (`BEA_NO_UPDATE_NOTIFIER`) rather than the note's suggested `BEA_ASK_HISTORY=0`. USAGE documents the mode and the variable. No size cap was added. `cli/tests/test_ask_history_private.py` covers a fresh history under umask 022 (file `0600`, directory `0700`), tightening an existing `0644` history without losing it, and the opt-out writing no file; they fail without the fix. Only macOS was exercised. `make check-all` passed (6030 tests). Shipped in `f508988c` (`cli`).
