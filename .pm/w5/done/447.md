# `beancount-migrate` eval 7 pins `monarch:sha256:` import-ids that come out only if the agent names the accounts `Assets:Checking`/`Assets:Savings`, a mapping the prompt never gives and the skill's naming rule contradicts

**Trivial · skills · 10m · A1.** Real QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1.
Eval 7 (`migrated-ids-survive-later-imports`) in
`skills/.claude/skills/beancount-migrate/evals/evals.json` expects
specific ids, for example "import-id monarch:sha256:89784d830e9af8e2
(checking) and import-id-2 monarch:sha256:0218b42481730d49 (savings)"
and the non-transfer ids `957422234a9fc7b5`, `9b811ad4dd24f37f` and
`33fe274b8cc7a957`, "computed, not invented". Each id hashes the account
name. Those values follow the mapping in
`skills/docs/examples/migration/expectations.json` (`Chase Checking →
Assets:Checking`, `Ally Savings → Assets:Savings`).

Eval 7's prompt only says "Chase Checking" and "Ally Savings", and
attaches only the export. The skill tells the agent to name these
accounts `Assets:Bank:<Name>` (`references/mapping.md:5`), and eval 1
even expects `Assets:Bank:ChaseChecking`. An agent that follows the
skill produces correct ids for its own mapping and fails the grader. No
product fix implemented.

The hunter checked this two ways, using the documented hash
`<date>|<exact amount> USD|<Original Statement>|<account>` (r33's
`hid.py`) and `bea import --csv … --account X` on the same row:

| Account | Checking id | Savings id |
|---|---|---|
| `Assets:Checking` / `Assets:Savings` | `957422234a9fc7b5` (pinned) | `33fe274b8cc7a957` (pinned) |
| `Assets:Bank:ChaseChecking` / `Assets:Bank:AllySavings` | `db3fdc64c4d06f82` | `1ff08bfed3cf531a` |

bea's own `csv:sha256:` ids follow the same rule. I checked the eval's
prompt text myself.

Verdict: the expectation is under-specified. bea and the documented
hash agree with each other.

Fix: either

- state the mapping in eval 7's prompt or files (for example "use
  Assets:Checking and Assets:Savings", or attach `expectations.json`);
  or
- reword the expectation as "ids equal the documented hash for the
  confirmed account mapping", checked with `verify-migration.py`.

Blast radius: the migrate eval suite. A correct agent run is scored as a
failure.

Dedupe: no `.pm` hits for the pinned ids. `w5/done/m10/done/t008.md`
checks the ids against `expectations.json`, not against what eval 7's
prompt provides. 356-362 and 446 cover other skill issues.

Acceptance: an agent run that follows `mapping.md`'s naming passes eval
7. The pinned ids appear only together with the mapping that produces
them.
