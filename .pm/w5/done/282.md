# Under `--json`, a refused flag-free import does not report the remembered settings it used

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A JSON preview of a flag-free import carries a `remembered` object, the
resolved `date_format` and the ambiguity notes. The same command with
`--apply`, when refused (exit 4), carries none of them in `error.result`,
although the docs say a blocked application "includes the full preview". An
agent that typed no mapping is not told which one was recalled. No product
fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Assets:Savings USD
2026-01-01 open Expenses:Food
2026-01-01 open Expenses:Uncategorized
```

`/absolute/books/dup1.csv`:

```csv
Date,Description,Amount,FITID
2026-04-02,Grocer,-20.00,A1
```

`/absolute/books/dup2.csv`:

```csv
Date,Description,Amount,FITID
04/02/2026,Grocer,-20.00,B7
```

`/absolute/books/rules.toml`:

```toml
[[rule]]
match = "grocer"
account = "Expenses:Food"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME (fresh), BEA_NO_UPDATE_NOTIFIER=1,
no inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean import dup1.csv --csv date=Date,amount=Amount,narration=Description,id=FITID --account Assets:Checking --rules rules.toml --default-account Expenses:Food --apply
bea --json -f main.bean import dup2.csv
bea --json -f main.bean import dup2.csv --apply
```

Actual: the JSON preview (exit 0) has `data.remembered`, `data.date_format:
"%m/%d/%Y"`, two `notes` and `config_source: "remembered --csv"`. The
refused apply (exit 4) has `error.result.config_source: "remembered --csv"`
but no `remembered` key, no `date_format` and no notes; `error.details`
holds only the possible-duplicate row. A worker saw an exit-2 failure of a
recalled run print only the bare usage error.

Control: the preview in the same sequence, and human mode, which prints
the settings line and the ambiguity note on stderr for the refused
command.

Expected: `docs/IMPORTING.md`: JSON reports `config_source` `remembered
--csv` "plus a `remembered` object with the same fields", and a blocked
application "includes the full preview in `error.result`".

Cause: `cli/src/cli/commands/import_.py:581-582` emits the notes through a
function that does nothing in JSON mode; `:650-658` re-raises the engine
error without attaching the frontend's notes, `remembered` or
`date_format`; `:670-689` adds them only on success.

Fix: on the error path merge the frontend notes, `date_format` and
`remembered` into `error.result` when present, and put the notes in
`error.details` otherwise. No dependency change; fields are added.

Blast radius: every `--json` import failure after settings were resolved
(recalled or inferred runs).

Dedupe: board search for `error.result` and remembered with JSON finds
w3/done/238 (the success envelope) and w3/done/425 (memory writes);
nothing covers the failure envelope.

Acceptance: the refused apply's `error.result` contains `remembered`,
`date_format` and the notes exactly as the preview does. Only macOS and
the checkout were exercised.

---

**Resolved 2026-10-13** — In `cli/src/cli/commands/import_.py` the import command's error path now adds the frontend's settings notes, the resolved `date_format` and the `remembered` object to `error.result` whenever the engine refused an import with a preview, in the same order and shape the successful JSON preview uses. A failure that has no preview (for example a missing `--into` directory) lists those notes at the head of `error.details` only when the column mapping was remembered or read from the header row; runs with a typed `--csv` or a Python importer keep their details to what the error itself lists, a narrowing of the note's "put the notes in `error.details` otherwise". Human output is unchanged, since the notes were already printed on stderr there, and `docs/IMPORTING.md` states both behaviours next to the existing "full preview in `error.result`" sentence. The regression test `tests/test_import_refused_json_reports_settings.py` runs the note's fixture through real commands and checks that a refused recalled apply and a refused explicit `--csv` apply carry exactly the preview's `remembered`, `date_format` and `notes`, that a preview-less recalled failure names the settings in its details while a typed one does not, and that human mode prints each note once; three of its five cases fail with the fix reverted, the two controls passing either way. Only macOS was exercised. `make check-all` passed. Shipped in `bc7c709f` (`cli`).
