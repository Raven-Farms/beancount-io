# USAGE says `price` rejects JSON mode, but `price status` and `price export` answer with the envelope

**Minor · cli · 5–10m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Docs.
The JSON section of the usage guide lists `price` among commands that
"reject JSON mode". Only the forward to `bean-price` does; `price status`
and `price export` return normal envelopes, as other parts of the same
document describe. No product fix implemented.

Fixture: `/absolute/books/a.bean` containing `2026-01-01 open Assets:A`.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea --json -f a.bean price status
```

Actual: exit 0, `{"bea": "0.3.1", "target": {"file":
"/absolute/books/a.bean"}, "data": {"sources": []}, "truncated": false}`.
A worker saw `--json price export` return an envelope with `output`,
`files`, `overwritten` and `sources`, and `bea --json price ./quotes` (the
forward) exit 2 with `bea price has no JSON output`.

Expected: the documentation matches the tool. `docs/USAGE.md` says
"Commands that cannot produce JSON keep their own shapes: `ask`, `doctor`,
`example`, `treeify`, `price`, `ingest`, and `query --source` reject JSON
mode", and its list of commands with structured results omits `price
status` and `price export`, while the managed-prices section documents the
`--json price export` answer.

Cause: `cli/src/cli/commands/price.py:30-39` dispatches `status`,
`refresh` and `export` before the JSON refusal, so only the forward
refuses; the sentence predates those subcommands.

Fix: in the JSON section say "`price` when it forwards to bean-price", add
`price status`, `refresh` and `export` to the structured-results list, and
reword the refusal message to say which `price` forms do have JSON. No
behaviour change.

Blast radius: documentation and one message.

Dedupe: board search for "reject JSON mode" and `--json price` finds
w3/done/221, w3/done/312 and w5/done/005, all about the forward's refusal.

Acceptance: the two USAGE sentences and the refusal message distinguish
the forward from the three subcommands. Only macOS and the checkout were
exercised.

---

**Resolved 2026-10-13** — The JSON output section of `cli/docs/USAGE.md` now says that `price` rejects JSON mode only when it forwards to `bean-price`, notes that `price status`, `refresh` and `export` answer with the envelope, and lists those three among the commands with structured results. The refusal itself, raised from `cli/src/cli/commands/price.py` through a new optional `when` argument on `refuse_json` in `cli/src/cli/errors.py`, now reads "bea price has no JSON output when it forwards to bean-price" and names the three subcommands that do answer in JSON; no behaviour changed and the other refusals keep their wording. `cli/tests/test_price_json_forms_documented.py` pins the two USAGE sentences, the forward's refusal message, the `--json price status` and `--json price export` envelopes, and the unchanged `example` refusal as a control; two of its four cases fail with the change reverted. `price refresh` is covered by the documentation assertion only, since the test does not run a refresh. Only macOS was exercised. `make check-all` passed. Shipped in `feb3ea5a` (`cli`).
