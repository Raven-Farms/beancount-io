# `format --check`/`-i`/`--dry-run` on a ledger whose include is unreadable (mode 000) aborts the whole run, naming neither the include nor its parent (gap in w5/442)

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-16, HEAD `d16aea3e`, checkout `bea 0.3.1`, macOS 26.5.1.
w5/442 made `format` report a directory or broken-link include as an
"unreadable include" with its reason, and format the rest. A
permission-denied include still stops everything: `-i` formats nothing, and
the JSON error has no `result`. No product fix implemented.

`A/main.bean`, with an unaligned transaction and `include "sub.bean"`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Equity:Opening
2026-01-02 * "t"
  Assets:Cash   5 USD
  Equity:Opening   -5 USD
include "sub.bean"
```

`A/sub.bean` holds one valid transaction, `chmod 000`.

```sh
bea format --check A/main.bean
bea --json format -i A/main.bean
```

Actual: both exit 1 with `Error: Could not read …/A/sub.bean: Permission
denied.`; `main.bean` is left unformatted (hash unchanged) and the JSON error
has no `error.result`.

Control: with `sub.bean` a directory or a broken link, the error is
`unreadable include: "sub.bean" (included by …/main.bean): …`, JSON carries
`result.missing[].reason`, and `-i` formats `main.bean`. `bea check` on the
mode-000 case exits 2 naming both files.

Expected: the same unreadable-include handling for a permission error.

Cause: `walk_closure` (`cli/src/cli/output.py:397-399`) drops the
`unreadable` list `_walk_closure` computes; `format.py:462-468` adds the file
to the targets; `_syntax_failures` → `_text()` (`format.py:481`) raises
`LedgerError` (`format.py:372`).

Fix: classify a read `PermissionError` as an unreadable include in the walk,
as w5/442 does for directories and broken links.

Dedupe: w5/120 (reads/writes), 442 (format, other causes) and 274
(directory walks) are done.

Acceptance: both commands report the unreadable include with its reason, and
`-i` formats `main.bean`. A test pins it.

---

**Resolved 2026-10-17** — Shipped in `55b38552` (`cli`). The closure walk (`_walk_closure` in `cli/src/cli/output.py`) now remembers which include first reached each member. A member that cannot be read, such as a mode-000 file, is reported as an unreadable include: `"sub.bean" (included by …/main.bean): …/sub.bean cannot be read: Permission denied`. It stays a member, so no output may overwrite it. `format` (`cli/src/cli/commands/format.py`) skips members it cannot read and formats the rest, as w5/442 does for a directory or broken link. `format --check` names the include beside `would format: …/main.bean`, and `--json format -i` formats `main.bean` with the include in `result.missing`. `tests/test_format_permission_denied_include.py` pins both (skipped as root), and both fail without the fix.
