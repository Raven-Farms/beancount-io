# `ingest extract -e LEDGER` misses duplicates when a ledger file starts with a UTF-8 BOM or spells an account in NFD, and gives no warning, though `bea check` and `list` read that ledger normally

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-17, HEAD `d75811df`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE:589-592 says a ledger saved with a UTF-8 BOM "loads like any other" and
that NFC and NFD spellings "resolve to one account". Doctor routes such
ledgers through the helper for that reason (USAGE:363). `ingest extract -e`
hands the ledger to Beangulp's stock loader instead, so its duplicate check
silently fails. Windows Notepad saves files with a BOM. No product fix
implemented.

`main.bean`:

```
option "operating_currency" "USD"
include "txns/jan.bean"
2026-01-01 open Assets:Bank:Checking USD
2026-01-01 open Income:Salary USD
```

`txns/jan.bean`, starting with the bytes `EF BB BF`:

```
2026-01-09 * "Salary" ""
  Assets:Bank:Checking  1000.00 USD
  Income:Salary
```

`downloads/bank-jan.csv` holds `Date,Payee,Amount`, `2026-01-03,Coffee,-4.50`
and `2026-01-09,Salary,1000.00`. The ingest script is a minimal
`beangulp.Importer` that turns each row into a one-posting transaction on
`Assets:Bank:Checking` and ends with `beangulp.Ingest([BankImporter()])()`.

```sh
bea -f /abs/main.bean check
bea ingest extract --config ingest.py -e /abs/main.bean downloads/bank-jan.csv
```

Actual: `check` exits 0. `extract` exits 0 and prints the 2026-01-09 Salary
entry as new, with no `; duplicate of` line. The NFD variant behaves the
same: the ledger spells `Assets:Bank:Épargne` in NFD, the importer emits NFC,
and nothing is flagged.

Control: the same `txns/jan.bean` without the BOM gives `; duplicate of
…/txns/jan.bean:1` and comments out the entry.

Expected: duplicates are detected for a BOM or NFD ledger, as every other bea
operation reads it. Failing that, the command exits 2 naming the file instead
of producing a wrong answer.

Cause:
- `cli/src/cli/commands/ingest.py:81-91` forwards `-e` straight to the script.
- Beangulp loads it with `beancount.loader.load_file` and discards the errors.
  The stock loader glues the BOM to the first directive and keeps NFD names
  separate.
- Ingest has no counterpart to doctor's `_needs_compat` routing.

Fix: when the `-e` closure has a BOM or non-NFC text, refuse with exit 2 and a
`format -i` hint, or have the helper provide the normalized entries.

Dedupe: w5/530 (open) covers `bea import` normalization; w5/135 (done) is the
doctor compat fix. Neither covers ingest.

Acceptance: the BOM fixture marks the Salary row as a duplicate (or exits 2
naming the file). A test pins it.

**Resolved 2026-10-18** — Shipped in `6a7b75475f84a0cfe3d602bdaf0ac0950ba99178` (`cli`). Chose the note's permitted refusal: `ingest extract -e/--existing` scans the plaintext existing-ledger include closure before running the user script or opening extraction output. A BOM-marked member is refused with usage exit 2 naming the actual file and a shell-quoted `bea format -i FILE` remedy. Text outside Unicode NFC is refused with a re-save-in-NFC hint that explicitly says format does not renormalize. Inspection uses the lexical path Beangulp itself loads, skips encrypted members, and conservatively considers all plaintext text, including strings/comments. USAGE documents these limits. Identify, archive and extract without an existing ledger stay unchanged.
