# A stray CR in a file with a managed price include makes bea rewrite the wrong line of it: the user's own directive vanishes from the load and from `price export`, and `check` fails on a false error

**Major · cli · 20–30m · A1.** Real CLI QA, 2026-10-16, HEAD `0864aeed`, checkout `bea 0.3.1`, macOS 26.5.1. Synthetic local feed server, allowlisted with `MANAGED_PRICE_ORIGINS`.
Before it loads, bea rewrites some managed `include` lines in memory: a
feed included twice, an unavailable one, or a refused one. `_swap_line`
counts lines with `bytes.splitlines`, which also breaks on a lone `\r`.
Beancount's line numbers count `\n` only, so one stray CR above the
include, for example in a pasted comment, shifts the swap onto the line
before it. The files on disk are unchanged; the load and the export are
wrong. No product fix implemented.

`main.bean` (`$FEED` = an allowlisted feed for BTC-USD with points
2026-10-14 60000, 10-15 61000 and 10-16 62000 USD):

```beancount
option "operating_currency" "USD"
include "$FEED"
2026-01-01 open Assets:Crypto BTC
2026-01-01 open Assets:Cash USD
2026-01-02 * "Buy BTC"
  Assets:Crypto  1 BTC {50000 USD}
  Assets:Cash  -50000 USD
include "sub.bean"
```

`sub.bean`, as bytes (`\r` is a lone CR inside a comment):

```text
; memo pasted from bank\r export\n
2026-10-16 price BTC 70000 USD\n
include "$FEED"\n
```

Isolated config/cache, closed stdin.

```sh
bea -f /abs/main.bean check
bea -f /abs/main.bean balance -x at_value Crypto --allow-errors
bea -f /abs/main.bean price export -o exp
```

Actual:

- `check` exits 1 with `<load>:0: File glob "$FEED" does not match any
  files`;
- `balance` values Crypto at 61,000 USD: the user's 70000 price line was
  commented out in place of the repeated include, and the feed's 62000 is
  still shadowed;
- `price export` exits 0, and the exported `sub.bean` has `; managed price
  feed already included from another file` where the price was, with the URL
  include still present. Stock `bean-check` fails on it.

With `--offline` and no cache (the unavailable-source path), the line
before the include is commented out instead, which adds `Invalid reference
to unknown account`.

Control: replace the CR with a space. `check` exits 0, the balance is
70,000 USD, and the export keeps the price.

Expected: a lone CR inside a comment means nothing to Beancount, so the
load is the same with or without it.

Cause: `_swap_line` (`cli/src/bea_engine/managed_load.py:959-963`) splits with
`splitlines`; its callers in the load (`:907`, `:941`, `:945`) and the
export (`:1607`, `:1620`) pass the lexer's `\n`-only line numbers.
`iter_includes`'s line starts in `cli/src/bea_engine/ledger/text.py:499-501`
split the same way.

Fix: count lines on `\n` only, using the `lexer_lines` helper the w5/380 fix
added for `write.py`. Check the other `splitlines` callers in
`managed_load.py` and `ledger/text.py`.

Blast radius: every load and export of a ledger with a managed include whose
file holds a lone CR above a rewritten include.

Dedupe: searched `_swap_line`, `lone CR`, `stray CR`. w5/169 and w5/380
fixed the same split in the reader and `write.py`; these sites were missed.

Acceptance: with the CR fixture, `check` exits 0, the balance is 70,000 USD,
and the export keeps the price line and replaces the include. A test pins
the load and the export.

---

**Resolved 2026-10-16** — Shipped in `7b15b76b` (`cli`). `_swap_line` (`cli/src/bea_engine/managed_load.py`) and the line starts in `iter_includes` (`cli/src/bea_engine/ledger/text.py`) now count lines with `lexer_lines`, on `\n` alone as Beancount's lexer does. `lexer_lines` moved from `write.py` to `ledger/text.py`, and `_option_location` uses it too. A lone CR in a comment above a repeated feed include no longer moves the swap: `check` passes, the user's 70000 USD price loads, and `price export` keeps the price line while replacing the include. The `--offline` unavailable-source swap goes through the same function. `tests/test_managed_include_lone_cr.py` pins the load and the export, and both fail without the fix. `tests/test_write_validation_hint_scans.py` now counts the lexer's `\n` splits as well as `splitlines`. Its whole-file ceiling rises from 4 to 6, and the count is still equal for 3 and 60 errors.
