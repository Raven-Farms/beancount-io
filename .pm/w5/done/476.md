# A price you declare yourself loses to the managed feed when its file starts with a byte-order mark, or when a line Beancount ignores above it contains a `"`

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-16, HEAD `0864aeed`, checkout `bea 0.3.1`, macOS 26.5.1. Synthetic local feed server.
USAGE promises "A price you declare yourself wins" over a managed feed point
for the same date and pair. bea finds the authored prices with a text scan.
The scan misses two kinds of price that Beancount reads, so the feed's
point stays in force and the holding is valued at the feed's price with
exit 0. No product fix implemented.

Base ledger: `option "operating_currency" "USD"`, `include "$FEED"` (BTC-USD
feed with a 2026-10-16 point at 62000 USD), opens for `Assets:Crypto BTC` and
`Assets:Cash USD`, and a buy of `1 BTC {50000 USD}`.

(a) Add `include "prices.bean"`, with `prices.bean` as the bytes
`\xef\xbb\xbf2026-10-16 price BTC 70000 USD\n` (a byte-order mark, then the
price on line 1).

(b) Instead, put these two lines in `main.bean` after the include:

```text
* Prices for the 12" binder
2026-10-16 price BTC 70000 USD
```

(an org-mode heading Beancount skips; `# … 27" monitor` behaves the same).

```sh
bea -f /abs/main.bean balance -x at_value Crypto
bea -f /abs/main.bean price status
```

Actual: Crypto is valued at 62,000 USD and `price status` shows `SHADOWED 0`
in both cases. `bea check` passes.

Control: without the mark, or with the price on line 2 of the marked file,
or with `12-inch` instead of `12"`, the value is 70,000 USD and SHADOWED is 1.

Expected: 70,000 USD and SHADOWED 1 in both cases.

Cause: `collect_ledger_price_pairs` (`cli/src/bea_engine/managed_load.py:146-166`).
The file is decoded at `:344` without stripping the mark, so the
line-anchored match misses line 1. `_STRING_OR_COMMENT_RE`, added for
w5/378, opens a string at a `"` on a line Beancount ignores entirely (a line
starting `*`, `:`, `#` or a flag character), so the price below it is masked
as string content.

Fix: strip a leading byte-order mark (and normalize as the loader does), and
blank lines the lexer ignores before masking strings. Check whether the
hosted `collectLedgerPricePairs` (`backend-cluster/ledger`) shares the scan;
it was rewritten in the same w5/378 change.

Blast radius: every managed include whose pair the user also prices by hand.

Dedupe: searched `byte-order mark`, `BOM`, `org-mode`, `shadowed`. w5/378
rewrote this collector; w1/163 handled date spellings. Neither covers these
two cases.

Acceptance: both fixtures value Crypto at 70,000 USD with SHADOWED 1. Tests
pin each.

---

**Resolved 2026-10-16** — Shipped in `fe055bff` (`cli`). `collect_ledger_price_pairs` (`cli/src/bea_engine/managed_load.py`) now drops a leading byte-order mark, as the loader does. `_STRING_OR_COMMENT_RE` also reads a line Beancount's lexer ignores (one starting `*`, `:`, `#` or a flag character `!&?%`, per `lexer.l`) whole, before a `"` on it can open a string. The BOM-prefixed `prices.bean` and the `* Prices for the 12" binder` heading both shadow the feed's same-day point (`shadowed_count` 1, `getprice` 70000). `tests/test_managed_price_authored_scan.py` pins the scan for the BOM, org heading, `#` and flag lines, plus both end-to-end layouts; all six fail without the fix. A price inside a multi-line string is still not one (w5/378). The hosted `collectLedgerPricePairs` (`backend-cluster/ledger`) uses the same masking regex; that is filed separately so this change stays in one package.
