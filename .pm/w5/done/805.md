# Three posting-grammar slips: `3 HOOL {{240}}` (a currency-less total cost Beancount accepts) is refused as "a value that is not one token", an empty lot label `{100 USD, ""}` is dropped so the lot merges with an unlabeled one, and bulk shorthand refusals misdescribe valid input

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `0f2118d8e`, checkout `bea 0.3.1`, macOS 26.5.1.
No product fix implemented.

1. **`{{240}}`.** `add transaction Buy --date 2026-02-01 -p 'Assets:Brokerage 3
   HOOL {{240}}' -p 'Assets:Cash -240 USD'` exits 2: `Directive 1 of 1 would be
   written as 0 directive(s); a field holds a line break or a value that is
   not one token (Beancount: syntax error, unexpected RCURL…)`. The
   hand-written equivalent passes `check` and books `3 HOOL {80 USD}` (hunter's
   run). Cause: `_cost_spec_text` (`cli/src/bea_engine/ledger/writer.py:179`)
   renders `{0 # 240}`, which needs a currency.
2. **Empty label.** On a ledger already holding `1 HOOL {100 USD}`, `--json add
   transaction … -p 'Assets:Brokerage 1 HOOL {100 USD, ""}' …` writes `1 HOOL
   {100 USD}` while the answer says `label: ''`. The two lots merge into
   `2 HOOL {100 USD}`; the hand-written `""` would keep two lots (hunter's
   run). Cause: `if cost.label:` (`writer.py:205`).
3. **Bulk shorthand wording.**
   - `"amount": "10"` gets `Could not parse amount '10' as a posting fragment:
     no amount found`; the amount lacks a currency, which bulk does not infer.
   - `"2 HOOL {100 # 5 USD}"` and `"{# 5 USD}"` are told they use a total cost
     `{{...}}` and to split the lot. The structured `cost {"number": "100",
     "number_total": "5"}` writes them fine (hunter's runs).

Fix:
1. Render `{{240}}` or refuse with "a total cost needs a currency".
2. Test the label with `is not None`.
3. Say "no currency" for (3a), and point to the structured compound cost for
   (3b).

Dedupe: w5/384 (done) is the bulk twin of 1; w5/733 and 722 (open) cover
other label and shorthand messages.
