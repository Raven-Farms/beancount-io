# `bea example -o ''` skips bea's own output checks and exits 1 with upstream's `Could not open file ''`: `forwarded_option` turns an empty value into "no option"

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
`forwarded_option` ends with `return value or None`. `example`'s
`_split_output` therefore sees no `-o`, skips the conflict, claim and
destination checks (w5/136, w5/277, 353), and forwards `-o ''` to
upstream. Other users of `forwarded_option` with output guards, such as
`ingest extract -o`, share the blind spot. No product fix implemented.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME and closed stdin.

```sh
bea example --seed 1 -o ''
```

Actual: exit 1 with `Error: bean-example failed (exit 1): Error: Could not
open file '': No such file or directory`. Reproduced three times by the
hunter and once by me.

Control: `treeify -o ''` exits 2 through its own check.

Expected: exit 2 naming `-o`/`--output`, like the other output
refusals.

Cause: `forwarded_option` (`cli/src/cli/output.py:588`, `return value or
None`), used by `_split_output` (`cli/src/cli/commands/example.py:42-43`).

Fix: return `value` unchanged so callers can tell `''` from absent, and
refuse an empty destination in the callers (`example`, `ingest extract`,
guarded forwards). Alternatively, refuse `''` inside the helper. No
dependency change.

Blast radius: `example -o ''`, and any forwarded command whose output
guard relies on `forwarded_option`.

Dedupe: 353 covers `example -o DIR`. w5/089 and w5/136 cover other `-o`
destinations. None covers an empty `-o`.

Acceptance: `example -o ''` (and `ingest extract -o ''`, if it is
affected) exits 2 naming the option, and nothing is forwarded. A test
pins it.

**Resolved (inside the helper).** `forwarded_option` (`cli/src/cli/output.py`) now returns the value unchanged. An empty or blank value raises `UsageError` (exit 2), for example `--output '' is empty; name a path, or omit --output.`. Every caller is covered:

- `example -o`;
- `ingest extract -o` and `-e`;
- `guard_forwarded_output`, for the guarded forwards.

Nothing is forwarded.

`tests/test_forwarded_empty_output.py` covers `example -o ''`, `example --output=`, `ingest extract -o ''` and `ingest extract -e ''`. Each exits 2 naming the option, without `Could not open file`, and no file is created. With the fix stashed, all four fail.
