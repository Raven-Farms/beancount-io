# `bea upgrade --check` exits 0 with `Latest release: unknown` (JSON `"latest": null`) when the index cannot be reached, so a failed check looks like a successful one

**Trivial · cli · 15m · A2.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13. Simulation: the index is pointed at a closed local port or an unroutable address.
`upgrade --check` is the explicit path that bypasses the daily cache. When
its fetch fails (offline, DNS, rate limit, malformed payload), the error is
swallowed the same way as for the silent courtesy notice. The command
prints `Latest release: unknown` and exits 0, and `--json` gives
`"latest": null` with exit 0. Someone asking "is there an update?" cannot
tell a failed check from a successful one, and nothing says why. The
failure is also written into the daily cache. No product fix implemented.

Use isolated BEA_CONFIG_DIR and XDG dirs, closed stdin, and
`BEA_UPDATE_API_URL=http://127.0.0.1:9` (closed port) or
`http://10.255.255.1` (unroutable).

```sh
bea upgrade --check
bea --json upgrade --check
```

Actual:

- Text: exit 0 with `bea 0.3.1 (installed by: checkout)`, `Latest release:
  unknown`, and `Would run: …`. The unroutable address takes 3.1 s.
- JSON: exit 0 with `{"data": {"channel": "checkout", "current": "0.3.1",
  "latest": null, …}}`.
- `update-check.json` is written with `"version": ""`.

Reproduced in a fresh run.

Control: with a reachable index, the command prints the real latest
version.

Expected: `docs/USAGE.md` says "Exit 0 is a promise: the documented effect
happened … A command that did nothing … exits nonzero and says what is
missing." `--check` is documented to "Report the installed and latest
versions". When the latest version could not be fetched, the command should
say so (for example, `Could not reach <index host> to check for a newer
release: <reason>`). It should exit 1 while still showing the installed
version and the advice, or at minimum include an explicit error field in
the JSON. The courtesy notice stays silent, as documented.

Cause: `upgrade --check` (`cli/src/cli/commands/upgrade.py:105-122`) calls
`update.latest_version(use_cache=False)`. That function's blanket
`except Exception` (`cli/src/cli/update.py:175-178`) exists for the silent
notice: it turns every failure into `""`/`None` and caches it.

Fix: have `--check` call `_fetch_latest` directly and let the failure
through, mapped to a one-line error that names the index host. Write the
cache only on success, or keep failure caching for the passive path only.
No dependency or API change.

Blast radius: `bea upgrade --check` on every channel, in text and JSON. The
passive notice and `bea --version` are unaffected.

Dedupe: searched `.pm/**` (including `done/`) for `upgrade --check`,
"Latest release", "unknown" and "offline". w5/008 left `--check`
"deliberately untouched". w2/m25 t004 and t006 shipped the command. None
covers a failed fetch.

Acceptance: with the index unreachable, `bea upgrade --check` names the
failure and the host and does not exit 0 (or the JSON carries an explicit
error field, per the owner's choice). With a reachable index, behaviour is
unchanged. A test with a refusing fake index covers text and JSON. Only
macOS and the checkout were exercised.

---

**Resolved 2026-10-15** — `bea upgrade --check` (`cli/src/cli/commands/upgrade.py`) now calls a new `update.check_latest(channel)` (`cli/src/cli/update.py`). It fetches fresh and raises "Could not check <host> for a newer release: <reason>." when the fetch fails, caching only a successful answer. The command exits 1 with that message and lists `bea <current> (installed by: …)` and `Would run: …` as details, in text and JSON. The passive notice and `--version` keep `latest_version`'s silent, cached path. With `BEA_UPDATE_API_URL=http://127.0.0.1:9`, both forms exit 1 naming `127.0.0.1:9` and `Connection refused`, and no cache file is written. USAGE's upgrade section says so. `tests/test_upgrade.py` turns the old `test_an_unreachable_index_still_reports_the_command` (which pinned exit 0 and "unknown") into the new contract and adds a JSON case against an HTTP-500 index; both fail with the fix reverted. Only macOS was exercised. `make check-all` passed. Shipped in `87c5e911` (`cli`).
