# Plain `bea check` or `bea doctor` leaves a load cache that later commands trust: a BQL literal stops matching, and a valid BOM ledger starts failing

**Major · cli · 45–60m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Fix together with [111](./111.md).
On a ledger big enough to use the load cache, the commands `bea` forwards
to stock Beancount (`check` in text mode, `doctor`) write a cache of the
raw text. `bea`'s own engine then reads that cache as if it had written it,
without the normalisation it applies on a fresh load. Two consequences,
both lasting until a ledger file changes: a query for `'Café Luna'` returns
no rows with exit 0 after a routine `bea check`; and a valid ledger saved
with a BOM fails `bea check` after `bea doctor`. No product fix
implemented.

Generator `/absolute/mk.py` (arguments: directory, transaction count,
optional third argument to prefix a BOM; the payee is `Cafe` + U+0301, the
decomposed spelling):

```python
import sys, pathlib
d = pathlib.Path(sys.argv[1]); n = int(sys.argv[2]); bom = len(sys.argv) > 3; d.mkdir(parents=True)
with open(d/"main.bean","w",encoding="utf-8") as f:
    f.write(('﻿' if bom else '')+'option "operating_currency" "USD"\n2000-01-01 open Assets:Bank USD\n2000-01-01 open Expenses:Food USD\n\n')
    for i in range(n):
        f.write(f'2020-01-{1+i%28:02d} * "t{i}"\n  Expenses:Food  1.00 USD\n  Assets:Bank\n\n')
    f.write('2021-03-01 * "Café Luna" "lunch"\n  Expenses:Food  12.50 USD\n  Assets:Bank\n')
```

```sh
python3 mk.py /absolute/big 60000
python3 mk.py /absolute/small 200
python3 mk.py /absolute/ctl 60000
python3 mk.py /absolute/bom 60000 bom
python3 mk.py /absolute/bomctl 60000 bom
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute`. The
query literal is the composed spelling `Café Luna` (U+00E9).

```sh
bea -f /absolute/big/main.bean check
bea -f /absolute/big/main.bean query "SELECT sum(position) AS spent WHERE payee ~ 'Café Luna' AND account ~ 'Food'"

bea doctor missing-open /absolute/bom/main.bean
bea -f /absolute/bom/main.bean check
```

Actual: `check` on `big` exits 0 and `.main.bean.picklecache` appears; the
query then exits 0 with `(no rows)`. On `bom`, `doctor` exits 0 and writes
the cache; `bea check` (and `--json check`) then exit 1:

```text
Error: /absolute/bom/main.bean: 1 error(s).
  /absolute/bom/main.bean:1: Invalid token: '﻿option'
```

Control: on `small` (too quick to be cached) `check` then the query prints
`12.50 USD`. On `ctl`, running the query first (the engine writes the
cache), then `check`, then the query again prints `12.50 USD` both times.
`bea --json check` on `bomctl`, with no cache present, reports
`"valid": true`. A worker also saw, with a stock-written cache on the BOM
ledger, `bea add balance` refused where it succeeds without the cache; and
a plugin error reported against the wrong `plugin` line after plain `bea
check` (the w1/done/101 symptom returning under a cache).

Expected: `docs/USAGE.md`: "A ledger saved with a UTF-8 BOM loads like any
other" and "Account names, search terms, and BQL literals compare
NFC-normalized". Neither may depend on which command last touched the
cache.

Cause: `cli/src/cli/commands/check.py:64` runs stock `bean-check` with no
shim (non-NFC strings deliberately go this way, `:114-154`), and `doctor`
does the same; both write `.main.bean.picklecache` with raw text.
`cli/src/bea_engine/managed_load.py:459-481` (`_load_fresh`) serves any
cache whose include set matches the files on disk and never checks that
the engine's own loader, which strips BOMs, normalises to NFC and records
plugin configs, produced it. `cli/src/bea_engine/query.py:933-936`
normalises the query on the assumption that ledger text is already NFC.

Fix: engine reads must not serve a cache the engine's default load did not
write: mark engine-written caches and reload anything unmarked, or run the
forwarded stock tools with the cache disabled so they never write the
shared file. The second option also covers [111](./111.md); a narrower fix
for 111 alone would not cover this. No dependency or API change.

Blast radius: every engine read after a forwarded command on a ledger that
takes a second or more to load: `query`, `list`, `balance`, reports,
`--json check`, and the pre-write reads of `add`. An editor running stock
`bean-check` on save has the same effect. Import duplicate detection
normalises both sides and a worker saw it unaffected.

Dedupe: board search for `picklecache`, "load cache", and NFC/NFD or BOM
with cache finds w5/111 (`check --auto` plugin state in the cache), w5/135
(`doctor` itself misreading BOM/NFD ledgers), w5/116 (document existence
frozen), w5/218 (read overlapping a commit) and w1/done/101 (plugin line,
no cache). None covers a natively written cache served to the engine.

Acceptance: on `big`, `bea check` followed by the query prints `12.50
USD`; on `bom`, `bea doctor missing-open` followed by `bea check` exits 0;
engine commands still reuse each other's cache on a large valid ledger.
Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — The engine's cached load (`_load_fresh` in `cli/src/bea_engine/managed_load.py`) now ends every load cache it writes with a short trailing mark and drops, then reloads over, any cache that lacks it, so a cache left by `bean-check`, `bean-doctor` or an editor's Beancount is never served to `query`, `list`, `balance`, reports, `--json check` or the pre-write reads; upstream tools stop reading at the pickle's own end and still reuse the engine's cache. By the time this was fixed the note's two exact sequences already passed, because `bea check` loads through the helper first and `bea doctor` routes a BOM ledger to the helper, but the cause was live: `bea doctor missing-open` on the non-BOM fixture followed by the composed-literal query still printed `(no rows)` with exit 0. The regression test uses a ledger made slow enough to be cached by a sleeping local plugin and covers the query after `bea doctor`, `--json check` and plain `check` on a BOM ledger after a stock `bean-check` wrote the cache, and engine reads reusing an untouched cache across `check` and `doctor`; the first two cases fail with the fix reverted. `docs/USAGE.md` states the rule. Caches written by earlier versions carry no mark and are rebuilt once on the next read. Only macOS was exercised. `make check-all` passed. Shipped in `2ff77650` (`cli`).
