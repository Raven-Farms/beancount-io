# A remembered CSV rules path replaced by a FIFO hangs import before even an explicit replacement can be used

**Minor · cli · 20–30m · A1/A2.** Real CLI QA, 2026-10-20, checkout
`bea 0.3.1`, HEAD `bc5b5d9d4`, Darwin 25.5.0 arm64, frontend Python 3.13.3.
Reproduced twice from pristine ledgers in human, JSON and explicit-override
variants: six bounded hangs. No product fix made.

Create `/abs/case/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
2024-01-01 open Expenses:Uncategorized USD
```

`bank.csv` is `Date,Description,Amount` with row
`2024-02-01,Grocer,-10`. `rules.toml` and `alternate.toml` both contain:

```toml
[[rule]]
match = "Grocer"
account = "Expenses:Food"
```

Use cwd `/abs/case`, isolated absolute `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`,
`BEA_NO_UPDATE_NOTIFIER=1`, no inherited `BEA_FILE`/`BEA_TOKEN`, closed stdin
and no TTY. First save a valid mapping with a successful preview:

```sh
bea --json --no-input --file /abs/case/main.bean import /abs/case/bank.csv --csv auto --account Assets:Cash --rules /abs/case/rules.toml
bea --json --no-input --file /abs/case/main.bean import /abs/case/bank.csv
```

Both exit **0** promptly and apply the rule. Replace only `rules.toml`
with a named pipe, with no writer attached. Bound the affected command:

```python
import os, subprocess
from pathlib import Path
case = Path('/abs/case')
rules = case / 'rules.toml'
rules.unlink()
os.mkfifo(rules)
env = os.environ.copy()
for key in ('BEA_FILE', 'BEA_TOKEN'):
    env.pop(key, None)
env.update(BEA_CONFIG_DIR=str(case / 'config'),
           XDG_CACHE_HOME=str(case / 'cache'), BEA_NO_UPDATE_NOTIFIER='1')
p = subprocess.Popen(
    ['/abs/checkout/cli/.venv/bin/bea', '--json', '--no-input',
     '--file', str(case / 'main.bean'), 'import', str(case / 'bank.csv')],
    cwd=case, env=env, stdin=subprocess.DEVNULL,
    stdout=subprocess.PIPE, stderr=subprocess.PIPE, text=True,
    start_new_session=True)
try:
    try:
        print(p.communicate(timeout=3), p.returncode)
    except subprocess.TimeoutExpired:
        p.terminate()
        print('timed out', p.communicate(timeout=2), p.returncode)
finally:
    rules.unlink()
```

Actual: timeout after about **3.0–3.1 seconds**, stdout/stderr empty. Only
the frontend exists; no engine child or intended prompt is involved.
SIGTERM ends it with subprocess status **−15**, a harness cleanup status.
The ledger and remembered-settings hashes are unchanged. The same happens
without `--json`, and with `--rules /abs/case/alternate.toml` appended:
the stale path is opened before the explicit usable replacement is selected.

Controls repeated twice: explicitly pass the FIFO as `--rules` along with
`--csv auto --account Assets:Cash`; it promptly exits **2** naming a pipe.
Remove the remembered file, or replace it with a directory instead: the
flag-free import exits **0** with the existing `importing without rules`
warning. Restore a regular file and re-save the mapping: preview works
again. Fresh `bea --json --file ... check` exits 0. All six timed-out
processes were reaped, all FIFOs removed and the regular rules restored;
no imports were applied.

Expected: a remembered non-regular rules path must not be opened. Follow
`cli/docs/IMPORTING.md:387–389`: warn that the remembered rules cannot be
used, then preview without them, saving that repair only after success.
A valid explicit replacement must still be used. Preserve the prompt
usage refusal for an explicit FIFO and the supported transient descriptor
input behavior; this does not request FIFO-rule support.

Cause: `cli/src/cli/commands/import_.py:1066` calls `_recall_csv`, whose
rules validation at :624–643 excludes descriptor paths but otherwise calls
frontend `load_rules` directly. `cli/src/cli/csv_mapper.py:333` opens with
`Path.read_text` before checking the file type, so an unfed FIFO blocks
before either exception handler can warn. The existing explicit-input
guard at `import_.py:859–884` checks only this command's supplied paths,
not the recalled one. Frontend `load_rules` has this one product caller;
the engine has a separate rules loader for the final chosen path.

Fix: safely reject non-regular recalled rules before opening, feeding the
existing warn-and-drop path and retaining an explicit replacement. Keep
missing/directory/regular controls, mapping repair timing and descriptor
handling. No dependency or API-adapter change is needed.

Dedupe: searched all board states and active milestone scopes for remembered
rules, named pipes and import hangs. Completed w5/582 (`95e5d653`) checks
explicit rules/config; completed w5/792 (`deb0d289c`) avoids remembering
descriptors and drops old descriptor records. This ordinary filesystem
path passes both safeguards. Open w5/885 is ingest's independent AST
preflight, not CSV memory validation. No overlapping repair or later fix.

Acceptance: bounded real-command tests cover human/JSON recall and the
explicit alternate, all returning promptly with the appropriate warning
or replacement rule; ledger/memory effects match preview policy. Preserve
explicit-FIFO refusal and the working controls. Evidence:
`.tmp/qa-2026-10-20-cli-loop-pass4-515fe144/repro_remembered_rules_fifo.py`,
`remembered-rules-fifo-results.json`, `remembered-rules-fifo-{1,2}/` and
`captures/remembered-rules-*.json`. Symlink-to-FIFO, native Windows and
repaired behavior remain unverified.

---

**Resolved 2026-10-22** — recalling remembered CSV settings now judges a remembered rules path before reading it: one that has become a pipe (or other non-regular file) takes the existing warn-and-drop path with "is a pipe, not a file", so the import proceeds without rules and an explicit `--rules` replacement is used; directories, missing files, descriptors and the explicit-pipe refusal are unchanged. `cli/tests/test_import_remembered_rules_fifo.py` runs the real commands under a timeout and fails (hangs) without the fix; shipped in the commit that moves this note (`cli`).
