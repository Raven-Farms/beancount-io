# Under an 8-bit locale the `bea import` preview is not UTF-8: `é` is one byte, and `→` or `東京` print as literal `→` / `東京` in the row table and the diff (gap in w5/405)

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `5d08dc41`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE says ledger text on stdout is UTF-8 whatever the locale, and only
messages are escaped. The import preview's diff is ledger text, and it is
what `--apply` is approved on. w5/405 fixed `list`, `balance` and `report`;
the import preview prints in the locale's codec. No product fix
implemented.

Ledger with `Assets:Checking` and `Expenses:Café` open; `bank.csv`:

```csv
Date,Description,Amount
2026-03-01,Café Zürich,-4.50
2026-03-02,東京,-1.00
```

```sh
LC_ALL=en_US.ISO8859-1 bea --file /abs/main.bean import bank.csv --account Assets:Checking --default-account Expenses:Café > out.txt
```

Actual: exit 0. `out.txt` starts `csv → Assets:Checking: 2 ready…`, the
payee prints as `東京`, `é` is the single byte `E9`, and the table
misaligns. `PYTHONIOENCODING=latin-1` behaves the same.

Control: `bea list open` under the same locale writes UTF-8.

Expected: the preview (summary, table and diff) is UTF-8 on stdout.

Cause: `cli/src/cli/commands/import_.py:1079-1139` prints through
`typer.echo`/`output.table` without `output.utf8_stdout()`, which `list.py:403`
and `report.py:145` call.

Fix: call `output.utf8_stdout()` before the preview.

Dedupe: w5/405 (done) covered list, balance and report.

Acceptance: the preview is UTF-8 under the 8-bit locale. A test pins it.

---

**Resolved 2026-10-17** — Shipped in `6d0e09c4` (`cli`). The text import preview (`cli/src/cli/commands/import_.py`) now calls `output.utf8_stdout()` before its first line, as `list`, `balance` and `report` do since w5/405. That covers the summary, the row table and the diff `--apply` is approved on. Under `PYTHONIOENCODING=latin-1` (or an 8-bit locale), `Café Zürich` and `東京` print as UTF-8, not one-byte `é` and `東京`. Messages on stderr keep their locale handling. `tests/test_import_preview_utf8.py` decodes the preview as UTF-8 and checks both payees, and it fails without the fix.
