# `bea ingest extract -o out.bean` on a module that binds `CONFIG` by import (`from myimps import CONFIG`) or inside `try:` exits 0 and writes nothing (gap in w5/167)

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `75a67e85`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE: a `CONFIG = [...]` import module given to `ingest` "is refused with exit
2 and pointed at `bea import --config`". The check looks only at module-level
assignments. A module that imports `CONFIG`, or assigns it inside
`try`/`if`/`with`, is run as an ingest script. Such a module never calls
Beangulp, so it does nothing and exits 0. USAGE: "Exit 0 is a promise: the
documented effect happened". No product fix implemented.

`myimps.py`: `from base import *` and `CONFIG = [Base([txn(...)])]`.
`importers.py`: `from myimps import CONFIG`. A download directory `dl/` with
`bank.txt`.

```sh
bea --file /abs/main.bean ingest extract --config importers.py dl -o out.bean
bea --file /abs/main.bean ingest identify --config s2.py dl     # s2.py: try: …CONFIG = [Base()] except ImportError: CONFIG = []
```

Actual: exit 0, empty stdout and stderr, and no `out.bean`. `bea import
bank.txt --config importers.py` reads the same module fine (`1 ready`).

Control: a module with a top-level `CONFIG = [...]` is refused with exit 2 as
documented.

Expected: both are refused with exit 2 and pointed at `bea import --config`.
Alternatively: refuse any `--config` script that never calls Beangulp (no
`Ingest(` call, no `__main__` guard) yet binds `CONFIG` anywhere.

Cause: `cli/src/cli/commands/ingest.py:186` and `_binds_config` (`:194`)
consider only module-level `ast.Assign`/`AnnAssign`, not `ImportFrom` or
nested bindings.

Fix: include `from … import CONFIG` (and `import … as CONFIG`) and bindings
nested in compound statements.

Dedupe: w5/167 (done) fixed the annotated `CONFIG:` shape only.

Acceptance: both commands exit 2 with the pointer to `bea import --config`. A
test pins them.

Addendum (CLI QA 2026-10-17, HEAD `d75811df`): a third way past the refusal,
with a different cause. A plain `CONFIG = [Imp()]` module whose only mention
of `Ingest(` is in a comment (`# beangulp.Ingest(CONFIG)()`) or a docstring
skips the exit-2 refusal. `bea ingest extract --config commented.py dl -o
out.bean` exits 0 silently and creates no `out.bean`. Without the comment, the
same file exits 2 with the documented pointer. Cause:
`cli/src/cli/commands/ingest.py:180` runs `re.search(r"Ingest\s*\(", text)` on
the raw source, comments included, and returns before the AST check, although
the docstring says "the shape is read from the syntax tree, not the spelling".
Fix: look for an `Ingest(...)` call node in the parsed AST instead.

---

**Resolved 2026-10-17** — Shipped in `e812b5a01` (`cli`). `_refuse_config_only_script` in `cli/src/cli/commands/ingest.py` now reads only the syntax tree. A real `Ingest(...)` or `x.Ingest(...)` call, or a `__main__` guard, lets the script run. `CONFIG` bound by `from … import CONFIG` or `import … as CONFIG`, or assigned inside `try`/`if`/`with` (not inside a def or class), is refused with exit 2 and the pointer to `bea import --config`. An `Ingest(` that appears only in a comment or docstring no longer skips the refusal, which also covers the addendum. USAGE updated. Test: `cli/tests/test_ingest_config_bound_any_way.py`.
