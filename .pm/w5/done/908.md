# Show a known zero value for a holding instead of an empty account balance

**Trivial · cli · 30–45m · A1.** Real CLI QA, 2026-10-21, checkout
`bea 0.3.1`, HEAD `e09a113e7` (CLI unchanged through `a6af6844a`), Darwin
25.5.0 arm64, frontend Python 3.13.3. A nonempty position whose conversion
is exactly zero displays `—` / `{}`, like an account with no holding.
The reported total remains correct; this finding concerns zero-versus-empty
display fidelity. No product fix implemented.

Synthetic `/abs/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Stock HOOL
2024-01-01 open Assets:Cash USD
2024-02-01 * "Holding"
  Assets:Stock 2 HOOL {100 USD}
  Assets:Cash -200 USD
2024-02-02 price HOOL 0 USD
```

From `/abs/books`, closed stdin/no TTY, isolated absolute `BEA_CONFIG_DIR`
and `XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, with inherited `BEA_FILE`
and `BEA_TOKEN` removed:

```sh
bea --json -f /abs/books/main.bean check
bea --json -f /abs/books/main.bean query "SELECT units(position), cost(position), value(position) WHERE account = 'Assets:Stock'"
bea --json -f /abs/books/main.bean balance Assets:Stock -t 2024-02 -x USD
bea --json -f /abs/books/main.bean report balance-sheet --account Assets:Stock -t 2024-02 -x USD
bea -f /abs/books/main.bean report balance-sheet --account Assets:Stock -t 2024-02 -x USD
```

Every command exits 0, stderr empty, ledger bytes unchanged. Check passes.
BQL returns Amount values **2 HOOL**, **200 USD**, **0 USD**. Both balance
and balance-sheet JSON report `valuation: "complete"`, but the Stock node
has `has_txns: true`, `balance: {}` and `balance_children: {}`; its Assets
ancestor's subtree balance is also `{}`. The balance sheet's `net_worth`
is correctly `{"USD":"0"}`. Human output shows:

```text
  Assets                                          —
    Stock                                         —
  Current-period earnings (credit):               0 USD
...
Net Worth: 0 USD
```

Expected: a known **0 USD** position value stays visible as `0 USD` /
`{"USD":"0"}`, while a genuinely empty account still shows `—` / `{}`.
The existing tree helper and report documentation distinguish a real
converted zero from no balance; native BQL already retains this position's
zero amount and its currency.

The same gap affects explicit zero-cost grants: replace the cost by
`{0 USD}`, the cash leg by `0 USD`, and the quote by `10 USD`. The ledger
holds two shares, BQL cost is **0 USD** and market value is **20 USD**, but
`-x at_cost` shows the empty maps/dashes. This is a stated zero cost, not an
unknown cost basis.

Both cases reproduced twice through `balance`, filtered balance sheet and
trial balance. Zero market prices fail the display in `USD` and `at_value`;
zero acquisition cost fails it in `at_cost`. Filtered overview also returns
`totals.assets: {}`; unfiltered balance sheet/trial balance still have the
same empty Stock leaf, so pruning is not the cause. Every read reports
complete valuation and preserves bytes.

Fresh controls, each twice across the four conversion modes and three tree
views (120 reads total, plus 12 overview/unfiltered confirmations):

- `units` retains **2 HOOL** in both affected fixtures.
- A 100 USD cost with a 10 USD quote shows **200 USD** at cost and **20 USD**
  at value/currency conversion. The zero-cost grant also correctly shows
  **20 USD** at market value; the zero-priced holding keeps **200 USD** cost.
- An opened Stock account with no transaction keeps the empty maps.
- A Stock parent with one +100 USD-cost child and one −100 USD-cost child
  retains the existing explicit **0 USD** rollup under conversion.

Cause: `_converted` in `cli/src/fava/core/tree.py:32–56` tries to recover
zero currencies by converting each source position independently. For a
zero-valued position, `CounterInventory.reduce`
(`core/inventory.py:115–131`) receives an Amount with number 0 and currency
USD, then `SimpleCounterInventory.add` (:50–56) discards that key. Each
one-position conversion is therefore empty too, leaving `_converted` no
currency to restore. A cancellation between nonzero children still works
because their individual conversions name USD.

Fix: retain the reducer's known output currency for a nonempty position
that converts to zero when constructing display-tree balances. Reuse the
existing conversion result; do not guess a currency from operating options,
replace a missing price with zero, or change inventory cancellation rules.
Keep genuinely empty accounts empty and retain the existing parent-rollup
zero behavior. `TreeNode.serialise` calls this helper for own/subtree balances
at :129–132; `bea balance` and all four reports consume those trees. No
dependency, backend or API change is needed.

Dedupe: whole-board zero-cost/zero-priced holding and `_converted` searches,
plus current milestone review, found no open coverage. Completed w3/357
(`98865a81b`) added conversion-zero recovery, and w1/072 (`a7327443c`)
retained zeros when nonzero children cancel; those controls still work.
Completed [506](./done/506.md) concerns derived equity/headline zeros, which
already display correctly here. Open [905](./905.md) concerns missing-price
route explanations; these quotes are present and valuation is complete.

Acceptance: both affected tree fixtures display typed zero USD in their
correct conversions, filtered and unfiltered, while all controls and totals
remain unchanged. Pin real CLI regression coverage. Sanitized evidence is
under ignored `.tmp/qa-2026-10-20-cli-loop-pass8-80df309f/`:
`repro_zero_value_holding_tree.py`, `zero-value-holding-results.json`,
`zero-value-holding-extra-results.json` and `captures/zero-tree-*.json`.

**Resolved 2026-10-22** — the display tree now converts each position into an inventory that keeps a known zero (`KeptZeroInventory` via `KeptZeroSource`), so a nonempty position worth exactly zero (a zero quote under `USD` or `at_value`, a stated zero cost under `at_cost`) reads `{"USD": "0"}` instead of `{}`; genuinely empty accounts stay empty, `units` keeps its quantity, and the nonzero conversions and the parent-cancellation zero are unchanged. `cli/tests/test_report_known_zero_holding.py` runs real `balance` and filtered balance-sheet reads for both fixtures and the controls and fails without the fix; shipped in the commit that moves this note (`cli`). The human renderer shares these trees and was not rerun separately.
