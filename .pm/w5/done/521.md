# `cloud logout` deletes the credential on a malformed `BEA_API_URL` without trying to revoke it, and reports a revocation the server received as "Could not reach the server" (exit 1)

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `d16aea3e`, checkout `bea 0.3.1`, macOS 26.5.1. Simulation: local stub API.
USAGE: logout exits 1 "when the server is unreachable or answers with an
error", 4 when the outcome is unknown, and a bad `BEA_API_URL` is a usage
error (exit 2). `cloud_logout` wraps everything after loading the credential
in one broad `except`, then deletes the file. Three cases go wrong. No
product fix implemented.

Stored `credentials.json` (`{"token": "<test>", "expireAt": "2027-01-01T00:00:00+00:00"}`), `BEA_TOKEN` unset.

```sh
BEA_API_URL=htps://api.example.invalid bea --json cloud logout   # typo'd scheme
bea cloud logout    # stub closes the connection after reading the POST
bea cloud logout    # stub answers 200 text/plain "OK"
```

Actual:

1. Exit 1: `Removed the local credential, but server revocation failed:
   BEA_API_URL must be an http(s) URL with a host…`. The credential is
   deleted and no request was attempted, so the live session is left
   unrevoked and can no longer be revoked from this machine.
2. Exit 1: `…server revocation failed: Could not reach the server
   (RemoteProtocolError).` The stub log shows the POST arrived.
3. Exit 1: `…Unexpected server response (HTTP 200)…`, while a bodiless 204
   exits 0 `Logged out.`

Control: `cloud status` with the bad URL exits 2; create and delete give exit
4 for a disconnect after sending and for an unreadable 200 (w5/422).

Expected: (1) exit 2 before anything, with the credential left in place;
(2) and (3) the unknown-outcome exit 4 that create and delete use. Connect
errors, connect timeouts and proxy refusals stay exit 1.

Cause: `cloud_logout` (`cli/src/cli/commands/cloud/app.py:78-99`) catches
`Exception` around building the client and the call, treats only
`httpx.TimeoutException` as unknown, and calls `clear_credentials()`
regardless.

Fix: build the client (and validate settings) before the `try`; classify
failures like the other writes; delete the file only after the request was
attempted.

Dedupe: w1/058 (timeout exit 4) and w5/368 (connect errors) are done; neither
covers these cases.

Acceptance: the three cases exit 2, 4 and 4 respectively; in case 1 the
credential file still exists. Tests pin each.

---

**Resolved 2026-10-17** — Shipped in `315af713` (`cli`). `cloud_logout` (`cli/src/cli/commands/cloud/app.py`) now builds the client, which validates `BEA_API_URL`, before the request, so a malformed URL exits 2 with `credentials.json` kept. Failures are classified like the other writes:
- connect errors, connect timeouts and proxy refusals stay exit 1 (nothing reached the server);
- other timeouts keep their exit-4 "timed out" wording;
- a dropped connection after the POST, an unreadable 2xx and a gateway timeout are the exit-4 unknown outcome.

The local credential is still removed after any attempted revocation. `tests/test_cloud_logout_failure_classes.py` pins the bad URL, a stub that closes after reading the POST, an unreadable `200 text/plain`, a refused connection and a bodiless 204; the first three fail without the fix.
