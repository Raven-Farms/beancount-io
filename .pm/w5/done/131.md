# `bea import x.csv --account … --rules …` silently drops both when an `importers.py` sits beside the ledger, and writes to the importer's account

**Major · cli · 30–45m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
When a Python importer config is picked up by default, `--account`,
`--rules`, `--default-account`, `--date-format` and `--delimiter` are
accepted and ignored. The row is written to whatever account the importer
names, with exit 0 and no message that the options had no effect. No product
fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Assets:Savings USD
2026-01-01 open Expenses:Food
2026-01-01 open Expenses:Groceries
2026-01-01 open Expenses:Uncategorized
2026-01-01 open Equity:Opening
2026-01-02 * "Opening balance"
  Assets:Checking  1000.00 USD
  Equity:Opening
```

`/absolute/books/savings.csv`:

```csv
Date,Payee,Narration,Amount,Currency,Category
2026-08-02,Cafe,Coffee,-5.25,USD,Expenses:Food
```

`/absolute/books/r.toml`:

```toml
[[rule]]
match = "coffee"
account = "Expenses:Groceries"
```

Copy the bundled example `cli/docs/examples/csv_importers.py` to
`/absolute/books/importers.py`.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea --file main.bean import savings.csv --account Assets:Savings --rules r.toml --apply
```

Actual: exit 0. stdout reports `categorized-checking → Assets:Checking: 1
ready` and `Wrote 1 entry`; stderr says only `Using importers from
/absolute/books/importers.py (default beside root ledger)`. The ledger gains:

```beancount
2026-08-02 * "Cafe" "Coffee"
  import-id: "csv:sha256:d584eb23f962432d"
  Assets:Checking    -5.25 USD
  Expenses:Food       5.25 USD
```

Savings is untouched and the rule is not applied.

Control: the same fixture and command without `importers.py` reports
`csv → Assets:Savings` and writes `Assets:Savings -5.25 USD` /
`Expenses:Groceries 5.25 USD` with rule `coffee`. A worker also saw the
options swallowed with a remembered `--config` in another directory, and
`--default-account`, `--date-format` and `--delimiter` ignored the same way;
`--csv auto --config importers.py` is refused with `Pass --csv or --config,
not both.` (exit 2).

Expected: `docs/IMPORTING.md` says "Always specify `--account` when importing
from a new account… `bea import checking.csv --account Assets:Checking
--apply`", and `docs/REFERENCE.md` describes these as options for `--csv`
rows. A run that resolves to a Python importer while any of them was passed
should exit 2 naming the option, as the explicit `--csv` + `--config` pair
already does, or honour them. Writing a savings statement into checking with
exit 0 breaks "Exit 0 is a promise".

Cause: `cli/src/cli/commands/import_.py:459` runs header inference only when
`_config_available(file) is None`; otherwise control reaches the importer
branch, which never reads the CSV option values. Only the explicit
`--csv`/`--config` conflict is checked (`:371-372`).

Fix: when the run resolves to a Python importer and any CSV-only option was
passed, raise a usage error naming the option and pointing at `--csv auto`.
No dependency or API change.

Blast radius: every ledger with `importers.py` beside it or a remembered
`--config`; preview and apply, text and JSON.

Dedupe: board search for `importers.py` with ignored/silently/dropped and
`_config_available` finds w5/done/003 (ambiguity hidden behind the importer
hint), w3/done/317 (`ingest` prints nothing) and w5/073 (options not
remembered between CSV runs); none covers options discarded by importer
selection.

Acceptance: the command exits 2, names `--account` (and each other ignored
option when passed) and leaves the ledger byte-identical; the control without
`importers.py` is unchanged. Real-command regression tests cover the default
config and a remembered `--config`. Only macOS and the checkout were
exercised.

---

**Resolved 2026-10-13** — `bea import` now exits 2 when a run resolves to a Python importer and any of `--account`, `--rules`, `--default-account`, `--date-format` or `--delimiter` was passed. The message names each option passed, the importer file and how it was selected, and points at `--csv auto`; nothing is read or written (`cli/src/cli/commands/import_.py`). `docs/IMPORTING.md` states the refusal. Real-command tests cover the default `importers.py`, a remembered `--config` and an explicit `--config`, in preview and apply, text and JSON (eight cases fail with the fix reverted), plus the unchanged control without an importer. An explicit `--config FILE` with these options is refused too. `make check-all` passed. Only macOS was exercised. Shipped in `b3fa346e` (`cli`).
