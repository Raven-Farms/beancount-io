# The advised `--csv sign=ledger` discards the remembered mapping instead of applying on top of it

**Minor · cli · 30–45m · A2.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, macOS. After a ledger-signed import, the next
file with the same header is read bank-signed and `bea import` advises
passing `--csv sign=ledger`. Doing exactly that ignores the remembered
mapping, re-infers from the header, and fails or silently replaces the saved
settings — so a monthly card export needs its whole mapping retyped every
time. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"

2026-01-01 open Assets:Checking USD
2026-01-01 open Liabilities:Card USD
2026-01-01 open Expenses:Food
2026-01-01 open Expenses:Uncategorized
2026-01-01 open Equity:Opening

2026-01-02 * "Opening balance"
  Assets:Checking  1000.00 USD
  Equity:Opening
```

`/absolute/books/a.csv`:

```csv
Datum,Text,Betrag
2026-01-05,Kaffee,3.00
```

and `/absolute/books/b.csv`:

```csv
Datum,Text,Betrag
2026-02-05,Tee,2.00
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`, and
a fresh configuration directory so no mapping is remembered.

```sh
bea -f /absolute/books/main.bean import a.csv --account Liabilities:Card --csv date=Datum,narration=Text,amount=Betrag,sign=ledger --apply
bea -f /absolute/books/main.bean import b.csv
bea -f /absolute/books/main.bean import b.csv --csv sign=ledger
```

Actual: the first exits 0 and writes one entry. The second exits 0, previews
the row bank-signed, and says `a.csv was imported with sign=ledger, but sign
is never carried to another file: b.csv is read bank-signed. Pass --csv
sign=ledger if it is ledger-signed.` The third exits 2:

```text
Error: Cannot read a column mapping from the header row of b.csv. Its columns are: Datum, Text, Betrag. Name them with --csv date=Date,amount=Amount,narration=Description.
```

Adding `--account Liabilities:Card` changes nothing. Repeated twice. With
English headers that inference can read and a remembered `payee=` mapping
plus `--rules`, the same command does not fail: it demands `--account`,
previews with the re-inferred `narration=` mapping and no rules, prints that
it discarded the remembered settings, and saves the inferred mapping over
them.

Control: the third step with the full mapping — `--csv
date=Datum,narration=Text,amount=Betrag,sign=ledger --account
Liabilities:Card` — previews the row ledger-signed and exits 0.

Expected: the command the tool itself advises should work on the file it was
advised for. `docs/IMPORTING.md` describes `sign=` as the one setting "a
different file always needs passed explicitly", alongside "When only one
account uses those headers, the next import needs no flags" — the sign is
passed per file and everything else is recalled. A `--csv` that carries only
keys (`sign=`, `encoding=`, `delimiter=`) should apply those keys on top of
the remembered mapping for that header and account, and infer from the header
only when nothing is remembered.

Cause: `cli/src/cli/commands/import_.py:409-420` sends a spec with keys but
no columns straight to `_inferred_mapping(explicit=True)`; `_recall_csv`
(`:421-422`) is consulted only when no `--csv` was given at all. The note at
`:455-458` advises the key-only form regardless.

Fix: for a key-only `--csv`, look up the remembered mapping first and merge
the typed keys into it, keeping its account, rules, default account and date
format; fall back to header inference when no entry matches. Do not overwrite
remembered settings with an inferred mapping in that case. No dependency or
API change.

Dedupe: board search for bare `sign=ledger` and key-only `--csv` finds
w1/150 and w3/279 (when the sign is replayed) and w3/311 (the discard note);
none covers the advised key-only command against a remembered mapping.

Acceptance: on the fixture the third command previews `2026-02-05` as a
ledger-signed row to `Liabilities:Card` with exit 0 and leaves the remembered
mapping intact; the English-header variant keeps its `payee=` mapping and
rules; `--csv encoding=cp1252` alone behaves the same way over a remembered
mapping and still infers when none exists. Only macOS and the checkout were
exercised.

---

**Resolved 2026-10-12** — A `--csv` spec that carries only keys (`sign=`, `encoding=`, `delimiter=`) is applied on top of the mapping remembered for that header and account instead of triggering header inference. On the fixture `bea import b.csv --csv sign=ledger` previews `2026-02-05` ledger-signed to `Liabilities:Card` with exit 0, and the stored mapping, account, rules, default account and date format are intact. With nothing remembered it still infers, and still fails on headers inference cannot read. `docs/IMPORTING.md` describes the form. Shipped in `3c366909` (`cli`).

Following w5/073, the typed keys are what the next flag-free run of that file replays: a typed `sign=ledger` records the file it was chosen for (so `--apply` writes what the preview showed), `sign=bank` clears it, and a typed `encoding=` is saved into the mapping. Sign itself is still never stored in the mapping.

Real-command regression tests cover the advised command followed by a flag-free apply, an English-header variant that keeps its `payee=` mapping and rules with no discard note, `sign=bank` overriding the file `sign=ledger` was chosen for, `encoding=cp1252` alone over a remembered mapping, and inference with nothing remembered. Four fail with the fix reverted; the nothing-remembered control passes either way. `make check-all` passed. Only macOS was exercised.
