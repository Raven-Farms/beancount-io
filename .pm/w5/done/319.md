# An importer whose `extract()` returns something other than directives is reported as `row 1 cannot be written as a ledger entry (AttributeError): 'str' object has no attribute '_replace'`

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12, beangulp enabled.
Some importers break the Beangulp contract: `extract()` returns a string,
a dict, a list containing `None`, or `None` itself. Each of these is
reported through a generic handler that shows a Python internal (`_replace`
or `object is not iterable`) and never says the value is not a Beancount
directive. A returned string is iterated one character at a time, so
"row 1" refers to its first character. No product fix implemented.

Use the [318](./318.md) ledger and environment, with `/absolute/books/stmt.txt`
and this inspected `importers.py`:

```python
from beangulp import importer

class Imp(importer.Importer):
    def identify(self, f): return f.endswith("stmt.txt")
    def account(self, f): return "Assets:Bank"
    def extract(self, f, existing): return "abc"   # case A

CONFIG = [Imp()]
```

Also run the variants `return [{"date": "2026-01-05"}]` (case B),
`return [None, <a valid Transaction>]` (case C), and `return None` (case
D).

```sh
bea -f main.bean import stmt.txt --config importers.py
```

Actual: every case exits 1 and leaves the ledger unchanged.

- A: `Error: Importer <run_path>.Imp row 1 cannot be written as a ledger
  entry (AttributeError): 'str' object has no attribute '_replace'. Pass
  --debug before the command for a traceback.`
- B: the same message with `'dict' object`.
- C: the same message with `'NoneType' object`.
- D: `Error: Importer failed (TypeError): 'NoneType' object is not
  iterable. …`

Reproduced in three fresh runs.

Control: an importer that returns `[]` previews `0 ready` and exits 0. A
float metadata value gets the documented `cannot be written as a ledger
entry` message, with the value as the reason.

Expected: `docs/IMPORTING.md` describes `extract()` as returning entries.
A row that is not a directive should be named as such, for example:
`Importer NAME row 2 is a str, not a Beancount directive; extract() must
return a list of directives`. A returned `None` should be reported as
"returned None instead of a list".

Cause: `cli/src/bea_engine/importing.py:209` and `:241` call
`list(importer.extract(...))`. That raises `TypeError` for `None` and
splits a string into characters. `_writable` (`:609-627`) then calls
`entry._replace`, which raises `AttributeError` for any value that is not
a directive.

Fix:

- Before calling `list()`, refuse a returned `None`, `str` or `bytes`, and
  name the importer.
- In `_writable`, check `isinstance(entry, data.ALL_DIRECTIVES)` first.
  If the check fails, raise a `LedgerError` that names the row and the
  type.

Keep the traceback for `--debug`. No dependency change.

Blast radius: `import --config`, in preview and `--apply`. `bea ingest`
passes output through upstream Beangulp and is out of scope.

Dedupe: board searches for `_replace`, "not a directive", "non-directive"
and "not iterable" together with importer found only unrelated notes.
w5/227 covers int metadata and w5/226 covers the `<run_path>` name.
Nothing is open.

Acceptance: cases A–D each exit 1 with a message that names the importer,
the row (or "extract() returned None") and the Python type, and contains
neither `_replace` nor `not iterable`. A test covers each case. Only macOS
and the checkout were exercised.

---

**Resolved 2026-10-15** — `cli/src/bea_engine/importing.py` calls a new `_extracted` on both importer paths. It refuses an `extract()` result that is `None`, a string, bytes or a dict ("Importer NAME extract() returned a str instead of a list of Beancount directives.") before calling `list()`. `_writable` now refuses a row that is not a Beancount directive ("Importer NAME row N is a dict, not a Beancount directive; extract() must return a list of directives.") before `_replace`. Both exit 1 and leave the ledger unchanged. `cli/tests/test_import_extract_not_directives.py` covers cases A–D, checking that neither `_replace` nor `not iterable` appears; all 4 fail with the fix reverted. Only macOS was exercised. `make check-all` passed. Shipped in `0e202213` (`cli`).
