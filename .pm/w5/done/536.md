# USAGE says new directives are written NFC, but only account names are; `add --into` also creates a new file under the NFD spelling typed, and a later NFC `--into` is refused as if the include line were NFD

**Trivial · cli · 15m · A1.** Real CLI QA, 2026-10-16, HEAD `5d08dc41`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE (around line 592) says "new directives are written NFC", and import
writes its text NFC (IMPORTING.md). `add` normalizes accounts only, so
mixed-normalization strings accumulate. The same habit (text pasted from
Finder or a PDF is often NFD) also gives an NFD file name under a glob
include. The next `--into` typed on a keyboard is then refused with wording
about an include line that does not exist. No product fix implemented.

```sh
# NFD text typed (e.g. pasted): "Notiz für Café"
bea --file /abs/main.bean add note --date 2026-02-01 -a Assets:Checking --comment "$NFD_TEXT"
# include "Ausgaben/*.bean", empty Ausgaben/:
bea --file /abs/main.bean add transaction … --into "$NFD/Ausgaben/März.bean"
bea --file /abs/main.bean add transaction … --into 'Ausgaben/März.bean'
```

Actual: the note is written byte-for-byte NFD. The first `--into` creates
the file under its NFD name (exit 0). The second exits 2 with `… Pass --into
'Ausgaben/März.bean' as the include line spells it. The two differ only in
Unicode form; the include line is NFD.` The include line is
`Ausgaben/*.bean`.

Expected: strings in new directives are written NFC, as USAGE says (or USAGE
narrows the claim to account names). A new `--into` file is created under
the NFC spelling. A respelling refusal names the file on disk, not an
include line.

Cause: `_nfc_entry_accounts` (`cli/src/bea_engine/ledger/writer.py:258-288`)
normalizes accounts only; `_respelling`
(`cli/src/bea_engine/ledger/write.py:204-221`) assumes a literal include.

Fix: NFC the directive's strings when rendering; create new `--into` files
with an NFC name; word the glob case around the matched file.

Dedupe: w5/434 (done) built the respelling wording for literal includes.

Acceptance: the note is written NFC; the second `--into` lands in the
existing file (or names it). A test pins both.

---

**Resolved 2026-10-17** — Shipped in `c3a5a33c` (`cli`). In `cli/src/bea_engine/ledger/write.py`, `destination()` creates a new `--into` file under the NFC spelling of its name; directories keep their on-disk spelling, so an existing NFD folder still resolves. The note's NFD-then-NFC pair now lands in one `Ausgaben/März.bean`. `_respelling` tells a file matched by a glob (`*`, `?`, `[`) from one a literal include names: `Pass --into 'Ausgaben/März.bean' as the file is named on disk. … the file's name is NFD.` For strings, the note's alternative was taken: USAGE now says new directives write their account names NFC and text keeps the bytes typed, as w5/130 decided for custom text values. Normalizing strings also broke legacy import ids hashed from pre-NFC narrations. `tests/test_add_nfc_strings_and_into.py` pins the NFC file name with the later write, and the glob wording on a normalization-insensitive file system (skipped elsewhere); both fail without the fix.
