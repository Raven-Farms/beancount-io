# A remembered importer record with invalid UTF-8 still blocks a flag-free CSV import with a pathless codec error (exit 1), and a lock file bea cannot open (mode 000, root-owned after sudo) is blamed on the lock directory (incomplete fixes of w5/592 and w5/593)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `3d73eb246`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-ups to w5/592 and 593 (done).
No product fix implemented.

1. **Record bytes (gap in w5/592).** `$BEA_CONFIG_DIR/importers/<sha256 of the
   ledger path>.json` holds the bytes `{"config": "\xff\xfe"}`. `bea -f
   /abs/main.bean import stmt.csv --account Assets:Bank` exits 1 with `Error:
   'utf-8' codec can't decode byte 0xff in position 12: invalid start byte.`. No
   file is named. IMPORTING (added by w5/592) says a record that is "not valid
   JSON … selects nothing", with a note naming the file. A truncated record
   behaves as documented. Cause: `_config_available`
   (`cli/src/cli/commands/import_.py:113`) catches only `OSError` around
   `read_text()`. A deeply nested `csv-<hash>.json` gives `maximum recursion
   depth exceeded` (hunter's run, contrived).
2. **Lock file permissions (gap in w5/593).** After one `add price` creates
   `$XDG_CACHE_HOME/bea/locks/<key>.lock`, `chmod 000` that file. The next `add
   price` exits 3 with `Cannot take the write lock: the lock directory
   …/bea/locks cannot be created or is not writable (Permission denied). Make
   it a writable directory…`, though the directory is writable. A FIFO or
   directory at that path is now named correctly. Cause:
   `cli/src/bea_engine/ledger/write.py` (around `:1033-1046`) falls through to
   the directory message when the path is a regular file.

Expected: (1) the corrupt-record note naming the file, then the header-row
fallback. (2) A message naming `<key>.lock` and the errno, with "remove it,
then retry".

Fix: read the record as bytes and treat decode (and recursion) failures as
corrupt; when the lock open fails but the path exists, name the file.

Dedupe: w5/592 and 593 (done) are the parents.

Acceptance: both cases name the file involved.

---

**Resolved 2026-10-20** — (1) `_config_available` reads the remembered-importer record as bytes and decodes inside its corrupt-record handling, so `{"config": "\xff\xfe"}` is ignored with "The remembered importer record … is not valid; ignoring it." and the header-row fallback imports the CSV, exit 0. The CSV-memory reader (`_stored_sources`) also treats a `RecursionError` from a deeply nested `csv-<hash>.json` as no memory. (2) When opening the lock fails and the path exists as a regular file, the refusal now reads `Cannot take the write lock: the lock file …/<key>.lock cannot be opened (Permission denied). Remove it, then retry. Nothing was written.` (exit 3) instead of blaming the directory; a directory that cannot be created keeps its message. `tests/test_corrupt_record_bytes_and_unopenable_lock.py` covers the invalid-UTF-8 record, the deeply nested CSV record, and a mode-000 lock file. Gate note: gated as one stack with w5/821 (one `make check-all`, 9738 passed; each item shipped as its own commit); its only failures were the known load-induced managed-price timeouts, which pass in isolation.
