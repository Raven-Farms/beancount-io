# A dangling `main.bean` symlink makes cwd discovery silently fall back to `main.beancount`, while `init` treats the same link as the root ledger

**Minor · cli · 20–30m · A2.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
Setup: the working directory holds a `main.bean` symlink whose target is
missing (for example, a synced folder that is not mounted) and an older
`main.beancount`. Every local command then reads and writes
`main.beancount`, exiting 0 with no warning. `bea init` in the same
directory refuses because `main.bean` "Already exists". So the two paths
disagree about which file is the root ledger, and writes land in the stale
file. No product fix implemented.

Create disposable `/absolute/books/main.beancount`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Equity:Opening
```

and a dangling link: `ln -s ../sync/ledger.bean /absolute/books/main.bean`.
`/absolute/sync/` exists; `ledger.bean` does not.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea check
bea add open --account Assets:Savings --date 2026-02-01 -c USD
bea --no-input init . --currency USD
```

Actual:

- `check` exits 0 silently.
- `add` exits 0 with `Added 1 open to /absolute/books/main.beancount.`, and
  the hash of `main.beancount` changes.
- `init` exits 4 with `Already exists: /absolute/books/main.bean. Choose a
  new path; init never overwrites a ledger.`

With only the dangling link and no `main.beancount`, `check` exits 2 with
`No ledger file at 'main.bean' (from the working directory)`, without
saying the link is broken. Reproduced in a fresh run.

Control: a regular-file `main.bean` next to `main.beancount` is chosen by
every command, and so is a live `main.bean` symlink.

Expected: `docs/USAGE.md` › Choosing the ledger: "`./main.bean` in the
working directory, or `./main.beancount` if `main.bean` is absent". A
dangling `main.bean` is not absent, and `init` already treats it as
present. The same section refuses an include that reaches "a broken
symbolic link" with exit 2. A broken root link should be refused the same
way, not bypassed.

Cause:

- `cli/src/cli/context.py:132-135` picks the default with `name.is_file()`.
  That returns False for a dangling link (and for a directory or FIFO), so
  discovery skips `main.bean` and takes `main.beancount`.
- `cli/src/cli/commands/init.py:124,132` uses `exists() or is_symlink()`,
  so `init` treats the same entry as present.
- The no-ledger error at `context.py:139-160` does not tell a broken link
  apart from a missing file.

Fix: in discovery, treat `main.bean` as present when `os.path.lexists` is
true. A dangling link, or any non-file, then exits 2 naming `main.bean` as
a broken symlink (with its target) instead of falling through to
`main.beancount`. No dependency or API change.

Blast radius: every local command that uses cwd discovery: `check`,
`list`, `query`, `balance`, `report`, `add`, `import --apply` and `price`.
The writes are the harmful case. Commands given `--file` or `BEA_FILE` are
unaffected, and `format` ignores discovery. A `main.bean` that is a
directory also falls through silently, by the same mechanism.

Dedupe: searched the board for "dangling", "broken symlink",
`is_symlink`, `main.beancount` and "discovery". Related but different:

- w1: cwd discovery ignoring `main.beancount` (fixed; that note added the
  fallback itself).
- w5/219: the no-ledger hint one directory down.
- Format's broken-symlink walk notes.

None of them covers a dangling root default that redirects writes to the
fallback.

Acceptance: on the fixture, `bea check` and `bea add open …` exit 2 naming
`main.bean` as a broken symlink, and `main.beancount` keeps its hash. With
the link removed, both use `main.beancount`. A regression test covers the
dangling-link and directory cases. Only macOS and the checkout were
exercised.

---

**Resolved 2026-10-14** — Cwd discovery in `cli/src/cli/context.py` now takes the first default name that is present (`os.path.lexists`), not the first regular file. A dangling `main.bean` exits 2 with "is a broken symbolic link to '<target>'", and a `main.bean` directory exits 2 as a directory; neither falls through to `main.beancount`, which keeps its hash. USAGE's Choosing the ledger section says so. `cli/tests/test_discovery_dangling_main_bean.py` covers `check` and `add` on a dangling link, the directory case and the plain fallback; the 3 refusal cases fail with the fix reverted. Only macOS was exercised. `make check-all` passed. Shipped in `5da265f0` (`cli`).
