# The import preview diff prints existing ledger lines raw, so escape sequences in the ledger's last lines reach the terminal

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
The import preview is the screen `--apply` is gated on, and `bea` escapes
control characters in its table and entries. The unified diff below the
table is the exception: its context lines, the last few lines of the
existing ledger including comments, are printed byte for byte. Cursor
movement sequences there can redraw the summary table above. It needs raw
escape bytes already in the ledger tail (a hand-edited or third-party
file); `bea`'s own writes store the escaped form. No product fix
implemented.

Generate the fixture in `/absolute/books` (`E` is the byte 0x1b):

```python
E = "\x1b"
fake = "1    new     2026-02-01  Coffee shop        -12.34 USD     hash  unmatched"
head = 'option "operating_currency" "USD"\n2026-01-01 open Assets:Cash USD\n2026-01-01 open Expenses:Uncategorized USD\n'
open("main.bean", "w").write(head + f"; statement marker{E}[7A{E}[2K{E}[G{fake}{E}[7B{E}[2K{E}[G ; statement marker\n")
open("ctl.bean", "w").write(head + "; statement marker\n")
open("bank.csv", "w").write("Date,Amount,Description\n2026-02-01,-9912.34,Wire to M. Allory\n2026-02-02,-5.00,Lunch\n")
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN/CI/COLUMNS, `TERM=xterm-256color`, closed
stdin unless a PTY is stated, cwd `/absolute/books`. Run on a real PTY, 100 columns.

```sh
bea -f main.bean import bank.csv --csv auto --account Assets:Cash
```

Actual: exit 0, ledger unchanged, and six raw ESC bytes in the terminal
stream; the diff context line arrives as

```text
 ; statement marker<ESC>[7A<ESC>[2K<ESC>[G1    new     2026-02-01  Coffee shop        -12.34 USD     hash  unmatched<ESC>[7B<ESC>[2K<ESC>[G ; statement marker
```

A worker replayed the stream through a small screen model: row 1 of the
table ends up reading `Coffee shop -12.34 USD` instead of `Wire to M.
Allory -9912.34 USD` (the `+` lines of the proposed entry still show the
true amount). That repaint was modelled, not observed in a terminal
emulator.

Control: the same command with `ctl.bean` emits no ESC bytes. A worker saw
the "Existing entry at …" block and `list transaction --details` escape
the same bytes.

Expected: `docs/USAGE.md` says control characters are shown as `\xNN` so
untrusted text cannot drive the terminal, and "That matters most in the
`import` preview, which is the surface `--apply` is gated on".

Cause: `cli/src/bea_engine/importing.py:436-443` builds the diff over the
original file text and `cli/src/cli/commands/import_.py:736` echoes it
without the inert-text filter used elsewhere.

Fix: print the diff through `output.inert_text` in text mode; JSON keeps
the exact value. No dependency or API change.

Blast radius: `bea import` preview and apply output on a terminal.

Dedupe: board search for `x1b`, "escape sequence", `unified_diff` and
"Existing entry at" finds w3/done/392 (imported CSV text), w5/107 (query
shell error banner), w5/108 (CR in query tables) and w5/148 (bidi
controls); none covers the diff's existing-ledger context.

Acceptance: the fixture's preview emits no ESC byte on a PTY and shows the
sequence as `\x1b[7A…`; the control output is unchanged. Only macOS and the
checkout were exercised.

---

**Resolved 2026-10-13** — The import preview's unified diff is now printed through the inert-text filter in `cli/src/cli/commands/import_.py`, so control characters in the existing ledger's context lines (and in the diff's file header) appear as a visible `\x1b[7A…` instead of reaching the terminal, in both preview and `--apply` output; `--json` keeps the exact diff value, and `cli/docs/USAGE.md` now says the diff is covered. The regression test `cli/tests/test_import_diff_context_is_inert.py` runs the note's fixture through the real command with terminal-style output and asserts no ESC byte and the escaped sequence for preview and `--apply`, the untouched JSON value, and that a plain ledger's text diff equals its JSON diff; the two terminal cases fail with the fix reverted. The note's fixture was also replayed on a real 100-column PTY: six raw ESC bytes before the change, none after, and the control output unchanged. As a side effect of the shared filter, a lone carriage return inside a context line is shown as a line break rather than escaped. Only macOS was exercised. `make check-all` passed. Shipped in `852e4eca` (`cli`).
