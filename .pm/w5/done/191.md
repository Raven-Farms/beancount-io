# `price export` dies with a raw `FileExistsError` after writing part of the snapshot when the ledger includes a file named `prices`

**Minor · cli · 30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
The export writes generated feed files into a `prices/` directory. If
the ledger itself includes a file literally named `prices`, the export
copies that file first and then fails to create the directory of the same
name: exit 1 with a Python `FileExistsError`, leaving a partial export.
Narrow trigger. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Assets:Coin BTC
2024-01-01 open Equity:Opening
2024-01-01 commodity BTC
2024-01-01 commodity USD

2024-01-02 * "Open"
  Assets:Cash  10000.00 USD
  Equity:Opening

2024-01-03 * "Buy"
  Assets:Coin  2 BTC {1000.00 USD}
  Assets:Cash  -2000.00 USD
```

followed by `include "http://127.0.0.1:PORT/prices/BTC-USD"` and `include
"prices"`, and an extensionless file `/absolute/books/prices` containing
`2024-03-01 price BTC 1700.00 USD`.

The feed is a **simulation**: a loopback server on `127.0.0.1` allowed
through `MANAGED_PRICE_ORIGINS`, which proves local handling only, not the
real service's behaviour. Use isolated BEA_CONFIG_DIR and a fresh
XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no inherited BEA_FILE/BEA_TOKEN,
closed stdin, no TTY, cwd `/absolute/books`. The simulated feed returns two BTC prices.

```sh
bea -f main.bean price export
ls main-export
```

Actual: exit 1: `Error: FileExistsError: [Errno 17] File exists:
'/absolute/books/main-export/prices'`. `main-export/` already holds
`main.bean` and `prices`; the feed file is missing.

Control: a worker ran the same ledger with the file named `manual`: exit
0, three files, and the export passes stock `bean-check`.

Expected: `docs/USAGE.md` — "`price export` also plans the directories it
needs: a file standing where the export needs a directory … is refused
the same way", that is before anything is written.

Cause: `cli/src/bea_engine/managed_load.py:811-818` checks only what is
on disk before the first write; the plan itself contains a file and a
directory at the same path, and the crash comes when the directory is
created.

Fix: check the plan against itself (a planned file that is an ancestor
of another planned path) and either rename the generated directory or
refuse before writing. No dependency or API change.

Blast radius: ledgers with an included file named `prices` (or the
shared-feed directory name) beside the root.

Dedupe: w5/056 (done) covers blockers already on disk; w5/117 is a
different raw error after a partial write.

Acceptance: the command refuses with exit 2 and writes nothing, or
succeeds with the feeds in a non-colliding directory; the `manual`
control is unchanged. Only macOS, the checkout and a loopback simulation
were exercised.

---

**Resolved 2026-10-13** — `price export` in `cli/src/bea_engine/managed_load.py` now chooses its feed directory against the files it is about to copy: when the ledger includes a file of its own named `prices`, the generated feeds go in `prices-managed/` (then `prices-managed-2/`, and so on) and the export succeeds with a snapshot that passes stock `bean-check`. The plan is also checked against itself before the first write, so any other planned file standing where another planned path needs a directory (for example an included file named `_shared` beside an include from outside the root's directory) is refused with exit 2 and "Nothing was written" instead of a raw `FileExistsError` after a partial export. `docs/USAGE.md` states both behaviours. The regression test `cli/tests/test_price_export_prices_file.py` runs the real command against a loopback feed for the `prices` case, a `prices` plus `prices-managed` case, the `_shared` refusal and the `manual` control; three of its four cases fail with the fix reverted and the control passes either way. Names that differ from `prices` only by letter case on a case-insensitive filesystem were not examined. Only macOS was exercised. `make check-all` passed. Shipped in `9f1dc8d6` (`cli`).
