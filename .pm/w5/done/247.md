# An included file named with `[…]`, `*` or `?` makes every `bea add` and `import --apply` fail, and `price export` writes a copy that does not load

**Major · cli · 45–60m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A ledger with `include "inc/*.bean"` where one matched file is called
`2024 [old].bean` passes stock `bean-check` and `bea check`, but no
validating write works: `bea` rewrites the matched paths into literal
`include` lines for its staged copy, and Beancount reads the brackets as a
glob character class that matches nothing. `price export` does the same
rewrite, exits 0, and produces a copy that fails to load. No product fix
implemented.

Create the fixture with Python:

```python
import os
d = "/absolute/books"; os.makedirs(d + "/inc")
open(d + "/main.bean", "w").write(
    'option "operating_currency" "USD"\n'
    'include "inc/*.bean"\n'
    '2026-01-01 open Assets:Checking USD\n'
    '2026-01-01 open Expenses:Food USD\n')
open(d + "/inc/2024 [old].bean", "w").write(
    '2026-02-07 * "Extra"\n  Expenses:Food  1.00 USD\n  Assets:Checking\n')
open(d + "/bank.csv", "w").write("Date,Description,Amount\n2026-03-03,Coffee,-4.50\n")
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.
Stock `bean-check main.bean` and `bea -f main.bean check` both exit 0.

```sh
bea -f main.bean add transaction Lunch --date 2026-03-01 -p 'Expenses:Food 7.00 USD' -p Assets:Checking
bea -f main.bean import bank.csv --account Assets:Checking --default-account Expenses:Food --apply
bea -f main.bean price export -o /absolute/exp
```

Actual: the first two exit 1 and write nothing:

```text
Error: The change would leave the ledger invalid; nothing was written.
  <load>:0: File glob "/absolute/books/inc/2024 [old].bean" does not match any files
```

The export exits 0 (`Exported 2 files to /absolute/exp.`), but its root
contains `include "inc/2024 [old].bean"` and stock `bean-check
/absolute/exp/main.bean` exits 1.

Control: the same fixture with `inc/2024 old.bean`: both writes exit 0 and
the export passes stock `bean-check`. A worker saw the same failure for a
bracketed folder matched by `years/*/*.bean`, for `--allow-errors`, for a
correctly escaped literal include, and a `Duplicate filename parsed` error
when a file named `q?.bean` sits beside `q2.bean`; and `bea add --into
"inc/new [2].bean"` succeed and thereby break every later write.

Expected: `docs/USAGE.md` requires only that a destination "match a
literal include or include glob"; a ledger that `bean-check` and `bea
check` accept should accept an append. `bea price --help` describes
`export` as a portable copy, so the copy must load.

Cause: `cli/src/bea_engine/ledger/write.py:188` (`LedgerSnapshot.staged`)
writes each matched path into an `include` string with only string
escaping, and Beancount globs every include string again;
`cli/src/bea_engine/managed_load.py:991-992` (`_rewrite_export_includes`)
does the same for exports.

Fix: pass every literal path injected into an include string through
`glob.escape` before string-escaping, at both sites (it yields `2024
[[]old].bean`, which stock accepts). No dependency or API change.

Blast radius: all `add` types, `add transactions` and `import --apply`
(with and without `--allow-errors`), and `price export`, on any ledger
whose include closure contains a file or folder named with `[`, `*` or
`?`. Reads and `format` are unaffected.

Dedupe: board search for glob, bracket, `glob.escape`, "does not match any
files" and "Duplicate filename parsed" finds w5/079 (the same rewrite
shifting line numbers), w5/144 and w5/202 (NFD names), w5/145 (absent
`--into`) and w5/190 (17th managed include); none involves glob
metacharacters.

Acceptance: on the fixture both writes exit 0 and change only `main.bean`;
the export passes stock `bean-check`; the same holds for a bracketed
folder and for `q?.bean` beside `q2.bean`. Only macOS and the checkout
were exercised.

---

**Resolved 2026-10-13** — Every resolved path that `bea` writes back into an `include` string now goes through one helper, `literal_include` in `cli/src/bea_engine/ledger/write.py`, which applies `glob.escape` before string escaping; it is used by write staging (`staged_include`), by the managed-price loader's staged copies and feed path, and by `_rewrite_export_includes` in `cli/src/bea_engine/managed_load.py`, so Beancount's second glob pass reaches exactly the file that was matched. `tests/test_include_glob_metacharacter_names.py` runs the real commands over a bracketed file, a bracketed folder, an already-escaped literal include, `q?.bean` beside `q2.bean`, `a*.bean` beside `ab.bean` and a plain-name control: `add transaction` and `import --apply` exit 0 and change only `main.bean`, and the `price export` copy passes stock `bean-check` with the same posting count as its source. It also covers a later write after `--into "inc/new [2].bean"` and a managed-price ledger read through a bracketed folder, which failed the same way on reads. With the source change reverted 12 of the 14 cases fail and the two plain-name controls pass. Only macOS was exercised. `make check-all` passed. Shipped in `7454b4bf` (`cli`).
