# An explicit `list --limit 50` still says "pass --limit for more" (gap in w3/325)

**Trivial · cli · 5m · A1.** Real CLI QA, 2026-10-17, HEAD `d6c32f470`, checkout `bea 0.3.1`, macOS 26.5.1. Gap in w3/325 (done).
No product fix implemented.

On a ledger with 80 transactions, `bea -f /abs/main.bean list transaction -l
50` (or `--limit=50`) prints `Showing the first 50; pass --limit for more.` on
stderr. w3/325 meant to stop telling a user who already passed `--limit` to
pass it.

Cause: `cli/src/cli/commands/list.py:456` compares the value with the default
(`limit == 50`) instead of checking whether the option was given.

Fix: decide from Click's parameter source.

Dedupe: w3/325 (done) is the parent; its resolution says "non-default limit".

Acceptance: an explicit `-l 50` says "raise --limit for more".
