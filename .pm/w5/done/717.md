# A CSV decode error past the first 8 KiB names the wrong byte offset (the offset within the 8192-byte chunk)

**Trivial · cli · 5–10m · A1.** Real CLI QA, 2026-10-17, HEAD `8cd20be7`, checkout `bea 0.3.1`, macOS 26.5.1. Found beside the w5/529 checks; it predates that fix.
IMPORTING.md:128 says the decode error "names the byte offset". No product
fix implemented.

`late.csv` has the header `Date,Description,Amount`, 400 ASCII rows
`2026-03-01,RowNNNN,-1.00`, then `2026-03-02,Caf\xe9,-4.50`. The bad byte is
at offset 10038.

```sh
bea --file /abs/main.bean import late.csv --account Assets:Checking
```

Actual: exit 2, `late.csv is not valid UTF-8 (invalid continuation byte at
byte 1846); it decodes as cp1252…`. 1846 = 10038 − 8192. In the hunter's
5000-row file, 2855 was reported instead of 133927.

Expected: `at byte 10038`.

Cause: decoding reads through a text-mode stream, so `UnicodeDecodeError.start`
is relative to the decoded chunk. See `cli/src/bea_engine/csv_mapper.py`
(around `:879` and `:917-918`) and the frontend `detect_delimiter`/
`open_records`.

Fix: compute the offset from the raw bytes, as `probe_decoding` does.

Dedupe: searched `byte offset`, `8192`; no CSV note.

Acceptance: the fixture reports 10038. A test pins it.
