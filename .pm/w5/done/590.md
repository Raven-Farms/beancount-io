# `update-check.json` is written through a symlink, so `bea upgrade --check` (and the daily notice) overwrite a file outside the config directory; a FIFO there hangs the command

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `595daa2f`, checkout `bea 0.3.1`, macOS 26.5.1. Synthetic local release index.
Every other state writer replaces a symlink rather than following it:
credentials use tmp + `os.replace`, importer memory uses `atomic_write`,
managed prices use `mkstemp` + `replace`. The update-check cache truncates
the link's target in place. No product fix implemented.

```sh
printf 'precious\n' > /abs/outside/precious.txt
ln -s ../outside/precious.txt "$BEA_CONFIG_DIR/update-check.json"
BEA_UPDATE_API_URL=http://127.0.0.1:<index> bea --json upgrade --check
cat /abs/outside/precious.txt
```

Actual: exit 0 with the correct answer; `precious.txt` now holds
`{"checked_at": …, "version": "9.9.9"}`, and the link remains, so the next
check overwrites it again. With a FIFO at that path, the command hangs with no
output.

Control: without the link, the cache is written in the config directory.

Expected: the cache is replaced atomically (the link itself replaced, never
followed), and a non-regular file there reads as "not cached".

Cause: `write_cache` (`cli/src/cli/update.py:152`) uses `path.write_text`;
`_can_write` (`:140-144`) uses `exists()`/`is_file()`, which follow links; the
read at `:118` blocks on a FIFO. By code reading, the passive daily notice on
PyPI/Homebrew installs shares `write_cache` (not exercised from a checkout,
which mutes it).

Fix: write via `atomic_write` (or `O_NOFOLLOW` + replace) and check `S_ISREG`
before reading.

Dedupe: searched `update-check` and `symlink`; w5/321, 322 and 375 (done)
concern other update-check behavior.

Acceptance: with the link, `precious.txt` is unchanged and the config
directory holds a regular cache file; with a FIFO, the check answers. Tests
pin both.

---

**Resolved 2026-10-17** — Shipped in `f2c7da0a` (`cli`).
- `write_cache` (`cli/src/cli/update.py`) now writes through `atomic_write`, which replaces a symlink at `update-check.json` instead of following it. The note's repro leaves `precious.txt` unchanged, and the config directory holds a regular cache file.
- `read_cache` opens without blocking (`_read_regular`) and treats anything but a regular file as "not cached". With a FIFO there, `bea --json upgrade --check` answers and replaces it with the cache.
- `_can_write` now asks whether the directory can take the replacement. A writable cache in a read-only config directory still falls back to the cache directory (the w5/321 behavior).
- `tests/test_update_cache_replaced_not_followed.py` pins `upgrade --check` past a link and past a FIFO, a FIFO read as "not cached", the daily notice's `latest_version` past a link, and the read-only directory fallback. All 5 fail without the fix. `make check-all` passed.
