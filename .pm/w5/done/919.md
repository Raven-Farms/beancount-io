# Keep accented bank references stable on repeat import

**Major · cli · 40–55m · A1.** Real CLI QA, 2026-10-21, checkout
`bea 0.3.1`, HEAD `971f6e88e` (CLI unchanged from reproduction through
`ebd9c003b`), macOS 26.5.1 arm64, frontend Python 3.13.3, managed engine
Python 3.12 / Beancount 3.2.3. A decomposed-Unicode native transaction ID
does not match the ledger after reload. An unchanged export becomes a
possible duplicate; reusing that same ID with a changed amount becomes
**new** and writes a second transaction with exit 0 instead of a conflict.
Fresh ledger checks still pass. No product fix implemented.

Create disposable `/abs/case/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
```

Save `/abs/case/make_csv.py` so the ID's normalization is unambiguous:

```python

    writer = csv.writer(stream)
    writer.writerow(["Date", "Description", "Amount", "ID"])
    writer.writerow(["2024-02-01", "Coffee", sys.argv[1], reference])
```

`BEA_NO_UPDATE_NOTIFIER=1`, inherited `BEA_FILE`/`BEA_TOKEN` removed,

First apply exits 0, `written: 1`, with `bank_id` and `import-id` metadata.
Repeat the import without editing any source bytes. Preview calls it
`possible_duplicate`, not an exact duplicate; default apply exits 4.
Choosing `--duplicates include --apply` writes it again, leaving cash at
`-9.00 USD` instead of `-4.50 USD`.

```sh
python3 /abs/case/make_csv.py -6.25
bea --json --no-input -f /abs/case/main.bean import /abs/case/bank.csv --account Assets:Cash --default-account Expenses:Food --csv date=Date,narration=Description,amount=Amount,id=ID

bea --json -f /abs/case/main.bean check
```

Actual: preview exits 0, status `new`; apply exits 0, `written: 1`. Fresh
BQL returns two rows under the **same reloaded ID**:

```text
-4.50  référence-1  bank:référence-1
-6.25  référence-1  bank:référence-1
```

Cash is **-10.75 USD**. Check exits 0. `--duplicates skip` and `include`
also write the changed-amount row because it was misclassified as new.
Expected: `cli/docs/IMPORTING.md` says exact native-ID matches skip and
reuse with different source amounts is a conflict requiring review. The
second apply should exit 4 and preserve the one-entry ledger, at -4.50 USD.

Repeated twice from pristine fixtures. Composed/NFC controls work: an
unchanged ID is `duplicate`, exit 0, written 0; its changed amount is
`conflict`, exit 4, ledger unchanged. Starting with the decomposed first
write and supplying the **composed spelling only on the second run** also
restores those correct outcomes, isolating the lookup representation.

The same four-way result reproduces twice through Python importers using
each default key (`bank_id`, `fitid`, `transaction_id`, `imported_id`), a
custom `booking_ref` with `--id-key booking_ref`, and an importer-supplied
`import-id` (`external:référence-1`): 48 fresh journeys. NFD unchanged rows
become possible duplicates, NFD changed amounts write as new, and incoming
NFC controls skip or conflict correctly.

Transfer aliases are affected too. A written transfer from CashA to CashB
with `import-id-2: "bank:<NFD référence-1>"` should identify CashB's own
statement row. Its NFD reference instead becomes a possible other side;
changing CashB's amount from 100 to 125 writes another transfer with exit 0,
leaving CashB at **225 USD**. NFC controls are an exact duplicate or a
conflict, leaving CashB at 100 USD. Eight fresh alias journeys, two repeats,
all pass final checks. Human CSV output reproduces the duplicate/conflict
loss and false successful second write twice as well.

Cause: the loader's `_canonical_bytes`
(`cli/src/bea_engine/compat.py:228–243`) NFC-normalizes ledger text before
parsing while preserving the authored file bytes. Incoming strings keep
their typed form. `_native_import_id` (`importing.py:2222–2227`) constructs
the incoming native `import-id` from the raw value; `_identities`
(`:1521–1546`) also uses raw `str(value)` for native metadata IDs,
`import-id` and `import-id-2`. The existing index at `:454` therefore has
NFC keys, while incoming lookup at `:519` has NFD keys. No hit reaches the
native amount/conflict check. Same-amount rows fall through to fuzzy
matching; changed amounts miss that too and stay new. Caller search finds
these shared helpers in indexing, row classification, native-ID detection
and generated-ID eligibility.

Fix: compare all stable identifier values using the NFC representation
already produced by the CLI's ledger loader, on both index and lookup
paths, including supplied IDs and transfer aliases. Keep source-account
scope, namespaces, case, whitespace and amount/conflict rules significant.
Keep authored text bytes as required by [536](./done/536.md); this is a
comparison-key repair, not blanket normalization of new directive strings.
Generated digests and their legacy migration keys need no new format or
rehash. No dependency or API change is needed.

Working controls, twice each: generated ASCII hashes already deduplicate
NFD/NFC descriptions; composed IDs differing by case remain distinct;
supplied IDs differing by a trailing space remain distinct; one ID used by
two source accounts stays scoped and a repeat skips only its own account.
These accompany the NFC, all-key, duplicate-policy and transfer controls.

Dedupe: searched every `.pm` state for Unicode/NFD/NFC native, bank, FITID
and supplied-ID matching, plus co-occurring normalization/ID notes; checked
active scopes, callers and targeted history. Completed
[w3/377](../w3/done/377.md) repaired generated hashes and fingerprints, not
native values. [w3/m45](../w3/done/m45/README.md) explicitly excluded
native-ID semantics. [w3/420](../w3/done/420.md) requires native amount reuse
to remain a conflict; this lookup miss prevents its correct comparator from
running. [818](./done/818.md) fixes transfer-alias ownership, not value
normalization. [866](./done/866.md) and open [881](./881.md) concern plugin
visibility; this needs no plugin. No overlapping open item or later fix found.

Acceptance: repeating the identical NFD source is an exact duplicate and
writes nothing under every duplicate policy; changing only its amount is a
conflict, exit 4, with unchanged ledger bytes. Cover CSV, representative
default/custom/supplied IDs and the second transfer ID. Keep the case,
whitespace, account-scope, generated-ID and composed-ID controls. Fresh BQL
must show one payment (-4.50 USD), or the original 100 USD transfer, and a
fresh check must pass.
