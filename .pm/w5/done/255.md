# CSV amounts written with a Unicode minus sign (U+2212) are refused, though w3/done/256 listed them among the spellings to accept

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
Fails loudly, so low priority. Some bank and spreadsheet exports write
negative amounts with the typographic minus `−` (U+2212). The closed note
w3/done/256 named that spelling in its reproduction and its fix section;
the fix covered symbols, thousands separators, parentheses and trailing
minus, but not this. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Bank:Checking USD
2024-01-01 open Expenses:Uncategorized
```

`/absolute/books/uminus.csv` (UTF-8; the sign before `4.50` is U+2212):

```csv
Date,Description,Amount
2024-03-01,Coffee,−4.50
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean import uminus.csv --csv date=Date,payee=Description,amount=Amount --account Assets:Bank:Checking
```

Actual: exit 2.

```text
Error: Row 1 (line 2): cannot parse amount '−4.50' in column 'Amount'. Accepted: plain decimals (1000.50), $/€ symbols, thousands separators, (parentheses) or trailing-minus negatives; comma decimals like 1.000,00 only when the whole column uses them.
```

Control: the same file with an ASCII `-4.50` previews one ready row. A
worker saw an amount followed by a zero-width space refused the same way,
while no-break-space thousands separators parse.

Expected: `-4.50 USD`, as for the other bank spellings; or, if this
spelling is deliberately unsupported, the error should say so (the two
signs look identical on screen) and the closed note should record the
decision.

Cause: `cli/src/bea_engine/csv_mapper.py:117` (`_split_amount_sign`)
accepts only ASCII `+` and `-`.

Fix: map U+2212 to `-` and strip zero-width spaces before the sign split.
No dependency or API change.

Blast radius: CSV import amount, debit and credit columns.

Dedupe: board search for `U+2212`, "Unicode minus" and zero-width finds
only w3/done/256 itself; w5/165 concerns no-break spaces in `format`.

Acceptance: the fixture previews `-4.50 USD`; the ASCII control is
unchanged. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — CSV amount, debit and credit cells written with the typographic minus sign (U+2212) now import as the negative they look like: `_split_amount_sign` in `cli/src/bea_engine/csv_mapper.py` maps U+2212 to `-` and drops zero-width characters (zero-width space, word joiner, stray byte-order mark) before it splits the sign, so the note's fixture previews `-4.50 USD`. A U+2212 still counts as one negative marker, so `(−4.50)` and `−4.50−` are refused as marked negative twice rather than cancelling, and `cli/docs/IMPORTING.md` now names the spelling. The regression test `cli/tests/test_csv_unicode_minus_amounts.py` covers leading and trailing U+2212, zero-width spaces, a comma-decimal column, the double-negative refusal, the real `import` preview for the amount and debit/credit columns, and the ASCII control; 16 of its 20 cases fail with the fix reverted, and the four ASCII controls pass either way. Only macOS was exercised. `make check-all` passed. Shipped in `aa184f1c` (`cli`).
