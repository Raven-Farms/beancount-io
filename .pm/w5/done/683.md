# BQL patterns built at run time with `&&`, `||` or `~~` (set operations) still exit 0 and print Python's raw `FutureWarning` with the engine's site-packages path (incomplete fix of w5/509)

**Trivial · cli · 5–10m · A1.** Real CLI QA, 2026-10-17, HEAD `db21f706`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/509 (done).
w5/509 added a run-time safety net for patterns the pre-check cannot see
(built by an expression). The net escalates only the "Possible nested set"
warning. Python also warns on set intersection, union and symmetric
difference, which w5/429's pre-check refuses for literals. No product fix
implemented.

```sh
bea --json -f /abs/main.bean query "SELECT narration WHERE narration ~ lower('[A&&B]')"
bea --json -f /abs/main.bean query "SELECT grep(lower('[P||Q]'), narration) AS g"
```

Actual: exit 0 with rows; stderr shows
`<engine>/site-packages/beanquery/query_compile.py:295: FutureWarning: Possible
set intersection at position 2` (and `query_env.py:320: … Possible set union`);
text mode prints `warning: Possible set intersection at position 2`.

Control: the literal `'[A&&B]'` and `upper('[[a]')` are refused with exit 2.

Expected: exit 2 with the w5/429 wording, no warning text.

Cause: `cli/src/bea_engine/query.py:1700` uses `filterwarnings("error",
message="Possible nested set", …)`.

Fix: escalate every `FutureWarning` from `re` during the run (or match
`Possible (nested set|set (intersection|union|difference|symmetric difference))`).

Dedupe: searched `set intersection`, `set union`; no match.

Acceptance: both queries exit 2 with the refusal. A test pins them.
