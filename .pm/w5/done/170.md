# `list document` returns absolute paths when the root ledger is a symlink

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
With a root ledger that is a symlink to a file in another directory,
`list document` shows each attachment as an absolute path instead of the
relative path written in the ledger. Feeding the listed value back to
`add document --path` is refused. No product fix implemented.

In `/absolute/sym`:

```sh
mkdir -p store books/receipts; printf x > books/receipts/r.pdf
printf '2024-01-01 open Assets:Cash\n2024-01-02 document Assets:Cash "receipts/r.pdf"\n' > store/ledger.bean
ln -s ../store/ledger.bean books/main.bean
cp store/ledger.bean books/plain.bean
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f /absolute/sym/books/main.bean list document
bea -f /absolute/sym/books/plain.bean list document
```

Actual: the first exits 0 with FILENAME
`/absolute/sym/books/receipts/r.pdf`.

Control: the second (a regular file with the same two lines) shows
`receipts/r.pdf`. A worker saw the same in JSON, and `add document
--path` refuse the absolute value with "must be relative to the
destination ledger file's directory".

Expected: `receipts/r.pdf`. `docs/USAGE.md` supports this layout: "A root
ledger that is a symlink keeps the path you named… its relative `include`
and `--into` paths resolve beside the link". The listing should show what
`add document` writes and returns.

Cause: `cli/src/bea_engine/ledger/listing.py:98` sets the root to
`Path(file).resolve().parent`, the link target's directory; an attachment
beside the link is then not under that root and is returned absolute.

Fix: derive the root lexically (absolute path without following the
link), as the include handling already does; keep the resolved comparison
only for containment. No dependency or API change.

Blast radius: text and JSON `list document` for any symlinked root.

Dedupe: board search for symlink with `list document`, absolute and
relative finds w5/done/066 (parent-relative attachments, which introduced
this root), w3/done/244 and w1/done/056 (symlinked root includes); none
covers the listing under a symlinked root.

Acceptance: both commands show `receipts/r.pdf`, in text and JSON. Only
macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — `list document` now takes the tree an attachment may live in from the lexical directory of the ledger path it was given, in `cli/src/bea_engine/ledger/listing.py`, instead of the directory of a symlinked root's target; the resolved comparison in the reader is kept for containment only. A root ledger that is a symlink therefore lists `receipts/r.pdf` as the ledger spells it, in text and JSON, the same as a regular file with the same lines. The regression test `cli/tests/test_list_document_symlinked_root.py` runs the real command against a symlinked and a regular root in both output modes and feeds the listed value back to `add document --path`; two of its three cases fail with the fix reverted, and the regular-root control passes either way. No acceptance clause is unmet. Only macOS was exercised. `make check-all` passed. Shipped in `9881ad5c` (`cli`).
