# Two more `CONFIG = [...]` modules get past `bea ingest`'s refusal and exit 0 having written nothing: one saved with a UTF-8 BOM, and one binding `CONFIG` by `from myimps import *` (incomplete fix of w5/635)

**Minor · cli · 5–10m · A1.** Real CLI QA, 2026-10-17, HEAD `3295e9a3d`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/635 (done), whose addendum case (a commented `Ingest(`) is now fixed.
USAGE says a `CONFIG = [...]` import module is refused with exit 2 and pointed
at `bea import --config`. No product fix implemented.

`myimps.py` binds `CONFIG = [Base([...])]` from a small `base.py` importer.
`bom.py` is the same bytes with a UTF-8 BOM, and `star.py` is `from myimps
import *`.

```sh
bea -f /abs/main.bean ingest extract --config /abs/bom.py /abs/dl -o /abs/out_bom.bean
bea -f /abs/main.bean ingest extract --config /abs/star.py /abs/dl -o /abs/out_star.bean
```

Actual: both exit 0 with empty output, and no `out_*.bean` is created. `bea
import dl/bank.txt --config star.py` reads the star module fine (`1 ready`).

Control: `myimps.py` itself is refused with exit 2 and the pointer.

Expected: exit 2 with the pointer for both.

Cause: `cli/src/cli/commands/ingest.py` (around `:180-183`) reads the module as
`utf-8`, keeping U+FEFF, so `ast.parse` raises `SyntaxError` and the check
gives up. `_binds_config` (around `:222`) matches only the alias name `CONFIG`,
not `*`.

Fix: parse with `ast.parse(script.read_bytes())` (or decode `utf-8-sig`), and
treat `from X import *` as binding `CONFIG` when sibling `X.py` binds it.

Dedupe: w5/635 and 167 (done) are the parents; w5/704 and 710 cover BOMs
elsewhere.

Acceptance: both commands exit 2 with the pointer.

## Additional spellings verified 2026-10-17

On HEAD `8e35a3636`, twice from pristine fixtures with checkout `bea 0.3.1`, isolated config/cache and stdin closed, three related cases remain:

```python
# alias.py: this really invokes the Beangulp entrypoint.
from beangulp import Ingest as Main
CONFIG = []
Main(CONFIG)()

# noinvoke.py: constructs an Ingest but never calls it.
import beangulp
CONFIG = []
beangulp.Ingest(CONFIG)

# indef.py: the function is never invoked.
import beangulp
CONFIG = []
def main():
    beangulp.Ingest(CONFIG)()
```

For each separate script, run `bea --file /abs/main.bean ingest extract --config /abs/SCRIPT.py /abs/bank.txt -o /abs/out.bean` beside a ledger opening Assets:Checking and a synthetic text document. `alias.py` is incorrectly refused with exit 2 as a CONFIG-only module. `noinvoke.py` and `indef.py` exit 0 with empty streams and create no output. A plain `CONFIG = []` control is refused with exit 2; the normal `if __name__ == "__main__": beangulp.Ingest(CONFIG)()` control runs and reports the document. No ledger hashes change.

Cause: `_refuse_config_only_script` accepts any `_calls_ingest` match anywhere in `ast.walk(tree)`, including an uncalled def or construction without a second call. `_calls_ingest` matches the spelling `Ingest`, losing import aliases. This is the same syntactic gate as the original findings; keep its scope limited to known CONFIG-only no-ops rather than imposing a new general script validator.

Extend acceptance: accept the aliased entrypoint call; refuse the two known CONFIG-only no-ops with the existing pointer. Cover the original BOM/star-import cases alongside these when changing the shared gate. No product fix implemented.

**Resolved 2026-10-20** — `_refuse_config_only_script` parses the module's bytes (a BOM or encoding cookie no longer makes it give up), treats `from helpers import *` as binding `CONFIG` when the sibling module does, and counts the Beangulp entrypoint only when it runs as the module loads — directly, through an assignment or call, or inside a function the module calls — naming import aliases such as `from beangulp import Ingest as Main`. So the BOM and star-import modules, a bare `beangulp.Ingest(CONFIG)` and an Ingest call only inside an uncalled `def` exit 2 with the pointer, while the aliased entrypoint, a called `def main()` and the `__main__` guard still run. Scope stays the known CONFIG-only no-ops. `tests/test_ingest_config_bound_any_way.py` covers all of them plus two extract journeys.
