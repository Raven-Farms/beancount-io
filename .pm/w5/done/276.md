# A stored `query` directive with an empty body makes `.run NAME` and `.run *` fail with `IndexError`

**Minor · cli · 20m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
Contrived (it needs a placeholder `query "name" ""` in the ledger), but
one such line stops `.run *` from answering any stored query. No product
fix implemented.

Create disposable `/absolute/books/stored.bean`:

```beancount
2026-01-01 open Assets:A USD
2026-01-01 open Expenses:F USD
2026-01-02 * "x"
  Expenses:F  1 USD
  Assets:A
2026-01-03 query "one" "SELECT account, sum(number) AS s GROUP BY account"
2026-01-05 query "empty" ""
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea --file stored.bean query ".run empty"
bea --file stored.bean query ".run *"
```

Actual: both exit 1 with `Error: IndexError: list index out of range Pass
--debug before the command for a traceback.`; `.run *` answers nothing.

Control: `bea --file stored.bean query ".run one"` prints its rows. A
worker saw a whitespace-only body refused with exit 2, and a traceback in
the shell and under `--source`.

Expected: `docs/USAGE.md`: an empty query is refused with exit 2, and "the
same one-statement rule covers… the body of a stored `query` directive
replayed by `.run NAME` or `.run *`".

Cause: `_run_stored` (`cli/src/bea_engine/query.py:451`) hands the empty
string to the shell's execute, and the parser raises `IndexError`; the
one-shot path has an empty-query guard, the stored path does not.

Fix: treat an empty stored body like an empty one-shot (exit 2 naming the
stored query), and let `.run *` continue past it. No dependency change.

Blast radius: `.run` one-shot, in the shell, and under `--source`.

Dedupe: board search for "list index out of range" with `.run` finds
nothing; w5/236 and w5/237 are other `.run`/dot-command items.

Acceptance: `.run empty` exits 2 naming the query; `.run *` answers `one`
and reports `empty`. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — `_run_stored` in `cli/src/bea_engine/query.py` now checks a stored `query` directive's body before handing it to the parser: a body that is empty, blank or only a comment makes `.run NAME` a usage error (exit 2) that names the stored query, instead of a bare `IndexError` with exit 1, and `.run *` skips such a query with a `Skipped stored query "NAME": its body is empty.` line on stderr, answers every other stored query and exits 0. The same code path serves the `--file` one-shot, `--json`, the native `--source` one-shot and both interactive shells, where the refusal is an ordinary error and the session stays usable; `cli/docs/USAGE.md` states the rule. `cli/tests/test_query_run_empty_stored_body.py` covers `.run NAME` for the three empty shapes on `--file` and `--source`, the JSON error envelope, `.run *` on both surfaces, both prompts, and the control that a stored query with BQL still runs; 11 of its 13 cases fail with the fix reverted. One deviation from the note: whitespace-only and comment-only bodies, which were already refused with exit 2 as a caret-under-nothing syntax error, now get the same named refusal as the empty one. Only macOS was exercised. `make check-all` passed. Shipped in `bef8841a` (`cli`).
