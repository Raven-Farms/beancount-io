# Text-mode cloud errors drop the backend request ID that `--json` keeps, so a terminal user who hits a 5xx has nothing to give support

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1. **Simulation:** the server behaviour comes from a local mock. The defect is in how the CLI handles it.

`BeaError.request_id` is filled from the response header and emitted in
the JSON envelope. The human renderer never prints it. A person in a
terminal, the user most likely to contact support, sees only `Error:
Server error (…)`. A 5xx may not reproduce, so rerunning with `--json`
is no fix. No product fix implemented.

Setup: a localhost mock answers with 500 and `X-Request-Id: req-qa-123`.
Use the environment from [366](./366.md).

```sh
bea cloud ledger list
bea --json cloud ledger list
```

Actual:

- The text run exits 1 with only `Error: Server error (mock 500
  message).`
- The JSON run includes `"request_id": "req-qa-123"`.

The hunter saw the same for 401, 403, 404, 429 and unexpected 200
bodies. Reproduced twice by the hunter and once by me.

Expected: `docs/PRFAQ.md` says "Preserve the backend request ID for
support". `docs/USAGE.md` says the unexpected-response error "preserves
the request ID when supplied". Text mode should show it too.

Cause: `_print_failure` (`cli/src/cli/output.py:173-184`) prints the
message and details but not `err.request_id`. Only the JSON branch emits
it.

Fix: when `err.request_id` is set, print `  Request ID: req-qa-123` after
the details, made inert like the other text. No dependency change.

Blast radius: every hosted command's text-mode error that carries a
request ID.

Dedupe: searched `.pm/**`, including `done/`, for `request_id` and
"request ID". w1/055 and w3/m46/t004 keep it in JSON. Nothing covers
text mode.

Acceptance: on the mock, text mode prints `Request ID: req-qa-123`, and
the JSON is unchanged. An error with no request ID prints no such line.
A test pins both.

**Resolved.** `_print_failure` (`cli/src/cli/output.py`) prints `  Request ID: <id>` after the details whenever `err.request_id` is set, made inert like the rest of the text. JSON output is unchanged. `docs/USAGE.md` notes the text line next to the envelope's `request_id`.

`tests/test_text_error_request_id.py` covers these cases on mocked responses:

- 500, 401 and 404 print `  Request ID: req-qa-123` in text mode;
- `--json` keeps `request_id` and does not add the line to the message;
- an error without the header prints no such line;
- an escape sequence in the header is neutralized.

With the fix stashed, the four printing cases fail.
