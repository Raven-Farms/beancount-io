# engine status still says an override is usable when its native-tool paths are nonexecutable files or directories, while check -v cannot run them (incomplete fix of w5/647)

**Minor · cli · 10–15m · A1/A2.** Real CLI QA, 2026-10-18, HEAD `b7dfbe1bf`, checkout `bea 0.3.1`, macOS 26.5.1. Reproduced twice for each shape, isolated config/cache, stdin closed, no TTY. Only disposable wrapper directories were changed; the installed engine was read, not modified. No product fix implemented.

Create `/abs/wrap/python`, mode 755, forwarding all arguments to the existing engine interpreter reported by `bea engine status`:

```sh
#!/bin/sh
exec /absolute/path/to/engine/bin/python "$@"
```

Beside the wrapper, create each of `bean-check`, `bean-doctor`, `bean-example`, `treeify` as either (a) a regular shell-script file at mode 644, or (b) a directory. A valid ledger needs only `2026-01-01 open Assets:Cash USD`.

```sh
BEA_ENGINE_PYTHON=/abs/wrap/python bea --json engine status
BEA_ENGINE_PYTHON=/abs/wrap/python bea --file /abs/main.bean check -v
```

Actual: status exits 0 with `usable: true`. `check -v` exits 1 with `[Errno 13] Permission denied: '/abs/wrap/bean-check'. Pass --debug before the command for a traceback.` Both shapes give that contradiction. Ledger hashes do not change.

Controls: absent native-tool paths now produce `usable: false`, naming the missing tools. Symlinks to the real engine's four executables produce `usable: true`, and `check -v` succeeds. Plain check on a clean ledger is an insufficient control: its helper precheck can return before it invokes the native tool, so it succeeds even with the broken wrappers.

Expected: status reports that the override's native tools cannot run, identifies the offending paths, and offers a working remedy. A directory or a file without execute permission cannot make an environment usable.

Cause: `launch.missing_native_tools` (`cli/src/cli/engine/launch.py:453`) checks only `Path.exists()`. `engine_status` (`cli/src/cli/commands/engine.py:49`) treats no missing paths as usable; `native_command` also accepts existence alone. The same four tool paths serve check, doctor, example and treeify.

Fix: distinguish missing paths from nonregular or nonexecutable tool paths, using platform-appropriate checks, and share those diagnostics with native command resolution. Do not execute arbitrary tools just to probe status.

Dedupe: whole-board searches for native tool executability, usable/permissions and directories found no open item. Parent w5/647 (done, `04397c733`) added presence checks but tested only absent siblings. w5/481 (done) covers unusable Python overrides.

Acceptance: both shapes report unusable with their cause; real executable symlinks remain usable; a native-command failure names the same cause without an unexpected Python-error hint. Pin text and JSON status.

---

**Resolved 2026-10-20** — `native_tool_problem` judges each native tool path without running it (missing, a directory, not a regular file, not executable on POSIX); `engine status` reports an override unusable naming each tool and its cause (`bean-check (not executable), … cannot run beside …`, text and JSON), and `native_command` resolves only a runnable tool, so `check -v` names `a 'bean-check' that cannot run (… is not executable)` instead of a raw `[Errno 13]` and the `--debug` hint. Executable symlinks to the real tools stay usable. `tests/test_engine_status_unusable_override.py` pins both shapes in text and JSON plus the `check -v` message and the symlink control; the engine-layout fixture now marks its tool executable. USAGE describes the check.
