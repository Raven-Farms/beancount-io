# Set-valued query cells change order between identical runs in JSON and CSV

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, macOS.
`tags`, `links` and other set-valued columns are emitted in Python hash
order in `--json` and `-f csv` output, so the same command on the same
ledger produces different bytes from one run to the next. The text table and
`bea list` both sort. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
2024-01-01 open Assets:Cash USD
2024-01-01 open Assets:Broker HOOL "FIFO"
2024-01-01 open Expenses:Food
2024-01-04 custom "budget" Expenses:Food "monthly" 400.00 USD TRUE 2024-01-01 -3.5
2024-01-05 * "Grocer" "Refund (partial)" #food #trip #reimbursable
  Expenses:Food  -5.00 USD
  Assets:Cash
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY. The fixture passes
`bea check`.

`PYTHONHASHSEED` is set only to make the variation repeatable; without it
the order varies by itself between runs.

```sh
PYTHONHASHSEED=1 bea --json -f /absolute/books/main.bean query "SELECT tags WHERE account = 'Assets:Cash'"
PYTHONHASHSEED=2 bea --json -f /absolute/books/main.bean query "SELECT tags WHERE account = 'Assets:Cash'"
PYTHONHASHSEED=2 bea -f /absolute/books/main.bean query -f csv "SELECT tags WHERE account = 'Assets:Cash'"
```

Actual: all exit 0. Seed 1 gives `["reimbursable", "food", "trip"]`; seed 2
gives `["reimbursable", "trip", "food"]` and the CSV cell
`"reimbursable, trip, food"`. Repeated across seeds 1–3.

Control (worker-observed): the text table prints `food  reimbursable  trip`
under every seed, and `--json list transaction` returns sorted tags.

Expected: identical output for an identical command and ledger. The only
instability `docs/USAGE.md` documents for queries concerns
`joinstr(tags)`. Sorted order, as the text renderer and `list` already
use, makes exports diffable and cacheable.

Cause: `cli/src/bea_engine/protocol.py:285-286` iterates a set unsorted;
the CSV join at `cli/src/bea_engine/query.py:925` inherits that order.

Fix: sort set and frozenset values in `_jsonable` and in the CSV cell
join. No dependency or API change.

Blast radius: any diff, golden file or cache keyed on query JSON/CSV with a
set-valued column (`tags`, `links`, `other_accounts`).

Dedupe: board search for hash seed, hash order and unstable tag order finds
nothing.

Acceptance: the three commands print the same sorted order under any
`PYTHONHASHSEED`, for `tags`, `links` and `other_accounts`. A
regression test runs the real command under two seeds and compares bytes.
Only macOS and the checkout were exercised.

---

**Resolved 2026-10-12** — The engine's JSON walk sorts the members of a set or frozenset, and the CSV cell is joined from that same value, so `--json` and `-f csv` print `tags` and `links` in one sorted order under any `PYTHONHASHSEED`, matching the text table and `bea list`. Shipped in `bcbea79d` (`cli`).

A regression test runs the real command under five hash seeds for `tags`, `links` and `other_accounts`, in JSON and CSV, and compares bytes across seeds as well as the sorted contents. The `tags` and `links` cases fail with the fix reverted; `other_accounts` passes either way on this fixture — it already came out in a stable order — so it stands as a pin rather than a reproduction. `make check-all` passed. Only macOS was exercised.
