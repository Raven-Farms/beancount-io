# A byte that is not valid UTF-8 in an `add` argument (a Latin-1 `é` from an old script or terminal) fails with a raw `UnicodeEncodeError … surrogates not allowed`, exit 1

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `604894f6`, checkout `bea 0.3.1`, macOS 26.5.1.
Python decodes undecodable argv bytes as surrogates. w5/185 made bulk JSON
input refuse them with a usage error naming the field. Command-line
arguments to `add` reach Beancount's parser, which fails while encoding.
The user sees a Python codec message filed as a validation failure. No
product fix implemented.

```sh
bea -f /abs/main.bean add transaction $'caf\xe9' --date 2026-01-05 -p 'Expenses:Food 1 USD' -p 'Assets:Cash'
bea -f /abs/main.bean add note -a Assets:Cash -m $'caf\xe9' --date 2026-01-05
```

Actual: exit 1 (`validation`), `Error: UnicodeEncodeError: 'utf-8' codec can't
encode character '\udce9' in position 17: surrogates not allowed. Pass --debug
before the command for a traceback.` (same under `--json`); the file is
unchanged.

Expected: exit 2 naming the argument: `the narration is not valid UTF-8 (byte
0xe9 at position 3); re-type it in a UTF-8 terminal`, as w5/185 does for
bulk rows.

Cause: `cli/src/bea_engine/ledger/adding.py:746` hands the text to
`parse_exact`; the `_surrogate_problems` scan (w5/185) runs only for bulk
rows.

Fix: run the surrogate scan on every `add` argument (frontend or engine),
naming the option.

Dedupe: searched `surrogate`; w5/185, 336, w1/112, 166 and w5/155 cover stdin
and JSON input.

Acceptance: both commands exit 2 naming the argument. A test pins them.

---

**Resolved 2026-10-17** — Shipped in `b0dbd3620` (`cli`). `adding.answer` in `cli/src/bea_engine/ledger/adding.py` now scans every single-add request field (`_refuse_undecodable_arguments`) before anything parses it. An argv byte that arrives as a lone surrogate in U+DC80–U+DCFF is refused with exit 2: `The narration is not valid UTF-8 (byte 0xe9 at position 3); re-type it in a UTF-8 terminal.` The message names the option the field came from (`-m/--comment`, `-p/--posting`, `--payee`, …). Any other lone surrogate gets the bulk path's unpaired-surrogate sentence. Test: `cli/tests/test_add_argument_not_utf8.py`.
