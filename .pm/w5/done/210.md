# `bea --no-input format`, `add transactions --from -` and `treeify` wait on the terminal forever instead of exiting 2

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
Three commands that read standard input read it even when it is a terminal
and the run is declared unattended (`--no-input` or `CI=true`). They print
nothing and block until someone types Ctrl-D. `bea query` has the guard
these lack. No product fix implemented.

Fixture: any directory; `/absolute/books/main.bean` containing
`2020-01-01 open Assets:Bank USD` for the controls.

Run each command on a real PTY (stdin, stdout and stderr all the terminal),
with isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN/CI, cwd `/absolute/books`, and an 8-second
bounded wait.

```sh
bea --no-input format
CI=true bea format
bea --no-input add transactions --from -
bea --no-input -f /absolute/books/main.bean add transactions --from -
bea --no-input treeify
```

Actual: all five print nothing and are still running after 8 seconds
(killed by the harness). No file changes. A worker confirmed that typing a
line and Ctrl-D lets `format` finish with exit 0, so it is blocked reading
the terminal, and saw the same for `--json add transactions --from -` and
`CI=1`.

Control (same PTY and environment):

```text
bea --no-input -f /absolute/books/main.bean query   => exit 2  Error: A query is required with --no-input. Pass it as an argument or on stdin.
bea --no-input format /absolute/books/main.bean     => exit 0
bea --json format --check                           => exit 2  Name the files to format: reading stdin has nothing to compare or rewrite.
```

Expected: `docs/USAGE.md`: "`--no-input` | Never prompt. Missing
confirmation or input fails with exit 2 instead of waiting." and
"`--no-input` is implied whenever stdin is not a terminal, whenever `--json`
is set, and when `CI` is truthy. In that mode nothing waits for a human."
The exit-code table gives 2 for "input needed under `--no-input`". Each
command should exit 2 naming the missing input.

Cause: `cli/src/cli/commands/format.py:83-88` routes the no-path case to
`_stdin_text()` (`:524-535`), which calls `stream.read()` without checking
`sys.stdin.isatty()` or `ctx.no_input`; `cli/src/cli/commands/add.py:484-488`
reads `--from -` the same way, and delegated `treeify` inherits the
terminal. The sibling guard is `cli/src/cli/commands/query.py:260-263`.

Fix: when stdin is a terminal and `ctx.no_input` is true, raise a usage
error (exit 2) before reading. Piped or redirected stdin is unchanged, and
an interactive run without `--no-input` may keep reading the terminal. No
dependency or API change.

Blast radius: `format` with no path or `-`, `add transactions --from -`,
`treeify` with no input file. A CI job with an allocated TTY (`docker run
-t`, `script`, some runners) hangs until its timeout.

Dedupe: board search for `isatty`, "is a terminal", `hangs`, `--from -`
and `--no-input` with `format`/`treeify` finds w1/done/040 (the same class
for `query --source`, fixed), w5/110 (`query ""` opens the shell), w5/163
(prompts on stdout) and w5/182 (lock wait); none covers these commands.

Acceptance: each of the five commands exits 2 within a second on a PTY with
a message naming the missing input; the three controls are unchanged; the
same commands with piped stdin still read it. A PTY regression test covers
`format` and `add transactions --from -`. Only macOS and the checkout were
exercised.

---

**Resolved 2026-10-13** — A shared guard, `refuse_terminal_stdin` in `cli/src/cli/context.py`, now raises a usage error (exit 2) when stdin is a terminal and the run is unattended (`--no-input`, `--json` or a truthy `CI`), and `bea format` with no path or `-` (`commands/format.py`), `bea add transactions --from -` (`commands/add.py`) and `bea treeify` with no input file (`commands/treeify.py`) call it before reading, each naming the missing input. Piped or redirected stdin is read as before, and an interactive run without `--no-input` may still type the input and end it with Ctrl-D. The PTY regression test `cli/tests/test_no_input_terminal_stdin.py` covers the five commands from the note plus `format -`, `--json add transactions --from -`, `CI=1` and `treeify -o`, the three controls (`query`, `format FILE`, `--json format --check`), typed interactive input and piped input for all three commands; 9 of its 12 cases fail (by waiting on the terminal) with the fix reverted. The refusals return in well under a second locally, though the test only bounds the wait rather than asserting that timing. Only macOS was exercised. `make check-all` passed. Shipped in `43dcf29e` (`cli`).
