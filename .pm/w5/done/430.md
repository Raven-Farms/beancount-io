# `bea check` loads the ledger twice, so a plugin's warnings and log lines print twice (and a plugin with side effects runs twice), where stock `bean-check` runs it once

**Trivial · cli · 15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
A plugin that calls `warnings.warn` and `logging.warning` prints each
message once under `bea balance` and under stock `bean-check`. Under
`bea check` each message prints twice. Python shows a given warning only
once per process, so this points to two separate loads. That costs time
on large ledgers, and plugins with side effects (network, file writes,
counters) run twice. No product fix implemented.

Create a plugin `pl/wplug.py`:

```python
import logging, warnings
__plugins__ = ["run"]
def run(entries, options_map):
    warnings.warn("wplug user warning")
    logging.warning("wplug logged a warning")
    return entries, []
```

and `pw.bean`: `plugin "wplug"` plus any valid ledger. Use isolated
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, and closed
stdin.

```sh
PYTHONPATH=/absolute/pl bea -f /absolute/pw.bean check
PYTHONPATH=/absolute/pl bea -f /absolute/pw.bean balance
```

Actual: `check` prints the `UserWarning` pair and `WARNING:root:wplug
logged a warning` twice. `balance` prints them once. The hunter reports
that the engine's own `bean-check pw.bean` also prints them once.
Reproduced twice by the hunter and once by me (`check`).

Expected: one load per command, so plugins run once, as with `bean-check`
and every other bea read.

Cause: not traced to a line. `check` (`cli/src/cli/commands/check.py`)
appears to run both bea's validation load and the forwarded bean-check.

Fix: reuse a single load for both purposes, or skip the second when the
first already produced the result. No dependency change.

Blast radius: `bea check` on ledgers with plugins, which is the most
common CI command: twice the plugin cost and duplicated plugin output.

Dedupe: searched `.pm/**`, including `done/`, for "loads twice", "plugin
runs twice" and `check` together with double. None covers this. r48
counted one load for read commands and did not measure `check`.

Acceptance: with the fixture plugin, `bea check` prints each message once.
A test counts plugin invocations during `check`.

Addendum (CLI QA r75, 2026-10-14): the cause is traced. It is
deliberate. `cli/src/cli/commands/check.py:85` runs the helper's `check
--documents-only` load, which applies the out-of-tree document rule
(w5/088), drops stale caches (w5/116) and names plugin failures
(w5/256). `check.py:104` then runs native `bean-check`, which loads
again. `--json check` loads once. The cost is about +0.18 s at 10k
transactions. A possible fix: when no bean-check options are passed,
skip the native run, because the helper load is already a full check.
Otherwise, document that `check` runs plugins twice. The A2 caveat about
an untraced cause no longer applies.

---

**Resolved 2026-10-15** — shipped in `0f30e04a` (`cli`), following the addendum's suggested fix:
the helper's `check --documents-only` pass (`cli/src/bea_engine/main.py`)
now also runs bean-check's own extra validations
(`HARDCORE_VALIDATIONS`) on the entries it loaded, and answers `clean`.
That covers no loader errors and nothing from those validations. With no
bean-check options and a clean answer, `bea check`
(`cli/src/cli/commands/check.py`) exits 0 from that single load. The
fixture plugin's `UserWarning` and `logging.warning` now print once, and
a counter plugin runs once. A ledger with errors, or a run with
bean-check options, still goes through native bean-check, which loads
again so that its output stays bean-check's own; plugins run twice
there, which USAGE now states. `--json check` is unchanged. Pinned by
`cli/tests/test_check_single_load.py`; its clean case fails without the
fix. Two signal and interrupt tests that held a plugin inside a plain
`check`'s bean-check now use the option form, which still forwards.
