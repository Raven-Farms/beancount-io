# The same conflicting same-day price exits 2 (`usage`) from `add price` but 4 (`conflict`) from `import --apply`; `add balance` with a different same-day value also exits 2

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-17, HEAD `6d74be10`, checkout `bea 0.3.1`, macOS 26.5.1.
IMPORTING says the import's price rule "follows `bea add price`", and
documents exit 4 for it (w5/302). USAGE calls it "the `--force` conflict
rule", and the exit-code table maps conflict to 4. `add price` and `add
balance` refuse the same condition as a usage error, so an agent branching
on the exit code treats one condition two ways. No product fix implemented.

Ledger with `2026-01-01 commodity EUR` and `2026-01-03 price EUR 1.10 USD`; a
beangulp importer whose `extract` returns `Price(2026-01-03, EUR, 1.20 USD)`.

```sh
bea --json -f /abs/main.bean add price --date 2026-01-03 --currency EUR --amount '1.20 USD'
bea --json -f /abs/main.bean import quotes.txt --config imp.py --apply
```

Actual: `add price` exits 2, `usage`: `EUR already has a 2026-01-03 price of 1.10
USD …; refusing 1.20 USD. Pass --force to record another quote.`; the import
exits 4, `conflict`, for the same pair. A different same-day `add balance`
exits 2.

Expected: one code for one condition (4 matches the table), documented in
USAGE.

Cause: `cli/src/bea_engine/ledger/adding.py:298-307` and `:703` raise
`protocol.UsageError`; `cli/src/bea_engine/importing.py:684` raises
`ConflictError`.

Fix: raise `ConflictError` in `add` too (or `UsageError` in import), and state
the choice in USAGE.

Dedupe: w5/302 (done) chose 4 for import only; w5/397 is related.

Acceptance: both commands give the same code. A test pins it.
