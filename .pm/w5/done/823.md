# A migrated digest whose source name has an underscore (`lunch_money:sha256:…`) is not recognised, and the bank row is written again with exit 0 (incomplete fix of w5/601)

**Minor · cli + skills · 5m · A1.** Real CLI QA, 2026-10-17, HEAD `5b305b485`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/601 (done).
IMPORTING and dedup.md say a migrated digest matches under "a lowercase
source name", and the migrate skill writes `<source>:sha256:…`. No product
fix implemented.

The ledger holds `2026-03-08 * "Trader Joes" "Weekly groceries"` with
`import-id: "lunch_money:sha256:9b811ad4dd24f37f"` (Checking −54.20).
`checking.csv` is `2026-03-08,TRADER JOES #123 SEATTLE WA,-54.20`.

```sh
bea --file /abs/main.bean import checking.csv --csv date=Date,narration=Description,amount=Amount --account Assets:Checking --apply
```

Actual: exit 0 with `1 ready, 0 exact duplicates`. It writes `import-id:
"csv:sha256:9b811ad4dd24f37f"`, the same digest, and Checking becomes −108.40.

Control: `lunch-money:sha256:…` gives `1 exact duplicates` (−54.20).

Expected: −54.20; an underscore is part of a lowercase source name.

Cause: `_GENERATED_ID` (`cli/src/bea_engine/importing.py:1168`) is
`[a-z][a-z0-9-]*:sha256:…`, with no `_`.

Fix: allow `_` (`[a-z][a-z0-9_-]*`), and state the exact source-name grammar in
IMPORTING, dedup.md and the migrate skill.

Dedupe: w5/601 (done) is the parent.

Acceptance: the fixture reports an exact duplicate.

---

**Resolved 2026-10-20** — `_GENERATED_ID` is now `[a-z][a-z0-9_-]*:sha256:<16 hex>`, so the fixture's `lunch_money:sha256:9b811ad4dd24f37f` row is an exact duplicate and Checking stays at −54.20. That id also counts as generated, not a bank ID, in twin reasons (w5/832). The grammar — a lowercase letter, then lowercase letters, digits, `-` or `_` — is now stated in `cli/docs/IMPORTING.md`, `skills/beancount-import/references/dedup.md` and `skills/beancount-migrate/SKILL.md`. `tests/test_import_generic_migration_prefix.py` gains a `lunch_money` case, which fails at HEAD.
