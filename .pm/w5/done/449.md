# `--into` naming a managed price include URL is treated as a local relative path: bea advises creating `https:/beancount.io/prices/`, then writes the entry into a local file the ledger never loads (exit 0)

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
PRFAQ says "Managed price feed files are read-only", and bea has a
read-only guard for managed sources. That guard checks the resolved local
path. `--into "https://beancount.io/prices/BTC-USD"` never reaches it,
because the include text is matched as a local glob:

- the first attempt tells the user to create a directory named
  `https:/beancount.io/prices`;
- once that directory exists, the write succeeds into a local file that
  the ledger never loads (the include still resolves to the managed
  feed).

The entry is silently orphaned. No product fix implemented.

Create a disposable `mp.bean`:

```beancount
option "operating_currency" "USD"
include "https://beancount.io/prices/BTC-USD"
2026-01-01 open Assets:Cash USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, and
closed stdin.

```sh
bea --offline -f /absolute/books/mp.bean add note --date 2026-01-05 -a Assets:Cash -m x --into "https://beancount.io/prices/BTC-USD"
mkdir -p "/absolute/books/https:/beancount.io/prices"
bea --offline -f /absolute/books/mp.bean add note --date 2026-01-05 -a Assets:Cash -m x --into "https://beancount.io/prices/BTC-USD"
bea --offline -f /absolute/books/mp.bean list note
```

Actual:

- The first run exits 2 with `Write destination directory
  …/https:/beancount.io/prices does not exist. Create the directory
  first.`
- After the `mkdir`, the second run exits 0 with `Added 1 note to
  …/https:/beancount.io/prices/BTC-USD.`
- `list note` does not show the note.

Reproduced twice by the hunter and once by me.

Control: `--into` naming a real local include writes, and the entry is
listed.

Expected: `--into` naming a managed (URL) include should be refused with
exit 2 using the read-only managed-feed message. URL includes should
never be matched as local paths or globs.

Cause: `_included_new_file` (`cli/src/bea_engine/ledger/write.py:266-275`)
treats the URL include text as a glob pattern. Its `os.path.split`
parent then matches the local `https:/…` directory (`:141-153`). The
read-only check (`:117-122`, `managed_source_for_path`) looks only at the
resolved local target.

Fix: leave `scheme://` includes out of `--into` pattern matching. When
the `--into` text equals a managed include URL, raise the existing
read-only error. No dependency change.

Blast radius: `add *`, bulk add and `import --apply` with `--into` naming
a managed feed, a plausible mistake for users who want to add prices
"into" the feed.

Dedupe: searched `.pm/**`, including `done/`, for managed together with
`--into`, read-only and URL. w5/285, w5/145, w5/144 and w5/247 (other
`--into` and include issues) and 377-379, 408, 409 and 423 (managed
prices) cover other cases. None covers this.

Acceptance: both runs exit 2 with the read-only message, no file is
created, and the misleading directory advice is gone. A test pins it.

Addendum (CLI QA r94, 2026-10-14): the same cause has three more
variants.

- An uppercase managed include (`include
  "HTTPS://beancount.io/prices/BTC-USD"`, which bea treats as managed)
  with `--into "HTTPS://…"` gets the same advice to create
  `…/HTTPS:/beancount.io/prices`.
- `--into "file:///abs/fa/x.bean"` gets `Write destination directory
  …/fa/file:/abs/fa does not exist. Create the directory first.`
- With a managed include, `query -o mg/https:/beancount.io/prices/BTC-USD`
  is refused as "the include pattern … matches that path", although the
  managed include never reads that file. The refusal is harmless, but
  its reason is wrong.

450 covers the read-side twin: refused URL includes loading local
`https:/…` files.

---

**Resolved 2026-10-15** — `--into` on `add`, `import` and `ask` now uses
an `IntoPath` type (`cli/src/cli/utils.py`). It reads the raw value before
Typer turns it into a `Path` and collapses `//`. Any `scheme://` value
exits 2 with `--into '<url>' names a URL.` For http(s), the message adds
that a managed price feed is read-only, and suggests declaring your own
price directive or passing a local included file. Both repro runs, before
and after the `mkdir`, exit 2 with that message. No file is created, and
the directory advice is gone. The uppercase `HTTPS://` variant and
`file:///…` are refused the same way. The `query -o` addendum no longer
reproduces after 450 (`60113d87`), because the write snapshot no longer
globs URL includes. USAGE notes the refusal. Pinned by
`cli/tests/test_into_url_refused.py`, which fails without the fix.
