# A currency conversion in the period keeps the empty trailing interval row the guide says is dropped

**Minor · cli · 20m · A1.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, macOS. With `--time` ending partway through an
interval, flow series are documented to drop the trailing fragment when no
entries fall in it. When the period contains any priced currency exchange, the
empty fragment is kept as an extra all-zero row. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Bank
2024-01-01 open Assets:Euro
2024-01-01 open Equity:Open
2024-01-01 open Expenses:Food

2024-01-01 * "Open"
  Assets:Bank  1000.00 USD
  Equity:Open

2024-01-02 price EUR 1.10 USD

2024-01-15 * "Buy EUR"
  Assets:Euro  100.00 EUR @ 1.10 USD
  Assets:Bank  -110.00 USD

2024-01-16 * "Lunch"
  Expenses:Food  12.00 USD
  Assets:Bank
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, and an absolute `--file`.

```sh
bea -f /absolute/books/main.bean report income-statement -t 2024-01 -i weekly
```

Actual: five period rows; the last is `2024-01-31  —  —  0.00 USD`, the
Monday–Wednesday tail of a week that runs into February. `bea list
transaction --from-date 2024-01-29` prints `No transactions found.`
Repeated twice.

Control: with the EUR leg replaced by `110.00 USD`, the same command prints
four rows ending `2024-01-28`.

Expected: `docs/USAGE.md` Reports — flow series "drop that fragment when no
entries fall in it, so a clipped boundary does not read as one more quiet
week". Four rows.

Cause: `cli/src/fava/modules/chart.py:58` decides by
`slice_entry_dates(filtered.entries, last.begin, last.end)`. Clamping the
ledger to `--time` inserts a synthesized `C "Conversion for (…)"`
transaction on the period's last day whenever the period holds a conversion,
so the fragment always appears to contain an entry.

Fix: judge the fragment by entries the ledger declares; ignore the summarize,
transfer and conversion entries the clamp synthesizes. No dependency or API
change.

Dedupe: board search for interval fragments and conversion entries finds
w3/375, which introduced the rule and does not mention clamp entries.

Acceptance: the fixture prints four rows in text and JSON for weekly and for
any interval whose last bucket is a quiet fragment; a fragment holding a real
entry on the last day still prints; balance series keep every bucket. Only
macOS and the checkout were exercised.

---

**Resolved 2026-10-12** — The trailing-fragment rule for flow series now counts only entries the ledger declares. Entries the time-filter clamp synthesizes — recognizable by Beancount's `<summarize>`, `<transfer_balances>` and `<conversions>` source markers — no longer make a quiet fragment look busy. On the fixture `report income-statement -t 2024-01 -i weekly` prints four rows ending `2024-01-28`, in text and JSON. The change is commented in the vendored source as a Beancount.io modification. Shipped in `51c748ec` (`cli`).

Regression tests cover the weekly fixture with a priced exchange and with a single-currency control, the text rows, a monthly interval whose last bucket is a quiet fragment, a fragment holding a real entry on the last day (kept), and the balance-sheet series (every bucket kept). Three fail with the fix reverted. Synthesized entries are identified by source marker rather than by flag, so a transaction the user flagged `C`, `S` or `T` still counts. `make check-all` passed. Only macOS was exercised.
