# With `--json --allow-errors`, `list` and `query` report the ledger's load errors only as plain text on stderr, while `balance` and `report` carry `ledger_valid`/`ledger_errors` in the JSON envelope

**Trivial · cli · 15m · A2.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
An agent that reads a partial answer through `--json --allow-errors`
learns from `balance` and `report` that the ledger is invalid, through
`ledger_valid: false` and `ledger_errors: [...]`. From `list` and
`query` it gets an envelope that looks complete. The errors are only in
human-readable stderr text, which agents usually discard. USAGE
documents this ("still print on stderr", and `ledger_errors` only for
reports), hence A2, but the asymmetry undercuts the JSON contract for
agents. No product fix implemented.

Use a USD ledger with a failing `2026-01-20 balance Assets:Cash 999 USD`.
Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, and
closed stdin.

```sh
bea --json -f /absolute/books/main.bean list open --allow-errors
bea --json -f /absolute/books/main.bean query --allow-errors "SELECT count(*)"
bea --json -f /absolute/books/main.bean balance --allow-errors      # control
```

Actual: the `list` envelope has only `bea`, `target`, `data`,
`truncated` and `limit`, and stderr carries `main.bean:3: Balance failed
…`. `query` behaves the same way. The `balance` control has `ledger_valid:
false` and one `ledger_errors` entry. Reproduced twice by the hunter and
once by me (`list`, `balance`).

Expected: the same machine-readable signal on every read that tolerates
errors. Add `ledger_valid`/`ledger_errors` to the `list` and `query`
envelopes when `--allow-errors` admits errors, or document the asymmetry
in the JSON contract section.

Cause: `cli/src/cli/commands/list.py:351` and
`cli/src/cli/commands/query.py:431` only call `render_ledger_errors`
(stderr).

Fix: include the formatted errors in the envelope, as the report path
does. No dependency change.

Blast radius: agents and scripts that use `list`/`query --json
--allow-errors`.

Dedupe: w5/308 (stderr closed) and w5/111 / w1/m13/t001
(`render_ledger_errors`) cover other aspects. None covers envelope
parity.

Acceptance: `list --json --allow-errors` and `query --json
--allow-errors` on the fixture include `ledger_valid: false` and the
error. A clean ledger omits the fields, or reports them as true and
empty. A test pins it.

Addendum (CLI QA r104, 2026-10-14): one concept, "pre-existing errors
tolerated by `--allow-errors`", currently travels in five ways:

| Command | Where the errors go |
|---|---|
| `balance`, `report *` | `data.ledger_valid` + `data.ledger_errors` (also on stderr) |
| `add *` (success) | `data.warnings`, mixed with advice prose |
| `import` | `data.validation_warnings`, mixed with advice prose |
| `list`, `query` | stderr text only (this note) |
| a failure | `error.ledger_warnings` (`query` only; writes omit it, see 461) |

An agent has to know every spelling to detect a partial answer. A
uniform contract would put `ledger_valid`/`ledger_errors` in `data`, keep
advice in `warnings`, and use `ledger_warnings` on failure. The import
`notes` vs `warnings` split is a smaller instance of the same thing.

---

**Resolved 2026-10-15** — `output.emit` takes the formatted loader errors. `list` and `query` (`cli/src/cli/commands/list.py`, `query.py`) pass them, so every `--json` envelope from those reads carries `ledger_valid` and `ledger_errors` beside `data`, because `list`'s `data` is an array and cannot hold them as a report's object does. A tolerated failing assertion now reads `ledger_valid: false` with the error, and a clean ledger reads `ledger_valid: true` with an empty list. The stderr banner is unchanged. USAGE's strict-reads paragraph documents the fields. The addendum's broader unification (`warnings`, `validation_warnings`, import `notes`) was not attempted; failures got `error.ledger_warnings` in w5/461. `cli/tests/test_read_envelope_ledger_errors.py` covers `list open` and `query` on the broken and clean ledgers; all 4 fail with the fix reverted. Only macOS was exercised. `make check-all` passed (6004 tests). Shipped in `d3fc5ffe` (`cli`).
