# `bea import --apply` validates the same candidate twice, so a one-row apply costs three full loads (8.7 s at 60k transactions) where `add transaction` costs one (3.5 s)

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-16, HEAD `3514cc17`, checkout `bea 0.3.1`, macOS 26.5.1.
`import_entries` validates the candidate for the preview (`validate_append`),
then `ledger_write.append` validates the same texts against the same
snapshot again under the lock. The snapshot check and
compare-before-replace already guard against files changing in between.
Plugins with side effects run three times. No product fix implemented.

A synthetic ledger of ~60,000 transactions (warm cache); `one.csv` =
`Date,Amount,Description` / `2025-01-05,-3.00,zz1`.

```sh
bea -f /abs/main.bean import one.csv --csv auto --account Assets:Cash --default-account Expenses:Food
bea -f /abs/main.bean import one.csv --csv auto --account Assets:Cash --default-account Expenses:Food --apply
bea -f /abs/main.bean add transaction zz2 --date 2025-01-06 -p 'Expenses:Food 3.00 USD' -p Assets:Cash
```

Actual: preview 5.5 s, `--apply` 8.7 s, `add` 3.5 s. An open-tracing run
shows three parses on `--apply`: the preview load, `validate_candidate` via
`validate_append` (`cli/src/bea_engine/importing.py:540` →
`ledger/write.py:2526`), and `validate_candidate` via `append` (`importing.py:663`
→ `write.py:2731`). At 300k transactions: preview 27 s, `--apply` 45.5 s,
`add` 16.7 s.

Expected: one validation of the candidate on `--apply`.

Fix: on `--apply`, skip the preview validation and let `append`'s validation
(under the lock) produce the preview rows, or pass the preview's result into
`append` with the snapshot it was taken against.

Dedupe: w5/431 (blocked) covers pre-reads in `add balance`/`add price`/bare
numbers; w1/167 and w5/123 cover per-row reloads; none covers `import`.

Acceptance: a test counts loads for a one-row `--apply` (two at most: read
and validate). Timings on the fixture approach `add`'s plus the preview read.

---

**Resolved 2026-10-17** — Shipped in `8ca73edf` (`cli`). The fix is in `cli/src/bea_engine/ledger/write.py`:
- **`append`:** accepts `validated=`, the answer `validate_append` already gave for the same texts against the same snapshot. It still verifies the snapshot unchanged under the lock and still compares before replacing, but skips the second `validate_candidate` load.
- **`import --apply`:** passes the preview's validation warnings (`cli/src/bea_engine/importing.py`). A one-row apply now reads the ledger once and validates once, two loads instead of three.

`tests/test_import_apply_load_count.py` counts the loads and fails without the fix (three). Not re-timed on the 60k fixture; the load count is the acceptance test. `make check-all` passed.
