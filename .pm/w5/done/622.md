# A forced `--delimiter` that does not split the header is reported as a missing `Date` column, and one refusal suggests a mapping that fails the same way (gap in w3/226)

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-16, HEAD `e2565f3b`, checkout `bea 0.3.1`, macOS 26.5.1.
w3/226's resolution: a "forced comma on a semicolon file names --delimiter
instead of a fake missing-column recovery". That holds only on the
`--csv auto` path, and only for `;`, tab and `|` in the header. With an
explicit mapping, or with a forced `;` on a comma file, the user is told
a column that is plainly present is missing. No product fix implemented.

`semi.csv`: `Date;Description;Amount` / `2026-04-01;Coffee shop;-4.50`.
`comma.csv`: the same data comma-separated.

```sh
bea -f /abs/main.bean import semi.csv --csv date=Date,amount=Amount,narration=Description --delimiter ',' --account Assets:Checking
bea -f /abs/main.bean import comma.csv --csv auto --delimiter ';' --account Assets:Checking
```

Actual: (1) exit 2, `The mapping names column 'Date' for date, which
semi.csv lacks.`, with no mention of the forced comma; (2) exit 2, `Its
columns are: Date,Description,Amount (delimiter ';'). Name them with --csv
date=Date,amount=Amount,narration=Description.` Following that (keeping
`--delimiter ';'`) fails with `… which comma.csv lacks.`

Control: `semi.csv --csv auto --delimiter ','` names the delimiter.

Expected: whenever the forced delimiter yields a one-column header, the
refusal says so, names the delimiter that would split it, and does not
suggest a mapping.

Cause: the one-column check (`cli/src/cli/commands/import_.py:239-247`) runs
only on the inference path and looks only for `;`, tab and `|`; the fallback
at `:249-253` suggests a mapping regardless; the explicit-mapping path
(`cli/src/bea_engine/csv_mapper.py:1043-1046`) has no delimiter hint;
`tests/test_csv_delimiter_import.py:91` covers `--csv auto` only.

Fix: apply the one-column detection on both paths and for every delimiter
(including `,`).

Dedupe: w3/226 (done) is the parent.

Acceptance: both commands name the delimiter problem. Tests pin them.

---

**Resolved 2026-10-17** — Shipped in `ffdd0dfbd` (`cli`).
- Whenever the delimiter in force reads the header as one column holding another separator, comma included, the refusal now says so and names the delimiter that splits it. No mapping is suggested.
- The engine's explicit-mapping column check (`unsplit_header` in `cli/src/bea_engine/csv_mapper.py`) does this, as does the frontend's header inference (`_inferred_mapping`).
- Command (1) now says "semi.csv's header was read as one column ('Date;Description;Amount') with delimiter ',', but it looks semicolon-separated. Pass --delimiter ';', or omit --delimiter so bea detects it." Command (2) says comma.csv "looks comma-separated … Pass --delimiter ','".
- `tests/test_import_unsplit_header_names_delimiter.py` pins both; both fail without the fix. w3/226's `test_csv_delimiter_import.py` passes unchanged. `make check-all` passed.
