# Format resolves a missing include against the working directory and rewrites the wrong file

**Major · cli · 30–45m · A1.** Real CLI QA, 2026-10-10, HEAD `97600b74`,
checkout `bea 0.3.1`, macOS. When a ledger's relative `include` matches nothing
beside the ledger, the formatter looks for the same name in the caller's
working directory and adopts whatever it finds there. `format --check` then
reports a complete, formatted include graph for a ledger `bea check` rejects,
and `format -i` rewrites a file the ledger does not include. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
2026-01-01 open Assets:Cash USD
include "y2026.bean"
```

Do not create `/absolute/books/y2026.bean`. In an unrelated directory create
`/absolute/other/y2026.bean`:

```beancount
2026-01-02 open Assets:Unrelated USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/other`:

```sh
bea format --check /absolute/books/main.bean
bea --file /absolute/books/main.bean check
```

Actual: `format --check` exits 0 with

```text
checked: /absolute/books/main.bean
checked: /absolute/other/y2026.bean
All 2 file(s) are formatted.
```

and `--json` reports `"scanned": 2`, `"missing": []` with both paths in
`target.files`. `bea check` on the same ledger from the same directory exits 1
with `<load>:0: File glob "y2026.bean" does not match any files`. Repeated
twice from fresh directories; a relative spelling (`../books/main.bean`)
behaves the same.

With `/absolute/other/y2026.bean` deliberately misaligned (a posting indented
three spaces), `bea format -i /absolute/books/main.bean` from
`/absolute/other` exits 0, prints
`formatted: /absolute/other/y2026.bean` and `1/2 file(s) formatted.`, and the
unrelated file's bytes change (compared with a saved copy). The ledger's
missing include is never mentioned.

The same walk feeds the output guards: from that directory,
`bea --file /absolute/books/main.bean query "SELECT 1" -o y2026.bean` is
refused as `would overwrite the ledger it reads (/absolute/other/y2026.bean)`
although the ledger reads no such file.

Control: the identical commands from a working directory with no `y2026.bean`
report `missing include: "y2026.bean" (included by /absolute/books/main.bean)`
and exit 1, and `-i` changes nothing. Creating the file beside the ledger
makes `format --check` and `bea check` both pass from any directory.

Expected: `docs/USAGE.md` says `format --check` gates on the include graph —
"a named file stands for its whole include closure" and "an include that
matches nothing fails naming the directive" — and that `-i` "formats every
reachable file". Reachability is Beancount's: for a ledger file, a relative
include resolves against the including file's directory only
(`beancount/loader.py`, `cwd = path.dirname(filename)` then
`glob.glob(os.path.join(cwd, include_filename))`); the process working
directory is used only for ledgers parsed from a string. So the gate must fail
on this fixture from every directory, and `-i` must never touch a file the
loader would not read. A CI job that runs from the repository root, where a
same-named file happens to sit, is the realistic shape of the false green.

Cause: `cli/src/cli/output.py:228-241` (`_include_matches`) tries
`source.parent` and then `Path.cwd()` for every relative include. Its
docstring says the loader matches "first against the including file's
directory … then against the working directory"; the loader does the second
only for string sources. `walk_closure` (`:249-286`) therefore returns the
working-directory file as a member and records nothing missing, and
`cli/src/cli/commands/format.py:431-434` formats or checks every member. The
fallback arrived with the include-closure gate in `50fd1b28` (w1/m23/t003).

Fix: resolve a relative include against the including file's directory only
when the source is a file. Keep the working-directory base solely where the
input genuinely is a string with no file (the stdin filter does not walk
includes at all today). `ledger_closure` and `missing_includes` share the walk,
so the output-destination guards and `check`'s compatibility probe inherit the
correction; their existing refusals for real members must still hold. Correct
the docstring. No dependency or API change.

Dedupe: board search for working-directory include resolution, cwd fallback,
missing include and `format --check` finds w3/370 and w1/m23/t003 (the gate
itself), w1/159 (include-string spellings), w1/087 (walk cost) and w3/340
(`BEA_FILE` versus cwd discovery); none covers the include base.
`git log -S'Path.cwd()' -- cli/src/cli/output.py` shows only the introducing
commit.

Acceptance: from a directory holding a same-named file, the fixture's
`format --check` exits 1 naming the missing include, `--json` lists it under
`missing` with `scanned: 1`, `-i` leaves the working-directory file
byte-identical, and `query -o y2026.bean` there is no longer refused as a
ledger alias. A real include beside the ledger still passes from any
directory, including through a child file in a subdirectory. Real-command
regression tests run from a foreign working directory. Only macOS and the
checkout were exercised.

---

**Resolved 2026-10-12** — The frontend's include walk resolves a relative include against the including file's directory only, as Beancount's loader does for a ledger read from a file; the working-directory fallback is gone. From a directory holding a same-named file, the fixture's `format --check` exits 1 naming the missing include with `scanned: 1`, `format -i` leaves the stray file byte-identical, and `query -o y2026.bean` is no longer refused as a ledger alias. `docs/USAGE.md` states the base. Shipped in `b54004c0` (`cli`).

Regression tests run `format` and `query` from a foreign working directory: the missing include under absolute and `../books/main.bean` spellings (text and JSON), the unrewritten namesake under `-i`, the query destination, and a control where a real include reached through a child file in a subdirectory still passes with `scanned: 3`. Four fail with the fix reverted; the control passes either way. No existing test relied on the fallback. `make check-all` passed. Only macOS was exercised. w5/087 (symlinked root) is separate and still open.
