# `bea format --currency-column N` deletes a no-break space beside an amount and merges two accounts

**Major · cli · 30–40m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A posting whose account is followed by U+00A0 (typically pasted text) is
a distinct account to Beancount. `bea format -i -c 40` removes the
character, exits 0, and the two accounts become one — the formatter has
changed what the ledger means. Without `-c` the same file is correctly
refused as "would have changed more than whitespace". The trigger is
narrow and stock `bean-format -c` does the same; the owner may downgrade.
No product fix implemented.

Create disposable `/absolute/books/main.bean`, where line 4 has U+00A0
(bytes `c2 a0`) immediately after `Expenses:Food`:

```sh
printf 'plugin "beancount.plugins.auto_accounts"\n\n2024-01-02 * "Lunch"\n  Expenses:Food\xc2\xa0 12.50 USD\n  Assets:Cash          -12.50 USD\n\n2024-01-03 * "Dinner"\n  Expenses:Food   30.00 USD\n  Assets:Cash    -30.00 USD\n' > main.bean
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean check
bea -f main.bean query "SELECT account, sum(position) GROUP BY account ORDER BY account"
bea format -i -c 40 main.bean
bea -f main.bean query "SELECT account, sum(position) GROUP BY account ORDER BY account"
```

Actual: `check` exits 0. The first query shows three accounts:
`Assets:Cash -42.50 USD`, `Expenses:Food 30.00 USD` and `Expenses:Food`
+ U+00A0 `12.50 USD`. `format` exits 0 with `1/1 file(s) formatted.`; the
`c2 a0` bytes are gone. The second query shows two accounts, with
`Expenses:Food 42.50 USD`.

Controls: the same fixture with an ASCII space formats to the same two
accounts it started with. The U+00A0 fixture with plain `bea format -i`
(no `-c`) exits 1: `bean-format could not align …: it would have changed
more than whitespace. Nothing was written.` A worker saw U+3000 behave the
same, where formatting turned a failing `bea check` (unknown account) into
a passing one, and `-w`/`-W` refuse like the default.

Expected: formatting changes only spaces, tabs and line ends, or refuses
— which is what `bea` says about this very file without `-c`.
`docs/USAGE.md` describes stdout, `-o` and `-i` as one transformation.

Cause: `cli/src/bea_engine/ledger/formatting.py` passes the currency
column to upstream's aligner, whose currency-column branch returns before
its whitespace-only assertion. That assertion is the only guard:
`formatting.py:171-176` catches `AssertionError` and nothing else.
Upstream's pattern separates account, number and currency with `\s+`,
which also matches U+00A0, U+2000–200A, U+202F, U+205F and U+3000, while
Beancount's lexer treats those as part of the account. Foreign line
breaks are already shielded in this file; foreign spaces are not.

Fix: keep verbatim any line containing a whitespace character other than
space or tab, as is done for foreign line breaks; or compare
non-whitespace content after alignment for every width option and name
the offending line. The first also lets default mode format the rest of
the file. No dependency or API change.

Blast radius: `format -c/--currency-column` on stdout, `-o`, `-i`,
`--check` and `--dry-run`. `add` and `import` never pass a currency
column.

Dedupe: board search for nbsp, no-break, ideographic, U+3000 and
`currency-column` finds w1/done/081 (the same `\s` mismatch in the price
feed pattern) and w1/136 (shielded foreign line breaks, not spaces);
w3/done/331 and 348 concern other `-c` behaviour.

Acceptance: `bea format -i -c 40` on the fixture either leaves line 4's
bytes intact or exits 1 naming line 4, and the query shows three accounts
afterwards; the ASCII control is unchanged. A real-command regression
test covers U+00A0 and U+3000. Only macOS and the checkout were
exercised.

---

**Resolved 2026-10-13** — `cli/src/bea_engine/ledger/formatting.py` now keeps verbatim, and out of upstream's aligner, any line holding a whitespace character other than space or tab ahead of a comment or string, the same way lines with foreign line breaks were already shielded; the rule applies to every width option and to the alignment of appended entries. `bea format -c N` therefore no longer deletes a U+00A0 or U+3000 beside an amount and merges two accounts, and the default and `-w`/`-W` modes now align the rest of such a file instead of refusing it, which is the note's first suggested fix rather than a refusal naming the line. `cli/docs/USAGE.md` states the rule. The regression test `cli/tests/test_format_keeps_foreign_spaces.py` runs real commands over U+00A0 and U+3000 for `-c 40`, automatic widths and `-w`/`-W`, checking that stdout, `-o` and `-i` agree, the line's bytes survive, the other postings still align, `--check` converges and the query still shows three accounts, with an ASCII-space control and a control showing that a foreign space inside a trailing comment does not exempt a posting; six of its eleven cases fail with the fix reverted. Only macOS was exercised. `make check-all` passed. Shipped in `a2e9d5fd` (`cli`).
