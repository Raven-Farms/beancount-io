# `bea ask > out.txt` at a terminal shows nothing, writes the approval panel into the file, and a blind `y` Enter still approves the AI's write

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `0c12f2dc`, checkout `bea 0.3.1`, macOS 26.5.1. Simulation: local stub of the AI proxy; stdin and stderr on a PTY, stdout to a file.
USAGE: "Questions are written to stderr, so a redirected or piped stdout
carries only results… when stderr is not a terminal either… the command
fails with exit 2". The REPL draws everything, including the consent panel,
on stdout. Redirected, the user sees nothing while a write waits on their
keystroke. The w5/163 resolution records "the `ask` REPL still draws on
stdout and was not changed". No product fix implemented.

Stub: one `write_directive` (`2026-02-01 * "Cafe" "latte"`), then text.
`BEA_NO_ASK_HISTORY=1`.

```sh
bea -f /abs/main.bean ask > out.txt    # type "add a latte", then y Enter, then Ctrl-D
```

Actual: exit 0. The terminal shows nothing. `out.txt` holds the welcome, the
prompt and the `Confirm AI write` panel. The latte is appended to the
ledger.

Control: `bea ask q --print > out.txt` puts only the answer in the file.

Expected: when stdout is not a terminal, the REPL draws on stderr (or the
TTY), or it refuses with exit 2 naming `--print`. No write can be approved
through an invisible panel.

Cause: `cli/src/cli/commands/ask.py:80` chooses the REPL on `ctx.no_input`
(stdin only); `cli/src/cli/ask/repl.py:50` `Console()` and the prompt_toolkit
session and `Application` draw on stdout.

Fix: as above.

Dedupe: w5/163 (done) listed this surface and left it unchanged; no open note.

Acceptance: with stdout redirected, the panel appears on the terminal (or the
command exits 2), and `out.txt` holds no prompt or panel. A PTY test pins it.

---

**Resolved 2026-10-17** — Shipped in `d18e2bf5` (`cli`). `bea ask` (`cli/src/cli/commands/ask.py`) now refuses the interactive session when stdout is not a terminal, exit 2, before any credential check or model call: `bea ask's interactive session draws on the terminal, and stdout is redirected, so its write-approval panel would not be seen. Ask one question with --print …`. `RunContext.stdout_is_a_terminal` (`cli/src/cli/context.py`) is the new public check. Of the note's two options this is the refusal, chosen over redrawing the whole session on stderr. `--print` and non-interactive runs are unchanged. USAGE says so in the ask section.

`tests/test_ask_redirected_stdout.py` runs `bea ask` on a PTY with stdout redirected to a file. It pins exit 2, the message on the terminal, an empty file and no requests. Without the fix the session hangs, drawing nothing on the terminal. `tests/test_ask_blank_question.py` now fakes a terminal stdout as well as stdin for its in-process session. `make check-all` passed.
