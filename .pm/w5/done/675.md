# `query --source`, the interactive query shell and doctor's compat path skip the `BEA_ENGINE_PYTHON` check: `/usr/bin/true` gives exit 0 with no output, `/usr/bin/false` exit 1 silent, Python 3.9 exit 2 with Python's usage text (gap in w5/309)

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-17, HEAD `6d74be10`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE: the engine overrides "are checked before use: … a program that is not a
Python able to load the engine … fails with a message naming the variable".
The helper path checks them. The streamed and captured engine paths return
the child's status unchanged, so a broken override passes silently. No
product fix implemented.

Any valid ledger (`bom.bean` with a UTF-8 BOM for doctor's compat path).

```sh
BEA_ENGINE_PYTHON=/usr/bin/true bea query --source /abs/q.bean 'select account'
BEA_ENGINE_PYTHON=/usr/bin/false bea query --source /abs/q.bean 'select account'
BEA_ENGINE_PYTHON=/usr/bin/true bea doctor lex /abs/bom.bean
BEA_ENGINE_PYTHON=/usr/bin/true bea -f /abs/q.bean query            # interactive, under a PTY
```

Actual: `/usr/bin/true` exits 0 with empty stdout and stderr (query, doctor and
the shell); `/usr/bin/false` exits 1 with empty stderr; a Python 3.9
interpreter exits 2 with `Unknown option: -P` and Python's usage text.

Control: `BEA_ENGINE_PYTHON=/usr/bin/true bea list open` exits 1 with
`BEA_ENGINE_PYTHON=… names an environment that cannot run the Beancount
engine…`.

Expected: the same exit-1 message on every engine path.

Cause: `run_engine_argv` (`cli/src/cli/engine/launch.py:72`) and `capture_engine`
(`:325`) go through `_spawn` (`:748-785`), returning the status; only `_parse`
calls `_refuse_unusable_engine` (`:655`).

Fix: probe the override (or damaged engine) before spawning on these paths,
or when the child exits nonzero without output.

Dedupe: w5/269, 309 and 481 (done) cover the helper and native paths; w5/647
(open) covers `engine status`.

Acceptance: the commands above exit 1 naming the variable. Tests pin them.
