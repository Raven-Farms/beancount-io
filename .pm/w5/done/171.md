# `list note` drops a note's tags and links

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
Beancount notes can carry tags and links, like documents. `bea list
note` shows neither, in the table or in JSON, so they cannot be seen or
scripted against. No product fix implemented.

Create disposable `/absolute/books/main.bean` (with an existing
`receipts/r.pdf`):

```beancount
2024-01-01 open Assets:Bank
2024-01-05 note Assets:Bank "called the bank about the fee" #dispute ^case-17
2024-01-05 document Assets:Bank "receipts/r.pdf" #dispute ^case-17
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`. The fixture passes `bea check`.

```sh
bea --json -f main.bean list note
bea -f main.bean list document
```

Actual: the note row is `{"date": "2024-01-05", "account":
"Assets:Bank", "comment": "called the bank about the fee", "meta": {}}`
— no tags or links. A worker confirmed the text table has only DATE,
ACCOUNT and COMMENT, and that stock Beancount loads the note with tag
`dispute` and link `case-17`.

Control: `list document` shows `#dispute` and `^case-17` in TAGS and
LINKS columns for the same line shape.

Expected: `list note` reports a note's tags and links the way `list
document` does.

Cause: `cli/src/bea_engine/ledger/models.py` (`NoteDirective` has no
`tags`/`links`), `reader.py` (the note lister never reads them) and
`cli/src/cli/commands/list.py` (no columns).

Fix: add sorted `tags`/`links` to the note model and listing, and the two
table columns. Whether `add note` should accept them is a separate owner
decision. The JSON row gains two fields.

Blast radius: `list note`, text and JSON.

Dedupe: board search for `list note` with tag and link finds w3/done/316
(document tags and links missing from the table, fixed); nothing covers
notes.

Acceptance: the note row carries `"tags": ["dispute"]` and `"links":
["case-17"]` and the table shows both; a note without them is unchanged
apart from empty fields. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — `bea list note` now reports a note's tags and links the way `list document` does: `NoteDirective` in `cli/src/bea_engine/ledger/models.py` gained `tags` and `links`, `list_notes` in `cli/src/bea_engine/ledger/reader.py` fills them sorted, and the note table in `cli/src/cli/commands/list.py` gained TAGS and LINKS columns. The regression test `cli/tests/test_list_note_tags_links.py` pins the JSON row (sorted `tags`/`links`), the table columns and cells, a note without tags or links (unchanged apart from the two empty fields), and the document control for the same line shape; both of its cases fail with the fix reverted. Because the model is shared with the write path, the directive echoed by `add note --json` also gains empty `tags` and `links`; `add note` still does not accept them, which stays a separate owner decision. Only macOS was exercised. `make check-all` passed. Shipped in `4d60b9f2` (`cli`).
