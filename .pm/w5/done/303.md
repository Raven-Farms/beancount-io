# `bea import`'s "Run: bea add open …" remedy drops the `--file` the import used, so the pasted line is refused or opens the account in a different ledger

**Minor · cli · 15–25m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
The walkthrough in `docs/IMPORTING.md` imports with
`bea --file books/main.bean import …` from the directory above the ledger.
When a row is blocked on an unopened account, the preview says
`Run: bea add open --account … --date … -c USD.`, with no `--file`. The
pasted line then goes through cwd discovery instead of the ledger being
imported. With no ledger in the cwd it is refused (exit 2). If the cwd has
its own `main.bean`, or `BEA_FILE` names another ledger, it exits 0 and
opens the account in that other ledger, and the import stays blocked. No
product fix implemented.

Create disposable `/absolute/work/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-08-01 open Assets:Checking USD
2026-08-01 open Expenses:Uncategorized
2026-08-01 open Equity:Opening
```

`/absolute/work/statement.csv`:

```text
Date,Payee,Narration,Amount
2026-08-02,Whole Foods,groceries,-20.00
```

`/absolute/work/rules.toml`:

```toml
[[rule]]
match = "whole foods"
account = "Expenses:Groceries"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/work`.

```sh
bea --file books/main.bean import statement.csv --csv date=Date,amount=Amount,payee=Payee,narration=Narration --account Assets:Checking --rules rules.toml
bea add open --account Expenses:Groceries --date 2026-08-02 -c USD   # the line the preview printed
```

Actual:

- The preview exits 0 with `Row 1: Account 'Expenses:Groceries' is not
  open. Run: bea add open --account Expenses:Groceries --date 2026-08-02
  -c USD.` The JSON `reason` has the same text.
- The pasted line exits 2 with `No ledger file at 'main.bean' (from the
  working directory). … pass --file books/main.bean.`

With an unrelated `main.bean` in `/absolute/work`, the pasted line instead
exits 0 with `Added 1 open to /absolute/work/main.bean.`, and rerunning the
import still shows row 1 `blocked`. Reproduced in three fresh runs.

Control: `bea --file books/main.bean add open --account Expenses:Groceries
--date 2026-08-02 -c USD` unblocks the row. Two other recipes already
carry the ledger: the `--into` hint (`cli/src/bea_engine/ledger/write.py:1016`)
prints `bea --file <root> <command> --into …`, and `init` adds `--file` to
its next command (`cli/src/cli/commands/init.py:199`).

Expected: `docs/IMPORTING.md` says blocked rows name "the `bea add open`
line that fixes it … so running it once unblocks them all". A line printed
to be run should act on the ledger being imported, wherever it is pasted.

Cause: `_blocked_reason` (`cli/src/bea_engine/importing.py:970-983`)
formats `bea add open --account … --date …` without the root ledger. The
engine knows the resolved file but does not pass it into the remedy.

Fix: when the ledger was not found by cwd discovery, prefix the remedy
with `bea --file <root>`. Quote it with `shlex.quote`, and print it
relative to the cwd if it is under the cwd, otherwise absolute. The
currency-mismatch remedy in the same function needs the same change. No
dependency or API change.

Blast radius: every blocked-row remedy from `import`, CSV and Python
importer alike, in preview and apply, in the text output and the JSON
`reason`. Agents that run `bea --file … import` from a repository root
and paste the hint are the main users.

Dedupe: searched `.pm/**` (including `done/`) for "add open", "Run:",
"paste", "--file" and "working directory", each combined with import or
hint.

- w3/386 and w5/154 fix which remedy is printed.
- w5/195 quotes the remembered-settings echo.
- w5/219 is the no-ledger hint that partly rescues the first case.
- w5/295 is about discovery of a dangling `main.bean`.

None of them covers the remedy dropping the ledger.

Acceptance: from `/absolute/work`, the printed remedy is
`bea --file books/main.bean add open --account Expenses:Groceries --date
2026-08-02 -c USD`, and pasting it unblocks row 1 in `books/main.bean`,
with or without a decoy `main.bean` in the cwd. A run from inside `books/`
may keep the short form. A real-command regression test pastes the
remedy back. Only macOS and the checkout were exercised.

Same class, found by a later sweep the same day: the empty-BQL-window
remedy `run: bea list transaction --from-date …`
(`cli/src/bea_engine/query.py:1624`) also omits the `--file` the query
used. Fix it with the same helper.

---

**Resolved 2026-10-14** — A new `bea_command(file)` (`cli/src/bea_engine/ledger/text.py`) prints `bea --file <ledger>` for a remedy meant to be pasted: relative when the ledger is under the cwd, absolute otherwise. It keeps a bare `bea` only when cwd discovery would already find that ledger (and `BEA_FILE` is unset). The import's blocked-row `add open` line (`_blocked_reason` in `importing.py`) and the empty-BQL-window `list transaction` hint (`query.py`) both use it. The currency-mismatch reason prints no command, so it is unchanged. From `/absolute/work`, the remedy is `bea --file books/main.bean add open --account Expenses:Groceries --date 2026-08-02 -c USD`; pasting it unblocks the row, with or without a decoy `main.bean`, and from inside `books/` the short form stays. IMPORTING.md says so. `cli/tests/test_import_remedy_keeps_file.py` pastes the remedy back in both cases and pins the short form and the query hint; the 3 remedy cases fail with the fix reverted. 17 existing import tests pinned the bare `bea add open` prefix and were updated to the new form. Only macOS was exercised. `make check-all` passed. Shipped in `093a5c00` (`cli`).
