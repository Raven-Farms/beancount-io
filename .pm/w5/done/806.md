# A Fava `collapse-pattern` or `insert-entry` regex that raises `OverflowError` or `RecursionError` blocks `balance` and every report (exit 1), though `check` passes; the recursion case is misreported as "Account nesting is too deep" for a 2-level account (gap in w5/091)

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-17, HEAD `f28d154ff`, checkout `bea 0.3.1`, macOS 26.5.1. Gap in w5/091 (done).
w5/091's fix says no `fava-option` value should be able to raise out of
option parsing, and that a ledger `bea check` accepts can be reported on. bea
ignores `collapse-pattern` and `insert-entry`, but still parses them. No product
fix implemented.

`ovf.bean`:

```
option "operating_currency" "USD"
2000-01-01 custom "fava-option" "collapse-pattern" "Expenses:.{4294967296}"
2024-01-01 open Assets:Checking USD
2024-01-01 open Equity:Opening
2024-01-02 * "x"
  Assets:Checking  5 USD
  Equity:Opening
```

`rec.bean` is the same with the pattern replaced by 1000 `(` followed by 1000
`)`.

Actual:
- `bea -f /abs/ovf.bean balance` exits 1 with `Error: OverflowError: the
  repetition number is too large.`. `--json report income-statement` gives
  category `validation`. `check`, `list` and `query` exit 0.
- `bea -f /abs/rec.bean balance` exits 1 with `Account nesting is too deep to
  report: 'Assets:Checking' is 2 levels deep.`
- Siblings: `report -a 'Assets:.{4294967296}'` and `treeify --pattern
  'A.{4294967296}'` exit 1 with the raw OverflowError, where `-a 'Assets:('`
  exits 2 (hunter's runs).

Control: `collapse-pattern "(unclosed"` (an ordinary `re.error`) is ignored, and
`balance` exits 0.

Expected: the bad option is collected like any other and ignored, so reports
exit 0. A malformed `-a` or `--pattern` exits 2.

Cause:
- `cli/src/fava/core/fava_options.py:115` and `:142` catch only `re.error`.
- `parse_options` (`:198`) catches `IndexError`, `TypeError` and `ValueError`.
- Every `RecursionError` is mapped to `too_deep`
  (`cli/src/bea_engine/report.py:108`, added by w5/209).

Fix: treat `OverflowError`, `RecursionError` and `MemoryError` from `re.compile`
as an invalid regex everywhere. Have `too_deep` apply only when an account is
actually deep.

Dedupe: w5/091 (done) sets the invariant, and w5/209 (done) added the
mapping; w1/018 covers `re.error` only.

Acceptance: both fixtures report normally; the `-a`/`--pattern` siblings exit 2.

---
**Resolved 2026-10-20** — `re.compile` blowups (`OverflowError`, `RecursionError`, `MemoryError`) are collected as invalid patterns at Fava option setters and every pattern-safety helper, so the bad options are ignored like any other invalid regex and reports exit 0; the `-a`/`--pattern` siblings exit 2, and the `too_deep` gate only refuses genuinely deep (100+) accounts. Shipped in `faa7fd7d5` (`cli`).
