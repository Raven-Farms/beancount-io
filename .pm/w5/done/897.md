# Preserve an explicitly selected acquisition date in import identity

**Major · cli · 45–60m · A1.** Two same-day sales selecting different dated
lots get the same generated ID. Importing the second statement silently skips
its sale, cash and gain, even with `--duplicates include`. Holdings stay at
3 HOOL instead of 2; `check` still passes. This is a missed explicit-selector
case after completed [349](./done/349.md), whose resolution omits lot dates
because booking fills them in. The importer here already states both dates;
they identify different lots. No product fix implemented.

Real CLI QA 2026-10-20, checkout `b70e52a67`, `bea 0.3.1`, Darwin 25.5.0
arm64, frontend Python 3.13.3, managed engine Python 3.12 with Beangulp
already enabled. Reproduced twice from pristine synthetic ledgers, separate
processes, closed stdin, isolated absolute BEA_CONFIG_DIR/XDG_CACHE_HOME,
BEA_NO_UPDATE_NOTIFIER=1, no inherited BEA_FILE/BEA_TOKEN.

Create `/absolute/qa/main.bean`:

```beancount
2024-01-01 open Assets:Broker:HOOL HOOL "STRICT"
2024-01-01 open Assets:Cash USD
2024-01-01 open Income:Gains USD
2024-01-02 * "Buy first lot"
  Assets:Broker:HOOL 2 HOOL {100 USD}
  Assets:Cash -200 USD
2024-01-03 * "Buy second lot"
  Assets:Broker:HOOL 2 HOOL {100 USD}
  Assets:Cash -200 USD
```

Create `statement-a.txt` containing `2024-01-02|` and `statement-b.txt`
containing `2024-01-03|`. Create `importers.py`:

```python
import datetime
from decimal import Decimal as D
from beancount.core import data, amount, position

class Imp:
    def identify(self, file):
        return str(file).endswith('.txt')
    def account(self, file):
        return 'Assets:Broker:HOOL'
    def extract(self, file, existing_entries=None):
        rows = []
        for line in open(file):
            lotdate, label = line.strip().split('|')
            cost = position.CostSpec(
                D('100'), None, 'USD',
                datetime.date.fromisoformat(lotdate), label or None, False)
            postings = [
                data.Posting('Assets:Broker:HOOL',
                    amount.Amount(D('-1'), 'HOOL'), cost,
                    amount.Amount(D('150'), 'USD'), None, None),
                data.Posting('Assets:Cash', amount.Amount(D('150'), 'USD'),
                    None, None, None, None),
                data.Posting('Income:Gains', amount.Amount(D('-50'), 'USD'),
                    None, None, None, None),
            ]
            rows.append(data.Transaction(
                data.new_metadata(str(file), 1), datetime.date(2024, 2, 1),
                '*', 'Broker', 'Sold HOOL', frozenset(), frozenset(), postings))
        return rows

CONFIG = [Imp()]
```

From `/absolute/qa`, with the environment above:

```sh
bea --json --no-input -f /absolute/qa/main.bean import statement-a.txt --config importers.py --duplicates include --apply
bea --json --no-input -f /absolute/qa/main.bean import statement-b.txt --config importers.py --duplicates include
bea --json --no-input -f /absolute/qa/main.bean import statement-b.txt --config importers.py --duplicates include --apply
bea --json -f /absolute/qa/main.bean query "SELECT sum(number) WHERE account='Assets:Broker:HOOL'"
bea --json -f /absolute/qa/main.bean check
```

All exit 0 with empty stderr. A writes 1 with
`import-id: "csv:sha256:335ae2f5a242ce17"` and the January 2 selector.
B's rendered entry correctly contains `{100 USD, 2024-01-03}`, but its
SOURCE AMOUNT drops the date, and its generated ID is identical. Preview
reports `ready: 0, duplicates: 1`, with reason
`import-id csv:sha256:335ae2f5a242ce17 is already in the ledger.` Its match
entry visibly selects January 2. Apply writes 0; ledger bytes are unchanged.
The query returns `3`, not the independently calculated `4 - 1 - 1 = 2`.
The second 150 USD proceeds and -50 USD gain are also absent.

Nearby controls, each twice:

- Same acquisition date in both statements: correct exact duplicate, writes 0,
  holdings 3.
- Distinct lot labels (`"first"`, `"second"` on purchases and selectors): B
  writes 1, holdings 2, fresh check passes.
- Both dated rows in one export: writes 2, holdings 2, fresh check passes;
  repeating that export writes 0. The occurrence suffix masks the collision
  only while both rows arrive together.

Cause: `cli/src/bea_engine/importing.py:1302–1339` drops `CostSpec.date`
from `_lot_stated` and `_lot`; `_lot_text` at 1367–1380 therefore omits it.
`_hash_import_ids` at 2417–2447 hashes equal amounts for these distinct
selectors. `_legs`/`_lots_agree` at 1385–1399 also cannot distinguish the
dates. Caller search finds the same rendering in SOURCE AMOUNT (2588),
canonical/legacy hash generation and matching; ordinary CSV postings carry
no cost. The original date omission landed with `9669be9d7` (349), and no
later explicit-date handling exists on current main. This is CLI identity
logic: both lots book correctly when actually submitted together.

Fix: retain explicitly supplied acquisition dates in lot identity, matching
and preview amounts. Keep an unstated date open so booking-supplied dates do
not break legitimate re-imports. Preserve lookup compatibility with older
date-less IDs, but content-check a date-less hit against an explicitly stated
selector before treating it as exact; do not let a lossy old key silently
consume a different lot. Update the documented hash contract with this case.

Dedupe: searched all `.pm` states for acquisition/lot/cost dates,
`_lot_stated`, `_lot_text` and import identity, and reviewed every active
milestone. Completed 349 covers different cost numbers/labels/prices and
records the date omission; completed 467/603 handle open costs and lot
splitting. Open [896](./896.md) is compatible multi-fill partitioning, not
this lost selector. Completed 465/561 cover query CSV cost rendering.
Customer trade/opening-lot work in w2/m45 and w2/m50 requires retaining true
acquisition dates, but does not repair CLI import matching. New follow-up to
349; no overlapping open repair or deployment lag found.

Acceptance: the two statements preview as distinct rows and both apply,
holdings 2, cash -100 and gains -100 USD, check clean; repeating either writes
0. Keep the three working controls above and open-cost re-import coverage.
Exercise older date-less IDs without silently skipping a different explicit
lot. Source and capture evidence retained locally in ignored pass5
`repro_lot_date_identity.py`, `lot-date-results.json`, and per-command
captures. Only macOS/checkout tested; no hosted data or optional installs.

**Resolved 2026-10-22** — an acquisition date an importer states on a cost (a `CostSpec` date or a resolved `Cost`) is now part of the lot: it shows in the preview source amount and in the generated import ID, and two sales selecting different dated lots are two rows (holdings 2, not 3). The date-less spelling stays as a lookup-only legacy key, so rows written before still match through the content check without consuming a different dated lot; an unstated date stays open. `cli/tests/test_import_lot_date_identity.py` runs the two-statement journey, the same-lot duplicate and the legacy-ID case and fails without the fix; `test_import_filing_root_account.py` now expects the dated amount; shipped in the commit that moves this note (`cli`).
