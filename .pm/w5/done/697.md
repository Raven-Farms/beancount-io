# Opening balances that sum to zero write `Equity:OpeningBalances -0 USD` (regression from w5/310)

**Trivial · cli · 5m · A1.** Real CLI QA, 2026-10-17, HEAD `101b89e3`, checkout `bea 0.3.1`, macOS 26.5.1. Regression from w5/310 (done, `dd8e4a53`).
w5/310 replaced `-sum(...)` with `total.copy_negate()` to keep the equity leg
exact. `copy_negate()` turns a zero total into `-0`, which unary minus did not.
No product fix implemented.

```sh
bea --no-input init z.bean --currency USD --date 2026-08-01 --opening-balance "Assets:Cash 20" --opening-balance "Liabilities:CreditCard -20"
```

Actual: exit 0. The ledger ends with:

```
2026-08-01 * "Opening balances"
  Assets:Cash              20 USD
  Liabilities:CreditCard  -20 USD
  Equity:OpeningBalances   -0 USD
```

`check` passes; the JSON listing shows `"0"`.

Expected: no `-0`. Either leave the zero equity leg out or write `0 USD`.

Cause: `cli/src/bea_engine/initiating.py:104` formats `total.copy_negate()`.

Fix: write the equity leg only when the total is nonzero, or normalize a zero
total to `0`.

Dedupe: w5/310 (done) is the parent; w5/217 (done) covers report rounding.

Acceptance: the fixture writes no `-0`. A test pins it next to w5/310's.
