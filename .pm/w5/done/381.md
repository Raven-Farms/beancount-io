# Read commands silently keep only the last of a repeated single-valued option: `list transaction -a Food -a Rent` lists only Rent rows, and `report -t 2026-01 -t 2026-02` reports February

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
[w5/238](./done/238.md) made `add` refuse two different values for one
single-valued option with exit 2, naming both. [311](./311.md) covers
`import` and `init`. The read commands still use plain Typer options,
which silently keep the last value.

A user or agent who writes `-a Food -a Rent` expecting OR, or AND as
with `--search`, gets only the Rent rows with exit 0. So does `-t … -t
…`, `--limit 1 --limit 3`, `--from-date` given twice, or `-x` given
twice. No product fix implemented.

Use any USD ledger with `Expenses:Food`, `Expenses:Rent` and
`Assets:Cash`, and one Food and one Rent transaction in January 2026.
Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, and closed stdin.

```sh
bea -f /absolute/books/main.bean list transaction -a Food -a Rent
bea --json -f /absolute/books/main.bean report income-statement -t 2026-01 -t 2026-02
bea -f /absolute/books/main.bean list transaction --from-date 2026-01-01 --from-date 2027-01-01
bea -f /absolute/books/main.bean balance -x units -x USD
```

Actual: every command exits 0 with no warning.

- `-a Food -a Rent` lists only the rent row.
- The income statement covers `2026-02-01 … 2026-03-01`.
- The doubled `--from-date` keeps 2027 and prints "No transactions
  found."

Reproduced by the hunter twice and by me once.

Control: `add transaction … --date 2026-01-07 --date 2026-01-08` exits 2
with `Conflicting values for one option: --date '2026-01-07' and --date
'2026-01-08'`.

Expected: `docs/USAGE.md` gives the rule for single-valued options: two
different values are refused "with exit **2** naming both … instead of
keeping the last". The list options table marks only `--search`, `--tag`
and `--link` as repeatable. The read commands should refuse conflicting
repeats in the same way.

Cause: the refusal lives only in `_SingleValueCommand`
(`cli/src/cli/commands/add.py:59-65`). `list`, `report`, `balance` and
`query` register plain Typer commands.

Fix: move `_SingleValueCommand` to a shared module and register the read
commands with it, keeping `--search`, `--tag` and `--link` repeatable.
No dependency change.

Blast radius: `list *`, `report *`, `balance` and `query` options such as
`-a`, `-t`, `--from-date`, `--to-date`, `--limit`, `-x`, `-i` and
`-c`, in text and JSON. Generated command lines often repeat a flag.

Dedupe: searched `.pm/**`, including `done/`, for "Conflicting values",
repeated option, and `_SingleValueCommand`. w5/238 covers `add`, 311
covers `import`/`init`, and 340 covers malformed filter values. None
covers the read commands.

Acceptance: each command above exits 2 naming both values. Repeated
`--search`, `--tag` and `--link` still work. Repeating the same value
twice is accepted, as in `add`. A test covers `list`, `report` and
`balance`.

**Resolved.** These commands are now registered with the shared `cli.single_value.SingleValueCommand`:

- every `list` subcommand (`list.py`);
- the four `report` subcommands (`report.py`);
- `balance` and `query` (`main.py`).

It is the same class `add`, `init` and `import` use. A repeated scalar option with two different values exits 2 with `Conflicting values for one option: -a 'Food' and -a 'Rent'. Pass it once.`, in text and JSON. An identical repeat is accepted. Multi-value options (`--search`, `--tag`, `--link`) are untouched, because the parser checks only `store` options. `docs/USAGE.md` extends the single-valued rule to the read commands and points at `-a 'Food|Rent'` for either account.

`tests/test_read_commands_single_value.py` covers six conflicts in text and JSON, all exit 2 naming both values:

- `list -a`, `--from-date` and `--limit`;
- `report -t`;
- `balance -x`;
- `query --format`.

It also has four controls that still pass: the same `-a` twice, repeated `--search`, repeated `--tag`, and the same `-t` twice. With the fix stashed, the 12 conflict cases fail.
