# A misspelled `fiscal-year-end` option name (`fiscal-year-ends`, `fiscalyearend`) silently makes `-t FY2026` the calendar year, with exit 0 and no warning, where Fava flags the unknown option (gap in w5/147)

**Minor · cli · 5–10m · A1.** Real CLI QA, 2026-10-17, HEAD `f28d154ff`, checkout `bea 0.3.1`, macOS 26.5.1. Gap in w5/147 (done).
w5/147's acceptance: a fiscal filter must never silently present the calendar
year as `FY2026`. bea honors only this one Fava option, so a typo in its name
is the main way it goes wrong. No product fix implemented.

`typo.bean` has `custom "fava-option" "fiscal-year-ends" "06-30"`, a 31.00 USD
food expense on 2025-12-31 (in FY2026 for a June year end), and a 10.00 USD
one on 2026-10-01.

```sh
bea -f /abs/typo.bean report income-statement -t FY2026
```

Actual: exit 0, `Income Statement — 2026-01-01 through 2026-12-31`, Food `10.00
USD`, and empty stderr. JSON shows `ledger_errors: []`, and `check --json` is
`{"valid": true, "errors": []}`. `fiscalyearend` and `"fiscal year end"` behave
the same (hunter's runs). The vendored Fava parser records `Unknown option
'fiscal_year_ends'`, but bea drops it.

Control: the correctly spelled option reports `2025-07-01 through 2026-06-30`,
Food `31.00 USD`.

Expected: when `--time` uses a fiscal spelling and an unknown `fava-option` key
looks like `fiscal-year-end`, warn on stderr naming its line, or refuse as
for an invalid value.

Cause: `_require_fiscal_year_end` (`cli/src/bea_engine/report.py:519`) keeps only
option errors whose key is exactly `fiscal_year_end`.

Fix: surface near-miss unknown keys when a fiscal period is requested.

Dedupe: w5/147 (done) covers invalid values only, and leaves other option
errors unsurfaced by design; this is a judgment call.

Acceptance: the fixture warns (or refuses) naming line 2.

---

**Resolved 2026-10-20** — when no `fiscal-year-end` is declared and `--time` uses a fiscal spelling, `_require_fiscal_year_end` now treats an unknown-option error whose name is a near miss of it (letters and digits only, case-folded, `SequenceMatcher` ratio ≥ 0.8: `fiscal-year-ends`, `fiscalyearend`, `fiscal year end`, `Fiscal-Year-End`) as the problem. The period is refused with exit 1: `The ledger's fiscal-year-end option looks misspelled, so the fiscal period in --time 'FY2026' is undefined.`, with the detail `…/typo.bean:2: Failed to parse fava-option entry: Unknown option … It looks like fiscal-year-end, the only Fava option bea reads.` Other unknown options and calendar periods are unaffected. USAGE says so. `tests/test_report_fiscal_option_misspelled.py` covers the four spellings (all fail at HEAD) and the controls. Gate note: gated as one stack with w5/808 (one `make check-all`, 9825 passed, no failures; each item shipped as its own commit). Shipped in `1ee7d673f` (`cli`)
