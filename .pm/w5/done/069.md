# Format check and in-place formatting fail on every ledger with a managed price include

**Major · cli · 30–45m · A1/A2.** Real CLI QA, 2026-10-10, HEAD `97600b74`,
checkout `bea 0.3.1`, macOS. A managed price include is the documented one-line
way to value holdings, and `bea format --check` is the documented CI gate. The
two cannot be used together: the formatter reads the URL as a file glob,
reports it as a missing include, and exits 1 — on an already formatted ledger,
with or without network, signed in or not. `format -i` exits 1 the same way
even when it has nothing to change. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
include "https://beancount.io/prices/BTC-USD"

2026-01-01 open Assets:Cash USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`:

```sh
bea format main.bean --check
bea format -i main.bean
```

Actual, `--check`: exit 1, empty stdout, stderr

```text
missing include: "https://beancount.io/prices/BTC-USD" (included by /absolute/books/main.bean)
Error: 1 include(s) are missing. Fix the files above and re-run.
```

Actual, `-i`: exit 1,

```text
Error: 0 file(s) formatted; 1 include(s) are missing. Nothing was written to the failed files.
  unchanged: /absolute/books/main.bean
  missing include: "https://beancount.io/prices/BTC-USD" (included by /absolute/books/main.bean)
```

Both were repeated twice; the file hash is unchanged throughout, so the file
is already formatted and nothing is "missing" that the user could add.
`bea --no-input format main.bean --check` — the exact line in
`cli/docs/examples/ledger-check.yml:35` — fails identically, and `--json`
carries the URL under `error.result.missing`. `format --dry-run` exits 0 but
prints the same `missing include` line. On an unformatted ledger with the
include, `-i` rewrites the file and still exits 1.

Controls: replacing the URL line with `include "prices.bean"` beside a real
`prices.bean` makes `--check` and `-i` exit 0 once formatted. Plain
`bea format main.bean` (stdout filter) exits 0 with the URL line intact. A
genuinely absent local include is still correctly reported as missing.

Expected: `docs/USAGE.md` Managed price includes says the line works "in every
command" and lists `check`, `list`, `query`, `report`, `import` and write
validation as seeing the resolved prices; its `format --check` section says an
include "that matches nothing fails naming the directive". A registered price
URL is not a file glob and has no file to format, so it must not count as a
missing include: an aligned ledger containing one passes `--check`, and `-i`
exits 0 after formatting it. Formatting never needs the network or a login, so
this should hold offline and signed out. Exit 0 here is what lets a ledger that
adopted live prices keep the bundled GitHub Actions gate.

Cause: `cli/src/cli/output.py:249-286` (`walk_closure`) resolves every
`include` string through `_include_matches` (`:228-241`), which globs it against
the including file's directory and the working directory; a URL matches no
file, so `:285` records a `MissingInclude`. `cli/src/cli/commands/format.py:434`
collects those, `:225` fails `--check` and `:188` fails `--in-place` whenever
the list is non-empty. The frontend already recognizes URL includes elsewhere:
`cli/src/cli/commands/check.py:16` (`_URL_INCLUDE_RE`) routes such a closure
through the helper instead of native bean-check.

Fix: classify an `http(s)://` include target as a remote include in the
closure walk — neither a member file nor a missing one — so `format --check`,
`--dry-run`, `-i` and their JSON results ignore it. Keep real unmatched local
includes failing exactly as today, and keep the `-o` ledger-alias guards that
share `walk_closure` unchanged (a URL can never alias an output path). Whether
a URL outside the managed allowlist is acceptable stays the loader's decision,
reported by `bea check`; the formatter should not judge it. Add the managed
include to the ledger-check rehearsal table in
`cli/docs/examples/ledger-check.md`. No dependency or API change.

Blast radius: `walk_closure` also feeds `ledger_closure` (output-destination
guards, `check`'s compatibility probe) and `missing_includes`; only `format`
turns the missing list into a failure. Directory walks (`bea format --check .`)
fail the same way for any walked file that carries the include.

Dedupe: board search for missing include, managed price, URL include and
`format --check` finds w3/370 and w1/m23/t003 (which introduced the include
gate for broken local graphs), w1/159 (include-string spellings) and the
managed-price items w3/433 and w3/436 (message text, export overwrite); none
covers a URL include in the formatter. `git log -S MissingInclude -- cli` shows
no URL handling.

Acceptance: an aligned ledger whose only unusual line is a managed price
include exits 0 for `format --check`, `--dry-run` and `-i`, offline and signed
out, with no `missing include` line and an empty `missing` list in JSON; an
unaligned one is rewritten by `-i` with exit 0; a missing local include beside
the URL still fails naming only the local one. Real-command regression tests
cover a named file, a directory walk and an include reached through a child
file. Only macOS and the checkout were exercised; no price was fetched.

---

**Resolved 2026-10-12** — The frontend's include-closure walk no longer treats an `http(s)://` include as a file glob, so a managed price include is neither a member file nor a missing one. An aligned ledger carrying one passes `bea format --check`, `--dry-run` and `-i` with exit 0, no `missing include` line and an empty `missing` list in JSON; a misaligned one is rewritten by `-i` with exit 0. Shipped in `a392b306` (`cli`).

Regression tests through the real `format` command cover a named file, a directory walk and an include reached through a child file across `--check`, `--dry-run`, `-i` and `--json`, an unaligned ledger formatted in place, and a missing local include beside the URL that still fails naming only the local one. Five fail with the fix reverted. `docs/USAGE.md` states the rule and `docs/examples/ledger-check.md` records that the gate accepts such a ledger from the release after 0.3.1, checked on a source checkout rather than a published build. `make check-all` passed. No price was fetched, and only macOS was exercised.
