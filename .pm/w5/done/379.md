# `bea price refresh` failure details read "….; serving revision none": a full stop followed by a semicolon, for every 404, 403, 5xx and auth failure

**Trivial · cli · 5m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1. **Simulation:** the 404 came from a localhost feed origin.

The managed-price failure messages end in a full stop, and the refresh
detail appends `; serving revision …` straight after them. w3/387 and
w3/433 cleaned up doubled full stops in this same failure text on other
paths, but missed this join. No product fix implemented.

Use a ledger that includes `http://127.0.0.1:<port>/prices/NOPE-USD`
(served as 404) plus valid aliases, with `MANAGED_PRICE_ORIGINS` set to
that origin. Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME and closed stdin.

```sh
bea -f /absolute/M/main.bean price refresh
bea --json -f /absolute/M/main.bean price refresh
```

Actual: exit 1. The detail reads `NOPE-USD: fetch failed (not-found):
HTTP 404: unknown price source. Choose an available pair at
https://beancount.io/live-prices.; serving revision none`, and the JSON
`error.details` is the same. The 403, 5xx and auth messages
(`managed_prices.py:336-351`) render the same way. Reproduced twice by
the hunter. I confirmed the join in the code.

Control: timeout and redirect messages have no final full stop and read
cleanly.

Expected: clean punctuation, for example `… live-prices (serving
revision none)` or `… live-prices; serving revision none`.

Cause: `cli/src/cli/commands/price.py:101-104` builds
`f"{source['alias']}: {source['error'] or source['freshness']}; serving
revision …"`.

Fix: strip a trailing `.` before the join, or put the revision in
parentheses. No dependency change.

Blast radius: `price refresh` failure details in text and JSON.

Dedupe: this is left over from w3/387 and w3/433. Nothing else covers
it.

Acceptance: a 404 refresh detail has no `.;`. A test pins it.

**Resolved.** The refresh failure detail in `cli/src/cli/commands/price.py` now strips a trailing `.` from the error (or freshness) before joining `; serving revision …`. A 404 now reads `NOPE: fetch failed (not-found): HTTP 404: unknown price source. Choose an available pair at https://beancount.io/live-prices; serving revision none`. Messages without a final full stop (timeout, redirect) are unchanged.

`tests/test_price.py::TestPriceRefreshFailures::test_a_failure_detail_has_no_full_stop_before_the_revision` refreshes a 404 feed in text and JSON. The detail has no `.;` and ends `; serving revision none`. With the fix stashed, both modes fail.
