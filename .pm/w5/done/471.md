# `bea query` text tables print `1.5E+3` for a decimal with a positive exponent and exit 1 with an internal `TypeError` on `NaN`/`Infinity`; CSV and JSON answer both

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-16, HEAD `8195088f`, checkout `bea 0.3.1`, macOS 26.5.1. Gap in the w5/294 fix.
USAGE promises "Text-table numbers, `-m` included, are fixed-point
(`0.00000001`, never `1E-8`)". The w5/294 renderer kept that for negative
exponents only: `round(x, -2)` and any other value with a positive exponent
still prints in scientific notation. A non-finite decimal crashes the text
render outright. No product fix implemented.

Disposable `main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Rent USD
2026-01-01 open Expenses:Fx USD
2026-01-05 * "Landlord" "rent"
  Expenses:Rent  1500.00 USD
  Assets:Cash
2026-01-06 * "Bank" "fx fee"
  rate: "inf"
  Expenses:Fx  1.00 USD
  Assets:Cash
```

Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, closed stdin.

```sh
bea -f /abs/main.bean query "SELECT account, number, round(number, -2) AS hundreds WHERE account ~ 'Expenses'"
bea -f /abs/main.bean query "SELECT date, decimal(entry_meta('rate')) AS rate WHERE account = 'Expenses:Fx'"
```

Actual:

- the first prints `Expenses:Rent  1500.00  1.5E+3` and `Expenses:Fx  1.00
  0E+2`, exit 0;
- `round(sum(number), -2) … GROUP BY account` prints `2.0E+3`; the same
  appears in `-o out.txt` and the interactive shell;
- the second exits 1 with `Error: TypeError: '>' not supported between
  instances of 'str' and 'int' Pass --debug before the command for a
  traceback.`, which also lacks a full stop before "Pass". `SELECT
  decimal('NaN')` does the same, and the PTY shell prints a raw traceback.

Control: `-f csv` prints `1500`, `0` and `Infinity`; `--json` prints `"1500"`,
`"0"` and `"Infinity"`. Negative exponents already print fixed-point.

Expected: text agrees with CSV and JSON. It prints `1500` / `0`, aligned on
the decimal point, and `NaN` / `Infinity` as words.

Cause: `FixedPointDecimalRenderer.format` (`cli/src/bea_engine/query.py:1431-1439`)
returns `str(super().format(value))` whenever the exponent is positive, and
the class does not override `update`. Upstream `DecimalRenderer.update`
(`beanquery/query_render.py`) sizes a positive-exponent value by
`len(str(value))` and compares `as_tuple().exponent > 0`, but that exponent is
the string `'n'` or `'F'` for NaN and Infinity. The missing full stop comes
from `cli/src/cli/engine/launch.py:437`, which appends the hint without
checking for one (`output._message` does check).

Fix: override `update` and `format` to measure and print positive-exponent
values with `format(value, "f")` and non-finite ones as their names. In
`launch.py`, end the message with a full stop before the hint.

Blast radius: every `--file` text query, `-m`, `-o x.txt`, the shell.
`--source` keeps upstream's rendering by design.

Dedupe: searched `E+`, `scientific`, `positive exponent`, `NaN`,
`Infinity`. Only w5/294 (done, negative exponents) is related.

Acceptance: both commands print fixed-point and named values with exit 0,
matching CSV. A test pins each.

---

**Resolved 2026-10-16** — Shipped in `59e2e244` (`cli`). The text-table `FixedPointDecimalRenderer` (`cli/src/bea_engine/query.py`) now overrides `update` as well as `format`. A positive-exponent decimal is measured and printed as its fixed-point digits (`_whole`: `1.5E+3` → `1500`, `0E+2` → `0`), aligned on the decimal point. A NaN or an infinity is measured and printed by name (`NaN`, `Infinity`, `-Infinity`), as CSV and JSON print them, instead of reaching upstream's `>` on its letter exponent. `cli/src/cli/engine/launch.py` ends the message with a full stop before the `--debug` hint. `tests/test_query_text_positive_exponent.py` pins `round(number, -2)`, a grouped `round(sum(number), -2)` with and without `-m`, `Infinity` from metadata, `NaN`/`-Infinity` literals, and the hint's punctuation; all five fail without the fix. `cli/docs/USAGE.md` documents both.
