# `price export` on a ledger with a missing `document` file dies with a raw `FileNotFoundError` after writing part of the export

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`),
checkout `bea 0.3.1`, macOS.
Exporting a ledger whose `document` directive points at a file that is not
there fails with a Python exception name, exit 1 "validation", after the
ledger copy and an empty attachment directory have already been written. No
product fix implemented.

Create disposable `/absolute/books/main.bean` and no `receipts`
directory:

```beancount
2000-01-01 open Assets:Bank USD
2021-03-01 document Assets:Bank "receipts/stmt.pdf"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY.

```sh
bea --json -f /absolute/books/main.bean price export --output /absolute/out
```

Actual: exit 1 with `{"error": {"category": "validation", "message":
"FileNotFoundError: [Errno 2] No such file or directory:
'/absolute/books/receipts/stmt.pdf' Pass --debug before the command for a
traceback.", "exit_code": 1}}`. `/absolute/out/main.bean` and an empty
`/absolute/out/receipts/` are left behind. A worker found that a second run
into the same directory raises the same raw error instead of the documented
collision refusal.

Control: with `receipts/stmt.pdf` present, the export exits 0 and lists
both files.

Expected: `docs/USAGE.md` describes export refusals as decided "before
anything is written". A ledger error that makes the export impossible should
be a clean refusal that names the directive and writes nothing.

Cause: `cli/src/bea_engine/managed_load.py:702-711` refuses only
unavailable price sources and does not look at the load's errors. The
attachment plan includes a `Document` entry whose file is absent, and the
copy at `:837-839` fails after the ledger files were written at
`:832-836`. On a retry the same-file test at `:795-796` raises on the
missing attachment before the collision check runs.

Fix: validate that every planned attachment source exists before writing
anything, and refuse with the directive's location; decide whether a missing
attachment blocks the export or is skipped with a warning under
`--allow-errors`. Guard the same-file test against a missing source. No
dependency or API change.

Dedupe: board search for export with missing attachments finds w5/056
(partial snapshot from a blocked directory), w5/090 (raw OS errors in
`init` and `format -o`), w4/180 and w1/044 (attachment copying); none
covers a missing source attachment.

Acceptance: the command exits non-zero with a message naming
`main.bean:2` and the missing path, no exception name, and no output
directory; a rerun behaves identically; the control is unchanged. Only macOS
and the checkout were exercised.

---

**Resolved 2026-10-13** — The export's attachment plan in `cli/src/bea_engine/managed_load.py` now refuses a `document` directive whose file is not there before anything is written, with exit 2 and a message naming the directive's file and line and the missing path. The refusal applies with or without `--allow-errors`, matching the existing refusals for attachments that cannot travel; `docs/USAGE.md` says so. The regression test covers the refusal, an identical rerun, `--allow-errors`, an untouched source tree, no output directory, and the control with the file present; it fails with the fix reverted. The note left open whether `--allow-errors` should skip the missing attachment with a warning; this fix always blocks. `make check-all` passed. Only macOS was exercised. Shipped in `0026da46` (`cli`).
