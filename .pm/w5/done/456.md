# `bea ingest extract -e LEDGER` leaves a world-readable full copy of a private ledger beside it (`.main.bean.picklecache`, 0644, next to a 0600 `main.bean`), and it persists after the command exits

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, umask 022.
[w5/175](./done/175.md) (Major) made read commands keep their load
cache in bea's private cache directory, so that no world-readable full
copy is left beside a private ledger. Its resolution notes that "the
optional `bea price` (bean-price) and `bea ingest` forwarders still run
upstream with its own cache placement". No note tracked that. When
beangulp loads the `-e` ledger for dedupe, it writes upstream's default
`.<file>.picklecache` beside the ledger, using the process umask. That
is a pickle of every entry, and it stays after the command exits. No
product fix implemented.

Use a ledger slow enough to be cached (the hunter used 60k transactions)
with `chmod 600 main.bean`, and the beangulp `ingest.py` from earlier
runs. Use fresh BEA_CONFIG_DIR/XDG_CACHE_HOME, umask 022, and closed
stdin.

```sh
bea ingest extract --config ingest.py -e /absolute/books/main.bean src
ls -la /absolute/books
```

Actual: exit 0. `books/` now holds `-rw-r--r-- .main.bean.picklecache`
(about 10 MB) beside `-rw------- main.bean`. Reproduced twice by the
hunter. I checked the listing on disk.

Control: `bea -f /absolute/books/main.bean balance` caches under
`$XDG_CACHE_HOME/bea/load-cache/` (a 0700 directory) and leaves nothing
beside the ledger.

Expected: the w5/175 rule. No world-readable copy of a private ledger,
and bea's cache placement applies to every load it starts.

Cause: `run_optional_script` (`cli/src/cli/engine/launch.py:213-226`)
builds its environment with `_helper_env()`. Unlike `_native_env`
(`:164-180`), that never sets `BEANCOUNT_LOAD_CACHE_FILENAME` to
`load_cache_pattern(...)`.

Fix: when `-e/--existing` names a ledger (`_extract_ledgers` already
finds it), set the load-cache environment variable to bea's pattern for
that ledger. Do the same for the bean-price forwarder. No dependency
change.

Blast radius: `bea ingest extract -e` on large private ledgers, and
probably the bean-price forwarder (not exercised, since beanprice is not
enabled).

Dedupe: w5/175 (done) names this deviation but filed nothing. w5/316
covers `price export` modes, and 455 covers `ask_history`. No other hit.

Acceptance: after the command, no `.main.bean.picklecache` exists beside
the ledger, and any cache is under `$XDG_CACHE_HOME/bea/load-cache/`. A
test pins it.

---

**Resolved 2026-10-15** — `run_optional_script` and `run_optional_native` (`cli/src/cli/engine/launch.py`) take the ledger their child loads and set `BEANCOUNT_LOAD_CACHE_FILENAME` to bea's private pattern for it, as `_native_env` already did; a pattern the user set still wins. `bea ingest extract` passes its `-e`/`--existing` ledger, and the `bea price` bean-price forwarder passes its first ledger source file. So no `.main.bean.picklecache` is left beside a private ledger, and the cache sits under `$XDG_CACHE_HOME/bea/load-cache/`. `cli/tests/test_ingest_existing_load_cache.py` runs a real `ingest extract -e` on a 0600 ledger whose plugin pauses past Beancount's one-second cache threshold. It asserts nothing beside the ledger and one cache under the private directory, and fails with the fix reverted. Because beanprice is absent from the suite's engine, only the bean-price ledger handoff is unit-tested. `test_forwarded_short_options.py`'s extract expectation gained the new keyword. Only macOS was exercised. `make check-all` passed (6023 tests). Shipped in `cbdf4cec` (`cli`).
