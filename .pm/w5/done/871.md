# An importer's statement balance with a wrong amount in a second currency is silently padded by a used pad (follow-up to w5/796)

**Major · cli · 20–30m · A1.** Found while fixing w5/796 (shipped `d4d22a2e3`), 2026-10-20.
USAGE:1110 says ordinary `add balance` "remains a strict assertion".
No product fix implemented.

`mc.bean` (from w5/796): a 2026-01-09 pad, a 2026-01-10 USD balance of
1100.00, 200 EUR held. An importer returning `Balance(2026-03-15,
Assets:Checking, 250.00 EUR)` is written with `--apply`, exit 0: the pad
silently inserts 50.00 EUR backdated to 2026-01-09.

Control: `add balance` with the same gap now exits 1 naming the pad and
50.00 EUR (w5/796).

Expected: the imported balance is refused or its row blocked, naming the
pad and the amount it would insert, and reported in JSON.

Cause: import appends rendered directive texts through Beancount-level
validation (`bea_engine/importing.py`), which the pad defeats — there is
no per-balance hook like `adding._balance`. Open design point: block the
row with the reason (import's idiom for unwritable rows) or fail the
whole `--apply`.

Dedupe: w5/796 (done) fixed the `add balance` half.

Acceptance: the imported statement balance is not silently padded; the
pad and 50.00 EUR are named; tests pin it.

---

**Resolved 2026-10-20** — the design point went to import's own idiom: an importer's `balance` row is **blocked** (so `--apply` refuses with exit 4 and writes nothing) when a pad an earlier assertion already used would silently fill its gap, by the rule `add balance` refuses with since w5/796, counting this import's earlier rows; the reason names the pad's location, date and source and the amount (`… holds 200.00 EUR on 2026-03-15 but this row asserts 250.00; the pad at …:10 (2026-01-09 from Equity:OpeningBalances) would silently insert the 50.00 EUR difference …`), in text and JSON. A staged pad still completes silently, an agreeing balance is still written, and the row is never unblocked by the open-account recheck. `tests/test_import_balance_used_pad_fill.py` pins the preview, the apply refusal and the agreeing control; IMPORTING says so. Gate note: gated as one stack with w5/843, 845 and 871 (one `make check-all`, each item shipped as its own commit); its only failures were load-induced managed-price fetch timeouts in `test_price_source_limit.py` that pass in isolation.
