# `sign=` is the one `--csv` key that may be repeated: the last value silently wins, so `sign=ledger,sign=bank` and `sign=bank,sign=ledger` write opposite signs, both with exit 0

**Minor · cli · 5–10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
Every other repeated `--csv` key is refused with `Duplicate --csv field
'date'` (and likewise for payee, encoding, delimiter, currency). `sign`
is handled before that check. A mapping that contradicts itself, as when
a template appends a default `sign=` to a user's own, books every row
with whichever sign comes last. No product fix implemented.

Use a USD ledger that opens `Assets:Cash` and `Expenses:Uncategorized`,
and `s.csv`:

```text
Date,Payee,Amount
2026-01-05,Shop,-5.00
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME (fresh per run),
BEA_NO_UPDATE_NOTIFIER=1, and closed stdin.

```sh
bea -f /absolute/books/main.bean import s.csv --account Assets:Cash --csv date=Date,payee=Payee,amount=Amount,sign=ledger,sign=bank --apply
bea -f /absolute/books/main.bean import s.csv --account Assets:Cash --csv date=Date,payee=Payee,amount=Amount,sign=bank,sign=ledger --apply
```

Actual: both exit 0. The first writes `Assets:Cash -5.00 USD` and the
second `Assets:Cash 5.00 USD` (each on a fresh copy). Reproduced twice
by the hunter and once by me.

Control: `…,date=Date,date=Date` exits 2 with `Duplicate --csv field
'date'`.

Expected: exit 2 with `Duplicate --csv field 'sign'`, like every other
key. `docs/IMPORTING.md` treats mapping misuse as a usage error.

Cause: `parse_mapping` (`cli/src/bea_engine/csv_mapper.py:365-368`)
assigns `sign` in its own branch, before the `elif name in columns`
duplicate check.

Fix: track whether `sign` was seen and raise the same duplicate error.
No dependency change.

Blast radius: `bea import --csv` with a repeated `sign=`, whether from a
user, a template or an agent. Every row gets the wrong sign.

Dedupe: searched `.pm/**`, including `done/`, for "Duplicate --csv field"
and repeated `sign=`. 311 covers repeated flags, not keys inside `--csv`.
None covers this.

Acceptance: both commands exit 2 naming `sign`, and nothing is written. A
single `sign=` still works. A test pins it.

---

**Resolved 2026-10-15** — both `parse_mapping` copies
(`cli/src/bea_engine/csv_mapper.py`, `cli/src/cli/csv_mapper.py`) now
track whether `sign=` was seen. A second one exits 2 with `Duplicate
--csv field 'sign'.`, whether the values agree or not, and nothing is
written. A single `sign=bank` or `sign=ledger` applies as before. The
internal merges of remembered settings always strip `sign=` before
appending one, so they never produce the repeat. Pinned by
`cli/tests/test_csv_duplicate_sign.py`, which fails without the fix.
