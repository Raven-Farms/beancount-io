# A `bea ask` reply cut mid-UTF-8 character, or sent in a non-UTF-8 charset, prints a raw codec error, and after an approved write the REPL drops the "already wrote" note (gap in w5/373)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `0c12f2dc`, checkout `bea 0.3.1`, macOS 26.5.1. Simulation: local stub of the AI proxy.
USAGE: "A successful HTTP response that the generated parser cannot read exits
1 with `Unexpected server response (HTTP 200).`… the CLI does not expose
parser exceptions". A turn that fails "after an approved write names the
directives it already wrote". w5/373 mapped `JSONDecodeError`, `IndexError`,
`KeyError` and `TypeError` to that path, but not `UnicodeDecodeError`. No
product fix implemented.

Stub reply: a valid `chat.completion` whose content is `Your café spend…`, the
body cut right after the first byte of "é" (ends `…"Your caf\xc3`), served as
`application/json`. Variant: the whole body latin-1 with `charset=iso-8859-1`.

```sh
bea -f /abs/main.bean ask q --print </dev/null
```

Actual: exit 1, `Error: 'utf-8' codec can't decode byte 0xc3 in position 171:
unexpected end of data. Pass --debug before the command for a traceback.`
(latin-1: `…byte 0xe9…invalid continuation byte`). In the REPL, after a
`write_directive` approved with `y`, the same sentence appears without
`Note: This question had already written 1 directive(s)…`, though the file
changed. A deeply nested body (`maximum recursion depth exceeded…`) and a
`"type": "custom"` tool call (`Custom tool calls are not supported.`) leak the
same way.

Control: the same body cut one byte earlier, at an ASCII character, gives
`Error: Unexpected server response (HTTP 200) from the assistant; nothing
was written…`.

Expected: the unreadable-reply sentence, plus the already-wrote note when a
write happened.

Cause: `_ProxyChatModel.request` (`cli/src/cli/ask/agent.py:356`) catches only
`(json.JSONDecodeError, IndexError, KeyError, TypeError)`; the rest reach the
generic handler (`main.py`) or `repl.py:320`, where `_naming_writes` is not
applied.

Fix: also map `ValueError` (covers `UnicodeDecodeError`), `RecursionError` and
the SDK's unsupported-tool `RuntimeError` to `UnreadableModelReply`.

Dedupe: w5/373 (done) is the fix this extends.

Acceptance: the cut and latin-1 replies give the unreadable-reply sentence;
after an approved write, the note is kept. A test pins both.

---

**Resolved 2026-10-17** — Shipped in `090a8d01` (`cli`). `_ProxyChatModel.request` (`cli/src/cli/ask/agent.py`) now maps `ValueError` (which covers `JSONDecodeError` and `UnicodeDecodeError`) and `RecursionError` to `UnreadableModelReply`. It also maps the SDK's bare `RuntimeError` for a custom tool call; its own `AgentRunError` failures are still reported apart. A reply cut inside a UTF-8 character, sent latin-1, nested too deep, or carrying a `"type": "custom"` tool call now gives `Unexpected server response (HTTP 200) from the assistant; …`. In a session that sentence names what the question already wrote.

Tests: the shared stub can now send raw bodies (`tests/conftest.py`). `tests/test_ask_unreadable_reply_bodies.py` pins the four bodies under `--print` and, on a PTY, the approved write followed by a cut reply, which keeps `this question had already written 1 directive(s)`. All five fail without the fix. `make check-all` passed.
