# A misplaced `-f LEDGER` after `ingest archive` silently becomes beangulp's `--overwrite` and replaces already-archived documents; after `query` it gives a bare "Unknown query format" with no hint

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12 with beangulp.
Everywhere else, bea explains a misplaced `-f` with `No such option: -f
Place -f before the command, for example: bea -f main.bean check.` Two
subcommands define their own `-f`, so that hint never fires for them:

- `query -f` is `--format`. The error names the ledger path as an
  unknown format and gives no hint.
- `ingest archive` forwards to beangulp, where `-f` is `--overwrite`. A
  user who types `bea ingest archive … -f main.bean` instead of `bea -f
  main.bean ingest archive …` overwrites documents that were already
  filed. The command exits 0, and the ledger path is also treated as
  another source file to archive. It moves only if an importer claims it.

No product fix implemented.

Use the beangulp `ingest.py` from the r51 run (its importer claims
`chk*` files), with `main.bean`, `src/chk-jan.csv` containing `new3`, and
an existing `docs/Assets/Bank/Chk/2026-01-31.chk-jan.csv` holding older
content. Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME,
BEA_NO_UPDATE_NOTIFIER=1, and closed stdin.

```sh
bea ingest archive --config ingest.py -o docs src                       # control
bea ingest archive --config ingest.py -o docs src -f /absolute/ing/main.bean
bea query -f /absolute/L/main.bean "SELECT count(*)"
```

Actual:

- The control exits 1 with `Destination file already exists. # Errors
  detected: documents will not be filed.`, and the old document is kept.
- With `-f`, it exits 0. The filed document is replaced (now `new3`), and
  `main.bean` is listed as a source.
- `query -f` exits 2 with `Unknown query format '/absolute/L/main.bean'.
  Choose one of: text, csv, beancount.`

Reproduced twice by the hunter and once by me (both).

Expected: USAGE's convention is that global switches precede the
command, and bea explains a misplaced `-f` everywhere else (`cli/src/cli/errors.py:215-228`).

- When `query --format`'s value is an existing ledger file, or ends in
  `.bean`/`.beancount`, add the "Place -f before the command" hint.
- When `ingest archive`'s `-f`/`--overwrite` is followed by an existing
  ledger file, refuse with exit 2 naming the collision, rather than
  overwrite filed documents.

Cause:

- `cli/src/cli/commands/query.py:316-317` raises the bare message.
- `ingest` forwards its arguments unchanged. The global hint fires only on
  Click's "No such option".

Fix: add both checks. No dependency change.

Blast radius: `bea ingest archive` users who misplace `-f`, which can
destroy already-archived statements, and `bea query` users who do the
same.

Dedupe: searched `.pm/**`, including `done/`, for `--overwrite`, `query
-f`, "Unknown query format" and "Place -f before". w2/021, w5/166 and
w3/436 cover other aspects. None covers the collision.

Acceptance: the archive command with `-f main.bean` exits 2 and changes
nothing. `query -f main.bean` exits 2 with the placement hint. `ingest
archive -f` without a ledger argument and `query -f csv` still work.
Tests pin both.

---

**Resolved 2026-10-15** — `query` (`cli/src/cli/commands/query.py`) adds
`-f after query is --format. Place -f before the command, for example:
bea -f main.bean check.` to the unknown-format refusal when the value
ends in `.bean`/`.beancount` or names an existing file. `ingest archive`
(`cli/src/cli/commands/ingest.py`) refuses `-f`/`--overwrite` followed
by a `.bean`/`.beancount` path before Beangulp runs: exit 2, `-f after
ingest archive is Beangulp's --overwrite, which replaces documents
already filed, and …/main.bean would be archived as a source. Place -f
before the command, … Nothing was changed.`. Both use w5/416's shared
`placement_hint`. `query -f csv` and `ingest archive -f` on its own (a
deliberate overwrite) still work. Pinned by
`cli/tests/test_misplaced_f_on_own_f.py`, which fails without the fix.
The archive case is tested at the forwarding boundary (Beangulp stubbed),
not against a live ingest script.
