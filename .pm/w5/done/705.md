# `bea treeify` treats `-` as a file name: `-o -` writes a file named `-` with exit 0, and `treeify -` then reads that file instead of stdin, or fails with a raw `FileNotFoundError` (gap in w5/352)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `d75811df`, checkout `bea 0.3.1`, macOS 26.5.1. Gap in w5/352 (done).
Elsewhere in bea, `-` means stdin or stdout: `format -`, `query -o -` and
`example -o -` all work that way, and `tests/test_contract.py:836` asserts
`query -o -` creates no file named `-`. The w5/352 resolution says "stdin
(`-` or none) … pass through as before", but `-` was never stdin for
upstream treeify. No product fix implemented.

`a.txt` holds `Assets:Bank:Checking   10 USD` and `Assets:Bank:Savings    20
USD`; `b.txt` holds `Expenses:Food:Dining   5 USD` and `Expenses:Food:Grocery
6 USD`.

```sh
bea treeify a.txt -o -
bea treeify - < b.txt
rm -- -; bea treeify - < b.txt
```

Actual:
1. Exit 0, empty stdout, and a new 84-byte file `./-` holding a.txt's tree.
2. Exit 0. It prints a tree of the stale `./-` and ignores stdin's Expenses
   rows.
3. Exit 1, `Error: treeify failed (exit 1): FileNotFoundError: [Errno 2] No
   such file or directory: '-'. Pass --debug before the command for a
   traceback.`

Control: `bea treeify < b.txt` renders b.txt.

Expected: `treeify -` reads stdin, and `-o -` writes to stdout, as
`example -o -` does. Otherwise both exit 2.

Cause:
- `_check_input` (`cli/src/cli/commands/treeify.py:126`) lets `-` through as
  stdin, then the rebuild forwards `-- -` (`:83-84`) to upstream, which opens
  it as a file.
- `-o -` becomes `Path("-")` (`:184`), and `atomic_write` (`:216`) creates it.

Fix: drop an input of `-` before forwarding, and treat `-o -` as no
destination (as `example.py:148` does).

Dedupe: w5/352 (done) exempted `-` without handling it. w5/535 and 570
(open) are other treeify issues.

Acceptance: the three commands render to stdout from the right source, and
no `./-` is created. A test pins both.

**Resolved 2026-10-18** — Shipped in `9420d991b904e065039443b66b73e83bed96587e` (`cli`). Treeify normalizes exact input/output `-` sentinels to stdin/stdout before rebuilding forwarded arguments or running validators/output guards. `treeify -` now uses the pipe even when a stale `./-` exists, and `-o -` prints the tree without creating or replacing that file. Parsed options, custom patterns and clustered flags survive the rebuild. Explicit `./-` remains a literal file; its output path becomes absolute before shared guards so it cannot inherit their stdout exemption and bypass a filesystem write-access refusal. USAGE documents both spellings.

All three original subprocess repros now render the expected source to stdout and preserve/avoid a literal dash file.
