# Empty lot labels still disappear from the transaction table and query CSV, though JSON and `--details` preserve them (follow-up to w5/805, 465 and 561)

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-20, HEAD
`8875694b083e2fee3cb63b2281c0653443662621`, checkout `bea 0.3.1`, macOS
Darwin 25.5.0 arm64; frontend Python 3.13.3. No product fix implemented.

Create a synthetic absolute `/abs/books/main.bean`:

```beancount
2024-01-01 open Assets:Stock HOOL
2024-01-01 open Assets:Cash USD
2024-02-01 * "unlabeled"
  Assets:Stock 1 HOOL {100 USD}
  Assets:Cash -100 USD
2024-02-01 * "empty"
  Assets:Stock 1 HOOL {100 USD, ""}
  Assets:Cash -100 USD
2024-02-01 * "named"
  Assets:Stock 1 HOOL {100 USD, "lot-a"}
  Assets:Cash -100 USD
```

Run with cwd `/abs/books`, closed stdin/no TTY, absolute isolated
`BEA_CONFIG_DIR` and `XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, and no
inherited `BEA_FILE` or `BEA_TOKEN`:

```sh
bea --file /abs/books/main.bean check
bea --file /abs/books/main.bean list transaction
bea --file /abs/books/main.bean query "SELECT position WHERE account = 'Assets:Stock'" --format csv
bea --file /abs/books/main.bean query "SELECT position.cost WHERE account = 'Assets:Stock'" -o /abs/books/lots.csv
bea --json --file /abs/books/main.bean query "SELECT position WHERE account = 'Assets:Stock'"
bea --file /abs/books/main.bean list transaction --details
```

Actual: all exit 0, stderr empty except the details command's explanatory
notice. The table spells both the unlabeled and empty-label postings as
`1 HOOL {100 USD, 2024-02-01}`. The position CSV likewise contains:

```csv
position
"1 HOOL {100 USD, 2024-02-01}"
"1 HOOL {100 USD, 2024-02-01}"
"1 HOOL {100 USD, 2024-02-01, ""lot-a""}"
```

The bare-cost CSV also omits the empty label. JSON keeps three cost labels
`null`, `""`, and `"lot-a"`; `list --details` renders the explicit `""`.
Controls with a nonempty label work. Both stdout CSV and `-o lots.csv` were
exercised. Repeated in two fresh directories/process sequences, each building
the ledger through three actual `add transaction` commands, which correctly
write the empty label since w5/805. Read commands leave the ledger's hash
unchanged. This is an output-fidelity defect; no bookkeeping data loss or
upstream lot-matching change is claimed.

Expected: the table's cost spelling agrees with `--details`, as
`cli/docs/USAGE.md` promises under Listing directives, and CSV retains the
label held in the JSON value, as the completed CSV findings require.

Cause: `cli/src/cli/commands/list.py:119` (`_cost`) and
`cli/src/bea_engine/query.py:2202` (`_csv_cost`) use `if cost.get("label")`,
so `""` takes the same branch as `None`. `_posting_amount` is the table
caller; `_csv_from_jsonable` uses `_csv_cost` for both positions and bare
costs, recursively covering inventory CSV cells and both CSV destinations.
The write renderer already tests `is not None`.

Fix: render a present empty string label in both output renderers. Pin
unlabeled, explicitly empty, and nonempty labels in the same fixture, for the
table and position/bare-cost CSV; keep JSON and details as working controls.
No dependency, backend or API change is needed.

Dedupe: searched all `.pm/**/*.md` states for empty lot/cost labels and
inspected every open/blocked milestone scope. w5/805 fixed write rendering in
`6f9181fa1`; its resolution explicitly leaves upstream matching alone.
w5/465 (`3feb465e2`) and w5/561 (`687e1b19`) fixed CSV date/nonempty-label
loss, and w3/366 (`779cba15b`) added table cost rendering. Targeted
`git log -S 'if cost.get("label")'` finds the two output introductions and no
subsequent repair. This is their remaining empty-string case.

Acceptance: the table and both CSV cost shapes preserve `""`; unlabeled and
named controls retain their current meanings; reads leave the ledger
byte-identical. Windows/Linux, native query-shell CSV and repaired behavior
remain unverified. Sanitized local evidence is retained in
`.tmp/qa-2026-10-20-cli-loop-d3c5ebec/`, especially
`captures/label-{1,2}-*.json` and the two `empty-label-repro-*` fixtures;
the complete public reproducer above does not depend on those ignored files.
