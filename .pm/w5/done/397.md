# Under the `unique_prices` plugin, the `add price` conflict refusal says "Pass --force to record another quote", but `--force` is then refused with a bare "Disagreeing price entries"

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
The same-day price conflict always offers `--force`. When the ledger loads
`beancount.plugins.unique_prices`, a second quote can never validate. The
forced write then fails with the plugin's message at the existing line.
That message has no `Proposed append` label and does not name the plugin.
No product fix implemented.

Use a USD ledger with `plugin "beancount.plugins.unique_prices"` and
`2026-01-05 price EUR 1.1 USD`, with the environment from [396](./396.md).

```sh
bea -f /absolute/books/main.bean add price --date 2026-01-05 -c EUR --amount '1.2 USD'
bea -f /absolute/books/main.bean add price --date 2026-01-05 -c EUR --amount '1.2 USD' --force
```

Actual:

- The first exits 2 with `EUR already has a 2026-01-05 price of 1.1 USD
  (at main.bean:10); refusing 1.2 USD. Pass --force to record another
  quote.`
- The second exits 1 with `main.bean:10: Disagreeing price entries`.

Reproduced twice by the hunter and once by me.

Control: without the plugin, `--force` writes the second quote.

Expected: when `unique_prices` is loaded, the first message should say to
edit the existing price at `main.bean:10` instead of offering `--force`.
A forced attempt should name the plugin and the proposed quote.

Cause: `cli/src/bea_engine/ledger/adding.py:636-642` always offers
`--force`.

Fix: check the loaded plugins and drop the `--force` advice when
`unique_prices` is present. Optionally, add a hint for `Disagreeing price
entries` in the write error loop. No dependency change.

Dedupe: searched `.pm/**`, including `done/`, for `unique_prices` and
"Disagreeing price". There are no hits. w5/115 covers balance `--force`.

Acceptance: with the plugin, the first command names the existing line
and does not mention `--force`. A forced attempt names `unique_prices`.
Without the plugin, behaviour is unchanged.

---

**Resolved 2026-10-15** — Shipped in `abc16946`. `_price` in `cli/src/bea_engine/ledger/adding.py` now reads the loaded plugins. When `unique_prices` is among them, a same-day conflict no longer offers `--force`. It says: "EUR already has a 2026-01-05 price of 1.1 USD (at main.bean:5); refusing 1.2 USD. This ledger loads the unique_prices plugin, which allows one EUR price in USD per day; edit the existing price at main.bean:5 instead." A `--force` attempt gets the same refusal, so it names the plugin, the proposed quote and the existing line, instead of the bare `Disagreeing price entries` from validation.

Deviation: the forced attempt now exits 2 (usage, like the conflict refusal) instead of 1, because it is refused before the write is staged.

Without the plugin, behaviour is unchanged: the refusal offers `--force`, and `--force` records the second quote. `tests/test_add_price_unique_prices.py` pins both plugin cases and that control. Both plugin cases fail without the fix.
