# Portable export silently skips a plugin resource directory it cannot list, reporting success for a snapshot that cannot load (follow-up to w5/868)

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-20, checkout
`bea 0.3.1`, HEAD `1d84de6de`, Darwin 25.5.0 arm64, frontend Python
3.13.3; non-root process. No product fix implemented.

Create disposable `/abs/case/books/main.bean`:

```beancount
option "operating_currency" "USD"
option "insert_pythonpath" "TRUE"
plugin "pkgplug"
2024-01-01 open Assets:Cash USD
```

Create `books/pkgplug/data/settings.json` containing
`{"label":"Synthetic"}`, and this inspected `books/pkgplug/__init__.py`:

```python
import json
from importlib.resources import files
CONFIG = json.loads(files(__package__).joinpath("data/settings.json").read_text())
__plugins__ = ["run"]
def run(entries, options):
    return entries, []
```

Keep the resource file readable, but make its directory searchable without
list permission. Use isolated absolute `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`,
`BEA_NO_UPDATE_NOTIFIER=1`, no inherited `BEA_FILE`/`BEA_TOKEN`, cwd
`/abs/case`, and closed stdin/no TTY:

```sh
chmod 111 /abs/case/books/pkgplug/data
bea --json --file /abs/case/books/main.bean check
bea --json --file /abs/case/books/main.bean price export --output /abs/case/snapshot
bea --json --file /abs/case/snapshot/main.bean check
chmod 755 /abs/case/books/pkgplug/data
```

Actual: source check exits 0. The plugin can read the known resource path;
directory list permission is unnecessary for that read. Export also exits 0,
listing only `snapshot/main.bean` and `snapshot/pkgplug/__init__.py`.
The resource and its directory vanish from the copy. A fresh snapshot check
exits 1 with `FileNotFoundError …/snapshot/pkgplug/data/settings.json`.
The source and resource bytes are unchanged. Repeated twice from pristine
fixtures; mode 0111, `readable=False`, `searchable=True` were verified.

Control: restore the resource directory to 0755 and export the exact same
source to a fresh destination. The resource is copied and the snapshot
check exits 0. Both runs restore directory permissions afterward; no
credentials, network or installation changes were involved.

Expected: a self-contained export carries the package's required resources,
or refuses before creating a partial snapshot, naming the directory it
cannot enumerate. USAGE's Managed price includes section says a selected
package travels whole and unreadable package entries refuse export. The
source ledger itself is valid, so this is not an invalid-plugin fixture.

Cause: `_package_files` in `cli/src/bea_engine/managed_load.py:2172`
walks the package with `os.walk(package)` and no `onerror`. A directory
enumeration failure is silently skipped; the file readability check sees
only names the walk returned. `_export_plugin_modules` then plans the
incomplete set as if it were complete. Selected plugin packages and local
helper packages share this walker.

Fix: handle traversal errors as an explicit path-named refusal before any
snapshot files land. Keep readable package resources, bytecode exclusions,
symlink containment and other existing export checks. Pin the searchable
but unlistable directory case with real source/export/snapshot subprocesses.

Dedupe: whole-board searches for package/plugin unreadability and export
directory traversal, plus open/blocked milestone scopes, found completed
w5/868 (`531c12c9b`). It added resource copies and unreadable-file/linked-dir
guards, but not enumeration-error handling. Targeted history traces this
walker to that fix; no later repair found. This is the traversal remainder,
not a second request to copy resources in general.

Acceptance: the mode-0111 fixture either exports a loadable complete copy
or refuses naming `pkgplug/data` with no destination residue; the 0755
control exports and checks. Windows and repaired behavior unverified.
Sanitized captures, source fixtures and both snapshots remain under
`.tmp/qa-2026-10-20-cli-loop-d3c5ebec/` (`export-unlistable-{1,2}/` and
matching `captures/export-unlistable-*.json`). The public setup suffices
without ignored evidence.

---

**Resolved 2026-10-22** — the plugin-package walker used by portable export now refuses a directory it cannot list, naming it and writing nothing, instead of skipping its resources. `test_a_package_directory_that_cannot_be_listed_is_refused` in `cli/tests/test_price_export_plugin_resources.py` fails without the fix; shipped in the commit that moves this note (`cli`).
