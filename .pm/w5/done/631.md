# `list transaction --search` cannot find a multi-line narration by the text the table shows ("Rent for January")

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `76c5b63e`, checkout `bea 0.3.1`, macOS 26.5.1.
The table flattens line breaks in a narration to spaces, and import's
duplicate matching does the same (IMPORTING: "replace CR/LF line breaks with
spaces before preview, duplicate matching"). `--search` compares the raw
narration, which still contains the newline, so the text the user reads
cannot be searched. No product fix implemented.

```beancount
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Rent USD
2024-01-06 * "Landlord" "Rent
for January"
  Expenses:Rent  1000.00 USD
  Assets:Cash
```

```sh
bea --file /abs/main.bean list transaction
bea --file /abs/main.bean list transaction --search "rent for january"
bea --json --file /abs/main.bean list transaction --search "rent for"
```

Actual: the table shows `Rent for January`; both searches return `No
transactions found.` / `"data": []`, exit 0.

Control: `--search "for january"` matches.

Expected: USAGE: `--search` is a case-insensitive substring over payee and
narration. Line breaks (in the entry and the term) compare as single spaces,
so both searches match.

Cause: `cli/src/bea_engine/ledger/reader.py:331-332` compares the raw narration;
the table flattens at `cli/src/cli/commands/list.py:242`.

Fix: collapse `[\r\n]+` (and surrounding spaces) to one space on both sides
before matching.

Dedupe: searched `--search` with line break, multi-line, newline; only w1/m26
(NFC search) is nearby.

Acceptance: both searches list the entry. A test pins it.

---

**Resolved 2026-10-17** — Shipped in `1e3f4f2f1` (`cli`). `list_transactions` in `cli/src/bea_engine/ledger/reader.py` compares search terms through `_search_key`. That key folds case as before and reads a line break, with the spaces around it, as one space, on both the entry side and the term side. `--search "rent for january"` and `--search "rent for"` now list the multi-line entry. USAGE's `--search` row says so. Test: `cli/tests/test_list_search_multiline_narration.py`.
