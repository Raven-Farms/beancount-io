# `bea doctor` misreads BOM-marked and NFD ledgers that `bea check` accepts, and exits 0

**Major · cli · 45–60m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
The forwarded `doctor` operations run stock `bean-doctor` without the
BOM/NFC compatibility that every other `bea` command applies. On a ledger
`bea check` calls valid, `print-options` prints default options,
`missing-open` invents an `open` for an account that is already open, and
`lex` reports an error token — all with exit 0. No product fix implemented.

Create disposable files in `/absolute/books`. `bom.bean` starts with the
three bytes `EF BB BF`, then:

```beancount
option "operating_currency" "EUR"
2026-01-01 open Assets:Cash
2026-01-01 open Equity:Opening
2026-01-02 * "x"
  Assets:Cash  10.00 EUR
  Equity:Opening
```

`nobom.bean` is the same text without the mark. `bom_open.bean` is the mark
followed by the same ledger without the `option` line. `nfd.bean`:

```beancount
2026-01-01 open Expenses:Café
2026-01-01 open Equity:Opening
2026-01-02 * "x"
  Expenses:Café  10.00 EUR
  Equity:Opening
```

with the `open` spelled with precomposed U+00E9 and the posting spelled `e`
followed by U+0301.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f bom.bean check; bea -f bom_open.bean check; bea -f nfd.bean check
bea doctor print-options bom.bean
bea doctor lex bom.bean
bea doctor missing-open bom_open.bean
bea doctor missing-open nfd.bean
```

Actual: all three `check` runs exit 0. `print-options bom.bean` exits 0
with `operating_currency: []`. `lex bom.bean` exits 0 and its first token is
`error 1 b'\xef\xbb\xbfoption'`. `missing-open bom_open.bean` exits 0 and
prints `2026-01-02 open Assets:Cash`. `missing-open nfd.bean` exits 0 and
prints `2026-01-02 open Expenses:Café`.

Control: `bea doctor print-options nobom.bean` prints
`operating_currency: ['EUR']`. A worker saw the same false open through a
BOM-marked include, `doctor context` exit 1 with `No entry could be found`,
`doctor roundtrip` reporting "Entries are the same" on `bom_open.bean`, and
`doctor region` (which runs through the engine helper) rendering correctly.

Expected: `docs/USAGE.md` says "A ledger saved with a UTF-8 BOM loads like
any other: the mark is skipped on read" and that "NFC and NFD spellings of
one name resolve to one account". `doctor` should read the ledger as the
rest of `bea` does, or refuse; it must not exit 0 with defaults and a false
`open` that, pasted into the ledger, creates a duplicate-open error.

Cause: `cli/src/cli/commands/doctor.py:185,207,222,275,312,351` launch stock
`bean-doctor` through `run_native`/`capture_native`. The BOM/NFC shim in
`cli/src/bea_engine/compat.py` is installed only inside engine-helper
processes; the pre-flight syntax guards run through the shimmed helper, see
no errors and let the unshimmed upstream run. `check.py`'s
`_closure_needs_compat` already handles the same case for `bea check`.

Fix: run the doctor operations through the engine helper as `region` does,
or reuse `_closure_needs_compat` to refuse with exit 2 and a `bea format -i`
hint. No dependency or API change.

Blast radius: `lex`, `dump-lexer`, `parse`, `print-options`, `context`,
`missing-open`, `display-context`, `directories`, `roundtrip`, for any
ledger or include with a BOM or a non-NFC account name.

Dedupe: board search for doctor with BOM, `utf-8-sig` and NFD finds w3/257
and w1/m26 (BOM/NFC loading, done) and w5/084 (a different native-launch
divergence for plugins); none covers doctor.

Acceptance: each command above either matches the no-BOM/NFC result or
exits nonzero with a one-line reason; `missing-open` prints no `open` for an
account that is open. Real-command regression tests cover a BOM root, a BOM
include and an NFD posting. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — `bea doctor` now checks the file it reads (for `lex`, `dump-lexer`, `parse`) or the whole include closure (for `print-options`, `context`, `missing-open`, `display-context`, `directories`, `roundtrip`) for a UTF-8 BOM or an account token outside Unicode NFC. Such a ledger runs the same upstream operation inside the engine helper, which reads both shapes as the rest of `bea` does; every other ledger still runs the stock `bean-doctor` executable with unchanged output. The regression test runs real commands on a BOM root, a BOM include and an NFD posting (14 of 15 cases fail with the fix reverted), with no-BOM and prose-only NFD controls. For a routed ledger `lex` shows the text as loaded, not the on-disk bytes; `docs/USAGE.md` says so. Only macOS was exercised. `make check-all` passed. Shipped in `66f75a81` (`cli`).
