# Preset init's success text reports 14 accounts for a blank ledger and the wrong opening date for a known opening balance

**Minor · cli · 15–25m · A1/A2.** Real CLI QA, 2026-10-20, checkout
`bea 0.3.1`, HEAD `55453a39b`, Darwin 25.5.0 arm64; frontend Python 3.13.3.
No product fix implemented.

Run in a disposable directory with closed stdin/no TTY, isolated absolute
`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, and no inherited
`BEA_FILE`/`BEA_TOKEN`:

```sh
bea init /abs/blank --preset blank@1 --currency USD --date 2024-02-01
bea --json --file /abs/blank/main.bean list open
bea init /abs/known --preset personal@1 --currency USD --date 2024-02-01 --opening-balance 'Assets:Cash 100'
bea --json --file /abs/known/main.bean list open
```

Actual: both init calls exit 0, stderr empty.

- Blank says `Created /abs/blank/main.bean with 14 accounts in USD.` and
  `Accounts open on 2024-02-01.` There are **zero** open directives, and
  `list open` returns `data: []`. JSON init of the same preset correctly
  returns `accounts: []` (separate fresh target).
- Known opening says `Accounts open on 2024-02-01.` Every open directive
  is actually dated **2024-01-31**, as the preset builder intends for the
  day-before opening transaction. The following text advises editing the
  opens to record earlier history, even though that preceding day is open.

Reproduced twice from fresh directories. Control: `personal@1` without an
opening correctly reports 12 accounts, matching 12 opens on 2024-02-01.
The generated files are correct; this is a success-summary defect. JSON
init/list reads and direct file contents establish the actual counts/dates.

Expected: successful creation describes the files it created: zero accounts
for blank, and the actual account-open date when a preset opening shifts it
to the day before the history boundary. A blank ledger should not claim
that any accounts were opened. Preserve the boundary date's separate
meaning and legacy fixed-template summaries.

Cause: `cli/src/cli/commands/init.py:309` uses
`data.get("accounts") or list(_ACCOUNTS)`, so the valid empty preset list
falls back to the legacy 14-account chart. The unconditional text at :326
uses the requested `day` for every account-open date, whereas
`cli/src/bea_engine/initiating.py:230` deliberately uses `day - 1` for
preset opening balances. Both errors come from reusing the legacy summary
without accommodating the preset builder's valid results.

Fix: retain a supplied empty account list and derive the opening-date text
from the actual creation result. Test blank, clean nonempty preset, known
opening and legacy creation through real human output, with fresh listings
as the controls. Do not change the generated accounting data to match the
incorrect text.

Dedupe: searched all board states for blank/14-account and preset opening
date summaries and reviewed open/blocked milestone scopes. Completed
w3/m53/t004 added preset creation in `1ba20bffa`, reusing the existing
summary; targeted `git log -S` finds the legacy count fallback and date
message without a preset-summary repair. w5/875 and 876 concern title
serialization and lost explicit zero input, respectively, not correct
generated data described incorrectly.

Acceptance: human account counts and dates match the fresh `list open`
result for the four controls; blank makes no account-opening claim. No
dependency, backend or API change. Windows/Linux and repaired behavior
unverified. Sanitized evidence and generated ledgers are under
`.tmp/qa-2026-10-20-cli-loop-d3c5ebec/`: captures
`preset-human-{1,2}-{blank,personal,known}.json`, the matching fixture
directories, and the earlier JSON preset captures in `sweep5/`. Public
commands above independently reproduce both symptoms.

---

**Resolved 2026-10-22** — the preset creation result carries the day its accounts open (`opened`), and the human summary reports the real account count (zero for `blank@1`, no "Accounts open" claim) and that date; the fixed chart keeps its summary. `cli/tests/test_init_preset_summary.py` checks four cases against fresh `list open`; shipped in the commit that moves this note (`cli`).
