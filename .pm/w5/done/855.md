# A Python importer posting with a cost but no units is written with its cost silently dropped, and exit 0 books USD into the stock account (gap in w5/638)

**Minor · cli · 15–25m · A1.** Real CLI QA, 2026-10-17, HEAD `8e35a3636`, checkout `bea 0.3.1`, macOS 26.5.1. Reproduced twice from pristine synthetic fixtures, using the absolute checkout executable, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, stdin closed, no TTY. No product fix implemented.

Create `main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Assets:Brokerage
```

Create `bank.txt` containing any synthetic text, and `imp.py`:

```python
import datetime
import beangulp
from decimal import Decimal as D
from beancount.core.amount import Amount
from beancount.core.data import Posting, Transaction
from beancount.core.position import Cost

class Bank(beangulp.Importer):
    @property
    def name(self): return "bank"
    def identify(self, f): return True
    def account(self, f): return "Assets:Checking"
    def extract(self, f, existing):
        return [Transaction({}, datetime.date(2026, 2, 3), "*", None,
            "Synthetic purchase", frozenset(), frozenset(), [
                Posting("Assets:Checking", Amount(D("-30"), "USD"), None, None, None, None),
                Posting("Assets:Brokerage", None, Cost(D("10"), "USD", None, None), None, None, None)])]

CONFIG = [Bank()]
```

```sh
bea --file /abs/main.bean import /abs/bank.txt --config /abs/imp.py --apply
bea --json --file /abs/main.bean query "SELECT account, position WHERE account ~ 'Brokerage'"
```

Actual: import exits 0, `1 ready`, `Wrote 1 entry`. The appended stock posting is a bare `Assets:Brokerage`; its cost is gone. Query exits 0 with `units: {number: "30", currency: "USD"}, cost: null`. Replacing `Cost(...)` with `CostSpec(D("10"), None, "USD", None, None, False)` has the same result. These are observable wrong writes, not just a missing annotation in the preview.

Control: supplying `Amount(D("3"), "HOOL")` on that posting preserves `{10 USD}`; query returns 3 HOOL with cost 10 USD. The only ledger changes in the failing cases are the captured successful appends.

Expected: refuse the unrepresentable posting with the importer, row, account and missing units named, exit 1, leaving the ledger byte-identical. IMPORTING promises that an importer value that cannot be written stops the import; `add transactions` already refuses cost without units (w5/212).

Cause: `_writable` in `cli/src/bea_engine/importing.py:868` checks that the printed row parses as one directive, not that its posting fields survive printing. Beancount's printer omits a cost when the posting has no units. The subsequent units check at `:366` covers only source-account postings, so the counter posting passes. `_writable` is shared by the CSV and Python-importer preparation paths; `Cost` and `CostSpec` both need checking before printing.

Fix: reject every transaction posting with a cost but no representable units before formatting, using `_writable`'s existing row-specific refusal.

Dedupe: searched the whole board, including done/blocked, for `cost dropped`, `cost but no units`, `units=None` and import/no-units. w5/212 is the completed bulk-add sibling; w5/638 is the completed importer-validation parent. No open item covers this import write. History: `8c1d18ce7` added the current guard.

Acceptance: both cost types refuse without writing; the explicit 3 HOOL control still writes and reloads with its cost. Pin the real import/apply and subsequent query in regression coverage.

---

**Resolved 2026-10-20** — `_writable` refuses, before printing, any importer transaction posting that has a cost (`Cost` or `CostSpec`) and no units: `Importer bank row 1 cannot be written as a ledger entry: its Assets:Brokerage posting has a cost but no units …`, exit 1, ledger byte-identical, on preview and `--apply` alike, for CSV and Python importers. A posting with units still writes and reloads with its cost (query: 3 HOOL at 30 USD). `tests/test_import_cost_without_units.py` pins both cost types and the control through real import/apply/query runs.
