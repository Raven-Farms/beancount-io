# A planned _SHARED file and relocated _shared/ include evade export's ancestor collision check, leaving two files behind before failure (gap in w5/191 and w5/652)

**Minor · cli · 10–20m · A1.** Real CLI QA, 2026-10-18, HEAD `e1bf4ac4a`, checkout `bea 0.3.1`, macOS 26.5.1 on case-insensitive APFS. `_SHARED` and `_Shared` each reproduced twice from pristine synthetic books and absent output directories, isolated config/cache, stdin closed and no TTY. No product fix implemented.

Create `books/main.bean`:

```beancount
option "operating_currency" "USD"
include "_SHARED"
include "../outside/accounts.bean"
2026-01-02 * "Transfer"
  Assets:Internal  1 USD
  Assets:External
```

`books/_SHARED` contains `2026-01-01 open Assets:Internal USD`.
`outside/accounts.bean` contains `2026-01-01 open Assets:External USD`.

```sh
bea --file /abs/books/main.bean check
bea --json --file /abs/books/main.bean price export -o /abs/snapshot
```

Actual: source check exits 0. Export exits 1 with `writing .../snapshot/_shared/01-accounts.bean failed (Not a directory). 2 of 3 files were already written (.../snapshot/_SHARED, .../snapshot/main.bean); the export is incomplete.` The two files remain. All original source files retain their bytes. A file named `_Shared` behaves identically.

Control: the same source with the local file/include spelled `_shared` is refused at planning with exit 2, `the export would write .../_shared as a file and .../_shared/01-accounts.bean inside it ... Nothing was written.` Its output directory remains absent.

Expected: the predictable file-versus-directory conflict is refused before creating the snapshot, as the exact-case control is. The usage contract and w5/191 explicitly promise a self-colliding plan writes nothing; this is distinct from a disk failure or a directory becoming unavailable during the export.

Cause: the complete-plan duplicate-name loop in `cli/src/bea_engine/managed_load.py:1640` folds equal destinations through `_name_key`, but the ancestor check around `:1690` builds `files = set(planned)` and compares each raw `dest.parents` against it. `_SHARED` therefore differs from `_shared` until the real filesystem encounters the collision after writing two copies. External includes always allocate under the latter directory. Managed feed directory allocation already uses folded name keys.

Fix: compare planned file names against planned ancestor directory names with the same normalized/case-folded keys used for equal destinations, before any write. Preserve the existing actionable refusal and original path spellings.

Dedupe: whole-board searches for `_shared`, planned ancestor collisions and case-folded export paths found the completed w5/191 (exact ancestor collision) and w5/652 (equal relocated destination collisions). Open w5/826 concerns interruption cleanup, not a deterministic preflight failure. No open item covers this missed ancestor spelling.

Acceptance: both case variants refuse with exit 2 and leave the output directory absent; source bytes remain unchanged. The lowercase refusal and an unrelated, valid three-file export remain correct. Preserve the portability policy on case-sensitive systems; only APFS was exercised here.

---

**Resolved 2026-10-20** — the plan's file-versus-directory check keys planned files and every destination's ancestors through `_name_key`, the fold the equal-destination check already used, so `_SHARED` and `_Shared` are refused at planning with exit 2 and nothing written, on every platform (portability policy unchanged); the refusal names the planned spellings. `tests/test_price_export_plan_collisions.py` covers `_shared`, `_SHARED` and `_Shared` (output absent, source bytes unchanged); the valid three-file export test still passes. Gate note: `make check-all` had three load-induced managed-price timeouts in `test_price_source_limit.py` (0 feed hits at load average ~60); the file passes in isolation.
