# A mode-000 include named by two root files is reported once, for the first includer only; a directory in the same place is reported for each (gap in w5/523)

**Trivial · cli · 5–10m · A1.** Real CLI QA, 2026-10-17, HEAD `9eece8ad`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/523 (done, `55b38552`).
No product fix implemented.

`A/main.bean` includes `sub.bean`, and `A/root2.bean` is `include "sub.bean"`.
`A/sub.bean` is mode 000.

```sh
bea --json format --check A/main.bean A/root2.bean
```

Actual: `error.result.missing` holds one entry, `{"include": "sub.bean",
"from": "…/A/main.bean", "reason": "…/sub.bean cannot be read: Permission
denied"}`. Text mode prints one line, and `root2.bean`'s include goes
unnamed.

Control: with a directory at `A/sub.bean`, the same command lists two
entries, one `from` each root (w5/442).

Expected: one entry per include that names the unreadable file.

Cause: `_walk_closure` (`cli/src/cli/output.py`, around `:536`) records only
the first includer with `named_by.setdefault`, and reads each file once.
Directory matches are appended once per directive.

Fix: report the unreadable member for every include that matched it.

Dedupe: w5/442 and 523 (done) are the parents.

Acceptance: the fixture lists both includers in JSON and text.
