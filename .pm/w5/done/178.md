# The BQL syntax-error caret points at the wrong place for multi-line queries and after `FROM accounts`

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, Beanquery 0.2.0, macOS.
The caret under a BQL syntax error is computed as an offset into a
different string from the one printed. For a multi-line query it sits 62
spaces into a line of its own, under nothing. For a query using the
`accounts` or `balances` table names, the JSON `details` caret is two
columns to the right of the offending token. No product fix implemented.

Create disposable `/absolute/books/main.bean` (with an empty
`docs/a.pdf`):

```beancount
2024-01-01 open Assets:Cash
2024-01-02 note Assets:Cash "plain note"
2024-01-03 note Assets:Cash "tagged note" #trip #tax #work ^inv-1
2024-01-05 document Assets:Cash "docs/a.pdf" #trip #tax #work ^inv-1
2024-01-06 * "Txn" #trip #tax #work ^inv-1
  Assets:Cash  1 USD
  Assets:Cash  -1 USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

Pipe this three-line query on stdin to `bea -f main.bean query`:

```sql
SELECT date, narration
FROM year = 2024
WHERE narration = = "x"
```

and run

```sh
bea --json -f main.bean query "SELECT account FROM accounts WHERE account = = 'x'"
```

Actual: both exit 2 (correct). The first prints the three query lines
and then a caret line indented 62 spaces — the absolute offset — instead
of under the second `=` on line 3. The second's `details` are:

```text
"  SELECT account FROM accounts WHERE account = = 'x'"
"                                                 ^"
```

The caret is under the `'` of `'x'`; the offending `=` is two columns to
the left.

Control: the same query with `FROM #accounts` puts the caret exactly
under the second `=`. A worker found 376 single-line generated parse
errors placed exactly.

Expected: the caret under the offending token of the text shown, or for
multi-line input the offending line with a column caret or `line N,
column M`.

Cause: `cli/src/bea_engine/query.py:936` builds the statement the parser
sees (NFC-normalized, with `accounts`/`balances` rewritten), but `:945`
passes the original text to the error renderer, and `:1138-1139` emit
`' ' * position` with no line or column mapping.

Fix: render against the string the parser saw, or map the offset back;
split multi-line input into line and column. No dependency or API
change.

Blast radius: every parse or compile error on multi-line BQL (heredoc,
stdin, `--source`), and JSON `details` for queries using the two table
names; a decomposed-Unicode literal before the error shifts it too
(worker observation).

Dedupe: board search for caret and multi-line finds w3/246 (added the
rewrite) and w1/026 and w1/085 (keep the caret); none covers
misalignment.

Acceptance: both carets sit under the second `=`; single-line placement
is unchanged. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — The BQL syntax-error renderer in `cli/src/bea_engine/query.py` now draws the caret against the statement the parser actually saw and maps the parser's absolute offset to a line and column: each query line is its own detail at one indent, and the caret follows the line the offset falls on. The `--json` one-shot path used to echo the text as typed while the offset counted the quotes the engine adds around `accounts` and `balances`, so it now echoes the rewritten statement (`FROM "accounts"`), matching what the text path already showed; a tab in an echoed line is shown as one space so the column holds. `cli/tests/test_query_syntax_error_caret.py` runs the real command for the three-line stdin query, both reserved table names, a tab-indented continuation line and three single-line controls, in text and `--json`; five of its ten cases fail with the fix reverted and the single-line controls pass either way. Pattern and literal errors, which echo the statement without a caret, are unchanged. Only macOS was exercised. `make check-all` passed. Shipped in `1145c24f` (`cli`).
