# An untraversable `bea/load-cache` directory fails every local read and write with a raw `PermissionError: [Errno 13]`, exit 1 "validation": a regression from the w5/220 cache check

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
If `$XDG_CACHE_HOME/bea/load-cache` exists but cannot be entered, every
helper-path command fails before it loads the ledger. This happens, for
example, after one `sudo bea …` leaves the directory root-owned at mode
`0700`, or after a backup restore with the wrong owner. `balance`, `list`,
`report`, `query` and `add` each exit 1 with `Error: PermissionError:
[Errno 13] Permission denied: '…/load-cache/<hash>.main.bean.picklecache'`,
and `--json` gives category `validation`. The cache is only an
optimisation. Native `bea doctor` still works, and the ledger is unchanged.
No product fix implemented.

Use any valid ledger at `/absolute/books/main.bean` and an isolated
`XDG_CACHE_HOME=/absolute/xc`, with isolated BEA_CONFIG_DIR,
BEA_NO_UPDATE_NOTIFIER=1, no inherited BEA_FILE/BEA_TOKEN, and closed
stdin.

```sh
bea -f /absolute/books/main.bean balance        # control: exit 0, creates xc/bea/load-cache (0700)
chmod 000 /absolute/xc/bea/load-cache            # stands in for a root-owned 0700 directory
bea -f /absolute/books/main.bean balance
bea --json -f /absolute/books/main.bean list transaction --limit 1
bea -f /absolute/books/main.bean add note --date 2026-01-05 -a Assets:Checking -m x
```

Actual: each command exits 1 with `Error: PermissionError: [Errno 13]
Permission denied: '/absolute/xc/bea/load-cache/<hash>.main.bean.picklecache'
Pass --debug before the command for a traceback.` With `--json` the
category is `validation`. Reproduced in three fresh setups.

Controls:

- Before the `chmod`, the same commands exit 0.
- `bea doctor context` exits 0.
- A read-only `XDG_CACHE_HOME` works when `load-cache` has not been created
  yet, because `launch.load_cache_pattern`
  (`cli/src/cli/engine/launch.py:151-157`) deliberately ignores `OSError`.
- An unreadable cache file inside a directory that can be entered is also
  tolerated.

Expected: the load cache is an optimisation, so an unreachable cache should
mean an uncached load, as it did before 220. At worst it should be exit 3
`auth`, naming the directory (the exit-code table lists "3 | `auth` |
Authentication or permission failure"). It should never be a validation
error prefixed with a class name that blocks every read.

Cause: `cli/src/bea_engine/managed_load.py:544` (`_load_fresh`, added in
`2ff77650` for w5/220) calls `cache.is_file()`. On the engine's Python
3.12, `pathlib.Path.is_file` re-raises `EACCES` from `stat`. Before
`2ff77650`, Beancount's own `os.path.exists` returned False and the load
continued uncached. `_engine_wrote` and `_mark_engine_cache` already catch
`OSError` (`managed_load.py:586-600`).

Fix: guard the probe with `try: present = cache.is_file() except OSError:
present = False`, or use `os.path.isfile`. Keep the later `exists()` and
`unlink` calls inside the same guard. Optionally, note the skipped cache
on stderr. No dependency or API change.

Blast radius: every command that loads through `managed_load._load_fresh`:
`balance`, `list`, `report`, `query`, `price`, all `add` kinds, and
`import`. Native `doctor` is unaffected.

Dedupe: board search for load cache together with permission, `0700`,
unreadable and `EACCES`.

- w5/175 (`f48c48fd`) and w5/220 (`2ff77650`) are the predecessors; neither
  tests an unreachable cache directory.
- w5/215 is the same failure class on the `importers/` directory.

Nothing is open.

Acceptance: with `load-cache` at mode 000, `balance`, `list`, `report`,
`query` and `add note` exit 0 with correct results and the write lands, or
each exits 3 naming the directory. Either way there is no `PermissionError:`
text and no `validation` category. A real-command regression test covers a
read and a write. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-15** — `_load_fresh` and `_mark_engine_cache` (`cli/src/bea_engine/managed_load.py`) probe the pickle cache with `os.path.isfile`/`exists`, which return False on EACCES, and drop caches through a new `_drop` that ignores `OSError`. `candidate_file` (`cli/src/bea_engine/ledger/write.py`) suppresses `OSError` when it removes a staged copy's sidecar, the third place the raw error came from. With `load-cache` at mode 000, `balance`, `list`, `report`, `query`, `add note`, `price export` and `check` all exit 0 with correct results, and the note lands. `cli/tests/test_load_cache_unreachable.py` covers a read and a write; both fail with the fix reverted. Only macOS was exercised. `make check-all` passed. Shipped in `74649a4b` (`cli`).
