# `cli/docs/agent-skills.md` says a skill's `name` must be lowercase and match its directory, but nothing enforces it, and the same page says the directory name does not matter

**Trivial · cli docs · 5–10m · A1.** Real CLI QA, 2026-10-16, HEAD `d16aea3e`, checkout `bea 0.3.1`, macOS 26.5.1.
The page contradicts itself: line ~18 says "The subdirectory's own name does
not matter to discovery, so renaming `test-skill` to `test-skill.bak` does
**not** disable it", while the field table (~line 46) says `name` is
"Lowercase, hyphens only, must match the parent directory name". `bea ask`
loads a skill whose `name` is `My Skill` in directory `x/` without comment.
No product fix implemented.

Expected: one rule. Either the table says these are conventions (for
portability with other agents' skill loaders) that bea does not enforce, or
bea enforces them and the discovery paragraph changes.

Cause: `_parse_skill` (`cli/src/cli/ask/skills.py:35-48`, `:72-85`) checks
only that `name` and `description` are present.

Fix: reword the table row as a recommendation (smallest change).

Dedupe: no `.pm` match for the table text; w5/287 and 454 are other skill
discovery issues.

Acceptance: the page states one consistent rule.

**Resolved 2026-10-17** — Shipped in `657eb4a5` (`cli`, docs only). `cli/docs/agent-skills.md`'s field table no longer says `name` "must match the parent directory name". It describes `name` as the skill's identity (a project copy wins), and gives lowercase-with-hyphens matching the directory as the convention other agents' skill loaders expect, kept for portability, which `bea ask` does not enforce. That agrees with the discovery paragraph and with `_parse_skill`, which requires only `name` and `description`. No code changed, so no regression test applies.
