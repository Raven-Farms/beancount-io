# A relative or file-typed `BEA_ENGINE_DIR` is accepted without a check (`engine status` reports "Engine 0.3.1 at rel/eng", exit 0), while a relative `BEA_CONFIG_DIR` is refused with exit 2

**Trivial · cli · 10m · A2.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1. The checkout serves the engine from source, so provisioning into the bad path was not observed. The status output and the code show the gap.

`BEA_CONFIG_DIR` refuses a relative path because it "would keep separate
state in every working directory". `BEA_ENGINE_DIR` has no such check.
A relative value would provision a full engine, a download, into every
working directory. A path that exists as a regular file can never hold
an engine, but `engine status` says "the next local command rebuilds
it". No product fix implemented.

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, and
closed stdin.

```sh
BEA_ENGINE_DIR=rel/eng bea engine status
BEA_ENGINE_DIR=/absolute/afile bea --json engine status     # afile is a regular file
BEA_CONFIG_DIR=rel/x bea engine status
```

Actual:

- The first run exits 0 with `Engine 0.3.1 at rel/eng` and
  `Provisioned: no`.
- The second exits 0 and reports `engine_root` as the file. The text form
  says the next local command rebuilds it.
- The third (control) exits 2 with `BEA_CONFIG_DIR must be an absolute
  path, got 'rel/x'. A relative one would keep separate state in every
  working directory.`

Reproduced twice by the hunter and once by me (relative and control).

Expected: `docs/USAGE.md` (environment) checks `BEA_CONFIG_DIR` and
`BEA_ENGINE_PYTHON` before use. `BEA_ENGINE_DIR` should get the same
treatment: exit 2, naming the variable, for a relative path or an
existing non-directory.

Cause: `engine_root` (`cli/src/cli/engine/paths.py:60-64`) returns
`Path(override).expanduser()` unchecked.

Fix: in `engine_root`, refuse a relative path or an existing
non-directory with `UsageError` naming `BEA_ENGINE_DIR`. No dependency
change.

Blast radius: users and packagers who set `BEA_ENGINE_DIR`.

Dedupe: searched `.pm/**`, including `done/`, for `BEA_ENGINE_DIR`. w1/119
to w1/121, w1/141, w2/022, w3/431, w5/011 and w5/320 cover other aspects.
None covers relative or file-typed values.

Acceptance: both bad values exit 2, naming the variable. An absolute
directory still works. A test pins both.

---

**Resolved 2026-10-15** — `engine_root` (`cli/src/cli/engine/paths.py`)
now checks `BEA_ENGINE_DIR` the way `BEA_CONFIG_DIR` is checked. A
relative value exits 2 with `BEA_ENGINE_DIR must be an absolute path, got
'rel/eng'. A relative one would install a separate engine in every
working directory.`, and nothing is created. A value naming an existing
file exits 2 with `… points at '…/afile', which is not a directory, so no
engine can live there. Correct or unset BEA_ENGINE_DIR.`, in text and
JSON (category `usage`). An absolute directory works as before. Together
with w5/419's ownership check, an existing directory that holds no engine
is never replaced. USAGE states the rule. Pinned by
`cli/tests/test_engine_dir_validated.py`, which fails without the fix.
