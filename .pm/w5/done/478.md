# `bea price refresh` accepts a feed body Beancount cannot parse, replaces the last good revision with it, exits 0, and every later command fails

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-16, HEAD `0864aeed`, checkout `bea 0.3.1`, macOS 26.5.1. Synthetic local feed server.
The feed validator is meant to accept "a strict subset of what Beancount's
lexer accepts" (`cli/src/bea_engine/managed_prices.py:59-62`), so a bad body
never displaces a good revision. It skips blank and comment lines without
ending the current point, so metadata after a blank line still attaches.
Beancount reads that metadata as a stray indented line. No product fix
implemented.

Feed `K1` first serves a valid point, which is cached:

```text
; alias: K1
; commodity: XA
; quote: USD
2026-10-15 price XA 10 USD
  observed-at: "2026-10-16T12:00:00Z"
```

Then it serves:

```text
; alias: K1
; commodity: XA
; quote: USD
2026-10-16 price XA 11 USD

  observed-at: "2026-10-16T12:00:00Z"
```

`main.bean`: `include "<origin>/prices/K1"` and `2026-01-01 open Assets:Cash USD`.

```sh
bea -f /abs/main.bean check            # caches the good revision, exit 0
bea -f /abs/main.bean price refresh
bea -f /abs/main.bean check
bea -f /abs/main.bean price status
```

Actual: `refresh` exits 0 with `K1: 28e4ae1e… → 61190c72…`; then `check`,
`balance` and the rest exit 1 with `…effective….beancount:6: syntax error,
unexpected INDENT`; `price status` shows `recent` with no error. The
previous blob is gone. A whitespace-only line or a column-0 `;` line between
the price and its metadata, or an indented `; comment` before the first
price, does the same.

Expected: the body is refused as invalid, the source keeps serving the
previous revision, and `refresh` reports the failure (exit 1, as for other
invalid feeds).

Cause: `parse_feed` in `cli/src/bea_engine/managed_prices.py:488-522`.
`_BLANK_RE` and `_COMMENT_RE` lines `continue` without resetting `current`,
and `_COMMENT_RE` accepts indented comments anywhere.

Fix: a blank line or a column-0 comment ends the current point (`current =
None`). Refuse an indented line that follows no directive. Mirror the rule
in the hosted feed parser if it shares the grammar.

Blast radius: every managed feed fetch (CLI); the hosted ledger service if
it shares the validator.

Dedupe: w1/081 (Unicode whitespace) and w5/377 (commodity grammar) are the
same class with other shapes, both done.

Acceptance: each of the four bodies is refused at refresh, the good revision
keeps serving, and `check` stays at exit 0. A test pins them.

---

**Resolved 2026-10-16** — Shipped in `3ef48d5b` (`cli`). `validate_managed_price_text` (`cli/src/bea_engine/managed_prices.py`) now ends the current point at a blank or whitespace-only line, or a comment at column 0, as Beancount's grammar does. Metadata after one is refused ("metadata without a preceding price directive"), and so is an indented comment with no point above it. An indented comment inside a point's metadata, which Beancount parses, is still accepted. `tests/test_managed_feed_orphan_indent.py` checks each of the four bodies against Beancount's own parser and then the validator; all four fail without the fix. It also checks two valid shapes and pins a `price refresh` that exits 1 and keeps serving the good revision (`check` stays at 0). The hosted feed parser (`backend-cluster/ledger/.../managed-price-feed.ts`) skips blank and comment lines the same way; that is filed separately so this change stays in one package.
