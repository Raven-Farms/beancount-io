# `bea example -o /dev/null` is refused with exit 4 "Already exists", unlike every other `-o` command

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
The documented rule is that a device or FIFO destination is written
through. `example` treats `/dev/null` as an existing file and demands
`--force`. No product fix implemented.

No fixture. Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY.

```sh
bea example --seed 1 --date-begin 2026-01-01 --date-end 2026-04-01 -o /dev/null
```

Actual: exit 4, `Error: Already exists: /dev/null. Pass --force to
overwrite it with a generated example; without it, example never
overwrites.`

Control: `bea query --source LEDGER "SELECT account" -o /dev/null` exits
0. A worker saw `format`, `treeify` and `ingest extract` write through
`/dev/null`, `/dev/stdout` and a FIFO, and `example -o /dev/null --force`
exit 0.

Expected: `docs/USAGE.md` lists `example -o` under the one destination
rule and says "A device or FIFO destination is written through rather than
replaced".

Cause: `cli/src/cli/commands/example.py:36` refuses on `output.exists() or
output.is_symlink()` without exempting non-regular files.

Fix: only an existing regular file (or a symlink to one) is a conflict. No
dependency change.

Blast radius: `bea example -o` with a device or FIFO.

Dedupe: board search for "Already exists: /dev" finds nothing; w5/157 is
`--json format -o /dev/stdout`.

Acceptance: the command exits 0 and writes through. Only macOS and the
checkout were exercised.

---

**Resolved 2026-10-13** — `bea example -o` no longer treats a device or FIFO destination as an existing file that needs `--force`: the conflict check in `cli/src/cli/commands/example.py` now exempts a destination whose target is neither a regular file nor a directory, so `-o /dev/null`, a symlink to a device and a FIFO are written through with exit 0, as the one destination rule in `docs/USAGE.md` already documents. An existing regular file, a symlink to one, a dangling symlink and a directory are still reported as a conflict with exit 4 unless `--force` is passed. The regression test `cli/tests/test_example_output_device_written_through.py` runs the real command against `/dev/null`, a symlink to it and a FIFO whose reader receives the generated ledger, plus those conflict controls; three of its five cases fail with the fix reverted. No documentation changed, since the documented behaviour was already the intended one. Only macOS was exercised. `make check-all` passed. Shipped in `4fd915cf` (`cli`).
