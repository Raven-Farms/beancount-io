# An imported balance blocked by the used-pad guard is blamed on an unopened account or currency mismatch, and its suggested command lacks required options (follow-up to w5/871)

**Minor · cli · 15–25m · A1.** Real CLI QA, 2026-10-20, checkout
`bea 0.3.1`, HEAD `1ad6ddc7a1177d9ffb4aeca510089dca546a1387`, Darwin
25.5.0 arm64, frontend Python 3.13.3. No product fix implemented. The
financial guard works: this finding concerns its misleading diagnostics.

Create synthetic `/abs/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking
2026-01-01 open Equity:OpeningBalances
2026-01-05 * "Deposit"
  Assets:Checking 1000.00 USD
  Equity:OpeningBalances
2026-01-06 * "Euros"
  Assets:Checking 200.00 EUR
  Equity:OpeningBalances
2026-01-09 pad Assets:Checking Equity:OpeningBalances
2026-01-10 balance Assets:Checking 1100.00 USD
```

Create an empty `statement.txt` and this inspected local `importers.py`:

```python
from datetime import date
from decimal import Decimal
from beancount.core import data, amount

class Statement:
    name = "statement"
    def identify(self, filepath): return True
    def account(self, filepath): return "Assets:Checking"
    def extract(self, filepath, existing):
        return [data.Balance(data.new_metadata(filepath, 1), date(2026, 1, 11),
            "Assets:Checking", amount.Amount(Decimal("250.00"), "EUR"), None, None)]

CONFIG = [Statement()]
```

With cwd `/abs/books`, closed stdin/no TTY, absolute isolated
`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, and no inherited
`BEA_FILE`/`BEA_TOKEN`:

```sh
bea --file /abs/books/main.bean check
bea --json --file /abs/books/main.bean import /abs/books/statement.txt --config /abs/books/importers.py
bea --json --file /abs/books/main.bean import /abs/books/statement.txt --config /abs/books/importers.py --apply
bea --file /abs/books/main.bean import /abs/books/statement.txt --config /abs/books/importers.py --apply
```

Actual: check passes; preview exits 0 with a blocked row. Apply exits 4 in
both modes and preserves the ledger bytes. Its main message is:

```text
Import needs review; nothing was written. 1 row is blocked by an unopened account or a currency mismatch; resolve it first.
```

Neither cause applies: both accounts are open and unrestricted in currency.
The row reason correctly says the existing pad would silently insert the
50.00 EUR gap. It ends with
`bea add balance --pad-from Equity:OpeningBalances pads it explicitly.`
Copying that command exits 2, `Missing option '--date'`. It also
omits `--account`, `--amount` and the ledger path. Repeated twice
from pristine directories, with separate human and JSON captures.

Expected: the headline identifies the need to resolve blocked rows without
inventing an account/currency problem when a different guard blocked them.
When offering explicit padding as the intentional alternative, give a
complete command for this ledger, account, date and amount, as the other
CLI remedies do. Keep exit 4 and the byte-preserving refusal. The approving
action is explicit; do not weaken the used-pad guard.

Cause: `cli/src/bea_engine/importing.py:909` hard-codes every blocked row as
an unopened account/currency mismatch (the plural branch at :912 does too).
w5/871 introduced another blocked reason in `_padded_balance_reason`
(:1936–1965) without updating that summary. Its final string assembles a
bare command rather than using the root-ledger command builder and the
Balance's already-known fields.

Blast radius: Python importers returning a Balance a used pad would fill;
the apply summary is shared by CSV/Python import review. Existing account
and currency blocks remain legitimate controls. Verified controls: an
agreeing `200.00 EUR` assertion writes and checks successfully, while plain
`add balance` for the 250.00 gap refuses naming the pad and 50.00 EUR. Human
and JSON apply messages are affected; the detail reason already names the
correct pad and should be retained.

Dedupe: searched all board states for the exact headline and padding
remedies, plus the open/blocked milestone scopes. w5/871 (`322ea6d40`) added
this guard and its shorthand; w5/858 (`70209b71e`) concerns missing mixed
invalid-row details, and w5/688 concerns a different explicit pad-date hint.
`git log -S` traces the old blanket headline to `4fd637652` and the new
padding remedy to `322ea6d40`; no later repair found.

Acceptance: both singular/plural blocked summaries remain accurate with pad
blocks, including mixtures with account blocks; the printed padding command
has the required fields and can be run against the synthetic ledger to make
the deliberate adjustment; a normal refusal still leaves every byte intact.
Pin human and JSON diagnostics. Windows/Linux and repaired behavior remain
unverified. Sanitized captures and fixture contents are retained under
`.tmp/qa-2026-10-20-cli-loop-d3c5ebec/` (`pad-{1,2}-import-next*` captures
and fixtures). The public setup above is sufficient without ignored files.
