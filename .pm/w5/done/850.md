# `bea check` with any bean-check option (`-C`, `-v`, native `--json`) shows only a reserved-key error and hides the ledger's other errors, with a wrong count (incomplete fix of w5/630)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `3295e9a3d`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/630 (done).
w5/630 says `check` reports the reserved key under every bean-check option. It
should add that error to the others, not replace them. No product fix
implemented.

`m.bean`:

```
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
2024-01-02 * "Shop" "receipt attached"
  filename: "scan-0042.pdf"
  Expenses:Food  1.00 USD
  Assets:Cash
2024-01-03 * "Shop" "unbalanced"
  Expenses:Food  2.00 USD
  Assets:Cash   -1.00 USD
2024-01-04 balance Assets:Cash -5.00 USD
```

Actual:
- `bea -f /abs/m.bean check` reports `3 error(s).` and lists all three.
- `check -C` (and `-v`) reports `1 error(s).`, only the line-3 reserved-key
  error.
- `check --json` gives `{"errors": [<reserved key only>]}`. The unbalanced
  transaction and the failed balance are missing.

Control: with `receipt:` instead of `filename:`, `check -C` lists both errors.

Expected: options that don't change what is loaded report the same errors
as plain `check`.

Cause: `cli/src/cli/commands/check.py` (around `:136-142`) adds reserved keys to
the crash list, which short-circuits native bean-check. With options, only
that list is printed. The short-circuit was meant for plugin and booking
crashes, but bean-check handles reserved keys itself.

Fix: run native bean-check and merge the reserved-key lines into its output
(as `_merge_json_errors` does for portability findings).

Dedupe: w5/630 (done) is the parent; w5/256 and 538 (done) are related.

Acceptance: all three forms report 3 errors. A test pins `-C` and `--json`.

---

**Resolved 2026-10-20** — with bean-check options (`-C`, `-v`, its `--json`) a reserved `filename:`/`lineno:` key no longer short-circuits native bean-check: bean-check runs, and the key's located error is added after its text list (exit 1) or merged into its JSON `errors`, so the note's ledger reports all three errors in every form; plain `check` still counts `3 error(s).`, and plugin and booking crashes still short-circuit. `tests/test_location_metadata_reserved.py` pins `-C`, `-v`, `--json` and plain check; USAGE says the key is added to the other errors, never in place of them.
