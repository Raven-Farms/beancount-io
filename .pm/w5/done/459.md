# `bea query -o out.beancount` (or `.bean`) on a SELECT writes an ASCII text table into a file named as a ledger; `.tsv` and `.json` destinations are refused for exactly this reason

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
`query -o` infers or refuses the output format from a few suffixes
(`.csv`, `.tsv`, `.json`). A ledger suffix is not among them, so a
SELECT's text table is written under a ledger name. Such a file can later
be included by a glob or opened as a ledger, and it then fails to parse.
`--format beancount` already refuses a SELECT with a clear message. No
product fix implemented.

Use any ledger with transactions. Use isolated
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, and closed
stdin.

```sh
bea -f /absolute/books/main.bean query -o /absolute/out/p.beancount "SELECT date, narration"
bea -f /absolute/books/main.bean query -o /absolute/out/p.tsv "SELECT date"
```

Actual: the first exits 0, and `p.beancount` holds the boxed text table
(`   date     narration` / `----------`). The second exits 2 with
`--output …/p.tsv looks like TSV; pass --format csv (or rename the file)
so the destination is not an ASCII text table.`. Reproduced by the
hunter for both `.bean` and `.beancount`, and by me once.

Control: `-o o.beancount "PRINT …"` writes valid directives.

Expected: treat `.bean`/`.beancount` like the other suffixes. Either
infer `--format beancount`, so a SELECT is refused by the existing "must
return entries; use PRINT" message, or refuse with "looks like a ledger
file; use PRINT or --format text".

Cause: `cli/src/cli/commands/query.py:300-316` handles only `.csv`,
`.tsv` and `.json`.

Fix: add the ledger suffixes to that mapping, inferring `beancount`. No
dependency change.

Dedupe: w5/289 (dot-commands with `-o`), w2/021 (beancount format) and
w5/159 (`-o` symlink alias) cover other cases, and earlier notes added
the `.tsv`/`.json` refusals. None covers ledger suffixes.

Acceptance: `query -o p.beancount "SELECT …"` exits 2 with the PRINT
hint and writes nothing. `PRINT` to `.beancount` still works. A test pins
both.

---

**Resolved 2026-10-15** — `query -o` (`cli/src/cli/commands/query.py`) now infers `--format beancount` from a `.bean` or `.beancount` destination (any letter case), alongside the existing `.csv` inference and `.tsv`/`.json` refusals. A SELECT there exits 2 with the existing "use PRINT, or --format text or csv" message and writes nothing, `PRINT` still writes directives, and an explicit `--format text` is still honoured. `cli/tests/test_query_output_ledger_suffix.py` covers the refusal for `p.beancount`, `p.bean` and `P.BEANCOUNT`, PRINT, and the explicit-format control; the 3 refusal cases fail with the fix reverted. Only macOS was exercised. `make check-all` passed (6012 tests). Shipped in `360c4ed6` (`cli`).
