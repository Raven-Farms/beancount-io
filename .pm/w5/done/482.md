# `bea ask` prints a proxy's entire HTML error page as the error message; the cloud commands say `Server error (HTTP 501).`

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `0864aeed`, checkout `bea 0.3.1`, macOS 26.5.1. Simulation: a local stub answers the AI proxy POST with a 501 HTML page. CDNs and reverse proxies answer 502/503/504 this way.
w3/381, w3/445 and w5/373 deliberately pass a plain-text sentence from the
server through to the user. A non-JSON body that is markup is passed
through too, so the user sees 18 lines of HTML instead of the status. No
product fix implemented.

```sh
BEA_TOKEN=<any> BEA_API_URL=http://127.0.0.1:<stub> bea -f /abs/main.bean ask "q" --print
BEA_TOKEN=<any> BEA_API_URL=http://127.0.0.1:<stub> bea cloud ledger create qa-books
```

Actual: `ask` exits 1 with `Error: Server error (<!DOCTYPE HTML> <html
lang="en"> … <p>Error code: 501</p> … </html>).` across 18 lines. `cloud
ledger create` exits 1 with `Error: Server error (HTTP 501).`

Expected: `Server error (HTTP 501).`, as the cloud commands say. Keep a short
plain-text sentence when the server sends one.

Cause: `cli/src/cli/errors.py:136-142` returns any non-JSON body as the
sentence; the cloud client (`cli/src/cli/api/client.py:246-250`) reads only
JSON.

Fix: fall back to `HTTP <status>` when the body looks like markup (starts
with `<`) or spans several lines or more than a short sentence.

Dedupe: searched `DOCTYPE`, `HTML`. w5/373 (unreadable model reply) is the
nearest; it does not cover an HTML error body.

Acceptance: the `ask` command above prints `Server error (HTTP 501).`; a
one-line plain-text body is still shown. A test pins both.

---

**Resolved 2026-10-16** — Shipped in `0b9f821c` (`cli`). `server_message` (`cli/src/cli/errors.py`) no longer passes markup through as the server's sentence: a body starting with `<` falls back to `HTTP <status>`, and so does raw text that spans lines or runs past 200 characters. `bea ask` therefore says `Server error (HTTP 501).`, as the cloud commands do. A short plain-text sentence and any message inside a JSON envelope, multi-line included, still pass through. `tests/test_ask_html_error_body.py` pins the HTML page, one-line markup, multi-line and long text, and both `ask` outcomes; five fail without the fix.
