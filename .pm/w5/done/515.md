# Global `--offline` is ignored by every `bea cloud` command: `bea --offline -y cloud ledger delete` sends the DELETE and exits 0

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `d16aea3e`, checkout `bea 0.3.1`, macOS 26.5.1. Simulation: local stub API on 127.0.0.1.
`--offline` reads "Never fetch" in `--help`, USAGE's options table and
REFERENCE. The code calls it "no network at all: a run on a plane or in a
sandbox" (`cli/src/cli/update.py:274`). `bea --offline price refresh`, the
other command that exists to use the network, refuses with exit 2. The cloud
commands never read the flag, so an agent that adds `--offline` to stay in a
sandbox still creates, deletes and revokes hosted resources. No product fix
implemented.

Child env: `BEA_API_URL=http://127.0.0.1:<stub>`, `BEA_TOKEN=<test token>`, isolated config/cache, closed stdin.

```sh
bea --offline --json -y cloud ledger delete qa/books
bea --offline cloud ledger create newbook
bea --offline cloud ledger list
```

Actual: all exit 0; the delete prints `{"data": {"ledger_id": "1005"}}`, and
the stub logs `DELETE /api-gateway/v1/ledgers/qa/books`, `POST
/api-gateway/v1/ledgers` and `GET /api-gateway/v1/ledgers?page=1&limit=50`.
`cloud logout` with a stored credential also POSTs the revocation.

Control: `bea --offline price refresh` exits 2 with `price refresh requires
network access; remove --offline.` and fetches nothing.

Expected: under `--offline`, each `bea cloud` command (and `bea ask`, whose
model calls go through the hosted proxy) exits 2 before reading credentials
or sending anything: `bea cloud … requires network access; remove
--offline.` `upgrade --check` stays the documented exception (USAGE: "still
asks, since that check is the explicit request"). If cloud commands are
meant to be exempt too, USAGE and `--help` should say so.

Cause: `ctx.offline` is set at `cli/src/cli/main.py:368` and is never read
under `cli/src/cli/commands/cloud/`, in `cli/src/cli/api/client.py`, or by
`ask`.

Fix: one check where the authenticated client is built (or in the `cloud`
and `ask` callbacks) that refuses under `--offline`.

Dedupe: w5/458 (update check) and w1/079 (price cache) cover other
`--offline` paths. No note covers cloud or ask.

Acceptance: the three commands exit 2 without a request; `price refresh` is
unchanged. A test with a stub pins it.

---

**Resolved 2026-10-17** — Shipped in `d78a8114` (`cli`). A `cloud_app` callback (`cli/src/cli/commands/cloud/app.py`) now refuses every `bea cloud` command under global `--offline` with exit 2 (`bea cloud ledger requires network access; remove --offline.`). It runs before credentials are read or anything is sent, while `--help` still answers. `bea ask` (`cli/src/cli/commands/ask.py`) refuses the same way, since its model calls go through the hosted proxy. `price refresh` is unchanged, and `upgrade --check` stays the documented exception. USAGE's options table lists the commands that refuse. `tests/test_offline_refuses_network_commands.py` uses a recording stub API to pin `cloud ledger delete/create/list`, `cloud logout` and `ask` (exit 2, no request; all fail without the fix), a control that does reach the stub, and `--help`.
