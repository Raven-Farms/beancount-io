# `bea example` exits 0 with a ledger that fails `bea check` when the range starts mid-year and crosses January 1

**Major · cli · 30–45m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
For a date range that begins after January and runs into the next year, the
generated example ledger contains a failing balance assertion. `bea example`
writes the file, prints the upstream validation error on stderr and still
exits 0. No product fix implemented.

No fixture is needed. Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea example --seed 1 --date-begin 2024-06-01 --date-end 2025-06-01 -o mid1.bean
bea -f mid1.bean check
```

Actual: `example` exits 0, writes `mid1.bean`, and stderr shows:

```text
<string>:2272: Balance failed for 'Assets:US:Federal:PreTax401k': expected 0 IRAUSD != accumulated 500.00 IRAUSD (500.00 too much)
```

`bea check` then exits 1 with the same error at `mid1.bean:2272`. A worker
found the same failure for seeds 0–7 and unseeded runs across three such
ranges, for the one-sided `--date-begin 2025-06-01`, and a second trigger
(`Invalid reference to inactive account`) when `--date-birth` falls after
January 1 of the begin year.

Control: `bea example --seed 1 --date-begin 2024-01-01 --date-end 2025-06-01
-o jan1.bean` has empty stderr and `bea -f jan1.bean check` exits 0.

Expected: `docs/USAGE.md` says "Exit 0 is a promise: the documented effect
happened", and `bea example` already refuses ranges the generator cannot
handle. An example its own `check` rejects is not a usable example; the run
should exit 1 and leave no new `-o` file, or produce a valid ledger.

Cause: `cli/src/cli/commands/example.py:42-47` judges only the upstream
return code. Upstream `bean-example` writes the file, then logs loader
errors to stderr and returns normally. The upstream defect is a yearly
`balance … 0 IRAUSD` assertion that assumes a full-year job.

Fix: treat upstream validation diagnostics as failure — generate to a
buffer, validate, and write atomically only when valid (exit 1 otherwise).
Optionally refuse `--date-birth` after the begin year's January 1 with
exit 2. No dependency or API change.

Blast radius: `bea example` with `--date-begin` not on January 1; the
default run is unaffected.

Dedupe: board search for `PreTax401k`, `IRAUSD`, `validate_output` and
"Balance failed" with example finds w1/086 (range guard) and w3/336
(overwrite); neither covers output validity.

Acceptance: the first command either exits 0 with a file that passes
`bea check`, or exits 1 and leaves no `mid1.bean`; the January 1 control is
unchanged. A real-command regression test covers a mid-year range. Only
macOS and the checkout (Beancount 3.2.3) were exercised.

---

**Resolved 2026-10-13** — `bea example` now captures the history `bean-example` generates and treats upstream's own validation errors as a failure: exit 1, naming the errors, with nothing printed or written (`cli/src/cli/commands/example.py`). The `-o` destination is written by `bea` itself, atomically, only after the run validates, so a failed run leaves no new file and an existing `--force` target untouched. Tests run the real command for a mid-year range to a file, to stdout and over a forced target, and for the January 1 control, which still passes `bea check`; ten cases fail with the fix reverted. The optional exit-2 refusal of a late `--date-birth` was not added; that case exits 1 through the same path. Side effect: a missing parent directory or a directory destination now exits 2 before generating, matching `treeify -o`. `docs/USAGE.md` describes the behaviour. Only macOS was exercised. `make check-all` passed. Shipped in `f48ae189` (`cli`).
