# The balance sheet's "Valuation/translation adjustment" for one period differs with and without `-t`: with `-t`, the FX gain moves onto an `Equity:Conversions` line the unfiltered report never shows

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-17, HEAD `d657cff90`, checkout `bea 0.3.1`, macOS 26.5.1.
No product fix implemented. Totals agree either way; the split does not.

`fxcost.bean`:

```
option "operating_currency" "USD"

2024-01-01 open Assets:USD USD
2024-01-01 open Assets:EUR EUR
2024-01-01 open Equity:Opening-Balances

2024-01-01 * "Opening"
  Assets:USD 1000.00 USD
  Equity:Opening-Balances

2024-01-10 * "Buy EUR"
  Assets:EUR 100.00 EUR @ 1.10 USD
  Assets:USD -110.00 USD

2024-01-31 price EUR 1.20 USD
```

```sh
bea -f /abs/fxcost.bean report balance-sheet
bea -f /abs/fxcost.bean report balance-sheet -t 2024-01
```

Actual: both cover 2024-01-01 through 2024-01-31 and exit 0.
- **Without `-t`:** `Equity -1,000.00 USD` and `Valuation/translation adjustment
  (credit): -10.00 USD`. JSON `valuation_adjustment` is `{"USD": "-10.0000"}`.
- **With `-t 2024-01`:** `Equity -1,010.00 USD`, including `Conversions -10.00 USD`,
  and `Valuation/translation adjustment (credit): 0.00 USD`. JSON is `{"USD":
  "0"}`.
- On the hunter's two-year household ledger at 2026-09-30, the adjustment is
  −924.03 USD without `-t`. With a `-t` range it is −715.81 USD, plus an
  `Equity:Conversions` line of −208.22.
- With `-t`, the units trial balance gains a Conversions line.

Expected: one equity breakdown per period. USAGE describes
`valuation_adjustment` as the derived reconciling figure, and the line is
labelled "translation". With `-t` it holds only the unrealized gain on lots,
not the exchange gain.

Cause: the adjustment is whatever remains after the equity tree
(`cli/src/fava/modules/financial_statements.py`, around `:124-137`). The tree
has `Equity:Conversions:Current` only when `-t` runs Beancount's period cut
(`cli/src/fava/core/filters.py`, around `:398-405`, reached from
`cli/src/fava/ledger.py:183-186`).

Fix: present the same split either way. Either fold the cut's
`Equity:Conversions:Current` into the adjustment line, or always show a
conversions line. Pin both forms in a test.

Dedupe: w5/505, 506, 127 and 501 (done) cover other equity lines.

Acceptance: both commands show the same equity and adjustment lines.

---

**Resolved 2026-10-19** — the sheet's equity tree leaves the clamp's `C`-flagged conversion bookings out, so the residual adjustment absorbs them and filtered/unfiltered sheets match byte for byte in text and JSON; user-written bookings keep their own flag and file, trial balance keeps the row per w5/501, and the w5/748 sheet notice for the folded row's residual is dropped (its numbers were identical either way).
