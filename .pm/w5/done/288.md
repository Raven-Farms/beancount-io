# `bea query --source memory:` prints a long traceback, and the bad-scheme error recommends `memory:...`

**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Fix with [250](./250.md).
The `--source` scheme allow-list (added by w3/done/274 so that unusable
schemes never reach a traceback) includes `memory`, which upstream cannot
attach from the command line. The refusal message for any other bad scheme
suggests it. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
2024-01-01 open Equity:Opening USD
2024-01-02 * "Open"
  Assets:Cash  100.00 USD
  Equity:Opening
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea query --source memory: "SELECT 1"
bea query --source bean:main.bean "SELECT 1"
```

Actual: the first exits 1 with a boxed traceback (about 70 lines) ending
`AttributeError: module 'beanquery.sources.memory' has no attribute
'attach'`. The second exits 2: `Error: --source scheme 'bean' is not
supported; use beancount:..., csv:..., memory:..., test:..., or a bare
path.`

Control: the second command's one-line refusal. A worker saw a `csv:`
source answer normally, an existing `-o` file left intact by the crash,
and stock `bean-query memory:` fail with the same `AttributeError`.

Expected: a one-line usage error (exit 2) for a scheme that can never
work, and a hint that lists only schemes that do.

Cause: `cli/src/cli/commands/query.py:41` (`_SOURCE_SCHEMES` includes
`memory` and `test`) and the message at `:50-51`; the upstream `memory`
source has no `attach`. `source_query`
(`cli/src/bea_engine/main.py:582-591`) catches only engine errors.

Fix: drop `memory` from the allow-list and the hint; decide whether
`test:` (Beanquery's unit-test table) belongs there. No dependency change.

Blast radius: `query --source` one-shot and shell.

Dedupe: board search for `memory:` and `_SOURCE_SCHEMES` finds
w4/done/181 and w1/done/038 (which mention `memory:` only as naming no
file) and w3/done/274 (unknown schemes).

Acceptance: `--source memory:` exits 2 with one line; the bad-scheme hint
names only working schemes. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — The `--source` scheme allow-list in `cli/src/cli/commands/query.py` no longer includes `memory`, whose upstream Beanquery module has no `attach`, so `bea query --source memory:` now exits 2 with the one-line "scheme 'memory' is not supported" refusal instead of an AttributeError traceback, for the one-shot and the interactive shell alike, and the hint for any bad scheme lists only `beancount:...`, `csv:...`, `test:...` or a bare path. `test:` stays in the list because it attaches and answers queries. The new `cli/tests/test_query_source_memory_scheme.py` covers three `memory` spellings with an existing `-o` export left intact, checks that every scheme the hint names actually answers a query, and checks that the interactive path never opens a prompt; all 5 cases fail with the fix reverted. The missing-file and directory preflight from w5/249 and w5/250 did not cover this, since it only inspects `beancount` and `csv` sources. The engine helper invoked directly with `memory:` still surfaces upstream's error; only the frontend refusal changed. Only macOS was exercised. `make check-all` passed. Shipped in `7938f876` (`cli`).
