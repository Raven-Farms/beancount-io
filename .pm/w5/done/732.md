**Minor · cli · 10–15m · A1.** Real CLI QA, 2026-10-17, HEAD `eea79d702`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/538 (done, `885acda5f`).
The w5/538 resolution says that "every read and write therefore names
FILE:LINE: Beancount cannot book this transaction". Two other booking failures
from the same upstream frame still escape. No product fix implemented.

A ledger opening `Assets:Checking USD`, `Assets:Brokerage`, `Income:Gains
USD` and `Equity:Opening`, with a deposit, plus:

```
2026-02-01 * "missing units with cost"
  Assets:Brokerage  HOOL {0 USD}
  Assets:Checking  -10 USD
```

```sh
bea -f /abs/r5.bean check
bea --json -f /abs/r5.bean balance
bea -f /abs/clean.bean add transaction gift --date 2026-02-01 -p 'Assets:Brokerage HOOL {0 USD}' -p 'Assets:Checking -10 USD'
```

Actual:
- `check` exits 1 with bean-check's traceback, ending `TypeError: bad operand
  type for abs(): 'type'`.
- `--json balance` exits 1 with `TypeError: bad operand type for abs():
  'type'. Pass --debug before the command for a traceback.`
- The add exits 1 with the same raw error, naming no posting; nothing is
  written.
- `HOOL {{0 USD}}` fails the same way (hunter's run).
- `EUR @ 0 USD` gives `AssertionError: Internal error; residual currency
  different than missing currency.` (hunter's run).

Control: `HOOL {5 USD}` and `EUR @ 2 USD` infer their units; `0 HOOL {{10
USD}}` gets w5/538's message.

Expected: `FILE:LINE: Beancount cannot book this transaction: …` for reads,
and an exit-2 refusal naming the posting for the `-p` add.

Cause: the booking guard (`cli/src/bea_engine/managed_load.py:612-627`)
catches only `DecimalException`.

Fix: also catch the `TypeError`/`AssertionError` that `_interrupted_booking`
can attribute to an entry. Refuse a units-elided `-p` posting next to a zero
cost or price at input.

Dedupe: w5/538 (done) is the parent; nothing open covers these messages.

Acceptance: the three commands name the line or posting, with no Python
error text. Tests pin `check` and the add.
