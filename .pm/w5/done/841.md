# On a ledger that knows no commodity, import advises "Name the commodity with --csv currency=CODE", and the next run refuses exactly that ("no commodity this ledger knows")

**Minor · cli · 5m · A1.** Real CLI QA, 2026-10-17, HEAD `473bce6af`, checkout `bea 0.3.1`, macOS 26.5.1.
IMPORTING.md (around :103-105) says a `currency=` constant "must be a commodity
the ledger already knows". No product fix implemented.

`main.bean` is zero bytes. Whitespace-only, comments-only, plugin-only and
BOM-only files behave the same. `bank.csv` is `Date,Description,Amount` /
`2026-03-01,Coffee,-3.50`.

```sh
bea -f /abs/main.bean import bank.csv --csv date=Date,amount=Amount,narration=Description --account Assets:Cash
bea -f /abs/main.bean import bank.csv --csv date=Date,amount=Amount,narration=Description,currency=USD --account Assets:Cash
```

Actual: the first exits 2 with `… no currency column and the ledger has no
single operating currency. Name the commodity with --csv currency=CODE, or
open the source account for one currency.` Following it exits 2 with
`currency=USD names no column of bank.csv and no commodity this ledger knows.
… declare it first: bea add commodity …`.

Control: on an `option "operating_currency" "USD"`-only ledger, `currency=USD` is
accepted.

Expected: when the ledger knows no commodity, lead with opening the source
account for one currency (or declaring the commodity), not with an option
the next run refuses.

Cause: the advice at `cli/src/bea_engine/csv_mapper.py:1315` is unconditional;
the known-currency gate is at around `:1124-1131`.

Fix: tailor the advice when no commodity is known.

Dedupe: w5/318 (done) is a different misadvice; w5/838 (open) covers the
missing `--file` in "bea add commodity".

Acceptance: following the first advice leads to an import that works.

---

**Resolved 2026-10-20** — when the ledger knows no commodity at all (empty, comment-only, BOM-only), the no-currency refusal now reads `no currency column, and the ledger knows no commodity yet. Open Assets:Cash for one currency first: bea add open --account Assets:Cash --currency CODE --date YYYY-MM-DD.`; following it lets the next import read its rows (the default category's own `add open` remedy is the usual next step), and a ledger that knows commodities keeps the `--csv currency=CODE` advice. `tests/test_import_currency_advice_on_empty_ledger.py` follows the advice on three empty shapes and pins the control. Gate note: gated as one stack with w5/840–842 (one `make check-all`, each item shipped as its own commit); its failures were load-induced managed-price fetch timeouts (`test_price_source_limit.py`, one `test_price.py` case) and a release test whose package download failed after three retries, none touching this change. Shipped in `2fd060ad3` (`cli`)
