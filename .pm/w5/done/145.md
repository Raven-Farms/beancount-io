# The first write into a not-yet-existing `--into` file under an include glob defeats `add price` conflict detection

**Major · cli · 15–20m on top of w5/092 · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS (APFS).
Creating the next period's file with `--into` is the normal flow for a
split ledger. When that file is matched by an include glob and does not
exist yet, `add price` no longer sees prices written after the glob in the
including file: a conflicting quote is accepted with exit 0, and an exact
duplicate is written. Fix together with w5/092, which names the same code
site under a different trigger. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
include "2024/*.bean"
2024-01-01 open Assets:Cash USD
2024-01-01 open Assets:Broker
2024-01-01 open Equity:Open
2024-01-01 commodity ACME
2024-03-15 price ACME 10 USD
2024-03-31 balance Assets:Cash 100 USD
```

`/absolute/books/2024/01.bean`:

```beancount
2024-01-05 * "open"
  Assets:Cash  100 USD
  Equity:Open
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY. cwd `/absolute/books`.

```sh
bea -f main.bean add price --into 2024/03.bean --date 2024-03-15 --commodity ACME --amount "12 USD"
bea -f main.bean check
bea -f main.bean list price
```

Actual: `add price` exits 0 with `Added 1 price to
/absolute/books/2024/03.bean.`; `check` exits 0; `list price` shows both
`2024-03-15 ACME 12 USD` and `2024-03-15 ACME 10 USD`.

Control: with an existing `2024/02.bean` (one zero-amount transaction) as
the destination, the same command exits 2: `ACME already has a 2024-03-15
price of 10 USD (at /absolute/books/main.bean:7); refusing 12 USD. Pass
--force to record another quote.`

A worker additionally observed with the absent destination: `--amount "10
USD"` under `--json` reports `"written": 1, "duplicate": false`; `add
balance` reports its duplicate at `main.bean` line 10 of an 8-line file;
and an import preview cites `Existing entry at main.bean:8` for an entry on
line 6.

Expected: `docs/USAGE.md` says "`add price` skips an exact
date/commodity/amount match anywhere in the root ledger's includes… A
different amount for the same date and commodity is refused naming both
values", and that "An absent destination is created only when a validated
write succeeds" — nothing suggests it weakens the checks.

Cause: `cli/src/bea_engine/managed_load.py:284` takes the plain-load path
only when every file in the snapshot exists. A planned, absent destination
sends the whole ledger through the shadow loader, whose glob expansion
(`:550`) joins matches with `"\ninclude "`; with the planned file counted,
even a one-file glob becomes two lines and every later line of the includer
shifts. The price is then looked for on the shifted line, classed as
plugin-generated and dropped from the conflict set.

Fix: as w5/092 — preserve the includer's line numbering in the shadow copy
or translate line numbers back. Add this trigger to that note's acceptance.
No dependency or API change.

Blast radius: `add price`, `add balance` and `import` when the destination
does not exist yet, is matched by a glob, and the includer has content
after the glob. No managed price include is needed.

Dedupe: w5/092 covers this site only with "a managed price include plus a
multi-file glob"; w5/079 is the write-validation twin. Neither mentions an
absent destination or a single-match glob.

Acceptance: the first command exits 2 naming `main.bean:7` and creates no
`2024/03.bean`; the exact-duplicate amount reports `duplicate: true` with
line 7; the existing-file control is unchanged. A real-command regression
test covers the absent destination. Only macOS and the checkout were
exercised.

---

**Resolved 2026-10-13** — The behaviour no longer reproduces: the single-line staged include that w5/092 put into `cli/src/bea_engine/managed_load.py` keeps the includer's line numbering on this path too, so with a not-yet-existing `--into` file under an include glob `add price` refuses the conflicting quote with exit 2 naming `main.bean:7`, creates no file, and reports the exact duplicate as `duplicate: true` at line 7. Nothing pinned this trigger, since the w5/092 tests need a managed price include and existing files, so this change is test-only: `cli/tests/test_into_absent_glob_destination_duplicates.py` runs the note's fixture through the real commands. It covers the conflict, the exact duplicate under `--json` and the `add balance` duplicate line for both an absent and an existing destination, plus a quote for another day still creating the absent file and passing `check`. With the w5/092 source change reverted, the three absent-destination cases fail and the four others pass. The import preview's cited line, which the note mentions as an extra observation outside its acceptance, was not given a test of its own. Only macOS was exercised. `make check-all` passed. Shipped in `318ec6e5` (`cli`).
