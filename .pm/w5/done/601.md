# `bea import` matches migrated digests only under `csv:`/`mint:`/`monarch:`/`qbo:`; beancount-migrate's generic path writes `<source>:sha256:`, so the first bank import after such a migration double-books every overlap row with exit 0

**Minor · cli + skills · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `5e09bcc4`, checkout `bea 0.3.1`, macOS 26.5.1.
`skills/.claude/skills/beancount-migrate/SKILL.md` (around line 58) and
`references/mapping.md` (around lines 88-90) write `<source>:sha256:<digest>`
for unknown sources (YNAB, Actual, a spreadsheet). They promise the first
import "won't double-book overlap rows". IMPORTING.md says bea recognizes
"any documented prefix", and the CLI's pattern lists four. The digest is
identical; only the prefix differs. No product fix implemented.

`main.bean`:

```beancount
option "operating_currency" "USD"

2026-03-04 open Assets:Checking USD
2026-03-04 open Expenses:Groceries USD
2026-03-04 open Expenses:Uncategorized USD

2026-03-08 * "Trader Joes" "TRADER JOES #123 SEATTLE WA"
  import-id: "ynab:sha256:9b811ad4dd24f37f"
  Assets:Checking     -54.20 USD
  Expenses:Groceries   54.20 USD
```

`checking.csv`: `Date,Description,Amount` / `2026-03-08,TRADER JOES #123
SEATTLE WA,-54.20`.

```sh
bea --file /abs/main.bean import checking.csv --csv date=Date,narration=Description,amount=Amount --account Assets:Checking --apply
```

Actual: exit 0, `1 ready, 0 exact duplicates`; it writes `import-id:
"csv:sha256:9b811ad4dd24f37f"`, the same digest; Checking is `-108.40 USD`.

Control: the same ledger with `monarch:sha256:` gives `1 exact duplicates`.

Expected: −54.20 USD; the digest matches under any source prefix.

Cause: `_GENERATED_ID = re.compile(r"(?:csv|mint|monarch|qbo):sha256:([0-9a-f]{16})")`
(`cli/src/bea_engine/importing.py:1036`).

Fix: match `[a-z][a-z0-9-]*:sha256:<16 hex>` (document it in IMPORTING.md), or
have the migrate skill's generic path write `csv:sha256:`.

Dedupe: searched `generic path`, `ynab`, `prefix`. No match.

Acceptance: the YNAB-prefixed fixture imports as an exact duplicate. A test
pins it.

---

**Resolved 2026-10-17** — Shipped in `eb0d8b68` (`cli`) and `891e2823` (`skills`).
- `_GENERATED_ID` (`cli/src/bea_engine/importing.py`) now accepts any lowercase source name (`[a-z][a-z0-9-]*:sha256:<16 hex>`). The note's `ynab:` fixture imports as `1 exact duplicates`, leaving Checking at −54.20 USD. A native id without `:sha256:` is still not a digest.
- IMPORTING and the import skill's `dedup.md` name the generic `<source>:sha256:` form beside `mint:`, `monarch:` and `qbo:`.
- `tests/test_import_generic_migration_prefix.py` pins `ynab`, `actual` and `my-sheet2` (all fail without the fix), plus the `monarch` and `csv` controls and a native `ref:` id.
- `make check-all` and the skills checks passed.
