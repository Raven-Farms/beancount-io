# `FROM ACCOUNTS`, `FROM Accounts` and `FROM Balances` are rewritten to a quoted mixed-case table that does not exist, exit 2, where `bean-query` accepts them

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `7898f69d`, checkout `bea 0.3.1`, macOS 26.5.1. Differential run against upstream `bean-query`.
bea quotes the reserved table names `accounts` and `balances` so that they
parse (w3/246, w3/398). It matches them case-insensitively but quotes the
text as typed, and table lookup is case-sensitive. No product fix
implemented.

Any ledger with a few opens.

```sh
bea --file /abs/main.bean --json query "SELECT account FROM ACCOUNTS"
bea --file /abs/main.bean query "SELECT account, amount FROM Balances"
```

Actual: exit 2, `Cannot run this BQL query: table "ACCOUNTS" does not
exist.`, with details showing `SELECT account FROM "ACCOUNTS"` (quotes the
user did not type).

Control: `FROM accounts` lists the accounts.

Expected: the rewrite emits the lowercase table name, so any case works.

Cause: `_RESERVED_TABLE_FROM` uses `(?i)` (`cli/src/bea_engine/query.py:51`)
and `_quote_reserved_tables` writes `f'"{query_string[start:end]}"'`
(`query.py:140`).

Fix: quote the lowercase name.

Dedupe: searched `FROM ACCOUNTS`, `FROM Balances`. No match.

Acceptance: both commands answer. A test pins them.

---

**Resolved 2026-10-17** — Shipped in `5773855b` (`cli`). `_quote_reserved_tables` (`cli/src/bea_engine/query.py`) still matches `accounts`/`balances` after `FROM`/`JOIN` in any case, but now quotes the lowercase name. `bea --json query "SELECT account FROM ACCOUNTS"` lists the accounts, and `bea query "SELECT account, amount FROM Balances"` lists the assertions, as `bean-query` does. `tests/test_query_reserved_tables.py::test_a_reserved_table_name_in_any_case_hits_the_real_table` pins both and fails without the fix. `make check-all` passed.
