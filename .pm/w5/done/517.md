# A gateway timeout (504, Cloudflare 524) on `cloud ledger create`/`delete` exits 1 "Server error", though the same timeout seen by bea's own timer exits 4 "outcome unknown"

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `d16aea3e`, checkout `bea 0.3.1`, macOS 26.5.1. Simulation: local stub returns proxy error pages.
USAGE: "A write whose outcome the CLI cannot know (a timeout mid-delete) exits
**4** and says so rather than guessing." A 504 or 524 is that same timeout,
reported by the proxy instead of by bea: the origin received the request and
did not finish answering. The user is told "Server error", retries, and gets
409 (create) or 404 (delete). The backend's own Fava client turns an upstream
timeout into 504 (`backend-cluster/backend-v2/src/foundation/fava/api-client.ts:79`),
so this is not theoretical. No product fix implemented.

Stub: `POST /api-gateway/v1/ledgers` and `DELETE *` answer 504 `text/html`
`<html><body><h1>504 Gateway Time-out</h1></body></html>` (variant: 524
with a `cf-ray` header).

```sh
bea --json cloud ledger create newbook
bea --json -y cloud ledger delete qa/books
```

Actual: both exit 1 with `{"category": "validation", "message": "Server
error (HTTP 504).", "exit_code": 1}`; the stub received both requests.

Control: a stub that sleeps 40 s makes the same create hit bea's ReadTimeout
and exit 4: `Creating ledger 'newbook' did not complete cleanly
(ReadTimeout). The outcome is unknown — check the current state before
retrying.`

Expected: on writes, 504 and 520–524 map to the unknown-outcome error (exit
4, "check the current state before retrying"); reads keep exit 1. USAGE's
"server errors exit 1" sentence gains that exception.

Cause: the write paths route only transport errors and `UnreadableSuccess`
to `unknown_write_outcome` (`cli/src/cli/commands/cloud/ledger/app.py:78-83`,
`cli/src/cli/commands/cloud/generated/ledger.py:97-101`, generated from
`cli/scripts/gen_cloud_commands.py:209-212`); `error_from_status`
(`cli/src/cli/errors.py:169`) maps every 5xx to exit 1.

Fix: classify gateway-timeout statuses on write paths as unknown outcomes,
in the generator and the hand-written create, and regenerate.

Dedupe: w5/422 (unreadable 2xx) and w5/368 (connect errors) are done; no
note covers 5xx gateway errors on writes.

Acceptance: both commands exit 4 with the unknown-outcome wording under
504/524; a 500 stays exit 1. A test pins it.

---

**Resolved 2026-10-17** — Shipped in `d35e69bf` (`cli`). `error_from_status` (`cli/src/cli/errors.py`) now raises `GatewayTimeout`, a `BeaError` with the same "Server error (HTTP 504)." text and exit 1, for 504 and Cloudflare's 520–524. Reads report it as before. The write paths turn it into the exit-4 unknown outcome: the hand-written `cloud ledger create`, plus `cloud ledger delete` and every other generated write through `scripts/gen_cloud_commands.py`, regenerated into `generated/ledger.py`. The message reads `Creating ledger 'newbook' timed out at the server's gateway (HTTP 504): the request arrived but was not answered. The outcome is unknown — check the current state before retrying.` USAGE's exit-code paragraph names the statuses. `tests/test_cloud_write_gateway_timeout.py` pins create and delete under 504 and 524 (all fail without the fix), a 500 write (exit 1), and a 504 read (exit 1).
