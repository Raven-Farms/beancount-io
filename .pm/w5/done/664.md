# Under `nounused` or `pedantic`, plain `add balance` cannot be a staged account's first use outside a terminal (scripts, `--json`, CI), though every other write can (gap in w5/221)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `5a0cdcb4`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE's two-step for these plugins: stage the open with `--allow-errors`,
then add the account's first entry. `add transaction`, `add transactions`,
`import`, `add note`, `add document`, `add close` and `add balance --pad-from`
all clear the staged error without the flag. Plain `add balance` runs a
strict pre-read that exempts only `Unused Pad`. A terminal is lenient, so
the same command works interactively and fails in a script. No product fix
implemented.

```beancount
option "operating_currency" "USD"
plugin "beancount.plugins.nounused"

2026-01-01 open Assets:Cash USD
2026-01-01 open Equity:Opening USD

2026-01-02 * "Fund"
  Assets:Cash  1000 USD
  Equity:Opening
```

```sh
bea --file /abs/main.bean add open --date 2026-01-03 --account Assets:Savings --currency USD --allow-errors
bea --file /abs/main.bean add balance --date 2026-01-10 --account Assets:Savings --amount "0 USD"     # stdin closed
```

Actual: exit 1, `The ledger already has 1 error(s); nothing was written. Pass
--allow-errors to write anyway.` with `main.bean:11: Unused account
'Assets:Savings'`, and no nounused hint (JSON the same). Under a PTY the same
command succeeds and `check` passes afterwards. `pedantic` behaves the same.

Expected: the balance is written without the flag, as the sibling writes
are.

Cause: the strict pre-read in `_balance` (`cli/src/bea_engine/ledger/adding.py:332`;
strictness set in `cli/src/cli/commands/add.py:309`) exempts only `Unused Pad`.

Fix: also exempt an `Unused account` error for the account being asserted.

Dedupe: w5/221 (done) and w5/553 (open, skills) are related.

Acceptance: the second command writes with stdin closed. A test pins it.
