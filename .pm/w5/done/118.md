# `bea doctor roundtrip` leaves a full-size load cache for its scratch file beside a slow-loading ledger

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`),
checkout `bea 0.3.1`, macOS.
The roundtrip diagnostic writes two scratch copies of the ledger and removes
them, but on a ledger slow enough to be cached Beancount also writes a hidden
cache for the first scratch copy, and that file stays behind — about three
times the size of the ledger. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2000-01-01 open Assets:Bank USD
2000-01-01 open Expenses:Food USD
include "big.bean"
```

and generate `/absolute/books/big.bean`:

```sh
python3 -c "open('big.bean','w').writelines(f'2020-01-01 * \"t{i}\"\n  Expenses:Food  1 USD\n  Assets:Bank\n\n' for i in range(60000))"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY.

```sh
bea doctor roundtrip /absolute/books/main.bean
ls -la /absolute/books
```

Actual: exit 0, and the directory now holds
`.main.roundtrip1.bean.picklecache` (9,973,919 bytes beside a 3.6 MB
ledger) in addition to the ledger's own `.main.bean.picklecache`. The run
used a fixture that also carried one `document` line; a worker reproduced
it twice on the fixture above and found a rerun overwrites the same file.

Control (worker-observed): a one-transaction ledger leaves nothing behind.

Expected: `docs/USAGE.md` says the roundtrip's scratch files are removed;
a diagnostic should leave the ledger directory as it found it, and w3/390
removed the same kind of leftover for writes.

Cause: upstream's roundtrip loads `<stem>.roundtrip1<ext>` through the
cached loader and deletes only the two scratch files.
`cli/src/cli/commands/doctor.py:267-275` (`_forward_roundtrip`) already
computes those names but neither disables the cache for the child nor removes
the sidecar.

Fix: run the forwarded child with `BEANCOUNT_DISABLE_LOAD_CACHE=1`, or
unlink the scratch files' sidecars afterwards. No dependency or API change.

Dedupe: board search for roundtrip and sidecar leftovers finds w3/390,
w3/440, w5/014 and w1/074 (write-path sidecars) and w1/156, w1/108
(roundtrip collisions); none covers this file.

Acceptance: after `doctor roundtrip` on the fixture, the directory listing
is unchanged except for the ledger's own cache; the small control is
unchanged. Only macOS and the checkout were exercised.

---

**Resolved 2026-10-13** — `bea doctor roundtrip` now removes the load cache Beancount writes for the first scratch file (`cli/src/cli/commands/doctor.py`). It follows `BEANCOUNT_LOAD_CACHE_FILENAME`, works beside the target of a symlinked ledger, and never removes the ledger's own cache or a file the run did not write. The note's first suggested fix (`BEANCOUNT_DISABLE_LOAD_CACHE=1` for the child) was not used, because Beancount then deletes the ledger's existing cache. Tests cover a cached ledger, an uncached slow one, a symlinked ledger and a configured cache name (these four fail with the fix reverted), plus a cache name shared with the ledger, a pre-existing file and the fast control. `make check-all` passed. Only macOS was exercised. Shipped in `3e63ae64` (`cli`).
