# Report balance series leave out `U`-flagged transactions that the headline includes

**Major (wrong numbers) · cli · 30m · A1.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, macOS. A transaction flagged with
the capital letter `U` — a flag `bea add transaction --flag U` accepts and
the guide documents — is counted in a report's headline balances but dropped
from its net-worth and asset series, so one report shows two different net
worths for the same date, with exit 0 and no warning. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Checking USD
2024-01-01 open Equity:Opening
2024-01-01 open Income:Salary
2024-01-01 open Expenses:Food

2024-01-01 * "Opening balance"
  Assets:Checking  1000.00 USD
  Equity:Opening

2024-02-10 U "Employer" "Salary, uncleared"
  Assets:Checking  500.00 USD
  Income:Salary

2024-03-05 * "Grocer" "Food"
  Expenses:Food  40.00 USD
  Assets:Checking
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, and an absolute `--file`.

```sh
bea -f /absolute/books/main.bean report balance-sheet -t 2024-Q1
bea -f /absolute/books/main.bean report overview -t 2024-Q1
```

Actual: the balance sheet prints `Assets 1,460.00 USD` and `Net Worth:
1,460.00 USD`, then monthly net worth `1,000.00`, `1,000.00`, `960.00 USD`.
`--json` gives `net_worth {"USD":"1460.00"}` against a last
`net_worth_series` point of `960.00`. The overview's ASSETS column ends at
960.00 while its INCOME column for February shows `-500.00 USD`: the income
arrives and the asset never moves. Repeated twice.

Independent check: `SELECT sum(position) WHERE account ~ '^Assets' AND date
<= 2024-03-31` returns `1460.00 USD`.

Control: the same file with `!` in place of `U` gives a series of
`1,000.00`, `1,500.00`, `1,460.00 USD`, matching the headline.

Expected: `docs/USAGE.md` Reports says balance series "must still reach the
as-of date", and Adding directives lists "a capital letter" as a valid flag.
The last series point must equal the headline for every flag.

Cause: `cli/src/fava/modules/chart.py:226` (`account_balance`) and `:324`
(`net_worth`) keep only transactions whose flag is not `FLAG_UNREALIZED`
(`"U"`). The headline tree and the flow series apply no such filter. The
exclusion is inherited from Fava, where it hid entries synthesized by
Beancount v2's `unrealized` plugin; the managed engine does not ship that
plugin, so a `U` entry here is a transaction the user wrote.

Fix: build balance series from every transaction the headline tree includes;
remove the flag exclusion in both generators. Keep the vendored-source
attribution intact. No dependency or API change.

Blast radius: `balance-sheet` `net_worth_series` and `overview`
`series.assets`/`series.liabilities`, text and JSON, with or without
`--account`. `fava/modules/accounts.py` carries the same filter but no
`bea` command reaches it.

Dedupe: board search for `FLAG_UNREALIZED`, unrealized and flag `U` finds
only dashboard and mobile holdings items; none concerns CLI report series.
`git log -S FLAG_UNREALIZED -- cli` shows only the vendoring commit.

Acceptance: on the fixture the March point is `1,460.00 USD` in both reports
and in JSON; a regression test pins last series point equal to headline for a
`U`-flagged entry; the `!` control is unchanged. Only macOS and the
checkout were exercised.

---

**Resolved 2026-10-12** — The vendored series generators (`account_balance` and `net_worth` in `src/fava/modules/chart.py`) no longer skip `U`-flagged transactions, so a report's balance series is built from every transaction its headline counts. On the fixture the March point is `1,460.00 USD` in `balance-sheet` and `overview`, text and JSON. The change is commented in place as a Beancount.io modification; vendored attribution is untouched. Shipped in `f1e9cdab` (`cli`).

Regression tests pin the last `net_worth_series` point equal to the headline for `U`, `!`, `*` and another capital-letter flag, the overview asset series against the income it reports, an `--account`-filtered series, and the text report showing a single period-end net worth. The four `U` cases fail with the fix reverted; the other flags pass either way. `fava/modules/accounts.py` carries the same filter but no `bea` command reaches it, so it is left as upstream wrote it. `make check-all` passed. Only macOS was exercised.
