# The `bea ask` system prompt hard-codes `^Expenses`/`^(Assets|Liabilities)` query examples and never tells the model the ledger's actual root names, so on a renamed-root ledger the suggested recipes match nothing

**Trivial · cli · 15–20m · A2.** CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1. **Confirmed from the code only.** Live model behaviour was not exercised.

The `ask` agent's static system prompt teaches BQL recipes that filter by
the default English roots. It never states the ledger's configured
`name_*` roots. On a ledger with `option "name_expenses" "Aufwand"`, a
model that follows the prompt queries `^Expenses` and gets 0 rows, and
the prompt itself says 0 rows means "nothing matched". Answers to
spending or net-worth questions are then wrong, or claim there is no
data. No product fix implemented.

Evidence:

- `cli/src/cli/ask/agent.py:50`, `:63` and `:67-70` give `WHERE account ~
  '^Expenses'` and `'^(Assets|Liabilities)'` for spending, net worth and
  holdings.
- The prompt is the static `_SYSTEM_PROMPT` plus today's date (`agent.py:292-304`).
- `cli/src/cli/ask/results.py:68` has a similar `Assets:Bank:Euro`
  example.

Expected: `ask` answers questions about the user's ledger, so the agent
should know that ledger's root names. The control is the rest of the
CLI, which reads `name_*` everywhere (reports, import defaults, hints).

Fix: add a dynamic system-prompt part that reads the options through a
cheap engine call and, when the roots differ from the defaults, states
them (for example "This ledger's roots are Aktiva, Passiva, Eigenkapital,
Ertrag, Aufwand; use them in place of Assets, … in the examples"). No
dependency change.

Blast radius: `bea ask` on ledgers with renamed roots, which is common
for non-English users.

Dedupe: searched `.pm/**`, including `done/`, for ask together with
`name_`, renamed roots and system prompt. There are no hits. 358 covers
the customer skills' recipes, not the CLI prompt.

Acceptance: on a renamed-root ledger, the prompt sent to the model (as
seen by a mock) names the configured roots. On a default ledger the
prompt is unchanged. A mocked-transport test pins both.

---

**Resolved 2026-10-15** — `make_agent` (`cli/src/cli/ask/agent.py`) now
registers a dynamic system-prompt part. It reads the root ledger's
`option "name_*"` lines as text (`ledger_root_names`; the frontend never
loads Beancount, and the root file's options decide the roots, the last
one winning). When any root differs from the default, the part says:
`This ledger renames its account roots: Aktiva (for Assets), Aufwand (for
Expenses). Use those names wherever the examples above say Assets,
Expenses, as in account ~ '^Aktiva' rather than '^Assets'.` On a default
ledger the part is empty, and Pydantic AI drops it, so the prompt sent to
the model is unchanged. Pinned by
`cli/tests/test_ask_prompt_renamed_roots.py`, which captures the system
prompt through a `FunctionModel` and fails without the fix. Live model
behaviour was not exercised.
