# If the ledger path contains `$NAME`, reads load the environment-expanded file: `check`, `balance` and `list` report a different ledger with exit 0, while writes go to the literal file

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
Upstream Beancount's loader runs `os.path.expandvars(os.path.expanduser(…))`
on the root ledger path, and `bea` passes the path through unchanged. If
the absolute path contains `$NAME` (in the file name or any parent
directory) and that variable is set, the ledger is read from a different
file:

- `check`, `balance`, `list`, `report`, `query` and `doctor` report on the
  other file with exit 0, and cite its path in errors.
- `add` validates and writes the literal file.
- With `$HOME` in the name, every read fails with a missing-file error
  naming an invented path.

[055](./done/055.md)'s resolution noticed this ("the upstream loader
expands environment variables in the root filename; … not changed here"),
but no note tracks it. No product fix implemented.

Create the disposable file `/absolute/books/$X.bean`, with a literal `$X`
in its name:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Equity:Opening
2026-01-02 * "REAL"
  Assets:Checking  100.00 USD
  Equity:Opening
```

Also create `/absolute/books/decoy.bean`: the same content with narration
`"DECOY"` and `999.00 USD`. Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME,
BEA_NO_UPDATE_NOTIFIER=1, no inherited BEA_FILE/BEA_TOKEN, closed stdin,
no TTY, and `X=decoy` in the environment.

```sh
bea -f '/absolute/books/$X.bean' balance
bea -f '/absolute/books/$X.bean' list transaction
bea -f '/absolute/books/$X.bean' check
bea -f '/absolute/books/$X.bean' add note --date 2026-01-05 -a Assets:Checking -m hi
```

Actual:

- `balance` exits 0 and shows `Checking 999.00 USD`.
- `list transaction` lists only the `DECOY` transaction.
- `check` exits 0. With a failing assertion appended to `decoy.bean`, it
  exits 1 citing `/absolute/books/decoy.bean:8`, although the JSON
  `target.file` says `$X.bean`.
- `doctor context` prints the decoy's entries.
- `add note` exits 0 and appends to the literal `$X.bean`.

With a file literally named `$HOME.bean`, reads fail with `<load>:0: File
"/absolute/books/Users/<user>.bean" does not exist`. Reproduced in three
fresh setups.

Control: with `X` unset, every command reads `$X.bean` correctly, because
`expandvars` leaves unknown names alone. Ordinary file names are
unaffected.

Expected: `--file` names "the ledger entry file", and the JSON envelope
reports that file as the target. A path given to `--file` should be read
as written. A read must never report a different ledger from the one
named, or from the one the next `add` writes.

Cause: `cli/src/bea_engine/managed_load.py:548` and `:554` (`_load_fresh`)
call `loader.load_file(str(entry))`, and upstream `beancount/loader.py:114`
expands `$NAME` and `~`. The staged-write load (`managed_load.py:390`)
uses a generated twin path that contains no `$`, which is why writes
validate the right file. The native `bean-check` behind `bea check`
expands the same way.

Fix: before handing the root to upstream, keep `$` from being expanded,
for example by loading through the staged twin or a symlink alias without
`$`. Do the same for the native `check` child. Alternatively, refuse with
exit 2 when the root path contains `$`, naming the expansion that would
happen. Includes are not expanded upstream and need no change. No
dependency or API change.

Blast radius: every command that loads the root through `load_file` or
native `bean-check`, whenever a component of the absolute path contains
`$` followed by the name of a set variable. Such names are rare, but the
result is silently wrong data.

Dedupe: searched the board, including `done/`, for `expandvars`, `$NAME`,
"environment variable" together with file name, and `$HOME`. w5/055 notes
the behaviour but scopes it out. w5/247 (glob characters in include names)
is a different mechanism. Nothing is open.

Acceptance: on the fixture with `X=decoy`, `balance`, `list`, `check` and
`doctor context` either report the `REAL` ledger (100.00 USD, with no
decoy path in any message), or each exits 2 naming the `$`. `$HOME.bean`
behaves the same way. A real-command regression test covers a set
variable, an unset one, and a `$` in a parent directory. Only macOS and
the checkout were exercised.

---

**Resolved 2026-10-15** — `refuse_expanding_ledger_path` (`cli/src/cli/context.py`) runs where `--file`/`$BEA_FILE`/cwd discovery resolves the root, and on `bea doctor`'s positional ledger (every operation but `list-options`). When `os.path.expandvars` would change the absolute path, the command exits 2 naming the file Beancount would read instead, so reads, `check`, `doctor`, and `add` all refuse before loading or writing anything. A `$` whose variable is unset still loads as written. The note's preferred alternative, loading through a `$`-free alias, was not taken: an alias outside the ledger's directory breaks relative includes, and the native `bean-check` child expands on its own. `cli/tests/test_ledger_path_env_expansion.py` covers `balance`, `list`, `check`, `add` (file unchanged), `doctor context`, `$HOME.bean`, a `$` in a parent directory, and the unset-variable control. The 7 refusal cases fail with the fix reverted. Only macOS was exercised. `make check-all` passed (5968 tests). Shipped in `07cd9770` (`cli`).
