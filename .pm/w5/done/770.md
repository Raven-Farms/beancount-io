# `bea doctor roundtrip` still prints raw tracebacks: a 30-line `CompareError` for two identical valid entries, and the 34-line double traceback when the scratch file name is too long (incomplete fix of w5/569 and w5/572)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `b9427aca2`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/569 and 572 (done).
No product fix implemented.

1. **Identical entries.** A ledger with two identical `2026-01-05 * "Coffee"`
   transactions (`Expenses:Coffee 3.00 USD` / `Assets:Cash`) passes `check`.
   `bea doctor roundtrip /abs/main.bean` exits 1 with 30 lines of traceback,
   ending `ValueError: CompareError(… message="Duplicate entry:
   Transaction(…`. Two identical `note` lines do the same (hunter's run).
   Control: different narrations print Congratulations.
2. **Long name.** For a ledger named with 245 `L`s plus `.bean`, `doctor
   roundtrip` exits 1 with 34 lines: `OSError: [Errno 63] File name too long:
   …roundtrip1.bean`, then `TypeError: stat: path should be string … not
   NoneType`. Control: a read-only folder exits 3 with one line (w5/572).

Expected: one line in both cases. For (1), either a multiset comparison that
passes, or a refusal naming the identical entries. For (2), a refusal naming
the scratch file problem.

Cause: `_forward_roundtrip` (`cli/src/cli/commands/doctor.py:530`) replays
upstream's `compare_entries` `ValueError` unchanged. `_private_roundtrip_artifacts`
(`:502`) refuses only EACCES/EPERM/EROFS from the pre-create, so other errnos
(ENAMETOOLONG, likely ENOSPC) reach upstream's crashing `finally`.

Fix: catch the duplicate-entry comparison error, and refuse any OSError from
the pre-create in one line.

Dedupe: w5/569 and 572 (done) are the parents; w5/643 (open) reaches the same
`finally` through `--strict-prices`.

Acceptance: both fixtures give a one-line answer with no traceback.
