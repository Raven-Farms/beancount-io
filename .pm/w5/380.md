# A lone CR (or `\r\r\n` line endings) in the ledger breaks bea's add-time error handling: a failed `add balance` is blamed on a plugin, failures on the new entry lose "Proposed append (not written)", and the documented `add pad --allow-errors` step is refused

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
[w5/169](./done/169.md) (`4926c039`) made the reader, the plugin lookup
and the document-path lookup count lines on `\n` only, as Beancount's
lexer does. The write path was not changed. It still splits the original
files with `bytes.splitlines()`, which also breaks on a lone `\r`.

Stray `\r` bytes, from pasted text or from `\r\r\n` endings after a
double conversion, therefore make the file look longer than the lexer
counts. Errors on the entry being appended then fall inside the
"original" line range and are treated as errors on existing lines:

- a failed balance is blamed on a plugin;
- the `Proposed append (not written)` prefix disappears;
- the exemption for the pad's own `Unused Pad` error no longer applies.

No product fix implemented.

Create disposable `/absolute/books/main.bean`. `bea check` exits 0 on it.

```sh
printf 'option "operating_currency" "USD"\n; pasted note: a\rb\rc\rd\re\rf\rg\rh\n2026-01-01 open Assets:Cash USD\n2026-01-01 open Equity:Opening USD\n2026-01-02 * "seed"\n  Assets:Cash 100 USD\n  Equity:Opening\n' > main.bean
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, and closed stdin.

```sh
bea -f /absolute/books/main.bean add balance --date 2026-02-01 --account Assets:Cash --amount '50 USD'
bea -f /absolute/books/main.bean add transaction X --date 2026-02-01 -p 'Expenses:Nope 5 USD' -p Assets:Cash
bea -f /absolute/books/main.bean add pad --date 2026-02-01 --account Assets:Cash --source Equity:Opening --allow-errors
```

Actual:

- `add balance` exits 1 with `main.bean:9: Balance failed … (50 too
  much)`, then `This assertion is generated by a plugin reading the line
  at …/main.bean:9; it is not a balance written in the ledger.`. The
  ledger has no plugin and no line 9, and the assertion-date hint is
  missing.
- `add transaction` exits 1 with `main.bean:9: Invalid reference to
  unknown account …`, without the `Proposed append (not written):`
  prefix.
- `add pad --allow-errors` exits 1 with `The change would introduce 1 new
  ledger error(s); nothing was written.` and `Unused Pad entry`.
- A file using `\r\r\n` throughout gives the same three results.
- The ledger is unchanged each time.

The hunter reproduced the balance and pad cases twice, and the
transaction case once. I reproduced the balance and pad cases.

Control: the same file with spaces in place of the `\r` bytes behaves
normally:

- the balance error has the `Proposed append (not written)` prefix and
  the date hint;
- the transaction error has the prefix;
- the pad exits 0 with `Added 1 pad` and the Unused Pad note.

Expected: w5/169 set the rule that line numbers follow Beancount's
lexer. `docs/USAGE.md` documents the two-step pad flow, in which a staged
pad's `Unused Pad` error is the exempt one, and says a failure in the
proposed text reads `Proposed append (not written): …`. A stray `\r`
should not change how the new entry's errors are classified.

Cause: `cli/src/bea_engine/ledger/write.py` uses `bytes.splitlines()` at
two sites:

- `:1152` and `:1156` build `original_lines`. These feed the
  original-line counts (`:1166`), the appended-line test (`:1203`,
  `:1215`) that governs the prefix and the pad/open exemption,
  `_plugin_origin` (`:1484-1508`) and the `_preexisting_errors` anchors
  (`:1577-1583`).
- `:821` builds `line_counts` for the balance hint.

Fix: split on `b"\n"` only, dropping the final empty piece when the
content ends with `\n`, as `4926c039` did for the reader. No dependency
change.

Blast radius: every `add` subcommand and bulk add on ledgers with stray
`\r` bytes. The messages are wrong, and the two-step pad flow cannot
start.

Dedupe: searched `.pm/**`, including `done/`, for `original_lines`,
"lone CR" together with add, "generated by a plugin", and "Unused Pad"
together with CR. Related notes:

- w5/169: reader, query and main only. Its diff leaves `write.py`
  untouched.
- w1/049 and w1/048: U+2028.
- w1/136: append indentation.
- 355: the formatter's lone CR.

None covers the write path.

Acceptance: on the fixture and on a `\r\r\n` file, the balance error has
the prefix and the date hint and no plugin sentence, the transaction
error has the prefix, and `add pad --allow-errors` exits 0. A real-command
test covers all three.
