# `.run` with an apostrophe in the stored query name fails with `ValueError: No closing quotation`

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A stored query named `this month's food` is listed by `.run`, but running
it by that name exits 1 with a bare `ValueError` (a traceback inside the
interactive shell, per a worker). The quoted form works. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
2026-01-05 * "Cafe" "Coffee"
  Expenses:Food  4.00 USD
  Assets:Cash
2026-02-05 * "Cafe" "Tea"
  Expenses:Food  3.00 USD
  Assets:Cash
2026-01-01 query "this month's food" "SELECT sum(position) AS total WHERE account ~ 'Food'"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean query ".run this month's food"
```

Actual: exit 1.

```text
Error: ValueError: No closing quotation Pass --debug before the command for a traceback.
```

Control: `bea -f main.bean query ".run \"this month's food\""` prints
`7.00 USD`; `bea -f main.bean query ".run nope"` exits 2 with `query "nope"
not found.`

Expected: a mistake in a `.run` argument is a usage error (exit 2) with one
line saying the name needs quoting; better, the name works exactly as
`.run` lists it.

Cause: `cli/src/bea_engine/query.py:455` (`shlex.split` in `_run_stored`)
raises `ValueError`, and the recovery wrapper (`:482-490`) catches only
engine errors.

Fix: try the whole argument as a literal name before splitting; otherwise
catch the `ValueError` and raise a usage error showing the quoted form. No
dependency or API change.

Blast radius: `.run` one-shot and in the shell, for names containing a
quote character.

Dedupe: board search for "No closing quotation", `shlex` and apostrophe
finds only unrelated items; w5/109, w3/done/397 and w1/done/067 are other
shell tracebacks with different inputs.

Acceptance: `.run this month's food` prints `7.00 USD`, or exits 2 naming
the quoted form; no `ValueError` text. Only macOS and the checkout were
exercised.
