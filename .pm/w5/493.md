# `bea --json check` answers `valid: true` for a ledger that `bea check` and `bean-check` reject: bean-check's extra validations run only on the text path

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `3f2372e1`, checkout `bea 0.3.1`, macOS 26.5.1.
`bean-check` runs `HARDCORE_VALIDATIONS` (data-type validation) after the
load. w5/430 added them to the helper's `--documents-only` pass, which text
`check` now uses, but its resolution notes "`--json check` is unchanged". So a
plugin that emits malformed entries passes the JSON check that scripts and
agents gate on. Text `check` fails it, and later reads crash on it. No
product fix implemented.

`notags.py` beside the ledger:

```python
from beancount.core import data
__plugins__ = ['notags']
def notags(entries, options_map):
    return [e._replace(tags=None) if isinstance(e, data.Transaction) else e for e in entries], []
```

`main.bean`:

```beancount
option "insert_pythonpath" "TRUE"
plugin "notags"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
2024-01-05 * "Lunch"
  Expenses:Food    10 USD
  Assets:Cash
```

```sh
bea --json -f /abs/main.bean check
bea -f /abs/main.bean check
bea --json -f /abs/main.bean list transaction
```

Actual: `--json check` exits 0 with `{"valid": true, "errors": []}`. Text
`check` (and upstream `bean-check`) exits 1 with `main.bean:5: Invalid data
types: Invalid tags type: <class 'NoneType'>`. `list transaction` exits 1
with `TypeError: 'NoneType' object is not iterable`. A BOM-marked copy of the
ledger (checked through the helper even in text mode) also passes text
`check`.

Expected: both forms give the same verdict (USAGE presents `--json check` as
the same check in an envelope; w5/084 asked for the same verdict).

Cause: `_validate` (`cli/src/bea_engine/main.py:879-888`) computes the
validation errors but returns them only under `--documents-only`. Without
it, only loader errors are reported. It is reached from
`cli/src/cli/commands/check.py:52` (compat path) and `:64` (`--json`).

Fix: report the `HARDCORE_VALIDATIONS` errors on every helper check path.

Dedupe: searched `HARDCORE`, `Invalid data types`. w5/430 and w1/m19/t003
(done) touch the same validations on other paths.

Acceptance: `--json check` exits 1 with the data-type error, and the
BOM-marked copy fails text `check` too. A test pins both.
