# An importer config that calls `sys.exit` (an unguarded `beangulp.Ingest(CONFIG)()`) is reported as "The Beancount engine did not answer", and with `--apply` as exit 4 "the outcome is unknown"

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `75a67e85`, checkout `bea 0.3.1`, macOS 26.5.1.
The common trigger is a Beangulp ingest script reused as `--config` without
an `if __name__ == "__main__":` guard. `Ingest(CONFIG)()` runs Click, which
calls `sys.exit`. IMPORTING.md says importer failures are reported as
`Importer failed (…)` with "what it printed first" kept. `SystemExit` escapes
the importer guard instead, so the engine writes no envelope. The frontend
then reports an engine failure, leaks the internal argv, and for `--apply`
claims the write outcome is unknown, though the importer runs before any
write. No product fix implemented.

`imp.py`:

```python
import beangulp
from base import *          # a small Importer subclass and a txn() helper
CONFIG = [Base([txn(datetime.date(2026, 2, 1), "Lunch", D("-10.00"))])]
beangulp.Ingest(CONFIG)()
```

(`sys.exit(3)` at import time, or `sys.exit(0)` inside `extract()`, behaves
the same.)

```sh
bea --file /abs/main.bean import bank.txt --config imp.py
bea --file /abs/main.bean import bank.txt --config imp.py --apply
```

Actual: preview exits 1 with `Error: The Beancount engine did not answer
'bea-engine import --file … --config-source --config' (exit 2).`; `--apply`
exits 4 with `… (exit 2); the outcome is unknown. Inspect the file before
retrying.` What the importer printed (Click's `Error: No such command
'import'.`, which explains it) is discarded. `main.bean` is unchanged.

Control: `raise ValueError("boom")` in identify, account or extract gives exit
1 `Importer failed (ValueError): boom …`.

Expected: exit 1, `Importer failed (SystemExit: 2)`, with the captured output
in `importer_output`, and a hint that an ingest script needs an `if __name__
== "__main__":` guard to be used with `--config`.

Cause: the importer calls are guarded with `except Exception`
(`cli/src/bea_engine/importing.py:249`, `:309`; `cli/src/bea_engine/protocol.py:118`),
so `SystemExit` escapes and the `_capturing` sink (`importing.py:51-78`) is
lost; `cli/src/cli/engine/launch.py:577-612` maps the missing envelope to
"did not answer", and for writes to exit 4.

Fix: also catch `SystemExit` around module loading, `identify`, `account` and
`extract`, and report it as an importer failure.

Dedupe: searched `sys.exit`, `SystemExit`, `did not answer` with importer; the
hits concern signals.

Acceptance: both commands exit 1 with the importer-failure message, the
guard hint and the importer's output. A test pins it.
