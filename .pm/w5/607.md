# A disk-full or file-size failure while staging is reported as a validation failure: `add transactions` says "Pass --partial", `--partial` marks every row "rejected", and `import --apply` says the import "would leave the ledger invalid" (gap in w5/410)

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `c210da9b`, checkout `bea 0.3.1`, macOS 26.5.1.
w5/410 gave staging I/O failures a clear sentence ("Cannot write a staged
copy … nothing was written"). Bulk add and import catch every `LedgerError`
as a validation failure, so a full disk turns into row-level advice that
cannot help. No product fix implemented.

A 40-transaction ledger; `bulk.json` with two valid rows; a two-row bank CSV.

```sh
bash -c 'trap "" XFSZ; ulimit -f 3; bea -f /abs/main.bean add transactions --from bulk.json'
bash -c 'trap "" XFSZ; ulimit -f 3; bea -f /abs/main.bean add transactions --from bulk.json --partial'
bash -c 'trap "" XFSZ; ulimit -f 3; bea -f /abs/main.bean import bank.csv --csv auto --account Assets:Checking --default-account Expenses:Food --apply'
```

Actual: (1) `Cannot write a staged copy of main.bean in … (File too large);
nothing was written. Pass --partial to append the rows that validate.`; (2)
`Added 0 of 2 transactions; 2 rows were rejected.` with `Row N: Cannot write a
staged copy…` for each row (JSON `rejected_rows: [0, 1]`); (3) `Import would
leave the ledger invalid; nothing was written.` with the disk error as detail.
A full 8 MB RAM disk gives the same. The ledger is unchanged throughout.

Control: a single `add transaction` gives only the staging sentence; an
unwritable directory exits 3 for both commands.

Expected: the staging sentence alone, with no `--partial` advice, no row
marked rejected, and no "invalid" claim.

Cause: staging I/O raises a plain `LedgerError` (`cli/src/bea_engine/ledger/write.py:944`,
`:958`); `cli/src/bea_engine/importing.py:543` and
`cli/src/bea_engine/ledger/adding.py:1351`, `:1376`, `:1397` treat any
`LedgerError` as validation.

Fix: a distinct exception for staging I/O; catch only `CandidateRejected` at
those sites.

Dedupe: w5/410 (done) kept the `validation` category and did not reach these
callers.

Acceptance: the three commands print only the staging sentence. A test that
fails the staging write pins them.
