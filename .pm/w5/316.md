# `bea price export` makes world-readable copies of a private ledger, its includes and its receipts (`0644`/`0755` from `0600`/`0700`)

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
`bea init` creates ledgers at mode `0600`, and the docs promise "New ledger
files are private by default". `bea price export` ignores the source modes
and writes its "self-contained copy" with the process umask, without
saying so. Under umask 022:

- every ledger file and included file becomes `0644`;
- every copied `document` attachment becomes `0644`;
- attachment directories become `0755`.

The copies sit beside the private originals, in `<ledger>-export/` by
default. No product fix implemented.

Create `/absolute/books/main.bean` with mode 0600:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Equity:Opening
include "private.bean"
2026-01-03 document Assets:Checking "receipts/r.pdf"
```

Also create `/absolute/books/private.bean` (0600) holding a transaction,
and `/absolute/books/receipts/r.pdf` (file 0600, directory 0700). Use
isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, and umask 022.

```sh
bea -f /absolute/books/main.bean price export
ls -lR /absolute/books/main-export
```

Actual: exit 0 with `Exported 3 files`. The listing shows:

- `-rw-r--r-- main.bean`
- `-rw-r--r-- private.bean`
- `drwxr-xr-x receipts`
- `-rw-r--r-- receipts/r.pdf`

A ledger created by `bea init` (0600) is exported at `0644` the same way.
Reproduced in three fresh runs.

Controls:

- `add --into` creates a new period file at `0600`, as documented.
- `add`, `import` and `format -i` preserve an existing file's mode.

Expected: `docs/USAGE.md` says "New ledger files are private by default
(`0600` on POSIX …)" and "New destinations are private (`0600` on POSIX)".
Only `query -o` documents "New exports use the caller's umask", and that
command exports a query result, not the books. The files `price export`
writes are complete ledger files and receipts, so they should be at least
as private as their sources. If the umask is the intended policy, it
should be documented and stated in the output.

Cause: `cli/src/bea_engine/managed_load.py:1104-1116` creates directories
and files with `dest.parent.mkdir(...)`, `dest.write_bytes(...)` and
`dest.write_text(...)`, which apply the umask, and copies attachments with
`shutil.copyfile`, which copies contents only, not the mode.

Fix (choose one):

- (a) Create each exported file with its source's permission bits
  (`shutil.copymode`, or an `os.open` mode), and create new directories
  with the source directory's mode or `0700`. Feed files take the root's
  mode.
- (b) Document the umask policy next to `price export`, and print a
  one-line note when a source is more private than its copy.

w5/175 established that a world-readable copy beside a private ledger is a
privacy defect worth fixing. No dependency or API change.

Blast radius: `price export`, with either the default destination or
`-o`, for every ledger file, include, attachment and feed.

Dedupe: searched the board, including `done/`, for `0600`, "private by
default", "world-readable", and `price export` combined with mode or
permission.

- w5/175: the world-readable load cache.
- w3/422: `query -o` modes and symlinks.
- w5/056, w5/058 and w5/072: export collisions, links and globs.

None of these covers export file modes.

Acceptance: on the fixture with umask 022, either (a) every exported file
is `0600` and `receipts/` is `0700`, or (b) the docs and the command output
state the umask policy. A real-command regression test checks the modes of
the ledger, include, attachment and feed copies. Only macOS and the
checkout were exercised.
