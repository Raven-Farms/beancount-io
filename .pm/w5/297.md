# An unreadable or incomplete `credentials.json` reads as "Not logged in", and `bea cloud logout` then says "Already logged out." with exit 0 while leaving the file and its token on disk

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
If the stored credential file exists but cannot be read or parsed, every
cloud command reports `Not logged in` (exit 3). Examples: mode 000, no
`expireAt`, not valid JSON. `bea cloud logout` then prints
`Already logged out.` and exits 0, without revoking or deleting anything.
The token stays on disk. No product fix implemented.

Use an isolated `BEA_CONFIG_DIR=/absolute/cfg` (mode 0700),
XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no inherited BEA_FILE/BEA_TOKEN,
closed stdin, no TTY. No network is involved; every case is decided
locally.

```sh
printf '{"token": "qa-fake-token-abc"}' > /absolute/cfg/credentials.json
bea cloud status
bea cloud logout
ls -l /absolute/cfg/credentials.json
```

Actual: `cloud status` exits 3 with
`Error: Not logged in. Run 'bea cloud login', or set BEA_TOKEN.`
`cloud logout` exits 0 with `Already logged out.`, and `credentials.json`
is still there with its token. These files behave the same way:

- a complete file (`"expireAt": "2099-01-01T00:00:00Z"`) at mode 000
- `{not json`
- `[]`
- `{"token": 5}`

Reproduced in three fresh runs.

Controls:

- A valid file with `"expireAt": 5` reads as `Session expired. Run 'bea
  cloud login' to re-authenticate.`, because a malformed expiry is
  deliberately treated as expired.
- With no file at all, `Already logged out.` is correct.

Expected: `docs/USAGE.md` › Cloud says "`cloud logout` revokes the stored
session and deletes the credential file. The file is deleted even when
revocation fails, but then the command exits nonzero and says the session
may still be valid". A credential file that is present but unusable should
be named, not reported as absent. Logout should delete it, or refuse while
naming it, rather than report success over it.

Cause: `cli/src/cli/auth/credentials.py:85-111` (`load_credentials`) wraps
reading and parsing in `except Exception: return None`. `PermissionError`,
`JSONDecodeError`, `KeyError` (no `expireAt`) and `TypeError` therefore all
look like "no file". `cli/src/cli/commands/cloud/app.py:48-50`
(`cloud_logout`) returns `Already logged out.` on `None` before
`clear_credentials()` (`:87`) is reached.

Fix:

- `load_credentials`: treat `FileNotFoundError` as "no file". Raise an
  `AuthError` for a file that is present but unusable, naming the path and
  the reason (unreadable, not JSON, missing field) and suggesting
  `bea cloud login` to replace it.
- `cloud_logout`: when the file exists but cannot be used, delete it
  (without a readable token it cannot be revoked), say so, and exit
  nonzero, as the doc already requires when revocation did not happen.
  Refusing while naming the path is an acceptable alternative.
- Keep a missing `expireAt` consistent with how a malformed one is treated.

No dependency or API change.

Blast radius: every command that calls `load_credentials` or
`require_credentials`: `cloud status`, `cloud ledger *`, `cloud logout`,
`ask`, and managed price fetches that relay a stored token. `BEA_TOKEN` is
unaffected.

Dedupe: searched the board for "Already logged out", `credentials.json`,
corrupt or malformed credentials, and `load_credentials`. Related notes:

- w1/002: logout with `BEA_TOKEN`
- w1/004: help path
- w1/057: non-ASCII token
- w1/058: a failed revocation reported as success
- w5/012: rejected `BEA_TOKEN` hint

None covers a stored file that is present but unreadable or incomplete.

Acceptance: with each listed bad file:

- `cloud status` exits 3 naming `/absolute/cfg/credentials.json` and why
  it is unusable.
- `cloud logout` either deletes the file and says so with a nonzero exit,
  or refuses while naming it. It never prints `Already logged out.` while
  the file exists.
- With no file, `Already logged out.` is unchanged.

A real-command regression test covers mode 000, invalid JSON and a missing
`expireAt`. Only macOS and the checkout were exercised.
