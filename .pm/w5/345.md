# A balance assertion dated before an account's existing `open` suggests "(bea add open, or a later --date)", but `bea add open` on an already-open account can only be refused as a duplicate

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
The balance-assertion recovery hint from w3/243 was written for accounts
that were never opened. It prints the same text when the account is
already open, but only on a later day or on the assertion's own day. In
that case the suggested `bea add open` cannot succeed. The right remedy is
to move the existing open earlier, or use a later `--date`. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-03-01 open Assets:Bank USD
2026-01-01 open Equity:OpeningBalances USD
```

Use the environment from [343](./343.md).

```sh
bea -f /absolute/books/main.bean add balance --date 2026-02-15 --account Assets:Bank --amount '50 USD'
bea -f /absolute/books/main.bean add open --account Assets:Bank --date 2026-02-01 -c USD
```

Actual:

- The first command exits 1 with `Review the assertion date: Assets:Bank
  must be open on an earlier day before this balance assertion (bea add
  open, or a later --date).`
- The same output also prints the correct inactive-account note:
  `Account opened 2026-03-01 at …/main.bean:2. Correct the transaction
  date or edit that directive`.
- Following the `bea add open` advice exits 1 with `main.bean:2: Duplicate
  open directive for Assets:Bank`. The ledger is unchanged.
- The hint is the same when the open is on the assertion's own day.

Reproduced by the hunter on two fixtures and once by me.

Control: for a never-opened account, the hint is right, and `add open
--date 2026-02-01` succeeds.

Expected: when the account already has an `open`, the hint should name
that line and say to move its date earlier or use a later `--date`, as
the inactive-account note does. It should not suggest `bea add open`.

Cause: `_balance_recovery_hints` (`cli/src/bea_engine/ledger/write.py:848-857`)
returns the same text whenever the account is not active on the
assertion's date. It does not tell "never opened" apart from "opened
later" or "opened the same day".

Fix: look up the account's `Open` entry. If one exists, print "Assets:Bank
opens on 2026-03-01 at main.bean:2; move that open before the assertion,
or use a later --date". Keep the current text for accounts that were never
opened. No dependency change.

Blast radius: `add balance`, including `--pad-from` and bulk rows, when
the assertion predates or shares the date of an existing open.

Dedupe: searched `.pm/**`, including `done/`, for "Review the assertion
date" and "must be open on an earlier day". w3/243 introduced the wording.
None covers the already-open case.

Acceptance: on the fixture, the hint names `main.bean:2` and does not
mention `bea add open`. The never-opened control is unchanged. A test
covers both. Only macOS and the checkout were exercised.
