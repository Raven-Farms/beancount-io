# `bea import` writes a self-cancelling entry, exit 0, when a rule, a category cell or `--default-account` names the `--account` itself

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-16, HEAD `8195088f`, checkout `bea 0.3.1`, macOS 26.5.1.
A counter account equal to the source account cannot record a bank row, yet
the import accepts it. The written entry posts `-100.00 USD` and `+100.00
USD` to the same account, `bea check` passes, and the bank movement
disappears from the balance. `--default-account Assets:Checking` is even
saved as a remembered setting for the header. No product fix implemented.

Disposable `main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Assets:Savings USD
2026-01-01 open Expenses:Uncategorized USD
```

`s.csv`:

```csv
Date,Description,Amount
2026-02-01,TRANSFER TO SAVINGS,-100.00
2026-02-02,COFFEE,-3.00
```

`rules.toml`:

```toml
[[rule]]
match = "transfer"
account = "Assets:Checking"
```

Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, closed stdin.

```sh
bea -f /abs/main.bean import s.csv --account Assets:Checking --rules rules.toml --apply
bea -f /abs/main.bean balance Assets:Checking
```

Actual: exit 0, `Wrote 2 entries`. Row 1's SOURCE AMOUNT reads `-100.00
USD, 100.00 USD`, and the entry is

```beancount
2026-02-01 * "TRANSFER TO SAVINGS"
  import-id: "csv:sha256:6e0ff1f508b86d0e"
  Assets:Checking         -100.00 USD
  Assets:Checking          100.00 USD
```

`balance` shows `Assets:Checking -3.00 USD`; the bank says -103.00. The same
happens with `--default-account Assets:Checking` (now remembered for the
header) or a `Category` column cell reading `Assets:Checking`.

Control: `account = "Assets:Savings"` in the rule writes -100 / +100 across
the two accounts.

Expected: refuse (exit 2) a rule account or `--default-account` equal to
`--account`, naming it. A category cell equal to it sends the row to review,
like an unknown category. `cli/docs/IMPORTING.md` describes each row as the
signed source amount against a counter account.

Cause: `_categorize` (`cli/src/bea_engine/csv_mapper.py:1265`, `:1275`,
`:1281`) returns the counter account without comparing it to
`self._account`; `:1233` builds the counter posting from it.
`_valid_account` (`cli/src/bea_engine/importing.py:195`) checks only syntax
for `--default-account`.

Fix: the refusals above, in the engine where the rule, category and default
are resolved, before anything is remembered.

Blast radius: `--rules`, `--default-account`, CSV category columns. Python
importers build their own postings and are out of scope.

Dedupe: searched `counter account equal`, `same account`, `cancels itself`,
`source account itself`. No match.

Acceptance: each of the three spellings is refused or reviewed with a
message naming the account; the ledger and remembered settings stay
unchanged. A test pins it.
