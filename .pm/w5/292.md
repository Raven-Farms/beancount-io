# `bea report --account Expenses:Food` also counts `Expenses:FoodTruck`: a "parent account" filter matches prefix siblings

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
The docs and `--help` say `--account` takes "a parent account
(`Expenses:Food`) or a regular expression". A plain account name also
matches sibling accounts that start with the same text: `Assets:Bank`
picks up `Assets:Bankroll`, and `Expenses:Food` picks up
`Expenses:FoodTruck`. The siblings' postings go into the tree, the totals,
`net_profit` and the interval series, with exit 0 and no warning. No
product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Bank USD
2026-01-01 open Assets:Bankroll USD
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
2026-01-01 open Expenses:Food:Dining USD
2026-01-01 open Expenses:FoodTruck USD
2026-01-01 open Equity:Opening USD

2026-01-02 * "Open"
  Assets:Bank  100.00 USD
  Assets:Bankroll  50.00 USD
  Assets:Cash  10.00 USD
  Equity:Opening

2026-01-05 * "Meal"
  Expenses:Food:Dining  7.00 USD
  Expenses:FoodTruck  3.00 USD
  Assets:Bank
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.
The ledger is unchanged afterwards.

```sh
bea -f main.bean report balance-sheet -a Assets:Bank
bea --json -f main.bean report income-statement -a Expenses:Food
```

Actual: both exit 0. The balance sheet shows:

```text
  Assets                                          140.00 USD
    Bank                                          90.00 USD
    Bankroll                                      50.00 USD
```

The income statement JSON has `"net_profit": {"USD": "-10.00"}`, and
`expenses.children` lists `Expenses:FoodTruck` at `3.00 USD` next to
`Expenses:Food`. `trial-balance -a Assets:Bank` and `overview` give the
same result. Reproduced in three fresh processes, one of them an
independent rerun.

Control: `-a '^Assets:Bank(:|$)'` shows only `Bank 90.00 USD`.
`-a Expenses:Food:Dining`, which has no prefix sibling, shows only
`7.00 USD`.

Expected: `docs/USAGE.md` (Reports): "`--account` takes a parent account
(`Expenses:Food`) or a regular expression (`'Expenses:(Food|Rent)'`) …
totals, trees, and the interval breakdown all describe the accounts you
asked for". `docs/REFERENCE.md` and `report --help`: "Account filter: a
parent account or a regular expression". `Expenses:FoodTruck` is not
under `Expenses:Food`, so the expenses should be 7.00 USD and the net
profit -7.00 USD.

Cause: `cli/src/bea_engine/report.py:747-764` (`_report_filter_match`)
delegates to `cli/src/fava/core/filters.py:438-458` (`account_predicate`).
That returns `has_component(name, value) or Match(value)(name)`, and
`Match` is an unanchored, case-insensitive regex search. Every account
name is also a valid regex, so a plain name matches any account that
contains it. `AccountFilter`, `_prune_sections` (`report.py:767`) and the
series all use the same predicate, so they agree with each other on the
wrong set of accounts.

Fix (choose one):

- (a) When the value is a syntactically valid account name, match by
  component only: the account and its descendants. Keep regex search for
  real patterns. w1/018 and w1/m15/t002 deliberately kept regex semantics,
  so the CLI owner should decide whether a literal name counts as a regex.
- (b) Keep the behaviour and document it in USAGE.md, REFERENCE.md and
  `--help` (`Expenses:Food` also matches `Expenses:FoodTruck`; anchor with
  `'^Expenses:Food(:|$)'`). Optionally warn on stderr when a literal name
  matches an account outside its own subtree.

No dependency or API change.

Blast radius: all four `report` subcommands. `bea balance` uses its own
documented substring matcher (`report.py:741`) and is out of scope. A
name with no prefix sibling is unaffected.

Dedupe: searched the whole board, `done/` included, for
`account_predicate`, `Bankroll`, `FoodTruck`, "sibling" and "prefix", and
ran `git log -S` on the predicate.

- w1/018: regex error classification and help text; kept regex semantics.
- w3/379: empty totals after a regex prune.
- w3/395: narrowed series and earnings.
- w3/396: a child filter that kept the parent's direct postings.
- w1/020 and w1/071: `bea balance`.

None of them covers a literal parent name matching its prefix siblings.

Acceptance: on the fixture, either (a) `report balance-sheet -a
Assets:Bank` shows `Assets 90.00 USD` with no `Bankroll` row and
`income-statement -a Expenses:Food` gives a `net_profit` of `-7.00 USD`,
or (b) USAGE.md, REFERENCE.md and `--help` describe the search semantics
with the anchored example. Either way, a real-command test pins the
chosen behaviour with a prefix sibling present. Only macOS and the
checkout were exercised.
