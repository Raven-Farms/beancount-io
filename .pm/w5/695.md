# A `~name` path with no such user (`init '~books'`, `BEA_FILE='~x/main.bean'`, `import '~x.csv'`, `format`, `add --into`) exits 1 with "Could not determine home directory"

**Trivial · cli · 15m · A1.** Real CLI QA, 2026-10-17, HEAD `101b89e3`, checkout `bea 0.3.1`, macOS 26.5.1.
`Path.expanduser()` raises `RuntimeError` for `~name` when no user `name`
exists. Bash and zsh scripts can pass such a path literally (quoted, or with
no matching user). No product fix implemented.

```sh
bea --no-input init '~books' --currency USD --date 2026-08-01
BEA_FILE='~nouserqa/main.bean' bea check
bea --file /abs/main.bean import '~nouserqa.csv' --account Assets:Checking
bea --file /abs/main.bean format '~nouserqa/x.bean'
bea --file /abs/main.bean add open -a Assets:Y --date 2026-08-01 --into '~nouserqa/y.bean'
```

Actual: every command exits 1 with `Error: Could not determine home
directory. Pass --debug before the command for a traceback.` The `--into`
case comes from the engine and reads `Error: RuntimeError: Could not
determine home directory.` `--file '~nouserqa/x.bean' init` fails the same
way.

Control: `bea --file '~nouserqa/main.bean' check` exits 2 with `No ledger file
at '~nouserqa/main.bean' (from --file)…`. `query -o '~nouserqa/out.csv'` exits
2 naming the missing parent directory.

Expected: exit 2 naming the path and its source, as `--file` already does.

Cause: unguarded `expanduser()` calls, for example
`cli/src/cli/commands/init.py:120,122` and `cli/src/cli/context.py:130`
(`$BEA_FILE`). `src/cli` and `src/bea_engine` contain about 45 such calls.

Fix: a shared helper that maps the `RuntimeError` to a usage error naming the
path, used for every user-supplied path. Alternatively, keep `~name` literal
when no such user exists, as the `--file` path effectively does.

Dedupe: searched `Could not determine home` and `expanduser`; nothing found.

Acceptance: each command above exits 2 naming the path. A test pins `init`,
`$BEA_FILE` and an engine path.
