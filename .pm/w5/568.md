# `bea doctor` resolves symlinks in the ledger path, unlike every other read: locations under a symlinked directory find nothing, and a symlinked root file loads the includes beside its target

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-16, HEAD `04c94595`, checkout `bea 0.3.1`, macOS 26.5.1. Differential run against upstream `bean-doctor`.
USAGE says a symlinked root "keeps the path you named, as bean-check does",
with includes resolved beside the link. `bea --json list` reports entry
sources under the link path. Upstream `bean-doctor` declares its ledger
argument with `resolve_path=True`, so doctor's entries carry the real path.
Every location bea passes, absolute or include-relative under the link,
then matches nothing. A cloud-synced folder reached through a symlink (for
example `~/Dropbox`) is the common case. No product fix implemented.

Fixture H: `real/books/main.bean` (`include "txns/jan.bean"`, opens for
`Assets:Cash USD` and `Expenses:Food USD`), `real/books/txns/jan.bean` (`2024-01-05
* "a" ^grp`, 10 USD food), and `link -> real`.

```sh
bea doctor context link/books/main.bean txns/jan.bean:1
bea doctor region link/books/main.bean txns/jan.bean:1:3
```

Actual: `context` exits 1 with `No entry could be found before
…/link/books/txns/jan.bean:1`; `region` exits 1 with `matched no entries`; the
absolute location under `link/` fails the same way.

Fixture C: `books/main.bean -> ../shared/main.bean`, with a
`books/txns/jan.bean` that posts to an unopened account. `bea --file
books/main.bean check` (and `bean-check`) read `books/txns/jan.bean` and
report the unknown account; `bea doctor missing-open books/main.bean` exits 0
with nothing, `doctor linked … ^grp` matches nothing, and `print-options`
lists only `shared/main.bean`.

Control: the same commands on `real/books/main.bean` work.

Expected: doctor reads the ledger at the path named, as `check` and `list`
do, and resolves locations against it.

Cause: upstream `beancount/scripts/doctor.py` uses `click.Path(resolve_path=True)`
for the ledger; bea forwards the link path (`cli/src/cli/commands/doctor.py:315-325`,
`:578`) and builds locations from it (`:164`).

Fix: run doctor ops with the unresolved path (the in-process `scoped` path can
swap `ledger_path`), or resolve location filenames the same way upstream
resolves the ledger, consistently with the roundtrip scratch names (w1/156).

Dedupe: w1/056 and w5/087 (done) fixed load and format; w1/156 (done) covered
roundtrip scratch files.

Acceptance: both fixtures give the same answers through the link as through
the real path. Tests pin them.
