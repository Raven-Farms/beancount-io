# `add`'s unknown-account fix-up (`To create it, use bea add open --account …`) drops the `--file` the user passed, so pasting it opens the account in a different ledger with exit 0 (gap in w5/303)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `e2565f3b`, checkout `bea 0.3.1`, macOS 26.5.1.
w5/303 established that a command printed for pasting names the ledger; the
`bea_command()` helper builds such commands. The unknown-account remedy (and
the `check_commodity` sibling, `bea add commodity`) are hard-coded. An agent
that pastes them in the same directory writes to whatever ledger cwd
discovery finds. No product fix implemented.

`books/main.bean` and a byte-identical `./main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
```

```sh
bea --file books/main.bean add transaction Latte --date 2026-04-01 -p 'Expenses:Coffee 4 USD' -p Assets:Cash
bea add open --account Expenses:Coffee --date 2026-01-01       # the printed remedy, date filled in
```

Actual: the first exits 1 with `… To create it, use bea add open --account
Expenses:Coffee --date YYYY-MM-DD.`; the paste exits 0 with `Added 1 open to
…/main.bean` (the decoy), and the retry still fails. Without a decoy the paste
exits 2 with "No ledger file".

Control: `bea -f w30/books.bean import …` prints `Run: bea --file
w30/books.bean add open …`.

Expected: `To create it, use bea --file books/main.bean add open --account
Expenses:Coffee --date YYYY-MM-DD.` (and the same for `add commodity`).

Cause: `cli/src/bea_engine/ledger/write.py:1636` (and `:1622`) hard-code `bea
add open` / `bea add commodity` instead of `bea_command(root)`
(`cli/src/bea_engine/ledger/text.py:79`).

Fix: build both with `bea_command`.

Dedupe: searched `To create it, use`; w5/303, 343, 154 and 438 (done) are
related.

Acceptance: both remedies name the ledger; pasting them fixes the original
command. A test pins them.
