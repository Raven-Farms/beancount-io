# `bea import` writes prices that `add price` would refuse or skip: a second, different quote for the same day, and the same quote spelled `110.0`; it also drops a statement price that a plugin already generates

**Minor · cli · 30–45m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
Import deduplicates price directives from a Python importer by their
printed text only. On a day that already has `price HOOL 110.00 USD`,
`bea import --apply` exits 0 and writes both `111.00 USD` (a conflicting
quote) and `110.0 USD` (the same quote spelled differently), even when the
two come from the same batch.

`bea add price` handles the same inputs differently: it refuses `111.00`
with exit 2 and reports `110.0` as already recorded. The reverse also
happens. A statement price that matches one `implicit_prices` generates is
skipped as `Identical directive already exists.` and never written, while
`add price` writes it. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Broker:Cash USD
2026-01-01 open Assets:Broker:HOOL HOOL
2026-01-01 open Equity:Opening
2026-01-01 commodity HOOL
2026-01-31 price HOOL 110.00 USD
```

Also create `/absolute/books/stmt.txt` (contents `x`) and an inspected
`/absolute/books/importers.py`:

```python
import datetime
from decimal import Decimal
from beancount.core import data, amount
from beangulp import importer

class Stmt(importer.Importer):
    def identify(self, filepath):
        return filepath.endswith("stmt.txt")
    def account(self, filepath):
        return "Assets:Broker"
    def extract(self, filepath, existing):
        m = data.new_metadata(filepath, 1)
        d = datetime.date(2026, 1, 31)
        return [
            data.Price(m, d, "HOOL", amount.Amount(Decimal("111.00"), "USD")),
            data.Price(m, d, "HOOL", amount.Amount(Decimal("110.0"), "USD")),
        ]

CONFIG = [Stmt()]
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`,
and the `beangulp` engine feature.

```sh
bea --json -f main.bean import stmt.txt --config importers.py --apply
bea -f main.bean check
bea -f main.bean list price
```

Actual: the import exits 0 with `"written": 2`, and both rows are `new`.
`check` exits 0. `list price` shows three quotes for one day:

```text
2026-01-31  HOOL      110.00 USD
2026-01-31  HOOL      111.00 USD
2026-01-31  HOOL      110.0 USD
```

Reproduced in three fresh runs. The preview shows the same diff.

Second case: a ledger with `plugin "beancount.plugins.implicit_prices"`
and a `2026-01-05` buy of `10 HOOL {100.00 USD}`, with an importer that
returns `2026-01-05 price HOOL 100.00 USD`. `import --apply` reports that
row as `duplicate` ("Identical directive already exists.") and leaves the
file unchanged. `list price --on-disk` then says `No prices found.`

Controls, on the pristine first ledger:

- `bea add price --date 2026-01-31 -c HOOL --amount "111.00 USD"` exits 2
  with `HOOL already has a 2026-01-31 price of 110.00 USD (at main.bean:6);
  refusing 111.00 USD. Pass --force to record another quote.`
- `--amount "110.0 USD"` exits 0 with `Price already recorded at
  main.bean:6; nothing was written.`
- On the `implicit_prices` ledger, `add price … 100.00 USD` writes the
  directive.

Expected: `docs/USAGE.md` says "`add price` skips an exact
date/commodity/amount match anywhere in the root ledger's includes … A
different amount for the same date and commodity is refused naming both
values; pass `--force` … Only written price directives count: a price a
plugin such as `implicit_prices` generates is neither a duplicate nor a
conflict." `docs/IMPORTING.md` says import "does not change the meaning of
existing transactions". Writing a second quote for a day changes the
ledger's valuation with no review step. The ledger should keep one price
per commodity and day, whichever command writes it.

Cause:

- `cli/src/bea_engine/importing.py:288` builds `other_entries` from every
  loaded non-transaction entry, including plugin-generated ones.
- `:418-422` marks an importer directive `duplicate` only when its printed
  text (`_directive_text`) is already in that set.
- There is no comparison of amounts by value (`110.0` and `110.00` print
  differently), and no date/commodity conflict check like the one in
  `add price` (`cli/src/bea_engine/ledger/adding.py:640`).
- Each accepted row's text is added to the set, so a second, different
  quote in the same batch also passes.

Fix: classify a `Price` the way `add price` does, counting only written
directives (`entry_generated`):

- The same date, commodity and amount (compared by value) is a
  `duplicate`.
- A different amount on the same date and commodity, whether in the
  ledger or earlier in the batch, is a `conflict`. `--apply` refuses it
  with exit 4 and names both values.

Keep the text comparison for other directive types; balances stay
precision-sensitive, as documented. No dependency or API change.

Blast radius: `import` through any Python importer that emits `price`
directives (brokerage and statement importers), in preview and apply,
including `--into`. The CSV mapper emits no prices.

Dedupe: searched `.pm/**` (including `done/`) for "Identical directive",
"nontransaction", price together with import or importer, and
`implicit_prices`, and ran `git log -S "Identical directive already
exists"`.

- w5/224 (`7d2490c0`) made the text comparison NFC- and reload-aware. It
  did not touch amount equality, conflicts, or plugin-generated entries.
- w5/183 covers concurrent `add price`.
- w5/291 and w5/285 cover the `add price` guard itself on staged loads.

None of them covers importer prices.

Acceptance:
