# `add` suggests `bea add open --account …` for an account whose root the ledger does not have

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
When a posting names an account under a root the ledger does not use, the
refusal ends with "To create it, use bea add open --account
Expenses:Essen". That command can never succeed; it fails with "Invalid
account name". The exit code is right; the remedy is a dead end. No
product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "EUR"
option "name_assets" "Aktiva"
option "name_expenses" "Aufwand"
2024-01-01 open Aktiva:Bank EUR
2024-01-01 open Aufwand:Essen EUR
2024-01-01 open Equity:Anfang EUR
2024-01-02 * "Opening"
  Aktiva:Bank  1000.00 EUR
  Equity:Anfang
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean add transaction --date 2024-03-02 "Brot" -p 'Expenses:Essen 3 EUR' -p 'Aktiva:Bank'
bea -f main.bean add open --account Expenses:Essen --date 2024-03-01
```

Actual: the first exits 1, file unchanged:

```text
Error: The change would leave the ledger invalid; nothing was written.
  Proposed append (not written): Invalid account name: Expenses:Essen
  Proposed append (not written): Invalid reference to unknown account 'Expenses:Essen' To create it, use bea add open --account Expenses:Essen --date YYYY-MM-DD.
```

The suggested command exits 1 with `Invalid account name:
Expenses:Essen`.

Control: a worker ran `-p 'Aufwand:Neu 3 EUR'` on the same ledger; its
hint's `add open` succeeds. `bea import` on this ledger names the roots
("its roots are Aktiva, Liabilities, Equity, Income, Aufwand").

Expected: no `add open` remedy that cannot work; name the ledger's roots
as import does. The same applies on a default-root ledger for an account
such as `Foo:Bar`.

Cause: `cli/src/bea_engine/ledger/write.py:694-703` appends the hint to
every "unknown account" error without checking the account's root against
the ledger's roots, though the options are already loaded.

Fix: when the root is not one of the ledger's roots, emit the
unknown-root message in place of the `add open` hint, or reject up front
with exit 2. No dependency or API change.

Blast radius: every writer that validates a candidate, on renamed-root
and default-root ledgers.

Dedupe: w1/done/157's report mentions this `add transaction` symptom but
its resolution covered import only; w5/done/009 concerns look-alike
names; w5/080 covers `add custom` on renamed roots.

Acceptance: the first command's message names the ledger's roots and
contains no `add open` suggestion; the `Aufwand:Neu` control keeps its
hint. Only macOS and the checkout were exercised.
