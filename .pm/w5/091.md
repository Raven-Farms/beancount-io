# `balance` and every report crash with `NotImplementedError` on a ledger carrying Fava's `default-file` option

**Major · cli · 20–30m · A2.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, macOS. `default-file` is a standard Fava
option that Beancount accepts as an ordinary `custom` directive. A ledger
that carries it passes `bea check` but cannot be reported on at all: `bea
balance` and all four `bea report` commands exit 1 with a bare exception
name. Anyone arriving from Fava with this line loses reports. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"

2026-01-01 open Assets:Checking USD
2026-01-01 open Equity:Opening

2026-01-02 * "Opening balance"
  Assets:Checking  5000.00 USD
  Equity:Opening  -5000.00 USD

2026-01-01 custom "fava-option" "default-file"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, and an absolute `--file`.

```sh
bea -f /absolute/books/main.bean check
bea -f /absolute/books/main.bean balance
bea --json -f /absolute/books/main.bean report overview
```

Actual: `check` exits 0. `balance` exits 1 with `Error:
NotImplementedError Pass --debug before the command for a traceback.`; the
JSON form is category `validation` with the same message. All four reports
fail identically, as does the two-value spelling `custom "fava-option"
"default-file" "main.bean"`. `list`, `query` and `add` on the same file
exit 0. Repeated twice.

Control: the same ledger with `custom "fava-option" "fiscal-year-end"
"06-30"` reports normally and `-t FY2026` resolves to that fiscal year;
unknown Fava options are ignored.

Expected: a ledger `bea check` accepts can be reported on. An editor-only
Fava option has no bearing on a balance and should be stored or ignored.

Cause: `cli/src/fava/core/fava_options.py:119-121` — `set_default_file`
is a stub that raises `NotImplementedError`. The option parser calls it and
catches only `IndexError`, `TypeError` and `ValueError`, so the exception
leaves `FavaLedger.__init__`, which every report load runs.

Fix: record the option as upstream Fava does — the given value, or the
entry's own filename when none is given — or ignore it. No `fava-option`
value should be able to raise out of option parsing. Keep the vendored-source
attribution. No dependency or API change.

Blast radius: `bea balance` and all four `bea report` kinds, text and JSON.

Dedupe: board search for `default-file`, `fava-option` and
`NotImplementedError` finds nothing; w5/084 concerns `fava.plugins.*` under
native bean-check, a different mechanism.

Acceptance: the fixture's `balance` and four reports exit 0 with the same
figures as a copy without the option, in both spellings; the fiscal-year
control is unchanged. Only macOS and the checkout were exercised.
