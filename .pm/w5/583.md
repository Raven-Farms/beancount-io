# With stderr closed (`2>&-`), bea's child processes start without fd 2: error text lands in stdout with exit 0 (`query --source … > out.csv`), and the query shell loops forever printing `RuntimeError: lost sys.stderr` (gap in w5/308)

**Major · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `f29eb957`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE (non-interactive behavior): with stderr closed, "warnings and errors
are dropped rather than written to stdout". w5/308 reopened fd 2 on
`/dev/null`. When fd 2 is closed, `os.open(os.devnull)` returns fd 2 itself,
opened non-inheritable (PEP 446). The `dup2` branch is skipped because the
descriptor is already 2, so every child bea spawns starts without fd 2. In
the child, Python's stderr writes fall back to stdout, and `input()` raises
`lost sys.stderr`. No product fix implemented.

`bad.bean`:

```beancount
option "operating_currency" "USD"
2026-01-02 * "x"
  Assets:Nope  1 USD
  Equity:Opening
```

```sh
sh -c "exec bea query --source bad.bean -f csv 'SELECT account, number' 2>&-" </dev/null > out.csv; echo $?
```

Actual: exit 0. `out.csv` begins with `…/bad.bean:2: Invalid reference to
unknown account …` and the entry context, then the CSV rows. A BQL syntax
error exits 2 with the loader errors and `error: Cannot run this BQL query…`
in stdout.

On a terminal with fd 2 closed, `bea query` shows no prompt and streams
`error:` / `Traceback … line = input(self.prompt) … RuntimeError: lost
sys.stderr` endlessly (~2 MB/s); `.exit` and Ctrl-D do nothing; only Ctrl-C
ends it. `lsof` shows the frontend's fd 2 on `/dev/null` and the engine child
with no fd 2.

Control: the same commands with `2>/dev/null` produce a clean CSV and a
working shell.

Expected: children inherit a `/dev/null` fd 2, so stdout carries only
results and the shell works.

Cause: `cli/src/cli/main.py:54-58` (`_discard_diagnostics`): no
`os.set_inheritable(2, True)` when `os.open` returned 2. Children are spawned
by `cli/src/cli/engine/launch.py` (`_spawn`). The existing
`tests/test_closed_stderr_keeps_stdout_clean.py` only covers paths where bea
captures the engine's output.

Fix: make fd 2 inheritable after the open (or always `dup2` a fresh
`/dev/null` onto 2). Add closed-stderr tests for `query --source` and for
the shell exiting on `.exit`.

Dedupe: searched `inheritable`, `lost sys.stderr`, `2>&-`. w5/308 (done) is the
fix this completes; w5/522 is the broken-pipe case.

Acceptance: `out.csv` holds only CSV rows (exit per the error), and the shell
under `2>&-` exits on `.exit`. Tests pin both.
