# A managed price include plus a multi-file include glob shifts line numbers on every read

**Major (silent wrong results, exit 0) · cli · 45–60m · A1.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, macOS. This is
the read-path twin of w5/079. When a ledger has a managed price include and
an include glob matching two or more files, every later line of that file is
numbered one or more too high after loading. Authored entries are then judged
"generated", `--on-disk` hides them, `add price` no longer sees its own
duplicates, and diagnostics name the wrong line. No product fix implemented.

The feed was a **simulation**: a loopback HTTP server allowlisted through the
documented `MANAGED_PRICE_ORIGINS` variable served one synthetic feed; no
Beancount.io endpoint was contacted and no credential was used. It served, at
`/prices/BTC-USD`:

```beancount
; alias: BTC-USD
; commodity: BTC
; quote: USD
2026-01-04 price BTC 53000.50 USD
  observed-at: "2026-10-10T00:00:00Z"
```

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
include "http://127.0.0.1:18765/prices/BTC-USD"
include "sub/*.bean"

2026-01-01 open Assets:Checking USD
2026-01-01 open Equity:Opening

2026-01-02 * "Opening balance"
  Assets:Checking  1000.00 USD
  Equity:Opening  -1000.00 USD

2026-01-03 price BTC 51000 USD
```

with `sub/a.bean` (`2026-01-01 open Expenses:Food`) and `sub/b.bean`
(`2026-01-01 open Expenses:Rent`).

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, and an absolute `--file`. Set `MANAGED_PRICE_ORIGINS` to the loopback origin.

```sh
bea -f /absolute/books/main.bean list transaction --on-disk
bea -f /absolute/books/main.bean add price --date 2026-01-03 -c BTC --amount '51000 USD'
```

Actual: the listing exits 0 with `No transactions found.` although the file
holds one. The unfiltered listing marks that transaction `generated` and
its JSON `lineno` is 9 where the file says 8. `add price` exits 0 with
`Added 1 price`, writing a second identical line (`grep -c 'price BTC'`
goes from 1 to 2); a different amount is also written without `--force`.
Repeated on fresh caches.

Controls: remove `sub/b.bean` so the glob matches one file — `--on-disk`
returns the transaction and `add price` answers that the price is already
recorded. Keep both files but delete the URL include — `--on-disk` is
correct.

Expected: `docs/USAGE.md` — `--on-disk` answers "exactly what `grep`
would find in the file"; `add price` "skips an exact date/commodity/amount
match" and refuses a different amount without `--force`. Line numbers in
listings and diagnostics are the file's own.

Cause: `cli/src/bea_engine/managed_load.py:550` rewrites each local include
in the staged shadow copy and joins a glob's matches with `"\ninclude "`,
so N matches turn one line into N and every later line moves down N−1.
Entries and errors are mapped back to the real file by filename only, so the
shifted `lineno` survives. `entry_generated`
(`cli/src/bea_engine/ledger/reader.py:116-149`) then reads the real file at
the wrong line and classes the entry as synthesized; the price duplicate rule
uses the same test.

Fix: the staged shadow must preserve each includer's line numbering — keep
the expanded includes on one physical line, or translate staged line numbers
back before entries and errors leave the loader. Share the approach with
w5/079, which names the equivalent join in `ledger/write.py`; fixing one
site does not fix the other. No dependency or API change.

Blast radius: every command that loads through the managed loader on such a
ledger — `check`, all `list` types, `query` (`meta('lineno')`), report
diagnostics, `add price`/`add balance` duplicate detection and import.

Dedupe: w5/079 limits itself to writers and `write.py`; w5/070 is feed rows
passing `--on-disk`, the opposite direction. Board search for managed
includes with globs or line numbers finds nothing else.

Acceptance: on the fixture `--on-disk` returns the authored transaction and
price, JSON `lineno` matches the file, `add price` reports the duplicate,
and a failing assertion later in the file is reported at its real line.
Only macOS and the checkout were exercised, against a simulated feed.
