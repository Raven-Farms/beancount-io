# `bea check --auto` fails a ledger that `bean-check --auto` accepts

**Major (regression) · cli · 20–30m · A1.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, Beancount 3.2.3, macOS. `--auto` is a native
bean-check option that `bea check --help` lists and the guide tells users to
reach by dropping `--json`. It no longer has any effect on the verdict: after
bean-check accepts the ledger, a second load without the option rejects it.
No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
2026-01-02 * "no opens"
  Assets:Cash  -5 USD
  Expenses:Food  5 USD
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY. Cwd `/absolute/books`:

```sh
bean-check --auto main.bean    # upstream, for comparison
bea check --auto
```

Actual: upstream exits 0. `bea check --auto` (and `-a`) exits 1:

```text
Error: /absolute/books/main.bean: 2 error(s).
  /absolute/books/main.bean:1: Invalid reference to unknown account 'Assets:Cash'
  …
```

`bea check --version` on the same ledger prints `Beancount 3.2.3` and then
the same errors with exit 1, where upstream exits 0. Repeated twice.

Control: the same transaction with two `open` lines exits 0 under
`bea check --auto`.

Expected: exit 0. `docs/USAGE.md` — "drop `--json` to use those native
options" such as `-v` / `--auto` — and `bea check --help` — `-a, --auto
Implicitly enable auto-plugins`. Completed w3/222 recorded `bea check
--auto` succeeding through bean-check.

Cause: `cli/src/cli/commands/check.py:64-70`. After native bean-check
returns 0, the handler always runs `launch.helper_json(["check", "--file",
…])` to apply the out-of-tree document rule. That second load does not know
about `--auto`, and also runs after `--version`. It was added by
`56601140` (w3/351).

Fix: the follow-up pass must not re-judge validity that bean-check already
accepted. Limit it to the document-path findings it exists for, or pass the
auto-plugin choice to the helper; skip it for `--version`. No dependency or
API change.

Blast radius: the native, non-JSON, non-compatibility path of `check` only.

Dedupe: board search for `--auto`, `check -a` and auto-plugins finds only
w3/222 (native flags under `--json`); nothing covers the helper recheck, and
`git log -S` on the helper call shows no later change.

Acceptance: the fixture exits 0 under `--auto` and `-a`; `--version`
exits 0 and prints only the version; a document that resolves outside the
ledger tree still fails plain `bea check`; a ledger with real errors still
exits 1 with `--auto`. Only macOS and the checkout were exercised.
