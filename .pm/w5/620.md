# The "Place X before the command" hint sends `doctor`, `treeify` and `example` users to a dead end: those commands ignore `--file` or refuse `--json` (gap in w5/416)

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-16, HEAD `e2565f3b`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE says `doctor`, `example` and `treeify` ignore `--file`, `BEA_FILE` and
cwd discovery. `doctor`, `example` and `treeify` also have no JSON output.
The misplaced-global hint is generic, so following it fails. No product fix
implemented.

```sh
bea doctor print-options -f main.bean        # hint: "Place -f before the command"
bea -f main.bean doctor print-options         # the hinted form
bea doctor lex main.bean --json               # hint: "Place --json before…"
bea --json doctor lex main.bean               # the hinted form
bea treeify -f bal.txt                        # hint: "Place -f before…"
bea -f bal.txt treeify                        # the hinted form
```

Actual: the hinted forms exit 2 with `Missing argument 'FILENAME'`, `bea doctor
has no JSON output` (`bea example --json` likewise), and for treeify silently
read stdin and refuse with `treeify found no hierarchical column`.

Control: `bea check --offline` gets the hint, and following it works.

Expected: per-command wording. For `-f`/`--file` on these commands: `bea
doctor takes the ledger as an argument: bea doctor print-options main.bean`
(and `bea treeify bal.txt`). For `--json`: say the command has no JSON output.

Cause: `refuse_misplaced_global` (`cli/src/cli/errors.py:221-233`) uses
`placement_hint` regardless of whether the command honors the global; called
from `cli/src/cli/commands/doctor.py:648`, `:681`, `treeify.py` and
`example.py:110`.

Fix: pass the command's handling of each global into the refusal and word it
accordingly.

Dedupe: w5/416 and 413 (done) introduced the hint.

Acceptance: each hint above names a form that works. A test pins them.
