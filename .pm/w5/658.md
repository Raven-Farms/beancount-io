# An earlier-dated duplicate `add open` gets a hint naming the unwritten proposal ("already opened at main.bean:9 for EUR") in a 7-line file (incomplete fix of w5/488)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `06e9ca0f`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/488 (done).
w5/488's addendum asked for one hint naming the existing open, with the
merged currency list. When the proposed open sorts before the existing one,
Beancount blames the existing open, and the hint takes "the other one", which
is the proposal. No product fix implemented.

`main.bean` (7 lines): `option "operating_currency" "USD"`, `2026-01-01 open
Assets:Checking USD`, `2026-01-01 open Equity:OpeningBalances USD`, a blank
line, and a 500 USD opening transaction.

```sh
bea -f /abs/main.bean add open --date 2025-12-01 --account Assets:Checking -c EUR
```

Actual: exit 1, nothing written: `Assets:Checking is already opened at
…/main.bean:9 for EUR; an account opens once. To allow USD too, edit that
open to '2025-12-01 open Assets:Checking EUR,USD'`. Line 9 is the proposal.

Control: the same command dated 2026-01-01 or 2026-02-01 names `main.bean:2`
correctly.

Expected: `already opened at …/main.bean:2 for USD … edit that open to
'2026-01-01 open Assets:Checking USD,EUR'`.

Cause: `cli/src/bea_engine/ledger/write.py:1741` picks `existing = next(… e is
not error.entry)`.

Fix: choose the open that is in the ledger (not the candidate append),
whichever one Beancount blamed.

Dedupe: w5/488 (done) is the parent.

Acceptance: the earlier-dated case names line 2. A test pins it.
