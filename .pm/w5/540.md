# `bea --json list transaction -a Food` output cannot be fed back into `add transactions`: "Row 1, matching_postings: Extra inputs are not permitted"

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `c3c42a48`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE says the directive models define the fields for both listings and bulk
input, and the bulk input already ignores `source` and `generated` so that
a listing can be re-fed. w3/376 added `matching_postings` to account-filtered
listings, and the strict input model refuses it. An agent that moves "the
food transactions" between ledgers this way fails. No product fix
implemented.

`mp.bean`:

```beancount
option "operating_currency" "USD"

2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD

2026-02-01 * "Lunch"
  Expenses:Food  12.00 USD
  Assets:Cash
```

`mpd.bean`: its first five lines.

```sh
bea -f /abs/mp.bean --json list transaction -a Food | jq .data | bea -f /abs/mpd.bean add transactions --from -
```

Actual: exit 1, `1 of 1 row(s) failed validation; nothing was written.` /
`Row 1, matching_postings: Extra inputs are not permitted`.

Control: the same pipe without `-a` exits 0 and reproduces the entry.

Expected: `matching_postings` is accepted and ignored on input, like `source`.

Cause: `cli/src/cli/commands/list.py:393` adds the key;
`TransactionDirective` (`cli/src/bea_engine/ledger/models.py`,
`extra="forbid"`) rejects it.

Fix: accept and drop `matching_postings` in the bulk input model.

Dedupe: w3/376 (done) introduced the key; nothing covers the round trip.

Acceptance: the filtered pipe writes the entry. A test pins the round trip.
