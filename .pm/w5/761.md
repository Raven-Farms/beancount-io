# `bea check --auto --cache-filename X` leaks bean-check's raw `WARNING:root:Cache disabled; Explicitly overridden cache filename … will be ignored.` (sibling of w5/417)

**Trivial · cli · 5m · A1.** Real CLI QA, 2026-10-17, HEAD `1d0fe90f3`, checkout `bea 0.3.1`, macOS 26.5.1. Sibling of w5/417 (done).
No product fix implemented.

```sh
bea --file /abs/main.bean check --auto --cache-filename /abs/my.cache
```

Actual: exit 0, with stderr `WARNING:root:Cache disabled; Explicitly
overridden cache filename /abs/my.cache will be ignored.`. No cache file is
written.

Control: `check -C --cache-filename X` drops the path and prints bea's own
`--no-cache turns the load cache off, so --cache-filename is ignored.`

Expected: the same handling under `--auto`, which isolates the cache itself.

Cause: `cli/src/cli/commands/check.py` (around `:74-78`) drops the path only
when the user's own arguments disable the cache. Under `--auto`, bea adds
`--no-cache` itself (around `:94`) and still forwards the path.

Fix: drop the path (with the note) whenever bea adds `--no-cache`.

Dedupe: w5/411, 417, 418 and 430 (done) do not cover `--auto`.

Acceptance: the command prints bea's note and no `WARNING:root` line.
