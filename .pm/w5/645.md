# Managed-price cache and URL edge cases: a head with `next_refresh_at` far in the future (written under a fast clock) suppresses refreshes until then, aliases `.`/`..` pass the URL policy as dot segments, and an ETag of `"head"` collides with `head.json`

**Trivial · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `c0267f61`, checkout `bea 0.3.1`, macOS 26.5.1. Synthetic local feed server.
No product fix implemented.

1. **Future refresh time.** After a `check`, set `next_refresh_at` in the
   feed's `head.json` to now + 7 days (what a clock running fast at fetch time
   leaves), then change the feed. Three `balance` runs make no request and keep
   the old valuation, printing a stale warning; only `price refresh` recovers.
   Fix: treat `next_refresh_at > now + REFRESH_SECONDS` as expired
   (`cli/src/bea_engine/managed_price_cache.py:280`).
2. **Dot-segment aliases.** `include "http://<origin>/prices/.."` resolves (the
   server logs `GET /prices/..`), and `price export` writes the hidden file
   `prices/...beancount`. The hosted policy normalizes the path with `new
   URL()` and refuses it; conversely it accepts `/prices/./BTC-USD`, which the
   CLI refuses. For `https://beancount.io/prices/..` the bearer gate would
   attach the token to a path servers normalize to `/` (same host; by code
   reading). Fix: refuse `.` and `..` aliases (or normalize as WHATWG URL
   does) before matching `_PRICES_PATH_RE`
   (`cli/src/bea_engine/managed_prices.py:55`).
3. **Reserved revision id.** A feed served with `ETag: "head"` gets revision id
   `head`, whose sidecar `head.json` overwrites the cache head: every online
   load refetches, and `--offline check` then says "no cached revision".
   Fix: prefix revision ids, or reject reserved names, in `feed_revision_id`
   (`managed_prices.py:646-652`).

Dedupe: searched `next_refresh_at` with clock, dot segments with prices; w1/088
is the cloud-path analogue.

Acceptance: each case behaves as fixed above. Tests pin them.
