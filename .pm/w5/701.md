# `cloud logout` drops the server's request ID from the new "lost or unreadable" outcome, and USAGE still gives logout's old exit codes (gap in w5/521)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `733ea312`, checkout `bea 0.3.1`, macOS 26.5.1. Simulation: a local stub API. Follow-up to w5/521 (done, `315af713`).
No product fix implemented.

With a stored credential:

1. **Request ID.** The stub answers the revocation with `200 text/plain "OK"`
   and `x-request-id: req-qa-123`. `bea --json cloud logout` exits 4:
   `{"error": {"category": "conflict", "message": "Removed the local
   credential, but the server's answer to the revocation was lost or
   unreadable (HTTP 200); the outcome is unknown…", "exit_code": 4}}`. The
   envelope has no `request_id`, and text mode has no `Request ID:` line. A
   524 with `cf-ray: 8a1b2c3d4e-SJC` behaves the same. Before `315af713`, the
   200 case kept `"request_id": "req-qa-123"`.
2. **USAGE:1826** still says logout exits "1 when the server is unreachable
   or answers with an error, exit 4 when the request timed out". An unreadable
   2xx, a dropped connection and the gateway statuses now exit 4 as well.

Control:
- `cloud ledger create` on the same unreadable 200 exits 4 with `"request_id":
  "req-qa-123"`; on the 524 it reports `"request_id": "8a1b2c3d4e-SJC"`.
- Logout on a 500 keeps `"request_id": "req-qa-500"`.

Expected: the logout envelope carries `request_id` whenever the backend sent
one (USAGE:309), and USAGE lists logout's exit-4 cases.

Cause: the new branch (`cli/src/cli/commands/cloud/app.py:122-135`) builds
`ConflictError(...)` without `request_id`. `unknown_write_outcome` and
logout's `except Exception` branch both pass it.

Fix: pass `request_id=getattr(exc, "request_id", None)`, and update USAGE:1826.

Dedupe: w5/521 (done) is the parent; w5/690 (open) covers 521–523
classification.

Acceptance: both stub cases include the request ID in JSON and text. A test
pins the 200 case.
