# `bea --json balance food cash` and `bea --json balance "food cash"` both report `account_filter: "food cash"`, though one selects two accounts and the other matches nothing

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
`bea balance` takes several positional substrings and keeps any account
that contains any one of them. The JSON envelope joins them with spaces
into one string. Two terms therefore look the same as one term that
contains a space: `food cash` matches `Expenses:Food` and `Assets:Cash`,
while `"food cash"` matches nothing. The text heading and the "No accounts
match …" note have the same ambiguity. No product fix implemented.

Use the fixture and environment from [340](./340.md).

```sh
bea --json -f /absolute/books/main.bean balance food cash
bea --json -f /absolute/books/main.bean balance "food cash"
```

Actual: both exit 0. The first gives `"account_filter": "food cash",
"account_filter_empty": false` and both accounts. The second gives
`"account_filter": "food cash", "account_filter_empty": true` and no
trees. Reproduced twice by the hunter and once by me.

Control: `report * -a` takes exactly one filter, so its `account_filter`
string is unambiguous.

Expected: `docs/USAGE.md` says `bea balance [ACCOUNT…]` prunes the trial
balance to the subtrees "whose account names contain any argument". The
envelope should carry the arguments as a list, for example
`"account_filter": ["food", "cash"]`, or in a new `account_filters` key
next to the existing string. The text output should quote each term.

Cause: `cli/src/bea_engine/report.py:142` sets `"account_filter": "
".join(accounts) if accounts else None`.

Fix: emit the list, either replacing the string (a JSON shape change to
note in USAGE) or alongside it, and quote the terms in the heading and in
the no-match note. No dependency change.

Blast radius: consumers of `bea balance --json`, plus the text heading and
the no-match note. The `report` subcommands are unaffected.

Dedupe: searched `.pm/**`, including `done/`, for `account_filter`.

- w1/126 covers `account_filter_empty`.
- w3/294 covers a blank filter recorded as `""`.
- w1/020, w3/292, w3/335, w3/379 and w3/395 cover filter semantics and
  totals.
- w5/305 covers a blank-argument message.

None covers how several terms are encoded.

Acceptance: the two commands produce distinguishable `account_filter`
values (two terms versus one), and the text heading quotes each term. A
test pins both. Only macOS and the checkout were exercised.
