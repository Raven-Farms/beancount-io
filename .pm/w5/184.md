# A bulk row with a malformed account name aborts the whole batch, defeats `--partial`, and names neither row nor field

**Minor · cli · 30–45m with w5/129 · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
In `add transactions`, a row whose account is misspelled in form
(`expenses:food`, `Expenses:Food Court`) is not rejected as a row. The
whole batch fails with exit 2 and a message about "0 directive(s)" that
names no field, and `--partial` writes nothing. A row with a well-formed
but unknown account is handled properly. Same guard as w5/129 (invalid
metadata key); one per-row fix closes both. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food
```

`/absolute/books/rows.json`:

```json
[{"date":"2026-02-01","narration":"r1","postings":[{"account":"Expenses:Food","amount":"10 USD"},{"account":"Assets:Cash"}]},
 {"date":"2026-02-02","narration":"r2","postings":[{"account":"expenses:food","amount":"11 USD"},{"account":"Assets:Cash"}]},
 {"date":"2026-02-03","narration":"r3","postings":[{"account":"Expenses:Food","amount":"12 USD"},{"account":"Assets:Cash"}]}]
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea --json -f main.bean add transactions --from rows.json --partial
```

Actual: exit 2, ledger unchanged, nothing written:

```text
{"error": {"category": "usage", "message": "Directive 2 of 3 would be written as 0 directive(s); a field holds a line break or a value that is not one token. Nothing was written.", "exit_code": 2}}
```

Control: the same file with row 2's account `Expenses:Foood` exits 1
with `Row 2: … unknown account 'Expenses:Foood' Did you mean
Expenses:Food?`, `"written_rows": [0, 2]`, `"rejected_rows": [1]`, and
rows 1 and 3 are in the ledger. A worker saw the single-entry `add
transaction -p "expenses:food 11 USD"` give a clear "Invalid account"
message, and the same batch abort for a currency of `TRUE`, a total cost
with no currency, and amount metadata with a lowercase currency; amount
metadata with a non-string currency gave a raw `AssertionError`.

Expected: `docs/USAGE.md` — "If any row is invalid the ledger is left
byte-identical and the command exits **1**, listing the rejected rows.
`--partial` appends the valid rows instead", and "Schema errors show a
human row number, field path, and example". Here: `Row 2,
postings.0.account: Invalid account …`, rows 1 and 3 written.

Cause: `cli/src/bea_engine/ledger/models.py:122` declares the posting
account as a plain string with no input validator. The row renders and
first fails in `require_one_entry_each`
(`cli/src/bea_engine/ledger/write.py:1037-1057`), a batch-level usage
error that neither the batch handler nor the per-row partial loop in
`adding.py` catches.

Fix: validate `account` on write input with the existing account parser
and the ledger's roots; more generally run the one-entry check per row
inside the validation loop and convert its failure to `Row N: …`. No
dependency or API change.

Blast radius: every schema-valid but unrenderable bulk row (accounts,
keyword-like currencies, incomplete costs, amount metadata).

Dedupe: w5/129 is the same guard reached through an invalid metadata
key, and its proposed fix covers only key grammar; w4/done/166 only
quotes the message.

Acceptance: the command exits 1 with a `Row 2` message naming the
account field, and rows 1 and 3 are written; without `--partial` nothing
is written and the same row message appears. Only macOS and the checkout
were exercised.
