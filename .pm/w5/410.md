# Ledger and `-o` write failures other than permission (disk full, file too large) report `OSError: [Errno 27] …` with category `validation` and never say nothing was written

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
The staged write for `add`, bulk add and `import --apply` maps only
`PermissionError` to a bea sentence (exit 3, "nothing was written"). On
a full disk or quota the write correctly leaves the ledger byte-identical
with no leftovers, but the user sees a Python class name and a
`validation` category. Nothing says the ledger is unchanged. `query -o`
fails the same way. `format -i` already reports `Could not finish
in-place formatting: [Errno 27] File too large.` No product fix
implemented.

Use any ledger. Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME,
BEA_NO_UPDATE_NOTIFIER=1, and closed stdin. A file-size limit stands in
for a full disk.

```sh
( trap "" XFSZ; ulimit -f 4; bea -f /absolute/L/main.bean add transaction X --date 2026-03-05 -p 'Expenses:Food 2 USD' -p Assets:Cash )
( trap "" XFSZ; ulimit -f 1; bea -f /absolute/L/main.bean query "SELECT date, narration, position" -o /absolute/o/q.csv )
```

Actual: exit 1 with `Error: OSError: [Errno 27] File too large Pass
--debug before the command for a traceback.`. JSON reports `category:
validation`. The ledger is byte-identical and no `.bea-*` file is left.
`import --apply` and bulk add behave the same way. Reproduced twice each
by the hunter and once by me (add).

Control: a read-only file or directory gets "… nothing was written" with
exit 3.

Expected: no class name, a sentence that says what failed, and the
assurance that the ledger is unchanged (the w3/298 and w5/089 rule). For
example: `Cannot write a staged copy of main.bean (File too large);
nothing was written.`

Cause: `candidate_file` (`cli/src/bea_engine/ledger/write.py:735-760`)
maps only `PermissionError`. Other `OSError`s reach the generic handler
(`cli/src/cli/main.py:197-198`, then `cli/src/cli/errors.py` `to_bea_error`).

Fix: map any `OSError` from the stage or replace step to that sentence
(exit 1, a non-`validation` category), and do the same in the `query -o`
write path. This is the same change as 408's `candidate_file` fix. No
dependency change.

Blast radius: `add *`, bulk add, `import --apply` and `query -o` on a
full disk or quota.

Dedupe: w5/156 kept the bare `[Errno 27]` text for `format -o`. 407
covers stdout and 408 covers managed reads. None covers these writes'
wording.

Acceptance: under the limit, each command prints the sentence without
`OSError:` and says nothing was written. JSON category is not
`validation`. A test simulates `EFBIG`.
