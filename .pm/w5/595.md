# An `-o` export to a different-case spelling of a glob-included directory (`-o Txns/backup.bean` for `include "txns/*.bean"`) joins the ledger on case-insensitive APFS and doubles balances, while `bea check` passes (gap in w5/072)

**Major · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `56b3a3ad`, checkout `bea 0.3.1`, macOS 26.5.1. Case-insensitive APFS (the macOS default).
w5/072 refuses an output path that "would become part of the ledger it
reads". The glob check compares resolved directory strings, and on APFS
`resolve()` does not fold case, so `…/Txns` is not equal to `…/txns`. The
file then lands inside the include directory. No product fix implemented.

`books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Equity:Opening USD
include "txns/*.bean"
```

`books/txns/a.bean`: `2026-01-02 * "a"`, `Assets:Cash 5 USD`, `Equity:Opening`.
From `books/`:

```sh
bea -f /abs/books/main.bean query "PRINT FROM date >= 2026-01-02" -o Txns/backup.bean
bea -f /abs/books/main.bean query "SELECT sum(position) WHERE account = 'Assets:Cash'"
bea -f /abs/books/main.bean check
```

Actual: the export exits 0 and creates `txns/backup.bean`; the sum goes from
5 USD to 10 USD; `check` exits 0. `format main.bean -o Txns/f.bean` and
`example -o Txns/e.bean` also exit 0 (the format copy then re-includes itself
and breaks `check`).

Control: `-o txns/backup.bean` is refused with `would become part of the
ledger it reads: include "txns/*.bean" … matches that path.`; an existing
case-variant file is refused too.

Expected: the case-variant spelling is refused the same way.

Cause: `_glob_would_match` (`cli/src/cli/output.py:633-643`) compares
`Path(dir).resolve() == target.parent`.

Fix: compare directory identity (`os.path.samefile` or `st_dev`/`st_ino` of the
existing directory) rather than path strings, for every `-o` user
(`query`, `format`, `example`, `treeify`, `price export`).

Dedupe: w5/072 (done) is the fix this extends; w5/574 is the `--into`
write-path twin.

Acceptance: `-o Txns/backup.bean` exits 2 with the include message on a
case-insensitive volume. A test pins it (skipped where the filesystem is
case-sensitive).

Addendum (CLI QA 2026-10-17, re-check of the w5/497 fix): the load cache has
the same case-folding gap, in the frontend and the engine. On a
60k-transaction ledger with `include "txns/*.bean"`, `bea -f /abs/main.bean
check --cache-filename TXNS/zcache.bean` and
`BEANCOUNT_LOAD_CACHE_FILENAME=TXNS/envcache.bean bea -f /abs/main.bean balance`
exit 0 and write a 10 MB pickle into `txns/`; the next load fails with `Cannot
decode '…/txns/zcache.bean' as UTF-8`. `txns/zcache.bean` is refused. Causes:
`_glob_would_match` (`cli/src/cli/output.py:683`) and the engine's
`_included_new_file` (`cli/src/bea_engine/ledger/write.py:397`) both compare
resolved path strings. The directory-identity fix should cover both, for
`-o` and the cache.
