# A detected CSV delimiter is remembered and then overrides detection for the next export

**Minor · cli · 20–30m · A2.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, macOS. The separator `bea import` detects for
one file is stored with the remembered mapping and forced onto the next file
that shares its header. An export re-saved with another separator is then
refused for lacking a column it plainly has. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"

2026-01-01 open Assets:Checking USD
2026-01-01 open Liabilities:Card USD
2026-01-01 open Expenses:Food
2026-01-01 open Expenses:Uncategorized
2026-01-01 open Equity:Opening

2026-01-02 * "Opening balance"
  Assets:Checking  1000.00 USD
  Equity:Opening
```

`/absolute/books/jan.csv`:

```csv
Date,Description,Amount
2026-01-05,Coffee,-3.00
```

and `/absolute/books/feb.csv`:

```csv
Date;Description;Amount
2026-02-05;Tea;-2,50
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`, and
a fresh configuration directory so no mapping is remembered.

```sh
bea -f /absolute/books/main.bean import jan.csv --account Assets:Checking --apply
bea -f /absolute/books/main.bean import feb.csv
```

Actual: the first exits 0 and writes one entry. The second exits 2:

```text
Using settings remembered from jan.csv for feb.csv: --csv date=Date,amount=Amount,narration=Description --date-format %Y-%m-%d --default-account Expenses:Uncategorized.
Error: The mapping names column 'Date' for date, which feb.csv lacks.
```

The settings line lists no delimiter, and `feb.csv` has a `Date` column.
Repeated twice; a tab-separated re-save fails the same way.

Controls: with a fresh configuration directory, `import feb.csv --account
Assets:Checking` previews `1 ready`. After the first step, `import feb.csv
--delimiter ';'` exits 0.

Expected: `docs/IMPORTING.md` says "Field separators are detected from the
header" and that a remembered setting is "re-validated per file"; of the date
format it says "Only a `--date-format` you passed is remembered". The header
of `feb.csv` matched the remembered one only because detection read it with
`;`, so the import should proceed with that separator. Only a delimiter the
user passed should be carried to another file, and one that is carried should
be printed among the settings in force.

Cause: `cli/src/cli/commands/import_.py:635` stores `csv_delimiter` even
when it came from `detect_delimiter` (`:467-468`). On recall, `:439-440`
replays the stored value, although `_recall_csv` matched the header using
fresh detection; `:562` omits a comma from the settings note.

Fix: remember a delimiter only when the user supplied it (`--delimiter` or
`delimiter=` in `--csv`); otherwise detect per file. When a remembered
explicit delimiter is replayed, name it in the settings line, comma included.
No dependency or API change.

Dedupe: board search for delimiter with remembered or recalled settings finds
w1/m24/t001, which specifies remembering an explicit override; nothing covers
a detected one.

Acceptance: on the fixture `import feb.csv` previews one ready row for
`2026-02-05` and −2.50 USD with no flag; an explicitly passed delimiter is
still remembered and now printed; JSON `remembered.delimiter` is `null`
after a detected run. Only macOS and the checkout were exercised.
