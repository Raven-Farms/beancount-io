# The first write into a not-yet-existing `--into` file hides a `../` include: `add price` writes a conflicting quote, and `--allow-errors` refuses over the old error

**Major · cli · 15–20m on top of 285 · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS. Fix with [285](./285.md).
On a ledger whose root includes a file through `..`, the first write into
a new period file (`--into 2026/02.bean`, not yet on disk) no longer sees
that file's entries. `add price` writes a different quote for a day that
already has one, or an exact duplicate, with exit 0; and `--allow-errors`
refuses the write, calling the error it was told to tolerate "new". Unlike
285 this needs no managed price include and is not a simulation. No
product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Uncategorized
2026-01-01 open Equity:Opening
2026-01-02 * "Open"
  Assets:Checking  100.00 USD
  Equity:Opening
include "../shared/prices.bean"
include "2026/*.bean"
```

`/absolute/shared/prices.bean`:

```beancount
2026-01-01 commodity HOOL
2026-02-10 price HOOL 110.00 USD
```

`/absolute/books/2026/01.bean`:

```beancount
2026-01-03 event "location" "NYC"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.
Run each case on a pristine copy.

```sh
bea --json -f main.bean add price --date 2026-02-10 -c HOOL --amount "111 USD" --into 2026/02.bean
bea -f main.bean check
bea -f main.bean list price
```

Actual: exit 0, `"written": 1, "duplicate": false`; `2026/02.bean` is
created with `2026-02-10 price HOOL  111 USD`. `check` exits 0 and
`list price` shows both quotes for the day:

```text
2026-02-10  HOOL      110.00 USD
2026-02-10  HOOL      111 USD
```

With `--amount "110.00 USD"` the same command also exits 0 with
`"written": 1, "duplicate": false`, writing an exact duplicate.

Second case: append `2026-01-24 balance Assets:Checking  5.00 USD` to
`/absolute/shared/prices.bean`, then

```sh
bea -f main.bean add note --date 2026-03-01 -a Assets:Checking -m "new month" --into 2026/02.bean --allow-errors
```

Actual: exit 1, nothing created.

```text
Error: The change would introduce 1 new ledger error(s); nothing was written.
  /absolute/shared/prices.bean:3: Balance failed for 'Assets:Checking': expected 5.00 USD != accumulated 100.00 USD (95.00 too much)
```

Control: `--into 2026/01.bean` (an existing file) and no `--into` both
exit 2 with `HOOL already has a 2026-02-10 price of 110.00 USD (at
/absolute/shared/prices.bean:2); refusing 111 USD. Pass --force to record
another quote.` The same layout with the file inside the root directory
(`include "shared/prices.bean"`) and the absent `--into 2026/02.bean` gives
the same correct refusal. The `--allow-errors` note into `2026/01.bean`
exits 0 with the old assertion as a warning. A worker saw the exact
duplicate reported as `written: 0, duplicate: true` into the existing
file, and, once, a CSV import duplicate cited as `Existing entry at
/absolute/shared/.bea-<hex>.tmp:4`, a file that no longer exists.

Expected: `docs/USAGE.md` says "`add price` skips an exact
date/commodity/amount match anywhere in the root ledger's includes" and
that a different amount for the same date and commodity is refused naming
both values; an absent destination "is created only when a validated write
succeeds", which does not weaken the checks; and every add command accepts
`--allow-errors` "for a semantic error already in the books".

Cause: `cli/src/bea_engine/managed_load.py:284` takes the plain load only
when every snapshot file exists, so a planned absent destination routes
the load through the staged-twin loader. `ledger/write.py:82` captures
include matches with `Path(p).absolute()`, which keeps `..`;
`managed_load.py:346` stages a twin beside that spelling and `:363` builds
the map back to originals from it. Beancount normalises include paths, so
entries and errors from the `../` file carry a normalised staged path the
map misses. `ledger/adding.py:568` then asks `entry_generated`
(`ledger/reader.py:115`) about a file that is gone, classes the price as
plugin-generated and drops it from the conflict set; `write.py:655-656`
keys the before-errors by the unmapped path, so the old error counts as
new.

Fix: normalise closure paths at capture, or key the map by the normalised
staged path, as 285 proposes. The line-shift fixes proposed in 145 and 092
do not cure this case. No dependency or API change.

Blast radius: any ledger with a `..` include, on the first write into a
new period file: the `add price` guard, every `add` kind and CSV import
under `--allow-errors`, and import duplicate diagnostics. `add balance`
shares the loader and was not hand-tested. A worker's random-sequence run
hit this 8 times on the price guard and 14 times under `--allow-errors`.

Dedupe: board search for `managed_load.py:284`, `../`, "absent", "new
file" and "next period" finds w5/145 (same gate, line-shift mechanism,
needs content after the glob), w5/285 (same map-back defect, needs a
managed price include), w5/096 (destination itself reached through `..`)
and w5/092, w5/079 (glob line shifts); none covers a plain `../` include
with an absent destination.

Acceptance: on the fixture, the 111 quote into the absent `2026/02.bean`
exits 2 naming `/absolute/shared/prices.bean:2` and creates nothing; the
110.00 quote reports a duplicate and writes nothing; the `--allow-errors`
note exits 0 with the old assertion as a warning. A real-command
regression test covers all three with no managed include. Only macOS and
the checkout were exercised.
