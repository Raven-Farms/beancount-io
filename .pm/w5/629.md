# Hosted ledger: the managed feed validator accepts metadata after a blank line or a column-0 comment, which Beancount reads as `unexpected INDENT`

**Minor · backend-cluster/ledger · 20–30m · A1.** Follow-up from w5/478 (CLI fix `3ef48d5b`).
The hosted feed parser (`backend-cluster/ledger/src/foundation/managed-prices/managed-price-feed.ts`)
skips `BLANK_RE` and `COMMENT_RE` lines without ending the current point, as the CLI's
`validate_managed_price_text` did before w5/478. Beancount ends a directive at a blank or
whitespace-only line and at a comment in column 0, and an indented comment needs a
directive above it. So these bodies validate but do not parse:

- price, blank line, indented `observed-at: "…"`;
- price, whitespace-only line, indented metadata;
- price, `; note` at column 0, indented metadata;
- `  ; note` before the first price.

Each gives `syntax error, unexpected INDENT` in Beancount's parser. In the CLI, such a
body replaced the last good revision and broke every later command. Found by reading
the code, not reproduced against the hosted service.

Fix: a blank line or a column-0 comment ends the current point; an indented comment
with no current point is refused. An indented comment inside a point's metadata stays
valid.

Acceptance: unit tests in the feed parser's suite refuse the four bodies above and
accept an indented comment between a price's metadata lines.
