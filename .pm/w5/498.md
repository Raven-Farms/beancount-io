# `doctor region --conversion value` rounds the converted tree to whole units (`1016 USD`, `-16 USD`), so it disagrees with `Net Income: (15.50 USD)`

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `3f2372e1`, checkout `bea 0.3.1`, macOS 26.5.1. Sibling of w5/101.
w5/101 made the doctor trees exact ("The tree and `Net Income` now agree in
both directions"). It did this by building the display context from the
precision of in-scope posting units. Market values and the `Unrealized`
line come from prices, whose precision the context never sees. No product
fix implemented.

`main.bean`:

```beancount
2024-01-01 open Assets:Broker HOOL
2024-01-01 open Assets:Cash USD

2024-01-02 * "Buy"
  Assets:Broker  10 HOOL {100 USD}
  Assets:Cash   -1000 USD

2024-01-03 price HOOL 101.55 USD
```

```sh
bea doctor region /abs/main.bean 4:6 --conversion value
```

Actual: exit 0; the tree shows `Broker 1016 USD` and `Unrealized -16 USD`;
the last line is `Net Income: (15.50 USD)`.

Control: without `--conversion`, and with `--conversion cost`, the numbers
are exact.

Expected: `Broker 1015.50 USD` and `Unrealized -15.50 USD` (10 × 101.55),
agreeing with `Net Income`.

Cause: `_context_of` (`cli/src/bea_engine/scoped.py:112-139`) learns
precision only from posting units.

Fix: build the context from the converted balances (or add the precision of
the prices used).

Dedupe: w5/101 and w3/352 (done) fixed the units-only case.

Acceptance: the command prints `1015.50` and `-15.50`. A test pins it.
