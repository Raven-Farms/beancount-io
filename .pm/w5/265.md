# CSV amounts with the currency symbol before the minus sign (`$-1,234.56`, `€ -1.234,56`) are refused once the number has a separator

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
`$-4.50` imports, but `$-1,234.56` does not: the sign is split off only
when it comes first, so with the symbol in front the grouping check sees
`-1,234` and fails. The error lists as accepted exactly what the cell
contains. `€ -1.234,56` is the standard Dutch currency format. Refusal
only, no misreading. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Assets:Euro EUR
2026-01-01 open Expenses:Uncategorized
```

`/absolute/books/us.csv`:

```csv
Date,Description,Amount
2026-03-01,Rent,"$-1,234.56"
```

`/absolute/books/nl.csv`:

```csv
Datum;Omschrijving;Bedrag
2026-03-01;Huur;€ -1.234,56
2026-03-02;Koffie;€ -4,50
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME (fresh), BEA_NO_UPDATE_NOTIFIER=1,
no inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean import us.csv --csv date=Date,amount=Amount,narration=Description --account Assets:Checking
bea -f main.bean import nl.csv --csv date=Datum,amount=Bedrag,narration=Omschrijving --account Assets:Euro
```

Actual: both exit 2.

```text
Error: Row 1 (line 2): cannot parse amount '$-1,234.56' in column 'Amount'. Accepted: plain decimals (1000.50), $/€ symbols, thousands separators, (parentheses) or trailing-minus negatives; …
Error: Row 1 (line 2): cannot parse amount '€ -1.234,56' in column 'Bedrag'. Accepted: …
```

Control: the same US file with `"-$1,234.56"` previews `-1234.56 USD`. A
worker saw `$-4.50`, `($1,234.56)`, `-€ 1.234,56` and `€ 4,50-` accepted,
and `$(1,234.56)` refused.

Expected: `docs/IMPORTING.md`: "Cells may carry currency symbols (`$4.50`,
`4,50 €`), thousands separators, accounting parentheses or a trailing minus
for negatives … and comma decimals".

Cause: `cli/src/bea_engine/csv_mapper.py:116-118` splits a leading sign
before symbols are stripped (`:121-134`), so the core keeps its `-`; the
grouping validators (`:213-218`, `:243-245`) then test the whole part with
the sign attached.

Fix: after stripping symbols, split a leading sign off the core again
(refusing two signs) and let the separator checks see the unsigned core;
accept a symbol-prefixed parenthesis too. No dependency or API change.

Blast radius: `amount=`, `debit=` and `credit=` cells in CSV import.

Dedupe: board search for `$-1,234`, "cannot parse amount" and
`_split_amount_sign` finds w1/done/153 (double negatives; lists `$-5.00` as
a working control, never with a separator), w3/done/256 (symbol support)
and w5/255 (Unicode minus).

Acceptance: both files preview `-1234.56 USD` / `-1234.56 EUR` and `-4.50
EUR`; the listed controls are unchanged. Only macOS and the checkout were
exercised.
