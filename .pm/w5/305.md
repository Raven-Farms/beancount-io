# A blank `bea balance` argument is refused as "accounts needs a non-empty value; drop accounts to leave it unset", naming an internal parameter rather than any option

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, Python 3.13.3.
A blank positional filter to `bea balance` exits 2, as documented. The
message, though, tells the user to "drop accounts", which is the Typer
parameter name, and no `accounts` flag exists. For `bea balance Cash ''`,
what needs dropping is the empty second argument. No product fix
implemented.

Use any valid ledger (for example, a fresh `bea init`), with isolated
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no inherited
BEA_FILE/BEA_TOKEN, closed stdin, and cwd at the ledger.

```sh
bea balance ''
bea balance Cash ''
bea --json balance ' '
```

Actual: each command exits 2 with `accounts needs a non-empty value; drop
accounts to leave it unset.` With `--json`, the text is the same and the
category is `usage`. Reproduced in three fresh runs.

Control: `bea report balance-sheet -a ''` and `bea list transaction -a ''`
both say `--account needs a non-empty value; drop --account to leave it
unset.`, naming a real option.

Expected: `docs/USAGE.md` (Reports) says a blank `bea balance` argument
"is refused (exit 2) naming the flag". For a positional argument, the
message should name the argument and the fix. For example: `An ACCOUNT
argument is empty; remove it, or pass an account substring.`

Cause: `cli/src/cli/commands/report.py:176` calls
`refuse_blank_filter("accounts", term)`. `cli/src/cli/utils.py:96-106`
uses one wording for every caller, `{flag} needs a non-empty value; drop
{flag} to leave it unset.`, which only makes sense for options.

Fix: pass a display name such as `ACCOUNT` and let `refuse_blank_filter`
take its own message for positional arguments. Optionally set
`metavar="ACCOUNT"`. No dependency change.

Blast radius: `bea balance`, in text and JSON. Every other caller passes a
real option name.

Dedupe: a board search for "non-empty value", "drop accounts" and "blank
`bea balance`" finds w5/064 (sigil-only tag and link filters, a different
input) and nothing else.

Acceptance: `bea balance ''` and `bea balance Cash ''` exit 2 with a
message that names the empty account argument and does not say "drop
accounts". A real-command test pins both. Only macOS and the checkout were
exercised.
