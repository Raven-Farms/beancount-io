# If `BEA_ENGINE_DIR` names an existing directory that holds no engine (for example a typo pointing at a data folder), first-use provisioning moves it aside and deletes it with `shutil.rmtree`

**Major · cli · 15–20m · A2.** CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1. **Confirmed from the code only.** Provisioning needs an installed layout and the network, so it was not run.

`engine_root` accepts `BEA_ENGINE_DIR` unchecked ([412](./412.md)).
`is_provisioned` is False for any directory that lacks the engine's venv
python and core packages. Provisioning builds `<root>.partial.<pid>`, and
on success `_publish` moves an existing `root` aside and deletes it with
`shutil.rmtree`. It does not check that bea created that directory. A
typo such as `BEA_ENGINE_DIR=~/books`, or any existing data folder,
would therefore be deleted once the engine install succeeds. If the
install fails, the root is left untouched. No product fix implemented.

Evidence:

- `engine_root` (`cli/src/cli/engine/paths.py:60-64`) returns the
  override as given.
- `is_provisioned` (`paths.py:107-121`) checks for the venv python and
  core packages only.
- `_publish` (`cli/src/cli/engine/provision.py:405-417`):

  ```python
  if root.exists():
      discarded = root.with_name(f"{root.name}.discarded.{os.getpid()}")
      os.replace(root, discarded)
      shutil.rmtree(discarded, ignore_errors=True)
  os.replace(partial, root)
  ```

  Its comment says "Something unusable is already there". That is true
  for a half-built engine, not for a user's folder.
- `_sweep_abandoned` (`provision.py:374-389`) only removes siblings with
  bea's specific `.partial.`, `.discarded.` and `.repair-discard.`
  suffixes, which is low risk.

Expected: bea never deletes a directory it did not create. A non-empty
`BEA_ENGINE_DIR` without a bea engine marker should be refused with a
`BeaError` naming it, or at least moved aside without deletion and
reported.

Fix: write a marker file (for example `.bea-engine`) when provisioning.
In `_publish`, discard `root` only if it carries the marker or is empty,
and otherwise raise. Combine this with 412's absolute and directory
checks. No dependency change.

Blast radius: anyone who sets `BEA_ENGINE_DIR`, for example packagers,
CI, or users relocating the engine, with a path that already holds other
data. The result is irreversible deletion of that directory.

Dedupe: 412 covers relative or file-typed values (status only). No note
covers deletion of an existing directory.

Acceptance: in an installed-layout test with `BEA_ENGINE_DIR` pointing at
a directory that holds a user file, the first local command refuses (or
provisions elsewhere) and the user file still exists. An existing
bea-made engine directory is still repaired. A test with a stub installer
pins it.
