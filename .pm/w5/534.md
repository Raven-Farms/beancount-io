# `add transaction -p 'Expenses:Food 4,50 EUR'` and `add balance --amount '4,50 EUR'` are refused with a raw `ValueError: Invalid number format: '4,50'`; `--tag café` is told to "use only letters"

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `5d08dc41`, checkout `bea 0.3.1`, macOS 26.5.1.
Both refusals are correct; the messages are not. A decimal comma is the
normal spelling in most of Europe. `add price`, `custom` and `init` explain
it, but postings and balances relay Beancount's parser exception. Tags are
ASCII-only in Beancount, but the refusal says "letters". No product fix
implemented.

```sh
bea --file /abs/main.bean add transaction --date 2026-02-01 -p 'Expenses:Food 4,50 EUR' -p Assets:Checking
bea --file /abs/main.bean add balance --date 2026-02-01 -a Assets:Checking --amount '4,50 EUR'
bea --file /abs/main.bean add transaction --date 2026-02-01 --tag café -p 'Expenses:Food 4 EUR' -p Assets:Checking
```

Actual: (1) exit 2, `--posting 1: ValueError: Invalid number format:
'4,50'`; (2) exit 2, `--amount: ValueError: …`; (3) exit 2, `'café' is not one
tag or link; use only letters, digits and - _ / . …`.

Control: `add price … --amount '4,50 EUR'` says `A comma is read only as a
thousands separator between groups of three digits, such as '1,538.25';
write the fraction after a decimal point, or remove the separators.`

Expected: (1) and (2) give the same comma message; (3) says "ASCII letters".

Cause: `cli/src/bea_engine/ledger/adding.py:746-760` (postings) and
`:582-586` (balance) relay the parser text and never reach the message in
`cli/src/bea_engine/amounts.py:28-33`; the tag wording is in
`cli/src/bea_engine/ledger/text.py:199` and `cli/src/cli/commands/list.py:315`.

Fix: detect a decimal-comma token and reuse the shared message; say
"ASCII letters" in the tag grammar text.

Dedupe: `Invalid number format` appears only in w3/259 (scientific notation).

Acceptance: the three messages read as above. A test pins them.
