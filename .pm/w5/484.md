# `balance`/`report` price-source warnings end in `..`, and `upgrade --check` shows raw Python parser text for an unreadable index answer

**Trivial · cli · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `0864aeed`, checkout `bea 0.3.1`, macOS 26.5.1. Synthetic local servers.
Two message slips that w5/379 and w5/375/376 fixed elsewhere. No product
fix implemented.

1. After a refresh fails with HTTP 503 for an allowlisted managed include,
   `bea -f /abs/main.bean balance` prints `Price source BTC-USD: recent;
   observed …; revision …; fetch failed (provider): HTTP 503: price service
   unavailable. Retry later; cached prices remain usable..`. Cause:
   `cli/src/cli/commands/report.py:155-160` appends `.` to an error that
   already ends in one; w5/379 fixed the same pattern in `price refresh`.
2. With `BEA_UPDATE_API_URL` pointing at an index that answers an HTML page,
   `{"info":{}}` or `{"info":null}`, `bea upgrade --check` exits 1 (correct)
   with `Could not check … for a newer release: Expecting value: line 1
   column 1 (char 0).`, `…: 'version'.` or `…: 'NoneType' object is not
   subscriptable.` Cause: `cli/src/cli/update.py:180` reports `str(exc)` for
   parser and shape errors.

Expected: one full stop, and `Could not check … for a newer release: the
index sent an unreadable answer.`

Fix: `rstrip('.')` before appending in `report.py`; map JSON and shape
errors in `update.py` to the fixed sentence (keep transport errors as they
are).

Dedupe: w5/379 (refresh), w5/322 and w5/375/376 (update check) are done and
do not cover these two.

Acceptance: both messages read as above. Tests pin each.
