# `add balance --pad-from` never reports how much it padded, so a credit-card statement balance entered with the wrong sign (77.04 instead of -77.04) is silently padded by twice the balance, exit 0

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `be46147e`, checkout `bea 0.3.1`, macOS 26.5.1. Found while driving a three-month agent journey with `--json --no-input`.
USAGE recommends the atomic pad and balance for reconciling. The answer
names the pad's date and accounts but not its amount, in text or JSON. A sign
error on a liability (statements print the balance owed as positive) becomes
a 154.08 USD adjustment that nothing reports. Finding it takes a second `list
transaction` and a look at the `P` entry. No product fix implemented.

`main.bean`:

```beancount
option "operating_currency" "USD"
2026-07-01 open Liabilities:CreditCard USD
2026-07-01 open Expenses:Dining
2026-07-01 open Equity:OpeningBalances
2026-07-05 * "Dinner"
  Liabilities:CreditCard  -77.04 USD
  Expenses:Dining
```

```sh
bea --json --no-input --file /abs/main.bean add balance --date 2026-10-02 --account Liabilities:CreditCard --amount "77.04 USD"
bea --json --no-input --file /abs/main.bean add balance --date 2026-10-02 --account Liabilities:CreditCard --amount "77.04 USD" --pad-from Equity:OpeningBalances
```

Actual: the first exits 1 with `expected 77.04 USD != accumulated -77.04 USD
(154.08 too little)` and generic advice (review missing transactions, record
fees); nothing mentions that liability balances are negative. The second exits
0 with `"written": 2, "pad": {"date": "2026-10-01", "account":
"Liabilities:CreditCard", "source_account": "Equity:OpeningBalances", "meta":
{}}, "warnings": []`; text prints `Added 1 pad and 1 balance to …`. `list
transaction` then shows `(Padding inserted for Balance of 77.04 USD for
difference 154.08 USD)`.

Control: when an existing pad covers the assertion, the warning names the
amount ("inserting X USD").

Expected: the answer reports the amount the pad inserts (JSON `pad.amount` and
a text line). When the asserted value is exactly the negation of the book
balance on a `Liabilities` account, both the failure and the pad path say so
(`the ledger holds -77.04 USD; liability balances are negative in Beancount —
did you mean -77.04 USD?`), and the pad path asks for `--force` before
writing.

Cause: the fresh-pad path (`cli/src/bea_engine/ledger/adding.py:350-357`,
answer at `:436-449`) never computes the difference (only the retry branch at
`:402` does); the failure hint is a fixed string
(`cli/src/bea_engine/ledger/write.py:1033-1037`).

Fix: as above.

Dedupe: searched `pad amount`, `opposite sign`, `negat` with liabilities.
w5/359 (done) fixed the reconcile skill's sign text; w5/323 (done) reshaped the
answer without an amount.

Acceptance: the pad answer names 154.08 USD; the sign hint appears for the
negated liability case, and `--pad-from` there requires `--force`. Tests pin
both.

Addendum (CLI QA 2026-10-16, precision sweep): the pad-omitted message
overstates the match. With `Assets:Bank 100.004 USD` in the book, `add balance
--date 2026-01-05 -a Assets:Bank --pad-from Equity:Opening --amount '100.01
USD'` (or `'100 ~ 0.004 USD'`) exits 0 with `Book balance already matches 100.01
USD; omitted the pad…` (the second drops the `~ 0.004`). Skipping the pad is
right under tolerance; the message should say the book holds 100.004 USD,
within the assertion's tolerance. Cause: `cli/src/bea_engine/ledger/adding.py:423-430`.

Addendum (CLI QA 2026-10-17, HEAD `116cf55c0`): a zero-history liability. With
`open Liabilities:Loan USD` and nothing posted, `add balance --date 2026-01-10 -a
Liabilities:Loan --amount "5000 USD"` exits 1 and prints `Opening adjustment
command: bea --file … add balance --date 2026-01-10 --account
Liabilities:Loan --amount '5000 USD' --pad-from Equity:OpeningBalances`. Run
verbatim, that exits 0, and `report balance-sheet` shows the loan adding
5,000 USD to net worth. A command bea generates for a Liabilities, Income or
Equity account with a positive amount should note that such balances are
negative in Beancount, and offer `-5000 USD`
(`_balance_recovery_hints`, `cli/src/bea_engine/ledger/write.py:1113`).
