# The load cache does not notice a `document` file appearing or vanishing: `check` says valid while every write is refused

**Major · cli · 45–60m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`),
checkout `bea 0.3.1`, macOS.
On a ledger large enough to be cached (about a second of loading), whether a
`document` directive's file exists is frozen at the time the cache was
written. Remove the attachment and `bea check` keeps exiting 0 — while every
`bea add` is refused for an error `check` denies, and `--allow-errors`
does not help. Restore a missing attachment and `check` keeps failing. The
state only clears when a ledger file's size or time changes. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2000-01-01 open Assets:Bank USD
2000-01-01 open Expenses:Food USD
include "big.bean"
2021-03-01 document Assets:Bank "receipts/stmt.pdf"
```

a file `/absolute/books/receipts/stmt.pdf` with any content, and generate
`/absolute/books/big.bean`:

```sh
python3 -c "open('big.bean','w').writelines(f'2020-01-01 * \"t{i}\"\n  Expenses:Food  1 USD\n  Assets:Bank\n\n' for i in range(60000))"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY.

```sh
bea -f /absolute/books/main.bean check
rm /absolute/books/receipts/stmt.pdf
bea -f /absolute/books/main.bean check
bea --json -f /absolute/books/main.bean check
bea -f /absolute/books/main.bean add note --account Assets:Bank --comment hi --date 2021-04-01 --allow-errors
```

Actual: the first `check` exits 0 and writes `.main.bean.picklecache`.
After the file is removed, `check` exits 0 and `--json check` exits 0 with
`{"valid": true, "errors": []}`. The `add note` exits 1 with `The change
would introduce 1 new ledger error(s); nothing was written.` and
`main.bean:5: File does not exist: "/absolute/books/receipts/stmt.pdf"`.
The ledger is unchanged, so its times never move and no bea write can clear
the state.

Reverse direction: with the cache deleted and the attachment absent,
`--json check` exits 1 with `File does not exist`; after creating the
file, `--json check` still exits 1 with the same error; after
`touch main.bean` it exits 0.

Control: with `BEANCOUNT_DISABLE_LOAD_CACHE=1`, `--json check` after the
removal exits 1 naming the missing file. A worker confirmed that the cold
`add note … --allow-errors` then exits 0 and writes, and that a
one-transaction ledger, which is never cached, flips immediately.

Expected: `docs/USAGE.md` says "Exit 0 is a promise … a write that exits 0
introduces no new `bea check` error", which needs `check` and write
validation to agree on what the ledger's errors are, and that a write
"accepts `--allow-errors` for a semantic error already in the books". The
missing attachment is already in the books. Adding the missing file is also
the natural repair for the reverse case and should take effect at once.

Cause: Beancount keys the cache on the include filenames with their sizes
and times, while its documents step checks attachment existence during the
load. Every engine read trusts the cache through
`cli/src/bea_engine/managed_load.py:459-481` (`_load_fresh`). The lockout
is bea's own: `cli/src/bea_engine/ledger/write.py:638` / `:645` load the
staged candidate fresh, while `:655` builds the `--allow-errors`
"before" set from the cached load of the real file, so the fresh error counts
as newly introduced.

Fix: in `_load_fresh`, on a cache hit, re-check the existence of each
cached `Document` entry's file (and each cached "File does not exist"
error) and reload when any disagrees; or do not serve the cache for a ledger
with `document` directives or a `documents` option. Do it with w5/111,
which changes the same function. No dependency or API change.

Blast radius: every `managed_load.load_file` caller and native
`bean-check`. A ledger must be slow enough to be cached, which is where
attachment-heavy multi-year books sit.

Dedupe: board search for picklecache, load cache and "File does not exist"
finds w5/111 (plugin state in the cache), w1/083 (new glob members), w3/351,
w4/180 and w1/044 (document paths and export) and w5/079, 081, 096 (other
`--allow-errors` refusals); none covers attachment existence.

Acceptance: on the fixture, removing the attachment makes the next `check`
exit 1 and `add … --allow-errors` exit 0; restoring it makes `check` exit
0 without touching a ledger file; a ledger without documents still reads from
the cache. A regression test uses a ledger slow enough to be cached. Only
macOS and the checkout were exercised.
