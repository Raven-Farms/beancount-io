# A damaged managed engine still gives raw Python tracebacks with no remedy from text `bea check`, `bea doctor` and `bea example`, and `engine enable` reports success into it, or blames the feature (incomplete fix of w5/320)

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-17, HEAD `46d7394e9`, `bea 0.3.1` installed from a freshly built wheel with isolated data directories, macOS 26.5.1 (hunter's runs, twice; code path checked).
USAGE (and the w5/320 resolution) says a damaged engine is reported by `engine
status`, and "every local command exits 1 naming the engine directory —
remove it and rerun". No product fix implemented.

Damage: after a first-use provision, delete
`<data>/bea/engine/0.3.1/lib/python3.12/site-packages/beancount/parser/_parser*.so`.

- `bea engine status` correctly says `Provisioned: damaged … Remove <root> and
  rerun`.
- `bea check`, `bea check -v`, `doctor roundtrip`, `doctor lex` and `doctor
  context` exit 1 with a full traceback ending `ImportError: cannot import name
  '_parser' from 'beancount.parser'`, and no directory or remedy.
- `bea example` exits 1 with `bean-example failed (exit 1): ImportError: …`.
- `bea engine enable beanprice` exits 0 with `Engine feature 'beanprice'
  ready.` and records the feature in the broken engine.
- `bea engine enable beangulp` exits 1 with `… installed but its packages are
  not importable.`, which blames the feature.

Control: `balance`, `report`, `format`, `--json check` and `list` print the
damaged-engine message.

Expected: every one of these exits 1 with the damaged-engine message.

Cause:
- Text `check` swallows the helper's damaged-engine error as `portable`
  (`cli/src/cli/commands/check.py`, around `:97-104`), then bean-check's crash
  exit drops it.
- `run_native`/`capture_native` never run `engine_load_failure`.
- `enable_feature` (`cli/src/cli/engine/provision.py:171`) never probes the
  base.

Fix: probe the managed engine (as `_refuse_unusable_engine` does) before
native runs, or when one fails, and in `enable_feature`.

Dedupe: w5/320 (done) is the parent; w5/724 (open) covers a false "damaged"
under `PYTHONIOENCODING`.

Acceptance: each command above prints the damaged-engine message. Tests pin
`check` and `engine enable`.
