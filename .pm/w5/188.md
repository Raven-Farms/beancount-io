# The five-second price-feed fetch limit does not cover response headers

**Minor · cli · 45m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A feed that sends its status line and then trickles headers holds every
command for as long as it keeps trickling, then reports "timed out after
5 seconds". The limit is enforced per socket read and on the body, not
on the whole exchange. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Assets:Coin BTC
2024-01-01 open Equity:Opening
2024-01-01 commodity BTC
2024-01-01 commodity USD

2024-01-02 * "Open"
  Assets:Cash  10000.00 USD
  Equity:Opening

2024-01-03 * "Buy"
  Assets:Coin  2 BTC {1000.00 USD}
  Assets:Cash  -2000.00 USD
```

followed by `include "http://127.0.0.1:PORT/prices/HD"`.

The feed is a **simulation**: a loopback server on `127.0.0.1` allowed
through `MANAGED_PRICE_ORIGINS`, which proves local handling only, not the
real service's behaviour. Use isolated BEA_CONFIG_DIR and a fresh
XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no inherited BEA_FILE/BEA_TOKEN,
closed stdin, no TTY, cwd `/absolute/books`. The simulated feed sends `HTTP/1.0 200 OK`, then one `X-Pad-N: x`
header every 3 seconds for five headers, then a valid one-price body.

```sh
bea -f main.bean check
```

Actual: exit 1 after 15.2 seconds, with `fetch failed (timeout): timed
out after 5 seconds`.

Control (worker observation, simulation): a feed that sends nothing for 8
seconds fails in 5.2 seconds, as does a body trickle. The worker measured
30 seconds for ten header lines and 60 seconds for twenty.

Expected: the code describes the limit as "The whole-exchange fetch
budget, mirroring the hosted five-second timeout", and w1/078 (done)
fixed the body half. The whole fetch should end near five seconds, and
the message should not understate the wait.

Cause: `cli/src/bea_engine/managed_prices.py:284-286` computes a deadline
but passes only a per-read socket timeout to the opener; the deadline is
first checked when reading the body.

Fix: bound the whole exchange with one wall-clock deadline (shrink the
socket timeout to the remaining budget per read, or run the fetch under a
joined worker) and report the real elapsed time. No dependency change.

Blast radius: every load of a ledger with a managed include, per feed.

Dedupe: w1/078 (done) covers body trickle only; board search for header
trickle finds nothing.

Acceptance: the command fails in about five seconds with the header
trickle; the fast-feed path is unchanged. Only macOS, the checkout and a
loopback simulation were exercised.
