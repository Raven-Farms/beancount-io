# `report -a Assets:OldCard -t 2025` for an account closed before the period prints a blank report, no "No accounts match" note, and JSON says `account_filter_empty: false`

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-16, HEAD `e03cf71e`, checkout `bea 0.3.1`, macOS 26.5.1. Sibling of w1/126.
`bea balance` and `report -a Assets:Nope` print the note and JSON `true`.
For an account that existed but was closed before the period, the report
prints only its three heading lines. A script reads `false` with all five
trees null. No product fix implemented.

`closed.bean`:

```beancount
option "operating_currency" "USD"

2024-01-01 open Assets:OldCard USD
2024-01-01 open Assets:Bank USD
2024-01-01 open Equity:Opening-Balances

2024-01-01 * "Opening"
  Assets:OldCard 100.00 USD
  Equity:Opening-Balances

2024-06-01 * "Move"
  Assets:Bank 100.00 USD
  Assets:OldCard

2024-06-02 close Assets:OldCard

2025-02-01 * "Interest"
  Assets:Bank 1.00 USD
  Equity:Opening-Balances
```

```sh
bea -f /abs/closed.bean report trial-balance -t 2025 -a Assets:OldCard
bea -f /abs/closed.bean --json report trial-balance -t 2025 -a Assets:OldCard
```

Actual: exit 0, text is the heading only; JSON `account_filter_empty: false`.
An account named only in a `custom "budget"` directive behaves the same.

Control: `report … -a Assets:Nope` prints `No accounts match Assets:Nope.`
and JSON `true`; `bea balance oldcard -t 2025` prints the note.

Expected: the note and `true`.

Cause: `cli/src/bea_engine/report.py:578` computes `bool(filtered.account)
and not filtered.entries`; the clamp's summary entries keep `entries`
non-empty.

Fix: judge emptiness from the pruned five-root tree (no account left).

Dedupe: w1/126 (done) fixed `balance`; w3/379, w5/341 and 445 are other
filter notes.

Acceptance: both commands report the empty filter. A test pins it.
