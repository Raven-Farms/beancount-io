# Stored queries after w5/559: `.run *` stops at the first stored query whose directive date closes its window, without naming it, and loses every other answer; and a stored `OPEN ON D CLOSE` is told "drop CLOSE: … already runs to the end of the ledger", which drops rows (incomplete fix of w5/559)

**Minor · cli · 15m · A1.** Real CLI QA, 2026-10-17, HEAD `a513b1113`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/559 (done, `0f19964c3`).
USAGE:762-763 says "`.run *` skips it with a line on stderr and answers the
rest". The code comment there says "One placeholder must not stop every other
stored query answering". No product fix implemented.

1. **`.run *`.** `sq3.bean` opens `Assets:Cash`, `Expenses:Food` and
   `Equity:Opening`, with an opening, a 2026-01-10 Lunch and a 2026-01-20
   Dinner. It has three stored queries dated 2026-01-15:
   - `a-ok`: `SELECT date, narration WHERE account = 'Expenses:Food'`
   - `b-zero`: the same `FROM OPEN ON 2026-01-15`
   - `c-ok`: the same `FROM OPEN ON 2026-01-05`

   `bea --file /abs/sq3.bean query ".run *"` exits 2 with empty stdout and
   only `This stored query's window covers no days: its query directive's
   date, 2026-01-15, closes the window (exclusive), and OPEN ON starts on that
   same day.` It never names `b-zero`, and `a-ok`/`c-ok` are not answered.
   With `-o`, the file is untouched. Before `0f19964c3` the command exited 0
   with both tables (hunter's run on the pre-fix tree).
2. **Bare `CLOSE` advice.** `bc.bean` has the same entries and two stored
   queries dated 2026-01-15:
   - `food-bare`: `… FROM OPEN ON 2026-01-05 CLOSE WHERE account =
     'Expenses:Food'`
   - `food-open`: the same without `CLOSE`

   `.run food-bare` exits 2 and advises `Or drop CLOSE: FROM OPEN ON
   2026-01-05 alone already runs to the end of the ledger.`. Following it,
   `.run food-open` exits 0 with only Lunch: Dinner (2026-01-20) is dropped,
   because a stored query's open window closes at its directive date. With
   `OPEN ON` on or after the directive date, the advice leads straight to the
   empty-window refusal.

Expected: (1) `.run *` skips `b-zero` with a stderr line naming it and
answers the rest; `.run b-zero` names it. (2) The bare-`CLOSE` advice for a
stored query says the window closes at the directive date, and suggests
`CLOSE ON <date>` or re-dating the directive.

Cause: `_run_stored`'s `*` loop (`cli/src/bea_engine/query.py:690`) lets the
new `_refuse_empty_window(..., stored_on=...)` refusal (`:2031`) escape, and
the message has no name. `_refuse_window`'s bare-CLOSE text (`:2061-2079`) has
no stored variant.

Fix: name the stored query in the refusal and skip it under `.run *`, and
pass the directive date into the bare-CLOSE branch.

Dedupe: w5/559 and 276 (done) are the parents; w5/177 and w3/398 cover
one-shot windows.

Acceptance: `.run *` on `sq3` prints `a-ok` and `c-ok` plus a named skip
line; `food-bare`'s advice keeps Dinner. Tests pin both.
