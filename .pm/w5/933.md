# Do not count a forecast overlay as a second independent root

**Minor · cli · 30–45m · A1.** A split ledger has one working root and a
forecast view that includes it. Naming the included file for an add or import
incorrectly refuses with two-root ambiguity. The error even suggests the
forecast view as the root to select. Explicitly selecting the working root
and `--into` succeeds. No product fix implemented.

Real CLI QA, 2026-10-21, HEAD `ea8bb9c94` (CLI unchanged after pulling
`2e12638c6`), checkout `bea 0.3.1`, macOS 26.5.1 arm64, frontend Python
3.13.3, existing managed Python 3.12.10. Separate subprocesses, closed
stdin/no TTY, isolated absolute `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`,
`BEA_NO_UPDATE_NOTIFIER=1`, no inherited `BEA_FILE`/`BEA_TOKEN`.

Create disposable `/abs/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
2024-01-01 open Equity:Opening USD
2024-01-02 * "Opening"
  Assets:Cash 1000.00 USD
  Equity:Opening -1000.00 USD
include "entries.bean"
```

`/abs/books/entries.bean`:

```beancount
2024-01-03 * "Old milk"
  Assets:Cash -3.25 USD
  Expenses:Food 3.25 USD
```

`/abs/books/forecast.bean`:

```beancount
option "operating_currency" "USD"
include "main.bean"
2024-03-01 * "Forecast only"
  Assets:Cash -7.00 USD
  Expenses:Food 7.00 USD
```

`/abs/books/bank.csv`:

```csv
Date,Description,Amount,Reference
2024-02-01,Coffee,-4.50,coffee-1
```

From `/abs/books`, with the isolated child environment above:

```sh
bea --json -f /abs/books/main.bean check
bea --json --no-input -f /abs/books/entries.bean import /abs/books/bank.csv --csv date=Date,narration=Description,amount=Amount,id=Reference --account Assets:Cash --default-account Expenses:Food
bea --json --no-input -f /abs/books/entries.bean import /abs/books/bank.csv --csv date=Date,narration=Description,amount=Amount,id=Reference --account Assets:Cash --default-account Expenses:Food --apply
bea --json -f /abs/books/entries.bean add note --date 2024-02-02 --account Assets:Cash --comment "Reviewed statement"
bea --json --no-input -f /abs/books/main.bean import /abs/books/bank.csv --csv date=Date,narration=Description,amount=Amount,id=Reference --account Assets:Cash --default-account Expenses:Food --into entries.bean --apply
bea --json -f /abs/books/main.bean query "SELECT account,sum(number) GROUP BY account ORDER BY account"
bea --json -f /abs/books/main.bean check
```

Actual exits: **0, 2, 2, 2, 0, 0, 0**. Both import forms and the note leave
all files unchanged and return empty stdout with this usage message on stderr:

```text
entries.bean is included by more than one root ledger: /abs/books/forecast.bean, /abs/books/main.bean. Say which ledger to check the write against: bea --file /abs/books/forecast.bean <command> --into entries.bean.
```

The explicit working-root import writes 1; fresh query returns Cash
992.25 USD, Food 7.75 USD and Opening -1,000 USD, and check passes.
The root, forecast and CSV remain byte-identical. Expected: the leaf uses
`main.bean`, as documented, without counting its forecast view as another
independent root or suggesting that view in the error.

Twelve fresh journeys, twice across six profiles: no overlay, ordinary `*`
overlay, `!` overlay, `!` overlay mentioning `entries.bean` only in a comment,
a pass-through include under a `*` overlay, and two genuinely independent
roots sharing the leaf. The `*`, comment and pass-through overlays all cause
false ambiguity in preview, apply and note. No overlay and a `!` overlay
without the comment route correctly; adding the comment alone causes refusal.
Genuine independent roots correctly refuse and must keep doing so. Explicit
root recovery works in every profile, repeat import writes 0, all root checks
pass and non-destination/source bytes are preserved. An initial deeper,
three-directory fixture reproduced the same false ambiguity before this matrix.

Cause: `cli/src/bea_engine/ledger/write.py:_scan_includers` (:1945–1999)
returns include-closure ancestors, not just immediate includers. Its cheap
name/glob prefilter admits `forecast.bean` because its transaction's `*`
also passes the glob-character check; the leaf name in a comment admits it
too. `write_through_root` (:2168–2183) starts `defining_root` separately from
each result. Starting directly at the forecast compares its whole closure
against the leaf, so `_defines_in` sees the working root's opens and counts
the forecast as a defining root. This skips the intermediate working root
where the overlay-stop rule would have applied. The real root and forecast
then become two distinct `tops`, triggering the ambiguity refusal.

Fix: resolve the include ancestry through its intermediate defining roots
before counting independent roots, so an overlay that defines nothing for
the working ledger does not become a separate alternative for its leaf.
Keep the stop below forecast/Fava overlays, pass-through climbing, explicit
root/`--into` behavior and genuine independent-root refusal. Do not remove
the ambiguity check or pick the first candidate. Shared helper callers are
engine `add`, `root` (frontend import-memory lookup), `append` and `import`
in `cli/src/bea_engine/main.py` (:286, :339, :381, :579). Runtime coverage is
add note and CSV import; other adds/raw append are source-traced only.
No dependency or backend/API change needed.

Dedupe: searched every board state for overlay/root ambiguity, transitive
