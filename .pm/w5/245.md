# `bea query -f csv` piped or redirected silently strips escape sequences from the data, while `-o FILE` keeps them and a terminal receives them raw

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
One-shot CSV and beancount-format query output is written through a
helper that removes ANSI sequences when stdout is not a terminal. So
`bea query -f csv … > out.csv` and `bea query -f csv … -o out.csv` give
different bytes for the same rows, and on a terminal the raw sequences are
passed through. Only ledgers that already hold raw ESC bytes are affected.
No product fix implemented.

Generate `/absolute/books/main.bean` (`E` is the byte 0x1b):

```python
E = "\x1b"
open("main.bean", "w").write(f'option "operating_currency" "USD"\n2026-01-01 open Assets:Checking USD\n2026-01-01 open Expenses:Food USD\n2026-01-04 * "ACME{E}[1mCORP{E}[0m" "ref{E}[2K7"\n  Expenses:Food  10.00 USD\n  Assets:Checking\n')
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN/CI/COLUMNS, `TERM=xterm-256color`, closed
stdin unless a PTY is stated, cwd `/absolute/books`.

```sh
bea -f main.bean query -f csv "SELECT payee, narration WHERE account ~ 'Food'" | cat -v
bea -f main.bean query -f csv -o o.csv "SELECT payee, narration WHERE account ~ 'Food'"
```

Actual: all exit 0.

| destination | bytes |
| --- | --- |
| pipe | `payee,narration` / `ACMECORP,ref7` |
| `-o o.csv` | `payee,narration` / `ACME<ESC>[1mCORP<ESC>[0m,ref<ESC>[2K7` |
| PTY | three raw ESC bytes sent to the terminal |

Control: the text format prints `ACME\x1b[1mCORP\x1b[0m  ref\x1b[2K7`
identically everywhere. A worker saw `--json` keep the exact value and
`-f beancount` behave like CSV.

Expected: `docs/USAGE.md`: "CSV cells hold the ledger's values verbatim, as
`bean-query` writes them". Redirecting and `-o` should produce the same
bytes, and a terminal should not receive raw escapes.

Cause: `cli/src/cli/commands/query.py:346` uses `typer.echo`, which strips
ANSI sequences on a non-terminal stream and passes them through on a
terminal; `-o` uses the engine's own writer.

Fix: write CSV and beancount output with a plain stream write so nothing
is stripped; when stdout is a terminal, show control characters as `\xNN`
as the text format does. No dependency or API change.

Blast radius: one-shot `query` in CSV and beancount formats, including
`PRINT`.

Dedupe: board search for `strip_ansi`, "verbatim" and CSI finds
w4/done/173 (text tables; mentions the stripping only as a testing
caveat) and w3/done/392; nothing covers the export divergence. w5/225 and
w5/230 are other CSV/PRINT fidelity items.

Acceptance: the piped output is byte-identical to `o.csv`; on a PTY no raw
ESC byte is emitted. Only macOS and the checkout were exercised.
