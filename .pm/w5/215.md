# An unreadable `importers/` directory fails every `bea import` with a raw `[Errno 13]`, even when all settings are on the command line

**Minor · cli · 20m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
When the import-memory directory under the config directory cannot be read
(wrong modes after a restore, or left root-owned by a privileged run), every
import stops with a bare Python `[Errno 13]` message, category `validation`,
exit 1. That includes a command that spells out every setting and needs no
memory. A read-only directory already degrades to a note. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Uncategorized USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "Open" "Opening balance"
  Assets:Checking  5000.00 USD
  Equity:Opening
```

`/absolute/books/checking.csv`:

```csv
Date,Description,Amount
2026-02-02,Grocer,-20.00
2026-02-03,Cafe,-4.50
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean import checking.csv --account Assets:Checking      # preview; creates $BEA_CONFIG_DIR/importers
chmod 000 "$BEA_CONFIG_DIR/importers"
bea -f main.bean import checking.csv --csv date=Date,amount=Amount,narration=Description --account Assets:Checking --apply
bea --json -f main.bean import checking.csv --account Assets:Checking
```

Actual: both later commands exit 1 and write nothing.

```text
Using column mapping (--csv).
Error: [Errno 13] Permission denied: '/absolute/config/importers/csv-43fe…22cd.json'
```

JSON: `{"error": {"category": "validation", "message": "[Errno 13]
Permission denied: '…'", "exit_code": 1}}`.

Control: with the directory at mode 555 the same `--apply` exits 0 and
writes both rows (a worker saw the note `Could not remember the column
mapping: … Pass --csv on the next import.`). With the directory at 000,
`bea check` still exits 0; a worker saw `list`, `balance`, `add` and
`format` unaffected too, and the same raw error when the whole config
directory is 000.

Expected: `docs/USAGE.md` gives exit 3 (`auth`) to "Authentication or
permission failure", and the code's own contract for this record
(`cli/src/cli/commands/import_.py:140-148`) is that "stale local state never
blocks an import". An import whose settings are all given should proceed
with a note; one that needs memory should name the directory and the
remedy.

Cause: `Path.is_file()` raises on `EACCES`, and it is called unguarded in
`_config_available` (`import_.py:38`), `_find_csv_entry` (`:176`) and
`_recall_csv` (`:198`); the `OSError` reaches the generic handler.

Fix: treat any `OSError` while probing or reading either memory record as
"no memory", with a stderr note naming the path. No dependency or API
change.

Blast radius: `bea import` only.

Dedupe: board search for `Errno 13` and `Permission denied` with import
finds w5/113 (lock directory under the cache home, for `add`/`format -i`),
w5/141 (dangling remembered importer path) and w1/done/105 (corrupt record
raising `TypeError`); none covers an unreadable memory directory.

Acceptance: with `importers/` at mode 000, the fully specified `--apply`
exits 0, writes both rows and notes that memory could not be read; the
flag-light preview either proceeds the same way or exits 3 naming the
directory; no `[Errno` text appears. Only macOS and the checkout were
exercised.
