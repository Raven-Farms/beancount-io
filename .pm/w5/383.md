# The duplicate-entry summary prints amounts in scientific notation: `(Assets:Cash 5.0E-7 BTC; Equity:Opening -5.0E-7 BTC)` for a ledger that says `0.00000050 BTC`

**Trivial · cli · 5–10m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12.
[w5/228](./done/228.md) changed import rows to fixed-point notation, and
its resolution names this gap: "The same `str(Decimal)` interpolation in
the duplicate-entry summary in … query.py was left alone". No product
fix implemented.

Use a ledger with `plugin "beancount.plugins.noduplicates"` and two
identical transactions posting `0.00000050 BTC` from `Equity:Opening` to
`Assets:Cash`, with the environment from [381](./381.md).

```sh
bea --json -f /absolute/books/main.bean list transaction
```

Actual: exit 1. The details read `main.bean:17: Duplicate transaction on
2026-01-02 "tiny" (Assets:Cash 5.0E-7 BTC; Equity:Opening -5.0E-7 BTC);
first entered at …:14.`. `bea --json check` uses the same formatter.
Reproduced twice by the hunter and once by me.

Control: the import preview prints `-0.00000050 BTC` since w5/228.

Expected: numbers in error output are written in fixed-point notation,
which is the rule w5/228 applied to import.

Cause: `_entry_summary` (`cli/src/bea_engine/query.py:1855-1876`)
formats `f"{posting.account} {units.number} {units.currency}"`.

Fix: use `format(units.number, "f")`. No dependency change.

Blast radius: duplicate-entry errors in read refusals and `check --json`
details, for small or large amounts.

Dedupe: w5/228 names the gap but filed nothing, and w3/302 introduced the
summary. No open note covers it.

Acceptance: the summary shows `0.00000050 BTC` and `-0.00000050 BTC`. A
test pins it.
