# Give a complete direction-column repair when `sign=ledger` is already active

**Trivial · cli · 15–20m · A1.** Real CLI QA, 2026-10-21, checkout
`bea 0.3.1`, HEAD `a59e51768` (CLI unchanged from reproduction at
`c2a3c7866`), macOS 26.5.1 arm64, frontend Python 3.13.3. This is a
**diagnostic-only** follow-up to [755](./done/755.md): preserve its refusal
of an unmapped direction column. Its proposed repair currently fails when
the active mapping already contains `sign=ledger`. No product fix implemented.

Disposable `/abs/case/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
```

`/abs/case/bank.csv`:

```csv
Date,Description,Amount,Type
2024-02-01,Coffee,4.50,DEBIT
```

Cwd `/abs/case`, isolated absolute `BEA_CONFIG_DIR` and `XDG_CACHE_HOME`,
`BEA_NO_UPDATE_NOTIFIER=1`, inherited `BEA_FILE`/`BEA_TOKEN` removed,
closed stdin and no TTY:

```sh
bea --json --no-input -f /abs/case/main.bean import /abs/case/bank.csv --account Assets:Cash --default-account Expenses:Food --csv date=Date,narration=Description,amount=Amount,sign=ledger
```

Actual: exit 2, usage, ledger byte-identical. The error says the column's
values are DEBIT/CREDIT words, the amounts carry no sign, and
`every debit would book as money in`. It then says:

```text
Add direction=Type to the --csv mapping (DEBIT/CREDIT, D/C, Dr/Cr, Af/Bij).
```

Follow that instruction by adding `,direction=Type` to the supplied mapping.
It immediately exits 2, usage, without changing the ledger:

```text
--csv direction=Column already decides each row's direction; drop sign=ledger.
```

The complete repair is to **replace** `sign=ledger` with `direction=Type`:

```sh
bea --json --no-input -f /abs/case/main.bean import /abs/case/bank.csv --account Assets:Cash --default-account Expenses:Food --csv date=Date,narration=Description,amount=Amount,direction=Type --apply
```

This exits 0, writes one row, and a fresh BQL read shows `Assets:Cash
-4.50 USD`; fresh `check` exits 0. Both refusals and the repair reproduce
twice in JSON and human output, from fresh ledgers.

Expected: the first refusal supplies a repair that can run directly. When
`sign=ledger` is active, say to replace it with `direction=Type`, rather than
adding a mutually exclusive option. Avoid the money-in prediction in this
branch: a nearby control with the same positive amount and explicit
`sign=ledger`, but no Type column, correctly writes `-4.50 USD`, not money in.
The refusal policy itself is documented in `cli/docs/IMPORTING.md` and
remains unchanged.

Cause: `_refuse_unmapped_direction`
(`cli/src/bea_engine/csv_mapper.py:406–433`) receives only the mapped columns
and always emits the bank-sign explanation and append instruction. Its
caller (`:1682`) has `self._mapping.sign` available but does not pass that
context. The frontend (`cli/src/cli/csv_mapper.py:244`) and engine
(`bea_engine/csv_mapper.py:608`) correctly reject the incompatible pair.
The fix belongs in the guard's context-aware message, not in weakening
those parsers or accepting a mapping the guard currently refuses.

Controls, repeated twice: without `sign=ledger`, adding `direction=Type`
works as the original hint says; a ledger-signed file containing positive
DEBIT `4.50` and negative CREDIT `-10.00` already imports the expected
`-4.50/+10.00`; removing the Type column leaves explicit sign inversion
working. Every resulting ledger passes a fresh check, and both refusal
steps preserve the ledger bytes.
