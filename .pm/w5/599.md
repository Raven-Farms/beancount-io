# A monthly autopay that reuses one bank reference is silently skipped as an "exact duplicate" when the months arrive as separate exports, though IMPORTING.md uses this exact case as "never a silent skip" (gap in w5/075)

**Major · cli · 20–30m · A1.** Real CLI QA, 2026-10-16, HEAD `5e09bcc4`, checkout `bea 0.3.1`, macOS 26.5.1.
IMPORTING.md (around line 446): "a monthly autopay reusing one reference" is
"a possible duplicate …, never a silent skip". w5/075 implemented that only
within one export ("Matches against ledger entries are unchanged"). Monthly
exports are how an autopay normally arrives. February's rent is then
dropped with exit 0, and nothing is reported. No product fix implemented.

`main.bean`:

```beancount
option "operating_currency" "USD"

2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Uncategorized
2026-01-01 open Equity:Opening

2026-01-02 * "Opening balance"
  Assets:Checking  1000.00 USD
  Equity:Opening
```

`jan.csv`: `Date,Description,Amount,Reference Number` /
`2026-01-01,Rent January,-1200.00,RENT-AUTOPAY`. `feb.csv`: same header,
`2026-02-01,Rent February,-1200.00,RENT-AUTOPAY`.

```sh
bea --file /abs/main.bean import jan.csv --account Assets:Checking --apply
bea --file /abs/main.bean import feb.csv --account Assets:Checking --apply
bea --file /abs/main.bean balance Assets:Checking
```

Actual: the second exits 0 with `0 ready, 1 exact duplicates`, `Row 1:
import-id bank:RENT-AUTOPAY is already in the ledger.`, and writes nothing;
Checking shows `-200.00 USD`.

Control: both rows in one file give `Row 2 (possible_duplicate): Stable ID
bank:RENT-AUTOPAY repeats row 1 of this import on a different date` (exit 4).

Expected: 1000 − 1200 − 1200 = −1,400.00 USD after review: a native-ID hit on
a ledger entry with a different date is a `possible_duplicate` naming that
entry, as within one file.

Cause: the w5/075 path (`cli/src/bea_engine/importing.py:427-443`) applies only
when the match is in the batch; a ledger hit falls through `_same_row`
(`:1062-1063`, equal amounts, any date) to `duplicate` (`:426`).

Fix: treat a different-date native-ID hit on a ledger entry like an in-batch
one. Whether a date edited in the ledger should still match is a product
call; note it in the fix.

Dedupe: searched `autopay`, `different date`; w5/075 (done) excluded this
path.

Acceptance: the February import reports the possible duplicate (exit 4, or
writes with `--duplicates include`). A test pins it.
