# An explicit `--csv` re-run silently forgets a remembered `--date-format`, and the next ambiguous export is booked month-first

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-12, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A day-first bank export is imported once with `--date-format %d/%m/%Y`. A
second explicit `--csv` run without the flag, on a file whose dates happen
to be unambiguous, erases the remembered format without naming it. The
third, flag-free import of a file with only low day numbers is then read
month-first: 4 October is written as 10 April, exit 0, with only the
generic ambiguity note. No product fix implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Assets:Euro EUR
2026-01-01 open Expenses:Uncategorized
```

`/absolute/books/aug.csv`:

```csv
Date,Description,Amount
02/08/2026,Coffee,-4.50
03/08/2026,Tea,-2.00
```

`/absolute/books/sep.csv`:

```csv
Date,Description,Amount
13/09/2026,Lunch,-9.00
```

`/absolute/books/oct.csv`:

```csv
Date,Description,Amount
04/10/2026,Bus,-2.50
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME (fresh), BEA_NO_UPDATE_NOTIFIER=1,
no inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, cwd `/absolute/books`.

```sh
bea -f main.bean import aug.csv --csv date=Date,amount=Amount,narration=Description --account Assets:Checking --date-format %d/%m/%Y --apply
bea -f main.bean import sep.csv --csv date=Date,amount=Amount,narration=Description --account Assets:Checking --apply
bea -f main.bean import oct.csv --apply
```

Actual: all exit 0. The second run's only note is `Using column mapping
(--csv).` The third prints `Using settings remembered from sep.csv for
oct.csv: … --date-format %m/%d/%Y …` and the generic "day-first and
month-first cannot be told apart" note, and writes `2026-04-10 ! "Bus"`.
The ledger now holds Coffee on 2026-08-02, Lunch on 2026-09-13 and Bus on
2026-04-10.

Control: a worker ran the second explicit command on the ambiguous
`oct.csv` instead; stderr then says `Discarded remembered settings for
oct.csv: --date-format %d/%m/%Y. Re-pass them to keep them across
refreshes.`

Expected: `docs/IMPORTING.md`: "A successful explicit `--csv` preview or
apply replaces the remembered settings; settings it drops are named, never
silently discarded."

Cause: `cli/src/cli/commands/import_.py:616-621` names the dropped format
only when it differs from the format inferred for the current file, while
`:634` stores the run's own (absent) choice regardless. When the current
file infers the same format, the explicit setting is erased unannounced.

Fix: name a remembered explicit `--date-format` whenever the refreshing
run did not pass one, or keep it when the file's inferred format agrees.
No dependency or API change.

Blast radius: remembered `date_format` only (`--rules` is always named).
Same family as w5/073.

Dedupe: board search for "Discarded remembered" and date-format with
dropped/forgot finds w3/done/425 (a failed preview replacing memory) and
w5/073 (typed options on a remembered run not saved); neither covers an
explicit refresh erasing the format silently.

Acceptance: the second command either keeps `%d/%m/%Y` or names it as
discarded; in the first case the third command writes `2026-10-04`. Only
macOS and the checkout were exercised.
