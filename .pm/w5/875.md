# `init --preset --title` deletes quotes and interprets backslashes as escapes, changing the saved title or refusing an otherwise valid title

**Minor · cli · 20–30m · A1/A2.** Real CLI QA, 2026-10-20, checkout
`bea 0.3.1`, HEAD `4c01ed572`, Darwin 25.5.0 arm64; frontend Python 3.13.3.
No product fix implemented.

In a disposable `/abs/case`, use isolated absolute
`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, no inherited
`BEA_FILE`/`BEA_TOKEN`, and closed stdin/no TTY. Each target below must be new:

```sh
bea --json init /abs/case/quoted --preset personal@1 --currency USD --date 2024-02-01 --title 'Family "A" ledger'
bea doctor print-options /abs/case/quoted/main.bean
bea --json init /abs/case/slashes --preset personal@1 --currency USD --date 2024-02-01 --title 'C:\new\test'
bea doctor print-options /abs/case/slashes/main.bean
bea --json init /abs/case/trailing --preset personal@1 --currency USD --date 2024-02-01 --title 'Family\'
```

Actual:

- Quoted title: init exits 0 and writes `option "title" "Family A ledger"`;
  doctor confirms `title: Family A ledger`. The two requested quotes vanish.
- Backslashes: init exits 0 and writes the unescaped source
  `option "title" "C:\new\test"`. The loaded title is `C:` followed by a
  newline and `ew`, then a tab and `est`; doctor prints that changed value.
- Trailing backslash: init exits 1, validation category,
  `Invalid token: 'operating_currency"'` at proposed line 2. It creates no
  ledger. The title's backslash escaped the line-1 closing quote.

All cases reproduced in two fresh directory sequences. Successful ledgers
pass `bea --json --file FILE check`, which does not detect the changed title.
Control: a manual synthetic ledger with properly escaped option strings
loads all three original titles unchanged through `doctor print-options`;
these are valid Beancount titles, not unsupported characters.

Expected: the title loaded from the created file equals the supplied title.
ADR021's Title and address section calls it unrestricted and any-script;
its setup rules say explicit values are never silently replaced. Quotes and
backslashes must be escaped as string content, preserving their values.

Cause: `cli/src/bea_engine/initiating.py:232` builds the title option using
`(title or entry["title"]).replace(chr(34), "")`: it deliberately removes
double quotes and interpolates every other character without Beancount
string escaping. `answer_preset` is the sole caller of this new title path,
reached by `bea init --preset`; legacy init has a fixed title. Existing
ledger-writing string escaping is available within the engine.

Fix: encode the title with the same Beancount string-value rules as the
other engine writers. Test the parsed option value after a real init and
fresh read, including embedded quotes, ordinary/backslash escape sequences,
a trailing backslash and a non-ASCII control. Retain atomic creation and the
no-overwrite behavior.

Dedupe: searched all board states for init/preset title escaping and
backslashes, and reviewed open/blocked milestone scopes. Completed
w3/m53/t004 introduced this path in `1ba20bffa`; targeted
`git log -S 'title or entry'` finds that introduction with no title repair.
w3/m54 owns staged web/native creation, not this local serializer. No
overlapping open finding or deployment lag found.

Acceptance: all three commands create valid files whose parsed titles match
their arguments exactly, without new dependencies or a backend/API change.
Windows/Linux, hosted creation and repaired behavior remain unverified.

`.tmp/qa-2026-10-20-cli-loop-d3c5ebec/`: `captures/s5-{1,2}-title-*.json`
