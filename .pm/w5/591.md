# bea's own cache entries that are not regular files break reads: a directory at the load-cache path crashes `bea check` with a raw traceback, and a FIFO there or in the managed-price cache hangs every read, `--offline` included (gap in w5/417/418)

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-16, HEAD `595daa2f`, checkout `bea 0.3.1`, macOS 26.5.1.
USAGE: a load-cache path that "is not a regular file at all (`/dev/null`, a
FIFO), is refused … instead of being deleted, read or waited on". That guard
(w5/417, 418) runs only when the user sets the cache path. bea's default
private cache files get no such check. Neither do the managed-price cache's
`head.json`, revision blobs and `.effective.*` files. The managed-price
cache's own docstring says a cache problem never fails a lenient load. No
product fix implemented.

Load cache (`$XDG_CACHE_HOME/bea/load-cache/<sha256(dir)[:32]>.main.bean.picklecache`):

```sh
mkdir -p -m700 "$XDG_CACHE_HOME/bea/load-cache/<D>.main.bean.picklecache"
bea -f /abs/main.bean check
bea -f /abs/main.bean balance
```

Actual: `check` exits 1 with bean-check's Python traceback ending
`IsADirectoryError: [Errno 21] Is a directory: '…picklecache'`; `balance`,
`list` and `--json check` exit 1 with `Error: IsADirectoryError: …`. A FIFO
at that path makes `balance` and `--json check` hang.

Managed-price cache: after one `price status` on a ledger with a managed
include, replacing `…/managed-prices/<hash>/head.json` (or a blob, or the
effective file) with a FIFO makes `balance`, `check` and `bea --offline price
status` hang. The engine child stays blocked after the frontend is killed.

Control: `BEANCOUNT_LOAD_CACHE_FILENAME=<fifo>` exits 2 with `which is not a
regular file … Nothing was changed.`; a directory in place of `head.json`
degrades with `warning: price cache not writable (Is a directory)…`.

Expected: non-regular entries in bea's own cache directories are treated as
absent (removed, or bypassed with a note); no traceback, no hang.

Cause: `not_a_load_cache` (`cli/src/bea_engine/ledger/write.py:550`,
`cli/src/cli/output.py:516`) is reached only when the variable is set
(`write.py:584`, `output.py:539` return early); `managed_load.py:576` checks
only `os.path.isfile`; native bean-check gets the same private path
(`cli/src/cli/engine/launch.py:138-161`). `_read_head`/`_read_blob`
(`cli/src/bea_engine/managed_price_cache.py:114`, `:126`) and `_holds`
(`managed_load.py:230`) use plain `read_text()`.

Fix: apply the regular-file check to bea's private cache paths before loading
or passing them on; open managed-cache files non-blocking (or check
`S_ISREG`) and treat non-regular ones as missing.

Dedupe: searched `load-cache` with FIFO, `IsADirectoryError`, `head.json`.
w5/417 and 418 (done) cover user-set paths only.

Acceptance: each fixture's reads answer (with at most a note) and nothing
hangs. Tests pin the directory and FIFO cases.
