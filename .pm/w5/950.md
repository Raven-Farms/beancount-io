# Resolve inferred compound costs before import hashing and comparison

**Major · cli · 45–60m · A1.** Two valid share purchases with different
cash prices receive the same generated import ID when a compound cost has
an inferred component. Importing the second statement silently writes zero,
even with `--duplicates include`: holdings stay **2 instead of 4 HOOL** and
Cash **−10.50 instead of −31.00 USD**. With a bank ID, re-importing the
unchanged first trade instead conflicts with its own prior write. No fix
implemented. This is import comparison, separate from [949](./949.md)'s
JSON round-trip encoder.

Real CLI QA, 2026-10-21, HEAD `2975eddb2`, checkout `bea 0.3.1`, macOS
26.5.1 arm64, frontend Python 3.13.3 and existing managed Python 3.12.10 /
Beancount 3.2.3 with Beangulp already enabled. Fresh processes, closed
stdin/no TTY, isolated absolute `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier
disabled, no inherited `BEA_FILE`/`BEA_TOKEN`. Synthetic local files only.

`/abs/books/importer.py` uses the real native parser:

```python
from pathlib import Path
from beancount.parser import parser
from beancount.core.data import Transaction

USE_BANK_ID = False

class Rows:
    def identify(self, file):
        return str(file).endswith(".trade")
    def account(self, file):
        return "Assets:Broker"
    def extract(self, file, existing=None):
        entries, errors, options = parser.parse_string(Path(str(file)).read_text())
        assert not errors, errors
        rows = [entry for entry in entries if isinstance(entry, Transaction)]
        for entry in rows:
            if USE_BANK_ID:
                entry.meta["bank_id"] = "trade-001"
        return rows

CONFIG = [Rows()]
```

Actual: every command exits 0. A writes one. B previews `duplicate`,
`include: false`, `id_source: hash`, and `amount: "2 HOOL {0.25 USD}"`.
Its reason is `import-id csv:sha256:caf7d9df6f757580 is already in the
ledger.` The displayed incoming entry pays **20.50**, while its matched
entry pays **10.50**. Apply writes zero and preserves the ledger exactly;
the final native check is clean, holdings are 2, and only one transaction
exists. Neither input nor the importer is modified.

Expected: A's native cost is **5.25 USD per share**, B's **10.25 USD**.
These are distinct purchases. Both write one, holdings become 4 and total
cost/Cash are **31.00 / −31.00 USD**. The missing per-unit component is
determined by the explicit cash posting; it is not zero. Independent
fresh ledgers containing each original B transaction also check and query
at the expected cost. No repeating-decimal or invalid-booking issue applies.

Second form: change both cost spellings to `{5 # USD}`, preserving the two
cash amounts. Its inferred totals differ; the same false skip occurs with
`amount: "2 HOOL {5 USD}"` and generated ID
`csv:sha256:009bc6136324025c`. Repeated twice from pristine books.

Bank-ID variant: set `USE_BANK_ID = True` and replace B with **A** in the
preview/apply commands. The first apply writes one, but repeating the exact
same source previews `conflict` and apply exits **4**, unchanged. Its
incoming fictitious 0.25 (or 5) cost disagrees with the booked 5.25 cost.
Both forms reproduce twice. Plain generated-ID repeats of A correctly skip.
Fully specified costs `{5 # 0.50 USD}` in A / `{10 # 0.50 USD}` in B
correctly write both trades and retain 4 HOOL; an unchanged bank-ID trade
with explicit cost correctly skips. These controls also ran twice.

Cause: `cli/src/bea_engine/importing.py:_lot_stated` (:1302–1320) maps
native `MISSING` to None. `_lot` (:1323–1341) then assumes the missing
per-unit component is zero when it divides the known total by units, or
returns the stated per-unit number while omitting an inferred total.
`_lot_text` (:1367) feeds this fictitious cost to `_hash_import_ids`
(:2417–2419) and `_source_amounts` (:2588). A canonical generated-ID hit
takes precedence (:544–551), so distinct cash prices cannot rescue B.
The same `_lot` feeds `_legs` / `_legs_agree` (:1386–1418) and native-ID
comparison, explaining the false conflict on unchanged A. Searches also
find lot-gated legacy lookup, nearest-row and twin matching callers; retain
their constraints and one-to-one behavior when correcting this shared value.

Fix: compare/hash a cost consistent with the valid full incoming transaction
when booking must infer one of its components. Preserve the distinction
between an absent component, a component needing inference and a genuine
zero. Do not fix the conflict by treating every unknown cost as a wildcard:
the distinct cash-priced trades must still remain distinct. Preserve ordinary
fixed per-unit/total/compound costs, exact re-imports, real bank-ID amount
conflicts, partial lot selectors and prior generated-ID compatibility;
older lossy digests must not silently consume another trade. Keep previews
read-only and refused applies atomic. No dependency or backend/API change.

Dedupe: whole-board and active/blocked milestone scans plus targeted `_lot`
history found no open inferred-cost repair. Completed 742
adds **known** compound components, 349/467/603 cover explicit lots and
booked split legs. Open 896 is greedy multi-fill assignment, 897 omits dates,
899 drops retained partial fields from text, and 881 covers source rewrites
by plugins. Here there is one unchanged, non-plugin source leg and the
numeric lot itself is fabricated. 949 concerns a separate JSON encoder;
fixing it alone does not change this importer pipeline.

Acceptance: both inferred forms import A then B as distinct purchases with
4 HOOL, cost/Cash 31.00/−31.00 USD and two entries. Exact repeats skip in
generated-ID and bank-ID modes; real corrections still conflict. Pin both
inference directions, explicit-cost controls, preview/apply file effects and

ID cases and repaired behavior remain unverified.
