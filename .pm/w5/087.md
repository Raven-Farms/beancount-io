# Format reads a symlinked root's includes beside the link target, so `-o` overwrites an included file

**Major · cli · 40–60m · A1.** Real CLI QA, 2026-10-10, HEAD `97600b74`, checkout `bea 0.3.1`, Beancount 3.2.3, macOS. Every other command resolves a symlinked
root ledger's relative includes beside the link, as documented. `bea format`
resolves them beside the file the link points to. Its `--check` and `-i`
then report a present include as missing, and its `-o` guard does not see the
real include, so an export aimed at it replaces it with exit 0. No product fix
implemented.

Create a disposable tree under `/absolute/t`. `store/main-2026.bean`:

```beancount
include "accounts.bean"
2026-01-02 * "x"
  Assets:A  1 USD
  Assets:B  -1 USD
```

`books/main.bean` is a symlink to `../store/main-2026.bean`, and
`books/accounts.bean` is:

```beancount
2026-01-01 open Assets:A
2026-01-01 open Assets:B
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, no
inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY. Cwd `/absolute/t`:

```sh
bea -f books/main.bean check
bea format --check books/main.bean
bea format books/main.bean -o books/accounts.bean
bea -f books/main.bean check
```

Actual: the first `check` exits 0 (as does upstream `bean-check`).
`format --check` exits 1 with `missing include: "accounts.bean" (included
by /absolute/t/store/main-2026.bean)`; `-i` fails the same way and never
formats `books/accounts.bean`. The `-o` command exits 0 and
`books/accounts.bean` now holds the root's text (hash changed). The final
`check` exits 1 with `Duplicate filename parsed`. Repeated twice.

Controls: with regular files in place of the symlink, `format main.bean -o
accounts.bean` exits 2 with `would overwrite the ledger it reads` and
`--check` reports nothing missing. On the symlinked root,
`bea -f books/main.bean query "SELECT account" -o books/accounts.bean` exits
2.

Expected: `docs/USAGE.md` Choosing the ledger — "A root ledger that is a
symlink keeps the path you named… its relative `include` and `--into` paths
resolve beside the link" — and Output destinations — a destination that is
"the root file or anything it includes" is refused, and "nothing gets past the
first". `--check` should scan `books/accounts.bean`; `-o
books/accounts.bean` should exit 2 leaving it byte-identical.

Cause: `cli/src/cli/commands/format.py:393` resolves each named path with
`.resolve()` and uses the resolved target as the closure root (`:422`,
`:431`); the alias guard at `:136-137` walks the closure of that resolved
path. `output._include_matches` (`cli/src/cli/output.py:237`) then looks
beside `source.parent`, which is the target's directory.

Fix: walk the include closure and apply the `-o` alias guard from the
lexical absolute path, as `context.entry_file` does for the other commands;
keep `resolve()` only for the write target, the lock key and deduplication.
No dependency or API change.

Blast radius: every `format` mode given a positional path or `--file`.
`check`, `query -o` and `treeify -o` already use the lexical path. When
run from inside `books/`, the working-directory fallback in w5/071 hides this
bug, so fixing 071 alone would expose it there.

Dedupe: board search for symlinked roots, "beside the link" and missing
includes finds w1/056 (the symlinked root for check, list, query, add, import
and price export — not format), w5/071 (the working-directory fallback) and
w3/329 (outbound symlinks in directory walks).

Acceptance: on the fixture `format --check` and `-i` scan and format
`books/accounts.bean` with nothing missing, `-o books/accounts.bean` exits
2 with the file unchanged, and the regular-file control is unchanged. Only
macOS and the checkout were exercised.
