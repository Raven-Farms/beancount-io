# Five small exit-contract slips: `import --into` a read-only directory blames a nonexistent managed price include, natives killed by a signal say "(exit -11)", group commands without a subcommand return the whole help as the JSON error, `cloud ledger list --limit 0` is not validated, and `price status --json` on an invalid ledger omits `ledger_valid`

**Trivial · cli · 20–30m · A1.** Real CLI QA, 2026-10-17, HEAD `6d74be10`, checkout `bea 0.3.1`, macOS 26.5.1.
No product fix implemented.

1. **Wrong blame.** With `include "txns/*.bean"`, an existing `txns/a.bean` and
   `txns/` at mode 555, `bea import s.csv --account Assets:Checking
   --default-account Expenses:Food --into txns/new.bean` exits 3 (correct)
   with `Cannot read …/main.bean: its managed price include (a managed price
   include) is resolved on a temporary copy…`; the ledger has no URL include.
   `add open --into txns/new.bean` says `Cannot stage a copy of new.bean … not
   writable`. Cause: a not-yet-existing member sends the load down the shadow
   path (`cli/src/bea_engine/managed_load.py:329`), and `_staging_refused`
   (`:880-887`) falls back to the literal phrase.
2. **Signal names.** A `bean-example` or `treeify` killed by SIGSEGV gives
   `bean-example failed (exit -11): No diagnostic was returned.`; other paths
   name `SIGSEGV`. Cause: `check_native` (`cli/src/cli/engine/launch.py:293-322`)
   uses the raw `returncode`, not `captured_status`.
3. **Group without subcommand.** `bea --json add` (also `list`, `report`,
   `cloud`) returns the whole multi-line help as `error.message`, prefixed
   `Usage:`, while `bea --json` alone says `Missing command.` Use a one-line
   `Missing subcommand: choose one of …`.
4. **Unvalidated paging.** `bea cloud ledger list --limit 0`, `--limit -3` and
   `--page 0` are sent to the server unvalidated (signed out, they exit 3
   instead of 2); help says "1-based" and "at most 100". Validate them first
   (sibling of w3/356).
5. **`price status` JSON.** On an invalid ledger, `bea --json price status`
   exits 0, prints raw ledger-error lines on stderr, and the envelope has no
   `ledger_valid`/`ledger_errors`, unlike `list` and `query` (w5/460).

Dedupe: no match for `resolved on a temporary copy` beyond w5/408; w3/356 and
w5/460 (done) are the precedents for 4 and 5.

Acceptance: each item behaves as described. Tests pin items 1, 3 and 4.
