# REFERENCE.md marks `add balance --amount` and `add price --amount` as "str (repeatable)" (a repeat exits 2), and shows `cloud ledger create --private, --public` with default "True" where `--help` says `[default: private]`

**Trivial · cli docs · 10–15m · A1.** Real CLI QA, 2026-10-16, HEAD `d16aea3e`, checkout `bea 0.3.1`, macOS 26.5.1.
REFERENCE.md is generated from the command tree by
`cli/scripts/gen_reference.py`. An agent reading it is told it may repeat an
option that is refused when repeated, and sees a default that is not a value
anyone types. No product fix implemented.

- `cli/docs/REFERENCE.md:513` and `:580`: `| --amount | str (repeatable) |
  required | … (pass once) |`. `bea add price -c EUR --amount '1 USD'
  --amount '2 USD' --date 2026-08-02` exits 2 with `Pass --amount exactly
  once; a price holds one amount (2 given).` The options are `list[str]`
  only so `_single_amount` can count the repeat.
- `cli/docs/REFERENCE.md:1293`: `| --private, --public | flag | True |
  Ledger visibility |`; `bea cloud ledger create --help` shows `[default:
  private]`.

Expected: `str` (not repeatable) for the two `--amount` options, and
`private` as the default.

Cause: `type_label` marks every list-typed option repeatable;
`default_label` prints the raw boolean for a two-name flag
(`cli/scripts/gen_reference.py`).

Fix: let a command mark an option single-valued (or detect the
`_single_amount` pattern), and render a paired flag's default by name.
Regenerate REFERENCE.md.

Dedupe: w5/241 (done) fixed other REFERENCE omissions.

Acceptance: the three rows read as above, and `gen_reference.py --check`
passes. A test of the generator pins both.
