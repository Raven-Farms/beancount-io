# `SELECT account, price ORDER BY price` exits 1 as "validation" with `AttributeError: 'NullType' object has no attribute 'currency'` when an unpriced posting sorts before a priced one

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-16, HEAD `7898f69d`, checkout `bea 0.3.1`, macOS 26.5.1. Upstream `bean-query` crashes too; bea surfaces it raw.
A valid query on a valid ledger fails. The message is a Python class name
reported as a ledger validation failure, and whether it fails depends on
the order of the postings. No product fix implemented.

`ob.bean`:

```beancount
2026-01-01 open Assets:Cash USD
2026-01-01 open Assets:Eur EUR
2026-01-02 * "FX"
  Assets:Cash  -11.00 USD
  Assets:Eur  10.00 EUR @ 1.10 USD
```

```sh
bea --file /abs/ob.bean --json query "SELECT account, price ORDER BY price"
```

Actual: exit 1, `{"error": {"category": "validation", "message":
"AttributeError: 'NullType' object has no attribute 'currency' Pass --debug
…"}}`; text is the same. Swapping the two posting lines makes it succeed.

Control: `ORDER BY account` and `ORDER BY cost_number` (a Decimal column with
NULLs) work.

Expected: the query answers with NULLs sorted first (as for Decimal columns),
or bea refuses with exit 2 and a one-line explanation (ordering by an Amount
column with NULLs is unsupported upstream; order by `number(price)` instead).

Cause: beanquery's sort key wrapper (`query_execute.py`, `nullitemgetter`)
ends up calling `Amount.__lt__` against NULL
(`beancount/core/amount.py`, `sortkey`); bea's `_compiled` re-raises
AttributeErrors other than its known ones.

Fix: a NULL-safe ORDER BY key for Amount/Position values in bea's execution
path, or the exit-2 explanation.

Dedupe: searched `NullType`, `ORDER BY price`. No match. The `--source`
traceback for the same query falls under w5/472.

Acceptance: the command answers (or exits 2 with the explanation) in both
posting orders. A test pins it.
