# Managed-price strict and unavailable messages give the wrong cause: a future observation "is older than 600 seconds", a missing stamp reads "latest observation unknown observation time", and a source with no cache says "cached prices remain usable"

**Trivial · cli · 10m · A1.** Real CLI QA, 2026-10-16, HEAD `c0267f61`, checkout `bea 0.3.1`, macOS 26.5.1. Synthetic local feed server.
No product fix implemented.

1. **Future stamp.** A feed whose `observed-at` is an hour ahead of the clock
   gives `bea --strict-prices -f /abs/main.bean check` → `latest observation
   2026-10-17T06:11:15Z is older than 600 seconds.` USAGE says a stamp more
   than five minutes ahead reads stale (w1/133); the message should say the
   stamp is in the future (clock skew), not old.
2. **No stamp.** A feed with no `observed-at` gives `latest observation unknown
   observation time is older than 600 seconds.` Expected: `has no observation
   time`.
3. **No cache.** With an empty cache and HTTP 503, `price status` and the load
   error say `HTTP 503: price service unavailable. Retry later; cached prices
   remain usable.`, though there is no cached revision. Expected: drop the
   last clause when nothing is cached.

Cause: `cli/src/bea_engine/managed_price_cache.py:377-382` (strict message)
and the fixed string at `cli/src/bea_engine/managed_prices.py:381`.

Fix: word each case by the actual condition.

Dedupe: w1/133 (future skew rule) and w5/484 (doubled full stop) are done
and do not cover these.

Acceptance: the three messages read as expected. Tests pin them.
