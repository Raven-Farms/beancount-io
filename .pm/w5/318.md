# A currency-mismatch row always says "name the row's commodity with --csv currency=CODE": a Python-importer run refuses `--csv`, and for a rule's category account the advice relabels the money and moves the block to the source account

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, engine Python 3.12, beangulp enabled.
`bea import` blocks a row that posts a currency the account's `open` does
not allow. The reason is always the same: `Post <X> instead — name the
row's commodity with --csv currency=CODE — or add <Y> to its open
directive.` That advice is wrong in two cases:

- **Python importer.** `--csv` cannot be used here. `--config … --csv
  currency=USD` exits 2 with `Pass --csv or --config, not both.`
- **CSV run where the blocked account is the rule's category account.**
  `currency=CODE` changes every posting in the row, so the money is
  relabelled and the row stays blocked, now on the source account. The
  real fix, choosing another category account, is never suggested.

No product fix implemented.

2026-01-01 open Expenses:Food USD

Also create `/absolute/books/stmt.txt` (containing `x`) and an inspected
`/absolute/books/importers.py`:

```python
import datetime
from decimal import Decimal as D
from beancount.core import data, amount
from beangulp import importer

def P(acct, n, c, price=None):
    return data.Posting(acct, amount.Amount(D(n), c), None, price, None, None)

class Imp(importer.Importer):
    def identify(self, filepath): return filepath.endswith("stmt.txt")
    def account(self, filepath): return "Assets:Bank"
    def extract(self, filepath, existing):
        m = data.new_metadata(filepath, 1)
        return [data.Transaction(m, datetime.date(2026, 1, 5), "*", "Shop", "Paris", frozenset(), frozenset(),
                [P("Assets:Bank", "-11.00", "USD"), P("Expenses:Food", "10.00", "EUR", amount.Amount(D("1.10"), "USD"))])]

CONFIG = [Imp()]
```

Actual:

1. Exits 4: `Row 1 (blocked): Cannot post EUR to 'Expenses:Food' (open for
   USD only). Post USD instead — name the row's commodity with --csv
   currency=CODE — or add EUR to its open directive.`
2. Following that advice exits 2: `Pass --csv or --config, not both.`
3. The preview blocks the row with `Cannot post USD to 'Expenses:Travel'
   (open for EUR only). Post EUR instead — name the row's commodity with
   --csv currency=CODE — …`.
4. Following that advice still blocks the row: `Cannot post EUR to
   'Assets:Bank' (open for USD only). …`.

The ledger is unchanged throughout. Reproduced in three fresh runs.

Control: on a CSV run where the source account itself is restricted,
`--csv …,currency=EUR` is the right remedy and unblocks the row. That is
the w3/421 case the text was written for.

Expected: `docs/IMPORTING.md` says "A currency mismatch offers the
currency setting first and widening the `open` directive last." The
currency setting is the right first remedy only when it sets the row's
commodity and the blocked account is the source account. Otherwise the
hint should name a fix the run can actually apply:

- For a Python importer: correct the importer's commodity, or the account
  it posts to.
- For a rule, category or default account: choose a category account
  that is open for that currency, or widen that account's `open`.

Cause: `_blocked_reason` (`cli/src/bea_engine/importing.py:984-997`)
builds one string for every blocked posting, whatever the run kind and
whether the posting is the source or a counter posting. `--csv currency=`
is added unconditionally at `:995-996`, from `78217b30` (w3/m49).

Fix: pass the run kind and the source account into `_blocked_reason`.
Offer `--csv …,currency=CODE` only for a CSV run whose blocked posting is
on the source account. For a counter posting on a CSV run, name the rule,
category or default account to change. For a Python importer, say the
importer must post a currency the account allows. In every case, keep
widening the `open` as the last option. No dependency or API change.

Blast radius: every currency-blocked row from `import`, in preview and
`--apply`, in text and JSON. That means Python importers (brokerage and
FX statements), and CSV runs whose rules, category cells or
`--default-account` name a currency-restricted account.

Dedupe: searched `.pm/**`, including `done/`, for "Post USD instead",
"currency mismatch" and "Cannot post", and ran `git log -S "name the row's
commodity with"`.

- w3/421 introduced the remedy for the CSV source-account case.
- w3/323 and w1/m23/t002 cover add-side currency mismatches.
- w5/134 covers the review wording.
- w5/303 covers a different remedy string.

None of these covers the importer path or counter accounts.

Acceptance:

- The importer row's reason does not mention `--csv`, and names
  `Expenses:Food` and the importer's commodity.
- The CSV rule row's reason names `Expenses:Travel` as the account to
  change, and does not suggest `currency=EUR`.
- A source-account mismatch on a CSV run still offers
  `--csv …,currency=CODE` first.

A real-command regression test covers all three in text and JSON. Only
