# `bea doctor missing-open` and `linked` still answer exit 0 on a partial load when an include is missing (rather than a syntax error), so the documented `missing-open main.bean >> main.bean` appends opens that duplicate the missing file's (incomplete fix of w5/596)

**Minor · cli · 10m · A1.** Real CLI QA, 2026-10-17, HEAD `3d73eb246`, checkout `bea 0.3.1`, macOS 26.5.1. Follow-up to w5/596 (done).
w5/596's resolution refuses a partial load that reads as complete, before
anything prints. A missing include hides directives the same way a syntax
error does. No product fix implemented.

`main.bean`:

```
option "operating_currency" "USD"
include "accounts.bean"
2026-01-10 * "Rent"
  Expenses:Rent 9.00 USD
  Assets:Bank
```

`accounts.bean` (which holds the opens) is absent.

```sh
bea doctor missing-open main.bean
```

Actual: exit 0, printing `2026-01-10 open Expenses:Rent` and `2026-01-10 open
Assets:Bank`, with empty stderr. `bea check` exits 1 with `File glob
"accounts.bean" does not match any files`. `doctor linked main.bean ^trip`
with one of two included files missing shows half the link group with exit 0
(hunter's run).

Control: a syntax error in an include is refused with exit 1 naming
`file:line`.

Expected: refuse `missing-open`, `linked` and `region` when an include is
missing, naming it and its includer.

Cause: `_refuse_partial_load` (`cli/src/cli/commands/doctor.py:599`) checks only
syntax errors. The closure walk's missing-include list is never consulted.

Fix: refuse on missing includes too.

Dedupe: w5/596 (done) is the parent.

Acceptance: the fixture exits 1 naming `accounts.bean`.
