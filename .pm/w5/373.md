# A malformed 200 body from the AI proxy reaches the `bea ask` user as a raw Python exception (`Error: list index out of range`, `Error: Expecting value: line 1 column 1 (char 0)`)

**Minor · cli · 15–20m · A1.** Real CLI QA, 2026-10-14, HEAD `bce2c992`, checkout `bea 0.3.1`, macOS 26.5.1, pydantic-ai 2.19.0. **Simulation:** the proxy behaviour comes from a localhost mock. The defect is in how the CLI handles it.

`translated_failures` converts the model SDK's failures into the CLI's
own sentences. Some 200 bodies make the model call raise other
exceptions, and those slip past it to the top-level handler, which
prints `str(exc)`:

- an empty `choices` array, which some OpenAI-compatible gateways return
  for a filtered prompt, raises `IndexError`;
- an empty body, an HTML body labelled `application/json`, or JSON cut off
  midway raises `JSONDecodeError`.

The user sees a bare Python message, not the documented
unexpected-response sentence, and is not told whether anything was
written. No product fix implemented.

Setup: `bea ask` posts to `{BEA_API_URL}/api-gateway/ai/openai/chat/completions`.
A localhost mock answers with 200 and either
`{"id":"x","object":"chat.completion","created":1,"model":"gpt-4o","choices":[]}`
or an empty body, both as `Content-Type: application/json`. Use isolated
BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1, an obviously
fake `BEA_TOKEN`, `BEA_API_URL` and `BEA_DASHBOARD_URL` on 127.0.0.1, and
closed stdin. Use any valid ledger.

```sh
bea -f /absolute/books/main.bean ask --print "q"
bea -f /absolute/books/main.bean --debug ask --print "q"
```

Actual:

- Exit 1 with `Error: list index out of range` (empty `choices`) or
  `Error: Expecting value: line 1 column 1 (char 0)` (empty body).
- A cut-off body gives `Error: Expecting property name enclosed in double
  quotes: line 1 column 60 (char 59)`.
- `--debug` shows `pydantic_ai/models/openai.py` `_process_response`
  (IndexError) and `openai/_response.py` `_parse` → httpx `json`
  (JSONDecodeError).
- A REPL turn prints the same raw sentence.

Reproduced by the hunter three or more times per body, and once each by
me.

Control: an HTML body sent as `text/html`, or a JSON object of the wrong
shape, gets the CLI sentence `The assistant could not complete this
question (UnexpectedModelBehavior); nothing was written to your ledger.
…`. 401, 429 and 500 are translated.

Expected: `docs/USAGE.md` says "A successful HTTP response that the
generated parser cannot read exits **1** with `Unexpected server response
(HTTP 200).` … the CLI does not expose parser exceptions". The ask
section says proxy failures read the same in `ask` as anywhere else. The
`translated_failures` docstring says no arm quotes the SDK's sentence.

Cause: `translated_failures` (`cli/src/cli/ask/agent.py:194-221`) catches
only `ModelHTTPError`, `ModelAPIError`, `UsageLimitExceeded` and
`AgentRunError`. The `IndexError` and `JSONDecodeError` raised by the
model call reach the catch-all in `cli/src/cli/main.py:197-198`.

Fix:

- Add an arm for `json.JSONDecodeError`, `openai.APIResponseValidationError`,
  and `IndexError`/`KeyError`/`TypeError` raised from the model call.
- Raise `BeaError("Unexpected server response (HTTP 200) … " +
  written_so_far(deps))` with the cause chained.
- Alternatively, catch broadly around `run_sync` while letting `BeaError`
  and `KeyboardInterrupt` pass through.
- No dependency change.

Blast radius: `bea ask --print` and REPL turns whenever the proxy or a
gateway in front of it returns an unreadable or empty-choices 200.

Dedupe: searched `.pm/**`, including `done/`, for
`UnexpectedModelBehavior`, "list index out of range", `JSONDecodeError`
and "Expecting value". Related notes:

- w3/449 and w3/454: translated SDK errors and session death.
- w5/276, w1/086 and w3/298: other commands.
- 366: the same class of defect on `cloud status`.

None covers the ask model call.

Acceptance: with each mocked body, `ask --print` and a REPL turn print
the unexpected-response sentence plus the written-so-far clause, with no
exception text. A mocked-transport test covers empty `choices` and an
undecodable body.
