# `add transactions --from ./-` and `bea format ./-` read stdin instead of the file named `-`: the wrong rows are written at exit 0

**Minor · cli · 5–10m · A1.** Real CLI QA, 2026-10-17, HEAD `87570e643`, checkout `bea 0.3.1`, macOS 26.5.1.
`./-` is the POSIX way to name a file called `-`. The help says that only `-`
reads stdin. No product fix implemented.

In a directory holding a file named `-` (one row, narration "FROM FILE NAMED
DASH") and `stdin_rows.json` (one row, narration "FROM STDIN"):

```sh
bea --file /abs/main.bean add transactions --from ./- < stdin_rows.json
```

Actual: exit 0, `Added 1 transaction`, and the ledger gains "FROM STDIN".
The file `-` is never read. With `</dev/null` it exits 2 `Invalid JSON at
line 1, column 1`. `bea format ./- < other.bean` prints stdin's ledger, and
`format -i ./-` refuses as stdin (hunter's runs).

Control: `--from /abs/-` writes "FROM FILE NAMED DASH". `bea treeify ./-`
reads the file.

Expected: `./-` (and any spelling other than a bare `-`) names the file.

Cause: Typer passes a `Path`, and `Path("./-")` normalizes to `Path("-")`.
The stdin checks compare the normalized value: `cli/src/cli/commands/add.py:577`
(`str(from_file) == "-"`) and `cli/src/cli/commands/format.py:409`.

Fix: decide stdin from the raw argument string.

Dedupe: w5/705 (open) is the reverse case in treeify (`-` treated as a file).

Acceptance: both commands read the file `-` when given `./-`. A test pins
`add`.
