## Objective

Provide a bounded way to retire historical application test bindings and rebuild supported live period caches from authoritative subscriptions, without deleting customer accounts or charging anyone.

## Context

Historical `paid_customers` rows survive subscription cancellation, and the old refresh bug can copy a live period end into a test row. Code fixes do not repair stored values. Production database row selection has not been inspected; build a detector instead of assuming any specific customer's rows are corrupt. The repository already has an operator scripts directory and usage guide.

## Steps

1. Add a documented maintenance entry point under `backend-cluster/backend-v2/scripts/`, defaulting to read-only preview and accepting an explicit bounded user selection/batch size. Reuse the corrected subscription mapping and established database access.
2. Report retired bindings, mismatched period caches, missing live customers and ambiguous Stripe results. Never treat a failed Stripe lookup as proof of absence.
3. Make apply explicit and transactional per selected user: record rollback data outside git, retire/archive old test application bindings, and refresh only verified live cache values. Avoid schema changes unless necessary; retain audit/account/ledger history.
4. Prove a second apply is a no-op and demonstrate restore using synthetic data. Document ordering: deploy t001–t003 first, then preview, review, bounded apply, and verify read-back.
5. Hand the tested preview/apply/rollback tooling to t011, which owns the actual existing-users rollout and its coverage evidence; never publish a customer report in the board.

## Files

- `backend-cluster/backend-v2/scripts/` — new retirement/reconciliation script and adjacent `__tests__/` fixtures.
- `backend-cluster/backend-v2/scripts/HOW-TO-USE-SCRIPT.md` — preview/apply, rollback, scope and operational ordering.

## Acceptance criteria

- [x] Default execution makes zero database/Stripe writes; apply requires explicit bounded selection and produces a rollback record outside tracked files.
- [x] Synthetic mixed histories are reconciled correctly; rerunning changes nothing and provider failures leave existing data intact.

## Out of scope
