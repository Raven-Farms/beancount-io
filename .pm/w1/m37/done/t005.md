## Objective

Make settings and checkout expose the single supported billing tenant, and show the plan and limits the backend actually resolved. Preserve the ordinary subscription and promotion-code journey.

## Context

`stripe-config.ts` selects test prices through `?env=dev`; `SubscriptionSection` exposes a Test Mode badge. The current-plan banner uses `useUserLimits`, while billing displays the Stripe product name. These are different facts, and hiding their disagreement would conceal the backend bug. Read `dashboard/AGENTS.md`; this app uses i18next language selection, not CMS locale-prefixed settings routes.

## Steps

1. Remove development client/price selection and its dead exports/branches. Old `?env=dev` URLs must not initiate test billing; ignore the retired flag or normalize to the supported settings route without a new redirect loop.
2. Remove the Test Mode badge and obsolete UI state; t006 owns deleting its locale keys across all languages.
3. Keep plan upgrades, billing management, cancellation/resumption, and new checkout sessions using the supported client. Retain promotion-code entry in newly created Checkout Sessions.
4. Extend existing settings tests with a consistent live Organization fixture: product card, current plan, quota display and upgrade choices agree. Do not hardcode a user/email exception or derive entitlement solely from a product display name.
5. Verify settings in English and Chinese through language selection; pass locale follow-up details to t006.
