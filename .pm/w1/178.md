# Give the server-side `purchase` its traffic source

Found by w1/m39/t011, carried over from t010. The backend reports `purchase` from the `invoice.paid` webhook through the GA4 Measurement Protocol. The webhook has no browser, so the event's `client_id` is derived from the user ID. It joins the journey through `user_id`, but GA4 attributes it to no session and no traffic source.

**Option:** carry the browser's GA client ID and session ID through Checkout and `changePlan` in the subscription's metadata, then send them with the `purchase` event.
- This changes the `createSubscriptionSession` contract, which the marketing pricing page also calls, so that page must send the IDs too.
- It needs a decision on putting analytics identifiers into Stripe metadata.

**Prerequisite:** decide only after w1/m39/t016 turns the event on and a few weeks of `purchase` data show whether the missing source matters.
