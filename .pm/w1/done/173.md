# `createLedger` and `updateLedger` need further review: they can publish a ledger

Found by w1/m38/t007's OpenAI rescan on 2026-10-18: "This new tool definition needs further review before it can be published." The same finding was on `manageLedgers` before the split. It appears on `createLedger` and `updateLedger` but not on `deleteLedger`. The difference between them is `private`, plus `name`, `description`, and `template`, none of which has an argument description.

The likely cause is `private`. `false` makes a ledger's financial data readable by anyone. An omitted `private` is forwarded as undefined by the ledger service (`backend-cluster/ledger/src/api/ledgers.ts`) to Gitea's repository-create API, whose `private` defaults to false, and no deployment sets Gitea's `FORCE_PRIVATE`. So an agent that leaves it out most likely creates a **public** ledger. This is unverified on production.

Options, for the user to choose:

1. Default an omitted `private` to `true` in `LedgerWorkflow.createLedger`, on every surface. This is a behavior change for REST and GraphQL callers that omit it, so check what the dashboard and mobile send.
2. Drop `private` from MCP `createLedger`/`updateLedger`, so MCP creates private ledgers only and cannot publish one. This would be a documented parity exception.
3. Keep the capability, describe every argument (especially that `false` publishes the ledger), and answer OpenAI's review.

Whichever is chosen: give every argument of both tools a description, deploy, and rescan.

**Blocked 2026-10-18** — Every option changes what a caller can do, and two of them change behavior beyond MCP: option 1 changes the default for REST, GraphQL, and the apps; option 2 is a parity exception. That makes this a product decision. **Unblock:** the user picks option 1, 2, or 3 (or another). The worker then implements it, describes every argument, and rescans after the operator deploys. **Owner:** the user.

Unblocked 2026-10-18: the user chose option 1, default to private.

---

**Resolved 2026-10-18** — `LedgerWorkflow.createLedger` now creates a private ledger when `private` is omitted or null, on REST, GraphQL, and MCP alike; only `private: false` publishes. Every `createLedger`/`updateLedger` argument is described in REST/OpenAPI and MCP, and the GraphQL privacy fields are described too, including that `false` makes a ledger readable by anyone. `lifecycle-parity.test.ts` "creates a private ledger unless publishing is asked for" covers omitted, null, false, and true on every surface, and it fails when the default is removed. Shipped in `0df4d5caf` (`backend-cluster/backend-v2`). The OpenAI rescan that confirms the review clears runs after the next deploy.
