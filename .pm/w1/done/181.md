# Clients misread the plan-limit errors

Found by w1/m40/t010. Since w1/m40/t004, refusing a new ledger or a new collaborator is a `RESOURCE_LIMIT_REACHED` error (HTTP 403). Its message names the plan that sets the limit: the actor's own for ledgers, the ledger owner's for collaborators. MCP returns the code and message as they are, which reads well for agents. Two clients reword it:

- **`bea`** maps every 403 to `AuthError` (`cli/src/cli/errors.py`, `error_from_status`). A plan limit therefore reads "Not authorized (…). Check that your account and credential have permission for this action." and exits 3 (auth). It is not a permission problem.
  - **Fix:** recognize the `RESOURCE_LIMIT_REACHED` code in the v1 error body, print the server's message as it is, and pick the exit category deliberately.
  - **Test:** the `bea cloud` ledger-create and collaborator paths.
- **The dashboard** maps the code to `common.errors.resourceLimitReached` ("You've reached your plan's limit. Upgrade to continue."). On someone else's ledger, an admin hitting the owner's collaborator limit is told to upgrade, which does not help.
  - **Fix:** use a collaborator-specific message that says the ledger owner's plan sets the limit, in all 15 locales, and pin it in the collaborator dialog's tests.

---

**Resolved 2026-10-19.**
- **`bea`:** `error_from_status` takes the v1 envelope's `error.code`. A `RESOURCE_LIMIT_REACHED` refusal prints the server's own sentence, which names the plan and its limit. It exits 1 (`validation`), not "Not authorized (…) check that your credential has permission" with exit 3. The code is read from the parsed envelope or the raw body. `tests/test_cloud_transport.py` pins human and `--json` output for `bea cloud ledger create`, and fails when the mapping is removed.
- **Dashboard:** adding a collaborator to someone else's ledger past the owner's limit now says only the owner's plan can lift it (`collaboration.ownerPlanLimitReached`, 15 locales). The owner keeps the generic "upgrade" message. The owner check is case-insensitive. `collaborators-limit-message.test.tsx` pins both cases.
