## Objective

Fix the new tool inventory before any code moves, so t002–t004 implement a decided design.

## Context

- Grouped tools today, with their branches:
  - `editLedgerFiles`: create, update/replace, delete, per file, batched into one commit.
  - `editEntrySource`: update, delete, delete_many.
  - `manageBankImport`: sync, submit, discard.
  - `manageBankConnection`: reconcile, map_account, set_currency, refresh, unlink.
  - `managePullRequests`: create, approve, reject.
  - `manageLedgers`: create, update, delete.
  - `manageLedgerCollaborators`: update, delete, leave.
- ADR 0008 D3 grouped these by shape to keep the tool list small (D2). This milestone reverses that for directory acceptance.
- Each `VERB_TABLE` row already names one verb, so most splits map one row to one tool.

## Steps

1. Name each new tool (verb-first, unique, 64 characters or fewer). Decide `editLedgerFiles`: split by kind, with each tool still accepting a batch of that kind in one commit. Decide whether `delete` and `delete_many` on entry source become one tool that takes a list.
2. Assign each tool's annotations by the directories' definitions: deletion, overwriting, cancellation, and access revocation are destructive.
3. Write the ADR 0008 amendment reversing D3, and the ADR 019 amendment quoting OpenAI's finding. Record the full old→new name map in both.

## Result (2026-10-18)

Decided and recorded in ADR 019's 2026-10-18 amendment (the full old→new table: 23 tools, one per `VERB_TABLE` verb) and ADR 0008's 2026-10-18 amendment (D3 reversed).

- **One tool per verb.** Each grouped tool's branches map 1:1 to existing verb rows, so `tools/list` goes from 27 to 43 tools.
- **File edits.** `updateLedgerFiles` takes, per file, either an exact-text edit (`old_string`/`new_string`) or a full replacement (`content`). Both are the `update` verb, so no `operation` field is needed. Cross-kind atomic batches go away, and each file tool commits one batch of its kind.
- **Entry-source deletes.** `delete` and `delete_many` stay separate tools (`deleteEntrySource`, `deleteEntrySources`) because they are separate verb rows.
- **Annotations** follow OpenAI's definitions. `reconcileBankAccounts` is destructive because reconciling can hard-delete accounts Plaid no longer shares (`src/features/plaid/utils/reconcile-accounts.ts`). Overwriting tools (`updateLedgerFiles`, `updateEntrySource`, `mapBankAccount`, `setBankAccountCurrency`, `updateLedger`) and access changes (`setLedgerCollaborator`, `removeLedgerCollaborator`, `leaveLedger`) are destructive.
- **Scope.** The in-product dashboard agent keeps its own `editLedgerFiles` tool. Only the MCP registration splits, and the executors are shared.
