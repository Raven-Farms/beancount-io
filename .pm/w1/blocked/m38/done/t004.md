## Objective

Replace the two editing dispatchers with per-operation tools, keeping batched single-commit writes within each operation kind.

## Context

- `editLedgerFiles` batches create, update/replace, and delete across files into one commit. Its three verbs (`ledger.editFiles.create`, `update`, `delete`) are pinned by name in the frozen baseline.
- `editEntrySource` (update, delete, delete_many) lives in `mcp-source-slices.ts`.
- `appendLedgerText`'s description references `editLedgerFiles`, so update the reference.

## Steps

1. Register the per-kind file tools (each takes a batch of that kind, in one commit, with `dry_run`) and the entry-source tools decided in t001.
2. Rebind the verb rows, add the three `editLedgerFiles` rows to the baseline rename map, and update the tests.

## Acceptance criteria

- [x] No `operation` argument remains on any editing tool. Batch atomicity within a kind is tested.

## Out of scope

- Cross-kind atomic batches; record their loss in the ADR amendment.

## Result

- `editLedgerFiles` is now `createLedgerFiles` (`files: [{path, content}]`), `updateLedgerFiles` (per file, an exact `old_string`/`new_string` replacement or a whole-file `content`), and `deleteLedgerFiles` (`files: [{path}]`). Each takes `description` and `dry_run`, and commits its batch in one commit. Cross-kind batches are gone, as the ADR 019 2026-10-18 amendment records.
- `editEntrySource` is now `updateEntrySource`, `deleteEntrySource`, and `deleteEntrySources`. Each publishes only its own result schema, which brought `tools/list` back under the size gate (96.4 KB).
- `ledger.editFiles.create/update/delete` rebound; `RENAMED_ON_MCP` in `parity-baseline.test.ts` maps the three frozen `editLedgerFiles` rows to the new names. The fixture is unedited.
- The in-product agent keeps its combined `editLedgerFiles` tool; only the MCP surface split.
- Served text, `docs/mcp.md`, `docs/api-parity.md`, `docs/mcp-agent-eval.md`, the conformance probe (check 5), and the agent-eval ledger reset name the new tools.
- `edit-ledger-files-refusals.test.ts` drives each tool with two files through the real registry and repo service and asserts one commit carrying both; dropping a file from the mapping fails it.
- Gates: `yarn typecheck`, `yarn lint`, `yarn test` (5,594 tests), and `yarn generate-v1-openapi` with no drift.
