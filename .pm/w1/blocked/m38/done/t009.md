## Result

`/simplify` over the m38 source commits (`1b5c78eec`, `bb80447c4`, `41ae2f578`, `f43480baa`), with four reviewers: reuse, simplification, efficiency, and altitude. Three of them converged on the main finding: the split tools still ran through the old grouped dispatchers, which re-parsed every call through an unpublished grouped schema.

Applied (net −125 lines in `src/features/ai-agent`):

- **Lifecycle, collaborators, pull requests, entry sources:** one handler per operation (`*_EXECUTORS`), each parsing the schema its tool publishes. The four grouped `*ToolInput` schemas are gone, including `sourceSliceInput`'s `superRefine`, along with the `operation`-injecting helper and an unreachable "create with `ledger`" refusal (the strict schema already refuses it). Approve and reject share one `reviewInput`.
- **Bank:** `BANK_OPERATIONS` has one entry per operation (schema, description, output, run). This removes `IMPORT_OPERATIONS`, both switch dispatchers, the `required()` checks, and the `dry_run` guard. Each tool's strict schema already requires those fields and refuses an undeclared `dry_run`. The `submit` input type comes from its schema.
- **Files:** `LEDGER_FILE_OPERATIONS` gives one entry per kind, mapping straight onto the shared executor. The in-product tool's combined schema reuses the same path, old-string, and new-string fields, so its text is unchanged. `toFileOperations` and the hand-written input type are gone.
- **Registry:** one `operationTool(name, title, entry, hints)` serves both tables. Named presets `IDEMPOTENT_DESTRUCTIVE` and `EXTERNAL_IDEMPOTENT_WRITE` replace eight inline spreads.
- **Published surface:** `tools/list` before and after differs only in the `ledger` argument text of `updateLedger` and `deleteLedger`, which now use the shared `ledgerSelection` wording like every other ledger tool (+26 bytes, well inside the 96 KiB gate).

Skipped, with reasons:

- Dropping each handler's own parse: kept. One parse per call against the published schema is the registry's stated convention, and direct callers rely on it.
- Caching the JSON-Schema conversion of `tools/list` across requests (~2 ms per list): the per-request registry predates m38 and lives in `composition-root.ts`, outside this diff.
- Byte-identical output schemas repeated across sibling tools (~14 KB): sharing them would change the published output contract.
- An allowlist for tools that span several verbs (`spansVerbs`): optional. The `tools/list` selector guard from t005 already fails on a reintroduced dispatcher.
- Reusing the MCP preview note in the in-product agent's description: it would change that agent's tool text.

Gates: `yarn typecheck`, `yarn lint`, `yarn test` (5,595 tests), `yarn generate-v1-openapi` (no drift).
