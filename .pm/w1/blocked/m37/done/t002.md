## Objective

Make the effective plan follow the actual live subscription's own identity and price, independent of historical customer row order. A live Organization customer must receive Organization limits across human and agent entry points.

## Context

`getUserTier()` currently passes a cached row's `clientId`, or `paidCustomers[0].clientId`, to a helper which independently selects the first active subscription across all clients. An unmatched price silently becomes PREMIUM. Synthetic reproduction already shows a live Organization price becoming PREMIUM with a dev cache row and ORGANIZATION with a prod cache row. `StripeService.listSubscriptions()` already annotates each subscription with its client ID.

## Steps

1. Reproduce the historical-dev-plus-live case with synthetic rows before changing behavior.
2. Resolve each candidate using its own client/customer binding and price configuration; exclude retired tenants and do not let arbitrary cached rows choose the plan map.
3. Define deterministic selection for multiple recognized active subscriptions (highest recognized purchased tier, stable tie handling), independent of input order. Preserve active-status eligibility and recognized legacy price mappings.
4. Restrict legacy fallbacks to explicitly recognized legacy situations. Unknown/missing prices must produce a diagnostic and the existing safe failure behavior, not masquerade as a successfully identified Premium purchase.
5. Inspect account profile, ledger creation, collaborator/directive/token quotas, and other callers so they consume the shared result rather than restating plan matching.

- [x] Old dev rows before/after a live Organization binding always resolve ORGANIZATION; no Stripe test client is queried to grant live access.
- [x] Permutations of multiple live subscriptions produce the same effective tier; legacy supported live prices remain compatible.
- [x] Unknown prices, missing bindings, expired/canceled subscriptions, and Stripe failures have explicit tested outcomes and no silent false Premium success.
- [x] Existing tier tests plus regressions pass, and account/quota consumers use the shared resolver.
