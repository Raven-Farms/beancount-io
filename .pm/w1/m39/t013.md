## Objective

Add tests that fail if the shipped behaviour breaks, using synthetic fixtures and mocked Stripe responses only.

## Context

- Same constraint as m37: no live charge, coupon redemption or subscription mutation, and no real customer data in fixtures.

## Steps

1. Backend:
   - classification over every configured price pair;
   - proration time passed through;
   - `ACTIVE`, `REQUIRES_ACTION` and `FAILED` mapping;
   - refusal of scheduled kinds and legacy targets;
   - per-session return URLs;
   - portal configuration;
   - authorization denial for API-key and OAuth credentials;
   - the edge cases: a legacy price choosing the same tier and cycle, two active subscriptions, double confirms, and Checkout for an existing subscriber.
2. Pricing-page contract (milestone README):
   - `createSubscriptionSession` accepts the pricing page's client and every price it sells, and returns a session URL;
   - `subscriptionStatus.hasActiveSubscription` keeps its meaning on both the verified-cache path and the live Stripe path;
   - `/settings/general` still links to Billing;
   - the sign-up `next=/pricing?billing=yearly` round trip still lands back on the pricing page.
3. Dashboard:
   - summary card and "Pay yearly" visibility;
   - plan row defaults;
   - sheet amounts and failure states;
   - the authentication fallback;
   - confirmation polling and timeout;
   - deep-link validation;
   - each prompt's recommended plan.

## Files

- Tests next to the changed modules in `backend-cluster/backend-v2/src/features/stripe/` and `dashboard/src/features/user-settings/`

## Acceptance criteria

- [ ] Each test fails when its behaviour is reverted.
- [ ] The pricing-page contract test fails if any price the pricing page sells is refused.
- [ ] No snapshot-everything or tautological tests.
- [ ] Both packages' full gates pass.

## Out of scope

- Browser end-to-end runs against live Stripe.
