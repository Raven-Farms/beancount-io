## Objective

After a password reset, every OAuth artifact issued to the user (grants, access tokens, refresh tokens, authorization codes, and the provider's interactive session) is revoked, so the mobile app and any connected third-party MCP client must sign in again.

## Context

- OAuth state lives in `oauth_adapter_storage` (`backend-cluster/backend-v2/src/features/oauth/data/oauth-adapter-model/schema.ts`), keyed by `(model, id)` with a denormalized `grant_id` column. There is no account column. The account ID is only inside `payload` (`accountId` on `Grant` and `Session` rows).
- `postgres-impl.ts:111` `revokeByGrantId` deletes one model's rows for a grant; oidc-provider calls it once per model.
- Mobile refresh tokens last 365 days (sliding), and third-party grants last 45 days (sliding, up to a year) (`features/oauth/data/config.ts`). Neither is revoked anywhere today, and there is no UI to list or revoke them.

## Steps

1. Add a model method that finds every `Grant` and `Session` row whose payload `accountId` is the user, and deletes every row (any model) sharing those `grant_id`s, plus the sessions. Either query `payload->>'accountId'` directly, or denormalize an `account_id` column with an index and a migration. Pick by how the table is queried elsewhere and say why in the commit.
2. Call it from `resetPassword` after the transaction in t001 commits. A failure is logged and surfaced; it must not roll back the password change.
3. Check what the mobile app does when its refresh is refused (`mobile/src/common/oauth/`): it should land on sign-in, not retry in a loop. Fix it there if not.
4. Consider whether account deletion should call the same method; if it is missing there too, note it as follow-up rather than widening this task.

## Acceptance criteria

- [ ] After a reset, a refresh token issued before it is refused at the token endpoint, and an access token issued before it no longer resolves to an identity (`resolveOidcIdentity`, `features/oauth/utils/oidc-verify.ts`).
- [ ] Another user's grants are untouched.
- [ ] The mobile app returns to sign-in after its refresh is refused.

## Out of scope

- API keys (see t001).
