## Objective

Check users and contributors can tell what a reset now does: the dashboard's reset success copy says other devices were signed out (in every shipped locale), the backend auth docs describe what a reset revokes and what it keeps (API keys), and the mobile sign-in path after a refused refresh reads as intended. Record the API-key decision explicitly; if keeping them, say where the user revokes them. Flag drift as follow-up work.

## Done (2026-10-18)

Walked every surface a reset touches:
- **Dashboard reset success copy** (`dashboard/src/features/auth/locales/*.ts`, `auth.passwordResetSuccessMessage`) now says every device and connected app was signed out: "Your password has been reset, and every device and connected app has been signed out. Redirecting to login...". All 15 locales are updated, each using its catalog's own sign-out word (Abmelden, ログアウト, 登出, Cerrar sesión, …). Persian keeps its ZWNJ joins.
- **Dashboard reset page.** t001 found that a browser signed in when it reset reached login only by a detour. The success timer now uses `hardNavigate("/auth/login")` (`common/lib/navigation/hard-navigate.ts`, doc updated) instead of a router navigation, so the router's cached profile from the revoked session is dropped. `reset-password-page.test.tsx` asserts the document navigation and that no router navigation happens.
- **Backend docs.** `backend-cluster/backend-v2/README.md` "Session lifetimes" now says what a reset revokes (every session, grant, refresh token and provider session, all or nothing), that already-issued access tokens lapse within the hour, and what it keeps.
- **Mobile.** A refused refresh returns the app to sign-in (verified in t002). No copy change is needed.

**Decision recorded: personal access tokens (API keys) and SSH keys survive a reset.** They are long-lived credentials a user creates on purpose, for CI, cron and Git, and revoking them would break running integrations without the user asking. Each is listed and revocable under Settings → Personal access tokens and Settings → SSH Keys, and the README says so. Revisit if the user wants a reset to revoke them too.
