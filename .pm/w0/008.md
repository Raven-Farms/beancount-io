# Return focus to the opener when the Journal New Entry dialog closes

**Severity:** minor (accessibility; WCAG 2.4.3 Focus Order). **Estimate:** 40–55 minutes including real-dialog tests. **Owner:** `dashboard` (journal). **A2:** a keyboard user who opens New Entry and backs out should land on the control they used, not at the top of the document.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `575a8798`. QA-owned headless Chromium, 1440×1000, en-US, authenticated owner on a synthetic ledger. No entry was created.

1. Open `/ledger/<owner>/<ledger>/journal`. Focus the toolbar **New Entry** link and press Enter. The dialog opens (`?action=new-entry&directive=transaction`) with focus on the Transaction tab.
2. Press Escape, or focus **Close** and press Enter.
3. `document.activeElement` is `BODY`. Pressing Enter again doesn't reopen anything.

The same happens from the sidebar's "+" action (navigation "Ledger") and from Overview's Recent activity **New Entry** link. That link navigates to the Journal route, so its original opener no longer exists. Reproduced on fresh loads for all four paths.

Working controls on the same build: Journal **Export**, Accounts **Open Account**, Budget dialogs, and Entry Context restore focus (w3/m23 and `restoreFocusOnDialogClose`).

## Root cause

The dialog is route-driven. `features/journal/pages/journal-page.tsx:338–352` opens `NewDirectiveDialog` when `action=new-entry` and clears the search on close. Its `DialogContent` (`features/journal/components/new-directive-dialog/index.tsx:53–54`) has no `onCloseAutoFocus`/return target. Radix's trigger association doesn't exist for a `<Link>` opener, so focus falls to `BODY`. `open-account-dialog.tsx:139–144` is the established pattern: `restoreFocusOnDialogClose(event, returnFocusRef?.current)` with a persistent fallback.

## Fix

Pass a `returnFocusRef` into `NewDirectiveDialog` and call `restoreFocusOnDialogClose` in `onCloseAutoFocus`. Return to the toolbar New Entry link when it exists. For openers outside the page (sidebar "+", Overview link, bookmarked `?action=new-entry`), fall back to the persistent toolbar link. Successful creation should land on the same persistent target, or on the new entry if that is the existing convention. Don't add timers or a global focus override to the Dialog primitive (w3/m23 DoD).

Acceptance: Escape, Close, and successful submit (with a mocked mutation) return focus to the toolbar New Entry link at 1440 and 390 widths, and immediate Enter reopens the dialog. Sidebar, Overview, and deep-link openers land on the same persistent link. Real-dialog interaction tests cover dismissal and async completion. Dashboard gates pass.
