# Reports' Cash flow chart draws a deficit period as money from nowhere, and same-named income and expense groups both read "Crypto"

**Minor · mobile · 30–45m · A2.** Native mobile QA, 2026-10-15, `main` at `22aec290`, development build `io.beancount.ios` (JS `1.20261002.50`) on iPhone 17e / iOS 26.5, dark appearance, English, default text size. Authenticated production session at `https://beancount.io/` with the dedicated QA account. Public ledger `open_ledger/crypto-example`. Report-only run.

## Repro

1. Select `open_ledger/crypto-example` (Browse ledgers → Explore → search `exam`), then open **Reports**. Leave the range at **6M** (May–Oct 2026; Reports anchors rolling ranges to the latest data point).
2. The income/expense bars show a loss-making half year (May about −$6K net, Jun about −$3K).
3. Under **Cash flow**: a green node labelled **Crypto** on the left feeds the central hub with a ribbon covering only the top half of the hub. The hub's lower part has no incoming ribbon at all. The hub then pours its full height into a red node on the right, also labelled **Crypto**.

Read-only BQL control (`queryShell`, HTTP 200): `SELECT root(account,2), sum(convert(position,"USD")) WHERE date >= 2026-05-01 AND (account ~ "^Income" OR account ~ "^Expenses") GROUP BY 1` returns `Income:Crypto −6517.84 USD` and `Expenses:Crypto 11427.94 USD`. The 4,910.10 USD shortfall was funded from existing balances, and the chart shows nothing for it.

**Expected:** the diagram conserves flow in both directions. A surplus period already gets a **Savings** outflow. A deficit period should get the mirror inflow (for example **From savings** or **Shortfall**) sized `linkedExpenses − linkedIncome`, so every part of the hub has a source. An income group and an expense group with the same leaf name should be distinguishable without relying on red versus green.
**Actual:** for any range where expenses exceed income, the hub is taller than everything feeding it. And both side nodes read **Crypto**.

## Root cause

- `mobile/src/screens/reports-screen/selectors/sankey-data.ts`, `transformToSankeyData`: after building links it computes `savings = linkedIncome − linkedExpenses` and adds a `SAVINGS_ID` node only when `savings > 0`. A negative balance adds nothing, so `d3-sankey` sizes the hub to its larger (outgoing) side and leaves the gap unexplained. The function's own comment says a hub taller than its income flow "break[s] conservation on screen"; only the surplus side is handled.
- Labels: `toRankedNodes(incomeValues, leafName)` and `toRankedNodes(expenseValues, leafName)` (`:292`, `:298`) use `leafName` from `common/account-util.ts:24` at `SANKEY_DEPTH = 2` (`:7`), so `Income:Crypto` and `Expenses:Crypto` both become `Crypto`.
- The web dashboard has the same surplus-only shape (`dashboard/src/features/reports/overview/lib/sankey-data-transformer.ts:287–290`), so this is a shared presentation gap rather than a mobile regression. The dashboard was not exercised in this run.

## Fix

In `transformToSankeyData`, when `linkedExpenses > linkedIncome`, push a source node (role `savings` or a new `shortfall` role with a translated label) and a link `shortfall → CASH_FLOW_ID` of `linkedExpenses − linkedIncome`. Mention it in `cashFlowChartSummary` alongside the existing savings variant. When an income row and an expense row share a leaf label, disambiguate them, for example `Crypto (income)` / `Crypto (expenses)` through translated suffixes, or by keeping one more account segment. Add selector tests for a deficit range (hub inflow equals outflow), a surplus range (unchanged), and a shared leaf name. Mobile only. Mirror the deficit node in the dashboard transformer as separate dashboard work if that surface should match.

## Blast radius

One producer (`transformToSankeyData`), one consumer (`components/cash-flow-sankey.tsx`), Reports tab only. Every ledger and range with a net loss is affected, and every ledger whose income and expense trees share a depth-2 name. Working control: `open_ledger/example` at 6M (a surplus period) draws a balanced chart with **Savings**.

**Resolved 2026-10-17** — Two changes to `transformToSankeyData`.

Deficit periods now conserve flow:
- When expenses exceed income, a new `SHORTFALL_ID` source node feeds the hub with `linkedExpenses − linkedIncome`.
- It reuses the Savings role, color and label. On the source side it reads as money drawn from savings, and the existing legend already names it.
- `sankeyShortfall` and a new `cashFlowChartSummaryWithShortfall` string tell VoiceOver how much came from savings.
- Surplus periods are unchanged.

Same-named groups get their side named:
- When an income group and an expense group share a leaf label, both get a translated suffix: `sankeyIncomeNodeLabel` "{{name}} (income)" and `sankeyExpensesNodeLabel` "{{name}} (expenses)".
- The folded "Other" rows stay generic.
- The three new keys are translated in all 13 locales.

Verified on iPhone 17e, `open_ledger/crypto-example` at 6M: the hub's left side is **Crypto (i…** plus a blue **Savings** inflow, and its right side is **Crypto (e…**. Every part of the hub now has a source.
