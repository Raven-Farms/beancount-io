## Objective

## Done (2026-10-18)

Ran `/simplify` over 90e765662, 785fbf8b5 and 8949012a2, with four reviewers: reuse, simplification, efficiency and altitude.

Fixed:
- **Altitude: one password-verification capability.** The Git proxy (a transport adapter) had re-implemented sign-in: budget check, `getByMail`, `verifyPassword`, then recording or clearing the count. It had already drifted from `loginUser`, missing the password length cap. `AuthService.verifyPasswordCredentials(email, password)` now holds the length cap, the budget, the lookup and the verify. `loginUser` adds the ban check and the JWT on top. The Git proxy calls it through `layers.services.auth` and maps `BadUserInputError` to 401; a `RateLimitedError` still reaches its 429 path. Dashboard and Git sign-in now share the budget by construction, not by comment.
- **The budget is one call, so its steps cannot be reordered.** `verifyPasswordWithinBudget(email, verify)` replaces the three exported steps (assert, record, clear): it checks, verifies, then records or clears. `clearPasswordFailures` stays for reset. The budget is typed as the limiter's `Budget`.
- **Efficiency: no more Redis write on every successful Git request.** A correct password deletes the counter only when the account had failures. Git basic auth runs on every request of a clone or fetch, and the old unconditional DEL was a Redis write on each one.
- **One fail-open wrapper.** `redis-counter.ts`'s three functions share it (`withCounterClient`) instead of repeating the null-client guard and catch-and-log.
- **One client address helper.** `clientAddress(ctx)` and `UNKNOWN_CLIENT_ADDRESS` (`src/server/client-address.ts`) back the GraphQL context, the REST limiter, the CLI requester hint and the sign-up and forgot-password checks, replacing scattered `"unknown"` literals. The one-use `const ip` locals in the auth resolver are gone.
- **Tests.**
  - The in-memory counter fake is now one shared helper (`foundation/redis/__tests__/fake-redis-counter.ts`), used by the sign-in budget tests and the Git proxy tests.
  - The Git proxy tests build a real `AuthService` over their mocked models, so the shared path is what they exercise.
  - The counter stubs added to three tests that never sign in are removed.

Skipped, with reasons:
- **Making `clientIp` optional.** The IP is a required `string` stored in the sign-up session; one constant removes the duplication without that churn.
- **Batching GET and PTTL in `peekCount`.** It only matters for accounts with recent failures.
- **Overlapping the budget check with the user lookup.** A refused attempt would then cost a database read.
- **Sharing the retry-after rounding.** The duplication predates m7.
- **Moving the dashboard `RATE_LIMITED` special case into the shared error module.** It means "this account's wrong-password budget" only on sign-in.

Unchanged behavior worth noting: the Git proxy still does not refuse banned users (only `loginUser` checks `isBlocked`), as before m7.

Gates: backend-v2 typecheck, eslint and knip pass. Jest passes 5783 of 5784; the one failure is the known environmental `upstream-survival.test.ts`. Weakening the budget fails 5 tests across the sign-in and Git suites.
