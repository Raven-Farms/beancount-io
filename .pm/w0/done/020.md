# Name the header filter that failed to parse on reports and Journal

**Severity:** minor. **Estimate:** 45–60 minutes (classify two server diagnostics, localized copy, field highlight, tests). **Owner:** `dashboard` (`common/lib/errors`, report/journal error states, header filter bar). **A2:** the header has three free-text filters (Time, Account, payee/tag). After a typo the page says only "Some of the information provided is invalid", so a newcomer can't tell which box to fix or what syntax it expects.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `575a8798`. QA-owned headless Chromium, 1440×1000, en-US, authenticated owner on a synthetic ledger. Read-only, reproduced on fresh loads.

1. On `/ledger/<owner>/<ledger>/balance-sheet`, type `last mnth` into the **Time** filter and press Enter. The URL becomes `?time=last+mnth`. The page alert reads "Error loading data — Some of the information provided is invalid. Please check and try again." The Time box is not marked invalid.
2. Type `payee:"Unclosed` into **Filter by tag, payee, ...** → `?filter=payee%3A%22Unclosed`, with the same generic alert.
3. The same generic text appears on Journal (`Error loading journal entries: Some of the information …`), Income Statement, Cash Flow, and Overview.

The server says exactly what's wrong, as `BAD_USER_INPUT`: `Failed to parse date: last mnth` and `Illegal character """`. In both cases the failing operation was sent twice with identical variables (two identical GraphQL errors per load).

## Root cause

w3/133 (`86ca4531`) routed report errors through the shared `getErrorMessageKey`, which deliberately collapses every `BAD_USER_INPUT` into `common.errors.badUserInput`. Nothing connects the error back to the filter that produced it. The header filter inputs (`time`, `account`, `filter` search params) have no invalid state.

## Fix

Recognize the two engine diagnostics narrowly, the same way w4/160 did for BQL columns: `Failed to parse date: <text>` → Time filter, and filter-grammar errors (`Illegal character …`, unbalanced quotes) → payee/tag filter. Show localized copy naming the field, with a short syntax hint (e.g. "Time filter not recognized — try 2026, 2026-08, 2026-Q3, or \"month\""), and set `aria-invalid` plus a described-by message on that header input. Don't render raw server text. Keep the generic fallback for everything else. Optionally investigate why the failing read is issued twice.

Acceptance: steps 1–2 identify the Time vs payee/tag field, on Balance Sheet, Income Statement, Cash Flow, Trial Balance, Journal, and Overview, at 1440 and 390. Correcting the field restores results. Unit tests cover both diagnostics and the generic fallback. Dashboard gates pass.
