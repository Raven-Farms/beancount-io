# Render report money at one precision per currency, independent of `render_commas`

**Severity:** minor. **Estimate:** about 60 minutes in the dashboard formatter and its hook. Promote to a milestone if a per-currency precision has to come from the ledger API. **Owner:** `dashboard` (`common/lib/format`, `common/hooks/use-format-number`). **A3:** the public example ledger shows `109,529.339 USD` beside `4,559.8 USD`. Neither is how a USD amount is written, and Fava shows `109,529.34` and `4,559.80`.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `575a8798`. QA-owned headless Chromium, 1440×1000, en-US. Public `open_ledger/example` (`render_commas` true, operating currency USD), plus the QA owner's synthetic ledger. Read-only, reproduced on fresh loads.

- `/ledger/open_ledger/example` Overview: Net Worth `117,649.488 USD`, `+2,191.507 USD from previous month`, `Cost basis 106,826.049 USD · Unrealized +10,823.439 USD`, accounts `48,471.385 USD` and `41,179.933 USD`.
- `/ledger/open_ledger/example/balance-sheet`: Assets `109,529.339`, Vanguard `81,749.999`, RGAGX `49,049.666`, next to GLD `4,559.8` and VEA `4,959.5`.
- Synthetic ledger (USD recorded to cents): Overview Money out `-2,095.6 USD` and Net worth change `+1,904.4 USD`. Income Statement `2,095.6`.
- The exports for the same periods print `2,095.60` and `1,904.40` (`features/reports/export/amount.ts`), so the page and its own Markdown export disagree on the digits.

## Root cause

`dashboard/src/common/lib/format/format-number.ts:14–27` `formatNumber`, via `useFormatNumber` (16 callers) and the Overview components, formats an amount with no knowledge of its currency. With `render_commas` true it calls `toLocaleString(locale)`, which keeps up to 3 fraction digits and drops trailing zeros. With `render_commas` false it uses `toFixed(2)` and strips zeros. So a grouping option changes the precision: one value renders as `48,471.385` or `48471.39` depending on `render_commas`. The file's own `formatQuantity` comment notes this ("it caps at the locale default of three fraction digits, or `toFixed(2)`").

## Fix

Choose the fraction digits per currency, the same way in both `render_commas` modes, and let `render_commas` control grouping only. Use the currency's display precision: the fractional digits the ledger itself records for that currency (Fava's display-context rule), falling back to the ISO 4217 minor units for ISO codes. Use it as both minimum and maximum, so USD always renders `4,559.80`, a three-decimal MUSD ledger keeps three, and integer commodities like VACHR stay integer. Thread the currency into the hook's callers that already have it (Overview cards, statement hierarchy cells). Don't change `formatQuantity`'s source-precision contract for units (w4/126, w3/109). Reuse the export layer's amount rules where they already encode this.

Acceptance: on `open_ledger/example`, Overview and Balance Sheet show `117,649.49`, `109,529.34`, `4,559.80`, and `48,471.39` USD (at cost and at value). The synthetic ledger shows `-2,095.60` and `1,904.40`, matching its exports. Toggling `render_commas` changes separators only. A three-decimal ledger such as `open_ledger/minimax` keeps three decimals. Unit tests cover USD, a 3-decimal currency, an integer commodity, negatives, zero, and both `render_commas` modes. Dashboard gates pass.

## Dedupe

Searched `.pm/**` for display precision, trailing zeros, render_commas, `toLocaleString`, and `minimumFractionDigits`. w3/110 fixed locale hydration in this formatter and w4/126 fixed unit tooltip precision, which explicitly kept `useFormatNumber` unchanged. w3/189 and w3/109 are mobile precision fixes. No item covers currency money precision on dashboard reports.

---

**Resolved 2026-10-15** — `formatNumber`/`useFormatNumber` (`common/lib/format/format-number.ts`) take an optional currency: an ISO 4217 currency (per `Intl.supportedValuesOf("currency")`) is written at its minor-unit precision in both `render_commas` modes, which now only toggles grouping; tickers, crypto and ledger-defined units such as MUSD keep source-driven formatting. Overview amounts, Net Worth cost basis/unrealized/change, statement hierarchy cells and Budget cards pass their currency, so `109,529.339`/`4,559.8` read `109,529.34`/`4,559.80` like the exports. Tests in `__tests__/format-number.test.ts`. Chart axes and tooltips are unchanged. Shipped in the commit that moved this note to `done/` (`dashboard`).
