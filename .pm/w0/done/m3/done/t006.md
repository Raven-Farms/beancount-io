## Objective

Run `/simplify` over the code this milestone changed (reuse, simplification, efficiency; behavior-preserving).

## Done (2026-10-17)

Ran `/simplify` over the milestone's code with four reviewers (reuse, simplification, efficiency, altitude).

Fixed:
- **Catalog edits parse instead of matching layout.** `editCatalogSource` and `ownCatalogKeys` used regexes that assumed a typed `const` and multi-line entries. The altitude reviewer confirmed `reports/locales` (an untyped `const … = {` with a local spread) made the editor throw, and that a one-line entry would have been deleted or duplicated. Both now use the TypeScript compiler, the same approach as `translations.test.ts`:
  - Own entries are the property assignments of the default-exported object and of the local objects it spreads.
  - Imported spreads are excluded by structure.
  - A factory-built catalog (`reports/export`) reads as having no entries.
  - Prettier lays out insertions, so indent detection is gone.
  - All 708 catalog files in the tree parse.
- **One `[TODO]` predicate.** The report checked `startsWith`, while the check and CI trimmed first, so a message with leading whitespace before `[TODO]` read as done in the report and as failing in CI. `TODO_MARKER` and `isTodoMessage` now live in `src/test/locale-scan.ts`, used by `translations.test.ts`, `i18n:check` and the report.
- **One rule each for plurals and copies.**
  - The plural-family rule had three copies. It is now `pluralFamily` in `src/i18n/plural.ts`, used by `findFlatPluralIssues`, the cross-language key test and the sync.
  - "Whole English copy minus the allowlist" is now one `wholeEnglishCopies`, used by the guard and the report.
- **Reused instead of redefined:** `TranslationEntry` (from `src/i18n/utils.ts`) and the target locales (`EN_COMPARED_LOCALES`).
- **Efficiency.**
  - Each catalog is imported once per run and again only after this run writes it. English used to be re-imported for every locale.
  - Inserting stops at the nearest neighbour instead of scanning every earlier key. The reviewer measured that at up to seconds per catalog for large syncs.
- **`i18n:check` covers the shared catalogs too.** It reports their `[TODO]`s; drift doesn't count for them because the run never syncs them. So the AGENTS.md statement that it lists every `[TODO]` now holds.
- **Cleanup.**
  - Misplaced and stale doc comments fixed. The shared-catalog guard's comment had described an old fallback.
  - An unused import, the `isStructuredFormat` re-check, the separate new-file renderer (new files now start from an empty catalog and go through the same editor), and the stale `tsx` shebang removed.
  - The two report key lists are now one `printKeyList`.

Skipped:
- **Declaring `tsx` as a devDependency.** Adding a dependency needs the user's approval. The scripts run through `node --import tsx`, as `search-console-report` already does.
- **Moving `i18n:check` into Vitest.** About 1–2 hours of restructuring; the check is already about 1 s inside `yarn lint`.
- **Unused `GlobalStats` fields and the duplicated progress-bar math.** Both predate this milestone.
- **Deleting `flatten-translation-keys.ts`.** Out of scope.

Checked on the real tree:
- Clean `main`: `i18n:check` passes and `i18n:prepare` writes nothing.
- With a new journal key, a deleted Russian `_few` and a new key inside `reports`' local `deReportsShared`, the run added exactly those entries beside their neighbours in all 14 locales (29 keys). Every written file is Prettier-clean, a third run wrote nothing, and `i18n:check` listed the 29 `[TODO]`s.

`sync-locale.test.ts` gains cases for the untyped local-spread catalog, a spread-only aggregate and a one-line entry. Neighbour insertion is now checked byte for byte after Prettier.

Gates: dashboard `format:check`, `lint` (including `i18n:check`), `test` and `build` pass.
