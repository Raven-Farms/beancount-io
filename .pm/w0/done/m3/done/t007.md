## Objective

Make sure the tool's new behavior is covered by meaningful tests: plural-aware sync per locale, idempotence, each `--check` failure mode, and whole-copy reporting. Tests must fail if any of those rules is removed.

## Done (2026-10-17)

Added an end-to-end test of the real CLI: `scripts/__tests__/prepare-translations.cli.test.ts`. It runs `node --import tsx scripts/prepare-translations.ts` on a fixture tree in which every locale is synced in its own plural forms. Four problems are then introduced: a German key deleted, an obsolete French key, a Russian `_few` deleted and a Spanish `[TODO]`.
- `--check` exits 1, lists exactly those four, and writes nothing.
- A run exits 0 and fixes exactly that drift. The Russian `_few` returns as `[TODO]` between `_one` and `_many`, the German key returns as `[TODO]`, and the French key is removed. English and the 11 other catalogs stay byte for byte as they were. `--check` then lists only the three `[TODO]`s left to translate.
- A second run changes no file.

Making the sync plural-blind again (the original bug) fails two of the three. The suite runs in about 2 s, in the node environment.

Together with the unit tests:
- `sync-locale.test.ts`: plural sync, drift, and AST edits for every catalog shape.
- `catalog-status.test.ts`: copies, the allowlist, `[TODO]` and half-translated messages.
- The CI guards that now share their predicates: `translations.test.ts`, `locale-stray-english.test.ts` and `plural.test.ts`.

Removed `scripts/__tests__/prepare-translations.test.ts` and `prepare-translations.edge-cases.test.ts` (98 tests). Neither imported the script. Every case asserted on literals defined inside the test, and several encoded behavior this milestone removed: "TARGET_LOCALES has 12 locales", plain key-set sync, `src/common/locales` paths. The suite total moves from 6,085 to 5,990.

Gates: dashboard `format:check`, `lint` (including `i18n:check`), `test` and `build` pass.
