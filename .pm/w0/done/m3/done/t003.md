## Objective

Add a read-only `--check` mode that exits non-zero when any catalog is missing a key, carries an obsolete key, has lost a plural form, or still has a `[TODO]` marker, and run it in dashboard CI.

## Context

- Dashboard CI: `.github/workflows/ci-dashboard.yml` runs `yarn format:check`, `yarn lint`, `yarn test`, `yarn build`.

## Steps

1. Implement `--check` with no writes and a readable list of offenders.
2. Wire it into an existing CI step (a script in `yarn lint` or a vitest wrapper).
3. Add fixtures that fail each way.

## Files

- dashboard/scripts/prepare-translations.ts
- dashboard/package.json
- dashboard tests

## Acceptance criteria

- [x] `--check` passes on `main` and fails on each fixture.
- [x] CI runs it.

## Out of scope

- Blocking on untranslated-but-not-`[TODO]` messages beyond the whole-copy rule.

## Done (2026-10-17)

`yarn i18n:check` (`prepare-translations.ts --check`) reports, without writing, everything a `yarn i18n:prepare` run would change, plus every `[TODO]`. It exits 1 when there is anything:
- keys code uses that English lacks;
- keys a locale's catalog is missing, its own plural forms included;
- keys a locale no longer needs;
- messages still marked `[TODO]`.

It reuses the sync's own planning (`readCatalogPair`, `missingEnglishKeys`, and `catalogDrift` in `scripts/lib/sync-locale.ts`), so passing the check means a run writes nothing. It works per catalog file, which `translations.test.ts` does not: that test compares key sets aggregated per language.

CI: `yarn lint` (the dashboard workflow's lint step) now ends with `yarn i18n:check`, about 2 seconds.

Found on the way: `tsx` is not a declared dependency, only hoisted from `@tanstack/router-generator`. Yarn Berry exposes only declared binaries, so `yarn i18n:prepare` and `yarn i18n:flatten` failed with "command not found: tsx". All three i18n scripts now run as `node --import tsx …`, the convention `search-console-report` already uses. That needs no new dependency. Declaring `tsx` directly would be sturdier, but adding a dependency needs the user's approval.

Evidence:
- On `main`: "Translation catalogs are in sync", exit 0.
- With a German key deleted, an obsolete German key added, a Russian `_few` deleted and a French `[TODO]`, it listed exactly those four and exited 1.
- `scripts/__tests__/sync-locale.test.ts` adds `catalogDrift` fixtures for a clean catalog and for each failure kind. Disabling `[TODO]` detection fails its case.

Gates: dashboard `format:check`, `lint` (including `i18n:check`), `test` and `build` pass.
