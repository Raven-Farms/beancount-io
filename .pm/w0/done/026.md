# Make a date-filtered Journal export load: carry opening balances or drop dependent assertions

**Severity:** minor. **Estimate:** 45–60 minutes in the ledger service plus a bean-check round-trip test. **Owner:** `backend-cluster/ledger` (`ledger-journal-service.ts` `plaintextJournal`), the source of the dashboard Journal **Export** download. **A1/A2:** the export is a `.beancount` file that users and agents will run `bean-check`/`bea check` on. A period export that fails on load looks like broken data.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `575a8798`. QA-owned headless Chromium, authenticated. Read-only (export is a GET-style download). Checked with `cli/.venv/bin/bean-check` (Beancount 3).

1. `/ledger/open_ledger/example/journal?time=2016` → **Export** → **Export**. The dialog promises "source transactions and balance assertions narrowed by the selected date, account, and search expression".
2. `bean-check` on the file reports **29 "Balance failed"** errors and **3 "No position matches"** lot-reduction errors (e.g. selling `VHT` lots bought in 2015). Exit status 1.
3. Same with the synthetic ledger at `time=2026-08`: `Balance failed for 'Assets:Cash': expected 49.75 USD != accumulated -90.25 USD`.
4. Control: the unfiltered export of `open_ledger/example` passes `bean-check` with 0 errors.

## Root cause

`plaintextJournal` (`backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts` ~649–695) clamps the directives to the window. That produces the `S`-flag opening-balance summarization transactions, but the loop then **skips** every transaction whose flag is in `PLAINTEXT_EXCLUDED_FLAGS = {P, S, T, C, U, R, M}` (:217) while still emitting every in-window `balance` directive. The file therefore asserts balances that it gives no way to reach, and reduces lots it never opened. `pad` directives aren't emitted either, so pad-dependent assertions can't hold even unfiltered (source-traced; the example ledger has no pads).

## Fix

When a `time` (or account/filter) narrowing is present, emit the clamp's opening summarization (the `S` transactions, with their `{cost}` lots) so the window is self-consistent. Alternatively, omit balance assertions and say so in a header comment, but then lot reductions still fail, so carrying openings is preferred. Emit `pad` directives that the emitted assertions depend on. Keep the unfiltered export byte-identical to today's apart from those additions, and keep the title escaping and root-name options.

Acceptance: exports of `open_ledger/example` for `time=2016`, `time=2017-03`, and the synthetic ledger's `time=2026-08` pass `bean-check` with 0 errors, and their transaction totals for the window are unchanged. A round-trip test in the ledger package parses the export of a fixture with a pre-window lot and an in-window assertion. Adapter/REST parity is kept if the export has other surfaces.
