## Done (2026-10-18)

Ran `/simplify` over 620ae4bea, ecfea5880 and e2a6116fd, with four reviewers: reuse, simplification, efficiency and altitude.

Fixed:
- **Reuse:** the reset page now calls the auth feature's existing login redirect instead of `hardNavigate`. That is logout's `redirectToLoginAfterLogout`, moved to `dashboard/src/features/auth/lib/redirect-to-login.ts` as `redirectToLogin` and shared by both pages. It uses `location.replace`, so Back no longer returns to the reset page whose token was just spent. The `hardNavigate` doc change from t003 is reverted.
- **`oauth-grant-model/types.ts`** imports `DbExecutor` from `@/drizzle/drizzle`, like the newer models, instead of a local `any`.
- **`revokeAllForUser`** builds the user condition once.
- **Tests:** the reset page test drops the now-dead router `navigate` mock. The reset fake's unused committed-state fallback and the SQL-capture fake's unused `config.values` branch are removed.

Skipped, with reasons:
- **Indexing the account column for the DELETE.** It scans the table once per reset, a table the hourly sweep keeps small. An index would cost every OAuth write.
- **A shared "end every credential" operation for reset and account deletion.** Account deletion is outside this diff; [w0/054](../../../054.md) adds its call and can extract the operation then.
- **A shared helper for the `userId:ledgerId` accountId format.** SQL `split_part` cannot share a JavaScript helper.
- **Clearing the auth cookie in the `resetPassword` resolver.** The browser that opens a reset link may be signed in as someone else, whose session must survive. A revoked cookie is already refused.
- **Replacing the transaction fake with call assertions.** The fake is what proves all-or-nothing behavior.
