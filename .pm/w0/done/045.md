# In Persian (RTL), text inputs styled with `LEADING_TEXT_ALIGN` stay pinned to the physical left — Profile fields and the Payee input put the caret and placeholder on the trailing edge

**Minor · mobile · 30–45m · A2.** Native mobile QA, 2026-10-15, `main` at `22aec290`, development build `io.beancount.ios` (JS `1.20261002.50`) on iPhone 17e / iOS 26.5, light theme, Persian (فارسی) selected in **Settings → Language**, then **Restart now** so the app relaunched right-to-left (restored to English afterwards). Authenticated production session at `https://beancount.io/` with the dedicated QA account. View only; nothing was saved.

## Repro

1. **Settings → Language → فارسی → Confirm → اکنون دوباره اجرا کن** (restart). The app relaunches mirrored: back chevron on the right, Browse ledgers tabs reversed, search icon on the right. All of that is correct.
2. Open **Profile** (`beancount:///(app)/profile`). Each card's label (**نام**, **نام خانوادگی**, **نام کاربری**) is right-aligned, but the field inside it renders at the **left** edge: the Persian placeholder **تنظیم نشده** sits left, and so do **puncsky** and the email.
3. Open the **Payee** input (`beancount:///(app)/payee-input`, also reached from New Transaction → Payee). The placeholder **لطفاً وارد کنید...** and the caret sit at the left edge, while the suggestion rows below are mirrored correctly (clock on the right, names right-aligned).

**Expected:** in an RTL layout, an input's text, placeholder and caret start at the leading (right) edge, matching its label and the rest of the mirrored screen. LTR ledger data typed into it (a username, a payee) should still sit at the leading edge, which is the purpose of `LEADING_TEXT_ALIGN`.
**Actual:** inputs stay on the physical left in both directions.

## Root cause

`mobile/src/common/rtl.ts:118–140` defines `LEADING_TEXT_ALIGN = "left"`. The comment justifies it because "iOS swaps left and right whenever the layout is right-to-left (`RCTTextAttributes.mm`)". That holds for `Text`: the Profile labels, which use the same constant, do render right-aligned. It does not hold for `TextInput` in this build. Inputs styled with it render physically left in RTL:

- `src/screens/profile/profile-screen.tsx` (`styles.input` / `styles.label` both use the constant; the label mirrors, the input does not)
- `src/components/text-input-screen/index.tsx:97` (Payee and Narration)

Other `TextInput`s that import the constant and need the same check (not exercised): `create-ledger-screen.tsx`, `add-budget-screen.tsx`, `open-account-screen.tsx`, `ledger-selection/index.tsx` (search), `ledger-file-browser-screen/index.tsx`, `agent-screen.tsx`.

## Fix

Keep `LEADING_TEXT_ALIGN` for `Text`. Add an input-specific value resolved at render, e.g. `leadingInputTextAlign() → isRtlLayout() ? "right" : "left"` (inputs are not swapped, so they need the explicit branch the comment forbids for `Text`), and document the distinction in `rtl.ts`. Apply it to every `TextInput` listed above. Extend `rtl.test.ts` with a guard that `TextInput` styles do not use `LEADING_TEXT_ALIGN`. Verify on device in Persian, after the restart, for Profile, Payee/Narration, New Ledger, Open Account and Browse search, plus an English control.

## Blast radius

Persian users on every form input. English and other LTR locales are unaffected. Ledger text alignment in lists (accounts, rows) is unaffected: those are `Text`.

**Resolved 2026-10-17** — In Persian, inputs now start at the leading (right) edge.

What changed:
- New `leadingInputTextAlign()` in `rtl.ts` returns `"right"` under RTL and `"left"` otherwise. It is the explicit branch `Text` must never take, because an iOS `TextInput` gets no left/right swap.
- `LEADING_TEXT_ALIGN`'s documentation now says it is for `Text` only.
- Applied to the leading-edge inputs: Profile (all three fields), the Payee/Narration screen (`text-input-screen`, which had no alignment at all), Create Ledger (both inputs), Browse ledgers search, and the Ask AI composer.
- Profile's read-only email is a `Text` that reused the input style. It gets `LEADING_TEXT_ALIGN` back, so iOS doesn't flip it to the trailing edge.

Verified on iPhone 17e after switching to فارسی and restarting:
- **Profile:** placeholders, the username and the email start at the right edge under their mirrored labels.
- **Payee:** the placeholder "لطفاً وارد کنید..." sits at the right edge.
- **English control:** after switching back to English and restarting, the layout is unchanged.
- The device was left in English.

Tests:
- `rtl.test.ts`: the input branch by direction.
- `rtl-input-align.test.ts`: walks every `.tsx`. No `TextInput` may use `LEADING_TEXT_ALIGN`; the five screens' inputs must use `leadingInputTextAlign()`; no `Text` may end on the input value. That last check caught the email.

All fail on the previous code. Mobile only.

Not covered here, for follow-up: Open Account's sub-path input and Add Budget's right-aligned amount (not exercised in RTL). On Payee, the "Suggestions" caption is a `Text` that still sits at the left, and its letter spacing breaks the Persian joins.
