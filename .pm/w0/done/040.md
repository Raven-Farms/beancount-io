# Add Budget's header Done skips the shared font-scale cap, so at accessibility sizes it renders larger than every other form's header action

**Minor · mobile · 10–15m · A2.** Native mobile QA, 2026-10-15, `main` at `22aec290`, development build `io.beancount.ios` (JS `1.20261002.50`) on iPhone 17e / iOS 26.5, light theme, English. Text size `content_size accessibility-large` (AX2, the supported ceiling per `.pm/DO_NOT_DO.md`); restored to `large` afterwards. Authenticated production session at `https://beancount.io/` with the dedicated QA account, on a synthetic ledger the account owns. View only; nothing was submitted.

## Repro

1. Set the text size to AX2 (`accessibility-large`).
2. On a ledger you can write, open **Budget → +** (or the inspected route `beancount:///(app)/add-budget`).
3. The header **Done** renders at full body scale, visibly larger than the screen title **Add Budget** beside it.

Control at the same size: **Open Account**, **New Ledger**, **Edit Transaction**, **Filters** and the file editor keep their header actions at the capped size, smaller than or level with the title.

Triage note: the original filing also reported row labels breaking mid-word and the date losing its year. Those reproduce only at AX5 and are out of scope under the AX2 ceiling. At AX2 the rows read whole words and the full date (`2026-10-15`).

**Expected:** Add Budget's header action follows the same cap as every other form header.
**Actual:** it grows without the cap.

## Root cause

`mobile/src/screens/add-budget-screen/add-budget-screen.tsx:274–292` renders the **Done** `<Text>` without `maxFontSizeMultiplier={headerActionMaxFontSizeMultiplier}` (`src/common/theme/typography.ts:105`, 1.4×). Every other form header applies it: `edit-transaction-screen.tsx`, `transaction-filters-screen.tsx`, `create-ledger-screen.tsx`, `multi-postings-transaction-screen.tsx`, `open-account-screen.tsx`, `text-input-screen`, `picker`. [w3/151](../../w3/done/151.md) and [w3/204](../../w3/done/204.md) listed Add Budget among the header consumers to inspect. Their fix (`109d95ae`) changed only `FormRow`'s accessibility value in this file, and `src/__tests__/header-action-font-scale.test.ts` covers only Edit Transaction, New Ledger and the file editor.

## Fix

Add `maxFontSizeMultiplier={headerActionMaxFontSizeMultiplier}` to the header **Done** text. Extend `header-action-font-scale.test.ts` to cover `add-budget-screen.tsx`, ideally by asserting over every screen that renders a `headerRight` text action, so the next new form cannot skip it. Verify at default and AX2, in light and dark.

## Dedupe

[w3/151](../../w3/done/151.md) and [w3/204](../../w3/done/204.md) are the predecessors (done); this is the consumer they did not reach. No open item.

## Unverified

Dark theme at AX2; the `Update Budget` variant (same component); Android font scaling.

---

**Resolved 2026-10-17** — Add Budget's header **Done** now carries `maxFontSizeMultiplier={headerActionMaxFontSizeMultiplier}`.

- **Same fix elsewhere:** the Quick Add next screen (`add-transaction-next-screen.tsx`) had the same uncapped header Done, which the new guard found, and is capped too.
- **Guard:** `header-action-font-scale.test.ts` now walks every `.tsx` under `src`. Every `<Text>` rendered inside a `headerRight` must carry the shared cap. It covers at least 7 form headers, including Add Budget, so the next new form cannot skip it. Without the fix it fails and names both files.
- **Verified on iPhone 17e at AX2 (`accessibility-large`):** before, Done rendered far larger than the "Add Budget" title; after, it sits at the capped size beside it. Text size was restored to `large`. Mobile only.
