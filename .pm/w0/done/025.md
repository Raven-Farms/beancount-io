# Show the OpenSSH key format (`ssh-ed25519 …`) in the New SSH key dialog, not a PEM block

**Severity:** minor (onboarding copy). **Estimate:** 20–30 minutes (2 keys × 15 locales, plus a rendered-copy test). **Owner:** `dashboard` (user-settings/ssh-keys). **A2:** hosted-to-local ledger workflows require an SSH key (`.pm/DO_NOT_DO.md`), so this dialog is a mandatory onboarding step. It currently tells users their key "should start with `-----BEGIN PUBLIC KEY-----`", which is not what `ssh-keygen` produces or what `~/.ssh/id_ed25519.pub` contains.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `575a8798`. QA-owned headless Chromium, en-US, authenticated owner. Every mutation was aborted by a route guard, so no key was added.

Open `/settings/ssh-keys` → **New SSH key**. The Public Key field's help reads: **"Paste your public key content here. It should start with "-----BEGIN PUBLIC KEY-----"."** The placeholder is a PKCS#8 PEM block (`-----BEGIN PUBLIC KEY-----\nMIIBIjANBgkqh…`). A user holding the standard `ssh-ed25519 AAAAC3Nza… user@host` line is told it's the wrong shape.

## Root cause

`dashboard/src/features/user-settings/locales/en.ts:337–346` (`userSettings.publicKeyDescription`, `userSettings.publicKeyPlaceholder`), and the same text in the other 14 locales. The dialog's test mocks these keys with the intended copy (`__tests__/key-create-dialog.test.tsx:26–28`: placeholder `ssh-rsa AAAA...`, description "Paste your public SSH key (starts with ssh-rsa or ssh-ed25519)"), so no test sees the text that actually ships.

## Fix

Change the description to say the key normally starts with `ssh-ed25519` or `ssh-rsa`, and how to print it (e.g. `cat ~/.ssh/id_ed25519.pub`). Use an OpenSSH placeholder (`ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA… you@example.com`). Optionally mention that PEM public keys are also accepted. w3/078 confirmed the hosted Gitea converts supported PEM keys, so don't add client-side rejection. Render the dialog with the real English catalog in a test.

Acceptance: the dialog's help and placeholder show the OpenSSH form in all 15 locales. A rendered test with real translations asserts it. Dashboard gates pass.
