## Done (2026-10-18)

Ran `/simplify` over 993524f70 and bf946617f, with four reviewers: reuse, simplification, efficiency and altitude.

Fixed:
- **Altitude: the count cache moved to the engine and is keyed by content.** t002 keyed the cache by `owner/repo@headSha`, but every committed write moves HEAD to a commit nobody has counted. A stream of writes therefore still parsed every commit twice. `countLedgerDirectives` (`foundation/rustledger/engine.ts`) now memoizes in a `CoalescingLruCache<number>(256)` keyed by `buildSnapshotCacheKey` (file contents, entry point, today), like `parseLedgerFiles`' snapshot cache. The map write N projects is a hit when it returns as write N+1's committed ledger. `core/directive-limit.ts` loses its SHA-keyed cache.
- **Efficiency: the current count is computed only when needed.** The precheck counts the projected ledger first and returns if it is within the limit. The current ledger is counted only for a write past the limit, to tell crossing or growing from shrinking. A within-limit write no longer parses the committed ledger at all.
- **Reuse:** `countDirectives(content)` calls `countLedgerDirectivesInProcess` instead of repeating its body.
- **Simplification:** dropped the worker-pool backpressure test for `directive-count`, which re-tested the shared `enqueue`. The core tests now read the counter's own results instead of recounting with a second regex.

Skipped, with reasons:
- **Redis-backed `CacheHelper` for the count.** A Redis round trip per check would cost more than the parse it saves on another replica.
- **Peeking the count before loading the file map in the push gate.** It needs a new cache API and a sequential HEAD-then-map load, and the file map is a cached Redis read.
- **Overlapping `getMaxDirectives` with the load.** Paid and exempt writes would pay a wasted file-map load.
- **A shared test helper for the dated-line counting stub.** Two small copies.

Tests:
- `foundation/rustledger/__tests__/count-ledger-directives.test.ts` (WASM loader stubbed): one parse per content; the next write's committed map served from the last write's projection; new content reparsed; a failed count not remembered. Defeating the cache key fails 2.
- `core/__tests__/directive-limit-current-count.test.ts` (renamed from `-count-cache`): a within-limit write counts only the projected ledger; a past-limit growing write counts both and is refused; a shrinking write on an over-limit ledger passes; a paid ledger counts nothing; the push-gate count and its commit; fail open with a log line on a pool refusal.

A real worker thread counted a two-file ledger as 2, and the same content again as 2 from the memo.

Gates: ledger `typecheck`, `eslint`, `lint:deadcode`, `test` (1353), `build` and `verify:rustledger` pass.
