## Objective

Make `countMap` use the worker-pool count, and stop recounting an unchanged commit: the precheck's "current" total is cached by repository and head SHA, so a write parses the projected map only.

## Context

- `backend-cluster/ledger/src/core/directive-limit.ts`: `countMap` (:36-39), `countDirectivesForRepo` (:58-74, serves `GET /ledgers/:owner/:repo_name/directive-count` in `api/ledgers.ts:238` for the git-push gate), `checkDirectiveLimitForFileChanges` (:101-146).
- `countDirectivesForRepo` already resolves the head SHA (`resolveHeadShaCoalesced`); the precheck loads the file map (`loadCachedFileMapForRepo`, which is cached by SHA) but not the SHA itself.
- The precheck's `try` fails open on any error (`log.warn("directive-limit pre-check failed open")`). Keep that, so a queue-full or timeout lets the write through as today, and keep it logged.

## Steps

1. Replace `withLedger` in `countMap` with the t001 export.
2. Cache the current count keyed by `owner/repo@sha` (small bounded LRU, or the existing build cache), and use it from both the precheck and `countDirectivesForRepo`.
3. Leave the projected count uncached (its content is new per write).

## Files

- backend-cluster/ledger/src/core/directive-limit.ts

## Acceptance criteria

- [x] Two writes against the same head SHA count the current map once.
- [x] A push that moves the head invalidates the cached count.
- [x] A worker timeout on the precheck lets the write through and logs it.

## Out of scope

## Done (2026-10-18)

Step 1 (`countMap` → worker pool) shipped with t001 in `993524f70`.

`core/directive-limit.ts` now has one `loadCommittedCount(client, owner, repo)` that both the write precheck and `countDirectivesForRepo` (`GET …/directive-count`, the git-push gate) use. It resolves HEAD and loads the committed file map in the same `Promise.all`, which is still one Gitea round trip: both go through `resolveHeadShaCoalesced`, as `count-directives-rpc-cost.test.ts` pins. It returns the count from a `CoalescingLruCache<number>(256)` keyed by `owner/repo@sha`.

So a commit is counted once however many writes and push checks hit it, concurrent ones included. A push changes HEAD and so the key. A repository with no commits is counted uncached. The projected map is still counted per write, and a failed count is never cached (the cache drops rejections). The precheck's fail-open `catch` and log line are unchanged.

Tests (`core/__tests__/directive-limit-count-cache.test.ts`; the counter is stubbed to count dated lines, so each call shows which map it saw):
- two writes against one commit count the current map once and the projected one twice;
- a moved HEAD counts again;
- the push gate's count and a later write share one count;
- two repositories at the same commit do not share one;
- a `RateLimitedError` from the pool fails open with "directive-limit pre-check failed open";
- a refused count is not remembered.

Defeating the cache key fails 2 of them.

Gates: ledger `typecheck`, `eslint`, `lint:deadcode`, `test` (1350) and `build` pass.
