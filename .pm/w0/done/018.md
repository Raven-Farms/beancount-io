# Answer missing receipt assets and malformed OAuth links with 404/400, not a 500 "unexpected error"

**Severity:** minor. **Estimate:** 45–60 minutes. **Owner:** `dashboard` (routes `ledger_assets.$ledgerRepoId.static.$.tsx`, `oauth.*consent.tsx`, root error page). **A2/A3:** receipt links written into ledgers (`/ledger_assets/<repo>/static/<file>`) and OAuth/connector links are entry points users follow from outside the app. A missing or malformed target shouldn't look like a server crash, or page on-call as one.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `575a8798`. QA-owned headless Chromium, signed in and signed out. Read-only. Each case reproduced on fresh loads.

| URL | HTTP | page shown | console |
| --- | --- | --- | --- |
| `/ledger_assets/999999/static/nope.png` | **500** | "Something went wrong — We encountered an unexpected error" + Try Again | `Error: Ledger with ID '999999' not found` |
| `/ledger_assets/1/static/nope.png` (also signed out) | **500** | same | `Error: Ledger not found` |
| `/ledger_assets/abc/static/x` | **500** | same | `Variable "$ledgerRepoId" of non-null type "Int!" must not be null` |
| `/oauth/consent` (no `uid`) | **500** | "Invalid URL Parameters" + Try Again | ZodError `uid` expected string |
| `/oauth/consent?client_id=x&redirect_uri=…` | **500** | same | same |
| `/oauth/identity-consent`, `/oauth/mobile-consent` (no params) | **500** | same | ZodError `uid` (and `scope`) |

Controls: `/ledger/<owner>/does-not-exist` and `/settings/nope` return **404** "Page not found". `/auth/reset-password?token=<bad>` returns a friendly "Token Expired" page. Signed-out ledger routes redirect to login.

## Root cause

- `dashboard/src/routes/ledger_assets.$ledgerRepoId.static.$.tsx`: `beforeLoad` does `Number(params.ledgerRepoId)` (NaN → `null` variable), awaits `GetLedgerAssetDownloadUrl`, and throws a generic `Error` when no URL comes back. GraphQL `NOT_FOUND` errors propagate as thrown errors. The root `ErrorPage` (`common/root-route/error-page.tsx`) renders them as "unexpected error", and SSR answers 500.
- `routes/oauth.consent.tsx` (and identity/mobile siblings): `validateSearch: z.object({ uid: z.string(), … })` throws on a missing `uid`. `ErrorPage` detects a validation error by message substring and shows "Invalid URL Parameters", but the response status stays 500 and it still offers "Try Again", which can't help.
- The producer of receipt links is `backend-v2/src/features/ledger/workflow/ledger-receipt-workflow.ts:246`, which writes `${dashboard.url}/ledger_assets/${repoId}/static/${filename}` into the ledger. Those links outlive the asset if it's moved or deleted, or if the reader lacks access.

## Fix

- Asset route: reject a non-integer `ledgerRepoId` and map `NOT_FOUND`/`FORBIDDEN` to TanStack `notFound()` (404 "This attachment isn't available"). Map `UNAUTHENTICATED` to the existing login redirect with `next`, and keep 5xx for genuine service failures.
- OAuth routes: treat a failed search validation as a 400 with a specific "This sign-in link is incomplete or expired — start again from the app" message and no Try Again button. Set the SSR status accordingly, and don't log it as an application error.
- Keep `ErrorDetails` for real failures.

Acceptance: the six URLs above return 404 (assets) or 400 (OAuth), with a specific message and no Try Again. A signed-out visitor to a private-ledger asset link is sent to login. A valid asset link still redirects to its signed download URL. Route tests cover NaN, not-found, and unauthenticated. Dashboard gates pass.

---

**Resolved 2026-10-15** — Receipt asset links (`routes/ledger_assets.$ledgerRepoId.static.$.tsx`) now answer 404 "Attachment unavailable" for a malformed repo id or a missing/forbidden ledger or file, keeping 5xx for real failures and the signed-out redirect path; the three OAuth consent routes answer 404 "Sign-in link incomplete" (no Try Again) when `uid`/`scope` are missing or malformed, via `beforeLoad` `notFound()`. Status 404 rather than the note's suggested 400: TanStack Start exposes not-found but no per-route client-error status, and 404 removes the 500. Verified on a local dev server against the hosted API; `routes/__tests__/ledger-assets-route.test.ts` covers the mapping. Copy in 15 locales. Shipped in the commit that moved this note to `done/` (`dashboard`).
