# Read-only ledgers offer "Update prices on the web" in the Home holdings sheet, which lands on a page that cannot update them

**Minor · mobile · 15–25m · A2.** Native mobile QA, 2026-10-15, `main` at `22aec290`, development build `io.beancount.ios` (JS `1.20261002.50`) on iPhone 17e / iOS 26.5, light theme, English, default text size. Authenticated production session at `https://beancount.io/` with the dedicated QA account. Public read-only ledger `open_ledger/example`. Report-only run; no ledger writes.

## Repro

1. Select `open_ledger/example` in the drawer (it lists under **Current ledger · OPEN_LEDGER**, not under the signed-in user's own ledgers).
2. On **Home**, tap the Net Worth caption **"At market value · 6 prices not updated since Sep 8, 2017 · 1 not in total ›"**.
3. The **Holdings and prices** sheet opens and lists six stale holdings and `-13 VACHR` (Not in total). Its only action is **Update prices on the web**.
4. Tap it. An in-app browser opens `beancount.io/ledger/open_ledger/example/commodities` signed out (**Log In / Sign Up**) and shows read-only price-history charts. Signing in there would not help either: the signed-in user cannot write to this ledger.

Repeated after a cold relaunch with the same result.

**Expected:** a ledger the user cannot write gets no call to action that implies they can update its prices. The sheet should keep the holdings list and close with **Done**, the same way Home already hides **Add transaction** for read-only ledgers.
**Actual:** the sheet always offers **Update prices on the web** to a signed-in reader, whatever their permission.

## Root cause

- `mobile/src/screens/home-screen/home-screen.tsx:64` already computes `const { canWrite } = useLedgerAccess();` and passes it to `RecentTransactionsCard` (`:262`, `onAddTransaction={canWrite ? onAddTransaction : undefined}`).
- The same screen renders `<ValuationSheet valuation=… ledgerId=… onClose=… />` at `:253–257` without any access information.
- `mobile/src/components/valuation-sheet/index.tsx:248–262` renders the footer button for every non-guest reader (`guest ? signIn : updatePricesOnWeb`), and `openCommodities` (`:170–177`) opens the commodities URL unconditionally.

## Fix

Pass `canWrite` (or an `onUpdatePrices` callback that is `undefined` when the reader cannot write) from `HomeScreen` to `ValuationSheet`. Render the footer action only for writers. Keep the guest branch (**Sign in**) unchanged, and keep the holdings list visible to every reader. No API change; mobile only.

## Blast radius and controls

- `ValuationSheet` has one production caller (`home-screen.tsx`). Signed-out examples reuse it through the guest branch, which is correct.
- Working control: Home's empty-state and recent-transactions **Add transaction** actions already gate on `canWrite`. Prior fixes of the same class: [w3/114](../w3/done/114.md) (read-only account filter offered Create) and [w3/121](../w3/done/121.md) (read-only budget history offered Delete).
- Adjacent: for an owned ledger the button still opens a signed-out in-app browser, so the owner must sign in again on the web. That is existing behavior of `expo-web-browser` sessions, not part of this fix.

## Dedupe

Searched `.pm/**` for `updatePricesOnWeb`, "Update prices", "holdings", "valuation sheet" and read-only CTAs: no open or completed item covers this sheet. `abfc55c1` removed iOS **Open in browser** from the ledger menu, but this button was out of its scope.

## Unverified

Android; VoiceOver; dark theme; an owned ledger's web flow after signing in.

---

**Resolved 2026-10-17** — `ValuationSheet` takes a `canWrite` prop, and `HomeScreen` passes the same `useLedgerAccess()` value that already gates Add transaction. The footer shows **Update prices on the web** only to readers who can write the ledger. Guests still get **Sign in**, and every reader still sees the holdings list. Verified on iPhone 17e: the public `open_ledger/example` sheet ends after its holdings, while the owned `puncsky/example` still offers the button. `valuation-sheet-accessibility.test.ts` covers writer, read-only reader, guest and holdings visibility. `empty-ledger-actions.test.ts` checks that Home passes `canWrite` true only for writers and admins, and false for readers, guests and a failed permission query. Both fail without the fix. Mobile only.
