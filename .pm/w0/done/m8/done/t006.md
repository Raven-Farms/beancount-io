## Objective

Add meaningful tests for what this milestone shipped:
- the archive service reaches Gitea with the right header for signed-in and anonymous callers, and never the ledger service;
- 404, non-OK and header-deadline failures map as before;
- a destroyed response body aborts the upstream request;
- the MCP blob refuses over the cap with and without `Content-Length` and stops reading once past it.

Reverting t001 or t003 must fail them. No tautological or snapshot-everything tests.

## Outcome

Every behaviour runs against a real HTTP server standing in for Gitea (`src/features/ledger/service/__tests__/archive-origin.ts`), with no node-fetch or `fetch` mocks:

- **Gitea header, never the ledger service:** `ledger-archive-service.test.ts` checks the request path `/api/v1/repos/{owner}/{repo}/archive/{archive}`, the caller's Basic header, and no `Authorization` at all for an anonymous public read. The service's config holds only `gitea`. The REST adapter suites (`archive-routes`, `download-archive-handler`, `archive-proxy`) assert the same path.
- **Failure mapping:** Gitea 404 maps to `NotFoundError`; 401 and 500 map to `ServiceUnavailableError`. A stalled origin fails as unavailable when the 90 s deadline fires, and its socket closes. The deadline is cleared once headers arrive.
- **Destroyed body:** destroying the service's body closes the Gitea socket. New for this task: `archive-routes.test.ts` "ends the Gitea request when the caller hangs up mid-download" aborts a real HTTP client through Koa and observes the upstream socket close.
- **MCP cap:** `archive-blob-cap.test.ts` covers exactly-the-cap with and without `Content-Length`, an over-cap `Content-Length` on a body that never finishes, and an endless undeclared body. Each is refused with `OPERATION_NOT_ALLOWED` and the `archive-download-url` hint, and the upstream socket closes.
- **Ledger:** `archive-route-retired.test.ts` holds the removed route at 404.

**Proven real:**

- Pointing the service back at the ledger route with the `Anonymous` marker (t001 reverted) fails 8 tests across the service and three REST suites.
- Removing both cap checks (t003 reverted) fails 2 of the 4 blob-cap tests: the over-cap ones, which no longer refuse.
- Piping the body through a PassThrough fails the hang-up test and the destroyed-body test.
- Dropping the deadline signal fails the deadline test.
- Restoring the ledger route fails the retired-route test.
