# Give the ledger visibility switch an accessible name

**Severity:** major (accessibility; WCAG 4.1.2 Name, Role, Value; axe `button-name`, critical). **Estimate:** 20–30 minutes. **Owner:** `dashboard` (ledger-data/settings). **A2:** the one control that publishes a private ledger is announced to screen-reader users only as "switch, on".

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `575a8798`. QA-owned headless Chromium, 1440×1000, en-US, light and dark, authenticated owner (admin) on a synthetic private ledger. Read-only; the switch was not toggled.

1. Open `/ledger/<owner>/<ledger>/settings`.
2. In the Visibility card, the switch `#visibility-toggle` (`role="switch"`, `aria-checked="true"`) has no accessible name. It has no text, `aria-label`, or `aria-labelledby`, and no `<label for>` points at it. axe-core 4.13 reports `button-name` (critical) in both themes, on every fresh load.
3. The visible "Private Ledger" text beside it is a `<Label>` with no `htmlFor`, so it doesn't label the switch.

## Root cause

`dashboard/src/features/ledger-data/settings/visibility-section/index.tsx:166–203` renders `<Label className="text-base">` without `htmlFor="visibility-toggle"` and `<Switch id="visibility-toggle" …>` without `aria-labelledby` or `aria-describedby`. The label text also flips between "Private Ledger" and "Public Ledger" with the state, so even once it's associated, the switch's name would change when it is toggled.

## Fix

Give the switch a stable name that states what "on" means, e.g. `aria-label={t("page.settings.privateLedger")}` ("Private ledger"), or a constant `<Label htmlFor>`. Point `aria-describedby` at the existing description paragraph so the consequence ("Only you and collaborators can access it" / the public warning) is announced. Keep the admin-only rendering (`LedgerAdminPermission`) and the w3/466 read-only behavior for non-admins.

Acceptance: the accessibility tree names the switch "Private ledger" (localized) with checked state and description, in both states. axe `button-name` passes on `/settings`. A component test asserts `getByRole("switch", { name: /private ledger/i })`. Dashboard gates pass.

## Dedupe

w3/466 (done, `d8bd5112`) made the section read-only for non-admins and didn't touch the switch's name. Searched `.pm/**` for `visibility-toggle`, visibility switch, privacy switch, and button-name: no other item.

---

**Resolved 2026-10-15** — The ledger visibility `Switch` (`features/ledger-data/settings/visibility-section/index.tsx`) is named by the constant `page.settings.privateLedger` ("Private ledger", localized) in both states and described by the visibility paragraph via `aria-describedby`, so it reads "Private ledger, switch, on/off" with its consequence. `__tests__/visibility-copy-buttons.test.tsx` asserts the name, state and description for public and private ledgers and fails on the old markup. Shipped in the commit that moved this note to `done/` (`dashboard`).
