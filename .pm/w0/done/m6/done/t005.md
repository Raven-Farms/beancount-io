## Done (2026-10-18)

Ran `/simplify` over afe16011f, c4afcd8ef, 324113c96 and a09e396e0, with four reviewers: reuse, simplification, efficiency and altitude.

Fixed:
- **Altitude: the commit client's type now says what the check reads.** `GiteaFileCommitClient` (`ledger/.../commit-ledger-files.ts`) includes the loader's `GiteaCommitClient` repos, and `checkDirectiveLimitForFileChanges` accepts it as well as the full API type. Both casts are gone. Before, a client that matched the narrow type compiled but made the check fail open silently.
- **Altitude: the exemption can no longer be forgotten.** `commitLedgerFiles(…, message, { directiveLimit, rawCreates? })` takes an options object with `directiveLimit` required, instead of a 7th positional argument with a `[]` placeholder. `LedgerEntryService` now carries the request's exemption too (`servicesForRequest` builds both services with it).
- **Efficiency: one tier lookup per commit.** The tier limit is looked up once per commit, started before the first read, and every CAS attempt reuses it (`DirectiveLimitOptions.maxDirectives`). Before, each attempt asked backend-v2, a Stripe-backed lookup, again, including for paid ledgers. The retry test now asserts one lookup.
- **Duplication: one limit lookup and one fail-open log line.** `evaluateDirectiveLimit` and `evaluateMergeDirectiveLimit` share `limitOrVerdict`, so the lookup and its fail-open and unlimited rules exist once. `assertMergeWithinDirectiveLimit` turns any failure into an `unknown` verdict and logs it in one place.
- **Dashboard: an action keeps its own failure text through the shared helper.** `getErrorMessageKey(error, fallbackKey)` lets an action keep its own failure text. The pull-request page and the root error page use it instead of comparing against the literal `"common.errors.generic"`.
- **Comments and tests.** The four copied "writes to Gitea directly" comments are now one note on `checkDirectiveLimitForFileChanges`. The two copied `NO_DIRECTIVE_LIMIT` stubs became an explicit mock of the merge verdict.
- **Docs.** The approve route's description is a plain concatenation. `backend-v2/src/features/gitea/AGENTS.md` now says `policy/` also serves the merge verdict and how it differs from the push gate. `scripts/check-agent-guidance.py` passes.

Skipped, with reasons:
- **`sha: ref ?? head` in the count response.** It names the commit actually counted.
- **Starting the merge's limit lookup alongside the pull-request read, and skipping the duplicate count when the merge base is HEAD.** Merges are rare, and the duplicate is a memo hit in the ledger.
- **Routing `files.ts` and `entries.ts` through `commitLedgerFiles`.** Their caller-SHA conflicts, deletes, renames and branch options do not fit the re-read-and-retry model.
- **Shared test fakes across test files.**
