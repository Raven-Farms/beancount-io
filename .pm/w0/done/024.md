# Gate Upload Receipt on write access like Smart Import, and invite anonymous visitors to sign in

**Severity:** minor. **Estimate:** 40–55 minutes including rendered permission tests. **Owner:** `dashboard` (receipt, importer). **A2:** visitors exploring a public example shouldn't be offered a receipt upload that can't be booked. An anonymous visitor shouldn't be told their "permissions could not be confirmed" when what they need is to sign in.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `575a8798`. QA-owned headless Chromium, 1440×1000, en-US. Public `open_ledger/example`, where the QA account can read but not write. Nothing was booked.

1. **Signed-in reader:** `/ledger/open_ledger/example/import` correctly shows "Import unavailable — This ledger is read-only for you…" (w4/193). `/ledger/open_ledger/example/receipt` shows the full upload zone ("Drag and drop your receipt here", **Choose File**, one `input[type=file]`). On the same ledger, Journal's New Entry is hidden.
2. **Anonymous:** `/receipt` shows the same live upload zone. Choosing a 20×20 PNG fires `GenerateTempAssetUploadUrl` → `UNAUTHENTICATED`, and the page then redirects to `/auth/login?next=…/receipt`, dropping the chosen file. After signing in the visitor still has no write access.
3. **Anonymous `/import`:** "Import unavailable — Write access could not be confirmed. Import is unavailable until your ledger permissions are resolved." That reads as an account problem, not "sign in to import".

## Root cause

- `dashboard/src/features/receipt/pages/receipt-page.tsx` renders `ReceiptUploadZone` unconditionally. It never consults `useLedgerPermission().canWrite`, unlike `features/importer/pages/import-page.tsx:26–60`, which w4/193 fixed.
- For anonymous visitors, `import-page.tsx` falls to `importer.access.unresolved` because `ledgerData.permissions` is absent. That key is meant for genuinely unresolved permission reads, not a signed-out visitor.

## Fix

Mirror ImportPage in ReceiptPage: mount the upload zone only with push/admin permission, and show the same accessible read-only notice otherwise, keeping Journal/Files/Query links. For signed-out visitors, on both Import and Receipt, show a "Sign in to import into this ledger" state with a login link that carries `next`. Reserve `unresolved` for authenticated users whose permission read failed. Keep the existing receipt flow unchanged for writers.

Acceptance: a reader and an anonymous visitor on `open_ledger/example/receipt` see no file input. Anonymous Import/Receipt offer sign-in. The owner on their own ledger keeps the full upload flow. Rendered tests cover writer, reader, anonymous, loading, and failed-permission states, following w4/193's tests. Dashboard gates pass.

## Dedupe

w4/193 (done) gated Smart Import only and named anonymous as a tested state but kept the "unresolved" copy for it. Searched `.pm/**` for receipt, read-only, write access, and upload gating: no item covers the Receipt route.
