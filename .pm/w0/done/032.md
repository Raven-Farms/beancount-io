# Recent Changes renders each commit's trailing newline as a blank second line; commit detail shows the raw message and a shrunken "No diff available." box

**Minor · mobile · 20–30m · A2.** Native mobile QA, 2026-10-15, `main` at `22aec290`, development build `io.beancount.ios` (JS `1.20261002.50`) on iPhone 17e / iOS 26.5, light theme, English, default text size. Authenticated production session at `https://beancount.io/` with the dedicated QA account. Public ledger `open_ledger/example`. Report-only run.

## Repro

1. Select `open_ledger/example`, then tap the bell in the header to open **Notifications**.
2. Under **Recent changes**, every row reads the commit subject (e.g. **verify: unaffected ledger still pushes**), then an **empty line**, then **v · Aug 20, 2026 f281c34**. The blank line is about 20pt in every row, so the list shows roughly seven commits per screen instead of ten.
3. Tap the first row. **Commit detail** shows the subject, a blank line, then **Author: v · Aug 20, 2026**. Under **Diff**, the grey **No diff available.** panel spans only the width of its text (about a third of the screen) instead of the full row.

Also reproduced on `open_ledger/crypto-example` in dark appearance: the one-line commits **update** and **Add main.bean** show the blank line, while **Rebuild as a 2025-2026 trader ledger on managed price feeds**, which wraps to two lines, fills the slot with no gap. That is the trailing-newline mechanism below, visible on screen.

GraphQL `listCommits(ledgerId:"open_ledger/example", branch:"main", page:1, limit:4)` returns HTTP 200 with messages such as `"verify: unaffected ledger still pushes\n"`: each one ends in `\n`. `getCommitDetails` for `f281c34` returns the same message with `stats {0,0,0}`, `files: []` and `diff: ""`, so **No diff available.** is the right text for this empty commit; only its layout is wrong.

**Expected:** a row shows the subject (first line) on up to two lines with the author line directly below it. Commit detail shows the subject as its title and any body below it, trimmed. The empty-diff panel spans the content width.
**Actual:** the raw message, trailing newline included, fills the two-line slot. A conventional `subject\n\nbody` message would likewise show the subject plus a blank line and hide the body.

## Root cause

- `mobile/src/screens/notifications-screen/notifications-screen.tsx:323–325` renders `{commit.message}` with `numberOfLines={2}`, and `:312` uses the raw message as the row's `accessibilityLabel`.
- `mobile/src/screens/commit-detail-screen/commit-detail-screen.tsx:201` renders `{commit.message}` verbatim.
- `commit-detail-screen.tsx:274–296`: the diff body sits inside a horizontal `ScrollView`, so `diffContainer` (`:95–97`, the grey background) shrinks to its child's width. With no diff lines, that child is the short `emptyText`.
- Working control: the web dashboard's `dashboard/src/features/git/commits/components/commit-list-item.tsx:72` renders `commit.message.split("\n")[0]`, and `commit-metadata.tsx:32–35` splits the subject from a trimmed extended message.

## Fix

Add a small helper (for example `splitCommitMessage(message) → { subject, body }`: first line trimmed; the rest trimmed, `null` when empty) next to the notifications `formatting.ts` helpers. Use `subject` for the Recent Changes row text and accessibility label. Use `subject` as the commit-detail title, with `body` rendered below it when present. Render the empty-diff text outside the horizontal `ScrollView`, or give it the container's full width, so the panel spans the row. Unit-test the helper on a trailing newline, `subject\n\nbody`, CRLF line endings, and an empty message. Mobile only; no API change.

## Blast radius

`grep` finds exactly two renderers of `commit.message` in `mobile/src`: the two sites above. The guest/examples routes have no Recent Changes screen. Loading skeletons, the ledger-errors section and the error/retry state are unaffected.

**Resolved 2026-10-17** — New `splitCommitMessage` in `notifications-screen/formatting.ts`:
- **Split:** the subject is the first non-blank line. The body is the rest, trimmed, or null when there is none. CRLF and CR count as LF.
- **Reflow:** a body paragraph's hard-wrapped lines are joined. Blank-line breaks, list items (which absorb their wrapped lines), indented code lines and trailer blocks keep their own lines.

Where it is used:
- **Recent Changes:** each row shows the subject for both its text and its accessibility label.
- **Commit detail:** the subject heads the summary, with the reflowed body below it.
- **Empty diff:** "No diff available." now sits outside the horizontal diff scroller, so its panel spans the row.

Verified on iPhone 17e:
- `puncsky/example` rows read subject, then author line, with no blank line.
- `open_ledger/crypto-example` `37814c4` shows its body reflowed, list item included.
- `open_ledger/example` `f281c34` shows a full-width empty-diff panel.
- A commit with a real diff (`8901a6b`) is unchanged.

Tests: `split-commit-message.test.ts` covers trailing newline, subject plus body, CRLF and CR, empty and blank messages, reflow, paragraphs, lists, code and trailers. `commit-message-display.test.ts` checks that neither screen renders a raw message and that the empty-diff text stays out of the horizontal scroller. All 13 fail on the previous code. Mobile only.
