## Done (2026-10-17)

Ran `/simplify` over the milestone's code with four reviewers (reuse, simplification, efficiency, altitude).

Fixed:
- **Structured refusal instead of prose parsing.** The apps regex-parsed an English sentence that crosses three packages, while the ledger already sent `details: {count, detail}`. backend-v2 now throws one `NewLedgerErrorsError` (a `ValidationError` in `shared/errors`) on both write paths, text and entries. It carries the named errors as `newLedgerErrors`, the way UNBALANCED carries `residual`. That reaches GraphQL `extensions` and REST `error.metadata`. Mobile and the dashboard read the field. The duplicated, reworded hint is gone: both refusals word it in one place.
- **Ledger handler.** The projection is checked first. Today's errors are read only when the projection has some, through the existing `getErrors`, so a clean write no longer loads and parses the ledger twice. `updates` is passed as the overlays directly, and the guard is nested.
- **Mobile.**
  - The `wouldBreak` result field and the two screens' copied ternaries are gone. Open Account and Add Budget put the described refusal into the `message` they already return.
  - `describeLedgerRefusal` is the one place that words it.
  - `useLedgerWrite` no longer takes the per-render `t` into its callback dependencies.
  - Reading GraphQL extensions reuses `graphql-error-codes.ts`, through the new `graphQLErrorExtensions` that `graphQLErrorCodes` is now built on.
- Test boilerplate collapsed into local helpers.

Skipped:
- **Loading the file map once for both parses.** After the reorder, the second load happens only on a refusal.
- **Sharing the directive-limit gate's load.** That predates this milestone.
- **Returning before and after errors from the bulk endpoint**, so MCP could drop its post-write bracket. That is an API change between the two services.
- **Classifying an engine `E3001` found by the projection as UNBALANCED.** That changes behavior; the ledger's own balance check already covers ordinary cases.

Removing `newLedgerErrors` from the error fails the REST, GraphQL and text-contract assertions. A clean write is asserted to skip the baseline read.
