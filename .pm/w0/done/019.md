# Tell `bea login` users their device code is unknown or expired, not "information provided is invalid"

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** `dashboard` (auth/device-auth-page). **A1 — Agent-native accounting:** browser device authorization is how the CLI and coding agents sign in. A mistyped or expired code should say so and point back to the terminal.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `575a8798`. QA-owned headless Chromium, 1440×1000, en-US, signed in as the QA owner. No session was approved.

1. Open `/auth/login/device` and type an 8-character code that no terminal issued (`ZZZZZZZZ`). The page submits once the code is complete.
2. `GetCliAuthRequest` returns `{"message":"CLI auth session not found or expired","extensions":{"code":"BAD_USER_INPUT"}}`.
3. The card shows only **"Some of the information provided is invalid. Please check and try again."** with "Use a different code". It doesn't say the code is unknown or expired, or that a new one comes from re-running `bea login`.
4. Same result when opening `/auth/login/device?user_code=ABCD-EFGH` (the prefilled-link form).

## Root cause

`dashboard/src/features/auth/pages/device-auth-page/index.tsx:67–75` renders `t(getErrorMessageKey(error))` for any query error, which maps every `BAD_USER_INPUT` to the shared generic sentence. The page already has the right copy, `auth.cliAuthSessionExpired` ("Session expired or not found."), but uses it only when the query succeeds with a non-pending request (`:80–84`). The server's not-found/expired case comes back as an error instead, so it never reaches that branch.

## Fix

Treat the `GetCliAuthRequest` "not found or expired" `BAD_USER_INPUT` (and `NOT_FOUND`, if the server reclassifies it) as the expired/unknown state. Show a specific localized message, e.g. "This code is unknown or has expired. Run `bea login` again for a new code.", with "Use a different code". Keep generic handling for network and service failures. Don't render the raw server message. Note the per-user attempt budget mentioned in the component: the message must not invite rapid retries of the same code.

Acceptance: an unknown code (typed or via `?user_code=`) shows the specific message in all 15 locales, and "Use a different code" returns to entry. A valid pending code still shows the approve/deny view. Network failure keeps the connection message. Component tests cover each branch, and dashboard gates pass.
