## Objective

The MCP archive resource has to return the archive as one base64 blob in a JSON-RPC response, so it cannot stream. Give it a byte cap, enforced before and while reading, and make the refusal point the agent to the streaming download URL resource that already exists.

## Context

- `backend-cluster/backend-v2/src/features/ai-agent/api/mcp-resources.ts`: `readArchive` (~:102-121) calls `ledgerArchiveService.download` and then `(await response.buffer()).toString("base64")`. The resource is registered as `ledgerArchive` (~:495), URI `beancount://{owner}/{name}/archive/{archive}`, and spends the shared archive-download budget (`server/api/rate-limit.ts`, `ARCHIVE_DOWNLOAD_BUCKET`).
- `ledgerArchiveDownloadUrl` (~:528, `beancount://{owner}/{name}/archive-download-url`) already hands out the authenticated REST URL that streams.
- MCP results use the `{ok:false, error:{code,message,hint}}` envelope; reuse its existing code for a size refusal if there is one.
- `server/api/op-class.ts` already records protocol notes for this operation (GraphQL cannot stream bytes); a blob size cap is the same kind of protocol constraint and belongs beside it.

## Steps

1. Pick the cap (start at 8 MiB, set as a named constant). Refuse at once when `Content-Length` is above it.
2. Otherwise read the stream with a running byte count, and destroy the upstream as soon as the count passes the cap.
3. Return the refusal with the cap in the message and the download-URL resource URI in the hint.
4. Record the cap as a protocol note in `op-class.ts`, next to the existing streaming note.

## Files

- backend-cluster/backend-v2/src/features/ai-agent/api/mcp-resources.ts

## Acceptance criteria

- [ ] An archive at or under the cap reads exactly as today.
- [ ] An archive over the cap, with or without `Content-Length`, is refused without buffering more than the cap plus one chunk, and the hint names `archive-download-url`.
- [ ] `surface-parity.test.ts` stays at zero gaps.

## Out of scope

- REST and GraphQL, which stream and keep no cap.
