## Objective

Run `/simplify` over the code this milestone changed (reuse, simplification, efficiency; behavior-preserving).

## Outcome

`/simplify` ran four review passes (reuse, simplification, efficiency, altitude) over t001–t003. Applied:

- **Altitude:** `LedgerArchiveService` now uses Node's built-in `fetch` and `Readable.fromWeb`, so destroying the body cancels the Gitea request itself. The node-fetch workaround is gone: the close-to-abort hook, the no-op `error` listener, the signal cast, and both `instanceof Readable` guards. The service returns a transport-agnostic `LedgerArchive` (`body`, `contentType`, `contentDisposition`, `contentLength`) instead of an HTTP client's `Response`, so the REST and MCP adapters no longer read headers or cast streams. Re-checked against the local stack's Gitea: deprecated-route bytes and headers match, and a client hangup ends the in-flight Gitea request at once. undici then opens one spare connection that carries no request and closes on its 4 s idle timeout.
- **Reuse:** the Basic header comes from `getBasicAuthHeader` (`features/auth/utils/auth.ts`).
- **Simplification:**
  - `readCappedArchive` returns `undefined` past the cap, so the refusal is built in one place.
  - The op-class note names `MCP_ARCHIVE_BLOB_MAX_BYTES` instead of repeating its value.
  - One `__tests__/archive-origin.ts` helper (a real HTTP Gitea stand-in) replaces the node-fetch mocks in the three REST archive tests and the duplicated setup in the service and blob-cap tests.
  - The ledger's retired-route test is a single 404 case. It still fails, with 500, when the route is restored.

Skipped:

- **Draining small error bodies for keep-alive:** a tiny internal-network cost, and an error body can be unbounded.
- **Retired ledger parity harness:** an archived record that "is not updated going forward".
- **Pre-existing `archive-parity` fixture:** outside this diff.
