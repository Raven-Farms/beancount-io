## Objective

Point `LedgerArchiveService.download` at Gitea's archive API instead of the ledger service, keep every check it does today, and make the streamed response bounded in time and cancellable.

## Context

- `backend-cluster/backend-v2/src/features/ledger/service/ledger-archive-service.ts`: validates the name (`assertSafeArchiveName`), authorizes `LEDGER_ARCHIVE_READ` through `authorizeLedger`, builds `Basic <ledger_username:ledger_password>` for a signed-in caller (or `Anonymous`), and fetches `${favaApi.baseUrl}/ledgers/{owner}/{name}/archive/{archive}` with `node-fetch`. It maps 404 to `NotFoundError("Archive")` and anything else to `ServiceUnavailableError("Ledger archive")`, destroying the body.
- The ledger hop it calls (`backend-cluster/ledger/src/api/files.ts:312-347`) only forwards that header to `${gitea.baseUrl}/api/v1/repos/{owner}/{repo}/archive/{archive}` and sends no header for anonymous callers.
- `config.gitea.internalBaseUrl` (`src/config/config.ts`) is what `features/gitea/api/git-proxy-handler.ts` already uses to reach Gitea from backend-v2.
- The generated `repoGetArchive` in `features/gitea/client/gitea-api.ts` goes through the client's JSON request path, so use a plain `node-fetch` call that keeps the body as a stream.
- The composition root passes `input.config` to the service (`foundation/composition/builder.ts:136`).
- Koa destroys a stream body when the response closes (`onFinish`), which is what ends the upstream request on a client disconnect, as long as the body is the upstream stream itself.

## Steps

1. Fetch `${config.gitea.internalBaseUrl}/api/v1/repos/{owner}/{repo}/archive/{archive}` with the same `Basic` header, and no `Authorization` header for anonymous callers. Narrow the service's config type from `favaApi` to `gitea`.
2. Add a response-headers deadline through an `AbortSignal`: generous enough for Gitea to generate a large archive's first byte, cleared once headers arrive. Map the abort to the existing `ServiceUnavailableError`.
3. Keep the 404 and non-OK mapping, and keep `archive-proxy.ts` forwarding `Content-Type` and `Content-Disposition` plus `Cache-Control: private, no-store`.
4. Check by hand in the local stack (`deploy/docker-mac`) that the dashboard's "Download ZIP" works for a private ledger and anonymously for a public one.
