## Objective

Add a `directive-count` task kind to the rustledger worker so a file map's directive count is computed off the main thread, under the pool's existing queue bound and per-task timeout.

## Context

- `backend-cluster/ledger/src/foundation/rustledger/rustledger-worker-protocol.ts` defines task kinds `parse`, `query`, `filter`, `find-entry-slice`.
- `rustledger-worker.ts` handles them; `rustledger-worker-pool.ts` exposes `parse(…)` and enforces `DEFAULT_MAX_QUEUE_DEPTH = 32` and `DEFAULT_TASK_TIMEOUT_MS = 120_000`.
- `engine.ts` `parseLedgerFiles` shows the Jest in-process fallback (`JEST_WORKER_ID`) that the new call should mirror.

## Steps

1. Add `{ kind: "directive-count", files, entryPoint }` to the protocol and its numeric result.
2. Handle it in the worker with `Ledger.fromFiles(…).directiveCount()` and always `free()` the ledger.
3. Add a pool method (e.g. `countDirectives(files, entryPoint)`) and an engine-level export that uses the pool outside Jest and the in-process path under Jest.

## Acceptance criteria

- [x] The worker returns the same count as the in-process `directiveCount()` for a multi-file ledger with `include`.
- [x] A full queue and a timed-out task reject with the pool's existing errors.

## Out of scope

- Changing pool size, queue depth or timeout defaults.

## Done (2026-10-18)

New task kind `directive-count` (`rustledger-worker-protocol.ts`), handled in `rustledger-worker.ts` by `countLedgerDirectivesInProcess` (`Ledger.fromFiles(…).directiveCount()`, freed afterwards). It is exposed as `RustledgerWorkerPool.countDirectives(files, entryPoint)` and, at the engine level, as `countLedgerDirectives`. Like `parseLedgerFiles` and `queryLedgerFilesResult`, `countLedgerDirectives` uses the pool outside Jest and the in-process path under it.

Deviation: `countMap` in `core/directive-limit.ts` already calls `countLedgerDirectives` (t002's first step). Knip refuses an export nobody calls, so shipping the export alone would have been red. Both the write precheck and `GET …/directive-count` now count in the worker pool. t002 is left with reusing the current count per commit.

Evidence:
- **Real worker thread** (ts-node with `--experimental-vm-modules`; Jest cannot boot the worker): a two-file ledger with `include` counted 3 through `countLedgerDirectives`, and 3 in-process.
- **`rustledger-worker-pool.test.ts`:** the pool posts `{ kind: "directive-count", files, entryPoint }` and resolves the worker's number; a third count with one worker busy and a full queue rejects with `RateLimitedError`. The timeout path is the shared `enqueue` one, already covered by "terminates timed-out synchronous work".
- **`directive-limit-managed-prices.test.ts` and `count-directives-rpc-cost.test.ts`** now stub `countLedgerDirectives` instead of `withLedger`, which `countMap` no longer calls.

Gates: ledger `typecheck`, `eslint`, `lint:deadcode`, `test` (1344) and `build` pass, and `verify:rustledger` passes ("All rustledger engine checks passed").
