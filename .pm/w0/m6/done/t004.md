## Objective

Check an agent or API client can discover the new refusal: the REST v1 docs and regenerated OpenAPI snapshot list `directive_limit_exceeded` for the source-slice update and pull-request merge; the MCP `updateEntrySource` and `mergePullRequest` descriptions mention it; the dashboard and mobile show the server's message for both. Verify the MCP guidance reads the same for Claude Code and Codex. Flag drift as follow-up work.

## Done (2026-10-18)

Walked every surface the two refusals reach:
- **REST v1 docs.** The source-slice routes' description (`source-slice-handler.ts`) now says an update past a free ledger's directive limit is refused with `RESOURCE_LIMIT_REACHED`, naming the limit and the projected count, and that deletes always pass. The pull-request approve route (`pull-request-routes.ts`) says the same for a merge; reject is unchanged. `docs/openapi/v1.json` is regenerated (`generate-v1-openapi`): four description lines, and the OpenAPI completeness test passes.
- **MCP.** The `updateEntrySource` and `mergePullRequest` tool descriptions (`mcp-tools.ts`) name the `RESOURCE_LIMIT_REACHED` refusal. The tool list is the same for Claude Code and Codex because both read it from the server. MCP tests pass.
- **GraphQL descriptions.** Left unchanged. They are copied into `dashboard/api-gateway.graphql`, the dashboard's generated definitions and mobile's generated schema, so a docs-only change would churn three packages for no behavior change.
- **Dashboard.** The entry editor already shows `RESOURCE_LIMIT_REACHED` as the localized "You've reached your plan's limit. Upgrade to continue." through `useErrorMessage`, the same as every other limit. The pull-request review page did not: a thrown refusal became "Failed to approve pull request". Approve and reject now name any refusal the app has words for (a plan limit, permission, outage), and keep their own text for anything else (`pr-review-page.tsx`). New test: "names a merge refused by the plan's directive limit". Reverting the page fails it.
- **Mobile.** The edit-transaction screen shows a refused save's server message inline beside the "couldn't save" toast (`edit-transaction-screen.tsx`). Mobile has no pull-request review screen.

Follow-up, not drift: the bulk-entries REST and MCP descriptions do not mention the directive limit either, although that route enforces it. Out of this milestone's two operations.
