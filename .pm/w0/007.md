# Accept the bank amount spellings the CLI already imports in dashboard Smart Import CSV

**Severity:** minor. **Estimate:** 45–60 minutes including exact-decimal tests. **Owner:** `dashboard` (importer). **A2:** the same bank export should import through the web app as it does through `bea import --csv`. The rows that get dropped are often the largest ones (`1,234.56`).

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `575a8798`. QA-owned headless Chromium, 1440×1000, en-US, authenticated owner on a synthetic ledger. All GraphQL mutations were aborted by a route guard, and nothing was imported.

`qa-import.csv` (UTF-8 BOM, CRLF):

```csv
Date,Payee,Description,Amount
2026-09-01,"Acme, Inc.","Salary ""Sept""",2500.00
2026-09-02,Cafe,Coffee,-4.50

2026-09-03,Store,"Big purchase","-1,234.56"
2026-09-04,Refund,Return,(12.00)
2026-09-05,Fees,Bank fee,-0.1
```

1. Open `/ledger/<owner>/<ledger>/import` and choose the file.
2. The preview shows "3 Valid | 2 Errors". `-1,234.56` and `(12.00)` both get "Amount must be a valid number". The quoting, BOM, CRLF, and blank-line handling are all correct.
3. **Continue to Configure** offers "Import 3 Transactions". The `-1,234.56` purchase and `(12.00)` refund are skipped unless the user retypes each cell.

Reproduced on fresh loads. A file where *every* amount is grouped skips this deterministic path and falls through to the server/LLM parser. That was not exercised here, because the mutation guard blocks it.

## Root cause and contrast

`dashboard/src/features/importer/utils/csv-validator.ts:118–160` (`parseAmount`) accepts only `^[+-]?(?:\d+(?:\.\d*)?|\.\d+)(?:[eE][+-]?\d+)?$`, with the comment "No commas/grouping". The CLI's equivalent was widened by w3/256 and w1/m24 t003 (`1aa50d2e`). It accepts `$` symbols, thousands separators, accounting parentheses, trailing-minus negatives, and comma decimals resolved per column, refuses mixed conventions, and keeps exact decimals.

## Fix

Port the CLI's amount grammar decision to the dashboard parser. Normalize `1,234.56`, `$1,000.00`, `(12.00)`, and `4.50-` to exact decimal strings before the existing exact-precision check. Resolve `1.000,00`/`-4,50` comma decimals from the whole column, never per cell, and refuse a column that mixes conventions with a localized row error. Keep `reason`-based errors, the exact-decimal guarantee, and the existing editable-cell revalidation. Update `features/importer/AGENTS.md`'s amount contract.

Acceptance: the fixture above previews 5 valid rows with amounts `2500.00`, `-4.50`, `-1234.56`, `-12.00`, and `-0.1`. US (`"$1,000.00"`, `$4.50`, `4.50-`) and EU (`;`-delimited `1.000,00`, `-4,50`) fixtures parse deterministically without the LLM fallback. Ambiguous mixed columns are refused. Exact-decimal unit tests cover each spelling. Dashboard gates pass.
