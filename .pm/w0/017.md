# Say why an Open Account name is invalid instead of one catch-all message

**Severity:** minor. **Estimate:** 30–40 minutes (validator reasons, 15 locales, tests). **Owner:** `dashboard` (`common/lib/beancount/account-token.ts`, Accounts and Journal Open Account forms). **A2:** a newcomer who types `Assets:bank` is told to remove spaces and empty parts, though the name has neither. The real rule (each component starts with a capital or digit) is never stated.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `575a8798`. QA-owned headless Chromium, 1440×1000, en-US, authenticated owner on a synthetic ledger. Every GraphQL mutation was aborted by a route guard, so no account was opened.

Open `/ledger/<owner>/<ledger>/accounts?action=open-account` and type each name into Account Name:

| input | Open Account | message |
| --- | --- | --- |
| `Assets:bank` | disabled | "Use colon-separated account components without spaces or empty parts" ← wrong reason |
| `Assets:Bank Account` | disabled | same (correct reason: space) |
| `Assets::Bank`, `Assets:Bank:` | disabled | same (correct reason: empty part) |
| `Foo:Bar`, `Assets` | disabled | "Account must start with one of: Assets, Liabilities, …" (correct) |
| `Assets:Café`, `Assets:1Bank`, `Expenses:Food:Coffee-Shop` | enabled | valid (correct for Beancount v3) |

## Root cause

`dashboard/src/common/lib/beancount/account-token.ts` `isCompleteAccountToken` returns only a boolean for several distinct failures (whitespace, fewer than two parts, empty part, component not starting with `\p{Lu}\p{Lo}\p{Nd}`, disallowed character). Both callers, `features/ledger-data/accounts/open-account-dialog.tsx:83` and `features/journal/components/new-directive-dialog/open-account-form.tsx:62`, map every false to `page.accounts.accountNameInvalid`. The mobile app already distinguishes these reasons (w4/047, e.g. its `openAccountEmptyComponent` message).

## Fix

Return a reason from the validator (`whitespace | empty-component | component-start | invalid-character`) and show a specific, localized message for each, all 15 locales. For example: "Each part must start with a capital letter or digit (e.g. Assets:Bank)", naming the offending component. Keep the accepted grammar exactly as it is (Unicode and digit-led components stay valid).

Acceptance: the table above shows a correct reason for each invalid row in both the Accounts dialog and the Journal "Account" tab. The valid rows stay enabled. Unit tests cover each reason, and dashboard gates pass.
