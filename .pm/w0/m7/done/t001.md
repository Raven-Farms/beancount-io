## Objective

Replace the two `clientIp` helpers with one that returns the address appended by the nearest trusted proxy, driven by a configured trusted-hop count, and use it for every limiter key.

## Context

- GraphQL: `backend-cluster/backend-v2/src/server/graphql/rate-limit-middleware.ts:24-27` reads `x-forwarded-for` from the context headers and takes entry 0.
- REST: `server/rest/rate-limit-middleware.ts:75-77` returns `ctx.ip`. Koa runs with `app.proxy = config.server.proxy` (`server/start-server.ts:59`, `config.ts:453`, always `true`) and the default `maxIpsCount` of 0, which makes `ctx.ip` the left-most entry.
- Git proxy limiter keys: `features/gitea/api/git-proxy-handler.ts` (`git-auth-fail:${ctx.ip}` and the general limiter).
- Koa's `app.maxIpsCount` keeps only the right-most N entries of `X-Forwarded-For`.

## Steps

1. Add a `TRUSTED_PROXY_HOPS` setting (default 1 for the shipped Caddy targets; 0 means "no proxy, use the socket"). Set `app.proxy` and `app.maxIpsCount` from it.
2. Make GraphQL's context carry the resolved `ctx.ip` instead of re-parsing the header, and delete the GraphQL `clientIp`.
3. Point every limiter key at the one value.

## Done (2026-10-18)

**Setting.** `TRUSTED_PROXY_HOPS` (`config.server.trustedProxyHops`, `parseTrustedProxyHops`) replaces the always-true `server.proxy`. It defaults to 1, the one Caddy or Traefik every shipped deployment puts in front of the backend. A value that is not a non-negative integer falls back to 1, never to trusting every entry.

**Koa.** `trustProxyHops(app, hops)` (`src/server/client-address.ts`, called from `start-server.ts`) sets `app.proxy = hops > 0` and `app.maxIpsCount = hops`, so `ctx.ip` is the entry the nearest trusted proxy appended, or the socket when nothing is trusted.

**One value for every limiter.** GraphQL's context carries `clientIp` (`ctx.ip || "unknown"`). Every hand-parsed read of the forwarded header is gone:
- the GraphQL rate limiter's own `clientIp` (left-most `X-Forwarded-For`);
- `sendForgotPasswordLink` and `signUp` (left-most `X-Forwarded-For`, then `x-real-ip`);
- the CLI device-sign-in requester address on REST and GraphQL (`firstForwardedIp`, deleted). It is display-only, but it is shown to the person approving the sign-in.

REST and the Git proxy already used `ctx.ip`; their comment now says what it is.

Not changed: the dashboard's server-side rendering calls backend-v2 directly, with no forwarded header. Under either setting it keys on the dashboard container's address, as it did before (left-most of nothing was "unknown").

**Docs.** `backend-v2/.env.example` and `README.md` document the variable. The deploy targets' settings are t003.

**Tests.**
- **New `src/server/__tests__/client-address.test.ts`** runs a real Koa server through `trustProxyHops` and `createContext`:

  - two hops count back two;
  - zero hops ignores the header;
