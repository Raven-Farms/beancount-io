# Don't open Overview Money movement on an empty future month when a time filter is set

**Severity:** minor. **Estimate:** 25–35 minutes. **Owner:** `dashboard` (`features/reports/overview/components/money-movement-section.tsx`). **A2:** choosing "this year" (`time=year`/`2026`) is a common first filter, and it turns the Money movement panel into "No money movement for this period" for **December 2026**, two months away.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `575a8798`. QA-owned headless Chromium, en-US, synthetic ledger whose latest activity is August 2026. Read-only, fresh loads.

| Overview URL | Money movement opens on |
| --- | --- |
| no filter | **August 2026** (latest active month): +4,000 / −2,095.6 USD |
| `?time=2026`, `?time=year`, `?time=2026-07 - 2026-12` | **December 2026**: "No money movement for this period" (both cards) |
| `?time=2026-Q3` | September 2026 (empty, but in the past) |

The user has to press **Previous** two to four times to reach real data, even though the selection contains August.

## Root cause

`money-movement-section.tsx:~191–200`: `defaultDate` prefers `getLatestActiveIntervalDate(...)` only when `preferActiveMonth && !hasFilters`. With any filter it falls back to `dates.at(-1)`, the last interval of the selected window, which can lie after today.

## Fix

With a filter, default to the latest *active* interval within the selection, falling back to the last interval that doesn't start after today. Never default to a future interval. Keep explicit Previous/Next navigation, the unfiltered behavior, and w4/103's comparison-window labelling.

Acceptance: on 2026-10-15, `time=2026`, `time=year`, and `time=2026-07 - 2026-12` open on August 2026 for the synthetic ledger. A selection with no activity opens on its last non-future month with the honest empty state. A fully future selection (`time=2030`) keeps its empty state. Unit tests pin the default with a fixed "today". Dashboard gates pass.

## Dedupe

w4/103 (comparison-window label), w3/145 (partial-month drill-down), and w0/027 (the same future-period choice on Budget cards, a separate component) are related. Searched `.pm/**` for money movement, default month, and future month: no item covers the Overview default.
