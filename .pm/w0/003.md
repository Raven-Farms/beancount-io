# Stop the BQL editor auto-closing brackets inside string literals

**Severity:** minor. **Estimate:** 20–30 minutes with a Monaco language-config test. **Owner:** `dashboard` (BQL feature). **A2:** a typed regex or narration pattern must reach the engine as typed; otherwise the query silently returns different rows.

## Live reproduction

Production `https://beancount.io`, 2026-10-15. Local main `575a8798`. Headless isolated Chromium, 1440×1000, real keyboard events (`keyboard.type`, 20ms/char) into the Monaco "Editor content" textbox.

1. Open `/ledger/<owner>/<ledger>/query`, select all, and delete.
2. Type `SELECT account WHERE account ~ '('`. The editor contains `SELECT account WHERE account ~ '('')'`.
3. Type `SELECT 'a(b'`. The result is `SELECT 'a(b')'`. Type `SELECT "x["`. The result is `SELECT "x[""]"`.
4. Running the mangled step-2 query returns "No data returned from query" instead of the unterminated-regex result the user asked for, with no hint that the text changed.

Reproduced on two fresh page loads. Pasting is unaffected; only typed input is mangled.

## Root cause

`dashboard/src/features/bql/lib/bql-language.ts` `BQL_LANGUAGE_CONFIGURATION.autoClosingPairs` lists `{`, `[`, `(`, `"`, and `'` without `notIn`. Monaco therefore auto-closes a bracket typed inside the string the quote pair just opened. The closing quote typed next lands before the auto-inserted bracket instead of overtyping, which leaves a stray bracket plus an extra quote pair.

## Fix

Add `notIn: ["string", "comment"]` to the bracket pairs, and to the quote pairs as Monaco's built-in languages do. The Monarch tokenizer must still classify an in-progress `'…` as `string` while typing. If the current complete-string regexes (`'(?:[^'\\]|\\.)*'`) don't cover an unterminated string, add an unterminated-string rule or a string state. Keep auto-closing for brackets typed outside strings.

Acceptance: typing each of the three inputs above yields exactly the typed text. Typing `SELECT sum(position)` still auto-closes and overtypes `)`. `/* */` comments behave the same. A unit test asserts the language configuration (and tokenizer state for an unterminated string). Dashboard gates pass.
