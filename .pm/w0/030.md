# Give the Overview Net Worth table view table semantics and a keyboard-scrollable region

**Severity:** minor (accessibility; WCAG 1.3.1 Info and Relationships, 2.1.1 Keyboard). **Estimate:** 25–35 minutes. **Owner:** `dashboard` (`features/reports/overview/components/net-worth-card.tsx`). **A2:** "Show table" exists to give a readable alternative to the chart, but assistive technology gets an unstructured run of text, and the overflowing list can't be scrolled by keyboard.

## Live reproduction

Production `https://beancount.io`, 2026-10-15, local main `575a8798`. QA-owned headless Chromium, 1440×1000, en-US. Read-only.

1. Open `/ledger/<owner>/<ledger>` (synthetic ledger) or `/ledger/open_ledger/example`, and press **Show table** in the Net Worth card. `aria-pressed` correctly flips (w4/086).
2. The accessibility tree for the table view is a single text run: `Aug 2026 17,108.51 USD Jul 2026 15,204.11 USD Jun 2026 13,184.51 USD …`. There is no table/list, no row/cell, and no column headers (Month / Net worth), so a screen reader can't move by row or announce which month a value belongs to.
3. The list is a `max-h-[230px] overflow-y-auto` box. With 12 months it overflows, but it has no `tabIndex`/role/name and contains no focusable elements, so keyboard users can't scroll to the older months.

## Root cause

`net-worth-card.tsx:~443–461` renders the table view as nested `<div>`s (date `<span>` + `FormattedAmounts`) inside a scrollable `<div>`.

## Fix

Render a real `<table>` with a caption/`aria-labelledby` pointing at the card title ("Net worth by month"), column headers (Month, Net worth), and one row per month. Multi-unit amounts stay in one cell, in the existing order. Make the scroll container focusable with a visible focus ring and a name (`tabIndex={0}`, `role="region"`, `aria-label`), or drop the height cap. Keep the visual design, the newest-first order, and the w4/086 toggle semantics.

Acceptance: the accessibility tree shows a named table with 2 column headers and one row per month. Tab reaches the region, and arrow/PageDown scroll it. axe reports no `scrollable-region-focusable` for the card. A component test asserts the table roles. Dashboard gates pass.
