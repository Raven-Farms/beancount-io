## Objective

Make the shared structured-write path validate the post-write ledger before it commits, and refuse a write that introduces new bean-check errors unless `allowInvalid` is set — the same contract the text-append route already has.

## Context

- Text-append: `backend-cluster/backend-v2/src/features/ledger/workflow/directive-append-workflow.ts` (`newErrors.length > 0 && !allowInvalid && !dryRun`) and its message contract in `utils/directive-text-contract.ts`.
- Structured writes: `LedgerEntryService.writeBulkEntries` (`features/ledger/service/ledger-entry-service.ts`) → the ledger service bulk endpoint (`backend-cluster/ledger/src/api/entries.ts`), which today only refuses an unbalanced transaction.
- All three surfaces already pass `allowInvalid` into the service (GraphQL `bulkEntries` arg, REST `entriesBodySchema`, MCP `addLedgerEntries`).

## Steps

1. Reuse the text-append validation (render the entries, diff the ledger's errors before and after) for structured writes; do not add a second validator.
2. Refuse with a transport-agnostic domain error that names each new error, mirroring the text-append message.
3. Keep `allowInvalid` committing and reporting the new errors.
4. Unit-test the workflow: duplicate `open` refused, `allowInvalid` commits, a clean write unchanged.

## Files

- backend-cluster/backend-v2/src/features/ledger/service/ledger-entry-service.ts
- backend-cluster/backend-v2/src/features/ledger/workflow/ (shared validation)
- backend-cluster/ledger/src/api/entries.ts (only if the check belongs in the ledger service)

## Acceptance criteria

- [ ] A second `open` for an open account is refused with nothing committed and the error named.
- [ ] `allowInvalid: true` commits and returns the new errors.
- [ ] A write that adds no error is unchanged.

## Out of scope

- Amount syntax validation (w3/641).
- The dashboard's warning for deliberate `allowInvalid` writes (w3/640).
