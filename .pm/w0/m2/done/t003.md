## Objective

When the server refuses a structured write, every write form in the native app and the dashboard shows the server's message instead of a generic failure or a success.

## Context

- Mobile: Open Account (`mobile/src/screens/open-account-screen/`), Add Budget (`add-budget-screen/`), New Transaction (`multi-postings-transaction/`) already show `result.message` on failure — confirm it carries the refusal text.
- Dashboard: New Entry forms, Open Account dialog and Smart Import (see w3/640 for the paths).

## Steps

1. Check each form's error path with a mocked refusal.
2. Show the named error inline; never close the form or toast success on a refusal.
3. Add component or unit tests for the refusal path.

## Files

- mobile/src/screens/**/use-*.ts and the screens above
- dashboard/src/features/journal/**, accounts Open Account dialog, importer

## Acceptance criteria

- [x] Each listed form shows the refusal text and stays open.
- [x] Tests cover the refusal path in both packages; mobile and dashboard gates pass.

## Out of scope

- The warning for deliberate `allowInvalid` writes (w3/640).

## Done (2026-10-17)

A would-break refusal reaches the clients as `VALIDATION_FAILED` on `entries`. Its `reason` ends with the new bean-check errors. Both clients read that detail and show "This would add an error to your ledger: <detail>", localized, instead of a generic failure. Nothing closes or reports success on a refusal.

Mobile:
- `src/common/ledger-refusal.ts` (`newLedgerErrorDetail`) reads the detail from the GraphQL error.
- `runLedgerWrite` gained an optional `describeRefusal` dependency. `useLedgerWrite` supplies it, so New Transaction, Edit Transaction, Add Transaction and Transaction Detail toast the named error. A screen's own `failureMessageFor` still wins.
- Open Account and Add Budget return `wouldBreak` from their hooks and show it in their inline error.
- New key `ledgerWouldBreak` in all 13 locales.

Dashboard:
- `getNewLedgerErrorDetail` in `src/common/lib/errors/error-message.ts`.
- `useErrorMessage` formats the refusal with `common.errors.wouldBreakLedger` (15 locales). Every form that formats through it shows the named error inline and stays open: the New Entry forms, the Accounts Open Account and Add Budget dialogs, and Smart Import's submit. Other `VALIDATION_FAILED` refusals keep the generic copy.

Tests:
- Mobile `src/common/__tests__/ledger-refusal.test.ts`.
- Dashboard "would-break refusals" in `error-message.test.ts`.
- Removing `describeRefusal` from `runLedgerWrite`, or the formatter branch, fails them.

Gates: mobile (prettier, tsc, eslint, knip, gqlops, unit) and dashboard (`format:check`, `lint`, `test`, `build`) pass.
