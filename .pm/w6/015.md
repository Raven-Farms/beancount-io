# Stop instructing addLedgerEntries callers to pass an unsupported description

**Severity:** minor. **Estimate:** 20–35 minutes. **Owner:** backend-v2. **A1 — Agent-native accounting:** the served reconciliation and close playbooks should propose calls the published tool schema accepts.

## Live reproduction

Production `https://beancount.io`, 2026-10-14; local main `57a26964`. MCP `beancount-mcp` 1.0.0, protocol `2025-11-25`; deployed SHA unavailable. Existing designated unpinned QA API key, scopes `ledger.read ledger.write ledger.admin`. Read-only prompt/discovery requests target public synthetic `open_ledger/example`.

Get `reconcile-account` with `ledger: open_ledger/example`, `account: Assets:US:BofA:Checking`, `period: 2017-09`. The successful playbook's Verify phase says to append with one `addLedgerEntries` call carrying the transactions and balance entry, **“with a `description` naming the account and period.”** A fresh repeat returns identical text.

Get `close-month` with the same ledger and `month: 2017-09`. Its Commit phase instructs the agent to pass the close report as `description` on the final `addLedgerEntries` **or** `editLedgerFiles` call.

But the live `tools/list` input schema for `addLedgerEntries` has only `entries`, `allowInvalid` and `ledger`, with `additionalProperties: false`. `description` is not accepted. `editLedgerFiles` does accept it, so the close prompt's alternative is valid only for that tool.

Helper patterns:

```sh
node .agents/skills/qa-shared/scripts/qa-mcp.mjs --credentials-file .env prompt reconcile-account '{"ledger":"open_ledger/example","account":"Assets:US:BofA:Checking","period":"2017-09"}'
node .agents/skills/qa-shared/scripts/qa-mcp.mjs --credentials-file .env prompt close-month '{"ledger":"open_ledger/example","month":"2017-09"}'
node .agents/skills/qa-shared/scripts/qa-mcp.mjs --credentials-file .env tools-list
```

No mutation was attempted to demonstrate this mismatch. The live strict schema and its executed source establish that the prescribed extra argument is invalid; a real model's repair behavior and a rejected write transcript remain unverified.

## Root cause and bounded repair

`backend-cluster/backend-v2/src/features/ai-agent/api/mcp-prompts.ts`, `reconcileAccount` Verify phase and `closeMonth` Commit phase, assume the two write tools share a description input. `mcp-tools.ts` instead defines `addLedgerEntriesInput` from `entriesBodySchema`, extends it with ledger selection, and makes it strict. `entries-handler.ts` defines that shared REST body as a strict object with entries/allowInvalid only. The legacy GraphQL add-entries arguments likewise have no description. This is stale prompt prose, not a missing advertised API argument or a reason to loosen validation.

Remove the unsupported description instruction from reconciliation. For close history, state that a description can accompany an already-needed `editLedgerFiles` write; `addLedgerEntries` cannot carry it. Preserve the explicit confirmation and validation gates. If the final action is an entry-tool write, provide the report to the user without claiming it became that commit's description. Never add a dummy edit solely to attach a report, and retain the instruction to leave the ledger untouched when no write remains.

Keep tool schemas and REST/GraphQL write behavior unchanged. Prompts perform no domain action and have no API-parity obligation, but their procedures must match the tools they name. Add focused prompt regression coverage for both corrected phases and the valid file-tool alternative; keep existing inventory/URI checks. Run backend-v2 typecheck/tests and normal OpenAPI drift checks without weakening strict input validation.
