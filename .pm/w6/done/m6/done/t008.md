## Objective

Prove first-hand that both hosts install from the live listings and that an installed skill does real work, and record dated evidence.

## Context

- Use clean host installations and a synthetic ledger. Never use real financial data. The first-query fixture and steps live in `docs/skills/first-query.md`.
- `bea` must be on `PATH` (`brew install bex-co/tap/bea` or `uv tool install beancount-io`).
- An agent turn needs a model provider key. If the worker has none for a host, block this task with that as the condition and still record the install-only results.

## Steps

1. OpenClaw: `openclaw skills install @<handle>/beancount-ask` on its own, then the rest of the suite. Run the first-query journey and confirm the answer comes from a shown `bea --json query`.
2. Hermes: `hermes skills search beancount` (and `--source clawhub`), then `hermes skills install` one listing. It must pass the scanner without `--force`. Run the same journey.
3. Hermes direct path: try `hermes skills install bex-co/beancount-io/skills/beancount-ask`. Since w2/m42 the suite sits directly under `skills/`, so the tap rule that skips directories starting with `.` no longer applies; record whether the direct install works.
4. Record the host versions, dates, listing versions, and results in `docs/skills/first-query.md`'s tested-with section or a sibling evidence file.
