## Objective

Complete a real OpenClaw sign-in on the hosted endpoint with the QA account, then one read and one `dry_run` write on a synthetic ledger. Record the result.

## Context

- Commands as documented: `openclaw mcp add beancount --url https://beancount.io/api-gateway/mcp --transport streamable-http`, then `auth: "oauth"`, then `openclaw mcp login beancount` and `openclaw mcp doctor beancount --probe`. Confirm the exact flags with `openclaw mcp add --help`.
- The probe lists capabilities without a model. The read and the write need an agent turn, and so a model provider key. If the worker has none, block this task on that with the probe results recorded.

## Steps

1. Add, log in, and approve on `/oauth/consent`, selecting one synthetic ledger.
2. Probe, then ask the agent for one read (for example, a balance) and one `dry_run` write.
3. Record the date, OpenClaw version, deployed backend revision, the tools the host loaded, and whether it read any resources.

## Evidence (2026-10-16)

- **Host:** OpenClaw 2026.10.4 (`383c124`), installed in an isolated prefix with a throwaway `HOME`. **Endpoint:** `https://beancount.io/api-gateway/mcp`, MCP server `beancount` 1.0.0 per `/.well-known/mcp.json`. The hosted endpoint exposes no deployed revision.
- **Sign-in.** `openclaw mcp add beancount --url https://beancount.io/api-gateway/mcp --transport streamable-http --auth oauth`, then `openclaw mcp login beancount`. Consent was approved with the QA account for the synthetic ledger `mcp-agent-eval` only.
  - OpenClaw printed "MCP OAuth credentials saved". Its stored grant holds a refresh token, with scope `openid offline_access ledger.read ledger.write ledger.admin`.
- **Probe.** `openclaw mcp probe beancount` reported 26 tools, resources, and prompts. OpenClaw names them `beancount__<tool>` and lists `listChanged` for all three.
- **Agent turn.** `openclaw agent --local --model openai/gpt-6-astra` called `getLedgerContext` and `listLedgers` (12 open accounts on the pinned ledger), then `appendLedgerText` once with `dry_run: true`. That returned a unified diff adding a balanced 1.00 USD transaction, with 0 validation errors before and after. Nothing was written.
- Per-requester gateway mode was not run end to end. Its redirect is covered by the t002 fixture, and t001's source reading found nothing else that differs from the CLI login.
