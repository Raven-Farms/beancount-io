# Align the public archive contract with native downloads

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** backend-v2. **A1 — Agent-native accounting / A2 — Frictionless onboarding:** an agent following the published archive parameter example should reach the same existing download that URL discovery advertises, with its successful response content type described by the contract.

## Live reproduction

Production `https://beancount.io`, 2026-10-11; main `fa8f716e`. MCP `beancount-mcp` 1.0.0, protocol `2025-11-25`; deployed SHA unavailable. Existing designated unpinned QA API key, scopes `ledger.read ledger.write ledger.admin`. Read-only public synthetic `open_ledger/stock-example`; no credentials or personal ledger contents appear here.

1. GET `/api-gateway/v1/openapi.json` returns HTTP 200. The `archive` parameter on GET `/api-gateway/v1/ledgers/{owner}/{name}/archive/{archive}` says “Git archives are `gitea-<branch>.zip`” and sets the example to `gitea-main.zip`.
2. Read `beancount://open_ledger/stock-example/archive/gitea-main.zip` through MCP. Two fresh requests return JSON-RPC `-32002`, `data.code: NOT_FOUND`, with message `Archive with ID 'gitea-main.zip' not found`. Equivalent REST downloads both return HTTP 404.
3. Change only the archive name to `main.zip`. MCP returns a base64 `blob`, MIME type `application/octet-stream`, and `beancount/contentDisposition` naming `stock-example-main.zip`. REST returns HTTP 200 with byte-identical 17,573-byte ZIP. SHA-256: `7cdcd97cfcbde48c9134286652ead0c0735ff828ecbc58594786f0bccecd7a0a`. ZIP CRCs validate, and all nine advertised source files are present.
4. `beancount://open_ledger/stock-example/archive-download-url` advertises a URL ending in `/archive/main.zip`, corroborating the working reference format.

Exact MCP helper calls, using only a path to the gitignored credential file:

```sh
node .agents/skills/qa-shared/scripts/qa-mcp.mjs --credentials-file .env read beancount://open_ledger/stock-example/archive/gitea-main.zip
node .agents/skills/qa-shared/scripts/qa-mcp.mjs --credentials-file .env read beancount://open_ledger/stock-example/archive/main.zip
```

The failure is a wrong published example, not missing archive delivery or a malformed binary envelope. MCP and REST agree, and URL discovery works.

## Root cause and bounded repair

`backend-cluster/backend-v2/src/features/ledger/api/rest/v1/archive-handler.ts` hardcodes the old `gitea-<branch>.zip` description/example in `archiveParamsSchema`; the generated `docs/openapi/v1.json` and live public document repeat it. `src/features/ledger/service/ledger-archive-service.ts` forwards the supplied archive name unchanged. The ledger service's `backend-cluster/ledger/src/api/files.ts` archive handler forwards that name directly to Gitea's repository archive route. Neither strips the `gitea-` prefix. Meanwhile `ledger-asset-service.ts:getLedgerArchiveDownloadUrl` already selects `main.zip` correctly.

Correct the backend-v2 parameter description/example to the native reference format, with `main.zip` as the verified example, and regenerate its OpenAPI snapshot using the package generator. Make MCP's existing archive resource description unambiguous if needed. Preserve valid reference names, the existing input allowlist, response bytes/metadata and all existing protocol behavior. Do not introduce prefix rewriting: `gitea-main` can itself be a legitimate branch name. The tar/gzip variant was subsequently verified below; use `main.tar.gz` as a second tested example if documenting it. The same handler also declares only `application/zip` and `application/gzip` successful response media types, whereas the verified upstream responses are `application/octet-stream`. Include the preserved upstream media type in the public contract; do not change the working stream/blob behavior merely to fit the incorrect documentation.

Acceptance: generated and served public OpenAPI use working reference examples and include the actual binary response media type; adapter/documentation coverage catches drift; the example reaches a ZIP blob through MCP and the corresponding existing REST route, while archive URL discovery remains consistent. Run backend-v2's native checks when implementing. GraphQL's existing archive-URL discovery already points to `main.zip`; preserve it and the eligible REST/MCP parity. No ledger-engine change is needed.

This is correction of an existing public API contract only. It adds no hosted-to-local workflow and does not change SSH setup requirements or introduce an export shortcut.
