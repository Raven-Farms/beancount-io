## Objective

Make sure the shipped host support cannot silently regress: each new fixture fails when the behavior it depends on is broken, and any fix from t002 has a regression test.

## Context

- `CI (backend parity)` runs `yarn test` on `backend-cluster/backend-v2/**`.

## Steps

1. Break each depended-on rule on purpose (the native default, the loopback-port match, the web redirect on an arbitrary origin) and confirm the matching fixture fails.
2. Add any missing regression test.

## Files

- `backend-cluster/backend-v2/src/features/oauth/api/__tests__/`

## Acceptance criteria

- [ ] Every new test fails when its behavior is broken on purpose. No tautological tests.

## Out of scope

- Network tests against the live hosts.

## Evidence

Each rule the shipped behavior depends on was broken on purpose in `oidc-route.ts` and the OAuth suite re-run, then the file was restored:

| Rule broken | New tests that fail |
| --- | --- |
| CIMD resolution off (`clientIdMetadataDocument.enabled: false`) | Hermes Agent's CIMD fixture |
| `offline_access` no longer a supported scope (registration validates a client's `scope`, `client_schema.js:714-722`) | All five DCR fixtures (OpenClaw CLI, its `localhost` retry, per-requester gateway, Hermes 0.19.0, Hermes DCR fallback) and both D5 tests |
| The D5 prompt rewrite disabled | "keeps offline_access for a third-party host that sends no prompt" |
| The rewrite widened to every client | The existing mobile test "without prompt=consent there is no refresh token to renew from", which guards the static-client boundary |
| D3's native default switched to `web` | None. Both hosts' redirects (a loopback port they registered, or HTTPS) are valid for web clients too, so neither depends on D3. This is correct, not a gap |

No test was added. Every behavior this milestone shipped already fails a test when broken, and the t007 refactor was re-proven the same way. Network calls to the live hosts stay out of unit tests.
