## Objective

Complete a real Hermes Agent sign-in on the hosted endpoint with the QA account, then one read through a resource wrapper tool or a tool, and one `dry_run` write on a synthetic ledger. Record the result. Also record what `--flow device` does against our server.

## Context

- Config as documented: `mcp_servers.beancount` in `~/.hermes/config.yaml` with `url: https://beancount.io/api-gateway/mcp` and `auth: oauth`, then `hermes mcp login beancount` and `hermes mcp test beancount`.
- Hermes prefers CIMD and falls back to DCR. Record which path it took.
- An agent turn needs a model provider key, the same block condition as t003.

## Steps

1. Configure, log in, and approve on `/oauth/consent`, selecting one synthetic ledger.
2. Test the connection, then ask the agent for one read, using `read_resource` where it chooses to, and one `dry_run` write.
3. Try `hermes mcp login beancount --flow device` and record the error. Then record which headless alternative works: paste-back or SSH port forwarding.
4. Record the date, Hermes version, deployed backend revision, and results.

## Evidence (2026-10-16)

- **Host:** Hermes Agent v0.22.2 (`d923a5eb`, `mcp` 2.0.0), the current release. It was installed the way its docs allow for a checkout (an editable install of the tag with the `[mcp]` extra, Python 3.14), in an isolated venv with a throwaway `HOME`. **Endpoint:** `https://beancount.io/api-gateway/mcp`, MCP server `beancount` 1.0.0. No deployed revision is exposed.
- **Sign-in.** `mcp_servers.beancount: {url: https://beancount.io/api-gateway/mcp, auth: oauth}`, then `hermes mcp login beancount` in a terminal.
  - Hermes presented its CIMD document as `client_id`, redirected to `http://127.0.0.1:27890/callback`, and sent `prompt=consent`.
  - Consent said "Its details are published by nousresearch.github.io", showed the loopback warning, and listed "Stay signed in". It was approved for the synthetic `mcp-agent-eval` ledger only.
  - Hermes printed "Authenticated — 26 tool(s) available". `~/.hermes/mcp-tokens/beancount.json` holds a refresh token, with scope `openid offline_access ledger.read ledger.write ledger.admin` and `expires_in` 3600.
- **Agent turn.** `hermes chat -Q --provider openai -m gpt-6-astra -q …` called `mcp__beancount__getLedgerContext` and `mcp__beancount__listLedgers`, then `mcp__beancount__appendLedgerText` once with `dry_run: true`. It returned a balanced diff with no new validation errors and wrote nothing. The model chose tools over the `read_resource` wrapper; t001's source reading confirms that Hermes registers the wrappers when the server advertises resources and prompts, as this one does.
- **Device flow.** `hermes mcp login beancount --flow device` fails with "Server does not advertise device authorization; use --flow browser if supported". The headless alternatives are the paste-back prompt that every login prints ("paste the redirect URL here") and the SSH port forward that Hermes suggests.
- **Hermes 0.19.0 (PyPI).** Its DCR, no-`prompt` path drops `offline_access` on production until backend-v2 is deployed at or after `1bc31bd0` (t002). PyPI is not a supported channel: v0.22.2 refuses to build a wheel and points to the shell installer, Docker, or Nix.
