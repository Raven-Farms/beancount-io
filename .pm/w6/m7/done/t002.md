## Evidence

- Fixtures in `oidc-route.test.ts`:
  - **OpenClaw:** CLI login on `127.0.0.1:8989`, its `localhost` retry, and the per-requester gateway's HTTPS callback on an arbitrary origin, each with its real registration (`client_name: "OpenClaw MCP"` and the discovered scope, no `application_type`).
  - **Hermes Agent 0.19.0 (PyPI):** DCR on an ephemeral port.
  - **Current Hermes:** its DCR fallback on pinned port 27890 (`application_type: native`), and its published CIMD document authorizing from a later pinned port.
  - All reach consent.
- **Root-cause fix (ADR 019 D5).** oidc-provider dropped `offline_access` from a third-party host's request that had no `prompt=consent`, so such a host (Hermes 0.19.0, or any MCP Python SDK 1.x client) got no refresh token. `oidc-route.ts` now adds `consent` to the prompt for a DCR/CIMD client that asks for `offline_access`. It leaves `prompt=none` and the static mobile and Discourse clients unchanged.
  - **Tests:** "keeps offline_access for a third-party host that sends no prompt, so it can refresh" fails with the fix disabled and passes with it. "leaves a silent prompt=none request silent" guards the exception.
- **Gates.** `tsc` is clean, eslint and knip are clean, and all 118 OAuth tests pass.
  - **Full unit run:** 4 suites failed. Three (well-known routes, body parser, edit-ledger refusals) pass when run alone, so they were load timeouts. `llm/utils/upstream-survival` also fails on clean `main` in this environment.
