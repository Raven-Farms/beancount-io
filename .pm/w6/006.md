# Preserve account balances in a zero-net balance-sheet summary

**Severity:** major. **Estimate:** 35–50 minutes, including shared-adapter coverage. **Owner:** backend-v2. **A1 — Agent-native accounting:** a filtered balance sheet must not erase nonzero accounts merely because their total cancels.

## Live reproduction

Production `https://beancount.io/api-gateway/mcp`, 2026-10-11; main `d81f7812`. Server `beancount-mcp` 1.0.0, protocol `2025-11-25`; deployment SHA is unavailable. Designated unpinned QA API key with `ledger.read ledger.write ledger.admin`, never recorded. Read-only requests against the existing synthetic MCP evaluation ledger.

Minimal balanced fixture for an independently prepared QA ledger:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Bank:Checking USD
2026-01-01 open Assets:Bank:Savings USD
2026-03-15 * "Transfer to savings"
  Assets:Bank:Checking  -500 USD
  Assets:Bank:Savings    500 USD
```

```sh
node .agents/skills/qa-shared/scripts/qa-mcp.mjs --credentials-file /path/to/qa.env read 'beancount://qa-owner/qa-book/statements/balance-sheet?conversion=units&filter=narration%3A%22Transfer%20to%20savings%22'
```

Two fresh requests return HTTP 200, `Content-Type: text/event-stream`, `mimeType: application/json`, and successful content:

```json
{"asOf":"2026-03-31","currency":"units","assets":0,"liabilities":0,"equity":0,"netWorth":0,"byAccount":[]}
```

The zero totals are correct for the selected transfer. The fake currency and omitted Checking `-500 USD` / Savings `500 USD` are wrong. Changing only `conversion=at_cost` or `conversion=at_value` also empties the breakdown and labels currency with the strategy name.

## Controls and parity

- `shape=fava` retains both leaf balances: Checking `{"USD":"-500"}` and Savings `{"USD":"500"}`. The Assets root, Bank parent, and net-worth point have empty aggregate maps because their children cancel.
- With `conversion=EUR`, the raw leaves still carry USD because this fixture has no EUR quote. Two fresh filtered MCP summaries instead label the zero totals EUR and drop the USD rows; REST repeats it. The unfiltered EUR request correctly resolves USD and retains its accounts. The existing rule says the requested currency wins only when the data carries it, so the fix must handle unobserved currency names as well as strategy names. Adding `time=2026-03` to the filtered units request also reproduces the omission.
- Changing only `conversion=USD` returns currency USD, the same zero totals, and both signed `byAccount` rows. Unfiltered `units` balance sheets also retain account balances because their aggregates supply USD evidence.
- The equivalent REST route `GET /api-gateway/v1/ledgers/qa-owner/qa-book/statements/balance-sheet` reproduces both fresh faulty summaries, both raw/explicit-USD controls, and `at_cost`/`at_value` cases. The shared projection is faulty on both protocols.
- GraphQL `getLedgerBalanceSheet(ledgerId:"qa-owner/qa-book",filter:"narration:\"Transfer to savings\"",conversion:"units") { netWorthData { date balance } assetsHierarchyData { account balance balanceChildren children } }` preserves the two leaf balances and empty aggregates, HTTP 200 without errors. `children` is a JSON scalar array, not an object-selection field.
- BQL `SELECT account, SUM(number) WHERE narration = 'Transfer to savings' GROUP BY account ORDER BY account` independently returns Checking `-500.00` and Savings `500.00`.

## Root cause and correction

`src/features/ledger/utils/report-summaries.ts:166–193` supplies `resolveCurrency` with only net-worth series balances and the Assets root's `balance_children`. All are empty in this case. `resolveCurrency` at lines 95–119 falls back to the requested strategy name. `flattenHierarchy` then reads nonexistent `balance["units"]` / `balance["at_cost"]` / `balance["at_value"]` as zero and removes both accounts.

The sole production caller is `fetchStatement` in `src/features/ledger/api/rest/v1/reports-handler.ts:73–94`, shared by REST and MCP statement resources. GraphQL `ledger-finance-resolver.query.ts:271–305` returns raw chart/tree data and does not apply the projection. This is a gateway summary defect; no engine arithmetic repair is indicated.

When the existing aggregate evidence has no currency keys, resolve the currency from the actual own balances in the Assets/Liabilities/Equity trees, including descendant accounts. Keep aggregate selection and tie/frequency policy unchanged when it has evidence. A strategy name is not a currency; reuse the strategy handling already present in the interval-summary correction. Preserve an explicit observed currency, zero aggregate totals, the correct as-of date, and each signed nonzero account without double-counting parent totals or adding different currencies together. Do not hardcode USD. Do not add a new parser, valuation engine, or cross-package import.

Add behavior coverage through shared REST/MCP statement adapters for this cancellation with `units`, `at_cost`, and `at_value`, explicit USD, the unobserved-EUR request with retained raw USD, a non-USD synthetic variant, truly empty accounts, and nonzero/mixed-currency aggregate controls. Keep raw/GraphQL values, schemas, and authorization intact. Run backend-v2 typecheck, tests, and OpenAPI drift generation when implementing.
