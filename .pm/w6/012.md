# Normalize recognized interval names before selecting report grouping

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** ledger. **A1 — Agent-native accounting:** a recognized daily or weekly interval name should retain its grouping when an agent capitalizes it, matching the Fava interval contract being ported.

## Live reproduction

Production `https://beancount.io`, 2026-10-11; main `7a99172a`. MCP `beancount-mcp` 1.0.0, protocol `2025-11-25`; deployed SHA unavailable. Existing designated unpinned QA API key, scopes `ledger.read ledger.write ledger.admin`; read-only public synthetic `open_ledger/example`.

Read:

```text
beancount://open_ledger/example/interval-totals?accountName=Assets%3AUS%3ABofA%3AChecking&conversion=units&time=2017-05&interval=daily&shape=fava
```

It returns 31 daily points, May 1–31. Change only `interval=daily` to **`interval=Daily`**: a successful resource read returns **one** May-31 point, the monthly aggregate `{"USD":"-401.61"}`. A fresh repeat has the same result; both REST controls match. Daily amounts sum to that same -401.61, so the defect changes the requested grouping rather than losing the total.

Likewise, `interval=weekly` returns five period ends (May 7, 14, 21, 28, 31), while `interval=Weekly` returns one May-31 aggregate. Lowercase `daily` and `weekly` match the independently reconciled daily/weekly account-report controls for this account and month.

GraphQL `getLedgerIntervalTotals` with `ledgerId: "open_ledger/example"`, the same `accountName`, `conversion: "units"`, `time: "2017-05"`, and `interval: "daily"` versus `"Daily"` returns 31 versus one point, without errors. The raw point contents match MCP/REST after the normal `accountBalances` field-name mapping.

Exact helper pattern: `node .agents/skills/qa-shared/scripts/qa-mcp.mjs --credentials-file .env read '<URI above>'`.

## Root cause and bounded repair

`backend-cluster/ledger/src/foundation/rustledger/interval-series.ts:resolveInterval` indexes `INTERVAL_ALIASES[key]` using the request spelling unchanged. The public report arguments are strings, so capitalized recognized names reach that lookup, miss the lowercase-only keys, and enter the fallback to monthly. `LedgerDataService` passes `interval` through; backend-v2's REST, MCP and GraphQL adapters likewise preserve the value.

The official [Fava interval resolver](https://github.com/beancount/fava/blob/main/src/fava/util/date.py#L327) lowercases names before selecting its interval and aliases. Thus `Daily` and `Weekly` are recognized Fava inputs, distinct from genuinely unknown names for which this port deliberately retains a monthly fallback. No repository policy declaring these recognized aliases case-sensitive was found.

Normalize letter case before the shared interval lookup. Preserve the existing fallback for genuinely unknown names, all ten current lowercase names/aliases, and the calendar boundaries, amounts and explicit-window semantics. Cover lowercase/title/upper/mixed case for the accepted names with a date span that distinguishes daily, weekly, monthly, quarterly and yearly output. Include a report-level case comparing `daily`/`Daily` and `weekly`/`Weekly` over a fixed month, asserting dates and balances rather than only success status.

The resolver supplies both `intervalTotals` and `accountBalanceSeries`. Data-service interval/account reports and finance-service overview/statement/net-worth series share it. Those additional consumers are source-traced; the live reproduction is interval totals across all three eligible protocols. A ledger-domain normalization keeps the adapters in parity without duplicating translations or changing schemas. Acceptance: equivalent case spellings produce identical period dates and amounts, and native ledger checks pass (`yarn test`, `yarn lint`, `yarn typecheck`, `yarn build`; engine verification where required by the scoped guide).
