# Preserve Beanquery GETPRICE currency argument normalization

**Severity:** minor · **Package:** ledger, with backend-v2 parity validation · **Estimate:** 35–50m after a compatible upstream release.

**A1 — Agent-native accounting.** An agent asking for a known exchange rate with lowercase currency arguments receives a missing value instead of the rate returned for uppercase arguments.

## Reproduction

Live 2026-10-15, https://beancount.io/api-gateway/mcp, synthetic open_ledger/crypto-example, designated unpinned QA API key (ledger.read/write/admin). Last observed server beancount-mcp 1.0.0, protocol 2025-11-25; deployed backend/engine revision unavailable. Read-only requests.

Call runBqlQueryStructured using the root .env:

```json
{"ledger": "open_ledger/crypto-example", "query": "SELECT GETPRICE('WETH', 'USD', 2026-09-15) AS upper_case, GETPRICE('weth', 'USD', 2026-09-15) AS lower_base, GETPRICE('WETH', 'usd', 2026-09-15) AS lower_quote LIMIT 1"}
```

Repeated fresh MCP requests return HTTP 200, ok true, one row `["2399.69", "", ""]`. REST POST /api-gateway/v1/ledgers/open_ledger/crypto-example/query with the same query and GraphQL queryShell return the same table. Native missing values are null; the adapter's existing blank rendering is not the cause. Expected all three rates to be 2399.69, following Beanquery's explicit normalization of GETPRICE string arguments.

Working controls: the ledger's WETH/USD manual price history contains 2399.69 on 2026-09-15. Uppercase direct/inverse/identity queries return 2399.69, 0.0004167204930636873929549233 and 1; independent rational arithmetic verifies the inverse within half its last decimal unit. A lookup before the first quote returns missing as expected. These controls check internal lookup behavior, not the market accuracy of synthetic prices.

Minimal valid native fixture:

```beancount
2026-01-01 open Assets:Test USD
2026-01-01 open Equity:Opening USD
2026-01-02 price EUR 1.20 USD
2026-01-03 * "Synthetic opening"
  Assets:Test 10 USD
  Equity:Opening -10 USD
```

```sql
SELECT GETPRICE('EUR','USD',2026-01-02) AS upper_case,
       GETPRICE('eur','USD',2026-01-02) AS lower_base,
       GETPRICE('EUR','usd',2026-01-02) AS lower_quote LIMIT 1
```

Installed @rustledger/wasm 0.24.0 Ledger.fromFiles(...).query(...) returns `["1.20", null, null]` with no validation/query errors. Official Beanquery 0.2.0 over the identical valid in-memory fixture returns `["1.20", "1.20", "1.20"]`.

## Root cause and repair direction

[Beanquery query_env.py](https://github.com/beancount/beanquery/blob/master/beanquery/query_env.py) explicitly constructs `(base.upper(), quote.upper())` before calling prices.get_price. Tagged [rustledger executor](https://github.com/rustledger/rustledger/blob/v0.24.0/crates/rustledger-query/src/executor/mod.rs) clones both strings unchanged in its GETPRICE arm, then calls price_db.get_price. The [price database](https://github.com/rustledger/rustledger/blob/v0.24.0/crates/rustledger-query/src/price.rs) uses exact base/quote lookup keys. Fresh upstream main source still has this unchanged string handling; no published fix or fixed commit was identified. Latest npm and installed WASM were both 0.24.0.

The ledger shell's engine query path delegates to Ledger.fromFiles(...).query(...); a valid direct native reproduction removes API adapters and cache as prerequisites. Normalize GETPRICE arguments at the upstream query function boundary in line with Beanquery. After upstream publishes support, adopt the compatible dependency with the ledger package manager and validate the actual engine plus REST/GraphQL/MCP together. Do not uppercase all ledger commodity data, rewrite arbitrary queries, patch adapter cells, fork the engine or vendor unreleased bytes.

Acceptance: uppercase, lowercase and mixed-case base/quote arguments resolve to the same direct/inverse rates; same-currency lookup remains 1; historical cutoffs, before-first/missing-price nulls and decimal precision remain correct. Preserve API envelopes and missing-value rendering. Exercise fresh and cached ledger loads. Mixed-case, chained-rate and cache variants are acceptance work, not claimed live coverage here.
