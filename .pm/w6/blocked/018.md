# Adopt upstream MIN/MAX support for posting amounts

**Severity:** minor. **Owner:** ledger. **Estimate:** 35–50 minutes after release. **Status:** blocked on the upstream WASM release. **A1 — Agent-native accounting:** an agent should be able to ask for the smallest or largest posting amount without changing a valid aggregate query into a sorting workaround.

## Live reproduction

Production `https://beancount.io`, 2026-10-15; initial local main `52aeaf63`, refreshed `81c1e792`. MCP `beancount-mcp` 1.0.0, protocol `2025-11-25`; deployed backend/engine SHA unavailable. Existing designated unpinned QA API key, scopes `ledger.read ledger.write ledger.admin`. Only public synthetic `open_ledger/freelancer-invoicing` was read; its README identifies fictional example clients.

```sh
node .agents/skills/qa-shared/scripts/qa-mcp.mjs --credentials-file .env call runBqlQueryStructured '{"ledger":"open_ledger/freelancer-invoicing","query":"SELECT MIN(units(position)) AS minimum, MAX(units(position)) AS maximum WHERE account ~ '"'"'^Assets:'"'"' AND number > 0"}'
```

Actual: `isError: true`, `BAD_USER_INPUT`, `Invalid BQL query: Query execution error: type error: cannot compare values`. Fresh separate calls containing only MIN and only MAX both reproduce. Equivalent REST query calls return HTTP 400 with the same message; GraphQL queryShell likewise returns that error. Expected: the minimum **792.40 USD** and maximum **12,000.00 USD** from these 17 positive asset postings, all denominated in USD.

REST: `POST /api-gateway/v1/ledgers/open_ledger/freelancer-invoicing/query`, body containing the query above. GraphQL: `queryShell(ledgerId: "open_ledger/freelancer-invoicing", query: <same query string>) { resultType table { types { name dtype } rows t } }`.

Working controls through both MCP and REST:

```sql
SELECT units(position) AS amount
WHERE account ~ '^Assets:' AND number > 0
ORDER BY units(position) ASC LIMIT 1
```

This returns `{"USD":"792.40"}`. Changing ASC to DESC returns `{"USD":"12000.00"}`. The same filter with `MIN(number), MAX(number)` returns `792.40, 12000.00`. Independent Decimal min/max over the full 23-transaction journal confirms both extrema and the single-currency premise. No comparison across currencies or monetary conversion is involved.

An independent Beanquery 0.2.0 in-memory control uses two balanced transactions with positive asset amounts 2 USD and 10 USD. The identical aggregate expression returns `2 USD, 10 USD`. No hosted ledger was written or exported into a workspace. The successful sorted controls preserve Amount cells as currency maps; they are not plain strings.

## Root cause and existing upstream correction

The local ledger dependency is `@rustledger/wasm` 0.24.0. Its [value_less_than implementation](https://github.com/rustledger/rustledger/blob/v0.24.0/crates/rustledger-query/src/executor/operators.rs#L149), used by MIN/MAX, handles numeric, string, date and boolean values but has no Amount arm. It reaches the demonstrated error fallback even though ORDER BY can order those amounts. The adapters share the ledger query producer, explaining the same failure on all three API surfaces; the exact deployed engine version was not observable.

Upstream already fixes the comparator in [25fc6be5 / PR 2493](https://github.com/rustledger/rustledger/commit/25fc6be5e3ae10e12e2338ffb87651a458c4c739), delegating Amount, Position and Inventory ordering to the existing ORDER BY comparator. The inspected patch includes regression coverage for the different aggregate paths. Only the Amount failure was reproduced live here; Position and Inventory failures are not additional verified findings. Upstream documents intentional differences from Beanquery for some cross-currency/cost ordering, so adoption must preserve that documented policy rather than require blanket Beanquery equality.

The [latest npm WASM package](https://www.npmjs.com/package/@rustledger/wasm) still reports 0.24.0 at this check. This is adoption of an existing upstream correction once released, not a request for an adapter aggregate implementation, another parser or vendored engine source. A current caller can explicitly sort the amounts and take the first row.

## Blocked / Unblock

**Blocked 2026-10-15** — the upstream release publisher has not provided a supported fixed WASM artifact on the checked latest channel.

**Unblock:** a supported published `@rustledger/wasm` artifact containing 25fc6be5 or equivalent Amount MIN/MAX support. Then a repository worker updates the existing ledger dependency with its owning package manager, regenerates the lockfile, and verifies the artifact. Coordinate that single dependency adoption with [016](./016.md) and [017](./017.md), which require different PRINT and date-operator fixes. An upstream main commit alone does not clear the release condition. No new upstream issue or comment was posted.

Acceptance after unblock: actual WASM MIN and MAX over same-currency Amount values agree with sorted endpoints and the independent Decimal extrema; include negative values, NULL skipping and empty input. Keep numeric/date/string aggregates working. Run relevant upstream-supported Position/Inventory cases under the documented ordering policy, without claiming those were live-proven here. Exercise query-adapter parity for REST, GraphQL and MCP; run the owning ledger native checks and separately recheck the hosted deployment. Preserve the GPL boundary and existing parity gates.
