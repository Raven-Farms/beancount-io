# Preserve negative SPLITCOMP component indices

**Severity:** minor · **Package:** ledger, with backend-v2 parity validation · **Estimate:** 35–50m after a compatible upstream release.

**A1 — Agent-native accounting.** Queries extracting the last account component using SPLITCOMP(..., -1) silently receive the account root, changing labels and any downstream grouping based on them.

## Reproduction

Live 2026-10-15 against https://beancount.io/api-gateway/mcp, synthetic open_ledger/freelancer-invoicing, designated unpinned QA API key (ledger.read/write/admin). Last observed beancount-mcp 1.0.0, protocol 2025-11-25; deployed revision unavailable. No ledger writes.

Call runBqlQueryStructured using the root .env:

```json
{"ledger": "open_ledger/freelancer-invoicing", "query": "SELECT account, SPLITCOMP(account, ':', 0) AS first_part, SPLITCOMP(account, ':', -1) AS last_part, LEAF(account) AS leaf_name, SPLITCOMP(account, ':', -2) AS parent_part LIMIT 3"}
```

Two fresh MCP requests succeed with identical rows; REST POST /api-gateway/v1/ledgers/open_ledger/freelancer-invoicing/query repeats the result twice, and GraphQL queryShell agrees once:

| account | index 0 | index -1 (actual) | LEAF control | index -2 (actual) |
| --- | --- | --- | --- | --- |
| Assets:Bank:Business | Assets | Assets | Business | Assets |
| Assets:Bank:TaxReserve | Assets | Assets | TaxReserve | Assets |
| Equity:Opening | Equity | Equity | Opening | Equity |

Expected index -1 to return Business / TaxReserve / Opening and index -2 to return Bank / Bank / Equity. All chosen indices are in range. Positive index 0 and LEAF are working controls. A further full 50-posting query verifies index 1 and LEAF against independent string splits; both pass on every row, while index -1 is wrong on all 50. REST matches the entire table. The preceding full 50-posting PARENT/LEAF/GREP/SUBST journey also matched independent account string operations and REST.

Minimal valid fixture:

```beancount
2026-01-01 open Assets:Bank:Business USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "Synthetic opening"
  Assets:Bank:Business 10 USD
  Equity:Opening -10 USD
```

Run the same SELECT without LIMIT against this fixture. Installed @rustledger/wasm 0.24.0 Ledger.fromFiles(...).query(...) returns the two account rows with every negative-index result equal to index 0, no validation/query errors. Official Beanquery 0.2.0 over the identical valid fixture returns Business/Bank for Assets:Bank:Business and Opening/Equity for Equity:Opening. This independent control establishes negative indexing semantics without relying on the API adapters.

## Root cause and repair direction

[Beanquery query_env.py](https://github.com/beancount/beanquery/blob/master/beanquery/query_env.py) implements SPLITCOMP by indexing the split components directly, preserving negative indices. The [tagged rustledger query executor](https://github.com/rustledger/rustledger/blob/v0.24.0/crates/rustledger-query/src/executor/mod.rs) clamps integer indices to zero before converting to usize in the SPLITCOMP arm; negative values therefore select the first component. Fresh upstream main still has this clamp. Latest npm and installed WASM were 0.24.0; no fixed commit or published repair was identified.

Local src/foundation/rustledger/engine.ts::queryLedgerFilesResultInProcess delegates the query through the cached native Ledger object. The direct native fixture reproduces independently of worker/cache/API layers. After upstream publishes a compatible engine with signed component indexing, adopt it with the ledger package manager and validate eligible REST/GraphQL/MCP behavior together. Preserve positive-index behavior and supported delimiter semantics. Do not rewrite user queries, replace projected cells, fork upstream or vendor unreleased WASM.

Acceptance: in-range -1/-2 select components from the end across two- and three-component accounts; positive 0/1 remain correct; repeated queries and all three APIs agree with the real native engine and independent expected values. Include a grouping regression using an extracted suffix after the primitive works. Out-of-range indices, empty delimiters and null inputs need explicit compatibility decisions/tests and were not live-verified here; do not silently clamp invalid indices to a valid component as a repair.
