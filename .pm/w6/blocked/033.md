# Preserve typed zero amounts from ONLY inventory extraction

**Severity:** minor · **Package:** ledger, with backend-v2 parity validation · **Estimate:** 35–50m after a compatible upstream release.

**A1 — Agent-native accounting.** An agent extracting a known zero balance from an inventory must receive a zero amount in the requested currency, rather than a missing value that changes downstream null handling.

## Reproduction

Live 2026-10-15, https://beancount.io/api-gateway/mcp, synthetic open_ledger/crypto-example, designated unpinned QA API key (ledger.read/write/admin). Last observed beancount-mcp 1.0.0, protocol 2025-11-25; deployed revision unavailable. No ledger writes.

Call runBqlQueryStructured using the root .env:

```json
{"ledger": "open_ledger/crypto-example", "query": "SELECT ONLY('ETH', SUM(position)) AS eth_amount, ONLY('ARTNFT', SUM(position)) AS zero_net_amount, ONLY('NO_SYNTHETIC_CURRENCY', SUM(position)) AS missing_amount, EMPTY(FILTER_CURRENCY(UNITS(SUM(position)), 'ARTNFT')) AS zero_empty, EMPTY(FILTER_CURRENCY(SUM(position), 'NO_SYNTHETIC_CURRENCY')) AS missing_empty"}
```

Two fresh MCP/REST queries and one GraphQL queryShell request return the same successful row:

```json
[{"ETH":"7.07495"},"","",true,true]
```

The native zero_net_amount and missing_amount are null; the existing wire mapper renders them blank. Expected typed amounts 0 ARTNFT and 0 NO_SYNTHETIC_CURRENCY respectively, preserving the requested currency as Beanquery does. EMPTY correctly returns true for both empty filtered unit inventories. Nonzero ETH extraction works and matches the complete 304-posting journal's net units. A nested MCP/REST control, COALESCE(NUMBER(ONLY('ARTNFT', SUM(position))), 42), returns the fallback 42 rather than numeric 0; the corresponding ETH expression preserves 7.07495. This makes the lost zero observable beyond formatting. The journal has two ARTNFT postings, -1 and 1, and no posting in the synthetic missing currency.

Minimal valid fixture:

```beancount
2026-01-01 open Assets:Bank:Business USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "Synthetic opening"
  Assets:Bank:Business 10 USD
  Equity:Opening -10 USD
```

```sql
SELECT ONLY('USD', SUM(position)) AS zero_amount,
       ONLY('EUR', SUM(position)) AS missing_amount,
       EMPTY(SUM(position)) AS is_empty
```

Installed @rustledger/wasm 0.24.0 Ledger.fromFiles(...).query(...) returns `[null, null, true]`, no validation/query errors. Official Beanquery 0.2.0 over the identical valid in-memory fixture returns 0 USD / 0 EUR / true. The balanced USD postings cancel completely, while EUR was never present. This is a native value-semantic error, not solely the known column-type inference issue.

## Root cause and repair direction

[Beanquery ONLY](https://github.com/beancount/beanquery/blob/master/beanquery/query_env.py) delegates to [Inventory.get_currency_units](https://github.com/beancount/beancount/blob/master/beancount/core/inventory.py), which returns an amount in the requested currency, including zero. The [tagged rustledger executor](https://github.com/rustledger/rustledger/blob/v0.24.0/crates/rustledger-query/src/executor/mod.rs) ONLY inventory arm calculates total units, then explicitly returns Null when total.is_zero(). Fresh upstream main retains that branch. A valid direct native fixture removes adapters/cache as prerequisites. Local ledger src/foundation/rustledger/engine.ts::queryLedgerFilesResultInProcess delegates to that query engine.

After upstream publishes a compatible artifact, adopt it with the ledger package manager and verify actual native results plus eligible REST/GraphQL/MCP together. Inventory extraction of a valid currency must preserve zero as an Amount, while genuinely null operands keep their null propagation. Preserve nonzero/negative values, currency selection, existing EMPTY semantics and envelopes. Do not replace every missing API cell with zero, patch projected values, rewrite user queries, fork upstream or vendor unreleased bytes. Position/Amount overload mismatch behavior is separate and was not exercised here.

Acceptance: empty inventory, cancelled units and absent-currency extraction each produce the requested typed zero; positive/negative extraction remains correct; EMPTY still reflects inventory emptiness; null inputs remain null. Include nested NUMBER/COALESCE or equivalent regression coverage so the zero-versus-null distinction is observable beyond formatting. Native-backed tests and all eligible API surfaces agree. Nested zero/ETH COALESCE expressions were exercised above; cost-lot cancellations with nonzero cost and null operands remain acceptance work, not claimed live coverage. Latest published and installed WASM checked this session were 0.24.0; no fixed commit identified.
