# Disable import and receipt file pickers until hydration

**Severity:** minor (lost initial user action). **Estimate:** 45–60 minutes for one bounded readiness repair across two upload control groups, dashboard. **A2:** an available file-picker action should not silently discard a reader's activation while the page initializes.

Production `https://beancount.io`, 2026-10-20, English/System theme, QA-owned isolated headless Chromium155.0.8059.85. Authenticated owner of the designated disposable synthetic ledger. Local main `c5e4cd11a`; deployed `main-D9qWGMxD.js`, full deployed revision unverified. Both relevant deployed sources match local byte-for-byte. No scripts were delayed and no API reads faulted in the retained picker reproductions.

## Reproduce and working controls

1. In a fresh authenticated context, navigate directly to `/ledger/<qa-owner>/<synthetic-ledger>/import`. Click the visible, enabled Browse files button as soon as it is available. The trusted native click reaches a button whose React onClick has not attached. No file chooser opens.
2. Wait until the handler is observed attached, then another 600 ms without another action. No delayed/replayed chooser appears. Retry the same button: exactly one chooser opens. Cancel with an empty selection; no file, upload or AI operation occurs.
3. Independently repeat with native Enter, both 1440×1000 and 390×844, and on `/receipt` with Choose File. All eight fresh cases lose the first action and work on retry. Recorded click/handler times in milliseconds after navigation start:

A document capture listener records native clicks; handler observation only checks for an existing React DOM onClick function, without installing/invoking it or changing disabled state. Actual Playwright filechooser events establish whether the action worked.

Two additional fresh narrow pointer controls capture diagnostics and reproduce: Import 3049/3407 ms and Receipt 1444/3874 ms. Unrelated sidebar reads abort during loading/teardown; they are not classified as failures causing the picker behavior. All chooser events were canceled empty, with zero mutation attempts. ## Cause and bounded repair

`features/importer/components/steps/upload/file-upload.tsx:98–99,125,164–176` server-renders the enabled Browse files button and clickable wrapper. Both rely on JavaScript calling the hidden `csv-upload` input's click method; only the input's parsing-busy condition is disabled. `features/receipt/components/receipt-upload-zone.tsx:75–76,100,139–151` has the equivalent Choose File/wrapper arrangement, with only the input gated on uploading. Neither initial picker has a hydration readiness gate or native pre-handler fallback.

Use the existing TanStack `useHydrated` convention already applied to Overview's Net Worth view buttons. Make these two upload picker control groups honestly unavailable before handlers are ready, then enable them on hydration. Include the clickable wrapper while preserving parsing/upload busy conditions and hidden-input behavior; disabling only a nested button must not leave its wrapper advertised as active. Preserve readable SSR instructions, file validation, write-permission gating, free client CSV parsing, explicit AI consent and normal chooser activation. Do not change global Button behavior, add timers/dependencies, hide the whole page, change API contracts or redesign every SSR interaction. Early drag/drop and post-selection Choose Different File are source-audit scope, not independently reproduced lost-action claims.

Acceptance: actual SSR followed by deferred hydration exposes unavailable initial picker controls; hydration enables pointer/Enter/Space activation at both widths. Cancellation stays harmless, normal CSV preview still needs no AI, and Receipt's validation/upload-failure recovery remains intact. Add meaningful hydration regression and browser checks of disabled→enabled state plus actual chooser activation; a client-only handler mock cannot verify this. Run dashboard format/lint/test/build when implementing. No actual Receipt parsing, asset upload or booking is needed.

FileUpload has one production caller, `components/steps/upload/index.tsx`, mounted by Smart Import. ReceiptUploadZone has one, `receipt/pages/receipt-page.tsx`, mounted only for writers. Other editor upload controls were not independently tested for this initial-action failure.
