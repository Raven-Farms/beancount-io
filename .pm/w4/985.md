# Stop Create Ledger's Next from submitting the ledger before Review

**Severity:** major. **Estimate:** 30–45 minutes, dashboard. **A2:** a newcomer creating their first ledger must see and confirm the Review step before anything is written.

Found while verifying [313](./done/313.md), 2026-10-22. The check used a local production build of `8cba9962b`, the fixture API with `--synthetic-owner`, fresh 1440×1000 and 390×844 pages, and every mutation blocked before transport. The deployed site was not exercised, and no ledger was created.

## Reproduction

1. Open `/ledger` and activate **Create Ledger**. At 390 px, open the sidebar first.
2. Step 1 of 3 (the starter template): activate **Next**. Step 2 of 3 (Details) shows the default name.
3. Activate **Next** again, by pointer or by native Enter. A **CreateLedger** mutation is sent at once, with the current form values, and the dialog then shows Step 3 of 3 (Review).

Every run reproduced it: 2 of 2 at 1440, one pointer and one Enter, plus 6 of 6 across both widths during the 313 verification. All attempts were blocked before transport. With a real server the ledger would be created before the reader sees Review. Its "Create Ledger" confirmation would then repeat a write that has already landed; the request id should make that idempotent, but this was not verified.

## Cause and bounded repair

`dashboard/src/features/ledger-list/components/ledger-form.tsx`, around lines 768–795, renders Next (`type="button"`) and the submit button (`type="submit"`) as the two branches of `isCreate && step < 2 ? … : …`. That puts them in one JSX slot, so React reuses a single `<button>` element.

`nextStep` (around line 316) awaits `form.trigger("name")` and only then calls `setStep(2)`. That re-render flips the same element to `type="submit"` before the browser runs the click's activation behavior, so the click submits the form.

Repair: give the two buttons distinct identities (separate `key`s), so the review step mounts a fresh submit button. Alternatively, make the form's submit handler ignore a submit while `step < 2`. Either way, Review must be reachable with no write, and its own Create Ledger must send exactly one. Preserve name validation on Details, Back, the draft resume (w3/m54/t006), the ledger-limit gating (313), and the edit form's Save.

Acceptance:
- Natively at both widths, Next from Details by pointer and by Enter reaches Review with zero CreateLedger requests.
- Create Ledger on Review sends exactly one request with the reviewed values.
- A regression covers the transition. jsdom may not run the button's activation behavior the way Chromium does, so prove the test fails without the fix.
- Dashboard format:check, lint, test and build pass.

## Dedupe

All board states were searched for ledger-form, CreateLedger submitted early and the review step. [W3/m54](../w3/blocked/m54/README.md) introduced the staged wizard. Its draft-resume work and 313's limit gating do not touch the button identity. No matching open or completed repair was found.
