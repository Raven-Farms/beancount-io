# Name imported amounts with the normalized value shown in preview

**Severity:** minor. **Estimate:** 25–40 minutes, dashboard. **A2:** a person reviewing a bank import through accessible names should receive the same interpreted amount as a person reading the preview.

Production `https://beancount.io`, 2026-10-20, English, QA-owned headless isolated Chromium 155.0.8059.85, authenticated disposable synthetic ledger. Repeated from fresh loads at 1440×1000 and 390×844. Local main `c5e4cd11a`; the two relevant deployed source-map contents exactly match local source. No AI parsing or categorization was invoked.

## Reproduce

1. Open `/ledger/<qa-owner>/<disposable-ledger>/import` and upload this semicolon-delimited CSV:

   ```csv
   Date;Payee;Description;Amount
   2026-10-20;qa-20261020-eu-credit;qa-20261020 grouped credit;2.500,00
   2026-10-20;qa-20261020-eu-fee;qa-20261020 comma fee;-4,50
   2026-10-20;qa-20261020-eu-debit;qa-20261020 grouped debit;-1.000
   ```

2. All three rows are valid and show their correctly interpreted amounts: `2500.00`, `-4.50`, `-1000`. There are no validation alerts.
3. Inspect row 3's actual button name: **`Edit Amount, row 3. Current value: -1.000`**, while its visible text is **`-1000`**. No amount button is named with `Current value: -1000`. This retains the bank token's ambiguity in the nonvisual preview even though the visual preview explicitly resolved it.
4. The date also displays `10/20/2026` while its name says `Current value: 2026-10-20`. The Payee control agrees in both forms and is a working control.
5. Open the amount editor: its correctly named `Amount, row 3` input contains the intended raw token `-1.000`. Escape returns to the same collapsed mismatch. Repeat after a fresh upload at the other width: identical result.

## Cause and repair

`dashboard/src/features/importer/components/steps/preview/editable-cell.tsx:238` interpolates raw `value` into `importer.preview.editCellLabel`, but `:264` renders `displayValue` when supplied. The only production consumer is `editable-preview-row.tsx`, whose four cell sites supply normalized amount readings (`:73`, `:205`) and localized dates (`:131`); Payee and Description retain raw display values.

Use the same resolved display value for the collapsed button's visible content and current-value name, including the existing empty/placeholder behavior. Keep the raw token in the editing input and keep the column's decimal convention, exact normalized submission, validation associations, row/field names and keyboard dismissal. This is a dashboard presentation fix; no API or dependency change is indicated.

Acceptance: a rendered preview driven by the real CSV parser names the fixture's amounts with their displayed normalized values and names the date with its localized display. Opening the editor still exposes the raw token; a valid edit updates both collapsed forms. Preserve plain dot-decimal and Payee/Description controls, invalid/empty cells, disabled states and error descriptions. Repeat the browser journey at both widths and run dashboard checks when implementing.
