# Remove the unsupported blank transaction status

**Severity:** minor. **Estimate:** 40–55 minutes, dashboard. **A2:** New Entry should offer transaction statuses that survive saving, without silently turning a selected blank status into Cleared.

Production `https://beancount.io`, 2026-10-20, QA-owned isolated headless Chromium155.0.8059.85, English, System theme without a media override, authenticated owner of the designated disposable synthetic ledger. Desktop1440×1000 and fresh narrow390×844 document loads. Local main `c5e4cd11a`; deployed `main-D9qWGMxD.js`, full deployed revision unverified.

## Reproduction and observed values

1. Open `/ledger/<qa-owner>/<synthetic-ledger>/journal?action=new-entry&directive=transaction`. Use a prefixed payee and two existing accounts: Assets:Cash −1 USD and Expenses:Food:Groceries +1 USD. No new account or auto-open action is needed.
2. Open the named Status combobox. It offers `* Cleared`, `! Pending`, and `(blank)`. Choose `(blank)`; the selected control actually announces `(blank)`.
3. Activate Create Transaction Entry once. The genuine BulkEntries request contains `transaction.flag: ""`. HTTP200 reports success and the modal closes.
4. The saved row displays `*`. Independent QueryShell readback returns flag `*` for the exact prefixed payee. Its two rows correspond to the two postings of this one transaction, not two bookings.
5. Raw file readback preserves the original file prefix and appends a header with two spaces between date and payee, such as `2026-10-20  "qa-20261020 status-choice-control" ""`; there is no flag token. The hosted ledger reports zero errors and interprets it as Cleared.
6. Restore the exact baseline, then repeat from a fresh390px load with a different prefixed payee. Again the selected value is `(blank)`, the request flag is empty, success is reported, and the UI/API flag is `*`. Restore again.

Working controls use the same valid form and native selector: Cleared emits `*` and Pending emits `!` unchanged. Those two payload controls were deliberately aborted before transmission; only the two blank-status probes above were sent and booked. A failure control retains the draft and useful connection guidance. No AI quota, other ledger, credentials or account settings were touched.

## Cause and bounded repair

`dashboard/src/features/journal/components/new-directive-dialog/transaction-form.tsx:395–413` explicitly offers and names a space-valued blank option. The form schema at:112 applies `z.string().trim()`, converting it to the empty string; transactionInput at:267 forwards that value. Thus the dashboard presents a status its ordinary save/read path cannot preserve.

The [upstream Beancount transaction grammar](https://github.com/beancount/beancount/blob/master/beancount/parser/grammar.y#L270-L291) requires the transaction keyword or a supported flag token; it provides no blank transaction status. The directly reproduced problem here is the dashboard choice and its roundtrip, not a claim that the hosted parser reported an error. A separate stock-parser execution was not performed.

Remove the unsupported blank option and its selected-value branch; constrain this New Entry form's flag schema to its supported Cleared/Pending values rather than trimming arbitrary input into an empty flag. Keep default Cleared, actual Pending, the localized Status name/selected-value semantics, keyboard selection, exact postings, validation and pending/retry behavior. Remove the now-unused blankStatus locale key consistently if it has no other consumer. Do not invent a new ledger status, broaden the upstream grammar, silently map a still-visible Blank option to Cleared, or restrict valid custom flags in unrelated source/API workflows.

This repair belongs to dashboard and changes no backend capability or REST/GraphQL/MCP contract. TransactionForm is owned by the shared New Entry dialog, reached from Journal entry actions and supported action/directive deep links. Other directive forms have no such status picker.

Acceptance: real selector/form interaction exposes only supported statuses and emits the selected nonempty flag. An attempted empty/space value cannot reach mutation submission. Preserve native status naming and keyboard controls, Cleared/Pending roundtrips, failure draft/retry and m33's pending-submission guard. Test the actual form payload rather than mocking the selector or checking only option text; run dashboard format/lint/test/build.
