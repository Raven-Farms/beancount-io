# Leave file-editor Escape to Monaco's active widgets

**Severity:** minor. **Estimate:** 45–60 minutes. **Owner:** dashboard. **A2:** dismissing an editor suggestion or Go to Line prompt should keep the reader in their current edit, without opening a file-departure decision.

## Reproduction and controls

Production `https://beancount.io`,2026-10-22; owned isolated headless Chromium155.0.8059.85, English/light/UTC, authenticated designated disposable QA ledger. Fresh390×844 and1440×1000 contexts independently reproduce this. Only unsaved edits; no Save, mutation or hosted write.

1. Open main.bean with editMode=true. At the actual Monaco editor, use native Cmd+End and append a prefixed local comment followed by an indented **Ass** on the next line.
2. Native Ctrl+Space opens Monaco's visible completion list with **Assets**. The editor textbox retains focus; Find is closed.
3. Press ordinary Escape. Instead of only dismissing completion, the app opens **Unsaved Changes / Stay / Leave Without Saving** and focuses Stay. The exact editor draft is retained. The fresh desktop event record confirms trusted Escape/keyCode27, isComposing=false, with the editor textbox as target.

This is an incorrectly initiated departure flow, not automatic draft deletion, a failed save or an input-method composition failure. The guard correctly protects the draft once invoked.

Passing desktop controls after Stay and explicit editor refocus:

- Reopen the same completion list and press Enter: Ass becomes Assets, with no departure dialog and the rest of the draft intact.
- Native Cmd+F followed by Escape closes Find, retains the exact draft and returns editor focus, with no departure dialog.
- With both widgets closed, ordinary Escape correctly opens Unsaved Changes. Explicit Leave Without Saving restores the original complete buffer and canonical read-only file URL. The narrow case also restores its complete original buffer after explicit discard.

Additional same-cause control: fresh1440 and390 dirty file editors open **Go to Line** with native Ctrl+G. The actual quick-input textbox says **Type a line number to go to (from 1 to 90)** and has no dialog/menu/Radix-popup ancestor. Escape again opens Unsaved Changes, retains the exact draft and focuses Stay. In the narrow control, accepting a subsequently reopened Go to Line prompt with Enter closes that widget without a departure dialog or draft change; exact destination-caret position was not established. Both complete buffers are restored by explicit discard. This is the same file-level key-ownership repair, not a second finding group.

## Source and bounded repair

`dashboard/src/features/ledger-editor/file-editor/components/ledger-file-view/text-editor.tsx:88–125` captures document keydown before Monaco handles it. For non-composing Escape it invokes shouldCancelEditOnEscape, prevents default/propagation and calls onCancel. `text-editor-utils.ts:55–67` protects the Find contribution and external dialog/menu/Radix-popup targets, but has no completion-widget ownership check. Completion retains focus on the editor textbox, which is outside those overlays.

The installed Monaco `esm/vs/editor/contrib/suggest/browser/suggestController.js:765–773` already binds **hideSuggestWidget** to Escape while its widget is visible and the text input is focused. The file-level capture listener takes the key before that existing editor action can dismiss completion.

Respect an active completion or Go to Line widget before starting file cancellation and let Monaco handle its existing dismissal. Keep this within the current editor integration; do not copy its widget controllers, patch dependencies or suppress all Escape actions. Preserve Find/Replace and external-layer ownership, the composition lifecycle guard, ordinary clean/dirty cancellation, read-only mode, save/find shortcuts and exact draft/caret behavior. No persistent draft store, dependency or backend/API change is indicated.

Acceptance: with the actual editor and a visible completion or Go to Line prompt, Escape closes only that widget, keeps edit mode/draft/focus and allows continued typing. A later Escape without a widget still invokes the correct cancellation decision. Preserve ordinary widget acceptance, Find dismissal and composing Escape, repeat desktop/narrow and run dashboard gates when implementing. A helper-only Find mock does not prove these widgets' ownership.
