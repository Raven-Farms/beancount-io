# Keep loaded Version History pages while selecting a commit

**Severity:** minor. **Estimate:** 45–60 minutes, dashboard. **A2:** reviewing neighbouring older changes should not require loading the same history page again after every selection.

Production `https://beancount.io`, 2026-10-20, English, QA-owned headless isolated Chromium 155.0.8059.85, designated disposable synthetic ledger. Fresh desktop 1440×1000 and narrow 390×844 reproductions. Local main `c5e4cd11a`; relevant deployed sources exactly match local files. This check only reads commits already created by the authorized QA journeys.

## Reproduce

1. On a synthetic ledger with more than 60 commits, open `/ledger/<owner>/<ledger>/commits` and let it select the newest commit. On narrow screens open **Version History**.
2. Press **Load older commits**. There are now 60 unique links, with the original 30 preserved in order. Focus remains on the load control: the existing pagination/focus fixes work.
3. Select a commit from the appended page, such as link 31. Its correct detail and diff load successfully.
4. Desktop history now has only **30 links**; the selected older commit is absent. The notice says **“The selected commit is outside the loaded history.”** On narrow screens the sheet closes normally, but reopening it reveals the same 60→30 reset and missing selected link.
5. Load the older page again to recover the neighbouring links. Choosing another older commit repeats the reset. Fresh loads at both widths reproduce this at natural latency, without intercepted responses.

Actual synthetic targets were `86131f7a4b92ebac7ef929322cbe058127fb22cb` (Delete file qa-20261020-notes.txt, desktop) and `dea232246d7bd725a0488ccc148f751ffd6273c1` (Update file qa-20261020-notes.txt, narrow). All relevant ListCommits/GetCommitDetails responses were HTTP 200 without GraphQL errors. The details themselves are correct; older history remains reachable by repeatedly loading it.

## Cause and bounded repair

`dashboard/src/common/components/ledger-layout/index.tsx:48–55` treats a changed commit pathname as route-pending, and `:145–153` replaces the entire Outlet with ReportLoadingState. This unmounts the history workspace while `features/git/commits/loaders/commit-loader.ts:20–28` reads the selected detail. `commits-split-view.tsx:47–51,71–78` consequently recreates its cursor/state and performs a fresh network-only page-1 query.

A separate diagnostic held one real GetCommitDetails request for 300ms, then continued it unchanged: the previously connected history nav became disconnected and link count became zero during loading; after success a new history nav contained 30 links and the outside-history notice. The interception was removed. This confirms the lifetime mechanism rather than blaming the paging API or a failed detail read.

Keep the ledger-scoped history workspace, loaded pages, cursor and list position through same-ledger commit selection, while showing truthful pending/error states for the changing detail. A scoped retained workspace/pending boundary can address this; do not simply expose the previous commit's diff under a new selected SHA. Preserve ledger-switch reset and abandoned-fetch guards, SHA deduplication, load/retry/end focus, initial newest selection, mobile sheet dismissal and the legitimate notice for an independently deep-linked commit outside the loaded pages. Both CommitDetailPage and CommitsListPage consume the workspace; the generic layout also serves other features, whose loading/access protections must remain intact.

Acceptance: mount the actual ledger layout, router, commit loader and Apollo pagination; load two pages, select an uncached page-2 commit through a delayed successful read, and retain the 60 links, cursor and selected item after settlement. The next load must request page 3. Exercise narrow sheet reopen, direct older deep links, detail failure/retry and ledger-switch isolation. A test mounting only CommitsWorkspace misses the unmounting parent. Run dashboard checks when implementing; no API or dependency change is required.
