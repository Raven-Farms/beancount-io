## Objective

Retaining unsaved text must also preserve the original revision against which that text was edited.

## Steps and acceptance

- [ ] Keep ledger/path/edit-base SHA consistent for a retained draft. A newer file read must not rebase the draft's Save onto that remote SHA without an explicit supported decision.
- [ ] Verify a prepared stale Save uses the original SHA and keeps the exact draft after refusal; independent remote bytes remain unchanged. This is compatibility coverage, not a reproduced overwrite from QA.
- [ ] Preserve BOM/line endings, current-SHA successful-save exit, pending-save readonly/single-write behavior, ordinary dirty Cancel/Stay/Discard and failed-save recovery.
- [ ] Keep stale error-category repair assigned to W23/032. No unconditional overwrite, backend/schema change or new persistence workflow.

## Files

Owning LedgerFileView/TextFileView save and revision state within `dashboard/`; use the minimal state needed by the retained session.
