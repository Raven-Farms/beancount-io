# Protect unsaved source edits on standalone entry pages

**Severity:** minor. **Estimate:** 45–60 minutes, dashboard. **A2:** a person opening a shared entry URL can edit its source, but leaving the page silently discards that work. The same editor opened from Journal already asks before discarding.

Production `https://beancount.io`, 2026-10-20, QA-owned isolated headless Chromium 155.0.8059.85, fresh authenticated owner contexts at 1440×1000 and 390×844, English/light. Local main `c5e4cd11a`; relevant deployed sources exactly match local. Only a disposable synthetic ledger was used. No Save/Delete or entry/file mutation was submitted.

## Reproduce and control

1. Open `/ledger/<owner>/<ledger>/entry/<entryHash>` for an ordinary source-backed transaction. Wait for the editable **Editor content** surface and stored source.
2. Append a local comment such as `; qa-20261020-direct-entry-local-draft`. Confirm the rendered text, **Source has been modified** and enabled **Save**.
3. Click **Back to journal**. Journal opens immediately, with no discard decision. Reopen the entry URL: the comment is gone and Save is disabled. Reproduced independently in both fresh viewport contexts.
4. At 390px, type the comment again and click **Open source at main.bean:83**. The file editor opens with `editMode=true&lineNumber=83`, without confirmation or the draft. Stored source is unchanged.
5. Working control in the same fresh narrow context: Journal → open that entry → type the identical comment → Close. The existing **Discard your edit?** dialog appears; **Keep editing** retains the comment and enabled Save. Explicit Discard then closes it.

Expected: leaving a dirty standalone entry page asks whether to keep editing or discard, including the source-file action. A clean page leaves immediately. This concerns browser-local drafts; there is no claim that saved ledger data is lost.

## Cause and bounded repair

The panel reports dirtiness at `entry-context-panel.tsx:167–169`, but no owner consumes it. Its source action at `:563–573` navigates immediately when `confirmLeave` is absent. EntryContextDialog supplies both callbacks and owns the working discard decision.

Connect standalone-page dirtiness to a router exit guard and the existing source-action callback. Reuse the repository's current blocker/discard pattern and localized choices; no persistent draft store or new dependency is needed. Preserve clean navigation, source line/edit-mode destination, reader and managed-source restrictions, and successful delete navigation. Keep a successful own write from being mistaken for an abandoned draft. Cover the real page's Journal/source exits, Keep editing preserving the actual text, explicit Discard reaching the destination, and clean/read-only controls. Include SPA navigation and the existing router unload policy; native-toolbar and unload behavior were not live-verified here. Run dashboard checks when implementing.
