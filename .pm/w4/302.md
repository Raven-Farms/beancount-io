## Cause and bounded repair

It does not check item.id across pages. Lines171–172 then render FeedCard with key=item.id. Newer events move the server's offset boundary, so individually unique pages can overlap and create repeated cards/keys. The raw server page is coherent; this is the client's accumulated-list merge.

Backend backend-cluster/backend-v2/src/features/gitea/feed/service/feed-service.ts:151–167 gets the sorted current feed then slices it by offset; getGiteaFeedItems caches the recent activity window for five minutes. That explains the real movement and does not require a backend pagination rewrite for this bounded repair. Preserve the existing API and authorization contract.
