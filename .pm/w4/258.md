## Cause and bounded repair

`dashboard/src/features/ledger-editor/file-editor/components/non-text-file-views.tsx:271–280` constructs data:image/<extension>;base64 directly. SVG requires image/svg+xml, so the raw extension is insufficient. The existing shared utils.ts::getMimeTypeFromExtension at :292 already maps SVG correctly, and downloadFile uses it successfully.

Use a consistent supported-image MIME mapping in the preview. Audit the full isImageFile extension set when reusing the helper: BMP is classified as an image but is currently absent from the helper's explicit switch. Preserve PNG/JPEG/GIF/BMP/WebP, case-insensitive extensions, exact bytes, alt text, responsive sizing, permissions and download/delete behavior. Do not introduce another independent MIME table or convert source files.

The renderImageContent try/catch at :270–299 cannot catch asynchronous image decode errors, and there is no img onError state. Make a genuine decode failure show the existing localized fallback while keeping Download available. A valid SVG must display; replacing every SVG with an error is not the repair. No API, dependency or cross-package change is needed.

Acceptance: through the real ImageFileView, the recorded SVG loads with native dimensions160×80 at desktop/narrow widths and its pixels are visible. An invalid image reaches a useful fallback, and switching files resets that state. Cover existing image formats and empty content, actual download byte equality and menu/dialog focus controls. A src-string-only test cannot prove browser decoding. Run dashboard checks when implementing.
