# Follow the new entry identity after a standalone source save

**Severity:** minor. **Estimate:** 35–50 minutes, dashboard. **A2:** editing an entry from its shared URL saves successfully, then replaces the editor with a not-found error. The saved entry exists under the new identity already returned by the mutation.

Production `https://beancount.io`, 2026-10-20; QA-owned isolated headless Chromium 155.0.8059.85, separate fresh authenticated owner contexts at 1440×1000 and 390×844, English/light. Local main `c5e4cd11a`; deployed EntryPage and EntryContextPanel match local exactly. Only two prefixed Note fixtures in the designated disposable synthetic ledger were changed, then the original file was restored byte-for-byte.

## Reproduce and control

1. Open `/ledger/<owner>/<ledger>/entry/<entryHash>` for a source-backed Note. The clean editor shows stored source and Save is disabled.
2. Change the Note comment from a prefixed original marker to its updated marker. Wait for the actual rendered source and enabled Save, then click **Save** once.
3. `UpdateLedgerEntrySourceSlice` returns HTTP 200, no GraphQL errors, and a different `entryHash`. The UI announces **Entry saved successfully**.
4. The page URL still contains the old hash. Its next actual `GetLedgerEntryContext` uses that old hash and returns HTTP 200 / `NOT_FOUND`. The editor disappears and the page says **The requested resource could not be found.** The same sequence reproduces independently at both widths.
5. API readback shows exactly two fixture Notes, each updated once, and zero ledger errors. Original pre-fixture file bytes remain intact. At 390px, manually opening the new hash returned by the successful save renders the updated source, disabled Save and no not-found notice. The write and new entry are valid; the old page address is obsolete.

Desktop old/new identities: `55b36c9923572aff960b73bbb48ae460` → `6e91d4adbc4938a1114de236605f8402`. Narrow old/new: `d5022695eb147b17405c97ee2f05633d` → `a53ea74bf5c7192a704d8c9e966d83d7`. These are disposable test entry identities, not credentials.

Expected: the successful save hands the standalone page the returned identity and leaves a usable saved-entry view at a valid address. A real missing entry or rejected concurrent edit must retain its existing error behavior.

## Cause and bounded repair

`dashboard/src/features/journal/components/entry-context-panel.tsx:514–530` awaits the source mutation but discards its response, then clears the Apollo cache and calls a no-argument `onSuccess`. The panel query at `:488–493` still reads the original prop hash. The standalone `pages/entry-page.tsx:47–54` passes its route hash and only `onDeleted`; it has no save identity handoff. The dialog caller closes after success, which hides this address problem there.

Carry the successful mutation's returned entry identity to the owning standalone route and transition to it without re-reading the obsolete identity. Preserve required cache refreshes, the dialog's close/focus behavior, real missing-entry errors, rejected-stale-edit draft recovery, permission restrictions and the write-outcome warning for an invalid ledger. Coordinate with w4/250 so the acknowledged own-save transition is permitted by its new dirty guard; that separate item covers exits before saving. No backend, protocol, dependency or global error-classifier change is needed.

Acceptance: drive the real panel/page save with an old hash and a successful new hash response. The valid new entry remains editable, the URL survives reload, and a subsequent edit targets the new identity. Cover unchanged-identity success, mutation failure/stale conflict retaining the draft, dialog success and standalone deletion. Do not test only a mocked panel or hide every NOT_FOUND. Run dashboard checks when implementing.
