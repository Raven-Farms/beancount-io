## Cause and bounded repair

`dashboard/src/features/ledger-data/commodities/managed-price-sources.tsx:106–138` writes the acknowledged source records into GetLedgerManagedPrices, then uses refetchQueries:GetLedgerCommodities with **awaitRefetchQueries:true**. The later read rejection rejects the combined refresh promise; onRefresh catches it as though refreshing the managed prices failed and emits the generic action-failure toast. The successful status cache update is already a working control.

Separate acknowledgement from chart-read completion in this owning component. Retain the confirmed source records; give truthful, bounded feedback for a failed chart read and a recovery path that retries that read. Preserve genuine pre-ack failure feedback, pending protection, current source errors/freshness, successful chart refresh and reader permissions. No global Apollo policy change, new mutation framework, dependency, feed/API change or automatic write replay.

Acceptance: a real-Apollo component regression independently controls acknowledgement and later read outcomes. Acknowledged/read-fail keeps the recent source and never claims that the action failed; its recovery requests the chart read without another refresh mutation. Acknowledged/read-success and pre-ack failure retain their respective behavior. Repeat desktop/narrow controls and run dashboard format:check, lint, test and build when implementing.
