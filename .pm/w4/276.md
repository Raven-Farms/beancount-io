## Cause and bounded repair

`dashboard/src/common/lib/utils/encode.ts:70–78` uses a nonfatal UTF-8 TextDecoder, replacing undecodable bytes. `features/ledger-editor/file-editor/components/ledger-file-view/text-file-view.tsx:58–72` makes that lossy value the editable buffer. The Save owner at `ledger-file-view/index.tsx:132–142` encodes that buffer as UTF-8. FileContentView at:52–59 validates decoded text only for unknown filename types; recognized `.csv` and other text extensions bypass that safety decision.

At the file-editor boundary, validate that the incoming bytes can be decoded as UTF-8 without replacement before enabling editing. For unsupported bytes, provide localized actionable guidance and preserve original-byte Download while preventing toolbar, shortcut and forced-edit-URL saves. A read-only/fallback view is sufficient; do not guess a legacy codec, silently convert, add encoding dependencies or build a converter UI. Keep valid UTF-8 Unicode/CRLF/LF, empty files, known large text files, ordinary permissions, SHA conflict protection and pending-draft ownership intact. Do not accidentally apply the unknown-preview size cap to every supported text file or globally change README decoding.

Acceptance: the actual incoming base64→file view→Save integration refuses the invalid UTF-8 seed before any write, while an independent valid UTF-8 counterpart permits the exact requested edit. Confirm original-byte Download and forced `editMode=true`/keyboard guards, with desktop/narrow behavior and meaningful byte assertions. Run dashboard format/lint/test/build when implementing. No backend/schema or REST/GraphQL/MCP capability change is required.
