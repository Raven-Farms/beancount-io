# Validate required New Entry text after trimming

**Severity:** minor validation. **Estimate:** 40–55 minutes. **Owner:** dashboard. **A2:** an apparently valid New Entry form should not prepare empty required values after normalizing what the reader typed.

## Reproduction and controls

Production `https://beancount.io`,2026-10-21 America/Los_Angeles, authenticated QA on the designated disposable ledger, English/light, isolated headless Chromium155.0.8059.85. Every BulkEntries request is intercepted and aborted **before transport**; no backend acceptance or booked-entry claim.

1. In independent fresh390×844 and1440×1000 New Entry → Balance contexts, type three spaces into Account, amount0.00 and Currency USD. Account exposes aria-invalid=false, no inline required error appears and **Create Balance Entry** is enabled.
2. Native Enter prepares one BALANCE entry whose **account is the empty string**. The schema trimmed the spaces only after accepting them as nonempty. Both widths reproduce the exact payload boundary.

4. The Note-content case repeats in another fresh390 context. Before submission there are no alerts, the blank-looking textarea contains three spaces, and Create Note Entry is enabled. The actual intercepted NOTE payload has the valid account and empty content. Its dialog screenshot was visually inspected.

Passing controls: genuinely empty Account disables Balance submission, sets aria-invalid=true and shows **Account is required**, without another mutation. Padded valid Account/Currency (` Assets:Cash ` / ` USD `) still prepare Assets:Cash/USD and preserve49.70. Padded nonblank Note text prepares the expected trimmed prefixed text with the correct account. Preserve that useful normalization; the defect is that whitespace-only required values bypass the same empty check.

## Cause and bounded repair

Four Zod chains apply min(1) before trim:

- `dashboard/src/features/journal/components/new-directive-dialog/balance-form.tsx:51,59`: account and currency.
- `dashboard/src/features/journal/components/new-directive-dialog/note-form.tsx:46–47`: account and content.

Thus the input passes length validation, then the resolver emits an empty normalized string. `use-account-availability.ts` intentionally treats an empty name as the form-validation responsibility, so its account guard does not repair the missing required check.

Normalize these required strings before testing their required length. Reuse the existing localized account/currency/content-required messages and field associations. Prevent submission and attempt0 BulkEntries while any required normalized value is empty. Preserve valid padded values, exact monetary strings, dates, Note interior whitespace/newlines, account-availability/opening behavior, pending guards and failed-write draft recovery. Do not tighten optional transaction text or change the deliberate unused-posting-row policy. No shared schema framework, API/backend change or dependency.

Acceptance: rendered actual Balance/Note forms cover empty and whitespace-only values for all four fields, associated required errors and zero requests. Correcting the field to a valid padded value enables one exact normalized payload;49.70 and meaningful Note content remain intact. Include desktop/narrow repeats and dashboard format:check, lint, test and build when implementing.
