# Keep Documents filenames and accounts readable beside tags on narrow screens

**Severity:** minor (responsive readability). **Estimate:** 40–55 minutes, dashboard. **A2:** a newcomer reading attached documents on a phone should recognize the filename, account and date without deciphering a vertical strip of individual characters.

Production `https://beancount.io`, 2026-10-20, English/light at ordinary text size, QA-owned headless isolated Chromium 155.0.8059.85, disposable-ledger owner. Local main `c5e4cd11a`, production `main-D9qWGMxD.js`; full deployed revision unverified. Real API fixture setup and unmodified UI rendering, with no CSS injection or response substitution.

## Reproduce

1. Create a small prefixed file and one real Document directive: filename `qa-20261020-document.txt`, account Assets:Cash, date 2026-10-20, tag `qa-20261020-tag`, link `qa-20261020-link`. The setup succeeds and the ledger check is clean. This uses the same ordinary-length fixture as w4/242; it is not an oversized-text or extreme-filename probe.
2. Fresh-load `/ledger/<qa-owner>/<synthetic-ledger>/documents` at 390×844. The filename column is **28.31px** wide, account **25.88px**, and date **40.77px**; tags and links take **137.38px** and **139.05px**. The filename and account break almost character by character. Even Filename/Account headers stack vertically. The sole data row is **472.5px** tall and the header **152.5px**.
3. Fresh-load at 1440×1000. The same unchanged row is **38.5px** tall, with readable filename/account/date columns of **296.09/185.06/129.53px**. Fresh-load at 390×844 again: the exact narrow geometry and vertical text repeat.

The narrow table is 399.63px inside a 372px overflow-x:auto container; the page itself stays 390px wide. The small local scroll range does not restore the squeezed columns. Zero page overflow alone therefore misses the failure. Filename keyboard activation still opens the correct stored file (w4/242 control); this finding claims readability, not lost bytes, wrong navigation or broken native row semantics.

## Cause and repair

`dashboard/src/features/ledger-data/documents/index.tsx:43–98,200–223` uses six preferred `w-*` column widths in a width:100% table without a local minimum width. The root body (`common/root-route/shell-component.tsx:24`) supplies inherited `overflow-wrap:anywhere`, so filename, account and date have very small min-content widths. Their columns shrink around the tags/links' nonwrapping, nonshrinking Badge contents (`common/components/ui/badge.tsx:7`). The shared Table wrapper already supports horizontal scrolling; the document table needs a readable width policy to use it.

Bound the fix to Documents: retain useful minimum column widths and readable filename/account/date tokens, allowing the existing local horizontal scroller to carry a table wider than the phone. Keep all six columns, full values, tag/link identity and keyboard access. Make the required scrolling usable by keyboard. Do not remove the global wrapping rule, globally change Table/Badge, truncate away attachment identity, or let the whole page overflow. The report hierarchy's local min-width table is an existing nearby convention, not a request for a second layout framework.

Acceptance: actual browser layout at 390px keeps this fixture's filename/account/date readable in normal horizontal text, with a bounded local scroll region and usable headers, while preserving the desktop control. Include a long relative filename, empty tag/link control, empty/loading state, keyboard filename activation and access to the last columns. Check real geometry/rendering rather than a test that only asserts an overflow class or zero page overflow. Coordinate the same file with w4/242's separate table-name repair; preserve w3/m25's native row semantics. Run dashboard format/lint/test/build when implementing; no API or dependency change is required.
