# Resolve changed-file links when Git headers contain a tab separator

**Severity:** minor. **Estimate:** 50–60 minutes, dashboard parser integration. **A2:** a reader reviewing a changed file should reach its diff even when its filename contains a space.

Production https://beancount.io, 2026-10-20, local main `c5e4cd11a`; QA-owned isolated headless Chromium155.0.8059.85, English/light, owner of a designated disposable synthetic ledger. Fresh 1440×1000 and 390×844 contexts. Actual Git commits and unchanged HTTP200 responses; no synthetic response substituted. Temporary files were removed before the history probes.

## Live reproduction and control

1. Upload a prefixed text file named `qa-20261020-diff spaced.txt` with 150 numbered lines. Open its creation commit through `/ledger/<qa-owner>/<synthetic-ledger>/commit/<sha>`, expand **files changed**, and activate that file link with native Enter.
2. The link/hash is `#diff-file-qa-20261020-diff%20spaced.txt`, but the rendered section ID is `diff-file-qa-20261020-diff%20spaced.txt%09`. There is no matching target. Desktop section top remains 325px and its scroll container stays 0; narrow top remains 387px and scroll stays 0.
3. Working control: another actual 150-line upload named `qa-20261020-diff-plain.txt` produces an exactly matching link/ID. Enter moves its desktop section 325→89px (pane scrollTop 236), and narrow 387→57px (scrollTop 330). The existing scrolling machinery works for a correctly parsed filename.
4. The real spaced-file deletion commit independently reproduces at 390px: the rendered path still includes the extra tab, its link has no target, and section top 387px/scrollTop 0 stay unchanged.
5. A separate real Unicode/reserved-punctuation upload, `qa-20261020-中文 & ?# +.txt`, also produces the same trailing-%09 mismatch. The ordinary file tree/view/download journey for that filename passes; the defect is in history diff identity.

GetCommitDetails returns clean metadata filename `qa-20261020-diff spaced.txt`, additions 150/deletions 0, and a diff header whose actual final byte is TAB: `+++ b/qa-20261020-diff spaced.txt\t`. Its deletion has `--- a/qa-20261020-diff spaced.txt\t` and `+++ /dev/null`. The plain-name control's header has no tab. Here `\t` denotes that recorded separator byte, not a literal backslash in the filename. No filename in these fixtures ends with whitespace.

## Cause and bounded repair

`common/components/diff-viewer/diff-viewer.tsx:64–66` passes the returned patch directly to react-diff-view 3.1.0. Its parseDiff delegates to installed gitdiff-parser 0.3.1. That parser's `index.js:142–162` copies the entire ---/+++ header suffix, strips only the a/ or b/ prefix, and leaves this tab attached to oldPath/newPath.

The dashboard's getDiffFilePath at:41–45 retains it. Focus matching at:158–164 compares that parsed path with the clean filename from CommitFileList and consumes a missing-target request. Section IDs at:294/:359 use the same contaminated path. CommitFileList's link at `features/git/commits/components/commit-file-list.tsx:48` correctly uses the clean API metadata filename. The browser cannot resolve the native fragment either.

Handle the header separator at the parser integration boundary so parsed paths, displayed headings, encoded IDs and selection matching agree on the actual Git filename. Check supported upstream behavior first; keep any necessary adapter bounded to header parsing. Preserve quoted paths, Unicode, percent/hash punctuation and legitimate filename whitespace. Do not trim every path/content line, remove real filename characters, alter diff contents, or weaken the existing deleted-file sentinel and canonical-before-rename matching rules. No backend/API or cross-package change is required.

Acceptance: with the real diff parser and FileList/CommitDetail integration, added and deleted patches carrying the recorded header tab resolve the clean file identity; native activation and fresh fragments reach their actual sections at both widths. Plain-name, modified/renamed paths, same-hash activation, actual filename whitespace, virtualized navigation and the explicit large-diff gate remain correct. Preserve shared PR diff rendering and Beancount highlighting. A mock parsed FileData object or test asserting only the URL would miss this defect. Run dashboard checks when implementing.
