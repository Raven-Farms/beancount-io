# Retry a failed Statistics section without reloading its healthy siblings

**Severity:** minor. **Owner:** dashboard. **Estimate:** 45–60 minutes. **A2:** a reader should be able to follow a Statistics section's connection guidance and retry that read while retaining the other tables and selected scope.

## Reproduction and controls

Production https://beancount.io,2026-10-21 America/Los_Angeles, anonymous public synthetic `open_ledger/crypto-example`, English/light, QA-owned isolated headless Chromium155.0.8059.85. Local main `1dd903739`; full deployed revision unverified. **Only named browser-local reads are aborted before transport; these are injected failures, not production outages.**

2. The failed section shows **Error / Failed to load postings data / Failed to Load Data / Connection problem. Please check your internet connection and try again.** Its component contains **zero buttons**, including no Retry/Try Again. The other two named tables, Account Last Entries and Entries Count by Type, remain available. One named read was aborted per context; neither document overflows horizontally.
3. Remove the fault and reload the same URL. All three tables return, including **38 Postings rows including the header**, with real account links and no failure guidance. The recoverable read and selected Time remain correct; a full-page reload is a working workaround.
4. In an additional fresh390 context, abort only `GetLedgerAccountLastEntries` and `GetLedgerEntriesCountPerType` with that same2025 scope, once each. Removing both faults and reloading restores all three tables, with38 Postings,27 Account Last Entries and13 Entries Count rows including headers. The three section readers share this missing-action pattern.

## Cause and bounded repair

The three self-contained observers omit `refetch`: `dashboard/src/features/ledger-data/statistics/postings-per-account.tsx:181–195`, `account-last-entries.tsx:189–203` and `entries-count-by-type.tsx:180–194`. Their matching custom ErrorState functions accept only a classified message and render no recovery action. StatisticsSection supplies the healthy/loading table shell; changing that shell alone cannot repair these separate error branches.

Supply each failed section with a localized accessible retry tied to its own current observer. Reuse existing error/retry presentation where appropriate. Preserve the current ledger/time/filter/account variables, keep healthy sibling tables usable, prevent competing activations while pending, handle another rejection and restore the failed section after success. A late attempt must not replace a newer scope. Retain useful classified guidance; do not require a page reload, invalidate every ledger query, reset filters or introduce a new dependency/API.

Acceptance: meaningful real-component/Apollo coverage for the three readers must reject a read, activate its own Retry by keyboard, exercise pending/repeated-failure/success states and verify exact current variables plus unaffected sibling data. Keep the existing loading/empty distinctions, names, localized directive types/percentages, account links and documented Account Last Entries date semantics. Repeat desktop/narrow, then run dashboard format:check, lint, test and build on implementation. No product fix or tests were authored by QA.
