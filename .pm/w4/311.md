## Reproduction and result

```csv
Date;Payee;Description;Amount
2026-10-21;qa-20261021 leading record;coffee;-12,50
2026-10-22;qa-20261021 leading record two;tea;1.000,00
```

1. Choose it at `/ledger/<qa-owner>/<synthetic-ledger>/import`. Preview reports2Valid, normalized amounts-12.50 and1000.00, enabled Continue and no AI offer.
2. Prefix the exact same bytes with `\r\n   \r\n`: one empty and one spaces-only CRLF record. Choose this variant from a fresh page.
3. Both widths now show **We couldn't read this CSV's columns**, with **Parse with AI (uses AI tokens)** and Upload Different File. No Preview/Continue or importable row is available. The header and every transaction byte after the7-byte prefix are unchanged.

A tab-delimited file repeats the same contrast at390:2Valid without the prefix, AI offer with it. A comma CSV with the identical blank prefix correctly reports2Valid and the same amounts. Thus leading blank records are already supported by the reader; the failure is delimiter-dependent. A fresh narrow recovery activates Upload Different File and chooses the unprefixed semicolon file:2Valid and Continue return. No AI button is activated and no quota is spent.

## Cause and bounded repair

`dashboard/src/features/importer/hooks/use-csv-parser.ts:23–34` samples only the first logical record's text. detectDelimiter at:43–59 parses that empty sample under each delimiter, finds no supported header or four-column candidate and defaults to comma. It never reaches the actual header. parseRecords at:80–88 already skips blank single-field records after trimming; with the correct delimiter the prefixed files therefore have the same header/data as the passing controls. With the mistaken comma choice their semicolon/tab records cannot map to the required four fields, and useMultiStageParser sends the zero-valid-row result to its explicit AI offer.

Sample the first nonblank logical record, using the reader's existing blank-record policy and quote-aware record boundaries. Preserve the first real header or headerless data record and its values. Do not search past a nonblank preamble or malformed record for a later recognizable header, strip blank lines inside quoted fields, change supported columns/amount conventions or bypass genuine parse errors. Keep the explicit AI choice for files that remain unreadable. No dependency, backend/API or translation change is indicated.

Acceptance: semicolon/tab CSV with leading empty or whitespace-only records previews the same exact rows/decimals as its unprefixed counterpart, with no ParseFile request. Keep the passing comma control, headerless four-column data, BOM handling, LF/CRLF, quoted embedded newlines and malformed-quote/header refusal. Repeat both widths and new-file recovery; run dashboard format:check, lint, test and build on implementation. Headerless/BOM variations are regression scope, not live failures claimed here.
