# Reject unsupported file branch routes instead of serving main under them

**Severity:** minor. **Estimate:** 45–60 minutes, dashboard. **A2/A3:** a file URL must identify the file context it displays; a nonexistent branch should not become a successful self-canonical copy of main.

Production `https://beancount.io`,2026-10-20, local main `d451a55e2`, isolated owned headless Chromium155.0.8059.85, English/light, signed out. Settled blob controls at1440×1000 and fresh390×844; directory/native file-row control at390px. Only public open_ledger/example was read. ## Reproduction and controls

1. A genuine GetLatestLedgerCommit control with branchName main returns a commit and no error. The same operation with `qa-20261020-nonexistent-branch` returns no commit and NOT_FOUND. The tested branch does not exist.
2. Open `/ledger/open_ledger/example/files/blob/qa-20261020-nonexistent-branch/README.md` and wait for the actual read-only Monaco editor. The document answers HTTP200 and renders the main README.
3. Its real canonical link is that same nonexistent-branch URL. There is no robots meta directive, and a fresh document response has no X-Robots-Tag. This route is represented as an indexable valid file, despite the independent missing-branch control.
4. Change only the branch segment to main. It also answers200. At each width, the settled visible Monaco text is identical between the fake-branch and main views. The comparison is of the same viewport's rendered text, not a claim that virtualized Monaco exposes every source byte in the DOM.
5. At390px open `/ledger/open_ledger/example/files/tree/qa-20261020-nonexistent-branch`. It also answers200 and shows main's file rows and README. Its existing noindex,follow directive is present; the directory is not claimed to be indexable. The README row's actual href is `/files/blob/main/README.md`; native Enter reaches that supported main view correctly.

No page error or narrow overflow occurred. Early samples taken before lazy Monaco loaded and a slow lookup for an absent optional robots element were excluded; the settled editor comparisons and explicit absent-meta checks above provide the evidence. The test branch was never created or used for a write.

## Cause and bounded repair

`dashboard/src/features/ledger-editor/file-editor/loader.ts:15–24` builds GetLedgerFile from owner/name/path and ignores params.branch, so the real existing main file satisfies the SSR existence check for any branch segment. FileEditorPage at index.tsx passes only ledgerId/filePath to LedgerFileView; its branch parameter is used only for the empty-path redirect. DirectoryPage likewise omits branch, and LedgerDirectoryView hardcodes main at:121 for its file links. The route/head logic can therefore preserve the unsupported branch in an otherwise successful blob canonical URL while the data read has only the default/main context.

Validate the currently supported main branch at the parameterized Files route boundary before reading, rendering or emitting a successful head. Unsupported branch values should reach an honest not-found response with useful navigation to main Files; a blob must not answer200 with a self-canonical unsupported URL. Keep the real main view, missing/refused-file handling and established legacy aliases working. Reuse the smallest shared guard for the demonstrated blob/tree routes and audit the sibling new/upload branch routes so they cannot silently ignore the same parameter. Their write behavior was source-traced only and was not exercised. No general branch/revision browser, backend/API change, archive/export feature, new dependency or access-policy change is needed.

Acceptance: real SSR and client-navigation tests distinguish supported main+existing file, unsupported branch+existing filename, missing file on main and refused paths. Unsupported blob status/robots/head are truthful and its file is not rendered from main under the wrong URL; native main file-row navigation still works at desktop/narrow widths. Test the route/data boundary, rather than just a branch-string predicate. Preserve existing file permissions and run dashboard format/lint/test/build.
