## Verification

**Fix.**
- A new `dashboard/src/common/hooks/use-query-retry.ts` (`useQueryRetry(error, refetch)`) runs on the shared `usePendingAction`. It allows one retry at a time and refuses a second Enter or click.
- Apollo clears `error` while it refetches, so the hook keeps the failure being retried. The error view stays mounted and `ReportErrorState` shows a busy Try Again through its new `retrying` prop.
- A rejected retry is handled and returns focus to Try Again.
- Trial Balance, Balance Sheet, Income Statement and Cash Flow's query-error branch render `ReportErrorState` on `failure` ahead of their loading state. Account Journal does the same inside its own card, and its chart, filters, pagination and other card stay as they are.
- Cash Flow's reconciliation error keeps its own branch, with no retry, and Account's primary-read `PageErrorState` is unchanged.
- `refetch` re-reads the current variables, so conversion, time, account, filter, interval and chart selection all stay.

**Native check:** fresh 1440/390 pages on the gated local build. The fixture API recorded anonymous reads of the public example ledger; the browser aborted or held only the target read.
- Each statement takes a client-side conversion change, then: failed read → Try Again → held retry (busy, a second Enter sends nothing) → aborted (focus returns to Try Again) → Enter.
- The final Enter recovers the same-scope read: Trial Balance 88 rows, Balance Sheet 46, Income Statement 74.
- Cash Flow under At Market Value recovers into its separate "cannot be reconciled" view.
- The Account Journal at `Assets:US:BofA:Checking?time=2016-08` recovers 13 rows with an unchanged URL.
- Every retry repeats the first read's variables. 0 forwarded mutations and 0 page errors.

**Regression:** `src/features/reports/__tests__/report-read-retry.test.tsx` covers all five observers with real Apollo.
