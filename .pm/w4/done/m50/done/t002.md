## Verification

**Fix.**
- `QueryView` now owns the hold. Given `onRetry`, usually the query's `refetch`, it runs `useQueryRetry` itself and keeps its error state, with a busy Try Again, until the retry settles.
- Otherwise "loading takes priority over error" still holds, and its existing tests pass.
- Commodities passes `onRetry={refetch}`. Its retry re-reads `GetLedgerCommodities` only: no managed-price refresh, no mutation, no global cache reset.
- The 332 acknowledgement and read contract is untouched.
- Budget's existing `onRetry` keeps working.

**Native check, 1440/390:** an aborted Commodities read shows "Failed to Load Commodities" with Try Again. A held retry is busy and a second Enter is refused; an aborted retry returns focus to Try Again. The next Enter recovers, with 0 mutations.

**Regression:** `src/features/ledger-data/commodities/__tests__/commodities-read-retry.test.tsx`, real Apollo, asserts no mutation operation at all.
