# Keep the active profile tab visible on narrow screens

**Severity:** minor accessibility/layout. **Estimate:** 40–55 minutes. **Owner:** dashboard. **A2/A3:** readers entering a profile view should be able to identify its active tab without first scrolling the tab strip.

## Reproduction and controls

Production `https://beancount.io`,2026-10-21 America/Los_Angeles; isolated headless Chromium155.0.8059.85, English/light. Anonymous public `open_ledger` at390×844, repeated independently on the QA profile and with a1440×1000 control. No social action is performed.

1. Open `/ledger/open_ledger?tab=followers`, or open the ordinary Ledgers view and activate its header's **456 followers** link. Wait for the Followers panel and tab transitions to finish.
2. **Followers (456)** is correctly aria-selected=true/data-state=active and its panel renders, but its label is clipped beyond the strip's right edge. The tab spans **x349.89–501.95**, while the existing horizontal scroll container spans **x4–386** with scrollLeft0. Only about36px of the152px trigger remains visible, chiefly its icon. Document width remains390, so a document-overflow-only check misses it.
3. In a separate390 QA-profile run, native End and Arrow navigation select and focus Followers correctly but likewise leave it at **x349.89–481.77**, with scrollLeft0. Home/Arrow tab selection and URL updates themselves work.
4. Native horizontal wheel scrolling is a passing control: the public strip moves to scrollLeft132 and the complete trigger becomes visible at **x217.89–369.95**. The content is reachable; selection/navigation fails to bring it into view automatically. At1440 the trigger is fully visible at x481.89–641.95.

The final public screenshot was taken after the tab's CSS transitions finished. Keep the existing horizontal container; the defect is the active/focused trigger remaining clipped, not a need to fit every tab simultaneously.

## Cause and bounded repair

`dashboard/src/features/user-profile/components/user-profile-tabs.tsx` keeps activeTab in state, synchronizes initialTab from the URL and renders the intended overflow-x-auto wrapper around a min-w-max tablist. It does not bring the selected trigger into that container after initial/deep-link selection or a change. The retained native Chromium run also leaves keyboard-selected focus clipped.

Ensure that initial/deep-link, header-driven and keyboard tab selection reveal the active trigger within this existing horizontal strip. Preserve correct counts, panel/ARIA state, native roving focus, query parameters and manual horizontal scrolling. Keep the page's vertical position; do not change global focus/scroll restoration, remove clipping globally or continually undo the reader's manual scrolling.

Acceptance: fresh390 public Followers URLs and the actual header link show the complete active label. End/Home/Arrow navigation keeps each focused selected trigger inside the strip at both ends. Ordinary1440 and manual-scroll controls remain correct. Use real rendered geometry plus meaningful selection/navigation regression coverage; a document-width or class-only assertion is insufficient. Run dashboard gates when implementing.
