## Objective

Keep the newly mailed private recovery challenge and existing authentication credentials out of user-copyable error reports while retaining useful failure context. Apply the existing ephemeral-auth noindex policy and a private-flow referrer policy to recovery URLs. Apply the dashboard's existing rule that diagnostic reports never include tokens.

## Context

- `ErrorDetails` passes `window.location.href` to `formatErrorReport`, which currently copies it verbatim. A failure on the emailed recovery URL therefore copies its private `recovery` challenge into the support report.
- Source inspection also confirms the same path retains reset and OAuth callback query values. This is a concrete diagnostic disclosure, separate from the accepted signup account-existence response.

- The new private recovery URL also inherits ordinary login indexing metadata; the existing `indexability.ts` policy requires noindex for ephemeral authentication flows. Keep ordinary acquisition login metadata intact.

## Steps

1. Add a regression using synthetic authentication URLs and prove the current formatter includes the private proof.
2. Sanitize the diagnostic URL and credential-bearing error context without storing or logging the original URL.
3. Mark private recovery metadata noindex/no-referrer and verify ordinary login metadata remains intact.
4. Verify ordinary error context, copy behavior and the recovery flow; run dashboard native gates, close through /pm and ship.
