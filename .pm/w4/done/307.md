# Show copy failure during stale-entry draft recovery

**Severity:** minor. **Estimate:** 25–40 minutes, dashboard. **A2:** a user following the stale-entry notice's Copy my edit instruction needs to know if the copy failed before choosing Reload.

Production https://beancount.io, 2026-10-21, English/UTC, owned isolated headless Chromium155.0.8059.85, authenticated owner of the designated disposable synthetic ledger. Fresh1440×1000 and390×844 repeats. Final dedupe main212f7007f; deployed EntryContextPanel exactly matches current source.

## Controlled browser reproduction

1. Open Journal on the synthetic ledger and use an existing entry's named Open entry button. Its real GetLedgerEntryContext succeeds. Make a uniquely prefixed raw source edit in the actual Monaco editor and activate Save.
2. Before transport, fulfill only that exact ledger/hash/checksum/source mutation with HTTP200 and a GraphQL NOT_FOUND error. The actual production handler displays its stale-entry notice, retains the attempted draft and offers **Copy my edit** and **Reload**. This is an injected stale state, not a claimed real concurrent edit or successful source write.
3. Replace this owned page's writeText with an in-memory rejecting implementation returning NotAllowedError. Activate Copy my edit with Enter. It receives exactly the attempted source, rejects, and the browser records an unhandled NotAllowedError. There is no error toast or new failure feedback. The existing stale notice still instructs the user to copy, then reload.
4. Change only the in-memory clipboard implementation to resolve and activate the same button again. The exact same attempted draft is supplied and the normal **Copied** success toast appears. Focus stays on Copy my edit in both failure and success.

Both independent widths produce one rejected call, zero error/success toasts on rejection and one pageerror, followed by the passing exact-payload retry and Copied toast. No actual system clipboard write occurs. No ledger mutation reaches the server: each case intercepts one narrowly matched UpdateLedgerEntrySourceSlice and the context blocks any other mutation. No source parsing, real stale-write race or lost draft is claimed. The defect is missing failure feedback and an unhandled promise in the recovery action.

## Cause and bounded repair

`dashboard/src/features/journal/components/entry-context-panel.tsx:599–608` invokes navigator.clipboard.writeText(staleDraft).then(successToast) without handling rejection. The ordinary successful branch works; failure escapes without explaining that the draft has not been copied. The parent save catch correctly recognizes NOT_FOUND/CONFLICT and retains staleDraft; preserve that behavior.

Handle the rejected clipboard operation with the existing localized **common.copyFailed** feedback. Show Copied only after resolution, keep the exact attempted draft and connected Copy button/focus available for retry, and leave Reload an explicit user action. Do not clear the draft, close the dialog, retry the ledger save or claim success on a failed copy. No new translation key, dependency or API change is needed.

Acceptance: exercise the actual panel's stale-save recovery through NOT_FOUND/CONFLICT, reject writeText, and verify visible localized failure, no success toast or unhandled rejection, retained draft and no reload/save side effect. Retry with a resolving implementation and assert the full exact source once per activation plus normal success feedback. Keep ordinary successful copying and Reload behavior. Run dashboard format:check, lint, test and build on implementation. CONFLICT and the standalone page are shared-code regression scope, not independently live exercised here.
