## Cause and bounded repair

`dashboard/src/common/components/markdown-renderer.tsx:21–31` removes every parser-generated pre container, then infers `inline` from whether code has a `language-` class. A language label is optional on a Markdown block. Installed `node_modules/mdast-util-to-hast/lib/handlers/code.js:22–49` always generates pre/code for a block and adds that class only when a language exists. The app consequently sends unlabelled blocks to CodeBlock's inline branch (`code-block.tsx:42–48`), which collapses whitespace and omits the block toolbar.

Determine block versus inline from parsed block/container structure independently of syntax-language metadata. Preserve real block whitespace and the existing named, keyboard-visible Copy code control even when language is absent. Keep ordinary inline spans inline. Retain labelled fences, code text, sanitization/URL safety, headingOffset, wrapping/scroll behavior, copy success/failure handling and timer cleanup. CodeBlock already supports an absent language in its block branch; no new dependency, API/backend change or global inline whitespace rule is needed.

Acceptance: render actual Markdown through the real renderer and CodeBlock for unlabelled fenced, indented, labelled fenced and inline controls. Both unlabelled block forms preserve the two logical lines/aligned spaces and expose block-copy affordances; inline spans remain inline. Verify the copied payload with an in-memory clipboard stub, plus narrow/desktop block layout and existing keyboard/error controls. Existing renderer tests mock CodeBlock, and the labelled-bash test cannot establish these missing block semantics. Run dashboard format/lint/test/build when implementing.
