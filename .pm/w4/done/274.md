# Preserve account-search keyboard focus through retry

**Severity:** minor. **Estimate:** 35–50 minutes, dashboard. **A2:** a keyboard retry should return a usable account picker, so the next arrow or retry key still reaches its controls.

Production `https://beancount.io`,2026-10-20, QA-owned isolated headless Chromium155.0.8059.85, signed-out public example ledger, English/light. Primary cases:1440×1000 with forced colors and a fresh390×844 ordinary-color context. A further fresh narrow document checks repeated failure and original input identity. Local main `c5e4cd11a`, deployed `main-D9qWGMxD.js`; full deployed revision unverified.

## Reproduction and controls

1. Before navigation, abort only browser GetLedgerAccounts requests. Open `/ledger/open_ledger` and use its visible example-ledger link. The two primary cases observe client navigation without another document request, avoiding an assumed SSR-cached account read. Open Search accounts...; open Sidebar first at390px. Wait for Failed to Load Data / Try Again.
2. Focus the search input, then Tab to Try Again. Allow the network again and activate the focused button with Enter. Exactly one genuine HTTP200 GetLedgerAccounts read returns60 accounts; the picker populates91 options, including generated parent paths.
3. After the options settle and another500ms, focus is BODY. The search input is present but unfocused. Press ArrowDown: selection stays Assets and the URL does not change. The same result occurs in both primary contexts; ordinary colors rule out W4/273's contrast-only paint failure.
4. Passing desktop workaround: Escape closes the popup and returns focus to its Search accounts... opener. Reopen it; the input is focused and ArrowDown moves Assets → Equity. In the narrow control, explicitly focusing the existing input also restores that arrow movement. The data/selection mechanism is usable once focus is repaired.
5. A separate narrow repeat keeps the network failing for one manual retry. The button reappears, but focus is BODY; pressing Enter there attempts zero additional reads. Focus input → Tab back to Try Again, allow the network, and Enter again: one successful read restores options but still leaves BODY focused. An element handle confirms the original input is still connected and is the current CommandInput after both attempts.

The third repeat used a full document navigation to the example; its failure state was verified before retry and is not claimed as another client-navigation control. Intentional aborted reads are controlled faults, not a production outage. No API response was substituted. No uncaught page error or ledger write occurred.

## Cause and bounded repair

`dashboard/src/common/components/ledger-layout/go-to-account.tsx:75–110` replaces the entire error branch, including the focused retry button, with a loading status during refetch. It later renders options or a new error button. The onClick at:92–94 only starts refetch and provides no focus handoff to the persistent CommandInput at:71–73. The removed focus owner leaves native keyboard events on BODY; the original input remains mounted in the identity control.

Keep a coherent focus owner through retry, preferably handing focus to the existing search input before the focused retry control is replaced. Preserve input text and the same popup; after success arrows/typing should immediately work, and after another failure a keyboard user should still be able to reach/retry the error action. Avoid a late completion focusing a closed/replaced popup, polling focus, remounting the picker or changing every Apollo refetch. Preserve the local Enter-propagation fix, one read per explicit retry, Space/pointer activation, normal option selection, Escape/opener focus, cached data and loading/empty/error distinctions. No shared Command selection redesign, dependency or backend/API change is needed.

Acceptance: with the real picker and controlled account reads, native Tab/Enter retry retains an appropriate input/control focus throughout loading and settled success/failure. After success, ArrowDown changes the selected account without manually refocusing or reopening; another failure remains keyboard-retryable. Confirm the original input/draft remains intact and the request count stays one. Exercise desktop/narrow and run dashboard format/lint/test/build.
