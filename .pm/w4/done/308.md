**Severity:** minor. **Estimate:** 40–55 minutes, dashboard. **A2:** Smart Import should identify malformed CSV fields before presenting changed payees or amounts as valid import rows.

## Reproduction and actual result

Open `/ledger/<qa-owner>/<synthetic-ledger>/import` and choose this UTF-8 CSV:

```csv
Date,Payee,Description,Amount
2026-10-21,"qa-20261021-quote-boundary vendor"tail,coffee,-12.50
2026-10-22,qa-20261021-quote-boundary plain,tea,"1"2.50
```

Both widths show **2 Valid** with Continue to Configure enabled and no malformed-record warning. The first Payee's actual editable-cell name/value is `qa-20261021-quote-boundary vendortail`. The second Amount's actual editable-cell name/value is `12.50`. Text after a closed quoted field is silently concatenated into that field; the misplaced quotes have disappeared before normal field validation. These are malformed CSV tokens, not supported currency/decimal spellings. No actual ledger amount was written in this check.

Expected: refuse these quote boundaries through the existing file-level parse failure path, with useful repair feedback and no importable rows. Do not guess that `"1"2.50` denotes12.50 or silently join a closed quoted payee to trailing text.

Working controls: a correctly escaped `"qa-20261021-quote-boundary vendor""tail"` keeps its literal internal quote at both widths; its ordinary12.50 amount stays12.50 and both rows remain valid. A separate unterminated-quote fixture at390 and a duplicate-header fixture at1440 both stop with the explicit AI offer and no Continue. Neither offer is activated. Python's independent csv.reader(strict=True) refuses the malformed closing quote and accepts both correctly quoted control rows. The failing boundary is distinct from already working EOF-inside-quote detection.

## Cause and bounded repair

`dashboard/src/features/importer/hooks/use-csv-parser.ts:91–117` leaves inQuotes on a closing quote, then handles the following character as ordinary unquoted text. It has no after-quote state to require a field/record boundary. At:120–124 a double quote anywhere outside quotes starts quoting, even after existing unquoted data. Consequently parseRecords deletes syntax characters and joins spans. parseCSV at:205–260 then validates only these altered four fields, so both malformed rows pass; amountInput has already become12.50 before parseAmount can reject the original token.

Track field-start, quoted-field and closed-quote states explicitly. After a quoted field closes, accept only the delimiter, record end/EOF and the parser's deliberate surrounding-padding policy; refuse additional field text. Refuse a quote beginning inside an already unquoted field rather than deleting it. Report the malformed boundary before building importable rows, using the existing file-level failure/explicit-choice flow. Keep original supported field values, exact amount tokens and documented normalizations. Do not concatenate fragments to invent a value or automatically send malformed CSV to AI.

Acceptance: the real parser/workflow refuses both supplied rows, including a malformed amount that would otherwise become a valid decimal; no Continue/import mutation is available and no AI call occurs without explicit choice. Cover a malformed later record and header, plus proper quoted fields/escaped quotes, quoted commas and semicolons, multiline CRLF, ordinary unquoted fields, empty fields and deliberately accepted padding. Preserve comma/semicolon/tab detection, header mapping, decimal conventions and precision refusal. Run dashboard format:check, lint, test and build on implementation. Other delimiters/header placements are regression scope, not live failures independently claimed here.

**Resolved 2026-10-22.** The CSV record parser now tracks the closed-quote state. After a quoted field closes, only padding, the delimiter or the record end may follow, and a quote can no longer open inside unquoted data. Either case refuses the whole file through the existing file-level failure, naming the record ("Unexpected text after a quoted field in CSV record 2"), so no importable rows are built and AI remains an explicit choice. Escaped quotes, quoted commas and semicolons, CRLF multiline fields, padding, empty fields and delimiter detection are unchanged. Shipped in `5c932543d` (`dashboard`).
