# Restore useful focus after a file Save fails

**Severity:** minor. **Estimate:** 40–55 minutes. **Owner:** dashboard. **A2:** a reader whose file Save fails should keep a useful keyboard position for continuing or retrying the retained draft.

## Reproduction and controls

Production `https://beancount.io`,2026-10-22; owned isolated headless Chromium155.0.8059.85, English/light/UTC, authenticated designated disposable QA ledger. Fresh390×844 and1440×1000 contexts independently reproduce this. **Failures are browser-local pre-transport aborts, not observed production outages.**

1. Open main.bean in edit mode and append a prefixed local comment. Verify the complete model equals the original buffer plus the exact comment.
2. Activate the actual **Save** button with native Enter. The desktop event record confirms a trusted Enter on the named Save button. Hold only its guarded UpdateLedgerFile before transmission; the request has the expected ledger/path/base SHA and exact UTF-8 draft after decoding its base64 content.
3. While held, Save is disabled, Monaco is read-only and focus falls to **BODY**. Release the request as a transport abort.
4. The app shows **Connection problem. Please check your internet connection and try again.** Save becomes enabled, Monaco becomes editable and the full draft remains intact. Focus stays on BODY, including after a one-second desktop settlement wait. Native typing `x` is ignored at both widths.
5. Explicitly refocus the editor and move to its end; native insertion of `x` appends exactly one character to the retained draft. This confirms that the buffer and input remain usable once focus is recovered.

A separate narrow control saves the recovered draft through **Cmd+S while the editor is focused**. During the held second request its editor retains focus, and after the same abort it remains focused with the exact draft. Both initial button saves and the shortcut control are blocked before transport: three attempts, zero hosted writes. Explicit discard restores every original complete buffer.

**Resolved 2026-10-22** — the file editor's toolbar remembers a save started from its Save button. When the save lock lifts with the toolbar still mounted (a failed save) and focus was lost to the page, it hands focus back to Save for a retry. A reader who moved focus during the save keeps it, Cmd+S from the editor keeps the editor's focus, and a landed save unmounts the toolbar so the saved view owns focus. The single-flight guard, read-only pending state, retained draft and failure toast are unchanged. `file-edit-mode.test.tsx` covers saving by Enter on Save, with focus dropped while disabled as the browser does: when the lock lifts, focus is on Save and Enter saves again. Controls check a deliberate move to Cancel during the save and a save started elsewhere, which take no focus; the handback case fails with the fix reverted. Native checks at 1440 and 390 px against the local fixture API held every UpdateLedgerFile and then aborted it before transport. Focus was BODY while held, then back on Save with the exact draft retained. Enter retried immediately (attempt 2) and focus returned to Save again, and a Cmd+S from the editor kept the editor focused. No writes or page errors. Shipped in `ad2b168dd` (`dashboard`).
