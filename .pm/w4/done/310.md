## Cause and bounded repair

`dashboard/src/features/importer/components/steps/preview/editable-cell.tsx:126–140` checks only key and multiline modifiers. Plain Enter prevents default and calls commitAndClose; Escape prevents default and calls cancelAndClose. Neither branch checks the native composition event. Both close paths unmount the focused input/textarea and restore the display button, explaining the observed blur and completed edit before composition ends.

Guard this local application-shortcut boundary with the existing `common/lib/keyboard/is-composition-key.ts` helper, using the React event's nativeEvent. Leave composing keys/default editing with the input method; retain ordinary Enter commit, Escape cancellation and the current multiline insertion shortcuts after composition ends. The helper already recognizes native isComposing and keyCode229. Do not force composition to finish, blur the field or change the global Input/Textarea primitives. No new dependency, API or backend change is needed.

Acceptance: drive the real EditableCell with composing Enter and Escape, asserting the editor stays mounted/focused and no application commit/cancel callback runs. After compositionend, the ordinary keys act once with exact final text and expected focus. Cover229 fallback, multiline Shift+Enter, blur commit, validation/error association and unchanged Date/Amount single-line behavior. Repeat browser-engine composition at both widths and run dashboard format:check, lint, test and build.229 and Date/Amount composition are regression scope, not independent live findings.
