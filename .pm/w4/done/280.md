## Cause and repair

`dashboard/src/features/importer/components/steps/configure/transaction-config-form.tsx:219,245,267` leaves source/currency/mapping editable. Only Back and Submit consume isSubmitting at:281,287. AccountMappingTable's row selectors/target/AI controls have no import-pending input; its loading flag concerns AI only. use-import-submit.ts snapshots input transactions into the request, then ImportWorkflowContainer's handleSubmit awaits completion and unconditionally moves to Finish, unmounting the edited form.

Freeze controls that change the submitted payload while isSubmitting is true: source/currency selectors and their Clear actions, target mapping, row/all-visible selection, and actions that rewrite mappings. Pass the pending state into the mapping boundary or use an equivalent real disabled boundary that covers its interactive controls. Preserve readable current values, loading feedback, the correct original payload and existing Back/Submit protection. Do not apply a late edit to an already submitted batch, automatically resend, add idempotency/API behavior, change explicit Start Over semantics or redesign the wizard. Already-running AI results and ambiguous post-commit transport failures were not exercised and remain audit scope.

Acceptance: in actual Configure components with a deferred submit, payload-changing controls cannot accept native edits until settlement; the original request stays exact and is issued once. On success the existing Finish journey works; on failure its current honest feedback/reset remains usable. Controls work before submission. Exercise both widths, source/currency/target/selection and Clear behavior without spending AI quota. Keep meaningful draft-preservation/decimal/permission checks and run dashboard format/lint/test/build.
