# Leave Gallery result navigation inactive during IME composition

**Minor · dashboard · 35 minutes.** A2: confirming input-method text must not unexpectedly leave the ledger search. Production beancount.io, 2026-10-20, owned isolated headless Chromium 155, Japanese application/browser locale, authenticated QA account, fresh 1440×1000 and 390×844 contexts. Searches and destinations use public `open_ledger/stock-example`; no ledger write or social action. Local main `8c5f352c6`, implicated deployed source exactly matches; full deployment revision unverified.

## Browser reproduction and controls

1. Open `/ledger-gallery?lang=ja`, wait for its real hydrated combobox, and focus it. Use a page-scoped Chromium CDP Input.imeSetComposition with preedit `stock-example` and selectionStart/End 13. Wait for the genuine search result. The URL is `/ledger-gallery?lang=ja&q=stock-example`; no option is active.
2. Dispatch ArrowDown through Input.dispatchKeyEvent while composition remains active. The captured browser-generated keydown has **isTrusted=true, isComposing=true, keyCode=40**. Gallery incorrectly makes `ledger-search-option-0` active/selected.
3. Dispatch Enter in the same composition. Its browser-generated keydown is **isTrusted=true, isComposing=true, keyCode=13**. Gallery navigates to `/ledger/open_ledger/stock-example`, interrupting composition instead of leaving the key to the input method.
4. Fresh narrow reproduction repeats both state changes. Wait for the actual destination: its title is “Stock & ETF Cost-Basis Example — beancount.io” and four Overview charts are mounted. A separate fresh narrow ordinary ArrowDown/Enter control has isComposing=false and correctly performs that same navigation.

These are Chromium browser-engine IME compositions and trusted key events, not JavaScript-dispatched untrusted keydown events. Physical OS Japanese/Chinese/Korean input-method sessions remain unverified. The [W3C composition-key contract](https://www.w3.org/TR/uievents/#events-composition-key-events) explains why key events can reach the page while the input method is composing. Ordinary shortcut behavior must resume after composition ends.

## Cause and bounded repair

`dashboard/src/features/ledger-list/pages/gallery-page/index.tsx:185–214` handles Escape, arrows and Enter without checking the native KeyboardEvent's composition state. ArrowDown mutates highlightedIndex; Enter then calls handleLedgerSelect. The search input is a plain Input with its own keyboard handler, so [286](./286.md)'s shared Combobox guard cannot fix this page. Route `src/routes/ledger-gallery.tsx` is the sole production GalleryPage renderer.

Keep Gallery's selection, dismissal and navigation actions out of active composition without canceling the input method's default action or forcing focus elsewhere. Do not navigate on compositionend. Retain the existing real-result/query ownership guards, normal arrows/Enter/Escape, URL search restoration, pointer selection, hydration readiness and scrolling behavior. Search reads during preedit are not the evidenced defect and do not need a new debounce policy or server change.

Acceptance: a real Gallery/input test with one genuine-shaped result sends composing ArrowDown/Enter and leaves active-descendant/selection/navigation untouched. After compositionend, ordinary arrows and Enter still select/open the result. Include a previously highlighted option, empty/failed/stale results and ordinary Escape/Clear controls. Repeat browser-engine composition at desktop/narrow widths and run dashboard format/lint/test/build. No new dependency, API or shared keyboard framework is needed.
