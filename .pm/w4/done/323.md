# Preserve manual target-account edits made while AI Fill is pending

**Severity:** minor. **Owner:** dashboard. **Estimate:** 45–60 minutes. **A2:** a newcomer reviewing an import should keep the account choice they made after requesting suggestions.

Production https://beancount.io, 2026-10-21, local main19e0fd1a2; QA-owned headless isolated Chromium155.0.8059.85, English/light, fresh1440×1000 and390×844 owner contexts on the designated disposable synthetic ledger. The real deployed wizard and reads are used. Only SuggestTransactionCategories is intercepted before transport and answered with an explicitly browser-local, schema-complete response. This verifies client handling of late suggestions, not real AI output, latency or a hosted import. No AI request reaches the server and no quota is spent.

## Reproduction and controls

1. Import a local CSV with header Date,Payee,Description,Amount and two prefixed synthetic rows dated2026-10-21/22, amounts-1.25/2.50. Continue to Configure. Set the first target to Expenses:Qa-20261021-Before; leave the second blank.
2. Activate AI Fill and hold its actual SuggestTransactionCategories query before transport. Its input has rowIndex0/1. Categorizing appears; both target fields remain enabled.
3. Focus the first target, select its text, type Expenses:Qa-20261021-Manual and Tab away using native browser keyboard input. It visibly retains that newer value while the suggestion request is waiting.
4. Release a client-only successful response with two CategorySuggestion objects: rowIndex0/1, targetAccount Expenses:Food, confidence0.9, source ai and reasoning qa-browser-local. Every selected GraphQL field, including __typename, is supplied.
5. The first target silently changes from the newer Manual choice to Expenses:Food. The untouched second row correctly fills Expenses:Food. Both rows remain selected, and the success toast says two transactions were categorized. Fresh desktop, narrow and another fresh narrow repeat reproduce this overwrite.
6. Passing failure/retry control in a separate fresh narrow context: abort the held request after making the same manual edit. The Manual choice and blank second target survive; a useful categorization-failed/connection message appears and AI Fill re-enables. Retrying with the schema-complete success response fills both targets. A subsequent explicit manual repair survives Configure → Back → Continue to Configure.

No Import action is invoked. The enabled Import state is context only; no misbooking, lost hosted data or combined import/suggestion race is claimed.

## Cause and bounded repair

`dashboard/src/features/importer/components/steps/configure/transaction-config-form.tsx:157–170` awaits categorizeTransactions, then reads the current form transactions. For every qualifying suggestion it unconditionally replaces targetAccount, including a target the user edited after the request began. Spreading txn preserves selection and other fields, but there is no earlier target/version snapshot to distinguish that newer manual edit. `account-mapping-table.tsx:97–116` manages AI loading and useful success/failure notices; target controls at:363–375 are disabled only for an import submission or an excluded row, so editing during categorization is deliberately possible.

Snapshot each requested row's stable identity and target choice before awaiting suggestions. Apply a returned suggestion only to a still-current row whose target has not been manually changed since that request. Preserve the newer manual choice, ordinary filling of untouched eligible rows, current selection, existing draft persistence and failure/retry behavior. An explicit bounded pending lock is also acceptable if editing is prevented from the start and values/focus remain usable; merely disabling AI Fill itself is already present. Keep this repair in the dashboard; no model, API, dependency or quota-policy change is needed.

Acceptance: a held successful suggestion cannot replace a target edited after the request starts; the untouched second row still fills. Cover failure followed by a successful explicit retry, unchanged pre-request targets, and Back/Configure draft retention with the real form and a deferred request. Preserve stable row mapping and confidence filtering. Repeat desktop/narrow and run dashboard format:check, lint, test and build when implementing. No billed AI call or hosted booking is required.
