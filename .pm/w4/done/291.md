## Cause and bounded repair

`dashboard/src/features/ledger-editor/file-editor/components/ledger-file-view/text-editor.tsx:84–117` installs a capture-phase document keydown listener. Escape calls shouldCancelEditOnEscape, prevents default/propagation and invokes onCancel. The helper in text-editor-utils.ts:58–66 protects Monaco Find and overlays, but knows nothing about active composition. TextFileView's cancellation initiates route exit, whose correct dirty guard shows the dialog.

Use the existing Monaco composition lifecycle to retain composition ownership before this document handler intercepts Escape, including native EditContext and textarea-backed editors. The installed public editor API exposes onDidCompositionStart/onDidCompositionEnd (monaco.d.ts:6048–6052); nativeEditContext.js:156–170 forwards its trusted composition events into those callbacks. Manage/reset/dispose the lifecycle with the actual editor instance, and preserve the native KeyboardEvent composition fallback where relevant. Do not disable IME, replace Monaco, remove the dirty guard or suppress all ordinary Escape actions. Keep Find/overlay ownership, read-only behavior and save/find shortcuts intact. Save-during-composition was not exercised and is not an additional confirmed finding.

TextEditor has one production consumer, TextFileView; the helper has one production Escape call. Source-traced scope is editable text files using that integration. Existing text-editor-escape.test.ts covers Find/overlay ownership and dirty ordinary cancellation, but has no composition lifecycle case. Add a real integration regression with composition active and a key whose isComposing is false: no onCancel/dialog/route exit. Cover the true flag fallback, compositionend followed by ordinary Escape, Find and overlay cases, clean/dirty drafts, instance disposal/remount and unchanged read-only behavior. Recheck both actual widths and run dashboard format/lint/test/build.
