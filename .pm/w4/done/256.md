# Preserve unsaved New Entry fields across type changes

**Severity:** minor (local draft loss on navigation). **Estimate:** 45–60 minutes, dashboard. **A2:** changing entry type, including by a single arrow key on the tablist, should not silently erase a valid entry draft.

Production https://beancount.io, 2026-10-20; local main `c5e4cd11a`. Separate fresh QA-owner contexts, isolated headless Chromium 155.0.8059.85, 1440×1000 and 390×844, English/light, America/Los_Angeles. Only unsaved forms in the designated disposable ledger; zero mutation requests.

## Reproduction and control

1. Journal → New Entry → Note. Select existing Assets:Cash, enter a prefixed Note content value and verify Create Note Entry is enabled.
2. Click the already active Note tab. Its exact account/content remain: a passing control.
3. Focus Note and press ArrowLeft. Wait for Balance to be selected and its Create Balance Entry button to render. The URL changes to directive=balance and the original Note input is disconnected. There is only the ordinary New Entry dialog and no discard decision.
4. Focus Balance and press ArrowRight. Wait for Note to be selected again. Both Account and Note content are now empty; Create Note Entry is disabled. Both fresh widths reproduce. A separate desktop pointer switch Balance → Note also lost the text.

Expected: retain each local draft for the life of the open dialog, or ask before discarding a dirty form. Merely navigating the tablist must not irreversibly remove accepted input without a decision. Explicitly closing/discarding the whole dialog is a separate user action. No pending request is needed here.

## Cause and bounded repair

`dashboard/src/features/journal/components/new-directive-dialog/index.tsx:84–87,112–139` uses ordinary TabsContent for each independently stateful form. Inactive content unmounts; NoteForm's local useForm defaults at `note-form.tsx:60–68` create empty fields when returning. `journal-page.tsx:389–400` changes directive search immediately, with no draft contract. Other three forms follow the same local-state structure; only Note draft loss was live reproduced.

Choose a bounded dialog-local retention or explicit dirty-transition policy for all four types. Preserve automatic keyboard tab navigation, correct selection/URL, validation/account suggestions, exactly one active submit target and normal explicit dismissal. Avoid a persistent/global draft store. A pending-state lock by itself does not fix this ordinary non-pending journey. Coordinate with w4/m33 so retention does not let an old submission close or reset a different draft.

Acceptance: a valid unsaved Note survives Note → Balance → Note with pointer and native arrow keys, or a clear discard choice can be declined without losing any fields. Cover Transaction posting rows and Balance/Account draft values through the real shared dialog, initial empty switching, successful reset and explicit dismissal. Keep inactive forms inaccessible and prevent accidental submission. Run dashboard checks when implementing.
