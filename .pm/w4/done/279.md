## Cause and bounded repair

`dashboard/src/common/lib/beancount/account-token.ts:8` accepts Lu/Lo/Nd initials and only L/Nd/hyphen continuations. Combining marks are category M and the initial ǅ is category Lt, so valid tokens fall outside those classes. COMPONENT_START at:18 repeats the narrower initial rule and supplies the wrong failure reason for the titlecase case. `open-account-schema.ts:34` feeds the refusal into the shared schema; `use-open-account-schema.ts` supplies it to Accounts OpenAccountDialog and Journal OpenAccountForm, whose submit buttons depend on isValid.

Admit the independently supported titlecase initials and combining-mark continuations in the shared token validation while preserving exact authored account strings. Keep the distinction between a valid initial and continuation; do not blanket-accept arbitrary Unicode, whitespace, empty segments, lowercase-led Latin components or underscores. Do not normalize decomposed input into another account identity as a substitute for accepting it. Preserve configured root-prefix checks, duplicate/open/closed-account checks, date validation and useful existing messages for genuinely invalid tokens. No API, dependency, translation or cross-package change is needed; the live write capability already accepts the inputs.

Acceptance: the real Accounts and Journal forms accept Hindi, the exact NFD spelling and titlecase-initial name, retaining their raw strings; composed/CJK/ASCII controls remain valid and lowercase/space/empty/underscore controls remain invalid. Cover the actual shared schema/form validity and disabled state, rather than mocking away validation. Retain meaningful existing validation-reason/localization tests and run dashboard format/lint/test/build.
