## Cause and bounded repair

`dashboard/src/common/lib/readme-reference.ts:21–23` explicitly returns null for an authored path ending in `/`. `common/components/markdown-renderer.tsx:229–238` interprets null as keeping the authored href. The browser then resolves that directory link from the application URL, which is neither the README source path nor consistently a slash-terminated directory URL. The same renderer already receives the correct source ledger/path from ReadmeCard at:89 and resolves relative files correctly.

Resolve explicit trailing-slash directory references from the README source folder and emit canonical Files tree hrefs in the supported main branch. Distinguish file versus directory destinations rather than sending folders to blob views. `child/`, `./` and valid parent-relative folder references should retain the correct ledger/path, including the root directory when appropriate. Preserve segment encoding and authored query/fragment suffixes; a native href must work without depending on a primary-click callback or adding a trailing slash to the current browser URL.

Keep the existing file/image repair, non-README Markdown behavior and authored external/root-relative/fragment references intact. Directory-shaped image sources should retain their existing behavior rather than being fetched as ledger files. No backend/API, new dependency, branch expansion, authored README rewrite or new translation is needed. Extensionless ambiguous destinations without a trailing slash are outside this bounded finding.

Acceptance: actual root/nested README directory links open the same locations as canonical folder-row links through keyboard and native new-tab navigation; `./` stays in the README's folder and parent-relative directories resolve correctly. Relative file links and existing image/fragment controls remain healthy. Cover the real contextual renderer/native hrefs with meaningful root/nested cases, repeat desktop/narrow and run dashboard format:check, lint, test and build when implementing. Root Overview README behavior is compatibility/acceptance scope, not live evidence in this probe.
