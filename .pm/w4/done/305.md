# Keep late Upload completion from redirecting after the user leaves

**Severity:** minor. **Estimate:** 45–60 minutes, dashboard. **A2:** someone who leaves a pending upload for Journal should remain there when the original batch finishes.

## Reproduction and result

1. Open `/ledger/<qa-owner>/<synthetic-ledger>/files/upload/main/`. Stage one uniquely prefixed benign text file through the actual file input and click **Upload Files**.
2. Hold only its exact CreateLedgerFile request. Cancel and Choose your files are disabled. The original accepted batch remains visible.
3. Activate the main-content **Journal** related link with Enter. No departure dialog appears. The URL reaches `/journal` and Journal is rendered: desktop has its Journal heading, narrow has its visible Filters control. No write has reached the server yet.
4. Release the original request unchanged. HTTP200, no GraphQL errors, exactly one file created with its original bytes. After the folder refresh, the old upload handler changes Journal to `/files/tree/main/` without another user navigation.

## Cause and bounded repair

`dashboard/src/features/ledger-editor/upload-files/index.tsx:156–216` captures the batch, awaits each CreateLedgerFile and then refreshDirectory, and unconditionally navigates to the captured ledger/directory Files tree. No active-view or operation ownership check revokes this completion's navigation after departure. The Journal related link remains usable while uploading. TanStack's stable useNavigate callback delegates to the global router and can still navigate after the old page unmounts.

Limit automatic successful departure to the same still-current upload journey. Once the user leaves, the authorized batch and its data refresh may finish, but its old completion must not replace the current route. Returning to Upload, switching ledger/directory parameters or starting a later batch must not restore an earlier operation's navigation authority. Preserve the accepted batch's write semantics; leaving does not prove a transmitted write was cancelled. No global navigation manager, persistent upload drafts, new dependency or backend/API change is indicated.

Acceptance: cover the real UploadFilesPage/router/mutation lifecycle with a held create, native Journal departure and late acknowledgement; Journal remains current. Add departure during the post-ack folder refresh and leave/return/new-selection cases. Preserve ordinary foreground completion navigating once, partial-batch retry, existing-name/size/permission checks, exact bytes, [248](./done/248.md)'s acknowledged-write classification and [259](./done/259.md)'s busy input guard. Run dashboard format:check, lint, test and build on implementation. Only the pre-transport create hold was live tested here; other timings/parameter changes are regression scope.
