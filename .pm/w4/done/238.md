# Restore Accounts and Journal keyboard focus after successful write refresh

**Severity:** minor (keyboard accessibility). **Estimate:** 45–60 minutes, dashboard. **A2:** after creating, closing or deleting an account, keyboard users should continue at a useful account control rather than restart navigation from the page body.

## Reproduce

Production `https://beancount.io`, 2026-10-20, headless isolated QA-owned Chromium 155.0.8059.85, English/light, authenticated disposable-ledger owner. Local main `c5e4cd11a`; production `main-D9qWGMxD.js`, full deployed SHA unverified. Real UI writes and real responses, with no throttling, response substitution or fabricated account permissions.

1. At 1440×1000, open `/ledger/<qa-owner>/<synthetic-ledger>/accounts`, activate **Open Account**, and create `Assets:Qa-20261020-Account` on 2026-10-20. `BulkEntries` succeeds, the modal disappears, and the settled directory shows the new Open account, zero postings and empty balance. After settlement plus 300ms, `document.activeElement` is **BODY**, not the persistent header link.
2. Use **Actions for Assets:Qa-20261020-Account → Close** and confirm. The real write succeeds and the settled row becomes Closed with the correct date. Focus again remains **BODY**, rather than its surviving actions button or the search fallback.
3. Fresh-reload Accounts at 390×844. Open the same row's **Delete** dialog, wait for both real source-context reads, and Cancel: focus correctly returns to that account's actions button.
4. Reopen and confirm Delete. `DeleteMultipleLedgerEntrySourceSlices` returns HTTP 200, `deletedCount:2`; the account's Open and Close directives are removed, and the row disappears. The settled **Search accounts...** input exists but is not focused; active element is **BODY**.

Passive DOM/focus observation during step 4 records the search input present initially, absent during cache-driven layout replacement, then present again with BODY still focused. The browser records fresh successful `GetLedger` and `GetLedgerAccountDirectives` reads. No network/page exception explains the focus loss. This observation does not alter responses, focus methods or application state.

Working controls: the fresh narrow Delete → Cancel returns to Actions. Open Account/New → Cancel and Escape return to New, and Enter on that returned link reopens the route-driven dialog once rendering settles. Thus ordinary connected-opener dismissal works; successful mutation/revalidation is the failing lifecycle. All write targets were created by this run, and the original file was restored byte-for-byte after deletion; original SHA-256, zero QA entries and an empty ledger-error list were verified.

## Cause and bounded repair

Accounts passes the broad cache-clear callback to all three successful write dialogs at `dashboard/src/features/ledger-data/accounts/index.tsx:667,680,694`. `common/hooks/use-apollo-cache.ts:19` evicts `ROOT_QUERY`, including the ledger metadata query. `common/components/ledger-layout/index.tsx:101–102` replaces the entire ledger subtree whenever that query is loading, unmounting the Accounts page and its otherwise persistent header/search controls. The account table also substitutes its loading view while its own read runs. The existing `restoreFocusOnDialogClose` only focuses a target connected at dismissal; it has no handoff to controls that mount after this refresh. A connected opener/fallback in a simple dialog test cannot prove this write lifecycle.

Coordinate successful Accounts refresh and focus restoration so focus lands on the **settled, connected** header Open Account/New link after create, the surviving account actions button after Close, and Search accounts after Delete removes its row. Preserve accurate post-write data, error states, permissions, route action cleanup, shared filters, initial loading and ledger-switch isolation. Reuse the existing focus conventions and keep the common Dialog primitive's behavior intact.

All `useApolloCacheClear` callers were searched. Other ledger consumers include Budget delete, file save/delete, Journal entry/new-directive writes and the out-of-date refresh control; their focus outcomes were not independently exercised here. Dashboard-sidebar and account-danger-zone callers also use the hook outside this ledger lifecycle. This finding claims the three Accounts paths above, not every cache clear.

Acceptance: run the actual ledger layout, Accounts page, Apollo cache and dialog primitives through success followed by real cache invalidation/refetch. Assert the final connected target after the replacement reads settle for create, Close and Delete, plus existing Cancel/Escape controls. Include pending/failed refresh, removed action buttons and ledger switches; mock responses may bound external services, but a mocked `useLedger`/no-op cache clear misses this cause. Repeat the fresh desktop/narrow synthetic journey and verify exact restoration. No API/schema/dependency change is required. Run dashboard format/lint/test/build when implementing.
