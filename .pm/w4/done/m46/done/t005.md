## Objective

Prove the owning editor survives the actual refresh boundary without weakening file concurrency.

## Acceptance criteria

- [x] Integration coverage drives the actual router, Apollo cache eviction/refetch, LedgerFileView and editor state; a no-op cache-clear mock or isolated external-content guard is insufficient.
- [x] Include the real LedgerLayout and BQL page: an unexecuted three-row query survives Refresh and the next Execute sends that exact query. Assert the retained current page/editor or an explicit discard choice, not merely a matching URL. Regress initial/pending-access and ledger-switch isolation.
- [x] Assert exact dirty text through pending, successful and failed same-file refresh; explicit discard and clean view refresh; original SHA in a retained draft's prepared save; stale failure retention; genuine path/ledger change and delayed old response isolation.
- [x] Preserve existing successful-save exit and pending-save locking coverage. Demonstrate the dirty-refresh regression fails with the relevant repair reverted.
- [x] Run dashboard format:check, lint, test and build from `dashboard/`. Use existing dependencies and meaningful behavior assertions.

## Verification — 2026-10-22

`dashboard/src/common/components/ledger-layout/__tests__/refresh-keeps-drafts.test.tsx` uses the real router, routes, `LedgerLayout`, Out of date indicator, `LedgerFileView`, `TextFileView`, BQL page and Apollo `InMemoryCache`. A controlled link holds, fails or answers each read with complete data built from the operation's own selection set. Only Monaco's runtime and the unrelated layout chrome are stubbed. The nine cases:
- the page, editor and draft survive a held refresh and its landing;
- Save sends the original SHA and exact draft, and a refusal keeps the draft;
- an explicit discard takes the refreshed file;
- a failed refresh keeps the draft with one shared toast whose Try again refetches;
- a clean view-mode refresh shows the new file in the same editor;
- an unexecuted BQL query survives, and Execute sends it exactly;
- a draft never appears on another file;
- a ledger switch replaces the page while the other ledger loads;
- a delayed read of the old file never lands on a new one.

`refused-path-view` gains the refused-with-stale-data case.

**Revert checks:**
- With the layout fix reverted, the held-refresh, failed-refresh and BQL cases fail.
- With the file-view fix reverted, the original-SHA save and failed-refresh cases fail.
- With the TextFileView base reverted, the original-SHA save fails.
- Without the refused-path rule, the new refused case fails.
- The clean-refresh and discard controls pass throughout.

**Preserved suites:** pending-access and ledger-switch isolation (`ledger-layout-pending`, importer and receipt access), successful-save exit and pending-save locking all pass.

**Gates:** dashboard `yarn format:check` 0, `yarn lint` 0, `yarn build` 0, and `yarn test` 0. See [t006](./t006.md) for the closing counts.
