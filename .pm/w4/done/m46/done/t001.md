## Objective

Prevent same-ledger cache refresh from silently replacing an unexecuted BQL or unsaved file editor.

## Steps and acceptance

- [x] Reproduce [FINDINGS](../FINDINGS.md) with the real file query, root eviction and editor lifecycle.
- [x] Include real LedgerLayout around BQL. The live original main and BQL editor both disconnect; inspect actual post-eviction query emissions and retain the already loaded current-ledger subtree. Keep initial/pending-access and identity-change isolation, rather than removing every loading guard.
- [x] Keep the current buffer through pending/successful/failed refresh, or require explicit consent before discarding it. Preserve editor Undo/focus state where retaining the session.
- [x] Bound retained content to the current ledger and file path. Initial loading, missing/denied files and a genuine identity change must never display another file's draft as current.
- [x] Keep ordinary clean view-mode refresh current. Preserve the ledger-layout retention and existing save locking/covered-exit fixes.

## Files and scope

`dashboard/src/common/components/ledger-layout/`, `dashboard/src/features/ledger-editor/file-editor/components/ledger-file-view/` and necessary owning integration. BQL is a regression consumer; avoid adding a separate draft store if retaining the layout solves it. No global cache-policy change, persistent drafts, backend/API change or dependency.

## Verification — 2026-10-22

**Cause.** A real Apollo 4.1 probe, with an `InMemoryCache` and a controlled link, showed what a ROOT_QUERY eviction does:
- Every watched query refetches with its old result still in `data` (`loading: true`, networkStatus 1).
- A failed refetch keeps that `data` and sets `error`.

`LedgerLayout`'s `!currentLedger || (loading && data?.getLedger)` therefore swapped the whole page for its loading shell, and `if (error)` swapped it for the error page. That disconnected `<main>`, the BQL editor and the file editor. W4/238's test had modelled the refetch as `data: undefined`, which Apollo does not emit.

**Fix:**
- `dashboard/src/common/components/ledger-layout/index.tsx` records the ledger this layout instance has shown (state set during render). A page already shown for the same ledger stays mounted through the refetch and through its failure.
- A first mount still waits for the access read, and a failed one still shows the error page; the Smart Import / Upload Receipt access suites pass.
- A ledger switch still shows the loading shell.
- `LedgerFileView` keeps the same file's retained `data` when its refetch fails. A refused path is still not found, and missing or denied files keep their views.
- A failure is reported once, through the shared `useRefreshFailedToast` with Try again (`dashboard/src/common/hooks/use-refresh-failed-toast.ts`).
- There is no cache-policy change, draft store, dependency or API change.
