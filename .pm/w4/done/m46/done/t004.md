## Objective and acceptance

Run `/simplify` over this milestone's code. Keep one clear owner for file identity, draft and edit-base revision, remove redundant snapshots/effects and preserve behavior. Avoid a global cache/navigation manager or a second draft store.

## Verification — 2026-10-22

`/simplify` ran four parallel reviewers (reuse, simplification, efficiency, altitude). Altitude confirmed the shown-ledger state as the right depth:
- `refetchQueries` would still emit loading or error with data, and would change what Refresh means.
- networkStatus cannot tell a first-mount access read from an eviction refetch.

**Applied:**
- **One toast hook.** A single `useRefreshFailedToast(error, retry)` in its own module replaces two identical toast effects. Being its own module, it leaves the 15 suites that mock `use-apollo-cache` untouched.
- **Retry action.** The toast gained **Try Again**, because the indicator hides itself even when the refresh fails.
- **Refused paths.** A refused path with stale data stays not found.
- **Simpler conditions.** The file view's error and not-found branches use plain `!fileContent` checks.
- **Merged comments.** The layout's overlapping comments are merged, and an out-of-date line is removed.
- **Memoized decodes.** The base64 decodes of the current file and of the draft's base are memoized, so a draft on a large file no longer decodes twice per keystroke.
- **Type alias.** A `FileRevision` alias replaces the repeated `NonNullable<…>`.
- **Test helpers.** `initialServer()`, a `REMOTE` default and `refreshAndSettle()`.

**Skipped:**
- A per-path `key` on `FileContentView`. The router already remounts the file route per path, and the identity test passes without it, so it would be dead defence.
- Storing only a SHA as the base. The BOM check and the dirty comparison need its content.
