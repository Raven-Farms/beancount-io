## Objective

Retaining unsaved text must also preserve the original revision against which that text was edited.

## Steps and acceptance

- [x] Keep ledger/path/edit-base SHA consistent for a retained draft. A newer file read must not rebase the draft's Save onto that remote SHA without an explicit supported decision.
- [x] Verify a prepared stale Save uses the original SHA and keeps the exact draft after refusal; independent remote bytes remain unchanged. This is compatibility coverage, not a reproduced overwrite from QA.
- [x] Preserve BOM/line endings, current-SHA successful-save exit, pending-save readonly/single-write behavior, ordinary dirty Cancel/Stay/Discard and failed-save recovery.
- [x] Keep stale error-category repair assigned to W23/032. No unconditional overwrite, backend/schema change or new persistence workflow.

## Files

Owning LedgerFileView/TextFileView save and revision state within `dashboard/`; use the minimal state needed by the retained session.

## Verification — 2026-10-22

**Bound to its revision.** `TextFileView` keeps `base`, the file revision the buffer was edited against.
- A newer read replaces the buffer only when it holds no draft, or in view or read-only mode.
- A draft keeps its base, and Save calls `onSave(content, base)`.
- `LedgerFileView` sends `base.sha` and takes the BOM from `base.content`.
- An explicit discard (Cancel → Leave Without Saving) adopts the current file.
- The unsaved-changes guard compares the draft with the base.

**Preserved behaviour.** Apollo 4 rejects a refused mutation even with `onError` (probed), so a stale refusal reaches the existing catch, and the draft and edit mode stay. BOM retention (`save-keeps-bom`), the pending-save lock and successful-save exit (`text-file-save-lifecycle`), dirty navigation and failed-save recovery suites all pass with the extra `base` argument.

**Natively, at both widths:** after a modeled remote revision and Refresh, Save sends the draft (marker present, remote line absent) with the original SHA `b014121c…`, not the refreshed `qa-m46-file-1`. The modeled stale refusal keeps the draft and edit mode. Stale-error classification remains with W23/032.
