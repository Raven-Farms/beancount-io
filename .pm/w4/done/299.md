# Return focus after restoring a public reader's hidden dashboard

**Severity:** minor. **Estimate:** 45–60 minutes, dashboard. **A2/A3:** a keyboard reader recovering an existing hidden dashboard layout should resume in that dashboard after closing Customize.

Production `https://beancount.io`, 2026-10-21 America/Los_Angeles, owned isolated headless Chromium155.0.8059.85, English/UTC, ordinary theme. Fresh guest public Example contexts at390×844 and1440×1000 independently reproduce. The relevant deployed page, customizer and layout hook match current source exactly; local main during final dedupe `8d4d672f9`. No hosted writes or substituted API responses.

## Reproduction and controls

1. Open `/ledger/open_ledger/example` with a valid previously saved all-hidden layout. For the repeatable isolated-browser control, seed only `ledger.open_ledger/example.overview.layout.v1` in localStorage with the following valid preference, then reload:

   ```json
   {"version":1,"order":["financial-position","money-movement","recent-activity","income-expenses","balance-sheet","cash-flow","readme"],"hidden":["financial-position","money-movement","recent-activity","income-expenses","balance-sheet","cash-flow","readme"]}
   ```

   This is an explicitly controlled saved-preference fixture, not malformed storage or a mocked server response. Public readers could save this layout through the formerly visible Customize header before `c37679bc2`; the current component explicitly retains the all-hidden recovery entry point for them. The current ordinary public header intentionally has no Customize trigger.
2. The real empty state says **All dashboard modules are hidden. Customize the dashboard to restore one.** Focus its Customize button and press Enter. All seven switches are unchecked.
3. Focus **Show module: Financial position** and press Space. The actual module appears, the same panel stays open, and focus stays on that switch. The empty-state opener is now disconnected. This portion of completed [185](./done/185.md) still works.
4. Press Escape and wait for the Sheet to finish closing. **Focus is BODY**, no Customize trigger remains, and the next native Tab reaches **Skip to main content**, restarting at the top of the shell. Both fresh widths repeat it. The existing main landmark is present with tabindex=-1, but is not used as a fallback. No horizontal overflow occurs.
5. At390px, repeat with keyboard **Reset layout** instead of the single switch. All modules return, the opener disappears, and dismissal again leaves BODY followed by the skip link.

Working controls: Escape without changing any switch returns to the still-connected empty-state Customize button at both widths. On the authenticated synthetic-ledger owner's dashboard, restoring from the empty-state prompt keeps the panel/switch focus and Escape returns to the persistent header Customize trigger at both widths. The desktop owner control also verifies native hide-all, reload persistence, Reset and a settled reload with all seven checked in default order. Ordinary nonboundary reordering retains focus; the boundary's next Tab reaches that module's enabled control and is not retained as a separate bug.

## Root cause and bounded repair

`dashboard/src/features/reports/overview/index.tsx:494–507` now passes `showTrigger={!publicReader}`. Its empty-state button at545–552 still stores `customizeOpener.current` and opens the persistent shared panel. Restoring a module removes that opener. `components/dashboard-customizer.tsx:100–116` renders no SheetTrigger for a public reader, and its onCloseAutoFocus handles only a connected custom opener. It assumes Radix can return to the header otherwise.

Installed Radix Dialog's modal `onCloseAutoFocus` (`node_modules/@radix-ui/react-dialog/dist/index.mjs:146–149`) prevents the default focus restoration and calls `context.triggerRef.current?.focus()`. With neither a connected custom opener nor a rendered header trigger, it focuses nothing. The real browser observations corroborate this exact missing fallback.

Choose a stable, visible content fallback when the actual opener disappeared and the reader has no header trigger, and explicitly complete the close-focus handoff. The existing programmatically focusable main landmark and `common/lib/main-content.ts` provide a local precedent; a supplied stable page-content ref is another bounded option. Native Tab should continue within the current dashboard after that handoff. Preserve connected-opener return, owners' header return, the intentional public-header policy, persistent panel lifetime, switch/reorder/Reset behavior, per-ledger saved layout and browser-only preferences. Do not reopen the panel automatically, retain a hidden phantom trigger, globally focus on every render or introduce API/dependency changes.

Add a meaningful owning-page test with the real customizer/Sheet and layout transitions: public-reader all-hidden → restore → close, Reset → close, unchanged Escape, and the owner-header control. Assert actual activeElement and continued keyboard navigation after close, rather than only dialog count or a callback invocation. Repeat both fresh browser widths and run dashboard gates when implementing.
