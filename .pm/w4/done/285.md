## Cause and bounded repair

`dashboard/src/common/lib/format/format-date-iso.ts:17–28` strips any timestamp suffix, parses the date part with date-fns parseISO, then formats that local Date. The installed date-fns parseISO implementation constructs a local result with setFullYear/setHours for a date without an explicit timezone. Pacific/Apia did not observe 2011-12-30, so that local midnight normalizes to the next day. This display formatter accepts the normalized Date and silently emits 2011-12-31.

Direct execution of the actual TypeScript helper in fresh Node processes confirms the mechanism: `2011-12-30` and `2011-12-30T12:00:00Z` return 2011-12-31 under TZ=Pacific/Apia, and 2011-12-30 under UTC/Los Angeles. The helper's documented timestamp behavior is to preserve its date part, so do not turn this repair into local-time conversion of timestamps. Adjacent dates and valid 0001/0099 controls remain exact; impossible 2026-02-30, null and empty input still return null in all three zones.

Validate and format the supplied calendar date independently of an observable local midnight. Keep exact day identity, zero padding, existing invalid-input behavior and the timestamp date-part contract. Reuse suitable existing date infrastructure without introducing a second broad date framework, a dependency, cross-feature imports or machine-timezone changes. Do not return a normalized following day or merely bypass validation.

The searched production callers are Events dates, Documents dates, Journal visible dates and journalEntryLabel accessibility text, Statistics Account Last Entries, commodity chart tooltip date labels, collaborator creation dates and SSH-key Added dates. Events is the live failing surface; the literal CommodityPriceHistory table is a passing control and does not call this helper. Other caller failures are source-traced regression scope, not independently proven live. No credential/collaborator changes or actual document upload is needed.

Acceptance: the actual helper preserves Dec 29/30/31 in UTC, Los Angeles and Apia, including a timestamp whose date part is day30; malformed/impossible/empty inputs and valid early years retain their contracts. Render Events with the three API dates and assert exact text in all zones. Audit representative Journal visible/accessible labels and the other shared callers so the repair remains centralized. Repeat actual narrow/desktop Events and the literal price-history control; run dashboard format/lint/test/build. Keep this frontend-only repair separate from backend date validation.
