## Objective

Keep a recoverable recording failure from erasing the corrected receipt review.

## Context

See [the milestone](../README.md), [original pending-success evidence](../source-973.md) and [failure recovery evidence](../FINDINGS.md). Implementation belongs to features/receipt hooks/components/pages and their existing tests.

## Steps

1. Preserve the exact reviewed fields, parsed/upload context and objectKey through insert refusal/exception. Provide an inspect/correct/manual retry path without re-upload/re-parse or automatic writes. Retain honest handling of uncertain transport outcomes and preserve explicit Upload Different Receipt plus initial upload/parse errors.

## Acceptance criteria

- [x] Verify the stated transition against the actual workflow/form and record evidence and limits.
- [x] Preserve the milestone's exact values, explicit reset, honest errors and duplicate-submit controls.

## Out of scope

Backend/API changes, actual hosted booking or AI quota use, persistent drafts, unrelated importer redesign and new dependencies.

## Verification

**Fix.**
- `use-receipt-workflow.ts` returns a failed Record to the `review` step it was sent from, with an `error`. The form stays mounted with its exact values, and the uploaded `objectKey` and `parsed` receipt are kept.
- The error shows beside Record (`role="alert"`), and focus returns to Record.
- **Honest outcome:** a server refusal (`success:false`, or a GraphQL refusal code such as BAD_USER_INPUT) says only that recording failed.
- A lost connection, a server fault (INTERNAL_SERVER_ERROR, SERVICE_UNAVAILABLE) or an unknown code adds the localized `receipt.workflow.recordUnconfirmed` (15 locales): *"It may have been recorded anyway, so check the Journal before recording it again."*
- There is no automatic resend.
- Upload Different Receipt still resets on purpose. Upload and parse failures keep the existing error view with Try Again.

**Native check, 1440/390:**
- **Aborted Record:** the corrected review stays, with the honest alert and focus on Record.
- **Enter retry:** sends variables identical to the first request, after exactly one upload URL, one PUT and one parse.
- **Modeled success:** the card shows `qa-m48-<w>-payee`, Aug 1, 2026, `18.75 USD`, `Expenses:Food:Coffee`, `Assets:US:BofA:Checking`.
- **Modeled `success:false`:** keeps the review with "Failed to record receipt transaction" and no Journal sentence.
- **Upload Different Receipt:** returns to the uploader.
- **Aborted ParseReceipt:** still shows Something went wrong, and Try Again returns to the uploader.
