## Cause and bounded repair

`dashboard/src/features/importer/hooks/use-csv-parser.ts:292–324` reads the file with nonfatal FileReader.readAsText. Its successful onload passes the already-replaced string into parseCSV; onerror only handles a failed read, so this decoding loss is not reported. `use-multi-stage-parser.ts:60–64` accepts the resulting validCount>0 and hands it to Preview. Configure's fields and the eventual submit mapper consume these same strings rather than the original bytes.

Validate decoding from the source bytes before permitting CSV row parsing. Preserve deterministic currently supported BOM decoding, using built-in decoders with loss detection; do not guess legacy encodings or add a dependency/encoding-converter interface. If the selected bytes cannot be decoded safely under that policy, stop the local import path and give localized, accessible re-save-as-UTF-8 guidance with an Upload Different File recovery. Carry the classified error through the multi-stage parser so it is not replaced with generic zero-valid-row/AI-offer messaging. Retain explicit user choice before any AI spend and leave PDF/OFX/image parsing behavior intact.

Preserve valid UTF-8, UTF-8/UTF-16 BOM controls, literal U+FFFD, CRLF, quoted records, recognized headers, exact amount conventions, unsupported-precision handling and ordinary file-read failure recovery. Do not detect failure with a post-decoding replacement-character substring check.

Acceptance: drive real Blob/File bytes through the parser and upload handoff, rather than mocking FileReader to return predecoded text. The85-byte seed must not become a valid configured corrupted row; its encoding error must remain actionable through the workflow. Confirm the five passing controls above, new-file recovery, zero implicit AI calls and desktop/narrow behavior; run dashboard format/lint/test/build when implementing. No backend/API surface change is needed.
