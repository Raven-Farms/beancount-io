## Reproduction and working controls

2. Reports correctly starts expanded, exposing six links including the current Balance Sheet. Its separate enabled chevron button has name **Reports**, aria-expanded=true and aria-controls=ledger-sidebar-reports. The Reports label is a separate navigation link.

4. In the same pages, inactive **Advanced** starts false. Enter opens it and Space closes it, with focus retained. Its ordinary toggle works.
5. Fresh-load `/ledger/open_ledger/example/query` at390px and open the sidebar. The active **Advanced** group similarly stays true with all three links after Enter, Space and pointer activation. Inactive Reports correctly changes false→true→false. This case checks sidebar behavior; it does not claim anonymous BQL execution or authenticate a guest.

Expected: automatic reveal on arrival keeps the selected destination discoverable, and an explicit activation afterward can close the section. A second activation reopens it. The enabled disclosure should implement its advertised show/hide action. The [W3C disclosure pattern](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) describes Enter and Space toggling the controlled content; no screen-reader speech or conformance audit is claimed here.

Independent native navigation control: at390px with time2016-08 and account Assets:US:BofA:Checking, keyboard activation of the separate Reports link reaches Income Statement, preserves both filters, updates the title and closes the drawer. The Balance Sheet child link returns with the same scope and dismissal behavior. Preserve these passing navigation contracts.

## Root cause and bounded repair

`dashboard/src/common/components/ledger-layout/ledger-sidebar.tsx:307–316` toggles only membership in openGroups. At358, `const isOpen = hasActiveItem || openGroups.has(group.id)` forces the active group true regardless of that membership. Consequently the click handler runs but neither adding nor removing the active group can close it. `renderMenuGroup` uses this same derived state for both the Reports chevron and other group-header buttons, their aria-expanded and submenu rendering.

Represent explicit disclosure choices so the current route's initial auto-reveal does not override a user's close action. Keep direct-load/new-route reveal and active/current styling correct while allowing close→open on the active group. Preserve the separate Reports landing link, filter propagation, selected child links, mobile dismissal/focus, collapsed-rail flyouts, status visibility/counts and ledger-scope isolation. Do not remove automatic reveal, force every group closed initially, disable the still-advertised action or replace navigation with a new accordion framework. No API or dependency changes are needed.

Add meaningful rendered Sidebar interaction coverage: an active group starts open, Enter/click closes it and removes its submenu from the accessibility tree, another activation reopens it, inactive groups still toggle, and a fresh/current-route transition reveals the selected destination appropriately. Existing `ledger-sidebar.test.tsx` proves inactive opening and initial active-route reveal but never activates an already active group's disclosure. Repeat expanded desktop/narrow browser controls and run dashboard gates when implementing.
