# Update native guest sign-in hrefs with the available fragment after hydration

**Severity:** minor. **Estimate:** 45–60 minutes, dashboard. **A2:** opening a sign-in continuation in a new tab should retain the same destination as ordinary activation, including its available page fragment.

Production `https://beancount.io`, 2026-10-20, English/light, QA-owned headless isolated Chromium 155.0.8059.85. Fresh signed-out contexts at 390×844 and 1440×1000. Local main `c5e4cd11a`; full deployed revision unverified. No password, OTP, email, upload, quota-spending or ledger mutation in these checks; every temporary context and child tab was closed.

## Reproduce and control

1. Fresh-load `/ledger/open_ledger/stock-example/receipt?time=2026-09#main-content`. The unavailable notice correctly offers **Sign in** and zero file inputs.
2. Wait three seconds after the link appears. Both `window.location.hash` and the live router location contain `#main-content`; router href is exactly `/ledger/open_ledger/stock-example/receipt?time=2026-09#main-content`.
3. Inspect the notice's actual anchor href. It is still `/auth/login?next=%2Fledger%2Fopen_ledger%2Fstock-example%2Freceipt%3Ftime%3D2026-09`, omitting the encoded fragment.
4. Middle-click that anchor. The real new tab reaches Login with `next=/ledger/open_ledger/stock-example/receipt?time=2026-09`; the fragment is lost. Close that owned tab.
5. Ordinary primary activation of the original link reaches Login with `next=/ledger/open_ledger/stock-example/receipt?time=2026-09#main-content`. This is a working client-navigation control, with zero document navigation requests. Repeat from a new context at the other width: same native/primary split.

This does not claim the whole return destination is lost, a failed login, or an actual password-completion result. The missing fragment is proved in the emitted destination before authentication. Initial Import notice hrefs showed the same omission, but native new-tab activation was independently exercised for Receipt only.

## Cause and bounded repair

`dashboard/src/common/components/ledger-write-access-notice.tsx:38–49` passes `getSafeReturnPath(useLocation())` into the Link during server rendering and hydration. The server href lacks the browser-only fragment; after hydration the router and primary-click callback have it, while the DOM anchor retains the server href. `common/lib/auth/auth.ts:121–123` correctly preserves a fragment when supplied, so changing its delimiter serializer again is not indicated.

The observed split is consistent with an initial server/client href hydration mismatch leaving the attribute unchanged; installed React's development hydration diagnostic explicitly documents that mismatched attributes are not patched (`node_modules/react-dom/cjs/react-dom-client.development.js:5440`), and TanStack Link has separate server static-prop and client navigation paths. The exact internal hydration timing was not instrumented. Repair the client enhancement so the first hydration output matches the server fallback, then a deliberate post-hydration update puts the available full safe continuation in the **actual href**. Preserve encoded fragments, path/query, empty hashes, hash changes and the existing safe-relative redirect policy. Keep these as real links with working native activation and ordinary navigation.

The shared notice has two production consumers: ImportPage and ReceiptPage. Cover both; preserve reader/anonymous/unresolved permission messaging and zero file inputs. Coordinate w4/237's separate header links, whose missing destination has a different producer cause. Avoid a global router override or removing safe continuation validation.

Acceptance: render the notice's server fallback without a fragment, hydrate at a browser URL with one, settle, then assert the actual anchor href decodes to the full safe next. A client-only rendered Link or navigation callback assertion misses this failure. Exercise primary and native new-tab activation in the browser at both widths, plus plain-path/query-only and safe-redirect controls. Run dashboard format/lint/test/build when implementing; no API, dependency or translation change is needed.
