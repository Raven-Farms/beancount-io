## Root cause and bounded repair

`backend-cluster/ledger/src/foundation/rustledger/directives-report.ts:327–343` maps each document's raw `directive.path` directly into the report, losing its directive identity/source provenance. `features/ledger/service/ledger-data-mappers.ts:123–143` copies that path to public filename. `LedgerDataService.getDocuments` calls these after filtering. Dashboard `features/ledger-data/documents/index.tsx` passes the returned filename directly to the existing repository-relative file navigator; it has no declaring-file context to recover.

The source location is available before collection: the engine's document-source probe and `getDirectiveSourceLocation` retain it. A current local probe through real `parseLedgerFilesInProcess` + collectDocuments + toDocumentsPublic produces zero errors and confirms:

| Declaring source | Raw path | Public filename |
| --- | --- | --- |
| main.bean | books/receipt.txt | books/receipt.txt |
| books/documents.bean | receipt.txt | receipt.txt — wrong base |

The existing `foundation/rustledger/document-validation.ts:76–83` already resolves document existence against the declaring file. That explains the clean ledger check alongside a broken report link. Reuse that established resolution contract at the report boundary while directive provenance is available, yielding a normalized repository-relative filename. Preserve the original directive/source text and source identity for editing, and verify provenance through production worker/cache serialization rather than assuming in-process weak-map state alone.

Keep root-source paths, legal relative segments, Unicode, tags/links, filters and file authorization/confinement intact. Do not guess a folder in the frontend, strip to a basename, fall back to an unrelated root file, fetch host-absolute paths or patch the upstream WASM dependency. Audit the legacy Journal Document filename serializer (`ledger-legacy-journal.ts:167–174`), which also copies the raw path, against its outward contract; native Journal attachment navigation was not exercised here. Keep this a ledger-owned normalization unit, without cross-package imports or a new path framework.

API parity: Query.getLedgerDocuments, REST `GET /api-gateway/v1/ledgers/{owner}/{name}/documents`, and the existing MCP **ledgerDocuments resource** must expose coherent attachment identity through their shared report. No new MCP tool is needed. Add meaningful real-parser/source-provenance and outward-contract tests for root/included paths and two includes with the same attachment basename; verify actual file read/open resolves each correctly. Preserve source edits and existing confinement/denied/missing-file behavior. REST/MCP were source-audited, not live reproduced during this browser run. Run the ledger checks and applicable backend parity checks when implementing.
