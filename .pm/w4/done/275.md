# Distinguish failed ledger-switcher reads from empty results

**Severity:** minor. **Estimate:** 45–60 minutes, dashboard. **A2:** readers should know why their ledger list is unavailable and be able to recover without guessing that closing the picker retries it.

Production `https://beancount.io`,2026-10-20, QA-owned isolated headless Chromium155.0.8059.85, authenticated synthetic-ledger owner, English/light. Fresh1440×1000 and390×844 contexts. Local main `c5e4cd11a`, deployed `main-D9qWGMxD.js`; full deployed revision unverified. Route `/ledger/<qa-owner>/<synthetic-ledger>/journal`.

## Reproduction and controls

1. In a fresh authenticated browser context with no persisted Apollo cache, hold only the browser's ListLedgers read before transmission. Let the page hydrate, open Sidebar at390px, then open the ledger switcher. It correctly shows Loading ledgers... while the single read is pending.
2. Abort that held read. Both widths settle on No ledgers found, zero options, zero alerts/toasts and no Retry, Reload or Try Again action. This is a controlled network failure, not evidence of a natural production outage; no response body was fabricated. There is no uncaught page error.
3. Restore transport with the popup still open. After500ms there is no new read and the false-empty message remains.
4. Escape and reopen the picker. A genuine HTTP200 ListLedgers response includes the known synthetic ledger. Filtering its full identifier produces one option with the current-ledger marker at both widths. No other ledger is opened or included in this public report.
5. Passing desktop control: search a deliberately nonexistent `qa-20261020-no-such-ledger-control` string after the healthy read. No ledgers found and zero options are correct in this successful no-match case.

## Cause and bounded repair

`dashboard/src/common/components/ledger-layout/ledger-switcher.tsx:130` destructures only data/loading from useQuery, ignoring error and refetch. At:142 it turns missing data into an empty array. CommandEmpty at:264 distinguishes loading from everything else, so a failed uncached request becomes the same message as a successful empty result.

Handle the failed read locally with classified, localized accessible error guidance and a keyboard-usable Retry. Preserve the popup and search text; clear the failure after successful recovery. Keep successful zero/no-match distinct from failure, retain any usable cached options on refresh failure, and preserve loading feedback, current-ledger marking, selection, dismissal and footer actions. Reuse existing error formatting and UI primitives; no dependency, backend/schema or other API surface change is needed. A new Retry must preserve native Enter activation and focus through loading/recovery, avoiding the separate account-picker failures recorded in completed135 and open274.

Acceptance: exercise the actual picker/Apollo lifecycle with a held then failed read, accessible error/Retry, exactly one explicit successful retry, and another failed retry. Verify retained search/popup and appropriate focus, empty/no-match and cached-data controls at desktop/narrow widths; run dashboard format/lint/test/build when implementing.
