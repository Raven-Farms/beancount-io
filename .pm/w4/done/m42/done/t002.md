## Verification

Local production build of current main served against the repo's GraphQL fixture API (`dashboard/scripts/perf-fixture-api.mjs --synthetic-owner`, replaying anonymous public `open_ledger/example` reads). Headless Chromium 155 at 1440×1000 and 390×844. Every BulkEntries call was held inside the browser and then aborted or answered client-side. This is a local simulation, not the deployed site.

- **New Entry Note, both widths:**
  - Pressing Enter on Create Note Entry sends one request, and the fields are disabled while it is held.
  - Focus parks on the Note tab panel. Three Shift+Tab and three Tab presses alternate between the Note panel and Close, and no focus event lands outside the dialog.
  - After the abort, the draft text and the connection message are present, and focus is on Create Note Entry. Tab goes to Close, Shift+Tab returns, and Enter retries (a second request). The second failure returns focus to Create Note Entry again.
  - A deliberate pending click on Close keeps Close focused through the failure.
  - A client-side success closes the dialog without any focus handoff to the submit control.
  - Before the fix, the same build left focus on the dialog container through pending and after the failure, and the next Tab restarted at the Note tab.
- **Accounts Open Account and Budget Add Budget, both widths:** a failed keyboard submission now returns focus to Open Account or Add Budget. Before the fix, focus was left on the dialog in both. While Accounts' write is pending, the dialog holds focus, Radix's trap returns Shift+Tab to it, and Tab reaches Close.
- **Callers:** Note, Accounts and Budget were exercised natively. Transaction (Cmd+Enter from an amount), Balance and New Entry Open Account are covered by the jsdom regressions and the existing suites only.
- **Docs:** no package README or scoped guidance describes submission focus, so there was no drift to fix. No new skill, package or API surface.
- **Limits:**
  - Under these fixtures the Budget dialog's account-suggestion popover stays mounted against fixture misses, which pauses the dialog's focus trap even while idle. That is pre-existing and not pending-specific, so Budget pending containment was only isolated at 1440px.
  - After a client-side success, both the baseline and the fixed build end on BODY rather than the New Entry link. Successful return focus belongs to completed w4/238 and was not changed here.
  - An early harness misroute let one anonymous BulkEntries reach the public API through the recording fixture. It was refused `UNAUTHENTICATED`, and no write occurred. After that, recording was turned off and every mutation was held in the browser.
  - Deployed production has not been re-checked.
