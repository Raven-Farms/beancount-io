## Objective

Prevent accepted pending edits and dialog reopening from being reset by an older completion.

## Context

See [the milestone](../README.md) and [browser evidence](../FINDINGS.md). The owning implementation is dashboard/src/features/user-settings/pages/general/user-profile-section.tsx and its existing component tests.

## Steps

1. Implement a bounded pending input/dismissal lock or equivalent draft ownership. Reproduce Escape and Close→reopen before local success at both widths, then prove no newer draft is closed or lost. Preserve idle cancellation, own-session success, failure retention and useful focus.

## Acceptance criteria

- [x] The stated objective is verified against the actual transition, with evidence and limitations recorded.
- [x] Preserve the milestone's existing validation, composition, error/retry and draft-ownership controls.

## Out of scope

Backend/API changes, actual account modifications, a persistent draft store, unrelated settings redesign and new dependencies.

## Verification

**Fix (bounded pending lock, the milestone's accepted policy):**
- While a profile save is pending, the name and username inputs are `readOnly`, so they keep focus and caret and accept no edit the completion would discard.
- Each Dialog's `onOpenChange` ignores a close, so Escape, the Close button and an outside click wait. Cancel stays disabled.
- Every other way to close is held, and the dialogs' open state is local, so a completion can only close the session that sent it. No session token is needed.
- A disabled Save drops focus, so it parks on the dialog and returns to Save when the write fails. An input that started the save keeps focus throughout.

**Regression:**
- Escape and Close during a held save leave the same dialog and draft. Its success then closes it.
- A Save started from the keyboard parks focus on the dialog and hands it back to Save on failure.

**Native, 1440/390:**
- During a held save, Escape and Enter on Close leave `Change Name` open with its draft.
- The modeled success closes it, with focus on Edit.
- A reopened draft (`qa-m47-<w>-newer`) stays open with no further request.
- Idle Escape and Username Cancel still close, with focus on Edit.
- Labels are `updating...` (disabled) and Cancel (disabled) while pending.
