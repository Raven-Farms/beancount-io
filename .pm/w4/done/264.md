# Make Try Again recover failed ledger child pages

**Severity:** minor. **Estimate:** 45–60 minutes, dashboard. **A2:** a transient read failure should be recoverable using the visible Try Again button without restarting the page.

Production https://beancount.io, 2026-10-20, local main `c5e4cd11a`; fresh owner contexts at 1440×1000 and 390×844, QA-owned isolated headless Chromium 155.0.8059.85, English/light, designated disposable synthetic ledger. This is an explicit browser-local read abort, not a natural production outage. All mutations guarded; none attempted.

## Fresh reproduction and controls

1. Open `/ledger/<qa-owner>/<synthetic-ledger>/files/tree/main` and let the UI hydrate. Abort only GetCommitDetails, then activate **Version History** through the actual UI. Its client-side selection reaches a real commit URL and issues one aborted read.
2. The ledger section shows **Something went wrong / This section couldn't be displayed. The rest of the page should still work. / Try Again**. Restore the network, then activate Try Again twice.
3. Desktop and fresh narrow repeats leave the same panel visible. There is still only the original single GetCommitDetails request: neither retry starts another read. No file list or diff appears.
4. Working control: reload that same commit URL after removing the fault. Actual commit metadata, file list and diff render successfully. Direct document loads may receive server-rendered details, so they are not a reliable setup for the browser-local fault.
5. Independently test Files → main.bean with only GetLedgerFile aborted. Both desktop and narrow reach the same section fallback. A first retry can issue a real successful file read, yet the error panel stays latched and no editor appears. The fresh narrow response is HTTP200, no GraphQL errors, file present with original blob `f1a0b83c1aaf9608113c6bd3174bf7d2dab35407`; after 1.4 seconds the error is still visible and editor count is 0. Desktop's second retry adds no further read and also stays failed. Reloading the same file URL recovers its real editor.

The two observed request behaviors are intentionally distinguished: commit retries issue no request; file retries may obtain healthy data without clearing the section failure. Neither is a missing file/commit, permission denial or malformed URL. The error's collapsed details identify TypeError: Failed to fetch; no Copy action was used.

## Cause and bounded repair

`common/components/ledger-layout/index.tsx:149–151` wraps the child Outlet in the generic React ErrorBoundary, keyed only by ledger. `common/components/error-boundary.tsx:52–54` handles Try Again solely by clearing its React state; it does not invalidate or rerun the failed route loader, coordinate pending completion, or reset a later successful match.

The commit/file child loaders call Apollo at `features/git/commits/loaders/commit-loader.ts:14–27` and `features/ledger-editor/file-editor/loader.ts:16–27`, rethrowing unexpected read errors through rethrowEntityRouteError. Installed @tanstack/react-router 1.167.0 `src/Match.tsx:275–297` throws a retained error match on client render; router-core `src/router.ts:2686–2710` invalidation clears that match error, marks it pending and reruns loading. A React-only reset does not perform this route recovery. The generic section boundary catches the child failure before the outer route error experience can recover it.

Bind the ledger Outlet's retry to an actual router-aware recovery path: rerun the failed child loading and clear the section boundary coherently with that outcome, or give these loader failures an appropriate route boundary. The same URL should reach its current content after a successful retry, while repeated failure remains actionable and pending content is truthful. Keep ordinary React panel retries local; do not turn every component error into global navigation/reloads or recreate the router.

Preserve ledger-switch isolation, pending safeguards, not-found/forbidden/login classification, existing error details, focus and the separate stale-chunk Reload Page behavior. Existing LedgerRouteError at:38–41 and root ErrorPage at:34–38 already connect their own retry to router.invalidate; preserve those bindings. No API, dependency or cross-package change is needed.

Acceptance: use the actual router, ledger layout, Outlet and controllable Apollo transport. Navigate from Files into an uncached commit/file, reject its real loader read, restore the transport, activate Try Again and assert a genuine new attempt plus the current detail/editor. Cover repeated failures, pending success, a successful file response arriving during recovery, keyboard activation, both widths, route/ledger changes and ordinary React/chunk failures. A test that only clicks a standalone ErrorBoundary around a synchronously throwing component misses the retained loader state. Run dashboard checks when implementing.
