## Objective

Keep correctly shaped but unsupported persisted Journal subtype values from making the actual read fail.

## Context

Fresh1440/390 transactionSubtypes=[*] reaches the real API as BAD_USER_INPUT and persists after reload. Desktop documentSubtypes=[attached] and narrow customSubtypes=[empty string] fail independently. Valid cleared/linked/budget controls restore the real records. FINDINGS.md records exact responses and source identities. The current mocked-query regression incorrectly treats transaction !/* and empty Custom as valid inputs.

## Files

dashboard/src/features/journal/pages/journal-page.tsx; existing Journal filter values/helpers and saved-filter regressions.

## Acceptance criteria

- [x] Validate each subtype list against the actual supported UI/API kinds before render/query; discard unsupported values or migrate only a verified legacy spelling. Preserve valid empty arrays and non-string filtering.
- [x] Valid transaction cleared/pending/other, document discovered/linked and custom budget values retain intended UI/query behavior, with canonical spelling if normalization is used. Keep the strict backend contract unchanged.
- [x] Fresh desktop/narrow unsupported-string controls load usable Journal records without invalid subtype variables or manual storage cleanup; preserve unrelated preferences and per-ledger isolation.
- [x] Replace the accepted-invalid mocked-query expectations with meaningful supported-kind and rejection regressions that fail when the guard is removed. No dependency or cross-package import.

## Out of scope

Backend validation changes, BQL history policy, global preference resets, and unrelated Journal features. Standing tasks retain full adoption/simplification/gate/closeout work.

## Verification

- The supported subtype values are now derived once from the Journal filter buttons, `JOURNAL_SUBTYPES` in `features/journal/components/journal-filter-buttons.ts`: transaction cleared/pending/other, document discovered/linked, custom budget.
- `journal-page.tsx` decodes each saved subtype list against its own set, as it already did for directive types. Unsupported strings are dropped before render and query, and a list left with nothing supported means no subtype filter. Valid empty arrays, non-string filtering and per-ledger keys are unchanged.
- No legacy spelling was migrated: `git log -S` shows the button values have been cleared/pending/other since the dashboard's first commit, so `*` was never a UI value.
- Saved browser values are filtered on read, not rewritten. The backend contract from W23/006 is unchanged.
- Native check on a local production build (Chromium 155, replayed public reads, mutations blocked), at 1440×1000 and 390×844:
  - Each of QA's saved values `transactionSubtypes=["*"]`, `documentSubtypes=["attached"]` and `customSubtypes=[""]` now sends no subtype variable. The Journal renders its table with 60 rows, a reload still works, and an unrelated canary key survives.
  - The controls `["cleared"]`, `["linked"]` and `["budget"]` send exactly those values.
