## Cause and bounded repair

`dashboard/src/features/importer/components/steps/configure/transaction-config-form.tsx:157–170` correctly applies only suggestions with confidence>=0.5, then returns no application result. `account-mapping-table.tsx:99–108` treats the fulfilled callback as completion for every input row and interpolates transactionCount into aiSuccessDescription. That prop is validRows.length at transaction-config-form.tsx:275–283, rather than the number of targets actually filled. The message therefore reports the full batch for zero, partial and complete application.

Return an applied-suggestion count/result from the form callback and render a truthful completion summary from it. Zero applied must state zero/no suggestions applied, and one applied must use the existing singular form; do not call every input row successfully categorized. Preserve low-confidence refusal, the >=0.5 boundary, missing-target warnings, selection, useful request-error feedback and manual mapping. If introducing message keys, translate all15 supported locales; existing count pluralization can be reused. No backend/model threshold or API contract change is needed.

Low-confidence output is a supported contract state: current backend `features/llm/utils/categorize-transactions/prompts.ts:28–33` explicitly describes0.0–0.5 as low confidence, its schema accepts numeric confidence, and `service/llm-service.ts:368–375` forwards it without filtering. This source trace supports the response shape; the deployed backend revision and real model's output remain unverified.

Acceptance: deferred zero/partial/full responses produce respectively0/1/2 applied counts through the actual form/table integration; values and missing-target warnings agree with the summary. Keep request-failure feedback and exact0.5 application as controls. Coordinate with [323](./done/323.md) so suggestions skipped to preserve newer manual choices are also excluded from the applied count. Run dashboard format:check, lint, test and build when implementing. A mocked callback that always returns the input size would miss this defect; no billed AI call is needed.
