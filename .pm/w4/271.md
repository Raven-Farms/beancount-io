# Keep authored event types distinct and named in the type filter

**Severity:** minor. **Estimate:** 50–60 minutes, dashboard. **A2:** readers should be able to identify and filter every valid event type without a value being mistaken for the filter's global action or leaving a control unnamed.

Production `https://beancount.io`, 2026-10-20, English, QA-owned isolated headless Chromium155.0.8059.85, authenticated owner of the designated disposable synthetic ledger,1440×1000 and fresh390×844 document loads. Local main `c5e4cd11a`; deployed `main-D9qWGMxD.js`, full deployed revision unverified.

## Reproduction and controls

1. In the designated synthetic ledger, append two valid prefixed-description events to the snapshotted main.bean: `2026-10-20 event "all" "qa-20261020 event type all"` and `2026-10-20 event "qa-20261020-other" "qa-20261020 event type other"`. The live API returns exactly those two distinct types/descriptions, with zero ledger errors.
2. Open `/ledger/<qa-owner>/<synthetic-ledger>/events`. Both events appear in the named Events table.
3. Open the type filter. Its three native menu items are `All Types`, `All Types`, and `qa-20261020-other`. The actual type `all` has been relabelled as another global action.
4. Focus the second All Types item and press Enter. Both events remain visible, rather than just the event whose type is `all`. Repeat from a fresh390px load: the same duplicate labels and two-row result occur.
5. Select `qa-20261020-other`: the table correctly narrows to its single event at both widths. In a settled narrow control, the global All Types state shows both events; searching `event type all` narrows to the genuine all event; clearing search restores both. This is a usable text-search workaround, not a working type selection.

Both menus were captured and visually inspected. No page error or page overflow occurred. Immediate empty role-table snapshots during Radix's menu-closing aria-hidden transition were excluded; the separately settled controls contain the correct rows.

## Cause and bounded repair

`dashboard/src/features/ledger-data/events/index.tsx:46` initializes selectedEventType to the string `all`. Lines95–99 prepend that same string to the distinct event-type values. A real all type therefore creates duplicate values/React keys. The predicate at:104–105 treats either selection as no type constraint. Lines184–196 also label both values All Types, so the actual type cannot be selected or identified distinctly.

Give the no-type-constraint state a representation distinct from every authored event type, such as null, and render its global menu action separately from the actual type options. Keep the real `all` label literal and its filter equality exact. Use distinct stable keys for the global action and event options; replacing all with another magic user-string value only moves the collision. Give an empty authored type an explicit localized display label in both its menu item and selected trigger while preserving the underlying empty-string identity. Preserve event dates/descriptions, sorting, local search composition, results counts, localized global action, named table, topbar-filter reset and existing loading/empty/error guidance. Do not rename or reject valid ledger events. Add the display-label translation in all supported locales; no backend/API, dependency or cross-package change is needed.

Acceptance: through the real Events component/menu, load all plus an ordinary second type. There is one global All Types action and a distinct literal all option; native selection of all returns exactly its one event and count1/2, ordinary selection still returns its event, and the global action returns both. Repeat with an empty authored type and the ordinary control: both the empty-type menu item and selected trigger have meaningful accessible names, selection still matches the exact empty string, and ordinary/global controls remain correct. Search composes with the selected type, and supported shared-filter changes reset the selector to the global state. A test that mocks away the menu or uses only noncolliding, nonempty type names would miss these failures. Run dashboard format/lint/test/build.
