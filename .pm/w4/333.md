# Name the Settings language popup as well as its trigger

**Severity:** minor accessibility. **Estimate:** 20–35 minutes. **Owner:** dashboard. **A2:** the language chooser should identify its purpose when focus enters its popup, separately from the current-language value.

## Reproduction and passing controls

Production `https://beancount.io/settings/general`,2026-10-21 America/Los_Angeles, authenticated QA, isolated headless Chromium155.0.8059.85. English at390×844 and an independent fresh German1440×1000 context.

1. Open Appearance's **Language** / **Sprache** combobox with native Enter. Its existing localized name and English/Deutsch value are correct.
2. The popup is exposed as a non-modal **dialog with an empty accessible name**. Chromium Accessibility.getFullAXTree reports role:dialog, name:"", ignored:false at both widths/locales. The actual popup has neither aria-label nor aria-labelledby; no popup heading labels it.

Choosing Deutsch updates the document language and value, closes the popup and restores focus to the named trigger. A separate fresh390 Escape control confirms focus returns after the close lifecycle and the dialog disappears.

No preference or navigation failure is claimed. Native accessibility metadata is verified; physical screen-reader speech is unverified.

## Cause and bounded repair

`dashboard/src/features/user-settings/pages/general/appearance-section/language-selector.tsx:49` renders bare PopoverContent without a name. The trigger already uses the translated `userSettings.currentLanguage` label, but that names only the trigger; Radix's separate dialog node receives no naming association. Shared PopoverContent forwards supplied accessibility attributes.

Give this popup the existing localized language label directly or associate it with a stable, appropriate heading. Keep its current native-language value,15 buttons, aria-current marker, pending language state, scrolling, keyboard selection, Escape and focus return. The sole production caller is General Settings Appearance; the desktop avatar Language submenu is separate and the native bridge intentionally omits this selector. No shared popup-policy rewrite, new translations, dependency or API operation.

Acceptance: a rendered real-Radix LanguageSelector exposes both a named combobox and a named dialog in English/German, before and after language updates; the current-option marker and selection/Escape focus controls remain correct. Assert the actual popup role/name rather than an unrelated heading. Repeat desktop/narrow native accessibility checks and run dashboard gates when implementing.
