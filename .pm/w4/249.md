# Keep cleared filters cleared when another field changes during loading

**Severity:** minor. **Estimate:** 40–55 minutes, dashboard. **A2:** consecutive filter actions should compose; changing Time after Clear all must not restore the account the user just removed.

Production `https://beancount.io`, 2026-10-20, English/System theme, QA-owned headless isolated Chromium 155.0.8059.85. Fresh 1440×1000 and 390×844 pages; authenticated reader of public `open_ledger/example`. Local main `c5e4cd11a`; relevant deployed sources exactly match local. Read-only throughout. Only the cleared-scope report request is held in this browser, then continued unchanged or cancelled by the superseding navigation; no server result is substituted.

## Reproduce

1. Fresh-load `/ledger/open_ledger/example/income-statement?time=2016-08&account=Expenses%3AFood`. Wait for settled data and Export. At 390px open **Filters → Report filters**.
2. Hold GetLedgerIncomeStatement requests whose account/time are both empty, and click **Clear all**. The browser URL correctly becomes the bare Income Statement route, and the held request has `account:"", filter:"", time:""`.
3. While that read remains pending, the still-usable controls display their previous settled values: Account `Expenses:Food`, Time `2016-08`. Paste `2016-09` into Time and press Enter.
4. The next actual request is `account:"Expenses:Food", filter:"", time:"2016-09"`. The final URL is `/income-statement?account=Expenses%3AFood&time=2016-09` and Account remains Food. The cleared account was restored without an account-selection action.
5. Repeat from a fresh page at the other width. Same result. On narrow screens close the sheet and wait for Export: the wrong retained scope remains after the report settles.

Expected: only Time is `2016-09`, with Account still empty and no account URL parameter. Working control: without holding the read, Clear all and wait for its fields to settle empty before setting Time. The result is `/income-statement?time=2016-09`, with no account filter. The source/data is correct for the scope actually requested; this finding does not claim incorrect backend calculations or mislabeled exports.

## Cause and bounded repair

`dashboard/src/common/components/ledger-search-controls/index.tsx:97–104` spreads the full `searchParams` snapshot from the last settled route into every single-field update. `ledger-search-params-provider/ledger-search-params-provider.tsx:21,39–44` derives that snapshot from `useSearch`. During the pending clear it still describes the old matched scope, although the browser URL already reflects the clear.

The provider's functional router search callback at `:46–72` receives the pending/current search, but `applyLedgerFilterSearch` replaces all three keys with the stale complete `next` object. The installed router already builds from `pendingBuiltLocation`/`latestLocation` (`node_modules/@tanstack/router-core/src/router.ts:1814–1815`); the old complete replacement is supplied by this consumer.

Compose a field edit against the router's latest intended scope, changing only that field. Keep Clear all an explicit atomic three-key clear. A functional updater or patch contract can express this without a second persistent filter store, disabling the still-useful controls or adding delays. Preserve normalization/legacy decoding, replace-history behavior, safe explicit clears under retainSearchParams, unrelated route state, pending-data/export guards and atomic Journal/Account-journal offset reset.

Production setter callers are only these two handlers (single-field change and Clear all). LedgerSearchControls is shared by the inline desktop header and stacked narrow sheet across ledger pages. Income Statement was live-tested; Time/Account/expression combinations and other routes are regression scope derived from that shared handler.

Acceptance: mount the actual controls, provider and router with a held route loader; clear all, commit a Time change before the clear completes, then settle both reads. The final URL, request variables and rendered controls retain the clear and the new Time. Cover a second distinct-field change while another is pending, Clear all as the final action, settled sequential controls, Back/reload, and both paginated routes' offset behavior. A test that waits for every navigation before the next action misses this failure. Run dashboard checks when implementing; no API or dependency change is required.
