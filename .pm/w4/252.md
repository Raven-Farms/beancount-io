# Expose filtered account and ledger options as active descendants

**Severity:** minor (accessibility). **Estimate:** 40–60 minutes, dashboard dependency integration. **A2:** when typing leaves one account or ledger and ArrowDown targets it, assistive technology should be told which option Enter will open.

Production `https://beancount.io`, 2026-10-20, headless isolated Chromium 155.0.8059.85. Fresh authenticated reader contexts at 1440×1000 and 390×844, English/light, public `open_ledger/example`. Local main `c5e4cd11a`; the deployed caller, wrapper and installed library bytes all match local. Read-only; no result substitution.

## Fresh reproduction and controls

1. Open Journal with `time=2016-08` and wait for the interactive client. At 390px open the Sidebar.
2. Open **Search accounts...** and type `Assets:US:BofA:Checking` with ordinary sequential keyboard events.
3. After the one result settles (400ms), DOM focus remains on the named combobox. Its aria-controls names the actual Suggestions list. The visible option has a stable DOM id and aria-selected=true, but the input has **no aria-activedescendant**.
4. Press ArrowDown and wait another 250ms. The same single option remains selected; the active-descendant reference is still absent. Both fresh widths reproduce.
5. Chromium Accessibility.getFullAXTree independently exposes the combobox as focused, expanded and not ignored, with a controls relationship and no activedescendant relationship.
6. Working control: shorten the query to `Assets:US:BofA`, producing two options, then press ArrowDown to change the selected value. The input now references the same id as the selected Checking option at both widths.
7. A further fresh narrow control presses Enter directly after the missing-reference state. It correctly opens the Checking account, keeps August, and closes both search and Sidebar dialogs. This is a missing accessible active-option relationship, not failed account navigation.

An earlier private synthetic-ledger control also reproduces with Assets:Cash and a pasted/full-value input event. No-match input clears the active reference correctly and Enter does not navigate. Actual screen-reader speech was not exercised.

## Dependency cause and bounded repair

`dashboard/src/common/components/ledger-layout/go-to-account.tsx:71–75` uses the real CommandInput. The shared `common/components/ui/command.tsx` forwards to cmdk without custom selection logic. Package.json requests cmdk ^1.1.1 and yarn.lock resolves 1.1.1.

The installed library derives selectedItemId by scheduling a read of the DOM-selected row. A filter-driven selection can emit before that row has rendered. A real change through an arrow event produces the valid reference, matching the control above. Command.Input writes aria-activedescendant after spreading consumer props, so adding that prop to this caller is overwritten.

This matches the independently documented [upstream issue #413](https://github.com/dip/cmdk/issues/413), still open when checked, and its [v1.1.1 source](https://github.com/dip/cmdk/blob/v1.1.1/cmdk/src/index.tsx). The [official latest release](https://github.com/dip/cmdk/releases/tag/v1.1.1) is still the installed version as checked on 2026-10-20. No upstream message or issue was sent in this run.

Evaluate the maintained upstream remedy or a minimal dependency/integration repair that derives the active id from the same selected value and rendered-item registry. Keep a single selection state; avoid a second picker implementation, DOM-polling timer, hardcoded ids or changing the correct Enter target. Generate any lockfile changes with dashboard's package manager. Preserve the popup name, empty/error/retry states, filtering, pointer selection, focus return, mobile dismissal and retained report scope.

CommandInput's only production consumers are this account picker and LedgerSwitcher; both are now live-reproduced and need dependency-regression coverage. The similarly named ledger form Combobox uses its own repaired active-option integration and is a separate control.

Acceptance: with the real Command boundary, assert that initial/filter-driven selection, single-result ArrowDown, multi-result movement, clear/no-match and remounted results keep the input reference aligned with the visible selected option and Enter target. The fresh-browser sequential typing sequence matters; testing only a different-value arrow move misses the failure. Run dashboard gates when implementing.
