**Severity:** minor. **Estimate:** 40–55 minutes. **Owner:** dashboard. **A2:** receipt review should not accept corrections that disappear when the earlier transaction snapshot completes.

Changes to the still-mounted form cannot update an already submitted transaction.

Lock payload-changing review controls for that pending interval using a real disabled boundary that covers the date picker, currency/account pickers and their clear/rewrite actions as well as text/amount inputs. Keep submitted values/preview readable, existing loading feedback, duplicate-submit guard, exact decimal strings, civil dates, account/document defaults and settled success behavior. Release the lock when the request settles; do not apply late edits to an in-flight payload, resend automatically or introduce persistence/API/idempotency work. Only the independently exercised text/amount fields establish the live defect; the remaining payload controls are the bounded repair's compatibility scope.

Acceptance: pending Payee/Description/Amount changes cannot be accepted and then silently discarded at either width; date/currency/account controls obey the same pending boundary. Pre-submit edits still serialize exactly, one pending insert remains one insert, settled controls recover correctly and success reflects its submitted snapshot. Add meaningful review/workflow coverage for this transition and run dashboard gates when implementing.
