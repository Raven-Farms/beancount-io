# Keep Budget's first Add action from being lost

**Severity:** minor initial-action loss. **Estimate:** 35–45m, dashboard Budget header. **A2:** a newcomer should not need to activate an apparently ready Add Budget button twice to open its form.

Production `https://beancount.io`,2026-10-22, English/light, isolated headless Chromium155.0.8059.85, disposable-ledger owner. Four fresh natural-load cases:1440×1000 and390×844, each with native Enter and pointer activation. No script/request delays, response substitution, form submission or hosted write. Local main `d960308a0`; full deployed revision unverified, Budget page source matches exactly.

## Reproduction and controls

1. Fresh-load `/ledger/<qa-owner>/<synthetic-ledger>/budget`. As soon as the visible header **Add Budget** button is available, activate it once.
2. At both widths and with both input methods, the button is enabled and receives a trusted native click while its React onClick is not yet attached. No dialog opens.
3. Let the page attach its handler, then observe another600ms without activation. No delayed/replayed dialog appears.
4. Retry the same button: one Add Budget dialog opens. Do not submit. In both pointer cases, native Escape closes it and returns focus to the header Add Budget button.

Observed times in milliseconds after navigation, rounded; these are individual runs, not performance benchmarks:

A passive document capture listener records only the matching button's trusted click/disabled state and whether an existing React DOM onClick function is present. Frame polling only reads that readiness; it does not install/invoke a handler or change application state, focus, responses or disabled flags. Actual dialog presence establishes the outcome. All four first clicks have `handlerAttached=false`; retry clicks have it true. Screenshots show the settled Budget page without a dialog after the first pointer action.

## Cause and bounded repair

`dashboard/src/features/ledger-data/budget/index.tsx` renders the header Button enabled with an onClick that sets the local Add dialog state. The server-rendered button has no native pre-handler behavior or hydration-readiness guard. A click before React begins handling this control is therefore lost.

Use the existing TanStack useHydrated convention to make this header action honestly unavailable until its handler is ready, then preserve normal pointer/Enter/Space opening and dismissal focus. Keep the readable page, write-permission wrapper, existing draft/pending-save behavior, filters and ordinary Add Budget dialog unchanged. No global Button policy, timer-based workaround, dependency, backend/API or unrelated SSR redesign.

Acceptance: a real server-render → hydrate lifecycle exposes the header action unavailable before readiness and enabled afterward; first usable pointer/Enter/Space activation opens exactly one dialog. Repeat desktop/narrow browser checks and preserve ordinary Escape/Cancel focus. Include a meaningful owning-page hydration regression and run dashboard format:check, lint, test and build when implementing. The empty-state **Add Your First Budget** branch was not independently retained as a failing case; preserve it, rather than claiming every Budget button has this gap.
