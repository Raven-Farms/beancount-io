# File editor: pressing Enter twice after a posting indents the next transaction, which bean-check then rejects ("unexpected INDENT")

**Severity:** minor-to-moderate. Adding a transaction at the end of a file is the editor's main job. **Estimate:** 20 minutes. Owner: mobile. A3: the Beancount language mode has no `indent` function, so Enter copies the current line's indentation. After a posting, the blank line and the next line both start at 2 spaces, so a new date line is indented. Conversely, Enter after a header gives no indentation, so a first posting starts at column 0 unless the user taps ⇥.

Code-level at `main` `57826d105`. A reviewer ran the app's CodeMirror setup with `insertNewlineAndIndent` under Node on `2026-10-20 * "Coffee"\n  Expenses:Food  4.50 USD\n  Assets:Cash`, then Enter, Enter and a typed date. The result was `…Assets:Cash\n\n  2026-10-21 * "Lunch"`, which bean-check 3.2.3 rejects with `syntax error, unexpected INDENT`. Not typed natively (no software keyboard in this run).

## Root cause

`mobile/src/components/code-editor/code-editor.tsx:78-82` (the language mode without `indent`), with `:194` (`defaultKeymap`).

## Fix

Give the language an `indent(state, textAfter, cx)` that returns 0 after a blank line or before text starting with a date, `indentUnit` after a header or posting line, and null otherwise.

**Acceptance:** the sequence above yields an unindented date line, and Enter after a header indents the first posting. Unit tests use the app's editor setup.

## Dedupe

w3/267 and w5/477/629 are the CLI and feed validator. Searched `.pm/**` for insertNewlineAndIndent, "unexpected INDENT" and auto-indent.
