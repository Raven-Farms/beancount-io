# An app link to another ledger silently discards unsaved file-editor changes

**Severity:** moderate. Typed ledger text is lost with no "Unsaved changes" prompt. **Estimate:** 1 hour. Owner: mobile. A3: w3/100 kept the unsaved-change guard for same-document app links. A link that switches ledgers bypasses it, because the editor remounts before navigation.

Code-level at `main` `d7a950d7f`. Not reproduced natively: the simulator's `openurl` raises a system confirmation the automation can't tap.

## Scenario

1. Open `main.bean` in the file editor and type without saving. Save is enabled.
2. Open a `beancount:///ledger/<other-ledger>/journal` link, from Mail or a notification.

You land on the other ledger with no Discard/Cancel alert. Returning to the first ledger's `main.bean` shows the saved text; the draft is gone.

Control: a link into the *same* ledger shows the guard alert.

## Root cause

- `mobile/src/common/app-links/open-app-link.ts:58-68` sets `ledgerVar(target.ledgerFullName)` first, awaits the navigator, and only then calls `router.replace`.
- `mobile/src/screens/ledger-file-editor-screen/index.tsx:317-324` keys `LedgerFileEditorSession` on `` `${ledgerId}\0${path}` ``. The ledger change remounts it as a fresh, clean session and throws the draft away.
- When `router.replace` then fires `beforeRemove` (`:576-594`), `hasUnsavedChanges` is already false.

## Fix

Before `openAppLinkTarget` changes `ledgerVar`, give the active editor a chance to block. Route the replace through the existing `beforeRemove` guard first, or register an "unsaved edits" check, set by the editor and consulted by `openAppLinkTarget`, that shows the same Discard/Cancel alert and aborts the link on Cancel. Switch the ledger only after Discard.

**Acceptance:**
- With a dirty editor, a cross-ledger link shows the unsaved-changes alert.
- Cancel keeps the editor, draft and ledger.
- Discard switches the ledger and navigates.
- A clean editor follows the link directly.
