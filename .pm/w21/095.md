# In Persian, a signed amount inside a labelled line renders reversed: `1,234.50$- :مانده` instead of `مانده: -$1,234.50`

**Severity:** moderate for fa users. A negative running balance reads as a positive amount with a stray trailing minus. **Estimate:** 45 minutes. Owner: mobile. A3: this is the mobile counterpart of the dashboard fix w3/479. Mobile joins LTR amounts into RTL sentences with no direction isolation, so on iOS the first Persian letter makes the whole line RTL, and the `-`, `+` and `$` neutrals attach to the wrong side.

Code-level at `main` `89ddcfe9e`, plus the reviewer's CoreText layout check of `"مانده: -$1,234.50"`, which gives the reversed order. Not exercised natively: switching to فارسی forces an app restart into RTL. A standalone amount with no Persian text, as in the transaction list, renders correctly.

## Where

- `mobile/src/screens/account-detail-screen/components/account-entry-row.tsx:157` builds `${t("balance")}: ${balanceText}`.
- `:152-156` builds the "at cost" note with a `+`; `:165-168` builds "off by".
- `mobile/src/common/valuation.ts:400-403` builds Home's "Cost … · Unrealized ±…" line.
- The Persian strings are `translations/fa.ts:210, 237, 348, 349`.
- `grep` finds no U+200E, U+2066 or U+2068 anywhere in `mobile/src`.

## Fix

Add one helper that wraps an interpolated amount in a first-strong or LTR isolate (`\u2066…\u2069`), with an LRM fallback if iOS 16 rendering needs it. Use it wherever an amount goes into a translated sentence: the balance, at-cost and off-by lines and the valuation line. Mirror w3/479's choice.

**Acceptance:**
- With fa, a liabilities account's rows read `مانده: -$1,234.50` in visual order.
- The at-cost note reads `+$5.00`.
- A unit test asserts the helper's output for `-$1.00`.
- English output is unchanged visually.
