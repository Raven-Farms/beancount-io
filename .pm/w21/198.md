# A repeated query parameter crashes three link-reachable screens (`?path=a&path=b` → "path.split is not a function")

**Severity:** minor (a hard crash; release builds have no route ErrorBoundary). This is the same class as w4/034, which fixed only the missing-parameter case. **Estimate:** 20 minutes. Owner: mobile. A3: Expo Router's `parseQueryParams` returns `string[]` for a repeated key. These screens type their params as `string` and call string methods on them.

Code-level at `main` `2e12638c6`. The reviewer reproduced it at unit level through Expo's own URL parsing: each link yields an array, and each screen expression throws.

## Links → crash

- `beancount:///ledger-file-editor?path=a.bean&path=b.bean`: `path.split is not a function` at `mobile/src/screens/ledger-file-editor-screen/index.tsx:646`. The `if (!path)` guard at `:309` lets the array through.
- `beancount:///add-budget?interval=a&interval=b`: `toUpperCase is not a function` at `add-budget-screen.tsx:202`. A repeated `account` or `currency` throws at `:223` and `:225` (`.trim`).
- `beancount:///open-account?prefill=Assets:A&prefill=Assets:B`: `.trim is not a function` via `open-account-screen.tsx:226` → `account-name.ts:50`.

## Fix

Read every route param through `firstRouteParam`, as merchant detail and transaction detail already do, and extend `src/__tests__/route-param-guards.test.ts` to cover array params for every route. Consider a route-level ErrorBoundary.

**Acceptance:** each link opens using the first value, or a graceful empty state, with no crash. The guard test fails if a route reads a param as a bare string.
