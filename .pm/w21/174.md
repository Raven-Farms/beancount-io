# A parent account's own postings never appear in the Accounts tree, so its children don't add up to it

**Severity:** moderate. Posting to `Expenses:Food` alongside `Expenses:Food:Groceries`, or to `Assets:Bank` alongside its subaccounts, is common. The parent then shows a total its visible children don't explain, which contradicts the table's own claim that children "always sum back to" the parent. **Estimate:** 30 minutes. Owner: mobile; the dashboard hierarchy has the same gap. A3: the tree reads only `balance_children` (the rolled-up total). The trial-balance query already fetches each node's own `balance`, and nothing renders it.

Reproduced natively on the iPhone 17e simulator (iOS 27.0) at `main` `dbfdff600`, on the disposable QA ledger, which I restored byte-for-byte to `f1a0b83c`. The fixture `; qa-20261020-tree` opened `Assets:Bank USD` and added `2026-09-02` "QA OWN": Assets:Bank +200.00 / Assets:Bank:Checking −200.00. Accounts → Assets → Bank reads **"$17,202.01"**, with children **Savings $10,500.00** and **Checking $6,502.01** (together $17,002.01). The $200 held on Bank itself has no row and no note.

## Where

- `mobile/src/components/account-list/select-account-list.ts:130` (reads `balance_children` only)
- `mobile/src/components/account-table/account-table.tsx:455` (the "sum back" claim)
- The dashboard has the same at `dashboard/src/features/reports/balance-sheet/hierarchy-list.tsx:209`.

## Fix

When a node has children and a non-zero own `balance`, add a synthetic child row ("Bank (own)") with that balance, tappable to the parent's own journal, or a note under the parent. Keep folding rules unchanged; a parent with own postings is already never folded away.

**Acceptance:** with the fixture, Bank expands to Savings $10,500.00, Checking $6,502.01 and "Bank (own)" $200.00. Add a selector unit test.
