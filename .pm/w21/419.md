# Two identical transactions share one entry_hash, so account detail's (and Transactions' and merchant detail's) "Load more" loops back to the first page forever

**Severity:** major. History past the first page or two becomes unreachable whenever one identical pair exists. **Estimate:** 30 minutes. Owner: mobile (optionally ledger). A3: the ledger's `hashEntry` leaves out source position, so two identical entries (two $4.50 coffees, same payee, same day) get the same `entry_hash`. Journal rows are keyed and de-duplicated by that hash. When the twin arrives on a later page it is dropped (`added < incoming`), and the screen reads that as "the list moved" (the w21/035 and 072 logic) and refetches from offset 0. With no cache type policies, that cuts the list back to 20 rows, and the cycle repeats. The code is `account-detail-screen/selectors/select-account-journal.ts:159-199` and `account-detail-screen.tsx:337-365`; Transactions' `utils/merge-journal-page.ts:10-26` and merchant detail (`:377-411`) do the same. Under `tsx`, the real `hashEntry` gives identical hashes for the same entry at lines 10 and 14, and paging loops (`offset=20 incoming=20 added=19 listMoved=true`) on every cycle. A same-page twin also produces duplicate React keys.

**Verified against production (2026-10-21, `main` `3e4352ec8`):** two identical `2026-08-29 * "QA TWIN" "Coffee"` entries on the disposable QA ledger came back from `getLedgerJournal` as `total 2` with 2 rows sharing **one distinct `entry_hash`**. The ledger was restored to `f1a0b83c`. The paging loop itself wasn't driven natively, because there is no scroll tool.

## Fix

Count a repeated hash as an overlap only when the item really repeats an earlier position (compare date, change and balance, or count occurrences), and key React rows by hash plus occurrence index, in all three merges. Optionally have the ledger add the source position to the key.

**Acceptance:** with one identical pair plus 22 later entries on an account, scrolling reaches the oldest entry, and no page is refetched from 0.
