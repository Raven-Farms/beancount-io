# Beancount's own default options raise red ledger errors: "account_previous_balances" and "account_rounding" give E7002 / E7007

**Severity:** moderate. A ledger copied from Beancount's docs (or the bean-example) gets a permanent bell badge and red error rows for options bean-check accepts. **Estimate:** 30 minutes. Owner: ledger. A3: the engine rejects option values Beancount accepts, and the ledger service passes those errors through unreconciled, though it already reconciles E7006 document-root errors.

Reproduced against production on 2026-10-21 through GraphQL `getLedgerErrors`, on the disposable QA ledger with `option "account_previous_balances" "Opening-Balances"` (Beancount's own default) and `option "account_rounding" "Rounding"` appended (restored byte-for-byte to `f1a0b83c`):
```
[E7002] Invalid leaf account name: 'Opening-Balances'
[E7002] Invalid leaf account name: 'Rounding'
[E7007] Option 'account_rounding' is accepted for compatibility but has no effect: …
```
A reviewer ran Beancount 3.2.3's `loader.load_file` on the same file, which reports no error for either option.

## Root cause

`backend-cluster/ledger/src/foundation/rustledger/engine.ts:624-626` (the post-processing chain), with `document-validation.ts` (the E7006 precedent).

## Fix

In the ledger service, drop E7002 when the value is a valid leaf that Beancount joins under the Equity root, and downgrade E7007 to a warning (with w21/188's severity, show it as a notice, not an error). This covers REST, GraphQL and MCP alike.

**Acceptance:** the two options produce no errors, with at most one warning for `account_rounding`. Unit tests are added.

## Dedupe

w21/188 covers warnings shown as errors, but E7007 arrives with severity `error`. w3/288 cites the default value. Searched `.pm/**` for E7002, E7007, account_previous_balances and account_rounding.
