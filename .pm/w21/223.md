# Opening a dashboard file link in the app drops "?lineNumber=", so the editor opens at the top instead of the error line

**Severity:** minor. **Estimate:** 10 minutes. Owner: mobile. A3: the dashboard's ledger-errors table links to `…/files/blob/<branch>/<path>?lineNumber=N` (w3/166). The app-link resolver maps that URL to the mobile editor with the path only, although the editor already accepts `initialLine`.

Code-level at `main` `9e6f6c9ba`. A reviewer ran the resolver under Node: `https://beancount.io/ledger/alice/home/files/blob/main/main.bean?lineNumber=42` → `{ pathname: "/ledger-file-editor", params: { path: "main.bean" } }`. Not exercised natively, because `simctl openurl` raises an alert the harness can't accept.

## Root cause

`mobile/src/common/app-links/resolve-app-link.ts:131-147` (the `files/blob` case) never reads `parsed.searchParams.get("lineNumber")`.

## Fix

When `lineNumber` is a positive integer, pass it as `initialLine`. Add a resolver test, including a non-numeric value being ignored.

**Acceptance:** the URL above resolves to `params: { path: "main.bean", initialLine: "42" }`, and the editor opens scrolled to line 42.

w21/131, 137 and 199 and w2/049 cover other app-link shapes; none mentions the line. Searched `.pm/**` for lineNumber, resolveAppLink and resolve-app-link.
