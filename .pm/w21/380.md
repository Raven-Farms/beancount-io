# Deleting a file that changed elsewhere toasts raw "sha does not match [given…, expected…]" and never refreshes, so every retry fails

**Severity:** minor. **Estimate:** 15 minutes. Owner: mobile. A3: the delete catch in `ledger-file-browser-screen/index.tsx:545-551` only toasts. `common/ledger-refusal.ts` passes the server text through for `BAD_USER_INPUT`, so with the live shape recorded in w21/079 the toast reads exactly `sha does not match [given: 8f9f…, expected: eeb8…]`. Nothing refetches, so each retry sends the same stale `entry.sha` until a pull to refresh or a return from the background. Once w23/032 changes the server status to `CONFLICT`, the toast becomes a generic "Failed to delete file", with the same stale retry.

Code-level at `main` `4e51c752c`. Not run natively; it needs a second writer to change the file while Files stays in the foreground.

## Fix

In the catch, on `isConflictError(msg)` or `CONFLICT`, run `invalidateLedgerData(client, "file")` and show a translated "This file changed elsewhere. The list was refreshed; try again."

**Acceptance:** after an external edit, Delete shows the translated message, and the next Delete succeeds.

## Dedupe

w21/079 (in-app writes, fixed), w21/195 and w23/032 (server status) differ. Searched `.pm/**` for "sha does not match", deleteLedgerFile and ledgerDeleteFileFailed.
