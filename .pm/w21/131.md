# An app link with a differently-cased owner opens your own ledger read-only and drops the "Current" marker

**Severity:** moderate. Opening `…/ledger/Alice.Smith/books` for a ledger owned by `alice.smith` hides every write action: Home + (New Transaction and Scan receipt), quick add, Open Account, Files create and delete, and the file editor, which shows a read-only banner. Browse ledgers then shows no "· Current". **Estimate:** 20 minutes. Owner: mobile. A3: the app link's owner and name are stored in `ledgerVar` exactly as typed. The backend resolves the owner case-insensitively and returns the stored spelling. `useLedgerAccess` requires `getLedger.id === ledgerId`, so `canWrite` becomes false.

Verified through the API at `main` `3c20a88e0` (read-only): `getLedger(ledgerId: "PUNCSKY/mcp-agent-eval")` returns `id: "puncsky/mcp-agent-eval"`. The ledger *name* must be lowercase, because the slug validator rejects uppercase; the owner part is accepted in any case. Not exercised natively: `simctl openurl` raises a system confirmation the automation can't tap.

## Where

- `mobile/src/common/app-links/resolve-app-link.ts:82-88`

- `mobile/src/common/hooks/use-ledger-access.ts:19`
- `mobile/src/screens/ledger-selection/index.tsx:282,317` (the `item.id === selected` comparison)

## Fix

After the readability check in `openAppLinkTarget`, store the canonical `getLedger.id` the server returned in `ledgerVar`, not the typed spelling. Optionally, compare ids case-insensitively on the owner segment in `useLedgerAccess`.

**Acceptance:**
- Opening the QA ledger through an upper-cased owner link keeps Home + and Files write actions, and Browse ledgers marks it "Current".
- `ledgerVar` holds `puncsky/mcp-agent-eval`.
- Add a unit test.
