# A text file over 10 MiB opens as an empty, editable document, and saving replaces the whole file with what was typed

**Severity:** major (data loss). Opening a large CSV or `.bean` import on mobile shows a blank editor with no warning. Typing and saving overwrites the entire file. **Estimate:** 30 minutes. Owner: mobile, plus a ledger-service check. A3: Gitea returns `content: null` for blobs over its inline limit (10 MiB by default). The ledger service's own `gitea-file-content.ts` says such a response "is an existing large file, never an empty file", but the plain `GET /files` route and GraphQL pass the null through. The editor decodes `content ?? ""` as an empty document with a valid sha and stays writable. `getLedgerFile` already returns `size`, which the editor ignores.

Code-level at `main` `36d9fbf59`. Not exercised: a file over 10 MiB can only be added by git push (the API caps writes at 1 MiB), which the shared QA ledger shouldn't take.

## Scenario

Files → `bank-export.csv` (11 MB, pushed via git) → a blank editor with no read-only banner. Type "x" and tap Save: success. Reopen: the file contains only "x".

## Where

- `mobile/src/screens/ledger-file-editor-screen/index.tsx:380-395` (and the reload path `:460`): `content ?? ""`, the sha accepted, writable
- `mobile/src/common/ledger-file-content.ts:3-9`
- `backend-cluster/ledger/src/api/files.ts:36, 96`
- `backend-cluster/backend-v2/src/features/ledger/utils/mappers.ts:29`
- `backend-cluster/ledger/src/features/gitea/utils/gitea-file-content.ts:7, 172-173` (the documented behaviour)

## Fix

- In the editor, treat `size > 0` with null or empty content as "too large to open on mobile": read-only, with a translated notice and no Save.
- In the ledger service, have the file read either fetch large blobs through the raw endpoint or flag them, consistently on REST, GraphQL and MCP, so no client can mistake a large file for an empty one.

**Acceptance:**
- An 11 MB file opens with a "too large" notice and can't be saved over.
- Empty files still open as empty and editable.
- Add a unit test on the init path with `{content: null, size: 11000000}`.
