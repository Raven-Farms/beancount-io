# New Transaction: deleting the last posting overwrites the amount typed in the posting above it, with no warning

**Severity:** minor-to-moderate (a typed number is silently replaced, and Done stays enabled). **Estimate:** 15 minutes. Owner: mobile. A3: `removePosting` (`mobile/src/screens/multi-postings-transaction/postings-utils.ts:374-388`) forces the new last row to `isAuto: true` when the deleted row was last, and `applyAutoFill` then replaces that row's typed `amountInput`/`amount`.

Code-level at `main` `73a36ae00`. In the reviewer's tsx run (Card −30, Groceries typed `10`, Household auto 20.00, Household deleted), Groceries becomes `30.00` (auto), `validatePostings` returns null, and `buildEntryInput` writes `Expenses:Groceries 30.00 USD`. The same happens when the user had turned Auto off and typed on the last row. Not exercised on the device: the delete is a swipe, which the simulator driver can't perform.

Steps: enter −30 on the first row, tap Add posting, type 10 on row 2, then swipe-delete row 3. Row 2 now reads 30.00.

## Fix

When the last row is removed, keep the new last row's typed amount and `isAuto` as they are, and let the form show the remainder as unbalanced. Switch that row to auto only if it was empty or zero.

**Acceptance:** after the steps, row 2 still reads 10 and the form reports the imbalance. Unit cases are added.

## Dedupe

w3/156 (Auto toggle availability), w21/110 and w21/029 differ. Searched `.pm/**` for removePosting, "remove posting", swipe together with delete, and auto toggle.
