# Create Ledger still says "A ledger with this name already exists" for a renamed ledger's former name, which the server now reports as reserved (w23/061)

**Severity:** low. **Estimate:** 15 minutes. Owner: mobile. A3 (code-level at `main` `7bdc974f6`): since `6dbbf15e0` (w23/061), the server returns `CONFLICT` with `reasonCode: LEDGER_NAME_RESERVED` and "'x' is the former name of owner/y … Choose a different name." (`ledger/src/api/ledgers.ts:135, 188, 412`; `backend-v2/src/foundation/fava/error-to-domain.ts:120-126`). Mobile's `create-ledger-screen/ledger-name.ts:91-92` treats any `field === "name"` conflict as a clash, and the message fallback at `:57-59` matches "choose a different name". So `create-ledger-screen.tsx:492-494` shows `createLedgerNameConflict` ("A ledger with this name already exists."), the false claim the server fix removed.

Scenario: rename `books-a` to `books-b`, then go to Create Ledger ▸ name `books-a` ▸ Create. No `books-a` appears in the list, yet the app says it exists. Not run natively (no renames or ledger creation in this QA run).

## Fix

Branch on `reasonCode === "LEDGER_NAME_RESERVED"` and show a translated "This name is reserved: it redirects to owner/books-b".

**Acceptance:** that case shows the reserved-name message. A unit case covers the reason code.

w23/061 changed only the server; w23/065 is its pin half. See w21/437 and w21/547. Searched `.pm/**` for LEDGER_NAME_RESERVED and createLedgerNameConflict.
