# Test connection says "Connected" without checking that the server's schema is new enough, though the README calls it a compatibility check

**Severity:** low. **Estimate:** 30 minutes. Owner: mobile. A3 (code-level at `main` `851db958a`): `common/server-url.ts:45-103` (called from `welcome/server-settings-screen.tsx:198`) checks only that `{ health }` returns "OK" and that OAuth discovery succeeds. The backend exposes no version. A self-hosted stack older than 2026-10-20 passes as "Connected", then fails as in w21/591 and w21/592. `mobile/README.md:134` calls the test "an advisory compatibility check".

## Fix

Add a cheap introspection probe (for example `__type(name: "BeancountError") { fields { name } }` and `__type(name: "LedgerSetupInput") { name }`), and report "This server is older than the app; some features won't work" when required types or fields are missing. Optionally, add a server version field.

**Acceptance:** against the old schema, the test reports the incompatibility, and a current server still reads "Connected". A unit case is added.

w21/213-216 and w21/484 cover reachability, timeouts, URLs and VoiceOver, not version compatibility. Searched `.pm/**` for "compatibility check" and "server version".
