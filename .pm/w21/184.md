# On any day after the last online session, Home's Spending card shows "Failed to load" offline, because its cache key changes daily

**Severity:** minor-to-moderate. Opening the app offline the next day shows cached net worth and recent rows, but the Spending card shows "Failed to load / Try again". **Estimate:** 20 minutes. Owner: mobile. A3: the card's query `time` is `spendingWindow()` = first of last month through *today* (for example `2026-09-01 - 2026-10-21`). The variables change every day, so yesterday's persisted result is never read. This came in with the w21/011 fix (2026-10-20). Home's budget panel has the same day-stamped key (`timeSpanToFilter("this-year")` ends today), a second cause of w21/080's "$0.00 / $500" rows that 080's fix wouldn't solve.

Code-level at `main` `b8c58c186`.

## Where

- `mobile/src/screens/home-screen/selectors/select-spending-compare.ts:45-52` (`spendingWindow`)
- `mobile/src/screens/home-screen/components/spending-card.tsx:100`
- `mobile/src/screens/home-screen/hooks/use-budget-panel.ts:90, 106-110` and `budget-screen/selectors/budget-labels.ts:104-108`

## Fix

Query with a key that is stable for the month (last month's start through this month's end, or no end bound) and cut to today on the client, or fall back to the most recent cached window when offline.

**Acceptance:** with the app opened online on day N, then offline on day N+1, the Spending card renders the cached months. The budget panel likewise shows cached actuals.
