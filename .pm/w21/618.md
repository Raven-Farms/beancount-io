# With a balance assertion already failing, any amount edit that changes its "got" figure is refused as "would introduce 1 new bean-check error" (w21/367 covered only entry-tagged messages)

**Severity:** minor (entries can't be corrected while an assertion is off). **Estimate:** 20 minutes. Owner: ledger. A3: `backend-cluster/ledger/src/features/ledger/utils/new-ledger-errors.ts:23-41` matches errors by full message and file. Balance messages carry the computed "got X", so any change to an affected amount counts as a new error. Mobile never sends `allowInvalid`.

Production (2026-10-22, disposable ledger, restored byte-for-byte): with `2026-08-29 balance Assets:Cash 40.00 USD` already failing ("expected 40.00, got 49.75"), `updateLedgerEntrySourceSlice` changing FARMERS MARKET from −23.50 to −27.00 is refused with `VALIDATION_FAILED`: "this edit would introduce 1 new bean-check error: Balance failed for Assets:Cash: expected 40.00 USD, got 46.25 USD (main.bean:87)". The error count is unchanged (it's the same assertion), but only the one amount that fixes it exactly can be saved.

## Fix

Compare balance failures by assertion identity (file, line, account and expected amount), ignoring the computed "got" figure, as w21/367 did for entry-tagged messages.

**Acceptance:** that edit saves, and an edit that breaks a *passing* assertion is still refused. Tests cover both.
