# Being signed out by an auth error (revoked token, UNAUTHENTICATED) leaves the previous account's Create Ledger draft, Recent accounts and merchant overrides on the device

**Severity:** moderate. **Estimate:** 15–20 minutes. Owner: mobile. A3: w21/053 made manual Log out clear the Create Ledger draft, and Log out also clears per-ledger Recent accounts (`accountUsageVar`), recurring-merchant overrides and the selected ledger. The auth-error sign-out path skips all of that. Suppose user A's session is revoked mid-use, or their account is disabled, and the app routes to Welcome. If user B then signs in on the same device within 24 hours and opens Create Ledger, **A's draft resumes**, including A's creation `requestId`. A's usage and override maps also stay on disk.

Environment: `main` at `e80968380`. Code-level: forcing a server-side revocation mid-session can't be driven on demand from the simulator.

## Root cause

`mobile/src/common/apollo/error-handling.ts:12-34`: `teardownAndRoute`, which `createAuthErrorLink` calls at `auth-error-link.ts:23` and `:50`, runs only `teardownSessionCaches` (the session plus the persisted and in-memory Apollo cache).

The full cleanup is `clearServerScopedState` in `mobile/src/common/server-url-actions.ts:29-59`. `screens/setting/logout.ts` uses it, but this path doesn't. It additionally does:
- `ledgerVar(null)` with `flushLedger()`
- `accountUsageVar({})`
- `merchantRecurringOverridesVar({})`
- `clearCreateLedgerDraft()`
- `clearPendingAuthorization()`

## Fix

Have `teardownAndRoute` call `clearServerScopedState()`, keeping its in-flight de-duplication and the route to `/auth/welcome`, so every sign-out path clears the same state.

**Acceptance:** a unit test where the auth-error link's teardown leaves no Create Ledger draft, account usage, merchant overrides or selected ledger in storage.
