# Account detail values a mixed cash-and-holdings account at the price on its last posting date, while the Accounts row and Home use the latest price

**Severity:** moderate. Tapping a brokerage row showing "$1,250.00" opens a header reading "$1,000.00 · At market value", with no stale-price warning. **Estimate:** 30 minutes. Owner: mobile. A3: the header is the last point of the account's balance series, and the ledger values each point at its own date (the account's last posting). `selectAccountBalanceSeries` swaps in the current trial-balance figure only for single-commodity ("units") displays; its own comment admits the latest point "for a holding left alone for months is an old one". A cash-plus-fund account, or a parent over several funds, keeps the stale value, and the staleness check runs against that same old date.

Reproduced natively on the iPhone 17e simulator (iOS 27.0) at `main` `f518cd365`, on the disposable QA ledger, which I restored byte-for-byte to `f1a0b83c`. The fixture `; qa-20261020-brk`:
- opened `Assets:Qa20261020Brk` and `commodity QAETF`
- funded it with 1000 USD from Checking on 2026-09-02
- bought `5 QAETF {150.00 USD}` the same day
- added `price QAETF 150.00 USD` (09-02) and **`200.00 USD` (10-20)**

Results:
- Accounts → Assets: **"Qa20261020Brk · $1,250.00"**, with Assets "At market value".
- Tap → account detail header: **"Balance · At market value · $1,000.00"**.

The reviewer also saw it live on `open_ledger/example`: `Assets:US:Vanguard` is $89,651.30 in the trial balance but $89,045.42 on the series' last point.

## Fix

For money displays too, use the trial-balance `current` value for the header, or end the series with a point valued today. Run the staleness check against today.

**Acceptance:** with the fixture, the header reads $1,250.00, matching the Accounts row and Home. Add a selector test.
