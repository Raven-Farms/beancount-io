# After the selected ledger is deleted, the drawer still pins it at the top as the current ledger (w21/054 follow-up)

**Severity:** minor. **Estimate:** 20–30 minutes. Owner: mobile. A3: w21/054's resolution says the "no longer available" path "refreshes the directory so the drawer prunes it". The refresh does drop the deleted ledger from the owner sections. But `ledgerVar` still holds its id, and the drawer synthesizes a placeholder row from that `owner/name` id and shows it in a separate **current-ledger** section at the top, highlighted. Reproduction: select `qa/my-book2`, delete it on the web, then open the app. Home shows "This ledger is no longer available", which is correct, but ☰ still lists **my-book2** at the top as current. Tapping it lands back on the gone screen.

Environment: `main` at `032af595c`. Code-level. Not reproduced natively, because it needs deleting a selected ledger, and the QA write authorization covers only the disposable ledger's contents, not ledger deletion. w21/054's native recheck also noted "Selecting a missing ledger wasn't re-exercised".

## Root cause

- `mobile/src/components/ledger-drawer/account-ledger-drawer.tsx:14-24`: when the selected id isn't in the directory, it runs `GetLedger`. That fails with NOT_FOUND, so it calls `getDrawerLedgers([], ledgerId, undefined)`.
- `drawer-ledgers.ts:37-47` then invents a `{ id, name, fullName }` row from the id.
- `getDrawerSections` (`:74-88`) renders any selected ledger missing from the list as the `current-ledger` section.
- `LedgerGuard`'s gone path (`ledger-guard.tsx:129-133`) refreshes the directory but leaves `ledgerVar` alone.

## Fix

Don't synthesize the current-ledger row when `GetLedger` returned NOT_FOUND (`isLedgerGone`). Or have the gone path clear `ledgerVar` (and `flushLedger`) once the user leaves via Browse ledgers. The synthesized row should stay for the legitimate case: a canonical link whose metadata hasn't arrived yet.

**Acceptance:** a unit test where a NOT_FOUND selected ledger yields no `current-ledger` section, and a pending (still loading) link still shows the placeholder row.
