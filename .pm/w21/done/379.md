# Commit detail renders every diff line at once (no virtualization or size cap), so opening a large commit stalls the screen

**Severity:** moderate. **Estimate:** 45 minutes. Owner: mobile. A3: `commit-detail-screen.tsx:338-353` draws the diff with a `FlatList` set to `scrollEnabled={false}`, inside a horizontal ScrollView inside a vertical ScrollView. `VirtualizedList._onLayout` takes its own content-sized height as the viewport, so it renders batches until every row exists. RN also skips its nested-list warning when scrolling is disabled. The parse at `:219` is not memoized. Under `tsx`, a commit adding 20,000 lines gives `parseDiff` 20,006 rows, all rendered, and the horizontal scroller is as wide as the longest line. The dashboard's diff viewer switches to virtual scrolling above 500 lines (`dashboard/src/common/components/diff-viewer/diff-viewer.tsx:15`). Mobile has no limit.

Code-level at `main` `4e51c752c`. Not run natively; it needs a multi-thousand-line commit.

## Fix

Make the diff the screen's single vertical `FlatList`, with the summary and the file list as `ListHeaderComponent`. Memoize the parse. Above a threshold, collapse each file to "Diff too large (N lines)" with a show-anyway button.

**Acceptance:** opening a 20,000-line commit stays responsive and renders only visible rows.

## Dedupe

w0/032, w2/072, w4/023, w21/272 and w21/297 cover the same screen but not size. Searched `.pm/**` for diff with large, freeze, perf and virtualiz, plus diffLines and FlatList.

Fixed with a lighter design than the note's. Commit detail now draws the first 500 diff lines (`DIFF_PAGE_LINES`) and shows a "Show N more lines" button (`commitDetailShowMore`, 13 locales) that reveals 500 more each press, so opening a 20,000-line commit builds 500 rows, not 20,000; a small commit looks as before and has no button. The diff is parsed once per diff with `useMemo` (it was re-parsed on every render), and parsing 20,000 lines is checked to stay well under two seconds. Tests (`large-diff.test.ts`: the page size and chunk arithmetic, the parse time, and the screen's slicing, memoized parse and button; the wiring case fails with the screen reverted). Deviation: not the single vertical `FlatList` with the summary as its header that the note proposed, and not a per-file "Diff too large" collapse. The diff keeps its horizontal scroller inside the screen's scroll, so rows are not virtualized; the bound on rows drawn is what keeps the screen responsive, and revealing everything of a huge commit still costs what it did before, one page at a time. Not run natively with a 20,000-line commit.
