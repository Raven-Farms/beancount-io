# A subfolder file named like a root file shows the root file's error in its editor banner

**Severity:** minor. It's left over from w21/089. **Estimate:** 10 minutes. Owner: mobile. A3: `messageNamesFile` treats a bare filename in a message as naming every file with that basename. w21/089 kept this assuming a bare name "is all the engine says", but the engine always writes the full repo path, so a bare name can only mean a root-level file.

Code-level at `main` `ba784a628`. The engine returns `"parse errors in main.bean"` for the root and `"parse errors in sub/main.bean"` for the include. With both, `filterFileErrors(errs, "sub/main.bean")` returns both, and the banner says "2 errors". Root `main.bean` correctly gets only its own.

## Root cause

`mobile/src/screens/ledger-file-editor-screen/utils.ts:15-26` (`messageNamesFile`).

## Fix

Treat a bare filename in a message as a root-level path, comparing only with `sameLedgerFile(named, filePath)`.

**Acceptance:** `sub/main.bean` shows only its own error. A unit case is added.
