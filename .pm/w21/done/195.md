# Leaving the file editor during "Saving…" skips its whole-file refresh, so other tabs stay stale and the next file delete is refused

**Severity:** minor-to-moderate. The save commits, but Transactions, Accounts and Home keep the old data. The Files row keeps the old sha, so deleting that file fails with "sha does not match". A "This save left errors" alert can also pop up over Files. **Estimate:** 20 minutes. Owner: mobile. A3: the `"file"` invalidation runs only in the editor's unmount cleanup, gated on `savedThisSessionRef`, which is set *after* the mutation resolves. Leaving mid-save runs the cleanup first with `false`, and nothing sweeps afterwards.

Code-level at `main` `7fa4c4682`.

## Where

`mobile/src/screens/ledger-file-editor-screen/index.tsx:445-452` (the unmount sweep), `:534` (the flag set late), `:576-594` (the guard) and `:430-440, 541-554` (the post-save alerts).

## Fix

Run `invalidateLedgerData(client, "file")` in the save's success path, not only on unmount, and suppress the post-save alerts once the screen has gone.

**Acceptance:** with a 2 s delay, Save → Back → Discard: Files and the other tabs show the saved state, and deleting the file succeeds.

## Dedupe

w21/079 is the stale-sha delete from a different trigger. Searched `.pm/**` for savedThisSession, "file scope", reportNewErrors and "left errors".

**Resolution (2026-10-21):** the file editor records when it unmounts (`unmountedRef`). A save that lands after that runs `invalidateLedgerData(client, "file")` itself, which the unmount cleanup had already skipped because the save had not yet set `savedThisSessionRef`, so other tabs and the Files row's sha are refreshed and the next delete of the file succeeds. It also skips the "This save left errors" alert so nothing pops over Files. A save that finished while the screen was open is still swept on unmount. Tests: `ledger-file-editor-screen/__tests__/jump-rearm.test.ts` (the wiring case fails with the editor reverted). Not exercised with a 2 s delay.
