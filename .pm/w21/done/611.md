# Home Spending's "See all" opens Reports on its default 6M (or the last picked range), not the window the card compared, so the totals match neither figure

**Severity:** low. **Estimate:** 15 minutes. Owner: mobile. A3 (code-level at `main` `9c394e685`): `home-screen/components/spending-card.tsx:97-104` navigates to `/reports` with no range, and `reports-screen.tsx:66` starts at `useState<TimeRange>("6M")` and takes no route parameter. With This month $129 and Last month $300, See all lands on 6M with an Expenses total of $2,429. If the user picked YTD or ALL earlier, it lands there instead.

Not run natively: the Spending card is below Home's fold.

## Fix

Pass a range parameter (1M, or a two-month window) from See all, and have Reports apply it on navigation.

**Acceptance:** See all opens Reports on a range that matches the card's figures. A test covers the parameter.

## Dedupe

See w21/011, w21/418, w21/523 and w21/572. Searched `.pm/**` for "See all" together with Spending, and the Reports range.

**Resolved 2026-10-22** — Spending's "See all" now asks Reports for 1M (the month the card's This month figure covers) through a one-shot `requestedReportsRange` var that Reports applies on focus-independent mount or change and clears; it works for the guest examples too. Two source-check tests pin the request and the apply-once. Shipped in the commit that moves this note (`mobile`).
