# Create Ledger finishing after the user left still switches the ledger and pops every screen back to the tabs (missed by w21/194)

**Severity:** minor. **Estimate:** 15 minutes. Owner: mobile. A3 (code-level at `main` `f61267f7d`): `create-ledger-screen.tsx:466-481` runs `ledgerVar(id)` and `router.dismissTo("/(app)/(tabs)")` after `await createLedger`, with no `useIsHere()` check. Back stays live while busy, and there's no `beforeRemove` guard. Scenario: tap Create (a preset takes seconds), go Back, and open New Transaction or Profile. When the create lands, the ledger switches under that screen and `dismissTo` pops it. A dirty New Transaction raises "Discard?", and if the user taps Cancel, the draft stays bound to the new, empty ledger.

Not run natively: this QA run doesn't create ledgers.

## Fix

If the user has left, only toast "Created owner/name" (with an Open action); don't switch or navigate. Or block Back while creating, as the other write screens do.

**Acceptance:** leaving during Create leaves the current screen and ledger untouched and shows the toast. A screen test covers it.
