# Create Ledger accepts names like "___", "_" or "!!_" that the server refuses, then shows only "Couldn't create the ledger. Please try again."

**Severity:** low. **Estimate:** 10 minutes. Owner: mobile. A3 (code-level at `main` `6c1f191b7`, proven under `tsx`): `create-ledger-screen.tsx:220` checks only that the slug isn't empty (`slugifyLedgerName(val).length > 0`). The server's `NEW_LEDGER_NAME_PATTERN` (`backend-v2/src/shared/ledger-slug.ts:18`, tightened by w23/064) requires a letter or digit, which is what the form's own message says ("Name must include at least one letter or number."). For "___", "_", "_-" and "!!_", the mobile check passes and the server's fails. The server answers `BAD_USER_INPUT`, which `classifyCreateLedgerError` treats as "other", so Create shows the generic retry message, and retrying can't succeed.

Not run natively: the failure appears only on Create, and this QA run doesn't create ledgers.

## Fix

Validate the name with the same pattern (a shared rule or a copy pinned by a test) and show the field's error on Next. Map `BAD_USER_INPUT` with `field: name` to the name error.

**Acceptance:** "___" shows the name error on Next. A unit case pins the client rule to the server pattern.

## Dedupe

Follows w23/064's tightening. Searched `.pm/**` for slugifyLedgerName, NEW_LEDGER_NAME_PATTERN and "at least one letter".

**Resolved 2026-10-22** — the form's name check is now `isNewLedgerName`: the slug must match a copy of backend-v2's `NEW_LEDGER_NAME_PATTERN` (a letter or digit, hyphens only between runs), so "___", "_", "_-" and "!!_" show the name error on Next. Cases in `ledger-name.test.ts` (`mobile`) include a restated server pattern. Mapping a server `BAD_USER_INPUT` for the name field to the field error was left out: with the client rule matching the server's, that refusal can no longer happen from this form.
