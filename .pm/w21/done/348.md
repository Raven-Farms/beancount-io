# A beancount.io link opens the same-named ledger on the user's self-hosted server

**Severity:** minor-to-moderate. The app shows another server's data under a teammate's beancount.io link. **Estimate:** 20 minutes. Owner: mobile. A3: `resolve-app-link.ts` always accepts the hosted origin. `use-app-link-handler.ts` resolves against `getServerUrl()`, and the readability probe in `open-app-link.ts` then queries the current, self-hosted server. `resolveAppLink("https://beancount.io/ledger/bob/household/journal", { serverUrl: "https://books.example.com" })` returns `{ledgerFullName: "bob/household", href: "/transactions"}`.

Code-level at `main` `99c937e0e`. Not run natively.

## Fix

Accept a host-qualified https link only when its origin equals the session's server. Otherwise, open it in the browser. Custom-scheme links carry no host and keep their current behaviour.

**Acceptance:** with a self-hosted server selected, a beancount.io link opens in the browser.

## Dedupe

Fixed. With a self-hosted server selected, a beancount.io https link is the hosted service's ledger, so it no longer opens the same-named ledger on the user's server. `resolveAppLink` now accepts the selected server's own host, and the hosted origin only when it is the server (or none is given). A new `resolveServerLink` (`app-links/server-link.ts`) decides per incoming link: an https link resolves against the server it names; a custom-scheme or bare-path link, which carries no host, is re-hosted onto the selected server (so it keeps its current behaviour); a hosted ledger link on another server's session returns `browser`. `useAppLinkHandler` opens that in the browser and clears the stashed link so nothing replays after sign-in. Tests (`server-link.test.ts`: browser on a self-hosted server, open on hosted and on the server's own host, hostless links re-hosted, non-ledger and foreign hosts ignored, handler wiring; the resolver test that pinned "hosted always accepted" now pins the new rule; the link-handler vm harness stubs the new module); six tests fail with the resolver and handler reverted. Deviation: `+native-intent` runs before the saved server is loaded, so it still rewrites the path and navigates the app to the matching tab of the current ledger before the handler sends the link to the browser; nothing is selected or opened under the wrong server.
