# Create Ledger's errors are silent to VoiceOver on iOS: a failed or conflicting Create is never announced (w21/354 sibling)

**Severity:** minor-to-moderate (accessibility). **Estimate:** 15 minutes. Owner: mobile. A3: `create-ledger-screen.tsx` renders every error as a plain `<Text>`: the form error (`errors.root`, `:824-826`), name (`:608-610`), currency (`:670-672`), Books begin (`:693-695`), opening amount (`:764-768`) and preview (`:789`). w21/354's `components/inline-error`, which announces on iOS, is used in Edit Transaction, Add Budget, Open Account, New Transaction and the text-input modal, but not here.

Code-level at `main` `dcac808bc` (`grep InlineError create-ledger-screen.tsx` finds nothing). Not exercised with VoiceOver. On a tier-limit or generic failure the spinner just stops; on a name conflict the screen silently jumps back to step 2 of 3.

## Fix

Render these errors with `InlineError`, and extend w21/354's announce guard to cover this screen.

**Acceptance:** each Create Ledger error is announced on iOS, and the guard test covers the screen.

## Dedupe

Sibling of w21/354 (done). Searched `.pm/**` for InlineError, announceForAccessibility, and Create Ledger together with VoiceOver.

Resolved. Create Ledger's six error renders (name, currency, Books begin, opening amount, the refused preview and the form-level `errors.root`) now use `InlineError`, which announces on iOS and sets the live region on Android, instead of plain `Text`, so a refused name, a tier limit or a generic failure is spoken to a VoiceOver user. The announce guard's form list includes the screen, and a new check pins each of the six `message={…}` renders and the absence of the old bare `Text` ones; the one for the screen fails against the old file, as does the form-list entry. The creation-refresh harness got a stub for the new import, and the w21/478 pin was updated to the `InlineError` render. Deviation: not run with VoiceOver.

Native recheck: not exercised. It concerns VoiceOver announcements, which the driver can't capture, and a failed Create, which this run doesn't attempt. It rests on its tests.
