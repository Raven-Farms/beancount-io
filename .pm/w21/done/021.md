# The account picker's Recent block ignores the selected root chip

**Severity:** minor. **Estimate:** 15–20 minutes. Owner: mobile. A2: a user narrows the picker to **Expenses** to choose a category, and the first row offered is `Assets:Cash`, because Recent pins the five most-used accounts whatever chip is active.

Environment: `main` at `4abd24b85`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). QA account, synthetic ledger `mcp-agent-eval`. Nothing was saved.

## Repro

1. Home → **+** → **Enter new transaction** → tap the first posting's account.
2. Tap the **Expenses** chip.
3. The list shows **Recent: Assets:Cash, Expenses:Food:Groceries**, then the **Expenses** section. `Assets:Cash` is outside the chosen root.

## Root cause

`mobile/src/screens/account-picker-screen/picker-sections.ts:82-97` (`visibleAccountSections`) filters the browse `sections` by `activeRoot`, but builds `recents` from `topAccounts(ranking, RECENT_LIMIT, accounts)` over every account.

## Fix

When `activeRoot !== ALL_ROOTS`, restrict recents to accounts under that root (`account === root || account.startsWith(root + ":")`). If none remain, drop the Recent block, which also brings back the lone-section rule (no header). Keep the All chip and search behaviour unchanged.

**Acceptance:** with Expenses selected, Recent lists only `Expenses:…` accounts, or is absent. All still shows mixed recents. Unit tests in `__tests__` cover a chip with recents of other roots, and a chip whose filtered recents are empty.

## Dedupe

Searched `.pm/**` for account picker together with recent, chip and root filter. The picker items (w3/154, w3/202, w4/050, w2/069) cover selection scrolling, truncation and labels. No item covers recents versus the chip.
