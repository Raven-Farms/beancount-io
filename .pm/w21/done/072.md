# Account detail never shows an entry added while its journal is being paged: overlap is deduped but never refetched

**Severity:** minor. **Estimate:** 15 minutes. Owner: mobile. A3: open an account that has more than one page of entries (page size 50). Another client (web, CLI or an agent) then adds an entry to that account, and the user scrolls. The next page (offset 50) now starts one row earlier, and `mergeAccountJournalItems` silently drops the repeated row. The new entry, which now sits at the top, is never fetched. Paging then stops (`added === 0` on a later page, or `loaded >= total` never matching). The list ends with "No more entries" one row short, until a manual pull to refresh.

Environment: `main` at `e80968380`. Code-level: the account journal rows have no testIDs and `onEndReached` can't be driven by the pinned Expo MCP, the same limit w21/035 recorded.

## Root cause

`mobile/src/screens/account-detail-screen/account-detail-screen.tsx:293-325` pages with `offset: items.length` and merges through `mergeAccountJournalItems` (`selectors/select-account-journal.ts:134-148`). It records `added < incoming` for `hasMoreAccountJournal` but never refetches. w21/035 fixed the same race for Transactions and merchant detail with `mergeJournalPage`'s overlap signal plus `refetch()` (`transactions-screen.tsx:200`). Its resolution considered account detail already covered because it dedupes.

## Fix

When a page overlaps (`added < incoming`), call `journalRefetch()`, as `transactions-screen.tsx:200` does, or reuse `mergeJournalPage`.

**Acceptance:** a unit test where loading page 2 after a new head entry was inserted triggers a refetch, so the new entry appears.

## Dedupe

w21/035 (done) covers Transactions and merchant detail only. Searched `.pm/**` for mergeAccountJournalItems and account journal overlap. No item.

**Resolved 2026-10-21** — Shipped in the commit that moved this note (`mobile`). The new `accountJournalPageOverlapped` in `select-account-journal.ts` names the overlap: the page added fewer rows than it returned. When a page overlaps, account detail's `loadMore` resets the page state and calls `journalRefetch()`, as `transactions-screen.tsx` does since w21/035, so the new head entry is fetched from the top. A test in `select-account-journal.test.ts` loads 50 rows, then a page 2 shifted by one head insert, and checks that the page is flagged. A wiring check confirms the screen refetches; it fails with the screen change reverted. Not driven natively: `onEndReached` can't be triggered through the pinned Expo MCP (see w21/035).
