# A failed first load on Reports, Accounts and Home's budget panel reads as real data: $0.00 reports, "No accounts", and an empty budget invite (siblings of w4/067)

**Severity:** major. These screens state wrong facts about the user's money instead of saying the load failed. **Estimate:** 1–1.5 hours. Owner: mobile. A3: w4/067 fixed this on Home's other cards with `selectCardLoadState`/`CardLoadFailure`. Three surfaces still treat "the query errored and nothing is cached" as an empty dataset. That happens on a fresh install, after signing out and back in, or on a ledger never opened on this device.

1. **Reports.** `reports-screen.tsx:143` sets `isLoading = incomeLoading && !incomeData`. After an error, loading is false with no data. The real cards render from empty arrays: an empty chart, Cash flow "no activity", Expenses **$0.00** and Income **$0.00**. There is no error and no retry. The stale banner (`:144`) needs cached data, so it stays hidden too.
2. **Accounts.** `accounts-screen.tsx:155-158` turns `accountsPending` false on error. `selectTrialBalanceCategories` (`components/account-list/select-trial-balance.ts:93-96`) returns `[]`, so `AccountTable` (`account-table.tsx:520`) says **"No accounts"**. `accountsError` feeds only the stale banner.
3. **Home budget panel.**
   - `home-screen/components/budget-card.tsx:82-86` ignores `useBudgetGroups().error`, so a user who has budgets is invited to "set a budget".
   - When the groups load but the actuals fail, `use-budget-panel.ts:113-117` catches the error and returns `[]`. `select-budget-panel.ts:49,64` then shows each row as **"$0.00 / $500.00"** with an empty meter.

Environment: `main` at `90b118713`. Code-level. Reproducing needs the network to fail before the screen's first load (airplane mode or Network Link Conditioner "100% Loss" on a device). The iOS simulator shares the host's network, and the app talks to production, so this wasn't driven natively.

## Fix

Route each surface through `selectCardLoadState` and `CardLoadFailure`, with a Retry that refetches the failing query, as Home's cards do since w4/067. In `use-budget-panel`, surface the actuals error instead of collapsing it to `[]`.

**Acceptance:** with the queries mocked to error and an empty cache, the following show a failure with Retry, never zeros or empty-state copy:
- the Reports cards
- the Accounts table
- the Home budget panel

Cached data with a failed refetch keeps showing the stale banner.

## Dedupe

w4/067 (done) covers Home's other cards, w21/068 the Notifications errors skeleton, w3/134 the Cash Flow error after a filter fix, and w21/076 the budget panel's `asOf`. Searched `.pm/**` for CardLoadFailure, "No accounts" and error states. None of them covers these three surfaces.

**Resolved 2026-10-21** — Shipped in the commit that moved this note (`mobile`). All three surfaces now use `selectCardLoadState` / `CardLoadFailure`, as Home's other cards do since w4/067. Cached data with a failed refetch still reads as ready, so the stale banner still works.
- **Reports:** a failed first income-statement load replaces the chart, Cash flow and both breakdowns with one failure card whose Retry refetches the statement. Recent transactions already handled its own failure.
- **Accounts:** a failed first trial-balance load shows the failure, whose Retry runs the screen's refresh, instead of `AccountTable`'s "No accounts".
- **Home budget panel:** `useBudgetGroups` now reports `loaded`, and a failed groups read shows the failure, whose Retry refetches the groups, instead of the "set a budget" invite. In `useBudgetPanel`, an actuals read that fails with nothing cached no longer collapses to `[]`. The new pure `settleBudgetPanel` fails the panel, and Retry re-runs the reads. The panel no longer shows "$0.00 / $500.00".

Tests in `src/__tests__/first-load-failures.test.ts` cover `settleBudgetPanel`'s behaviour plus source checks of the three render branches; all fail with the fix reverted. The screens can't be rendered by the unit runner, and a no-network first load wasn't driven natively.

**Native recheck 2026-10-21** (iPhone 17e, iOS 27.0, `main` with this fix, Metro restarted with `--clear`): on the normal path, Reports renders its chart and Cash flow, and Accounts renders its full tree with balances; the new failure branches don't show while loads succeed. The failure path wasn't forced, because the dev build talks straight to the production API and the simulator has no per-app offline switch.
