# Mobile Open Account rejects valid Hindi, decomposed-accent and titlecase names (mobile counterpart of w4/279)

**Severity:** minor. **Estimate:** 30–45 minutes. Owner: mobile. A2/A3: w4/279 fixed the dashboard's Open Account to accept names the ledger engine accepts: Devanagari with combining vowel signs, a decomposed `É` (E + U+0301), and a titlecase initial such as `ǅ`. Its dedupe notes that the separate mobile validator's "Unicode normalization/category edges were unverified". They are broken the same way on mobile.

Environment: `main` at `ed1526534`. Mobile's shipped `validateAccountName` (`mobile/src/screens/open-account-screen/account-name.ts`) run unchanged under Node 24. Engine control on the synthetic disposable ledger `mcp-agent-eval`: a file with the three `open` directives produced **no** `getLedgerErrors`, and was restored byte-for-byte.

## Results

| name | mobile `validateAccountName` | engine |
| --- | --- | --- |
| `Assets:Qa-20261020:हिंदी` | `invalidCharacters` | accepted |
| `Assets:Qa-20261020:Épargne` (decomposed) | `invalidCharacters` | accepted |
| `Assets:Qa-20261020:Épargne` (composed, control) | ok | accepted |
| `Assets:Qa-20261020:ǅep` (U+01C5 titlecase) | `componentMustStartUppercase` | accepted |
| `Assets:Qa-20261020:Snacks` (control) | ok | accepted |

So a user typing a Hindi account, or an accented name their keyboard produces in decomposed form, gets an inline refusal and a disabled Done for a name the ledger would open.

## Root cause

`mobile/src/screens/open-account-screen/account-name.ts`:

- The character check allows letters, digits and hyphens but not combining marks (`\p{M}`: `\p{Mn}` / `\p{Mc}`), so `ि`, `ं` and U+0301 are "invalid characters".
- `startsSubcomponent` accepts `\p{Lu}`, digits or caseless letters, but not titlecase `\p{Lt}` (`ǅ.toUpperCase()` is `Ǆ`, so the caseless test fails).

## Fix

Mirror the dashboard fix: allow `\p{M}` after the first code point, and accept `\p{Lt}` as a valid initial. Normalize to NFC before validating and before writing, so a decomposed `É` is written composed and duplicates are detected consistently (w0/037's already-open check). Keep refusing lowercase Latin initials, punctuation and empty components.

**Acceptance:** the three names validate ok, and Open Account enables Done and writes them (NFC). `bank:checking`, `Assets:Bank:` and `Assets:Bank:Chécking Acct` keep their refusals. Unit tests in `account-name` cover each case above.

## Dedupe

Dashboard: w4/279 (done). Mobile: w3/165 (done) added digit, accent and caseless-letter initials but not combining marks or titlecase. Searched `.pm/**` for combining mark, titlecase, Hindi and Open Account validation. No open mobile item.

---

**Resolved 2026-10-21** — `mobile/src/screens/open-account-screen/account-name.ts` now follows the dashboard's w4/279 rules (`eb425cf84`). A subcomponent may start with a titlecase letter (`\p{Lt}`, so `ǅep`), and combining marks (`\p{M}`) may follow the initial, so Devanagari vowel signs and a decomposed U+0301 are accepted. `validateAccountName` checks components in NFC, and `composeAccountName` writes NFC, so a keyboard's decomposed `É` is opened composed and the already-open check compares like with like. Lowercase Latin initials, a mark as an initial, spaces and other punctuation, empty components and bad roots are still refused. `open-account-name.test.ts` covers the note's five names (accepted) plus `bank:checking`, `Assets:Bank:`, `Assets:Bank:Chécking Acct`, `Assets:bank` and a mark-led component (refused with their reasons), and that composition writes NFC. Reverting fails 2 cases. Native gates pass: format, lint, typecheck, `yarn test:unit` (2494 passed, 1 skipped). Not checked on the simulator. Shipped in the commit that moved this note (`mobile`).
