# On any server older than 2026-10-21, `getLedgerErrors` fails validation (it now selects `code` and `hint`), so Notifications breaks, the bell reads 0, and the editor's error checks go silent

**Severity:** major for self-hosted users (a broken ledger looks clean). **Estimate:** 20 minutes. Owner: mobile. A3 (code-level at `main` `851db958a`; the document was validated with graphql-js against mobile's own 2026-08-14 schema snapshot, `76b9ce336`): `common/graphql/queries/getLedgerErrors.graphql:6-7` selects `code` and `hint`. The backend added them in `85c43b5e6` (2026-10-21, w21/311), and mobile selects them unconditionally since `a48f3bd0a` (w21/424). w21/311 recorded production rejecting the query with `Cannot query field "code"` before its deploy. On an older server:
- Notifications shows `CardLoadFailure`, and Retry always fails (`notifications-screen.tsx:371-372`).
- The drawer bell counts 0 (`ledger-drawer-header.tsx:106`).
- The editor's banner disappears, and the post-save check swallows the failure (`ledger-file-editor-screen/index.tsx:507-516`), so a save that breaks the ledger gives no warning.
- Transaction detail's per-entry errors are always empty (`transaction-detail-screen.tsx:458`).

`mobile/README.md:134` promises compatibility with self-hosted deployments. Also, the committed `mobile/src/generated-graphql/schema.graphql` lacks `code` and `hint`, so the document fails against the repo's own snapshot.

## Fix

Fetch `code` and `hint` in a separate query (the `CurrentUserAvatar` pattern), or retry without them on a validation error, and refresh the committed schema snapshot.

**Acceptance:** against a schema without `code`/`hint`, errors still list (without hints), and the bell counts them. A test validates the documents against the old snapshot.

**Resolved 2026-10-22** — a second document, `getLedgerErrorsBasic` (filename, line, message), is the fallback for a server that rejects the `code` and `hint` the full one selects. `useLedgerErrors` (Notifications, the bell, transaction detail) reads it when the full read fails with a validation error (`isUnknownFieldError`), listing errors without hints; the editor's check after a save goes through `queryLedgerErrors`, which falls back the same way and rethrows any other failure. A test validates the basic document against the committed older schema with graphql-js, and the fallbacks are exercised in `ledger-errors-older-server.test.ts` (`mobile`). The generated hook code was written by hand in codegen's shape because codegen reads the live server, so a real `yarn codegen` run should confirm it; the committed `schema.graphql` snapshot was not refreshed (it is what the older-server test uses).
