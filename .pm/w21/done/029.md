# At AX2, New Transaction's posting accounts shrink to "Asse…cking" and "Ex…ries"

**Severity:** minor (readability at a supported size). **Estimate:** 20–30 minutes. Owner: mobile. A2: New Transaction is where a user confirms which accounts money moves between. At `accessibility-large` (AX2, within the supported ceiling), each posting row shares one line between the account name and the amount field. The account is middle-ellipsized to a few letters, so `Assets:Bank:Checking` reads "Asse…cking" and `Expenses:Food:Groceries` reads "Ex…ries", and a wrong account can't be spotted before saving.

Environment: `main` at `af1a5bf54`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0), dark, `content_size accessibility-large`, cold launch. QA account, synthetic ledger `mcp-agent-eval`. Nothing was saved.

## Repro

1. Set AX2, launch → Home → **+** → **Enter new transaction**.
2. The postings read **"Asse…cking" 0.00** and **"Ex…ries" 0.00 [auto]**. At the default size they read `Assets:Bank:Checking` / `Expenses:Food:Groceries` in full.

## Root cause

`mobile/src/screens/multi-postings-transaction/multi-postings-transaction-screen.tsx:319-338`: `postingRow` is one row holding `postingAccountWrap` (`<Text numberOfLines={1} ellipsizeMode="middle">`) beside `postingAmountWrap` (sign toggle, amount input, auto badge). The amount input caps its scale (`amountMaxFontSizeMultiplier`), but the account text does not, and the row never stacks. The same pattern was fixed elsewhere, for example "Keep transaction posting account names readable at enlarged text sizes" on the detail screen.

## Fix

At `prefersStackedLayout(fontScale)`, render the account on its own line (up to 2 lines, or `ellipsizeMode="head"` so the leaf, the part that differs, survives) with the amount controls below, right-aligned. Keep the single row at default sizes. Key the account Text on `fontScale` for live changes.

**Acceptance:** at AX2, both postings show at least `…Bank:Checking` / `…Food:Groceries`, and the amount field, sign toggle and auto badge stay fully visible and tappable. The default size is unchanged. The swipe-to-remove action still works. A layout test asserts the stacked branch.

## Dedupe

The detail screen's posting rows (done, "Keep transaction posting account names readable at enlarged text sizes") and the account picker (w4/050) were fixed. The **entry form's** posting rows were not. Searched `.pm/**` for posting with enlarged text, AX2 and truncation.

---

**Resolved 2026-10-20** — `PostingRow` stacks from `prefersStackedLayout(fontScale)`, which AX2 crosses. The account takes the full width on up to two lines, with `ellipsizeMode="head"` so `…Bank:Checking` and `…Food:Groceries` survive. Its `flex: 1` wrapper is dropped when stacked so it can't collapse. The sign toggle, amount input and auto badge sit under it, aligned to the trailing edge. The account Text is keyed on `fontScale`. The single row at default sizes and the swipe-to-remove action are unchanged. `posting-row-layout.test.ts` pins the stacked branch, the line and ellipsis rule, the amount placement and the key on the source. Mobile gates pass: format, tsc, eslint, knip, and 2455 unit tests. Not checked at AX2 on the simulator. Shipped in `824602372` (`mobile`).

**Native recheck 2026-10-20** — dev build at `afbb70a15`, AX2: New Transaction shows `Assets:Bank:Checking` and `Expenses:Food:Groceries` in full, each above its amount (wrapping mid-word at the line end), with the auto badge visible.
