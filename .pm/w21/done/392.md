# Add Budget refuses Persian, Arabic-Indic and full-width digits (the amount field w21/230 didn't cover)

**Severity:** minor. **Estimate:** 10 minutes. Owner: mobile. A3: `isBudgetAmount` (`budget-screen/build-budget-entry.ts:36-37`) uses an ASCII-only `\d`, so `۵۰۰` is refused although New Transaction accepts it since w21/230. Code-level at `main` `62533363c`; from the regression audit.

## Fix

Normalize numerals with `toAsciiNumerals` (after w21/386's separator fix) before validating, and submit ASCII.

**Acceptance:** `۵۰۰` is accepted as 500 in Add Budget.

## Dedupe

w21/365 (Create Ledger dates) and w0/038 / w21/302 (sign) differ. Searched `.pm/**` for isBudgetAmount and "budget" with Persian.

Fixed. Add Budget's amount accepts digits from any keyboard: `isBudgetAmount` and `buildBudgetEntry` normalise through the shared `toAsciiNumerals`, so `۵۰۰`, `٥٠٠` and full-width `５００` are accepted as 500, the Arabic decimal mark `٫` reads as a point, and the amount is written to the ledger as ASCII (`500`, `500.5`), with the sign rules for spending caps and income targets unchanged. The Arabic thousands separator is still refused here (a budget takes the plain number), as w21/386 left it, as is any other junk. Tests (`build-budget-entry.test.ts`: the accepted and refused inputs and the ASCII payload with signs; two fail with the module reverted). Not run natively.

Native recheck: not exercised. Saving a budget would write to the ledger through Add Budget, and the shared budget delete path is unsafe while w21/476 is open. It rests on `build-budget-entry.test.ts`.
