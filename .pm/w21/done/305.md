# VoiceOver can't tell the Transactions filters are on, and the account row's ✕ is announced as a second "Reset"

**Severity:** minor (accessibility). **Estimate:** 15 minutes. Owner: mobile.

Code-level at `main` `ba784a628`:
- **Filters button:** `mobile/src/screens/transactions-screen/transactions-header.tsx:63-74` always reads "Filters, button". The only active cue is a plain dot (`activeFilterCount > 0 && <View style={styles.filterDot} />`). With 1M plus an account applied, a screen-reader user can't tell why the list is short or reads "No transactions match".
- **Account ✕:** `mobile/src/screens/transaction-filters-screen/transaction-filters-screen.tsx:395` uses `accessibilityLabel={t("reset")}`, the same name as the header Reset (`:297-309`), which clears everything. Swiping the sheet reads "Reset, button" twice, and the second clears only the account.

## Fix

- Give the Filters button an `accessibilityValue` like "2 active", with a new key in 13 locales.
- Label the ✕ "Clear account" (or `allAccounts`).

**Acceptance:** with filters applied, VoiceOver reads "Filters, 2 active, button", and the ✕ reads "Clear account". A source check covers both.

## Dedupe

w2/067 covered only the sheet header's roles. Searched `.pm/**` for filterDot, activeFilterCount together with accessibility, and close-circle.

Fixed. The Transactions Filters button now carries an `accessibilityValue` of "Active: N" (`filtersActive`, 13 locales) when filters are applied, so VoiceOver reads "Filters, Active: 2, button" and a user hears why the list is short; the dot stays as the visual cue. The filter sheet's account ✕ is now "Clear account" (`clearAccount`, 13 locales) instead of "Reset", so it no longer duplicates the header Reset that clears everything. Deviation: the value is worded "Active: N" rather than "N active" so it reads correctly in languages where a counted adjective changes form. Source checks in `transactions-screen/__tests__/filter-accessibility.test.ts` (two fail with the two components reverted). Mobile gates and deadcode green; not read with VoiceOver.
