# Delete and Edit on a plugin copy act on its template: deleting "Car insurance (4/12)" removes the whole amortized series, with only a single-transaction confirmation

**Severity:** major (silent loss of the source entry and every copy). **Estimate:** 1–2 hours. Owner: mobile + ledger/backend-v2 (parity). A3: the `amortize_over` and forecast plugins give every copy its template's source identity (`backend-cluster/ledger/src/foundation/rustledger/plugins/amortize-over.ts:169` `inheritDirectiveSourceId`; `forecast.ts:99`), so entry context answers a copy with the template's slice and checksum, and delete and edit target the template. The mobile detail screen can't tell a copy from a real entry: `select-transaction-detail.ts:14-26` lists no generated marker that fits a copy (its flag is `*` or `#`), and `select-transaction-write-actions.ts:5-9` gates Delete and Edit only on write access and a loaded checksum.

Confirmed on production at `main` `a69419ae4`, with a fixture written to the disposable ledger and restored byte-for-byte:

- **API:** with `plugin "fava.plugins.amortize_over"` and a 2026-06-01 entry for 600.00 USD with `amortize_months: 12`, the journal lists copies (1/12) to (5/12). `getLedgerEntryContext` for each of the five copy hashes returns the same checksum and the template's slice (`2026-06-01 * "QA Insurer" "…car insurance"`).
- **Native (iPhone 17e):** opening "(4/12)" ($50.00, Sep 1) shows the Edit pencil and a ⋯ menu with Share link, Copy link and Delete. Delete asks only "Are you sure you want to delete this transaction?". The dialog was cancelled.

Confirming deletes the whole $600 source entry, so every month's copy disappears, past ones included. Edit opens the template's text, not the copy that was tapped.

## Fix

Have entry context say that the entry is a plugin copy (for example `generated_from` / `plugin_copy`) through REST, GraphQL and MCP together, per the parity rule. On mobile, either hide Delete and Edit for copies or say that the whole series goes ("Deletes all 12 monthly copies of 'Car insurance'"), and point Edit at the source. Adding `#` to the generated-flag list alone is not enough: amortized copies keep `*`, and real `#` entries exist.

**Acceptance:** with the fixture above, a copy's detail screen no longer offers a one-entry Delete that removes the series, and the API reports provenance identically on all three surfaces.

## Dedupe

Searched `.pm/**` for amortiz, forecast, plugin copy, generated and provenance. Only CLI plugin items turned up (w5/946, w5/291), and w21/189 covers plugin error locators; none covers delete or edit on a copy.

Resolved, in two halves.

Server (shipped): an entry's context now says when it is a copy. The ledger marks every directive that `amortize_over`, `forecast` or the pad pass generates (a provenance mark that survives clones, links added to a copy and the worker's structured clone) and `getContext` returns `generated_from`, the source entry's hash, else null. It is in the ledger OpenAPI spec and the fava client, and backend-v2 passes it through GraphQL (`EntryContext.generated_from`), REST (`entry-context`, with the v1 OpenAPI snapshot refreshed) and MCP (`getEntryContext`, whose description and `docs/mcp.md` tell an agent to address the source instead). A new three-surface test reads the same value on REST, GraphQL and MCP (fails without the change); ledger tests cover the marks, the capture/restore round trip, each plugin's output, the pad pass and `getContext`.

Mobile (shipped, interim): the detail screen withholds Edit and Delete from a copy. A copy has no flag of its own, so `isPluginCopy` compares the entry's day, payee and narration with the first line of the slice it was answered with (an amortized copy's name or day differs, a forecast occurrence's marker is missing, a pad's slice is not a transaction) and leaves what it cannot read alone. Tests cover the (1/12) copy that shares the template's day, a later copy, a forecast occurrence, a pad, ordinary entries in several forms, and the screen's wiring; they fail without the change.

Deviations: the mobile half's authoritative version, and a link to the source with a sentence on why Edit and Delete are gone, is split to blocked note **w21/496**, because mobile's client is generated from production's schema, which lacks the field until the ledger service and backend-v2 deploy (a query selecting an unknown field would fail the whole entry context on older and self-hosted servers). The ledger service and backend-v2 changes need those deploys. The dashboard's entry-context panel has the same gap and is not changed. `Api.ts` was extended by hand with the one field: regenerating it from the OpenAPI spec also removed `severity` from `BeancountErrorPublic`, which exists in `Api.ts` but not in the spec (`idl/` was not updated for it), so a regeneration is out of scope here. No native run of the fixture.

Native recheck (iPhone 17e, fresh Metro `--clear` at `5b9620947` + `e69026bb0`): with the note's amortize fixture (`plugin "fava.plugins.amortize_over"`, 600.00 USD over 12 months from 2026-06-01; disposable ledger, restored), the "(5/12)" copy's detail shows no Edit pencil, and its ⋯ menu offers only Share link and Copy link, with no Delete. Fixed on mobile. Production doesn't yet serve `EntryContext.generated_from` (GraphQL answers "Cannot query field \"generated_from\""), so the server half isn't deployed; mobile's slice-header fallback (`isPluginCopy`) carries it until then, and the app doesn't query the field, so nothing breaks meanwhile.
