# Deleting a file that's already gone returns `SERVICE_UNAVAILABLE` ("try again") on REST, but `NOT_FOUND` on GraphQL and MCP

**Severity:** low. **Estimate:** 15 minutes. Owner: ledger. A3 (code-level at `main` `77ab889b4`; Gitea behavior confirmed on a local `gitea/gitea:1.24.7`): REST deletes go through `/change-files` → `changeExistingFiles` (`ledger/src/api/files.ts:182-209`). Gitea answers a missing delete there with **500** "repository file does not exist". w21/468's not-found check (`:204-206`) looks only at `update` operations, so backend-v2 reports `SERVICE_UNAVAILABLE`. GraphQL's single-file delete gets 404 → `NOT_FOUND`. MCP's `foldOperations` returns `NotFoundError` up front (`edit-ledger-files-tool.ts:195-196`), but it can still hit the 500 in a race.

Request: `DELETE /api-gateway/v1/ledgers/<o>/<l>/files/nope.bean {"sha":"<any>"}` returns `SERVICE_UNAVAILABLE`. Not called on production (REST credentials aren't in this QA setup).

## Fix

Apply the missing-path check to `delete` operations too, and map Gitea's "does not exist" 500 to 404.

**Acceptance:** a missing-file delete returns `NOT_FOUND` on all three surfaces, with a parity test.
