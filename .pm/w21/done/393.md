# Deleting a budget history entry that changed elsewhere fails with a bare "Failed to delete budget" and every retry fails the same way

**Severity:** minor. **Estimate:** 15 minutes. Owner: mobile. A3: `use-delete-budget-entry.ts:39-66` shows a generic failure on NOT_FOUND or a hash mismatch, never reloads, and every retry fails. This is the dead end w21/250 fixed for transactions. Code-level at `main` `62533363c`; from the regression audit.

## Fix

Reuse `classifyStaleDelete`'s gone and conflict handling (with w21/387's stricter matching): reload the budget groups, and say the entry changed elsewhere.

**Acceptance:** after the budget line is edited elsewhere, Delete refreshes the history, and a second Delete works.

## Dedupe

This is a sibling of w21/250. Searched `.pm/**` for "Failed to delete budget" and useDeleteBudgetEntry.

Fixed. `useDeleteBudgetEntry` now recognises an entry changed or removed elsewhere with the same classifier as the transaction delete (`classifyStaleDelete`: NOT_FOUND from the entry-context read, a hash that no longer resolves, or a slice/checksum conflict, using w21/387's whole-word matching): it refreshes the ledger data (`invalidateLedgerData(client, "entries")`, so the budget history is re-read) and returns "This budget entry changed elsewhere. The history was refreshed; try again." (`budgetDeleteChanged`, 13 locales), which the history row already shows in place of "Failed to delete budget". A second Delete then works on the refreshed list. Any other failure keeps its message and does no refresh. Tests (`budget-screen/hooks/__tests__/use-delete-budget-entry.test.ts`, running the real hook with React and Apollo stubbed: NOT_FOUND and a sha conflict refresh and say so, and SERVICE_UNAVAILABLE leaves the generic message with no refresh; the first two fail with the hook reverted). Not run natively.
