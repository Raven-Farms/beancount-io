# The Budget chart colors months before the budget existed red, as "over target"

**Severity:** minor. **Estimate:** 15–25 minutes. Owner: mobile. A2: a user who starts a Groceries budget in August opens the chart and sees **July painted red**, the "over budget" color, although no budget applied in July. Every month before the first directive with any spending reads as a failure, so a new budget always looks behind on its first view.

Environment: `main` at `3a27e8791`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). QA account, synthetic disposable ledger `mcp-agent-eval` with `2026-08-01 custom "budget" Expenses:Food:Groceries "monthly" 300 USD` and `2026-09-01 … 350 USD` (restored byte-for-byte afterwards).

## Repro

1. Home → Budget → **See all**, YTD.
2. The dashed budget line is **0** through July, then 300 (Aug) and 350 (Sep, Oct prorated). It is correct, and the header's Oct $225.81 = 350 × 20/31.
3. **July's** Groceries actual ($120.40) is drawn **red**. August's $180.85 is green (under 300). July had no budget to be over.

## Root cause

`mobile/src/screens/budget-screen/selectors/select-budget-card-stats.ts:41-50` (`selectPointFavorability`) computes `varianceStatus(actual - |budget|)` for every point. With `budget = 0` (`budgetForInterval` returns 0 for periods before any directive), any spending is "over", so it's unfavorable and red.

## Fix

Return a third state for points whose budget is 0 because no directive was in effect yet (distinct from an explicit `0` budget), for example `null` favorability, and render those bars in a neutral color (the theme's muted or secondary tone), with the accessibility summary saying "no budget". Keep red and green for periods that had a budget. An explicit zero budget should still read red on any spend.

**Acceptance:** with the repro fixture, July's bar is neutral and Aug–Oct keep their current colors. A ledger whose budget starts in January shows no neutral bars in YTD. Unit tests cover a pre-budget period, an explicit zero budget and a normal period.

## Dedupe

Searched `.pm/**` for budget with "no budget", pre-budget and "not yet in effect". w4/038 (YTD span), w2/039 (zero-target control at large text) and w3/m1 (budget page) don't cover pre-directive coloring.

---

**Resolved 2026-10-20** — `selectPointFavorability` takes the group's budget history and returns `null` for a point whose budget is zero and whose date falls before the first directive. The budget card passes `group.budgetHistory`, and `BudgetBarChartD3` draws a `null` bar in the neutral `black40` instead of red. `budgetChartSummary` already counted only explicit `false` as over target, so the spoken "over target" count also leaves those months out. I did not add separate "no budget" wording. An explicit zero budget is still judged, so spending on it reads red. A period the first directive starts partway through carries a prorated budget and is judged too. Tests in `select-budget-card-stats.test.ts` cover the repro (July unjudged, then August green and September red), the explicit zero budget, the partial first period, and the neutral bar. Mobile gates pass: format, tsc, eslint, knip, and 2466 unit tests. Not checked on the simulator. Shipped in `5caaed887` (`mobile`).
