# The drawer's ledger list is erased from the saved cache by an offline launch, so the next offline launch shows an empty drawer with an error (regression from the w21/054 fix)

**Severity:** minor (regression). **Estimate:** 15–25 minutes. Owner: mobile. A2: the w21/054 fix (`fbbf3623c`) revalidates the drawer's ledger directory on every mount. Revalidation calls `load(true)`, which evicts `listLedgers` from the Apollo cache **before** fetching. When the fetch fails (no network), `revalidate` re-publishes the old list to the screen but never writes it back to the cache. The cache persists on every write, eviction included, so the empty state is saved to disk. The first offline launch looks fine; the **second** offline launch shows no ledgers and an error.

Environment: `main` at `b2d1e3903`. Harness-level: the real `LedgerDirectory` class compiled and run against a real `InMemoryCache` with an always-failing link (scratch harness, not committed). Offline launches weren't driven on the simulator.

| step | state |
| --- | --- |
| cache holds `listLedgers`, launch 1 offline | screen shows the cached list, `error:false`; cache entry **evicted** afterwards |
| launch 2 offline | `{ ledgers: [], loading: false, error: true }`, "Network request failed" |
| before `fbbf3623c` | both offline launches showed the cached list (`load()` read cached pages) |

## Root cause

`mobile/src/common/ledger-directory/ledger-directory.ts:55-64` (`revalidate` → `load(true)` evicts then fetches; the failure path doesn't restore the cache), called on mount from `ledger-directory-provider.tsx:22`.

## Fix

Revalidate without evicting first: fetch `network-only`/`no-cache` and only on success replace the cached pages (the refresh path's atomic swap). Or write the previous snapshot back to the cache on failure. Keep w21/054's behaviour (a deleted ledger disappears after the next successful revalidation).

**Acceptance:** two consecutive offline launches both list the cached ledgers; an online launch after a ledger was deleted elsewhere drops it. A unit test covers failing revalidation followed by a cache read.

## Also from the same review (minor)

`3030ea1e8` (w21/053): the Create Ledger draft's 24-hour lifetime counts from `savedAt`, which every keystroke and mount resets (`mobile/src/common/create-ledger-draft.ts:31-40, :62`). A draft touched daily keeps a `requestId` older than the server's 24-hour idempotency window, so a retried create can't be deduplicated. Store the requestId's creation time separately and expire on that.

**Resolved 2026-10-21** — Shipped in the commit that moved this note (`mobile`). Both regressions are fixed.
- **Directory:** a refresh in `LedgerDirectory.load` no longer evicts `listLedgers` up front. It holds the pages it fetched (still `no-cache`) and only once the list is complete evicts every variant and writes the new pages in one `cache.batch`. A failed offline revalidation therefore leaves the cached pages in place, and the next offline launch lists them. The w21/054 behavior is unchanged: a successful revalidation drops a deleted ledger, and the existing tests still pass.
- **Draft:** the Create Ledger draft stores `requestedAt`, the time its `requestId` was minted. The screen carries it through every save, and the 24-hour expiry runs from it. A draft without it falls back to `savedAt`.

Tests: failing revalidation followed by a cache read and a second offline launch (`ledger-directory.test.ts`), plus the lifetime measured from `requestedAt` and its wiring (`create-ledger-draft.test.ts`). Each fails when its module is reverted.

Not checked on the simulator.

**Native recheck 2026-10-21 (partial)** — On iPhone 17e (iOS 27.0), dev build 1.20261002.50, with Metro restarted `--clear` on `main` containing `e2b25b8e1`. Online behaviour is unchanged: the drawer lists example and mcp-agent-eval after a cold start. The stored `create-ledger-draft` now carries **`requestedAt`** (the requestId's mint time) separately from `savedAt`. Not exercised: the offline relaunch sequence, since the simulator shares the host network, so the directory test (`ledger-directory.test.ts`) is the evidence. The draft was cleared afterwards.
