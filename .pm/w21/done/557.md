# VoiceOver users can't remove a posting: "Remove posting" exists only as a swipe action

**Severity:** minor (a11y blocker inside the form). **Estimate:** 15 minutes. Owner: mobile. A3: `multi-postings-transaction-screen.tsx:332-346` puts "Remove posting" only in a gesture-handler `Swipeable`'s `renderRightActions`. The row has no `accessibilityActions` or `onAccessibilityAction`, and there's no visible remove button. Under VoiceOver a swipe moves focus instead, so a user who added a posting by mistake can only abandon the whole draft. Code-level at `main` `18664fa5e`; the spoken output is derived from the props (and proven under `tsx` where a builder is involved), not from a VoiceOver run.

## Fix

Add an `accessibilityActions: [{ name: "delete", label: t("removePosting") }]` (with a handler) on the posting row, or a visible remove control.

**Acceptance:** VoiceOver announces "Actions available" on a removable posting, and swiping up offers Remove posting. A render test covers the action.

## Dedupe

w21/462 and w21/029 mention the swipe; neither covers an accessible alternative. Searched `.pm/**` for "Remove posting" and accessibilityActions.

---

**Resolved 2026-10-22** — the posting row's account button, the first element VoiceOver lands on, carries a named `delete` action ("Remove posting") whenever the row can be removed, and runs the same `onRemove` as the swipe; the swipe stays. Source-level cases in `remove-posting-action.test.ts` (`mobile`); not run under VoiceOver, so the spoken "Actions available" is derived from the props.
