# On first use, Scan Receipt renders its "Camera access is needed… Enable it in Settings" screen behind the system camera prompt

**Severity:** low. **Estimate:** 5 minutes. Owner: mobile. A3: `receipt-capture-screen/camera-view.tsx:108-113, 152-157`: an undetermined permission (`granted: false`, `canAskAgain: true`) takes the `!permission.granted` branch. The comment at `:146-147` says not to flash the denied copy, but it guards only `permission === null`. Under `tsx`, undetermined gives the denied copy plus Choose from photos, Cancel and Allow camera. VoiceOver can land on it once the prompt closes.

Native (iPhone 17e at `5867356e4`; camera permission reset with `simctl privacy reset camera`): Home ▸ + ▸ Scan Receipt shows the system "Allow "Beancount" to access your camera?" alert. Under its blur, an icon-like shape sits where the denied screen's camera icon would be. That isn't conclusive, because the alert can't be dismissed from the app driver.

## Fix

Treat `canAskAgain && !granted` while a request is pending as "asking" and render the plain letterbox.

**Acceptance:** on first use, only the letterbox shows behind the system prompt. A unit case covers the undetermined state.

## Dedupe

See w21/283. Searched `.pm/**` for "Camera access is needed" and canAskAgain.

---

**Resolved 2026-10-22** — Scan Receipt's camera view (`camera-view.tsx`) now shows the plain letterbox while the system camera prompt is up. It records when its one automatic `requestPermission` has come back (`prompted`), and the new pure `cameraPromptPending` (`receipt-utils.ts`) is true for a permission that isn't granted, may still be asked, and has no answer yet. So an undetermined permission no longer draws "Camera access is needed… Enable it in Settings" behind the prompt. A refusal on record that can't be asked again (`canAskAgain: false`) still shows the denied copy at once, and a refusal after the prompt shows it when the prompt closes. Unit cases plus a source check in `receipt-capture-screen/__tests__/camera-permission-refresh.test.ts` (fail without the change) (`mobile`). Not run natively (the system alert can't be dismissed from the app driver).

Native recheck (iPhone 17e): not exercised conclusively. With the camera permission reset, the system "Allow camera" alert covers the screen, and it can't be dismissed from the app driver, as in the original report. The fix's unit case covers the undetermined state.
