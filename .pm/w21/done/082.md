# The Narration input never shows suggestions: the ledger's narrations are fetched, but the multiline layout has no suggestions list

**Severity:** moderate. This is a regression: entry loses its narration autocomplete. **Estimate:** 30–45 minutes. Owner: mobile. A3: on New Transaction, Payee opens with a **SUGGESTIONS** list of the ledger's payees (CITY BUS, TRADER JOES, LANDLORD LLC, …). Narration shows only "Please input…". Typing `pr`, a prefix of the existing narration "Produce", shows nothing either; only the iOS keyboard's own word predictions appear. `GetLedgerNarrations` still runs on every open.

Reproduced natively on the iPhone 17e simulator (iOS 27.0), dev build 1.20261002.50, `main` at `705ec4ba4`, on the disposable QA ledger. The steps were Home ＋, Enter new transaction, Narration, type `pr`. Payee was the control. Nothing was saved.

## Root cause

- `mobile/src/screens/multi-postings-transaction/narration-input-screen.tsx:21-28` passes `multiline={true}` together with `suggestions={data?.getLedgerNarrations}`.
- `mobile/src/components/text-input-screen/index.tsx` (around `:215-260`) renders the suggestions card only in the single-line branch. The multiline branch is a bare `TextInput`.
- The likely origin is w3/211, "Keep long narration drafts visible above the native keyboard", which made Narration multiline.

## Fix

Render the same suggestions card under the multiline input, sized so the draft stays visible above the keyboard, which is w3/211's constraint. Filter by the typed text, as Payee does.

**Acceptance:**
- Natively: Narration lists the ledger's narrations, and typing `pr` narrows the list to "Produce".
- A long multiline draft stays visible above the keyboard.
- A component test where `multiline` with `suggestions` renders the list.

## Dedupe

w4/m35 (blocked) is about suggestion queries that fail, not ones that are never rendered. w3/211 introduced the multiline layout. Searched `.pm/**` for narration suggestions and getLedgerNarrations. No item.

**Resolved 2026-10-21** — Shipped in the commit that moved this note (`mobile`). `TextInputScreen` (`components/text-input-screen/index.tsx`) now builds its suggestions card once and renders it in both branches. In the multiline branch it sits inside the `KeyboardAvoidingView` under the input, and both take `flex: 1`. They split the space above the keyboard, so a long draft stays visible as w3/211 requires, and the input regains the full height when nothing matches. Filtering is the same as for Payee. The new harness test `__tests__/suggestions.test.ts` runs the real component:
- multiline plus suggestions renders the list inside the keyboard-avoiding body
- `pr` narrows it to "Produce"
- the single-line Payee list is unchanged

The two multiline cases fail with the fix reverted. Not re-checked natively.
