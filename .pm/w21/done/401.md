# On iOS, typing an apostrophe in Search finds nothing: Smart Punctuation turns "Trader Joe's" into "Trader Joe’s"

**Severity:** moderate. It hits any iPhone user with Smart Punctuation on, the iOS default, searching a payee with an apostrophe. **Estimate:** 15 minutes. Owner: mobile. A3: `components/search-bar/index.tsx:117-128` sets only `autoCorrect={false}`. RN 0.86 has no `smartQuotesType` prop. `plain-search-filter.ts:37` escapes the text literally, and the server matches a literal case-insensitive regex (`directive-filter.ts:583`). Under `tsx`, `"Trader Joe’s"` (U+2019) matches nothing against `Trader Joe's`, and the reverse fails for ledgers imported with curly quotes. w2/045's native run saw this exact field turn typed input into `E.B.’s “Beer”`, but excluded that attempt and never filed it.

Code-level at `main` `aedab56ba`. It can't be driven here, because the hardware keyboard suppresses iOS smart punctuation and the paste route bypasses it.

## Fix

In `toPlainSearchFilter`, after escaping, replace each of `'`, `‘` and `’` with `['‘’]`, and each of `"`, `“` and `”` with `[\x22“”]`, keeping w2/045's quote rule. Merchant detail shares the helper.

**Acceptance:** typing `Trader Joe's` on the iOS keyboard finds the entry, and a straight-quote search finds a curly-quoted payee.
