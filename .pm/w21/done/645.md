# Avatar initials split emoji and combined characters: "🇩🇪 Hans" shows half a flag, "👩‍💻 Ada" loses the joined emoji, "दीपक" loses its vowel sign

**Severity:** low. **Estimate:** 10 minutes. Owner: mobile. A3 (code-level at `main` `ab4fddb8d`, proven under `tsx`): `common/user-display.ts:20-27` (`userInitials`) takes `Array.from(word)[0]`, a single code point, for the Profile, Settings and drawer avatars (`components/user-avatar/index.tsx:86`). "🇩🇪 Hans" gives "🇩H" (a boxed letter), "👩‍💻 Ada Lovelace" gives "👩L", "👍🏽 Sam" gives "👍S", "दीपक कुमार" gives "दक", "ﬁona Lee" gives "FIL", and a decomposed "Ömer Koç" gives "OK".

Not run natively (no profile changes on the QA account).

## Fix

Take the first grapheme with `Intl.Segmenter` (granularity "grapheme") after NFC normalization.

**Acceptance:** those names give "🇩🇪H", "👩‍💻L", "👍🏽S", "दीकु", "FL" and "ÖK". Unit cases are added.

---

**Resolved 2026-10-22** — mobile's `userInitials` (`common/user-display.ts`) now takes each word's first grapheme after NFKC normalization, re-taking it after upper-casing (which can expand "ﬁ" to "FI"). The grapheme is a flag pair, or a character with its marks, emoji presentation selector or skin tone, through zero-width-joined parts, plus an Indic virama's conjunct ("क्ष"). The note's names give "🇩🇪H", "👩‍💻L", "👍🏽S", "दीकु", "FL" and "ÖK". Deviation: a pattern rather than `Intl.Segmenter`, so every runtime (Hermes included, where Segmenter isn't assured) gives the same answer and the tests run the code the app runs. Unit cases in `common/__tests__/user-display.test.ts` (fail without the change) (`mobile`). Not checked natively (it needs a profile name change).
