# Statement import (parseFile) still sends HEIC images to the model, so they fail as a generic parse error (w21/108 covered receipts only)

**Severity:** moderate. w21/108 asked for a clear BAD_USER_INPUT "on every surface". **Estimate:** 15 minutes. Owner: backend-v2. A3: `parseFile` passes the stored content type straight to the model with no check. Only receipt parsing got the `RECEIPT_CONTENT_TYPES` allowlist. The dashboard importer accepts `image/*` and uploads with `file.type`, so a `.heic` arrives as `image/heic`.

Code-level at `main` `3e830700b`: `backend-cluster/backend-v2/src/features/llm/service/llm-service.ts:163-190` (`mediaType: contentType` at :189) against `:236` (the receipt check). `parseFile` is exposed on GraphQL, REST (`file-parse-route.ts:29`) and MCP.

## Fix

Apply the same allowlist (JPEG, PNG, GIF, WebP, PDF, plus the text formats `parseFile` supports) in `parseFile`, with a parity test on all three surfaces.

**Acceptance:** a HEIC `parseFile` returns BAD_USER_INPUT naming the accepted formats on REST, GraphQL and MCP.

## Dedupe

This is a follow-up to w21/108 (done). w21/282 is the Android receipt picker. Searched `.pm/**` for heic, parseFile, RECEIPT_CONTENT_TYPES and file-parse-route.

Fixed. `LLMService.parseFile` now checks the stored content type before the download URL or the model: an image in a format the models do not read (HEIC, HEIF, TIFF, BMP, any `image/*` outside JPEG, PNG, GIF, WebP, with parameters like `; charset` ignored) is refused with BAD_USER_INPUT, "s3ObjectKey must be a CSV, OFX, QIF, spreadsheet or PDF export, or an image (JPEG, PNG, GIF, WEBP)", on REST, GraphQL and MCP alike (all go through the service). Deliberately narrow: only unsupported images are refused; text, PDF, OFX/QIF and spreadsheet exports are not images and go through as before (the existing `classifyFile` decides how they are read), so no working import can start failing. The image list is shared with the receipt allowlist (`MODEL_IMAGE_TYPES`). Tests: service cases (four unsupported types refused before the download; six accepted types reach it) and a three-surface parity case in `file-parse-parity.test.ts` (REST 400 with the code and message, GraphQL BAD_USER_INPUT, MCP error code; no download, model call or charge). backend-v2 typecheck, lint (knip), the full suite (373 suites, 6479 tests) and `generate-v1-openapi` (unchanged) green; five of the new cases fail with the service reverted.
