# Regression from w21/364: Home's budget panel shows $0.00 actual for every monthly budget, because it picks last month's interval row

**Severity:** major (every monthly budget on Home reads "$0.00 / …", contradicting the Budget page). **Estimate:** 15 minutes. Owner: mobile. A3: `currentIntervalItem` (`mobile/src/screens/budget-screen/selectors/budget-selectors.ts:552-562`, from `20034f4d9`) keeps the latest row with `item.date <= today`, assuming rows are dated at period start. The ledger dates each interval row at its period's **last** day (`backend-cluster/ledger/src/foundation/rustledger/interval-series.ts:352`, `date: range.endInclusive`). On 2026-10-21, October's row is dated 2026-10-31 and is skipped, so September's empty row is read. It is called from `home-screen/hooks/use-budget-panel.ts:175`. w21/337's to-today read (a row dated today) hides the bug only when the month has entries after today. Weekly budgets read last week, not this week.

Reproduced natively (iPhone 17e, fresh Metro at `097ca30dc`) with monthly budgets QaShopB 300, QaFoodB 600 and QaTransB 150, and spending of 200, 288 and 70 on Oct 3–5 (written to the disposable ledger and restored). Home's panel read "QaFoodB $0.00 / $406.45", "QaShopB $0.00 / $203.23" and "QaTransB $0.00 / $101.61", unchanged after refetching. The Budget page for the same budgets showed Actual $288.00 and $200.00. The panel showed correct actuals earlier the same day, before `20034f4d9`. A tsx run of the real `intervalTotals` and panel selectors confirms it: HEAD picks 2026-09-30 (actual 0), while the pre-364 code and the fix pick 2026-10-31 (288).

## Fix

Pick the first row dated on or after today (rows come in date order): `items.find((item) => item.date.slice(0, 10) >= today.slice(0, 10)) ?? null`. Switch `current-interval-item.test.ts` to period-end dates; its fixtures use period starts, which the server never sends.

**Acceptance:** the fixture's panel reads $288.00, $200.00 and $70.00, and a weekly budget reads the current week's row. Tests use server-shaped (period-end) dates.

## Dedupe

Regression of w21/364 (done). w21/377 and w21/337 are not the cause. Searched `.pm/**` for currentIntervalItem and for budget panel together with "$0.00".

Resolved. This was a regression in my w21/364 fix, which assumed interval rows are dated at their period's start. The ledger dates each row at its period's last day (`range.endInclusive`), so on 2026-10-21 October's row (10-31) was skipped and September's empty row read, giving "$0.00 of $406.45" for every monthly budget on Home. `currentIntervalItem` now returns the first row dated on or after today, the period still in progress (it does not rely on row order): October's 2026-10-31 for a monthly budget, the 10-25 row for the week of Oct 19 to 25, today's row for a daily budget or a read clipped at today, and null once every row has ended. The tests were rewritten with server-shaped (period-end) dates, including the note's monthly fixture (288 on the 10-31 row), and six of them fail against the old function. Deviation: the pre-364 behaviour reasoned from the code and the note's tsx run, not re-driven natively here; the panel hook's call site is unchanged.
