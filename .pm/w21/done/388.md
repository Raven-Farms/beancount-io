# After an edit that keeps the entry's hash (metadata, posting order), the detail screen still shows the old entry, so the save looks lost

**Severity:** moderate. w21/251's Acceptance is not met. **Estimate:** 15 minutes. Owner: mobile. A3: w21/251 returns to the detail screen on an unchanged hash (`edit-transaction-screen.tsx:358-363`). But `transaction-detail-screen.tsx:432-434` prefers the entry copy stashed when the row was opened (`open-transaction-detail.ts:30-43, 59`), which is never refreshed after an edit, over the refetched entry. Metadata is read from it (`:576`). Under `tsx`, `resolveSaveExit(h, h)` gives `unchanged`, and `selectStashedTransaction` returns the old copy, without the new `invoice`.

Code-level at `main` `62533363c`. Not driven natively, because typing into the code editor isn't possible here.

## Fix

Clear or refresh `selectedTransactionVar` (and the guest one) on an unchanged exit, or prefer the refetched entry once it arrives.

**Acceptance:** adding `invoice: "INV-7"` and saving returns to a detail that shows it.

## Dedupe

This is a follow-up to w21/251 (done). w21/296 and done/094 differ. Searched `.pm/**` for stash, selectedTransactionVar and unchanged.

Fixed. When an edit keeps the entry's hash (a metadata edit, a comment, a reordered posting), Edit Transaction now drops the copy of the entry that the detail screen stashed when its row was opened (`selectedTransactionVar(null)`), whether or not the user is still on the edit screen. That copy predates the edit and the detail screen preferred it to anything refetched, so adding `invoice: "INV-7"` and saving returned to a detail without it. With the stash gone the detail screen reads the entry-context copy and its focus refetch (the ledger was written meanwhile) brings in the new metadata. A changed hash is unaffected, since a stash for the old hash is already ignored. Tests (`edit-transaction-screen/__tests__/unchanged-exit-stash.test.ts`: the stash serves its own entry, a cleared stash yields none, and the clear sits on the unchanged exit ahead of the `here` branches; the wiring case fails with the screen reverted). Deviation: the cleared stash shows the context copy (possibly pre-edit for a moment) until the focus refetch lands, instead of the instant stash paint; not run natively, since typing into the code editor is not possible there.
