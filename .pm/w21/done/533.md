# A balance assertion that fails its explicit `~` tolerance shows as passing: `diff_amount` stays null for E2002 (w21/087 symptom)

**Severity:** minor. **Estimate:** 15 minutes. Owner: ledger. A3: `journal-serialize.ts:207-208, 248` reads only E2001 failures. The engine reports a failed explicit tolerance as E2002 ("Balance exceeds explicit tolerance for A: expected X C ~ T, got Y C (difference: D)"), which neither check matches.

Production (2026-10-22, disposable ledger, restored): `Assets:QaTol` holds 100.00 USD, with `2026-01-07 balance Assets:QaTol 99.995 ~ 0.001 USD`. `getLedgerErrors` reports E2002 at that line, but the journal's Balance row has `diff_amount: null`. So mobile's account detail shows no "Off by", and the failing row looks the same as a passing one.

## Fix

Parse E2002 as well (the expected, actual and difference figures), and set `diff_amount` from it.

**Acceptance:** that fixture gives `diff_amount` 0.005 USD (with the sign convention E2001 uses), and the app shows "Off by". A test covers E2002.
