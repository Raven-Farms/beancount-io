# Same-day ordering reverts to grouped-by-type whenever a plugin adds a directive (auto_accounts, implicit_prices), so running balances are wrong again (w21/134)

**Severity:** moderate. The service's own plaintext export writes `plugin "beancount.plugins.auto_accounts"`, so this setup is common. **Estimate:** 20 minutes. Owner: ledger. A3: `restoreEntrySortOrder` falls back to the engine's order for a whole date whenever any `date|type` count differs from the source text. Plugins that add directives (generated `open`s, generated same-day `price`s) always cause that mismatch.

Code-level at `main` `3e830700b`. A reviewer ran 134's pad-order fixture through `parseLedgerFilesInProcess` and `accountJournalItems`:
- **Without a plugin:** Salary +100 → 100, Note, Pad, Padding +400 → 500. Correct.
- **With `auto_accounts`:** Pad, Padding → **400**, Salary → 500, Note. This is the original bug.
- **With `implicit_prices`** and a same-day `10 EUR @ 1.1 USD`: the same wrong order.

## Root cause

`backend-cluster/ledger/src/foundation/rustledger/entry-sort-order.ts:73-79`. The export is at `ledger-journal-service.ts:765`.

## Fix

Keep source order for every `date|type` key whose count matches, and fall back only for the keys that don't. Order generated directives by type after the matched ones.

**Acceptance:** with either plugin, the fixture reads Salary → 100, Note, Pad, Padding → 500. Unit tests are added.

## Dedupe

This is a follow-up to w21/134 (done). w5/903 is an unrelated CLI price warning. Searched `.pm/**` for restoreEntrySortOrder and entry-sort-order.

Fixed in the ledger service. `restoreEntrySortOrder` no longer drops a whole day back to the engine's grouping when one `date|type` count disagrees with the source. Type rank (open, balance, everything else, document, close) always applies; within a rank the directives whose `date|type` maps to source lines are ordered by line, and a key that cannot be mapped (a plugin added a directive: `auto_accounts`' generated opens, `implicit_prices`' generated prices) keeps the engine's order and follows the mapped ones. The comparison is two groups, so it stays transitive. Checked against the live engine on 134's pad-order fixture: with `plugin "beancount.plugins.auto_accounts"` the account journal now reads Salary +100 → 100, Note, Pad, Padding +400 → 500, the same as with no plugin; before the change it read Pad, Padding → 400, Salary → 500 (the original bug). Unit tests in `entry-sort-order.test.ts` cover `auto_accounts`-style and `implicit_prices`-style additions and the unmappable-directive rule; the old test that pinned "engine order for the whole day" was replaced by the per-key rule (three cases fail with the module reverted). Ledger typecheck, lint, build and the full suite (113 suites, 1493 tests) green. Needs the ledger service deployed. Deviation: the generated directive itself lands after the mapped ones of its rank, not at a position Beancount's plugin would give it (its generated entries carry a synthetic line); only the order of the source's own directives is guaranteed.
