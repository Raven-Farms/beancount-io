# A payee with trailing whitespace makes a merchant's header disagree with its own rows: "2 transactions · $3.00" over three listed rows totalling $7

**Severity:** moderate. The Merchants list row, the detail header and the detail list give three different answers for the same merchant. Trailing spaces are common in padded CSV imports. **Estimate:** 30 minutes. Owner: mobile. A3: w21/046 made a merged Merchants row pass every spelling to its detail. The directory trims each BQL payee before keying, though, so the raw `"Starbucks "` spelling is lost, and the detail's exact `payee = "…"` BQL never matches it. The detail's row filter trims both sides, so it shows the row anyway.

Reproduced natively on the iPhone 17e simulator (iOS 27.0) at `main` `74d1e1700`, on the disposable QA ledger, which I restored byte-for-byte to `f1a0b83c`. The fixture `; qa-20261020-ws` added `"QA STARBUX"` entries of 1.00 and 2.00 USD (24 and 25 Aug) and `"QA STARBUX "`, with a trailing space, for 4.00 USD (26 Aug).
- **Merchants:** one row, "QA STARBUX · 3 transactions · Aug 26, 2026".
- **Detail header:** "QA STARBUX · 2 transactions · $3.00 · Aug 24, 2026 – Aug 25, 2026".
- **Detail list:** three rows, −$4.00 (26 Aug), −$2.00 and −$1.00. They total $7.00 and run to 26 Aug.
- Recurrence detection also only sees the trimmed spelling's rows (`use-payee-recurrence.ts`).

## Root cause

- `mobile/src/screens/merchants-screen/selectors/bql-table.ts:32-36` `asString` trims every string cell.
- `aggregate-payees.ts:119-140` keys and records `spellings` from that trimmed value. Both BQL rows therefore collapse into one spelling, `"QA STARBUX"`, and `otherSpellings` (`:163-165`) is empty.
- The detail's `buildMerchantMetaBql` / `buildMerchantCurrencyTotalsBql` (`merchant-detail-screen/selectors/merchant-stats.ts:41,50-55,66`) compare `payee = "QA STARBUX"` exactly.
- `filterExactPayee` (`filter-exact-payee.ts:23,29`) trims both sides and keeps all three rows.

## Fix

Keep the raw BQL payee as the spelling. Use a payee-specific reader that doesn't trim, with the trimmed, lower-cased form used only as the grouping key and display name, so `otherSpellings` carries `"QA STARBUX "` through to the detail. Alternatively, make the detail's BQL whitespace-tolerant, for example an anchored regex `^\s*QA STARBUX\s*$` built through `bqlPayeeEquals`'s escaping, so it agrees with `filterExactPayee`.

**Acceptance:**
- The fixture's detail reads "3 transactions · $7.00 · Aug 24 – Aug 26", matching the list row and the listed rows.
- A unit case in `aggregate-payees` tests keeps both spellings for `["X", "X "]`.
