# When the session ends mid-action, the app jumps to Welcome without explanation, then shows a raw "OAuth grant is no longer valid" alert on top

**Severity:** moderate. The user loses an open Edit Transaction, Open Account or file-editor draft and is never told they were signed out, or why. **Estimate:** 1 hour. Owner: mobile. A3: auth teardown clears the session silently. `app/(app)/_layout.tsx` then redirects to Welcome, which shows no reason. The in-flight write's failure handler shows the `OAuthRefreshError` text raw, because no mapper recognises it (see w21/117).

Code-level at `main` `d2b68a65e`. Not exercised natively: it needs mitmproxy rewriting `/api-gateway/` to UNAUTHENTICATED and the token endpoint to `invalid_grant`.

## Scenario

The refresh grant is revoked or rejected (w21/064 makes this happen in real use), and the user taps ⋯ → Delete or saves in the file editor. The session clears and the stack unmounts to Welcome, then a native alert opens on top: "Failed to delete transaction / OAuth grant is no longer valid". With a legacy session it reads "Authentication required" instead.

## Where (`mobile/src/`)

- `common/oauth/token-manager.ts:11-15, 171-176`
- `common/oauth/oauth-token-manager.ts:9-12` clears the session and does no routing.
- `common/apollo/auth-error-link.ts:22-33`
- `common/apollo/error-handling.ts:12-33`
- `app/(app)/_layout.tsx:22-24` redirects to Welcome.
- `app/auth/welcome.tsx` has no reason slot, and there's no "session expired" string in `en.ts`.

## Fix

This is messaging only. Per `.pm/DO_NOT_DO.md`, no draft recovery across restarts.
- Suppress write-failure alerts whose cause is an auth teardown (`OAuthRefreshError` or UNAUTHENTICATED).
- Set a one-shot sign-out reason, for example in a reactive var, that Welcome shows as translated copy: "Your session ended. Sign in again to continue."

**Acceptance:** with the token endpoint forced to `invalid_grant`, Delete lands on Welcome showing the translated session-ended notice, with no raw OAuth alert. A normal Log out shows no notice.

## Dedupe

w21/064 is the cause of involuntary sign-outs; w21/071 is data left behind after a teardown. Neither covers messaging. Searched `.pm/**` for "OAuth grant is no longer valid", "session ended", "session expired", UNAUTHENTICATED and "Welcome reason".

**Resolved 2026-10-21** — Shipped in the commit that moved this note (`mobile`). This is messaging only, and per DO_NOT_DO no draft is recovered.
- **Sign-out reason:** the new `signOutReasonVar` (`common/vars/sign-out-reason.ts`) is set to "sessionEnded" by both involuntary teardowns, the auth-error link (`teardownAndRoute`) and a terminal token refresh (`oauthTokenManager.onTerminalFailure`). It is not set by the user's own Log out.
- **Welcome:** it shows "Your session ended. Sign in again to continue." (new `sessionEndedNotice`, 13 locales) as an alert-role line. Starting a sign-in clears it.
- **Silenced alerts:** the new `isAuthTeardownError` recognises UNAUTHENTICATED or a terminal `OAuthRefreshError`, directly or as Apollo's `networkError`. A write failing that way now resolves silently in `runLedgerWrite` (`signedOut: true`: no toast, no haptic), and Delete Transaction shows no dialog. The file editor's save returns without its alert.

Tests:
- `welcome-actions-layout.test.ts`: the notice appears once and sign-in clears it; Log out shows none.
- `delete-transaction.test.ts`: no dialog or toast for UNAUTHENTICATED or a terminal refresh. These fail with the change reverted.
- `error-handling.test.ts`: both teardowns set the reason and the shared cleanup doesn't.

Not exercised natively, since it needs mitmproxy forcing `invalid_grant`.

**Native recheck 2026-10-21:** not exercised. Ending the session needs the server to reject the refresh token (`invalid_grant`), which the QA contract's no-credential-change rule rules out for the shared account. Covered by the unit tests only.
