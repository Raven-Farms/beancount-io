# The drawer keeps listing a ledger that no longer exists across cold starts, and choosing it leaves Home on "Failed to load / Try again"

**Severity:** minor. **Estimate:** 30–45 minutes. Owner: mobile. A2: ledgers get deleted or renamed on the web. The drawer, the app's ledger switcher, builds its list from the persisted Apollo cache and never asks the server again on launch. A removed ledger therefore stays listed through any number of relaunches, until the user happens to pull to refresh inside the drawer. Choosing it gives no explanation: every Home card fails with "Failed to load" and a **Try again** that can never succeed. Browse ledgers → Your ledgers, which fetches fresh, already omits it, so the two lists disagree on the same screen family.

Environment: `main` at `4d08f0a72`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). QA account. Read-only. (The missing ledger wasn't removed by this QA run.)

## Repro (observed)

1. The QA account's `listLedgers` returns 2 ledgers (`example`, `mcp-agent-eval`), and `getLedger("…/my-book2")` answers `NOT_FOUND`.
2. Cold-launch the app (repeated several times this session) → ☰. The drawer lists **example, mcp-agent-eval, my-book2**.
3. Drawer → Browse ledgers → **Your ledgers** lists only the 2 that exist.
4. Back in the drawer, tap **my-book2**. Home shows skeletons, and **Recent Transactions: "Failed to load · Try again"** and **Spending: "Failed to load · Try again"**. Nothing says the ledger is gone, and it stays selectable. Switching back to `mcp-agent-eval` recovers.
5. Even after that failed selection, reopening the drawer still lists my-book2. The failure doesn't prune it.

## Root cause

- `mobile/src/common/ledger-directory/ledger-directory.ts:47-110` (`LedgerDirectory.load`): when `refresh` is false, each page comes from `client.readQuery(LedgerDirectoryDocument)` and the network is used only on a cache miss. `LedgerDirectoryProvider` (`ledger-directory-provider.tsx:21`) calls `load()` without `refresh` on mount. The Apollo cache is persisted, so after the first-ever fetch a cold start never revalidates. That is the w21/006 problem, but this store reads the cache directly and so bypasses `APOLLO_DEFAULT_OPTIONS`. The test "reuses cached pages" (`__tests__/ledger-directory.test.ts:54`) pins this behavior.
- Selecting an id the server answers `NOT_FOUND` for falls through to each card's generic error state. There is no ledger-level "no longer available" handling like the per-route `RouteLedgerUnavailable`.

## Fix

Render the cached list immediately, then revalidate once per cold start or foreground (`load()` followed by a background `refresh()`, or a network read that replaces the snapshot atomically as the refresh path already does). On a `NOT_FOUND` for the selected ledger, show "This ledger is no longer available" with a switch action and drop it from the directory, rather than per-card retries. Update the cache-reuse test to allow one revalidation.

**Acceptance:** after a ledger is deleted on the web, the next cold start's drawer no longer lists it, without a pull-to-refresh. Selecting a stale id shows a ledger-unavailable state, not "Failed to load / Try again". Unit tests cover revalidation and the `NOT_FOUND` path.

## Dedupe

w21/006 (done) fixed cold-start revalidation for Apollo-watched queries, and this hand-rolled store isn't one. w3/199 covers the drawer's layout. w2/040, w2/042 and w2/054 handle ledger-bound detail routes becoming unavailable, not the selected ledger itself. Searched `.pm/**` for ledger directory, drawer stale, deleted ledger and `listLedgers` cache. No open item.

**Resolved 2026-10-21** — `LedgerDirectory` gains `revalidate()`. It loads the cached pages at once, then reads the server and replaces the list whole through the existing atomic refresh path. `LedgerDirectoryProvider` calls it on mount, so a cold start's drawer drops a ledger deleted on the web without a pull-to-refresh. A failed revalidation keeps the cached list and reports no error, because it is a background check; pull to refresh still reports a network failure. `LedgerGuard` also checks the selected ledger with the read context Home already uses. A `NOT_FOUND` (`isLedgerGone`) renders one "This ledger is no longer available" screen with Browse ledgers, instead of a "Failed to load · Try again" on every card, and refreshes the directory so the drawer prunes it. Network and other failures don't count as gone. Two new keys, `ledgerGoneTitle` and `ledgerGoneMessage`, are translated in all 13 locales. `ledger-directory.test.ts` adds a restart that shows the cached rows and then drops the deleted ledger, and a failed revalidation that keeps the cache quietly. The existing "reuses cached pages" case still holds for plain `load()`. `ledger-gone.test.ts` covers `NOT_FOUND` against network and other errors, plus the guard's wiring. `guest-access.test.ts`'s module mocks gained the new imports. Reverting fails 5 cases. Native gates pass: format, lint, typecheck, `yarn test:unit` (2545 passed, 1 skipped). Not exercised on the simulator. Shipped in the commit that moved this note (`mobile`).

**Native recheck 2026-10-21** — Passed on iPhone 17e (iOS 27.0), dev build 1.20261002.50, with Metro restarted `--clear` on `main` containing `613ce3516`.
