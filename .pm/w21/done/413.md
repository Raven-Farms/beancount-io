# The parked keypad add flow (beancount://add-transaction-legacy) overwrites chosen accounts, saves ¥1500 as 15.00 JPY, posts twice on a double tap, and fills closed accounts

**Severity:** minor (the route is reachable only by deep link, w4/033). **Estimate:** 45 minutes, or retire the route. Owner: mobile. A3: four defects found under `tsx` in `add-transaction-screen/`, none fixed there although their counterparts were fixed in the live New Transaction screen:
1. **The review screen overwrites FROM/TO** (`add-transaction-next-screen.tsx:160-172`, with TO built from `name_expenses` only at `:136-141`). For "ACME PAYROLL", the keypad screen fills Income:Salary → Assets:Bank:Checking, then the review screen re-fills FROM with Assets:Bank:Checking, and the save is `-3000.00 USD Assets:Bank:Checking` / `3000.00 USD Assets:Bank:Checking`.
2. **Zero-decimal currencies are wrong by 100×.** `getMoneyByKeyValues` (`add-transaction-screen.tsx:142-157`) always shifts two digits, so keys 1, 5, 0, 0 give `15.00 JPY` (cf. w21/231 and 389).
3. **No in-flight guard on Done** (`add-transaction-next-screen.tsx:182-226, 249-250`). Two taps ran `addEntries` twice in a `tsx` harness (cf. w21/044).
4. **Payee autofill ignores close and open dates** (`quick-add-accounts-selector.tsx:111-121`), so a closed Visa is filled and Done is refused (cf. w21/045, 103 and 229).

Code-level at `main` `c06a57c9a`; deep links can't be driven on this simulator.

## Fix

Either delete the parked route (w4/033 notes nothing links to it), or port the live screen's single-flight gate, minor-unit formatting, `isOpenOn` filtering, and skip the review screen's autofill when FROM/TO arrive as params.

**Acceptance:** the route is removed, or each of the four repros behaves like New Transaction.
