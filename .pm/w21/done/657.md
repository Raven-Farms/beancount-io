# A glob `include "y/*.bean"` pulls dotfiles (`y/.hidden.bean`) into hosted balances, which bean-check and `bea` skip

**Severity:** low (needs hidden .bean files in an included folder). **Estimate:** 10 minutes. Owner: ledger. A3: `file-map-loader.ts` (`BEAN_FILE_RE = /\.(bean|beancount)$/`) loads dotfiles into the engine's file map, and rustledger's glob matches them. Python's glob skips leading-dot names. Compared at `main` `1ec9cb250`: bundled `@rustledger/wasm` 0.24.0 against Python Beancount 3.2.3 with beanquery 0.2.0, on the same text. With `y/a.bean`, `y/B.bean` and `y/.hidden.bean`, rustledger loads all three and Beancount loads two. A hidden draft or template counts in hosted figures but not locally.

## Fix

Leave dotfiles out of glob matches (or out of the file map), matching Beancount.

**Acceptance:** `y/.hidden.bean` isn't included by `y/*.bean`. A test covers it.

## Dedupe

None found. Searched all of `.pm/` for glob together with dotfile, and BEAN_FILE_RE.

---

**Resolved 2026-10-22** — the ledger service's include-glob matcher now follows Python's `glob`: no wildcard (`*`, `?`, `[…]`, `**`) matches the leading `.` of a file or directory name, while a literal leading dot opts in (`y/.*.bean`, `.archive/*.bean`). The engine is handed the FileMap without the hidden files no include reaches under those rules (`parseableFiles`), so `include "y/*.bean"` no longer counts `y/.hidden.bean` in hosted figures; checked against the bundled `@rustledger/wasm` 0.24.0 and Python's `glob` on the same tree. Remaining divergence, unchanged by this: a glob plus an explicit include of the same hidden file still reports "Duplicate filename parsed" in the hosted engine. Tests in `file-map-loader.test.ts` and the new `hidden-include.test.ts` (both fail without the change) (`backend-cluster/ledger`). A ledger service deploy carries it to production.
