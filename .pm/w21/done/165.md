# Home's budget panel only ranks the first 12 budgets alphabetically, so an overspent budget later in the alphabet never appears

**Severity:** moderate. With 13 or more budgets, Home's Budget card can show three comfortably under-budget rows while a budget at 250% is left out, with no hint of the omission. The Budget screen still shows it Above target. The panel's own docs say it shows the budgets closest to their limit "rather than the first few alphabetically". **Estimate:** 1 hour (client) or a server capability (see the TODO). Owner: mobile. A3: `use-budget-panel.ts` keeps `groups.slice(0, BUDGET_PANEL_QUERY_CAP)`, with a cap of 12, in alphabetical order *before* fetching actuals. It then ranks only those by percent used. The TODO at `:34` names the missing server capability.

Reproduced natively on the iPhone 17e simulator (iOS 27.0) at `main` `c83b5e680`, on the disposable QA ledger, which I restored byte-for-byte to `f1a0b83c`. The fixture `; qa-20261020-b13`:
- opened `Expenses:QaB01` … `QaB13`
- `2026-10-01 custom "budget" Expenses:QaBNN "monthly" 100.00 USD` for all 13
- one `2026-10-05` spend: QaB13 250.00, QaB01–03 10.00 each

On Home, the panel rows (by testID) are:
- **`budget-row-Expenses:QaB01-USD` — "$10.00 of $100.00, 10% used, Below target"**, plus QaB02 and QaB03.
- **`budget-row-Expenses:QaB13-USD` — not found.**

## Where

- `mobile/src/screens/home-screen/hooks/use-budget-panel.ts:28-38, 85`
- `budget-screen/selectors/budget-selectors.ts:285-289` (alphabetical `groupBudgetEntries`)
- `select-budget-panel.ts:1-4` (the stated intent)

## Fix

Fetch actuals for all budget groups in batches, or add the server capability in the TODO (budgets with current-period actuals in one request, on REST, GraphQL and MCP), then rank the whole set. Until then, at least show "+N more budgets" with a link to the Budget screen when the cap truncates.

**Acceptance:** with the fixture, Home's panel lists QaB13 (250%) first. Add a hook test with 13 groups.
