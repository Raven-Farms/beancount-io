# A commit's per-file +/− counts read 0 for files under a directory ending in "b" (`lib/`, `web/`, `db/`) and miss deleted `---` or added `++` lines

**Severity:** minor-to-moderate. A commit's FILES row disagrees with its own STATS header and the rendered diff. **Estimate:** 30 minutes. Owner: backend-v2. A3: `parseFileStatsFromDiff` has two flaws:
- It takes the file name from the first `b/` in the `diff --git a/… b/…` header (`/b\/(.+)$/`). For `a/lib/x.bean` that match falls inside the old path, so the key becomes `x.bean b/lib/x.bean` and never matches Gitea's `lib/x.bean`.
- It tells header lines from content by prefix alone (`!startsWith("+++")`, `!startsWith("---")`), so a deleted `---` line or an added `++…` line isn't counted.

This is the backend twin of w4/done/023, which fixed only the mobile `parseDiff` by tracking whether the line is inside a hunk.

Code-level at `main` `cf6122e14`. The reviewer ran the real function on a synthetic `lib/x.bean` edit and got `[["x.bean b/lib/x.bean", {additions: 1, deletions: 1}]]`, and on a README change that deletes a `---` rule and got `{README.md: 0/0}`. The disposable ledger has no such paths, so neither was seen live.

## Where

`backend-cluster/backend-v2/src/features/gitea/commits/service/commits-service.ts:98` (file-name regex) and `:105`, `:112` (prefix guards).

## Fix

- Parse the header as `^diff --git a/(.*) b/(.*)$` with the two paths split at the matching midpoint, or read `+++ b/<path>` instead.
- Count `+` and `-` lines only inside a hunk (after `@@`, until the next `diff --git`), as mobile's `parseDiff` does.

**Acceptance:** unit tests cover `lib/x.bean` (+1/−1), a deleted `---` line (−1), an added `++note` line (+1), and a path containing `b/` in a rename.

## Dedupe

w4/done/023 is the mobile parser; w4/done/263 is the dashboard's tab-in-filename issue. Searched `.pm/**` for parseFileStatsFromDiff, "per-file stats", `b/` together with regex, and `lib/`.

**Resolution (2026-10-21):** the parser half was fixed by w21/132 (`4bbc36785`): the header is split at its matching midpoint (`rename to` names a rename's new path), and `+`/`-` are counted only inside a hunk. This adds the acceptance tests, in `commits-service.test.ts` ("per-file counts the old parser missed"): `lib/x.bean` +1/−1, a deleted `----` and an added `+++note` line, and a rename between paths containing `b/`. Run against the pre-132 parser, the same inputs give `x.bean b/lib/x.bean`, `README.md 0/0` and `b/old.bean b/lib/b/new.bean`.
