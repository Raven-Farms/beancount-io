# Budget header says "Above target" in red for a period before the budget existed, over an all-grey chart

**Severity:** moderate. The card's headline contradicts its own chart and flags a budget that hasn't started as overspent. Home's budget row says the same thing ("$50.00 of $0.00, 0% used, Above target"). **Estimate:** 30 minutes. Owner: mobile. A3: w21/033 made `selectPointFavorability` return `null` (neutral grey) for periods before a budget's first entry. `selectBudgetCardStats` got no such guard. With the latest point's budget at 0, `variance = actual − 0` is "above" and unfavorable.

Reproduced natively on the iPhone 17e simulator (iOS 27.0) at `main` `5edfef868`, on the disposable QA ledger, which I restored byte-for-byte to `f1a0b83c`. The fixture `; qa-20261020-budfut` was `2026-10-05 * "QA BUDFUT"` with Expenses:Transport 50.00 USD from Assets:Cash, plus `2026-11-01 custom "budget" Expenses:Transport "monthly" 300.00 USD`. Today is 2026-10-21.
- Home: the budget row `budget-row-Expenses:Transport-USD` has the accessibility value **"$50.00 of $0.00, 0% used, Above target"**.
- Budget → YTD: the card shows **Monthly · USD · "Above target"**, then Budget $0.00, Actual $50.00, Variance **+$50.00** in red. Every bar from May to October is neutral grey and the budget line is flat at $0.
- The reviewer traced the same output on **LY** for any budget dated after last year.

## Root cause

- `mobile/src/screens/budget-screen/selectors/select-budget-card-stats.ts:73-91` takes `latest.budget` (0 before the effective date), computes `variance = actual − budget`, and passes it to `varianceStatus`/`isFavorableVariance` without the pre-budget check.
- Home's panel calls the same selector, so its overlap with w21/076's zero-budget half is this cause.

## Fix

When the latest point predates the budget's first effective date (the same test `selectPointFavorability` uses), return `status: null` and `variance: null` with a neutral "Starts {date}" or "Not yet in effect" label, both in the card header and in Home's row. Don't compare against 0.

**Acceptance:**
- With the fixture, the card shows no "Above target" badge and no red variance; it gives a neutral "not yet in effect" state.
- Home's row reads neutrally.
- A budget in effect behaves as before.
- Add a selector unit test.

## Dedupe

w21/033 covers chart bars only; w21/076 covers Home `asOf` and a zero budget reading 0%; w4/184 is the dashboard. Searched `.pm/**` for future-dated, "not yet in effect", pre-budget, "above target" and LY.

**Resolved 2026-10-21** — Shipped in the commit that moved this note (`mobile`). `selectBudgetCardStats` now applies the same pre-budget test as w21/033's `selectPointFavorability`, through shared `firstBudgetDate` and `beforeFirstBudget` helpers. When the latest period is a zero budget dated before the first directive, it returns no status, no variance, no progress, a favorable flag, and `startsOn` set to that date. The card shows a neutral "Starts {date}" badge (new `budgetStartsOn` key in 13 locales) instead of a red "Above target", and the red variance disappears with it. On Home, such a budget's row has an empty meter, ranks last, and is announced as "… Starts {date}" rather than "Above target". Budgets in effect are judged as before. Tests in `select-budget-card-stats.test.ts` cover the note's fixture, an in-effect control, the card badge and Home's row; all fail with the fix reverted. Not re-checked on the simulator.
