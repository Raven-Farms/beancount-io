# A failed pull to refresh wipes the loaded Transactions list and account journal, replacing them with a raw Apollo error

**Severity:** moderate. **Estimate:** 30–45 minutes. Owner: mobile. A3: open Transactions online so the list loads, lose the network, then pull to refresh. The whole list disappears and is replaced by **"Failed to load transactions: "** plus the raw Apollo message. Account detail does the same with `journalLoadError`.

That contradicts the app's own rule in `card-load-state`, "Cached data with a failed refetch stays ready", and the stale-banner pattern Home, Accounts and Reports use. Neither screen shows a stale banner, and the only retry is to pull again.

Environment: `main` at `90b118713`. Code-level. It needs the network to drop between the load and the refresh, which the simulator can't do because it shares the host's network.

## Root cause

- `mobile/src/screens/transactions-screen/transactions-screen.tsx:294`: `sections={isInitialLoading || error ? [] : sections}`, with the message at `:317-323`.
- `mobile/src/screens/account-detail-screen/account-detail-screen.tsx:438` has the same pattern with `journalError`.

## Fix

Blank the list only when there is no data: `error && !data`. When cached rows exist, keep them and show the shared stale-data banner, with a retry that refetches. Use a translated error message instead of the raw Apollo text.

**Acceptance:**
- A component test where a refetch error with prior data keeps the rows and shows the stale banner.
- An error with no data still shows the failure state.
