# w21/111's fix double-scales the drawer's line heights at AX2: each line is about twice as tall, and wrapped names split far apart

**Severity:** moderate (regression). At AX2 the drawer is now mostly empty space, with fewer rows on screen than before. **Estimate:** 20 minutes. Owner: mobile. A3: `scaleLineHeights` multiplies each fixed `lineHeight` by `fontScale`, assuming "Dynamic Type scales `fontSize` but not a point `lineHeight`". React Native already does that scaling on iOS, so the line height is scaled twice (`lineHeight × fontScale²`):
- Fabric: `RCTAttributedTextUtils.mm:229-232`, `lineHeight * RCTEffectiveFontSizeMultiplierFromTextAttributes(...)`.
- Paper: `RCTTextAttributes.mm:141`.

Reproduced natively on the iPhone 17e simulator (iOS 27.0) at `main` `4b40d3039` (includes `fd9033f38`), at AX2 (`accessibility-large`), light mode, with the drawer open from Home:
- The selected "mcp-agent-eval" row wraps to "mcp-agent-" and "eval", about **111 pt** apart. "Ledgers" grows from about 13 to 28 px cap height (×2.15), and 24 × 2.15² ≈ 111. The row is about 236 pt tall.
- "example" and the owner header are spaced the same way. "Browse ledgers" leaves its compass icon stranded below the first word.
- At the default size the drawer is unchanged.

## Root cause

- `mobile/src/common/theme/dynamic-type.ts` (`scaleLineHeights`) scales again what the renderer already scales.
- It is applied by `useDrawerStyles()` in `mobile/src/components/ledger-drawer/ledger-drawer.tsx:332-339`.
- The original w21/111 clipping therefore had another cause. Look at containers that cap the text box at AX2, for example the `maxFontSizeMultiplier` / `allowFontScaling` combination or the row's `minHeight` with a fixed inner height.

## Fix

Revert `scaleLineHeights` for the drawer. Re-diagnose w21/111's clipping against the real cause, using the simulator's view inspector or `automation_find_view` frames of the clipped labels. If a line height must be adjusted at all, use `maxFontSizeMultiplier` on the Text rather than pre-scaling the number.

**Acceptance:**
- At AX2, drawer names and headers render whole with normal line spacing; the selected row's two lines sit about one line height (about 50–55 pt) apart.
- Default size is unchanged.
- A source check rejects multiplying `lineHeight` by `fontScale` in theme helpers.

## Dedupe

w21/111 (done) is the clipping this fix targeted, and its recheck records this regression. w21/246 is the tab header at AX2. Searched `.pm/**` for scaleLineHeights, "line height" with AX2, and double together with scale.

**Seen again 2026-10-21** (`main` `10857997b`, AX2): with the drawer open from Home, the doubled spacing pushes "Browse ledgers" to the bottom edge, with its compass icon stranded below the label. Merchants and the profile/Settings row are below the visible area. I couldn't tell whether that section scrolls, because the MCP has no scroll gesture. If it doesn't, those entries are unreachable at AX2.

Fixed in mobile: the drawer no longer pre-scales its line heights. React Native's iOS text layout already multiplies a point `lineHeight` by the text size (`RCTAttributedTextUtils.mm`: `lineHeight * RCTEffectiveFontSizeMultiplierFromTextAttributes`, confirmed in the installed 0.86 source), so w21/111's `scaleLineHeights` made each line about fontScale-squared tall (24 pt to 111 pt at AX2) and split wrapped names far apart. `scaleLineHeights` is gone; `relaxLineHeights` drops a style's fixed `lineHeight` once text is enlarged (fontScale above 1) and keeps it unchanged at the default and smaller sizes, so the platform's natural line height applies at large sizes, which can neither clip a glyph nor double the spacing. The drawer's three components still style through `useDrawerStyles()`. Tests: `relax-line-heights.test.ts` replaces `scale-line-heights.test.ts` (default sizes unchanged, the fixed line height dropped and everything else kept, no theme helper multiplies `lineHeight` by `fontScale`, and the drawer wiring); it fails with the three files reverted. Deviations: the note asked to re-diagnose w21/111's original clipping on a simulator, which I cannot do; the source shows the platform scales the line height, so the original clipping's cause is still unexplained, and the natural-line-height approach is chosen because it avoids both failures whatever that cause was. Not re-checked on the simulator at AX2 or AX3, so if "Ledgers" or a name still clips there, that is a new note.

**Native recheck (2026-10-21, iPhone 17e, AX2 `accessibility-large`, Metro restarted with `--clear`):** fixed. With the drawer open from Home, the selected row wraps to "mcp-agent-" / "eval" on two tightly spaced lines, and the whole row is about 100 pt tall where before it was about 236 pt. "Browse ledgers" keeps its compass icon beside the first line, and every row from Ledgers to the identity row fits in the top two-thirds of the screen. The text size was then restored to `large`.
