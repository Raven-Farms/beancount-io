# A recurring paycheck's typical amount is unsigned in Merchants ("Employer · Monthly · $5,000.00"), so it reads like a bill and contradicts its detail header

**Severity:** minor. **Estimate:** 10 minutes. Owner: mobile. A3: `merchant-row-text.ts:62-66` formats the typical amount with the unsigned `formatAmount`, while the detail header uses the signed `formatMerchantTotal` (`format-merchant-total.ts:18-23`, from w2/041).

Code-level at `main` `6854ec3a0`. In the reviewer's tsx run, a salary series at -5000 USD on 07-31, 08-31 and 09-30 gives `typicalAmountByCurrency {USD: -5000}`, and the row reads "$5,000.00", styled exactly like a $15.99 subscription. The detail header reads "−$15,000.00". Not exercised on the device.

## Fix

Format the typical amount with the signed formatter (or the app's income/expense presentation) so the row and the header agree.

**Acceptance:** the salary row shows its income sign and matches the detail header's convention. A unit case is added.

## Dedupe

w2/041 is the header totals, w4/006 the detail rows, w21/171 price changes. Searched `.pm/**` for "typical amount", typicalAmount, unsigned and salary.

Resolved. The Merchants row formats a recurring merchant's typical amount with the detail header's own formatter (`formatMerchantTotal`, the signed one from w2/041), so a salary row reads "-$5,000.00" (or "~-$5,000.00" when approximate) and matches the detail header's convention, while a bill stays "$15.99" with no "+"; the VoiceOver label follows because it reuses the same string. Tests cover a paycheck and a bill, exact and approximate; the paycheck case fails against the old unsigned formatter. Deviation: no native run.
