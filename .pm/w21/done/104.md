# Create Ledger stores a liability's opening balance with the wrong sign, and the iOS keypad can't type a minus

**Severity:** major for anyone starting books with a card or loan balance. Net worth goes up by the debt instead of down, and a balance assertion pins the wrong value. **Estimate:** 45 minutes. Owner: mobile, plus a backend check. A3: ADR021 says "A liability the customer says they owe is stored as the corresponding negative posting." The mobile form sends the typed amount as-is, the server writes it verbatim, and nothing negates liabilities.

Checked natively on the iPhone 17e simulator (iOS 27.0) at `main` `cd02f5446`; no ledger was created. In + New → Preset → Personal → Next, the opening-account list offers Liabilities:CreditCard and Liabilities:Loan. Focusing "Opening balance (optional)" brings up the **iOS decimal pad: digits, "." and delete, with no "−" key**. A user can only enter `500`. The "like 100 or -30.50" hint appears only after a validation error.

## Root cause

- `mobile/src/screens/create-ledger-screen/create-ledger-screen.tsx:644-659` uses `keyboardType="decimal-pad"`, and `:300-315` sends `openingAmount` unchanged.
- `backend-cluster/backend-v2/src/features/ledger/setup/build-ledger.ts:166-191` writes `<account> <amount>`, the negated Equity leg, and `balance <account> <amount>` verbatim.
- So `Liabilities:CreditCard 500 USD` / `Equity:OpeningBalances -500 USD`. The same applies to Liabilities:Loan and Rental's Liabilities:Deposits.

## Fix

Treat the opening amount as "amount owed" for liability accounts:
- Label the field "Amount owed" when a Liabilities account is chosen.
- Negate it before sending, in the client and, per ADR021, in `build-ledger.ts`, so REST, GraphQL and MCP agree.
- Keep accepting an explicit negative for power users, using a numbers-and-punctuation keypad where a sign is needed.

**Acceptance:**
- Creating a Personal ledger with CreditCard 500 writes `Liabilities:CreditCard -500 USD` and a matching balance assertion.
- Home net worth reads −$500.
- Assets are unchanged.
- Add a build-ledger unit test.

**Resolved 2026-10-21** — Shipped in the commit that moved this note (`backend-v2`, `mobile`). Server: `build-ledger.ts` now gives an opening amount the ledger's sign through `ledgerOpeningAmount`. A positive amount on a `Liabilities:` account is the amount owed, stored as the negative posting ADR021 calls for, so CreditCard 500 writes `Liabilities:CreditCard -500 USD`, `Equity:OpeningBalances 500 USD` and `balance Liabilities:CreditCard -500 USD`. An explicit negative stays as written, and other accounts are unchanged. It runs in the shared builder, so REST, GraphQL, MCP and the dashboard's form all get it. Mobile: with a Liabilities account chosen, the field reads "Amount owed (optional)" (new `createLedgerAmountOwed`, 13 locales), and the keypad is `numbers-and-punctuation` on iOS (`numeric` on Android), so a sign can be typed. The client does not negate, which avoids a double negation. Tests:
- `build-ledger.test.ts`: the CreditCard/Cash case and the explicit-negative case. The liability case fails with the server change reverted.
- `amount-owed.test.ts`: the label and keypad wiring; it fails with the screen change reverted.

backend-v2 typecheck, lint and 6413 tests pass. Home net worth after a real creation was not checked natively, and the dashboard form's label still says opening balance.
