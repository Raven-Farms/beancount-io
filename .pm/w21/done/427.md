# Guest mode: a single NOT_FOUND for one entry or file still blanks the whole example as "no longer public" (the gap w21/292 left)

**Severity:** minor-to-moderate. **Estimate:** 15 minutes. Owner: mobile. A3: `guestReadFailure` counts NOT_FOUND as `"unavailable"` (`common/guest/guest-client.ts:17-27`), and `flagsSession` always flags `"unavailable"` (`:60-65`) even for the per-entry `GetLedgerEntryContext` and per-file `getLedgerFile` reads (`:44-46`). The flag swaps every screen for `guestUnavailable` (`examples/example-ledger-provider.tsx:170-191`). Under `tsx`, after a successful `GetLedger`, one `GetLedgerEntryContext` answering NOT_FOUND logs `failures: ['unavailable']`. So transaction detail's own "removed" state never shows to a guest, and a foreground refetch after the example changes replaces the visit with "This example is no longer public or available"; Retry then remounts and drops the stack.

Code-level at `main` `669120634`.

## Fix

Flag `"unavailable"` only for FORBIDDEN/UNAUTHENTICATED, or for NOT_FOUND on `GetLedger`/`LedgerReadContext`. Leave per-entry and per-file NOT_FOUND to each screen.

**Acceptance:** in guest mode, an entry that vanished shows the detail's removed state, and the example stays usable.
