# The shipped production self-host stack (deploy/docker) can't be used from the mobile app with any server URL

**Severity:** major for self-hosters. With either the app domain or the API domain, the app can't sign in. The MCP OAuth authorization endpoint shares the same broken route. **Estimate:** 1 hour. Owner: deploy, plus backend-v2. A3: in production the OAuth issuer is `DASHBOARD_URL` (`https://APP_DOMAIN`), and the app requires issuer = server URL with GraphQL and `/api-gateway/oauth/*` on that same origin. The shipped Caddyfile routes only `/.well-known/*` on APP_DOMAIN to the backend, and the dashboard proxies `/api-gateway` only in dev (`vite.config.ts` `devProxy`). This breaks backend-v2's README "OAuth deployment contract".

Code-level at `main` `709af935d`. docker-mac runs in development mode with the issuer at `SERVER_URL`, so it can't show this. It needs a `deploy/docker` stack on real domains.

## Behaviour

- **`https://APP_DOMAIN/`:** the health POST to `/api-gateway/` hits the dashboard (404), so Test connection says "incompatible". Sign In passes discovery (`/.well-known` is proxied), then opens `APP_DOMAIN/api-gateway/oauth/auth`, which is the dashboard's NotFound page.
- **`https://API_DOMAIN/`:** health passes, but discovery's `resource` is `https://APP_DOMAIN/v1`, a mismatch, so "incompatible".

## Where

- `deploy/docker/Caddyfile:5-14` (same in `deploy/docker-single-psql/Caddyfile`)
- `backend-cluster/backend-v2/src/config/config.ts:355-356`
- `mobile/src/common/oauth/discovery.ts:141-163`
- `mobile/src/common/server-url.ts:54`

## Fix

Route `/api-gateway/*` on APP_DOMAIN to backend-v2 in both production Caddyfiles, so APP_DOMAIN is the single front door the OAuth contract describes. This is one fully self-hosted stack, not a managed/self-hosted bridge (`.pm/DO_NOT_DO.md`).

**Acceptance:**
- On a deploy/docker stack, `curl -XPOST https://APP_DOMAIN/api-gateway/ -d '{"query":"{health}"}'` returns the backend's answer.
- The mobile app connects with `https://APP_DOMAIN/` and completes sign-in.

## Dedupe

w1/m5/t011 verified only docker-mac and hosted. Searched `.pm/**` for Caddyfile, APP_DOMAIN, API_DOMAIN, "front door" and "/api-gateway/oauth".

Fixed in deploy: both production Caddyfiles (`deploy/docker`, `deploy/docker-single-psql`) now send `/api-gateway/*` on `{$APP_DOMAIN}` to backend-v2, beside the existing `/.well-known/*` route, so the OAuth issuer host is the single front door the backend README's contract describes: the health POST, GraphQL and `/api-gateway/oauth/*` (authorization, token) now reach the backend instead of the dashboard's 404/NotFound page. `deploy/docker/README.md` says to enter `https://<APP_DOMAIN>` as the mobile server URL, and why the API domain alone does not match the issuer. Verified: both Caddyfiles are identical and `caddy validate` (caddy:2-alpine, placeholder domains) passes. Deviations: no full stack run on real domains, so the acceptance's curl and the app sign-in were not driven; the `API_DOMAIN` mismatch is by design (issuer is `DASHBOARD_URL`) and is documented, not changed.
