# Cancelling New File during w21/222's folder lookup still creates the file and opens it; the lookup has no timeout or busy state

**Severity:** moderate (a write the user cancelled). **Estimate:** 20 minutes. Owner: mobile. A3: in `ledger-file-browser-screen/index.tsx`, `handleCreate` sets `createInFlightRef` (`:427`), then awaits the folder listing with `network-only` and no abort or timeout (`:432-449`). After that it closes the dialog and runs `createLedgerFile` (`:451`), then opens the editor (`:467, 480-485`). Cancel (`:722`) only hides the dialog and never voids the attempt. Steps: type `sub/notes`, tap Create, tap Cancel before the listing returns. The commit `create sub/notes.bean` still lands and the editor opens. Meanwhile Create looks enabled, but extra taps do nothing, with no spinner. On a hung server, reopening the dialog doesn't help until the request settles.

Code-level at `main` `ebb642e45`, from the regression audit of `ff5574928`. Not driven natively.

## Fix

Keep an attempt id or a cancelled flag in a ref, and skip the create after the `await` if the dialog was cancelled. Bound the lookup, for example with `CONNECTION_TIMEOUT_MS`, and show a busy, disabled Create while it runs.

**Acceptance:** Cancel during the lookup creates nothing and opens nothing.

## Dedupe

This is a follow-up to w21/222 (done); w21/357 is the same dialog's VoiceOver escape. Searched `.pm/**` for createInFlightRef, knownExisting, listingHasFile and "new file" with cancel.

Fixed. Each New File attempt takes a number, and Cancel (`cancelCreate`) moves the counter on, frees the in-flight lock and closes the dialog, so an attempt still waiting on the folder lookup finds itself void after the `await` (checked on every outcome of the lookup, before the dialog closes and before `createLedgerFile`) and returns: nothing is created and no editor opens. The lookup is bounded by `CONNECTION_TIMEOUT_MS` (8 s) with `settleWithin`; past the bound, as for an unreadable folder, the server stays the judge, as w21/222 already decided. While the lookup runs the dialog's Create is disabled and marked busy (`TextInputModal` gained a `busy` prop that disables Confirm and sets `accessibilityState.busy`), and reopening the dialog works at once because Cancel releases the lock. Tests (`ledger-file-browser-screen/__tests__/cancel-create.test.ts`: the cancel handler, the post-lookup guard placed before the dialog closes, the bound and the busy wiring; two pinned dialog tests updated for the new `validation !== true || busy` and the second `setCreateModalVisible` call; three fail with the screen and modal reverted). Deviation: the abandoned request itself is not aborted (it finishes or fails on its own), and no spinner was added beside the dimmed Create. Not driven natively.
