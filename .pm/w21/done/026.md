# Transaction Filters raises a duplicate-key error when a reversed custom range shows its message

**Severity:** minor. **Estimate:** 10–15 minutes. Owner: mobile. A2: the live text-size fix (`42572c825`) keyed several Filters labels on `fontScale`. Two of them are siblings in the Date range section, so React logs "Encountered two children with the same key, `1`" the moment the validation message appears. React treats duplicate keys as unsupported: on a later re-render the section title or the message can be duplicated or dropped.

Environment: `main` at `6747b4c00` (Metro from the main checkout), dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0), default text size (`fontScale` 1).

## Repro

1. Transactions → filter icon → Date range **Custom**.
2. Set START to 2027-01-20 (after END 2026-10-20) → Confirm.
3. "End date must be on or after the start date." appears, as intended, and a LogBox **Console Error** appears with it: *"Encountered two children with the same key, `1`"*, source `transaction-filters-screen.tsx (364:13)`.

## Root cause

`mobile/src/screens/transaction-filters-screen/transaction-filters-screen.tsx`, Date range section (lines 332-372). The section `View`'s children include `<Text key={fontScale} style={styles.sectionTitle}>` (line 333) and, conditionally, `<Text key={fontScale} style={styles.rangeError} testID="filter-range-error">` (line 365). Both keys are `1`. The rows above already namespace theirs (`start-${fontScale}`, `end-${fontScale}`).

## Fix

Namespace the two keys, for example `` `range-title-${fontScale}` `` and `` `range-error-${fontScale}` ``. While there, give each keyed `Text` in this file a distinct prefix, so a future sibling can't collide. Optionally extend the m37 font-scale test so it fails on two identical `key={fontScale}` siblings in one parent.

**Acceptance:** the repro shows the message with no console error. A live text-size change while the message is visible still remeasures both texts. The unit suite passes.

## Dedupe

Introduced by `42572c825` (w2/m37 live remeasure, done). Searched `.pm/**` for duplicate key and "same key". No item. The other `key={fontScale}` users (`account-picker-screen.tsx`, `dashboard-card`) key texts under different parents and don't collide.

**Resolved 2026-10-20** — Every `fontScale`-keyed element in `transaction-filters-screen.tsx` now has its own prefix (`range-title-…`, `range-error-…`, `status-title-…`, `account-title-…`, `chip-…`, `header-reset-…`, `header-close-…`, `account-row-…`, `apply-…`), alongside the existing `start-` and `end-`. The section title and range error no longer share key `1`, and both still remount on a live size change. `font-scale-key-collisions.test.ts` scans every `.tsx` under `src` and fails when one parent's children, looking through conditionals, repeat a `fontScale` key expression.
