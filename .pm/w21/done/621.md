# Edit Transaction lacks w21/342's web-view recovery: if iOS kills the editor's web view, the draft resets and the last shortcut is inserted again at the top

**Severity:** minor (silent loss of an in-progress edit). **Estimate:** 20 minutes. Owner: mobile. A3 (code-level at `main` `ab6c875a9`): `edit-transaction-screen.tsx:567-577` passes no `onReady` or `onDraft` to the DOM editor, and `insertSpec` (set at `:459`) is never cleared. The file editor has this wiring (`ledger-file-editor-screen/index.tsx:1098-1099`). After a WebContent crash, the editor reloads the original slice, re-applies the stale `insertSpec` at position 0, and drops later keystrokes as stale revisions while Save stays enabled. w21/342's resolution names this as "Not covered … a follow-up", but nothing was filed.

Native (iPhone 17e, w21/342's technique; nothing saved, then discarded): Transactions ▸ FARMERS MARKET ▸ pencil, focus the end of line 3, and tap the "!" key ("USD!"). Then `kill -9` the editor's `com.apple.WebKit.WebContent`, the child of `launchd_sim` that started when the editor opened. The editor reloads the *original* slice (no "!") while Save stays enabled. Tapping ":" next shows "USD!" again: the stale `insertSpec` was re-applied, and the ":" never appeared.

## Fix

Reuse the file editor's recovery: `onReady`/`onDraft` to restore the draft, and clear `insertSpec` after it's applied.

**Acceptance:** after killing WebContent mid-edit, the draft survives and nothing is re-inserted. A test covers the recovery wiring.

## Dedupe

Named as a follow-up in w21/342 (done). Searched `.pm/**` for onReady, onDraft and createEditorRecovery.

---

**Resolved 2026-10-22** — Edit Transaction now has the file editor's web-view recovery (`edit-transaction-screen.tsx`): an `editor-recovery` instance records the loaded slice, the editor's draft and the saved text; `onReady`/`onDraft` put the draft back under a new epoch with a restarted revision tracker when the page announces itself a second time; and `insertSpec` is cleared once the editor has made the edit, on reseed and on reload, so the last shortcut is not applied again. Source-check tests pin the wiring (the recovery rules themselves are in `editor-recovery.test.ts`); the native kill-the-WebContent check was not run here. Shipped in the commit that moves this note (`mobile`).
