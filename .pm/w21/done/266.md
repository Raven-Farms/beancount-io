# Reports' Recent transactions says "No transactions yet" whenever the income statement is loading or has failed

**Severity:** minor-to-moderate. **Estimate:** 20 minutes. Owner: mobile. A3: the card filters the journal by a month anchor taken from the income statement. While the statement is loading or after it fails, the anchor is `null`, and `selectAccountTransactions` returns `[]` for every range except ALL. The card shows its loading tile only while its *own* journal query loads, so once the journal is in it renders the empty-state "No transactions yet". An empty range (YTD on a stale ledger, a 1M month with only transfers) reads the same, where Cash flow says "No cash flow in this range".

Code-level at `main` `de881e646`. Run under Node on three Income/Expenses transactions: `selectStatementAnchorMonth(undefined, …)` returns `null`, and `selectAccountTransactions` gives 0 rows for 1M, 6M, YTD and 1Y, and 3 for ALL.

## Root cause

- `mobile/src/screens/reports-screen/reports-screen.tsx:122-130`: `anchorMonth` comes from the statement.
- `selectors/select-account-transactions.ts:67-69`: a null anchor returns `[]`.
- `components/account-transactions-card.tsx:122-127`: shows `recentTransactionsEmpty`.

## Fix

Pass the statement's state into the card: show the loading tile while the anchor is null and the statement is loading. When the statement failed, fall back to the newest matching entry's month, or show the card's failure state, never the empty text. Use range-aware empty copy ("No transactions in this range").

**Acceptance:** with the statement failing, the card shows either rows or a failure state, never "No transactions yet". An empty range reads "No transactions in this range". Unit or source checks are added.
