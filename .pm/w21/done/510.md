# A resumed Create Ledger draft demands an opening balance "again" when none was ever entered (w21/500 false positive)

**Severity:** low. **Estimate:** 15 minutes. Owner: mobile. A3: `mobile/src/screens/create-ledger-screen/create-ledger-screen.tsx:318` sets `amountLost` whenever the draft has an opening account. Then `openingAmountOwed` (`setup-presets.ts:185-191`) blocks Next even when the amount was blank, which the form labels "(optional)" and which is a valid setup that sends no opening line.

Native (iPhone 17e; no ledger was created):
1. Create Ledger, step 2. Choose Assets:Bank and leave "Opening balance (optional)" blank.
2. Kill the app, relaunch, and reopen Create Ledger (the draft resumes).
3. Tap Next.

It stays on step 2, with a red error under the empty field ("Enter the opening balance again… It is not kept in the saved draft."). To go on, the user has to invent an amount or switch to Decide later. The draft was put back to Decide later afterwards.

## Fix

Store in the draft whether an amount had been typed (a boolean, not the amount), and set `amountLost` only then.

**Acceptance:** a blank-amount draft resumes and Next reaches Review with no opening line. A draft whose amount was typed still asks for it. Unit cases are added.

## Dedupe

False positive of w21/500 (done). Searched `.pm/**` for amountLost and "opening balance again".

---

**Resolved 2026-10-22** — the draft now stores a flag for whether an opening amount was typed (never the amount); a resumed draft with a blank optional amount keeps its step and no longer demands the balance again, while a typed one (and a draft saved before the flag) still does. Unit cases in `create-ledger-draft.test.ts` (`mobile`).

Native recheck (iPhone 17e, fresh Metro `--clear` with `400ceda21`, second launch; no ledger created): Create Ledger ▸ Preset ▸ Personal ▸ Next ▸ opening account Assets:Bank, with "Opening balance (optional)" left blank. After killing and relaunching the app, Create Ledger resumes at step 2, and Next goes straight to Review (step 3) with no "Enter the opening balance again" error. Fixed. The draft was set back to "Decide later" afterwards, and Create was never tapped.
