# Coming back to the file editor jumps the cursor to the original error line and opens the keyboard

**Severity:** minor. After working elsewhere in a file and visiting View errors, Back scrolls the user away from where they were editing. **Estimate:** 15 minutes. Owner: mobile. A3: a `useFocusEffect` re-applies the route's `initialLine` on every focus, and the jump calls `view.focus()`. The comment says the re-arm exists so a repeated deep link re-jumps, but it also fires on any ordinary return to the screen.

Code-level at `main` `6a478b53f`.

## Scenario

1. Open a file from a Notifications error row; it jumps to line N.
2. After more than 3 s, edit near the end of the file and save something that adds an error.
3. In the "Save left errors" alert, tap View errors, then Back.
4. The cursor and scroll position jump back to line N, and the keyboard opens.

## Where

- `mobile/src/screens/ledger-file-editor-screen/index.tsx:626-633` (and `:437`)
- `mobile/src/components/code-editor/code-editor.tsx:198-206, 451-456`

## Fix

Re-arm the jump only when the route's `initialLine` param or deep-link nonce actually changes, not on every focus. Alternatively, clear the param with `router.setParams` after the first jump.

**Acceptance:** in the scenario, Back keeps the cursor and scroll where the user left them. Opening the same error link again still jumps.

## Dedupe

w4/034 and w4/022 are unrelated editor items. Searched `.pm/**` for initialLine, jumpToLine, useFocusEffect and re-arm.

**Resolution (2026-10-21):** the editor's jump re-arms from a `useEffect` on the `initialLine` param instead of `useFocusEffect`, and clears the param once taken (`router.setParams({ initialLine: undefined })`). An ordinary return to the screen, such as Back from View errors, leaves the cursor and scroll alone, while a link opened again sets the param anew and still jumps. Test: `ledger-file-editor-screen/__tests__/jump-rearm.test.ts` (fails with the screen reverted). Not exercised natively.
