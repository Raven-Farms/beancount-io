# A failing balance assertion looks exactly like a passing one in account detail: the ledger service always sends `diff_amount: null`, so w21/050's "Off by" line never renders

**Severity:** moderate. The one balance row a user most needs to notice is indistinguishable from the others. **Estimate:** 1–2 hours. Owner: ledger (serializer), plus a mobile check. A3: w21/050 added an error-styled "Off by X" detail to Balance rows, built from `diff_amount`. But the rustledger serializer hard-codes `diff_amount: null`, so the line can never appear.

Reproduced natively on the iPhone 17e simulator (iOS 27.0), dev build 1.20261002.50, `main` at `8e6023f62`, on the disposable QA ledger. Restored byte-for-byte to `f1a0b83c`.
- I appended `2026-10-01 balance Assets:Cash  50.00 USD`; the account holds 49.75.
- `getLedgerErrors` correctly reports "Balance failed for Assets:Cash: expected 50.00 USD, got 49.75 USD", and the bell shows 1.
- Accounts → Cash lists **"Assets:Cash · Balance · Balance 50.00 USD · $0.00"** for 1 October. That is styled exactly like the passing 29 August row "Balance 49.75 USD", with no "Off by −0.25 USD" and no error colour.

## Root cause

- `backend-cluster/ledger/src/foundation/rustledger/journal-serialize.ts:240` and `ledger-legacy-journal.ts:143` emit `diff_amount: null`. The comment at `journal-serialize.ts:50-54` says the failed-assertion diff "is a beancount balance-check artifact rustledger's `DirectiveJson` does not expose".
- The validator already computes the difference: its error text carries both the expected and the actual amount.
- `mobile/src/screens/account-detail-screen/selectors/select-account-journal.ts:206` reads `raw.diff_amount`. Its test feeds a non-null value the server never sends.

## Fix

In the journal serializer, join each Balance directive with its balance-check error (same date, account and currency), and fill `diff_amount` as actual − expected. Do it for all journal reads, and so for REST, GraphQL and MCP alike, per the parity rule. Add a ledger serializer test with a failing assertion. The mobile renderer from w21/050 then shows the line unchanged, and the dashboard's account journal gains it too.

**Acceptance:**
- `getLedgerAccountJournal` for the fixture returns `diff_amount: {number: "-0.25", currency: "USD"}` on the 1 October row.
- Mobile account detail shows "Off by −0.25 USD" in the error colour.
- Passing assertions keep `null`.

## Dedupe

w3/556 (done) added the asserted `amount` and recorded `diff_amount` as always null under rustledger, without filing the gap. w21/050 (done) is the mobile renderer; its native recheck didn't exercise a failing assertion. Searched `.pm/**` for diff_amount and "off by". No open item.

**Resolved 2026-10-21** — Shipped in the commit that moved this note (`backend-cluster/ledger`). rustledger's `DirectiveJson` has no failed-assertion diff, but its validator reports each failure as an `E2001` error: "Balance failed for A: expected X C, got Y C", with file and line but no date. The new `failedBalanceDiffs(directives, errors)` (`journal-serialize.ts`) joins those errors back onto the Balance directives by account and asserted amount (compared numerically), and fills `diff_amount` with `actual − expected`, computed exactly with `bignumber.js`. A key shared by more assertions than errors stays `null`, so a passing assertion is never marked failed. `serializeDirective` takes the diffs, and every journal read passes them: `getJournal`, `getAccountJournal`, `getContext` and the V1 legacy journal. REST, GraphQL and MCP all read through these, and the field already exists on every surface. Checked against the live WASM engine on the note's fixture: the 1 October row returns `diff_amount: {number: "-0.25", currency: "USD"}` and the passing 29 August row keeps `null`. `failed-balance-diffs.test.ts` covers the join, numeric matching, the ambiguity guard, multi-failure pairing, non-E2001 errors and the read wiring; the wiring check fails with it reverted. The mobile renderer from w21/050 is unchanged and should now show "Off by −0.25 USD", but it was not re-checked on the simulator. Neither was the dashboard's account journal.
