# Mobile loads at most 500 budget directives, so a heavy user's oldest budget card silently disappears (mobile counterpart of w4/235)

**Severity:** moderate for heavy users. **Estimate:** 20 minutes. Owner: mobile. A3: `use-budget-groups.ts:20-27` asks for `limit: 500` (with a TODO) and never checks `total`. The server returns the newest first and slices (`ledger-journal-service.ts:670-690`). Under `tsx`, a set-once 2024 rent budget plus 25 categories revised monthly for 20 months (501 directives) returns 500, and `Expenses:Rent` is missing from both the Budget page and Home. The dashboard now pages until complete (`use-budget-entries.ts:39-61`, w4/235).

Code-level at `main` `f628d4727`.

## Fix

Page with `fetchMore` until `data.length >= total`, as the dashboard and Transactions do.

**Acceptance:** with 501 budget directives, all 26 budget cards appear.

## Dedupe

This is the mobile half of w4/235, which listed native mobile only as a follow-up. Searched `.pm/**` for BUDGET_PAGE_SIZE, "limit: 500" and truncat.

Fixed. `useBudgetGroups` (the Budget page and Home's panel) now reads every budget directive. The first page still asks for 500 and stays a watched query on the shared cache entry; when its `total` says more exist, `readBudgetPages` reads the remaining offsets (500, 1000, …) one page at a time with `network-only`, tied to the first page they follow. The groups are built only once every page is in (`loaded` is false until then, `loading` stays true), and a page that fails or comes back empty is an error with a retry (`refetch` re-reads), never a partial set that would compare against the wrong targets and drop the oldest card, the dashboard's rule from w4/235. With 501 directives the Budget page and Home show all 26 cards. Tests (`read-budget-pages.test.ts`: offsets for 1,203 directives, one extra page for 501 and none for 500, an empty page failing, and the hook's wiring; the wiring case fails with the hook reverted; the pinned today-watcher source check was updated for the new memo deps). Deviation: the extra pages are held in component state, not the persisted cache, so a heavy user with more than 500 budget directives sees the first page's budgets only after the extra pages load online (offline cold start shows an error rather than a partial list). Not run natively with 501 directives.

Native recheck (iPhone 17e, fresh Metro `--clear` at `4f32df08b`): with 502 budget directives on the disposable ledger (the oldest, `2024-01-01 … Expenses:QaOldest "monthly" 50.00 USD`, plus 501 daily `Expenses:QaMany` entries; restored afterwards), Home's panel has the row `budget-row-Expenses:QaOldest-USD` ("$0.00 of $33.87, 0% used, Below target"), so the oldest card is no longer dropped. Fixed.
