# Regression from w21/313: after any in-app write, Notifications' "Show older changes" skips a whole page of commits or disappears

**Severity:** moderate. **Estimate:** 15 minutes. Owner: mobile. A3: `notifications-screen.tsx:259-280` keeps `pagesLoaded` and `noOlder` in React state and pages with `fetchMore({ page: pagesLoaded + 1 })` (the button condition is at `:433`). `invalidate-ledger.ts:64` evicts `listCommits` on every `entries` or `file` write, and the watched query refetches page 1, so the list drops back to 30 rows while `pagesLoaded` stays at 2. Pull to refresh resets both; this path doesn't.

Under `tsx`, with a real Apollo 3.14.1 client serving 75 commits plus the screen's own `fetchMore`/`appendCommitPage`/`isLastCommitPage` and the real `invalidateLedgerData`:
1. Show older → 60 rows.
2. An editor save and Back → 30 rows, with `pagesLoaded` still 2.
3. The next Show older → 46 rows; **30 commits are skipped** (46..17).

After paging to the end, any quick add drops the list to 30 rows with **no Show older button**. A remount shows the merged list, which then shrinks to 30.

Code-level at `main` `3440909ec`. Not driven natively (the error-fix-and-return path needs an editor edit).

## Fix

Derive the page count from what's shown (`Math.ceil(commits.length / COMMITS_PAGE_SIZE)`), or reset `pagesLoaded` and `noOlder` whenever `listCommits` comes back with exactly one page. A `typePolicies` merge or offset-based paging also works.

**Acceptance:** after Show older, a save elsewhere, and Show older again, no commit between the pages is missing, and the button reappears after a reset to page 1.

## Dedupe

This is a regression from w21/313; w21/035, 072, 353 and 419 cover other screens. Searched `.pm/**` for pagesLoaded, "Show older", notificationsShowOlder and fetchMore.

Addendum (Files review, code-level at `f651bd704`): the gap also needs no write. The app's foreground refresh (`refetchQueries({include:"active"})`) drops the list back to its first page while `pagesLoaded` stays 2. The next Show older then skips a page (sha60 to sha31 in the reviewer's run of Apollo 3.14.1 under tsx).

Resolved. Show older no longer keeps a page counter beside the list. The page to ask for is derived from the rows shown (`shownCommitPages`, rounding up so a commit listed once across a shifted page still counts as its page), and the end is remembered as the page that came back short (`lastPage`), so the button shows only while the list is still at or past it. A write or a foreground refresh that refetches page one now makes the next Show older ask for page two again instead of skipping one, and the button reappears after the list resets. Pull to refresh and a ledger change clear `lastPage`. Covers the foreground-refresh addendum too, as no write is needed. Tests pin the derived count and the screen's wiring (the old counter is gone); the wiring pins fail against the old screen. Deviation: the Apollo behaviour was reasoned from the note's reproduction and the unit tests, not re-run under a real client or natively.
