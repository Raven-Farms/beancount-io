# Returning to the app while offline flips the file editor (and every write surface) to "read-only" mid-edit

**Severity:** moderate. Unsaved edits become unsaveable: Save disappears and the banner says "This ledger is read-only. Choose a ledger you can edit…". It only clears after a later successful refetch, in practice another background-and-foreground while online. **Estimate:** 20 minutes. Owner: mobile. A3: `useLedgerAccess` sets `canWrite` only when `!error`. The foreground refresh refetches every active query, and on a network failure Apollo 3.14 keeps the old data but sets `error`, so a transient failure reads as "no write permission".

Code-level at `main` `6a478b53f`. Not exercised natively: forcing offline needs the host's Network Link Conditioner.

## Where

- `mobile/src/common/hooks/use-ledger-access.ts:16-20`
- `mobile/src/common/hooks/use-foreground-refresh.ts:16-20`
- `mobile/src/screens/ledger-file-editor-screen/index.tsx:346-350, 689, 700-713, 770`
- Every `canWrite` consumer (Home +, quick add, Open Account, Files) hides its write actions the same way.

## Fix

Derive `canWrite` from the last known `data` and ignore a refetch error when cached permissions exist. Treat only an authorization or NOT_FOUND result as read-only. The save itself still fails, with w21/117's offline copy, if the network is still down.

**Acceptance:** with a dirty editor, background → offline → foreground leaves Save visible and the editor writable. Going back online and saving succeeds. A real permission loss still shows read-only.

## Dedupe

w21/117 is the raw offline text on save; w21/131 is the owner-case id mismatch that also clears `canWrite`. Searched `.pm/**` for useLedgerAccess, canWrite, "offline read-only" and "foreground refresh".

**Resolution (2026-10-21):** `useLedgerAccess` now answers with `selectCanWrite` (`common/ledger-access.ts`). Cached permissions survive a refetch error, and only `FORBIDDEN`, `NOT_FOUND` or `UNAUTHENTICATED` read as read-only; guests, another ledger's permissions and read-only grants are still refused. A save made while still offline fails with w21/117's offline copy.

Tests: `common/__tests__/select-can-write.test.ts` fails with the fix reverted. The `empty-ledger-actions.test.ts` cases that used a plain `Error("Offline")` as "no permission" encoded the bug; they now use an access-lost (`FORBIDDEN`) answer. Not exercised natively offline.

**Native recheck 2026-10-21:** not exercised. The simulator has no per-app offline switch, so an offline foreground can't be produced. Covered by `select-can-write.test.ts` only.
