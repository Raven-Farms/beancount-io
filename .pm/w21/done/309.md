# Option errors (E7001/E7002/E7004) carry no file or line, so their rows can't be tapped and no editor banner shows them

**Severity:** minor-to-moderate. **Estimate:** 30 minutes. Owner: ledger. A3: the engine's `getErrors()` returns option errors with `file: null, line: null, code: null`, with the code inside the message text (`"[E7001] Invalid option \"bogus_option\""`). The mapper then sets `source: null`. Beancount reports the same errors with the option's filename and line.

Code-level at `main` `ba784a628`; the null source was seen in production for the E7002/E7007 rows in w21/308. On mobile, `notifications-screen.tsx:153` marks such rows not fixable, and `filterFileErrors` never matches `main.bean`.

## Root cause

`backend-cluster/ledger/src/features/ledger/service/ledger-data-mappers.ts:42-54` (`toBeancountErrorsPublic`). Included files' options are already blanked by `neutralizeIncludedOptionsAndPlugins`.

## Fix

Relocate option errors to the matching `option` line of the entry-point file (as `reportUrlIncludes` already relocates errors), and move the `[E70xx]` prefix into `code`.

**Acceptance:** an `option "bogus_option" "x"` error has `main.bean` and its line. The Notifications row opens the editor at that line, and the banner lists it.

## Dedupe

w21/187 covers parse errors and w21/189 missing includes and E8005; neither covers options. w5/200 is CLI-only. Searched `.pm/**` for E7001 and "Invalid option".

Fixed in the ledger service, so every client inherits it. New `locateOptionErrors` (run in `parseLedgerFilesInProcess` after the option-value reconciliation) moves an option error's `[E70xx]` tag into `code`, strips it from the message, and puts the error on the entry-point file's matching `option` line: a line naming the quoted option and carrying the quoted value wins, then one naming it, then one whose value was quoted (a bad account leaf or `account type` names no option); among equals the last line, which is the one that wins and the one a duplicate is reported on. Comments never match, `[E7006]` (its own reconciliation) and errors it cannot place are left untouched. Checked against the live engine on a file with a comment and eight option lines: E7001 `bogus_option` at line 2, E7002 `render_commas`/`booking_method` at 4 and 5, E7003 `title` at its second occurrence (7), E7008 `name_assets` at 8, E7007 as a warning at 11, all with `main.bean` and their codes. On mobile that makes the Notifications row fixable and lets the editor's banner list it (`filterFileErrors` matches the file), with no mobile change.
