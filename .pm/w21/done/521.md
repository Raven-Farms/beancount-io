# The file editor's error banner drops the server's fix hint that Notifications shows (w21/424 incomplete)

**Severity:** low. **Estimate:** 10 minutes. Owner: mobile. A3: `mobile/src/screens/ledger-file-editor-screen/index.tsx:958-960` maps each error to `{ message, lineno }`, so `hint` is lost before `ErrorBanner`. `errorHint(err)` is then always null, and the row's VoiceOver label (`errorMessageWithHint`) has no hint either. The query, `useLedgerErrors` and `filterFileErrors` all carry `hint`. w21/424's tests check only the render source, so they miss this.

Native (iPhone 17e at `605af3313`, disposable ledger; the probe file and include were removed and the ledger restored byte-for-byte): `main.bean` includes `qa-20261020-latin1.bean`, a Latin-1 file. Notifications shows the error with the hint "Re-save the file as UTF-8, or remove the include that reaches it." Tapping the row opens the file in the editor. Expanding "1 error" shows the message and "line 1", but no hint.

## Fix

Keep `hint` in the map, or pass the `filterFileErrors` rows through unchanged.

**Acceptance:** the expanded banner shows the hint under the message, and VoiceOver reads it. A test renders the banner from the screen's real mapping.
