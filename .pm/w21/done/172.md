# The brand matcher treats an accented letter as a word boundary, so "Café Amazonía" gets the Amazon logo

**Severity:** minor. It's the same within-word collision the matcher guards against for ASCII ("targeted", "gapping"), but with accents. **Estimate:** 15 minutes. Owner: mobile.

Code-level at `main` `698f8aba5`. The reviewer ran `matchBrand`: "Café Amazonía" → amazon.com, "Büro Amazonē" → amazon.com, and "Amazonas Cafe" → null (correct).

## Where

`mobile/src/common/brand-matcher/index.ts:238-240` uses an ASCII-only word-character test, `/[a-z0-9]/`.

## Fix

Use a Unicode-aware boundary, for example `/[\p{L}\p{N}]/u`. Add non-ASCII test cases.

**Acceptance:** "Café Amazonía" and "Büro Amazonē" match no brand. Existing ASCII cases are unchanged.

## Dedupe

**Resolution (2026-10-21):** `matchBrand`'s word-boundary test now treats any Unicode letter, digit or combining mark as part of a word (`/[\p{L}\p{N}\p{M}]/u`, the same escapes Open Account's name check already runs in Hermes). "Café Amazonía" and "Büro Amazonē" match no brand, "Café Amazon" still matches, and the existing ASCII cases are unchanged.
