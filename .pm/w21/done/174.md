# A parent account's own postings never appear in the Accounts tree, so its children don't add up to it

**Severity:** moderate. Posting to `Expenses:Food` alongside `Expenses:Food:Groceries`, or to `Assets:Bank` alongside its subaccounts, is common. The parent then shows a total its visible children don't explain, which contradicts the table's own claim that children "always sum back to" the parent. **Estimate:** 30 minutes. Owner: mobile; the dashboard hierarchy has the same gap. A3: the tree reads only `balance_children` (the rolled-up total). The trial-balance query already fetches each node's own `balance`, and nothing renders it.

Reproduced natively on the iPhone 17e simulator (iOS 27.0) at `main` `dbfdff600`, on the disposable QA ledger, which I restored byte-for-byte to `f1a0b83c`. The fixture `; qa-20261020-tree` opened `Assets:Bank USD` and added `2026-09-02` "QA OWN": Assets:Bank +200.00 / Assets:Bank:Checking −200.00. Accounts → Assets → Bank reads **"$17,202.01"**, with children **Savings $10,500.00** and **Checking $6,502.01** (together $17,002.01). The $200 held on Bank itself has no row and no note.

## Where

- `mobile/src/components/account-list/select-account-list.ts:130` (reads `balance_children` only)
- `mobile/src/components/account-table/account-table.tsx:455` (the "sum back" claim)
- The dashboard has the same at `dashboard/src/features/reports/balance-sheet/hierarchy-list.tsx:209`.

## Fix

When a node has children and a non-zero own `balance`, add a synthetic child row ("Bank (own)") with that balance, tappable to the parent's own journal, or a note under the parent. Keep folding rules unchanged; a parent with own postings is already never folded away.

**Acceptance:** with the fixture, Bank expands to Savings $10,500.00, Checking $6,502.01 and "Bank (own)" $200.00. Add a selector unit test.

## Also: the same defect on Reports' breakdown cards (added 2026-10-21)

`mobile/src/screens/reports-screen/selectors/select-ranged-account-tree.ts:81-110`: `rollup` adds each node's own sum into `balanceChildren`, but `toTreeNode` doesn't keep it. Reading the trial balance's own `balance` (this item's proposed fix) won't reach Reports, whose tree has no own-balance field.

A reviewer's Node run on Expenses:Food 50 (own), Food:Groceries 100 (own), Groceries:Costco 60, Food:Dining 30 and Rent 1000 gives:
- Food reads **240**, while its children add to 190.
- Expanding Groceries (160) shows only Costco 60.
- No "(own)" row appears at either level.

Carry each node's own sum on the tree node, so the synthetic "(own)" child serves both trees.

**Resolution (2026-10-21):** fixed in the shared account-tree selector (`components/account-list/select-account-list.ts`). A node with sub-accounts and a non-zero own `balance` gets a synthetic `own` child carrying that balance and the parent's account (tapping opens the parent), so the rows beneath a parent add up to it. A parent holding its own money is never folded as a pass-through.
- **Accounts tab:** reads the trial balance's own `balance` and shows "{name} (own)" (`accountOwnPostings`, 13 locales) under a row key of its own. The fixture's Bank now reads Savings $10,500.00, Checking $6,502.01 and Bank (own) $200.00.
- **Reports (addendum):** `selectRangedAccountTree` now carries each node's own sum as `balance`, so the same rows appear on the breakdown cards. The reviewer's case gives Food 240 = Groceries 160 + Food (own) 50 + Dining 30, and Groceries 160 = Groceries (own) 100 + Costco 60. Own rows get a distinct testID, and Cash flow now counts a parent's own amount at deeper levels.

Tests: `select-account-list.test.ts`, `select-ranged-account-tree.test.ts` and `flatten-rows.test.ts` fail with the change reverted. The `below-fold-test-ids` guard was updated for the label and testID shape. Deviation: the dashboard hierarchy's same gap was not changed. Not re-run natively.

**Native recheck 2026-10-21** (iPhone 17e, iOS 27.0, `main` `817c05ae8`, Metro restarted with `--clear`; the original tree fixture): **not fixed on the Accounts tab.** Bank lists Savings and Checking only, with no "(own)" row. The bundle includes the change. The cause is that `graftZeroAccounts` clones nodes without `balance`. Filed as w21/331. Reports wasn't checked natively.
