# Clearing Create Ledger's "Books begin" brings back w21/051: the server's UTC fallback opens accounts tomorrow in the evening across the Americas

**Severity:** moderate. **Estimate:** 10 minutes. Owner: mobile (plus backend-v2). A3: `create-ledger-screen.tsx:359` sends `historyStart: values.historyStart || undefined`, and `setup-presets.ts:213` accepts empty as "today". The server falls back to `new Date().toISOString().slice(0,10)` (`backend-v2/.../setup/build-ledger.ts:57, 100, 114`). Under `tsx` with `TZ=America/Los_Angeles` at 22:30 on 2026-10-21, the sent value is `undefined` and the server date is `2026-10-22`. The real `previewLedgerSetup({preset:"personal@1"})` run at 20:19 PDT returned `2026-10-22 open Assets:Bank USD`. The first entry dated today is then refused against an inactive account, and Review doesn't show the date.

Code-level at `main` `9bd067834`.

## Fix

Send `values.historyStart.trim() || defaultHistoryStart()`, and replace the backend's UTC fallback with a local or explicit date.

**Acceptance:** a cleared Books begin in Los Angeles at 22:30 opens accounts on today's local date.

## Dedupe

w21/051 (default only), w4/317 (dashboard), w21/330 (spaces) and 365 (digits) differ. Searched `.pm/**` for "Books begin", historyStart, toISOString and empty.

Resolved on the mobile side. `setupFields` now sends the phone's local day when "Books begin" is cleared, instead of leaving it for the server to fill with the UTC date; the Review preview and the create both go through it, so accounts open on today's local date at 22:30 in Los Angeles. A typed date still wins. Tests pin a blank field at 22:30 local and the typed-date case, and fail against the old rule. Deviation: the backend-v2 UTC fallback is unchanged; it serves clients that send no date (REST/GraphQL/MCP callers) and the server cannot know a caller's time zone, so replacing it is a contract decision for the API owner rather than something to slip into this fix. No native run.

Native recheck: not exercised. The fixed date only appears in the accounts a created ledger opens; Review doesn't show it, and this run doesn't create ledgers. (The run was at 23:35 local time, when UTC is already the next day, so a create would have shown it.) It rests on the `setupFields` tests.
