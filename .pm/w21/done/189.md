# A missing `include` shows raw engine text ("…file not found in virtual filesystem…") with no tap target

**Severity:** minor. The Notifications row reads "failed to read file X: file not found in virtual filesystem: X", leaking an internal term, with no file or line, so it can't be tapped. In a subfolder it names the resolved path, not what the user typed. **Estimate:** 30 minutes. Owner: ledger. A3: the engine reports a `LOAD` error with `file: null`. `reportUrlIncludes` (w4/017) already finds the including file and line for URL includes but skips plain paths. Upstream `bean-check` gives no line either (`<load>:0`), so this is about diagnostic quality, not parity.

Code-level at `main` `789588341`; the reviewer ran the engine. Plugin errors without a locator (E8005, amortize and forecast) behave the same way.

## Where

`backend-cluster/ledger/src/foundation/rustledger/url-include-errors.ts:44-80` (URL includes only).

## Fix

Extend the include relocation to plain paths: point the error at the including file and the `include` line, quote the path as written, and replace "virtual filesystem" wording with "included file not found".

**Acceptance:** `include "qa-missing.bean"` in `main.bean` yields an error located at that line, reading "Included file not found: qa-missing.bean", and it's tappable on mobile.

## Dedupe

w4/017 covers URL includes; w2/m26/t001 covers renames. Searched `.pm/**` for "failed to read file", "virtual filesystem" and "missing include".

**Resolution (2026-10-21):** `reportUrlIncludes` (`rustledger/url-include-errors.ts`) now relocates a missing plain-path include too, not only URLs. The error points at the including file and the `include` line, quotes the target as written, and reads "Included file not found: <target>" in place of the engine's "failed to read file X: file not found in virtual filesystem: X". Run on the real engine, `include "qa-missing.bean"` gives that message at `main.bean:2`, and a nested `include "../typo.bean"` gives it at `books/jan.bean:1`, as written rather than as resolved. Because the located error comes from the shared snapshot, every surface and mobile's Notifications row (tappable on a file and line) get it. URL includes are unchanged. Tests: `rustledger/__tests__/url-include-errors.test.ts`. Two of its cases pinned "a missing repository include is left untouched" and were rewritten. A missing file nothing includes stays untouched. Plugin errors without a locator (E8005) are not addressed. Needs a ledger deploy.
