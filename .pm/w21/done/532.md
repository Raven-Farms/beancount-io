# Account detail's "Off by" amounts land on the wrong balance assertion when the file isn't in date order

**Severity:** minor (a wrong figure on a reconciliation screen). **Estimate:** 20 minutes. Owner: ledger. A3: `backend-cluster/ledger/src/foundation/rustledger/journal-serialize.ts:276-281` pairs failed-balance errors with assertions by position. When several failing assertions share an account and amount, the errors are sorted by file and line, but the assertions are sorted by date. `failed-balance-diffs.test.ts:72` covers only a file whose line order matches its date order.

Production (2026-10-22, disposable ledger, restored byte-for-byte): `Liabilities:QaCard` gets −40.00 on 01-03, `balance 0.00` on 02-01, +15.00 on 01-20, then a backdated `balance 0.00` on 01-10 appended last. `getLedgerErrors` is right: line 97 (01-10) "got −40.00" and line 93 (02-01) "got −25.00". But `getLedgerJournal(directiveTypes:["Balance"])` gives 02-01 `diff_amount` −40.00 and 01-10 −25.00, swapped. Mobile's account detail shows each row's "Off by" from that field (`select-account-journal.ts:273`). Two included files whose filename order and date order disagree behave the same way.

## Fix

Pair errors with assertions by source location (file and line), not by sorted position.

**Acceptance:** with that fixture, 01-10 reads −40.00 and 02-01 reads −25.00. A test covers out-of-order lines and two included files.
