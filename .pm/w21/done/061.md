# Create Ledger suggests USD for Bulgaria (euro since 2026-01-01), Ukraine, Romania, Czechia and other regions: mobile's hand-rolled currency list diverges from the setup catalog

**Severity:** minor. **Estimate:** 20–30 minutes. Owner: mobile. A1/A3: ADR021 suggests the operating currency from the device region. Mobile hard-codes a 20-country euro set plus 22 region→currency pairs, and falls back to USD for everything else. The canonical setup catalog, which the hosted builder and `bea init` share (`backend-cluster/backend-v2/src/features/ledger/setup/currencies.json`, mirrored in `cli/src/bea_engine/setup_currencies.json`), maps 248 regions. The two disagree: a Bulgarian user, in a locale the app ships, is offered **USD** instead of **EUR**.

Environment: `main` at `5189bf519`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). The simulator region was set to `bg_BG` and restored to `en_US`. No ledger was created, and the resulting draft was cleared.

## Repro (observed)

Region bg_BG → relaunch → ☰ → **+ New** → **Preset** → **Next**. **Operating currency: USD**. The catalog says `"BG": "EUR"`.

Under Node, the shipped `suggestCurrency` returns USD for `BG`, `AD`, `MC`, `ME`, `SM`, `VA` and `XK` (all euro users) and for `UA`, `RU`, `CZ`, `HU` and `RO`. The catalog maps them to EUR, UAH, RUB, CZK, HUF and RON.

## Root cause

`mobile/src/screens/create-ledger-screen/setup-presets.ts:135-193`: a local `EUROZONE` set (20 members, missing Bulgaria's 2026 accession) and a 22-entry `REGION_CURRENCY`, both separate from the catalog that ADR021 makes the cross-engine source of truth.

## Fix

Generate mobile's table from the canonical `currencies.json` `regionCurrency` map, or copy it as a checked-in JSON with a parity test against the backend file, the way the CLI mirrors it. Keep `suggestCurrency`'s signature and the USD fallback only for regions the catalog lacks. Add `BG→EUR` and the euro-using non-members.

**Acceptance:** `suggestCurrency("BG")` is EUR, `UA` is UAH and `RO` is RON. A parity test fails if mobile's table and the catalog drift.

## Dedupe

Searched `.pm/**` for suggestCurrency, region currency, eurozone and Bulgaria. No item. Adjacent: the dashboard's `features/ledger-list/lib/setup-presets.ts:210-216` has the same hand-rolled `EUROZONE`/`REGION_CURRENCY` shape and likely the same gaps (separate package).

---

**Resolved 2026-10-21** — Shipped in the commit that moved this note (`mobile`). `suggestCurrency` now reads `regionCurrency` from `mobile/src/screens/create-ledger-screen/setup-currencies.json`. That file is a byte-identical copy of the canonical `backend-cluster/backend-v2/src/features/ledger/setup/currencies.json`, the same mirroring the CLI uses. The hand-rolled `EUROZONE` and `REGION_CURRENCY` are gone. `BG` gives EUR, `UA` UAH, `RO` RON and `XK` EUR, while a region the catalog has no row for (`AQ`) and anything malformed still fall back to USD. A drift test in `setup-presets.test.ts` compares the copy to the catalog, skipping when the backend isn't in the checkout, and fails when one region is edited. The dashboard's similar list is a separate package and was not touched.

Not checked on the simulator.
