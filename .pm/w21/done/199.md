# A Files link to a ledger you can't read opens your *current* ledger's same-named file, editable

**Severity:** minor-to-moderate. Following `…/ledger/<other-owner>/<ledger>/files/blob/main/main.bean` for an unreadable ledger sends the user to Safari. On returning, the app shows *their own* ledger's `main.bean`, titled only "main.bean", with Save enabled when writable. Even for a readable ledger, the previous ledger's same-path file shows briefly, with Save, until the switch lands. **Estimate:** 30 minutes. Owner: mobile. A3: the app-link resolver builds the editor href as `params: { path }` with no `ledger` binding. Account, entry and commit links carry `ledger=<owner/name>` and show an "unavailable" state on a mismatch. The editor follows the ambient `ledgerVar`, and `+native-intent` navigates before `openAppLinkTarget`'s readability check.

Code-level at `main` `2e12638c6`. The reviewer ran `rewriteSystemPath` at unit level: `beancount:///ledger/stranger/private/files/blob/main/main.bean` → `/ledger-file-editor?path=main.bean`, while the account, entry and commit links include `&ledger=stranger%2Fprivate`.

## Fix

Add `ledger: ledgerFullName` to the files href, and have the editor bind it with `bindRouteLedger`, showing the unavailable state when it doesn't match the selected ledger, as the other detail routes do.

**Acceptance:**
- An unreadable-ledger file link never shows the current ledger's file. It shows the unavailable state, or leaves the user where they were.
- A readable cross-ledger link shows only the target ledger's file.
- Add a resolver unit test.

## Dedupe

w3/100 and w21/090 are about switching between readable ledgers; w21/083 is stale replay; w21/131 is owner case. Searched `.pm/**` for unreadable, files/blob, ledger-file-editor together with "ledger param", and bindRouteLedger.

**Resolution (2026-10-21):** the app-link resolver adds `ledger: <owner/name>` to a Files link's editor href, as account, entry and commit links already carry it. The editor reads it and binds it with `bindRouteLedger` against the selected ledger. On a mismatch, whether the ledger cannot be read (the selection never changes) or the switch has not landed yet, it renders the unavailable state (`fileEditorUnavailable`, 13 locales, titled with the path) and issues no request, so another ledger's same-named file is never shown or saved. Every in-app way into the editor (Files browser rows and Create, Notifications error rows, transaction detail's error shortcut) passes the ledger too. A link without the param still opens in the selected ledger. Tests: `resolve-app-link.test.ts`, and `route-param-guards.test.ts` for the binding and the in-app pushers; they fail with the resolver and editor reverted. Not exercised through a real unreadable-ledger link.
