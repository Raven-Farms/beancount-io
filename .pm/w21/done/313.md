# Notifications' "Recent changes" shows only the last 30 commits; older history can't be reached from the app

**Severity:** minor (a capability gap). QA, agent and import-heavy ledgers pass 30 commits quickly. **Estimate:** 20 minutes. Owner: mobile.

Code-level at `main` `2e850e737`: `mobile/src/screens/notifications-screen/notifications-screen.tsx:227` fixes `{ branch: "main", page: 1, limit: 30 }`. There is no `fetchMore` or "load more", and no other screen lists commits. Commit detail for older commits is reachable only through a Home feed link. The dashboard has "Load older commits" (w3/468, w4/246).

## Fix

Add a "Show older" footer that calls `fetchMore({ page: n + 1 })` and ends when a page comes back short. Or relabel the section as "Last 30 changes".

**Acceptance:** a ledger with 45 commits can reach the oldest from Notifications.

## Dedupe

w4/246 and w3/468 are the dashboard equivalents. Searched `.pm/**` for "limit: 30", fetchMore and "older commits".

Fixed. Notifications' Recent changes now ends with a "Show older changes" footer (`notificationsShowOlder`, 13 locales) once the first page of 30 is full: it asks `listCommits` for the next page with `fetchMore`, merges it by sha (`appendCommitPage`, so a commit that shifts across pages is listed once), and disappears when a page comes back shorter than 30 (`isLastCommitPage`). It shows busy while loading, keeps the rows already shown if a page fails (the button stays to try again), and a pull to refresh or another ledger starts over from page 1. A ledger with 45 commits reaches the oldest in two taps of the list: 30 + 15 (short, so the button goes). Tests in `notifications-screen/__tests__/show-older.test.ts` (the merge and last-page rules, plus source checks of the screen wiring, which fail with the screen reverted).
