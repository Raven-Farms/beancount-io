# Create Ledger: Create works while the preview is still loading, and looks enabled after the preview fails (w21/478 incomplete)

**Severity:** minor. **Estimate:** 20 minutes. Owner: mobile. A3 (code-level at `main` `a06f559aa`):
- `create-ledger-screen.tsx:417` sets `previewBlocked = startKind === "preset" && Boolean(previewError)`, which ignores the preview's loading state. On a slow network, tapping Create on Review while the preview spinner shows creates the ledger before its accounts were shown, against w21/478's own rule ("Create waits for the preview").
- `:542` disables the button when blocked, but the dimmed style (`:555`) applies only while `busy`. After a failed preview, Create stays bright and silently does nothing.
- The network-failure branch (around `:877-888`) renders `CardLoadFailure`, which has no alert role, so VoiceOver doesn't hear why Create stopped working (the "refused" branch uses `InlineError`; see w21/479).

Not run natively: the simulator can't cut or throttle the network here.

## Fix

Block on `previewLoading || previewError`, dim the label whenever the button is disabled, and render the network failure with an alert role (or `InlineError` with a Retry).

**Acceptance:** Create is visibly disabled while the preview loads or has failed, and the failure is announced. The screen's tests cover all three states.

Incomplete fix of w21/478 and w21/479 (done). Searched `.pm/**` for previewBlocked, CardLoadFailure and "Create Ledger" together with preview.
