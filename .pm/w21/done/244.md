# The drawer's ledger filter finds nothing for "my book" or a description word, where Browse ledgers finds the ledger

**Severity:** minor. The filter appears once you have 10 or more ledgers. **Estimate:** 15 minutes. Owner: mobile. A3: the drawer filter is one substring match on `owner/name`, while Browse ledgers splits the query into words and also searches the description. Both fields use the same "Search" placeholder.

Code-level at `main` `4ba42392a`. Run under Node for `qa/my-book` with description "Household budget":

| Query | Drawer | Browse ledgers |
|---|---|---|
| my book | 0 | 1 |
| book my | 0 | 1 |
| qa my-book | 0 | 1 |
| household | 0 | 1 |

"my book" is the likely query, since Create Ledger turns "My Book" into `my-book`.

## Root cause

`mobile/src/components/ledger-drawer/drawer-ledgers.ts:131-136` (`fullName.toLowerCase().includes(needle)`), against `ledger-selection/discovery-store.ts:21`.

## Fix

Reuse Browse ledgers' word-split match in the drawer, treating `-`, `_` and `/` as separators. Searching descriptions there also needs `description` in `LedgerDirectory.graphql`.

**Acceptance:** the four queries above match in the drawer. A unit test covers them.

## Dedupe

w4/049 is the drawer query lost on a tab switch. Searched `.pm/**` for drawer-ledger-filter, FILTER_FROM_LEDGERS and filterLedgers.

Fixed in mobile: the drawer's ledger filter and Browse ledgers now share one matcher, `ledgerMatchesQuery` (`common/ledger-search.ts`): every word of the query must be found in `owner/name` or the description, in any order, with `-`, `_`, `/` and `.` read as word breaks. "my book", "book my", "qa my-book" and "household" all find `qa/my-book` ("Household budget") in the drawer as in Browse; an account name or a name fragment ("qa/", "my-bo") still brings up its ledgers. To search descriptions in the drawer, the `LedgerDirectory` query now selects `description` (the generated query type and document were updated by hand to match what codegen emits; the field is already on the production `Ledger` type, and `createLedger` already returned it, so the directory refresh after creating a ledger stays typed), and `DrawerLedger` carries it. Tests: `ledger-search.test.ts` runs the four queries through both filters, plus substring, all-words, empty-query and description-less cases; the drawer cases fail with `drawer-ledgers.ts` reverted. Deviation: ledgers cached before this change lack `description` until the directory revalidates (on mount and on return to the app), so a description word finds nothing for that moment; no device run.
