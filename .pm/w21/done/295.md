# When the ledger list fails to load, the guard says "No ledger selected" and offers Create, instead of an error with Retry

**Severity:** moderate. A flaky sign-in invites the user to create a duplicate ledger, and Settings and Log out sit behind the same guard (w21/217). **Estimate:** 15 minutes. Owner: mobile. A3: `LedgerGuard` reads only `{ data, loading }` from `useListLedgersQuery`. Once the query fails, `loading` is false and there is no first ledger, so it falls through to the empty state ("No ledger selected / Create a ledger or discover one to continue") with only Create and Discover.

Code-level at `main` `c3ec33b97`. Scenario: sign in on a flaky network. The OAuth finalizer only logs the failed ledger list (`oauth-sign-in-finalizer.ts:102`) and navigates in. `ledgerVar` stays null, and the guard's own fetch fails the same way. The only recovery is backgrounding the app and returning.

## Root cause

`mobile/src/components/ledger-guard/ledger-guard.tsx:113` (`error` dropped), `:136` and `:152` (empty state).

## Fix

Destructure `error` and `refetch`. When there is no ledger, an error and no data, show `CardLoadFailure` with Retry instead of Create/Discover.

**Acceptance:** a failing ledger list shows the failure with Retry, and Retry recovers once the network is back. A unit or source check covers it.
