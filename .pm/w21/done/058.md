# In a non-USD ledger, every USD balance is relabelled in the ledger's currency: "Bank €17,202.01", and Home's net-worth chart shows a fake −98% crash

**Severity:** major (wrong currency on real balances). **Estimate:** 45–60 minutes. Owner: mobile. A1/A2: a European or Asian user whose `operating_currency` is EUR, GBP or JPY and who also holds a USD account sees that account's dollars printed as their own currency. `resolveCurrencyBalance` falls back to the map's **USD** entry whenever the operating currency is absent, and the caller formats the number with the operating currency's symbol. The parent rows are computed correctly ("1 not in total"), so the screen contradicts itself. On Home, history points that predate the first EUR posting are USD values read as EUR, so net worth appears to collapse.

Environment: `main` at `f87fc7771`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). QA account, synthetic disposable ledger `mcp-agent-eval` with `option "operating_currency"` switched from USD to **EUR**, plus one EUR account seeded with 200.00 EUR. Every other account stayed USD. Restored byte-for-byte afterwards.

## Repro (observed)

1. **Accounts:** Assets reads **€200.00 · 1 not in total**, which is correct. Its children read **Bank €17,202.01**, Qa…Eur €200.00 and **Cash €49.75**. Liabilities shows **CreditCard:Visa −€143.25**, Income **−€8,000.00** and Expenses **€4,091.49**. All are USD amounts with the € symbol, and the children sum to far more than their parent.
2. **Home → Net Worth 6M:** **€200.00 · 1 not in total**, change **−€12,984.51 (−98.48%)**, and a chart that plunges at the right edge. The earlier points are the USD net worth read as EUR.

## Root cause

`mobile/src/common/balance-util.ts:37-63`: `operatingKey(map, currency)` returns `"USD"` whenever `currency` isn't a key of the map, not only for an empty map. `resolveCurrencyBalance` then returns that USD number, and callers format it with `currency`. Affected callers include the Accounts tree (`components/account-list/select-account-list.ts` `toNode`), the Home series (`home-screen/selectors/select-balance-sheet-series.ts`), the account journal rows and section totals (`account-detail-screen/selectors/select-account-journal.ts:~206-210, :275`) and the Reports tree (w21/038). A Node run of `selectBalanceDisplay({USD:"50.00"},{USD:"50.00"},"EUR")` returns `{kind:"money", value:50, notInTotal:[]}`: €50 with no disclosure.

## Fix

Drop the USD fallback for non-empty maps. A map that lacks the operating currency contributes **0** in that currency, and its other currencies go to the existing "not in total" disclosure. A single-commodity account keeps its units display (`selectBalanceDisplay` already supports `kind: "units"`), so Bank reads "17,202.01 USD". Keep the empty-map case returning 0 under the operating currency. Re-check every `resolveCurrencyBalance` and `operatingKey` caller, and have each format with the key it actually read from.

**Acceptance:** with the probe ledger, Accounts shows the USD accounts in USD units (or excluded and disclosed), never with €. Assets equals the sum of its €-denominated children. Home's history shows no fake crash. A USD-operating ledger is unchanged. Unit tests cover `{USD}` under EUR, `{EUR, USD}` under EUR and `{}`.

## Dedupe

w21/038 (open) has the same function as its root but the inverse symptom: a USD ledger *drops* EUR spending in Reports. Fixing `resolveCurrencyBalance` once should close both, so link the fixes. w2/047 (done) covered non-USD running balances. Both selector reviews this session flagged the fallback; this item is the native confirmation. No other item.

**Resolved 2026-10-21** — Shipped in the commit that moved this note (`mobile`). `operatingKey`, the "USD when the currency is missing" fallback, is removed. `resolveCurrencyBalance` now reads only the active currency, so a map without that currency contributes 0. The map's other holdings go to the existing `notInTotalOf` disclosure. `selectBalanceDisplay` gives a lone USD balance under EUR its own units ("50.00 USD"), so Bank reads in USD rather than €. Home's history points that predate EUR read 0 instead of USD-as-EUR. The account journal reads each map in the active currency only. The Reports tree discloses the other currency per w21/038 instead of adding it in. A USD-operating ledger is unchanged, and a ledger with no `operating_currency` still defaults to USD through `getPrimaryCurrency`.

Tests that pinned the fallback now assert the new behavior. They cover `{USD}` under EUR, `{EUR, USD}` under EUR and `{}` (`balance-util`, `balance-display`, `series-util`, the account list, the balance-sheet series, the account journal and balance series, and the ranged tree). Reverting the resolver alone fails six of them.

Not checked on the simulator.
