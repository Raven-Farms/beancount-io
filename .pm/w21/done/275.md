# New File refuses any name containing a dot ("2024.q1", "Jan. expenses"), though the dialog says ".bean" is added when the extension is omitted

**Severity:** minor. **Estimate:** 10 minutes. Owner: mobile.

Code-level at `main` `7f85628b8`. `checkLedgerFileName` under Node returns `{ ok: false, issue: "extension" }` for `2024.q1`, `v1.2 notes`, `J.Smith accounts`, `Jan. expenses` and `sub/2024.q1`; `notes` passes. The dialog copy is at `translations/en.ts:492-493`.

Reproduced natively on the iPhone 17e simulator (iOS 27.0), with nothing created: Files → + → paste `2024.q1` shows **"Use a .bean or .beancount name"** with Create disabled, directly under "If you omit the extension, .bean is added."

## Root cause

`mobile/src/screens/ledger-file-browser-screen/utils.ts:37`: `last.includes(".") ? last : \`${last}.bean\``.

## Fix

Add `.bean` unless the name already ends in `.bean` or `.beancount`. Keep refusing other explicit extensions (`.txt`), or show the final name ("Will be created as 2024.q1.bean").

**Acceptance:** `2024.q1` creates `2024.q1.bean`, and `notes.txt` is still refused. Unit cases are added.

## Dedupe

w21/014 (done) and w21/222 cover other name rules. Searched `.pm/**` for checkLedgerFileName, ledgerFileNameExtension and "omit the extension".

Fixed. `checkLedgerFileName` adds `.bean` to a last segment unless it is already a `.bean`/`.beancount` name or ends in a short run of letters after the last dot (1–5, read as an explicit extension): "2024.q1", "v1.2 notes", "J.Smith accounts", "Jan. expenses" and "sub/2024.q1" now create `….bean`, "notes." becomes "notes.bean", and "notes.txt", "data.csv" and "sub/readme.md" are still refused. Deviation: a name like "report.final" (a letters-only suffix of up to five) is read as an extension and refused; the note's own cases do not distinguish that. The "Will be created as" preview was not added. Tests in `ledger-file-browser-screen/__tests__/dotted-names.test.ts` (the add-.bean case fails with `utils.ts` reverted). Mobile gates and deadcode green.
