# Reports' rounded category percentages don't add up to 100% (33/33/33 = 99%, 96/5 = 101%)

**Severity:** cosmetic. **Estimate:** 10 minutes. Owner: mobile. A3: each row is rounded on its own with `Math.round(pct)` (`category-breakdown.tsx:351`), and the spoken value does the same (`select-breakdown-rows.ts:72`). Three 100 USD categories print 33% three times (99%); the w3/216 income figures print 96% + 5% (101%, which also depends on w21/370).

Code-level at `main` `d5c763aa2`. Not run natively.

## Fix

After w21/370, use largest-remainder rounding over the visible positive rows, and feed the same integers to the accessibility value.

**Acceptance:** the printed shares of the positive rows always sum to exactly 100%.

## Dedupe

Only w21/039 matched, and it is unrelated. Searched `.pm/**` for "sum to 100", "add up to 100", 101%, 99% and "largest remainder".

Fixed. `roundedShares` (largest-remainder rounding over the section's non-negative rows) gives each row a whole percent and the printed shares add up to exactly 100: three equal categories read 34 / 33 / 33 (the extra point goes to the first on a tie), and 96.4 / 4.6 read 95 / 5 instead of 96 / 5. The Reports breakdown card prints those integers and feeds the same integers to the spoken value (`breakdownRowAccessibilityValue`), so the label and VoiceOver agree; the bar width keeps the exact share; a refunded row has no share, as after w21/370. Tests (`select-breakdown-rows.test.ts`: sums of 100 for equal, uneven and many-row cases, tie and remainder placement, refunded and empty inputs, and the card wiring; the wiring case fails with the card reverted). Not run natively.
