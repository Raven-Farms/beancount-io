# Guest mode: the file editor tells a guest to "Choose a ledger you can edit", and Budget's "Set a spending target" opens sign-in without saying so

**Severity:** minor (copy and UX). **Estimate:** 20 minutes. Owner: mobile.

Code-level at `main` `3443fb319`.
- **File editor:** every non-writer, guests included, sees `ledgerReadOnly` ("This ledger is read-only. Choose a ledger you can edit to make changes.") at `mobile/src/screens/ledger-file-editor-screen/index.tsx:740-759`. A guest's drawer offers only read-only examples plus Sign In. The `guestReadOnly` string already exists.
- **Budget card:** all three public examples have no budgets (anonymous query, `total: 0`), so guest Home shows the "Set a spending target for any account" invite. Every tap target calls `guest.requestSignIn()` (`home-screen/components/budget-card.tsx:108-111, 178, 188`), which opens the system sign-in browser with no label or hint. After sign-in, the user lands on the example's Home, not Budget.

## Fix

- For guests, show guest copy in the editor ("Read-only example. Sign in to edit your own ledger.").
- In the budget empty state, show "This example has no budgets", or label the action "Sign in to set budgets" and give it an accessibility hint.

All copy is needed in 13 locales.

**Acceptance:** a guest sees no advice they can't follow, and every sign-in action says it signs in.
