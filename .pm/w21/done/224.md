# VoiceOver reads a Notifications "Recent changes" row as the commit subject only, without its author, date or SHA

**Severity:** minor. QA runs and agents often write many commits with the same subject; the bell screen above showed five "qa-20261020: mobile remove/append" rows. A VoiceOver user hears them identically. **Estimate:** 10 minutes. Owner: mobile. A3: the row's `accessibilityLabel` is the subject, and a label on a pressable replaces its children, so the visible "author · date sha" line is never read.

Code-level at `main` `9e6f6c9ba`. The visible rows were checked natively: the second line shows "‹author› · Oct 21, 2026 0530ce7".

## Root cause

`mobile/src/screens/notifications-screen/notifications-screen.tsx:332` sets `accessibilityLabel={commit.subject}`. The author line is rendered at `:346-355`.

## Fix

Build the label from the subject, plus `formatCommitAuthorLine(...)`, plus the short SHA, in the same order as the visible text.

**Acceptance:** a source or unit test shows that the row label includes the author, date and short SHA.

## Dedupe

w21/139, 140, 142 and 143 and w4/done/m7 are other accessibility labels; none covers this row. Searched `.pm/**` for `accessibilityLabel={commit`, commit.subject, and notifications combined with VoiceOver.

**Also (2026-10-21):** a commit with an empty message (possible over SSH with `--allow-empty-message`) renders a blank row. `splitCommitMessage("")` returns `subject: ""` (`formatting.ts:78`), so both the visible text and the label are empty and VoiceOver says only "button". Fall back to a localized "(no message)".

Fixed in mobile: a Notifications "Recent changes" row's accessibility label is now built by `commitRowAccessibilityLabel`, in the order the row shows: the subject, then "author · day" (`formatCommitAuthorLine`), then the short SHA (the server's `shortSha` when sent), so five commits with one subject no longer sound identical. The 2026-10-21 addendum is fixed too: a commit with an empty message shows and speaks a localized "(no message)" (`commitNoMessage`, all 13 locales) instead of a blank row, in both the Notifications row and the commit detail header. Tests: `commit-row-label.test.ts` (order, distinct labels for one subject, short-SHA and no-date cases, the empty-message fallback, and the wiring); the pinned AST counts in `commit-message-display.test.ts` were updated for the new expressions. The label cases fail with the helper reverted. Deviation: no VoiceOver run on a device.
