# Home's Spending card sums only the newest 200 transactions, so a busy month hides last month's spending

**Severity:** major. **Estimate:** 45–60 minutes. Owner: mobile. A2: "This month vs. last month" is Home's only spending figure. Any ledger with more than 200 transactions across those two months (imported bank feeds, a small business, a family budget) gets a wrong comparison, with no hint that it is partial.

Environment: `main` at `ab6f2adf7`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0), "today" = 2026-10-20. QA account on `https://beancount.io`, synthetic disposable ledger `mcp-agent-eval`. The fixture was one file write, restored byte-for-byte afterwards (sha256 checked, clean ledger check).

## Repro

1. Add to the ledger one September expense, `2026-09-15 * "qa-20261020-sep"` with Expenses:Food:Groceries 100.00 USD, and **205** October expenses of 1.00 USD each, Expenses:Food:Coffee dated 2026-10-01 to 10-20. `getLedgerErrors` stays empty.
2. Relaunch the app → Home → scroll to **Spending**.
3. The card shows **Last month ≈ $0** and **This month ≈ $200**. The true values are **$100.00** and **$205.00**.

## Root cause

- `mobile/src/screens/home-screen/components/spending-card.tsx:25,71-82`: `useGetLedgerJournalQuery` with `offset: 0, limit: SPENDING_WINDOW` (200) and no date filter, so it gets the newest 200 transactions.
- `mobile/src/screens/home-screen/selectors/select-spending-compare.ts:51-79` sums Expenses postings over whatever entries it is given. Once the newest 200 all fall in this month, last month's entries are never fetched, and this month is capped at its newest 200.
- The selector's note says there is "no expenses-only monthly time series in the API". `getLedgerIntervalTotals(accountName, interval: "month", conversion, time)` now provides one, and Budget already uses it (`budget-screen/hooks/use-budget-actuals.ts`). It rolls up sub-accounts server-side.

## Fix

Fetch the two months directly: `getLedgerIntervalTotals` for the Expenses root (`accountName` from the ledger's root names), `interval: "month"`, `conversion: "units"`, `time` = first day of last month through today. Read the two points in the active currency. Keep the card's loading, failure and `cache-and-network` behavior. If the journal path has to stay, pass `time` for the two-month window and page until `total` is reached, rather than truncating. While here, derive the Expenses root from ledger options rather than the literal `"Expenses"` prefix.

**Acceptance:** with the repro fixture, the card shows $100.00 and $205.00. On an ordinary ledger the values match Reports' monthly Expenses for September and October. A unit test feeds more than 200 entries (or mocks the interval query) and asserts both months.

## Dedupe

Searched `.pm/**` (including `done/`) for SPENDING_WINDOW, the Spending card and "this month vs last month". w4/020 (testIDs) and w2/048 (axis labels) touched this card, but not its data window. No open item.

---

**Resolved 2026-10-20** — The Spending card queries `getLedgerIntervalTotals` instead of the newest 200 journal rows. It asks for the ledger's Expenses root, with the name from `LedgerReadContext`'s `nameExpenses` (falling back to `Expenses`), `interval: "month"`, `conversion: "units"`, and `time` = the first of last month through today (`spendingWindow`). Both months come back whole with sub-accounts rolled up, and `selectSpendingCompare` reads the two months' totals in the active currency. Loading, failure and `cache-and-network` behavior are kept, and the card waits for the read context so it never queries the wrong root.

`select-spending-compare.test.ts` was rewritten for the new input. It covers the window (including January), the repro's $100 / $205, the active currency, ignoring other months, null balances, and the card's wiring, which no longer queries the journal. Mobile gates pass: format, tsc, eslint, knip, the GraphQL operations check, and 2396 unit tests. Not re-run on the simulator against the 205-transaction fixture, and not compared live with Reports.
