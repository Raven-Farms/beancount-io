# On the device, every count uses the English plural rule: Russian shows "5 ошибки", Ukrainian "2 запису", Slovak "2 chýb"

**Severity:** moderate to high for ru, uk, sk (and fr/pt at 0). It's a visible grammar error on Merchants, the file editor, the bell, Budget history, valuation notes and the VoiceOver chart summaries. **Estimate:** 45 minutes. Owner: mobile. A3: `plural.ts` picks the CLDR category with `Intl.PluralRules` and otherwise falls back to "1 → one, else other". Hermes, the app's JS engine, has no `Intl.PluralRules`. A reviewer found 0 occurrences of `PluralRules` in the shipped iOS `hermesvm`, beside 4–8 of `Intl.NumberFormat`. So the fallback always runs on device. The unit tests pass only because Jest runs under Node, which has `Intl.PluralRules`.

Reproduced natively on the iPhone 17e simulator (iOS 27.0) at `main` `6a7949ccc`, on the disposable QA ledger with five failing `balance` assertions (`; qa-20261020-err5`; restored byte-for-byte to `f1a0b83c`). With the app in Русский, Files → main.bean's banner reads **"5 ошибки"**; Russian needs "5 ошибок". The app was switched back to English afterwards.

A reviewer's comparison of CLDR against the fallback found 79 of 209 (locale, key, count) renderings differ, for example:
```
ru.merchantsTransactionCount n=5   CLDR: 5 транзакций   device: 5 транзакции
ru.merchantsTransactionCount n=21  CLDR: 21 транзакция  device: 21 транзакции
uk.budgetHistoryCount n=2          CLDR: 2 записи       device: 2 запису
sk.ledgerEditorErrorCount n=2      CLDR: 2 chyby        device: 2 chýb
fr.ledgerEditorErrorCount n=0      CLDR: 0 erreur       device: 0 erreurs
```

## Root cause

`mobile/src/common/plural.ts:15-40` (`rulesFor` returns null without `Intl.PluralRules`; the fallback is `count === 1 ? "one" : "other"`). w4/m28/t002 shipped it assuming the English-rule fallback "covers its absence".

## Fix

Give `plural.ts` integer plural rules for the shipped locales that don't need `Intl` for every shipped locale. ru, uk and sk use one/few/many/other; fr and pt treat 0 and 1 as one; the rest match English or have only "other". Keep `Intl.PluralRules` as the preferred path when it exists. Alternatively, add `@formatjs/intl-pluralrules`, which is a new dependency and needs owner approval. Add a test that deletes `Intl.PluralRules` and checks ru 1/2/5/21, uk 2, sk 2 and fr 0.

**Acceptance:**
- On the simulator in Русский, five errors read "5 ошибок" and a merchant with 5 transactions reads "5 транзакций".
- The `Intl`-less test passes.

## Dedupe

w4/m28/t002 (done) shipped the pluralizer. w21/077 and w21/098 (done) fixed catalog shapes only. Searched `.pm/**` for PluralRules, Hermes, "English-rule fallback", "5 транзакции" and "2 chýb".

Fixed in mobile: `plural.ts` carries CLDR cardinal rules for every shipped language (`builtinPluralCategory`: ru and uk one/few/many, sk one/few/other with many for fractions, fr and pt treating 0 and 1 as one, fa treating 0 and 1 as one, zh other only, and English's one-only-for-1 for en, de, nl, es, ca and bg) and `pluralCategory` uses it whenever the runtime has no `Intl.PluralRules`, which is always on Hermes. Runtimes that have `Intl` still ask it first. On a device, five errors in Russian now read "5 ошибок" and a merchant with five transactions "5 транзакций"; Ukrainian "2 записи", Slovak "2 chyby" and French "0 erreur" follow. When there is no `Intl`, the categories a catalog must provide (`pluralCategoriesOf`) are now ru/uk/sk's four, zh's one, and one/other elsewhere. Tests in `translations/__tests__/plural.test.ts` close the Node-only gap the note describes: the built-in rules are compared with Node's own for every shipped locale and every count from 0 to 1000 and a few fractions, the note's examples are pinned, and a run with `Intl.PluralRules` deleted checks `pluralCategory`, `pluralKeys` and a registered i18n-js pluralizer (Russian 5, 2, 21); the comparison and the delete-Intl cases fail with `plural.ts` reverted. Deviations: `many` for millions in es, ca, fr and pt (CLDR 42+) is not modelled (counts that large do not occur); I did not run the Russian simulator steps.
