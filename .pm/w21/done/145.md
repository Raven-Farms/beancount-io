# Payee suggestions, Account Picker and Browse Ledgers lists can't bring their last rows above the keyboard

**Severity:** moderate. With 9–13 payee matches the list is too short to scroll, so rows 9 and up stay covered. With more, about 5 rows remain unreachable at the end. The only way out is Return, which dismisses without choosing. **Estimate:** 30 minutes. Owner: mobile. A3: these ScrollViews have no keyboard inset (`automaticallyAdjustKeyboardInsets` or `KeyboardAvoidingView`) and no `keyboardDismissMode`. Account Picker relies on a fixed `paddingBottom: 150` against a 291–336 pt overlap. Create Ledger already uses `automaticallyAdjustKeyboardInsets`.

Code-level geometry at `main` `aa4a9793a` (iPhone 17e: keyboard top at about 508–553 pt, rows 44 pt).

## Where (`mobile/src/`)

- `components/text-input-screen/index.tsx:252-260` (the single-line suggestions ScrollView)
- `screens/account-picker-screen/account-picker-screen.tsx:147-149, 556-574`
- `screens/ledger-selection/index.tsx:262-265`

## Fix

Add `automaticallyAdjustKeyboardInsets` (iOS) and `keyboardDismissMode="on-drag"` to these lists, and drop the fixed 150 pt padding in favour of the inset.

**Acceptance:** on a ledger with 15+ payees, typing one letter in Payee lets the user scroll to and tap the last match with the keyboard up. The same holds for Account Picker search results.

## Dedupe

w3/177 fixed empty-state placement only and left Account Picker out; w21/082 is the multiline narration case. Searched `.pm/**` for "payee suggestions keyboard", "account picker keyboard" and "scroll above the keyboard".

**Resolution (2026-10-21):** three lists now take `automaticallyAdjustKeyboardInsets` (iOS) and `keyboardDismissMode="on-drag"`: the single-line suggestions ScrollView in `text-input-screen` (Payee and friends), Account Picker's SectionList and Browse Ledgers' FlatList. Account Picker's fixed `paddingBottom: 150` is now `gutter`, since the inset does that work. Android already resizes for the keyboard. **Native recheck 2026-10-21:** not exercised. The simulator uses a hardware keyboard, so the software keyboard never covers the lists, and the MCP can't scroll to the last rows. Covered by `keyboard-inset-lists.test.ts` only.
