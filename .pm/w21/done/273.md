# A file-editor save conflict is a dead end: "Keep Editing" can never save, and "Reload" throws the text away

**Severity:** moderate (loses work). **Estimate:** 30 minutes. Owner: mobile. A3: the editor's sha only changes after a successful save or a reload. After a conflict and Keep Editing, every Save sends the same stale sha and conflicts again. The only ways out are Reload, which replaces the buffer, or leaving, which discards it. Nothing offers to overwrite, keep a copy, or merge.

Code-level at `main` `7f85628b8`. Scenario: edit `main.bean` on mobile, change it from the CLI or web, tap Save, then Keep Editing. Every later Save fails the same way.

## Root cause

`mobile/src/screens/ledger-file-editor-screen/index.tsx:547-559` (the conflict alert). `shaRef` is updated only at `:528` (save) and `:475` (reload).

## Fix

Offer "Overwrite": refetch only the current sha and resave the buffer, after a confirmation that names the risk. Or reload while preserving the user's buffer, for example by copying it to the clipboard with a toast, or showing it side by side.

**Acceptance:** after a conflict, the user can either save their text over the new version or keep a copy of it before reloading. A harness test covers both paths.
