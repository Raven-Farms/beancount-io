# On a lossy or captive network, cold start waits on the splash for about 60 s even though the cache is ready

**Severity:** moderate. On hotel Wi-Fi, a captive portal or a dead connection, the app shows its splash for about a minute before opening on the cached data it already had. Airplane mode fails fast; only a lossy or hung path shows this. **Estimate:** 30 minutes. Owner: mobile. A3: the splash awaits a `network-only` `GetLedger` before `setAppIsReady`, with no timeout. If the token has expired, the auth link first runs a refresh fetch, also with no timeout. React Native's fetch has no default timeout, so iOS's roughly 60 s request timeout governs. With the server up but the ledger service slow, the wait is the backend's 30 s fava timeout, and then w21/182 applies.

Code-level at `main` `b8c58c186`.

## Where

- `mobile/src/common/providers/splash-provider/splash-provider.tsx:109-116`
- `mobile/src/common/apollo/client.ts:11-16`
- `mobile/src/common/oauth/token-manager.ts:150-161`

## Fix

Bound the splash's ledger check and the token refresh with an `AbortController` timeout of a few seconds. On timeout, proceed with the persisted selection and cached data (the offline path), and revalidate in the background once ready.

**Acceptance:** with Network Link Conditioner at 100% loss, a signed-in cold start shows cached Home within about 5 s. The ledger check still runs when the network returns.

## Dedupe

The splash items on the board cover RTL, locale (w21/126) and Keychain (w21/154). Searched `.pm/**` for splash, timeout, network-only, GetLedger, setAppIsReady and lossy.

**Resolution (2026-10-21):** the splash waits at most 5 s (`LEDGER_CHECK_DEADLINE_MS`) for its `network-only` `GetLedger` (`settleWithin`, `common/settle-within.ts`), a bound that also covers a token refresh before it. Past the deadline it opens on the persisted selection and cached data, the offline path, and the check keeps running behind: if it later answers NOT_FOUND or FORBIDDEN, the selection is cleared as at launch (w21/182). A rejection inside the window is handled as before. Tests: `common/__tests__/settle-within.test.ts` (the wiring case fails with the splash reverted).

Deviation: the request itself is not aborted, since Apollo's query is only raced, not given an `AbortController`. The bound is on the wait, which is what the splash needs. Not exercised under a 100%-loss Network Link Conditioner.
