# The file editor tells a user whose edit access was removed "Your text is still here. Try again in a moment.", which can never succeed (w21/378 follow-up)

**Severity:** low. **Estimate:** 15 minutes. Owner: mobile. A3: `ledger-file-editor-screen/index.tsx:788-791` falls back to `ledgerEditorSaveFailedHint` whenever `ledgerWriteFailureMessage` returns null, and it returns null for `FORBIDDEN` (`common/ledger-refusal.ts`, the trailing `return null`). `updateLedgerFile` checks `LEDGER_FILES_WRITE` first (`backend-v2/src/features/ledger/workflow/ledger-workflow.ts:882`), so a downgraded collaborator gets `FORBIDDEN` / "Authorization denied" (`authorization-service.ts:850, 1106`).

Code-level at `main` `fe720cf39`. The reviewer's tsx run of the editor's catch order on `{extensions:{code:"FORBIDDEN"}, message:"Authorization denied"}` gives the generic hint. Not exercised: it needs a second account to downgrade the QA user, which is outside this run's scope.

## Fix

Show the retry hint only for transient codes (SERVICE_UNAVAILABLE, INTERNAL_SERVER_ERROR). For FORBIDDEN, say edit access was removed and offer Copy (reuse `copyDraft`).

**Acceptance:** a FORBIDDEN save says the user can no longer edit this ledger and offers Copy. Unit cases are added.
