# File create: REST commits "Update <path>" and refuses an empty message, while GraphQL commits "Create <path>" and accepts `""`

**Severity:** low. **Estimate:** 10 minutes. Owner: backend-v2. A3 (code-level at `main` `77ab889b4`): REST `PUT …/files/{path}` (`files-handler.ts:167`) defaults to `Update ${path}` even when it creates the file, and refuses `message: ""` (`min(1)`). GraphQL `createLedgerFile` uses the ledger's `body.message || "Create ${path}"` (`ledger/src/api/files.ts:311`), so it writes "Create x" and accepts `""`. MCP requires `description` and uses it as the message.

Mobile notices only in history: Notifications ▸ Recent changes lists a file created from the CLI or REST as "Update new.bean".

## Fix

Default to "Create <path>" when REST's PUT creates the file, and pick one rule for an empty message on all surfaces, with a parity test.

**Acceptance:** creating a file without a message commits "Create <path>" on REST and GraphQL, and `""` is handled the same way everywhere.
