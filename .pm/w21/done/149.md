# New Transaction doesn't fill in a payee's usual accounts when the payee name has punctuation (`Dupar's`, `Mr. Marcel`, `Chase:Slate`, `25 Degrees…`)

**Severity:** moderate. On the example ledger, 6 of 35 two-posting payees silently skip w21/023's account seeding, and the postings stay on the defaults. **Estimate:** 10 minutes. Owner: mobile. A3: the seeding hook sends the raw payee as `getLedgerJournal`'s `filter`, which the server parses as advanced-filter syntax. Names containing `'`, `.` or `:`, or starting with a digit, are rejected with BAD_USER_INPUT. The hook ignores errors, so `seedPostingsFromPayee` gets no history. Merchant detail had the same bug and was fixed by quoting with `toPlainSearchFilter` (w3/112); this hook never was.

Verified through the API at `main` `225612324` (read-only, `puncsky/example`): `getLedgerJournal(query: {filter})`
- `Chichipotle` → total 47
- **`Dupar's` → "Illegal character \"'\""**
- **`Mr. Marcel` → "Illegal character \".\""**
- **`Chase:Slate` → "Trailing tokens"**
- the quoted `"Dupar's"` → total 6

The reviewer found the same for `Giacomo's Restaurant`, `E.B.'s Beer and Wine` and `25 Degrees Burger Bar` (Unexpected token NUMBER).

## Where

- `mobile/src/screens/add-transaction-screen/hooks/use-two-posting-suggestions.ts:36` sends `query: { filter: payee, limit: 50 }`.
- It's used by `multi-postings-transaction-screen.tsx:514` (the seed at `:730`) → `payee-seed.ts:41`.

## Fix

Send `filter: toPlainSearchFilter(payee)`, as merchant detail does, and keep the client-side exact-payee re-filter. Surface the hook's error, or log it in dev, so a parse failure isn't silent.

**Acceptance:**
- On `puncsky/example`, picking Dupar's, Mr. Marcel or Chase:Slate as the payee fills in their usual accounts, as Chichipotle does.
- Add a unit test for the query variables.

## Dedupe

w21/023 introduced the seeding; w3/112 fixed merchant detail only; w21/032 is the BQL payee quote on the merchant header. Searched `.pm/**` for useTwoPostingSuggestions, seedPostingsFromPayee, payee-seed, "Illegal character", toPlainSearchFilter and Dupar.
