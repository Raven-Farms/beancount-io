# Android: the tab bar covers the last rows of every tab, so the last file or account row and Transactions' "Retry" can't be tapped

**Severity:** minor on Android. **Estimate:** 20 minutes. Owner: mobile. A3: Android uses the JavaScript tab bar, positioned `absolute` with height `80 + insets.bottom` (`components/ledger-tabs/index.tsx:167-175`). The lists have no bottom padding for it: `transactions-screen.tsx:349-350`, `account-table.tsx:565-566`, `ledger-file-browser-screen/index.tsx:750-751` and `dashboard-scroll-view/index.tsx:82`. They rely on `contentInsetAdjustmentBehavior="automatic"`, which only works on iOS (`8703234ea` fixed iOS only). The bottom 80dp plus the navigation bar stays under the pill, and taps there hit the tab bar. Code-level at `main` `ac126c6ae`; Android not exercised (no emulator in this QA run).

## Fix

On Android, add `paddingBottom: tabBarHeight` to these lists' content (or use `useBottomTabBarHeight()`).

**Acceptance:** the last row, the Retry footer and the last Home card scroll fully above the bar on Android.

## Dedupe

See w21/242 (stacked tab bar on Back). Searched `.pm/**` for "Android" together with "tab bar" and contentInsetAdjustmentBehavior.

---

**Resolved 2026-10-22** — fixed once in the navigator rather than in each list: Android's JavaScript tab bar now gives every scene `sceneStyle: { paddingBottom: TAB_BAR_CONTENT_HEIGHT + bottomInset }` (the height now lives in `tab-bar-metrics.ts`, shared with the bar itself), so Transactions, Accounts, Files, Home and Reports all end above the bar and their last rows and Retry footers can be tapped; iOS's native tabs inset their content themselves and are unchanged. A side effect on Android: content no longer scrolls underneath the translucent pill. Source-level cases in `android-scene-inset.test.ts` (`mobile`); Android was not run (no emulator).

Recheck: not exercised. It's Android-only, and this run uses the iOS simulator. On iOS, the Transactions, Accounts and Files lists still scroll above the tab bar as before.
