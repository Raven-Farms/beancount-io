# A ledger without `option "operating_currency"` shows Home's Net Worth, Assets and Spending as $0.00 USD, with every amount under "Not in total"

**Severity:** moderate for imported ledgers; ledgers created in the app always write the option. **Estimate:** 20 minutes. Owner: mobile. A3: `home-screen.tsx:75` takes `getPrimaryCurrency(currencies)`, which falls back to "USD" (`common/currency-util.ts:7-10`), and `ledger-meta-utils.ts:64` builds `currencies` from `operating_currency` only. Under `tsx` on a EUR ledger with no option: Home currency USD, net worth `$0.00`, caption "1 not in total" (EUR 2500), and both Spending bars 0 (EUR 120 not in total).

Code-level at `main` `6d8c869b2`. Not run natively; it means removing the shared ledger's option.

## Fix

With no operating currency, fall back to the ledger's dominant commodity (for example, the largest in the latest net-worth point) instead of a blind USD, and share it with w21/395's Add Budget fix.

**Acceptance:** the EUR ledger without the option shows its net worth and spending in EUR on Home.

## Dedupe

w21/395 has the same root cause, for Add Budget. w21/262 and 406 cover only the loading fallback, and 058 differs. Searched `.pm/**` for getPrimaryCurrency, "USD fallback" and "no operating_currency".

Fixed. A ledger without `option "operating_currency"` now reads in its own currency instead of a blind USD. The read-context query also fetches the ledger's commodities (`attributes.currencies`), and `ledgerPrimaryCurrency` picks the first operating currency, else the first commodity that is a known currency (a ticker like VTI is not one), else the first commodity, and USD only for a ledger that holds none yet. `useLedgerReadContext` exposes it as `primaryCurrency`, and Home, Accounts, Reports and account detail use it where they called `getPrimaryCurrency(currencies)`, so the EUR ledger's net worth, Assets, Spending bars, Reports charts and account figures read in EUR rather than $0.00 with everything under "Not in total". Ledgers that declare the option are unchanged. Tests (`currency-util.test.ts`: the pick for each case and the four screens plus the hook wired to it; the cases fail with the util, hook and Home reverted). Deviation: the note suggested the dominant commodity by amount in the latest net-worth point; that needs the balance sheet, which itself needs the currency, so the first known currency stands in (a ledger with several currencies and no operating one reads in the first). The generated client was regenerated for this one field only (a fresh codegen from production also moved the schema files; they were left as committed). Not run natively.

Native recheck: not exercised. The disposable ledger is USD-only and declares USD, so removing the option would still read USD and wouldn't distinguish the fix. A EUR conversion would disturb the other QA worker's fixture. It rests on its tests; w21/395 (Add Budget currencies) is in the same position.
