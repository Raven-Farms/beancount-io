## Objective

Add meaningful tests for the shipped behavior: an edit or delete that adds an error is refused; the same with `allowInvalid` commits; pre-existing errors don't block; a stale checksum still fails first; and the mobile delete, edit and file-editor paths render the refusal or warning.

## Acceptance criteria

- [ ] Restoring the unguarded `commitTransforms` call makes the ledger tests fail.
- [ ] Restoring the toast-only delete handler makes the mobile test fail.

## Outcome

Tests for the milestone's behavior, with the file for each:

- **An edit or delete that adds an error is refused, and nothing is committed.** Single delete, re-date and multi-delete: ledger `source-slice-new-errors.test.ts`. All three operations on REST, GraphQL and MCP: backend-v2 `source-slice-parity.test.ts`.
- **`allowInvalid` commits the same write.** Both files above.
- **Pre-existing errors don't block.** A moved error and an edit that fixes an error: `source-slice-new-errors.test.ts`. Matching that ignores line shifts and keeps files apart: `new-ledger-errors.test.ts`.
- **A stale checksum fails before any projection.** `source-slice-new-errors.test.ts`.
- **The shared helper.** `refuseNewLedgerErrors` never reads today's errors for a clean projection, refuses naming the write, and lets old errors through: `new-ledger-errors.test.ts`.
- **Mobile.** Delete refusal dialog: `delete-transaction.test.ts`. Edit inline refusal plus conflict detection: `save-failure.test.ts`, via `selectOutcomeFailure`. File-editor new-error warning: `new-ledger-error.test.ts`.
