## Objective

Run `/simplify` over the code this milestone changed (reuse, simplification, efficiency; behavior-preserving). In particular, share one projected-error helper between `entries.ts` and the source-slice service instead of two copies.

## Acceptance criteria

- [ ] One projection-and-refuse helper serves add, edit and delete. Gates still pass.

## Outcome

`/simplify` ran four reviews over the milestone's diff: reuse, simplification, efficiency and altitude.

Applied:

- **One shared refusal path.** `refuseNewLedgerErrors(after, before, action)` in `ledger/src/features/ledger/utils/new-ledger-errors.ts` now serves add (`api/entries.ts`) and edit/delete (`assertNoNewErrors`). It reads `before` only when the projection has errors.
- **`newLedgerErrors` is one pass.** It does a counted match by message and file, the same rule the mobile copy uses.
- **The `allowInvalid` guard is inside `assertNoNewErrors`.** Each write site is now one line.
- **Mobile.** `LedgerError` has one definition, shared by `use-ledger-errors.ts`. The delete test drives the screen's real `ledgerWriteFailureMessage`. The file editor reads its before-save snapshot in the save handler instead of mirroring it into a ref every render.
- **backend-v2.** The comment on how `details.action` is mapped is corrected.

Skipped:

- **backend-v2 rewording the ledger's refusal.** This is the established w0/m2 contract.
- **Folding the check into `commitTransforms`/`commitLedgerFiles`.** It is one line per site now, and running it inside the CAS loop is a larger change.
- **A `showRefusal` dependency on `runLedgerWrite` for every screen.** That would change Open Account, Add Budget and Edit, which already render refusals inline.
- **Reusing the edit screen's `outcome.message`.** Conflict detection needs the raw server message.
- **Reusing parse results for the before-errors snapshot.** It is already a worker-cache hit.
- **Parallelizing projection transforms.** A gain of one file at most.

Gates: ledger 1387 tests, lint, typecheck and build. backend-v2 fava and parity suites. Mobile tsc, eslint, knip, prettier, and 2356 unit tests.
