## Objective

In the native app, a refused edit or delete keeps the user on the screen with the refusal readable. A file-editor save that leaves new ledger errors says so instead of plain success.

## Context

- Edit: `mobile/src/screens/edit-transaction-screen/edit-transaction-screen.tsx:249-290,469` already shows `outcome.message` inline. Confirm `describeLedgerRefusal` produces it.
- Delete: `mobile/src/screens/transaction-detail-screen/transaction-detail-screen.tsx:293-335` reports through toasts only.
- File editor: `mobile/src/screens/ledger-file-editor*`. No error comparison happens today. The dashboard's `useWriteOutcome` (w3/640) is the behavioral model.
- Related: `w21/001` (New Transaction's refusal is toast-only).

## Steps

1. Delete: on refusal, keep the detail screen and show the refusal in an alert (or inline) with the full text.
2. File editor: compare `getLedgerErrors` before and after a save. When new errors appear, show a persistent warning that names the first one, with a way to open Notifications.
3. Add component or unit tests for each refusal or warning path.
