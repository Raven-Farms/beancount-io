# The file editor's title shows only the file name, so `books/2025/jan.bean` and `books/2026/jan.bean` look the same

**Severity:** low. **Estimate:** 10 minutes. Owner: mobile. A3 (code-level at `main` `b1ba52fcd`): `ledger-file-editor-screen/index.tsx:956` (`fileName = path.split("/").pop()`) and `:999` (`title: fileName`). The folder isn't shown anywhere in the editor. Opening either year's `jan.bean` (from Files, or from a Notifications error) gives the same "jan.bean" header, so the user can't confirm which year they're editing before saving.

## Fix

Show the folder (for example as a subtitle "books/2025") or a middle-truncated full path, as the Files breadcrumb does (w21/277).

**Acceptance:** the two files' editors are distinguishable. A render test covers a nested path.

## Dedupe

See w21/277 (breadcrumb). Searched `.pm/**` for basename, "same-named" and the file title together with the editor.

---

**Resolved 2026-10-22** — a file in a folder gets a one-line, middle-truncated path under the header (`editorPathLine`, monospaced, muted), so `books/2025/jan.bean` and `books/2026/jan.bean` are told apart before saving; a file at the root shows no line, the name being the path. Cases in `path-line.test.ts` (`mobile`); not run natively.

Native recheck (iPhone 17e, same bundle with `5c72de841`; probe files deleted): opening `qa/nested.bean` shows the title "nested.bean" with "qa/nested.bean" beneath it. Fixed.
