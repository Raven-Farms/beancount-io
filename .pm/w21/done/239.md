# Account detail: a failed pull to refresh replaces the loaded balance chart with a permanent skeleton, with no stale-data banner

**Severity:** moderate. Pull to refresh while offline (or on a flaky connection) and the account's chart, headline and range pills vanish behind a loading tile, which looks like loading forever. **Estimate:** 20 minutes. Owner: mobile. A3: the screen passes `error={Boolean(reportError)}` without checking whether data is already loaded, and `BalanceChartCard` renders any `error` as a `LoadingTile`. The stale banner only watches the journal query. Home does this correctly (`Boolean(balanceSheetError) && !balanceSheet`), and w21/081 fixed only the journal on this screen.

Code-level at `main` `4ba42392a`. A reviewer checked Apollo 3.14.1 with `cache-and-network`: a failed refetch reports `{ data: {...}, error: "Network request failed", loading: false }`, so the data survives. Evaluating the screen's own expressions on that state shows `BalanceChartCard` rendering `LoadingTile` and `StaleDataBanner` false. Not forced natively; the simulator has no per-app offline switch.

## Root cause

- `mobile/src/screens/account-detail-screen/account-detail-screen.tsx:418`: `error={Boolean(unitsCurrency ? unitsReportError : reportError)}`.
- `mobile/src/components/balance-chart-card/index.tsx:67-70` turns `error` into `<LoadingTile/>`.
- `account-detail-screen.tsx:447-449`: `isShowingStaleDataFromQueries` gets only the journal query.

## Fix

Pass `error && !data` for whichever report is active, and add both report queries to the stale check. Give a first-load failure `CardLoadFailure` with Retry, as w21/080 did elsewhere.

**Acceptance:** a refetch error with data loaded keeps the chart and shows the stale banner. An error with no data shows a failure card with Retry. Source or unit checks cover both.

## Dedupe

w21/081 (done) is the journal half, and w21/080 (done) the first-load failures on Reports, Accounts and the budget panel. Searched `.pm/**` for BalanceChartCard, reportError, unitsReportError, and LoadingTile together with account detail.

Fixed in mobile: account detail passes the balance chart a failure only when its first load failed with nothing to draw (`selectChartFailed`: the active report, units for a commodity account and market otherwise, has an error and no data), so a failed pull to refresh keeps the loaded chart, headline and range pills. Both report queries now feed the stale-data banner next to the journal's. A first-load failure no longer draws the loading skeleton forever: `BalanceChartCard` shows `CardLoadFailure` with a Retry that refetches the active report, as w21/080 did on Reports, Accounts and the budget panel. Tests: `select-chart-failed.test.ts` (a loaded chart survives an offline refresh in both modes, a first-load failure fails, only the active report is judged) and source checks of the screen and card wiring; the wiring checks fail with the two files reverted. Deviation: the simulator has no per-app offline switch, so the offline refresh was not driven natively.
