# The "Saving…" toast disappears after 2 seconds while the save is still running

**Severity:** minor. On a slow network nothing shows the save is in progress after 2 s, which invites Cancel → Discard (w21/194). **Estimate:** 10 minutes. Owner: mobile. A3: loading toasts get the default 2000 ms duration like any other toast. `runLedgerWrite` shows its "Saving…" toast without a duration and only dismisses it when the write settles. Edit Transaction's Save also stays enabled while saving.

Code-level at `main` `10857997b`. A reviewer ran the real `runLedgerWrite` and `toastDuration` with the provider's scheduling and a 6 s write: "Saving…" showed until t=1999, nothing showed at t=2000–5999, and "Saved" appeared at t=6000.

## Root cause

- `mobile/src/common/providers/toast-provider/toast-queue.ts:21-28` (default duration for every type) and `index.tsx:83-85`.
- `ledger-write.ts:94-96`.
- Callers: `edit-transaction-screen.tsx:293` and `multi-postings-transaction-screen.tsx:636`.

## Fix

Don't put `loading` toasts on a timer; rely on the dismiss `runLedgerWrite` already returns. Optionally disable Save while saving.

**Acceptance:** with a 6 s write, "Saving…" stays visible until the result toast. A unit test covers the loading duration.

## Dedupe

w21/044 recorded the toast gone at +2.4 s as evidence only, and w21/001 changed error toasts. Searched `.pm/**` for "loading toast", toastDuration and "Saving…".

Fixed. `toastDuration` gives a "loading" toast `MAX_LOADING_TOAST_DURATION` (60 s) instead of the 2 s default, so "Saving…" stays up for a slow write until `runLedgerWrite`'s own dismiss removes it when the write settles; the only caller of a loading toast is `runLedgerWrite` (checked), and the cap only keeps a toast whose caller never settled from lasting forever. Other types keep their durations, and an explicit duration is still honoured. Optional part not done: Edit Transaction's Save is not disabled while saving; the write path's in-flight guard already prevents a second submit. Tests added to `toast-provider/__tests__/index.test.ts` (fails with `toast-queue.ts` reverted). Mobile gates and deadcode green; not timed on a slow network.

**Recheck (2026-10-21): not exercised natively.** It needs a ledger write that takes longer than 2 s with a "Saving…" toast showing. Writes on this setup finish in about 1–2 s (w21/197's "Deleting..." toast lasted about 1.5 s), and there is no network throttling.
