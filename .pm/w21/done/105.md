# On Create Ledger's Review step, Create silently does nothing for a name conflict or an invalid opening amount

**Severity:** moderate. The spinner stops and no message appears; the user can't tell what's wrong. **Estimate:** 30 minutes. Owner: mobile.

Code-level at `main` `cd02f5446`. Not exercised natively, because the success path creates a production ledger.

## Scenario

- **A:** use the name of a ledger you already own → Next → Create. The server refuses ("already exists"), and `setError("name", …)` sets an error that only step 2 renders. The same happens when the ledger list failed to load and the default `my-book` collides.
- **B:** opening amount `12.` → Next → Create. The form schema fails, and the amount error also renders only on step 2.

## Root cause

- `mobile/src/screens/create-ledger-screen/create-ledger-screen.tsx:360-362` sets the conflict on the `name` field.
- The name error (`:525-527`) and amount error (`:660-664`) render only on step 2.
- Next on step 2 (`:382`) validates only `name`.
- The Review step shows only `errors.root`.

## Fix

On submit failure, jump back to step 2 when a step-2 field has an error. Also validate the whole step-2 schema on Next, not just `name`. Alternatively, mirror field errors into the Review step's error area.

**Acceptance:** both scenarios show a visible message, either back on step 2 with the field highlighted or on Review. Nothing is created.

## Dedupe

Searched `.pm/**` for createLedgerNameConflict, "review step", "already exists" and "Create does nothing".

**Resolved 2026-10-21** — Shipped in the commit that moved this note (`mobile`). Every field the Create Ledger form validates sits on the form step (`FORM_STEP`), and it now behaves accordingly:
- Next from that step validates the whole schema (`trigger()`) rather than only `name`, so an invalid opening amount like `12.` stops there with its message.
- A server name conflict sets the name error and returns to the form step.
- An invalid submit returns there through `handleSubmit`'s invalid callback.

Both scenarios now show the field's message instead of a silent Create, and nothing is created. `review-errors.test.ts` checks the validate-all Next and both return paths; it fails with the screen change reverted. Not exercised natively, because the success path creates a production ledger.
