# A link to another ledger while New Transaction has unsaved input switches the ledger under the draft, so Done writes ledger A's draft into ledger B (sibling of w21/090)

**Severity:** minor (a write to the wrong ledger). **Estimate:** 30 minutes. Owner: mobile. A3 (code-level at `main` `f61267f7d`, partly proven under `tsx`): `common/app-links/open-app-link.ts:94-104` asks `confirmDiscardUnsavedEdits()`, but only the file editor registers a check, so it resolves `true` while New Transaction is dirty. New Transaction reads `ledgerId` from `useLedgerGuard()` (`multi-postings-transaction-screen.tsx:450`) and isn't keyed by ledger. If the navigation then hits its `beforeRemove` "Discard your changes?" and the user taps Cancel, the draft stays with ledger B's id and currency, and Done writes A's accounts into B (or is refused there).

Not run natively: `simctl openurl` can't be accepted here.

## Fix

Register New Transaction (and other dirty write forms) with `confirmDiscardUnsavedEdits`, so the link asks *before* switching, as w21/090 does for the editor. Or key the form by ledger.

**Acceptance:** with a dirty draft, a link to ledger B asks first, Cancel keeps ledger A, and nothing is written to B. A test covers it.
