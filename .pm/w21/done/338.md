# File editor: pressing Enter twice after a posting indents the next transaction, which bean-check then rejects ("unexpected INDENT")

**Severity:** minor-to-moderate. Adding a transaction at the end of a file is the editor's main job. **Estimate:** 20 minutes. Owner: mobile. A3: the Beancount language mode has no `indent` function, so Enter copies the current line's indentation. After a posting, the blank line and the next line both start at 2 spaces, so a new date line is indented. Conversely, Enter after a header gives no indentation, so a first posting starts at column 0 unless the user taps ⇥.

Code-level at `main` `57826d105`. A reviewer ran the app's CodeMirror setup with `insertNewlineAndIndent` under Node on `2026-10-20 * "Coffee"\n  Expenses:Food  4.50 USD\n  Assets:Cash`, then Enter, Enter and a typed date. The result was `…Assets:Cash\n\n  2026-10-21 * "Lunch"`, which bean-check 3.2.3 rejects with `syntax error, unexpected INDENT`. Not typed natively (no software keyboard in this run).

## Root cause

`mobile/src/components/code-editor/code-editor.tsx:78-82` (the language mode without `indent`), with `:194` (`defaultKeymap`).

## Fix

Give the language an `indent(state, textAfter, cx)` that returns 0 after a blank line or before text starting with a date, `indentUnit` after a header or posting line, and null otherwise.

**Acceptance:** the sequence above yields an unindented date line, and Enter after a header indents the first posting. Unit tests use the app's editor setup.

## Dedupe

w3/267 and w5/477/629 are the CLI and feed validator. Searched `.pm/**` for insertNewlineAndIndent, "unexpected INDENT" and auto-indent.

Fixed. The editor's Beancount language now carries an indent rule (`beancountIndent`, in the import-free `beancount-language.ts`) installed as a CodeMirror `indentService`, installed together with the stream language at both places it is set up (initially and through the language compartment). After a dated header or an indented line (a posting, metadata) Enter indents one unit; after a blank line, or before text starting with a date, the line starts at column 0; other top-level lines (`option`, `include`, comments) are left to CodeMirror's default. An indent service rather than the stream parser's `indent`, because only the service is told which position is being indented. Verified against the real CodeMirror under Node with `insertNewlineAndIndent` and the app's rule: after `2026-10-20 * "Coffee"` / `  Expenses:Food  4.50 USD` / `  Assets:Cash`, Enter twice leaves an unindented blank line (so a typed date is not indented, no "unexpected INDENT"), and Enter after the header gives `\n  ` for the first posting. Unit tests for the rule and the wiring are in `code-editor/__tests__/beancount-language.test.ts` (and the line-wrapping pin was updated for the renamed extension); they fail with the editor and rule reverted. Mobile gates and deadcode green; the DOM component was not typed into on a device.

Native recheck (iPhone 17e, fresh Metro `--clear` at `c751cbcfe`; soft keyboard): in `main.bean`, on a blank line I inserted `2026-10-21 * ` from the accessory chips, then pressed Return, typed "a", pressed Return twice and typed "b". "a" was indented two spaces after the header, and "b" started at column 0 after the blank line. The edit was discarded unsaved, and the ledger is unchanged. Fixed.
