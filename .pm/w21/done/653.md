# The entry validators accept tags and links the engines can't read (`#café`, `#旅行`) and quoted flags (`'X`), so writes fail with raw parse errors, or with allowInvalid commit unreadable lines

**Severity:** low. **Estimate:** 15 minutes. Owner: ledger. A3 (code-level at `main` `c1c3be649`; the validator and rustledger 0.24 were run, and Beancount 3.2.3 checked):
- Tags and links: `entry-tokens.ts:24-25` allows `[\p{L}\p{N}_/.-]+`, which w23/033 chose deliberately for `#旅行`. Both engines' lexers are ASCII-only (`#[A-Za-z0-9\-_/.]+`). rustledger reads `#café` as tag `caf` and drops `#旅行`, and Beancount reports "Invalid token". `entries-amount-syntax.test.ts:358, 374` pins `#旅行` against a mocked engine.
- Quoted flags: `'[A-Za-z]` (`entry-tokens.ts:22-23`, pinned at `entry-tokens.test.ts:40`) isn't Beancount syntax. As a transaction flag the whole transaction drops with parse errors; as a posting flag, that posting drops.

The projected check refuses these with a raw parse error. With `allowInvalid` they commit lines the engine can't read.

## Fix

Match the engines' grammar: ASCII-only tags and links, and no quoted flags. Run these tests against the real engine.

**Acceptance:** those inputs are refused by the validator with its clear message. Tests use the real engine.

## Dedupe

Follows w23/033; see w21/649. Searched all of `.pm/` for "#旅行" and "'X".

**Resolved 2026-10-22** — the ledger service's entry validator (`entry-tokens.ts`) now follows both engines' lexers: tags and links are `[A-Za-z0-9_/.-]+` (so `#café` and `#旅行` are refused as "is not a valid tag" instead of being read as `#caf` or dropped), and a quoted flag (`'X`) is no longer a transaction or posting flag; Unicode account names are unchanged. Checked against Python Beancount 3.2.3 ("Invalid token" for all three) and the bundled `@rustledger/wasm` 0.24.0. Tests: `entry-tokens.test.ts`, `entries-amount-syntax.test.ts` (the REST refusal), and a live check in `scripts/verify-rustledger.ts` that the validator accepts a tag or flag exactly when the real engine reads it back as written (fails without the change) (`backend-cluster/ledger`). A ledger service deploy carries it to production.
