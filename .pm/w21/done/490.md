# Signed-out links to an example's Accounts or Files page still hit the sign-in wall, though guests have both tabs (w21/345 follow-up)

**Severity:** low. **Estimate:** 5 minutes. Owner: mobile. A3: `GUEST_VIEWS` (`mobile/src/common/app-links/guest-link-visit.ts:10-14`) maps only `/`, `/transactions` and `/reports`, while the guest tab group has `accounts` and `files` (`example-routes.ts`).

Code-level at `main` `e8b5e15a8`. In the reviewer's tsx run, `…/open_ledger/example/accounts` resolves to `href:"/accounts"` and `…/open_ledger/example/files/tree/main` resolves to `href:"/ledger"`, and `guestLinkVisit` returns null for both, so the link waits behind sign-in. Not exercised natively. If w21/345's "file links keep the old behaviour" was meant to cover `/files/tree`, only the Accounts half is new.

## Fix

Add `"/accounts": "accounts"` and `"/ledger": "files"` to `GUEST_VIEWS`.

**Acceptance:** both links open the guest example on the matching tab. A unit case is added.
