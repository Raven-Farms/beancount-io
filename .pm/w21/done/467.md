# On Android the search field has no clear button, so leaving a search means deleting it character by character

**Severity:** low (Android only). **Estimate:** 15 minutes. Owner: mobile. A3: `SearchBar`'s only clear control is `clearButtonMode="while-editing"` (`mobile/src/components/search-bar/index.tsx:125`), an iOS-only React Native prop. Transactions' `right` slot holds only the filter button (`transactions-header.tsx:62-81`). The three other screens that use `SearchBar` are affected the same way. On iOS the button shows only while the field is focused.

Code-level at `main` `bed2252b0`; not exercised (no Android device in this run).

## Fix

Draw a clear (✕) button inside `SearchBar` whenever `value` is non-empty, with an accessibility label (`t("clear")` or similar), on both platforms.

**Acceptance:** with text in any search field, a labelled clear button empties it on Android and on iOS.

## Dedupe

Searched `.pm/**` for clearButtonMode, "clear button", and Android together with search and clear. No hits.

Resolved. `SearchBar` now draws its own clear (✕) button whenever the field holds text, on both platforms, labelled "Clear search" (`clearSearch`, with each locale's existing `discoveryClear` wording as its value, so no new translation), and no longer sets the iOS-only `clearButtonMode`, which would have doubled the control on iOS. The four screens that use the shared component get it, including Transactions beside its filter button. Source-wiring tests pin the button, its label and role, and the absence of the native prop; two fail against the old component. Deviation: not run on an Android device or the simulator; on iOS the button now shows whenever there is text, not only while the field is focused.

Native recheck, iOS half (iPhone 17e, fresh Metro `--clear` at `290c6bd95`): with "bus" in Transactions search and the keyboard dismissed, the field shows its own ✕ (iOS used to show the native one only while editing), and only one. Tapping it empties the field and restores the full list. Fixed on iOS; Android wasn't exercised (no Android device).
