# The README's "Try the live demo — no sign-up" link sends a signed-out app user to sign in, although the app can show that ledger as a guest

**Severity:** moderate (A2: the first-run demo path). **Estimate:** 30 minutes. Owner: mobile. A3: `README.md` links `https://beancount.io/ledger/open_ledger/example/income-statement?…`, which rewrites to `/reports`. While signed out, `pending-app-link.ts` stashes the link and `app/(app)/_layout.tsx` redirects to `/auth/welcome`. The link only replays after the user signs in. Yet `open_ledger/example` is a curated guest example (`src/common/guest/guest-state.ts`) that the `/examples` routes show without an account (w4/m29).

Code-level at `main` `99c937e0e`. Not run natively; see w21/344 for why.

## Fix

When the user is signed out and the target is a curated guest example on the hosted server, open the matching `/examples/(tabs)/…` route in guest mode instead of stashing the link.

**Acceptance:** with the app signed out, the README demo link opens the example's Reports in guest mode.

## Dedupe

Nothing on the board covers this. Searched `.pm/**` for "guest example", "live demo" and "signed-out link".

Fixed. Signed out, a link to one of the curated public examples (`open_ledger/example`, `nvidia`, `crypto-example`) on the official server now opens that example as a guest instead of waiting behind the welcome screen. `guestLinkVisit` (`common/app-links/guest-link-visit.ts`) decides: the example must be one of `EXAMPLE_IDS`, the selected server the official one, and the link's page one the guest tabs have (home, Transactions via journal, Reports via income statement or balance sheet). In `useAppLinkHandler`, when `routeIncomingAppLink` leaves a link waiting because nobody is signed in, the handler checks it, drops the stash, starts the guest visit on that example and view, waits for the navigators like the signed-in path, and replaces to the matching `/examples/(tabs)/…` route; if a session appeared while it waited it clears the visit instead. Everything else (other ledgers, budget, account, entry, commit and file links, self-hosted servers) behaves as before: stashed and replayed after sign-in. Tests (`guest-link-visit.test.ts`: the README demo link maps to Reports, home and journal mappings for every example, the unmapped cases, and the handler wiring; one handler test fails with `use-app-link-handler.ts` reverted; the two link-handler vm harnesses got stubs for the new imports). Not run natively: deep links are unusable on this simulator and hosted AASA is still 404 (w4/blocked/001), so the cold-start race with the signed-out redirect to welcome (the replace runs after the navigator-ready wait, like the signed-in path) is untested on a device.
