# The file editor has no way to dismiss the keyboard for writable non-.bean files (README.md, prices.csv, .py), covering about 300 pt of the editor for the whole session

**Severity:** moderate. **Estimate:** 20 minutes. Owner: mobile. A3: the app's keyboard accessory bar, whose chevron is the only dismiss control, is shown only for Beancount files: `showAccessory = canWrite && beancount && …`. w4/040 then hid the WebView's own accessory (`hideKeyboardAccessoryView: true`) unconditionally, removing its ✓. Plain-text files therefore have no dismiss affordance; Save doesn't blur, and WKWebView doesn't dismiss on scroll or tap.

Code-level at `main` `aa4a9793a`. The disposable ledger's Files list holds only `main.bean` and another worker's upload, so I didn't open a plain-text file natively.

## Where

`mobile/src/screens/ledger-file-editor-screen/index.tsx:601-602` (`showAccessory`), `:781` (`hideKeyboardAccessoryView: true`) and `:786-793`.

## Fix

Show the accessory bar with its dismiss chevron for every writable, editable text file (skip only the Beancount-specific buttons for non-.bean files), or blur the editor on Save.

**Acceptance:** open a writable `README.md` and tap into it: a dismiss control appears and hides the keyboard. `main.bean` is unchanged.

## Dedupe

w4/040 is the cause; its acceptance ("the keyboard can still be dismissed") is broken for these files. Searched `.pm/**` for hideKeyboardAccessoryView, "dismiss the keyboard" and "text file editor keyboard".

**Resolution (2026-10-21):** the file editor now shows the keyboard accessory bar for every writable file (`showAccessory = canWrite && isKeyboardVisible && initialized`). `KeyboardAccessoryBar` takes `shortcuts`, and the editor passes `shortcuts={beancount}`, so a README.md or prices.csv gets the bar with only its dismiss chevron, while `main.bean` keeps its insert buttons unchanged. Test: `keyboard-accessory-bar/__tests__/editor-keyboard-chrome.test.ts` (fails with the change reverted). Not exercised natively on a plain-text file.
