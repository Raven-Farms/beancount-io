# Account picker search with a space finds nothing ("credit card"), then offers to create an account the form refuses

**Severity:** moderate. Two-word searches are natural, and every one fails. **Estimate:** 20 minutes. Owner: mobile. A3: `filterAccounts` trims only the ends of the query, so an inner space must match a character in the account name, and account names never contain spaces. The Create row then appears, prefilled with the spaced text, which Open Account refuses as an invalid character.

Reproduced natively on the iPhone 17e simulator (iOS 27.0) at `main` `26fb7ee69`, with nothing created. New Transaction → first posting → Account Picker, search **"credit card"**: the picker shows "No matching accounts" and **Create "credit card"**, although `Liabilities:CreditCard:Visa` is open. A reviewer's Node run shows `food groc`, `public transit` and `bank checking` also return `[]`, while `food:groc` finds Groceries. Each Create prefill composes to a name like `Expenses:Credit card`, which fails `invalidCharacters`.

## Root cause

`mobile/src/common/account-search.ts:147-163` (`filterAccounts`). The Create row comes from `account-picker-screen/picker-sections.ts:142`.

## Fix

Split the query on whitespace and require every word to fuzzy-match (or treat a space as a component wildcard). Don't offer Create while the query has whitespace, or have `capitalizeAccountPrefill` turn "credit card" into `CreditCard`.

**Acceptance:** "credit card" lists `Liabilities:CreditCard:Visa`, and no Create row offers a name with a space. Unit cases cover the four queries above.

## Dedupe

w21/060 (search lowercasing), w21/122 (closed account) and w21/244 (drawer filter) are different. Searched `.pm/**` for filterAccounts, fuzzyMatch, multi-word and "credit card".

Fixed in mobile: the account picker's search reads its query as words. `filterAccounts` splits the trimmed query on whitespace and requires every word to fuzzy-match the account (scores add up; a single word scores exactly as before), so "credit card", "food groc", "public transit" and "bank checking" find `Liabilities:CreditCard:Visa`, `Expenses:Food:Groceries`, `Expenses:Transport:PublicTransit` and `Assets:Bank:Checking`, in any order and with any spacing. For a query that genuinely matches nothing, the Create row no longer seeds a name with spaces: `splitPrefillAccountName` joins the words of each component into one (`credit card` seeds `CreditCard`, `my savings:emergency fund` seeds `MySavings:EmergencyFund`), so Open Account does not refuse it; text without whitespace is untouched. Tests: multi-word cases in `account-search.test.ts` and the prefill cases in `open-account-name.test.ts`; two older pins that expected "coffee shop" to stay unrewritten were updated to this design (a lowercase hyphenated name still shows validation speaking); the new cases fail with the two files reverted. Deviation: I chose the note's second option (join the words) over hiding the Create row while the query has whitespace, so a new two-word account can still be created from the picker; no simulator run.
