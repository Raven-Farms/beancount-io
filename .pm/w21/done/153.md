# Signing out of the app leaves the browser signed in, so the next Sign In re-enters the same account with one "Approve" tap and no password

**Severity:** moderate (privacy/security on shared devices). After Settings → Sign out, anyone who taps Sign In sees the approve screen for the previous account and can sign in as them. **Estimate:** 1 hour. Owner: mobile, plus a dashboard OAuth logout check. A3: sign-in deliberately uses the shared system browser session (`preferEphemeralSession: false`, so a browser session is reused). Sign-out revokes the refresh token and clears local state but never ends the browser's beancount.io session cookie. The consent page opens straight on the existing account whenever that cookie is present.

Code-level at `main` `bca6a678c`. Not exercised natively, because it requires signing the QA session out and back in.

## Where

- `mobile/src/common/oauth/start-authorization.ts:27-30`
- `mobile/src/screens/setting/logout-action.ts:10-28` (no browser-session logout)
- `dashboard/src/features/oauth/funcs/mobile-consent-state.ts:31-34` and `dashboard/src/features/oauth/pages/mobile-consent.tsx:287` (the consent page auto-selects the cookie account)

## Fix

On sign-out, also end the browser session: open `/api-gateway/oauth/logout` in an auth session (`openAuthSessionAsync`) that returns to the app. Alternatively, use `preferEphemeralSession: true`, which gives up silent re-login. At minimum, show "Not you? Switch account" on the consent page when it was reached from the app after sign-out.

**Acceptance:** sign in, sign out, tap Sign In: the browser asks for credentials, or shows an explicit account chooser, rather than a one-tap Approve for the previous user.

## Dedupe

w1/m5/t009 lists global browser single sign-out across other clients as out of scope; this is the app's own session. Searched `.pm/**` for ephemeral, preferEphemeral, end_session, oauth/logout, authSess and "browser session".

**Resolution (2026-10-21):** fixed through the existing `screen_hint` channel rather than a browser logout. oidc-provider's `end_session` would not clear the dashboard's own login cookie, which is what the consent page reads.
- **Mobile:** sign-out marks "account choice needed" in SecureStore (`common/oauth/account-choice.ts`), after the local wipe so the wipe cannot erase it. While the mark is set, Sign In requests `screen_hint=select_account`; Sign Up keeps its own hint. The shared completer clears the mark once a sign-in persists, so a cancelled browser still asks next time.
- **backend-v2:** forwards `select_account` to the mobile consent page alongside `signup` (`OAUTH_CONFIG.interaction.selectAccountScreenHint`).
- **Dashboard:** the consent page then shows "Continue as {email}" / "Use another account" instead of a one-tap Approve. The chooser state names its alternative: register after Sign Up, login after a sign-out. A signed-out browser still gets the login form.

Older servers ignore the unknown hint, so the app is safe ahead of a deploy. Tests: mobile `authorization-url`, `authorization-launcher` and `logout` tests; backend `oidc-route.test.ts`; dashboard `mobile-consent-state`, `mobile-consent-search` and `mobile-loader` tests. Each package's new cases fail with its change reverted. Deviation: the browser session itself stays signed in; the acceptance's "explicit account chooser" branch is what's met. Not exercised natively, and the backend and dashboard halves need deploys.
