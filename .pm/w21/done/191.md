# A multi-line narration is silently changed on save: a line ending in an amount gets about 50 spaces inserted, and trailing spaces and `\r` are dropped

**Severity:** moderate. Narration text the user typed (for example "Groceries⏎2 x Milk 3.50 EUR") is committed altered, with no error, because the result still parses. **Estimate:** 30 minutes. Owner: ledger. A3: the serializer's Fava-style `align` and per-line rstrip run on every physical line of the rendered directive, including lines *inside* a multi-line string. A continuation line ending in `<number> <CURRENCY>` matches `ALIGN_RE` (its prefix has no `"`) and is padded to the currency column; every line is right-stripped. Mobile's narration field is multiline.

Code-level at `main` `ca1f36a34`. The reviewer ran the real transpiled serializer and parsed the output with `@rustledger/wasm` 0.24.0. `Groceries⏎2 x Milk 3.50 EUR` reads back as `"Groceries\n2 x Milk<47 spaces>3.50 EUR"`; `line one␠␠␠⏎line two` loses its spaces, and `x\r\ny` loses the `\r`. Quotes, backslashes, tabs, emoji and RTL text all round-trip exactly.

## Where

- `backend-cluster/ledger/src/foundation/rustledger/journal-serialize.ts:450` (`ALIGN_RE`) and `:742-760` (`stripAndAlign`), called from `entry-build.ts` (`entryInputToText`)
- `mobile/src/screens/multi-postings-transaction/narration-input-screen.tsx:24` (`multiline`)

## Fix

In `stripAndAlign`, skip alignment and rstrip for lines that begin inside an open string literal. `source-slice.ts`'s `endsInsideString` already tracks that.

**Acceptance:** the four inputs above round-trip byte-exact through `entryInputToText` and the parser. Ordinary posting lines still align. Add a serializer test.

## Dedupe

w3/415 is the same class of bug in the CLI's `bea format`. Searched `.pm/**` for "multi-line narration align", ALIGN_RE, stripAndAlign and "currency column".

**Resolution (2026-10-21):** `stripAndAlign` (`rustledger/journal-serialize.ts`) now treats text inside a quoted string as the user's, not layout. It tracks string state with `source-slice.ts`'s `endsInsideString` (now exported): a line that starts inside a string is not aligned, and a line that ends inside one is not right-stripped. Ordinary posting lines still align to column 61. All four inputs from the note (`Groceries⏎2 x Milk 3.50 EUR`, `line one␠␠␠⏎line two`, `x\r\ny`, and quotes/tabs/RTL/emoji) were serialized with `entryInputToText` and parsed with the real engine: each narration reads back byte-exact. Tests: `rustledger/__tests__/serialize-multiline-narration.test.ts` (4 of 5 cases fail with the serializer reverted). Needs a ledger deploy.
