# Account detail: the chart's "Try again" leaves the journal stuck on "Failed to load journal", which has no retry of its own

**Severity:** low. **Estimate:** 10 minutes. Owner: mobile. A3: `account-detail-screen/account-detail-screen.tsx:460-463` (`retryChart`) refetches only the context and the report, not `journalRefetch`. The journal's empty state (`:553-560`) takes only `loading` and `message`, with no retry. Opening a never-loaded account offline fails both. Back online, the chart's Try again restores the chart, but the journal stays failed until a pull. Code-level at `main` `966ff79aa` (selector behavior proven under `tsx`; Apollo 3.14.1 keeps the old `data` and sets `error` on a failed refetch, `useQuery.js:236-253`). Not run natively: the simulator can't cut the network here.

## Fix

Have `retryChart` also refetch the journal (or give the journal's failure its own Retry).

**Acceptance:** one Try again recovers the whole screen. A screen test covers it.

## Dedupe

See w21/239 and w21/081. Searched `.pm/**` for retryChart, journalLoadError and AccountJournalListEmpty.

---

**Resolved 2026-10-22** — `retryChart` also calls `journalRefetch()`, so the chart's Try again re-reads the context, the report and the journal: one tap recovers an account that never loaded. Source-level cases in `retry-recovers-screen.test.ts` (`mobile`); not run natively (the simulator cannot cut the network).

Native recheck (iPhone 17e): not exercised. It needs a failed refresh (the network cut, then restored), and the simulator can't cut the network here. The fix's tests cover it.
