# A journal app link drops its ?account=, ?time= and ?filter=, and keeps the user's earlier Transactions filter instead

**Severity:** moderate. The app shows a different account's journal from the one the link names. **Estimate:** 30 minutes. Owner: mobile. A3: the dashboard layout keeps `account`, `filter` and `time` on every ledger page (`retainSearchParams`), so copied journal URLs carry them routinely. `resolve-app-link.ts` (`case "journal"`) returns a bare `"/transactions"`. `openAppLinkTarget` sets `ledgerVar` but never touches `transactionFiltersVar`, and `selectFiltersForLedger` keeps any filter already stored for that ledger.

Code-level at `main` `99c937e0e`: the real resolver was run with `tsx`. Not run natively, because deep links are unusable on this simulator, and hosted AASA is still 404 (w4/blocked/001).

## Repro

`…/ledger/alice/books/journal?account=Assets%3ABank&time=2025-01&filter=%23trip` resolves to `{ledgerFullName: "alice/books", href: "/transactions"}`. With an earlier `Expenses:Food` filter on alice/books, the tab still reads `{statuses: [], range: "all", account: "Expenses:Food"}`. A plain `/journal` link also opens with the old filter.

## Fix

Have the resolver parse `account` and `time` (a year, a month or a range) into `TransactionFilters`, and write them to `transactionFiltersVar` before navigating. Otherwise, reset the scoped filters on any journal app link.

**Acceptance:** a journal link with `?account=X` opens Transactions filtered to X. One without parameters opens unfiltered.

## Dedupe

Only w21/223 (`?lineNumber=` on file links) is close. Searched `.pm/**` for "transactionFiltersVar", "?account=" and "app link".

Fixed. A journal app link now carries its own Transactions filters. `journalLinkFilters` (`common/app-links/journal-link-filters.ts`) reads `?account=` (up to the 256-character filter limit) and `?time=` (a year, a quarter such as `2025-Q2`, a month, a day, or two joined as `2025-01 - 2025-03`) into a custom window with inclusive ends, and `resolveAppLink` puts the result on the target as `filters`; a link without parameters carries the empty filters. `openAppLinkTarget` writes them under the target ledger through the new `setTransactionFiltersForLedger` (beside the var, so the reader-scoping test still holds) after selecting the ledger, so a link replaces whatever filter was left in the app. The server-cased ledger rewrite keeps the filters. Only journal links carry filters; other targets leave the stored filter alone. A week, an impossible date, a reversed range or any unreadable `time` filters nothing, and `?filter=` (the dashboard's free-text query) has no counterpart in the app and is ignored. Tests (`journal-link-filters.test.ts`: parameters, every period form, the unreadable cases, the wiring in `open-app-link`; the two pinned resolver expectations and the open-link vm harness updated for the new field and import); five of them fail with the resolver and opener reverted. Not run on a device: deep links are unusable on this simulator and hosted AASA is still 404 (w4/blocked/001).

Native recheck: not exercised. `xcrun simctl openurl` raises the system "Open in Beancount?" alert, which the simulator driver can't accept (its taps reach the app's window, not SpringBoard), and hosted AASA is still 404 (w4/blocked/001), so no journal link can reach the app here. The fix rests on its unit tests.
