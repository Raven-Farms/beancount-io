# Notifications' "Show older changes" never goes away when the commit count is a multiple of 30 (w21/431 regression)

**Severity:** minor-to-moderate. **Estimate:** 10 minutes. Owner: mobile. A3: `noOlder = lastPage !== null && shownPages >= lastPage` (`notifications-screen.tsx:281`, with `commit-pages.ts` `shownCommitPages`). With 60 commits, page 3 comes back `[]` (backend `commits-service.ts`), which sets `lastPage = 3`, but the rows add up to only 2 pages, so the button stays, and each tap asks for page 3 again.

Code-level at `main` `18b56a778`, from the reviewer's tsx run of the real `appendCommitPage`, `isLastCommitPage` and `shownCommitPages` with the screen's button rule (`:451-453`): with N=30 and N=60, four taps each return 0 rows and the button stays shown; with N=75 it disappears correctly. A last short page holding only duplicates does the same. The old counter hid the button in all of these. Not exercised natively (it needs an exact commit count).

## Fix

When a short page arrives, remember the merged row count (`endRows`), and use `noOlder = endRows !== null && listCommits.length >= endRows`; a refetch to page 1 still brings the button back.

**Acceptance:** with 30 or 60 commits, the button disappears after the empty page. Unit cases are added.
