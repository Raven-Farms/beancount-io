# New Transaction's account picker offers closed accounts, and the save is then refused

**Severity:** minor. **Estimate:** 30–45 minutes. Owner: mobile. A2: once a user closes an account (a paid-off card, an old bank), the mobile posting picker keeps listing it beside the open ones, with no marker. The user picks it, fills in the entry and taps Done. Only then does the server refuse: "This would add an error to your ledger: Posting to inactive account … (closed on …)". The dashboard's account combobox lists only open accounts.

Environment: `main` at `02be01390`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0), "today" = 2026-10-20. QA account, synthetic disposable ledger `mcp-agent-eval` with `2026-01-01 open Assets:Qa20261020Closed USD` / `2026-09-01 close Assets:Qa20261020Closed`. The fixture was removed afterwards and the ledger checked clean. Nothing was written by the refused save.

## Repro

1. Home → **+** → **Enter new transaction** → tap the first posting's account.
2. The Account Picker's Assets section lists **Assets:Qa20261020Closed** next to Checking, Cash and Savings, with no "closed" label.
3. Pick it, enter `-1.23` (Groceries auto-balances), tap **Done**.
4. The toast and inline error read: *"This would add an error to your ledger: Posting to inactive account Assets:Qa20261020Closed on 2026-10-20 (closed on 2026-09-01) (main.bean:93)"*. The ledger is unchanged.

`getLedger.attributes.accounts` includes the closed account. `getLedgerErrors` was empty, so the ledger itself was valid.

## Second path: payee autofill (observed)

The w21/023 payee seed has the same gap. A payee whose history used `Liabilities:Qa20261020OldCard` (closed 2026-09-01 after a pay-off) is picked on New Transaction (2026-10-21), and the form autofills **Liabilities:Q…20OldCard** as the FROM account. `seedPostingsFromPayee` (`multi-postings-transaction/payee-seed.ts:31-43`) takes `history.from/to.autoFill` with no open-at-entry-date check. Apply the same close-date filter there, skipping a closed suggestion in favour of the default, so the fix covers both entry points.

## Root cause

The picker (`mobile/src/screens/account-picker-screen/account-picker-screen.tsx`, the `accounts` memo around line 296) takes `assets`/`expenses` from `useLedgerReadContext` → `LedgerReadContext.graphql` → `getLedger.attributes.accounts`, which lists every declared account, closed ones included. Nothing filters by close date. The dashboard (`dashboard/src/common/components/ledger-comboboxes/account-combobox.tsx:44-48`) queries `GetLedgerAccounts` with `status: "open"` instead.

## Fix

For posting pickers (`type` other than `filter`), exclude accounts whose close date is before the entry's date. The picker already receives `entryDate` (w21/008), so a back-dated entry can still use an account that was open on that day. Source the close dates from the existing account-status query (`getAccounts` with status, or the account list with `closeDate`) instead of `attributes.accounts`. Keep closed accounts in the Transactions **filter** picker, since their history is still searchable. Optionally show them there with a "closed" hint.

**Acceptance:** with the fixture above, the New Transaction picker for a 2026-10-20 entry doesn't list `Assets:Qa20261020Closed`. Back-dating the entry to 2026-08-15 lists it again. The Transactions filter picker still lists it. A unit test covers the date boundary: an entry on the close date itself stays allowed, because Beancount sorts `Close` after same-day transactions. Confirm that rustledger agrees before encoding it.

## Dedupe

Searched `.pm/**` for closed account, inactive account, `status: "open"` and GetLedgerAvailableAccounts with mobile. w21/008 (back-dated open date) and w0/037 (duplicate open) touch the same picker but not close dates. w3/560 is the dashboard's never-opened account check. No item covers closed accounts in the mobile picker. Not checked: the Edit Transaction posting picker, which uses the same picker.

**Resolved 2026-10-21** — A new `LedgerAccountCloseDates` operation (`getLedgerAccountDirectives { account closedAt }`, behind `useAccountCloseDates`) supplies close dates. The pure `openOn`/`isOpenOn` (`mobile/src/common/account-close-dates.ts`) keep an account while `entryDate <= closedAt`. The posting pickers (every non-`filter` picker: New Transaction's postings, quick add, Add Budget) now list only accounts open on the entry's date, or today when none is passed, so a back-dated entry still offers an account open that day. The Transactions filter picker keeps closed accounts. The w21/023 payee autofill takes the same check: a side whose usual account is closed by the entry's date keeps the form's default, and nothing changes when both are closed. **Boundary verified on the engine:** rustledger accepts a posting dated the close day and refuses the next day, so an entry on the close date keeps the account. Generated code covers only the new operation. It was regenerated against the committed schema; production's newer, unrelated schema changes were not swept in. New `account-close-dates.test.ts` covers the 2026-10-20 exclusion, the 2026-08-15 back-date, the close-day boundary, the not-yet-loaded fallback and the picker's wiring.
