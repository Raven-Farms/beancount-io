# Returning to the app resets a guest's example ledger: navigation, filters and the open transaction are thrown away on every foreground

**Severity:** minor–moderate. **Estimate:** 20 minutes. Owner: mobile. A3: signed out, open Examples, pick an example, set a Transactions filter and open a transaction's detail. Then background the app, or pull down Control Center, and come back. The example restarts at its first tab:
- the filter is cleared,
- the detail screen and its back history are gone,
- the cache is refetched.

That contradicts the provider's own contract (`example-ledger-provider.tsx:104`): "Keep the anonymous cache and permissions around tabs AND their pushed read screens".

Environment: `main` at `705ec4ba4`. Code-level. The native repro needs signing the QA account out, which this run avoided.

## Root cause

`mobile/src/screens/examples/example-ledger-provider.tsx:119-124` bumps `attempt` on every AppState `active`. `GuestLedgerSession` is keyed on `attempt` (`:127-128`) and wraps the whole examples `<Stack>` (`examples-layout.tsx:98-131`). So the stack, the guest Apollo client (`clearStore`) and the scoped `transactionFilters`/`selectedTransaction` vars are all rebuilt. The bump was meant as a retry after a failed read. `ExamplesSession` already refreshes the catalog on activation (`examples-layout.tsx:61-66`).

## Fix

Bump `attempt` on activation only when the visit is in a failed state (`resumeFailure`). Otherwise refetch the active queries in place, as `use-foreground-refresh` does for signed-in screens.

**Acceptance:** a component test where an AppState `active` with a healthy visit keeps the same `GuestLedgerSession` instance, and a failed visit still remounts.

**Resolved 2026-10-21** — Shipped in the commit that moved this note (`mobile`). `ExampleLedgerProvider` no longer bumps `attempt` on AppState `active`. `GuestLedgerSession` now listens through the shared `createForegroundRefresher`, as signed-in screens do since w21/024. A healthy visit refetches the guest client's active queries in place, keeping its stack, the scoped filters and the open transaction. A failed visit (`resumeFailure` or a read failure) still calls `retry`, which remounts it. In `read-boundary.test.ts`, the outer provider registers no AppState listener, so a return can't change the session key. A background/active cycle on a healthy visit causes no remount, while a failed visit remounts once. Both fail with the fix reverted. Not driven natively, which would need signing the QA account out.

**Native recheck 2026-10-21:** not exercised. Guest mode needs the QA session signed out, which would mean signing back in through the browser flow mid-run. Covered by the unit tests only.
