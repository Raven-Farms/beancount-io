# After a failed Sign In, Welcome keeps the old server's error after the server is changed, and VoiceOver never announces the failure

**Severity:** minor. **Estimate:** 10 minutes. Owner: mobile. A3: Welcome stays mounted under the Server screen (`app/auth/_layout.tsx` is a plain Stack, and Save calls `router.back()`). The hook's server-change effect (`mobile/src/screens/welcome/use-native-sign-in.ts:41-50`) returns at `if (!running.current) return;` and never clears `failure`, so a failure that has already settled survives Save or Restore default until the next tap on Sign In. The failure text (`welcome/index.tsx:192-194`) has no `accessibilityRole="alert"`, unlike the session-ended notice just below it (`:196`), so VoiceOver users get no feedback after a failed or timed-out sign-in.

Code-level at `main` `eaa3c8730`; not exercised natively, because changing the device's server setting and signing out were out of scope for this run.

Steps: signed out, set an unreachable but valid `https://` server, tap Sign In, and wait for "Could not reach that server." Then open the gear, tap Restore default (or save a working URL) and go Back. Welcome still says "Could not reach that server.", which reads as if the new server is unreachable too.

## Fix

In the effect, call `setFailure(null)` whenever the server changes, before the `running.current` check. Add `accessibilityRole="alert"` to the failure text.

**Acceptance:** after the steps above, no error shows until the next attempt, and the failure text is announced. A hook or source test is added.
