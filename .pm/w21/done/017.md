# With camera access denied, Scan Receipt hides "Choose from photos", so a receipt already in the library can't be scanned

**Severity:** minor. **Estimate:** 20–30 minutes. Owner: mobile. A2: many users decline camera access on the first prompt, and many receipts arrive as screenshots or emailed images. The capture screen has a photo-library button, but it is drawn only in the granted-camera branch. A user who said no to the camera gets Cancel and Open Settings, nothing else.

Environment: `main` at `c1b96b438`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0), English. Camera access revoked with `xcrun simctl privacy <udid> revoke camera io.beancount.ios`, then reset afterwards.

## Repro

1. Revoke camera access (or tap **Don't Allow** on the first prompt).
2. Home → **+** → **Scan Receipt**.
3. The screen shows "Camera access is needed to take a photo of your receipt. Enable it in Settings." with **Cancel** and **Open Settings** only.

Control: with camera granted, the top bar has a photo-library icon (`onPickFromLibrary`) next to the flash toggle.

## Root cause

`mobile/src/screens/receipt-capture-screen/camera-view.tsx:134-166`: the `!permission.granted` branch returns early with only the two pills. The library action, wired from `receipt-capture-screen.tsx:58,170` (`ImagePicker.launchImageLibraryAsync`, which since w3/168 needs no broad library permission), is only in the camera branch's top bar (around line 202).

## Fix

Add a third action to the denied state, **Choose from photos**, which calls `onPickFromLibrary`. Optionally make it the primary action and the Settings link secondary. Give it `accessibilityRole="button"` and a translated label in all locales, reusing the existing library-button label if there is one. Keep Cancel and Open Settings.

**Acceptance:** with camera denied, Scan Receipt shows Choose from photos, and picking an image proceeds to the same preview → parse flow as the camera branch (verify up to the preview; don't spend parse quota in QA). With camera granted, nothing changes. The accessibility-labels guardrail passes.

w3/168 (done) let the picker work without broad library access, and w3/176 (done) labelled the camera actions. Neither covers the denied-camera screen. Searched `.pm/**` for receipt with denied, camera permission and library.
