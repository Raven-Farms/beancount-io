# Opening a ledger from Browse ledgers or Create Ledger stacks another copy of the whole tab bar each time

**Severity:** moderate. Each switch leaves the previous tab bar mounted underneath, with all its screens and live queries. Android Back from Home lands on the old copy, still on whatever tab it showed, and leaving the app takes one extra Back per switch. **Estimate:** 15 minutes. Owner: mobile. A3: both screens are pushed onto the `(app)` stack (from the drawer or the guard), then call `router.replace("/(app)/(tabs)")` after switching. In expo-router 57, that replaces the pushed screen with a *new* `(tabs)` route rather than returning to the existing one.

Code-level at `main` `4ba42392a`. A reviewer ran expo-router's own `findDivergentState`, `getPayloadFromStateRoute` and `StackRouter.getStateForAction` for "push Browse ledgers, then replace": after one switch the stack is `(tabs) | (tabs)`, and after three it is `(tabs) | (tabs) | (tabs) | (tabs)`. Not driven natively: the pinned Expo MCP can't send Android Back, and iOS edge-swipe competes with the drawer gesture.

## Root cause

- `mobile/src/screens/ledger-selection/index.tsx:185` and `mobile/src/screens/create-ledger-screen/create-ledger-screen.tsx:416`: `router.replace("/(app)/(tabs)")`.
- Pushed from `ledger-drawer.tsx:690,695` and `ledger-guard.tsx:158,176,209`.

## Fix

Use `router.dismissTo("/(app)/(tabs)")`, as `edit-transaction-screen` already does, so the stack pops back to the existing tab bar.

**Acceptance:**
- After three switches through Browse ledgers, the `(app)` stack holds one `(tabs)`.
- Android Back from Home leaves the app.
- A unit test on the router state (as the reviewer ran) covers it.

## Dedupe

w3/122 and w1/032 are other back-stack issues. Searched `.pm/**` for `router.replace`, `(tabs)`, "back stack", "hardware back" and dismissTo.

Fixed in mobile: Browse ledgers (`ledger-selection`) and Create Ledger now return with `router.dismissTo("/(app)/(tabs)")` after switching or creating, which pops to the tab bar already mounted below the pushed screen, as `edit-transaction-screen` does, instead of `router.replace`, which in expo-router replaced the pushed screen with a NEW `(tabs)` route and left another whole tab bar mounted (with every screen and live query) on each switch. The stack therefore keeps one `(tabs)` after any number of switches, and Android Back from Home leaves the app. If no tab bar exists below (the screen was reached on a bare stack), `dismissTo` navigates to it, which is what the replace did. Tests: `tab-bar-stacking.test.ts` checks both call sites; it fails with the two screens reverted; the Create Ledger vm harness stub gained `dismissTo`. Deviation: not a router-state test: the reviewer's check ran expo-router internals (`findDivergentState`, `StackRouter.getStateForAction`) that the jest-lite runner does not host, so the stacking itself was not re-run here, and Android Back was not driven.
