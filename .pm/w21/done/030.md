# A transaction the ledger reports as broken opens with no sign of its error

**Severity:** minor. **Estimate:** 30–45 minutes. Owner: mobile. A1/A2: Notifications lists "Transaction does not balance: residual 1.00 USD — main.bean:89". Opening that same transaction from Transactions shows a normal-looking detail: −$1.00 from Cash, +$2.00 to Transport, with no warning that it is unbalanced and therefore what the error is about. A user fixing errors must go through Notifications and the raw file editor; the place where they look at the entry tells them nothing.

Environment: `main` at `3c2e709ba`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). QA account, synthetic disposable ledger `mcp-agent-eval`, with three deliberate errors added and then restored byte-for-byte: a balance failure at line 87, an unbalanced `qa-20261020-err` at line 89, and `Assets:Nope` never opened at line 93.

## Repro

1. Put an unbalanced transaction in the ledger (`Assets:Cash -1.00 USD` / `Expenses:Transport 2.00 USD`).
2. The Home bell shows **3**, and Notifications lists all three errors with file and line. Correct.
3. Home → Recent Transactions → **qa-20261020-err**. The detail shows FROM −$1.00 / TO +$2.00 and Entry Context `main.bean:89`. There is no error banner and no mention of the residual. The same holds for `qa-20261020-err2` and its unopened account.

## Root cause

`mobile/src/screens/transaction-detail-screen/transaction-detail-screen.tsx` never reads ledger errors. `useLedgerErrors` (`src/common/hooks/use-ledger-errors.ts`, already used by Notifications and the bell) returns `{filename, lineno, message}`, and the detail already knows the entry's `meta.filename` and `meta.lineno` (shown in Entry Context).

## Fix

In the detail screen, select errors whose `filename` equals the entry's and whose `lineno` falls within the entry's line span (start line through the end of its postings; the source slice already gives the length). Render them in a red banner above Money flow, in the file editor's error-banner style, with an action to open the file editor at that line, as Notifications does. Keep the screen unchanged when there are no matching errors.

**Acceptance:** with the repro fixture, `qa-20261020-err` shows "Transaction does not balance: residual 1.00 USD" in a banner, and its action opens `main.bean` at line 89. `qa-20261020-err2` shows the never-opened error. An error-free transaction shows no banner. A unit test covers the line-span matcher (an error on the entry's first line, on a posting line, and on the next entry excluded).

## Dedupe

Searched `.pm/**` for "does not balance" and unbalanced with detail or mobile. The CLI items (w3/303, w3/264) and w3/156 (auto-balance toggle) are other surfaces. No item links ledger errors into the mobile transaction detail.

---

**Resolved 2026-10-20** — The transaction detail reads `useLedgerErrors` and selects, with the pure `selectEntryErrors`, the errors in the entry's own file whose line falls from its `meta.lineno` through the end of its source slice. It shows them in a red banner above Money flow, with "Open in the file editor" (13 locales). The action pushes the editor at the error's line, on the guest route for an example ledger. Error-free entries show nothing new, and an error with no line or in another file is left out. `select-entry-errors.test.ts` covers the first line and a posting line, the line before, the next entry, another file, no line, a longer path, a missing source, and the wiring above Money flow. Mobile gates pass: format, tsc, eslint, knip, and 2460 unit tests. Not checked on the simulator against the three-error fixture. Shipped in `497ebd610` (`mobile`).
