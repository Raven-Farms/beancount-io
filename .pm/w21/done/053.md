# Create Ledger keeps its draft forever in AsyncStorage, opening balance included (ADR021 says session-only, no balances), and resumes stale dates for the next user too

**Severity:** minor (privacy and stale-default). **Estimate:** 30–45 minutes. Owner: mobile. A2/A3: ADR021 ("Resuming") says to keep the in-progress setup "minus opening amounts … in browser **session** storage", because "raw balances are never written to unprotected browser persistence". Mobile writes the whole form to `AsyncStorage` on every change and removes it only after a successful create. The draft, including the opening balance, survives relaunches, days and sign-out. Reopening **+ New** later resumes at the old step with the old "Books begin" date and currency, and a different account signing in on the same device inherits it.

Environment: `main` at `d4f6d97d8`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). No ledger was created.

## Repro (observed)

1. Under region de_DE, open + New → **Preset** → **Next**. Step 2 shows EUR and Books begin 2026-10-21. Leave the screen without creating.
2. Switch the region back to en_US and terminate and relaunch the app. Then + New: the flow **resumes at Step 2** with **EUR** and **2026-10-21**, not the fresh defaults (USD, today).
3. The app's storage holds key `create-ledger-draft` = `{"step":1,"startKind":"preset","presetId":"PERSONAL","requestId":"req-…","values":{…,"currency":"EUR","historyStart":"2026-10-21","openingAccount":"","openingAmount":""}}`. `openingAmount` is part of the persisted values, so a typed opening balance is stored in plain persistent storage. (Only this key was read. No other storage values were printed.)

## Root cause

`mobile/src/screens/create-ledger-screen/create-ledger-screen.tsx`:

- Lines 256-266: an effect writes `{ step, startKind, presetId, requestId, values: watch() }` to `AsyncStorage` under the global key `create-ledger-draft` on every change. `values` includes `openingAmount`.
- Lines 237-253: any stored draft is restored on mount with no age limit, so `historyStart` comes back as a past date (compare w21/051).
- Line 330: the only `removeItem` runs after a successful create. `clearServerScopedState` (`src/common/server-url-actions.ts:28-53`), used on sign-out and server change, doesn't clear it, and the key isn't scoped by user or server.

## Fix

Follow ADR021. Exclude `openingAmount` (and any balances) from the persisted draft. Scope the draft to the signed-in user and server, and clear it in `clearServerScopedState`. Give it a short lifetime (for example the 24-hour `requestId` window) and don't restore `historyStart` from a draft older than today. Recompute it, or show it as changed. Keep the requestId resume that makes a retried create idempotent.

**Acceptance:** after entering an opening balance and leaving, the stored draft contains no amount. Sign-out removes the draft. A draft from yesterday reopens with today's Books begin (or asks). Unit tests cover serialization without amounts and expiry.

## Dedupe

Scope: this narrows the Create Ledger resume that ADR021 designed. It adds no draft-recovery UI, and `.pm/DO_NOT_DO.md`'s retired New Transaction draft recovery is unaffected. 
ADR021 sets the rule. w21/051 is the separate UTC-date default on the same screen. Searched `.pm/**` for create-ledger-draft, draft, resume and AsyncStorage with Create Ledger. No item.

**Resolved 2026-10-21** — A new `mobile/src/common/create-ledger-draft.ts` owns the Create Ledger draft under ADR021's resume rule:

- `serializeCreateLedgerDraft` stores the draft with `openingAmount` blanked and a `savedAt` stamp, so no balance is written to persistent storage. The opening account choice and `requestId` stay, so a retried create remains idempotent.
- `restoreCreateLedgerDraft` refuses a draft older than the `requestId`'s 24-hour window, a pre-change draft with no `savedAt`, or a corrupt one. A draft saved on an earlier day reopens with today's Books begin.
- `clearCreateLedgerDraft` removes it. It now runs after a successful create and in `clearServerScopedState`, which sign-out and a server change use, so the next account on the device starts fresh.

The draft is cleared on sign-out rather than keyed per user, which covers the "different account inherits it" case without a migration. Mobile has no session-only storage; the 24-hour lifetime plus clearing is its equivalent. No draft-recovery UI was added (`DO_NOT_DO.md`'s New Transaction rule is untouched). `create-ledger-draft.test.ts` covers serialization without the amount, a same-day resume, yesterday's draft reopening with today's date, 24-hour expiry, legacy and corrupt drafts, and the clear plus its sign-out wiring. `creation-refresh.test.ts`'s module mock gained the new module. Keeping the amount or dropping the sign-out clear fails 2 cases. Native gates pass: format, lint, typecheck, `yarn test:unit` (2540 passed, 1 skipped). Not exercised on the simulator. Shipped in the commit that moved this note (`mobile`).
