# Edit on an entry changed elsewhere opens a blank "Failed to load transaction" sheet with no Retry, every time

**Severity:** minor. **Estimate:** 15 minutes. Owner: mobile. A3: Edit Transaction's first-load `contextUnavailable` branch ignores `isEntryGone(contextError)`, though its Reload path already shows `transactionDetailRemoved`. The detail behind it doesn't refetch either, because no in-app write bumped `ledgerRevisionVar`, so w21/094's focus refetch doesn't fire. The pencil fails the same way on every tap.

Code-level at `main` `6a7949ccc`. This is the same scenario as w21/250 (the entry changed on the web while its detail is open), tapping the pencil instead of Delete. w21/094's original repro recorded the "Failed to load transaction" sheet natively.

## Root cause

`mobile/src/screens/edit-transaction-screen/edit-transaction-screen.tsx:427-431, 500-505` (the first-load branch), against `:199-203, 433-439` (the Reload path's gone handling).

## Fix

On a first-load NOT_FOUND, render the existing gone state and call `invalidateLedgerData(client, "entries")`, so the detail shows the gone state on return.

**Acceptance:** with the entry changed elsewhere, Edit shows "This transaction was changed or removed…", and Back shows the detail's gone state.
