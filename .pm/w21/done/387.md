# A delete or edit refused for a real reason is reported as "changed elsewhere" whenever the message contains "sha", "409" or "conflict" (e.g. an account named Shares)

**Severity:** moderate. **Estimate:** 20 minutes. Owner: mobile. A3: since w21/250, `classifyStaleDelete` (`transaction-detail-screen/delete-transaction.ts:47`) runs `isConflictError` (`common/ledger-conflict.ts:6-8`), a plain substring test for `sha`, `conflict` or `409`, over the whole error message, and that result replaces the refusal dialog (`:71-79`). Under `tsx`, using the validation-failure text from `__tests__/delete-transaction.test.ts`: an account like `Assets:Brokerage:Shares`, "expected 409.00 USD" or "(main.bean:1409)" all classify as `conflict`. So a delete that would break a balance assertion says "changed elsewhere… try again", and every retry gets the same answer. The edit path has the same substring test (`edit-transaction-screen/save-failure.ts:40-41`).

Code-level at `main` `62533363c`. Not driven natively.

## Fix

Check refusal codes (VALIDATION_FAILED, UNBALANCED) first, and treat only a CONFLICT/409 *code* or the exact "sha does not match" phrase as a conflict.

**Acceptance:** a refused delete on `Assets:Brokerage:Shares` shows the refusal reason.

## Dedupe

This is a follow-up to w21/250 (done). w4/045, w21/028, 367, 378 and 380 differ. Searched `.pm/**` for isConflictError, ledger-conflict, 409 and "false conflict".

Fixed. Conflict detection no longer fires on words that merely contain `sha` or `409`. `isConflictError` matches whole words only: `sha`, `sha256` and `sha256sum`, `conflict`, and an HTTP or status-code 409, so an account like `Assets:Brokerage:Shares`, an amount of 409.00 or a line `main.bean:1409` is no longer a conflict. `isConflictFailure(error)` is now the one classifier for every caller (the file editor's save, Edit Transaction's `selectOutcomeFailure`, the stale-delete classifier, the Files delete): it first rules out a refusal the server explained (`VALIDATION_FAILED`, `UNBALANCED`, or a `newLedgerErrors` extension), then accepts the `CONFLICT` code or the optimistic-lock text. Edit Transaction also no longer re-reads the app's own refusal wording for "conflict": a refusal in the app's words is returned as rejected as it is. Tests (`ledger-m15.test.ts`: look-alike words are not flagged and the real phrases still are; `delete-conflict.test.ts`: a refusal naming Shares is not a conflict; `delete-transaction.test.ts`: the refused delete on `Assets:Brokerage:Shares` shows its refusal reason in the dialog and is not stale; all four new cases fail with the three sources reverted; the existing sha256sum, 409 and conflict cases still pass). Not driven natively.
