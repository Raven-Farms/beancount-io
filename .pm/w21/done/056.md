# An account opened from the Accounts tab doesn't appear there after Done: the tree's account list (`getLedger`) isn't refreshed by the app's own write

**Severity:** minor. **Estimate:** 15–25 minutes. Owner: mobile. A2: Accounts → **+** → Open Account → **Done** returns the user to Accounts, where the account they just created is missing. It shows up only after some other screen happens to refetch the ledger's account list, or after a relaunch. The server reflects the new `open` within 2 s, so this is the client's invalidation, not backend lag (contrast w1/033).

Environment: `main` at `f120a3df2`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0), "today" = 2026-10-21. QA account, synthetic disposable ledger `mcp-agent-eval` (restored byte-for-byte afterwards).

## Repro (observed)

1. Accounts → **+** → name `Qa20261020Fresh2` under Assets → **Done**. The ledger now has `2026-10-21 open Assets:Qa20261020Fresh2 USD`.
2. Back on Accounts, about 6 s later: Assets lists Bank, Cash and the earlier `Qa20261020Fresh`, but **not** `Qa20261020Fresh2`.
3. Open New Transaction → the account picker, which mounts fresh and refetches `getLedger`. It lists Fresh2. Back on Accounts, Fresh2 now appears at $0.00.
4. Server check: after an API `open` of a third account, `getLedgerTrialBalance` contains it on the first read at +2.1 s, and on every read after.

## Root cause

- The Accounts tree grafts zero-balance accounts from `useLedgerReadContext(ledgerId).accounts`, which is `getLedger.attributes.accounts` (`mobile/src/screens/accounts-screen/accounts-screen.tsx:78-107` → `components/account-list/select-trial-balance.ts:88-115`, `accounts: accountNames`). A newly opened account has no postings, so this list is its only source.
- Open Account invalidates scope `"entries"` (`open-account-screen/use-open-account.ts:41`). `ENTRIES_FIELDS` (`src/common/apollo/invalidate-ledger.ts:43-63`) evicts `ledgerMeta` and `getLedgerTrialBalance` but **not `getLedger`**, which the read-context query (`LedgerReadContext.graphql`) uses. The mounted Accounts screen keeps the cached list (`nextFetchPolicy: cache-first`).

## Fix

Add `getLedger` to the eviction set for writes that can change the account set: at least the `entries` scope (account open and close, which `ENTRIES_FIELDS`' own comment lists) and `file`. Alternatively, have `useOpenAccount` refetch the read-context query after a successful open. Keep `getLedgerEntryContext` excluded, as documented.

**Acceptance:** after Done, Accounts lists the new account at $0.00 immediately, without relaunch or visiting another screen. A unit test asserts that `invalidateLedgerData(client, "entries")` evicts `getLedger`.

---

**Resolved 2026-10-21** — `ENTRIES_FIELDS` (`mobile/src/common/apollo/invalidate-ledger.ts`) now includes `getLedger` and `getLedgerAccountDirectives`, so the `file` scope inherits them. Open Account's `invalidateLedgerData(client, "entries")`, and every other entry or file write, evicts the ledger's account list and close dates, and Apollo refetches the watched read-context query. Accounts then grafts the new zero-balance account into its tree right after Done, and the posting pickers' close dates (w21/045) follow an open or close made in the app. `getLedgerEntryContext` stays excluded, as documented. The trade is one extra `getLedger` refetch per write while a consumer is mounted. `invalidate-ledger.test.ts`'s entries-coverage case now requires both fields, and it fails with the change reverted. The existing eviction and refetch tests prove that an evicted field refetches its watched query. Native gates pass: format, lint, typecheck, `yarn test:unit` (2548 passed, 1 skipped). Not exercised on the simulator. Shipped in the commit that moved this note (`mobile`).
