# Until the ledger's read context loads, or if its first load fails, a non-USD ledger's Home shows net worth and spending as $0 in USD

**Severity:** minor-to-moderate. A wrong headline flashes on every cold start, and on a failed first load it stays with no error. **Estimate:** 20 minutes. Owner: mobile. A3: Home takes `getPrimaryCurrency(currencies)`, which falls back to "USD" while `useLedgerReadContext` has no data. `isLoading` and `chartError` never wait on it, and Spending treats a context error as settled.

Code-level at `main` `26fb7ee69`. A reviewer's Node run on a EUR ledger:
- **Context not loaded or failed:** currency USD, headline 0, "1 not in total", and Spending this month 0 with "Not in total: 300 EUR".
- **Loaded:** EUR, headline 17,200, Spending 300.

## Root cause

`mobile/src/screens/home-screen/home-screen.tsx:72` (`getPrimaryCurrency`) and `:164-170` (`isLoading`, `chartError`). `isShowingStaleDataFromQueries` ignores a failure with nothing cached.

## Fix

Hold the chart and Spending skeletons until the read context settles. If it failed, show the card failure state (`CardLoadFailure`) instead of rendering with the "USD" fallback.

**Acceptance:** on a EUR ledger, Home never renders a USD headline. A failed context read shows the failure card with Retry. A unit or source check covers it.

## Also: Accounts has the same fallback (added 2026-10-21)

`mobile/src/screens/accounts-screen/accounts-screen.tsx:89` uses `getPrimaryCurrency` (USD fallback). `:111-114` lists nothing until accounts arrive, close dates are empty until loaded, and the skeleton (`:166-169`) waits for neither.

A reviewer's Node run on a EUR ledger:
- **Before the read context lands:** Assets reads "$200 · 1 not in total", and Wise ranks above Girokonto.
- **With the context loaded but close dates pending:** a closed, emptied account shows as a $0 row.

Hold the skeleton until both settle, and show `CardLoadFailure` if the context read fails.

Fixed in mobile: Home and Accounts no longer render in the "USD" fallback while the ledger's read context loads, or when it fails. A shared `selectReadContextState(data, error)` says loading, ready or failed. Home holds the chart skeleton while the context is loading and treats a failed first load as a chart failure; the charts card now shows `CardLoadFailure` with a Retry (refetching the context and the balance sheet) for a failed first load instead of the same skeleton, so a failure no longer looks like loading forever. The Spending card holds until its own context read lands (it no longer runs with the default Expenses root when the context errored) and shows the failure card with Retry for a failed context. Accounts (the note's added section) holds its skeleton until the context and the close dates have settled (`useAccountCloseDatesState`) and shows the failure card when the context read fails, so Wise no longer ranks above Girokonto and a closed, emptied account no longer flashes as a $0 row before the dates land. Cached data with a failed refresh is unchanged (the stale banner). Tests: `selectReadContextState` cases and wiring checks for the four components in `card-load-state.test.ts`; they fail with the four files reverted. Deviation: no simulator run on a EUR ledger.
