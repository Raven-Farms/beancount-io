# Update Budget keeps Currency editable, and its picker silently switches a non-operating budget currency to the first option

**Severity:** moderate. "Updating" a budget can start a second budget while the original keeps its old amount, with no indication. **Estimate:** 30 minutes. Owner: mobile. A3: the screen locks the account in update mode because "a budget's history belongs to one account+currency pair, so changing it here would silently start a different budget". The currency is part of that pair but stays editable.

Code-level at `main` `9c7878b18`.

## Scenarios

1. **Explicit change:** a USD card → Update Budget → Currency → EUR → 450 → Done writes `custom "budget" … 450 EUR`. A new EUR card appears and the USD card is unchanged.
2. **No explicit choice:** a budget in a currency that isn't an operating currency → Update Budget → open the Currency row → Done. The picker can't find the current value, so the wheel starts on the first item (`selectedIndexForValue` → 0). Done commits that item, and the update writes a new budget in another currency.

## Where

- `mobile/src/screens/add-budget-screen/add-budget-screen.tsx:194-205` locks only `account`.
- `:358-362`: the Currency `FormRow` always opens the picker.
- `:277-280`: `currencyItems` lists only operating currencies.
- Budgets are grouped by `account::currency` (`budget-screen/selectors/budget-selectors.ts:250`).

## Fix

In update mode, lock the currency like the account: a read-only row showing `params.currency`. When adding a budget, include the current value in `currencyItems` even when it isn't an operating currency, so the picker never falls back to index 0.

**Acceptance:**
- In update mode the Currency row isn't tappable and the written directive keeps the card's currency.
- Add mode is unchanged.
- A non-operating current value stays selected in the picker.

## Dedupe

This was weighed earlier in this run and not filed, because the dashboard's update dialog also leaves currency editable. The silent first-option switch, and the screen's own stated reason for locking the account, make it a defect. w21/034, w4/232 and w3/101 (the picker's first option on a different screen) are related. Searched `.pm/**` for "Update Budget currency", lockedAccount and account+currency.

**Resolved 2026-10-21** — Shipped in the commit that moved this note (`mobile`). In update mode, Add Budget's Currency row is now read-only, locked like the account. It shows the card's currency, so the written directive keeps it and can't start a second budget. The currency picker's options come from the new `budgetCurrencyOptions` (`add-budget-screen/currency-options.ts`): the operating currencies, or USD with none, plus the current value when it isn't among them. A non-operating currency therefore stays selected instead of falling back to the first option. Add mode is otherwise unchanged. `currency-lock.test.ts` covers the options and the lock wiring; the wiring check fails with the screen change reverted. Not exercised natively.

**Native recheck 2026-10-21** (iPhone 17e, iOS 27.0, `main` `236d64746`, Metro restarted with `--clear`; disposable QA ledger with a quarterly USD budget on `Expenses:QaBudQtr`, restored byte-for-byte to `f1a0b83c`): Budget → Update Budget shows **Currency USD as a plain row with no chevron**, read-only like Account. Date and Interval keep their chevrons. **Fixed** for the operating-currency case. A non-operating budget currency wasn't seeded.
