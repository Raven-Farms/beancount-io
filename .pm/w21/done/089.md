# The file editor's error banner shows errors from same-named files in other folders

**Severity:** moderate. A clean file shows another file's errors, and tapping one jumps to a line in the wrong file. **Estimate:** 30 minutes. Owner: mobile. A3: server error filenames are repo-relative paths (`included/payroll.bean`), so an exact path match is enough. Mobile also accepts a bare-name match and an `endsWith("/" + name)` match.

Code-level at `main` `d7a950d7f`. Not reproduced natively: it needs two included same-named files in different folders, which would add include lines to the shared QA ledger.

## Scenario

`main.bean` includes `2023/transactions.bean`, which has a syntax error at line 12, and `2024/transactions.bean`, which is clean. Opening `2024/transactions.bean` shows "1 error · line 12" in the banner; tapping it scrolls to line 12 of the clean file. Likewise, any `sub/main.bean` shows the root `main.bean` errors. The banner also hides the read-only notice (`index.tsx:700-702`).

## Root cause

`mobile/src/screens/ledger-file-editor-screen/utils.ts:13-19` `filterFileErrors` keeps an error when `e.filename === filePath || e.filename === fileName || e.filename.endsWith("/" + fileName)`. The second and third clauses match any file with the same basename. The dashboard compares the exact path only. Called from `index.tsx:648`.

## Fix

When `e.filename` is set, match `e.filename === filePath` only, after normalizing a leading `./` or `/`. Keep the null-filename message fallback (the comment at `:21-25`), but match the full path there when the message contains one.

**Acceptance:** unit cases in `utils` tests:
- `2023/x.bean` errors are excluded for path `2024/x.bean`.
- Root `main.bean` errors are excluded for `sub/main.bean`.
- An exact-path match is kept.
- A null filename whose message names the file is kept.
