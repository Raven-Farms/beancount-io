# Searching `#tag` or `^link` in Transactions finds nothing, even for the tags the detail screen shows

**Severity:** minor. **Estimate:** 30–45 minutes. Owner: mobile. A2: tags and links are how Beancount users group a trip, a project or a receipt. The transaction detail shows `#qa-trip` `#work` `^qa-receipt-001` as chips, but a Transactions search for `#work` is sent as a quoted string that matches nothing. The chips aren't tappable, so the app offers no way to list everything with a tag.

Environment: `main` at `c2065789b`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). QA account, synthetic ledger `mcp-agent-eval`. The fixture was restored byte-for-byte.

## Repro

1. Add `2026-08-30 ! "qa-20261020-tags" "qa-20261020 tagged pending" #qa-trip #work ^qa-receipt-001` (Cash → Coffee 4.25).
2. Transactions → open it. Details shows **TAGS #qa-trip #work** and **LINKS ^qa-receipt-001**. Tapping a chip does nothing.
3. Transactions → search `#work`. The app sends the filter `"#work"` (`toPlainSearchFilter`), which the server answers with zero rows (table below). Verified through the API with the same filter string, not by typing in the native field.

API control (`getLedgerJournal` with `filter`):

| filter | total |
| --- | --- |
| `#work` (Fava tag syntax) | **1** |
| `^qa-receipt-001` | **1** |
| `"#work"` (what the app sends) | **0** |
| `"^qa-receipt-001"` | **0** |

## Root cause

`mobile/src/screens/transactions-screen/utils/plain-search-filter.ts` quotes every query as a regex STRING literal, which matches payee and narration only. That is deliberate for punctuation (w2/045, w4/092). The side effect is that `#…` and `^…` tokens, which Fava's filter grammar supports natively, never reach it as tags or links.

## Fix

In `toPlainSearchFilter`, pass a query that is a single tag or link token through unquoted (`/^[#^][A-Za-z0-9_\-./]+$/`, Beancount's tag/link charset), and keep quoting everything else. Optionally make the detail screen's tag and link chips buttons that open Transactions with that query. Keep the punctuation and quote handling from w2/045 unchanged.

**Acceptance:** searching `#work` lists the tagged entry, `^qa-receipt-001` lists the linked entry, and `#nope` shows the empty state (no error). `Mr. Marcel`, quotes and `\x22` keep their current results. Unit tests in `plain-search-filter` cover the pass-through and a near-miss (`#a b` stays quoted).
