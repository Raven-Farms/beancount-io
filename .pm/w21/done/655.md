# The hosted engine drops tags and links on `note` directives, and `pushtag` on notes and documents, so tag and link filters miss them

**Severity:** low. **Estimate:** 30 minutes (upstream, plus the service). Owner: ledger (rustledger upstream). A3: rustledger's `NoteJson` has no tags or links, and `pushtag` isn't applied to notes and documents. `directive-filter.ts` `tagPredicate` checks only transactions and documents, and `journal-serialize.ts` writes a note's suffix as `tagsLinksSuffix([], [])`. Compared at `main` `1ec9cb250`: bundled `@rustledger/wasm` 0.24.0 against Python Beancount 3.2.3 with beanquery 0.2.0, on the same text. `2024-02-01 note Assets:Cash "dispute filed" #dispute ^case-42` under `pushtag #trip` has tags `{dispute, trip}` and link `{case-42}` in Beancount, and none in rustledger. Filtering the journal by `#dispute`, `#trip` or `^case-42` leaves those notes out.

## Fix

Report upstream (expose note tags and links, apply pushtag to notes and documents), then read and filter them in the ledger service.

**Acceptance:** the note matches those tag and link filters. Tests use the real engine.

**Resolved 2026-10-22** — the ledger service restores what the bundled `@rustledger/wasm` 0.24.0 still drops: the parse's source probe now reads a note's inline tags and links, and the tags `pushtag` holds over a note or a document (per file, until `poptag`), and carries them on the directive as it already did for a document's inline ones. The journal filter's `#tag` and `^link` predicates match notes, and a note's text rendering keeps its tags and links. The probe runs for a note only when a note line has a `#`/`^` token or its file pushes tags. Entry IDs are unchanged for notes (their hash still folds in no tags, as before). Not done here: upstream rustledger is not patched, and the public journal note DTO has no tags/links fields (a contract change). Tests: `directive-filter.test.ts`, `source-slice.test.ts` (fail without the change) and a live check in `scripts/verify-rustledger.ts` using the real engine (`backend-cluster/ledger`). A ledger service deploy carries it to production.
