# After w21/167, pre-entered events still count toward "enough history", so a manual Recurring mark reads "Irregular" instead of "Not enough history"

**Severity:** minor (a regression of w0/039's rule). **Estimate:** 10 minutes. Owner: mobile. A3: `detectRecurrence` now ignores future events, but `hasEnoughHistory` still counts them. The merchant detail header's date range also still ends on the future date without a "Scheduled" label; only the list row got it.

Code-level at `main` `61ad1916c`. Under Node, with 09-05 and 10-05 paid, 11-05 pre-entered and today 10-21: `hasEnoughHistory` is true while `detectRecurrence` is null, so a manual mark resolves to "Irregular" (`resolve-recurring.ts:37`). Before 167 this series was detected as Monthly.

## Root cause

`mobile/src/screens/merchants-screen/selectors/detect-recurrence.ts:283-291` (`hasEnoughHistory`), and `merchant-detail-screen.tsx:518-524` with `merchant-stats.ts:98` (the unbounded detail range).

## Fix

Pass `today` to `hasEnoughHistory` and apply the same `day <= today` filter. Label or cap the detail header's last date ("… – Aug 30 · Scheduled Nov 5").

**Acceptance:** the fixture's manual mark reads "Not enough history", and the detail header marks the future date. Unit cases are added.
