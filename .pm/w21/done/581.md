# Open Account: Back during "Saving…" drops the account picker's callback, so the new account isn't filled into the posting (despite the w21/194 comment)

**Severity:** low. **Estimate:** 10 minutes. Owner: mobile. A3 (code-level at `main` `f61267f7d`, proven under `tsx` with the real `pushOpenAccount`, `deleteFn` and `runAccountCreatedCallback`): `open-account-screen.tsx:258` clears the registration on unmount (`AccountCreated.deleteFn()`). Then `:365-374` ("Left during the save: … a picker still gets its account (w21/194)") calls `runAccountCreatedCallback`, which finds nothing, and the picker receives `null`. Picker ▸ Create "Expenses:Coffee" ▸ Done ▸ Back while saving: the account is opened, but the posting stays unfilled.

Not run natively (timing).

## Fix

Defer the cleanup until the in-flight save settles, or capture the callback before awaiting.

**Acceptance:** leaving during the save still fills the posting with the new account. A unit case covers it.

## Dedupe

Gap in w21/194 (done). Searched `.pm/**` for runAccountCreatedCallback and AccountCreated.

---

**Resolved 2026-10-22** — Open Account takes the picker's callback (`AccountCreated.getFn()`) before the save and hands it to `runAccountCreatedCallback(account, onCreated)`, so leaving during "Saving…" (which unmounts the screen and discards the registration) still fills the posting with the new account; the delivery stays one-shot and a no-op when nothing was registered. Cases in `push-open-account.test.ts` (`mobile`).
