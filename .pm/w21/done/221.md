# Text containing "%" followed by two hex digits is decoded twice between screens: a narration "50%50" comes back as "50P", and a file named "2024%20Q1" opens the wrong file

**Severity:** moderate. User text is silently changed and saved. In the file case, a different file can open in the editable editor. **Estimate:** 45 minutes. Owner: mobile. A3: `router.push({ pathname, params })` URL-encodes each value. expo-router decodes it once when it parses the URL, then `useLocalSearchParams` runs `decodeURIComponent` on the value a second time. Any literal `%XX` in free text is turned into the character it encodes. A `%` not followed by two hex digits (`50%off`), `#`, `?`, `+` and Unicode all round-trip correctly.

Reproduced natively on the iPhone 17e simulator (iOS 27.0) at `main` `24a2d3f2c`, with nothing saved:
1. Home → + → Enter new transaction → Narration. Paste `QA Split 50%50 run` → Save. New Transaction shows **"QA Split 50%50 run"**.
2. Tap Narration again. The input opens prefilled with **"QA Split 50P run"**. Save there would store the altered text.

A reviewer ran expo-router 57.0.4's own `resolveHref` / `getStateFromPath`, plus the decode from `useLocalSearchParams`, under Node: path `notes/2024%20Q1.bean` arrives as `notes/2024 Q1.bean`, and `tax-15%2025.bean` as `tax-15 25.bean`.

## Root cause

- `node_modules/expo-router/build/LocationProvider.js:61-64` decodes the already-parsed params again.
- Senders of free text:
  - `multi-postings-transaction-screen.tsx:734-746` (narration and payee) → `narration-input-screen.tsx` / `payee-input-screen.tsx`
  - `ledger-file-browser-screen/index.tsx:425` and `:522` (`params: { path }`)
  - `notifications-screen.tsx:157-163` (error rows)
  - `resolve-app-link.ts:139-146`, which also decodes the path itself
- Reader: `ledger-file-editor-screen/index.tsx:302`.

## Fix

Add one helper that encodes free-text params once more before `push` (`encodeURIComponent(value)`), or a wrapper hook that reads the raw value. Use it at every free-text param site. Add a round-trip unit test for `%20`, `%25`, `%50`, `%E2%82%AC`, `50%off`, `#` and `?`.

**Acceptance:**
- In the steps above, the reopened narration reads "QA Split 50%50 run".
- A file created as `2024%20Q1` opens as itself.

## Dedupe

The dashboard (w4/202, w3/m15) and the CLI/REST (w3/m46) had their own percent-encoding fixes; nothing on mobile. w21/216 is server URL validation. Searched `.pm/**` for useLocalSearchParams, decodeURIComponent, double-decod, `%25`, `%20` and percent.

Fixed in mobile: new helper `routeText` (`common/route-text.ts`) escapes each `%` in free text once more before it is pushed, so the router's second decode (the route-params hook decodes a value that expo-router already decoded when parsing the URL) returns exactly what was sent; a string without `%` is untouched. Applied at every in-app sender of free text: file paths (`ledger-file-browser` x2, notifications error rows, the transaction-detail error link, `resolve-app-link`), payee and narration (`add-transaction-next`, the quick-add selector, the multi-postings screen, the keypad's `currentPayee`), merchants (`payee` and the JSON `otherSpellings`), and the receipt prefill (`prefillPayee`, `prefillNarration`). Escaping at the sender rather than a reader hook was chosen because the second decode happens inside the router, so a reader cannot recover the original. Tests: `route-text.test.ts` models the push/parse/hook pipeline and round-trips `%20`, `%25`, `%50`, `%E2%82%AC`, `50%off`, `100%`, `#`, `?`, Unicode and empty text (and shows the unescaped values breaking), plus source checks that every sender escapes; the sender checks fail with three of the senders reverted. The `route-param-guards` pins were updated for the new call. Deviations: a deep link that carries a literal `%XX` (an external URL) is still decoded twice, as it is outside this app's senders; the agent screen's `q` param has no in-app sender and was left alone; no simulator run of the narration steps.
