# "Choose from photos" fails for ordinary iPhone camera photos (HEIC) with "Could not read receipt"

**Severity:** moderate. The default iPhone photo format can't be scanned from the library, and retrying always fails; only the in-app camera, which saves JPEG, works. **Estimate:** 20 minutes. Owner: mobile, plus a backend message fix.

Code-level at `main` `cd02f5446`. Not exercised natively: each attempt spends the QA account's AI parse quota. The provider-side rejection rests on Anthropic's and OpenAI's documented image formats (jpeg, png, gif, webp), which exclude HEIC.

## Root cause

- `mobile/src/screens/receipt-capture-screen/receipt-capture-screen.tsx:58-61` calls `launchImageLibraryAsync({ mediaTypes: ["images"], quality: 0.85 })` without `preferredAssetRepresentationMode`. On iOS, expo-image-picker then returns the original asset, HEIC included.
- `backend-cluster/backend-v2/src/features/llm/service/llm-service.ts:224-230` accepts any `image/*`, although its own message promises "JPEG, PNG, GIF, WEBP", and forwards it to the model. The provider error surfaces as `parse_failed` → `receiptParseFailed`.

## Fix

- **Mobile:** pass `preferredAssetRepresentationMode: ImagePicker.UIImagePickerPreferredAssetRepresentationMode.Compatible`, so iOS transcodes to JPEG.
- **Backend:** reject image types outside jpeg/png/gif/webp with a clear BAD_USER_INPUT on every surface.

**Acceptance:**
- A HEIC added with `xcrun simctl addmedia` and picked from the library parses into New Transaction.
- Uploading `image/heic` directly to the API returns the clear unsupported-format error.
