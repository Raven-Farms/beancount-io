# Open Account's name check disagrees with the engine on non-ASCII: Persian or full-width digits pass and are then refused, while a ZWNJ inside a Persian word is blocked

**Severity:** minor-to-moderate, especially for Persian users. A component starting with Persian digits from the default fa keyboard (`Assets:۱۴۰۲`) shows "Will be created as…" with Done enabled, and the server then refuses with a raw parse error. Meanwhile `Assets:Bank:خانه‌ها` (with a ZWNJ, normal in Persian) is blocked with "Use only letters, numbers, and hyphens", although rustledger accepts it. The app's own Persian string `حساب‌ها` contains a ZWNJ. **Estimate:** 30 minutes. Owner: mobile. A3: `startsSubcomponent` accepts any `\p{N}` as a component's first character, but rustledger allows only ASCII digits there. The body regex has no `\p{Cf}`, so it rejects ZWNJ.

Code-level at `main` `ca1f36a34`. The reviewer checked these names against `@rustledger/wasm` 0.24.0. Other names mobile accepts but the engine refuses: `１２３`, `٣Bank`, `०`, `Ⅷ`, `²nd`, `①Bank`, `ʰBank`, `ـBank`.

## Where

`mobile/src/screens/open-account-screen/account-name.ts:97-103` (`startsSubcomponent`) and `:142` (the body regex).

## Fix

Mirror the engine's grammar exactly: first character an uppercase or titlecase letter (or other letter, as w21/041 allows), or an ASCII digit; body letters, marks, digits, hyphens, and allowed format characters such as ZWNJ. Add a test table generated from the engine's accept/reject results.

**Acceptance:**
- `Assets:۱۴۰۲` is rejected client-side with a translated message.
- `Assets:Bank:خانه‌ها` is accepted and opens successfully.
- Existing w21/041 and w3/165 cases are unchanged.

## Dedupe

w21/041 and w3/165 fixed under-acceptance (Hindi, titlecase, digits); w23/033 is server-side validation. Searched `.pm/**` for "Persian digit", Arabic-Indic, full-width, ZWNJ and startsSubcomponent.

**Resolution (2026-10-21):** `validateAccountName` (`open-account-screen/account-name.ts`) now follows the grammar I probed in the real engine, `@rustledger/wasm` 0.24, over every code point from U+0021 to U+2FFFF (one open directive per file, requiring the account name to round-trip):
- **First character:** an uppercase or titlecase letter, any `\p{Lo}` letter, or an ASCII digit. Persian `۱۴۰۲`, full-width `１２３`, Devanagari `०`, `Ⅷ`, `²nd`, `①`, the modifier letter `ʰ` and the tatweel `ـ` are refused client-side (the translated "must start with an uppercase letter or digit" message).
- **Body:** letters, marks, digits, hyphens, plus ZWNJ and ZWJ. `Assets:Bank:خانه‌ها` is accepted, and `_` and spaces stay refused.

Tests: `src/__tests__/open-account-name.test.ts` has an accept/reject table (w21/041 and w3/165 cases unchanged and passing); it fails with the old validator. Deviation: the engine's body is more permissive than this (any non-ASCII character, even a space or an emoji). The app stays stricter than the engine there, so it never opens a name that `bean-check` itself would refuse beyond ZWNJ/ZWJ. Not exercised through a real Open Account.

**Native recheck (2026-10-21, iPhone 17e, Metro restarted with `--clear` at `main` `3529410fe`):** both cases behave as specified.
- **Persian digits refused:** pasting `Bank:۱۴۰۲` into Open Account (Assets root) shows "Each account component must start with an uppercase letter or a number." inline, and Done stays disabled.
- **ZWNJ accepted end to end:** with `Bank:خانه‌ها` (U+200C inside the word), Done is enabled and the preview reads "Will be created as Assets:Bank:خانه‌ها". Tapping Done committed `2026-10-21 open Assets:Bank:خانه‌ها USD` to the disposable QA ledger. `getLedgerErrors` returned `[]`, and the account appeared under Assets ▸ Bank on the Accounts tab.

The ledger was then restored to `f1a0b83c`. Full-width digits and the other rejected code points were not tried natively.
