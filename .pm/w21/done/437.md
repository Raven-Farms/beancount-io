# A Create Ledger request still in progress is reported as "A ledger with this name already exists"

**Severity:** minor-to-moderate. **Estimate:** 10 minutes. Owner: mobile. A3: `create-ledger-screen/ledger-name.ts:80` treats any `CONFLICT` code as a name conflict. The server's "Ledger creation conflict: A creation with this requestId is still in progress" is also `CONFLICT`, while a real name clash carries `reasonCode: LEDGER_NAME_ALREADY_EXISTS`. Under `tsx`, both classify as `conflict`. A user who reopens mid-create and taps Create is sent back with a false name error, and renaming then hits w21/434.

Code-level at `main` `9bd067834`.

## Fix

Map a name conflict only on `extensions.reasonCode === "LEDGER_NAME_ALREADY_EXISTS"` (or `field === "name"`). Treat the in-progress conflict as "Still creating…" and retry with the same `requestId` after a delay.

**Acceptance:** an in-progress create never shows the name error.

## Dedupe

w23/008 (server release) and w21/105 differ. Searched `.pm/**` for "still in progress", classifyCreateLedgerError and createLedgerNameConflict.

Resolved. `classifyCreateLedgerError` no longer reads every CONFLICT as the name's. A name clash is recognised by the server's `reasonCode: LEDGER_NAME_ALREADY_EXISTS` (or `field: "name"`, which backend-v2 merges into the GraphQL error extensions); a message saying "still in progress" is a new kind, `creating`; any other conflict falls through to the message check and, if that finds nothing, is not blamed on the name. For `creating` the screen keeps the requestId and shows the new `createLedgerStillCreating` text ("…still being created. Wait a few seconds, then tap Create again."), translated into all 13 locales; the same request tapped again returns the ledger once the first attempt finishes (w21/434). Tests cover the name clash, the in-progress conflict (as a GraphQL error and as a plain message) and an unrelated conflict; the last two fail against the old classifier. Deviation: the note's automatic retry after a delay is not built: the person taps Create again, on the same id; no native run.
