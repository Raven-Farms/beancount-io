# Mobile has no untranslated-string guard, and a straight port of the dashboard's would miss its common leak shapes

**Severity:** minor (prevention). Several English leaks filed this run (w21/091, w21/140, w21/176, w21/177), plus some unfiled small ones, would have been caught. **Estimate:** 2 hours. Owner: mobile. A3: mobile's locale tests check only the translation files. `accessibility-labels.test.ts` checks that a label exists, not that it's translated (`accessibilityLabel="Close"` passes), and `permission-strings.test.ts` actively pins English.

Code-level at `main` `55e5919a6`.

## Leaks a guard would flag today (besides the filed items)

- `create-ledger-screen.tsx:598`: `placeholder="YYYY-MM-DD"` (de "JJJJ-MM-TT", ru "ГГГГ-ММ-ДД")
- `components/picker/index.tsx:183-184` (`"Done"`/`"Cancel"`) and `components/text-input-modal/index.tsx:148-149` (`"Confirm"`/`"Cancel"`) default props. These are latent: current callers override them.
- `setting/main-content.tsx:203`: `|| "Unknown"`

## What a port of `dashboard/src/test/no-untranslated-user-facing-strings.test.ts` would miss

- Its prop-default rule matches only names like `label`, `message`, `text`, `title` or `*Label`, so `confirmButtonText` and `cancelButtonText` slip through.
- Its attribute set is web-only. Mobile needs `accessibilityLabel`, `accessibilityHint`, `accessibilityValue.text`, `Stack.Screen` `title`/`headerTitle`, `Alert.alert` arguments and `showToast({message})`.
- It ignores `??`/`||` fallbacks in `.ts` helpers (how w21/140 happened), helper-built unit words (w21/177) and number-only templates (w21/096).

## Fix

Add an AST-based mobile guard covering those shapes, with an allowlist for brand names, currency codes, URLs and account names. Fix or allowlist the current hits.

**Acceptance:** the guard fails on a reintroduced `accessibilityLabel="Close"`, `?? "Pending"` or `placeholder="YYYY-MM-DD"`, and passes on main after the listed leaks are fixed.

## Dedupe

w0/m1 and w4/158 guard the translation files; w4/done/043 fixed two literals without a guard. Searched `.pm/**` for "untranslated-user-facing", "no-untranslated", "hardcoded English" and "mobile guard".

**Resolution (2026-10-21):** new AST guard `src/__tests__/no-untranslated-strings.test.ts` parses `src/` and `app/` with the TypeScript compiler. It flags:
- string literals in copy JSX attributes (`accessibilityLabel`, `accessibilityHint`, `placeholder`, `title`, `headerTitle`, `label`, `message`);
- JSX text;
- `??`/`||` string fallbacks, parameter and destructured defaults, and `Alert.alert`/`showToast` arguments, when sentence-like;
- copy object keys (`title`, `headerTitle`, `headerBackTitle`, `text`, `message`, `label`, `placeholder`), when sentence-like.

Its allowlist covers the brand, URLs and Beancount's default root names. Self-tests confirm it fails on a reintroduced `accessibilityLabel="Close"`, `?? "Pending"`, `placeholder="YYYY-MM-DD"`, a "Done" default and an `Alert.alert` sentence, and that type tags pass.

Current hits fixed: Create Ledger's date placeholder (`datePlaceholder`, 13 locales); the Picker and TextInputModal default buttons (now `t("done")`/`t("confirm")`/`t("cancel")`); Settings' version fallback (`t("unknown")`); the Sankey's English `refundsLabel`/`clawbacksLabel` defaults (now required, as the screen already passes them). Allowlisted: "Beancount.io", the server URL placeholder, default root names. With a leak reverted the guard fails. Deviations: helper-built unit words and number-only templates (w21/177, w21/096) are not detected by this guard.

**Recheck 2026-10-21:** this is a test-only guard, with nothing to drive on the simulator. Its incidental copy fixes (Create Ledger's date placeholder, the picker and modal default buttons) were in place on the bundle used for the w21/104–107 rechecks.
