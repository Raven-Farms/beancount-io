# After a reinstall, Sign In still offers one-tap Approve for the previous account (w21/154 doesn't set the account-choice mark)

**Severity:** minor-to-moderate (privacy on shared or handed-down phones). **Estimate:** 10 minutes. Owner: mobile. A3: w21/154 deletes and revokes the previous install's Keychain session but never calls `markAccountChoiceNeeded`. w21/153 built that mark so the next Sign In asks for an account choice, and only Log out sets it. Sign-in shares browser cookies (`preferEphemeralSession: false`), which survive an uninstall, so the consent page still offers the previous account's one-tap Approve.

Code-level at `main` `3e830700b`. Run under Node, `buildAuthorizationUrl` yields no `screen_hint` after the reinstall path and `select_account` after a sign-out.

## Root cause

`mobile/src/common/vars/session.ts:43-55` (`forgetSessionFromPreviousInstall`). The only caller of `markAccountChoiceNeeded` is `src/screens/setting/logout.ts:26`.

## Fix

When a previous-install session is found, also call `markAccountChoiceNeeded().catch(() => undefined)`, and add a case to `install-marker.test.ts`.

**Acceptance:** after a reinstall that found a stored session, the first Sign In requests `screen_hint=select_account`.

## Dedupe

This is a follow-up to w21/153 and w21/154 (both done). Searched `.pm/**` for forgetSessionFromPreviousInstall, markAccountChoiceNeeded and select_account.

Fixed. `forgetSessionFromPreviousInstall` now calls `markAccountChoiceNeeded()` (best effort) when it finds a session left in the Keychain by a previous install, before it deletes that session, so the first Sign In after such a reinstall requests an explicit account choice (`select_account`) like a sign-out does, instead of offering the previous account's one-tap Approve from the browser cookies that survive an uninstall. A reinstall that found no stored session sets nothing. Source check added to `common/__tests__/install-marker.test.ts` (fails with `session.ts` reverted); the `buildAuthorizationUrl` side is the existing w21/153 path, which already turns the mark into `select_account`. Mobile gates and deadcode green; not run through a real reinstall.

**Recheck (2026-10-21): not exercised natively.** It needs uninstalling and reinstalling the dev build and then a full browser OAuth sign-in. That would wipe the signed-in QA session this loop depends on, and credential flows stay out of this loop.
