# Creating a ledger fails on any server older than 2026-10-20, even for Starter and Sample, with a generic error or an endless preview Retry (ADR021's older-backend rule not followed)

**Severity:** minor for self-hosted users. **Estimate:** 45 minutes. Owner: mobile. A3 (code-level at `main` `851db958a`; validated with graphql-js against the 2026-08-14 schema): `common/graphql/queries/createLedger.graphql:6-7, 14-15` always declares `$setup: LedgerSetupInput` and `$requestId` and passes them. `previewLedgerSetup.graphql:1-2` uses the same type. Both were added on the backend in `45ddc33f8` (2026-10-20), and mobile adopted them in `c597c8c9d`. An older server rejects the document (`Unknown type "LedgerSetupInput"`, `Unknown argument "setup"`) for every start kind (`create-ledger-screen.tsx:448-467`), so the user sees `createLedgerGenericError`. For presets, `previewFailureKind` (`ledger-name.ts:157-170`) treats `GRAPHQL_VALIDATION_FAILED` as "unreachable", which gives an endless Retry card, and `previewBlocked` stops Create.

`docs/adrs/ADR021-backend-v2-ledger-creation-experience.md:117-121` says clients must treat a rejected `setup`/`requestId` as "this server does not support guided setup", say so, and offer creation with server defaults. `:180` adds "older backends must keep working".

## Fix

Send Starter and Sample without the new arguments (a separate document), and map a validation error on the setup path to the ADR's message plus an explicit "create with server defaults" choice.

**Acceptance:** against the old schema, Starter and Sample create, and a preset shows the unsupported-server message with the fallback. Tests validate the documents.

## Dedupe

None of w3/m54, w4/314-321, w23/048-049 or w2/m54 covers older backends. Searched `.pm/**` for "older backend" and LedgerSetupInput.

**Resolved 2026-10-22** — a second mutation document, `CreateLedgerBasic` (name, privacy, description, template), is the fallback: when a create fails with a validation rejection (`isUnsupportedDocumentError`, now shared with w21/591) and the start is Starter or Sample, the same create is sent without `setup` and `requestId`; a preset cannot, and shows "This server does not support guided setup. Go back and choose Starter or Sample …" (`createLedgerSetupUnsupported`, 13 languages, naming each locale's own Starter and Sample labels) both on Review and after Create, in place of the endless Retry (`previewFailureKind` gains `unsupported`). The note's "create with server defaults" choice is that message pointing at the first step, not a button. Tests: the real submission handler against a rejecting server (`creation-refresh.test.ts`), and `older-server.test.ts` validating the basic document against the committed older schema (`mobile`). As in w21/591 the generated code was written by hand in codegen's shape, so a real `yarn codegen` run should confirm it; the translations are mine.
