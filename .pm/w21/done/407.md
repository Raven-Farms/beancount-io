# Regression from w21/270: "APPLE *ICLOUD", "APPLE *SUBSCRIPTION" and similar charges lost the Apple logo

**Severity:** minor-to-moderate (common Apple subscription descriptors). **Estimate:** 10 minutes. Owner: mobile. A3: in `common/brand-matcher/index.ts`, "apple" is both a `COMMON_WORD_KEYS` entry (`:184`) and an `AGGREGATORS` head (`:206-212`). An unrecognised tail is rewritten to `"apple <tail>"` (`:230-231`) and re-matched (`:267-269`), and the common-word scan skips it (`:277`). Under `tsx`, `APPLE *ICLOUD`, `APPLE *SUBSCRIPTION`, `Apple *Apple Music` and `APPLE* BILL` return `null` now but `apple.com` at `90555dc51^`; only `APPLE *ITUNES` still matches.

**Natively confirmed (2026-10-21, iPhone 17e, `main` `c9c36d8e7`):** a disposable "APPLE *ICLOUD" payee shows the generic document icon in Merchants, with no Apple logo. The ledger was restored to `f1a0b83c`.

## Fix

When the tail after an aggregator head is not a recognised brand, return the head's own brand (`BRAND_MAP[head]`) instead of re-matching `"head tail"`. Add the APPLE cases to `processor-prefix.test.ts`.

**Acceptance:** "APPLE *ICLOUD" shows the Apple logo, and "PAYPAL *NETFLIX" still shows Netflix's.

## Dedupe

This is a regression from w21/270 (done). Searched `.pm/**` for "APPLE *", ICLOUD, "apple logo" and aggregator.

Fixed. When an aggregator's tail after `*` is not a brand the matcher knows, the match now falls back to the head's own brand. `resolveStarMerchant` still reads "head tail" so a more specific key wins ("UBER *EATS" is ubereats.com), and `matchBrand` returns the head's brand (`BRAND_MAP[head]`) when that scan finds nothing. That is the case w21/270 broke: "apple" is a common-word key that matches only on its own, so "apple icloud" matched nothing and "APPLE *ICLOUD", "APPLE *SUBSCRIPTION", "Apple *Apple Music" and "APPLE* BILL" lost the Apple logo. A processor's unknown merchant still has no logo ("PAYPAL *LOCALBAKERY"), "PAYPAL *NETFLIX" is still Netflix, and a longer name that merely starts with Apple ("Apple Valley Dental") still gets none. Tests (`processor-prefix.test.ts`: the four descriptors and ITUNES, an unknown Uber tail, the processor and specific-tail cases and the longer name; the first fails with the matcher reverted). Not run natively.

Native recheck (iPhone 17e, fresh Metro `--clear` at `6c3c3c84c`): payees "APPLE *ICLOUD" and "APPLE *SUBSCRIPTION" (disposable ledger, restored) both show the Apple logo on their Transactions rows. Fixed.
