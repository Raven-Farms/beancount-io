# Reports labels a net-negative category "0%" of its section

**Severity:** minor. **Estimate:** 10–15 minutes. Owner: mobile. A2: when a period's income is a clawback, or a category is net-refunded, Reports shows the row's amount correctly (`-$250.00`) next to **"0%"**. It is the only category, so it is 100% of the section, or rather "no meaningful share". A literal 0% is simply wrong, and VoiceOver reads it too.

Environment: `main` at `01503f884`+, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). QA account, synthetic disposable ledger `mcp-agent-eval` with a 2026-10-07 `Income:Salary +250.00 USD` clawback (restored byte-for-byte afterwards).

## Repro

Reports → **1M**. The Income card reads **-$250.00**, with the single row **Salary -$250.00 · 0%** and an empty bar. The income/expense chart above draws the −$250 bar correctly (the w21/022 fix).

## Root cause

`mobile/src/screens/reports-screen/components/category-breakdown.tsx:279-282`:

```ts
// Negative rows (a net-refunded category) can't draw a meaningful slice, so the bar is hidden but the amount still shows.
const pct = total > 0 ? Math.max(0, Math.min(100, (node.value / total) * 100)) : 0;
```

Hiding the bar is deliberate. But `pct` collapses to `0`, which is then printed (`{Math.round(pct)}%`, line 331) and spoken (`breakdownRowAccessibilityValue(amountText, pct, t)`, line 345).

## Fix

Make `pct` nullable: `null` when `total <= 0` or `node.value < 0`. Render "—" (or omit the label) and skip the share in the accessibility value when it is `null`. Positive rows keep their percentages.

**Acceptance:** the repro shows Salary −$250.00 with no "0%" (a dash or nothing), and VoiceOver says the amount without a share. Ordinary positive categories are unchanged. A render test covers a negative-only section and a mixed section with one refunded row.

## Dedupe

w3/216 (done) preserved negative signs in category amounts. Searched `.pm/**` for category share, percent and negative. No item covers the share label.

## Adjacent state (same repro)

The Sankey draws only positive links by design (`sankey-data.ts`, w0/034), so a range whose only income or expense rows are negative has no links (`cash-flow-sankey.tsx:250,281`). If touching this card, use copy that doesn't claim nothing happened, such as "Nothing to chart: this range has only refunds or reversals", when the statement totals are non-zero.

Positive rows keep their clamped percentages. `select-breakdown-rows.test.ts` covers positive shares, a negative-only section (the -$250.00 clawback), a zero section, a refunded row beside positive ones, and the spoken value. **Deviation:** the note asked for a render test, but the repo's jest-lite runner doesn't render React Native components, so the logic was moved into the tested pure function and the component only calls it.
