# Transaction filters survive sign-out and sign-in, unlike every other server-scoped local value

**Severity:** minor (privacy and consistency). The next sign-in on the device, possibly another user with access to the same shared or public ledger, opens Transactions already narrowed by the previous session's account or status filters. **Estimate:** 15 minutes. Owner: mobile. A3: `clearServerScopedState` says it clears "every local value that can be derived from a server-backed ledger". It resets the selected ledger, recent accounts, merchant overrides and the Create Ledger draft, but not `transactionFiltersVar`. Sign-out doesn't restart the JS runtime.

Code-level at `main` `650ce6f72`. Not exercised natively: it needs a full sign-out and OAuth sign-in, and the true cross-user case needs a second account on the same ledger.

## Root cause

- `mobile/src/screens/transactions-screen/filters/var.ts:21` is an in-memory reactive var keyed by ledger, not by user or server.
- `mobile/src/common/server-url-actions.ts:29-57` `clearServerScopedState` doesn't reset it.

## Fix

Reset `transactionFiltersVar` (and its draft) in `clearServerScopedState`, and add it to that function's test, which enumerates the cleared values.

**Acceptance:** set an account filter, log out, and sign in. Transactions opens unfiltered with no filter badge. The scoped-state test covers the var.

## Dedupe

w3/115 is the ledger switch; w21/071 is the auth-error teardown (a different path, filters not mentioned). Searched `.pm/**` for transactionFiltersVar, "sign out" together with filter, and clearServerScopedState.

**Resolved 2026-10-21** — Shipped in the commit that moved this note (`mobile`). `clearServerScopedState` now calls the new `resetTransactionFilters()` (`filters/var.ts`), which puts `transactionFiltersVar` back to no filters. Log out, a server change and (since w21/071) an auth-error sign-out therefore leave Transactions unfiltered for the next sign-in. The filter modal's draft is component state that dismissal already drops, so it needs no reset. The reset is a function in the var's own module, so `common/` never touches the var directly and the existing every-reader-scopes-it guard still holds. The cleanup test in `error-handling.test.ts`, which lists the cleared values, now includes it and fails with the change reverted. Not exercised natively, since it needs a full sign-out and sign-in.

**Native recheck 2026-10-21:** not exercised. It needs a sign-out and a fresh browser sign-in of the shared QA session mid-run. Covered by the unit tests only.
