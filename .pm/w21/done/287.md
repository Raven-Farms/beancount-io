# VoiceOver never reads Settings row descriptions (including "Deleting account…"), and reads Version as "dimmed"

**Severity:** minor (accessibility). **Estimate:** 15 minutes. Owner: mobile. A3: `ListItemHorizontal` builds its label from `title` and `content` only, and an explicit label replaces the children, so `description` is never spoken. Rows without `onPress` are disabled touchables, which VoiceOver reads as "dimmed". The Delete Account row has no busy state while deleting.

Code-level at `main` `567bd1801`. A reviewer rendered the real `ListItemHorizontal` under Node:
```
Delete Account (idle)     => label "Delete Account", role button | visible: "Delete Account", "Permanently remove your account and data"
Delete Account (deleting) => label "Delete Account", disabled false | visible: "Deleting account…"
Version                   => label "Version, 1.20261002.50", disabled true
```

## Root cause

`mobile/src/screens/setting/list-item.tsx:87-92` (label), `:99` (`disabled={!onPress}`) and `:114-116` (description). The Delete Account row is at `main-content.tsx:171-196`.

## Fix

- Include `description` in the label, or move it to `accessibilityHint`.
- Pass `accessibilityState={{ busy: deleteAccountLoading }}` on Delete Account.
- Render Version as a plain accessible `View`.

**Acceptance:** VoiceOver reads "Delete Account, Permanently remove your account and data, button", announces busy while deleting, and reads Version without "dimmed".

## Dedupe

w21/142, 224 and 243 are the same pattern at other sites; none lists Settings. Searched `.pm/**` for ListItemHorizontal, deleteAccountInProgress and dimmed.

Fixed. The Settings row label now comes from `listItemLabel` (title, then the value, then the description when they are text), so Delete Account reads "Delete Account, Permanently remove your account and data" plus the button role, and "Deleting account…" while it runs. `ListItemHorizontal` takes a `busy` prop that sets `accessibilityState.busy`, passed by Delete Account (`deleteAccountLoading`). A row with no action (Version) renders as an `accessible` plain `View` instead of a disabled `TouchableOpacity`, so VoiceOver no longer reads it as "dimmed". Tests in `setting/__tests__/list-item-accessibility.test.ts` (label cases plus structural checks; the structure cases fail with `list-item.tsx` and `main-content.tsx` reverted). Mobile gates and deadcode green; not read with VoiceOver.
