# Without `conversion`, trial balance, account report and interval totals value in USD on GraphQL but in the operating currency on REST and MCP

**Severity:** minor (parity rule; latent for mobile, which always passes `conversion`). On an EUR ledger, the same request without `conversion` returns USD-valued trees from GraphQL and EUR-valued ones from REST and MCP. **Estimate:** 30 minutes. Owner: backend-v2. A3: GraphQL's `ConversionArgs` sets `defaultValue: "USD"`. REST and MCP pass no conversion, and the ledger service's `resolveConversion(undefined)` returns the operating currency.

Code-level at `main` `afd7265e3`; the reviewer read all three adapters and the shared service.

## Where (`backend-cluster/`)

- GraphQL: `backend-v2/…/ledger-report-resolver.types.ts:21` (USD default), used at `ledger-finance-resolver.query.ts:317` and `ledger-data-resolver.query.ts:633, 670`
- REST: `analysis-handler.ts:36` (optional, no default), segments at `:124, 138, 166`
- MCP: `mcp-resources.ts:236-258`
- Service: `ledger/src/foundation/rustledger/cost-valuation.ts:39-41`

## Fix

Remove GraphQL's `"USD"` default so it falls through to the operating currency, matching REST and MCP, and check the balance-sheet and income-statement routes (REST hard-codes "USD" at `reports-handler.ts:47`) for the same alignment.

**Acceptance:** on an EUR ledger, the three surfaces return EUR-valued trees without `conversion`. Add a parity test.

## Dedupe

Searched `.pm/**` for "ConversionArgs defaultValue", resolveConversion and "default conversion".

Fixed in backend-v2: GraphQL `ConversionArgs.conversion` no longer defaults to "USD" (now nullable), and the REST/MCP statement query schema (`statementQuerySchema`, balance sheet and income statement) drops its `.default("USD")`, so an omitted conversion reaches the ledger service as undefined and values in the operating currency on all three surfaces. The OpenAPI snapshot is regenerated (the `default` is gone, the description names the new default). `statement-parity.test.ts` (which drives GraphQL, REST and MCP) and `income-overview-currency-parity.test.ts` now pin that no conversion is sent when omitted; with the fix reverted, 8 of those tests fail. Deviation: the summary helper `resolveCurrency` still labels a data-less report "USD"; that is a label for empty data, not a valuation, and was left alone. The legacy resolver's explicit "USD" calls are unchanged.
