# New File still refuses common dotted names ("Mr.Smith", "2024.Q", "budget.march", "acme.inc") as wrong extensions

**Severity:** low. **Estimate:** 10 minutes. Owner: mobile. A3: w21/275's `/^[A-Za-z]{1,5}$/` treats any letters-only suffix of up to five letters as an extension (`ledger-file-browser-screen/utils.ts:20-27`). Under `tsx`, `Mr.Smith`, `J.Smith`, `budget.march`, `2024.Q`, `taxes.final`, `acme.inc`, `rent.jan` and `archive.old` all return `{ok:false, issue:"extension"}` under copy promising that ".bean is added" when the extension is omitted. 275's resolution disclosed this as a deviation, but nothing was filed.

Code-level at `main` `669120634`.

## Fix

Refuse only a known list of non-ledger extensions (txt, csv, md, json, py, …), or show "Will be created as X.bean".

**Acceptance:** "Mr.Smith" creates `Mr.Smith.bean`, and "notes.txt" is still refused.

## Dedupe

This is a follow-up to w21/275. Searched `.pm/**` for checkLedgerFileName and "omit the extension".

Resolved. `withBeanExtension` now treats a suffix as an extension only when it is on a list of known non-ledger ones (txt, csv, md, json, yaml, py, pdf, xlsx, ofx, … matched case-insensitively), instead of any one-to-five-letter word. "Mr.Smith", "J.Smith", "budget.march", "2024.Q", "acme.inc" and "archive.old" now create `….bean`; "notes.txt", "NOTES.TXT", "export.xlsx" and "scan.pdf" are still refused, and `.bean`/`.beancount` names are kept as typed. Tests cover both sets and the first fails against the old rule. Deviation: the list is a judgement call, not exhaustive, so an unlisted real extension (say `.docm`) is saved as `name.docm.bean`; the dashboard's New File was not checked.
