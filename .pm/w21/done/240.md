# Account detail's 1M / 3M / 6M count back from the account's last posting, not today, so a quiet account shows old changes as recent

**Severity:** moderate. It is 21 October and the ledger is active, but a Savings account last moved in March reads "+$500.00 (+50.00%)" on 1M, and "+$1,500.00" on 3M, 6M and 1Y. Home's chart doesn't do this. **Estimate:** 30 minutes. Owner: mobile. A3: `filterSeriesByRange` anchors every window on the series' last point. Its comment says the anchoring is meant for a stale *ledger*, but for one account's sparse series the last point is that account's last posting.

Code-level at `main` `4ba42392a`. A reviewer ran `selectAccountBalanceSeries` plus the card's filter and baseline under Node, with points `2026-02-03` 1000 and `2026-03-05` 1500:

```
1M  periods ["2026-02","2026-03"] headline 1500 change 500    // expected Sep–Oct, change 0
3M  periods ["2026-02","2026-03"] headline 1500 change 1500   // expected Aug–Oct, change 0
6M  periods ["2026-02","2026-03"] headline 1500 change 1500   // expected change 0
```

## Root cause

`mobile/src/common/series-util.ts:117-131` (`filterSeriesByRange`) uses `series[series.length - 1]` as the anchor. It is called from `components/balance-chart-card/index.tsx:75-92`.

## Fix

For account detail, pass the ledger's latest date (or today, capped as w21/166 proposes) as the reference month, and carry the account's balance forward to it, so empty recent months read as unchanged.

**Acceptance:** with the fixture above on 2026-10-21, 1M, 3M and 6M read "+$0.00", and 1Y reads "+$1,500.00". A unit test covers it.

## Dedupe

w21/164 covers missing months *inside* the window; its dense-series fix may cover this too, but it doesn't describe this symptom. w21/166 covers future-dated anchors, and w4/036 the baseline. Searched `.pm/**` for filterSeriesByRange, "latest data point", anchored and dormant.

Fixed in mobile: an account's balance series is carried to today's month with its last balance (`carryBalanceToToday` in `series-util.ts`, built on `forwardFillMonths`), so the 1M/3M/6M windows count back from today rather than from the account's last posting. `selectAccountBalanceSeries` takes `today` and uses it when today's trial-balance value is unknown (an account the trial balance does not list); with the value known it already ended the series on today (w21/179), so that path just gets the same guard. `selectAccountUnitsSeries` takes `today` as well, so a quiet commodity account holds its units to today; the screen passes `today` to both. On 21 October the note's fixture (1000 on 2026-02-03, 1500 on 2026-03-05) reads +$0.00 over 1M, 3M and 6M and +$1,500.00 over 1Y, via the card's own window and baseline helpers. An account that moved this month, and callers that pass no day, are unchanged. Tests: four cases in `select-account-balance-series.test.ts` (both series kinds, both money paths, the unchanged cases) plus a wiring check; they fail with the selector and screen reverted. Deviation: the generic `filterSeriesByRange` anchoring on the latest point stays as the stale-ledger behaviour the comment describes; only account detail's series is extended. No simulator run.
