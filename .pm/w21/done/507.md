# A refused edit shows the refusal twice with different line citations: the banner says "(near this entry)", the toast says "(main.bean:87)" (w21/369 follow-up)

**Severity:** low. **Estimate:** 10 minutes. Owner: mobile. A3: Edit Transaction's banner reads the refusal in editor terms through `selectOutcomeFailure(..., { where })` (`edit-transaction-screen.tsx:316-334`, w21/369). The same failure also goes through `useLedgerWrite`'s own toast (`failureMessage` and `ledgerWriteFailureMessage`, with no `where`), so the toast shows the raw file citation over the editor. Since w21/354, VoiceOver also announces the raw one.

Reproduced natively (iPhone 17e, fresh Metro at `9611fed12`, disposable ledger, edit discarded). An invalid edit to FARMERS MARKET showed the banner "…Balance failed for Assets:Cash: expected 49.75 USD, got 73.25 USD (near this entry). To put a quote inside text, write it as \"." and, at the same time, a toast reading "…got 73.25 USD (main.bean:87)".

## Fix

Pass `quietFailure` (from w21/385's `LedgerWriteSpec`) for refusals the screen explains in its banner, or have the toast use the same `where`.

**Acceptance:** a refused edit shows one refusal, in editor terms, and VoiceOver announces that one.
