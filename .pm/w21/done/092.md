# Entry Context balance rows are blank for a zero balance and run several currencies together as "100.00 USD,50.00 EUR"

**Severity:** moderate. "Balances Before/After Entry" is wrong exactly when it is most informative: an account's first posting, a payoff to zero, or a multi-currency or lot holding. **Estimate:** 30 minutes. Owner: mobile; the dashboard has the same formatter. A3: the server sends each account's balance as `string[]`, one string per currency or lot. Mobile's `formatBalances` only understands a `{number, currency}` object and otherwise uses `String(amount)`: `[]` becomes `""`, and a two-element array becomes a comma-joined string.

Reproduced natively on the iPhone 17e simulator (iOS 27.0) at `main` `d7a950d7f`, on the disposable QA ledger, which I restored byte-for-byte to `f1a0b83c`. The fixture `; qa-20261020-ec` opened `Assets:Qa20261020Wallet`, `Expenses:Qa20261020Fresh` and an equity seed. It seeded the wallet with `100.00 USD` and `50.00 EUR`, then spent `10.00 USD` from it to `Expenses:Qa20261020Fresh`.

Transaction "QA FRESH SPEND" → Entry Context:
- **Balances Before Entry:** `Assets:Qa…020Wallet 100.00 USD,50.00 EUR`, where the run-on amount squeezes the account name into an ellipsis, and `Expenses:Qa20261020Fresh` with an **empty** amount.
- **Balances After Entry:** `90.00 USD,50.00 EUR` and `10.00 USD`.

Control: CITY BUS, a single-currency entry, reads correctly ("60.00 USD", "133.25 USD").

## Root cause

- `mobile/src/screens/transactions-screen/entry-context/index.tsx:201-215` `formatBalances` falls through to `String(amount)` for arrays.
- The server shape is `Record<account, string[]>`, from `backend-cluster/ledger/src/foundation/rustledger/source-slice.ts:984-990`, typed `JSONObject` in `EntryContext.balances_before/after`.
- The dashboard has the same function at `dashboard/src/features/journal/components/entry-context-panel.tsx:211-223`.

## Fix

Treat an array value as a list of amounts:
- An empty list renders `0` (or "—"), not blank.
- Several amounts render one per line under the account, or are joined with `", "` and allowed to wrap.

Lot strings like `10 HOOL {100.00 USD, 2026-01-01}` contain commas, so one-per-line is the safer choice. Keep the `{number, currency}` branch. Make the same change in the dashboard panel in the same change, or file it there.

**Acceptance:**
- The fixture shows the Fresh account's "before" as zero or a dash.
- The wallet shows `100.00 USD` and `50.00 EUR` as separate lines, with the account name not truncated by the amount.
- Unit tests cover `[]`, a one-element array, a two-element array, a lot string and the object form.

## Dedupe

w4/058 and w4/207 cover Entry Context layout and accessibility, not value formatting. Searched `.pm/**` for "balances before", "balances after", journalBalances, BalanceSection and formatBalances.

**Resolved 2026-10-21** — Shipped in the commit that moved this note (`mobile`). Entry Context's balance formatting moved into the pure `formatEntryBalances` (`entry-context/format-entry-balances.ts`), which reads the server's `string[]` per account. An empty list is a zero balance ("0"). Each currency or lot is its own amount, and lot strings keep their commas intact. The `{number, currency}` object form is still read. `BalanceSection` stacks the amounts one per line in a trailing column, so the wallet reads "100.00 USD" / "50.00 EUR" without squeezing the account name. `format-entry-balances.test.ts` covers `[]`, one and two amounts, a lot string, the object form and the one-per-line render; the render check fails with the change reverted. **Not done:** the dashboard's `entry-context-panel.tsx` has the same formatter and was not changed in this mobile-scoped item; it needs its own note. Not re-checked on the simulator.
