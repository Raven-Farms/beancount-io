# Menu items (Home, Accounts and Transactions "+" menus, the detail ⋯ menu) read their icon glyph as part of their name

**Severity:** low. **Estimate:** 10 minutes. Owner: mobile. A3: `components/menu-button/index.tsx:212-226`: each item is a `Pressable` with a role but no `accessibilityLabel`, and its children are `{item.icon}` plus the label. Vector icons render as `<Text>{glyph}</Text>` (`create-icon-set.js:62`), so iOS adds the private-use character to the name: "Enter new transaction, <glyph>, button". The label guardrail misses it because the icon arrives as a prop. Callers: `home-screen.tsx:225-252`, `accounts-screen.tsx:199`, `transactions-screen.tsx:333` and `transaction-detail-screen.tsx:613-627`. Code-level at `main` `18664fa5e`; the spoken output is derived from the props (and proven under `tsx` where a builder is involved), not from a VoiceOver run.

## Fix

Give each item `accessibilityLabel={item.label}` and hide the icon (`importantForAccessibility`/`accessibilityElementsHidden`).

**Acceptance:** VoiceOver reads "Enter new transaction, button". The guardrail covers MenuButton.

Same class as w21/141 (done), whose list of sites didn't include MenuButton. Searched `.pm/**` for MenuButton and "glyph".

**Resolved 2026-10-22** — each MenuButton item carries `accessibilityLabel={item.label}` and its icon sits in a view hidden from assistive technology, so VoiceOver reads "Enter new transaction, button" on every menu that uses it (Home, Accounts, Transactions and the detail ⋯). A guardrail for the component is in `menu-button/__tests__/item-accessibility.test.ts` (`mobile`); not run under VoiceOver.
