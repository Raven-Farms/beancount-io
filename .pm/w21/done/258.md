# The account picker's loose matching hides Create for genuinely new names: "uber", "fuel" or "pets" match unrelated accounts

**Severity:** minor-to-moderate. A user who wants a new category sees an unrelated account and no way to create one from the picker. **Estimate:** 15 minutes. Owner: mobile. A3: Create appears only when the search has zero results, and the scattered-letter matcher almost always finds something.

Code-level at `main` `26fb7ee69`. On a 32-account chart shaped like `bean-example`, a reviewer's Node run found 3 of 21 new category names with no Create row:
- `uber` → `Income:US:Babble:Salary`
- `fuel` → `Expenses:Health:Life:GroupTermLife`
- `pets` → `Expenses:Transport:Tram`

On a smaller chart, `pets` matches `Expenses:Travel:Hotels` and `phone` matches `Expenses:Housing:Rent`.

## Root cause

`mobile/src/screens/account-picker-screen/picker-sections.ts:134-143` (Create only with zero results), and `mobile/src/common/account-search.ts:101-124` (subsequence matching).

## Fix

Offer Create under the results whenever no result contains the query as a contiguous substring of a component (or whenever the query isn't an existing account's exact name).

**Acceptance:** "pets" on the sample chart shows Create beneath any loose matches. Unit cases are added.

## Dedupe

w3/114 and w21/122 are different Create problems. Searched `.pm/**` for showCreateAccountRow, "create row", scattered and subsequence.

Fixed in mobile: the account picker's Create row now also follows the search results when none of them really contains the query. `showCreateBelowResults` is true for a writer when there are results and no result contains every word of the query as a contiguous, case-insensitive (and NFC-folded) piece of its name; a ledger that already has an account named by the query keeps its hit and shows no Create. The screen renders the same row (now one `createRow` element) as the list footer in that case, while the empty state keeps its own Create row for a search with no results. So on a chart where `pets` scatters across `Expenses:Transport:Tram`, `uber` across `Income:US:Babble:Salary` and `phone` across `Expenses:Housing:Rent`, the unrelated matches are listed and Create "pets" sits beneath them; "food", "rent", "credit card" and "FOOD:groc" show no Create. A closed account named exactly still shows its closing note instead (w21/122), and read-only sessions get no row. Tests in `picker-sections.test.ts` (the loose names, real hits, empty results, access, NFC, and the footer wiring); they fail with the two files reverted. Deviation: no simulator run, and the contiguous check is per word of the query, so a multi-word query counts as found only if every word is contiguous in one account.
