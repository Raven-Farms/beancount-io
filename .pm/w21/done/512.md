# Notifications' "Show older" hides one page early after the app returns to the foreground (w21/498 regression)

**Severity:** low. **Estimate:** 15 minutes. Owner: mobile. A3 (code-level at `main` `a06f559aa`): `mobile/src/screens/notifications-screen/notifications-screen.tsx:289-314` remembers the end of history as a row count (`endRows`), and clears it only on a ledger switch or a pull to refresh. Coming back to the foreground re-fetches the list (`common/apollo/refresh-on-foreground.ts:19`), which drops it to page 1 but keeps the old `endRows`.

Scenario:
1. A ledger has 60 commits. Show older twice reaches 60, and the button hides.
2. The app goes to the background, and one commit is made elsewhere (61 in all).
3. Back in the app, 30 rows show. Show older brings 60, and the button hides again (`60 >= endRows`), so the oldest commit can't be reached.

Not run natively: it needs 60 or more commits on the disposable ledger.

## Fix

Clear `endRows` whenever the first page is re-fetched (or when the newest commit's sha changes), not only on a ledger switch.

**Acceptance:** that scenario reaches the 61st commit. A unit or screen test covers a refetch after the end was found.

## Dedupe

Regression of w21/498 (and w21/431's refetch case). Searched `.pm/**` for endRows, historyEnded and "Show older".

---

**Resolved 2026-10-22** — the remembered end of the history now carries the newest commit it was found under; a refetch that brings a new newest commit forgets the end, so Show older reaches the 61st commit. Unit cases for `endRowsFor` in `show-older.test.ts` (`mobile`).
