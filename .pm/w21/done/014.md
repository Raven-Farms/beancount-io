# New Ledger File disables Create without saying why, and refuses folders the server accepts

**Severity:** minor. **Estimate:** 30–45 minutes. Owner: mobile. A2: a newcomer splitting their ledger into files (a common Beancount step) types a name and gets a greyed-out button with no explanation, whether the name already exists, has a slash, or uses the wrong extension.

Environment: `main` at `da60d3c87` (clean worktree served by Metro), dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0), English. QA account on the synthetic disposable ledger `mcp-agent-eval` (only `main.bean`). Nothing was created.

## Repro

1. Files → **+**. The dialog reads "Enter a unique .bean or .beancount filename. If you omit the extension, .bean is added."
2. Type `main`. It normalizes to `main.bean`, which exists, and **Create file** stays grey. No message.
3. Type `../qa-20261020.bean`. Grey, no message. Correct to refuse, but silent.
4. By code, `sub/x.bean` is also refused (`trimmed.includes("/")`), although the server and the dashboard accept nested paths (w3/196: "`a/b/c.bean` works").

## Root cause

- `mobile/src/screens/ledger-file-browser-screen/utils.ts:3-19` (`normalizeLedgerFileName`) returns `null` for any `/`, and `index.tsx:369-377` folds "invalid" and "duplicate" into one boolean.
- `mobile/src/components/text-input-modal/index.tsx:128,181-187`: `validateInput` is boolean-only, so the modal can disable Confirm but can't say why. Its only other caller is Delete Account's phrase check.

## Fix

Let `validateInput` return a reason (`string | null`, or `{ ok, message }`), render it under the field in the error color, and announce it for accessibility. In Files, map the reasons to translated messages: "A file named main.bean already exists", "Use a .bean or .beancount name", "Names can't contain .. or \\". Allow `/`-separated relative paths with non-empty, non-`.`/`..` segments, mirroring the server's `assertSafeRepoPath` as w3/196 did for the dashboard, or else say plainly that folders aren't supported here. Keep the existing re-validation in `handleCreate`.

**Acceptance:** typing `main` shows the already-exists message with Create disabled. `../x.bean` shows the traversal message. `notes.txt` shows the extension message. `notes` and (if nested paths are allowed) `sub/notes.bean` enable Create. Unit tests cover each reason, and Delete Account's confirm still works.

## Dedupe

w3/196 (done) fixed the same class on the **dashboard** (Create File offered Save for names the server refuses). Its mobile counterpart has the opposite failure: it refuses, but silently. Searched `.pm/**` for create file, filename validation and TextInputModal. No mobile item.

---

**Resolved 2026-10-20** — `TextInputModal`'s `validateInput` may return a string. That disables Confirm and shows the string under the field in the error color, in a polite live region. A boolean still means valid or silently invalid, so Delete Account's phrase check is unchanged.

New Ledger File validates with `checkLedgerFileName`:

- `main` → "A file named main.bean already exists".
- `../x.bean`, a backslash, an empty, `.` or `..` segment, or control characters → "Use a name without \, .. or empty folder names".
- `notes.txt` or `.bean` → "Use a .bean or .beancount name".
- `notes` and `sub/notes.bean` enable Create, because relative folder paths are now allowed as the server allows them (w3/196).

The messages are in 13 locales. `handleCreate` re-checks with the same function. The old `ledger-m15` expectation that nested paths are refused was changed on purpose. `check-ledger-file-name.test.ts` covers each reason, the accepted cases, the empty field and the wiring. Mobile gates pass: format, tsc, eslint, knip, and 2409 unit tests. Not checked on the simulator, and folder creation was not exercised against the server. Shipped in `85814e7b0` (`mobile`).

**Native recheck 2026-10-20** — iPhone 17e (iOS 27.0), dev build serving a clean `origin/main` worktree at `5013b5ab4`. Files → + → `main` shows "A file named main.bean already exists" under the field, and Create file stays disabled. Nothing was created.
