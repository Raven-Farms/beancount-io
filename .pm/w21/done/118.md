# Merchants, merchant detail and Entry Context load errors append the raw Apollo message, and two of them offer no Retry

**Severity:** minor-to-moderate. "加载商户失败：Network request failed" or "错误: Network request failed" replaces the content. The Entry Context error wins even when cached context exists. **Estimate:** 45 minutes. Owner: mobile. A3: the prefix keys `merchantsLoadError` ("Failed to load merchants: ") and `journalError` are built to have `error.message` concatenated onto them. w21/013's fix text said "translate the fallback" for Entry Context, but only the NOT_FOUND branch changed.

Code-level at `main` `d2b68a65e`.

## Where (`mobile/src/screens/`)

- `merchants-screen/merchants-screen.tsx:283-289` (with `error = rollupError ?? seriesError` at `:206`). It has no Retry button, and a failure of only the secondary recurrence query replaces the whole list.
- `merchant-detail-screen/merchant-detail-screen.tsx:538-545, 564-569` has a Retry but still appends the raw text.
- `transactions-screen/entry-context/index.tsx:220, 248-255`: `entryError = contextError ?? error` overrides cached context, and there's no Retry. The detail screen has no RefreshControl either.

## Fix

Show translated, whole-sentence copy (no concatenation) with a Retry that calls `refetch`. Keep showing cached data with an inline "couldn't refresh" note when data exists. For Merchants, render the rollup list even when only the series or recurrence query failed.

**Acceptance:**
- Offline, in 中文, all three show translated copy with no English transport text.
- Each has a Retry that recovers once the network returns.
- Cached Entry Context stays visible on a refresh failure.
