# On iOS the "tab" role is dropped and collapsed rows never say they expand

**Severity:** minor-to-moderate. **Estimate:** 30 minutes. Owner: mobile. A3: Home's chart tabs (`components/segmented-pages/index.tsx:227, 244-245`) and Browse ledgers (`ledger-selection/index.tsx:225-229`) use `accessibilityRole="tablist"` and `"tab"`. Fabric's role-to-trait conversion (`ReactCommon/react/renderer/components/view/accessibilityPropsConversions.h`, around line 100) maps only `"tabbar"`, so an unselected tab has no trait and doesn't sound tappable.

`RCTViewComponentView.mm` adds "expanded" only when `expanded` is true and never speaks "collapsed". These expandable rows label themselves with the bare name and `accessibilityState={ expanded }`, so a collapsed row gives no hint that it opens:
- Reports categories (`category-breakdown.tsx:271-276, 365-368`)
- Budget history (`budget-history-rows.tsx:152-155`)
- the file editor's error toggle (`ledger-file-editor-screen/index.tsx:229-231`)
- Entry context (`entry-context/index.tsx:270`)

The account table works around this with actions and a `chevronLabel` (w2/075).

Code-level at `main` `5a4e27da4` against React Native 0.86 (Fabric) sources in `mobile/node_modules`. Not exercised with VoiceOver, which this simulator setup can't drive.

## Fix

Use `accessibilityRole="tabbar"` on the container, or give each tab button semantics with a localized "tab, N of M" value. Give each expandable row a localized collapsed/expanded value, or expand/collapse `accessibilityActions`, as `account-table` does.

**Acceptance:** VoiceOver reads an unselected tab as tappable, and a collapsed row says it is collapsed.

## Dedupe

w4/049 and w4/064 mention the tab role in passing; w2/075 covers only the account table. Searched `.pm/**` for tablist, tabbar, "tab role", collapsed, expanded and disclosure.

Fixed. Tabs: `tabRole` (`common/accessibility.ts`) is `button` on iOS, where Fabric gives `tab` no trait, and `tab` on Android; Home's chart tabs (`segmented-pages`) and Browse ledgers use it, keeping `accessibilityState.selected` so an unselected tab sounds tappable and the active one reads "selected". Expandable rows: `disclosureAccessibility(expanded, t)` returns the expanded state plus a localized hint, "Double-tap to expand" when collapsed and "Double-tap to collapse" when expanded (new keys `a11yTapToExpand` / `a11yTapToCollapse`, 13 locales), because iOS speaks "expanded" but never "collapsed". Used by both Reports category rows (top-level and child), Budget history, the file editor's error toggle and Entry context; the account table keeps its own chevron actions (w2/075). Tests (`common/__tests__/accessibility.test.ts`: the helper and role under an iOS and an Android stub, and a check that those rows and tab bars use them and no longer set a bare expanded state or the `tab` role; the two wiring cases fail with two sources reverted). Deviation: the tab container keeps `tablist` (no iOS trait, harmless), and the hint is read after the row's value, so the order on iOS is name, value, state, hint. Not exercised with VoiceOver.
