# Transactions filter "Custom" seeds a 0–2 day window near month-end instead of "last month through today"

**Severity:** minor. **Estimate:** 10 minutes. Owner: mobile. A2: choosing **Custom** in the Transactions filter seeds the range as "last month through today". `setMonth(getMonth() - 1)` on the 29th–31st lands on a day the earlier month lacks, and JS rolls it forward into the current month. The "month" collapses to a few days, or one.

Environment: `main` at `8d4d672f9`. Harness-level: the exact component lines run under Node. Today on the simulator is 2026-10-21, where the bug doesn't trigger.

| today | seeded start | expected |
| --- | --- | --- |
| 2026-03-31 | 2026-03-03 | 2026-02-28 |
| 2026-03-29 | 2026-03-01 | 2026-02-28 |
| 2026-05-31 | 2026-05-01 | 2026-04-30 |
| 2026-12-31 | 2026-12-01 | 2026-11-30 |

## Root cause

`mobile/src/screens/transaction-filters-screen/transaction-filters-screen.tsx:227-234` builds `monthAgo` with an unclamped `setMonth`. The same package's `select-filter-query.ts` `monthsBack` already clamps (`setDate(0)` on overflow) for the 1M/3M pills.

## Fix

Reuse `monthsBack(today, 1)` (export it, or a shared helper) for the Custom seed. Add a test for 2026-03-31 and 2026-12-31.

**Acceptance:** on 2026-03-31, Custom seeds 2026-02-28 → 2026-03-31. Other days are unchanged.
