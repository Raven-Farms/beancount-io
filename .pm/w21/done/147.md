# Latest Updates shows every Blog and Release date one day early anywhere west of UTC

**Severity:** minor-to-moderate. For every user in the Americas, every blog and changelog row on Home reads one day early, all day. **Estimate:** 15 minutes. Owner: mobile, plus an optional backend change. A3: beancount.io's RSS gives date-only posts as midnight UTC, and the backend forwards `publishedAt: "2026-10-21T00:00:00.000Z"`. `formatFeedDate` treats it as a real moment and formats it in the device's time zone, so UTC−7 gives "Oct 20, 2026". Gitea activity items are real timestamps and are correct.

Verified through the API at `main` `f5e4d1cb2` (read-only). `getFeed(limit: 60)` returns 20 `BLOG` items with `publishedAt "2026-10-21T00:00:00.000Z"` and a `CHANGELOG` item with `"2026-09-17T00:00:00.000Z"`. The reviewer ran `formatFeedDate` under `TZ=America/Los_Angeles` and `Pacific/Honolulu` (Oct 20) against `UTC` and `Asia/Tokyo` (Oct 21). The card sits below the fold on Home, so it wasn't read on the simulator.

## Where

- `mobile/src/screens/home-screen/components/feed-card.tsx:74` → `mobile/src/common/date-format.ts:97-113` (`formatFeedDate`)
- The backend side is `backend-cluster/backend-v2/src/features/gitea/feed/service/feed-service.ts:326`.

## Fix

For BLOG and CHANGELOG sources, format the date as a calendar day: use the UTC date parts, or format with `timeZone: "UTC"`. Alternatively, the backend could send these as `YYYY-MM-DD` and mark them date-only. Keep real-moment formatting for ledger activity.

**Acceptance:**
- With the simulator in America/Los_Angeles, today's Blog rows read "Oct 21, 2026".
- Ledger "Committed to" rows keep their local date.
- Add a unit test across TZs.
