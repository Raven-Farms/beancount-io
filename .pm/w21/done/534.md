# Booking and interpolation errors (code `BOOK`) have no file or line, so the app can't open them (w21/187 and w21/309 pattern)

**Severity:** low. **Estimate:** 30 minutes. Owner: ledger. A3: the engine emits `BOOK` with no location, and `ledger-data-mappers.ts:44` (`toBeancountErrorsPublic`) maps that to `source: null`. The post-processing at `foundation/rustledger/engine.ts:680` locates option, include and source errors, but not these. The message already carries the entry's date and narration.

Production (2026-10-22, disposable ledger, restored): `2026-01-05 * "qa-20261020 cost and elided"` with `Assets:QaBroker2 10 HOOL {}` and an elided `Assets:Cash` returns only `{filename: null, lineno: null, code: "BOOK", message: "interpolation failed: cannot infer currency for posting to account Assets:Cash (2026-01-05, …)"}`. A bare `@@` price fails the same way. In the app, the Notifications row has no tap target, and the file editor's banner, which matches by filename, never shows it.

## Fix

Locate `BOOK` errors to their entry, as the engine does for option errors (w21/309): map the entry's date and narration, or better, the engine's entry index, to its source span.

**Acceptance:** that fixture's error reports `main.bean` and the transaction's first line, and the app opens it. A test covers interpolation and `@@` cases.

## Dedupe

Same pattern as w21/187 (syntax) and w21/309 (options); see w21/367. Searched `.pm/**` for "interpolation failed", BOOK and "no file or line".
