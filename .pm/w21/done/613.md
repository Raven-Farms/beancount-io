# A parent account's page never pages past two identical internal transfers: the journal snaps back to 20 rows forever (w21/419 still open for zero-change twins)

**Severity:** minor. **Estimate:** 20 minutes. Owner: mobile. A3 (code-level at `main` `5a71c68fb`, proven under `tsx`): `account-detail-screen/selectors/select-account-journal.ts:165-168` keys rows by `[entry_hash, change, balance]`. On a parent account, a transfer between two of its children nets to change `{}`, so identical twins (one `entry_hash`, per w21/419) share the whole key. `mergeAccountJournalItems` (`:178`) drops the second, `accountJournalPageOverlapped` (`:204`) reports the list moved, and `account-detail-screen.tsx:367-380` refetches from page 1, forever ("offset=20 incoming=20 added=19 listMoved=true", with hasMore still true). When both twins land on one page, React gets a duplicate key. Identical Note or Balance directives collide the same way.

Not run natively (it needs 40 or more entries and scrolling).

## Fix

Use `journalRowKeys`' occurrence suffix (as w21/419 did for the paged lists) in the account journal's keys and merge.

**Acceptance:** twin internal transfers on a parent page through to the oldest entry, with distinct keys. Unit cases are added.

**Resolved 2026-10-22** — The account journal now tells a moved list from identical twins the way Transactions does: `mergeAccountJournalItems` appends the page as it is when the list's `total` is unchanged (and dedupes only when it moved or is unknown), and `accountJournalItemKeys` gives each twin an occurrence-suffixed row key and lookup slot. Unit cases cover the append, the moved-total dedupe, and the distinct keys. Shipped in the commit that moves this note (`mobile`).

Native recheck (iPhone 17e): not exercised. It needs 40 or more entries on a parent account, with twins at a page boundary, and scrolling to page, which the harness can't drive. The fix's unit cases cover the keys and the merge.
