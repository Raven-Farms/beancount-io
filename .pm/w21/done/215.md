# Sign-in discovery has no timeout: Sign In spins for about 60 s on an unreachable server, and fixing the URL meanwhile doesn't release it

**Severity:** minor-to-moderate. Test connection gives up after 8 s and says the URL can still be saved and tried. Sign In then waits about 60 s with Sign In and Sign Up disabled. Changing the server during the wait doesn't help, and the late failure ("Could not reach that server") refers to the old URL. **Estimate:** 20 minutes. Owner: mobile. A3: `discoverOAuthServer` runs with no abort signal (React Native's XHR timeout is 0), and `running.current` and the in-flight launcher promise block new attempts.

Code-level at `main` `709af935d`. A repro is `docker compose pause backend-v2` on docker-mac.

## Where (`mobile/src/`)

- `common/oauth/start-authorization.ts:17`
- `common/oauth/discovery.ts:97`
- `…/use-native-sign-in.ts:33`
- `app/auth/welcome/index.tsx:124`

## Fix

Give discovery the same 8 s `AbortController` timeout as Test connection. Abort an in-flight attempt when the server URL changes, and attribute errors to the URL they were for.

**Acceptance:** with backend-v2 paused, Sign In fails within about 8 s with a timeout message. Changing the server re-enables Sign In immediately.

## Dedupe

w21/183 is the splash timeout. Searched `.pm/**` for "discovery timeout", "sign-in spinner" and CONNECTION_TIMEOUT_MS.

Fixed in mobile: sign-in discovery now has the same 8 s limit as Test connection (`discoverWithTimeout`, sharing `CONNECTION_TIMEOUT_MS`), so a server that accepts the connection and never answers fails Sign In within about 8 s as a timeout ("The server did not respond in time", a new `timeout` outcome from `runNativeSignIn`) instead of spinning for a minute. Changing the server during the wait now releases the screen at once: the launcher gained `abortDiscovery()` (it aborts an attempt still waiting on discovery and clears the in-flight guard so the next tap starts fresh; an attempt whose browser is already open is left alone), and `useNativeSignIn` calls it when the server URL changes, drops the abandoned attempt's late outcome so an error about the old URL is never shown, and clears the pending state. Tests: `bounded-discovery.test.ts` (silent server times out; caller abort is not called a timeout), two launcher cases (abort lets the next attempt start and signals the old one; an open browser is untouched) and the runner mapping; the launcher cases fail with the launcher change reverted. Deviations: no docker-mac pause repro on a device or simulator; the hook's server-change effect is not unit-tested directly (the runner has no hook harness), only its building blocks.

**Recheck (2026-10-21): not exercised natively.** The path is reachable only from Welcome while signed out, against a server that accepts the connection and never answers. That means signing the QA session out, pointing the app at a black-hole server, and then restoring the server and redoing the full browser OAuth sign-in. This loop does not drive that.
