# An account whose only posting is in the future shows "$0.00 · Not enough data to chart yet" while its Accounts row and journal say −$20,000.00 (w21/491 regression)

**Severity:** low. **Estimate:** 20 minutes. Owner: mobile. A3: `mobile/src/screens/account-detail-screen/selectors/select-account-balance-series.ts:133-139` (`boundedMonthEnds`, from w21/491) drops every month-end row up to today, and `:184` returns `[]` before today's trial-balance value is spliced in. So the header falls back to $0.00. w21/179 ties the header to the Accounts row.

Native (iPhone 17e at `22c99f600`, disposable ledger, restored): `Liabilities:QaLoan` opened 2026-01-01, with its only posting `-20000.00 USD` on 2026-11-01 (today is 2026-10-22). The Accounts row reads −$20,000.00. The detail header reads "Balance $0.00", with "$0.00" and "Not enough data to chart yet", and the journal beneath lists "QA Lender −$20,000.00 · Balance: −$20,000.00".

$0.00 is the balance *as of today*, so the owner should choose which figure this screen shows. It must then agree with the row, or say "as of today". Compare w21/517: the units path for the same kind of future entry shows the future balance.

## Fix

Pick one rule for future-dated postings across the Accounts row, the detail header and the units path (w21/517), and label an as-of-today figure as such.

**Acceptance:** with that fixture, the header and the Accounts row show the same figure, or the header is labeled as of today. Unit cases are added.
