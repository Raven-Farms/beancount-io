# A JPY ledger shows its money as "円1,500.00": the yen sign comes first, the code maps to 円 instead of ¥, and two decimals are always added

**Severity:** major for Japanese and Korean users. **Estimate:** 45–60 minutes. Owner: mobile. A3: in a ledger whose operating currency is JPY, the Home headline reads **"円1,500.00"** and the change reads **"+円1,500.00"**. Every operating-currency figure goes through the same helpers: account table, budget cards, the Reports category breakdown, the merchant total and the chart tooltip. A Japanese reader expects "¥1,500" or "1,500円". The yen has no minor unit, so ".00" is wrong too. KRW renders as "₩50,000.00", with the same decimal error. Non-operating JPY postings fall back to the code but still get two decimals: Home Recent and merchant detail show "+1,500.00 JPY" for the same posting that account detail shows as "+1,500 JPY".

Environment: iPhone 17e simulator (iOS 27.0), dev build 1.20261002.50, `main` at `e80968380`. Probe on the disposable QA ledger: `operating_currency` swapped from USD to JPY, plus an `Assets:Bank:QaYenAcct` seeded with 1500 JPY. Restored byte-for-byte to blob `f1a0b83c`.

## Reproduction

1. Use a ledger with `option "operating_currency" "JPY"` and `2026-09-01 * "seed"  Assets:Bank:X 1500 JPY / Equity:Opening -1500 JPY`.
2. Open Home. The Net Worth headline shows "円1,500.00" and "+円1,500.00".
3. Recent Transactions shows "+1,500.00 JPY", while the account detail row shows "+1,500 JPY".

## Root cause

- `mobile/src/common/currency-util.ts:12-17`: `getCurrencySymbol` returns `currency-icons`' `symbol`, which is **"円"** for JPY (and "Fr." for CHF). Only CNY is overridden.
- `mobile/src/common/number-utils.ts`:
  - `annotateCurrency` always prefixes the symbol.
  - `groupThousands` defaults to `digits = 2`, so every `formatMoneyWithCurrency` and `formatSignedMoneyWithCurrency` caller shows two decimals regardless of the currency's minor unit.

## Fix

- Resolve symbols through `Intl.NumberFormat` currency data, or a small override table: JPY → "¥", and use the ISO 4217 minor units (JPY and KRW 0, KWD 3) as the default scale.
- Recorded amounts keep their own scale, as account detail already does.
- Keep the w21/058 rule that a currency never borrows another's symbol.

**Acceptance:**
- A JPY ledger shows "¥1,500" (no decimals) on Home, Accounts, Budget and Reports.
- KRW shows "₩50,000".
- USD still shows "$1,234.50".
- A JPY posting reads the same on Home Recent, merchant detail and account detail.

## Dedupe

w21/058 is the wrong-symbol fallback (USD labelled €), and w21/057 is the mixed-currency headline. Neither covers symbol choice or minor units. w0/010 is the CLI's report precision. Searched `.pm/**` for 円, JPY, "minor unit" and zero-decimal. No mobile item.

**Resolved 2026-10-21** — Shipped in the commit that moved this note (`mobile`). In `currency-util.ts`, an override table now maps JPY (and CNY, as before) to "¥". The new `currencyMinorUnits` gives each ISO 4217 code its minor unit (0 for JPY, KRW and VND…; 3 for KWD, BHD, JOD, OMR…; 2 otherwise, custom commodities included). `formatMoneyWithCurrency` and `formatSignedMoneyWithCurrency`, which Home, Accounts, Budget, Reports and the chart summaries share, format at that unit, so a JPY ledger reads "¥1,500" / "+¥1,500", KRW reads "₩50,000", and USD still reads "$1,234.50". The entry-row `formatAmount` (Home Recent, merchant detail) floors at the minor unit too, so the posting reads "1,500 JPY" as it does on account detail. Recorded scales above the floor still show. One existing expectation ("15,000.00 JPY") moved to "15,000 JPY". Tests in `number-utils.test.ts` and `transaction-display-utils.test.ts` fail with the fix reverted. Not re-run on the simulator. Unchanged: the symbol is still a prefix (no "1,500円" suffix form), and RTL symbols such as KWD's "د.ك" still prefix.
