# A posting flag `%` is accepted and committed ("Added 1 entry successfully"), but the hosted engine reads the postings as comments: the entry has 0 postings (silent data loss)

**Severity:** major (silent loss on REST, GraphQL and MCP). **Estimate:** 20 minutes. Owner: ledger. A3: `backend-cluster/ledger/src/features/ledger/utils/entry-tokens.ts:22` allows `%` as a posting flag, and the renderer writes `  % Assets:Cash  -7.00 USD` (`journal-serialize.ts:689`). rustledger 0.24 treats an indented `%` line as a comment, so the transaction parses with 0 postings and no error. The wire balance check and the projected-error check both pass. Beancount 3.2.3 parses the flag. See w5/844 (rustledger skips `%` lines); nothing covers the write path.

Production (2026-10-22, disposable ledger, restored byte-for-byte): `bulkEntries` with two `%`-flagged postings (−7.00 / +7.00 USD) returns "Added 1 entry successfully". `main.bean` contains both `% …` lines, but `getLedgerJournal` returns the QA PCT entry with **0 postings**.

## Fix

Refuse `%` (and any flag the hosted engine can't read) as a posting flag until rustledger parses it, and add a projected check that the rendered entry has as many postings as were sent.

**Acceptance:** that write is refused with a clear message, and the other flags still work. Tests run the real engine, not a mock.

## Dedupe

See w5/844 and w23/033. Searched all of `.pm/` for "%" together with flag and entry-tokens.

---

**Resolved 2026-10-22** — the ledger service's entry validator no longer takes `%` as a posting or transaction flag, and says why: `postings[0].flag "%" is not a valid flag: the ledger engine cannot read a "%" flag yet, and would drop the posting; use another flag`. So the `bulkEntries` write is refused instead of committing an entry with no postings, on REST, GraphQL and MCP. Checked against the bundled `@rustledger/wasm` 0.24.0 (a `%` posting is read as a comment; a `%` transaction is a parse error) and Python Beancount 3.2.3 (reads both). Every other flag still works. Instead of the note's runtime posting-count check, a live check in `scripts/verify-rustledger.ts` runs every printable ASCII flag the validator accepts through the real engine on a transaction and a posting and requires each to read back intact; it names `%` without the change. Unit tests in `entry-tokens.test.ts` (`backend-cluster/ledger`). A ledger service deploy carries it to production.

Production recheck: awaits the ledger service deploy (with w21/532–534, 550, 569, 651–657). The probe is w21/650's `%`-flagged `bulkEntries` on the disposable ledger.
