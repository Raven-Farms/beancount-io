# Browse ledgers → Starred stops after 30 ledgers, so local search never finds the rest

**Severity:** moderate for power users. Starred shows exactly 30 rows, there's no "Load more", and searching the 31st by name says "No matches". The hook's own comment says "load all account lists so local search never silently searches only page one". **Estimate:** 20 minutes. Owner: mobile. A3: the page loop stops when `items.length >= result.total`, but the backend's `total` for starred repos is **the returned page's length**, a contract w3/m21 kept on purpose ("total is the returned page size"). So page 1 (30 items) sets `total = 30` and the loop exits.

Code-level at `main` `3c20a88e0`. Not exercised natively: it needs 31 or more stars on the QA account, a write to account social state outside the disposable-ledger authorization.

## Where

- `mobile/src/screens/ledger-selection/use-discovery.ts:84-87`
- `backend-cluster/backend-v2/src/features/gitea/user-profile/service/user-profile-service.ts:438` (`total: repositories.length`)
- No test covers `use-discovery.ts`.

## Fix

Continue paging while a page comes back full (`repositories.length === PAGE_SIZE`), as the dashboard's w3/m21 fix does, and drop the `total` condition for this list. Add a hook test with a 31-item fake.

**Acceptance:** with 31 starred ledgers, Starred lists all 31 and search finds the 31st.
