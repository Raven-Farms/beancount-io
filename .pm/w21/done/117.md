# Ledger saves and deletes show raw transport text ("Network request failed", "OAuth refresh failed", "Received status code 502"), so being offline reads like a ledger rejection

**Severity:** moderate. Every non-English user sees English transport strings on failed writes. On Edit Transaction, "Network request failed" appears under the hint that "a stale checksum or invalid beancount will be rejected", sending users to hunt for a syntax error that doesn't exist. No failure alert offers a Retry, even where the write is idempotent (the sha-keyed file save). **Estimate:** 2 hours. Owner: mobile. A3: w21/m1 kept server text so validation refusals stay readable, but its fallback, `ledgerWriteFailureMessage`, returns `error.message` for **every** non-refusal error. Mobile has no equivalent of the dashboard's `no-raw-error-message` guard.

Code-level at `main` `d2b68a65e`. Not exercised natively: forcing offline needs the host's Network Link Conditioner or `pfctl`, since the simulator uses the Mac's network stack. Production already masks internals ("Internal server error", `backend-v2/src/server/graphql/format-error.ts:89-97`), so this is about language and error class, not leaked internals.

## Where (`mobile/src/`)

- **The shared fallback:** `common/ledger-refusal.ts:39-46`. It feeds:
  - the Edit Transaction inline error (`edit-transaction-screen/save-failure.ts:38`, shown at `edit-transaction-screen.tsx:316,491`)
  - the Delete Transaction toast and alert (`transaction-detail-screen.tsx:355-356`, `delete-transaction.ts:32-37`)
  - Open Account (`open-account-screen/use-open-account.ts:50`)
  - Add Budget (`budget-screen/hooks/use-save-budget.ts:39`)
- **The same pattern, written separately:**
  - budget history delete (`use-delete-budget-entry.ts:60-63`)
  - the file editor save alert (`ledger-file-editor-screen/index.tsx:538-555`)
  - file browser refresh, create and delete toasts, which show only the raw text (`ledger-file-browser-screen/index.tsx:358-363, 428-433, 481-486`)
- **Possible messages:** Apollo's `Network request failed`, `Response not successful: Received status code 502`, the app's own `OAuth refresh failed` (`common/oauth/token-manager.ts:11-15,163`) once a token over an hour old needs a refresh while offline, and the server's English "Too many requests…" for RATE_LIMITED.

## Fix

Add one mapper keyed on `graphQLErrors[].extensions.code` and `networkError`:
- VALIDATION_FAILED, BAD_USER_INPUT and UNBALANCED keep the server's ledger text.
- A network or fetch failure gets translated "You're offline. Nothing was saved." copy with Retry where safe.
- RATE_LIMITED gets translated copy using `retryAfter`.
- An OAuth refresh failure is handled as in w21/119.
- Anything else gets the screen's existing generic string, as New Transaction already does (`multi-postings-transaction-screen.tsx:630-646`).

Then port the dashboard's raw-error guard to mobile with mobile-shaped patterns: `*Error.message`, `caught.message`, `showToast({ message` fed from an error, and `Alert.alert(…, msg)`. Allowlist genuine ledger-error data (notifications, the editor banner, the transaction error banner).

**Acceptance:**
- With the network blocked, in 中文, Edit Transaction, Delete, Open Account, Add Budget, file save, create and delete all show translated offline copy, and none shows an English transport string.
- A VALIDATION_FAILED refusal still shows the ledger's own text.
- The new guard test fails on a reintroduced `error.message` in UI.

## Dedupe

w21/m1 (refusal text), w21/081 (list-wipe pattern) and w21/107 (Create Ledger) are related. Searched `.pm/**` for "Network request failed", "OAuth refresh failed", ledgerWriteFailureMessage, "Received status code", RATE_LIMITED and no-raw-error.

**Resolved 2026-10-21** — Shipped in the commit that moved this note (`mobile`). `ledgerWriteFailureMessage` (`common/ledger-refusal.ts`) now classifies an error instead of returning its message:
- A refusal reads as "This would add an error…".
- VALIDATION_FAILED, BAD_USER_INPUT and UNBALANCED keep the server's ledger text.
- A network error, a non-2xx response or an offline OAuth refresh reads "You're offline. Nothing was saved." (new `ledgerWriteOffline`, 13 locales).
- RATE_LIMITED gets `ledgerWriteRateLimited`.
- Anything else is null, so the screen's generic copy shows.

Edit Transaction, Delete Transaction, Open Account and Add Budget already used it. The budget history delete, the file editor's save alert and the file browser's create and delete toasts now use it too, and the file browser's refresh toast (a read) shows the generic load failure. Edit Transaction's stale-checksum detection now reads the raw error before mapping. Tests:
- `ledger-refusal.test.ts` covers the classes.
- Three tests that pinned raw "Network request failed" now expect the offline copy.
- The new `no-raw-error-message.test.ts` guard fails on an `instanceof Error ? x.message` / `? xError.message` fallback in screens or components. It flagged all four old sites with the fixes reverted, and three classifier modules and conflict-detection lines are exempt.

Not done: a Retry button for the idempotent file save. Read-only list screens that show a query's message (Merchants, quick-add) are outside the guard's write scope. w21/119 (OAuth refresh) is its own item. Not exercised offline natively.

**Native recheck 2026-10-21:** not exercised. A failed write needs the network to drop mid-save, and the simulator has no per-app offline switch. A successful save path was exercised in the same session, with nothing new surfacing. Covered by the unit tests and the raw-message guard only.
