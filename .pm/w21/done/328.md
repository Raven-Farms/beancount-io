# The legacy journal endpoint's account filter still matches substrings (w21/113 fixed only the main journal)

**Severity:** minor-to-moderate. **Estimate:** 15 minutes. Owner: ledger. A3: `runLegacyJournal` still does `new RegExp(accountFilter, "i")` with an `includes` fallback. It is served by GraphQL `journalEntries(accountFilter)` and REST `GET /api-gateway/v1/legacy/journal-entries`.

Code-level at `main` `3e830700b`. A reviewer ran it in plain Node with Cash, CashApp and Cash:Wallet: `"Assets:Cash"` and `"Assets:Cas"` both return all three. The fixed `applyAccountFilter` returns Cash and Wallet for the first and nothing for the second.

## Root cause

`backend-cluster/ledger/src/features/ledger/service/ledger-legacy-journal.ts:313-323`, with the resolver at `ledger-legacy-resolver.query.ts:463, 665`.

## Fix

Move the plain-name matcher out of `directive-filter.ts` into a shared helper and use it here, with parity tests on REST and GraphQL.

**Acceptance:** the legacy endpoint returns the same accounts as the main journal for both inputs.

## Dedupe

This is a follow-up to w21/113 (done). Searched `.pm/**` for runLegacyJournal, ledger-legacy-journal and journalEntries.

Fixed in the ledger service. The plain-name/regex account matcher behind the main journal moved into a shared `makeAccountNameMatcher` (exported from `directive-filter.ts`), and `runLegacyJournal` now uses it, compiled once per request instead of `new RegExp(accountFilter, "i")` with an `includes` fallback. For the note's fixture (Assets:Cash, Assets:CashApp, Assets:Cash:Wallet): `Assets:Cash` returns Cash and Wallet, `Assets:Cas` returns nothing, `Cash` and `cash:wallet` match whole components case-insensitively, and a regex such as `^Assets:Cash(App)?$` still works; an invalid regex is now a literal match (Fava's rule) rather than a substring one, which still matches nothing in the existing case. The GraphQL `journalEntries(accountFilter)` and REST `legacy/journal-entries` surfaces both run this function. Tests added to `ledger-legacy-journal.test.ts` (three fail with the legacy module reverted); the invalid-regex test was renamed for the literal rule. Ledger typecheck, lint, build and the full suite (113 suites, 1497 tests) green. Needs the ledger service deployed.

**Production recheck (2026-10-21): inconclusive.** GraphQL `journalEntries(accountFilter:)` takes no ledger id and returned 0 rows for both `Assets:Cas` and `Assets:Cash` for the QA session, so the account it reads could not be confirmed and the substring behaviour could not be told apart.
