# Add Budget refuses a decimal comma ("49,99") that New Transaction accepts

**Severity:** low. **Estimate:** 15 minutes. Owner: mobile. A3 (code-level at `main` `a06f559aa`): `mobile/src/screens/budget-screen/build-budget-entry.ts:42-45` (`isBudgetAmount`, `/^[+-]?\d+(\.\d+)?$/`) is the only amount field that doesn't use `parseExactAmount`. That function reads a single `,` as a decimal comma (the w21/031 rule) and is used by New Transaction and Create Ledger. In German, "49,99" is refused with "Geben Sie eine Zahl ein, z. B. 500 oder 49.99.", and a keypad that offers only "," as the separator can't type a decimal budget at all. The code comment refuses *grouping* commas on purpose; a decimal comma isn't grouping.

Not run natively (needs a device region change).

## Fix

Parse with `parseExactAmount` and write its normalized result, keeping the refusal for ambiguous grouping.

**Acceptance:** "49,99" saves `49.99`, and "1,234.56" and "1.234,56" are handled as in New Transaction. Unit cases are added.

## Dedupe

Siblings: w21/031 and w21/386 (the decimal-comma rule) and w21/392 (budget numerals). Searched `.pm/**` for isBudgetAmount and "decimal comma".

---

**Resolved 2026-10-22** — Add Budget now parses the amount with `parseExactAmount` and writes its normalized result: "49,99" saves 49.99, and "1,234.56", "1.234,56" and "1 234,56" read as in New Transaction; junk (`12..3`, `abc`, `1e3`, a trailing point) stays refused. Unit cases in `build-budget-entry.test.ts` (`mobile`).
