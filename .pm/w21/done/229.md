# The posting picker and payee autofill offer accounts that aren't open yet on a back-dated entry, so the save is refused

**Severity:** moderate. This is the open-date half of w21/045, which filtered closed accounts. **Estimate:** 30 minutes. Owner: mobile. A3: the close-dates query fetches only `closedAt`, and `isOpenOn` / `openOn` check only that. An account opened after the entry's date passes, is offered in the picker, and is filled in by the payee seed. Done is then refused by the engine's "not opened until" check (the refusal recorded in w21/008).

Code-level at `main` `7e42f850e`. A reviewer ran the helpers under Node from `mobile/`. With `Assets:NewBank` opened 2026-10-01 and an entry dated 2026-09-15:
- `openOn([...], "2026-09-15")` keeps `Assets:NewBank`.
- `isOpenOn("Assets:NewBank", "2026-09-15")` returns `true`.
- `seedPostingsFromPayee` fills in `Assets:NewBank` for a payee last used with it.

## Root cause

- `mobile/src/common/graphql/queries/ledgerAccountCloseDates.graphql` selects `closedAt` only, although `LedgerAccountItem.openedAt` exists (`generated-graphql/types.ts:749`).
- `mobile/src/common/account-close-dates.ts:17-40`: `closeDatesOf`, `isOpenOn` and `openOn` ignore the open date.
- Callers: `account-picker-screen.tsx:306`, and the payee seed at `multi-postings-transaction-screen.tsx:521`.

## Fix

Fetch `openedAt` too, and treat an account as usable when `openedAt <= entryDate <= closedAt`. Keep the Transactions filter picker unfiltered, as w21/045 did.

**Acceptance:** with the dates above, the picker hides `Assets:NewBank` for a 2026-09-15 entry and shows it for 2026-10-01, and the payee seed falls back to the default. Unit cases are added next to w21/045's.

## Dedupe

w21/045 (close date), w21/008 (a newly opened account's date) and w21/103 (a closed default) are siblings; none checks the open date. Searched `.pm/**` for openedAt, isOpenOn, `openOn(`, "not opened until" and "opened after".

Fixed in mobile: the close-dates read now also selects `openedAt` (`LedgerAccountCloseDates`; the generated query type and document were updated by hand to match what codegen emits, since codegen runs against the production schema and the field already exists there), `closeDatesOf` keeps each account's open date beside its close date, and `isOpenOn` requires `openedAt <= entryDate <= closedAt`. Every caller that already asks it therefore changes with it: the posting picker's `openOn` hides an account that is not open yet for a back-dated entry (and shows it from its open date, where Beancount books the open first), and the payee seed and `defaultPostingAccounts` stop filling in such an account and fall back to the default. The Transactions filter picker stays unfiltered, as w21/045 left it. A read that supplies only close dates still filters by them alone, and nothing is hidden until the dates load. The map type stays `ReadonlyMap<string, string>` with an optional `openedOn`, so no caller or existing test changed shape. Tests: five cases next to w21/045's in `account-close-dates.test.ts` (hidden before, shown on and after, both ends for a closed account, the seed's check, graceful when dates are absent); four fail with the helper reverted. Deviation: no simulator run of the picker.
