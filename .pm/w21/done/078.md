# Transactions' relative date filters (1M/3M/YTD) freeze "today" when they are applied, so after midnight new entries stay hidden while the badge still counts the filter

**Severity:** minor. **Estimate:** 20–30 minutes. Owner: mobile. A3: apply 1M on 2026-10-21, and the journal query asks for `2026-09-21 - 2026-10-21`.

1. Leave the app open past midnight, or resume it the next day without touching the filter sheet.
2. Add an entry dated 2026-10-22, from mobile or anywhere else.

The list never shows the new entry, even though the filter means "the last month through today". Pull to refresh refetches the same frozen range. 3M and YTD behave the same way. Only reopening and re-applying the filters moves the window.

Environment: `main` at `524a980c7`. Code-level. The simulator follows the host clock, so crossing midnight can't be driven on demand.

## Root cause

`mobile/src/screens/transactions-screen/transactions-screen.tsx:127-131`:
- `filterQuery = useMemo(() => toFilterQuery(filters, new Date()), [filters])` captures the date once per filter change.
- The badge on the line above (`countActiveFilters(filters, new Date())`) re-evaluates on every render.
- `use-foreground-refresh.ts` refetches on resume, but with the memoised variables.

## Fix

Key the memo on the local calendar day as well. For example, a `useToday()` hook that updates on AppState `active` and at local midnight, passed to `toFilterQuery` and `countActiveFilters` alike. Then a resumed or long-open app advances relative ranges, and the refetch carries the new window.

**Acceptance:** a hook or unit test where advancing the mocked clock past midnight, plus an AppState `active` event, changes the 1M query's end date to the new day.

These tabs never unmount, so after days of suspension the price-staleness warnings are judged against the old date. The shared `useToday()` fix should cover these sites too.

## Also: a scheduled budget change never takes effect on a mounted Home or Budget screen (added 2026-10-21)

`mobile/src/screens/budget-screen/hooks/use-budget-groups.ts:47-53` memoizes `groupBudgetEntries(...)` on `[data]` only. Its default `activeDate` is "today", read inside the function (`budget-selectors.ts:233`), and Apollo keeps the same `data` object when a refetch returns identical data.

Take directives `2026-01-01 … "monthly" 300 USD` and `2026-11-01 … "weekly" 80 USD`. A reviewer ran the resolver under Node: active date 10-31 gives monthly/300, and 11-01 gives weekly/80. A Home tab left open across 1 November keeps the monthly interval, amount, direction badge and current-entry highlight until it remounts or the data changes. Key this memo on the same `useToday()`.

**Resolved 2026-10-21** — Shipped in the commit that moved this note (`mobile`). New `useToday()` (`common/hooks/use-today.ts`) returns the local `YYYY-MM-DD` and advances both on a local-midnight timer and on AppState `active`. Its logic lives in the pure `createTodayWatcher` / `msUntilNextLocalMidnight` (`common/today-watcher.ts`). Transactions keys `toFilterQuery` and the badge's `countActiveFilters` on it, so 1M, 3M and YTD move with the day, and the foreground refetch carries the new window. Accounts, Home and account detail now take `today` from it instead of a mount-time `useMemo`, which covers the addendum. `today-watcher.test.ts` crosses midnight on a mocked clock, sends `active`, and checks that the 1M query's end moves from 2026-10-21 to 2026-10-22. It also checks the four screens' wiring, which fails with the screen changes reverted. The budget addendum is covered too: `use-budget-groups.ts` passes `useToday()` to `groupBudgetEntries` and keys its memo on `[data, today]`, so a directive scheduled for 1 November takes over on a mounted Home or Budget screen. A wiring check in the same test file covers it. `empty-ledger-actions.test.ts` stubs the new hook. Midnight was not crossed on the simulator.

**Native recheck 2026-10-21:** not exercised. The simulator follows the host clock, so neither midnight nor a scheduled 1 November budget can be reached in this run. The current-day behaviour (Custom seeding 2026-09-21 → 2026-10-21, Home and Accounts rendering) is unchanged on `main` `7a7b0be95`.
