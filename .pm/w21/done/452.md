# The account picker hides "Create" when the typed full name is a prefix of an existing account ("Expenses:Food" with Expenses:Food:Groceries present)

**Severity:** minor. **Estimate:** 15 minutes. Owner: mobile. A3: `showCreateBelowResults` (`mobile/src/screens/account-picker-screen/picker-sections.ts:160-172`) treats any result that contains every query word as a substring as an exact hit. A full new name such as `Expenses:Food`, `Expenses:Gift` or `Assets:Bank:Check` is a substring of an existing account, so neither the empty-state nor the footer Create row appears.

Code-level at `main` `17da1541a`. In the reviewer's tsx run, with the chart `Expenses:Gifts`, `Expenses:Food:Groceries`, `Expenses:Car:Insurance` and `Assets:Bank:Checking`, all four queries above return false for both Create rows. Not exercised on the device. From New Transaction, the user has to leave for the Accounts tab's "+" to create the account.

## Fix

When the query contains `:` (a full account name), count only an exact match as a hit (NFC, case-insensitive, after `capitalizeAccountPrefill`).

**Acceptance:** "Expenses:Food" offers Create beside `Expenses:Food:Groceries`, and an exact existing name still hides it. Unit cases are added.

## Dedupe

w21/258, w21/374 and w21/122 cover other Create-row cases. Searched `.pm/**` for showCreateBelowResults, create row, prefix and exact.

Resolved. `showCreateBelowResults` now reads a query that starts at a root account and contains a colon ("Expenses:Food", "Assets:Bank:Check") as a whole account name, not a piece of one: it hides the Create row only when the ledger has exactly that account (NFC, case-insensitive, spaces around colons ignored). So a new "Expenses:Food" beside "Expenses:Food:Groceries" offers Create, and "Expenses:Food:Groceries" itself still does not. Deviation from the note's wording: a colon alone does not switch the rule on, because a partial path such as "FOOD:groc", which an existing test pins as a search for a piece of a name, must keep hiding Create; the rule applies only when the first segment is a root of some result. Tests cover the note's four queries, exact hits in other cases, and the partial-path cases; the new one fails against the old rule. No native run.
