# Transactions search text carries over to another ledger after a drawer switch

**Severity:** minor-to-moderate. Ledger B's list is silently narrowed by a search typed on ledger A, often to "No transactions match". The search box sits in the scrolling header, so the cause can be off-screen. **Estimate:** 20 minutes. Owner: mobile. A3: w3/115 scoped the filter sheet per ledger. Its repro notes say "Search state was cleared to isolate the account filter", so search itself was never scoped.

Reproduced natively on the iPhone 17e simulator (iOS 27.0) at `main` `650ce6f72`, read-only:
1. On mcp-agent-eval, Transactions → search **"farm"** gives FARMERS MARKET only.
2. Drawer → **example**. Transactions still shows **"farm"** in the box, and the example ledger's journal is filtered to "Farmer Fresh" rows (Sep 6 2017, Aug 19 2017, …).

A term ledger B doesn't contain shows the empty state instead. I switched back to mcp-agent-eval afterwards.

## Root cause

`mobile/src/screens/transactions-screen/transactions-screen.tsx:107,112`: `searchQuery` is component state on a tab that stays mounted across a ledger switch, and nothing resets it when `ledgerId` changes.

## Fix

Reset `searchQuery` and the debounced value when `ledgerId` changes, or key them by ledger the way the filters are.

**Acceptance:** after the switch above, ledger B's Transactions shows an empty search box and the full journal. Add a unit or hook test.

w3/115 is filters across a ledger switch; w21/078 is filter dates. Searched `.pm/**` for searchQuery, "search text" and "ledger switch".
