# Home's Recent Transactions and Reports' account-transactions card key rows by `entry_hash`, so identical twin entries share a key (w21/419 missed them)

**Severity:** low. **Estimate:** 10 minutes. Owner: mobile. A3 (code-level at `main` `ae229c963`, proven under `tsx`): `home-screen/components/recent-transactions-card.tsx:121` uses `key={entry.entry_hash || index}`, and so does `reports-screen/components/account-transactions-card.tsx:152`. w21/419 showed that identical entries share one `entry_hash`, and fixed only the paged lists with `journalRowKeys`. For twin rows, Home's keys are `['h-coffee','h-coffee','h-rent']`, where `journalRowKeys` gives `['h-coffee','h-coffee#1','h-rent']`.

Native (iPhone 17e, disposable ledger, restored): two identical "QA Cafe 4.50" entries on 2026-10-21 both render on Home. No duplicate-key warning showed in a 9 s console capture, so the visible symptom (a dropped or duplicated row when the list shifts) wasn't reproduced.

## Fix

Use `journalRowKeys` in both cards.

**Acceptance:** twin rows get distinct keys on Home and in Reports' card. A unit case is added.
