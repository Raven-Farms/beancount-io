# Open Account's name check disagrees with the engine on non-ASCII: Persian or full-width digits pass and are then refused, while a ZWNJ inside a Persian word is blocked

**Severity:** minor-to-moderate, especially for Persian users. A component starting with Persian digits from the default fa keyboard (`Assets:۱۴۰۲`) shows "Will be created as…" with Done enabled, and the server then refuses with a raw parse error. Meanwhile `Assets:Bank:خانه‌ها` (with a ZWNJ, normal in Persian) is blocked with "Use only letters, numbers, and hyphens", although rustledger accepts it. The app's own Persian string `حساب‌ها` contains a ZWNJ. **Estimate:** 30 minutes. Owner: mobile. A3: `startsSubcomponent` accepts any `\p{N}` as a component's first character, but rustledger allows only ASCII digits there. The body regex has no `\p{Cf}`, so it rejects ZWNJ.

Code-level at `main` `ca1f36a34`. The reviewer checked these names against `@rustledger/wasm` 0.24.0. Other names mobile accepts but the engine refuses: `１２３`, `٣Bank`, `०`, `Ⅷ`, `²nd`, `①Bank`, `ʰBank`, `ـBank`.

## Where

`mobile/src/screens/open-account-screen/account-name.ts:97-103` (`startsSubcomponent`) and `:142` (the body regex).

## Fix

Mirror the engine's grammar exactly: first character an uppercase or titlecase letter (or other letter, as w21/041 allows), or an ASCII digit; body letters, marks, digits, hyphens, and allowed format characters such as ZWNJ. Add a test table generated from the engine's accept/reject results.

**Acceptance:**
- `Assets:۱۴۰۲` is rejected client-side with a translated message.
- `Assets:Bank:خانه‌ها` is accepted and opens successfully.
- Existing w21/041 and w3/165 cases are unchanged.

## Dedupe

w21/041 and w3/165 fixed under-acceptance (Hindi, titlecase, digits); w23/033 is server-side validation. Searched `.pm/**` for "Persian digit", Arabic-Indic, full-width, ZWNJ and startsSubcomponent.
