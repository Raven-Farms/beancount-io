# Mobile Budget applies the older of two same-date budget directives (mobile counterpart of w4/232)

**Severity:** major. **Estimate:** 30–45 minutes. Owner: mobile. A2: revising today's budget with **Update Budget** writes a second directive on the same date. w4/232 fixed the dashboard so the later directive wins. The mobile selector has the same tie-order bug, which w4/232 noted ("The mobile package owns a separate selector … not exercised"). On mobile the old target keeps applying, and history lists it first.

Environment: `main` at `f526e932e`+, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0), "today" = 2026-10-20. QA account, synthetic disposable ledger `mcp-agent-eval` with `2026-08-01 custom "budget" Expenses:Food:Groceries "monthly" 300 USD` followed by `… "monthly" 500 USD` on the same date (restored byte-for-byte afterwards).

## Repro

1. Home → Budget → **See all** (YTD).
2. The header reads **Budget $193.55**, which is `300 × 20/31`, so the **older** 300 USD target is applied. With the later 500 USD directive in effect it should read **$322.58** (`500 × 20/31`). The dashed budget line sits at $300 for Aug–Sep.
3. Expanding "2 entries" lists **300 USD first, then 500 USD**, both dated 2026-08-01.

The journal API returns same-date entries newest-first (500 then 300). That is the producer contract w4/232 documented: `backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts:610-618`.

## Root cause

`mobile/src/screens/budget-screen/selectors/budget-selectors.ts` (`groupBudgetEntries`, around lines 250-262): a stable sort by `entry.date` keeps the API's newest-first order for equal dates. The "newest one dated on or before activeDate" loop then ends on the older directive. History and `prepareBudgetHistory` / `budgetForInterval` inherit the same order.

## Fix

Mirror the dashboard fix (`57591bf1f`): reverse the newest-first journal entries into ledger order before the stable date sort, so the later same-date directive is the current target, the last history step and the chart/headline basis. Then render the history newest-first. Don't sort by entry hash.

**Acceptance:** the repro shows Budget **$322.58** and a $500 budget line from August, with history listing 500 USD then 300 USD. Deleting the 500 row returns the card to 300. Distinct-date budgets are unchanged. A unit test feeds newest-first journal data with two same-date targets and asserts the current target, history order and prorated value.

## Dedupe

Dashboard fix: w4/232 (done, `57591bf1f`), which explicitly left the mobile selector unexercised. No mobile item. Searched `.pm/**` for same-date budget and tie order.
