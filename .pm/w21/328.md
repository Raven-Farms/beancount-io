# The legacy journal endpoint's account filter still matches substrings (w21/113 fixed only the main journal)

**Severity:** minor-to-moderate. **Estimate:** 15 minutes. Owner: ledger. A3: `runLegacyJournal` still does `new RegExp(accountFilter, "i")` with an `includes` fallback. It is served by GraphQL `journalEntries(accountFilter)` and REST `GET /api-gateway/v1/legacy/journal-entries`.

Code-level at `main` `3e830700b`. A reviewer ran it in plain Node with Cash, CashApp and Cash:Wallet: `"Assets:Cash"` and `"Assets:Cas"` both return all three. The fixed `applyAccountFilter` returns Cash and Wallet for the first and nothing for the second.

## Root cause

`backend-cluster/ledger/src/features/ledger/service/ledger-legacy-journal.ts:313-323`, with the resolver at `ledger-legacy-resolver.query.ts:463, 665`.

## Fix

Move the plain-name matcher out of `directive-filter.ts` into a shared helper and use it here, with parity tests on REST and GraphQL.

**Acceptance:** the legacy endpoint returns the same accounts as the main journal for both inputs.
