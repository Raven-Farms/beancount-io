# Leaving the app for more than 30 s during a receipt upload makes it fail on return ("Upload failed"), even when the photo reached S3

**Severity:** minor. **Estimate:** 20 minutes. Owner: mobile. A3 (code-level at `main` `5867356e4`; a line-for-line copy with the real `createIdleGuard` was run under `tsx`): `receipt-capture-screen/use-receipt-workflow.ts:96-100` (a 30 s JS idle timer), `:102-118` (`createUploadTask` with no `sessionType`, so iOS's background URLSession keeps uploading while JS is suspended) and `:128` (`timedOut` checked before the result's status). On resume, the overdue timer can fire before the completion event, so a finished 200 is thrown away: `phase=error upload_s3_timeout (S3 status was 200, completed=true)`. The retry re-uploads the whole photo. Not run natively (it needs an upload, and this run spends no parse quota).

## Fix

Check the result's status before the idle flag, and pause or reset the idle guard while the app is backgrounded (AppState).

**Acceptance:** an upload that finishes while backgrounded proceeds to parsing on return. A unit case covers the ordering.
