# Signing out of the app leaves the browser signed in, so the next Sign In re-enters the same account with one "Approve" tap and no password

**Severity:** moderate (privacy/security on shared devices). After Settings → Sign out, anyone who taps Sign In sees the approve screen for the previous account and can sign in as them. **Estimate:** 1 hour. Owner: mobile, plus a dashboard OAuth logout check. A3: sign-in deliberately uses the shared system browser session (`preferEphemeralSession: false`, so a browser session is reused). Sign-out revokes the refresh token and clears local state but never ends the browser's beancount.io session cookie. The consent page opens straight on the existing account whenever that cookie is present.

Code-level at `main` `bca6a678c`. Not exercised natively, because it requires signing the QA session out and back in.

## Where

- `mobile/src/common/oauth/start-authorization.ts:27-30`
- `mobile/src/screens/setting/logout-action.ts:10-28` (no browser-session logout)
- `dashboard/src/features/oauth/funcs/mobile-consent-state.ts:31-34` and `dashboard/src/features/oauth/pages/mobile-consent.tsx:287` (the consent page auto-selects the cookie account)

## Fix

On sign-out, also end the browser session: open `/api-gateway/oauth/logout` in an auth session (`openAuthSessionAsync`) that returns to the app. Alternatively, use `preferEphemeralSession: true`, which gives up silent re-login. At minimum, show "Not you? Switch account" on the consent page when it was reached from the app after sign-out.

**Acceptance:** sign in, sign out, tap Sign In: the browser asks for credentials, or shows an explicit account chooser, rather than a one-tap Approve for the previous user.
