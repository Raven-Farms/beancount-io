# Commit detail's VoiceOver label never pluralises: "+1 additions" in English and wrong case forms in ru, uk, sk and bg

**Severity:** minor (accessibility). **Estimate:** 20 minutes. Owner: mobile. A3: the Stats section of commit detail is announced as `t("commitDetailAdditions", { count })` and `t("commitDetailDeletions", { count })`. Both keys are plain strings in every catalog, so `count` only fills in the number and the noun never changes.

For a commit with 1 added and 2 deleted lines, VoiceOver reads:
- en: **"+1 additions, -2 deletions"**
- ru: **"+1 строк, -2 строк"** (should be "+1 строка, -2 строки")
- sk: "+1 riadkov"
- uk and bg have the same pattern.

The visible text is only `+N` / `−N`, so only the spoken label is wrong.

Environment: `main` at `9351533e2`. Code-level: the catalog values were read directly, and `count`-keyed plural objects work elsewhere in the same catalogs (e.g. `en.ts:70` `{ one, other }`). Not driven natively with VoiceOver.

## Root cause

- `mobile/src/screens/commit-detail-screen/commit-detail-screen.tsx:232-236`
- `mobile/src/translations/*.ts`: `commitDetailAdditions` and `commitDetailDeletions` (e.g. `en.ts:461-462`, `ru.ts:463-464`) are strings, not plural objects.

## Fix

Turn both keys into plural objects in all 13 locales, with `one`/`other`, plus `few`/`many` where `Intl.PluralRules` needs them (ru, uk, sk, bg). The existing catalog plural-completeness check should then cover them.

**Acceptance:**
- 1 and 2 yield "+1 addition" and "−2 deletions" in en.
- ru yields "+1 строка", "+2 строки" and "+5 строк".
