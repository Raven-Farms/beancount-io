# Config plugins override the app's permission strings: a vague camera prompt, plus microphone and Face ID permissions the app never uses

**Severity:** major (store review and user trust). **Estimate:** 20–40 minutes. Owner: mobile. A2/A3: the first thing Scan Receipt shows is iOS's camera prompt, and it reads "Allow Beancount to access your camera" with no reason. The binary also declares microphone and Face ID usage and requests Android `RECORD_AUDIO`, though no code records audio or uses biometrics. App Review guideline 5.1.1 expects a specific purpose string and no unneeded permissions.

Environment: `main` at `531d6af16`. Native dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). Home → **+** → **Scan Receipt**.

## Evidence

- **On device:** the camera alert reads "Allow “Beancount” to access your camera? — Allow Beancount to access your camera".
- **Installed `Info.plist`** (`plutil -p`): `NSCameraUsageDescription` = "Allow Beancount to access your camera", `NSMicrophoneUsageDescription` = "Allow Beancount to access your microphone", `NSFaceIDUsageDescription` = "Allow Beancount to access your Face ID biometric data."
- **Current source**, not a stale binary: `npx expo config --type introspect` in `mobile/` resolves the same three strings, and `android.permissions` includes `android.permission.RECORD_AUDIO`.
- **What `app.json` asks for** (`ios.infoPlist`, lines 36-46): `NSCameraUsageDescription: "Beancount uses the camera to scan receipts."`, and `NSMicrophoneUsageDescription: false`, `NSFaceIDUsageDescription: false` to suppress them.

## Root cause

Config plugins run after `ios.infoPlist` and overwrite it:

- `app.json:116-124`, `expo-camera` with `"cameraPermission": "Allow $(PRODUCT_NAME) to access your camera"`, `"microphonePermission": …` and `"recordAudioAndroid": true`.
- `app.json:137`, `expo-secure-store` with no options. Its default `faceIDPermission` adds `NSFaceIDUsageDescription`.
- `rg 'recordAsync|useMicrophonePermissions|LocalAuthentication|requireAuthentication' mobile/src mobile/app` finds no usage.

## Fix

- `expo-camera`: set `cameraPermission` to the intended receipt string (or drop the option so `ios.infoPlist` wins), `microphonePermission: false`, `recordAudioAndroid: false`.
- `expo-secure-store`: `["expo-secure-store", { "faceIDPermission": false }]`. Confirm the plugin version honours `false`, or use the documented way to omit it.
- Make `expo-image-picker`'s `photosPermission` match the infoPlist wording ("scan receipts" rather than "attach receipts"), so one string is the source of truth.
- Add a unit test that runs the resolved config (or parses `app.json`) and asserts the three keys, and the absence of `RECORD_AUDIO`, so a plugin default can't creep back.
- Rebuild the dev client, since this is a native change.

**Acceptance:** `npx expo config --type introspect` shows the receipt-specific camera string, no `NSMicrophoneUsageDescription`, no `NSFaceIDUsageDescription`, and no `RECORD_AUDIO`. A rebuilt dev client's Scan Receipt prompt shows that string. Secure-store sign-in persistence still works after a relaunch.

## Dedupe

Searched `.pm/**` (including `done/`) for NSCameraUsageDescription, purpose string, usage description and microphone. w4/063 (iOS localizations) touched Info.plist for languages only. "Open the receipt photo picker without requiring broad library access" covered the picker flow, not the strings. No open item.
