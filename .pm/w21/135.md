# A pad fires even when the balance already passes within its tolerance, so balances are wrong and Beancount's "Unused Pad entry" error is missing

**Severity:** moderate where explicit tolerances are used. The padded account reads its asserted value instead of its real one, equity is off by the difference, and the Errors screen stays empty where Beancount reports an error. **Estimate:** 1 hour. Owner: ledger. A3: Beancount's pad plugin (`beancount/ops/pad.py:103-106`) inserts padding only when the difference exceeds the balance tolerance, and otherwise leaves the Pad unused, which is an error. rustledger 0.24 pads any non-zero difference, and the service accepts its padding transactions unchanged.

Code-level at `main` `67bf3f9e0`. The reviewer reproduced it with the real engine (`@rustledger/wasm` 0.24.0) through `LedgerFinanceService` and `LedgerJournalService`, against Beancount 3.2.3. It wasn't run against production.

## Scenario

`Assets:Cash` +100.00, a 2.00 lunch, `2026-01-31 pad Assets:Cash Equity:Opening-Balances`, `2026-02-01 balance Assets:Cash 100.00 ~ 5.00 USD`.
- **Expected (bean-check):** Assets:Cash is 98.00, with an "Unused Pad entry" error.
- **Actual:** the trial balance shows Assets:Cash 100. The journal adds "(Padding inserted … difference 2.00 USD)" with balance 100.00, `getErrors` returns `[]`, and Equity:Opening-Balances is off by 2.00.

Without an explicit `~` tolerance, the gap is below a cent and disappears when rounded to 2 decimals.

## Where

`backend-cluster/ledger/src/foundation/rustledger/engine.ts:141-150` and `:621` (engine padding taken as-is).

## Fix

After `expandPads`, drop any padding transaction whose difference is within the next balance assertion's tolerance, using the same tolerance the balance check uses. Emit Beancount's "Unused Pad entry" error for that Pad. Alternatively, fix it in rustledger and bump the version.

**Acceptance:**
- The fixture's trial balance shows Assets:Cash 98.00, with no padding row.
- `getLedgerErrors` includes "Unused Pad entry", matching bean-check on REST, GraphQL and MCP.

## Dedupe

w1/116, w5/611, w5/798 and w5/799 are CLI `bea add balance --pad-from` items. Searched `.pm/**` for "Unused Pad", "pad tolerance", "padding inserted" and expandPads.
