# The file editor's "View errors" pushes another Notifications, so fixing the error from there leaves an outdated copy of the file open beneath it

**Severity:** minor (a later save from the old copy hits a conflict). **Estimate:** 30 minutes. Owner: mobile. A3 (code-level at `main` `869713dae`): the "Saved, with a new ledger error" alert's **View errors** calls `router.push("/(app)/notifications")` (`ledger-file-editor-screen/index.tsx:527`). Notifications' error row then pushes a *second* editor for the same file (`notifications-screen.tsx:201`). The first editor loads its text once (the `initialized` guard, about `:462-482`) and doesn't reload on return.

Scenario:
1. Files ▸ `main.bean`. Add `2026-01-02 balance Assets:Cash 1.00 USD` and Save.
2. In the alert, tap View errors, then the error row (a second editor opens).
3. Delete the line and Save.
4. Back, Back.

The first editor still shows the deleted line, and typing there and saving hits the "changed elsewhere" conflict. The stack is Files → editor → Notifications → editor. Opening the editor from Notifications first gives Notifications → editor → Notifications.

Not run natively: it needs typing and saving in the DOM editor, which the driver can't do reliably here.

## Fix

Have View errors return to an existing Notifications (or show the file's errors in place, as the banner does). Reload the editor's text on focus when the file's sha has changed and there are no unsaved edits.

**Acceptance:** after that scenario, the editor you land on shows the fixed text, and the stack has no duplicate Notifications or editor. A screen test covers it.
