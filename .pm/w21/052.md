# At the largest text size the drawer's header breaks single words mid-word: "Ledger / s" and "Ne / w"

**Severity:** minor. **Estimate:** 15–25 minutes. Owner: mobile. A2/A3: the drawer is the app's ledger switcher. w3/199 made its rows reachable at enlarged text, but its header row, the **Ledgers** section label next to the **+ New** button, still squeezes both into half the width. At `accessibility-extra-extra-extra-large`, iOS breaks each single word mid-word. VoiceOver is unaffected, but the visible labels read as "Ledger", "s", "Ne" and "w". w4/014 fixed the same defect class ("FROM" breaking mid-word) in Money flow.

Environment: `main` at `968af1c32`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0), English, light, text size `accessibility-extra-extra-extra-large` (restored to `large` afterwards). Read-only.

## Repro

1. Set Settings → Accessibility → Larger Text to the maximum and relaunch.
2. Home → ☰. The header renders **"Ledger" / "s"** on two lines on the left, and **"+ Ne" / "w"** on the right. The ledger rows below wrap only at hyphens (`mcp-` / `agent-` / `eval`), which is acceptable.
3. At `large` the same header fits on one line.

## Root cause

`mobile/src/components/ledger-drawer/ledger-drawer.tsx:141-173`: `sectionHeader` is a `flexDirection: "row"` with `justifyContent: "space-between"`. Both `sectionLabel` and the `newButton` / `newButtonText` have `flexShrink: 1` and no `numberOfLines` or wrap rule, so at large font scales each gets about half the row and the text engine breaks inside the word. The rendering is around lines 801-817.

## Fix

Let the row wrap instead of shrinking the words (`flexWrap: "wrap"` with the button keeping its intrinsic width, `flexShrink: 0`). Alternatively, stack label and button when `fontScale` exceeds a threshold, like the other large-text arrangements in this file (`stacked`). Optionally cap the button text with the app's existing `headerActionMaxFontSizeMultiplier`. Don't truncate "Ledgers" to an ellipsis.

**Acceptance:** at the maximum accessibility size, "Ledgers" and "New" each render as whole words, and the button keeps a 44-pt target. Default size is unchanged. The layout test for the drawer covers the large-text header.
