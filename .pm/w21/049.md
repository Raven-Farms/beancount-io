# Files locks every file named `main.bean`, not just the root one, so a nested `main.bean` can't be deleted from the app

**Severity:** minor. **Estimate:** 10–15 minutes. Owner: mobile. A2: multi-file ledgers often keep per-year or per-account folders, and a folder's own `main.bean` is a common layout. The server refuses to delete only the ledger's root file (`path === "main.bean"`). Mobile's Files screen compares the bare filename, so it shows the lock and withholds Delete for **every** `main.bean` at any depth. w3/626 noted this as an unfiled side observation when it fixed the dashboard counterpart.

Environment: `main` at `bb516d998`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). QA account, synthetic disposable ledger `mcp-agent-eval`. The fixture file was created and deleted through the API, and the ledger was left with only its original `main.bean`.

## Repro

1. Create `qa-20261020/main.bean` (a comment line, not included by the root file).
2. Files → the root shows the folder and the root `main.bean`, which correctly has a lock.
3. Open **qa-20261020**. Its `main.bean` row also shows the **lock** and offers no Delete. The folder can't be emptied from the app, although the server's `deleteLedgerFile` accepts this path (the cleanup delete through the API succeeded).

## Root cause

`mobile/src/screens/ledger-file-browser-screen/utils.ts:60-62`: `canDeleteLedgerFile(filename)` returns `filename !== "main.bean"`. Callers pass `entry.name` (`index.tsx:220`, `:456`, `:497`). The server rule (backend-v2 `ledger-workflow.ts`, `deleteLedgerFile`) compares the full path.

## Fix

Make it `canDeleteLedgerFile(path)` with `path.replace(/^\/+/, "") !== "main.bean"`, matching the dashboard's w3/626 rule, and pass `entry.path` at the three call sites. Keep the root lock and its accessibility label.

**Acceptance:** the root `main.bean` stays locked. `qa-20261020/main.bean` (and `/qa-20261020/main.bean`) shows Delete and deletes after confirmation. Unit tests in `utils` cover the root, a leading-slash root and a nested path.
