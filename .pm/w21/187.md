# Syntax errors lose their file and line ("parse errors in main.bean"), so the user can't find or jump to the bad line in the app

**Severity:** major. A single typo in any ledger file produces a Notifications row with no location and no tap target, and the editor banner's error row can't jump to a line. The user has no way to find the bad line on mobile. This affects REST, GraphQL and MCP alike. **Estimate:** 1 hour. Owner: ledger. A3: `Ledger.fromFiles(...).getErrors()` collapses every syntax error into one `LOAD` error per file with `file: null, line: null`. The same engine's `parseMultiFile(files, entryPoint)` returns the exact location (`P0012`, `main.bean` line 4; `2026/jan.bean` line 3 for an included file), and `bean-check` reports the line too.

Verified through the API at `main` `789588341` on the disposable QA ledger, which I restored byte-for-byte to `f1a0b83c`. The fixture appended `2026-08-30 * "qa-20261020 parse"` with `Assets:Cash  abc USD`. `getLedgerErrors` returned **`{message: "parse errors in main.bean", filename: null, lineno: null}`**, plus the one-posting warning in w21/188. The reviewer confirmed the engine's located alternative and the `bean-check` output.

## Where

- `backend-cluster/ledger/src/foundation/rustledger/engine.ts:141-150` (`snapshotOf` uses `getErrors()`)
- `ledger-data-mappers.ts:42-54` (`toBeancountErrorsPublic`, `source: null`)
- `mobile/src/screens/notifications-screen/notifications-screen.tsx:153-196` (a row is tappable only with a `filename`)
- `mobile/src/screens/ledger-file-editor-screen/utils.ts:22-26`

## Fix

When a `LOAD` "parse errors in X" error is present, replace it with the located parse errors from `parseMultiFile` (message, file and line), so every surface gets tappable, jumpable rows.

**Acceptance:** with the fixture, `getLedgerErrors` returns a parse error with `filename: "main.bean"` and the bad line. The Notifications row opens the editor at that line, and the banner row jumps. Add a ledger-service test.
