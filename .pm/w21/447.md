# The file editor's error banner shows another file's errors when one file's name starts with the other's ("main.bean" picks up "main.beancount")

**Severity:** low. **Estimate:** 10 minutes. Owner: mobile. A3: `messageNamesFile` in `mobile/src/screens/ledger-file-editor-screen/utils.ts:17-31` finds the start of the file name in an error message but never checks where it ends. The reviewer's tsx run of the real `filterFileErrors(errs, "main.bean")` keeps "parse errors in main.beancount" and "Errors in main.bean.bak: oops".

Code-level at `main` `1e9f0fc30`; not exercised on the device. This fallback applies only to an error that carries no file name (the located errors from w21/187 usually do), so it's niche. A ledger with both `main.bean` and `main.beancount` would show the second file's parse errors in the first file's editor.

## Fix

Require the character after the match to be the end of the text, whitespace, `:` or closing punctuation, not a continuation of the name (`[\w.-]`).

**Acceptance:** the two messages above are filtered out for `main.bean` and still match `main.beancount` and `main.bean.bak` respectively. Unit cases are added.
