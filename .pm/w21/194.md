# A save or delete that completes after the user has left still navigates, popping whatever screen is now on top; "Discard" during "Saving…" doesn't stop the write

**Severity:** moderate. On a slow connection, the user taps Back during "Saving…", chooses Discard, and opens another transaction. When the save lands, a "Saved" toast fires, the entry is written anyway, and the unrelated screen closes. Edit Transaction's `dismiss(2)` pops two screens from wherever the user now is. **Estimate:** 45 minutes. Owner: mobile. A3: none of the write completions checks that its screen is still mounted or focused, and expo-router's `router` is global, so `GO_BACK` acts on the current top of the stack. The unsaved-changes guard ignores `saving`, so Discard is offered for an in-flight write.

Code-level at `main` `7fa4c4682`. It needs a network delay of about 3 s.

## Where (`mobile/src/`)

- `screens/multi-postings-transaction/multi-postings-transaction-screen.tsx:583-600` (the guard ignores `saving`) and `:647-657` (`router.back()`)
- `common/ledger-write.ts:109-114` (Delete Transaction's `goBack()`)
- `screens/edit-transaction-screen/edit-transaction-screen.tsx:330-355` (`dismiss(2)` / `dismissTo`)
- `screens/add-budget-screen/add-budget-screen.tsx:258-259` and `screens/open-account-screen/open-account-screen.tsx:317-322`

## Fix

- Gate post-write navigation on the originating screen still being focused (`navigation.isFocused()`, or an "is mounted" ref); otherwise only show the toast.
- While a save is in flight, have the guard say "Saving… leave anyway? The entry will still be saved" instead of "Discard".

**Acceptance:** with a 3 s delay, Back → leave → open another detail: when the save lands, the other screen stays put and a toast says "Saved". Edit's `dismiss(2)` never pops unrelated screens.

## Dedupe

w21/150 is swipe-back bypassing the guard; w4/304 is the dashboard twin. Searched `.pm/**` for "already left", unmount, "wrong screen", `dismiss(2)`, and Discard together with Saving.
