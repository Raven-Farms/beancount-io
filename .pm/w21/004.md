# Open Account turns a typed full name into `Assets:Assets:Bank:Checking`

**Severity:** minor. **Estimate:** 30–45 minutes. Owner: mobile. A2: everywhere else, the app shows accounts by their full name (`Assets:Bank:Checking` in the picker, Money flow and the Accounts tree). A newcomer who types or pastes that name into Open Account gets a nested account under a doubled root. The duplicate-account check doesn't catch it either.

Environment: `main` at `ab6f2adf7`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0), light, English. QA account on `https://beancount.io`, on the synthetic disposable ledger `mcp-agent-eval`, which already opens `Assets:Bank:Checking`. Nothing was saved.

## Repro

1. Accounts → **+** (Open Account). The root selector reads **Assets:** and the sub-path placeholder reads `Bank:Checking`.
2. Enter `Assets:Bank:Checking` in the sub-path field.
3. The helper line reads **"Will be created as Assets:Assets:Bank:Checking"**, and **Done** turns enabled.

Entering `Liabilities:CreditCard:Visa` with the Assets root likewise offers `Assets:Liabilities:CreditCard:Visa`. Controls: a lowercase `bank:checking` is rejected inline ("Each account component must start with an uppercase letter or a number"). The account picker's **Create** prefill splits a typed root correctly.

## Expected / actual

- **Expected:** a sub-path that begins with one of the five roots (case-insensitive, then `:`) moves that root into the selector and keeps the rest as the sub-path. `Assets:Bank:Checking` then resolves to `Assets:Bank:Checking`, and w0/037's "already open" refusal applies. The other option is to refuse with an inline message, but switching the root is what the prefill path already does.
- **Actual:** the text is composed under the selected root as-is, so the app offers to open a duplicate-looking account that no other screen would ever suggest.

## Root cause

`mobile/src/screens/open-account-screen/account-name.ts:22-33` (`composeAccountName`) joins `rootPrefix` with whatever was typed. `splitPrefillAccountName` (same file, lines 36-58) already performs the needed split, but it is used only for the `prefill` route param (`open-account-screen.tsx:213-226`), never for typed input.

## Fix

In the sub-path's change handler, run the text through `splitPrefillAccountName(text, currentRoot)`. When it returns a different root or a shorter sub-path, set both. Typing `Expenses:` then switches the selector to Expenses with an empty sub-path. Then the existing validation, the "Will be created as" preview and the already-open refusal all see the real name. Keep verbatim casing after the root, so lowercase components are still refused, not silently capitalized.

**Acceptance:** with Assets selected, entering `Assets:Bank:Checking` shows the already-open refusal and Done stays disabled. `Liabilities:CreditCard:Visa` switches the selector to Liabilities, and `Expenses:Food:Snacks` previews `Expenses:Food:Snacks`. Unit tests cover root peeling for each root, mixed case (`assets:Bank:X`), and a sub-path that merely contains a root name later (`Bank:Assets` stays under the selected root).

## Dedupe

Searched `.pm/**` (including `done/`) for doubled roots (`Assets:Assets`), Open Account normalization and prefill. w0/037 (already-open refusal), the "half-typed name" note and "Capitalize the account picker's Create prefill" covered neighbours. None covers a root typed into the sub-path. No open item.

## Not verified

Android, Persian (RTL root selector), and the dashboard's Open Account dialog, which has its own input.
