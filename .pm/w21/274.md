# On Android, Back from a Files sub-folder leaves the tab (or the app) instead of going up a folder

**Severity:** minor-to-moderate (Android). **Estimate:** 15 minutes. Owner: mobile. A3: the folder stack is component state, and "up" is only the breadcrumb chevron. There is no `BackHandler` in the browser; the only one in `src/` is the drawer's, which runs only while the drawer is open. Re-tapping the Files tab only scrolls to the top.

Code-level at `main` `7f85628b8`. Not driven: the simulator is iOS, and the pinned Expo MCP has no Android Back.

## Root cause

`mobile/src/screens/ledger-file-browser-screen/index.tsx:313-322` (the stack), `:548-550` and `:574-588` (the chevron), and `:300` (`useScrollToTop`).

## Fix

While in a sub-folder, register a `hardwareBackPress` handler that pops the stack (inside `useFocusEffect`), and reset to the root on the tab's `tabPress` when already at the top.

**Acceptance:** on Android, Back from Files › 2026 shows Files root, and a second Back leaves the tab. A source or unit check covers it.
