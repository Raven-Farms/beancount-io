# An iOS swipe-back gets past the unsaved-changes guard: the editor slides away, then "Discard your changes?" pops up over Files, and Cancel leaves the navigation stack broken

**Severity:** moderate. This affects the file editor, Edit Transaction and New Transaction, the three screens with an unsaved-changes guard. Swipe-back is the most common way to leave a screen on iOS. **Estimate:** 45 minutes. Owner: mobile. A3: the guards use `navigation.addListener("beforeRemove", …)`. The native-stack inside expo-router 57 blocks the native gesture (`preventNativeDismiss`) only for routes registered through `usePreventRemove` (`preventedRoutes[route.key]?.preventRemove`). So the swipe dismisses natively, the JS guard then fires late, and the library reports "removed natively but didn't get removed from JS state… prevented in a 'beforeRemove' listener, which is not fully supported in native-stack". The custom header back button goes through `router.back()` and is still guarded (w4/011).

Code-level at `main` `6a478b53f`, traced through the installed library. Not exercised natively: expo-mcp has no swipe tool, and idb isn't installed.

## Scenario

Files → main.bean → type `x` → swipe back from the left edge. Files appears, then the Discard alert appears on top. Cancel keeps you on Files, while JS still thinks the editor is current and its edits are invisible.

## Where

- `mobile/src/screens/ledger-file-editor-screen/index.tsx:576-594`
- `mobile/src/screens/edit-transaction-screen/edit-transaction-screen.tsx:378`

- No route sets `gestureEnabled: false`.

## Fix

Replace the `beforeRemove` listeners with `usePreventRemove(hasUnsavedChanges, ({ data }) => …)`, which also sets `preventNativeDismiss`, so iOS blocks the swipe and shows the alert while the screen is still visible. Keep the save-success bypass.

**Acceptance:**
- On iOS, a swipe-back from a dirty editor, Edit Transaction or New Transaction doesn't leave the screen. The alert appears over the screen.
- Cancel stays put with the edits intact; Discard leaves.
- No "removed natively" warning is logged.
