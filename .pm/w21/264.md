# Home's lower cards load with short skeletons, so everything below jumps by 160–260 pt when data arrives

**Severity:** minor (polish). It breaks `mobile/AGENTS.md`'s rule that the view mustn't shift when data lands. **Estimate:** 20 minutes. Owner: mobile.

Code-level at `main` `26fb7ee69`:

| Card | Skeleton | Loaded |
|---|---|---|
| Recent Transactions (`recent-transactions-card.tsx:95`) | one 160 pt tile | 5 × ~64 pt rows ≈ 320 pt |
| Latest Updates (`feed-card.tsx:123-139`) | 3 × 28 pt ≈ 84 pt | 5 rows of ~51–69 pt |
| Budget (`budget-card.tsx:153-158`) | 2 × 34 pt, no gap | up to 3 rows with 12 pt gaps |

## Fix

Build each skeleton row by row to match the loaded layout (as `TransactionsListSkeleton` does), at `RECENT_LIMIT`, `FEED_LIMIT` and `BUDGET_PANEL_ROWS` rows.

**Acceptance:** on a cold Home load, Spending's top edge moves by less than 8 pt between skeleton and data. A layout test pins the skeleton heights.
