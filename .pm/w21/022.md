# A refund month's negative Expenses bar runs off the bottom of the Reports chart, through the month label

**Severity:** minor. **Estimate:** 20–30 minutes. Owner: mobile. A2: refunds and returns make a month's net expenses negative, which is common in a short window such as 1M. The Income vs Expenses chart then draws the red bar below $0, past the plot floor, over the month label and into the legend, with no axis tick to read it against.

Environment: `main` at `c23bb468f`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0), light, English, "today" = 2026-10-20. QA account, synthetic disposable ledger `mcp-agent-eval`. The fixture was restored byte-for-byte (sha256 checked, clean ledger check).

## Repro

1. Add `2026-10-05 * "qa-20261020-refund"` with `Assets:Bank:Checking 80.00 USD` / `Expenses:Food:Groceries -80.00 USD`, so October's only income or expense posting is a refund.
2. Relaunch → **Reports** → **1M**.
3. The y-axis runs $0 → $80 (for the Net Profit dot, +$80). The **Expenses** bar starts at $0 and extends **down** past the axis, overlapping "OCT" and stopping at the legend. There is no negative tick.

## Root cause

`mobile/src/common/d3/income-expense-bar-chart.tsx:85-91`:

```ts
const maxBar = Math.max(0, ...income, ...expense);
const yMax = Math.max(maxBar, ...net, 1);
const yMin = Math.min(0, ...net); // net can dip below zero (a loss month)
```

`yMin` considers only `net`, never `income` or `expense`. A negative bar (net refunds, or negative income such as a clawback) maps below `chartHeight - BOTTOM_PADDING`, and `restingBarRect` draws it there.

## Fix

Include the bars in the lower bound: `const yMin = Math.min(0, ...net, ...income, ...expense);`. `.nice()` then adds a negative tick, and the zero line rises so the bar stays inside the plot. Check that the month labels at `chartHeight - 8` stay clear. Do the same review of `budget-bar-chart-d3.tsx`, which already uses `Math.min(0, ...actuals, ...budgets)`, as the control.

**Acceptance:** the repro shows the Expenses bar inside the plot under a −$80 tick, with "OCT" readable below the plot. Ordinary months are unchanged. A unit test on the chart's scale computation with a negative expense asserts `yScale(-80)` lies within the plot range.
