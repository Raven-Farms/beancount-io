# Add Budget: Done re-enables while the post-save refresh runs, so a second tap writes the budget twice and pops the Budget screen too

**Severity:** moderate. On a slow connection, two identical `custom "budget"` directives and two commits are written. The second completion's `router.back()` also pops the Budget screen. **Estimate:** 20 minutes. Owner: mobile. A3: `canSubmit` is guarded only by the mutation's `loading` and `saved`. Apollo sets `loading: false` before the awaited mutation resumes, and `saveBudget` then awaits `invalidateLedgerData(client, "entries")` (a refetch of every mounted ledger query). For that whole window `loading` is false, `saved` is still false, and the form is unchanged, so Done is live.

Code-level at `main` `7fa4c4682`. A native repro needs a host network delay of about 1.5 s.

## Where

- `mobile/src/screens/budget-screen/hooks/use-save-budget.ts:20-29`
- `mobile/src/screens/add-budget-screen/add-budget-screen.tsx:222-227` (`canSubmit`) and `:240-266` (`handleSubmit`)
- Open Account has the same window (`use-open-account.ts:41`, `open-account-screen.tsx:264-271, 297-323`). The server refuses its duplicate `open`, so the user gets an error haptic and an error flash instead of a duplicate.

## Fix

Use an in-flight ref or single-flight (like New Transaction's `createSingleFlight`) that stays set until the whole save, including invalidation, finishes. Set `saved` as soon as the mutation succeeds.

**Acceptance:** with a 1.5 s delay, rapid repeated Done taps produce exactly one directive and one navigation. Add a hook test.
