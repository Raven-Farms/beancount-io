# Budget "ALL" shows $0 actual and a green "Below target" for the current period while its read is loading or has failed (every offline day after the first)

**Severity:** moderate (a wrong headline figure, the pattern w21/080 fixed for Home and Reports). **Estimate:** 20 minutes. Owner: mobile. A3: in `mobile/src/screens/budget-screen/hooks/use-budget-actuals.ts:88-122`, `allTimeThroughToday(fetched, undefined, …)` leaves out the current period while the current-period read has no data, as w21/332 intended. Lines 118-121 then call `periodsThrough(last.date, …)`, which adds the current period back with `actual: 0`. `budget-group-card.tsx` (around `:200` and `:299-336`) computes the header stats from that series even when `error` is set; only the chart switches to `budgetLoadFailed`.

Code-level at `main` `3a3c7e4fb`. In the reviewer's tsx run (a 400 USD monthly budget, today 2026-10-21, all-time results through November, current-period read undefined), the series ends `{2026-10-31, actual 0, budget 270.97}`, and `selectBudgetCardStats` returns `actual 0`, `status "below"`, `favorable true` and `progressPercent 0`. Not exercised on the device. The current-period read's window (`<period start> - <today>`) changes daily, so offline it is never cached, and from the second offline day ALL keeps these $0 figures above a "Failed to load" chart.

## Fix

Call `periodsThrough` only when the current-period read has data (or `time !== undefined`). While `error` is set, don't show judged stats (show the failure in the header too).

**Acceptance:** with the current-period read pending or failed, ALL shows no $0 / "Below target" for the current period. Unit cases are added.
