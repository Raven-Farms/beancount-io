# A padding entry's detail screen switches to "changed or removed" once any other transaction has been opened

**Severity:** minor. **Estimate:** 20 minutes. Owner: mobile. A3: `transaction-detail-screen.tsx:338` skips entry context for a generated (padding) entry only while `selectedTransactionVar` still holds that entry. The stash holds only the transaction tapped last, so opening any other transaction from a screen above overwrites it. The padding screen still in the stack then loads context, the server answers NOT_FOUND for the padding hash (as in w3/140), and `isEntryGone` turns that into the "This transaction was changed or removed" state, which also refetches every entry list.

Code-level at `main` `a69419ae4`. The reviewer's tsx run of the real selectors gives `shouldLoadContext = false` with the padding entry's own stash and `true` once another entry is stashed, and `isEntryGone(NOT_FOUND)` is true.

Reproduced natively (iPhone 17e, `a69419ae4`), with a pad and balance fixture written to the disposable ledger and restored. The padding entry "(Padding inserted for Balance of 100.00 USD …)" opened normally. Tapping its asset posting, then opening another transaction on that account and going Back twice, left the padding screen reading "This transaction was changed or removed. Go back to see the current list."

Steps: open a padding entry, tap a posting to reach the account, open any transaction there, then go Back twice. The padding entry now claims it was removed. A cold link to a padding entry shows the same false message.

## Fix

Capture the first stashed entry in a ref per screen, so a later overwrite can't revive the context query. Never read NOT_FOUND as "gone" for an entry known to be generated.

**Acceptance:** after the steps above, the padding entry still renders, and no context query fires for it. A unit or screen test is added.

## Dedupe

Related but different: w3/140 (Share/Copy for generated entries), w21/013 and w21/094 (the removed state for entries that really were deleted), w21/388 (stale detail after a hash-keeping edit). Searched `.pm/**` for stash, padding, NOT_FOUND and entry gone.
