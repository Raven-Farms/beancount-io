# Log out can hang for about 60 seconds on a captive or lossy network, with no busy state

**Severity:** minor. **Estimate:** 20 minutes. Owner: mobile. A3: `performLogout` (`mobile/src/screens/setting/logout-action.ts:18-28`) waits for the token revocation request before clearing local state. That request (`oauth/token-manager.ts:218-234`) has no timeout or abort, unlike the refresh path. The Settings handler (`main-content.tsx:232`) waits for the whole logout before routing and shows no busy state. On Wi-Fi with no internet, nothing happens until the OS request timeout, about 60 s (compare w21/183 and w21/215). A second tap starts a parallel logout. The session and the cached account data stay on the device until it finishes. Account deletion signs out through the same path.

Code-level at `main` `7280ccceb`. Not run natively.

## Fix

Clear local state first and revoke in the background, or bound the revocation with a short abort timer of 5–10 s. Show a busy state and ignore repeat taps.

**Acceptance:** on a network that drops every request, Log out returns to Welcome within a few seconds, and repeat taps do nothing.

w21/blocked/064 is refresh-token rotation. Searched `.pm/**` for revokeOAuthSession, revocation, logout and "sign out" with timeout, hang, captive and offline.
