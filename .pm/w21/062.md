# The file editor converts CRLF files to LF on save: adding one line rewrites every line ending, so the commit touches the whole file

**Severity:** minor (silent whole-file rewrite). **Estimate:** 20–30 minutes. Owner: mobile. A2/A3: ledgers kept on Windows, or exported by Windows tools, use CRLF line endings. Editing one in the mobile editor normalizes every `\r\n` to `\n`. The user's one-line change becomes a whole-file diff in history. That breaks blame, causes merge noise with a desktop checkout, and mixes endings when the desktop tools append CRLF again. w3/258 fixed the same mixed-ending problem for `bea add`.

Environment: `main` at `5745bd076`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). QA account, synthetic disposable ledger `mcp-agent-eval`. A CRLF fixture file was created through the API and deleted afterwards, and `main.bean` was untouched.

## Repro (observed)

1. Create `qa-20261020-crlf.bean` = `; qa-20261020 crlf file line1\r\n; line2\r\n; line3\r\n`.
2. Files → open it → add `; qa added` on the last line → **Save**. The save succeeds.
3. `getLedgerFile` bytes: `…line1\n; line2\n; line3\n; qa added`. All three CRLFs became LF.
4. The commit's stats read **+4 −3**: the three untouched lines are deleted and re-added.

## Root cause

The CodeMirror document normalizes line separators, and `handleSave` → `encodeLedgerFileContent(text)` (`mobile/src/common/ledger-file-content.ts`) writes the normalized text back. Nothing records the file's original line-ending style. (w4/268 preserved a UTF-8 BOM the same way; line endings were left out.)

## Fix

On load, detect the dominant line ending (`\r\n` versus `\n`). On save, re-join the editor's lines with it, so only edited lines change. Treat mixed files conservatively: keep the majority style, or refuse lossy editing with a notice, as w4/276 does for encodings. Cover the existing BOM handling in the same round-trip test.

**Acceptance:** the repro saves as `…line1\r\n; line2\r\n; line3\r\n; qa added` (plus `\r\n` if a newline is added), and the commit shows **+1** (or +1 −1 for a touched last line). LF files are unchanged. A unit test round-trips CRLF, LF and BOM+CRLF through decode → edit → encode.
