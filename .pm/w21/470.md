# Pull to refresh on Home skips Spending's to-today read and its scheduled-entry check, so "This month" goes stale or counts unpaid bills again (w21/337 follow-up)

**Severity:** minor-to-moderate. **Estimate:** 15 minutes. Owner: mobile. A3: the refresh effect in `mobile/src/screens/home-screen/components/spending-card.tsx:120-124` refetches only the month-long window query. The to-today read (`:131-141`) and `useScheduledThisMonth` (`hooks/use-scheduled-this-month.ts:18-24`, which exposes no refetch) stay on cache, because `nextFetchPolicy` is `cache-first` (`common/apollo/default-options.ts:18`). In-app writes evict them, so this bites after changes made elsewhere (web, CLI) and pulled in with pull to refresh.

Code-level at `main` `c039662e6`. In the reviewer's tsx run of the real `withMonthToDate` and `selectSpendingCompare`, with the to-today read cached at $300 and the refreshed window holding $2,000 for October, the card shows `thisMonth: 300`. Conversely, a check that was false at mount stays false after rent is pre-entered elsewhere, so the refreshed window counts it: w21/337's bug again. Not exercised on the device.

## Fix

In the `refreshSignal` effect, also refetch the scheduled check (return `refetch` from `useScheduledThisMonth`) and, when it is active, the to-today query.

**Acceptance:** after an outside change and a pull to refresh, "This month" matches the ledger, with pre-entered bills excluded. A wiring test is added.
