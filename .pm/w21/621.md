# Edit Transaction lacks w21/342's web-view recovery: if iOS kills the editor's web view, the draft resets and the last shortcut is inserted again at the top

**Severity:** minor (silent loss of an in-progress edit). **Estimate:** 20 minutes. Owner: mobile. A3 (code-level at `main` `ab6c875a9`): `edit-transaction-screen.tsx:567-577` passes no `onReady` or `onDraft` to the DOM editor, and `insertSpec` (set at `:459`) is never cleared. The file editor has this wiring (`ledger-file-editor-screen/index.tsx:1098-1099`). After a WebContent crash, the editor reloads the original slice, re-applies the stale `insertSpec` at position 0, and drops later keystrokes as stale revisions while Save stays enabled. w21/342's resolution names this as "Not covered … a follow-up", but nothing was filed.

Not run natively (the kill-WebContent technique from w21/342 works here, but this pass didn't drive it).

## Fix

Reuse the file editor's recovery: `onReady`/`onDraft` to restore the draft, and clear `insertSpec` after it's applied.

**Acceptance:** after killing WebContent mid-edit, the draft survives and nothing is re-inserted. A test covers the recovery wiring.

## Dedupe

Named as a follow-up in w21/342 (done). Searched `.pm/**` for onReady, onDraft and createEditorRecovery.
