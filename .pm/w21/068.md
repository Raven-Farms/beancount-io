# Notifications' Ledger Errors section shimmers forever when the errors query fails, with no message or retry

**Severity:** minor. **Estimate:** 15–20 minutes. Owner: mobile. A2: the bell screen's **Ledger errors** section stays pending until `getLedgerErrors` answers. If that query fails (offline, server error) before any data arrives, the section shows a skeleton indefinitely. The **Recent changes** section beside it shows `CardLoadFailure` with **Try again** in the same situation.

Environment: `main` at `8d4d672f9`. Code-level and harness-level: `selectSectionsPending` was run under Node. A failing errors query wasn't forced on the simulator.

## Evidence

- `mobile/src/screens/notifications-screen/section-state.ts:14`: `errorsPending: !state.errorsLoaded`.
- `mobile/src/common/hooks/use-ledger-errors.ts`: `loaded` is `data !== undefined`, which never turns true after a failure.
- `notifications-screen.tsx:206-211`: the screen destructures `loaded` from `useLedgerErrors()` but not `error`. Only the commits card goes through `selectCardLoadState` / `CardLoadFailure` (around line 308).
- `selectSectionsPending({errorsLoaded:false, commitsLoading:false, commitsLoaded:true})` → `errorsPending: true`, with no failure branch.

## Fix

Read `error` from `useLedgerErrors()` and route the errors section through the same `selectCardLoadState` → `CardLoadFailure` (retry = `refetch`) as the commits section. Keep "Ledger is healthy" only for a loaded empty list.

**Acceptance:** with the errors query failing, the section shows "Failed to load · Try again", and Try again recovers when the network returns. Unit test for the failure state.
