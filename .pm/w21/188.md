# Engine warnings ("Transaction has only one posting", "Cannot close account with non-zero balance") are listed and counted as ledger errors although bean-check passes

**Severity:** moderate. The bell badge and the red Notifications rows report errors on a ledger `bean-check` accepts, and "Ledger is healthy" is hidden. A one-posting unbalanced entry gets two rows. The write gate may also refuse a structured close because of a warning (code-level). **Estimate:** 45 minutes. Owner: ledger and backend-v2, plus mobile. A3: rustledger marks E3004 and E1004 `severity: "warning"`, and the service itself treats the ledger as valid (`engine.ts:635` checks `severity === "error"`). But `toBeancountErrorsPublic` drops `severity`, GraphQL doesn't expose it, and mobile counts every row.

Verified through the API at `main` `789588341` on the disposable QA ledger, restored to `f1a0b83c`. The fixture was `2026-08-30 * "qa-20261020 one-leg"` with `Assets:Cash  0 USD`. `getLedgerErrors` returned **`{message: "Transaction has only one posting", filename: "main.bean", lineno: 90}`** as an ordinary error.

## Where

- `backend-cluster/ledger/src/foundation/rustledger/ledger-data-mappers.ts:42-54` (drops severity)
- `backend-cluster/backend-v2/src/features/ledger/api/resolvers/ledger-data-resolver.query.ts:458-471` (no severity field)
- `mobile/src/common/hooks/use-ledger-errors.ts`
- The write gate is `new-ledger-errors.ts` (`refuseNewLedgerErrors` via `checkProjectedErrors`).

## Fix

- Expose `severity` on REST, GraphQL and MCP.
- Exclude warnings from `getLedgerErrors`'s error semantics and from the write gate, or return them separately.
- On mobile, count only errors in the bell and show warnings in a distinct, non-red style, if at all.

**Acceptance:**
- With the fixture, the bell shows no badge and Notifications reads "Ledger is healthy", with the warning shown as a warning if exposed.
- A real unbalanced entry still counts.

## Dedupe

Searched `.pm/**` for severity, warning, E3004, E1004, "only one posting" and "non-zero balance".
