# Saving over an entry changed elsewhere shows "Ledger resource not found" instead of w4/045's Reload choice

**Severity:** minor. **Estimate:** 20–30 minutes. Owner: mobile. A1/A2: w4/045 added a stale-edit path to Edit Transaction, with the `editConflict` message plus *Keep Editing* / *Reload*. In a real concurrent edit it never triggers. The server identifies entries by a content-derived hash, so once the entry changes elsewhere a save is answered **not found**, not as a checksum conflict. The user sees the raw server text and a draft that will fail on every retry.

Environment: `main` at `ab4d8f48e`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). QA account, synthetic disposable ledger `mcp-agent-eval`. Restored byte-for-byte (sha256 checked, clean ledger check).

## Repro

1. Transactions → FARMERS MARKET → pencil (Edit Transaction).
2. Outside the app, change that entry's narration (`"Produce"` → `"Produce qa-ext"`).
3. In the app, change the narration to `"Produce app"` → **Save**.
4. Inline under the hint: **"Ledger resource not found"**. There is no alert and no Reload. The hint line above still promises "A stale checksum or invalid beancount will be rejected with an error."

**Control (same run):** the file editor in the same race (open `main.bean`, change it outside the app, edit and Save) correctly shows **File Changed** with *Keep Editing* / *Reload*, and Reload drops the local edit. Its save is keyed by the file `sha`, so the string match fires there.

w4/045's own notes say "Not exercised: a real checksum conflict … and the alert on device". This is that exercise.

## Root cause

- `mobile/src/common/ledger-conflict.ts`: `isConflictError(message)` only matches `sha`, `conflict` or `409` in the message text.
- `mobile/src/screens/edit-transaction-screen/save-failure.ts` (`selectSaveFailure` / `selectOutcomeFailure`) routes everything else to `{ kind: "rejected", message }`, which here is the server's NOT_FOUND text.
- The ledger service resolves the entry by its content hash (`backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts`, `resolveSourceEntryId` / `locateSlice`), so a changed entry produces a not-found error before any checksum comparison.

## Fix

In `selectOutcomeFailure`, classify by error code, not text. Treat `NOT_FOUND` from the update (via `graphQLErrorCodes(outcome.error)`, `src/common/graphql-error-codes.ts`) as `{ kind: "conflict" }` for Edit Transaction. Keep the string match as a fallback. On Reload, if the original hash no longer resolves, show w21/013's "This transaction was changed or removed" state instead of reseeding.

**Acceptance:** repeating the repro shows `editConflict` with *Keep Editing* / *Reload*, and Reload leads to the changed-or-removed state (or the fresh source if it can be found). Invalid Beancount still shows the server's message. `save-failure.test.ts` gains a NOT_FOUND-coded error case.

Follow-up to w4/045 (done; its device check was explicitly not exercised). w21/013 (done) covers opening a removed entry, not saving over a changed one. Searched `.pm/**` for "resource not found", conflict and stale checksum.
