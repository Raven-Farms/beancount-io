# Selecting all three status chips counts as an active filter though it filters nothing

**Severity:** minor (cosmetic). On an empty ledger it replaces the welcome screen with "No transactions match your search or filters." **Estimate:** 10 minutes. Owner: mobile.

Code-level at `main` `ba784a628`. Under Node, `toFilterQuery({ statuses: ["cleared", "pending", "other"], range: "all" })` returns all three `transactionSubtypes`, and `countActiveFilters` returns `1`. The server's Cleared + Pending + Other matches every transaction (`backend-cluster/ledger/src/foundation/rustledger/journal-serialize.ts:443-457`).

## Root cause

`mobile/src/screens/transactions-screen/filters/select-filter-query.ts:119-121, 145` treat any non-empty `statuses` as active. The empty state is at `transactions-screen.tsx:291-294`.

## Fix

Treat "every status selected" as no status filter, in both `toFilterQuery` and `countActiveFilters`.

**Acceptance:** with all three chips selected, there is no dot, no subtype filter is sent, and an empty ledger shows its welcome. Unit cases are added.
