# w21/176's iOS permission-string files were never committed (`mobile/.gitignore` ignores `locales/ios/`), so the camera prompt stays English and the unit suite fails

**Severity:** high. `CI` (mobile) `yarn test:unit` fails on a clean checkout, and the w21/176 localization never reaches a build. **Estimate:** 15 minutes. Owner: mobile. A3: commit `19021a1dd` points `mobile/app.json:51-65` (`expo.locales`) at `./locales/ios/<lang>.json`. But `mobile/.gitignore:75` has a bare `ios` pattern, which also matches `mobile/locales/ios/`, so the 13 JSON files exist only in the author's working tree. Expo's `getLocales` catches the missing file, warns and returns null, so prebuild and EAS still succeed, just without any `InfoPlist.strings`.

Verified at `main` `24df51bf0` on a clean checkout:
- `git check-ignore -v mobile/locales/ios/en.json` prints `mobile/.gitignore:75:ios`.
- `git ls-files mobile/locales` is empty, and the directory doesn't exist.
- `node ./scripts/jest-lite-runner.js src/__tests__` fails with `ENOENT … mobile/locales/ios/en.json` from `permission-strings.test.ts`.

## Fix

Anchor the pattern to `/ios`, or add `!locales/ios/` after it. Commit the 13 locale files and re-run 176's native verification of the camera prompt in a non-English language.

**Acceptance:** `git ls-files mobile/locales/ios` lists 13 files, the mobile unit suite passes on a clean clone, and a prebuilt iOS app shows the localized camera purpose string.
