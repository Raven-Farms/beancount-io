# Returning to the app never refreshes a mounted screen, so Home can contradict Transactions after an outside change

**Severity:** major. **Estimate:** 30–45 minutes. Owner: mobile. A1/A2: the agent loop is to switch to Claude Code, CLI or web, change the ledger, then switch back to the app. w21/006 made each screen revalidate **once per mount**. Tabs stay mounted for the whole session, though, and nothing refetches when the app returns to the foreground. So Home keeps showing a removed transaction and the old net worth, while a tab mounted later shows the current ledger.

Environment: `main` at `6bb228f84` (includes w21/006's `APOLLO_DEFAULT_OPTIONS`), dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). QA account, synthetic disposable ledger `mcp-agent-eval`. Fixture restored byte-for-byte.

## Repro

1. Append `2026-10-05 * "qa-20261020-refund" … Assets:Bank:Checking 80.00 USD / Expenses:Food:Groceries -80.00 USD` outside the app, then relaunch. Home shows the refund and Net Worth **$17,188.51**.
2. Remove the entry outside the app, restoring the file.
3. Keep the app running. Background it (open Settings), wait, and foreground it.
4. **Home** still shows **qa-20261020-refund +$80.00** in Recent Transactions and Net Worth **$17,188.51 (+$4,004.00)**. The ledger's real net worth is **$17,108.51**.
5. Tap **Transactions**, whose first mount happens after the change: the refund is **absent**. The two tabs disagree about the same ledger until the user happens to pull to refresh on Home or relaunch.

## Root cause

- `mobile/src/common/apollo/default-options.ts`: `fetchPolicy: "cache-and-network"`, `nextFetchPolicy: "cache-first"`. That means one network check per mount or variables change, by design.
- No `AppState` "active" handler refetches in the signed-in app. `rg AppState mobile/src` finds it only in `screens/examples/` (the guest example ledger). There is no `useFocusEffect` on the tab screens either.

## Fix

On `AppState` change to `active` (throttled, e.g. at most once per 30 s, and only when signed in with a selected ledger), run `client.refetchQueries({ include: "active" })`, or reuse the existing ledger invalidation (`invalidateLedgerData`) with a "foreground" reason. Keep cached data on screen while refetching (no skeleton flash), and swallow offline errors into the existing stale banner. Optionally do the same on tab focus for tabs untouched for more than N seconds.

**Acceptance:** repeating steps 1–4, Home drops the refund row and shows $17,108.51 within one network round trip of foregrounding. Rapid background/foreground cycles send at most one refetch per throttle window. Offline foregrounding keeps the cached screen with the stale banner. A unit test drives an `AppState` change and asserts one `refetchQueries` call.
