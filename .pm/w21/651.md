# Futures currencies like "/ESZ24" and "/6E" are refused as "not a valid currency", though both engines accept them (w23/033)

**Severity:** low (traders, API and agents; mobile when the ledger already uses one). **Estimate:** 10 minutes. Owner: ledger. A3 (code-level at `main` `c1c3be649`; the validator and rustledger 0.24 were run on the same input): `entry-tokens.ts:26` requires a leading `[A-Z]`. rustledger and Beancount 3.2.3 accept `/ESZ24` (Beancount's `lexer.l` lists `/6J` and `/NQH21` as examples). This hits posting units and prices, `open` currencies, `commodity`, `price` and custom amounts on REST, GraphQL and MCP. On mobile, New Transaction is refused whenever the ledger already uses such a commodity.

## Fix

Use Beancount's currency grammar (an optional leading `/`).

**Acceptance:** `/ESZ24` passes and `/6.3` is still refused. Tests cover both.

None found (searched all of `.pm/` for "/ESZ24", futures and "not a valid currency").
