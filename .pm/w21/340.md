# File editor: tapping an error row while the keyboard is open scrolls the error line behind the keyboard

**Severity:** minor. **Estimate:** 15 minutes. Owner: mobile. A3: `jumpToEditorLine` centres the line in the full editor height, then re-centres at 100, 500 and 1000 ms with `scrollTop = top - clientH/2`. Neither step accounts for `keyboardInset`, so w3/214's margin never applies, and the keyboard stays up when a native error row is tapped.

Code-level at `main` `57826d105`: `mobile/src/components/code-editor/code-editor.tsx:198-228` (`:204` and `:218`). Geometry on an iPhone 17 Pro with the banner collapsed: the editor is about 693 pt tall, and the inset is about 346 pt (`ledger-file-editor-screen/index.tsx:627-631`). The centred line lands at about 346 pt, under the accessory bar; with the error list expanded, about 70 pt inside the keyboard. Not seen natively (the software keyboard is suppressed in this run).

## Fix

Keep the inset in a ref and centre within the visible area (`top - (clientH - inset) / 2`), passing `yMargin` to the first `scrollIntoView`.

**Acceptance:** with the keyboard up, tapping an error row leaves the target line visible above the accessory bar.

## Dedupe

w21/152 (re-arming the jump) and w3/214 (caret while typing) are different. Searched `.pm/**` for jumpToEditorLine and "behind the keyboard".
