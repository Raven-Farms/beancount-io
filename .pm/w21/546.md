# A resumed Create Ledger draft from an earlier day silently replaces a typed Books begin with today and reopens on Review (w21/053 over-applied)

**Severity:** minor (one tap on Create starts the books today, and back-dated entries are refused). **Estimate:** 20 minutes. Owner: mobile. A3 (code-level at `main` `6c1f191b7`, proven under `tsx`): `mobile/src/common/create-ledger-draft.ts:112-120` applies `...(stale && { historyStart: today })` to any draft saved on an earlier day, including a date the user typed on purpose. w21/053 meant to refresh only a stale *default*. Review doesn't show Books begin, so the change is invisible. The probe restored `step 2` with `historyStart 2026-10-22` for a draft typed as `2026-01-01`.

Second effect: a Create sent at 23:58 and resumed at 00:05 changes the fingerprint, so `isNewCreateRequest` returns true and a new requestId is minted. If the first Create went through, the retry reports "already exists" (w21/502 by another path).

Not run natively: it needs a day change while the draft is open.

## Fix

Store whether Books begin was typed, and refresh only an untouched default. Exclude the refresh from the request fingerprint (or keep the stored requestId while a Create is unresolved).

**Acceptance:** a typed 2026-01-01 survives a next-day resume, a default date refreshes, and a resumed in-flight Create keeps its requestId. Unit cases are added.

## Dedupe

Over-application of w21/053; see w21/502 and w21/510. Searched `.pm/**` for historyStart together with stale, and create-ledger-draft.
