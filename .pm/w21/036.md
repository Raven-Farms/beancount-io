# The Transactions account filter offers only leaf accounts, so "all Food spending" can't be filtered

**Severity:** minor. **Estimate:** 30–45 minutes. Owner: mobile. A2: filtering by a category such as `Expenses:Food` (groceries, restaurants, coffee together) is the most natural way to scope a journal. The server supports it, but the filter's account picker lists only opened leaf accounts, and searching `Expenses:Food` returns its three children, never the parent. The Accounts tab already lets you open `Expenses:Food` as a combined journal, so the two surfaces disagree.

Environment: `main` at `69d2134a3`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). QA account, synthetic ledger `mcp-agent-eval`. Nothing was saved.

## Repro

1. Transactions → filter icon → **Account** → Account Picker.
2. Browse Expenses or search `Expenses:Food`. Only `Expenses:Food:Groceries`, `…:Coffee` and `…:Restaurants` are offered, with no `Expenses:Food` row.

API control: `getLedgerJournal(query: { account: "Expenses:Food", directiveTypes: [Transaction] })` returns **total 6**, all Food children combined. The filter's `account` parameter (`select-filter-query.ts:128-130`) passes straight through to it.

## Root cause

`mobile/src/screens/account-picker-screen/account-picker-screen.tsx` (around line 293) sources `accounts` from the ledger meta's open accounts. Parent segments that are never `open`ed don't exist in that list, for every picker `type`, including `"filter"`.

## Fix

For `type: "filter"` only, derive parent prefixes from the open accounts (`Expenses:Food` from `Expenses:Food:Groceries`) and include them in browse and search results, ranked above their children for a prefix query and labelled as including sub-accounts (for example a trailing "· all"). Posting pickers and Open Account must keep leaf-only behaviour, since postings can't target an unopened parent.

**Acceptance:** the filter picker offers `Expenses:Food`. Applying it lists the 6 Food transactions, and the filter dot and summary name the parent. The New Transaction posting picker still offers no parent rows. A unit test covers parent derivation and the type gate.
