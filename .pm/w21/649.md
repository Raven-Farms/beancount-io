# Since w23/033, a valid account name containing ZWNJ or ZWJ (normal in Persian) is refused with raw English API text: "entry 0: account … is not a valid account" (undoes w21/192)

**Severity:** minor for Persian users. **Estimate:** 15 minutes. Owner: ledger (and mobile copy). A3: `backend-cluster/ledger/src/features/ledger/utils/entry-tokens.ts:18` (`NOT_IN_A_TOKEN = /[\s\p{C}]/u`) refuses U+200C and U+200D, which are `\p{Cf}`. This came in with `0cca7cf29` (w23/033) and runs at `api/entries.ts:166`. w21/192 established that rustledger accepts them, and mobile's Open Account allows them on purpose (`open-account-screen/account-name.ts:180`). The refusal reaches the user unchanged through `common/ledger-refusal.ts:209-211`. Existing ZWNJ accounts (from the file editor) also refuse New Transaction and Add Budget ("entry 0: postings[0].account … is not a valid account").

Production (2026-10-22, disposable ledger; nothing written, ledger identical to its snapshot): `bulkEntries` opening `Assets:Bank:خانه‌ها` (with a ZWNJ) returns `BAD_USER_INPUT` "entry 0: account \"Assets:Bank:خانه‌ها\" is not a valid account". In the app, Open Account enables Done and previews "Will be created as …", then shows that English text in any language.

## Fix

Allow ZWNJ and ZWJ inside account components in the token rule (matching rustledger and w21/192). Separately, map token refusals to translated copy on mobile instead of showing API field paths.

**Acceptance:** that open succeeds on all three surfaces, and other format characters are still refused. Tests cover it.

## Dedupe

Regression of w21/192 by w23/033. Searched `.pm/**` for ZWNJ, 200c and NOT_IN_A_TOKEN.
