# In Persian, UI text left at natural alignment sits on the physical left, against `rtl.ts`'s documented rule

**Severity:** minor. **Estimate:** 45–60 minutes (an app-wide default plus a guard). Owner: mobile. A2/A3: Persian is the app's right-to-left locale. Section titles, card subtitles and empty-state lines that hug the left edge, beside rows correctly mirrored to the right, read as a half-translated layout.

Environment: `main` at `137a3e464` (Metro from the main checkout), dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). Settings → زبان → فارسی → restart. QA account, synthetic ledger `mcp-agent-eval`.

## Observed (this run)

- **Settings:** the section titles **حساب**, **تنظیمات برنامه**, **پشتیبانی** and **دعوت دوستان** render at the **left** edge. The row titles below them (زبان, تم, …) are at the right.
- **Home → Spending:** the subtitle «این ماه در برابر ماه گذشته» is at the left, under the "See all" link, while the card title «هزینه‌ها» is at the right.
- **Home → Budget:** the empty-state line «برای یک حساب هدف تعیین کنید» is at the left.
- w0/049 (done) recorded the same thing as an unfiled follow-up: "Settings section titles, Add Budget's footnote, the drawer's 'Browse ledgers' row label, and the read-only notice's link … an explicit `LEADING_TEXT_ALIGN` moved each label checked here to the right. Worth its own item."

## Root cause

`mobile/src/common/rtl.ts:131-154` documents "UI copy needs nothing": `natural` alignment should follow the string's own direction. On this build it does not. Texts with no `textAlign` land on the physical left in RTL, while texts with `textAlign: LEADING_TEXT_ALIGN` (`"left"`, which iOS swaps under RTL) land at the leading (right) edge. Examples without `textAlign`: `SectionHeader` (`src/screens/setting/list-item.tsx:140-158`), `spending-card.tsx` `subtitle` (29-34), `budget-card.tsx` `emptyText` (48-51). Controls that work: Settings `ListItem.title` and `DashboardCard` titles (`components/dashboard-card/index.tsx:60`), which set `LEADING_TEXT_ALIGN`.

## Fix

Decide the app-wide default, as w0/049 asked:

- **Preferred:** give the shared typography layer (or a small `AppText` wrapper, if the codebase already has one) `textAlign: LEADING_TEXT_ALIGN` by default, so UI copy follows the layout. Opt out only where text must centre (empty-state blocks, buttons) or trail (amounts).
- **Or:** add `LEADING_TEXT_ALIGN` to each block-level UI `Text` that is full-width and not centred. Start with the surfaces above, the drawer rows and the read-only notice link.

Then update the `rtl.ts` comment, so "UI copy needs nothing" no longer misleads, and extend `src/common/__tests__/` with a guard over full-width `Text` styles in the listed screens.

**Acceptance:** in Persian after a restart, the Settings section titles, the Spending subtitle, the Budget empty line, the drawer's Browse ledgers and Merchants labels, and Add Budget's footnote all start at the right edge. English is unchanged. Centred empty states stay centred. A test pins the chosen default.
