# In-app commits are signed with the Gitea username and the account's real email, not the user's name or a noreply address

**Severity:** minor (display) to moderate (privacy). On public ledgers, anyone who can read the commits sees the author's signup email. **Estimate:** 45 minutes. Owner: backend-v2 + deploy. A3:
- Signup creates the Gitea user with only username, password and email, so `full_name` stays empty, and `updateProfile` stores first and last name in Postgres only.
- In-app commits are made without an explicit author, so Gitea signs them as that user: name = username (its fallback when `full_name` is empty), email = the account email.
- Gitea's keep-email-private default is off, and `deploy/` doesn't set it.

Verified against production on 2026-10-21: on the disposable QA ledger, the five latest commits' authors all carry a real (non-noreply) email, and each author name equals that email's local part. Notifications shows that username on every row ("‹username› · Oct 21, 2026"). Addresses are deliberately not recorded here.

## Root cause

- `backend-cluster/backend-v2/src/features/auth/service/auth-service.ts:274-280` (Gitea user creation).
- `account-service.ts:286-303` (`updateProfile`).
- `backend-cluster/ledger/src/features/ledger/operations/commit-ledger-files.ts:215-218` and `ledger/src/api/entries.ts:246-253` (commits without an author).
- `commits-service.ts:278-279` returns the name and email, and `listCommits` allows anonymous reads of public ledgers.

## Fix

- Set Gitea's `full_name` from first and last name at signup and in `updateProfile` (`adminEditUser`), and backfill existing users.
- Enable Gitea's default keep-email-private in the deploy config, and pass a noreply author on in-app commits.
- Optionally drop `email` from anonymous API responses. Git history itself also carries the email, so the deploy setting is the real fix.

**Acceptance:** a new in-app commit shows the user's name and a noreply email, and anonymous `listCommits` on a public ledger exposes no real email.
