# After a transaction or budget write, the Files tab keeps the old file sha, so deleting that file fails with "sha does not match" until a pull to refresh

**Severity:** minor. **Estimate:** 10–15 minutes. Owner: mobile. A3: the Files tab stays mounted after its first visit (`LazyTabScreen`). Its listing is `cache-and-network` with the global `nextFetchPolicy: "cache-first"`.

Every entry write is a git commit to the target file: add, edit or delete a transaction, save or delete a budget, open an account. Each one changes that file's `sha`, `size` and `lastCommitSha`. But the `entries` invalidation scope doesn't evict `getLedgerDirContent`, so the tab keeps the old rows.

Its delete action sends the cached `entry.sha` as an optimistic lock. Repro:
1. Have an included file such as `extra.bean` that holds a transaction.
2. Open the Files tab.
3. Edit or delete that transaction.
4. Return to Files without pulling to refresh, and delete `extra.bean`.

The delete is refused, and the file stays until a pull to refresh. A file an entry write creates also doesn't appear until a refresh. Backgrounding the app in between hides the bug, because `use-foreground-refresh` refetches.

Environment: `main` at `b63069d2f`. The server half was verified through the GraphQL API on the disposable QA ledger, with a throwaway `qa-20261020-stale.bean`: create, update, then delete with the pre-update sha. The delete returned **`BAD_USER_INPUT` "sha does not match [given: 8f9f…, expected: eeb8…]"**. Deleting with the fresh sha succeeded. The file is gone and `main.bean` is unchanged at `f1a0b83c`. The client half is code-level: the native flow needs an included file holding an entry.

## Root cause

`mobile/src/common/apollo/invalidate-ledger.ts:70-78`: `getLedgerDirContent` is listed only in `FILE_FIELDS`. Its own comment notes the sha is the delete lock. `ENTRIES_FIELDS` (`:~45-68`) omits it. The callers that use the `entries` scope are:
- `use-add-entries-to-remote.ts:28`
- `edit-transaction-screen.tsx:298`
- `transaction-detail-screen.tsx:361`
- `use-save-budget.ts:28`
- `use-delete-budget-entry.ts:57`
- `use-open-account.ts:41`

## Fix

Move `getLedgerDirContent` into `ENTRIES_FIELDS`. It's cheap, and it is the lock token for a destructive action.

**Acceptance:**
- An `invalidate-ledger` unit test where an `entries` invalidation evicts `getLedgerDirContent`.
- Natively: after editing an entry in an included file, deleting that file from the still-mounted Files tab succeeds without a refresh.
