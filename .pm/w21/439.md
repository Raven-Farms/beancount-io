# Regression from w21/316: VoiceOver chart stepping loses its place on any parent re-render (value and header disagree, a month repeats)

**Severity:** minor-to-moderate (accessibility). **Estimate:** 10 minutes. Owner: mobile. A3: `common/d3/interactive-line-chart.tsx:777-780` resets `stepIndex` to null on every new `numbers` array, but leaves the `scrub.value` written by stepping (`:762`) and the 5 s rest timer (`:764`) alone. Both callers rebuild the array on every render (`account-charts-card.tsx:261-271`, `balance-chart-card/index.tsx:94`; the file's own comment at `:587` notes "equal-but-new arrays constantly"). Under `tsx` with the real `stepChartIndex`/`chartPointText`: one decrement moves the cursor and header to index 4; after a re-render, VoiceOver's value reads index 5 (the latest) while the header shows 4, and the next decrement lands on 4 again. On Home the trigger is any refetch, or the header-height growth (`handleHeaderLayout` → `setMeasured`).

Code-level at `main` `0150cff1d`.

## Fix

Reset only when `!sameSeries(previous, numbers)`, as the morph effect does, and in the same place set `scrub.value = SCRUB_IDLE` and clear `stepRest.current`. Or derive the value text from the index the header shows.

**Acceptance:** stepping survives a refetch without repeating or desyncing.
