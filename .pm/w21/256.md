# An account stored in decomposed Unicode (NFD) can't be found by search, and Open Account creates a second, identical-looking "Expenses:Café"

**Severity:** moderate for ledgers imported from systems that write NFD (macOS file names, some bank exports). **Estimate:** 20 minutes. Owner: mobile. A3: since w21/041, `composeAccountName` normalises what the user types to NFC, but the ledger's own names are compared raw, in search and in Open Account's duplicate check. rustledger accepts both spellings as different accounts.

Code-level at `main` `26fb7ee69`. A reviewer ran the real functions under Node, plus `@rustledger/wasm` 0.24.0:
- With `Expenses:Cafe\u0301` in the list, searching `café` or `Café` returns `[]` and shows Create; `caf` finds it.
- `openAccountSubmitState` for the typed `Café` returns `{ alreadyOpen: false, canSubmit: true }`.
- rustledger validates both opens, and a query then returns two distinct `Expenses:Café` rows.

## Root cause

- `mobile/src/common/account-search.ts:87-134`: `fuzzyMatch` and `lowerAligned` don't normalize.
- `mobile/src/screens/open-account-screen/account-name.ts:198`: exact `includes`.
- `closedAccountNamed` (w21/122) does the same.

## Fix

Normalize both sides to NFC in `fuzzyMatch` / `lowerAligned`, `openAccountSubmitState` and `closedAccountNamed`. Report a match as already open using the ledger's own spelling.

**Acceptance:** with an NFD `Expenses:Café`, searching "café" finds it, and Open Account says it's already open. Unit cases cover both.

## Dedupe

w3/278 is the CLI version, and w21/041 the typed-name normalisation. Searched `.pm/**` for NFD, decomposed and normaliz.
