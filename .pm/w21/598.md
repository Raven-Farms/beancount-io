# Latest Updates puts an evening commit (Pacific) above the next day's blog posts, so the dates read out of order

**Severity:** low. **Estimate:** 20 minutes. Owner: backend-v2 and mobile. A3 (code-level at `main` `c9cda71b9`, proven under `TZ=America/Los_Angeles tsx` with the real helpers): `backend-v2/src/features/gitea/feed/service/feed-service.ts:212-213` sorts by instant. Blog posts are stamped at midnight UTC (beancount.io's atom feed, checked live), and mobile shows them as a UTC calendar day (w21/147, `feed-logic.ts` `feedDateIsCalendarDay`; `feed-card.tsx:91-96`). A commit at Oct 21 18:30 PDT (01:30Z on Oct 22) sorts above the Oct 22 posts, so the rows read "… · Ledger · Oct 21, 2026" above "… · Blog · Oct 22, 2026". This affects any commit made between 17:00 and 23:59 Pacific.

Not run natively: the feed card is below Home's fold.

## Fix

Sort blog rows by their calendar day at the end of that day (or sort by the displayed day, then by time), on the server or the client.

**Acceptance:** the rows' displayed dates never go up as you read down. A unit case covers an evening Pacific commit.
