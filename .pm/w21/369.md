# An edit refusal cites file line numbers the editor doesn't show (often the next entry's) and repeats the same parse error

**Severity:** minor. **Estimate:** 20 minutes. Owner: mobile, plus ledger for de-duplication. A3: the server joins each error as `message (file:line)` (`ledger/src/shared/errors/domain-errors.ts:153`). The app shows it unchanged (`mobile/src/common/ledger-refusal.ts:39`, `edit-transaction-screen.tsx:321`), but its editor numbers lines from 1 for the entry. Typing `"Dinner at "Joe's""` on an entry at file line 7 is refused with `parse error: unexpected "J" in transaction header (2024.bean:7); parse error: unexpected input (2024.bean:7)` and two more copies of the second error. A narration ending in a backslash cites `(2024.bean:11)`, the *next* entry. Nothing says the quote needs escaping.

Code-level at `main` `d1ce598bc`; the reviewer ran the real ledger update path in-process. Not run natively.

## Fix

Map the cited line to an editor line using the context's `entry.meta.lineno`, or say "near this entry" when it falls outside. Drop duplicate messages, and add a hint for an unbalanced `"` or a trailing `\`.

**Acceptance:** a bare quote in the middle entry's narration gives one message naming editor line 1 and suggesting `\"`.
