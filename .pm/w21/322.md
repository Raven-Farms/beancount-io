# After w21/160 and w21/162: an exact written price with 9+ decimals shows as "≈" and rounded, and a bare metadata key reads "key: null"

**Severity:** low. **Estimate:** 15 minutes. Owner: mobile (or the ledger for the preferred fix).

Code-level at `main` `3e830700b`, run under Node:
- **Prices (w21/160):** `DERIVED_SCALE = 8` treats any per-unit figure with more than 8 decimals as derived from a total. `@ 1.123456789 USD` shows "@ ≈$1.1235", and `@ 0.000000012` shows "@ ≈$0.000000012", an exact value marked approximate. Precise FX rates and tiny crypto prices are hit. See `select-transaction-detail.ts:157, 170`.
- **Metadata (w21/162):** a bare `key:` line renders "key: null". See `select-transaction-detail.ts:139`.

## Fix

- Have the ledger send the written `@@` / `{{}}` totals (w21/160's optional fix) so derived figures are known, or raise the threshold to about 12 decimals.
- Render a null metadata value as the bare key, or "key: —".

**Acceptance:** `@ 1.123456789 USD` shows exactly, and a bare key shows no "null". Unit cases are added.
