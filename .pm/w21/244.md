# The drawer's ledger filter finds nothing for "my book" or a description word, where Browse ledgers finds the ledger

**Severity:** minor. The filter appears once you have 10 or more ledgers. **Estimate:** 15 minutes. Owner: mobile. A3: the drawer filter is one substring match on `owner/name`, while Browse ledgers splits the query into words and also searches the description. Both fields use the same "Search" placeholder.

Code-level at `main` `4ba42392a`. Run under Node for `qa/my-book` with description "Household budget":

| Query | Drawer | Browse ledgers |
|---|---|---|
| my book | 0 | 1 |
| book my | 0 | 1 |
| qa my-book | 0 | 1 |
| household | 0 | 1 |

"my book" is the likely query, since Create Ledger turns "My Book" into `my-book`.

## Root cause

`mobile/src/components/ledger-drawer/drawer-ledgers.ts:131-136` (`fullName.toLowerCase().includes(needle)`), against `ledger-selection/discovery-store.ts:21`.

## Fix

Reuse Browse ledgers' word-split match in the drawer, treating `-`, `_` and `/` as separators. Searching descriptions there also needs `description` in `LedgerDirectory.graphql`.

**Acceptance:** the four queries above match in the drawer. A unit test covers them.
