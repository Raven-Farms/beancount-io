# The Accounts tab still doesn't show a parent's own postings: graftZeroAccounts' clone drops "balance", so w21/174's "(own)" row is never built there

**Severity:** moderate. This is w21/174's own scenario: Bank's children still don't add up to Bank on the Accounts tab. **Estimate:** 10 minutes. Owner: mobile. A3: w21/174 builds the "(own)" child from each raw node's `balance`. On the Accounts tab, `selectAccountTreeFromRoot` first runs `graftZeroAccounts` (from w21/099) with the ledger's open accounts. Its `clone` copies only `account`, `balance_children` and `children`, so every node's `balance` becomes undefined, `ownValue` is 0, and no own row is created. Reports, which passes no account list, is unaffected.

Reproduced natively on the iPhone 17e simulator (iOS 27.0) at `main` `817c05ae8`, with Metro restarted with `--clear`. The served bundle contains `accountOwnPostings`, and I used 174's original `; qa-20261020-tree` fixture (200 USD posted to `Assets:Bank` itself), restored byte-for-byte to `f1a0b83c`. Accounts → Assets → Bank ($17,202.01) lists **Savings $10,500.00** and **Checking $6,502.01** only, with **no "Bank (own) $200.00"** row.

Production's trial balance does return `Assets:Bank` with `balance: {"USD": "200"}`. Running the real `selectTrialBalanceCategories` on that data under Node gives:
- with an empty account list: `Assets:Bank 200 (own)`.
- with the screen's open-account list: no own row.

## Root cause

`mobile/src/components/account-list/select-account-list.ts:414-418` (`clone` in `graftZeroAccounts`), feeding `toNode`'s `ownValue = raw.balance ? … : 0` at `:140-143`.

## Fix

Copy `balance` (and any other field `toNode` reads) in `clone`. Add a test that runs `selectTrialBalanceCategories` with a non-empty account list and checks the own row.

**Acceptance:** with the tree fixture, the Accounts tab shows "Bank (own) $200.00" under Bank. A unit test with listed accounts covers it.
