# Toasts and most inline errors are silent under iOS VoiceOver, so a save's success or refusal is never announced

**Severity:** moderate. A VoiceOver user can't tell whether Done saved the entry. **Estimate:** 45 minutes. Owner: mobile. A3: every toast renders `accessibilityRole="alert"` with `accessibilityLiveRegion="polite"` (`src/common/providers/toast-provider/index.tsx:58-63`). On iOS, React Native maps `"alert"` to `UIAccessibilityTraitNone` (`React/Views/RCTViewManager.m:31`), and `accessibilityLiveRegion` is documented as Android-only. `AccessibilityInfo.announceForAccessibility` is called in exactly one place, New Transaction's pre-save check (`multi-postings-transaction-screen.tsx:617`).

`runLedgerWrite` (`src/common/ledger-write.ts:119, 138`) reports both success and refusal only through a toast: add, edit and delete transaction, and Open Account. Copied, Profile updated, Files create/delete and Referral copy are toast-only too.

Inline errors carry only the Android prop:
- New Transaction's save error (`multi-postings…:830-846`)
- Open Account's errors (`open-account-screen.tsx:445, 450-454, 513`)
- the text-input modal (`components/text-input-modal/index.tsx:242-249`)
- Add Budget's invalid amount (`add-budget-screen.tsx:370-377`)

Add Budget's submit error (`:380`) and Edit Transaction's save error (`edit-transaction-screen.tsx:475`) have nothing.

Code-level at `main` `5a4e27da4` against React Native 0.86 (Fabric) sources in `mobile/node_modules`. Not exercised with VoiceOver, which this simulator setup can't drive.

## Fix

On iOS, have the toast provider call `AccessibilityInfo.announceForAccessibility` when a toast shows. Add one `InlineError` component that announces on iOS and keeps the live region on Android, and use it at every site above. Add a guard test so that a live region without an iOS announcement fails.

**Acceptance:** with VoiceOver on iOS, saving a transaction announces success, and a refused save announces its message.
