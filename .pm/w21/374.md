# The account picker hides a not-yet-open account but then offers "Create" for it, which dead-ends at "already open in this ledger"

**Severity:** minor. **Estimate:** 15 minutes. Owner: mobile. A3: since w21/229, `openOn` hides an account whose open date is after the entry's date. But `account-picker-screen.tsx` treats a search for it like an unknown name: "No matching accounts" plus **Create "Assets:QaFutureBank"**. Create opens Open Account prefilled, which then says **"Assets:QaFutureBank is already open in this ledger."** with Done disabled. Nothing ever says the account opens on a later date, or that the entry date is the obstacle. Closed accounts already get an explanatory row (`account-picker-closed-row`).

**Natively confirmed (2026-10-21, iPhone 17e, `main` `ebb642e45`):**
1. I appended `2026-11-01 open Assets:QaFutureBank USD` to the disposable QA ledger.
2. New Transaction (dated 2026-10-21) → posting account → search `Assets:QaFutureBank` showed "No matching accounts · Create "Assets:QaFutureBank"".
3. Tapping Create showed Open Account's "already open" error.

The ledger was restored to `f1a0b83c`.

## Fix

Mirror the closed-account row: when the query matches an account that opens after the entry date, show a non-tappable row such as "Assets:QaFutureBank opens on 2026-11-01. Change the date to use it.", and don't offer Create for an existing name.

**Acceptance:** that search shows the opens-on row and no Create row.
