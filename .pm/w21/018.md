# Home's Spending chart gives VoiceOver axis ticks but never the two amounts it compares

**Severity:** minor (accessibility). **Estimate:** 20–30 minutes. Owner: mobile. A2: "This month vs. last month" is a two-number comparison drawn as two bars. A VoiceOver user hears the y-axis ticks and the "Last month" / "This month" captions, but not the numbers. That is the case `mobile/AGENTS.md` rules out: "Charts need a summarizing `accessibilityLabel` instead of exposing SVG nodes."

Environment: `main` at `4e260b554`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). `automation_find_view("spending-card")` returns an empty `label`. The other Home and Reports charts carry summaries (Budget per w3/124, Cash flow per w4/054, balance charts).

## Root cause

- `mobile/src/common/d3/bar-chart-d3.tsx:30-102` renders a plain `<View><Svg>…<SvgText>…` with no `accessible` container and no `accessibilityLabel` prop. Its only caller is `mobile/src/screens/home-screen/components/spending-card.tsx:115-119`.
- Control: `budget-bar-chart-d3.tsx` requires an `accessibilityLabel` and passes it to `ScrollableAxisChart`, which wraps the plot in `<View accessible accessibilityLabel=…>` (`scrollable-axis-chart.tsx:68`).

## Fix

Give `BarChartD3` a required `accessibilityLabel` and wrap its SVG in an `accessible` view that carries it, mirroring `BudgetBarChartD3`. In `SpendingCard`, pass a translated summary such as "Spending: last month $100.00, this month $205.00", built with `formatMoneyWithCurrency` and the card's currency (for example a new `spendingChartSummary` key in all locales). Keep the empty and failure states as they are.

**Acceptance:** `automation_find_view("spending-card")` (or an a11y snapshot) exposes one element whose label names both months and amounts. The axis tick texts are no longer separate VoiceOver stops. A unit test renders the card with known values and asserts the label. The accessibility-labels guardrail passes.
