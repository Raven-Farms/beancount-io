# New Transaction shows a green "✓ $0.00" remainder for an amount it refused to parse

**Severity:** minor. **Estimate:** 20–30 minutes. Owner: mobile. A2: entering `1,234.56`, a common thousands-grouped amount, is refused by the exact-decimal parser from w3/m34, which is correct. But the screen says nothing: the amount greys out, the automatic posting stays 0.00, and the Remainder row shows a green **✓ $0.00**, which reads as "balanced". Done stays disabled with no reason given. w3/m34's DoD listed exactly this as a requirement: "Invalid/incomplete/unsafe values cannot produce … a misleading green balance state."

Environment: `main` at `44f81a3c3`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). Nothing was saved.

## Repro

1. Home → **+** → **Enter new transaction**.
2. In the first posting's amount, enter `1,234.56`.
3. The amount shows `1,234.56` in grey, the auto posting stays `0.00`, Remainder shows **✓ $0.00** in green, and Done is disabled. There is no message. `1,25` (decimal comma) works as documented.

## Root cause

- `mobile/src/screens/multi-postings-transaction/postings-utils.ts:32-54` (`parseExactAmount`) returns `null` for grouping commas, as designed.
- `validatePostings` (lines 315-323) returns `invalidAmount`, so `canSave` is false. But `remainder(postings)` ignores unparsed postings, so the Remainder row (`isRemainderBalanced`) shows green ✓ zero. The only `invalidAmount` feedback is a toast on Done (`multi-postings-transaction-screen.tsx:536-542`), and since Done is disabled the user never gets it, and the toast's copy is the generic "invalid balance".

## Fix

When `validationError === "invalidAmount"`:

- give that posting's amount field an error state (red text or underline, `accessibilityHint` with the reason), and
- render the Remainder row neutral, not green ✓, with an inline message such as "Use digits and one decimal point (1234.56)".

Optionally accept grouping commas when the shape is unambiguous (`^\d{1,3}(,\d{3})+(\.\d+)?$`), as w5/213 did for the CLI. Keep `1,25` as a decimal comma.

**Acceptance:** entering `1,234.56` shows the field error and a neutral remainder with the message, and Done stays disabled. Correcting the amount to `1234.56` clears the error and balances the auto posting. Unit tests cover the remainder state and message for an unparsed posting, plus the grouping case if it is accepted.

## Dedupe

Residual of w3/m34 (done), whose DoD forbade the green state for invalid input. w5/213 accepted comma grouping in the CLI. Searched `.pm/**` for grouping comma, `1,234` and invalid amount on mobile. No open item.
