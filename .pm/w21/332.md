# Budget ALL still counts a pre-entered entry inside the current period, so ALL reads $300 spent while YTD reads $0 (w21/168 follow-up)

**Severity:** minor-to-moderate. It breaks 168's acceptance ("ALL's headers match YTD's"). **Estimate:** 20 minutes. Owner: mobile. A3: w21/168 trims ALL at the *end of the period* containing today, not at today. Without a window the ledger builds whole periods, so a future entry inside the current month, quarter or year stays in ALL, while YTD and Home end at today on the server.

Code-level at `main` `61ad1916c`. A reviewer ran `throughCurrentPeriod` and the ledger's `intervalTotals` under Node on a quarterly insurance budget with 300 USD on 04-15, 07-15 and a pre-entered 11-15, today 2026-10-21. ALL's last point is `2026-12-31 {USD: 300}` (Above target), while YTD's is `2026-10-21 {}`. A monthly budget with an entry pre-entered for 30 October behaves the same.

## Root cause

`mobile/src/screens/budget-screen/selectors/budget-selectors.ts:298-305` (`throughCurrentPeriod`) and `hooks/use-budget-actuals.ts:73-77`.

## Fix

Send ALL a time window ending today, so the server clips the current period as it does for YTD, or re-query the current period up to today.

**Acceptance:** with the fixture, ALL and YTD show the same current-period actual. A unit case covers it.
