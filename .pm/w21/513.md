# Home's Recent Transactions can't use its offline cache on a later day: the query's date window changes daily (w21/471 regression)

**Severity:** low. **Estimate:** 15 minutes. Owner: mobile. A3 (code-level at `main` `a06f559aa`): `recent-transactions-card.tsx:66` passes `time: recentTransactionsWindow(today)` (`0001-01-01 - <today>`). The variables, and so the Apollo cache key, change every day, so the cache persisted for offline use (w21/006) has no entry on the next day. `use-budget-panel.ts` avoids this on purpose with a month-wide window (w21/184).

Scenario: open Home online, then kill the app. The next day, cold-start offline. The other cards show their cached data, but Recent Transactions shows "Couldn't load".

Not run natively (it needs a day change and an offline cold start).

## Fix

Use a window that only changes rarely (for example through the end of the current month, then filter out future rows on the client), or read the last cached result when the key misses.

**Acceptance:** an offline cold start on a later day shows the last cached recent rows, with no future-dated entries. A unit test covers it.

Regression of w21/471; see w21/006 and w21/184. Searched `.pm/**` for recentTransactionsWindow and "Recent Transactions" together with offline.
