# A merchant whose name contains `"` opens with no header: the BQL escape `\"` is a syntax error on the rustledger engine

**Severity:** minor. **Estimate:** 30–45 minutes. Owner: mobile. A2: payees like `The "Corner" Shop` or `12" Sub Co` are ordinary bank-import text. Their merchant detail loads the transaction rows but silently drops the whole header: count, total, date range and the Recurring toggle. The toggle is the only way to mark a merchant recurring.

Environment: `main` at `e48090a3b`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). QA account, synthetic disposable ledger `mcp-agent-eval`, with two `qa O'Reilly "Q" Café` entries added and then restored byte-for-byte.

## Repro

1. Add entries with payee `qa O'Reilly "Q" Café` (written in the file as `"qa O'Reilly \"Q\" Café"`). `getLedgerErrors` stays empty.
2. Drawer → **Merchants**. The payee is listed with "2 transactions · Aug 31, 2026".
3. Tap it. The screen shows only the two transaction rows. There is no header (name, count, −$5.00 total, date range) and no Recurring toggle, even after more than 10 s. Control: ACME CORP shows the full header.

API control (`queryShell` on the same ledger):

| literal sent | result |
| --- | --- |
| `payee = "qa O'Reilly \"Q\" Café"` (what `escapeBqlString` produces) | **syntax error** at the `\"` |
| `payee = "Lowe's"` (apostrophe only, `open_ledger/real-estate-example`) | 1 row (works) |
| `payee = 'qa O''Reilly "Q" Café'` | parses, **0** rows (no `''` escape) |
| `payee ~ "^qa O'Reilly \x22Q\x22 Café$"` | **2** rows |

## Root cause

`mobile/src/screens/merchant-detail-screen/selectors/escape-bql-string.ts` emits `"…\"…"` and documents `\"` as supported ("validated 2026-08-20 against live `queryShell`"), which was before the ledger service moved to the rustledger WASM engine (`@rustledger/wasm` 0.24.0). That engine's BQL string literal has no `\"` escape. `buildMerchantMetaBql` and `buildMerchantCurrencyTotalsBql` (`selectors/merchant-stats.ts:35-56`) both fail, and the screen renders without the header rather than an error.

## Fix

Build the payee predicate as an anchored regex, escaping regex metacharacters and encoding `"` as `\x22` (and `\` as `\x5c`), which is the approach `transactions-screen/utils/plain-search-filter.ts` already uses: `payee ~ "^<escaped>$"`. Use it for both header queries. Separately, when either header query errors, show the screen's retryable failure state instead of silently omitting the header. Update the escaper's docstring to the engine's actual grammar, and add a unit test with a payee containing `"`, `'` and `\`.

**Acceptance:** the repro shows the header (2 transactions, −$5.00, Aug 31, 2026, Recurring toggle). `Lowe's` and `Ethereum 2.0` (w3/112's controls) still work. A forced query error shows a retry, not a headerless screen.

## Dedupe

w3/112 (done) fixed the merchant detail **journal** filter for punctuation (`Ethereum 2.0`, `Lowe's`). Its header queries worked then because apostrophes need no escape. Neither it nor w3/155 covered `"` in a payee. Searched `.pm/**` for escapeBqlString, quoted payee and rustledger string literal.
