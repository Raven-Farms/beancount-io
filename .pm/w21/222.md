# Files' New File check doesn't catch an existing file inside a folder, so the dialog closes and the create fails

**Severity:** minor. **Estimate:** 20 minutes. Owner: mobile. A3: w21/014 let New File accept folder paths. The "already exists" check still compares the folder-qualified name against the current folder's bare names, so `sub/notes` passes even when `sub/notes.bean` exists. Create stays enabled, the dialog closes and the typed name is lost, and the server then refuses to create over the existing file with an error toast.

Code-level at `main` `9e6f6c9ba`. A reviewer ran `checkLedgerFileName` under Node from `mobile/`: at the root, with entries `["main.bean", "sub"]`, the input `sub/notes` returns `{ ok: true, filename: "sub/notes.bean" }`, while `main` is correctly refused. Not exercised natively; it would create a file in the shared QA ledger.

## Root cause

`mobile/src/screens/ledger-file-browser-screen/index.tsx:374` and `:395` pass `entries.map((entry) => entry.name)`, the current folder only. `checkLedgerFileName` (`utils.ts:40-42`) compares the joined `filename` against that list.

## Fix

For a name that contains `/`, look up the target folder's listing (`getLedgerDirContent`), or keep the dialog open and show the server's conflict inline when the create fails. A bare name keeps the current-folder check.

**Acceptance:** typing `sub/notes` at the root, when `sub/notes.bean` exists, shows "already exists" before submitting, or keeps the dialog open with that message. A unit case covers it.

## Dedupe

w21/014 (done) added folder paths, and its acceptance covered only the current folder. w21/088 and w21/142 are other Files issues. Searched `.pm/**` for checkLedgerFileName, existingNames, "already exists" and New File.
