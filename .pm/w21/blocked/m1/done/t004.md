## Objective

The changed write contract is discoverable and accurate everywhere an API client, agent or app user meets it.

## Steps

1. Check that the REST v1 docs, MCP tool descriptions (`backend-cluster/backend-v2/docs/mcp.md`) and the API parity notes describe the refusal and `allowInvalid` for edits and deletes.
2. Check that the customer skills that edit or delete entries (`skills/`) still tell agents what to do on a refusal. Flag any drift as follow-up work.
3. Confirm the guidance reads the same for Claude Code and Codex.
