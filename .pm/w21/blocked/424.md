# Mobile does not show the ledger service's fix hints, now that GraphQL returns code and hint

**Severity:** minor. **Estimate:** 20 minutes. Owner: mobile. Split from w21/311, whose backend half shipped: GraphQL `getLedgerErrors` returns nullable `code` and `hint`, matching REST and MCP.

Mobile's `getLedgerErrors` query selects only `filename`, `lineno` and `message`, so Notifications and the editor banner never show hints such as `TS_PLUGIN_SKIPPED`'s "Did you mean \"fava.plugins.…\"?" and `INVALID_UTF8`'s "Re-save the file as UTF-8…".

## Fix

Add `code` and `hint` to `common/graphql/queries/getLedgerErrors.graphql`, regenerate the client, and show the hint under the message in `notifications-screen.tsx` and the editor's `ErrorBanner`. Keep the row's accessibility label reading the hint.

**Acceptance:** a ledger error that carries a hint shows it under the message in Notifications and in the editor banner. A source or unit check covers the query fields and both renders.

## Dedupe

w21/311 is the backend half (done). w21/188 added `severity` to the same type and has the same deploy dependency. Searched `.pm/**` for `getLedgerErrors` and hint.
