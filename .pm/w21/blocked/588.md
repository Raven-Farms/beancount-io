# New File creates a file nothing includes, so entries typed into it never count, and Files doesn't show which files the ledger reads

**Severity:** minor (a user's entries silently don't count). **Estimate:** 30 minutes, needs a product call. Owner: mobile and backend-v2. A3: `ledger-file-browser-screen/index.tsx:476-561` (`handleCreate`) and the dialog text (`translations/en.ts:562-563`) say nothing about includes, and `createLedgerFile` (`ledger-workflow.ts:~902-925`) adds no include line. An orphan file produces no errors, so a transaction typed into a new `investments.bean` never appears in Home, Accounts or Reports, with no warning.

Native (iPhone 17e at `b1ba52fcd`, disposable ledger; the files were deleted afterwards and the ledger is identical to its snapshot): two files created next to `main.bean` (`qa-2.bean`, `qa-10.bean`) list in Files exactly like included ones, with no sign that the ledger doesn't read them.

## Fix

Offer to add `include "<path>"` to `main.bean` when creating a file (default on), and mark files the ledger doesn't read in Files ("Not included").

**Acceptance:** a new file is included (or clearly marked as not), and an entry saved into it counts. Tests cover the include offer and the marker.

---

**Blocked 2026-10-22** — Still wanted, but the note says it needs a product call and it changes what creating a file does. Adding an `include` line to `main.bean` makes New File a two-file write (the new file and the entry point) with its own failure and conflict cases, and an agent or CLI that creates a file through REST, GraphQL or MCP would either keep creating orphans or start editing `main.bean`, so the surfaces have to agree. The "Not included" marker needs the set of files the ledger reads, which no list read returns today (rename and the include loader know it server-side).

**Unblock:** the owner decides whether creating a file includes it (in the app only, or on every surface), whether the dialog asks, and whether Files marks files the ledger does not read (which needs a read that returns them); then it is a mobile change plus, for the surface-wide choices, a ledger and backend-v2 change with parity cases and a deploy. Who can clear it: the repository owner (product decision).
