# BQL queries still return the padded balance after w21/135, so query results disagree with the journal and trial balance

**Severity:** moderate. **Estimate:** 30 minutes. Owner: ledger. A3: `dropPaddingWithinTolerance` runs only inside `parseLedgerFilesUncached`. BQL goes through `queryLedgerFilesResultInProcess`, which hands the raw files to `Ledger.fromFiles`, and that pads any non-zero difference. Callers include the shell service and mobile's BQL-backed data (Merchants, budget actuals).

Code-level at `main` `3e830700b`. A reviewer ran `@rustledger/wasm` 0.24.0 on 135's fixture (+100, a 2.00 lunch, a pad, `balance Assets:Cash 100.00 ~ 5.00 USD`). The snapshot has no padding row and raises E2003, but `SELECT sum(position) WHERE account='Assets:Cash'` returns 100.00 USD instead of 98.00. Not deployed yet in production either (see w21/135).

## Root cause

`backend-cluster/ledger/src/foundation/rustledger/engine.ts:628-637` (the parse path) against `:702-722` (the BQL path), with callers at `ledger-shell-service.ts:93, 109`.

## Fix

When padding was dropped, run BQL over the materialized directive stream (`materializeDirectiveStreamWithSourceMap` with `omitPadDirectives`), as the Fava-plugin path already does.

**Acceptance:** on 135's fixture, the BQL sum is 98.00 USD, matching the journal. Unit tests are added.
