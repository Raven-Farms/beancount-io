# Creating a file that already exists now shows a generic "Couldn't create" (or a bodiless "Save failed") on mobile: the server's new `CONFLICT` isn't passed through (w23/032 regression)

**Severity:** minor. **Estimate:** 15 minutes. Owner: mobile. A3: since `ecdaa6224` (w23/032), the ledger service answers Gitea's "repository file already exists" with 409, and GraphQL returns `CONFLICT` (it used to be `BAD_USER_INPUT`). `mobile/src/common/ledger-refusal.ts:130` passes server text only for `VALIDATION_FAILED`, `BAD_USER_INPUT` and `UNBALANCED`, so the file browser shows the generic `ledgerCreateFileFailed` toast (`ledger-file-browser-screen/index.tsx:562-567`). By then the dialog has closed (`:526`) and the typed name is lost. The editor's Recreate (`ledger-file-editor-screen/index.tsx:706-712`) shows "Save failed" with no body.

Production (2026-10-22, disposable ledger; nothing written): `createLedgerFile(path: "main.bean")` returns `CONFLICT` "Ledger resource conflict: main.bean already exists; update it with its sha, or choose another path". Mobile reaches this when its file list is stale (another device created the file) or on Recreate after someone else recreated it.

## Fix

Map `CONFLICT` on file create to `ledgerFileNameExists` (keep the dialog open with the name), and to the changed-elsewhere refresh in the editor's Recreate.

**Acceptance:** a stale-list create of an existing name shows "A file named notes.bean already exists" with the dialog still open, and Recreate explains the conflict. Unit cases are added.
