# Files between 1 and 10 MiB open as editable, but every save is refused after the user has edited

**Severity:** moderate. A long-lived `main.bean` grows past 1 MiB naturally (transaction appends have no cap). Fixing a typo in the editor then fails with "Save failed — File content must be at most 1 MiB (1048576 bytes); received N bytes" in English. Above about 1.5 MiB the request body exceeds the 2 MB parser limit, and the failure is a raw HTTP 413 (inferred). **Estimate:** 20 minutes. Owner: mobile. A3: the editor is writable unless the content is non-UTF-8 and never checks `size` against the 1 MiB explicit-write cap enforced by backend-v2.

Code-level at `main` `36d9fbf59`.

## Where

- `mobile/src/screens/ledger-file-editor-screen/index.tsx:349-350` (writability) and `:553-554` (raw failure text)
- `backend-cluster/backend-v2/src/features/ledger/utils/explicit-file-size.ts:3-20` (the 1 MiB cap)
- `backend-cluster/backend-v2/src/server/middleware/body-parser-middleware.ts:30` (2 MB body limit)
- The uncapped append path is `ledger-repo-service.ts:260`.

## Fix

When `size` is over 1 MiB, open read-only with a translated notice ("Too large to edit on mobile; edit on the web or with the CLI"). Map the server's size error to that notice too. Same `size` check as w21/185.

**Acceptance:** a 1.3 MB file opens read-only with the notice, and no edit-then-fail cycle happens.
