# Budget "1Y" builds the invalid window `2023-02-29 - 2024-02-29` on leap days, so the view fails every 29 February

**Severity:** minor (fails one day in four years, then always on that day). **Estimate:** 10–15 minutes. Owner: mobile. A2: Budget → **1Y** asks the server for "the same calendar date one year back through today". On 29 February the start becomes 29 February of a non-leap year. The server's Fava-style range parser rejects it, so the 1Y view errors all day. The next occurrence is 2028-02-29.

Environment: `main` at `e8a876d13`. Code-level: verified by running the shipped `timeSpanToFilter` and the ledger service's own `parseDateRange` under Node (TZ=UTC and America/Los_Angeles). This can't be reproduced on the simulator today, because it follows the host clock.

## Evidence

- `timeSpanToFilter("last-12m", "2024-02-29")` → `"2023-02-29 - 2024-02-29"`.
- `backend-cluster/ledger/src/foundation/rustledger/directive-filter.ts` `parseDateRange("2023-02-29 - 2024-02-29")` → `undefined`. `applyTimeFilter` then throws `TimeFilterParseError`, which the Budget screen shows as a load error.
- Controls: `2026-10-21` → `2025-10-21 - 2026-10-21` (fine). The dashboard's `subYears(now, 1)` clamps to `2023-02-28`.

## Root cause

`mobile/src/screens/budget-screen/selectors/budget-labels.ts:110-117`: `start: \`${year - 1}${today.slice(4)}\`` swaps the year in the string without clamping the day to the target month's length.

## Fix

Compute the start with real date arithmetic, clamping 29 Feb to 28 Feb in a non-leap year (the `monthsBack` clamp in `select-filter-query.ts` shows the pattern). Add a unit test for 2024-02-29 and a control date.

**Acceptance:** `timeSpanToFilter("last-12m","2024-02-29")` is `"2023-02-28 - 2024-02-29"`, and the server parses it.

## Adjacent observation (harness-only, verify before acting)

The same review found that a window's first, partial period is budgeted in full. With 1Y on 2026-10-21, the server's first monthly bucket counts actuals only for 21–31 Oct 2025, but `budgetForInterval` prorates from the calendar month start (`use-budget-actuals.ts:73-79` → `budget-selectors.ts:~361`). The first bar is set against a full $310 target instead of about $110. This was demonstrated only in a Node harness.
