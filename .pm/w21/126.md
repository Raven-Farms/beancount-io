# A fresh install ignores the device language and starts in English; on a Persian device it shows English text in a mirrored RTL layout that Settings can't undo

**Severity:** major for non-English users' first run. **Estimate:** 30 minutes. Owner: mobile. A3: `translations/index.ts` sets `i18n.locale = getLocale()` from the device. `localeVar` is a persistent var that defaults to `"en"`, and `loadLocale()` returns null on a fresh install, so the splash doesn't call `setLocale`. The first `useTranslations()` call then sees `i18n.locale ("de") !== localeVar ("en")` and forces `i18n.locale = "en"`. Only the Settings picker ever writes `localeVar`. So w4/063's `CFBundleLocalizations` fix can never take effect.

Code-level at `main` `c26bdfe94`. Not exercised natively: it needs the simulator's `AppleLanguages` changed and the app's persisted `locale` key removed from AsyncStorage.

## Persian is worse

- The splash runs `applyLayoutDirection(locale ?? i18n.locale)` with `"fa"`, forces RTL and reloads. The app then renders English text in a mirrored layout.
- Settings shows "English", and choosing English does nothing, because `changeTo === locale` returns early. The user can't get back to LTR without picking another language first.

## Where (`mobile/src/`)

- `common/hooks/use-translations.ts:9-14`
- `common/vars/locale.ts:3-6` (default `"en"`)
- `translations/index.ts:65`
- `common/providers/splash-provider/splash-provider.tsx:86,102`
- `screens/setting/main-content.tsx:236-238` (the early return)

## Fix

When `loadLocale()` returns null, seed `localeVar` with the device-derived `i18n.locale`. Pick the closest supported language, falling back to `en`, and don't persist it until the user chooses. Alternatively, default the var from `getLocale()`.

**Acceptance:**
- With `AppleLanguages` set to `de en` and no saved `locale`, first launch is German and Settings shows "Deutsch".
- With `fa`, first launch is Persian in RTL.
- A saved choice still wins.
- Add a unit test for the init path.
