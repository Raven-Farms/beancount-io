# Android: after granting camera access in Settings, the receipt screen still says "Camera access is needed"

**Severity:** minor-to-moderate (Android). **Estimate:** 10 minutes. Owner: mobile. A3: CameraView ignores `useCameraPermissions()`'s refresh function, and the hook reads the permission only on mount. Android doesn't restart the app when access is granted, so the stale denied state stays until the user cancels and reopens Scan Receipt. On Android after the first denial, the "Open Settings" button shows the system prompt instead.

Code-level at `main` `c612cae39`.

## Root cause

`mobile/src/screens/receipt-capture-screen/camera-view.tsx:95` (the third return value is unused) and `:172-176` (Open Settings).

## Fix

Re-run `getPermission()` on AppState `active` (or on screen focus). Label the button by what it does ("Allow camera" when it can ask again, "Open Settings" otherwise).

**Acceptance:** after granting in Settings and returning, the camera appears. A unit or source check covers the AppState refresh.

## Dedupe

w21/017 (camera denied with no library option) and w3/168 (photo picker permission) are different. Searched `.pm/**` for useCameraPermissions, getPermission and "return from Settings".
