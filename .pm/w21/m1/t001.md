## Objective

Before committing, `updateSourceSlice`, `deleteSourceSlice` and `deleteMultiSourceSlices` project the transformed files and refuse with `NewLedgerErrorsError` when the write adds a bean-check error, unless the caller passes `allowInvalid`.

## Context

- `backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts:788,835,904` commit through `commitTransforms` (line 486) with no projection.
- The pattern to follow is `backend-cluster/ledger/src/api/entries.ts:223-247`: `checkProjectedErrors` on the overlays, then `getErrors` only when the projection has errors, then `newLedgerErrors(before, after)`.
- REST handlers: `backend-cluster/ledger/src/api/journal.ts:115-180`.

## Steps

1. Build the post-transform content for each touched file and run `checkProjectedErrors` with it as overlays.
2. Throw `NewLedgerErrorsError(introduced)` when new errors appear. Pre-existing errors don't block.
3. Accept `allowInvalid` in the service params and in the three REST bodies.

## Files

- backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts
- backend-cluster/ledger/src/api/journal.ts

## Acceptance criteria

- [ ] Deleting, or re-dating past a balance assertion, an entry that the assertion depends on is refused, and the ledger file is unchanged.
- [ ] The same calls with `allowInvalid: true` commit.
- [ ] A stale `sha256sum` still fails as before. An edit that fixes an existing error commits.
