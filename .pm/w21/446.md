# File editor: a failed load says "Failed to load file" with no Retry, and a failed Copy & Reload fails silently while keeping the stale sha

**Severity:** minor. **Estimate:** 20 minutes. Owner: mobile. A3: two load-failure paths in `mobile/src/screens/ledger-file-editor-screen/index.tsx` give the user no way forward.

- **No Retry on load failure.** The `error` branch (`:885-890`) renders only the text "Failed to load file". The `unavailable` branch below it has Reload and Back to Files buttons. The query is `network-only` (`:406`), with no polling and no pull-to-refresh, so coming back online changes nothing. Only leaving and reopening the file, or a foreground refresh, retries. The reviewer's tsx run of `selectLedgerFileEditorState({loading:false, hasError:true, hasData:false, …})` returns `"error"`.
- **Copy & Reload swallows a failed reload.** `handleReload` (`:506-511`) awaits `refetch()` with no try/catch. `copyThenReload` (`:550-563`) plays the success haptic first, and the conflict alert calls it as `void copyThenReload(content)`. A reload that fails on a flaky network shows nothing, leaves an unhandled rejection, and keeps the stale sha, so every later Save conflicts again.

Code-level at `main` `1e9f0fc30`; not exercised on the device. The network can't be toggled from the simulator driver.

## Fix

Give the error branch the unavailable state's Reload button (or `CardLoadFailure` with Retry). Catch inside `handleReload`, show `ledgerEditorLoadFailed`, and keep the buffer.

**Acceptance:** an offline open shows a Retry that loads the file once online. A rejected reload after Copy & Reload shows an error and leaves the text in place. Unit or source-wiring tests are added.
