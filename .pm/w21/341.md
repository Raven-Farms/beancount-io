# The file editor's text ignores the system text size on iOS (fixed 14 px, pinch-zoom disabled), including at AX2

**Severity:** minor (accessibility). It reproduces at AX2, within `.pm/DO_NOT_DO.md`'s ceiling. **Estimate:** 20 minutes. Owner: mobile. A3: the editor hard-codes `fontSize: "14px"` for the code and the gutter, and no `fontScale` reaches it. WKWebView doesn't apply Dynamic Type to px sizes, and Expo's DOM page template sets `user-scalable=no`. At AX2, where native body text is about 33 pt, ledger source stays at 14 px with no way to enlarge it.

Code-level at `main` `57826d105`: `mobile/src/components/code-editor/code-editor.tsx:94-100`, and `node_modules/@expo/cli/build/src/start/server/middleware/DomComponentsMiddleware.js:113`. Consistent with this session's AX2 screenshots, where the editor text didn't grow; that wasn't measured.

## Fix

Pass `useWindowDimensions().fontScale` as a prop and scale the editor font (and gutter) through a compartment, as the theme already is, with a sensible cap.

**Acceptance:** at AX2, the editor text is visibly larger than at the default size. A source check covers the prop.
