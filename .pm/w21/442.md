# On Android, a reinstall never sets the account-choice mark, so Sign In can still offer the previous account's one-tap Approve (w21/318's platform sibling)

**Severity:** low (speculative; inferred from platform behaviour, not reproduced). **Estimate:** 10 minutes. Owner: mobile. A3: `common/vars/session.ts:45-51` sets `markAccountChoiceNeeded()` only when SecureStore finds a session left by a previous install (called from `splash-provider.tsx:68-69`). On Android, Keystore-backed SecureStore data does not survive an uninstall, so `stored === null` and the mark is never set, yet Custom Tabs cookies do survive. Android's auto-backup can also restore AsyncStorage, so the install marker reads "known" and the path never runs.

Code-level at `main` `0150cff1d`.

## Fix

Call `markAccountChoiceNeeded()` on every `"fresh-install"`, not only when a stored session was found.

**Acceptance:** the first Sign In after an Android reinstall requests account selection.
