# Saving a file that was deleted elsewhere is a dead end: a bare "Failed to save" with no reason, no Reload and no way to keep the draft

**Severity:** moderate. The draft is stuck, and leaving discards it. **Estimate:** 30 minutes. Owner: mobile. A3: `ledger-file-editor-screen/index.tsx:597-617` routes only `isConflictError` (a text match on "sha", "conflict" or "409") to Reload. Everything else becomes `Alert.alert(t("ledgerEditorSaveFailed"), ledgerWriteFailureMessage(...) ?? undefined)`. When the file was deleted on the web or with the CLI, Gitea refuses the update, and backend-v2 (`foundation/fava/unwrap-response.ts`) maps a 404 to `NotFoundError("Ledger resource")` and a 5xx to `ServiceUnavailableError`. Under `tsx`, both give `isConflictError` false and `ledgerWriteFailureMessage` null, so the alert has no body. `shaRef` still holds the dead sha, so every retry fails the same way.

Code-level at `main` `4e51c752c`. Not run natively, because the disposable ledger's only file is `main.bean`.

## Fix

Classify NOT_FOUND on save with `isLedgerGone(err)`. Say the file was deleted elsewhere, and offer to re-create it at the same path with the buffer (`createLedgerFile`) or to copy the buffer. Add unit cases for NOT_FOUND and 5xx.

**Acceptance:** after the file is deleted elsewhere, Save explains that and offers re-create or copy, and the draft is never lost silently.
