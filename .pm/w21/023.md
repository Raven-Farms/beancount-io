# Picking a known payee in New Transaction doesn't bring its usual accounts, a capability lost when multi-posting became the default

**Severity:** minor (regression in entry speed). **Estimate:** 45–60 minutes. Owner: mobile. A2: the most common entry is a repeat ("TRADER JOES again"). The keypad flow that was the default until `9c240d2ee` (2026-07-22) prefilled a known payee's accounts through `usePayeeAccountSuggestions` / `useTwoPostingSuggestions`. The multi-posting form that replaced it keeps whatever default accounts it opened with, so every repeat entry needs two extra account picks.

Environment: `main` at `e9942a252`, dev build `io.beancount.ios` 1.20261002.50 on iPhone 17e (iOS 27.0). QA account, synthetic ledger `mcp-agent-eval`. Nothing was saved.

## Repro

1. Home → **+** → **Enter new transaction**. The postings default to `Assets:Bank:Checking` / `Expenses:Food:Groceries`.
2. **Payee** → pick **TRADER JOES** from Suggestions. Both of its transactions are `Liabilities:CreditCard:Visa` → `Expenses:Food:Groceries`.
3. Back on the form, the payee reads TRADER JOES, but the first posting is still **Assets:Bank:Checking**.

Control: CITY BUS (always `Assets:Cash` → `Expenses:Transport`) behaves the same way, so no payee changes the accounts.

## Root cause

- The live route `app/(app)/add-transaction.tsx` renders `MultiPostingsTransactionScreen`. Its payee row (`multi-postings-transaction-screen.tsx:637-647`) only sets `payee`.
- The suggestion hooks (`src/screens/add-transaction-screen/hooks/use-payee-account-suggestions.ts`, `use-two-posting-suggestions.ts`) are imported only by the parked `add-transaction-next-screen.tsx` and `quick-add-accounts-selector.tsx` (w4/033 recorded those routes as parked).

## Fix

When a payee is chosen and the user hasn't touched the postings yet (`initialDraft` postings unchanged), look up that payee's most recent two-posting transaction (reuse `twoPostingPayees` / the journal query the payee screen already runs) and seed the source and target accounts from it, leaving amounts empty. Don't override postings the user already edited. Offer this only for two-posting history, so mixed splits don't seed partial accounts.

**Acceptance:** picking TRADER JOES seeds `Liabilities:CreditCard:Visa` / `Expenses:Food:Groceries`. Picking CITY BUS seeds `Assets:Cash` / `Expenses:Transport`. Picking a payee after changing an account leaves the accounts alone. A typed new payee leaves the defaults. Unit tests cover the seeding rule; no change to the parked routes is required.
