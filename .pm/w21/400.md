# Searching a check or order number ("#1042") finds nothing: a lone #-token is sent only as a tag filter (regression from w21/025)

**Severity:** moderate. Narrations like "Check #1042" and "Order #112-…" are common. **Estimate:** 10 minutes. Owner: mobile. A3: `transactions-screen/utils/plain-search-filter.ts:12, 29` sends any lone `#…` or `^…` token unquoted, as a Fava tag or link filter only. Under `tsx`, `#112-3456789-1234567` and `^monthly` (in a narration) also find nothing. Before w21/025 these searches worked.

**Verified against production (2026-10-21, `main` `aedab56ba`):** with `2026-08-30 * "QA LANDLORD" "Check #1042"` on the disposable QA ledger, `getLedgerJournal(filter:)` returned **0** for `#1042`, 1 for `"Check #1042"`, and **1** for the proposed `#1042,"#1042"` (Fava's `,` means OR). The ledger was restored to `f1a0b83c`.

## Fix

For a lone tag or link token, send `<token>,"<escaped token>"`, so it matches the tag or the text. A real `#trip` tag search keeps working.

**Acceptance:** searching `#1042` lists the "Check #1042" entry, and `#trip` still lists tagged entries.

## Dedupe

This is a regression from w21/025, which lists near-misses such as `coffee #work` but not `#digits` in a narration. Searched `.pm/**` for "Check #", "#1042", "check number" and toPlainSearchFilter.
