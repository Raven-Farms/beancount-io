# The file editor's Recreate and Overwrite skip the save guard and show no "Saving…", so a Save tapped meanwhile brings back a false "File Deleted" or silently drops the Overwrite

**Severity:** minor. **Estimate:** 20 minutes. Owner: mobile. A3 (code-level at `main` `f61267f7d`; modeled under `tsx`): `ledger-file-editor-screen/index.tsx:681-716` (`recreateFile`) and `:649-662` (`overwriteRemote`) never set `saveInFlightRef` (`:490`), and the header's "Saving…" (`:964`) tracks only `updateLedgerFile`, so Save stays live.

- Recreate: a Save tapped during `createLedgerFile` sends the deleted file's sha. It gets NOT_FOUND, and a second "File Deleted" alert appears over a restore that is succeeding. Recreate from that alert then gets CONFLICT (see w21/564).
- Overwrite: a Save tapped during the refetch sends the stale sha, shows "File Changed" again, and holds the guard, so Overwrite's own save returns false and is dropped.

Not run natively: the driver's taps are too slow for the interleaving.

## Fix

Route Recreate and Overwrite through the same in-flight guard and "Saving…" state as Save (with w21/522's baseline update).

**Acceptance:** Save is ignored during Recreate and Overwrite, and neither produces a second alert. A screen test covers both.

See w21/378, w21/522 and w21/564. Searched `.pm/**` for saveInFlightRef, recreateFile and overwriteRemote.
