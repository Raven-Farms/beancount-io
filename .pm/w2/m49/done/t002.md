## Objective

Settle which skill refreshes `price` directives and how: a user (or agent) can bring ledger prices current through the documented `bea` path, and ask's missing-price report points at exactly that step.

## Context

- Today `bea engine enable beanprice` is an orphan line in `skills/README.md`; `beancount-add` can write a single user-supplied `price`, and no skill owns bulk refresh.
- `bea --file "$ledger" price status` already reports freshness (cited in beancount-ask).

## Steps

1. Rehearse the `bea price` path on a synthetic ledger with priced commodities; record what it writes, how stale prices are detected, and what a user must configure.
2. Write the refresh procedure into the owning skill's text (or its references), with propose-then-confirm before any `price` write, and point ask's unpriced-commodity output at it.

## Files

- Owning skill's `SKILL.md`/`references/`, `skills/beancount-ask/SKILL.md` pointer

## Acceptance criteria

- [x] A fresh agent session following only the shipped text brings a stale fixture's prices current (or states precisely why it cannot), with no price written before confirmation.

## Out of scope

- New price sources or a quote service.

## Result

Price refresh now has an owner: `beancount-add` (new Refreshing prices section), since it already owns `price` writes. Three propose-first paths, all rehearsed 2026-10-19 against `bea 0.3.1` on a synthetic ledger: (1) managed price include — the skill shows the exact `include` line for the user to add (skills never edit `include`s), then confirms via the new `price-status` recipe; the fetch itself was not rehearsed because this machine's cloud session is expired (`bea cloud status`: session expired), which the shipped text names as the user step (`bea cloud login` / `BEA_TOKEN`). (2) Fetched quotes — `bea engine enable beanprice` succeeds, and `bea price -e 'USD:yahoo/VTI'` (no `--json`; forwarded bean-price has no JSON mode) printed a live `2026-10-19 price VTI 375.54 USD`; quotes are proposed with their source and written per quote via the `price` recipe only after a yes. (3) User-supplied quote via the existing recipe — rehearsed end to end (wrote 2026-10-19 VTI 310.00, holdings revalued 7500.00 → 7750.00). `bea-cli.md` gains executable `price-status`/`price-refresh` recipes (new test: both answer `sources: []` and write nothing on a plain ledger; suite 121 OK), and beancount-ask's unpriced/stale output now points at this workflow by name.
