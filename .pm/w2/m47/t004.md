## Objective

Give the PDF and receipt paths evals that would catch a wrong import, not just a missing one. Every fixture is synthetic, and no real statement or receipt enters the repository.

## Context

- Skill evals live in each skill's `evals/evals.json` with fixtures under `evals/files/`. `scripts/skills/ci-check.py` validates fixture paths and runs `bea check` on `*ledger.beancount`.
- Generating PDFs must not add a dependency without approval, because the repository asks before adding any dependency. Either check in the generated files together with the stdlib script that wrote them, or write a minimal PDF by hand. The same input must produce the same bytes, so fixtures do not churn.

## Steps

1. Statement cases:
   - A two-page statement with a carried-forward subtotal, which must not become a transaction, and a description wrapped across lines.
   - A statement with one misread figure, where opening + movements ≠ closing. The skill must stop before writing.
   - A memo containing an instruction, which is recorded or flagged and never followed.
   - The same PDF imported twice, which must add zero entries.
   - A later CSV of an overlapping period, which must show suspected duplicates and no new writes.
2. Receipt cases:
   - A receipt PDF with tax and tip, whose parts must sum to the total or prompt a question.
   - A receipt image, if both clients read images. Otherwise record the client limitation.
   - A ledger that declares `option "documents"`, so the file lands in its layout.
3. Make each eval's expectations name the ledger effect (entries written, the assertion, the `document` link), not only the reply text.

## Files

- The chosen import skill's `evals/` and `skills/.claude/skills/beancount-add/evals/`
- A fixture generator beside the fixtures, if one is used

## Acceptance criteria

- [ ] Each case above has an eval with a synthetic fixture, and `ci-check.py` passes.
- [ ] Regenerating the fixtures leaves the files byte-identical.

## Out of scope

- Running the evals on real clients (t005).
