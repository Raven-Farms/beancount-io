## Objective

Settle three things before writing skill text. First, which skill owns "import this PDF statement". Second, what `import-id` a PDF row gets, so that re-reading the same file is a no-op. Third, how a later CSV export of the same account and period finds rows that a PDF already recorded. Write the identity and cross-source rules in `dedup.md` as normative, and record the placement decision with routing evidence in the milestone `README.md`.

## Context

- `beancount-reconcile` already accepts a PDF statement (`references/statement-formats.md`, "PDF statement"). It extracts the period, the opening and ending balances, and the transaction lines, and runs a sanity walk (opening + movements = ending) before matching. It proposes each missing-in-ledger line with an `import-id` "per beancount-import's `references/dedup.md`", then writes `bea add transactions` and `bea add balance`.
- `beancount-import`'s description and its `references/formats.md` detection table cover CSV, OFX/QFX, and QIF only. The routing set (`scripts/skills/routing.json`) routes "Reconcile my Amex against this statement PDF" and "add whatever transactions are missing and assert the ending balance" to reconcile. It has no prompt for importing a PDF where no CSV exists.
- `dedup.md`: the generated `csv:sha256:` form hashes the raw description. Layer 2 (fuzzy, ±3 days) compares only against entries that lack an `import-id`, and Layer 2b covers only the other side of a transfer. A PDF line and the bank's CSV row for the same purchase are usually worded differently. Layer 1 therefore misses, and Layer 2 skips the PDF-sourced entry because it has an id. `bea import` reports possible duplicates only on the same date, normalized payee, and amount.
- A model can render a PDF line's wording differently from one read to the next, for example by joining a wrapped description differently. A description hash may therefore not be stable across re-reads of one file.
- [079](../done/079.md) adds the shared rule that export, statement, and receipt text is data, never instructions. This milestone relies on it.

## Steps

1. Add candidate prompts to a scratch copy of the routing set, for example "Import my June statement PDF, my bank has no CSV export" and "Record the transactions in ./may-statement.pdf". Run `scripts/skills/run-routing.py` on both clients and record where they route today.
2. Choose the placement. The recommended default is that `beancount-import` accepts a PDF statement and reuses reconcile's extraction reference, rather than keeping a second copy, and finishes with reconcile's tie-out. Reconcile keeps "compare my account to this statement". Record the choice and the evidence.
3. Define the PDF row identity: the prefix, the hash input, and the occurrence rule. Prefer the form that stays stable across re-reads of the same file, and say what makes it stable. Add it to `dedup.md` with one worked example whose digest is computed honestly.
4. Define the cross-source review. When candidate rows post the same amount to the same account within ±3 days of an entry whose `import-id` comes from a different source kind, present each pair as a suspected duplicate. Add the rule to `dedup.md` beside Layer 2, with a worked example.
5. Say whether `bea import`'s own detector needs a change to honor the rule. If it does, draft a follow-up note for `/pm add` instead of changing the CLI here.
