# Let beancount-close propose the recurring entry it already detects as missing

`beancount-close` flags expected-but-missing recurring entries as findings and never creates them (a real missing entry is recorded through import or add). As a user this means re-describing the same rent/mortgage/subscription in a second conversation every time. Consider: when the user confirms a gap is a real missing entry, close hands add a prefilled proposal (same payee/account/amount as the prior months, period date) inside the same session — still propose-then-confirm, still never fabricated silently. Needs a decision on whether close may compose add this way, plus an eval where the user declines and nothing is written. Sub-hour to scope; promote if the composition design grows.
