# beancount-init writes a short AGENTS.md into the new ledger

**Idea · skills · ~1h · A1/A2.** From the skills research, 2026-10-18.

A new ledger carries no instructions for the next agent that opens it. If the suite is not installed in that session, or if the user opens the folder with a different client, the agent has to rediscover the root file, the include layout, and the rule that `bea check` must pass. Three published Beancount projects write an `AGENTS.md` into the ledger they create: [quints](https://github.com/sealambda/quints), [beancount-ai-ledger](https://github.com/Xbang0222/beancount-ai-ledger), and [auto-bean](https://github.com/SamArgt/auto-bean). `skills/beancount-init/SKILL.md` does not (checked 2026-10-18).

Have `beancount-init` write a short `AGENTS.md` after `bea init` and `bea check` pass. It should cover:

- The root file, and where includes go.
- The account roots and naming in use.
- The import-rules path, once it exists.
- That every write is proposed and confirmed first, and that the root `bea check` passes before anything counts as done.
- Where to get the skills.

Rules:

- Write it only for a ledger the skill just created. For an existing ledger, offer it and never overwrite an existing `AGENTS.md` or `CLAUDE.md`.
- Check how each client picks the file up at the time of the work. Claude Code may need a one-line `CLAUDE.md` that imports `AGENTS.md`. This repository's "no `CLAUDE.md`" rule governs this repository, not customer ledgers.
- Keep the template in `beancount-init/references/`, and cover it with an eval: a fresh session in the new ledger runs `bea check` before reporting success.
