## Objective

Make every phase of `beancount-close` record what it checked and the state it ended in, so the close report shows exactly what was verified and what was not. A green ledger check must never stand in for a verified close.

## Context

- `skills/beancount-close/SKILL.md` runs seven phases: Scope, Reconcile, Assert, Recurring, Flags, Report, Commit. `references/close-checklist.md` defines the reconcile outcomes as tied, partial (reconcile withheld the assertion over unresolved items), and unverified (no statement), plus unpinned assertions and carried flags.
- The commit subject is `close: <period> — <n> reconciled, <m> unverified`, and its body is the close report. Only a red check blocks the commit proposal.
- ADR 020's release gate for this row: "An unresolved reconciliation or absent statement stays visible; a green ledger check alone never becomes proof of a fully verified close." The same row asks for an optional owner and due date for teams, and for the simple personal-ledger path to be preserved.
- t001 gives each reconciled account a coverage section (statement period, row counts, totals, exclusions, residual) that this step can cite instead of re-deriving.

## Steps

1. For each active account, record its evidence: the statement file or files, the statement period, the coverage counts from reconcile, and the residual. Record one state:
   - **tied:** a passing assertion over the whole close period.
   - **partial:** reconcile withheld the assertion.
   - **partly covered:** the statement period does not span the close period.
   - **unverified:** no statement.
   - **blocked:** a step could not run, with the reason (for example, reconcile is not installed, or the user stopped).
2. Give each phase a status line that names any blocker. Keep the rule that only a red check blocks the commit proposal, but make the report's headline and the commit body list every account that is not tied. `<n> reconciled` in the subject counts tied accounts only.
3. Accept an owner and a due date per step only when the user supplies them. Otherwise omit those fields entirely, so the personal close report is no longer than today's example.
4. Label the `check:` line as ledger validity. Never write "verified", "complete", or "clean" in the headline unless every active account is tied over the whole period.

## Acceptance criteria

- [x] The report lists every active account with its state and evidence, and a statement covering only part of the period gives "partly covered", not tied.
- [x] With no owner or due date supplied, the report contains no owner or due-date fields.
- [x] Neither the headline nor the commit message calls the close verified while any active account is not tied.

## Out of scope

- Persisting close state between sessions, calendars, reminders, or team assignment beyond an owner and due date the user states.

## Result

Shipped with this task: `beancount-close` now records per-account evidence (statement files, statement period, coverage counts from reconcile's Coverage phase, residual) and one of five states — tied, partial, partly covered, unverified, blocked with reason (reconcile-missing is blocked, no longer silently unverified). The report headline counts tied only and lists every not-tied account; the commit subject is now `close: <period> — <n> tied, <m> not tied` (first-month guide, its expectations, verifier fixtures, and close eval 1 updated to match; the rehearsal records keep their historical subjects). Owner/due-date fields exist only when the user supplies them — the personal example report carries none. The `check` line is labeled ledger validity, and neither headline nor commit message may call a close verified/complete/clean while any active account is not tied. Full skills gates pass (ci-check, 118 behavioral tests, 15 first-month verifier tests).
