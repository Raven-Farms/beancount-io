## Objective

Prove that an existing user upgrades cleanly: from an install of the previous revision, `git pull` plus `install` leaves both clients listing the new names, and a ledger with an options config block still works.

## Context

- `docs/skills/installation.md` "Update" is the procedure users follow.

## Steps

1. Install the pre-rename revision into scratch Claude Code and Codex skill directories.
2. Update the checkout to the rename revision and run `install` and `verify`.
3. Ask each client to list `beancount-*` skills, and run one options eval against a ledger carrying `;; beancount-options config`.
4. Record versions, dates, and revisions in `docs/skills/routing-rehearsal.md` or a dated upgrade section of the install guide's evidence.

## Files

- `docs/skills/` (evidence)

## Acceptance criteria

- [ ] Both clients list exactly the renamed suite, with no dangling link in either directory.
- [ ] The options eval re-reads the existing config block without re-asking its settings.

## Out of scope

- Registry installs.
