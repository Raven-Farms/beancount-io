## Objective

Make `install`, `verify`, and `uninstall` handle links left under retired skill names, so an upgrade does not leave a dangling `beancount-options` or `beancount-close` link in a user's agent directory.

## Context

- `scripts/skills/beancount-skills.py` derives the suite from `beancount-*/SKILL.md` on disk. An entry not in the suite gets "not part of this suite; left untouched", so today a stale link would stay forever.
- The helper is stdlib-only and must never touch skills it did not install (`skills/AGENTS.md`).

## Steps

1. Keep a short list of retired names and their replacements in the helper.
2. `install`: replace a retired-name link that points into this checkout with the new name. `verify`: fail on a retired-name link into this checkout. `uninstall`: remove retired-name links into this checkout.
3. Leave non-link copies and links into other checkouts untouched, reported as today's `CONFLICT`.
4. Mention the upgrade behavior in `skills/docs/installation.md` "Update".

## Files

- `scripts/skills/beancount-skills.py`, `scripts/skills/test_beancount_skills.py`, `skills/docs/installation.md`

## Acceptance criteria

- [ ] After `git pull` and `install`, the destination holds the new links and no retired-name link into the checkout.
- [ ] A user's own copy under a retired name survives every subcommand.

## Out of scope

- Registry installs (w6/m6).
