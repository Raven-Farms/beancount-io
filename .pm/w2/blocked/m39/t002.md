## Objective

Decouple persisted config headers from skill names, so renaming a skill never strands the config already written into customers' ledgers.

## Context

- `beancount-options/SKILL.md` reads and writes a `;; beancount-options config` comment block at the top of the user's main ledger. `beancount-import` and `beancount-reconcile` use `;; beancount-import config` and `;; beancount-reconcile config`.
- `skills/AGENTS.md` "Shared suite conventions" describes the config blocks.

## Steps

1. Keep `;; beancount-options config` byte-for-byte as the header the renamed skill reads and writes.
2. State in `skills/AGENTS.md` that config-block headers are a persisted contract, independent of skill directory names.

## Files

- `skills/.claude/skills/beancount-options/SKILL.md`, `skills/AGENTS.md`

## Acceptance criteria

- [ ] The options skill's discovery and write steps name the existing header exactly.
- [ ] `skills/AGENTS.md` records the header rule.

## Out of scope

- Changing any config block's contents.
