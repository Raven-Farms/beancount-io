## Objective

Turn one mainstream broker activity export (CSV or investment OFX) into proposed lot-carrying entries through the import pipeline's dedup discipline: buys, sells with booking-produced gains, dividends, fees — reviewed as one batch, idempotent on re-import.

## Context

- `beancount-import` handles bank/card CSV, OFX/QFX, QIF, and PDF statements; investment activity (lot buys/sells) is not among its shapes today, and `beancount-trade` refuses statement files by design.
- Every imported row carries an `import-id` per `beancount-import/references/dedup.md`; sells must reduce lots the ledger actually holds or stop and ask.

## Steps

1. Pick the first format from real export shapes (document which and why), build a synthetic export fixture, and derive the row-to-lot mapping empirically with `bea check`.
2. Write the procedure into the owning skill decided by the mapping's home (import stage vs trade batch), including the unheld-lot and unknown-commodity stops.

## Files

- Owning skill text/references, `references/dedup.md` if a new source kind is named

## Acceptance criteria

- [x] The synthetic export imports to entries whose lots, cash, and gains match hand-computed figures, re-import adds zero entries, and a sell of an unheld lot stops before any write.

## Out of scope

- Options activity (beancount-options), margin/short activity.

## Result

Broker activity CSV imports as lots through `beancount-import` (new `references/broker-activity.md` + skill wiring). First format chosen: CSV with a confirmed, persisted column + action mapping (investment OFX deferred to importer-author — mainstream broker activity exports are CSV-shaped, and the mapper-confirm pattern already exists for bank CSV). Fixed action vocabulary (buy/sell/dividend/reinvest/fee/interest/transfer); unknown actions stop and ask. Sells resolve their lot against held lots and the account's booking method before staging — ambiguous asks, unheld stops; gains are always booking-produced (an export's own gain figure is compared, never typed). Dedup reuses the existing `csv:sha256` lot-posting hash form (worked example with a real computed digest in the reference), so re-import is a Layer-1 no-op. Derived empirically: a synthetic 3-row export (buy with itemized fee, dividend, sell with fee) staged to one atomic batch on a two-lot fixture — lots, cash, and the 1000.00 booked gain all tie. Description changed, so the routing run is owed at t005 with the rest of the milestone.
