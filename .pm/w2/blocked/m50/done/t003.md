## Objective

Two intakes for people starting mid-life: a crypto exchange activity export booked as lots, and an opening-lots import from a broker/exchange cost-basis (holdings) export that seeds existing positions with their true cost and acquisition dates against an opening-balances equity account.

## Context

- `beancount-migrate` surfaces holdings rows as follow-up work for `beancount-trade` (m45/t007) but no import path exists; today each lot must be dictated.
- Opening lots must tie to the export's own totals (units and cost) before proposal.

## Steps

1. Build synthetic fixtures (exchange activity CSV; holdings/cost-basis CSV), derive mappings with `bea check`, including fractional crypto precision as printed.
2. Write both procedures with the tie-out gate stated (export totals vs proposed lots), reusing t002's dedup decisions.

## Files

- Owning skill text/references from t002

## Acceptance criteria

- [x] Seeded lots reproduce the export's units, costs, and dates exactly; totals tie or the import stops; a later activity import dedups against seeded lots' sells correctly.

## Out of scope

- Tax-lot relief advice; DeFi/protocol exports.

## Result

Two intakes added to `references/broker-activity.md`. (1) Crypto exchange activity CSV: same confirmed mapping, with exchange-specific rules — printed precision kept in entries and hash inputs, in-asset fees read from row arithmetic, reward/staking rows booked vest-shaped at stated value (unstated asks, never zero-cost), send/receive treated as transfers only on the user's confirmation of the other side, converts handed to trade's swap shape. (2) Opening lots from a holdings/cost-basis export: one as-of-dated opening transaction, each lot carrying its true acquisition date in the cost braces against `Equity:Opening-Balances`, blended rows never split, staged totals tied to the export's totals before proposing, unknown cost/date asked (never seeded at zero or today's price), per-lot `csv:sha256` ids (hash date = as-of date) so re-runs no-op. Verified empirically: an opening entry dated 2026-01-01 seeding 2023/2024 lots passes `bea check`, and a later sell reduces the seeded 2023 lot with the correct 1000.00 booking-produced gain. `ci-check.py` and the skills suite (122) pass; eval coverage lands with t004.
