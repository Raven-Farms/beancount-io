# Say plainly where ledger data goes, and how the suite relates to upstream Beancount

**Idea · skills · 30–45m · A3.** From the skills research, 2026-10-18.

Two concerns come up again and again wherever people discuss agents and Beancount, and neither `skills/README.md` nor `docs/skills/installation.md` answers them:

- **Privacy.** "Bold to send your banking information to Anthropic" ([HN, Sep 2024](https://news.ycombinator.com/item?id=41550603)). The announcement of a beanquery MCP server warned users to "be careful which data you want to share with which LLM". Some users choose local models for this reason ([beancount discussion #971](https://github.com/beancount/beancount/discussions/971)).
- **Affiliation.** In [beancount discussion #831](https://github.com/beancount/beancount/discussions/831) (June 2024), a Beancount maintainer says the Beancount project is not affiliated with beancount.io and calls its claims misleading.

Add a short "Your data" section to `skills/README.md`, linked from the install guide. It should say:

- The skills read and write files on the user's machine. Nothing reaches Beancount.io unless the user connects the hosted MCP server.
- The agent's model provider sees whatever the agent reads, such as ledger lines, exports, and statements. That follows from the client the user runs, not from the skills.
- Which clients can run the suite against a local model, but only if that has been verified on a real client. Otherwise, leave the claim out.
- The suite builds on upstream Beancount and Beangulp, through `bea`, and is not the Beancount project.

The repository owner approves the affiliation wording before it ships. Keep the section factual and short, with no marketing language.

**Draft (2026-10-19, awaiting owner approval — not yet in `skills/README.md`):**

> ## Your data
>
> The skills read and write ledger files on your machine, through `bea`.
> Nothing reaches Beancount.io's servers unless you connect the hosted MCP
> server for a hosted ledger; a local ledger stays local.
>
> Your agent's model provider is a separate matter. Whatever the agent reads
> to do the work — ledger lines, bank exports, statements — goes to the model
> behind the client you run, under that client's terms. The skills cannot
> change that; if it decides your choice of client or model, weigh it there.
>
> This suite builds on upstream [Beancount](https://github.com/beancount/beancount)
> and Beangulp, through `bea`. It is part of Beancount.io and is not the
> Beancount project.

The local-model question is deliberately absent: no suite run against a local model has been verified on a real client (checked the install guide and references 2026-10-19), and this note says to leave the claim out until one has.
