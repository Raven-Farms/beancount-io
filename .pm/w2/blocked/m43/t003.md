## Objective

Keep every customer skill within the Agent Skills specification after this milestone, so a description that grows past the limit or a renamed folder fails CI instead of failing a registry later.

## Context

- Root `AGENTS.md`: ask the user before adding a new dependency. Running `skills-ref` in CI is a dependency, even when pinned through `uv tool run`.
- `ci-check.py` already checks that `name` and `description` exist, and checks the metadata form. It does not check the specification's length limits, the name's character rules, or that the name matches its folder.
- If t002 recorded a rule the suite cannot meet, exempt only that rule, by name, with a pointer to the record.

## Steps

1. Ask the user whether CI may run a pinned `skills-ref`. If yes, add it to `.github/workflows/ci-skills.yml`. If not, implement the specification's frontmatter rules in `ci-check.py` with the standard library.
2. Run `ci-check.py` and `test_ci_check.py`.

## Files

- `scripts/skills/ci-check.py` or `.github/workflows/ci-skills.yml`, `scripts/skills/test_ci_check.py`

- [ ] CI fails on a description over 1024 characters, a name containing `--`, a name that differs from its folder, and a `metadata` value the chosen form forbids. Each case is covered by a test.
- [ ] The user's dependency decision is recorded in this task.
