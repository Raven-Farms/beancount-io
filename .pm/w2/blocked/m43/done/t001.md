## Objective

Flag every development skill under `.agents/skills/` as internal, so public skill installers skip it while Claude Code and Codex keep loading it in this repository. Make CI require the flag on development skills and forbid it on customer skills.

## Context

- 19 `SKILL.md` files sit under `.agents/skills/` (`loopx`, `mermaid`, `mobile-release`, `pm`, `pm-brainstorm`, the four `qa-find-bugs-*`, ten `routine-*`, and `ship`). The root `.claude/skills` links to them.
- [vercel-labs/skills](https://github.com/vercel-labs/skills) hides a skill whose frontmatter sets `metadata.internal: true`, unless `INSTALL_INTERNAL_SKILLS=1`. Check in its source whether it requires the boolean `true` or also accepts the string `"true"`, since the Agent Skills specification limits `metadata` values to strings (t002).
- `scripts/skills/ci-check.py` `check_metadata` requires any `metadata` to be a single-line JSON object, for development skills too. `metadata: {"internal": true}` fits that rule. If t002 changes the rule, follow it.
- A research run on 2026-10-18 found that a bare `npx skills add bex-co/beancount-io --list` lists 28 skills. Re-verify before changing anything.

## Steps

1. Run `npx skills add bex-co/beancount-io --list` and record the output and CLI version.
2. Add the flag to the 19 development skills. In `ci-check.py`, fail when a development skill lacks it or a customer skill carries it.
3. List the local checkout with the CLI (`npx skills add . --list`), then the GitHub repository after the push. Confirm Claude Code and Codex still list the development skills in this repository.

## Files

- `.agents/skills/*/SKILL.md`, `scripts/skills/ci-check.py`, `scripts/skills/test_ci_check.py`

## Acceptance criteria

- [x] After the push, `--list` against `bex-co/beancount-io` shows only `beancount-*` skills. With `INSTALL_INTERNAL_SKILLS=1`, it also shows the 19 development skills. Both outputs are recorded.
- [x] Claude Code and Codex still list every development skill when run in this repository.
- [x] `ci-check.py` fails for a development skill without the flag and for a customer skill with it.

## Out of scope

- Moving or renaming development skills, and changing their descriptions.

## Result

Shipped with this task: all 19 development skills under `.agents/skills/` now carry `metadata: {"internal": true}`, and `scripts/skills/ci-check.py` fails a development skill without the boolean flag (the string `"true"` included, pinned by test) or a customer skill with it. Form evidence: vercel-labs/skills checks `metadata?.internal === true` on both its local and remote listing paths (cloned 2026-10-19), and the one-line JSON form yields the boolean while staying valid for the other frontmatter parsers. Recorded 2026-10-19 with skills CLI 1.5.18: baseline `npx skills add bex-co/beancount-io --list` found 28 skills (9 customer + 19 development); after the flag, the local checkout lists exactly the 9 `beancount-*` skills, and `INSTALL_INTERNAL_SKILLS=1` lists all 28. Both clients still load the development suite in this repository: a fresh client session lists all 19, and the second client's pre-model skills catalog (its rollout, built client-side before the usage-limited turn failed) also lists all 19 at `.agents/skills/<name>/SKILL.md`. Post-push rerun against GitHub (2026-10-19, after `64f36006a`): 9 skills by default, 28 with `INSTALL_INTERNAL_SKILLS=1`.
