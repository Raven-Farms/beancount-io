## Objective

Write evals that show the skill changes only what was asked, refuses what the contract refuses, and keeps the ledger checkable. Then label the edit prompts in the suite routing set, so descriptions are measured, not guessed.

## Context

- Eval cases and fixtures live in `skills/<name>/evals/`. `scripts/skills/ci-check.py` validates `evals.json`, the fixture paths, and every `*ledger.beancount` with `bea check`.
- Fixture cases:
  - a multi-file ledger with includes;
  - a nested monthly-file layout that must survive a move;
  - a rename touching `open`, `balance`, `pad`, `note`, `document`, and an import rules file;
  - a recategorization where one matched entry is a split;
  - a fix that breaks a balance assertion, so the change is not committed;
  - a dirty working tree;
  - a ledger outside Git;
  - a narration containing an instruction, which stays data.
- Routing: in `scripts/skills/routing.json`, relabel "Fix the typo in the payee of yesterday's Starbucks transaction" from `none` to this skill. Add positives (recategorize, rename, tag a trip, move a year into its own file, undo the last change) and near-misses: a new purchase goes to `beancount-add`, a new bank export to `beancount-import`, and a failing balance assertion against a statement to `beancount-reconcile`. Hosted-ledger edits stay `none`.

## Steps

1. Write the fixtures and `evals.json`.
2. Update the routing set. Run `python3 scripts/skills/ci-check.py` and `python3 scripts/skills/test_ci_check.py`.
