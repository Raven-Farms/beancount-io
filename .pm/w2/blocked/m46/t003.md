## Objective

Make every change reviewable and reversible:
- record the root `bea check` result before the change;
- show the diff and wait for a yes;
- apply the change, then check again;
- commit it as one checkpoint whose message names the request;
- make "undo the last change" revert exactly that commit.

Refuse, or ask, exactly where t001's contract says: a dirty working tree, a ledger outside Git, or a check that gets worse.

## Context

- Users want review before any write, and they reject silent corruption ([Mandalivia](https://www.mandalivia.com/obsidian/hledger-obsidian-personal-finance-with-claude-code/)).
- When the ledger was already red, compare the error sets: the change may not add an error. A new error means no commit, and the files are restored.
- Undo reverts only this skill's own checkpoint commits. It never resets, rebases, or deletes other commits.
- Do not run `bea format --in-place` over files the user did not ask to reformat. Edited lines keep the surrounding alignment, and `bea format --dry-run` can show drift on the touched lines.

## Steps

1. Write the rails into the procedure as numbered gates, with the exact commands and the message for each refusal.
2. Write the commit message format and the undo procedure, so "undo" finds the right commit and reports what it reverted.
