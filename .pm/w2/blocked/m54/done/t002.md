## Objective

An immediate upgrade charged inside Billing is a purchase too. Give the dashboard the id and amount of the invoice `changePlan` charged, so it can record that purchase once with a stable transaction id.

## Context

- `changePlan` returns `PlanChangeResult` (`backend-cluster/backend-v2/src/features/stripe/api/subscription-resolver.ts`), which has `status`, `clientSecret`, `hostedInvoiceUrl`, `subscriptionId` and the new limits, but no invoice id.
- The immediate path is `operations/plan-change-apply.ts`: it updates the subscription with `proration_behavior: "always_invoice"`, so the proration invoice is the subscription's latest invoice.
- `REQUIRES_ACTION` results finish in the browser (`dashboard/src/features/user-settings/pages/general/bank-approval.ts`); the invoice id must be present on that result too, so the purchase can be recorded once the bank approves.

## Steps

1. Add nullable `invoiceId`, `amountPaid` (minor units) and `currency` to `PlanChangeResult` for immediate changes (`ACTIVE` and `REQUIRES_ACTION`); null for scheduled, refused and failed results.
2. Fill them from the proration invoice in `plan-change-apply.ts` without an extra Stripe call where the update already returns it expanded.
3. Regenerate schema/codegen; add the fields to the dashboard's `changePlan` document.

## Files

- `backend-cluster/backend-v2/src/features/stripe/operations/plan-change-apply.ts`
- `backend-cluster/backend-v2/src/features/stripe/api/subscription-resolver.ts`
- `dashboard/src/graphql/**` (the `changePlan` document and generated types)

## Acceptance criteria

- [ ] An immediate upgrade's result carries the proration invoice's id, amount and currency; a scheduled change's carries none.
- [ ] A `REQUIRES_ACTION` result carries the invoice id.
- [ ] Backend gates pass; the dashboard compiles against the new fields.

## Out of scope

- Sending the `purchase` event (t005).
