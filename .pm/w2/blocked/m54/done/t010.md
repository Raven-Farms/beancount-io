## Objective

Lock in the behaviour that would silently regress: where Checkout returns, that a purchase is counted exactly once, and that the celebration respects the same rules.

## Steps

1. Backend: success/cancel URLs per `returnTo`, braces unencoded; the in-sheet invoice fields; no Measurement Protocol code path left.
2. Dashboard: `purchase` once per transaction across remount, storage unavailable, empty id, $0 and pending; in-sheet upgrade and bank-approval success record once, scheduled changes never; confetti skips reduced motion and replays; the "Start using" and "Back to work" choice; the cancelled notice clears its parameter.
3. Mutation-check each new test: break the rule, watch the test fail, restore.
