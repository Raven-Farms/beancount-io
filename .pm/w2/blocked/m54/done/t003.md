## Objective

The user chose to count purchases in the browser only. Remove the server-side reporter, which has never been switched on in production, so GA4 has one purchase source and nobody can double-count by setting a secret later.

## Context

- `backend-cluster/backend-v2/src/features/stripe/operations/report-purchase.ts` sends `purchase` through the Measurement Protocol from the `invoice.paid` case of `api/stripe-webhook-handler.ts`, claiming a `reported_purchases` row first. It is off unless `GA_MEASUREMENT_ID` and `GA_MEASUREMENT_PROTOCOL_SECRET` are set (`src/config/config.ts`).
- The variables are wired in `backend-cluster/backend-v2/.env.example`, its `README.md`, and every `deploy/*/docker-compose.yml` and `.env.example`.
- `operations/minor-units.ts` (money formatting) is shared with the billing emails and stays.
- Find the `reported_purchases` model and migration; drop the table in a new migration rather than editing history.

## Steps

1. Remove the `invoice.paid` purchase call, `report-purchase.ts`, its tests, and the config fields.
2. Remove the variables from the env examples, Compose files and backend README.
3. Add a migration dropping `reported_purchases` and remove its model and registry entry.
