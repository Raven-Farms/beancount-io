# `bea add close` writes a close over an account that still holds a balance, with no warning

**Minor · cli · 30–45m · A1.** Found while building [w2/m40](./blocked/m40/README.md) (`beancount-add`), 2026-10-19, `bea` 0.3.1.

`bea --file main.bean --json --no-input add close --date 2026-10-18 --account Assets:OldSavings` exits 0 with `written: 1` and empty `warnings` while `Assets:OldSavings` still holds 100.00 USD. The balance is then stranded in a closed account: later postings to it are refused, and reports keep counting it. Upstream Beancount only catches this when the ledger loads the `check_drained` plugin.

`beancount-add` works around it at the skill layer: it reads the balance through the close date first (`balance-before-close` in its SKILL.md) and stops on a nonzero row, and `test_close_writes_over_a_balance_so_the_balance_read_must_come_first` pins today's CLI behavior. The fix belongs in `bea add close` itself, where every agent and user gets it: refuse a close while the account holds a nonzero balance in any currency (naming each amount and the command to move it), unless `--force` is passed, the same pattern `add price` already uses for a conflicting quote. Check whether a hosted close path exists on REST, GraphQL, or MCP and needs the same refusal (root `AGENTS.md` parity rule). When it ships, flip the skills test to expect the refusal and keep the skill's read as the friendly explanation.
