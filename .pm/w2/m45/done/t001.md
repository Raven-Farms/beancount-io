## Objective

Decide where investment trades live: a new top-level skill (working name `beancount-invest`) or a widened `beancount-options`. Write down its trigger, input contract, deliverable, and evaluation set, which are [ADR 020](../../../../docs/adrs/ADR020-skills-accounting-workflow-candidates.md)'s four criteria. Base the decision on routing evidence, not on naming taste.

## Context

- `scripts/skills/routing.json` has no stock, fund, dividend, split, or crypto prompts today. The trade boundary is unmeasured.
- `beancount-add` ([m40 t001](../../blocked/m40/done/t001.md)) owns single things the user just did, including a price directive. A stock buy described in words is a near-miss for it, so draw the line explicitly: anything that carries cost basis or reduces a lot belongs to the trade skill.
- `beancount-options` already covers per-contract cost basis, assignment, and exercise (`skills/beancount-options/SKILL.md`). Its `Assets:Brokerage:<Broker>:{Cash,Options,Stock}` hierarchy is the natural home for shares received on assignment.
- [w5/763](../../../w5/763.md) records that `{}` does not match "any held lot" under the default `STRICT` booking. Any procedure that reduces lots must account for it.
- `ci-check.py` rejects routing labels that name a skill that does not exist yet. Measure on a scratch copy, as m40's t001 did, and land the labels with the SKILL.md in t002.
- [m41](../../blocked/m41/README.md) is compacting every skill into plain procedures (`w2/m41/t009`). Write the new text in that style.

## Steps

1. Draft the scope and skip list, naming the sibling each excluded request goes to.
2. Draft positive and near-miss prompts for trades, dividends, splits, lot transfers, vests, and crypto, against add and options.
3. Run the routing set with each placement in a scratch install on both clients. Record the results in `docs/skills/routing-rehearsal.md`, and choose the placement that routes without taking prompts from siblings.
