# The skills' recipe tests run the checkout's unreleased `bea`, not the release customers install

**Minor · skills CI · 45m–1h · A1.** Found in [w2/m41](./m41/README.md) t001, 2026-10-19.

`skills/scripts/test_beancount_skills.py` and `ci-check.py` resolve `bea` from `PATH`, else `uv run --project cli bea`. In `CI (skills)` and in a synced checkout that is the CLI source on `main`, which reports `bea 0.3.1` but carries every fix merged since the `cli-v0.3.1` tag. Customers run the published `beancount-io==0.3.1`. The two already differ: on `main` a batch row accepts `"cost": {}` (lot selection) and `number_total`, while the published 0.3.1 rejects both ("1 of 1 row(s) failed validation"). The suite's guidance follows the release (bea-cli.md, Version notes), but nothing in CI would catch a recipe that only works on unreleased code.

Add a second leg that runs the executable recipes against the published minimum, for example `uvx --from 'beancount-io==<minimum>' bea`, with the version read from bea-cli.md's declared minimum. Keep the checkout leg, which catches CLI changes that would break the skills before they ship. Report which leg failed.
