## Objective

Write a labeled set of at least 40 realistic ledger requests, each with the one skill that should handle it or `none`, covering every near-miss pair in the milestone `README.md`.

## Context

- Per-skill behavior evals live in `skills/.claude/skills/<name>/evals/evals.json`. The routing set is suite-wide, so it lives outside the installed skill directories (proposed: `skills/evals/routing.json`). The installer links only `beancount-*` directories, so the set is never installed into a customer's agent.
- Descriptions today: the frontmatter of each `skills/.claude/skills/*/SKILL.md`.

## Steps

1. Draft prompts in the words users actually type: bank and app names, "month-end", "sold a cash-secured put". Use a few phrasings per skill, not one.
2. For every positive prompt, add at least one near-miss that should go elsewhere or nowhere. Give each entry a `why` naming the sibling it could be confused with.
3. Keep the prompts synthetic: no real names, accounts, or amounts.

## Files

- `skills/evals/routing.json` (new)

## Acceptance criteria

- [ ] At least 40 entries; every skill has positives and at least one near-miss negative; every pair in the milestone README appears.
- [ ] Each entry has `prompt`, `expected` (a skill name or `none`), and `why`.

## Out of scope

- Behavior expectations after routing (the per-skill evals own those).
