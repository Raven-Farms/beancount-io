## Objective

Send GA4's recommended `purchase` event from the browser exactly once per paid transaction, so the `checkout_started` → `purchase` funnel is measurable without any operator setup.

## Context

- Analytics: `dashboard/src/common/analytics/{events.ts,track.ts}`; `track()` is the typed gtag wrapper and the event map documents each event. `docs/event-taxonomy.md` and its guard test (`src/common/analytics/__tests__/event-taxonomy.test.ts`) must list every tracked event.
- GA4 deduplicates `purchase` events sharing a non-empty `transaction_id` on web streams, but this task must not rely on that: guard locally too.
- Checkout: the confirmation's "done" state has `session_id` (t004) and the confirmed subscription's price (amount, currency, interval) from `subscriptionStatus`. In-sheet upgrade: t002's `invoiceId`, `amountPaid` and `currency`, on `ACTIVE` or after `bank-approval.ts` reports success.
- GA4 `purchase` params: `transaction_id`, `value` (major units), `currency` (upper case), `items[]` with `item_id` (price id), `item_name` (tier), `item_variant` (`month | year`), `price`, `quantity: 1`.

## Steps

1. Add `purchase` to the typed event map with those params.
2. Add a `recordPurchase()` helper that sends once per `transaction_id`, remembered in `localStorage` (falls back to sending once per page when storage is unavailable), and skips an empty id or a zero value.
3. Call it from the confirmation's "done" state (Checkout session id) and from the change sheet's successful immediate charge (invoice id), including the bank-approval success path.
4. Rewrite the `purchase` row and the monetary-exception note in `docs/event-taxonomy.md` as client-side.

## Files

- `dashboard/src/common/analytics/{events.ts,track.ts}` or a new `purchase.ts`
- `dashboard/src/features/user-settings/pages/general/{checkout-confirmation.tsx,subscription-section.tsx,plan-change-sheet.tsx,bank-approval.ts}`
- `dashboard/docs/event-taxonomy.md`

## Acceptance criteria

- [ ] One `purchase` per transaction id across refresh, back navigation and a second tab; none while confirming, on timeout, without a session id, or for a $0 transaction.
- [ ] An in-sheet upgrade that charged records one `purchase` with the invoice id; a scheduled change records none.
- [ ] The taxonomy guard test passes with the rewritten row.

## Out of scope

- Server-side reporting (retired in t003); traffic-source attribution (the browser event carries it natively).

## Done — 2026-10-20

`recordPaidTransaction()` (`dashboard/src/features/user-settings/lib/paid-transaction.ts`) sends GA4 `purchase` once per Stripe invoice per browser (`localStorage`, else once per page load), with value in major units, upper-case currency and the plan as its item; an empty id or $0 sends nothing. It fires on the Checkout confirmation for the subscription's first invoice (`billingReason: subscription_create`, read from a new `Subscription.latestInvoice` field — the Checkout session carries no amount, and a coupon makes the list price wrong) and in the change sheet when an immediate change is paid or the bank approves it. The invoice id is the transaction id in both places. The event taxonomy now documents a browser-side `purchase`.
