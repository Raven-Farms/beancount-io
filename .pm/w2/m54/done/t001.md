## Objective

After a paid Checkout, Stripe sends every customer to the dashboard confirmation instead of the marketing pricing page, with the Checkout session id in the URL. A Checkout the customer abandons returns to where it started: the pricing page (unchanged) or, when the dashboard started it, Billing.

## Context

- `successUrl` and `cancelUrl` are static in `SUBSCRIPTION_CONFIG` (`backend-cluster/backend-v2/src/features/stripe/service/stripe.ts`, the `successUrl: "https://beancount.io/pricing/?success=true"` line). `createSubscriptionSession` in `service/subscription-service.ts` passes `success_url: clientConfig.successUrl` and builds `cancel_url` with `checkoutCancelUrl()`.
- The GraphQL mutation is `createSubscriptionSession(clientId, priceId)` in `api/subscription-resolver.ts`. The marketing pricing page, served outside this repository, calls it with exactly those two arguments, so any new argument must be optional and default to today's behaviour.
- The dashboard confirmation reads `checkout`, `session_id` and `return` from `/settings/billing` (`dashboard/src/features/user-settings/lib/billing-search.ts`). The way back to an in-product prompt is already remembered in `sessionStorage` before leaving for Checkout (`lib/billing-return.ts`), so the success URL does not need to carry it.
- `{CHECKOUT_SESSION_ID}` is a literal Stripe fills in. Building the URL with `URL`/`URLSearchParams` percent-encodes the braces and Stripe then leaves them unfilled — write it as a string or assert the final value.
- `stripe-service.ts` falls back to `successUrl` for the portal return when `portalReturnUrl` is empty; keep that fallback pointing somewhere sensible.

## Steps

1. Set `successUrl` to `https://beancount.io/settings/billing?checkout=success&session_id={CHECKOUT_SESSION_ID}`.
2. Add an optional `returnTo` argument (an enum such as `PRICING | BILLING`, default `PRICING`) to the mutation and service. `BILLING` makes `cancel_url` `https://beancount.io/settings/billing?checkout=canceled`; `PRICING` keeps `checkoutCancelUrl()`.
3. Regenerate the GraphQL schema/codegen artifacts both packages commit, and `yarn generate-v1-openapi` if the operation appears there.
4. Tests: both URLs for each plan and cycle with the literal `{CHECKOUT_SESSION_ID}`; the two-argument call still produces the pricing-page cancel URL.

## Acceptance criteria

- [ ] A session's `success_url` ends in `session_id={CHECKOUT_SESSION_ID}` with the braces unencoded.
- [ ] Without `returnTo`, `cancel_url` is byte-identical to today's pricing-page URL.
- [ ] With `returnTo: BILLING`, `cancel_url` is the Billing URL with `checkout=canceled`.
- [ ] `yarn typecheck`, `yarn lint` and `yarn test` pass in `backend-cluster/backend-v2`.

## Out of scope

## Done — 2026-10-20

Shipped in a83111079. `successUrl` is `https://beancount.io/settings/billing?checkout=success&session_id={CHECKOUT_SESSION_ID}` (braces unencoded). `createSubscriptionSession` takes an optional `returnTo: CheckoutReturnTo` (`PRICING` default, `BILLING`); omitted or null, the cancel URL is byte-identical to before, and `BILLING` cancels to `https://beancount.io/settings/billing?checkout=canceled`. The portal return no longer falls back to the success URL. Tests: success/cancel URLs per `returnTo`, null treated as the pricing page; both rules mutation-checked. The operation stays GraphQL-only, so op-class, rate-limit and the v1 OpenAPI spec are unchanged.
