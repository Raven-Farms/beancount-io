## Objective

Make the confirmation the right landing for every buyer. A buyer from an in-product prompt keeps "Back to work"; a buyer from the pricing page or Billing gets a primary "Start using <plan>" into the product; a buyer who cancelled Checkout from Billing is told nothing was charged.

## Context

- Billing page: `dashboard/src/features/user-settings/pages/billing/index.tsx`; search schema `lib/billing-search.ts` already accepts `checkout: success | canceled`, `session_id` and `return`.
- The confirmation: `pages/general/checkout-confirmation.tsx` (confirming → done/pending) driven by `use-checkout-confirmation.ts`; `subscription-section.tsx` recovers the way back with `takeReturnPath()` and starts Checkout in `startCheckout()`.
- Checkout from the dashboard must now pass `returnTo: BILLING` (t001).
- The ledger home is `/ledger`.

## Steps

1. Pass `returnTo: BILLING` from `startCheckout()`.
2. On `checkout=canceled`, show a non-blocking notice that nothing was charged, then drop the parameter from the URL so a refresh does not repeat it.
3. In the "done" state, render "Start using <plan>" linking to `/ledger` as the primary action when there is no way back, and keep "Back to work" primary when there is one; "View billing" stays secondary.
4. Keep `session_id` available to the confirmation for t005/t006.
