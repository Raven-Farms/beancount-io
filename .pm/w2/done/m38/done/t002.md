## Objective

Make CI reject a routing set that has drifted from the suite: unknown labels, duplicate prompts, or a skill with no near-miss negative.

## Context

- `skills/scripts/ci-check.py` already validates SKILL.md frontmatter and every `evals.json`; `skills/scripts/test_ci_check.py` tests it. `CI (skills)` runs both on `skills/**` changes.

## Steps

1. Load the routing set and compare `expected` labels with the skill directories on disk.
2. Fail on unknown labels, duplicate prompts (after whitespace normalization), and skills missing positives or near-miss negatives.
3. Add failing-fixture tests to `test_ci_check.py`.

## Files

- `skills/scripts/ci-check.py`, `skills/scripts/test_ci_check.py`

## Acceptance criteria

- [x] Renaming a skill directory without moving its labels fails `ci-check.py` with a message naming the label.
- [x] Each new rule has a test that fails when the rule is removed.

## Out of scope

- Running any client in CI.

## Result

`check_routing()` in `skills/scripts/ci-check.py` loads `skills/evals/routing.json` and fails on a missing field, a duplicate id, a prompt repeated after whitespace and case folding, an `expected` or `confusable` name that is not a customer skill directory, an entry listing its own skill as confusable, and a customer skill with no positive or no near-miss entry. `TestRoutingSet` in `test_ci_check.py` covers each rule; disabling any one of the six `fail()` calls turns exactly one test red.
