## Objective

Make every skill say that it works on local ledger files, and tell the agent where to go when the ledger is hosted on Beancount.io.

## Context

- Only `beancount-ask`'s description says "local". The others start by searching the working directory for `.beancount` files, which finds nothing for a user whose ledger is hosted.
- The hosted MCP server already serves rewritten playbooks of four skills as prompts: `close-month`, `reconcile-account`, `categorize-imports`, `spending-report` (`backend-cluster/backend-v2/src/features/ai-agent/api/mcp-prompts.ts`).

## Steps

1. Add "local" (or "local ledger files") to each description where it is missing.
2. Add one line to each body's discovery step: when the ledger is hosted and the Beancount.io MCP server is connected, use its tools and the matching prompt instead of this skill.
3. Point to the canonical place for this rule rather than restating it differently in eight places.

## Files

- `skills/.claude/skills/*/SKILL.md`, `skills/.claude/skills/beancount-init/references/bea-cli.md` (if the rule lives there)

## Acceptance criteria

- [x] The hosted-ledger routing prompts route to `none` on both clients in t007.
- [x] The hand-off names the four MCP prompts exactly as the server registers them.

## Out of scope

- Adding a hosted backend to the skills.

## Result

Every description now says "local" and skips "ledgers hosted on Beancount.io" (312–530 characters, valid YAML).
