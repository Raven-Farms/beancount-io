# The import config example stores the date format, columns, and sign twice, in two vocabularies

**Minor · skills · 15–20m · A1.** Found in the agentic-skill review of `skills/`, 2026-10-18.

The `chase-checking` stanza in the `beancount-import/SKILL.md` config block (Discover step) now carries both the original human-readable line and the `bea`-native lines added in the 2026-10-18 cleanup:

```
;;   format: csv  columns: date=1,desc=2,amount=3  date_format: MDY  sign: negative=outflow
;;   csv_mapping: date=Date,narration=Description,amount=Amount,sign=bank
;;   date_format: %m/%d/%Y
```

`date_format` appears twice in one stanza with different values (`MDY` and `%m/%d/%Y`). The columns (`columns: date=1,…` vs `csv_mapping: date=Date,…`) and sign (`negative=outflow` vs `sign=bank`) are each stated twice in different terms. An agent reading the block back on a repeat import has to guess which key wins. A user editing one copy leaves the other stale.

Give CSV sources one representation: the `bea`-native keys that are passed on every run. Keep the human-readable line only for OFX/QIF and other non-mapper sources, or rename the `bea` keys so no key repeats (`bea_date_format:`). Update the paragraph after the example and `references/bea-import.md` to match, and check that `beancount-importer-author`'s "read it as the spec" step still finds every field.
