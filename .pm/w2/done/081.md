# Decide whether `beancount-ask` becomes `beancount-query`

**Decision · skills · 15m after evidence · A1.** Found in the agentic-skill review of `skills/`, 2026-10-18. Held out of [m39](../blocked/m39/README.md), which renames only the two skills that collide with Beancount directives.

`beancount-ask` runs BQL through `bea --json query` and shows the query with every figure. `bea ask` is a different command that hands the question to another model, and the skill tells agents not to use it (`beancount-ask/SKILL.md`, "Keep query execution here rather than delegating the question to another LLM via `bea ask`"). The shared word is a plausible source of misroutes and of confusion for users who know the CLI. "Ask" is also the product's verb (the dashboard's Ask AI), which argues for keeping it.

Decide from evidence, not taste. [m39](../blocked/m39/README.md) t001 runs m38's routing set against a `beancount-query` variant. Rename only if the `bea ask` and BQL near-miss prompts route better with the new name on both clients and nothing regresses. If so, promote a follow-up that reuses m39's installer retirement and reference-update steps. If not, record the numbers here and close.

---

**Resolved 2026-10-19** — Decided by evidence: keep `beancount-ask`. [m39](../blocked/m39/README.md) t001 ran the routing set twice per client against a scratch suite where `beancount-ask` was renamed `beancount-query` (recorded in `skills/docs/routing-rehearsal.md`, "Proposed renames"). The five ask positives routed 5/5 and the four ask near-misses (`bea ask`, BQL and Beancount documentation, a hosted ledger) 4/4 in every run on both clients under both names, so the new name routes nothing better, and this note's rule says not to rename. No change shipped. (`skills`)
