## Objective

Read the current Claude Code plugin and marketplace documentation and the current Codex plugin documentation. Then choose where each manifest lives, how it points at `skills/`, and the plugin's name. Record the decision, with the doc sections it rests on, in this task's `## Decision` section before t002 and t003 start.

## Context

- After m42, the suite is at `skills/<name>/SKILL.md`, and m42's guard rejects any directory in `skills/` without a `SKILL.md`. A `.claude-plugin/` folder inside `skills/` would fail it. The candidate is a repository-root `.claude-plugin/marketplace.json` whose plugin entry has `"source": "./skills"` and declares its skills inline or by path. Confirm that the format accepts a plugin entry without its own `plugin.json` under that source.
- 2026-10-18 research, to re-check rather than assume: a self-hosted marketplace can be added with a sparse fetch (`claude plugin marketplace add <repo> --sparse …`), so users do not clone the 10,000-file monorepo. A plugin name may not start with `claude-`. A bare `beancount` name risks a brand hold in directory review, so the proposed name is `beancount-io`. Codex reads `.codex-plugin/plugin.json`, with a `skills` path, and ChatGPT also reads `.claude-plugin/marketplace.json`.
- Root `AGENTS.md` forbids parallel copies, and requires equivalent Codex behavior for any platform-specific configuration. `.agents/` holds development skills only. If Codex's marketplace file would live under `.agents/plugins/`, check that it cannot be mistaken for a development skill, and that `CI (skills)` and `check-agent-guidance.py` still describe the tree correctly.
- The repository root also holds `.mcp.json` and `.claude/settings.json` for contributors. Neither may end up inside the plugin.
