## Objective

Every install made before this milestone is a set of absolute symlinks into `$SKILLS_SRC/skills/.claude/skills/<name>`. After one `git pull`, those links point at nothing and the skills disappear from Claude Code and Codex without an error. Teach the installer to recognize and repair those links, and give `docs/skills/installation.md` a one-time upgrade path that works exactly as written.

## Context

- `install` writes `SOURCE_DIR / name` as each link target. `is_linked()` compares resolved paths, and `describe_conflict()` reports any other link as `links to … (target missing), not this checkout`. So today, re-running `install` after the pull refuses every old link as a conflict.
- An old link is this checkout's when its `os.readlink()` target is `<checkout root>/skills/.claude/skills/<name>`, where `<checkout root>` is the new source's repository root. A link into the old layout of a different checkout is not ours, and must still be reported as a conflict and left alone.
- Old checkouts sparse-check-out `skills` only, so after the pull they lack `scripts/skills/` and `docs/skills/`, and the installer path they know (`$SKILLS_SRC/skills/scripts/beancount-skills.py`) is gone. The upgrade has to start from Git: `git -C "$SKILLS_SRC" pull --ff-only`, then `git -C "$SKILLS_SRC" sparse-checkout set skills scripts/skills docs/skills`, then `python3 "$SKILLS_SRC/scripts/skills/beancount-skills.py" install <each destination>`.
- Workspace-only installs (`<workspace>/.claude/skills`, `<workspace>/.agents/skills`) have the same links and the same repair.

## Steps

1. In `install`, treat an owned old-layout link as ours: replace it with a link to `skills/<name>` and print `relinked <entry> -> <target> (moved from skills/.claude/skills)`.
2. In `verify`, report such a link as `FAIL <name>: links to the old skills/.claude/skills layout; repair with: python3 <script> install <dest>` rather than `link to missing …`. In `uninstall`, remove owned old-layout links as well.
3. Add a short "Upgrading from the old layout" section to `docs/skills/installation.md`, with the three commands above. Keep it until a later cleanup decides the window has passed, and point to it from `skills/README.md`'s install block.

## Files

- `scripts/skills/beancount-skills.py`, `docs/skills/installation.md`, `skills/README.md`

## Acceptance criteria

- [ ] For a destination holding links made by the pre-move installer, the documented upgrade gives `verify` → `OK`, with no manual `rm`.
- [ ] A link into another checkout's old layout is still a conflict: `install` changes nothing, and the message names it.
- [ ] `verify` never writes, and `uninstall` still removes only links into this checkout.

## Out of scope

- A redirect stub at `skills/scripts/beancount-skills.py`, because `skills/` holds no non-skills. The guide is the upgrade path.
